React.memo 怎样跳过组件渲染？什么情况下会失效？

memo 包住的组件在父组件重新渲染时，会把新旧 props 逐个用 Object.is 浅比较，全都相同就跳过渲染。对象、函数、JSX children 每次渲染都是新引用，会让比较失败，需要让 props 引用保持稳定；也可以传第二个参数自定义比较。组件自己的 state 或它读的 Context 变化时，memo 拦不住。

参考答案

简答

父组件重新渲染时，默认所有子组件都会跟着重新渲染。memo(Component) 给子组件加了一道检查：新旧 props 逐项用 Object.is 比较，全都一样就跳过这次渲染，直接复用上次的结果。

这个比较是浅比较，只看每个 prop 的引用。对象字面量、数组、箭头函数、JSX children 每次渲染都是新建的，内容一样引用也不同，比较就过不去。所以要让传给 memo 组件的 props 引用稳定：传基本类型，把对象拆成几个基本类型 prop，或者用 useMemo、useCallback 缓存。

需要特殊比较规则时，可以给 memo 传第二个参数 arePropsEqual(prevProps, nextProps)，返回 true 就跳过。但它必须比较所有 props，包括函数，否则会一直用着旧回调。

要注意，组件自己的 state 或它读的 Context 变了，memo 照样会重新渲染，它只管父组件传来的 props。memo 只是性能优化，React 不保证一定跳过，去掉以后程序逻辑应该仍然正确。

memo 在哪一步起作用

下面的搜索页里有一个主题切换按钮和一个结果列表。我们希望切换主题时，列表不要重新渲染。

JSX
import { memo, useCallback, useMemo, useState } from 'react';

const ResultList = memo(function ResultList({ items, onSelect }) {
  return items.map((item) => (
    <button key={item.id} onClick={() => onSelect(item.id)}>
      {item.title}
    </button>
  ));
});

export default function Search({ all }) {
  const [query, setQuery] = useState('');
  const [theme, setTheme] = useState('light');

  const items = useMemo(
    () => all.filter((item) => item.title.includes(query)),
    [all, query],
  );
  const handleSelect = useCallback((id) => console.log(id), []);

  return (
    <div className={theme}>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <button onClick={() => setTheme((t) => (t === 'light' ? 'dark' : 'light'))}>切换主题</button>
      <ResultList items={items} onSelect={handleSelect} />
    </div>
  );
}

点切换主题，Search 重新渲染，轮到 ResultList 时，React 拿这次的 items、onSelect 和上次的逐个用 Object.is 比较。两个引用都没变，ResultList 这次就不渲染了，它下面的按钮也跟着不渲染。

你可能会想，只加 memo 不行吗？不行。去掉 useMemo，filter 每次都返回新数组；去掉 useCallback，箭头函数每次都是新的。只要有一个 prop 是新引用，比较就失败，memo 等于白加。这两个 Hook 本身的区别和使用边界，见《useMemo 和 useCallback 有什么区别？什么时候不该用？》。

为什么内容一样，比较还是失败

这一点跟 React 无关，是 JavaScript 本身的规则。可以用 node 运行看看：

JavaScript
function render() {
  return { items: [1, 2], onSelect: () => {} };
}

const a = render();
const b = render();
console.log(Object.is(a.items, b.items));       // false
console.log(Object.is(a.onSelect, b.onSelect)); // false
console.log(Object.is('light', 'light'));       // true

组件每渲染一次就相当于调用一次 render，里面写的数组字面量和箭头函数都会重新创建，内容一样，引用却不同。字符串、数字这类基本类型按值比较，所以不受影响。

JSX children 也是一样。<Card><Title /></Card> 里的 <Title /> 每次渲染都会生成新的元素对象，作为 children prop 传给 memo(Card)，比较永远失败。

怎样让 props 保持稳定

React 文档给了几个方向。最简单的是少传对象：如果子组件只用到 user.name，就直接传 name，字符串按值比较。必须传对象时，用 useMemo 缓存它；传函数时，用 useCallback 缓存，或者把不依赖组件状态的函数挪到组件外部。

文档还建议，先尝试不用 memo 的结构调整：把状态下放到真正用它的组件里，或者让包裹型组件接收 children。这样父组件的状态变化根本碰不到这些子组件。

自定义比较函数

JSX
const Chart = memo(function Chart({ points, onHover }) {
  // ...
}, (prev, next) => (
  prev.points.length === next.points.length &&
  prev.points.every((p, i) => p.x === next.points[i].x && p.y === next.points[i].y) &&
  prev.onHover === next.onHover
));

第二个参数返回 true 表示“props 相等，可以跳过”。React 文档提醒了两点。一是不要漏掉函数类型的 prop，否则组件被跳过后，里面闭包读到的还是旧的 props 和 state。二是不要做深比较，除非确定数据结构有上限，深比较可能比重新渲染还慢，甚至让页面卡住。

memo 管不到的情况

memo 只拦截“父组件重新渲染导致的渲染”。组件自己调用 setState 改了 state，或者它用 useContext 读的 Context 变了，都会照常重新渲染。Context 这条路径的细节见《React Context 有哪些性能问题？怎样避免不必要的重新渲染？》。

如果慢的原因是一次渲染了太多 DOM，memo 也帮不上忙，应该用虚拟列表或拆分组件。

有了 React Compiler 还要手写吗

React Compiler 在构建时分析符合 React 规则的组件，自动加上等价于 memo、useMemo、useCallback 的缓存。启用以后，新代码一般不需要再手写 memo。已有代码里的手写缓存可以先留着，确认编译器已经覆盖了对应组件再删。详见《React Compiler 解决了哪些优化问题？》。

常见追问

memo 和 useMemo 是一回事吗？

不是。memo 包裹整个组件，props 没变时跳过它的渲染；useMemo 是 Hook，在组件内部缓存一个值。两者经常配合使用，useMemo 负责让传进去的 prop 保持同一个引用。

每个组件都包上 memo 好不好？

没有必要。React 文档说，大多数交互本来就足够快，memo 只在组件经常用相同的 props 重新渲染、而且渲染逻辑比较昂贵时才有明显效果。props 每次都在变的组件，加了只会多一次比较。
