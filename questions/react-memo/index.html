memo、useMemo、useCallback 各自优化什么？

memo 在 props 浅比较相同时跳过子组件渲染，useMemo 缓存计算结果，useCallback 缓存函数引用。它们只在依赖正确、性能确有问题时有用；启用 React Compiler 后多数手写缓存可以交给编译器。

参考答案

简答

  • memo(Component)：父组件重新渲染时，如果新旧 props 用 Object.is 逐项比较都相同，就跳过这个子组件的渲染。
  • useMemo(fn, deps)：依赖不变时返回上次的计算结果，用于昂贵计算或需要保持引用稳定的对象。
  • useCallback(fn, deps)：依赖不变时返回同一个函数引用，等价于 useMemo(() => fn, deps)。
  • 组件自身的 state 或它读取的 Context 变化时，memo 照样会重新渲染。
  • 这些都是性能优化，去掉后程序逻辑应该仍然正确；先用 React DevTools Profiler 确认瓶颈再加。

三者配合

JSX
import { memo, useCallback, useMemo, useState } from 'react';

const ResultList = memo(function ResultList({ items, onSelect }) {
  return items.map((item) => (
    <button key={item.id} onClick={() => onSelect(item.id)}>
      {item.title}
    </button>
  ));
});

export default function Search({ all }) {
  const [query, setQuery] = useState('');
  const [theme, setTheme] = useState('light');

  const items = useMemo(
    () => all.filter((item) => item.title.includes(query)),
    [all, query],
  );
  const handleSelect = useCallback((id) => console.log(id), []);

  return (
    <div className={theme}>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <button onClick={() => setTheme((t) => (t === 'light' ? 'dark' : 'light'))}>切换主题</button>
      <ResultList items={items} onSelect={handleSelect} />
    </div>
  );
}

切换主题时 Search 重新渲染，但 items 和 handleSelect 的引用没变，所以 ResultList 被跳过。去掉任意一个 useMemo 或 useCallback，每次渲染都会生成新引用，memo 的比较就会失败。

什么时候不值得用

  • 计算本身很便宜，缓存的比较开销和代码复杂度反而更高。
  • props 里经常有每次都新建的对象、数组或 JSX children，memo 永远比较不通过。
  • 慢的原因是一次渲染太多 DOM，这时应该用虚拟列表或拆分组件，而不是缓存。

更好的第一步通常是调整结构：把状态下放到真正用它的组件，或者把不变的部分作为 children 传进来，让它不随父组件重新渲染。

和 React Compiler 的关系

React Compiler 1.0 已稳定发布。它在构建时分析符合 React 规则的组件，自动插入等价的缓存。启用后，新代码一般不需要再手写 memo、useMemo、useCallback。已有代码里的手写缓存可以先保留，确认编译器覆盖了对应组件后再删除，详见《React Compiler 解决了哪些优化问题？》。

常见追问

  • memo 能自定义比较吗？第二个参数传 arePropsEqual(prev, next)，但必须比较所有 props，包括函数，否则会读到旧回调。
  • useMemo 能保证一定缓存吗？官方说明 React 可能在某些情况下丢弃缓存，所以不能用它保存必须持久的数据。
