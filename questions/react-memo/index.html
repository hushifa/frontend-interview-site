memo、useMemo、useCallback 各自优化什么？

memo 让子组件在 props 没变时跳过渲染，useMemo 缓存一个计算结果，useCallback 缓存一个函数。它们得配合使用才有效，而且只在确实慢的时候才值得加；启用 React Compiler 后大部分可以交给编译器。

参考答案

简答

父组件重新渲染时，默认所有子组件都会跟着重新渲染。memo(Component) 给子组件加了一道检查：新旧 props 逐项用 Object.is 比较，全都一样就跳过这次渲染。

可是函数和对象每次渲染都是新建的，引用变了，memo 的比较就过不去。所以需要 useMemo(fn, deps) 缓存计算结果，useCallback(fn, deps) 缓存函数，依赖不变就返回上一次的同一个值。useCallback(fn, deps) 等价于 useMemo(() => fn, deps)。

三者常常一起用：useMemo 和 useCallback 保证 props 引用稳定，memo 才能真正跳过子组件。useMemo 单独用也可以，用来避免重复的昂贵计算。

要注意，组件自己的 state 或它读的 Context 变了，memo 照样会重新渲染。这些都只是性能优化，去掉以后程序逻辑应该仍然正确，先用 React DevTools Profiler 确认瓶颈再加。

三者怎么配合

下面的搜索页里有一个主题切换按钮和一个结果列表。我们希望切换主题时，列表不要重新渲染。

JSX
import { memo, useCallback, useMemo, useState } from 'react';

const ResultList = memo(function ResultList({ items, onSelect }) {
  return items.map((item) => (
    <button key={item.id} onClick={() => onSelect(item.id)}>
      {item.title}
    </button>
  ));
});

export default function Search({ all }) {
  const [query, setQuery] = useState('');
  const [theme, setTheme] = useState('light');

  const items = useMemo(
    () => all.filter((item) => item.title.includes(query)),
    [all, query],
  );
  const handleSelect = useCallback((id) => console.log(id), []);

  return (
    <div className={theme}>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <button onClick={() => setTheme((t) => (t === 'light' ? 'dark' : 'light'))}>切换主题</button>
      <ResultList items={items} onSelect={handleSelect} />
    </div>
  );
}

点切换主题，Search 重新渲染。items 的依赖 all、query 都没变，useMemo 返回上次那个数组；handleSelect 依赖是空数组，useCallback 返回上次那个函数。ResultList 收到的两个 props 引用都没变，memo 就跳过了它。

你可能会想，只加 memo 不行吗？不行。去掉 useMemo，filter 每次都返回新数组；去掉 useCallback，箭头函数每次都是新的。只要有一个 prop 是新引用，memo 的比较就失败，等于白加。

为什么函数和数组每次都是新的

这一点跟 React 无关，是 JavaScript 本身的规则。可以用 node 运行看看：

JavaScript
function render() {
  return { items: [1, 2], onSelect: () => {} };
}

const a = render();
const b = render();
console.log(Object.is(a.items, b.items));       // false
console.log(Object.is(a.onSelect, b.onSelect)); // false
console.log(Object.is('light', 'light'));       // true

组件每渲染一次就相当于调用一次 render，里面写的数组字面量和箭头函数都会重新创建，内容一样，引用却不同。字符串、数字这类基本类型按值比较，所以不受影响。这就是 useMemo 和 useCallback 要解决的问题。

什么时候不值得用

计算本身很便宜时，缓存的比较开销和多出来的代码反而更贵。

props 里经常带着每次都新建的对象、数组或 JSX children 时，memo 永远比较不通过，加了也没用。

如果慢的原因是一次渲染了太多 DOM，缓存帮不上忙，应该用虚拟列表或拆分组件。

更好的第一步通常是调整结构：把状态下放到真正用它的组件里，或者把不变的部分作为 children 传进来。这样父组件的状态变化根本碰不到它们。

有了 React Compiler 还要手写吗

React Compiler 1.0 已经稳定发布。它在构建时分析符合 React 规则的组件，自动加上等价的缓存。启用以后，新代码一般不需要再手写 memo、useMemo、useCallback。

已有代码里的手写缓存可以先留着，确认编译器已经覆盖了对应组件再删。详见《React Compiler 解决了哪些优化问题？》。

常见追问

memo 能自定义比较逻辑吗？

可以，第二个参数传 arePropsEqual(prev, next)。但它必须比较所有 props，包括函数。如果漏掉函数，组件被跳过后就会一直用着旧回调。

useMemo 能保证一定缓存住吗？

不能。官方说明 React 在某些情况下可能丢弃缓存，所以它只能当性能优化用，不能用来保存必须一直存在的数据。
