Redux 的单向数据流为什么强调 reducer 的纯粹性？

Redux 中状态只能通过 dispatch(action) 改变，reducer 根据旧 state 和 action 计算新 state。reducer 必须是纯函数且不修改原 state，这样变化才能通过引用比较检测，也才能被记录、重放和测试。Redux Toolkit 用 Immer 让"可变"写法生成不可变更新。

参考答案

简答

  • 数据流：组件 dispatch(action) → reducer 计算新 state → store 通知订阅者 → 组件用选择器读取需要的部分并重新渲染。
  • reducer 是纯函数：相同输入得到相同输出，不发请求、不读时间和随机数、不修改参数。
  • 必须返回新对象而不是修改旧 state，react-redux 靠引用比较判断选择器结果是否变化，原地修改会导致界面不更新。
  • Redux Toolkit 的 createSlice 内置 Immer，可以写 state.items.push(x)，Immer 会生成新的不可变对象。
  • 副作用放在 thunk（createAsyncThunk）或 listener middleware 中；服务端数据的请求和缓存推荐用 RTK Query。

Redux Toolkit 示例

JavaScript
import { configureStore, createSlice } from '@reduxjs/toolkit';

const bookmarksSlice = createSlice({
  name: 'bookmarks',
  initialState: { ids: [] },
  reducers: {
    toggled(state, action) {
      const id = action.payload;
      const index = state.ids.indexOf(id);
      if (index === -1) state.ids.push(id);
      else state.ids.splice(index, 1);
    },
  },
});

export const { toggled } = bookmarksSlice.actions;

export function makeStore() {
  return configureStore({ reducer: { bookmarks: bookmarksSlice.reducer } });
}
JSX
import { useDispatch, useSelector } from 'react-redux';

function BookmarkButton({ id }) {
  const saved = useSelector((s) => s.bookmarks.ids.includes(id));
  const dispatch = useDispatch();
  return <button onClick={() => dispatch(toggled(id))}>{saved ? '取消收藏' : '收藏'}</button>;
}

用 makeStore() 工厂函数创建 store，SSR 时每个请求创建一个新实例，避免不同用户共享状态。

不确定的值放在 action 里

JavaScript
const todosSlice = createSlice({
  name: 'todos',
  initialState: [],
  reducers: {
    added: {
      reducer(state, action) {
        state.push(action.payload);
      },
      prepare(text) {
        return { payload: { id: crypto.randomUUID(), text, createdAt: Date.now() } };
      },
    },
  },
});

ID 和时间在创建 action 时生成，reducer 本身仍然是确定的，重放同一个 action 会得到相同结果。

选择器与派生数据

JavaScript
import { createSelector } from '@reduxjs/toolkit';

const selectTodos = (s) => s.todos;
const selectDone = createSelector([selectTodos], (todos) => todos.filter((t) => t.done));

state 中只存原始数据，派生数据用 memoized 选择器计算。如果 useSelector 中直接写 s.todos.filter(...)，每次都返回新数组，组件会在任何 action 后重新渲染。

异步逻辑

JavaScript
export const fetchTodos = createAsyncThunk('todos/fetch', async (_, { signal }) => {
  const res = await fetch('/api/todos', { signal });
  return res.json();
});

createAsyncThunk 自动派发 pending、fulfilled、rejected 三个 action，reducer 在 extraReducers 中处理它们。

什么时候用 Redux

  • 很多组件共享、频繁更新的客户端状态，需要调试工具追踪每次变化。
  • 只是缓存接口数据：用 RTK Query 或 TanStack Query。
  • 只是少量全局状态：Context、Zustand 更轻。

常见追问

  • 为什么不能在 reducer 里 fetch？请求是副作用，结果不确定，记录和重放 action 时无法得到相同的 state。
  • Immer 有什么限制？要么修改草稿，要么返回新值，不能两者同时做。
