React Compiler 解决了哪些优化问题？

React Compiler 在打包时自动给组件加上缓存，相当于替你写好 memo、useMemo、useCallback。它只处理遵守 React 规则的代码，管不了渲染内容太多、接口太慢这类问题。

参考答案

简答

以前为了少渲染、少计算，要手写 memo、useMemo、useCallback，写多了容易漏依赖，写少了又没效果。React Compiler 是一个打包时运行的 Babel 插件（babel-plugin-react-compiler），它分析你的组件，自动把这些缓存加上。1.0 已经稳定发布。

它能这么做，是因为 React 要求渲染是纯函数：不改 props 和 state，Hook 在顶层调用。只要代码守这些规则，编译器就能判断哪些值只跟哪些输入有关，输入不变就复用上次的结果。违反规则的组件，它会直接跳过，不报错。

它主要面向 React 19，React 17、18 也能用，要额外装 react-compiler-runtime 并配置 target。配套的 lint 规则在 eslint-plugin-react-hooks 的推荐预设里，能提前找出会被跳过的代码。

要注意，它减少的只是重复渲染和重复计算。DOM 太多、接口慢、包太大，还是要靠虚拟列表、数据加载策略和代码拆分。

编译器具体做了什么

先看一个普通组件，它算出购物车总价，再格式化成货币：

JSX
function CartSummary({ items, currency }) {
  const total = items.reduce((sum, item) => sum + item.price * item.count, 0);
  const formatted = new Intl.NumberFormat('zh-CN', { style: 'currency', currency }).format(total);
  return <Price value={formatted} onCopy={() => navigator.clipboard.writeText(formatted)} />;
}

没有编译器时，父组件每渲染一次，这里的 total、formatted 都要重算，传给 Price 的箭头函数也是新的。函数是新的，Price 就会跟着重新渲染。

编译以后，total、formatted、回调函数和 JSX 都会按它们依赖的 items、currency 缓存起来。只要这两个值没变，父组件再怎么渲染，Price 收到的 props 都和上次一样，就会被跳过。要手写达到同样效果，你得写两个 useMemo、一个 useCallback，再给 Price 包一层 memo。

为什么不守规则的代码会被跳过

编译器加缓存的前提是“输入一样，输出就一样”。如果组件在渲染时改了外部变量，或者直接改 props，那输入一样输出也可能不同，缓存就会让结果出错。

所以编译器遇到这种代码时选择不碰它，组件照旧每次执行。这也意味着它不会报错提醒你，要靠 lint 规则提前发现。

在 Vite 里怎么接入

@vitejs/plugin-react 6.0 起去掉了内联的 babel 选项，改成配合 @rolldown/plugin-babel 使用预设：

JavaScript
// vite.config.js
import { defineConfig } from 'vite';
import react, { reactCompilerPreset } from '@vitejs/plugin-react';
import babel from '@rolldown/plugin-babel';

export default defineConfig({
  plugins: [react(), babel({ presets: [reactCompilerPreset()] })],
});

6.0 之前的版本写成 react({ babel: { plugins: ['babel-plugin-react-compiler'] } })。如果你用自定义 Babel 配置，编译器插件必须排在第一个，因为它要分析还没被其他插件改写过的源码。

怎么确认它生效了

最直观的是看 React DevTools，被编译的组件名旁边会显示 “Memo ✨” 标记。也可以看构建产物，里面会出现从 react/compiler-runtime 导入的缓存函数。

如果某个组件编译后行为不对，可以在函数体第一行写 "use no memo"，让编译器临时跳过它。等找到并修好根本原因，再把这行删掉。

老项目怎么迁移

建议一步一步来：先打开 lint 规则，把违反 React 规则的代码修掉；然后可以按目录逐步启用编译。原来手写的 useMemo、useCallback 不用一次删光，编译器能和它们共存，确认组件已经被编译、行为没变以后再清理。

常见追问

编译器会改变程序的行为吗？

对遵守规则的代码不会，它只是多加了缓存。如果代码依赖“每次渲染都要重新执行一遍”来产生副作用，编译后可能表现不同，但这种代码本身就违反了规则。

有了编译器还要学 memo 吗？

要。面试和读老代码都会遇到，而且理解 memo 才知道编译器在替你做什么。对比见《memo、useMemo、useCallback 各自优化什么？》。
