React Compiler 解决了哪些优化问题？

React Compiler 在构建时分析遵守 React 规则的组件和 Hook，自动插入记忆化，减少不必要的重新渲染和重复计算。它需要构建工具接入，会跳过违反规则的代码，也不能解决渲染内容过多、请求慢这类问题。

参考答案

简答

  • React Compiler 是构建期的 Babel 插件（babel-plugin-react-compiler），1.0 已稳定发布，自动完成过去手写的 memo、useMemo、useCallback。
  • 它只编译遵守 React 规则的代码：渲染是纯函数、不修改 props 和 state、Hook 在顶层调用。违反规则的组件会被跳过，不会报错。
  • 主要面向 React 19，也支持 React 17、18，后者需要额外安装 react-compiler-runtime 并配置 target。
  • 配套的 lint 规则在 eslint-plugin-react-hooks 的推荐预设中，可以提前发现会被编译器跳过的代码。
  • 它减少的是重复渲染和重复计算；DOM 数量太多、接口慢、包体积大，仍要靠虚拟列表、数据加载策略和代码拆分。

在 Vite 中接入

@vitejs/plugin-react 6.0 起移除了内联的 babel 选项，改为配合 @rolldown/plugin-babel 使用预设：

JavaScript
// vite.config.js
import { defineConfig } from 'vite';
import react, { reactCompilerPreset } from '@vitejs/plugin-react';
import babel from '@rolldown/plugin-babel';

export default defineConfig({
  plugins: [react(), babel({ presets: [reactCompilerPreset()] })],
});

6.0 之前的版本写成 react({ babel: { plugins: ['babel-plugin-react-compiler'] } })。使用自定义 Babel 配置时，编译器插件必须排在第一个，因为它要分析未经其他插件改写的源码。

编译器做了什么

JSX
function CartSummary({ items, currency }) {
  const total = items.reduce((sum, item) => sum + item.price * item.count, 0);
  const formatted = new Intl.NumberFormat('zh-CN', { style: 'currency', currency }).format(total);
  return <Price value={formatted} onCopy={() => navigator.clipboard.writeText(formatted)} />;
}

编译后，total、formatted、传给 Price 的回调和 JSX 都按依赖（items、currency）缓存。items 和 currency 不变时，即使父组件重新渲染，Price 也收到相同的 props 并被跳过。手写的话需要两个 useMemo、一个 useCallback，再给 Price 套 memo。

验证是否生效

  • React DevTools 中被编译的组件名旁会显示 "Memo ✨" 标记。
  • 构建产物里会出现从 react/compiler-runtime 导入的缓存函数。
  • 某个组件编译后行为异常，可以在函数体第一行写 "use no memo" 临时跳过，修好根本问题后删掉。

迁移已有项目

  1. 先启用 lint 规则，修复违反 React 规则的代码。
  2. 可以按目录逐步启用编译。
  3. 手写的 useMemo、useCallback 不必一次删光，编译器能和它们共存；确认组件已被编译、行为不变后再清理。

常见追问

  • 编译器会改变程序行为吗？对遵守规则的代码不会，它只增加缓存。依赖"每次渲染都重新执行"这类副作用的代码可能表现不同，这类代码本身就违反了规则。
  • 和 memo 的对比见《memo、useMemo、useCallback 各自优化什么？》。
