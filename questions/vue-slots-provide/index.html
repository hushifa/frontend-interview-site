插槽、作用域插槽和 provide/inject 各解决什么问题？

插槽让父组件往子组件的指定位置塞内容；作用域插槽让子组件把数据交出来，由父组件决定怎么显示；provide/inject 让祖先组件把东西直接传给很深的后代，不用一层层传 props。

参考答案

简答

插槽就是子组件留出的空位，父组件往里填内容。比如卡片组件留一个 footer 的位置，父组件用 <template #footer> 往里放按钮。这些内容是在父组件里写的，所以只能用父组件的数据。

作用域插槽是反过来让子组件交数据。子组件写 <slot :item="item"> 把每一行的数据传出去，父组件用 #default="{ item }" 接住，自己决定这一行长什么样，列表和表格的行模板常这么做。

provide/inject 解决的是跨层传递。祖先组件 provide(key, value)，任意深度的后代 inject(key) 就能拿到，中间的组件完全不用管。

用 provide 时有两点要注意。想让注入的值是响应式的，就 provide 一个 ref 或 reactive，并把修改数据的方法一起 provide 出去，让状态只在提供者里改。key 用 Symbol 防止重名，TypeScript 里用 InjectionKey<T> 带上类型。

作用域插槽：列表组件

下面的 DataList 负责加载中、空状态和列表结构，但每一行长什么样交给使用方：

vue
<!-- DataList.vue -->
<script setup>
defineProps({ items: Array, loading: Boolean });
</script>

<template>
  <p v-if="loading">加载中…</p>
  <ul v-else-if="items.length">
    <li v-for="item in items" :key="item.id">
      <slot :item="item">{{ item.title }}</slot>
    </li>
  </ul>
  <slot v-else name="empty"><p>暂无数据</p></slot>
</template>
vue
<DataList :items="users" :loading="loading">
  <template #default="{ item }">
    <strong>{{ item.name }}</strong> <small>{{ item.email }}</small>
  </template>
  <template #empty>还没有用户，<a href="/invite">邀请一位</a></template>
</DataList>

插槽内容写在父组件里，按理只能访问父组件的数据，那 item 是哪来的？是子组件通过 <slot :item="item"> 递出来的。父组件在 #default="{ item }" 里接住它，就能用了。

<slot> 标签里面的内容是默认内容。父组件没传这个插槽时，就显示 {{ item.title }} 和“暂无数据”。

provide/inject：表单上下文

表单里的字段可能嵌在很多层组件里面，每一层都传 disabled 和 errors 会很麻烦。用 provide/inject 可以让字段直接拿到表单的状态：

JavaScript
// form-context.js
import { inject, provide, reactive, readonly } from 'vue';

const FormKey = Symbol('form');

export function provideForm() {
  const state = reactive({ disabled: false, errors: {} });
  const setError = (field, msg) => { state.errors[field] = msg; };
  provide(FormKey, { state: readonly(state), setError });
  return state;
}

export function useForm() {
  return inject(FormKey, null);
}
vue
<!-- FormField.vue，可以放在 Form 下任意深度 -->
<script setup>
import { useForm } from './form-context';
const props = defineProps({ name: String });
const form = useForm();
</script>

<template>
  <input :name="props.name" :disabled="form?.state.disabled" />
  <p v-if="form?.state.errors[props.name]">{{ form.state.errors[props.name] }}</p>
</template>

为什么 provide 出去的是 readonly(state)？因为如果每个后代都能直接改 state，出了问题就不知道是谁改的。用 readonly 包一层，后代只能读，想改就得调 setError，所有修改都发生在提供者这里，排查起来很方便。

常见追问

怎么判断父组件有没有传某个插槽？

在 <script setup> 里用 useSlots()，模板里可以直接判断 $slots.footer。

inject 找不到对应的 key 会怎样？

返回第二个参数给的默认值。没有给默认值的话，开发环境会给出警告。
