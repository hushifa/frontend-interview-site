Angular 中 Observable 和 Signals 怎样协作？

Observable 适合描述随时间到达的事件和异步流，可以组合、取消；Signal 适合表示随时能同步读取的当前状态。用 toSignal 把 Observable 转为 Signal 给模板用，用 toObservable 把 Signal 的变化接入 RxJS 管道。

参考答案

简答

Signal 和 Observable 描述的是两种东西。Signal 是“现在的值”，任何时候都有值，读取是同步的。Observable 是“一串陆续到来的事件”，可能还一个值都没有，也可能已经结束或者出错了。

两者可以互转。toSignal(obs$) 会订阅 Observable，把最新的值变成 Signal，组件销毁时自动取消订阅。第一个值到达之前，这个 Signal 的值是 undefined，可以用 initialValue 给一个初始值。反过来，toObservable(sig) 在 Signal 变化后发出新值，方便接上 debounceTime、switchMap 这些操作符。

所以分工是：要防抖、取消上一次请求、合并多个事件流，用 RxJS；表示界面状态和派生值，用 Signal 更简单。

有一点要注意，Observable 出错以后，读取 toSignal 得到的 Signal 会抛错，所以要在管道里用 catchError 处理掉。

一个搜索框把两者串起来

搜索框是最典型的场景：输入是界面状态，适合 Signal；防抖、取消旧请求是流的处理，适合 RxJS；结果又要给模板用，再转回 Signal。

TypeScript
import { Component, inject, signal } from '@angular/core';
import { toObservable, toSignal } from '@angular/core/rxjs-interop';
import { HttpClient } from '@angular/common/http';
import { catchError, debounceTime, distinctUntilChanged, of, switchMap } from 'rxjs';

@Component({
  selector: 'app-search',
  template: `
    <input [value]="query()" (input)="query.set($any($event.target).value)" />
    @for (item of results(); track item.id) {
      <p>{{ item.title }}</p>
    }
  `,
})
export class SearchComponent {
  private http = inject(HttpClient);
  readonly query = signal('');

  readonly results = toSignal(
    toObservable(this.query).pipe(
      debounceTime(300),
      distinctUntilChanged(),
      switchMap((q) =>
        q
          ? this.http
              .get<{ id: number; title: string }[]>(`/api/search?q=${encodeURIComponent(q)}`)
              .pipe(catchError(() => of([])))
          : of([]),
      ),
    ),
    { initialValue: [] },
  );
}

用户连续输入时，debounceTime(300) 等他停下 300 毫秒才往下走。新的查询到来时，switchMap 会取消上一次还没完成的请求，所以慢回来的旧结果不会覆盖新结果。initialValue: [] 让模板在第一次请求完成前也能直接遍历，不用处理 undefined。

这里最容易写错的是 catchError 的位置。它写在 switchMap 里面、单个请求的后面。如果放到外层管道上，一次请求出错，整条流就结束了，之后用户再怎么输入都不会触发搜索。放在里面，出错的只是这一次请求，换成空数组，外面的流继续工作。

订阅什么时候需要手动清理

toSignal 和模板里的 async 管道都会自动取消订阅。自己写 subscribe 的时候，就要用 takeUntilDestroyed()，让订阅在组件销毁时结束：

TypeScript
this.socket.messages$.pipe(takeUntilDestroyed()).subscribe((m) => this.messages.update((l) => [...l, m]));

在构造期间调用时它不需要参数；在别的地方调用，要传入 DestroyRef。

只是按参数请求一次数据时

如果需求只是“参数变了就重新请求”，不需要防抖这类流处理，可以直接用 Angular 的 resource 或 rxResource。它们把参数 Signal 和异步加载结合在一起，不用手动来回转换，详见《Angular Signals 的依赖追踪与 computed 有什么特点？》。

常见追问

toSignal 能在组件外调用吗？

它要在注入上下文里调用，因为要靠注入上下文知道什么时候自动取消订阅。在别的地方调用，需要通过 injector 选项传一个注入器进去。

像 BehaviorSubject 这种同步就有值的 Observable，能省略初始值吗？

可以，设置 requireSync: true。这样 Signal 的类型里就不会带 undefined。
