Vue 2 有哪些组件通信方式？哪些写法在 Vue 3 中被移除或改变？

Vue 2 常用 props 和 $emit、.sync、$attrs/$listeners、provide/inject、EventBus 和 Vuex 通信。到了 Vue 3，$listeners 并进了 $attrs，.sync 换成 v-model:xxx，$on/$off 被删掉，EventBus 要换成 mitt 这类库。

参考答案

Vue 2 已于 2023-12-31 停止维护，本题 Vue 2 部分以 2.7 为准。props 单向数据流、插槽与 provide/inject 的取舍分别见《为什么 Vue 提倡 props 单向数据流？》和《插槽、作用域插槽和 provide/inject 各解决什么问题？》。

简答

Vue 2 里父子通信首选 props 向下传、$emit 向上发事件。需要“双向”时用 v-model 或 .sync，它们只是语法糖，本质还是 prop 加事件。

其他方式按耦合程度排：包装组件用 $attrs 和 $listeners 把属性和监听器透传给内部元素；跨很多层用 provide/inject；全局共享状态用 Vuex；$parent、$refs 直接拿到组件实例，耦合最强；任意组件之间还可以用 new Vue() 做一个 EventBus。

到了 Vue 3，有几处变了。$listeners 被移除，监听器以 onXxx 的形式并进了 $attrs，$attrs 也开始包含 class 和 style。.sync 和 model 选项被移除，改成 v-model:title，组件 v-model 默认的 prop 和事件也从 value/input 变成了 modelValue/update:modelValue。

还有一处影响很大：实例上的 $on、$off、$once 没了，所以基于 new Vue() 的 EventBus 不能用了，官方建议换成 mitt、tiny-emitter 这类库。官方推荐的状态管理也从 Vuex 变成了 Pinia。

Vue 2 的通信方式一览

方式方向说明
props / $emit父 → 子 / 子 → 父最常用，数据流清晰
v-model / .sync双向语法糖:title.sync="t" 等价于 :title="t" @update:title="t = $event"
$attrs / $listeners透传包装组件把未声明的属性和监听器转交给内部元素
$parent / $children / $refs直接访问实例便捷但耦合重，适合调用子组件方法
provide / inject祖先 → 后代Vue 2 中注入的值默认不是响应式，除非提供的是响应式对象
EventBus任意组件const bus = new Vue()，用 $on/$emit/$off
Vuex全局集中管理共享状态

为什么 $listeners 并进了 $attrs

在 Vue 3 的虚拟 DOM 里，事件监听器就是名字带 on 前缀的普通属性，比如 onClick。既然它们本来就是属性，再单独放一个 $listeners 就没必要了，所以统一归到 $attrs 里。

vue
<!-- Vue 2 -->
<input v-bind="$attrs" v-on="$listeners" />

<!-- Vue 3 -->
<input v-bind="$attrs" />

两个版本都可以配合 inheritAttrs: false 控制透传到哪个元素。要注意，Vue 3 的 $attrs 包含 class 和 style，所以关掉 inheritAttrs 以后，它们也不会自动落到根元素上了，这是迁移时容易漏的地方。

.sync 改成了 v-model 参数

vue
<!-- Vue 2 -->
<ChildComponent :title.sync="pageTitle" />

<!-- Vue 3 -->
<ChildComponent v-model:title="pageTitle" />

子组件这边不用改，仍然是 emit('update:title', value)。Vue 3 允许同一个组件绑定多个 v-model，.sync 的用途就被覆盖了，组件的 model 选项也随之移除。

EventBus 为什么不能用了

Vue 2 的 EventBus 是借用了组件实例自带的 $on、$emit、$off。Vue 3 的组件实例不再实现这套事件接口，new Vue() 也没了，这个写法就失效了。要保留事件总线，可以换成专门的库：

JavaScript
// Vue 3：用 mitt 替代 new Vue() 作为事件总线
import mitt from 'mitt';
export const bus = mitt();

bus.on('saved', handler);
bus.emit('saved', payload);
bus.off('saved', handler);

不过迁移指南同时提醒，大多数情况下不建议用全局事件总线，事件从哪发、谁在听很难追踪。优先考虑 props 和事件、provide/inject 或者全局状态管理。$emit 本身还在，用来触发父组件监听的事件。

其他变化

$children 被移除了，要访问子组件改用模板 ref。Vuex 4 仍然支持 Vue 3，但官方文档说明 Vuex 已进入维护模式，新项目推荐用 Pinia。

常见追问

Vue 3 里子组件 emit 的事件需要声明吗？

推荐用 emits 选项或 defineEmits 声明。没声明的监听器会留在 $attrs 里，默认透传到子组件的根元素上，可能导致同一个事件触发两次。

迁移时 .sync 和 $listeners 能先临时保留吗？

可以。@vue/compat 迁移构建提供了 COMPONENT_V_MODEL、INSTANCE_LISTENERS、INSTANCE_EVENT_EMITTER 等兼容开关，可以先跑起来，再一项项替换。
