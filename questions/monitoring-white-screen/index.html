怎样检测页面白屏？常见方案有哪些误报？

白屏检测通常在加载完成后延迟检查根节点有没有内容，或者用 elementFromPoint 采样视口里的关键点，看是不是只剩容器元素，再结合错误日志和资源失败找原因；骨架屏、慢网络、后台标签页和合法的空状态都会造成误报。

参考答案

简答

白屏就是页面打开以后什么都没显示出来。浏览器没有“白屏了”这种原生事件，所以只能在约定的时间点自己判断，属于经验性的检测。

常用两种办法。一种是看根节点，比如 #app 里面是不是空的。另一种是在视口里取一些点，用 document.elementFromPoint(x, y) 看每个点上最上层的是什么元素，如果全是 html、body、#app 这类容器，就说明这些地方什么都没画出来。

只知道白了还不够，还得知道为什么白。所以判定白屏时，要把同一会话里的 JS 错误、资源加载失败和接口异常一起带上。

要注意误报。骨架屏、加载中、后台标签页、慢网络，还有合法的空列表，都可能被当成白屏，需要白名单、隔一会儿再查一次，以及跳过不可见的页面。

最简单的办法：看根节点

JavaScript
function rootIsEmpty() {
  const root = document.getElementById('app');
  return !root || root.childElementCount === 0;
}

SPA 渲染失败时，根节点通常还是空的，所以这是成本最低的信号。

可是它有盲区。如果应用渲染出了一个空壳布局，或者一个全屏的错误遮罩，根节点里就有子元素了，检查会通过，用户看到的却还是一片空白。

更准的办法：在视口里采样

下面在视口的横向中线和纵向中线上各取 9 个点，中心点只取一次，一共 17 个点，看每个点上最上层的元素：

JavaScript
const CONTAINERS = new Set(['HTML', 'BODY']);

function isBlankScreen(rootId = 'app') {
  const w = window.innerWidth;
  const h = window.innerHeight;
  const points = [];
  for (let i = 1; i <= 9; i += 1) {
    points.push([(w * i) / 10, h / 2]); // 横向中线
    if (i !== 5) points.push([w / 2, (h * i) / 10]); // 纵向中线，跳过已采样的中心点
  }
  const emptyCount = points.filter(([x, y]) => {
    const top = document.elementFromPoint(x, y);
    return !top || CONTAINERS.has(top.tagName) || top.id === rootId;
  }).length;
  return emptyCount === points.length;
}

这里要求所有采样点都落在容器上才算白屏，阈值也可以按业务放宽，比如 90%。

这个方法也有局限。它只看命中的是什么元素，不看实际画出来的像素。所以一个透明或者纯白背景的大块元素会被当成“有内容”。反过来，设了 pointer-events: none 或 visibility: hidden 的元素不会被命中，采样会穿过它们落到下面一层。

什么时候检查

太早检查，页面还没渲染完，就会误报。所以一般在 load 之后再延迟几秒，留出接口和渲染的时间。

第一次判定为空白时，先别急着报，隔一段时间再查一两次，连续都是空白才上报，这样能过滤掉慢网络。

document.visibilityState === 'hidden' 时要跳过，因为后台标签页的渲染可能被浏览器推迟。

除了首次加载，路由切换之后也可以检查。SPA 的白屏经常发生在懒加载的分包加载失败时。

怎样找到白屏的原因

白屏上报要带上下文，否则只能知道“白了”。最近的 JS 错误和未处理的 Promise 拒绝最有用，采集方式见《前端怎样全局捕获 JS 错误、Promise 拒绝和资源加载失败？》。脚本或 CSS 加载失败也要带上，特别是 CDN 上的入口文件和懒加载分包。另外还有关键接口的状态码和耗时，以及页面 URL、发布版本、浏览器版本。

常见的根因有这几种：入口脚本因为 CDN 故障或者缓存了旧 HTML 而 404；首屏渲染抛错，又没有错误边界兜底；浏览器不支持产物里用到的语法。

误报从哪里来，怎么处理

骨架屏和 loading 占位是最常见的。可以把骨架屏的选择器加进“仍在加载”的白名单，检查时发现它，就过一会儿再查。

合法的空状态也会误报，比如搜索没结果、购物车是空的，页面本来就几乎是空白。这类页面应该渲染一个明确的空状态元素，让检测知道这是正常的。

全屏的 Canvas、视频或者 iframe 也要注意。采样点命中的就是这些元素本身，它们里面到底画没画东西，检测看不出来，需要按业务另外确认。

还有用户很快就离开了的情况。页面还没渲染完用户就切走了，所以检查前先确认页面仍然可见。

常见追问

能用截图比较像素吗？

可以在合成监控或者测试环境里做。线上在用户端截图成本高，还涉及隐私，一般不用。

白屏率怎么算？

用检测到白屏的页面访问数，除以完成了检查的访问数。被跳过的后台访问不算进分母。

有了错误边界，还需要白屏检测吗？

需要。资源加载失败、入口脚本根本没执行的时候，错误边界自己都没运行起来，兜不住。
