网页字体加载怎样优化？font-display、子集化、preload 和 size-adjust 各解决什么问题？

字体优化从四处下手：font-display 决定字体没到时文字怎么显示；子集化和 unicode-range 让文件变小、只在用到时才下载；preload 让关键字体更早开始下载，而且必须写 crossorigin；size-adjust 把回退字体调到接近网页字体的尺寸，减少换字体时的布局偏移。

参考答案

简答

页面用了自定义字体，用户打开时字体文件还没下完，文字要么暂时看不见，要么先用系统字体显示、等字体到了再换。字体加载优化要解决的就是这段时间里的三个问题：文字看不见太久、字体文件太大、换字体时页面跳动。

font-display 管第一件事，它决定字体没到时文字是先隐藏还是先用回退字体显示，以及字体晚到了还换不换。正文常用 swap 或 optional，不让用户长时间对着空白。

文件大小靠子集化和 unicode-range。子集化是用工具把用不到的字形删掉再生成 WOFF2；unicode-range 把一套字体拆成几个文件并标明各自覆盖的字符，页面用不到某个范围的字符，那个文件就不下载。首屏一定要用的字体再用 <link rel="preload" as="font"> 提前下载，这里必须写 crossorigin，否则预加载的文件用不上，字体会再下一遍。

最后要注意页面跳动。回退字体和网页字体宽度不同，换字体时文字会重新排版，造成布局偏移，影响 CLS。可以用 size-adjust 等描述符把回退字体调到接近网页字体的尺寸，具体比例要按两种字体的实际度量来算。

字体没到时文字怎么显示

浏览器从开始用某个网页字体起，把等待过程分成三段。阻塞期里，字体还没到，文字用一个不可见的回退字体占位，也就是用户看不到字；交换期里，先用回退字体显示，字体在这段时间到了就换上；进入失败期以后，字体再到也不换了。font-display 就是调这三段的长短：

CSS
@font-face {
  font-family: 'Brand';
  src: url('/fonts/brand-latin.woff2') format('woff2');
  font-display: swap;
}

按 MDN 的说法，block 是短阻塞期加无限交换期；swap 是极短阻塞期加无限交换期；fallback 是极短阻塞期加短交换期；optional 是极短阻塞期，没有交换期。CSS Fonts 规范建议，“短”在大多数情况下取 3 秒，“极短”取 100 毫秒以内。

那正文该选哪个？如果品牌字体一定要出现，并且能接受换一次字，用 swap。如果更在意页面稳定，用 optional，第一次访问字体没及时到就一直用回退字体，等有缓存以后再用品牌字体。fallback 介于两者之间，字体在短交换期内到了就换，晚了就不换。

图标字体是例外，常用 block。因为图标字体换成回退字体显示，看到的是一些没有意义的字符或方框，宁可短时间看不见。

为什么浏览器会有这段等待？因为多数浏览器要等页面真正用到某个字体时才开始下载它，下载时机和怎样用 JavaScript 控制、检测加载，见《网页字体什么时候开始下载？怎样用 CSS Font Loading API 控制和检测加载？》。

怎样让字体文件变小

格式先统一成 WOFF2。MDN 的网页字体教程写道，所有现代浏览器都支持 WOFF2，只提供需要的格式，既能减少要提供的文件数，也有助于让字体下载更小。

然后是子集化，也就是只保留页面真正用到的字形。中文字体动辄几千上万个字，最省的做法是只给标题等固定文字生成子集。fontTools 的 subset 命令可以按文字或码点范围生成子集，并直接输出 WOFF2：

bash
fonttools subset brand.ttf --text-file=title-chars.txt --flavor=woff2 --output-file=brand-title.woff2

正文的文字不固定，没法只取几个字，这时可以按 Unicode 范围把字体拆成多个文件，再用 unicode-range 告诉浏览器每个文件覆盖哪些字符：

CSS
@font-face {
  font-family: 'Brand';
  src: url('/fonts/brand-latin.woff2') format('woff2');
  unicode-range: U+0000-00FF;
  font-display: swap;
}

@font-face {
  font-family: 'Brand';
  src: url('/fonts/brand-cjk-1.woff2') format('woff2');
  unicode-range: U+4E00-5FFF;
  font-display: swap;
}

两段声明用同一个 font-family，看起来像同一套字体，浏览器会按页面上出现的字符决定下载哪个文件。MDN 写得很明确：页面上一个范围里的字符都没用到，这个文件就不下载；只要用到一个，就下载整个文件。所以 unicode-range 本身不会把文件变小，它只是让你可以把字体拆细，拆得越细，每个页面要下的就越少。

preload 字体为什么必须写 crossorigin

字体写在 CSS 的 @font-face 里，浏览器要先拿到 CSS，再发现页面用到了它，才会去下载，发现得比较晚。MDN 在介绍 preload 时也说，资源被发现得越晚、体积越大，预加载的好处越明显。首屏关键字体可以在 HTML 里提前声明：

HTML
<link rel="preload" href="/fonts/brand-latin.woff2" as="font" type="font/woff2" crossorigin />

as="font" 告诉浏览器这是字体，type 让不支持 WOFF2 的浏览器跳过这次下载。读者通常会问：字体就放在自己的域名下，为什么还要写 crossorigin？MDN 的解释是，字体总是以匿名模式的 CORS 请求获取的，预加载的 crossorigin 要和真正请求的 CORS 模式一致，哪怕请求并不跨域。不写 crossorigin，预加载的请求模式就和 @font-face 发出的请求对不上，预加载的那份用不上。

preload 只用于首屏马上要用的那一两个字体文件。它和 prefetch、preconnect 的区别，可以看《preload、prefetch、preconnect、dns-prefetch 和 modulepreload 有什么区别？》。

换字体时页面为什么会跳

用 swap 时，用户先看到的是回退字体。两种字体的字宽、行高往往不一样，品牌字体一到，每行能放的字数变了，段落高度跟着变，下面的内容就被往下推。这种不是由用户操作引起的位移，就是 CLS 衡量的布局偏移，指标含义见《LCP、INP、CLS 分别衡量什么？》。

改法是不直接用系统字体当回退，而是声明一个“调整过尺寸的系统字体”：

CSS
@font-face {
  font-family: 'Brand Fallback';
  src: local('Arial');
  size-adjust: 104%;
  ascent-override: 92%;
}

body {
  font-family: 'Brand', 'Brand Fallback', sans-serif;
}

size-adjust 是一个缩放倍数，按 MDN 的说明，这个字体的字形轮廓和各项度量都会按这个比例缩放，MDN 也专门举了用它调整回退字体、让它更接近主字体的例子。ascent-override 调的是基线以上的高度。这里的 104% 和 92% 只用来演示，实际数值要根据两种字体的度量计算，不能照抄。调好以后，回退字体排出来的行宽和行高接近品牌字体，换字体时文字基本不会重新折行。

常见追问

用 JavaScript 能知道字体什么时候加载好吗？

能，用 CSS Font Loading API 的 FontFace.load() 或 document.fonts.ready。在 Canvas 上画字或测量文字宽度前等它们完成，用的才是网页字体，详见《网页字体什么时候开始下载？怎样用 CSS Font Loading API 控制和检测加载？》。

preload 的字体越多越好吗？

不是。预加载的资源会和 CSS、首屏图片这些关键资源抢带宽，只给首屏真正用到的一两个字体文件加 preload。
