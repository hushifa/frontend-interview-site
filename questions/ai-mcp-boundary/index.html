MCP、模型工具调用和聊天界面是什么关系？

MCP 是一套协议，规定 AI 应用怎样发现和调用外部服务提供的工具、资源和提示。模型只是提出"想调用什么"，真正决定、授权、确认和展示的是宿主应用。本题按 2026-07-28 版规范讲无状态请求、server/discover 和授权的变化。

参考答案

简答

MCP 是 AI 应用和外部能力之间的一套协议。外部服务叫 Server，它提供工具、资源和提示；AI 应用叫 Host，Host 里面的 Client 负责去发现和调用这些能力。

模型提出的工具调用只是一个建议。哪些工具能让模型看到、执行前要不要授权、要不要请用户确认，都是 Host 说了算。

2026-07-28 版规范有几个大变化：去掉了 initialize 握手和 Mcp-Session-Id，每个请求自己在 _meta 里带上协议版本和客户端能力，Server 必须实现 server/discover。Streamable HTTP 的 Last-Event-ID 续传也删了，流断开以后，客户端要用新的请求 ID 重新发请求。

授权方面，远程 Server 走 OAuth，客户端注册推荐用 Client ID Metadata Documents，动态客户端注册（DCR）已经标为弃用。

三个角色分别是谁

Host 是用户直接使用的 AI 应用，比如 IDE、桌面助手，或者网页聊天背后的服务端。它管着模型、界面，以及多个 Client。

Client 是 Host 里面的一个连接对象，一个 Client 对应一个 Server，负责和它通信。

Server 是提供能力的一方。它可以是本机上的一个进程，通过标准输入输出通信，也就是 stdio；也可以是远程服务，通过 Streamable HTTP 通信。

一次工具调用大致是这样走的：

text
用户任务 → Host 选出允许的工具 → 模型提出 tools/call 参数
        → Host 校验参数、确认权限、必要时请用户批准
        → Client 发送请求 → Server 执行 → Host 检查结果并更新界面

可以看到，模型只出现在中间一步，它只负责提出参数。前面选工具、后面校验和执行，都在 Host 手里。

Server 提供的三种能力要分清楚：工具是去执行操作的；资源是提供给模型看的上下文数据；提示是可以复用的输入模板。还要注意，资源内容和工具返回结果里的文字都是数据，里面可能藏着提示词注入，Host 要按不可信内容处理。

2026-07-28 版改了什么

这一版最大的方向是“无状态”：每个请求自己带齐需要的信息，不再依赖之前建立的会话。具体对比如下：

方面2025 年各版本2026-07-28 版
连接建立initialize 握手协商版本与能力无握手；每个请求的 _meta 携带 io.modelcontextprotocol/protocolVersion 和 clientCapabilities
能力发现握手返回Server 必须实现 server/discover，Client 可先调用它选版本
会话Mcp-Session-Id 头移除；跨调用状态由 Server 生成的句柄作为普通参数传递
服务端通知GET 长连接、resources/subscribe统一用 subscriptions/listen
断线续传Last-Event-ID 重放移除；流断开即丢失该请求，客户端用新请求 ID 重试
Server 向客户端索取输入Server 发起 sampling/createMessage、elicitation/create 等请求多轮请求模式：结果返回 resultType: "input_required"，客户端补充 inputResponses 后重试原请求

还有几处小变化。ping 和 logging/setLevel 被移除了，日志级别改成每个请求在 _meta 里用 io.modelcontextprotocol/logLevel 指定。所有结果都新增了一个必填字段 resultType，取值是 "complete" 或 "input_required"。Sampling、Roots 和 Logging 这几个功能被标为弃用，旧的 HTTP+SSE 传输方式也是弃用状态，新实现应该直接接 Streamable HTTP。

授权怎么做，浏览器能不能直接当 Host

远程 Server 的授权基于 OAuth。2026-07-28 版要求客户端校验授权响应里的 iss，也就是“这个授权是谁签发的”；凭据要按签发方分开保存，换了授权服务器就要重新注册。客户端注册推荐用 Client ID Metadata Documents，DCR 只是为了兼容才保留。

浏览器页面能直接当 Host 吗？一般不行。网页启动不了本地进程，长期令牌放在前端也不安全。常见做法是让后端或者桌面应用来当 Host，网页只负责展示调用状态、收集用户确认。

界面上要展示哪些状态

出错要分清是哪一层的错。连接失败、能力发现失败、协议版本不匹配（UnsupportedProtocolVersionError），这些是“根本没调到”；工具执行失败是“调到了但没成功”。两者要分开显示。

工具调用本身分成待确认、执行中、成功、失败、结果未知。为什么会有“结果未知”？因为响应流断了的时候，Server 可能已经执行完了，客户端只是没收到结果。新版又去掉了断线续传，所以有副作用的工具，要靠业务自己的幂等键，避免重试时又执行一遍。

如果结果是 input_required，说明 Server 需要用户补充信息，界面要能收集输入，再带着它重试原来的请求。

常见追问

接入 MCP 以后，模型就能访问用户的全部数据了吗？

不能。模型只看得到 Host 放进上下文的工具描述和工具结果。真正执行时，还要受 Host 和 Server 两边的权限限制。

工具注解里写了“只读”，可以不用确认吗？

注解是 Server 自己写的，只能拿来辅助展示，不能当成安全依据。要不要确认，由 Host 按自己的策略决定。
