MCP、模型工具调用和聊天界面是什么关系？

MCP 规定 AI 应用怎样发现和调用外部服务器提供的工具、资源和提示；模型只提出调用，宿主应用负责选择能力、授权、确认和展示结果。按 2026-07-28 版规范说明无状态请求、server/discover 和授权变化。

参考答案

简答

  • MCP 是宿主应用与外部能力之间的协议：Server 暴露工具、资源和提示，Host 里的 Client 发现并调用它们。
  • 模型的工具调用只是建议。Host 决定哪些工具进入上下文，并在执行前做授权和用户确认。
  • 2026-07-28 版去掉了 initialize 握手和 Mcp-Session-Id，每个请求在 _meta 里带协议版本和客户端能力，Server 必须实现 server/discover。
  • 同一版本删除了 Streamable HTTP 的 Last-Event-ID 续传：响应流断开后，客户端要用新的请求 ID 重新发起请求。
  • 远程 Server 走 OAuth 授权，客户端注册改推 Client ID Metadata Documents，动态客户端注册（DCR）已标为弃用。

三个角色

  • Host：用户直接使用的 AI 应用，例如 IDE、桌面助手或网页聊天后端。它管理模型、界面和多个 Client。
  • Client：Host 内部与某个 Server 通信的连接对象。
  • Server：提供能力的一方，可以是本机进程（stdio），也可以是远程服务（Streamable HTTP）。

一次调用的链路：

text
用户任务 → Host 选出允许的工具 → 模型提出 tools/call 参数
        → Host 校验参数、确认权限、必要时请用户批准
        → Client 发送请求 → Server 执行 → Host 检查结果并更新界面

工具、资源和提示是三种不同能力。工具执行操作；资源提供上下文数据；提示是可复用的输入模板。资源和工具结果里的文字都是数据，可能含有提示词注入，Host 按不可信内容处理。

2026-07-28 版的主要变化

方面2025 年各版本2026-07-28 版
连接建立initialize 握手协商版本与能力无握手；每个请求的 _meta 携带 io.modelcontextprotocol/protocolVersion 和 clientCapabilities
能力发现握手返回Server 必须实现 server/discover，Client 可先调用它选版本
会话Mcp-Session-Id 头移除；跨调用状态由 Server 生成的句柄作为普通参数传递
服务端通知GET 长连接、resources/subscribe统一用 subscriptions/listen
断线续传Last-Event-ID 重放移除；流断开即丢失该请求，客户端用新请求 ID 重试
Server 向客户端索取输入Server 发起 sampling/createMessage、elicitation/create 等请求多轮请求模式：结果返回 resultType: "input_required"，客户端补充 inputResponses 后重试原请求

这一版还移除了 ping、logging/setLevel，日志级别改为每个请求在 _meta 里用 io.modelcontextprotocol/logLevel 指定；所有结果新增必填字段 resultType（"complete" 或 "input_required"）。Sampling、Roots 和 Logging 功能被标为弃用，旧的 HTTP+SSE 传输也处于弃用状态。新实现应直接接入 Streamable HTTP。

授权与浏览器边界

远程 Server 的授权基于 OAuth。2026-07-28 版要求客户端校验授权响应里的 iss，按签发方保存凭据、换授权服务器时重新注册；客户端注册推荐 Client ID Metadata Documents，DCR 只为兼容保留。

浏览器页面不能启动本地进程，长期令牌也不适合放在前端。常见做法是由后端或桌面宿主充当 Host，网页只负责展示调用状态和收集用户确认。

界面要展示的状态

  • 连接或发现失败、协议版本不匹配（UnsupportedProtocolVersionError）要和工具执行失败分开显示。
  • 工具调用分为待确认、执行中、成功、失败、结果未知。响应流中断时 Server 可能已经执行完毕，有副作用的工具要靠业务幂等键避免重复执行。
  • input_required 表示 Server 需要用户补充信息，界面要能收集输入并重试原请求。

常见追问

  • 接入 MCP 后模型就能访问用户的全部数据吗？ 不能。模型只看到 Host 放进上下文的工具描述和结果，执行仍受 Host 和 Server 两侧权限限制。
  • 工具注解里写了"只读"，可以免确认吗？ 注解来自 Server，只能辅助展示。是否需要确认由 Host 根据自身策略决定。
