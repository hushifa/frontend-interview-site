安全整数是什么？什么时候要用 BigInt？

Number 只能精确表示 ±(2^53 - 1) 以内的整数，超出后相邻整数可能变成同一个值，可用 Number.isSafeInteger 检查。BigInt 能精确表示任意大的整数，但不能和 Number 混算、除法向零截断、JSON.stringify 不支持，大整数 ID 应该用字符串传。

参考答案

简答

后端返回一个 19 位的订单 ID，前端拿到后末几位变了，这就是撞上了安全整数的上限。

JavaScript 的 Number 是 64 位双精度浮点数，用来存有效数字的只有 53 位。所以能精确表示的整数范围是正负 2^53 - 1，也就是 Number.MAX_SAFE_INTEGER（9007199254740991）。超过以后，相邻的两个整数可能变成同一个值。可以用 Number.isSafeInteger 检查一个数是否在范围内。

需要更大的整数时用 BigInt，写成 123n 或 BigInt('123')，它能精确表示任意大的整数。但它不能和 Number 混在一起算，会抛 TypeError；除法会把小数部分直接去掉；JSON.stringify 遇到它也会报错。

所以接口里超出安全范围的 ID 应该用字符串传。小数为什么算不准是另一个问题，见《0.1 + 0.2 为什么不等于 0.3？怎么解决？》。

超出安全范围会发生什么

JavaScript
console.log(Number.isSafeInteger(2 ** 53)); // false
console.log(9007199254740991n + 2n); // 9007199254740993n
console.log(5n / 2n); // 2n

第一行说明 2 ** 53 已经不是安全整数了。超过这个值以后，浮点数没有足够的位来区分相邻的整数，2 ** 53 === 2 ** 53 + 1 会得到 true。

第二行用 BigInt 从最大安全整数再加 2，精确得到 9007199254740993n。同样的运算换成 Number，结果会落到相邻的可表示值上，算不准。

第三行是 BigInt 的除法，结果向零截断，5n / 2n 是 2n，不会得到 2.5。

BigInt 和 Number 不能混算，是为了避免偷偷丢精度，必须由你明确转换。Math 上的方法也不接受 BigInt。

转换时也要小心。BigInt('9007199254740993') 从字符串解析，能拿到精确值；BigInt(9007199254740993) 先写成了 Number 字面量，精度在进入 BigInt 之前就丢了；BigInt(1.5) 不是整数，会抛 RangeError；Number(big) 把 BigInt 转回数字，可能会丢精度。

接口返回的大整数 ID 为什么变了

JavaScript
JSON.parse('{"id":9007199254740993}').id; // 9007199254740992

后端返回的 ID 是 9007199254740993，解析出来却是 9007199254740992。因为 JSON.parse 会把数字直接转成 Number，超出安全范围的那一刻精度就丢了，之后再怎么处理都找不回来。

解决办法是让后端把 ID 用字符串返回，前端只把它当字符串比较和传递，需要运算时再 BigInt(id)。另外 ES2026 给 JSON.parse 加了读取原始文本的能力，reviver 函数的第三个参数 context.source 能拿到数字的原始文本，用之前要确认目标运行环境支持。

反过来，要把 BigInt 发给后端，JSON.stringify 会抛错。可以在 replacer 里把 BigInt 转成字符串，或者给 BigInt.prototype 定义 toJSON，前者影响范围更小。

常见追问

Number.MAX_SAFE_INTEGER 和 Number.MAX_VALUE 有什么区别？

MAX_SAFE_INTEGER 是能精确表示每一个整数的上限，约 9 × 10^15。MAX_VALUE 是 Number 能表示的最大值，约 1.8 × 10^308，但在那么大的范围里，相邻可表示数之间隔得很远，大部分整数都存不准。

BigInt 能用来算金额吗？

可以把金额换成“分”这样的最小单位整数后用 BigInt 算，适合超出安全范围的大金额。但它只表示整数，除不尽的部分会被截掉，舍入和分摊规则要自己定。
