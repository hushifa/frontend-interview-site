浮点精度、安全整数和 BigInt 有哪些边界？

JavaScript 的数字是二进制浮点数，0.1 + 0.2 不等于 0.3，超过 2^53 - 1 的整数也存不准。BigInt 能精确表示任意大的整数，但不能和普通数字混着算。金额一般换成"分"这样的整数来算。

参考答案

简答

JavaScript 的 Number 是 64 位双精度浮点数，用二进制存小数。0.1、0.2 这样的十进制小数，在二进制里是无限循环的，只能存个近似值，所以 0.1 + 0.2 !== 0.3。

整数也有上限。能精确表示的范围是正负 2^53 - 1，也就是 Number.MAX_SAFE_INTEGER，超过以后，相邻的两个整数可能变成同一个值。可以用 Number.isSafeInteger 检查。

需要更大的整数时用 BigInt，写成 123n，它能精确表示任意大的整数。但它不能和 Number 混在一起算，会抛 TypeError；除法会把小数部分直接去掉；JSON.stringify 遇到它也会报错，所以后端返回的大整数 ID 应该用字符串传。

金额计算最好用“分”这类最小单位的整数来算，或者用十进制库，显示的时候再格式化。

为什么 0.1 + 0.2 不等于 0.3

JavaScript
console.log(0.1 + 0.2 === 0.3); // false
console.log(9007199254740991n + 2n); // 9007199254740993n
console.log(5n / 2n); // 2n

第一行是 false，因为 0.1 和 0.2 存进去时都有一点点误差，加起来误差也加上了。打印出来就能看到：

JavaScript
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(2 ** 53 === 2 ** 53 + 1); // true
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON); // true

第二行说明整数也会出问题。2 ** 53 和 2 ** 53 + 1 居然相等，因为超过安全范围以后，浮点数已经没有足够的位来区分相邻的整数了。上面例子里的 BigInt 9007199254740991n + 2n 就能精确得到 9007199254740993n，换成 Number 就算不准了。

比较小数时，常见做法是看差值是否足够小，比如第三行用 Number.EPSILON。它是 1 和比 1 大的下一个可表示数之间的差，只适合比较大小在 1 附近的数。数值比较大时，误差也跟着变大，要用相对误差：Math.abs(a - b) <= Number.EPSILON * Math.max(Math.abs(a), Math.abs(b))。

toFixed 为什么没有四舍五入

JavaScript
console.log((1.005).toFixed(2)); // 1.00

按四舍五入应该是 1.01，结果却是 1.00。因为 1.005 实际存储的值比 1.005 略小一点，toFixed 按存储的真实值来舍入，自然得到 1.00。所以不要把 toFixed 当四舍五入工具。界面显示用 Intl.NumberFormat，计算时换成整数单位。

BigInt 有哪些规则

操作结果
1n + 1TypeError
5n / 2n2n，向零截断
1n == 1 / 1n === 1true / false
typeof 1n'bigint'
Math.max(1n)TypeError
JSON.stringify({ a: 1n })TypeError

BigInt 和 Number 不能混算，是为了避免偷偷丢精度，必须由你明确转换。除法“向零截断”就是直接去掉小数部分，5n / 2n 是 2n。Math 上的方法也不接受 BigInt。

转换时也要小心。BigInt('9007199254740993') 从字符串解析，能拿到精确值；BigInt(1.5) 不是整数，会抛 RangeError；Number(big) 把 BigInt 转回数字，可能会丢精度。

接口返回的大整数 ID 为什么变了

JavaScript
JSON.parse('{"id":9007199254740993}').id; // 9007199254740992

后端返回的 ID 是 9007199254740993，解析出来却是 9007199254740992。因为 JSON.parse 会把数字直接转成 Number，超出安全范围的那一刻精度就丢了，之后再怎么处理都找不回来。

解决办法是让后端把 ID 用字符串返回。另外 ES2026 给 JSON.parse 加了读取原始文本的能力，reviver 函数的第三个参数 context.source 能拿到数字的原始文本，用之前要确认目标运行环境支持。

金额怎样算才准

JavaScript
const cents = [1999, 1].reduce((sum, value) => sum + value, 0); // 2000
const text = new Intl.NumberFormat('zh-CN', {
  style: 'currency',
  currency: 'CNY',
}).format(cents / 100); // ¥20.00

19.99 元加 0.01 元，存成 1999 分和 1 分，整数相加不会有误差。只在最后显示时除以 100，交给 Intl.NumberFormat 格式化。

如果涉及汇率、税率这类小数乘除，要先定好舍入规则，再用 decimal.js 这样的十进制库，或者用 BigInt 按最小单位计算，自己处理除不尽的余数怎么分摊。

常见追问

为什么 0.5 + 0.25 是精确的？

因为 0.5 是 2 的负一次方，0.25 是 2 的负二次方，二进制能精确表示，存进去没有误差。

-0 有什么用？

-0 === 0 是 true，但 Object.is(-0, 0) 是 false，1 / -0 是 -Infinity。它保留了方向信息，比如一个数从负方向趋近 0。
