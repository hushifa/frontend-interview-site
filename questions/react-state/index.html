为什么调用 setState 后，当前变量还是旧值？

每次渲染拿到的 state 是一份快照，调用 setter 只是预约下一次渲染，当前这次的变量不会变。直接传值和传函数在排队时含义不同，同一个事件里的多次更新会被合并成一次渲染。

参考答案

简答

组件每次渲染，useState 返回的都是这一次的状态值。事件处理器里读到的 count，就是这次渲染的那个值，可以把它理解成一张快照。

调用 setCount 并不会改这个变量，它只是把一个更新排进队列，请求 React 再渲染一次。新的值要到下一次渲染才拿得到，所以当前函数里的 count 还是旧的。

这也解释了为什么 setCount(count + 1) 连写三次只加 1：三次用的都是同一张快照。要基于前一个值累加，就传函数 setCount(c => c + 1)，React 会把上一步的结果传给下一步。

另外，React 18 起所有更新默认自动批处理，同一个事件里的多次 setter 只触发一次渲染，包括 Promise、setTimeout 和原生事件回调里的更新。

先看三个按钮

下面三个按钮分别演示直接传值、传函数和两者混用：

JSX
import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  function replaceThreeTimes() {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    console.log(count); // 仍是本次渲染的值，例如 0
  }

  function incrementThreeTimes() {
    setCount((c) => c + 1);
    setCount((c) => c + 1);
    setCount((c) => c + 1);
  }

  function replaceThenIncrement() {
    setCount(count + 5);
    setCount((c) => c + 1);
  }

  return (
    <>
      <output>{count}</output>
      <button onClick={replaceThreeTimes}>+1（三次替换）</button>
      <button onClick={incrementThreeTimes}>+3（三次函数更新）</button>
      <button onClick={replaceThenIncrement}>+6</button>
    </>
  );
}

从 0 开始点第一个按钮，结果是 1，而且 console.log 打印的还是 0。因为这次渲染里 count 就是 0，三次都算出 0 + 1，队列里是三次“替换成 1”。

点第二个按钮结果是 3。传进去的是函数，React 处理队列时把上一步的结果交给下一步：0 变 1，1 变 2，2 变 3。

点第三个按钮结果是 6。先“替换成 5”，再对 5 执行“加 1”。

用纯 JavaScript 模拟这个队列

React 处理队列的方式，可以用几行代码模拟出来，用 node 运行就能看到同样的结果：

JavaScript
function processQueue(base, queue) {
  return queue.reduce(
    (state, update) => (typeof update === 'function' ? update(state) : update),
    base,
  );
}

const count = 0; // 这次渲染的快照
console.log(processQueue(count, [count + 1, count + 1, count + 1])); // 1
console.log(processQueue(count, [(c) => c + 1, (c) => c + 1, (c) => c + 1])); // 3
console.log(processQueue(count, [count + 5, (c) => c + 1])); // 6

直接传值时，值在放进队列之前就已经算好了，用的都是快照里的 0。传函数时，函数要等 React 处理队列时才执行，拿到的是上一步的结果。区别就在于“什么时候算”。

批处理是什么

批处理就是 React 把同一个事件里的多次 setter 攒在一起，最后只渲染一次。上面每个按钮都调了好几次 setter，但每次点击只渲染一次。

React 18 之前，只有 React 事件处理器里会这样做。React 18 用 createRoot 以后，setTimeout、Promise 回调和原生事件里的更新也会自动批处理。

因为 setter 只是排队，它也不返回 Promise，await setCount(x) 等不到新状态。想在更新后读 DOM，把逻辑放进 Effect。极少数必须马上刷新的场景可以用 flushSync，但当前函数里的局部变量依然是旧快照。

更新函数要保持纯

c => c + 1 只应该根据参数算出下一个状态。开发环境的严格模式会把更新函数调用两次，来暴露里面的副作用。所以不要在里面发请求、改外部变量，或者写日志当作业务依据。

常见追问

想马上用到更新后的值怎么办？

自己先算出来再用：const next = count + 1; setCount(next); send(next);。不要指望 setter 之后读 count。

对象类型的 state 怎么更新？

要创建新对象，比如 setForm({ ...form, name })。如果原地改了对象再把同一个引用传给 setter，React 认为没变，不会重新渲染。
