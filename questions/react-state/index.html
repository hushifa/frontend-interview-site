为什么调用 setState 后，当前变量还是旧值？

每次渲染拿到的 state 是一份快照，setter 只是请求下一次渲染。替换更新和函数式更新在队列里的含义不同，自动批处理会合并同一事件里的多次更新。

参考答案

简答

  • 组件每次渲染时，useState 返回这一轮的状态值，事件处理器捕获的也是这一份快照。
  • 调用 setter 是把更新排进队列、请求重新渲染，当前函数里的 count 变量不会变。
  • setCount(count + 1) 连写三次只加 1；要基于前值累加，用 setCount(c => c + 1)。
  • React 18 起所有更新默认自动批处理，包括 Promise、setTimeout 和原生事件回调里的更新。

快照与队列

JSX
import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  function replaceThreeTimes() {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    console.log(count); // 仍是本次渲染的值，例如 0
  }

  function incrementThreeTimes() {
    setCount((c) => c + 1);
    setCount((c) => c + 1);
    setCount((c) => c + 1);
  }

  function replaceThenIncrement() {
    setCount(count + 5);
    setCount((c) => c + 1);
  }

  return (
    <>
      <output>{count}</output>
      <button onClick={replaceThreeTimes}>+1（三次替换）</button>
      <button onClick={incrementThreeTimes}>+3（三次函数更新）</button>
      <button onClick={replaceThenIncrement}>+6</button>
    </>
  );
}

从 0 开始：

  • replaceThreeTimes 三次都用快照 0 算出 1，队列里是"替换为 1"三次，结果为 1。
  • incrementThreeTimes 排入三个函数，React 依次把上一步结果传给下一步：0→1→2→3。
  • replaceThenIncrement 先替换为 5，再对 5 加 1，结果为 6。

批处理

批处理把同一个事件里的多次 setter 合并成一次渲染。React 18 之前只有 React 事件处理器里会批处理，React 18 的 createRoot 下，setTimeout、Promise 回调和原生事件里的更新也会自动批处理。

setter 不返回 Promise，await setCount(x) 等不到新状态。需要在更新后读 DOM，应把逻辑放进 Effect；极少数必须同步刷新的场景可以用 flushSync，但当前处理器里的局部变量仍是旧快照。

更新函数要纯

c => c + 1 只能根据参数计算下一状态。开发环境的严格模式会调用两次更新函数来暴露副作用，所以不要在里面发请求、修改外部变量或写日志当作业务依据。

常见追问

  • 想拿到更新后的值？直接用计算出的新值：const next = count + 1; setCount(next); send(next);。
  • 对象状态怎么更新？创建新对象：setForm({ ...form, name })，原地修改后再 set 同一个引用不会触发渲染。
