Canvas 的 transform 怎样影响坐标和绘制？

当前变换矩阵决定之后画的坐标怎样落到位图上，translate、scale、rotate 的调用顺序会改变结果。用 save/restore 限制局部状态，用 setTransform 处理高 DPI，用完整矩阵的逆变换把指针坐标换回绘图空间。

参考答案

简答

Canvas 有一个“当前变换矩阵”，你调 translate、scale、rotate，改的都是它。之后画的每个点都会先经过这个矩阵，再落到位图上。可是它只影响之后的绘制，已经画好的像素不会动，所以做动画要清空后按新状态重画。

矩阵 (a, b, c, d, e, f) 把点 (x, y) 变成 (a·x + c·y + e, b·x + d·y + f)。新变换是乘在当前矩阵右边的，所以调用顺序会影响结果：先 translate(100, 0) 再 scale(2, 2)，点 (10, 5) 变成 (120, 10)；反过来就是 (220, 10)。

三个方法要分清：transform() 在当前矩阵上叠加，setTransform() 直接替换，resetTransform() 恢复成单位矩阵。每帧都调 scale() 却不重置，缩放就会越叠越大。

还要注意，改 canvas.width 或 height 会清空画布并重置所有状态，之后要重新设变换。

调用顺序为什么会影响结果

下面先平移再缩放，然后看点 (10, 5) 最后落在哪：

JavaScript
const ctx = document.createElement('canvas').getContext('2d');
ctx.translate(100, 0);
ctx.scale(2, 2);
const p = new DOMPoint(10, 5).matrixTransform(ctx.getTransform());
console.log(p.x, p.y); // 120 10

代码里先写的是 translate，可是点实际上先被缩放成 (20, 10)，再平移 100，变成 (120, 10)。原因就是新变换乘在右边，离点最近，最先作用到点上。

可以换个角度理解：每次变换都是在移动“坐标系”。先把坐标系右移 100，再在新坐标系里放大 2 倍，所以画在 (10, 5) 的点会落到 (120, 10)。

怎样绕图形中心旋转

rotate() 用的是弧度，而且总是绕当前原点转。如果直接转，图形会绕画布左上角甩出去。所以要先把原点挪到图形中心，再按以中心为原点的坐标来画：

JavaScript
ctx.save();
ctx.translate(cx, cy);
ctx.rotate(Math.PI / 4);
ctx.fillRect(-20, -10, 40, 20); // 以中心为原点
ctx.restore();

save 和 restore 保存的是什么

save() 把当前的状态压进一个栈里，包括矩阵、填充和描边样式、线宽、裁剪区域等；restore() 把它弹出来。上面的例子用它把旋转限制在这一个图形上，画完就恢复。

但它不是撤销像素，画上去的东西不会消失。它也不会清空当前路径，所以画新图形还是要先 beginPath()。

高清屏怎样设置

CSS 尺寸是 300×150、设备像素比为 2 时，把位图设成 600×300，再调 ctx.setTransform(2, 0, 0, 2, 0, 0)。这样绘图代码可以继续按 CSS 像素写坐标。场景的平移和缩放，再叠加在这个矩阵之上。

怎样把指针坐标换回绘图空间

点击时拿到的是屏幕上的坐标，要知道点在了场景里的哪里，就得把变换倒推回去，也就是乘逆矩阵：

JavaScript
// worldToBitmap：绘制场景时使用的完整矩阵，已包含 DPR
function clientToWorld(canvas, clientX, clientY, worldToBitmap) {
  const rect = canvas.getBoundingClientRect();
  if (rect.width === 0 || rect.height === 0) return null;
  const x = ((clientX - rect.left) * canvas.width) / rect.width;
  const y = ((clientY - rect.top) * canvas.height) / rect.height;
  const p = new DOMPoint(x, y).matrixTransform(worldToBitmap.inverse());
  return Number.isFinite(p.x) && Number.isFinite(p.y) ? { x: p.x, y: p.y } : null;
}

先把 client 坐标按比例换算成位图坐标，再乘逆矩阵。DPR 已经包含在矩阵里了，不要再除一次，否则会偏。

矩阵要用绘制时实际用的那个，保存下来传进来。不要在 restore() 之后随手读 getTransform()，那时读到的已经不是画图时的矩阵了。

缩放为 0 时，矩阵没有逆，算出来是非有限数，所以函数返回 null。另外，canvas 有边框、内边距或者 CSS 旋转时，这个换算就不成立了，要额外处理。

清空画布为什么没清干净

clearRect() 也受当前变换影响。比如矩阵放大了 2 倍，clearRect(0, 0, canvas.width, canvas.height) 清的区域就跑到了画布外面。所以清空整个位图时，要先重置矩阵：

JavaScript
ctx.save();
ctx.resetTransform();
ctx.clearRect(0, 0, canvas.width, canvas.height);
ctx.restore();

还有一点：裁剪区域仍然会限制清除的范围，重置矩阵并不会取消 clip()。

常见追问

为什么点击位置总是偏移一倍？

通常是 DPR 被处理了两次，比如矩阵里已经乘过了，换算时又除一次；或者把 CSS 尺寸当成了位图尺寸。
