如何减少 Playwright 端到端测试的不稳定？

用 getByRole 等面向用户的定位器和自动重试的 web-first 断言代替固定等待；每个测试使用独立的浏览器上下文和独立的后端数据；在触发操作前注册事件等待；失败时用 trace 定位原因，而不是靠重试掩盖。

参考答案

简答

  • 操作前 Playwright 会自动等待元素可见、稳定、可接收事件；expect(locator).toBeVisible() 这类断言会重试直到超时。不要写 waitForTimeout(1000)。
  • 定位器优先 getByRole、getByLabel、getByText，少用依赖 DOM 结构的 CSS 和 XPath。
  • 每个测试有独立的浏览器上下文（Cookie、存储互不影响），但后端数据要自己隔离，例如每个测试创建自己的用户或订单。
  • 等待弹窗、下载、请求时，先创建等待的 Promise，再执行点击，否则事件可能在开始监听前就发生了。
  • 开启 trace: 'on-first-retry'，失败时查看每一步的截图、DOM 和网络；retries 只能暴露不稳定，不能修复它。

断言要会重试

TypeScript
// 不稳定：只读取一次
expect(await page.getByRole('status').textContent()).toBe('已保存');

// 稳定：自动重试直到满足或超时
await expect(page.getByRole('status')).toHaveText('已保存');

事件等待的顺序

TypeScript
const downloadPromise = page.waitForEvent('download');
await page.getByRole('button', { name: '导出' }).click();
const download = await downloadPromise;
expect(download.suggestedFilename()).toBe('orders.csv');

数据隔离

TypeScript
test('删除订单', async ({ page, request }) => {
  const created = await request.post('/api/test/orders', {
    data: { title: `测试订单-${test.info().testId}` },
  });
  const { id } = await created.json();

  await page.goto(`/orders/${id}`);
  await page.getByRole('button', { name: '删除' }).click();
  await expect(page.getByText('订单已删除')).toBeVisible();
});

测试通过 API 准备数据比通过界面点击更快，也不会受其他界面的问题影响。并行运行时，不同测试不要共用同一条数据。

登录状态复用

在 setup 项目里登录一次，用 storageState 保存 Cookie 和本地存储，其他测试直接加载。会修改账号设置的测试应使用单独的账号，见《Playwright fixtures 解决了什么测试维护问题？》。

常见不稳定原因

现象原因处理
偶尔点不到按钮动画或遮罩还在等遮罩消失的断言，或在测试环境关闭动画
列表数量不对数据来自其他并行测试每个测试用自己的数据
本地通过，CI 失败时区、语言、视口不同在配置中固定 timezoneId、locale、viewport
依赖第三方服务外部不稳定用 page.route 模拟第三方

常见追问

  • 不稳定的测试怎么处理？先用 --repeat-each 在本地复现，再查 trace。确实暂时无法修复时，用 test.fixme 标记并记录原因，而不是一直靠重试通过。
