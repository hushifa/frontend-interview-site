浏览器直传对象存储时，如何设计安全的分片上传？

业务服务器负责鉴权、创建上传会话、为每个分片签发短期预签名 URL 并在最后合并；浏览器直接把分片 PUT 到对象存储。安全边界在签名范围、过期时间、对象键由服务端决定，以及合并前的校验和未完成上传的清理。

参考答案

简答

  • 文件不经过业务服务器，节省带宽；但签名和凭据只在服务端生成，浏览器拿不到长期密钥。
  • 流程：创建上传会话 → 每个分片申请预签名 URL → 浏览器 PUT 分片并记录返回的 ETag → 服务端按分片编号和 ETag 合并。
  • 对象键、大小上限、内容类型由服务端决定并写进签名，浏览器不能自己指定路径。
  • 存储桶要配置 CORS，允许页面来源的 PUT，并用 ExposeHeaders 暴露 ETag，否则脚本读不到它。
  • 未完成的上传会一直占用存储，要设置生命周期规则自动清理。

下文以 S3 的接口为例，其他云厂商的分片大小、编号规则和接口名称不同。

浏览器上传一个分片

JavaScript
async function uploadPart(file, partNumber, partSize, url, signal) {
  const start = (partNumber - 1) * partSize; // S3 分片编号从 1 开始
  const body = file.slice(start, start + partSize);

  const response = await fetch(url, { method: 'PUT', body, signal });
  if (!response.ok) throw new Error(`分片 ${partNumber} 失败：${response.status}`);

  const etag = response.headers.get('ETag');
  if (!etag) throw new Error('读不到 ETag，检查存储桶 CORS 的 ExposeHeaders');
  return { partNumber, etag };
}

同一编号的分片重新上传会覆盖之前的内容，所以分片 PUT 可以安全重试。并发数按网络情况取一个小值并可调，不要一次发出全部分片。

安全要点

  • 预签名 URL 有效期尽量短，只授权单个对象的单个分片。
  • 合并时服务端校验分片总数、总大小和调用者身份，不信任浏览器传来的文件大小。
  • 需要内容完整性时，让分片请求携带校验和（S3 支持 CRC64NVME、SHA-256 等算法），存储端校验不一致会拒绝。
  • 合并完成后再做类型检测和病毒扫描，通过后才对外可见。
  • 文件上传的通用安全边界见《前端文件上传有哪些安全边界？》。

常见追问

  • 怎么支持断点续传？服务端保存 uploadId 和已完成的分片，见《浏览器分片上传如何实现可靠的暂停与续传？》。
  • 分片编号有什么限制？S3 的编号范围是 1 到 10000，可以不连续；启用校验和时必须从 1 开始连续编号。分片大小下限等限制见 S3 的 multipart upload limits 页面，其他厂商规则不同。
