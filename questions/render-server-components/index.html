React Server Components 和 SSR 是同一件事吗？

不是。SSR 把组件树渲染成 HTML，客户端组件也参与 SSR，之后还要 hydration。Server Components 只在服务端或构建时运行，可以直接访问数据库，代码不会发到浏览器，输出的是序列化的组件结果。两者可以配合使用。

参考答案

简答

不是一回事，它们解决的问题不同。SSR 解决的是“首屏 HTML 怎样在服务端生成”：组件在服务端执行一次，生成 HTML；浏览器再下载同一份组件代码，做 hydration 接上事件。

Server Components 解决的是“哪些组件只在服务端跑”。它们可以写成 async 函数，直接查数据库，代码和依赖都不会进客户端的包，也不需要 hydration。

两种组件靠 'use client' 分开。写了它的文件，连同它导入的模块，都会进客户端包，可以用 state、Effect 和浏览器 API。Server Component 可以渲染 Client Component，但传过去的 props 必须能序列化。反过来，Client Component 不能导入 Server Component，但可以通过 children 接收一个已经渲染好的 Server Component。

容易混的一点是 'use server'。它标记的是 Server Function，也就是客户端可以调用的服务端函数，不是 Server Component。Server Component 不需要任何指令。

先看一个文章页

文章页本身是 Server Component，收藏按钮需要点击状态，是 Client Component。

JSX
// app/article/[id]/page.jsx —— Server Component
import { db } from '@/lib/db';
import { marked } from 'marked'; // 只在服务端使用，不进入客户端包
import BookmarkButton from './BookmarkButton';

export default async function ArticlePage({ params }) {
  const { id } = await params;
  const article = await db.article.findUnique({ where: { id } });
  return (
    <article>
      <h1>{article.title}</h1>
      <div dangerouslySetInnerHTML={{ __html: marked(article.body) }} />
      <BookmarkButton articleId={article.id} />
    </article>
  );
}
JSX
// BookmarkButton.jsx —— Client Component
'use client';

import { useState } from 'react';

export default function BookmarkButton({ articleId }) {
  const [saved, setSaved] = useState(false);
  return <button onClick={() => setSaved(!saved)}>{saved ? '已收藏' : '收藏'}</button>;
}

浏览器最后只下载 BookmarkButton 的代码。marked 这个 Markdown 库和数据库客户端都留在服务端，因为用到它们的组件从来不在浏览器里运行。如果只用 SSR，这些依赖也要打包给浏览器，因为 hydration 时组件要在客户端再跑一遍。

示例里的正文如果来自用户输入，渲染成 HTML 之前必须先做清洗。

一次请求里发生了什么

两者配合时，大致是这样的顺序：

  1. 服务端运行 Server Components，生成 RSC payload。这是一种描述组件树的序列化格式，其中 Client Component 的位置只放一个引用和它的 props。
  2. 框架再用 SSR 把这棵树，包括 Client Components，渲染成 HTML，和 RSC payload 一起发出去。
  3. 浏览器先显示 HTML，然后下载 Client Component 的代码并 hydration。
  4. 之后在客户端导航，只请求新页面的 RSC payload，不用整页 HTML。

所以 SSR 负责的是“先给一份 HTML”，Server Components 负责的是“哪些组件只在服务端跑”，两者是叠在一起用的。

Client Component 怎样包住服务端内容

Client Component 不能导入 Server Component，可是像标签页这种外壳需要交互、里面内容来自服务端的场景很常见。办法是用 children：

JSX
// Client Component 通过 children 接收服务端内容
'use client';
export function Tabs({ children }) {
  const [tab, setTab] = useState(0);
  return <div>{/* 切换逻辑 */}{children}</div>;
}
JSX
// Server Component 中
<Tabs>
  <ServerRenderedList />
</Tabs>

ServerRenderedList 在服务端就渲染好了，作为 props 传给 Tabs。Tabs 只管把它放到某个位置，不需要知道它是怎么实现的，所以也不用导入它。

有哪些要注意

传给 Client Component 的 props 会发到浏览器。所以不要把整条数据库记录直接传过去，只传需要的字段。

只能在服务端用的模块，可以导入 server-only 包。万一被客户端代码误导入，构建时就会报错，而不是悄悄把它打包出去。

Server Components 需要框架支持打包和路由，比如 Next.js App Router。单独用 React 没办法直接启用。

常见追问

Server Components 能用 Hook 吗？

不能用 useState、useEffect 这类有状态或者有副作用的 Hook，因为它不在浏览器里运行，也不会重新渲染。

和 Server Functions 有什么区别？

Server Function 是客户端可以调用的服务端函数，用 'use server' 标记，详见《React Server Functions/Actions 的边界是什么？》。
