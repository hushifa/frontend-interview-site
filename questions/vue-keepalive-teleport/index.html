KeepAlive 与 Teleport 有哪些使用边界？

KeepAlive 让切走的组件不销毁、切回来状态还在；Teleport 把一段模板渲染到页面别处，比如 body 下面，但组件关系不变。前者管状态保留，后者管 DOM 位置，定时器暂停和弹窗交互都得自己处理。

参考答案

简答

这两个内置组件解决的是不同问题。<KeepAlive> 包住动态组件或路由视图后，被切走的组件不会卸载，而是放进缓存，切回来时输入的内容、滚动位置都还在。<Teleport to="body"> 则是把一段内容渲染到指定的 DOM 节点下，常用于弹窗，避免被父元素的 overflow: hidden 或层叠上下文挡住。

KeepAlive 切走时触发 onDeactivated，切回时触发 onActivated。用 include、exclude 按组件 name 决定缓存谁，用 max 限制数量，超了就淘汰最久没访问的那个。

它的边界在于，被缓存的组件还活着。定时器、轮询、WebSocket 不会自己停，要在 onDeactivated 里暂停、onActivated 里恢复。

Teleport 只搬 DOM，props、事件、provide/inject 仍然按原来的组件树传。目标节点必须在挂载时已经存在，Vue 3.5 起可以加 defer，等同一轮渲染里的目标出来再挂。

KeepAlive 怎么用

下面用按钮在列表页和详情页之间切换，外面包一层 KeepAlive，最多缓存 5 个：

vue
<script setup>
import { shallowRef } from 'vue';
import ListPage from './ListPage.vue';
import DetailPage from './DetailPage.vue';

const current = shallowRef(ListPage);
</script>

<template>
  <button @click="current = ListPage">列表</button>
  <button @click="current = DetailPage">详情</button>
  <KeepAlive :max="5">
    <component :is="current" />
  </KeepAlive>
</template>

从列表切到详情再切回来，列表页不会重新创建，状态都在。可是列表页如果开着一个每 10 秒刷新的轮询，切走以后它还会继续跑，白白发请求。所以要用那一对钩子控制它：

vue
<!-- ListPage.vue -->
<script setup>
import { onActivated, onDeactivated } from 'vue';

let timer;
function startPolling() {
  timer = setInterval(refresh, 10_000);
}

onActivated(startPolling); // 首次挂载时也会调用
onDeactivated(() => clearInterval(timer));
</script>

为什么轮询只写在这对钩子里就够了，不用再写 onMounted？因为 onActivated 在首次挂载和每次从缓存恢复时都会调用，onDeactivated 在进入缓存和最终卸载时都会调用，开和关正好一一对应。

在 Vue Router 里的写法是这样：

vue
<RouterView v-slot="{ Component }">
  <KeepAlive include="ListPage">
    <component :is="Component" />
  </KeepAlive>
</RouterView>

include 匹配的是组件的 name。用 <script setup> 写的组件，会根据文件名自动推断 name，所以 ListPage.vue 就能被 include="ListPage" 匹配到。

Teleport 怎么用

vue
<script setup>
import { ref } from 'vue';
const open = ref(false);
</script>

<template>
  <button @click="open = true">打开</button>
  <Teleport to="body">
    <dialog v-if="open" open aria-labelledby="dlg-title" @close="open = false">
      <h2 id="dlg-title">确认删除？</h2>
      <button @click="open = false">取消</button>
    </dialog>
  </Teleport>
</template>

对话框的 DOM 出现在 body 下面，可是 open 仍然由这个组件控制，点“取消”照样能改它。这就是“只搬 DOM，不改组件关系”。

不过 Teleport 只解决位置问题。一个真正的模态对话框，还需要打开时把焦点移进去、按 Esc 关闭、关闭后焦点回到触发按钮。用原生 <dialog> 的 showModal() 能直接获得这些行为，Teleport 本身不提供。

还有两个细节。:disabled="true" 能让内容留在原位不搬走，比如移动端想内联显示时。服务端渲染时，Teleport 的内容会单独输出，所以目标容器要在服务端模板里就存在。

常见追问

KeepAlive 怎么手动清掉某个组件的缓存？

动态修改 include 列表，把这个组件的 name 移出去，它的缓存就会被清掉。

两个 Teleport 指向同一个目标会怎样？

按挂载顺序依次追加到目标节点里，后挂载的排在后面。
