组合式函数和 mixin 相比有什么维护优势？

组合式函数是普通函数，通过参数接收输入、通过返回值暴露状态，来源一目了然，可以自由组合和重命名。mixin 把属性和方法合并进组件，来源不清、容易命名冲突、相互之间存在隐式依赖。Vue 3 推荐用组合式函数复用逻辑。

参考答案

简答

  • 组合式函数（composable）是以 use 开头、内部使用 Vue 响应式 API 的函数，在 setup 中调用。
  • 返回值显式解构：const { x, y } = useMouse()，模板里的每个变量都能找到来源。
  • mixin 的三个问题：属性来源不清楚、多个 mixin 之间同名属性互相覆盖、mixin 之间通过 this 产生隐式依赖。
  • 每次调用组合式函数都会创建独立的状态；要在多个组件间共享，把状态定义在函数外部，或使用 Pinia。
  • 在组合式函数内部注册的生命周期钩子和侦听器，属于调用它的那个组件，组件卸载时自动清理。

示例

JavaScript
// useFetch.js
import { ref, toValue, watchEffect } from 'vue';

export function useFetch(url) {
  const data = ref(null);
  const error = ref(null);
  const loading = ref(false);

  watchEffect(async (onCleanup) => {
    const controller = new AbortController();
    onCleanup(() => controller.abort());
    loading.value = true;
    error.value = null;
    try {
      const res = await fetch(toValue(url), { signal: controller.signal });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      data.value = await res.json();
    } catch (err) {
      if (err.name !== 'AbortError') error.value = err;
    } finally {
      loading.value = false;
    }
  });

  return { data, error, loading };
}
vue
<script setup>
import { useFetch } from './useFetch';

const props = defineProps({ id: Number });
const { data: user, loading } = useFetch(() => `/api/users/${props.id}`);
</script>
  • toValue 接受普通值、ref 或 getter，传 getter 时 props.id 变化会重新请求。
  • 返回 ref 组成的普通对象，调用方解构后仍保持响应式，也可以重命名（data: user）。

和 mixin 对比

JavaScript
// mixin 写法
export default {
  mixins: [userMixin, permissionMixin],
  mounted() {
    console.log(this.user, this.can); // 来自哪个 mixin？会不会被覆盖？
  },
};

组合式函数中如果一个函数需要另一个的结果，通过参数传入：usePermission(user)，依赖关系写在代码里。

编写约定

  • 函数名以 use 开头。
  • 输入参数接受 ref 或 getter 时用 toValue 统一读取。
  • 只在 <script setup> 或 setup() 中同步调用，不要在异步回调里调用，否则生命周期钩子无法关联到组件。
  • SSR 中避免在模块顶层创建共享状态，否则会被多个请求共用，导致用户数据串到别人页面上。

常见追问

  • 和 React 自定义 Hook 的区别？Vue 的 setup 只执行一次，组合式函数也只调用一次，不受调用顺序限制，也没有依赖数组和过期闭包问题。
  • VueUse 是什么？一个常用组合式函数集合，例如 useStorage、useIntersectionObserver，可以直接使用或参考实现。
