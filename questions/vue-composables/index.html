组合式函数和 mixin 相比有什么维护优势？

组合式函数就是一个普通函数，参数传进去、状态通过返回值拿出来，变量从哪来一眼就能看到。mixin 把属性直接混进组件，来源不清还容易重名，Vue 3 推荐用组合式函数复用逻辑。

参考答案

简答

组合式函数，英文叫 composable，就是一个以 use 开头、里面用了 Vue 响应式 API 的普通函数，在 setup 里调用。比如 const { x, y } = useMouse()，鼠标位置的逻辑全封装在里面。

它比 mixin 好维护，是因为来源清楚。用了 mixin 以后，组件里的 this.user 可能来自任何一个 mixin，多个 mixin 有同名属性还会互相覆盖，mixin 之间还可能偷偷通过 this 依赖对方。组合式函数的返回值是显式解构出来的，模板里每个变量都能找到出处，重名了也能直接改名。

一个函数需要另一个函数的结果时，就当参数传进去，比如 usePermission(user)，依赖关系写在代码里。

要注意两点。每次调用都会创建一份独立的状态，想在组件间共享，就把状态定义在函数外面，或者用 Pinia。另外，组合式函数里注册的生命周期钩子和侦听器属于调用它的那个组件，组件卸载时会自动清理，所以一般要在 setup 里同步调用。

先看一个组合式函数

下面的 useFetch 负责请求数据，并把数据、错误、加载状态三个 ref 返回出去：

JavaScript
// useFetch.js
import { ref, toValue, watchEffect } from 'vue';

export function useFetch(url) {
  const data = ref(null);
  const error = ref(null);
  const loading = ref(false);

  watchEffect(async (onCleanup) => {
    const controller = new AbortController();
    onCleanup(() => controller.abort());
    loading.value = true;
    error.value = null;
    try {
      const res = await fetch(toValue(url), { signal: controller.signal });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      data.value = await res.json();
    } catch (err) {
      if (err.name !== 'AbortError') error.value = err;
    } finally {
      loading.value = false;
    }
  });

  return { data, error, loading };
}

组件里这样用：

vue
<script setup>
import { useFetch } from './useFetch';

const props = defineProps({ id: Number });
const { data: user, loading } = useFetch(() => `/api/users/${props.id}`);
</script>

这里传进去的是一个函数 () => ...，不是字符串。为什么？因为 useFetch 内部用 toValue(url) 读取地址，toValue 能接受普通值、ref 或者 getter 函数。传 getter 时，watchEffect 执行期间读到了 props.id，所以 id 一变就会重新请求。如果直接传字符串，就只是当时的一个值，之后不会再变。

返回的是由 ref 组成的普通对象，所以调用方解构以后仍然是响应式的，还能顺手改名，比如 data: user。

mixin 的问题出在哪

看一段 mixin 写法：

JavaScript
// mixin 写法
export default {
  mixins: [userMixin, permissionMixin],
  mounted() {
    console.log(this.user, this.can); // 来自哪个 mixin？会不会被覆盖？
  },
};

读这段代码的人没法直接知道 this.user 是谁提供的，得一个个打开 mixin 去找。如果两个 mixin 都定义了 user，后面的会覆盖前面的。更麻烦的是，permissionMixin 里可能直接读 this.user，它依赖 userMixin 却没写在任何地方，删掉一个另一个就坏了。

换成组合式函数，这种依赖就得明着写：const { user } = useUser(); const { can } = usePermission(user);。

写组合式函数要守哪些约定

函数名以 use 开头。参数可能是 ref 或 getter 时，用 toValue 统一读取。

一般要在 <script setup> 或 setup() 里同步调用，不要放进异步回调里。<script setup> 是唯一的例外：编译器会在顶层 await 之后恢复当前组件，所以 await 后面也能调用。因为生命周期钩子要关联到“当前正在初始化的组件”，异步回调执行时这个组件已经不是当前组件了，钩子就挂不上去。

做服务端渲染时，不要在模块顶层创建共享状态。服务器上这个模块只加载一次，顶层变量会被所有请求共用，用户的数据就可能串到别人的页面上。

常见追问

和 React 自定义 Hook 有什么区别？

Vue 的 setup 只执行一次，组合式函数也只调用一次，所以不受调用顺序的限制，也没有依赖数组和读到旧闭包值的问题。React 组件每次渲染都会重新执行 Hook。

VueUse 是什么？

一个常用组合式函数的集合，比如 useStorage、useIntersectionObserver。可以直接拿来用，也可以参考它的实现。
