Vue 2 项目如何迁移到 Vue 3？

先升到 Vue 2.7，用组合式 API 提前改写，清理 filters、$listeners、.sync 这些旧写法；确认组件库和浏览器支持没问题后，再用 @vue/compat 迁移构建逐个消除警告，同时升级路由和状态管理。

参考答案

Vue 2 已于 2023-12-31 停止维护，本题 Vue 2 部分以 2.7 为准。通信写法的具体改动见《Vue 2 有哪些组件通信方式？哪些写法在 Vue 3 中被移除或改变？》。

简答

我会分三步走。第一步先评估能不能迁：依赖 Vue 2 内部 API 的库、还没有 Vue 3 版本的组件库、必须支持 IE11 的项目，都可能要暂时留在 Vue 2。

第二步先升级到 Vue 2.7。它内置了组合式 API、<script setup> 和单文件组件 CSS 里的 v-bind，可以在 Vue 2 上提前改写代码，把之后的差距缩小。

第三步用 @vue/compat 正式切换。它是一个可以配置 Vue 2 兼容行为的 Vue 3 构建，默认按 Vue 2 的方式运行，遇到废弃用法就发警告，可以一项项修。主要的破坏性变更有：createApp 取代 new Vue()，组件 v-model 重做并移除 .sync，$listeners、$on、filters 被移除，beforeDestroy/destroyed 改名，过渡类名变化等。

生态也要一起升：vue-router 4、Vuex 4 或者改用官方推荐的 Pinia，vue-template-compiler 换成 @vue/compiler-sfc。

第一步：先评估依赖和运行环境

迁移构建文档列出了几类限制。依赖 Vue 2 内部 API 或未公开行为的库最麻烦，最常见的是访问 VNode 的私有属性。用了 Vuetify、Quasar、ElementUI 这类组件库，最好等它们出 Vue 3 兼容版本。Vue 3 不支持 IE11，必须支持 IE11 的项目只能留在 Vue 2。自己搭的 SSR 迁移成本更高，vue-server-renderer 要换成 @vue/server-renderer。

这一步的意义在于，有些障碍不是改代码能解决的，要先弄清楚再动手。

第二步：在 Vue 2.7 上提前改写

2.7 发布说明列出的移植功能有组合式 API、单文件组件的 <script setup>、CSS v-bind，以及 defineComponent() 的类型推断改进。原来用 @vue/composition-api 插件的项目，把导入改成从 vue 导入就行。

不过 2.7 有边界。它的组合式 API 底层还是 Vue 2 的 getter/setter 响应式；createApp()、<script setup> 里的顶层 await、模板表达式里的 TypeScript 语法和 Reactivity Transform 都没有移植。

为什么要多这一步，不直接上 Vue 3？因为在 2.7 上改写时，应用一直能正常运行，可以按模块慢慢来。这一阶段还可以顺手清理迁移后不再支持的写法：废弃的具名/作用域插槽语法（2.6 已支持新语法）、filters、$listeners、.sync、EventBus 等。

第三步：用 @vue/compat 切到 Vue 3

迁移构建文档给出的流程是这样的。先升级工具链：自定义 webpack 的把 vue-loader 升到 16；用 Vue CLI 的执行 vue upgrade，或者改用 Vite。然后在 package.json 里把 vue 升到 3，装同版本的 @vue/compat，用 @vue/compiler-sfc 替换 vue-template-compiler。最后在构建配置里把 vue 的别名指向 @vue/compat，并在编译选项里设置 compatConfig: { MODE: 2 }：

JavaScript
// vite.config.js
export default {
  resolve: { alias: { vue: '@vue/compat' } },
  plugins: [
    vue({ template: { compilerOptions: { compatConfig: { MODE: 2 } } } }),
  ],
};

跑起来以后，先修编译期的错误，比如 filters，再一个个处理浏览器控制台里的运行时警告。每个警告都有 ID，比如 GLOBAL_MOUNT 表示 new Vue() 要换成 createApp，OPTIONS_BEFORE_DESTROY 表示 beforeDestroy 要改名。

有一项要特别留意：过渡类名的变化是唯一没有运行时警告的特性，得自己全局搜索 .*-enter、.*-leave 这类类名。

接着改用 createApp 挂载，升级 Vuex 4 和 vue-router 4。冲突比较大的组件，可以通过 compatConfig 选项单独切到 Vue 3 的行为。警告全部清掉以后，移除迁移构建。

状态管理从 Vuex 换到 Pinia

Vue 官方文档说明，Pinia 已经接替了 Vuex 的角色，Vuex 进入维护模式，新项目推荐 Pinia。迁移时可以先升级到 Vuex 4 保证能跑，再按模块逐步改写成 Pinia store。

常见追问

为什么不直接重写？

大型项目一次性重写风险太高。先升 2.7、再用迁移构建，应用在每一步都能保持可运行，出了问题也容易定位。

迁移构建能一直用下去吗？

不能。它就是为过渡准备的，有些特性在 Vue 2 和 Vue 3 中行为冲突，最终还是要移除它，切到正式的 Vue 3。

必须先改成组合式 API 吗？

不必。Vue 3 仍然完整支持选项式 API，组合式 API 只是一个可选的改写方向。
