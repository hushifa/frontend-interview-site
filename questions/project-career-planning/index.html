面试官问“你的职业规划是什么”，应该怎样回答？

职业规划题看的是方向是否和岗位一致、会不会持续成长、能不能稳定待下去。按“未来一到三年的方向 → 正在做的具体行动 → 这个岗位怎样帮你走这条路”来讲，方向要说到具体能力，行动要有真实例子，并提前了解岗位和公司，不要说空话，也不要暗示很快会离开。

参考答案

本题是回答思路与示例，不对应某个官方规范。示例中的经历和时间只用来演示怎样表达。

简答

面试官问“你的职业规划是什么”，不是要你交一份五年计划，而是想知道三件事：你想往哪个方向发展，这个方向和岗位合不合得上，你是不是真的在为它做事。比如应聘性能方向的前端岗位，说“想在性能和工程化上做深”，就比说“想成为技术专家”有用得多。

回答按三层讲。先说未来一到三年想深入的方向，要具体到能力，比如“浏览器渲染和性能监控”。再说你已经在做的事，比如最近系统学了什么、在项目里推动了什么，这部分最能证明你不是随口一说。最后落到岗位上，说清楚这个岗位的哪些职责正好能帮你走这条路。

想讲好这一层，面试前要先了解岗位和公司，看招聘要求、产品和技术博客，知道他们在做什么、需要什么人。不同阶段侧重也不同：应届生讲打好基础、尽快独立负责模块；有几年经验的讲在某个方向做深，或者开始带新人、负责更大的模块。

要注意几个坑。不要说“还没想好”，显得没有方向；不要说“几年后想转行”“想创业”这类让面试官担心你待不久的话；也不要说一个和岗位毫不相关的方向。说的规划要是真的，面试官会顺着追问你具体做了什么。

面试官想从这道题里听到什么

这道题看起来很虚，其实面试官的判断很具体。第一，你的方向和岗位是不是一致，招一个想做底层引擎的人去写业务页面，双方都不会满意。第二，你会不会持续学习，一个说得出自己在补什么、怎么补的人，入职以后大概率也会主动成长。第三，你会不会稳定待一段时间，培养一个新人需要成本，面试官不希望一年后就要重新招人。

所以回答不能只表态，要让面试官从你的话里得出这三个判断。

怎样讲出具体的方向和行动

先看一个回答示例，应聘的是负责 C 端页面和构建工具的前端岗位：

接下来一到三年，我想在前端性能和工程化这个方向深入下去。之前在项目里做过首屏优化，越做越觉得只会套用技巧不够，所以最近在系统地补浏览器渲染和网络这部分，也在团队里推动接入了真实用户的性能监控，现在每周会看一次核心页面的数据。

我了解到这个岗位要负责核心页面的体验，还要维护团队的构建工具，和我想走的方向很一致。我希望在这里先把核心页面的性能做扎实，之后能把这些经验沉淀成团队的工具和规范。

这段回答具体在哪里？方向不是“成为技术专家”，而是“前端性能和工程化”；行动不是“多学习”，而是正在补哪块知识、在团队里做了什么、现在多久看一次数据；最后落到了这个岗位的两项具体职责上。

岗位职责从哪里来？要在面试前做功课。MDN 的求职指南建议，申请之前先研究这家公司，读他们的网站和博客，了解他们的历史和目标，花点时间用他们的产品；面试前再看看公司最近的新闻、市场位置和主要竞争对手，因为面试官常会问一些问题来考察你对公司和行业的了解。做完这些，你说“这个岗位能帮我走这条路”时，才有具体内容可讲。

不同阶段怎样调整

应届生或工作一两年。 面试官不期待你有很长远的规划，更看重你能不能快速上手。可以说先在一个方向打好基础，比如把框架原理和浏览器机制学扎实，尽快能独立负责一个模块，再根据项目里的积累确定要深入的方向。

工作三到五年。 要讲出一个明确的技术方向，并且有项目经历支撑。也可以讲职责范围上的变化，比如从完成需求到负责整个模块的技术方案，开始带新人做代码评审。

应聘技术负责人。 规划要从个人扩展到团队，讲你会怎样规划团队的技术方向、怎样培养人、怎样平衡业务交付和技术建设。

不管哪个阶段，都要和自己的实际水平相符。MDN 的求职指南也提醒，要按自己的经验水平申请岗位，学了三个月 JavaScript 就去申请高级开发岗位并不现实。规划同理，说得太大而又讲不出现在在做什么，反而让人觉得不可信。

常见的不好的回答

  • “我还没想好。”显得没有方向，也没有认真准备面试。
  • “五年后想做架构师。”只有头衔，说不出要补哪些能力、现在在做什么。
  • “以后想转产品”“想自己创业”。面试官会担心你很快离开。
  • 规划和岗位毫无关系，比如面业务前端岗却只讲想做游戏引擎。
  • 背了一段很漂亮的规划，被追问“最近在学什么、学到哪了”就答不上来。

常见追问

你以后想走技术路线还是管理路线？

如实说当前的倾向，并说明理由。比如“现在更想在技术上做深，因为还有很多想解决的问题；带人这件事我也在尝试，最近在带一位新同事做代码评审，以后看团队需要和自己的适合程度再决定”。不要为了迎合面试官说自己想做管理，也不要把管理说得一无是处。

如果这个岗位和你的规划不完全一致，你会怎么想？

说清楚哪些部分一致、哪些部分你愿意先投入。比如“岗位里业务开发占大头，和我想做的工程化不完全一样，但业务做得多，才知道工具该解决什么问题；我希望先把业务做好，再在过程中找到能改进的工具和流程”。这比硬说“完全一致”更可信。

你最近在学什么？

这是在验证你说的规划是不是真的。讲一个具体的东西和进展，比如“最近在看浏览器渲染流程，用 DevTools 的 Performance 面板把公司的列表页录了一遍，发现一个强制同步布局的问题，已经改掉了”。说得出学了什么、用在了哪里，就比列一串书名有说服力。
