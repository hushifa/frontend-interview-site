Cookie、localStorage 和 sessionStorage 如何选择？

Cookie 会随请求发送，适合服务端需要读取的小数据；localStorage 持久保存、按源共享；sessionStorage 只在当前标签页会话内有效。

参考答案

简答

  • Cookie 会自动随匹配的请求发送，单个约 4KB，适合会话标识这类服务端要读取的数据。
  • localStorage 按源持久保存，同源的所有标签页共享，容量通常约 5MB。
  • sessionStorage 按源加标签页隔离，关闭标签页后清除。
  • 两种 Web Storage 都是同步 API、只能存字符串，页面脚本都能读到，不要存令牌等敏感数据。

选择建议

  • 登录会话：服务端下发 HttpOnly; Secure; SameSite=Lax 的 Cookie，页面脚本读不到，XSS 无法直接窃取。
  • 主题、语言、草稿：localStorage。
  • 单个标签页的流程状态：sessionStorage，例如多步表单的进度。
  • 大量结构化数据或二进制：IndexedDB，它是异步的，不阻塞主线程。

使用细节

JavaScript
function readJSON(key, fallback) {
  try {
    const raw = localStorage.getItem(key);
    return raw === null ? fallback : JSON.parse(raw);
  } catch {
    return fallback;
  }
}
  • 写入可能抛出 QuotaExceededError，隐私模式或存储被禁用时也可能失败，读写都要处理异常。
  • 其他同源标签页修改 localStorage 时，本页会收到 storage 事件，修改的那一页自己收不到。
  • sessionStorage 在"复制标签页"时会复制一份，之后两边互相独立。
