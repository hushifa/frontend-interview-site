defineProperty 和 Proxy 实现的响应式有什么区别？

Vue 2 的 defineProperty 只能一个个监听已有属性，初始化时要把整个 data 走一遍；Vue 3 的 Proxy 直接代理整个对象，用到嵌套对象时才代理它，所以属性增删、数组下标、Map 和 Set 都能检测到。

参考答案

Vue 2 已于 2023-12-31 停止维护，Vue 2 部分以 2.7 为准，Vue 3 部分以 3.5 为准。

简答

两者最根本的差别在于监听的单位。defineProperty 是给对象上某一个已经存在的属性装 getter 和 setter，所以 Vue 2 初始化时要把整个 data 递归遍历一遍。Proxy 是给整个对象套一层代理，任何属性的读写都会经过它，Vue 3 只在读到嵌套对象时才为它创建代理。

因为监听的是整个对象，Proxy 还能拦截更多操作：deleteProperty 拦删除，has 拦 in，ownKeys 拦遍历。所以 Vue 3 能检测属性的增删、in 判断、遍历，以及数组下标和 length 的修改，Vue.set 和 Vue.delete 也就被移除了。

Map、Set、WeakMap、WeakSet 在 Vue 3 里由专门的集合处理器拦截 get、set、add 等方法；Vue 2 不支持它们的响应式。

依赖管理上，Vue 3 由 effect 执行时读属性调用 track 登记依赖，写属性时调用 trigger 找到依赖它的 effect 去重新执行或调度。代价是 Proxy 没法 polyfill，所以 Vue 3 不支持 IE11。

能力边界对比

Vue 2（defineProperty）Vue 3（Proxy）
新增/删除属性检测不到，需 Vue.set/Vue.deleteset、deleteProperty 陷阱可检测
key in obj、for...in/Object.keys依赖不到新增的 keyhas、ownKeys 陷阱可追踪
数组下标赋值、改 length检测不到，靠重写 7 个变异方法直接检测
Map/Set不支持collectionHandlers 支持
原对象原地修改，加上 getter/setter 和 __ob__不修改原对象，返回代理；修改原对象不会触发更新
浏览器ES5，支持 IE9+Proxy 无法 polyfill，Vue 3 不支持 IE11

官方 Vue 3 文档说明：Vue 2 因为浏览器支持的限制只用 getter/setter；Vue 3 对 reactive 对象用 Proxy，对 ref 用 getter/setter。迁移指南也写明，在基于 Proxy 的变更检测下，$set 和 $delete 不再需要。

初始化开销有什么不同

Vue 2 在创建实例时一次性递归转换所有嵌套属性。数据越大，初始化越慢，哪怕有些属性从来没被渲染过。所以大型只读数据常用 Object.freeze 跳过转换。

Vue 3 的 reactive() 一开始只代理顶层。get 陷阱返回的值如果是对象，才调用 reactive(res) 给它创建代理，并且用一个 WeakMap（proxyMap）缓存起来，同一个原对象总是得到同一个代理。

不过 Proxy 也有代价，每次访问属性都要经过代理的陷阱函数。大数据可以用 shallowRef、shallowReactive 或 markRaw 跳过深层代理。两者的性能差多少，取决于数据规模和访问方式，这里不给具体倍数。

effect、track、trigger 怎么配合

Vue 3.5 的结构是这样的。全局有一个 targetMap: WeakMap<target, Map<key, Dep>>，记录“某个对象的某个 key 被哪些 effect 依赖”。track(target, type, key) 在当前有正在运行的 effect 时，找到或创建对应的 Dep 并登记。trigger(target, type, key) 取出对应的 Dep 通知订阅者。

新增或删除属性时，trigger 还会触发一个专门给遍历用的 ITERATE_KEY，因为 Object.keys 这类遍历的结果变了；数组改 length 时，会触发受影响的那些下标。组件渲染、computed、watch 都建立在 effect 之上，组件更新再通过调度器进入异步队列。

实际跑一下

下面这段代码把 Vue 2 检测不到的四种操作都做了一遍：新增属性、改 length、操作 Map、删除属性。

JavaScript
// 用 Node 运行，vue@3.5.x
const { reactive, effect, toRaw } = require('vue');
const s = reactive({ a: { b: 1 }, list: [1, 2, 3], m: new Map() });
const log = [];
effect(() => log.push(`${'c' in s} ${s.list.length} ${s.m.get('k')}`));

s.c = 1; // 新增属性
s.list.length = 1; // 改 length
s.m.set('k', 2); // Map
delete s.c; // 删除属性
console.log(log);
// [ 'false 3 undefined', 'true 3 undefined', 'true 1 undefined', 'true 1 2', 'false 1 2' ]

console.log(s.a === s.a); // true，嵌套代理被缓存
console.log(toRaw(s).a === toRaw(s.a)); // true，原对象没有被替换

log 里有五行：第一行是 effect 首次执行，后面四行对应四次修改，每一次都被检测到了。effect 来自 @vue/reactivity，它是同步执行的，所以每次修改都立即记一行；组件渲染则会经过调度器合并。

最后两行说明了懒代理的两个特点。s.a === s.a 是 true，说明嵌套对象的代理被缓存了，不会每次读都新建一个。toRaw(s).a === toRaw(s.a) 也是 true，说明原对象里的 a 还是那个普通对象，Vue 3 没有改动原对象。

常见追问

Vue 2.7 也有 reactive()，它也是用 Proxy 实现的吗？

不是。2.7 的 reactive 仍然基于 defineProperty，限制和 Vue 2 一样。

解构 reactive 对象为什么会失去响应式？

解构得到的是属性当时的普通值，之后读写这个变量都不会经过代理的 get 和 set，Vue 也就追踪不到了。
