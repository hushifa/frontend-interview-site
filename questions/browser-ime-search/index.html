中文输入法期间怎样触发搜索？composition 与请求竞态如何一起处理？

用拼音打字时，没选完字之前的 input 事件都不该发请求。等 compositionend 后再防抖搜索，并取消上一个请求，只渲染最新结果。

参考答案

简答

用拼音输入“前端”时，没选字之前输入框里会先出现 q、qian、qian d 这些中间值，每一次都会触发 input 事件。如果每次都发搜索请求，就是在拿拼音去搜。

浏览器把这段“还在选字”的过程叫组字（composition）。开始时触发 compositionstart，选完时触发 compositionend，中间的 input 事件 event.isComposing 是 true。

所以做法是：组字期间跳过搜索，等 compositionend 之后按最终的值触发一次防抖搜索。

另外还要处理请求竞态：每次发新请求前把上一个取消掉，只渲染最后一次请求的结果，避免旧结果覆盖新结果。

先看完整的写法

JavaScript
function bindSearch(input, search) {
  let composing = false;
  let timer;
  let controller;

  const run = () => {
    clearTimeout(timer);
    timer = setTimeout(async () => {
      controller?.abort();
      controller = new AbortController();
      const { signal } = controller;
      try {
        const results = await search(input.value.trim(), signal);
        if (!signal.aborted) render(results);
      } catch (error) {
        if (error.name !== 'AbortError') renderError(error);
      }
    }, 250);
  };

  input.addEventListener('compositionstart', () => {
    composing = true;
  });
  input.addEventListener('compositionend', () => {
    composing = false;
    run();
  });
  input.addEventListener('input', (event) => {
    if (composing || event.isComposing) return;
    run();
  });
}

这里有两件事。第一件是组字：input 事件里只要还在组字就直接返回，等 compositionend 再调用 run()。第二件是竞态：run() 里先 abort() 上一个请求，再发新的，结果回来时如果已经被取消就不渲染。

为什么要同时检查两个标记

你可能会问，既然有 event.isComposing，为什么还要自己维护一个 composing 变量？因为不同浏览器里这几个事件的先后顺序不完全一样，两个都查一遍更稳。

还有的浏览器在 compositionend 之后又会再触发一次 input。这样 run() 会被调两次，不过有 250 毫秒的防抖，两次会合并成一次请求。

为什么要取消旧请求

用户先搜“前”，再搜“前端”，两个请求同时在路上。如果“前”的结果后回来，页面上显示的就是旧结果，这就是请求竞态。

abort() 让旧请求直接作废，它的 Promise 以 AbortError 结束，catch 里会忽略这种错误。要让取消真正生效，search 内部得把 signal 传给 fetch。

回车键也要处理

组字时按回车，是在确认候选词，不应该提交表单：

JavaScript
input.addEventListener('keydown', (event) => {
  if (event.key === 'Enter' && !event.isComposing) submit();
});

不过 Safari 里确认候选词的那次回车，keydown 的 isComposing 可能是 false。可以再检查 event.keyCode === 229 作为兜底。

常见追问

搜索为什么用防抖，不用节流？

搜索关心的是用户停下来以后的最终输入。节流会在输入过程中按固定间隔发请求，防抖是等停下来再发，所以更合适。

只用请求序号丢弃旧结果行不行？

可以避免旧结果覆盖新结果，但旧请求还在占用网络。abort() 能把请求真正取消掉，两者可以一起用。
