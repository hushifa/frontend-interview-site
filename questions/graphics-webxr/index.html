WebXR 应用需要处理哪些设备与会话边界？

WebXR 会话要先检测模式、由用户操作发起；参考空间决定坐标原点；渲染使用会话自己的 requestAnimationFrame，按设备给出的每个视图绘制；输入源会变化，会话可能结束或暂时不可见。

参考答案

简答

  • 模式有 inline、immersive-vr、immersive-ar。先用 navigator.xr.isSessionSupported() 检测，再在用户点击时调用 requestSession()。
  • 参考空间决定坐标相对于谁：viewer 跟随头部，local 是起始位置附近的固定原点，local-floor 把原点放在地面。单位是米。
  • 渲染用 session.requestAnimationFrame()，在回调里用 frame.getViewerPose() 拿姿态，再遍历 pose.views 逐个绘制，不要假设固定两个视口。
  • 跟踪丢失时 getViewerPose() 返回 null，这一帧跳过即可。
  • 输入源（手柄、手、凝视）会在会话中增减，监听 inputsourceschange；会话结束时监听 end 并恢复页面。

启动会话

JavaScript
const button = document.querySelector('#enter-vr');

if (navigator.xr && (await navigator.xr.isSessionSupported('immersive-vr'))) {
  button.hidden = false;
  button.addEventListener('click', async () => {
    const session = await navigator.xr.requestSession('immersive-vr', {
      optionalFeatures: ['local-floor'],
    });
    const space = await session
      .requestReferenceSpace('local-floor')
      .catch(() => session.requestReferenceSpace('local'));
    startRendering(session, space);
  });
}

需要安全上下文。isSessionSupported() 返回 true 也可能因为权限或设备占用而请求失败，失败时提示用户，不要循环重试。

local-floor 不可用时退回 local，并调整场景高度。

帧循环

JavaScript
function startRendering(session, space) {
  session.requestAnimationFrame(function onFrame(time, frame) {
    session.requestAnimationFrame(onFrame);
    const pose = frame.getViewerPose(space);
    if (!pose) return; // 跟踪暂时丢失

    for (const view of pose.views) {
      const viewport = session.renderState.baseLayer.getViewport(view);
      drawScene(view.projectionMatrix, view.transform.inverse.matrix, viewport);
    }
  });
}

XRFrame 只在当前回调内有效，不能保存起来在异步代码里使用。普通窗口的 requestAnimationFrame 不能代替会话的帧调度。

输入

  • XRInputSource 的 targetRayMode 区分 tracked-pointer（手柄或手）、gaze、screen。
  • 用 select、squeeze 事件处理交互，再自己做射线命中。不要写死"第一个手柄的第二个按钮"。
  • 保留二维页面上的替代操作，空间手势不适合所有用户。

会话结束与可见性

  • 监听 end：恢复页面状态，清理监听器，释放只属于 XR 的资源。
  • 监听会话的 visibilitychange：visible-blurred 时场景可能仍可见，但不处理输入，帧回调可能被降频，应暂停交互；hidden 时帧回调完全停止。两种状态都不代表会话结束。

常见追问

  • 命中测试、手部追踪这些能力怎么用？ 作为 requiredFeatures 或 optionalFeatures 申请。只把必需的放进 requiredFeatures，否则不支持的设备会直接无法启动。
  • 模拟器测试够吗？ 只能验证逻辑。帧率、跟踪丢失、舒适性要在真机上测试。
