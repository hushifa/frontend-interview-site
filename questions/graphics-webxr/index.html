WebXR 应用需要处理哪些设备与会话边界？

WebXR 就是在网页里做 VR 和 AR。会话要先检测模式、由用户操作发起；参考空间决定坐标原点；渲染使用会话自己的 requestAnimationFrame，按设备给出的每个视图绘制；输入源会变化，会话可能结束或暂时不可见。

参考答案

简答

WebXR 让网页能进入 VR 或 AR。进入的那一段体验叫会话，模式有 inline、immersive-vr、immersive-ar 三种。要先用 navigator.xr.isSessionSupported() 检测，再在用户点击时调用 requestSession()。

进入以后先要定坐标原点，这叫参考空间：viewer 跟着头部走，local 是起始位置附近的一个固定点，local-floor 把原点放在地面上。单位都是米。

渲染要用会话自己的 session.requestAnimationFrame()。在回调里用 frame.getViewerPose() 拿到头部姿态，再遍历 pose.views 一个个画，不要假设永远是左右两只眼。跟踪丢了时 getViewerPose() 会返回 null，这一帧跳过就行。

还要注意，手柄、手这些输入源会在会话中途增减，要监听 inputsourceschange；会话也可能结束，要监听 end，把页面恢复过来。

怎样启动一个会话

下面的代码先检测支不支持，支持才显示按钮，用户点了才进入：

JavaScript
const button = document.querySelector('#enter-vr');

if (navigator.xr && (await navigator.xr.isSessionSupported('immersive-vr'))) {
  button.hidden = false;
  button.addEventListener('click', async () => {
    const session = await navigator.xr.requestSession('immersive-vr', {
      optionalFeatures: ['local-floor'],
    });
    const space = await session
      .requestReferenceSpace('local-floor')
      .catch(() => session.requestReferenceSpace('local'));
    startRendering(session, space);
  });
}

WebXR 需要安全上下文。还要注意，isSessionSupported() 返回 true，请求也可能因为权限或者设备被占用而失败。失败时提示用户就好，不要循环重试。

local-floor 申请成可选功能，拿不到就退回 local。这时原点不在地面上了，要自己调整场景的高度。

每一帧怎么画

JavaScript
function startRendering(session, space) {
  session.requestAnimationFrame(function onFrame(time, frame) {
    session.requestAnimationFrame(onFrame);
    const pose = frame.getViewerPose(space);
    if (!pose) return; // 跟踪暂时丢失

    for (const view of pose.views) {
      const viewport = session.renderState.baseLayer.getViewport(view);
      drawScene(view.projectionMatrix, view.transform.inverse.matrix, viewport);
    }
  });
}

为什么要遍历 pose.views，不直接画左右眼？因为视图有几个由设备决定。VR 头显通常是两个，手机 AR 可能只有一个，所以按设备给的来画。每个视图有自己的投影矩阵和视口。

XRFrame 只在当前这次回调里有效，不能存起来留到异步代码里用。普通窗口的 requestAnimationFrame 也不能代替会话的帧调度，因为头显的刷新节奏由会话控制。

输入要怎么处理

每个输入源是一个 XRInputSource，它的 targetRayMode 说明是哪种：tracked-pointer 是手柄或手，gaze 是凝视，screen 是屏幕触摸。

交互要用 select、squeeze 这些事件来处理，再自己做射线命中，算出指向了哪个物体。不要写死“第一个手柄的第二个按钮”，因为设备千差万别，输入源还会变。

另外要在二维页面上保留替代操作，空间手势不是所有用户都能做。

会话结束或者看不见了怎么办

监听 end：恢复页面状态，清掉监听器，释放只属于 XR 的资源。

还要监听会话的 visibilitychange，它有两种不可见的状态。visible-blurred 时场景可能还看得见，但不处理输入，帧回调也可能降频，所以要暂停交互。hidden 时帧回调完全停止。这两种状态都不代表会话结束了。

常见追问

命中测试、手部追踪这些能力怎么用？

在请求会话时，把它们放进 requiredFeatures 或 optionalFeatures 申请。只把必需的放进 requiredFeatures，不然不支持的设备会直接启动不了。

用模拟器测试够吗？

只能验证逻辑。帧率、跟踪丢失、会不会晕，这些要在真机上测。
