Hydration mismatch 为什么发生，应该怎样修复？

Hydration 时客户端第一次渲染的结果必须与服务端 HTML 一致。常见原因是渲染中用了时间、随机数、浏览器专属 API，两端数据或时区不同，HTML 嵌套不合法，或者浏览器扩展修改了 DOM。修复方法是让两端用同一份初始数据，只有浏览器才有的内容等挂载后再更新。

参考答案

简答

服务端渲染出 HTML 以后，客户端不会重建 DOM，而是把组件逻辑和事件“接到”已有的 DOM 上，这一步叫 hydration。它的前提是客户端第一次渲染的结果和服务端 HTML 一样，对不上就叫 hydration mismatch。

常见原因有这些：渲染时调了 Date.now()、Math.random()；读了 window、localStorage；服务端和浏览器的时区、语言不同；两端拿到的数据不同；HTML 嵌套不合法；浏览器扩展往页面里插了节点。

React 18 起，不一致不再只是一个警告，文本不同也算。React 会丢掉这部分服务端 HTML，从最近的 Suspense 边界开始改成客户端渲染，没有边界就从根开始，并通过 onRecoverableError 上报。

修复原则是：首次渲染只用两端都一样的输入，浏览器才有的内容等 useEffect 之后再更新，Vue 里是 onMounted。suppressHydrationWarning 只能用在没法避免的单个文本差异上，比如时间戳，不能拿来掩盖结构问题。

先看一个显示本地时间的组件

JSX
// 错误：服务端和浏览器的时间、时区都可能不同
function Clock() {
  return <time>{new Date().toLocaleTimeString()}</time>;
}

这段代码在纯客户端渲染时没问题，一上 SSR 就会报 mismatch。原因是它被执行了两次：服务端算一次，生成 HTML；客户端 hydration 时又算一次。两次之间隔了时间，服务器和用户的时区也可能不同，结果自然对不上。

改法是让第一次渲染用两端相同的输入，也就是服务端传过来的时间，等挂载后再换成本地时间：

JSX
// 正确：首次渲染使用服务端传来的时间，挂载后再切换到本地时间
function Clock({ serverTime }) {
  const [text, setText] = useState(() => new Date(serverTime).toISOString());
  useEffect(() => {
    setText(new Date().toLocaleTimeString());
    const id = setInterval(() => setText(new Date().toLocaleTimeString()), 1000);
    return () => clearInterval(id);
  }, []);
  return <time dateTime={serverTime}>{text}</time>;
}

useEffect 只在浏览器里、hydration 完成之后执行，所以放在里面的本地时间不会参与比对。

常见原因和改法

原因例子修复
不确定的值时间、随机数由服务端生成并作为数据传给客户端；ID 用 useId
浏览器专属 APIwindow.innerWidth、localStorage首次渲染使用默认值，挂载后读取
两端数据不同客户端重新请求得到更新的数据把服务端使用的数据序列化到页面里，客户端直接复用
不合法的嵌套<p> 里放 <div>，<a> 里放 <a>修正 HTML 结构，浏览器解析时会自动改写这类结构
浏览器扩展翻译、广告拦截插件改写 DOM用无痕模式复现，确认是否是扩展造成

不合法嵌套这一条容易让人困惑：代码里明明写的是 <p><div>，为什么会不一致？因为浏览器解析 HTML 时会自动修正这种结构，实际 DOM 变成了别的样子，React 拿自己的结果去比，就对不上了。

确实没法在服务端渲染的组件

有些组件就是只能在浏览器里跑，可以包一层：

JSX
function ClientOnly({ children, fallback = null }) {
  const [mounted, setMounted] = useState(false);
  useEffect(() => setMounted(true), []);
  return mounted ? children : fallback;
}

服务端和客户端第一次渲染都输出 fallback，两边一致；挂载后 mounted 变成 true，才渲染真正的内容。代价是多一次渲染，而且首屏看不到这部分内容，所以只用于确实没法服务端渲染的组件。

怎样排查

先看控制台报错，里面有组件栈和差异内容，React 19 会直接显示服务端和客户端哪里不同。然后打开页面源代码，那是服务端返回的 HTML，拿它和 hydration 后的 DOM 对比。

如果在自己电脑上复现不了，试试固定时区和语言。服务端、测试环境和用户浏览器的这些设置经常不一样。

常见追问

不一致会造成什么后果？

一是性能浪费，因为要重新渲染；二是页面会闪烁；严重时事件会绑到错误的节点上。

Vue 里怎么处理？

原理一样。Vue 3.5 起可以给元素加 data-allow-mismatch，抑制预期之内的不一致警告，还可以限定类型，比如只允许 text 或 class 不一致。
