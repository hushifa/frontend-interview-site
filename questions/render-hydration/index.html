Hydration mismatch 为什么发生，应该怎样修复？

Hydration 时客户端第一次渲染的结果必须与服务端 HTML 一致。常见原因是渲染中使用了时间、随机数、浏览器专属 API，两端数据或时区不同，HTML 嵌套不合法，或者浏览器扩展修改了 DOM。修复方法是让两端使用同一份初始数据，只在浏览器中才有的内容等到挂载后再更新。

参考答案

简答

  • Hydration 是客户端把组件逻辑和事件"接到"服务端已经生成的 DOM 上，前提是客户端首次渲染与服务端 HTML 一致。
  • 常见原因：渲染时调用 Date.now()、Math.random()；读取 window、localStorage；服务端与浏览器时区、语言不同；服务端和客户端拿到的数据不同；不合法的 HTML 嵌套；浏览器扩展插入了节点。
  • React 遇到文本不一致时会报警告；遇到较严重的不一致，会丢弃这部分服务端 HTML，在客户端重新渲染到最近的 Suspense 边界。
  • 修复原则：首次渲染只使用两端都相同的输入；浏览器专属的内容在 useEffect（Vue 中是 onMounted）之后再更新。
  • suppressHydrationWarning 只能用于无法避免的单个文本差异（如时间戳），不能用来掩盖结构问题。

例子：显示本地时间

JSX
// 错误：服务端和浏览器的时间、时区都可能不同
function Clock() {
  return <time>{new Date().toLocaleTimeString()}</time>;
}
JSX
// 正确：首次渲染使用服务端传来的时间，挂载后再切换到本地时间
function Clock({ serverTime }) {
  const [text, setText] = useState(() => new Date(serverTime).toISOString());
  useEffect(() => {
    setText(new Date().toLocaleTimeString());
    const id = setInterval(() => setText(new Date().toLocaleTimeString()), 1000);
    return () => clearInterval(id);
  }, []);
  return <time dateTime={serverTime}>{text}</time>;
}

常见原因与修复

原因例子修复
不确定的值时间、随机数由服务端生成并作为数据传给客户端；ID 用 useId
浏览器专属 APIwindow.innerWidth、localStorage首次渲染使用默认值，挂载后读取
两端数据不同客户端重新请求得到更新的数据把服务端使用的数据序列化到页面里，客户端直接复用
不合法的嵌套<p> 里放 <div>，<a> 里放 <a>修正 HTML 结构，浏览器解析时会自动改写这类结构
浏览器扩展翻译、广告拦截插件改写 DOM用无痕模式复现，确认是否是扩展造成

只在客户端渲染的组件

JSX
function ClientOnly({ children, fallback = null }) {
  const [mounted, setMounted] = useState(false);
  useEffect(() => setMounted(true), []);
  return mounted ? children : fallback;
}

服务端和首次客户端渲染都输出 fallback，挂载后才渲染真实内容。会多一次渲染，首屏也看不到这部分内容，只用于确实无法在服务端渲染的组件。

排查方法

  • 看控制台报错中给出的组件栈和差异内容，React 19 会显示服务端和客户端的不同之处。
  • 查看页面源代码（服务端 HTML），与 hydration 后的 DOM 对比。
  • 固定时区和语言复现：服务端、测试环境和用户浏览器的设置常常不同。

常见追问

  • 不一致会造成什么后果？性能浪费（重新渲染）、闪烁，严重时事件绑定到错误的节点上。
  • Vue 中怎么处理？原理相同，Vue 3.5 起可以给元素加 data-allow-mismatch 来抑制预期之内的不一致警告，并可以限定类型（如 text、class）。
