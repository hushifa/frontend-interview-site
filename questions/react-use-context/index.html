useContext 怎样用？什么时候该用 Context 而不是 props？

用 createContext 创建 Context 并给出默认值，在上层用 <SomeContext value={...}> 提供值（React 19 之前写 SomeContext.Provider），下层组件调用 useContext 读取离它最近的那个 Provider 的值，找不到 Provider 时才用默认值。Context 适合主题、语言、登录用户这类很多层都要用的数据；层级不深时先传 props 或用 children 减少层级。

参考答案

简答

应用要支持深色模式，按钮、卡片、弹窗分布在很深的层级里，每一层都传 theme prop 太麻烦。可以 createContext 建一个 ThemeContext，在根部用 <ThemeContext value={theme}> 包住，任何深层组件里调用 useContext(ThemeContext) 就能拿到当前主题。

useContext 会往上找离它最近的同一个 Context 的 Provider，读它的 value；一个都找不到，才用 createContext 时给的默认值。React 19 起可以直接把 <SomeContext> 当 Provider 渲染，之前的版本写 <SomeContext.Provider>。

Context 不是 props 的替代品。React 文档建议先直接传 props，哪怕要传几层，数据从哪来一眼就能看出；中间层只是转手时，可以让它接收 children，减少层级。主题、语言、当前登录用户这类很多深层组件都要用、变化又不频繁的数据，才适合放进 Context。

要注意 Provider 必须在调用 useContext 的组件上层，默认值只在完全找不到 Provider 时生效。另外 value 变化时，所有读这个 Context 的组件都会重新渲染，怎样避免不必要的渲染见《React Context 有哪些性能问题？怎样避免不必要的重新渲染？》。

基本用法

下面是一个主题切换的完整写法，注意 Provider 放在读取它的组件的上层：

JSX
import { createContext, useContext, useState } from 'react';

const ThemeContext = createContext('light');

export default function App() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext value={theme}>
      <Toolbar />
      <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>
        切换主题
      </button>
    </ThemeContext>
  );
}

function Toolbar() {
  return <Button>保存</Button>;
}

function Button({ children }) {
  const theme = useContext(ThemeContext);
  return <button className={`btn-${theme}`}>{children}</button>;
}

Toolbar 没有接收也没有传递 theme，Button 怎么拿到的？useContext 不走 props，它沿着组件树往上找最近的 ThemeContext Provider。中间隔多少层都没关系。点切换按钮后，theme 状态变化，Provider 的 value 变了，Button 自动用新值重新渲染。

有两个容易出错的地方。一是 Provider 必须在调用 useContext 的组件上面，同一个组件自己渲染的 Provider 对自己无效。二是默认值只在完全找不到 Provider 时使用：如果上层写了 <ThemeContext value={undefined}>，读到的就是 undefined，不是默认值。默认值也永远不会变，要让 Context 能变化，就要像上面这样配合 state。

value 变化时会发生什么

Provider 的 value 变化后，React 会让下面所有读这个 Context 的组件重新渲染，memo 拦不住，也不会只通知用到某个字段的组件。每次渲染都写 value={{ user, login }} 会让这件事频繁发生。为什么会这样、怎样用 useMemo 稳定 value、怎样拆分 Context，见《React Context 有哪些性能问题？怎样避免不必要的重新渲染？》；Context 配合 useReducer 管理状态，见《Context 与 useReducer 适合管理什么状态？》。

什么时候用 Context，什么时候传 props

React 文档建议先别急着用 Context。先试着直接传 props，即使要传好几层，数据流也一目了然。如果中间层只是转手，往往说明少抽了组件，可以让中间组件接收 children，比如把 <Layout posts={posts} /> 改成 <Layout><Posts posts={posts} /></Layout>，层数自然就少了。这两种都不合适时，再用 Context。

常见追问

useContext 能写在条件语句里吗？

不能，它和其他 Hook 一样只能在组件顶层调用。React 19 新增的 use API 也能读取 Context，而且可以写在 if 和循环里，适合只在某个分支里才需要 Context 的情况。

为什么组件读不到 Provider 提供的值？

常见原因有三个。Provider 和 useContext 写在了同一个组件里，或者 Provider 在它下面；Provider 根本没包住这个组件；或者构建工具的问题（比如用了符号链接）让 Provider 和 useContext 拿到的是两个不同的 Context 对象。

Context 适合放什么数据？

适合放变化不频繁、很多组件都要用的数据，比如主题、语言、当前登录用户、路由信息。只有一两层的数据直接传 props 更清楚。高频变化的数据，比如输入框内容、拖拽坐标，放进 Context 会让大量组件跟着重新渲染，更适合放在局部 state 里。
