JavaScript 的值类型与相等比较应该怎样理解？

JavaScript 有 7 种原始类型，其他都是对象。原始值比较的是值，对象比较的是是不是同一个。===、Object.is 都不转换类型，区别只在 NaN 和正负零；== 会先转换类型再比。

参考答案

简答

JavaScript 的原始类型有 7 种：undefined、null、boolean、number、bigint、string、symbol，除此之外都是对象。

原始值比较的是值本身，对象比较的是身份，也就是是不是同一个对象。两个属性完全一样的对象，只要不是同一个，就不相等。

不转换类型的比较有三种，区别只在两个特殊值上。=== 认为 NaN 不等于自己，+0 等于 -0。Object.is 正好相反，NaN 等于自己，+0 和 -0 不相等。Map、Set、includes 用的是 SameValueZero，NaN 等于自己，+0 也等于 -0。

== 会先按规则转换类型再比较，结果很难记，所以日常都用 ===。语言也没有内置任何一种深度比较。

下面用代码确认表里关于 NaN 和正负零的几格：

JavaScript
console.log(NaN === NaN); // false
console.log(Object.is(NaN, NaN)); // true
console.log(Object.is(+0, -0)); // false
console.log(new Set([NaN, NaN, +0, -0]).size); // 2

NaN === NaN 是 false，这是浮点数标准规定的。Set 里放了四个值，最后只剩 2 个，因为 SameValueZero 认为两个 NaN 相同，+0 和 -0 也相同。

所以判断一个值是不是 NaN，不能用 ===，要用 Number.isNaN。全局的 isNaN 也不可靠，它会先把参数转成数字，isNaN('abc') 也是 true。

对象为什么按身份比较

JavaScript
const first = { count: 1 };
const second = { count: 1 };
const alias = first;

console.log(first === second); // false
console.log(first === alias);  // true
alias.count = 2;
console.log(first.count);      // 2

first 和 second 内容一模一样，比较结果却是 false，因为它们是两个不同的对象。alias = first 没有复制对象，只是让 alias 也指向同一个对象，所以它们相等，通过 alias 改了属性，first 也能看到。

这也解释了为什么 new Set([{ id: 1 }, { id: 1 }]) 有两项。想按业务 ID 去重，就把 ID 取出来作为键。

函数传参也是这个道理。参数是按值传递的，只是对象的“值”就是对它的引用。所以函数里改参数对象的属性，调用方能看到；函数里给参数重新赋值，只是让参数指向了别的东西，调用方的变量不变。

== 会怎样转换类型

JavaScript
console.log(0 == '');       // true
console.log(false == '0');  // true
console.log([] == false);  // true
console.log([] == []);     // false

== 的规则大致是：布尔值先转成数字，字符串和数字比较时把字符串转成数字，对象和原始值比较时先把对象转成原始值。

所以 [] == false 的过程是：false 转成 0，[] 转成原始值是空字符串，空字符串再转数字也是 0，结果相等。可是 Boolean([]) 是 true，空数组明明是真值，却“等于” false，这就是 == 让人困惑的地方。两边都是对象时不转换，只看身份，所以 [] == [] 是 false。

因此日常都用 ===。唯一常见的有意用法是 value == null，它能同时匹配 null 和 undefined。

typeof 有哪些特例

typeof null 的结果是 'object'，这是早期实现留下的错误，一直没改。函数返回 'function'，数组却返回 'object'，判断数组要用 Array.isArray。还有 new Boolean(false) 创建的是一个对象，对象都是真值，所以它在条件判断里是真。

怎样判断两个对象内容相同

语言没有内置深度比较，要自己写或者用库。写之前要想清楚很多规则：数组顺序算不算，Date 是不是比时间值，Map 和 Set 怎么比，碰到循环引用怎么办，原型要不要一样。

用 JSON.stringify 比较看起来简单，但属性顺序不同结果就不同，而且会丢掉 undefined、函数这些值。业务数据如果有稳定的 ID，直接比 ID 最可靠。

常见追问

“原始值存在栈上、对象存在堆上”这种说法对吗？

这是引擎内部怎么实现的问题，语言规范没有这么规定，规范只规定了能观察到的行为，比如对象按身份比较。面试时可以说这是常见的实现方式，但不是语言规则。

原始值不可变是什么意思？

原始值本身不能被修改。比如写 str[0] = 'x'，字符串不会变。给变量赋一个新字符串，是让变量换了一个值，原来的字符串并没有被改。
