:has() 怎样根据后代或相邻元素设置样式？

:has() 以当前元素为锚点检查相对选择器是否匹配，匹配后选中的仍是当前元素。它既能表达包含某个后代，也能表达后面紧接某个兄弟元素等关系。

参考答案

普通的 .card img 选择卡片里的图片；.card:has(img) 选择里面存在图片的卡片。变化的关键不只是“往上找父元素”，而是可以用一个元素与周围元素的关系，决定要不要选中它自己。

:has() 括号里写的是相对选择器，以括号外面的元素为锚点。例如 .card:has(> img) 中，> img 从当前卡片出发寻找直接子图片；满足条件后，被设置样式的仍然是 .card。

不同组合符表达不同关系

选择器选中了谁
.card:has(img)任意深度后代中有图片的卡片
.card:has(> img)直接子元素中有图片的卡片
h2:has(+ p)后面紧接着一个同级段落的二级标题
li:has(~ li.active)后续兄弟中存在活动列表项的列表项

h2:has(+ p) 能用来调整标题与紧随正文之间的距离，它没有选择 p，也没有要求 p 是 h2 的子元素。因此把 :has() 只叫作“父选择器”会漏掉相邻、后续兄弟等用法。

让原生选项的状态带动整张卡片

以前要给选中的套餐卡片加边框，常见做法是监听单选框变化，再用 JavaScript 同步一个 .selected 类。现在可以直接查询单选框状态：

HTML
<fieldset class="plans">
  <legend>选择学习节奏</legend>
  <label class="plan">
    <input type="radio" name="pace" value="daily" checked />
    <span>每天一题</span>
  </label>
  <label class="plan">
    <input type="radio" name="pace" value="weekly" />
    <span>每周专题</span>
  </label>
</fieldset>
CSS
.plan {
  display: flex;
  align-items: center;
  gap: 0.5rem;
  padding: 1rem;
  margin-block: 0.5rem;
  border: 2px solid #cbd5e1;
  border-radius: 0.5rem;
}

.plan:has(> input:checked) {
  border-color: #1d4ed8;
  background: #eff6ff;
}

.plan:has(> input:focus-visible) {
  outline: 2px solid #1d4ed8;
  outline-offset: 3px;
}

原生单选框仍然提供互斥选择、表单值和键盘交互，:has() 只让卡片外观跟随这些真实状态。用户用鼠标点标签，或者通过键盘切换选项，都无需额外维护一份“选中卡片”的样式状态。

这里保留了单选框本身。即便目标浏览器不支持 :has() 而忽略增强规则，仍能通过单选框判断选中状态；不能先把原生控件完全隐藏，再让必要反馈只依赖某个选择器。

“有任意一个”和“两个都要有”怎样写

.card:has(img, video) 中的逗号表示或：有图片或者有视频就匹配。.card:has(img):has(video) 则要求两个条件同时成立，图片和视频可以在不同后代分支中。

否定的位置也会改变含义：

  • .card:not(:has(img))：卡片没有图片后代。
  • .card:has(:not(img))：卡片至少有一个不是图片的后代。

一张同时包含图片和段落的卡片不满足第一条，却满足第二条，因为段落不是图片。空卡片满足第一条，但不满足第二条，因为它根本没有后代。

不能把 :has() 再嵌套进另一个 :has()。例如要找“包含带图片文章的区块”，应根据真实关系写成 section:has(article img) 等合法选择器，而不是 section:has(article:has(img))。伪元素如 ::before 也不能按普通后代元素放进 :has() 查询。

权重和性能不能忽略

:has() 的特异性贡献取参数列表中最高的那一个。.card:has(.cover, #hero) 中，.card 贡献一个类，参数里的 #hero 贡献一个 ID，合计为 1-1-0。即便当前卡片只是因为含有 .cover 而匹配，参数中的 ID 仍然影响这条选择器的权重。

如果希望整条默认样式容易覆盖，可以按设计使用 :where(.card:has(...)) 把这一部分特异性归零，而不是不断给业务覆盖规则叠加 class。

浏览器需要在相关 DOM 或状态改变后更新匹配结果。:has() 并非天然不能用于动态页面，但 body:has(...)、*:has(...) 等过宽锚点可能扩大需要检查的范围。明确到具体组件，关系明确时使用 >、+ 等限制，再用真实交互测量样式计算成本，比一律禁用或一律替代 JavaScript 更合理。

它很适合让样式响应结构、选中态和焦点态；业务中的权限、库存、异步提交结果仍应由数据与程序管理，不能把 CSS 匹配当成业务规则的唯一实现。
