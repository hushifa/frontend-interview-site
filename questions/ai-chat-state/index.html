AI 聊天界面为什么不能只有 loading 一个状态？

AI 对话要分别表达等待首字、流式接收、完成、中断、失败和工具待审批。按请求、消息、片段分层建模并使用稳定 ID，才能处理停止、重试和迟到事件。

参考答案

简答

  • 一个 loading 分不清等待首字、正在输出、等待工具审批、用户已停止和中途失败，而这几种状态下用户能做的事不同。
  • 按请求、消息、片段三层建模：请求有生命周期，消息由多个片段组成，片段可以是文本、工具调用或引用。
  • 只有收到协议的正常结束事件才标记完成；断线或停止后保留的文字要标成不完整。
  • 每次尝试有新的请求 ID，旧请求的迟到事件不能写进当前消息。
  • 用户向上翻阅时暂停自动滚动；读屏器按段落或状态播报，不逐 token 播报。

状态怎样分层

以 Vercel AI SDK 的 useChat 为例，它的 status 有四个值：submitted（已发送，等待响应流开始）、streaming（正在接收）、ready（完成，可发下一条）、error。消息内容放在 parts 数组里，按 type 区分文本、推理、文件、来源和工具调用。

这四个值描述的是请求层。业务还需要更细的信息：

TypeScript
type Generation = {
  requestId: string; // 每次尝试一个新 ID
  messageId: string;
  phase: 'submitted' | 'streaming' | 'finished' | 'stopped' | 'failed';
};

type Part =
  | { id: string; type: 'text'; text: string; complete: boolean }
  | {
      id: string;
      type: 'tool';
      callId: string;
      phase: 'receiving-args' | 'needs-approval' | 'executing' | 'succeeded' | 'failed';
    };

请求还在 streaming 时，某个工具片段已经 succeeded 是正常情况，所以不要把所有状态压成一个全局字段。工具片段的确认和执行流程见《模型提出工具调用后，前端应该怎样展示和确认？》。

状态转换规则

  • 发送后进入 submitted，显示"等待回复"和停止按钮。
  • 收到第一个可展示片段进入 streaming。
  • 收到协议的结束事件才进入 finished。连接 EOF、用户停止、服务端报错分别进入 stopped 或 failed，已收到的文字保留并标注"未完成"。
  • 每个增量事件按 requestId 和片段 ID 定位目标；requestId 不是当前请求的事件直接丢弃。

重试与重复任务

用户没看到首字就点重试时，服务端可能已经开始生成，再发一次会产生第二个任务。重试要带上原任务 ID 或幂等键，由服务端决定是复用还是新建。断线后怎样接回同一个任务，见《AI 流式输出断线后，怎样恢复同一条生成任务？》。

滚动和无障碍

  • 用户停在底部时跟随输出；向上滚动后停止跟随，并显示"有新内容"按钮。
  • 不要每个 token 都触发滚动和布局测量，可以按帧合并更新。
  • 读屏器用 live region 播报阶段变化（开始回答、回答完成、需要确认），不要逐字播报。
  • 停止、重试、批准按钮的可访问名称保持稳定，内容更新时不移动焦点。

常见追问

  • 停止按钮什么时候可用？ submitted 和 streaming 时都可用，等待首字时用户也可能想取消。停止对服务端的影响见《点击“停止生成”后，服务端一定停止调用模型吗？》。
  • 测试要覆盖哪些情况？ 首字前取消、流中出错、停止后迟到增量、快速重试、切换会话、工具待审批。
