React useId 解决什么 ID 生成问题？

用 useId 生成 SSR 与客户端一致的关联 ID，理解它不适合做列表 key 或业务唯一标识。

参考答案

useId 用于生成组件内部需要关联的 ID，例如 label 与 input、描述文本与控件的 htmlFor/aria-describedby。它能在服务端渲染和客户端 hydration 中保持匹配。

它不是数据库 ID、业务实体 ID，也不适合作为列表 key；列表 key 应来自数据本身。不要把生成的 ID 暴露为跨请求或持久化协议的一部分。

重复使用组件时可以基于一个 ID 拼接多个相关元素，但要保持组件实例之间的隔离。服务端和客户端的组件树结构变化仍可能导致 hydration 问题。

React 题目需要分清渲染阶段、提交阶段、事件处理和副作用。状态更新可能合并或排队，组件也可能重新渲染多次；不要把“函数执行了一次”直接等同于“页面只更新了一次”。

实际设计时先确定状态的唯一来源，再决定是局部状态、Context、外部 store 还是服务端数据。清理订阅、请求和定时器，并用目标 React 版本的文档核对新 API 的约束。

实际组件中，最难排查的通常不是某个 Hook 的语法，而是状态来源重复和副作用没有清理。把服务端数据、用户输入和派生显示值分开，组件会更容易测试，也不容易在重新渲染后产生重复请求。
