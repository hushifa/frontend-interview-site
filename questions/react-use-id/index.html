React useId 解决什么 ID 生成问题？

useId 给每个组件实例生成一个唯一的 ID，而且服务端和客户端生成的一样，主要用来把 label、提示文字和输入框关联起来。它不能当列表 key，也不适合当业务 ID 或 CSS 选择器。

参考答案

简答

写表单时，<label htmlFor>、aria-describedby 都要指向某个元素的 id。可组件会被复用，页面上放两个同样的输入框，写死的 ID 就重复了。const id = useId() 给当前组件实例返回一个专属的字符串，同一个组件渲染多份也各不相同。

它比自增计数器、Math.random() 强的地方在于服务端渲染。只要服务端和客户端的组件树结构一致，两边生成的 ID 就一样，hydration 时不会对不上。hydration 就是浏览器拿到服务端的 HTML 后，React 接管页面的过程。

它主要用来把元素关联起来，比如 htmlFor、aria-describedby、aria-labelledby、aria-controls，让屏幕阅读器读得对。一个组件要多个 ID 时，只调一次，再拼后缀。

要注意，它不能用来生成列表 key，key 应该来自数据本身。它生成的格式也会随版本变，别拿它写 CSS 选择器。

一个密码输入框

下面的组件要把 label、提示文字和错误信息都跟输入框关联起来：

JSX
import { useId } from 'react';

function PasswordField({ error }) {
  const id = useId();
  const hintId = `${id}-hint`;
  const errorId = `${id}-error`;

  return (
    <div>
      <label htmlFor={id}>密码</label>
      <input
        id={id}
        type="password"
        aria-describedby={error ? `${hintId} ${errorId}` : hintId}
        aria-invalid={Boolean(error)}
      />
      <p id={hintId}>至少 8 位，包含字母和数字</p>
      {error && <p id={errorId} role="alert">{error}</p>}
    </div>
  );
}

只调用了一次 useId，另外两个 ID 是拼后缀得到的。页面上放两个 PasswordField，每个实例拿到的 id 不同，后缀拼出来的也不同，互不冲突。屏幕阅读器聚焦到输入框时，就能读出它自己那一份提示。

为什么不用计数器

用一个全局计数器 let n = 0，每次 n++ 当 ID，看起来也唯一。问题出在服务端渲染上：服务端渲染时数到了几，浏览器重新执行时不一定数到同样的数，比如服务端处理过别的请求，计数器早就不是 0 了。两边 ID 不一样，hydration 就会不匹配。Math.random() 更是每次都不同。

useId 不靠计数，它根据组件在树里的位置生成 ID。只要两边的树结构一样，结果就一样。

ID 长什么样

具体格式是 React 内部实现，会随版本变化。19.0 是 :r: 这种形式，19.1 改成了 «r»，19.2 又改成了 _r_，后者可以直接用于 view-transition-name 和 XML 名称。所以不要依赖格式，也不要拿它写 CSS 选择器。

一个页面有多个 React 根

同一个页面上有几个独立的 React 根时，它们各自生成的 ID 可能重复。可以用 createRoot 或 hydrateRoot 的 identifierPrefix 选项给每个根设置不同的前缀。服务端渲染时，两端要用相同的前缀。

常见追问

为什么不能拿它做列表 key？

useId 的值取决于组件在树里的位置，而 key 要在列表重排时跟着数据走。一个绑位置、一个绑数据，目的正好相反。

组件外面也要用这个 ID 怎么办？

在父组件里调用 useId，再通过 props 传给需要的子组件。
