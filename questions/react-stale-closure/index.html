React 中的过期闭包为什么会读到旧状态？

每次渲染创建的函数都捕获了那一次渲染的 props 和 state。如果某个函数被保存下来（计时器、订阅、依赖数组不完整的 Effect），之后调用时读到的仍是创建时的旧值。修复方式取决于需求：函数式更新、补全依赖、useEffectEvent 或 ref。

参考答案

简答

  • 组件函数每次渲染都重新执行，其中定义的函数通过闭包捕获这一轮的 props 和 state。
  • 函数被长期保存后（例如 setInterval 回调、事件订阅、useCallback 依赖不完整），后续调用读到的是它创建那一轮的值，这就是过期闭包。
  • 只需要基于前值计算新状态时，用函数式更新 setCount(c => c + 1)，回调不必读 count。
  • 需要读到最新值并且值变化时应重新同步，把它补进依赖数组。
  • 需要读最新值但不想因它重新订阅，用 useEffectEvent（React 19.2 起稳定）；在事件之外保存最新值也可以用 ref。

典型问题

JSX
function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1); // count 永远是 0
    }, 1000);
    return () => clearInterval(id);
  }, []); // 缺少 count 依赖

  return <span>{count}</span>;
}

Effect 只在挂载时执行一次，回调捕获的 count 是 0，所以显示停在 1。

三种修复

函数式更新，最适合这个场景：

JSX
useEffect(() => {
  const id = setInterval(() => setCount((c) => c + 1), 1000);
  return () => clearInterval(id);
}, []);

补全依赖，代价是每次 count 变化都会重建计时器：

JSX
useEffect(() => {
  const id = setInterval(() => setCount(count + 1), 1000);
  return () => clearInterval(id);
}, [count]);

useEffectEvent，用于读取不该触发重新同步的值：

JSX
import { useEffect, useEffectEvent } from 'react';

function Ticker({ step }) {
  const [count, setCount] = useState(0);
  const onTick = useEffectEvent(() => setCount((c) => c + step));

  useEffect(() => {
    const id = setInterval(onTick, 1000);
    return () => clearInterval(id);
  }, []);
  // 修改 step 时不重建计时器，下一次 tick 使用新的 step
}

用 ref 保存最新值

不在 Effect 中的场景，例如传给第三方库、只注册一次的回调：

JSX
const latestQuery = useRef(query);
useEffect(() => {
  latestQuery.current = query;
});

useEffect(() => {
  return editor.on('save', () => submit(latestQuery.current));
}, [editor]);

ref 在 Effect 中更新，不要在渲染期间写 ref.current。

不要用删依赖来"修复"

为了让 Effect 少执行而删掉依赖，会把过期闭包变成隐藏 bug。开启 eslint-plugin-react-hooks 的 exhaustive-deps 规则，让工具检查依赖是否完整。

常见追问

  • 事件处理器会有过期闭包吗？一般不会，每次渲染都会传入新的处理器。异步处理器在 await 之后读到的仍是点击时那一轮的值，这是快照语义，通常正是想要的。
  • 详细的快照规则见《为什么调用 setState 后，当前变量还是旧值？》。
