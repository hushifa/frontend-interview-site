React 中的过期闭包为什么会读到旧状态？

每次渲染创建的函数，记住的都是那一次渲染的 props 和 state。函数被定时器、订阅或依赖不全的 Effect 留下来，以后再调用时读到的还是当时的旧值。改法看需求：函数式更新、补全依赖、useEffectEvent 或 ref。

参考答案

简答

React 每渲染一次，就把组件函数重新执行一遍。这一遍里定义的函数，通过闭包记住的是这一遍的 props 和 state。

如果这个函数被长期保存下来，比如 setInterval 回调、事件订阅，或者 useCallback、useEffect 的依赖没写全，那之后不管过多久调用它，读到的都是它创建那一次的值。这就叫过期闭包。

怎么改要看你想要什么。只是根据旧值算新值，用函数式更新 setCount(c => c + 1)，回调根本不用读 count。值变了确实应该重新同步，就把它补进依赖数组。想读最新值、又不想因为它重新订阅，用 useEffectEvent，它从 React 19.2 起稳定。不在 Effect 里的场景，也可以用 ref 保存最新值。

最不该做的是为了少执行几次就删依赖，那只是把过期闭包藏了起来。

先看一个停住的计时器

下面的计时器想每秒加 1，结果数字到 1 就不动了：

JSX
function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1); // count 永远是 0
    }, 1000);
    return () => clearInterval(id);
  }, []); // 缺少 count 依赖

  return <span>{count}</span>;
}

依赖数组是 []，Effect 只在挂载时跑一次，定时器回调也只在那时创建了一次。创建它的那次渲染里 count 是 0，它就一直记着这个 0。

之后组件确实重新渲染了，也有了值为 1 的新 count，可是那是另一次渲染里的另一个变量，旧回调看不到。所以它每秒执行的都是 setCount(0 + 1)。闭包的原理可以看《什么是闭包？它有哪些实际应用？》。

三种改法

如果只是想基于旧值加 1，函数式更新最合适。回调不读外面的 count，由 React 把最新值传进来：

JSX
useEffect(() => {
  const id = setInterval(() => setCount((c) => c + 1), 1000);
  return () => clearInterval(id);
}, []);

也可以老老实实补上依赖。这样每次 count 变化，Effect 都会清掉旧定时器、用新的 count 建一个新的。能用，但定时器反复重建：

JSX
useEffect(() => {
  const id = setInterval(() => setCount(count + 1), 1000);
  return () => clearInterval(id);
}, [count]);

第三种场景是：回调要读某个值的最新版本，但这个值变了不应该重建定时器。这时用 useEffectEvent：

JSX
import { useEffect, useEffectEvent } from 'react';

function Ticker({ step }) {
  const [count, setCount] = useState(0);
  const onTick = useEffectEvent(() => setCount((c) => c + step));

  useEffect(() => {
    const id = setInterval(onTick, 1000);
    return () => clearInterval(id);
  }, []);
  // 修改 step 时不重建计时器，下一次 tick 使用新的 step
}

onTick 每次被调用时都能读到最新的 step，而且它不用写进依赖数组，所以改 step 不会重建定时器。

不在 Effect 里时用 ref

有些回调是交给第三方库、只注册一次的，这时可以用 ref 存最新值：

JSX
const latestQuery = useRef(query);
useEffect(() => {
  latestQuery.current = query;
});

useEffect(() => {
  return editor.on('save', () => submit(latestQuery.current));
}, [editor]);

ref 是同一个对象，每次渲染后 Effect 都把最新的 query 写进 current。回调读的是 latestQuery.current，不是某一次渲染的 query，所以总是新的。注意要在 Effect 里更新 ref，不要在渲染期间写 ref.current。

为什么不能靠删依赖来解决

删掉依赖，Effect 确实少执行了，可它里面用到的值就再也不会更新，过期闭包从明面上的警告变成了藏起来的 bug。打开 eslint-plugin-react-hooks 的 exhaustive-deps 规则，让工具检查依赖是否写全。

常见追问

事件处理器会有过期闭包吗？

一般不会，因为每次渲染都会给按钮传一个新的处理器。但异步处理器在 await 之后读到的，仍然是点击那一次渲染的值。这是快照语义，通常正是你想要的。
