GitHub Actions 中 workflow、job、step 和 runner 是什么关系？

用前端检查流程解释自动化层级、执行环境和数据传递，区分顺序、缓存与产物，并说明检查成功不等于已经部署。

参考答案

可以把 workflow 看成一份自动化流程说明，job 是其中可独立调度的任务，step 是任务内部的执行步骤，runner 则是实际运行这些步骤的机器或执行环境。

例如一次推送触发“检查前端” workflow，它安排一个检查 job，在 Linux runner 上依次检出代码、准备 Node、安装依赖、测试和构建。

四层对象各负责什么

对象作用
workflow定义触发事件、任务及整体配置，通常位于 .github/workflows
job组织一组步骤，并决定执行环境与任务依赖
step运行 shell 命令，或通过 uses 调用可复用 action
runner执行任务，提供操作系统、工具、文件系统和计算资源

同一个 job 中的步骤通常顺序执行并共享相应工作目录，但每个 run 步骤是独立的 shell 过程。上一步创建的文件可以继续使用，普通 shell 局部变量却不会自动变成下一步的环境变量。

一个只检查、不发布的例子

下面假设项目已经定义 format:check、check 和 build 脚本，并提交了 npm 锁文件：

yaml
name: 前端检查

on: [push, pull_request, workflow_dispatch]

permissions:
  contents: read

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - name: 检出代码
        uses: actions/checkout@v7
      - name: 准备 Node
        uses: actions/setup-node@v7
        with:
          node-version: '22'
          cache: npm
      - name: 安装与检查
        run: |
          npm ci
          npm run format:check
          npm run check
          npm run build

workflow_dispatch 允许手动触发；push 和 pull_request 对应仓库事件。uses 复用 action，run 执行命令，二者不是不同类型的 runner。

例子固定了 Node 主版本，不等于固定精确补丁版本；ubuntu-latest 镜像也会更新。要求更强复现时，还应按项目需要明确版本文件、工具和环境。action 的主版本标签同样可能更新，要求固定具体实现时可以使用审核过的提交 SHA。

Job 之间怎样决定先后

没有声明依赖的 job 可以并行调度，是否立即执行还受可用 runner 和并发限制影响。需要先检查后部署时，应通过 needs 等机制表达关系，而不是依赖它们在 YAML 中的排列顺序。

GitHub 托管 runner 通常为 job 提供新的环境；自托管 runner 的持久状态与清理策略又由维护者负责。无论哪种，都不要假设另一个 job 的本地目录一定还能直接访问。

跨 job 传文件通常使用 artifact，传少量值可以使用相应输出机制。配置 needs 只建立执行依赖，不会顺便把前一个 job 的文件复制过来。

缓存与构建产物不能混用

缓存主要用于加速，例如复用包管理器的下载缓存。setup-node 的 npm 缓存不等于把一份永远正确的 node_modules 带到所有任务中，依赖安装仍需要执行并检查锁文件。

artifact 则用于保存和传递这次任务产生的文件，例如 dist 或测试报告。部署若要使用已经验证的产物，应明确取得同一次构建的 artifact，而不是在另一个步骤中悄悄用不同环境重新生成。

缓存命中也不等于构建正确，缓存键和失效条件不合理时反而可能保留旧结果。

绿色检查不代表网站已经上线

上面的流程只证明相应命令成功，没有配置部署任务，所以不会自动发布网站。真正发布还需要明确目标环境、所需权限、产物来源和发布后的验证。

PR 检查与正式发布可以具有不同权限。来自外部分支的代码、秘密变量和可写令牌，应按平台事件与权限模型分别设计，不能把一个部署配置无条件用于所有来源的检查。

排查失败时沿着 workflow run、job、具体 step 和日志定位。先区分没有触发、等待 runner、环境准备失败、命令失败或部署失败，通常比把所有情况统称为“Actions 坏了”更容易解决。
