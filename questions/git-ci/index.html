GitHub Actions 中 workflow、job、step 和 runner 是什么关系？

workflow 定义自动化流程，通过 push、pullrequest、手动触发等事件启动。一个流程包含多个 job，每个 job 在 runner 上执行一组 step；step 可以运行命令或复用 action。

参考答案

workflow 定义自动化流程，通过 push、pull_request、手动触发等事件启动。一个流程包含多个 job，每个 job 在 runner 上执行一组 step；step 可以运行命令或复用 action。

job 之间默认具有独立执行环境，依赖顺序通过 needs 等机制声明。需要跨 job 传递文件时使用产物等机制，不能假设上一个 runner 的本地目录仍然存在。

前端常见流程包括锁定依赖安装、格式检查、类型检查、测试和构建。发布应使用所需的最小权限，并区分检查和真正部署。缓存用于加速，构建产物用于交付，二者目的不同。

交付时检查

发布流程要区分源码、构建产物和部署环境，并在提交前固定依赖和构建参数。每次发布都应能找到对应提交、产物和验证结果，失败时可以回到上一个可用版本。

自动化任务遵循最小权限，缓存只用于加速，产物才是交付对象。部署后还要检查 HTML、静态资源、规范网址、Sitemap 和关键页面，而不是只看流水线是否显示成功。
