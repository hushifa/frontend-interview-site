Intl.DisplayNames 怎样本地化语言、地区和货币名称？

Intl.DisplayNames 能把 fr、JP、EUR 这样的代码翻译成当前语言的名称，按 type 区分语言、地区、文字、货币等。名称来自运行时的 CLDR 数据，只用于展示，存储和提交仍用代码，并要想好 fallback 行为。

参考答案

简答

页面上要显示“法语”“日本”“欧元”，而数据里存的是 fr、JP、EUR 这样的代码。Intl.DisplayNames 就是干这个的：构造时给出显示语言和 type，再调用 of(code) 拿到名称。type 可以是 language、region、script、currency、calendar、dateTimeField。

这些名称不用自己维护翻译表，因为浏览器和 Node.js 自带了 CLDR 数据。可是数据版本不同，名称也可能不同，所以名称只拿来显示，存储和接口里传的始终是代码。

认不出的代码怎么办，要提前想好。默认 fallback: 'code'，会原样返回代码；设成 'none' 就返回 undefined，交给应用自己处理。代码格式本身不合法，比如地区写成 123x，会直接抛 RangeError。

还有两点要注意。同样配置的实例要缓存复用；SSR 时服务端和客户端要用同一个 locale 创建，否则文字不一样，水合会对不上。

先看基本用法

下面分别取地区、语言和货币的中文名称，最后一行换成英文显示。

JavaScript
const region = new Intl.DisplayNames('zh-CN', { type: 'region' });
const language = new Intl.DisplayNames('zh-CN', { type: 'language' });
const currency = new Intl.DisplayNames('zh-CN', { type: 'currency' });

region.of('TW'); // 台湾（Node 22 实测）
language.of('fr'); // 法语
language.of('zh-Hant'); // 繁体中文
currency.of('EUR'); // 欧元
new Intl.DisplayNames('en', { type: 'region' }).of('JP'); // Japan

同一个 of()，传什么代码就翻译什么，显示成哪种语言由构造时的第一个参数决定。

这些名称来自 CLDR，也就是 Unicode 维护的一套各国语言习惯数据。地区名称尤其容易受数据影响。产品对某些名称有特定要求时，准备一张自己的覆盖表，优先用表里的写法，查不到再用 of() 的结果。

代码格式本身不合法时，of() 会直接抛错。比如 new Intl.DisplayNames('en', { type: 'region' }).of('123x') 抛的是 RangeError，调用处要有准备。

认不出的代码会返回什么

先看三种情况，结果可能和直觉不一样。

JavaScript
new Intl.DisplayNames('en', { type: 'region' }).of('XX'); // 'XX'
new Intl.DisplayNames('en', { type: 'region', fallback: 'none' }).of('XX'); // undefined
new Intl.DisplayNames('en', { type: 'language' }).of('xx-unknown'); // 'xx (UNKNOWN)'

XX 格式合法但没有对应地区。默认设置下它原样返回 'XX'，界面上不会报错，但用户看到的是一串代码。改成 fallback: 'none' 后返回 undefined，应用就能自己决定显示什么。

第三行最容易让人误会。xx-unknown 的语法是合法的，运行时把它解析成“语言 xx 加上变体 unknown”（new Intl.Locale('xx-unknown').region 是 undefined），然后拼出了一个名称，所以根本没走到“返回代码”那一步。因此，想判断“是不是真的认识这个代码”，要用 fallback: 'none'，再检查结果是不是 undefined。

语言名称有两种风格

同一个 en-GB，有两种说法。

JavaScript
new Intl.DisplayNames('en', { type: 'language' }).of('en-GB'); // British English
new Intl.DisplayNames('en', { type: 'language', languageDisplay: 'standard' }).of('en-GB');
// English (United Kingdom)

默认是方言风格，直接说“British English”。languageDisplay: 'standard' 改成“语言（地区）”的标准写法。

做语言切换菜单时，通常让每个选项用它自己的语言显示，例如“日本語”“English”。因为来切换语言的人，往往正是看不懂当前界面语言的人，他得能认出自己的语言。

生成下拉选项

下面把一组语言代码变成选项列表，并按当前界面语言排序。

JavaScript
function createLanguageOptions(codes, uiLocale) {
  const names = new Intl.DisplayNames(uiLocale, { type: 'language', fallback: 'none' });
  return codes
    .map((code) => ({ value: code, label: names.of(code) ?? code }))
    .sort((a, b) => a.label.localeCompare(b.label, uiLocale));
}

value 存代码，label 只用于显示。用了 fallback: 'none'，认不出的代码由 ?? code 兜底，这一步是应用自己决定的。

实例要缓存，SSR 要统一 locale

创建实例要加载语言数据，所以同样的 locale 和 type 缓存一个实例反复用，不要每次渲染都新建。

SSR 时，服务端和客户端必须用同一个 locale 创建实例。否则服务端渲染出“法语”，客户端算出“French”，文字不同就会造成水合不一致。

常见追问

能用显示名称反查代码吗？

不能。名称不唯一，还会随数据版本变化。所以选项的值要一直保留代码，名称只管显示。

阿拉伯语的名称怎么显示？

new Intl.DisplayNames('ar', { type: 'language' }).of('en') 返回的是阿拉伯文。把它嵌到其他语言的页面里时，要设置 dir="auto" 或者用 <bdi> 把方向隔离开，否则会影响周围文字的排列。
