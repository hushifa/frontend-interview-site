Custom Elements、Shadow DOM 和 template 分别负责什么？

Custom Elements 定义可复用的自定义元素及生命周期；Shadow DOM 提供组件内部 DOM 和样式的封装边界；template 保存尚未直接渲染的片段，slot 用于内容分发。这些技术可以组合，也可以分别使用。

参考答案

Web Components 是一组可组合的浏览器能力，不是一个强制配套使用的框架。Custom Elements 解决自定义元素身份与生命周期，Shadow DOM 解决内部树和样式封装，template 保存可复用的惰性片段，slot 则让外部内容参与组件展示。

可以定义自定义元素而不使用 Shadow DOM，也可以给合适的普通元素附加 shadow root，不必先创建自定义类。

用一个小组件看各部分职责

JavaScript
const template = document.createElement('template');
template.innerHTML = `
  <style>
    :host { display: inline-block; padding: 4px 8px; border: 1px solid currentColor; }
    strong { margin-inline-end: 4px; }
  </style>
  <strong></strong><slot>未提供内容</slot>
`;

class InfoBadge extends HTMLElement {
  static observedAttributes = ['label'];

  constructor() {
    super();
    const root = this.attachShadow({ mode: 'open' });
    root.append(template.content.cloneNode(true));
  }

  connectedCallback() {
    this.updateLabel();
  }

  attributeChangedCallback() {
    this.updateLabel();
  }

  updateLabel() {
    this.shadowRoot.querySelector('strong').textContent = this.getAttribute('label') ?? '';
  }
}

customElements.define('info-badge', InfoBadge);

页面可以使用 <info-badge label="状态">已完成</info-badge>。自定义名称包含连字符，注册后浏览器按类定义管理元素；template 的内容不会自己出现在页面上，clone 后才放入组件内部。

模板字符串在这里是开发者固定内容，动态 label 使用 textContent 写入。不能把任意外部文本拼入 innerHTML，再以“组件封装”为理由忽略注入风险。

slot 分发内容，不是复制一份 DOM

例子中的“已完成”仍是宿主元素的 light DOM 子节点，通过 slot 参与显示。没有分配内容时才显示 slot 的后备文字。

命名 slot 可以提供标题、操作区等插槽。slotchange 关注分配节点变化，不是所有已分配节点内部文字和后代变化的通用通知；需要更细变化时仍应使用对应状态或观察方式。

封装不是绝对隔离

普通外部选择器不会随意穿透到 shadow tree，内部样式也通常不会直接污染外部。但继承属性、CSS 自定义属性、宿主样式和显式开放的 part 仍可形成主题接口。

closed 模式主要限制通过 element.shadowRoot 获取根，并不是安全沙箱，也不适合藏密钥。组件脚本仍在页面执行环境中，不能把它当作隔离不可信代码的边界。

跨 shadow 边界的事件还涉及 bubbles、composed 和事件目标重定向。设计公共自定义事件时，应明确是否允许穿越边界及 detail 的结构；使用者看到的 target 不一定是内部最深层节点。

生命周期可能重复发生

connectedCallback 不表示“整个对象只初始化一次”。元素被移除再插入时可能再次连接，应避免重复安装全局监听或启动重复计时器。disconnectedCallback 中释放连接期资源，再次连接时按需恢复。

constructor 适合建立自身基础结构，不应假设外部子节点和属性已经全部准备完。异步工作也要处理断开后的迟到结果，不能只靠 DOM 移除自动取消网络或订阅。

attribute 与 property 是两种接口

HTML attribute 主要提供字符串或存在性信息，JavaScript property 可以承载对象和其他类型。二者不会自动双向同步，应明确转换、默认值和反射规则，避免属性更新互相递归。

复杂表单组件还要处理表单值、校验、禁用、焦点和无障碍语义，必要时使用 ElementInternals 等能力。自定义元素本身不会自动拥有 button、input 的全部行为。

跨框架复用的价值在于公开稳定的元素、属性、方法与事件契约；状态管理、SSR、版本与样式主题仍需工程设计，不能因为使用原生标签就认为这些问题自然消失。
