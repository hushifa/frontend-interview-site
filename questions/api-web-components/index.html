Custom Elements、Shadow DOM 和 template 分别负责什么？

Custom Elements 定义新标签和它的生命周期，Shadow DOM 把组件内部的结构和样式隔离开，template 存一段不渲染的模板。三者合起来就是 Web Components，任何框架里都能用。

参考答案

简答

想写一个 <app-button>，在 React、Vue 和普通页面里都能用，就要靠浏览器原生的 Web Components。它由几样东西配合完成。

Custom Elements 负责“定义新标签”。customElements.define('app-button', Class) 注册以后，浏览器就认识这个标签，还会在它插入、移除、属性变化时调用 connectedCallback、disconnectedCallback、attributeChangedCallback。名字必须带连字符。

Shadow DOM 负责“隔离”。attachShadow({ mode: 'open' }) 给元素造一棵独立的 DOM 子树，外面的样式选不中里面的元素，里面的样式也漏不出去。<template> 负责“存模板”，内容会被解析，但不渲染、不执行脚本、不加载图片，用的时候 content.cloneNode(true) 复制一份。<slot> 在 Shadow DOM 里留个位置，显示使用者传进来的子元素。

组件和外界通过 attribute、JavaScript 属性和自定义事件通信。要注意事件想传出 Shadow DOM，得设置 composed: true。

写一个按钮组件

下面把三样东西放在一起：template 存结构和样式，Shadow DOM 隔离，Custom Elements 注册标签。

JavaScript
const template = document.createElement('template');
template.innerHTML = `
  <style>
    :host { display: inline-flex; gap: 4px; }
    :host([variant='danger']) button { background: crimson; color: white; }
  </style>
  <button part="button"><slot></slot></button>
`;

class AppButton extends HTMLElement {
  static observedAttributes = ['disabled'];

  constructor() {
    super();
    this.attachShadow({ mode: 'open' }).append(template.content.cloneNode(true));
    this.button = this.shadowRoot.querySelector('button');
  }

  attributeChangedCallback(name, oldValue, newValue) {
    if (name === 'disabled') this.button.disabled = newValue !== null;
  }

  connectedCallback() {
    this.button.addEventListener('click', this.#onClick);
  }

  disconnectedCallback() {
    this.button.removeEventListener('click', this.#onClick);
  }

  #onClick = () => {
    this.dispatchEvent(new CustomEvent('app-click', { bubbles: true, composed: true }));
  };
}

customElements.define('app-button', AppButton);
HTML
<app-button variant="danger">删除</app-button>

“删除”两个字是怎么显示到按钮里的？它是 app-button 的子元素，Shadow DOM 里的 <slot> 留了位置，就把它显示在 <button> 里面。

为什么 template 只创建一次？因为它是模板，每个实例 cloneNode(true) 复制一份就行，不用每次都重新解析 HTML。

observedAttributes 列出要监听的属性，只有列出来的属性变化时才会调用 attributeChangedCallback。属性被移除时 newValue 是 null，所以用 newValue !== null 判断是否禁用。

样式隔离了，主题怎么改

Shadow DOM 挡住了外部的选择器，但不是什么都挡。color、font 这类继承属性，以及 CSS 自定义属性（--xxx），都会穿透进来。所以给组件做主题，主要靠 CSS 自定义属性。

如果想让外部直接改某个内部元素，就给它加 part 属性，外部用 ::part(button) 选中。组件内部写样式时，:host 选中宿主元素本身，::slotted() 选中插槽里的顶层元素。

常见追问

事件怎样传出 Shadow DOM？

派发事件时设置 composed: true，事件才能跨出 Shadow DOM 边界。跨出去以后，外面看到的 event.target 会被重定向成宿主元素，看不到内部的按钮。

和 React、Vue 组件有什么区别？

Web Components 是浏览器原生的，不依赖任何框架。但它没有内置的响应式和模板绑定，状态变了要自己更新 DOM，所以通常会借助 Lit 这类库来写。

服务端渲染怎么办？

用声明式 Shadow DOM，把 Shadow Root 直接写进 HTML，见《Declarative Shadow DOM 适合解决什么问题？》。
