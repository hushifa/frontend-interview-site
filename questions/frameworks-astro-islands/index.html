Astro Islands 架构怎样减少客户端 JavaScript？

Astro 默认把组件在服务端渲染为 HTML，不发送 JavaScript；只有加了 client:* 指令的组件才作为"岛屿"在浏览器中加载和激活。岛屿彼此独立，可以使用不同框架。适合内容为主、交互局部化的站点。

参考答案

简答

  • 没有 client:* 指令的组件只在服务端（或构建时）渲染为 HTML，浏览器不会收到它的 JavaScript。
  • 加了指令的组件是交互岛屿，各自独立加载和 hydration。
  • 激活时机：client:load 页面加载时，client:idle 浏览器空闲时，client:visible 进入视口时，client:media 媒体查询匹配时，client:only 跳过服务端渲染只在客户端渲染。
  • 不同岛屿可以用 React、Vue、Svelte 等不同框架，但岛屿之间不共享 Context，需要通过外部 store、URL 或事件通信。
  • 适合博客、文档、营销页、电商详情页；整页高度交互、状态紧密耦合的应用，收益有限。

示例

astro
---
import Header from '../components/Header.astro';
import SearchBox from '../components/SearchBox.jsx';
import Comments from '../components/Comments.vue';
---

<Header />
<article>
  <h1>文章标题</h1>
  <p>正文是纯 HTML，不需要 JavaScript。</p>
</article>
<SearchBox client:load />
<Comments client:visible />
  • Header 和正文只输出 HTML。
  • SearchBox 页面一打开就可以用。
  • Comments 滚动到评论区时才下载代码并激活。

激活前的交互

岛屿激活之前，服务端渲染的 HTML 已经可见但还不能响应事件。延后激活的组件里如果放了重要按钮，用户点击可能没有反应。处理方式：

  • 首屏关键交互用 client:load。
  • 尽量让基础功能不依赖脚本，例如用真正的 <a> 链接和 <form> 提交。

岛屿之间共享状态

JavaScript
// store.js
import { atom } from 'nanostores';
export const cartCount = atom(0);

React 岛屿和 Vue 岛屿各自订阅同一个 store。Astro 官方文档推荐 Nano Stores 这类与框架无关的状态库。

服务器岛屿

server:defer 指令让某个组件在页面主体之外单独在服务端渲染，例如个性化的用户头像，页面其余部分可以被缓存。它需要服务端运行时，纯静态托管无法使用。

常见追问

  • 和 SSR + 全量 hydration 有什么区别？传统 SSR 框架会在客户端激活整个页面的组件树；Islands 只激活标记的部分，其余部分的组件代码根本不会发到浏览器。
  • 多个框架会让体积变大吗？会，每种框架的运行时都要下载，应尽量统一。
