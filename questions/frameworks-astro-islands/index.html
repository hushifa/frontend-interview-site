Astro Islands 架构怎样减少客户端 JavaScript？

Astro 默认把组件在服务端渲染为 HTML，不发送 JavaScript；只有加了 client:* 指令的组件才作为“岛屿”在浏览器中加载和激活。岛屿彼此独立，可以使用不同框架。适合内容为主、交互局部化的站点。

参考答案

简答

想象一个页面大部分是静态的文字和图片，只有搜索框、评论区这几块需要交互。Astro 的做法是：整页都在服务端或构建时渲染成 HTML，默认一行 JavaScript 都不发；只有加了 client:* 指令的组件，才会在浏览器里加载代码并激活。这些能交互的小块就叫岛屿。

每个岛屿独立加载、独立 hydration，激活时机由指令决定：client:load 页面加载时，client:idle 浏览器空闲时，client:visible 进入视口时，client:media 媒体查询匹配时。client:only 比较特殊，它跳过服务端渲染，只在客户端渲染。

岛屿之间互相独立，所以可以一个用 React、一个用 Vue。代价是它们不共享 Context，要通信得靠外部 store、URL 或者事件。

所以它适合博客、文档、营销页、电商详情页这种内容为主的站点。如果整个页面都是交互、状态紧密耦合，收益就有限了。

先看一个页面

astro
---
import Header from '../components/Header.astro';
import SearchBox from '../components/SearchBox.jsx';
import Comments from '../components/Comments.vue';
---

<Header />
<article>
  <h1>文章标题</h1>
  <p>正文是纯 HTML，不需要 JavaScript。</p>
</article>
<SearchBox client:load />
<Comments client:visible />

Header 和正文没有指令，只输出 HTML，浏览器不会收到它们的组件代码。SearchBox 用了 client:load，页面一打开就加载，马上能用。Comments 用了 client:visible，用户滚到评论区时才去下载代码并激活，没滚到就一直不加载。

激活之前点了会怎样

岛屿激活之前，它的 HTML 已经能看到了，但还不能响应事件。所以如果把一个重要按钮放进延后激活的组件里，用户点了可能没反应。

处理办法有两个。首屏的关键交互用 client:load，不要延后。另外尽量让基础功能不依赖脚本，比如用真正的 <a> 链接和 <form> 提交，这样脚本没加载完也能用。

岛屿之间怎样共享状态

岛屿之间没有共同的父组件，也就没法用 Context。办法是把状态放到一个跟框架无关的地方：

JavaScript
// store.js
import { atom } from 'nanostores';
export const cartCount = atom(0);

React 岛屿和 Vue 岛屿各自订阅这同一个 store，一边改了，另一边就能收到。Astro 官方文档推荐的就是 Nano Stores 这类与框架无关的状态库。

服务器岛屿是什么

还有一种反过来的需求：页面大部分可以缓存，只有个性化的一小块，比如用户头像，必须按请求生成。server:defer 指令让这个组件和页面主体分开，单独在服务端渲染，页面其余部分照样可以缓存。它需要服务端运行时，纯静态托管用不了。

常见追问

和 SSR 加全量 hydration 有什么区别？

传统 SSR 框架会在客户端把整个页面的组件树都激活一遍，所有组件代码都要下载。Islands 只激活标记过的部分，其余组件的代码根本不会发到浏览器。

用好几个框架会让体积变大吗？

会，每种框架的运行时都要单独下载，所以还是尽量统一用一个。
