Screen Orientation API 的锁定和解锁有什么限制？

Screen Orientation API 能读取方向并在受支持的上下文中请求锁定，适合全屏游戏等沉浸式场景；普通页面应优先响应式布局，并处理权限、失败和退出清理。

参考答案

简答

  • screen.orientation.type 和 angle 读取当前方向，change 事件监听方向变化，读取功能在主流浏览器中都可用。
  • screen.orientation.lock() 请求锁定方向，返回 Promise；它不是 Baseline 特性，通常只在移动设备的全屏模式下才会成功。
  • 不支持或条件不满足时 Promise 会拒绝（如 NotSupportedError、SecurityError），必须捕获并提供降级。
  • 退出全屏或不再需要时调用 unlock()，让屏幕重新跟随设备旋转。
  • 普通页面用响应式布局和方向媒体查询适配横竖屏，不要强制锁定。

读取方向

JavaScript
function report() {
  const { type, angle } = screen.orientation;
  console.log(type, angle); // 例如 'landscape-primary' 90
}

screen.orientation.addEventListener('change', report);

只需要调整布局时，用 CSS 更简单：

CSS
@media (orientation: landscape) {
  .player { height: 100dvh; }
}

锁定方向

JavaScript
async function enterLandscapePlayer(element) {
  try {
    await element.requestFullscreen();
    await screen.orientation.lock('landscape');
  } catch (error) {
    // 不支持锁定时显示"请横置设备"的提示
    showRotateHint(error.name);
  }
}

document.addEventListener('fullscreenchange', () => {
  if (!document.fullscreenElement) screen.orientation.unlock();
});
  • 先进入全屏再锁定，这是大多数支持的浏览器的前提条件。requestFullscreen 需要由用户手势触发。
  • 文档不可见、处于不允许锁定的 iframe（sandbox 缺少 allow-orientation-lock）时会抛 SecurityError。
  • 锁定请求进行中再次调用 lock() 或调用 unlock()，前一个 Promise 会以 AbortError 拒绝。
  • 用户退出全屏时同时解锁，避免页面停留在锁定状态。

兼容性

lock() 的支持有限。Safari 可以读取 screen.orientation，但调用 lock() 会失败，所以必须有降级方案：显示旋转提示，或用 CSS 旋转容器（会影响输入和无障碍，谨慎使用）。桌面浏览器通常也不支持锁定。

适用场景

  • 适合：全屏视频、游戏、相机取景等明确需要特定方向的沉浸式场景。
  • 不适合：普通文章、表单、列表页面。用户可能因为习惯或身体原因固定使用某个方向，WCAG 1.3.4 要求内容不限定显示方向，除非方向对功能必不可少。

常见追问

  • PWA 能在 Manifest 中固定方向吗？Manifest 的 orientation 字段可以设置安装后应用的默认方向，支持程度同样因平台而异。
  • 旧的 window.orientation 还能用吗？它已废弃，应改用 screen.orientation。
