Screen Orientation API 的锁定和解锁有什么限制？

Screen Orientation API 能读取方向并在受支持的上下文中请求锁定，适合全屏游戏等沉浸式场景；普通页面应优先响应式布局，并处理权限、失败和退出清理。

参考答案

先区分布局方向和设备方向

CSS 的 (orientation: landscape) 根据视口宽高判断，适合决定两列还是单列布局。screen.orientation.type 和 angle 描述设备屏幕方向，适合读取或请求方向锁定。分屏、浏览器工具栏、键盘和可调整窗口可能改变视口比例，却不一定让设备物理旋转。

自然方向也因设备而异，不能固定认为角度 0 就是手机竖屏。布局应优先使用容器查询、视口和实际可用空间；只有功能本身依赖横竖屏时，才考虑 Orientation API。

读取方向时要订阅变化并清理

JavaScript
function watchOrientation(onChange) {
  const orientation = screen.orientation;
  if (!orientation) return () => {};

  const report = () => onChange({
    type: orientation.type,
    angle: orientation.angle,
  });

  orientation.addEventListener('change', report);
  report();
  return () => orientation.removeEventListener('change', report);
}

初次报告当前值，组件销毁时移除监听。方向变化时，游戏画布、视频控件和布局尺寸可能都需要重新计算，但不要把每个变化都当成一次完整页面重载。输入框、滚动位置和用户正在编辑的内容应保留。

lock() 是受条件限制的请求

方向锁定通常只适合用户主动进入的全屏游戏或沉浸式播放器。某些浏览器要求文档已经全屏，且必须在用户手势触发的调用链中执行：

JavaScript
async function enterLandscape() {
  if (!screen.orientation?.lock) return false;

  try {
    if (!document.fullscreenElement) {
      await document.documentElement.requestFullscreen();
    }
    await screen.orientation.lock('landscape');
    return true;
  } catch (error) {
    console.warn('方向锁定失败', error);
    return false;
  }
}

即使 API 存在，平台策略、权限、沙箱、文档状态和显示模式也可能拒绝请求。不能把 lock() 成功当成所有设备都会横屏，也不能把失败当成程序异常而阻塞核心功能。进入全屏和锁定是两个 Promise，任一步失败都要决定是否退出已进入的全屏并给出可理解的提示。

unlock() 不等于马上转回原方向

解锁只是撤销应用设置的限制，让系统和浏览器重新决定方向，不保证设备立即旋转或回到调用前的角度。退出游戏时应释放自己拥有的锁定；如果多个模块共享方向控制，需要由拥有者统一管理，不能一个组件卸载就解除另一个功能仍在使用的锁。

页面进入后台、全屏被系统打断或用户主动退出时，也要清理监听、停止渲染循环和恢复 UI。迟到的锁定结果不能覆盖已经退出的状态。

降级不能把用户挡在页面外

锁定失败时，游戏可以提示“建议横屏”，但应仍然可退出、可滚动或以适配布局运行。普通表单、阅读页和后台系统不应显示无法关闭的“请旋转设备”遮罩，只因为 CSS 还没有适配好。

强制方向可能影响键盘、放大文字、读屏和单手操作。只有方向本身是功能要求时才值得牺牲自由旋转；否则应优先改进响应式布局。

测试要覆盖真实移动设备、自动旋转关闭、全屏进入和退出、前后台切换、横竖屏连续变化、独立 PWA 和嵌入 iframe。桌面窗口拖动只能验证布局，不能证明移动平台会允许方向锁定。
