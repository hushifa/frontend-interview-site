Error Boundary 和 Suspense 分别处理什么？

Error Boundary 捕获子树在渲染、生命周期中抛出的错误并显示备用界面；Suspense 在子树等待数据或代码加载时显示 fallback。两者常一起包在异步区域外，分别处理"失败"和"等待"。

参考答案

简答

  • Error Boundary 捕获后代组件在渲染、生命周期方法和构造函数中抛出的错误，显示备用 UI，避免整棵树卸载。
  • Error Boundary 不捕获事件处理器、setTimeout 等异步回调里的错误，也不捕获服务端渲染的错误和它自身的错误。
  • 目前只能用类组件实现（getDerivedStateFromError + componentDidCatch），实践中常用 react-error-boundary 库。
  • Suspense 在子树"挂起"时显示 fallback。能触发挂起的是 lazy 组件、use(promise) 和支持 Suspense 的框架数据加载，普通 Effect 里的 fetch 不会。
  • 已经显示过内容的 Suspense 边界，如果更新包在 Transition 里，React 会保留旧内容而不是切回 fallback。

组合使用

JSX
import { Suspense, lazy } from 'react';
import { ErrorBoundary } from 'react-error-boundary';

const Chart = lazy(() => import('./Chart.jsx'));

export default function Dashboard() {
  return (
    <ErrorBoundary
      fallbackRender={({ error, resetErrorBoundary }) => (
        <div role="alert">
          <p>图表加载失败：{error.message}</p>
          <button onClick={resetErrorBoundary}>重试</button>
        </div>
      )}
    >
      <Suspense fallback={<p>图表加载中…</p>}>
        <Chart />
      </Suspense>
    </ErrorBoundary>
  );
}
  • 加载 Chart 的代码块时显示"加载中"；加载失败（如网络断开）时 Promise reject，错误交给 ErrorBoundary。
  • ErrorBoundary 放在 Suspense 外面，等待和失败都只影响这一块区域。

手写 Error Boundary

JSX
class ErrorBoundary extends React.Component {
  state = { error: null };

  static getDerivedStateFromError(error) {
    return { error };
  }

  componentDidCatch(error, info) {
    reportError(error, info.componentStack);
  }

  render() {
    if (this.state.error) return this.props.fallback;
    return this.props.children;
  }
}

getDerivedStateFromError 在渲染阶段决定显示备用 UI，componentDidCatch 在提交阶段做上报。

边界放在哪里

  • 按用户可以独立理解的区域划分：一个卡片、一个面板、一个路由页面。整个应用只有一个顶层边界的话，任何小错误都会让全屏变成错误页。
  • 多个并排的 Suspense 会各自显示 fallback；希望它们一起出现，就包在同一个 Suspense 里。
  • 嵌套 Suspense 可以逐级显示：外层先出页面骨架，内层再出详细数据。

事件处理器里的错误

JSX
async function handleSave() {
  try {
    await save(form);
  } catch (err) {
    setError(err.message);
  }
}

事件和异步回调的错误不会进入 Error Boundary，要自己 try/catch 并更新状态显示。

常见追问

  • 错误恢复后怎么重新渲染？react-error-boundary 的 resetErrorBoundary 或 resetKeys 会清空错误状态，重新渲染子树。
  • React 19 在错误处理上有什么变化？createRoot 新增 onCaughtError、onUncaughtError 选项，用于统一上报。
