Error Boundary 和 Suspense 分别处理什么？

Error Boundary 管"出错了"，子组件渲染时抛错就显示备用界面；Suspense 管"还在等"，代码或数据没到就显示加载提示。两者常一起包在一块异步区域外面。

参考答案

简答

一块界面在加载时可能遇到两种情况：还没加载完，或者加载失败了。Suspense 处理前一种，子树在等代码或数据时，先显示它的 fallback。Error Boundary 处理后一种，子组件在渲染、生命周期方法或构造函数里抛了错，它显示备用界面，不让整个应用白屏。

能让 Suspense 进入等待的，是 lazy 组件、use(promise) 和支持 Suspense 的框架数据加载。在普通 Effect 里 fetch 是不会触发的。

它们的用处是把“等待”和“失败”限制在一小块区域里，其他部分照常显示。Error Boundary 目前只能用类组件写，实际项目常用 react-error-boundary 库。

要注意，Error Boundary 抓不到事件处理器、setTimeout 这类异步回调里的错误，也抓不到服务端渲染的错误和它自己抛的错误。另外，已经显示过内容的 Suspense，如果更新包在 Transition 里，React 会保留旧内容，不会退回 fallback。

先看两个一起用

下面的仪表盘按需加载一个图表组件。Suspense 负责加载中，ErrorBoundary 负责加载失败。

JSX
import { Suspense, lazy } from 'react';
import { ErrorBoundary } from 'react-error-boundary';

const Chart = lazy(() => import('./Chart.jsx'));

export default function Dashboard() {
  return (
    <ErrorBoundary
      fallbackRender={({ error, resetErrorBoundary }) => (
        <div role="alert">
          <p>图表加载失败：{error.message}</p>
          <button onClick={resetErrorBoundary}>重试</button>
        </div>
      )}
    >
      <Suspense fallback={<p>图表加载中…</p>}>
        <Chart />
      </Suspense>
    </ErrorBoundary>
  );
}

Chart 的代码还在下载时，lazy 让组件进入等待，Suspense 显示“图表加载中”。如果网络断了，import() 返回的 Promise 失败，错误就交给外面的 ErrorBoundary，显示失败提示和重试按钮。

ErrorBoundary 放在 Suspense 外面，所以等待和失败都只影响这一块。页面其他地方不受影响。

Error Boundary 自己怎么写

目前只有类组件能当 Error Boundary，因为要用到两个类组件专有的方法：

JSX
class ErrorBoundary extends React.Component {
  state = { error: null };

  static getDerivedStateFromError(error) {
    return { error };
  }

  componentDidCatch(error, info) {
    reportError(error, info.componentStack);
  }

  render() {
    if (this.state.error) return this.props.fallback;
    return this.props.children;
  }
}

getDerivedStateFromError 在渲染阶段运行，它把错误存进 state，决定接下来显示备用界面。componentDidCatch 在提交阶段运行，适合做错误上报。一个管“显示什么”，一个管“上报”。

为什么事件里的错误抓不到

Error Boundary 只能抓到 React 渲染组件过程中抛出的错误。点击事件、setTimeout 回调、await 之后的代码，执行时 React 早就渲染完了，错误不经过渲染流程，边界自然拦不住。

这类错误要自己 try/catch，再用 state 显示：

JSX
async function handleSave() {
  try {
    await save(form);
  } catch (err) {
    setError(err.message);
  }
}

边界应该放在哪里

按用户能独立理解的区域来划：一张卡片、一个面板、一个路由页面。如果整个应用只有一个顶层边界，任何一个小组件出错，全屏都会变成错误页。

Suspense 也是同样的思路。几个并排的 Suspense 会各自显示自己的 fallback，想让它们一起出现，就包进同一个 Suspense。嵌套的 Suspense 可以逐级显示，外层先出页面骨架，内层再出详细数据。

常见追问

出错以后怎么让它重新渲染？

react-error-boundary 提供了 resetErrorBoundary 函数和 resetKeys 属性，调用或者 key 变化时会清掉错误状态，重新渲染子树。

React 19 在错误处理上有什么变化？

createRoot 新增了 onCaughtError 和 onUncaughtError 两个选项，分别处理被边界捕获的错误和没被捕获的错误，方便统一上报。
