content-visibility: auto 与移除 DOM 有什么区别？

content-visibility: auto 让浏览器跳过屏幕外内容的布局和绘制，但 DOM、状态和可访问内容都还在；它需要配合 contain-intrinsic-size 提供占位尺寸，不能替代虚拟列表。

参考答案

简答

  • auto 时，元素离开视口后浏览器跳过其后代的布局和绘制，接近视口时再渲染。
  • 节点仍在 DOM 中：页内查找、锚点跳转、Tab 焦点和辅助技术都能访问，组件状态也不丢失。
  • 跳过渲染的元素没有内容尺寸，要用 contain-intrinsic-size: auto 500px 给出估计高度，否则滚动条会跳动。
  • 节点本身的内存和 JavaScript 工作不会减少；上万条数据仍应使用虚拟列表。
  • hidden 值相当于内容不可见但保留渲染状态，和 display: none 不同。

用法

CSS
.article-section {
  content-visibility: auto;
  contain-intrinsic-size: auto 600px;
}

auto 600px 表示首次未渲染时按 600px 占位，渲染过一次后记住真实尺寸。适合长文章分节、评论区、长表单分组这类结构简单、数量中等的内容。

和移除 DOM 对比

content-visibility: auto移除 DOM（虚拟列表）
节点数量不变只保留可见的少量节点
页内查找、焦点可用不在 DOM 中的内容找不到
状态保留要自己保存和恢复
适用规模数百个区块数千到数十万条

注意事项

  • 它会对元素应用 layout、style、paint 包含，position: fixed 的后代会以该元素为参照，溢出内容会被裁剪。
  • 屏幕外的图片和 iframe 不会因此停止加载，仍需 loading="lazy"。
  • 计时器、订阅等 JavaScript 工作照常运行，需要单独暂停。
  • 用 Performance 面板对比开启前后的渲染耗时，收益取决于被跳过内容的复杂度。
  • content-visibility: hidden 始终跳过内容渲染，但保留元素已有的渲染状态，切回可见时比 display: none 更快恢复；它的内容对页内查找和焦点不可用，适合暂时隐藏的标签页面板。

常见追问
