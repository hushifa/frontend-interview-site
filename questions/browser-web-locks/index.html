Web Locks 怎样协调多个标签页对同一资源的操作？

navigator.locks.request() 在同源的标签页和 Worker 之间获取命名锁，回调返回的 Promise 完成时释放；支持共享锁、ifAvailable、steal 和 signal 取消，适合保证只有一个标签页刷新令牌或执行同步。

参考答案

简答

  • navigator.locks.request(name, callback) 获取同源范围内的命名锁，callback 返回的 Promise 结束时锁自动释放。
  • 默认是独占锁（exclusive），mode: 'shared' 允许多个读者同时持有。
  • ifAvailable: true 拿不到锁时立即以 null 调用回调，不排队等待；signal 可以取消排队。
  • steal: true 强行释放其他持有者的锁并立即获得，原持有者的 request() Promise 以 AbortError reject。
  • 持有锁的标签页关闭或崩溃时，锁会被自动释放。

示例：只让一个标签页刷新令牌

JavaScript
async function refreshTokenOnce() {
  return navigator.locks.request('token-refresh', async () => {
    const current = readToken();
    if (current && !isExpired(current)) return current;

    const next = await fetchNewToken();
    saveToken(next);
    return next;
  });
}

多个标签页同时发现令牌过期时，它们排队进入。第一个刷新成功后，后面的进入时检查发现令牌已有效，直接返回，不再重复请求。request() 的返回值就是回调的返回值。

选一个标签页当主节点

JavaScript
navigator.locks.request('leader', () => {
  startBackgroundSync();
  return new Promise(() => {});
});

回调返回一个永不结束的 Promise，锁会一直持有到这个标签页关闭，之后排队的下一个标签页自动接管。

超时等待

JavaScript
const controller = new AbortController();
setTimeout(() => controller.abort(), 3000);

try {
  await navigator.locks.request('export', { signal: controller.signal }, doExport);
} catch (error) {
  if (error.name === 'AbortError') showBusy();
  else throw error;
}

注意事项

  • 锁只在同源内有效，不能协调不同源或不同设备。
  • navigator.locks.query() 可以查看当前持有和排队的锁，用于调试。
  • 回调内出错时锁同样会释放，错误会从 request() 抛出。
  • 同一个锁里嵌套请求同名的独占锁会造成死锁。
