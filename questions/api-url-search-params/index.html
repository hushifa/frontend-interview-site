URLSearchParams 怎样处理筛选状态、重复参数和编码？

URLSearchParams 负责解析和生成查询字符串。get 只取第一个值，getAll 取全部；set 覆盖，append 追加。空格会编码成 +，读出来的值都是字符串，要自己转换和校验。

参考答案

简答

列表页的筛选条件要放进网址，比如 ?q=react&tag=a&tag=b&page=2，这样刷新和分享都能保留。读写这串参数就用 URLSearchParams。

同名参数可以有多个。get(key) 只返回第一个值，没有时返回 null；getAll(key) 返回所有值组成的数组。写的时候，set 覆盖同名参数，append 再追加一个值。所以多选标签用 append 写、getAll 读。

编码上，toString() 按表单格式编码，空格变成 +，而 encodeURIComponent 编成 %20。两种写法解析出来都是空格。

要注意读出来的全是字符串。页码要转成数字并校验，不合法就回退到默认值。另外 sort() 按键排序，同样的筛选条件能生成同样的网址，方便缓存。

筛选状态和网址互相转换

下面两个函数，一个把网址解析成筛选条件，一个把筛选条件写回网址。

JavaScript
function parseFilters(search) {
  const params = new URLSearchParams(search);
  const page = Number(params.get('page'));
  return {
    keyword: params.get('q')?.trim() ?? '',
    tags: params.getAll('tag'),
    page: /^[1-9]\d*$/.test(params.get('page') ?? '') ? page : 1,
  };
}

function toSearch({ keyword, tags, page }) {
  const params = new URLSearchParams();
  if (keyword) params.set('q', keyword);
  for (const tag of tags) params.append('tag', tag);
  if (page > 1) params.set('page', String(page));
  params.sort();
  const text = params.toString();
  return text ? `?${text}` : '';
}

parseFilters('?q=react+hooks&tag=a&tag=b&page=abc');
// { keyword: 'react hooks', tags: ['a', 'b'], page: 1 }

toSearch({ keyword: 'react hooks', tags: ['a', 'b'], page: 2 });
// '?page=2&q=react+hooks&tag=a&tag=b'

为什么 page=abc 变成了 1？因为读到的是字符串 'abc'，用正则检查不是正整数，就回退成默认的第 1 页。不校验的话，Number('abc') 是 NaN，后面分页就会出错。

写回网址时，第 1 页和空关键词这些默认值不写进去，地址更短。sort() 把参数按键排好，而且是稳定排序，两个 tag 保持原来的先后顺序。

空格为什么变成了加号

下面几行可以在 Node 里直接运行：

JavaScript
console.log(new URLSearchParams({ q: 'a b&c' }).toString()); // q=a+b%26c
console.log(new URLSearchParams('q=a%20b').get('q')); // a b
console.log(new URLSearchParams('q=a+b').get('q')); // a b
console.log(encodeURIComponent('a b')); // a%20b

URLSearchParams 用的是 application/x-www-form-urlencoded 编码，也就是表单提交的格式，规定空格写成 +。encodeURIComponent 是另一套规则，写成 %20。所以生成的字符串不一样，但解析时 + 和 %20 都会还原成空格。

第一行里 & 被编码成了 %26。如果自己用字符串拼接参数，&、=、# 这些字符不编码，就会把查询字符串的结构弄坏，所以不要手拼。

还有一点，修改 URL 对象的 url.searchParams，会同步更新 url.search，两者是联动的。

常见追问

数组参数用 tag=a&tag=b 还是 tag=a,b？

前者和表单提交的格式一样，用 getAll 直接就能读。后者网址更短，但值里不能出现逗号。两种都行，和后端约定好一种。

怎样更新网址而不刷新页面？

用 history.replaceState(null, '', toSearch(filters))。如果是翻页这种用户希望能后退回去的操作，用 pushState。
