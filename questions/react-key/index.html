列表中的 key 为什么不能随意使用数组下标？

key 告诉 React 同级元素的身份，决定组件状态和 DOM 是复用还是重建。下标表示位置，稳定 ID 表示数据本身；列表插入、删除或排序时，用下标会把状态错配到别的条目上。

参考答案

简答

  • React 协调列表时按 key 匹配新旧元素：key 相同就复用组件实例和 DOM，key 不同就卸载旧的、创建新的。
  • key 只需要在兄弟元素之间唯一，并且在多次渲染之间保持稳定。
  • 用下标当 key 时，在列表头部插入或重新排序后，组件内部状态（输入框草稿、勾选、焦点）会留在原来的位置，显示到别的数据上。
  • 列表只会追加、从不重排，且条目没有内部状态时，下标可以用；其他情况用数据自带的 ID。
  • 不要在渲染时生成 key，例如 Math.random() 或 crypto.randomUUID()，那样每次渲染都会重建所有条目。

下标导致状态错位

JSX
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo, index) => (
        <li key={index}>
          {todo.text} <input placeholder="备注" />
        </li>
      ))}
    </ul>
  );
}

假设列表是 [A, B]，用户在 A 的输入框里输入了"重要"。之后在头部插入 C，列表变成 [C, A, B]：

  • key 0 原来对应 A，现在对应 C。React 认为 key 0 的元素还在，于是复用它的 <input>。
  • 结果"重要"显示在 C 这一行。

改成 key={todo.id} 后，A 的 key 不变，React 会移动 A 对应的 DOM，输入框内容跟着 A 走。

key 的其他用法

key 不只用于列表。给同一个位置的组件换 key，可以让 React 丢弃旧实例、重新创建：

JSX
<ProfileForm key={userId} userId={userId} />

切换用户时表单状态全部重置，不需要写 Effect 去手动清空。

常见追问

  • key 会作为 prop 传给组件吗？不会，组件内读不到 props.key，需要的话另传一个 prop。
  • 数据没有 ID 怎么办？在数据进入应用时（例如从接口取到后）生成一次 ID 并保存，而不是在渲染时生成。
  • Fragment 能加 key 吗？可以，要写成 <Fragment key={id}>，简写 <> 不能加 key。
