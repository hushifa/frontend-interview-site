列表中的 key 为什么不能随意使用数组下标？

key 告诉 React 列表里每一项"是谁"，React 靠它决定复用还是重建组件。下标只代表位置，列表一插入、删除或排序，组件里的状态就会跑到别的数据上。

参考答案

简答

列表重新渲染时，React 要判断新列表里的每一项，对应旧列表里的哪一项。它靠的就是 key：key 相同就复用原来的组件和 DOM，key 不同就把旧的卸载、新建一个。这个新旧对比的过程叫协调。

用下标当 key，key 代表的是“第几个”，而不是“哪条数据”。一旦在头部插入或者重新排序，原来第 0 个位置的组件状态，比如输入框里打的字、勾选状态、焦点，会留在第 0 个位置，显示到另一条数据上。

所以 key 应该用数据自带的 ID。它只要在兄弟元素之间唯一、在多次渲染之间不变就行。列表只会追加、从不重排，而且每项没有内部状态时，用下标也没问题。

还要注意，不要在渲染时生成 key，比如 Math.random() 或 crypto.randomUUID()。那样每次渲染 key 都不同，所有条目都会被重建。

下标会让状态错位

下面每一行有一个备注输入框，key 用的是下标：

JSX
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo, index) => (
        <li key={index}>
          {todo.text} <input placeholder="备注" />
        </li>
      ))}
    </ul>
  );
}

假设列表是 [A, B]，用户在 A 那一行的输入框里打了“重要”。然后在头部插入 C，列表变成 [C, A, B]。

结果“重要”出现在了 C 那一行。为什么？React 对比新旧列表时，发现 key 0 还在，于是复用 key 0 原来的 <li> 和里面的 <input>，只把文字从 A 改成 C。输入框里的内容存在 DOM 里，没人去动它，就留在了原位。

改成 key={todo.id} 以后，A 的 key 一直是 A 的 ID。React 能认出 A 只是挪到了第二位，就移动 A 对应的 DOM，输入框内容跟着 A 一起走，C 则新建一行。

key 还能用来重置组件

key 不只用在列表上。给同一个位置的组件换一个 key，React 会认为这是另一个组件，丢掉旧的、重新创建：

JSX
<ProfileForm key={userId} userId={userId} />

切换用户时，表单的所有状态都会重置。你不需要写 Effect 去手动清空每个字段。

常见追问

组件里能读到 props.key 吗？

读不到。key 是给 React 用的，不会作为 prop 传进组件。组件里需要这个值的话，另外传一个 prop。

数据本身没有 ID 怎么办？

在数据进入应用的时候生成一次 ID 并保存下来，比如从接口拿到数据后。不要在渲染时生成，否则每次都是新的。

Fragment 能加 key 吗？

可以，但要写完整的 <Fragment key={id}>。简写的 <> 不能加 key。
