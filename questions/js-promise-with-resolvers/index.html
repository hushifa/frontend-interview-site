Promise.withResolvers 适合解决什么问题？怎样避免 deferred 泄漏？

Promise.withResolvers（ES2024）一次返回 promise、resolve 和 reject，适合把一次性事件或回调桥接成 Promise，替代在构造器外部保存 resolve 的写法。Promise 只能结算一次，不能当消息队列；它也不负责取消和清理，监听器和定时器要在结算时移除。

参考答案

简答

  • Promise.withResolvers() 返回 { promise, resolve, reject }，等价于在 new Promise 执行器里把两个函数存到外部变量。
  • 适合"结果由之后的某个事件决定"的场景：等待 Worker 就绪、等待一次用户确认、把回调 API 包装成 Promise。
  • Promise 只结算一次，之后的 resolve 调用被忽略；连续消息要用队列、异步迭代器或流。
  • 它不会取消底层工作；监听器、定时器要在结算时移除，否则闭包会一直被持有。
  • ES2024 标准化，主流浏览器和 Node.js 22 都支持。

对比旧写法

JavaScript
let resolveReady;
const ready = new Promise((resolve) => {
  resolveReady = resolve;
});

const { promise, resolve, reject } = Promise.withResolvers();

桥接一次性事件并清理

JavaScript
function waitForWorkerReady(worker, timeout = 5000) {
  const { promise, resolve, reject } = Promise.withResolvers();

  const timer = setTimeout(() => {
    cleanup();
    reject(new Error('等待 Worker 启动超时'));
  }, timeout);

  function cleanup() {
    clearTimeout(timer);
    worker.removeEventListener('message', onMessage);
    worker.removeEventListener('error', onError);
  }

  function onMessage(event) {
    if (event.data?.type !== 'ready') return;
    cleanup();
    resolve(event.data.version);
  }

  function onError(event) {
    cleanup();
    reject(event.error ?? new Error('Worker 启动失败'));
  }

  worker.addEventListener('message', onMessage);
  worker.addEventListener('error', onError);
  return promise;
}

成功、失败、超时三条路径都调用 cleanup。不移除监听器时，Worker 后续每条消息都会调用 onMessage，并让闭包里的对象无法回收。

支持取消

JavaScript
function waitForMessage(target, signal) {
  const { promise, resolve, reject } = Promise.withResolvers();

  function cleanup() {
    target.removeEventListener('message', onMessage);
    signal?.removeEventListener('abort', onAbort);
  }
  function onMessage(event) {
    cleanup();
    resolve(event.data);
  }
  function onAbort() {
    cleanup();
    reject(signal.reason);
  }

  if (signal?.aborted) {
    onAbort();
  } else {
    target.addEventListener('message', onMessage);
    signal?.addEventListener('abort', onAbort, { once: true });
  }
  return promise;
}

signal 可以不传。取消只是停止等待并移除监听器，对方正在执行的工作要靠它自己检查取消状态。

一次性语义

JavaScript
const next = Promise.withResolvers();
next.resolve('第一条');
next.resolve('第二条');
next.promise.then(console.log); // 第一条

用一个 deferred 表示"下一条消息"会丢失消息。需要连续数据时用 ReadableStream 或异步生成器，并设计缓冲上限。

常见追问

  • 超时用 Promise.race 够吗？只能让调用方提前得到超时结果，被竞争的任务仍在运行。应让超时触发 AbortController.abort()，并把 signal 传给下游。
  • 不支持的环境怎样降级？用 new Promise 实现同样的工厂函数即可。
