Temporal 为什么把 Instant、PlainDate 和 ZonedDateTime 分开？

Date 只存一个时间戳，却同时被当成本地时间和 UTC 时间用，生日、预约、跨时区计算很容易出错。Temporal 用不同类型表示不同意思：Instant 是一个确定的瞬间，PlainDate 只是日历上的一天，ZonedDateTime 是某个时区里的时刻。

参考答案

简答

Date 里其实只存了一个毫秒时间戳，可它同时提供 UTC 和本地时间两套读写方法，于是“日期”和“时刻”经常被混在一起，生日存进去换个时区就差一天。Temporal 把不同意思的时间分成不同类型。

Instant 是时间线上一个确定的瞬间，不带时区和日历，适合日志、事件时间戳。PlainDate 只有年月日，不对应任何具体时刻，适合生日、账期；同类的还有 PlainTime、PlainDateTime、PlainMonthDay。ZonedDateTime 是一个瞬间加上 IANA 时区名，比如 Asia/Shanghai，适合会议和当地日程。

分开的好处在计算上最明显。跨夏令时那天，“加 1 天”和“加 24 小时”结果不一样，ZonedDateTime 会按时区规则算对。另外 Temporal 对象都不可变，add 返回新对象；月份从 1 开始，而 Date 从 0 开始。

兼容性要注意。Temporal 已进入 TC39 Stage 4，部分浏览器已经内置，但 MDN 仍标注为非 Baseline（Limited availability），其他环境要用 @js-temporal/polyfill 或 temporal-polyfill。

Date 哪里容易出错

JavaScript
new Date('2024-01-01');       // 按 UTC 午夜解析
new Date('2024-01-01T00:00'); // 按本地时间解析

两个字符串只差一个时间部分，解析出来却是不同的时刻。只写日期时按 UTC 午夜解析，带上时间就按本地时间解析。

所以把生日存成 Date('2024-01-01')，在 UTC-8 时区的用户那里显示，UTC 午夜对应当地的前一天下午，生日就变成了 12 月 31 日。问题在于生日本来就不是一个“时刻”，硬塞进时间戳里就会出这种错。

三种类型分别怎么用

JavaScript
const date = Temporal.PlainDate.from('2024-02-28');
console.log(date.add({ days: 1 }).toString()); // 2024-02-29

const instant = Temporal.Instant.from('2024-01-01T00:00:00Z');
console.log(instant.toZonedDateTimeISO('Asia/Shanghai').hour); // 8
console.log(
  instant.toZonedDateTimeISO('America/Los_Angeles').toPlainDate().toString(),
); // 2023-12-31

PlainDate 只管日历，2024 年是闰年，2 月 28 日加一天就是 29 日，跟时区没有关系。

Instant 是一个确定的瞬间。同一个瞬间放到上海是 1 月 1 日早上 8 点，放到洛杉矶还是 12 月 31 日。要显示成当地时间，就转成对应时区的 ZonedDateTime。

存时区时也要注意。+08:00 这种固定偏移只能还原出某一个瞬间，里面没有夏令时规则。安排未来的当地日程，要存 Asia/Shanghai 这样的时区名，规则变了也能算对。

跨夏令时为什么加一天不等于加 24 小时

JavaScript
const start = Temporal.ZonedDateTime.from(
  '2024-03-09T12:00:00-05:00[America/New_York]',
);
console.log(start.add({ days: 1 }).hour);  // 12
console.log(start.add({ hours: 24 }).hour); // 13

从中午 12 点开始，加 1 天还是 12 点，加 24 小时却变成了 13 点。

因为 2024 年 3 月 10 日纽约开始夏令时，时钟拨快了一小时，那一天只有 23 小时。“明天中午”离现在只有 23 小时，再过 24 小时就到了下午 1 点。

所以要按业务意思选单位。每天固定时间的提醒用 days，有效期 24 小时的令牌用 hours，或者直接用 Instant。

秋天回拨时，又会有一个本地时刻出现两次，比如凌晨 1 点半出现两遍。这时 from 的 disambiguation 选项决定选哪一个，可选 'compatible'、'earlier'、'later'、'reject'。

还有哪些常用规则

比较两个日期，用 Temporal.PlainDate.compare(a, b) 或者 a.equals(b)，不能用 < 或 ===。

月份加法会处理月末。Temporal.PlainDate.from('2024-01-31').add({ months: 1 }) 得到 2024-02-29，因为默认的 overflow: 'constrain' 会把不存在的 2 月 31 日压到当月最后一天。

取当前时间用 Temporal.Now.instant()、Temporal.Now.plainDateISO()。toString() 输出 ISO 8601 格式，ZonedDateTime 还会带上 [时区] 后缀，这是 RFC 9557 定义的格式。判断环境支不支持，可以写 typeof globalThis.Temporal === 'object'。

常见追问

Temporal 和 Intl.DateTimeFormat 是什么关系？

Temporal 负责计算，格式化显示交给 toLocaleString 或 Intl.DateTimeFormat，后者也能直接接收 Temporal 对象。

已有的 Date 怎样转成 Temporal？

用 Temporal.Instant.fromEpochMilliseconds(date.getTime())，或者直接调用 date.toTemporalInstant()。Date 本来就只是一个瞬间，所以先转成 Instant，再按需要转成其他类型。
