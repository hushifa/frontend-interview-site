Temporal 为什么把 Instant、PlainDate 和 ZonedDateTime 分开？

Date 只表示一个毫秒时间戳，却同时提供 UTC 和本地时间的读写方法，生日、预约和跨时区计算很容易混淆。Temporal 用不同类型区分语义：Instant 是时间线上的一点，PlainDate 是无时区的日历日期，ZonedDateTime 是带 IANA 时区的时刻，跨夏令时的日历运算按时区规则处理。

参考答案

简答

  • Instant：时间线上的一个确定瞬间，没有时区和日历，适合日志和事件时间戳。
  • PlainDate：只有年月日，不对应任何时刻，适合生日、账期；同类还有 PlainTime、PlainDateTime、PlainMonthDay。
  • ZonedDateTime：瞬间 + IANA 时区，适合会议和当地日程；跨夏令时加 1 天和加 24 小时的结果不同。
  • Temporal 对象不可变，add 返回新对象；月份从 1 开始，而 Date 从 0 开始。
  • Temporal 已进入 TC39 Stage 4，部分浏览器已内置；MDN 仍标注为非 Baseline（Limited availability），其他环境用 @js-temporal/polyfill 或 temporal-polyfill。

Date 的问题

JavaScript
new Date('2024-01-01');       // 按 UTC 午夜解析
new Date('2024-01-01T00:00'); // 按本地时间解析

同一个日期字符串少了时间部分就换了时区。生日存成 Date 后，在 UTC-8 时区显示会变成前一天。

三种类型

JavaScript
const date = Temporal.PlainDate.from('2024-02-28');
console.log(date.add({ days: 1 }).toString()); // 2024-02-29

const instant = Temporal.Instant.from('2024-01-01T00:00:00Z');
console.log(instant.toZonedDateTimeISO('Asia/Shanghai').hour); // 8
console.log(
  instant.toZonedDateTimeISO('America/Los_Angeles').toPlainDate().toString(),
); // 2023-12-31

同一个瞬间在上海是 1 月 1 日早上 8 点，在洛杉矶还是 12 月 31 日。

+08:00 这样的固定偏移只能还原某个瞬间，不包含夏令时规则；安排未来的当地日程要存 Asia/Shanghai 这类时区名。

跨夏令时

JavaScript
const start = Temporal.ZonedDateTime.from(
  '2024-03-09T12:00:00-05:00[America/New_York]',
);
console.log(start.add({ days: 1 }).hour);  // 12
console.log(start.add({ hours: 24 }).hour); // 13

3 月 10 日纽约时钟拨快一小时，所以"明天中午"距今只有 23 小时。每日重复的提醒用 days，有效期 24 小时的令牌用 hours 或直接用 Instant。

秋季回拨时一个本地时刻会出现两次，from 的 disambiguation 选项（'compatible'、'earlier'、'later'、'reject'）决定选哪一个。

其他要点

  • 比较用 Temporal.PlainDate.compare(a, b) 或 a.equals(b)，不能用 < 或 ===。
  • Temporal.PlainDate.from('2024-01-31').add({ months: 1 }) 得到 2024-02-29，默认 overflow: 'constrain' 把超出的日期压到月末。
  • 当前时间：Temporal.Now.instant()、Temporal.Now.plainDateISO()。
  • 序列化：toString() 输出 ISO 8601，ZonedDateTime 带 [时区] 后缀（RFC 9557）。
  • 能力检测：typeof globalThis.Temporal === 'object'。

常见追问

  • 和 Intl.DateTimeFormat 什么关系？Temporal 负责计算，格式化用 toLocaleString 或 Intl.DateTimeFormat，后者也接受 Temporal 对象。
  • 已有的 Date 怎样转换？Temporal.Instant.fromEpochMilliseconds(date.getTime())，或 date.toTemporalInstant()。
