scheduler.postTask 怎样表达前端任务优先级？

scheduler.postTask 让你给任务标上 user-blocking、user-visible、background 三种优先级，还能取消或改优先级；scheduler.yield() 用来在长任务中途让出主线程。两者都要先做特性检测。

参考答案

简答

页面上的工作有轻重缓急：响应点击最急，渲染可见内容其次，预取下一页最不急。scheduler.postTask(callback, { priority }) 就是让你给任务标上优先级，有 user-blocking、user-visible（默认）、background 三档，它返回一个 Promise。

任务排上以后还能调整。用 TaskController 创建 signal 传进去，之后可以取消任务，也可以用 setPriority() 改还没执行的任务的优先级。

长任务要中途歇一下，就用 scheduler.yield() 让出主线程。之后的代码按原来任务的优先级继续，会排在普通 setTimeout 任务前面。

要注意，优先级只决定这些任务之间谁先谁后，打断不了正在执行的代码，也不是实时保证。兼容性上，MDN 把 scheduler.yield() 标为 Limited availability，用之前先检测 globalThis.scheduler?.yield。

先看一个可以升级的预取任务

预取下一页本来不急，用 background 优先级。可是用户一聚焦搜索框，说明马上要用了，就把它升级：

JavaScript
const controller = new TaskController({ priority: 'background' });

scheduler
  .postTask(() => prefetchNextPage(), { signal: controller.signal })
  .catch((error) => {
    if (error.name !== 'AbortError') throw error; // abort 后 Promise 以 AbortError 拒绝
  });

searchInput.addEventListener('focus', () => {
  controller.setPriority('user-visible');
});

window.addEventListener('pagehide', () => controller.abort());

优先级不写在 postTask 里，而是写在 TaskController 上，因为之后要通过同一个 controller 去改它。用户离开页面时 abort()，没执行的任务就不跑了。

为什么要 catch？任务被取消时，返回的 Promise 会以 AbortError reject。不处理的话，会冒出一个未处理的 Promise 拒绝。

用 yield 把长任务切开

渲染一万行数据，一口气跑完会让页面卡住，用户点什么都没反应。可以每处理一批就让出一次：

JavaScript
async function yieldToMain() {
  if (globalThis.scheduler?.yield) return scheduler.yield();
  return new Promise((resolve) => setTimeout(resolve, 0));
}

async function renderRows(rows) {
  for (let i = 0; i < rows.length; i++) {
    appendRow(rows[i]);
    if (i % 100 === 99) await yieldToMain();
  }
}

每处理 100 行让出一次，浏览器在中间就能响应点击和输入，INP 也会降下来。不支持 scheduler.yield() 的浏览器退回 setTimeout。

为什么优先用 yield 而不是直接 setTimeout？因为 setTimeout 会排到任务队列末尾，前面可能还有一堆别的任务；yield 之后的代码排在普通 setTimeout 任务前面，能更快接着干。

和其他调度方式怎么选

方式用途
requestAnimationFrame下一帧渲染前修改 DOM
queueMicrotask当前任务结束前执行，不让出主线程
setTimeout(fn, 0)让出主线程，排到任务队列末尾
requestIdleCallback空闲时执行，没有空闲可能一直不执行
postTask带优先级和取消的任务队列

常见追问

把任务设成 user-blocking，能打断正在跑的代码吗？

不能。优先级只影响排队的顺序，正在执行的代码要自己跑完或者主动 yield，后面的任务才有机会执行。它也不是实时保证。

任务被取消后会发生什么？

postTask 返回的 Promise 会以 AbortError reject。所以要 catch 住，把 AbortError 当成正常情况忽略掉。
