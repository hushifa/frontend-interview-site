层叠、优先级、继承和 !important 谁先决定样式？

CSS 先按来源、重要性和层叠层等规则筛选声明，再比较选择器特异性、作用域接近程度和出现顺序。继承参与缺省值处理，不会把父元素选择器的权重传给子元素。

参考答案

“ID 比 class 优先，后写的覆盖先写的”只说中了 CSS 的一部分。浏览器为某个元素的某个属性决定值时，需要先找出适用的声明，再按层叠规则排序。选择器权重只在前面的比较仍然打平时起作用。

比如同一个按钮的颜色来自组件库、业务样式和行内样式，浏览器会分别处理它的 color、background 等属性，并不是一次挑中某个选择器后，就让整个规则块覆盖其他规则块。

先比较声明的身份，再比较选择器

先排除不匹配当前元素、媒体条件不成立等不适用的规则。随后，来源与重要性的大致优先顺序如下，越靠下越高：

层级声明或正在生效的值
1浏览器默认样式中的普通声明
2用户样式中的普通声明
3网站作者的普通声明
4CSS 关键帧动画产生的值
5网站作者的 !important 声明
6用户样式的 !important 声明
7浏览器样式的 !important 声明
8正在进行的 CSS 过渡产生的值

“用户样式”指用户为阅读体验设置的样式，例如通过浏览器相关功能或扩展应用的样式，不是网站代码里切换主题的 class。用户的重要声明可以压过网站的重要声明，这使用户仍有机会强制使用适合自己的文字颜色等设置。

表中动画、过渡指它们正在为该属性产生的值，不代表声明了 transition，这个属性就永远拥有最高优先级。

在同一来源与重要性中，还要处理 @layer、行内样式等因素。条件都相同时，才比较选择器特异性；仍相同则比较 @scope 的作用域接近程度，最后才是源码出现顺序。没有使用作用域规则时，通常不必额外考虑作用域接近程度。

为什么 class 能盖过 ID

下面两条规则都命中 <button id="save" class="button">保存</button>：

CSS
@layer vendor, app;

@layer vendor {
  #save {
    color: red;
  }
}

@layer app {
  .button {
    color: blue;
  }
}

按钮是蓝色。两个声明都是作者的普通声明，但 app 层晚于 vendor 层，先在层的比较中获胜，不需要再让 ID 与 class 比大小。

对于同一来源的普通声明，后声明的层高于先声明的层，不在任何层里的普通样式又高于层内普通样式。对于 !important 声明，层的顺序会反过来：早声明的层优先，层内的重要声明也高于未分层的重要声明。因此不能把普通声明的层顺序直接套在 !important 上。

行内普通样式高于作者样式表里的普通声明，但可以被作者样式表的 !important 覆盖。行内 !important 又高于作者样式表中的重要声明，不过仍然不能压过用户或浏览器的重要声明以及正在生效的过渡值。

选择器特异性怎么比较

通常把特异性写成三列：ID 数量、类/属性/伪类数量、类型/伪元素数量，从左往右逐列比较，不是十进制加权求和。再多的 class 也不会自动“进位”成一个 ID。

CSS
#app .button { color: red; }       /* 1-1-0 */
.panel .toolbar button { color: blue; } /* 0-2-1 */

假设其他层叠条件相同，第一条获胜。组合符 >、+、空格不会增加特异性。

:where(...) 以及它的参数整体贡献为零，适合写容易被业务覆盖的默认样式。:is()、:not()、:has() 自身不再额外算一个普通伪类，其贡献取参数列表中特异性最高的选择器。例如 .button:is(.primary, #save) 的特异性是 1-1-0，即便某个元素只是通过 .primary 分支匹配，也不能忽略参数里的 #save。

继承为什么不参与“父子权重大战”

HTML
<div id="page">
  <span class="label">保存成功</span>
</div>
CSS
#page { color: red !important; }
.label { color: blue; }

文字仍然是蓝色。父级的声明在为父级决定颜色，子级的声明在为子级决定颜色，两者没有直接竞争。继承传递的是父级的计算值，而不是它的选择器特异性或 !important 身份。

删掉 .label 的颜色声明后，color 这种默认继承的属性会从父级得到红色。像 margin 这种默认不继承的属性，缺少声明时通常使用初始值，而不是复制父级的外边距。

另外，显式写 color: inherit 会要求继承；initial 要求初始值；unset 对可继承属性按 inherit 处理，对不可继承属性按 initial 处理。所以“有自己的声明就绝不继承”也不准确，声明本身就可能要求继承。

遇到样式不生效，先在 DevTools 找到具体属性，看声明是没匹配、被哪一层覆盖，还是值来自继承。确认这些后再改选择器。直接叠加 ID 或 !important，可能只是把问题推给下一次覆盖。
