层叠、优先级、继承和 !important 谁先决定样式？

多条样式抢同一个属性时，浏览器按固定顺序比：先看来源和 !important，再看层叠层，然后才是选择器优先级、作用域远近和书写顺序。继承来的值最弱，元素只要被直接选中就轮不到它。

参考答案

简答

同一个元素的同一个属性被好几条规则设置时，浏览器要决定听谁的，这个过程叫层叠。它按固定顺序比：来源和重要性、层叠层、选择器优先级、@scope 的作用域远近，最后是书写顺序。前面一步分出胜负，后面就不比了。

优先级按三列算：ID 个数、类和属性和伪类个数、元素和伪元素个数，从左往右逐列比。所以十个类也赢不了一个 ID。:where() 的优先级是 0，:is()、:not()、:has() 取参数里最高的那个。

!important 会把顺序反过来。普通声明里后声明的层赢，加了 !important 后先声明的层赢，来源的顺序也一样反过来。

继承是最弱的。只有元素自己没有被任何规则直接设置这个属性时，才用从父元素继承来的值，父元素选择器的优先级再高也带不下来。

优先级怎么算

CSS
#nav a { }        /* 1-0-1 */
.menu .item a { } /* 0-2-1 */
a:hover { }       /* 0-1-1 */
:where(.menu) a { } /* 0-0-1 */

注释里的三个数字就是三列。比较时先比第一列，#nav a 有一个 ID，直接赢过另外三条，不管它们有多少个类。第一列相同再比第二列，以此类推。

:where(.menu) a 里虽然写了类，但 :where() 不计优先级，所以只剩一个元素选择器。

还有几条规则：写在元素 style 属性上的内联样式，比任何选择器都优先。通配符 * 和 >、空格这些组合符不计入优先级。

层叠层为什么能无视优先级

CSS
@layer reset, components, utilities;

@layer components {
  .button { padding: 8px 16px; }
}

@layer utilities {
  .p-0 { padding: 0; }
}

元素同时有 button 和 p-0 两个类，最后 padding 是 0。这里两个选择器优先级一样，可是就算把 .button 写成 #app .button，结果还是 0。

原因是层叠层比优先级先比较。第一行声明了层的顺序，后声明的 utilities 赢，选择器优先级根本轮不到比较。没有放进任何层的样式，比所有层里的普通样式都优先。

这样组件库的样式可以放在低的层里，业务代码想覆盖时不用再拼命提高选择器优先级。

加了 !important 为什么顺序反过来

普通声明的来源顺序是：浏览器默认样式 < 用户样式 < 作者样式，作者就是写网页的人。加了 !important 后变成：作者 < 用户 < 浏览器默认。这样设计是为了让用户能用重要声明盖过网页，比如为了可读性强制放大字号。

层也一样会反过来，看下面的例子：

CSS
@layer base, theme;

@layer base {
  a { color: red !important; }
}

@layer theme {
  a { color: blue !important; }
}

链接是红色。按普通声明，后声明的 theme 应该赢，但两条都是重要声明，顺序反转，先声明的 base 层更优先。

另外，正在进行过渡的属性值优先级最高，动画的值则高于所有普通声明。

父元素优先级更高，为什么子元素不听它的

CSS
.card { color: gray; }
p { color: black; }

.card 里的 <p> 是黑色。很多人会觉得 .card 是类选择器，优先级比 p 高，应该是灰色。

可是 .card 选中的是父元素，灰色传到 <p> 上是继承来的值。p 选择器直接选中了这个元素，直接命中的声明总是比继承值优先，不用比优先级。

color、font 这类文字属性默认会继承，margin、border 这类默认不继承。想让不继承的属性继承，可以写 inherit。

样式不生效时怎么查

打开开发者工具的 Styles 面板，被覆盖的声明会被划掉，可以看到是哪条规则盖过了它。Computed 面板会显示每个属性的最终值，以及它来自哪条规则。

常见追问

怎样避免选择器优先级越写越高？

用层叠层安排各部分样式的先后，后面的层天然能覆盖前面的。基础样式用 :where() 写成零优先级，方便别人覆盖。尽量不用 ID 选择器和 !important。
