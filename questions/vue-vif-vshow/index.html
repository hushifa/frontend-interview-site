v-if、v-show 与列表 key 应该怎样选择？

v-if 改变条件子树是否存在，v-show 通常保留子树并切换显示；key 决定更新时如何识别同级记录。选择要同时考虑初始成本、切换成本、状态保留、焦点和副作用生命周期。

参考答案

两个区域都能在条件为 false 时看不见，但“看不见”不代表它们经历了相同的事情。v-if 通常让对应条件子树不再存在，v-show 则让已经存在的内容通过 display 隐藏。

组件本地状态、DOM 身份、监听器与初次加载工作都会受到这个区别影响，所以不能只用一句“频繁切换选 v-show”结束判断。

用两个有草稿的计数面板观察区别

vue
<!-- StatefulPanel.vue -->
<script setup>
import { onMounted, onUnmounted, ref } from 'vue';

const props = defineProps({ label: String });
const count = ref(0);
const draft = ref('');
onMounted(() => console.log(`挂载 ${props.label}`));
onUnmounted(() => console.log(`卸载 ${props.label}`));
</script>

<template>
  <section :data-mode="props.label">
    <h3>{{ props.label }}</h3>
    <output>{{ count }}</output>
    <button type="button" @click="count++">增加</button>
    <label>草稿<input v-model="draft" /></label>
  </section>
</template>
vue
<!-- Parent.vue -->
<script setup>
import { ref } from 'vue';
import StatefulPanel from './StatefulPanel.vue';
const visible = ref(false);
</script>

<template>
  <section>
    <button type="button" @click="visible = !visible">{{ visible ? '隐藏' : '显示' }}</button>
    <StatefulPanel v-if="visible" label="v-if" />
    <StatefulPanel v-show="visible" label="v-show" />
  </section>
</template>

初始为 false 时，v-if 面板没有被创建，v-show 面板则已经挂载，只是显示被关闭。首次显示后，分别增加计数、填写草稿，再隐藏并显示：v-if 的普通子组件重新挂载，本地计数与草稿重新初始化；v-show 那份实例仍保留原来的值。

这里强调的是子组件内部状态。如果草稿保存在父级，子组件重新挂载时又从父级取得它，数据也可以保留。因此是否丢失草稿，不只由指令决定，还取决于状态所有权。

初始成本与切换成本不同

v-if 是惰性的，初始条件不成立时可以省掉该分支的创建工作。以后每次进入或退出，可能需要创建、卸载组件和 DOM，并处理相应生命周期。

v-show 一开始就需要承担渲染与组件建立成本，后续主要调整显示。大型内容即使初始隐藏，也可能已经建立侦听、计时器或其他工作，不能把它当成没有资源开销的占位。

因此罕见打开的复杂面板常适合 v-if，频繁切换且需要保留实例的区域可以考虑 v-show。最终还要测量真实内容，不是每个场景都有一条永远正确的速度排名。

隐藏不会自动暂停组件内部的工作

v-show 不触发普通卸载，也不会自动停止请求、轮询、订阅或动画脚本。若这些工作只应在可见时运行，应让它们依据可见状态主动暂停或清理。

display:none 的内容不参与正常布局，相关尺寸读取可能变为 0。隐藏期间初始化需要真实尺寸的图表或编辑器，可能得到错误布局；应在合适的显示阶段测量或通知外部实例调整。

v-if 触发卸载也不意味着任意外部资源都由 Vue 自动认识并释放，组件仍需实现清理。KeepAlive 还会改变某些组件的停用与保留规则，应按真实树结构判断，不能把所有条件退出都视为普通销毁。

template、else 与列表条件有不同语法规则

v-if 可以用于 template，把多个元素作为一个条件块；v-else、v-else-if 需要相应的相邻分支关系。v-show 需要实际元素的显示样式，不支持用 template 当作同样的隐藏容器，也不能与 v-else 组成相同的分支链。

Vue 3 中，同一元素同时写 v-if 与 v-for 时，v-if 的优先级更高，这时不能按直觉认为循环变量已经可供条件使用。应先用 computed 过滤出要显示的列表，或用外层结构表达条件与循环，而不是依赖容易误读的同元素组合。

如果条件决定整张列表是否存在，可以把条件放在外层；如果决定每条记录是否出现，派生出相应列表通常更清楚。

key 表达记录身份，不只是消除警告

列表更新可能复用已有组件。稳定且同级唯一的业务 ID，能让本地编辑、焦点和组件状态跟随正确记录。

数组下标表示位置，插入、删除或重排之后，同一个位置可能已经是另一条记录。若每行有本地草稿，用下标 key 就可能把旧状态复用给新记录。渲染时生成随机 key 则走向另一个极端，会不断制造新身份并重建组件。

key 通常应采用稳定的原始标识，如记录 ID，而不是每次新建的对象。它的范围是同一组兄弟节点，不是全站必须只有一份的数据库命名空间。

对真正固定、没有重排增删与身份相关状态的列表，下标风险较低；一旦新增搜索、排序或编辑功能，这个前提就可能不再成立。

保留状态与保持可用性需要一起设计

隐藏当前焦点所在区域时，应把焦点移动到合理的仍可操作位置，而不是让键盘用户突然失去上下文。弹层、折叠区与复杂表单还需要相应的状态提示和无障碍关系。

想跨卸载保留业务草稿，可以提升状态或持久化；想保留组件实例，可以按需求评估 KeepAlive。不要为了保留一点数据，就无界地把所有大型区域永久 v-show 隐藏。

验证时除了看内容是否出现，还应观察首次挂载、再次显示、草稿、焦点、定时任务与列表重排。视觉相同的两种写法，生命周期成本可能完全不同。
