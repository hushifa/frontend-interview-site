CDN 和反向代理缓存异常应该怎样排查？

把链路拆成浏览器、CDN 边缘、中间层、反向代理和源站，逐层比对响应头和缓存键，找出是哪一层返回了旧内容或错误响应。关键证据是 Age、Cache-Status 或厂商缓存头、ETag 和 Vary。

参考答案

简答

  • 先确认问题在哪一层：直接请求源站正常、经过 CDN 异常，就是缓存层的问题。
  • 看 Age 判断副本已经缓存多久，看 Cache-Status 或厂商头（如 X-Cache、CF-Cache-Status）判断哪一层命中。
  • 对比 ETag 或 Last-Modified 和源站当前值，确认副本是否是旧版本。
  • 检查缓存键：查询参数、Vary 头、设备类型和语言是否被正确纳入或排除。
  • 修复后按 URL 或标签清除缓存，并保留证据，复盘缓存规则。

排查步骤

  1. 复现并记录：完整 URL、时间、地区、响应头。不同地区命中不同的边缘节点，结果可能不同。
  2. 绕过浏览器缓存：用无痕窗口或 curl -sI，排除本地缓存。
  3. 直连源站：通过源站域名或 curl --resolve 指定 IP 请求，对比响应头和内容。
  4. 逐层看缓存信息：每一层的命中状态、Age、新鲜期。
  5. 检查源站返回的 Cache-Control：是否被 CDN 规则覆盖，CDN 是否忽略了 private。
  6. 检查缓存键和 Vary：内容随语言或登录状态变化，但缓存键没区分，就会串内容。
bash
curl -sI https://www.example.com/app.js | grep -iE 'age|cache|etag|vary|date'
curl -sI --resolve www.example.com:443:203.0.113.10 https://www.example.com/app.js

常见原因

现象可能原因
发版后仍是旧 JSHTML 被长期缓存，引用旧哈希；或无哈希文件被长期缓存
用户看到别人的数据个性化响应缺少 private，CDN 按 URL 缓存了
偶发 502 被缓存CDN 缓存了错误响应，负缓存时间过长
语言或设备版本串了缺少 Vary，或缓存键未包含区分维度
命中率很低缓存键包含追踪参数、时间戳，或 Vary: User-Agent 导致碎片化

用户数据串号属于安全事故，原理和防护见《什么是 Web 缓存投毒？如何避免把用户数据缓存给别人？》。

预防

  • HTML 用 no-cache，静态资源用哈希文件名加长期缓存。
  • 个性化接口默认 private, no-cache，CDN 规则对带 Cookie 或 Authorization 的请求不缓存。
  • 缓存键白名单只保留影响内容的参数。
  • 错误响应设置很短的缓存时间或不缓存。

常见追问

  • 清除 CDN 缓存后用户还是旧的？浏览器本地缓存还在新鲜期，CDN 清除管不到，所以需要哈希文件名。
  • Age 一直是 0？可能每次都回源，也可能该层没有缓存或不输出 Age。
