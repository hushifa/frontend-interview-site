Canvas 图形命中测试应该怎样实现？

Canvas 只有一个 DOM 元素，点中了哪个图形要应用自己判断。用 Path2D 让绘制和命中共用同一份几何，统一坐标系后用 isPointInPath 检测，重叠时从最上层往下找，对象多时先用包围盒或空间索引粗筛。

参考答案

简答

在 Canvas 上画了一个圆，用户点了一下，浏览器只知道点了 canvas 这个元素，不知道点没点中那个圆。判断“点中了哪个图形”就叫命中测试，要靠应用根据自己保存的几何信息来算。

常用做法是用 Path2D 定义形状。同一个对象既拿来 fill() 绘制，也拿来给 isPointInPath() 检测，这样画出来的和判断用的永远是同一份形状。

坐标要特别小心。isPointInPath(path, x, y) 里的 x、y 是位图坐标，不受当前变换影响；path 却会按当前变换参与检测。所以指针坐标要先换算成位图坐标。

图形重叠时，按绘制的反方向从上往下查，第一个命中的可交互对象胜出。对象很多时，先用包围盒、网格或四叉树把候选缩小，再做精确检测。

先看最基本的用法

JavaScript
const canvas = document.querySelector('canvas');
const ctx = canvas.getContext('2d');

const circle = new Path2D();
circle.arc(50, 50, 20, 0, Math.PI * 2);
ctx.fill(circle);

ctx.isPointInPath(circle, 50, 50); // true
ctx.isPointInPath(circle, 80, 50); // false

圆心在 (50, 50)，半径 20。点 (50, 50) 在圆里，所以是 true；点 (80, 50) 离圆心 30，超出半径，所以是 false。

要注意，isPointInPath 看的是路径的填充区域，跟像素是什么颜色无关。

只描边的线条，要用 isPointInStroke，它的结果受 lineWidth 影响。线很细时手指很难点中，触摸操作可以临时把线宽调大，放大命中范围。带孔洞的路径，比如圆环，要传入和绘制时相同的填充规则 'nonzero' 或 'evenodd'，否则孔洞里也可能算命中。

指针坐标怎样换算

指针事件给的是 client 坐标，也就是相对浏览器视口的 CSS 像素。可是 canvas 的位图尺寸可能和它在页面上显示的尺寸不一样，所以要先按比例换算成位图坐标：

JavaScript
function toBitmap(canvas, event) {
  const rect = canvas.getBoundingClientRect();
  return {
    x: ((event.clientX - rect.left) * canvas.width) / rect.width,
    y: ((event.clientY - rect.top) * canvas.height) / rect.height,
  };
}

这里假设 canvas 没有边框和内边距，也没有 CSS 旋转。

绘制时如果设置了变换，检测时也要用同一个变换：

JavaScript
ctx.setTransform(2, 0, 0, 2, 100, 0);
ctx.isPointInPath(circle, 200, 100); // true，圆心 (50,50) 映射到位图 (200,100)

这个变换先放大 2 倍，再向右移 100，所以圆心 (50, 50) 落在位图的 (200, 100)。检测时传的点是位图坐标，路径则跟着当前变换走，两边就对上了。

另一种做法是反过来：把指针坐标用变换的逆矩阵转回图形自己的局部坐标，再在单位矩阵下检测，见《Canvas 的 transform 怎样影响坐标和绘制？》。两种做法只能选一种，混着用会把变换补偿两次。

重叠时怎样找到最上面的图形

下面的函数从最后画的图形开始往前找，先用包围盒快速排除，再精确检测：

JavaScript
// x、y 和 shape.bounds 都是画布位图坐标；shape.path 是局部坐标，配合 shape.matrix 使用
function hitTest(ctx, shapes, x, y) {
  const saved = ctx.getTransform();
  try {
    for (let i = shapes.length - 1; i >= 0; i--) {
      const shape = shapes[i];
      if (!shape.selectable) continue;
      const { left, top, right, bottom } = shape.bounds;
      if (x < left || x > right || y < top || y > bottom) continue; // 包围盒粗筛
      ctx.setTransform(shape.matrix);
      if (ctx.isPointInPath(shape.path, x, y)) return shape;
    }
    return null;
  } finally {
    ctx.setTransform(saved); // 检测完恢复原矩阵，不影响后续绘制
  }
}

为什么要倒着遍历？因为 shapes 是按绘制顺序存的，后画的盖在上面，倒着找就是从上往下找。

包围盒就是能框住图形的最小矩形。判断点在不在矩形里只要几次比较，比精确检测便宜得多，所以先用它排除掉大部分图形。

哪些对象锁定了、不可选、允许点击穿透，这些由业务模型自己标记，比如这里的 selectable。如果用了网格、四叉树这类空间索引，对象移动、缩放、删除时要同步更新索引。

还有别的办法吗

还有一种叫颜色拾取。在一张看不见的离屏画布上，给每个对象用一种唯一的颜色画一遍，点击时读出那个位置的像素颜色，就知道是哪个对象。

它适合形状复杂、数量巨大的场景。可是要关掉抗锯齿，否则边缘会混出别的颜色；getImageData 有读回像素的开销；画布被跨源图片污染以后，也读不出像素。

常见追问

命中检测之外还要做什么？

拖动要配合 setPointerCapture，保证手指移出图形也不丢事件。重要的操作还要提供键盘或普通控件的入口。

能用 isPointInPath 判断像素是不是透明吗？

不能，它只看几何形状。要按透明度判断，得用颜色拾取或者直接读像素。
