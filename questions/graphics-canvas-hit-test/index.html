Canvas 图形命中测试应该怎样实现？

用 Path2D、isPointInPath 和坐标转换判断点击图形，理解绘制像素和交互区域不是同一件事。

参考答案

Canvas 不会自动为每个绘制图形创建 DOM 事件目标。交互层需要保存图形的几何数据，使用 Path2D、isPointInPath 或自定义空间索引，根据指针坐标判断命中对象。

在“Canvas 图形命中测试应该怎样实现？”这个问题中，先确定坐标系、设备像素比、对象规模和渲染上下文，再分别测量绘制、命中测试、资源释放和无障碍替代。这里的 Canvas、命中测试、交互 不是孤立的 API 名称，而是会共同影响输入、过程和最终结果。

图形题先确定坐标系、设备像素比、渲染上下文和对象规模，再设计绘制与命中测试。绘制结果、交互区域和无障碍替代不一定是同一层数据，需要分别维护。

命中前要把页面坐标转换到 Canvas 坐标，处理 CSS 缩放、设备像素比、旋转和当前变换矩阵。绘制顺序决定视觉遮挡，命中顺序也要按业务决定是否从上层图形向下层查找。

大量图形时逐个测试会变慢，可以先用包围盒、网格或四叉树缩小候选范围。命中区域还应提供键盘和辅助技术替代，不要让 Canvas 成为唯一交互入口。

大量对象时要测量重绘、纹理、内存和资源释放，不能只看静态截图。动画、缩放和窗口尺寸变化还要验证取消、降级和设备能力差异。

实际图形功能要把绘制、交互和资源释放分开测量。对象数量增加后，单次重绘、命中测试和纹理占用可能成为不同瓶颈，不能只优化其中一个环节。
