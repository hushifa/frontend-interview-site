ResizeObserver 为什么可能出现循环通知错误？

ResizeObserver 在元素尺寸变化后通知你。如果回调里又改了被观察元素的尺寸，浏览器会在同一帧里反复通知，处理不完就推迟到下一帧，并报 "ResizeObserver loop completed with undelivered notifications"。

参考答案

简答

控制台里经常能看到一行 ResizeObserver loop completed with undelivered notifications。它的意思是：有些尺寸变化的通知，这一帧没来得及送出去。

ResizeObserver 是在布局算完、绘制之前回调的，告诉你元素的内容框、边框框等尺寸。如果回调里又改了尺寸，浏览器会在同一帧里再检查一遍、再通知。但为了不死循环，后面几轮只处理比上一轮更深层的元素。

剩下处理不了的通知，浏览器留到下一帧，同时在 window 上触发这条错误。

这个错误一般不影响功能，但它说明代码里有“尺寸变了 → 回调改尺寸 → 尺寸又变”的循环，应该消除。办法是只在值真的变了时才写、尽量用 CSS 解决，或者把修改推迟到 requestAnimationFrame。

正常的用法

下面根据卡片宽度切换布局，宽度小于 480 就标记成 small。

JavaScript
const observer = new ResizeObserver((entries) => {
  for (const entry of entries) {
    const width = entry.contentBoxSize[0].inlineSize;
    entry.target.dataset.size = width < 480 ? 'small' : 'large';
  }
});
observer.observe(card);

这里回调只改了 data-size 属性，CSS 根据它调整卡片内部元素的排列，卡片自己的尺寸不变。所以回调执行完，被观察的元素没有新的尺寸变化，就不会循环。

什么写法会产生循环

下面想让盒子的高度始终是宽度的一半：

JavaScript
new ResizeObserver(([entry]) => {
  entry.target.style.height = `${entry.contentRect.width / 2}px`;
}).observe(box);

回调改了高度，元素尺寸又变了，浏览器就要再通知一次。如果宽度也会受高度影响，比如高度变大后出现了滚动条，挤占了宽度，那宽度一变高度又变，就来回循环，浏览器只好放弃一部分通知并报错。

怎样消除循环

第一，只在尺寸真的变了时才更新。比较新旧值，一样就不写，避免重复写入触发新一轮通知。

第二，能用 CSS 就别用 JavaScript。上面“高度是宽度一半”用 aspect-ratio: 2 / 1 就能做；按容器宽度调整样式，可以用容器查询 @container。大部分这类需求都不需要 ResizeObserver。

第三，确实要改尺寸，就放进 requestAnimationFrame，推迟到下一帧再改，打断同一帧内的循环。

和 window 的 resize 事件有什么区别

window 的 resize 只在视口大小变化时触发。可是侧边栏收起、图片加载完撑开内容，单个元素的尺寸变了，视口并没有变，resize 就不会触发。ResizeObserver 能感知这些单个元素的变化。

常见追问

测试里老是出现这条错误，能不能直接屏蔽？

可以在测试的全局错误处理里按这条消息过滤掉。但不要在生产环境里把所有错误都吞掉，否则真正的错误也看不到了。

这个错误会让页面出问题吗？

通常不会，没送出去的通知会推迟到下一帧。但它说明存在尺寸循环，可能导致布局抖动，最好找到回调里改尺寸的地方修掉。
