ResizeObserver 为什么可能出现循环通知错误？

参考答案

ResizeObserver 观察元素盒尺寸的变化，适合组件尺寸由容器而非单纯窗口大小决定的场景。观察目标的内容盒、边框盒等需要按 API 选项和支持情况明确区分。

若回调修改布局导致被观察目标再次改变尺寸，就可能形成反馈循环。浏览器会采用机制避免无限处理，并可能报告循环相关错误；这不能理解为每次报错都来自观察器本身的缺陷。

修复应让更新条件收敛，避免尺寸没发生有意义变化时重复写入，必要时把写操作移到合适的帧时机。requestAnimationFrame 可以改变调度时机，但不能让错误的循环逻辑自动消失。组件销毁时也要停止观察。

使用边界

使用 Web API 前要确认安全上下文、权限、用户手势、浏览器支持和可用的降级路径。请求、监听器、流、对象 URL 或设备句柄都应有明确的结束和清理逻辑，不能把“调用成功”当成整个任务已经完成。

接口返回的异常、取消和用户拒绝应分别处理。浏览器端的取消只代表客户端停止等待，涉及写入、上传或设备操作时还要查询实际状态。
