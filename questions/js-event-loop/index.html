事件循环中，任务和微任务按什么顺序执行？

同步代码执行完、调用栈清空后，宿主会进入微任务检查点，把微任务队列清空（包括清空过程中新加入的），然后再取下一个任务，浏览器在合适时机渲染。Promise 回调是微任务，定时器回调是任务。

参考答案

简答

  • 当前同步代码先运行到调用栈清空，期间注册的回调只是入队。
  • 调用栈清空后进入微任务检查点，微任务队列会被清空，清空过程中新加入的微任务也在这一轮执行。
  • Promise 回调、queueMicrotask 和 MutationObserver 回调属于微任务；setTimeout、用户事件、MessageChannel 消息属于任务。
  • 浏览器可以在两个任务之间渲染，但不保证每个任务后都渲染；requestAnimationFrame 回调在渲染前执行。
  • 微任务不断产生新的微任务，会让后续任务和渲染一直等待。

经典输出题

JavaScript
console.log('A');
setTimeout(() => console.log('B'), 0);
Promise.resolve().then(() => console.log('C'));
console.log('D');
// 输出顺序：A → D → C → B

A、D 是同步代码。then 回调进入微任务队列，setTimeout 回调进入定时器对应的任务源。脚本执行完后先清空微任务输出 C，之后事件循环才取出定时器任务输出 B。

一轮循环大致做什么

  1. 从某个任务队列取出一个任务执行（脚本本身、定时器回调、事件回调等）。
  2. 调用栈清空后执行微任务检查点，直到微任务队列为空。
  3. 如果到了渲染时机，依次处理 resize/scroll 等事件、requestAnimationFrame 回调、样式与布局、绘制。
  4. 回到第 1 步。

HTML 规范允许浏览器在多个任务源之间按优先级选择，所以"不同来源的任务谁先执行"不是固定顺序，只能保证同一任务源内按入队顺序。

await 与微任务

JavaScript
async function run() {
  console.log(1);
  await null;
  console.log(3);
}
run();
console.log(2);
// 1 → 2 → 3

await 之前的代码同步执行；await 之后的部分作为微任务恢复。

微任务饥饿

JavaScript
function loop() {
  queueMicrotask(loop); // 永远不会让出给定时器和渲染
}

需要长时间分片处理时，应把每片放进任务（setTimeout、MessageChannel、scheduler.postTask）或用 scheduler.yield() 让出，而不是放在微任务里循环。

常见追问

  • Node.js 的顺序一样吗？大体模型相同，但 Node 有 process.nextTick 队列和 libuv 的阶段划分，见《Node.js 事件循环和浏览器有什么不同？nextTick 一定先于 Promise 吗？》。
  • setTimeout(fn, 0) 是否立刻执行？不会，它至少等当前任务和微任务完成；嵌套层级较深时浏览器还会把延迟钳制到至少 4ms。
