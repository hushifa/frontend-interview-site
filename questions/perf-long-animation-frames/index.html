如何用 Long Animation Frames API 定位卡顿来源？

Long Animation Frames（LoAF）记录超过 50ms 才完成渲染的帧，包含渲染、样式布局的开始时间和参与这一帧的脚本列表。每个脚本记录给出调用者、来源 URL、函数名和强制布局耗时，比 Long Tasks API 更能回答"是谁让这一帧变慢"。它不是 Baseline，需要特性检测。

参考答案

简答

  • 长任务看单个任务，LoAF 看一整帧：多个 30ms 的任务落在同一帧，单个都不算长任务，但会形成一个长动画帧。
  • 条目字段：duration（整帧）、blockingDuration（帧内超出 50ms 预算的阻塞时间）、renderStart、styleAndLayoutStart、scripts。
  • scripts 里每项包含 invoker（如 BUTTON#submit.onclick）、invokerType、sourceURL、sourceFunctionName、duration、forcedStyleAndLayoutDuration。
  • 生产环境按页面、交互和设备聚合分位数，采样上报摘要；不支持时降级到 Event Timing 和实验室录制。
  • MDN 标注为实验性、有限可用，需要特性检测。

采集

JavaScript
function observeLoAF(report) {
  if (!PerformanceObserver.supportedEntryTypes?.includes('long-animation-frame')) return () => {};

  const observer = new PerformanceObserver((list) => {
    for (const frame of list.getEntries()) {
      report({
        duration: Math.round(frame.duration),
        blocking: Math.round(frame.blockingDuration),
        scripts: frame.scripts.map((script) => ({
          invoker: script.invoker,
          type: script.invokerType,
          source: script.sourceURL,
          fn: script.sourceFunctionName,
          duration: Math.round(script.duration),
          forcedLayout: Math.round(script.forcedStyleAndLayoutDuration),
        })),
      });
    }
  });
  observer.observe({ type: 'long-animation-frame', buffered: true });
  return () => observer.disconnect();
}

blockingDuration 的算法：取帧内每个超过 50ms 的任务，各自减去 50ms 后求和，其中最长的任务还要加上渲染时间。例如 70ms 和 120ms 两个任务、渲染 20ms，结果是 (70 − 50) + (120 + 20 − 50) = 110ms。

从字段到原因

现象指向的问题方向
某个 invoker 的 duration 很大事件处理或回调里做了大量同步工作减少工作、分片、Worker
forcedStyleAndLayoutDuration 很大写 DOM 后立即读布局属性（布局抖动）先批量读再批量写
sourceURL 是第三方域名第三方脚本在交互时执行延迟加载或隔离第三方，见《第三方脚本怎样接入，才能控制性能和安全风险？》
脚本时间不多，renderStart 到结束很长样式计算和布局成本高缩小 DOM、简化选择器、content-visibility

和其他指标的关系

  • Long Tasks：只知道有长任务，归因只到 iframe 级别，见《什么是长任务，为什么会影响交互响应？怎样观测和拆分？》。
  • Event Timing / INP：知道哪次交互慢、慢在输入延迟、处理还是呈现。把慢交互的时间段和同时发生的 LoAF 关联，就能找到具体脚本，见《INP 很高时，如何定位到底是哪一段交互变慢？》。

上报注意

  • sourceURL 是打包后的地址，配合版本号和 Source Map 在服务端还原，不要把 Source Map 公开。
  • 只上报超过阈值的帧并采样，回调里不要做重活。
  • 页面隐藏时用 navigator.sendBeacon() 批量发送。

常见追问

  • 为什么有时 scripts 为空？短脚本不会单独记录，帧的耗时也可能主要在样式、布局和绘制上。
  • 不支持的浏览器怎么办？用 Event Timing、自定义交互标记和 DevTools 录制做替代。
