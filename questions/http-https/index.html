HTTPS 相比 HTTP 提供了哪些保障？

HTTPS 就是把 HTTP 放在 TLS 加密连接里传。它保证内容别人看不到、改不了，并证明你连的就是这个域名的服务器；但它不保证网站本身可信。

参考答案

简答

HTTPS 就是 HTTP 跑在 TLS 上。TLS 是一层加密连接，HTTP 的请求和响应都在里面传。

它提供三样保障。第一是机密性，中间人看不到内容，不过目标 IP 能看到，通常 SNI 里的域名也能看到。第二是完整性，内容被改了会被发现，运营商没法往页面里插广告。第三是身份认证，证书证明你连的就是这个域名的持有者，就算 DNS 被劫持也冒充不了。

TLS 1.3 的完整握手只要 1 个往返，并且默认有前向保密：服务器私钥以后泄露了，之前被录下来的流量也解不开。

要注意，证书只证明域名归谁，钓鱼网站一样能拿到证书。所以小锁图标不代表网站可信，HTTPS 也替代不了登录和权限校验。

TLS 1.3 握手在做什么

握手就是双方在发数据前，商量好用什么算法、算出同一把密钥。TLS 1.3 大致是三步。

第一步，客户端发 ClientHello，列出支持的算法，并且直接附上自己的密钥材料，叫 key_share。第二步，服务器回 ServerHello，选定算法，也给出自己的 key_share。到这里双方已经能算出握手密钥了，所以后面服务器发的证书、CertificateVerify、Finished 都是加密的。第三步，客户端校验证书链和签名，发出 Finished，接着就能发应用数据。

和 TLS 1.2 比，1.2 的完整握手要 2 个往返，证书是明文传的，还允许静态 RSA 密钥交换，这种方式没有前向保密。1.3 把静态 RSA 和一批旧算法都删了。

为什么 1.3 有前向保密？因为完整握手用的是临时 Diffie-Hellman 密钥交换，每次连接的密钥都是临时生成的，用完就丢，跟服务器的长期私钥无关。唯一的例外是只用 PSK、不带 DHE 的会话恢复。

会话恢复时还可以用 0-RTT，在第一个包里就带上应用数据。但 0-RTT 的数据可能被攻击者重放，所以只适合幂等请求。

证书到底校验了什么

浏览器会检查四件事：证书链能追溯到它信任的根证书、证书没过期、没被吊销、证书上的域名和你访问的域名一致。

可以看出，这里面没有一条是“网站是好人”。证书只证明域名控制权，所以钓鱼网站同样能拿到有效证书。

部署时要注意什么

一是混合内容。HTTPS 页面里加载 HTTP 的脚本会被浏览器拦截，图片这类被动内容会被自动升级成 HTTPS 或者拦截。

二是 HSTS。用户第一次输入域名时可能先走 HTTP，这一次就可能被降级劫持。Strict-Transport-Security 响应头让浏览器在有效期内只用 HTTPS 访问这个域名。

三是很多 API 只在安全上下文里能用，比如 Service Worker、Web Crypto 的 crypto.subtle、地理位置。

四是 TLS 如果在 CDN 或负载均衡那里就结束了，CDN 到源站这一段要单独加密。

常见追问

HTTPS 慢在哪里？

主要慢在握手的往返。TLS 1.3、连接复用、会话恢复和 HTTP/3 都在减少这部分开销。加解密本身的 CPU 成本在现代硬件上很小。

抓包工具为什么能看到 HTTPS 内容？

它在本机装了自己的根证书，自己做中间人。浏览器信任了这个根证书，才放行了它签出来的证书。
