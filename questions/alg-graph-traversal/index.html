前端场景中的图遍历应该怎样建模？

模块依赖、页面跳转、组件引用都可以看成有方向的图。DFS 用栈沿一条路走到底，适合找出所有能到达的节点、检查循环依赖；BFS 用队列一层层往外扩，能找到经过边数最少的路径。两种都要记录走过的节点，不然遇到环会无限循环。

参考答案

简答

前端里很多关系都是图，比如模块之间的依赖。可以用一个 Map<节点, 邻居数组> 来表示，这叫邻接表，app → router 就表示 app 依赖 router。

遍历有两种方式。DFS 是深度优先，用栈，先沿一条路一直走到底，适合找出所有能到达的节点。BFS 是广度优先，用队列，按距离一层层往外扩，所以第一次碰到目标时，走的就是边数最少的路。

两种都要用一个 Set 记下访问过的节点，因为图里可能有环，不记的话会绕着环无限循环。时间复杂度都是 O(V + E)，V 是节点数，E 是边数。

检查循环依赖要用 DFS 的三种状态：没访问、访问中、已完成。走着走着又碰到一个“访问中”的节点，说明绕回来了，就是有环。实现时用显式的栈或队列代替递归，图很深时不会栈溢出。

用邻接表表示依赖

JavaScript
const dependencies = new Map([
  ['app', ['router', 'ui']],
  ['router', ['url']],
  ['ui', ['button']],
  ['button', []],
  ['url', []],
]);

这和树有什么不同？树里每个节点只有一个父节点，也不会有环。图里一个节点可以被好几个节点依赖，还可能 A 依赖 B、B 又依赖 A。所以遍历图时，必须记住哪些节点已经走过了。

DFS：找出所有能到达的节点

比如想知道从入口 app 出发，最终会打包进哪些模块：

JavaScript
function depthFirst(start, graph) {
  if (!graph.has(start)) return null;
  const visited = new Set();
  const stack = [start];

  while (stack.length > 0) {
    const node = stack.pop();
    if (visited.has(node)) continue;
    visited.add(node);
    const neighbors = graph.get(node) ?? [];
    // 反向入栈，让第一个邻居先出栈，与递归 DFS 的访问顺序一致。
    for (let index = neighbors.length - 1; index >= 0; index--) {
      if (!visited.has(neighbors[index])) stack.push(neighbors[index]);
    }
  }
  return [...visited];
}

console.log(depthFirst('app', dependencies));
// ['app', 'router', 'url', 'ui', 'button']

为什么邻居要反着放进栈？因为栈是后进先出的。app 的邻居是 router、ui，反着放，ui 先进、router 后进，弹出来的就是 router。这样先走 router 那条路一直到底，访问顺序和递归写法一致。

为什么出栈以后还要再判断一次 visited？因为同一个节点可能被好几个邻居都压进栈里，第二次弹出来时它已经访问过了，直接跳过。

起点不在图里时，这里和下面的函数都统一返回 null。

这类遍历的用途很多：分析一个入口文件会打包进哪些模块、删掉某个包会影响哪些页面。

BFS：找最短路径

想知道 app 是通过哪条最短的依赖链用到 button 的：

JavaScript
function shortestPath(start, target, graph) {
  if (!graph.has(start)) return null;
  const queue = [start];
  const previous = new Map([[start, null]]);

  for (let head = 0; head < queue.length; head++) {
    const node = queue[head];
    if (node === target) break;
    for (const neighbor of graph.get(node) ?? []) {
      if (previous.has(neighbor)) continue;
      previous.set(neighbor, node);
      queue.push(neighbor);
    }
  }

  if (!previous.has(target)) return null;
  const path = [];
  for (let node = target; node !== null; node = previous.get(node)) path.push(node);
  return path.reverse();
}

console.log(shortestPath('app', 'button', dependencies)); // ['app', 'ui', 'button']
console.log(shortestPath('url', 'app', dependencies)); // null，边是有向的

previous 一个变量干了两件事：它记录了访问过哪些节点，也记录了每个节点是从谁那里过来的。找到目标以后，顺着 previous 一路往回找，就是完整路径，最后反转一下。

第二个调用返回 null，因为边是有方向的。app 依赖 url，不代表 url 能走到 app。

队列为什么用 head 下标去读，而不是 shift()？因为 shift() 每次要把整个数组往前挪一位，队列大了会很慢。

检查循环依赖，并排出依赖优先的顺序

JavaScript
function dependencyFirstOrder(graph) {
  const state = new Map();
  const order = [];

  function visit(node) {
    const current = state.get(node);
    if (current === 'visiting') throw new Error(`发现循环依赖：${node}`);
    if (current === 'done') return;
    state.set(node, 'visiting');
    for (const neighbor of graph.get(node) ?? []) visit(neighbor);
    state.set(node, 'done');
    order.push(node);
  }

  for (const node of graph.keys()) visit(node);
  return order;
}

console.log(dependencyFirstOrder(dependencies));
// ['url', 'router', 'button', 'ui', 'app']

为什么要三种状态，两种不够吗？只用“访问过”的话，分不清两种情况：一种是这个节点在当前这条路上，又绕回来了，这是环；另一种是它之前从别的路走过、已经处理完了，这完全正常。“访问中”表示还在当前路径上，碰到它才是环。

节点要等它所有的依赖都处理完了，才加进 order。所以结果里，被依赖的总是排在使用者前面，url 在 router 前，app 在最后。这就是一种拓扑排序。

这里为了展示三种状态用了递归，依赖链很长时要改成显式栈。基于入度的另一种写法，见《如何用拓扑排序解析前端任务和模块依赖？》。

常见追问

DFS 和 BFS 的空间复杂度是多少？

都是 O(V)。但占空间的时机不同：图很宽时，BFS 的队列会很大；路径很长时，DFS 的栈会很深。

边有权重时，还能用 BFS 找最短路径吗？

不能。BFS 只保证经过的边数最少。边有权重时，要用 Dijkstra 算法。

依赖要异步加载时怎么遍历？

先把节点标记成访问过，再去发请求，这样同一个节点不会被重复加载。同时要限制并发的请求数量。
