前端场景中的图遍历应该怎样建模？

模块依赖、页面跳转和组件引用都可以建模为有向图。DFS 用栈沿一条路径走到底，适合找出所有可达节点和检测循环依赖；BFS 用队列逐层扩展，能找到边数最少的路径。两者都要用访问集合避免在环上无限循环。

参考答案

简答

  • 图用 Map<节点, 邻居数组> 的邻接表表示，app → router 表示 app 依赖 router。
  • DFS 用栈，先沿一条路径深入；BFS 用队列，按距离逐层扩展，第一次到达目标时得到的就是边数最少的路径。
  • 两者都用 Set 记录访问过的节点，否则遇到环会无限循环；时间复杂度都是 O(V + E)。
  • 检测循环依赖用 DFS 的三种状态：未访问、访问中、已完成。遇到"访问中"的节点说明存在环。
  • 用显式栈或队列代替递归，可以避免深度很大的图导致调用栈溢出；起点不在图中时，下面的实现统一返回 null。

邻接表

JavaScript
const dependencies = new Map([
  ['app', ['router', 'ui']],
  ['router', ['url']],
  ['ui', ['button']],
  ['button', []],
  ['url', []],
]);

图和树的区别在于一个节点可以有多个父节点，也可以有环，因此遍历时必须记录访问过的节点。

DFS：所有可达节点

JavaScript
function depthFirst(start, graph) {
  if (!graph.has(start)) return null;
  const visited = new Set();
  const stack = [start];

  while (stack.length > 0) {
    const node = stack.pop();
    if (visited.has(node)) continue;
    visited.add(node);
    const neighbors = graph.get(node) ?? [];
    // 反向入栈，让第一个邻居先出栈，与递归 DFS 的访问顺序一致。
    for (let index = neighbors.length - 1; index >= 0; index--) {
      if (!visited.has(neighbors[index])) stack.push(neighbors[index]);
    }
  }
  return [...visited];
}

console.log(depthFirst('app', dependencies));
// ['app', 'router', 'url', 'ui', 'button']

用途：分析一个入口文件会打包进哪些模块、删除某个包会影响哪些页面。

BFS：最短路径

JavaScript
function shortestPath(start, target, graph) {
  if (!graph.has(start)) return null;
  const queue = [start];
  const previous = new Map([[start, null]]);

  for (let head = 0; head < queue.length; head++) {
    const node = queue[head];
    if (node === target) break;
    for (const neighbor of graph.get(node) ?? []) {
      if (previous.has(neighbor)) continue;
      previous.set(neighbor, node);
      queue.push(neighbor);
    }
  }

  if (!previous.has(target)) return null;
  const path = [];
  for (let node = target; node !== null; node = previous.get(node)) path.push(node);
  return path.reverse();
}

console.log(shortestPath('app', 'button', dependencies)); // ['app', 'ui', 'button']
console.log(shortestPath('url', 'app', dependencies)); // null，边是有向的

previous 同时充当访问集合，并记录每个节点是从哪里来的，用来回溯出路径。用下标遍历队列，避免 shift() 每次移动整个数组。

循环依赖检测与依赖优先顺序

JavaScript
function dependencyFirstOrder(graph) {
  const state = new Map();
  const order = [];

  function visit(node) {
    const current = state.get(node);
    if (current === 'visiting') throw new Error(`发现循环依赖：${node}`);
    if (current === 'done') return;
    state.set(node, 'visiting');
    for (const neighbor of graph.get(node) ?? []) visit(neighbor);
    state.set(node, 'done');
    order.push(node);
  }

  for (const node of graph.keys()) visit(node);
  return order;
}

节点在所有依赖处理完后才加入 order（后序），所以结果中依赖总排在使用者之前，这就是一种拓扑排序。示例为了展示三种状态使用了递归，依赖链很长时要改成显式栈。基于入度的写法见《如何用拓扑排序解析前端任务和模块依赖？》。

常见追问

  • DFS 和 BFS 的空间复杂度？ 都是 O(V)。BFS 的队列在图很宽时会很大，DFS 的栈在路径很长时会很深。
  • 边有权重时还能用 BFS 找最短路径吗？ 不能。BFS 只保证边数最少，带权重要用 Dijkstra。
  • 依赖要异步加载时怎么遍历？ 先把节点标记为访问过再发起请求，避免同一个节点被重复加载；同时限制并发请求数。
