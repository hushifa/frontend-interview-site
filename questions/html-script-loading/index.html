script 的 async、defer 和 module 有什么区别？

普通 script 会暂停 HTML 解析去下载和执行；defer 并行下载，在解析完成后按顺序执行；async 并行下载，下载完立即执行、不保证顺序；type="module" 默认按 defer 方式执行，并启用模块语义。

参考答案

简答

  • 普通 <script src>：解析到这里就停下，下载并执行完才继续，放在 head 里会推迟页面显示。
  • defer：下载不阻塞解析，在 HTML 解析完、DOMContentLoaded 之前按书写顺序执行。
  • async：下载不阻塞解析，下载完马上执行，多个 async 脚本谁先下载完谁先执行。
  • type="module"：默认像 defer，可以加 async；支持 import、自动严格模式、顶层变量不进全局，同一模块只执行一次。
  • 依赖页面 DOM 或其他脚本的代码用 defer 或模块；独立的统计、广告脚本用 async。

时间线

text
普通：  解析 ──停──[下载][执行]── 继续解析
defer： 解析 ─────────────────────── 完成 → [执行]
          └──[下载]──┘
async： 解析 ─────停──[执行]── 继续解析
          └──[下载]┘

写法

HTML
<head>
  <script src="/app.js" defer></script>
  <script type="module" src="/main.js"></script>
  <script src="https://analytics.example.com/a.js" async></script>
</head>
  • defer 和 async 只对外部脚本生效，内联脚本写了也没用；内联模块脚本可以加 async。
  • 模块脚本跨源加载需要 CORS 响应头。
  • 动态创建的 <script> 默认就是 async，需要顺序时设置 script.async = false。

下载不阻塞不等于不卡

脚本执行仍然占用主线程。大的打包文件即使用了 defer，执行时也会推迟交互。减少首屏 JavaScript、按路由拆分代码，比调整属性更重要。

预加载

  • <link rel="modulepreload" href="/chunk.js"> 提前下载并解析模块依赖。
  • <link rel="preload" as="script"> 提前下载普通脚本，但不会执行。

常见追问

  • 脚本放在 body 末尾和 head 里加 defer 有什么区别？两者都不阻塞解析。defer 让浏览器更早发现并开始下载脚本，所以通常更快。
