script 的 async、defer 和 module 有什么区别？

普通 script 会让浏览器停下解析去下载和执行；defer 边解析边下载，解析完再按顺序执行；async 边解析边下载，下载完马上执行，不保证顺序；module 默认和 defer 一样，还多了模块的规则。

参考答案

简答

浏览器读 HTML 时碰到一个普通的 <script src>，会停下来，等脚本下载完、执行完才接着往下读。放在 head 里的大脚本，就会推迟页面显示。

defer 和 async 都让下载不再挡着解析，区别在什么时候执行。defer 等 HTML 全部解析完，在 DOMContentLoaded 之前按书写顺序执行。async 下载完马上执行，多个 async 脚本谁先下载完谁先执行。

type="module" 默认就像 defer，也可以加 async。它还开启了模块的规则：能用 import，自动严格模式，顶层变量不会跑到全局，同一个模块只执行一次。

怎么选：依赖页面 DOM 或其他脚本的代码，用 defer 或模块；统计、广告这种独立的脚本，用 async。要注意下载不挡解析，不等于页面不卡，脚本执行时照样占主线程。

三种方式的时间线

text
普通：  解析 ──停──[下载][执行]── 继续解析
defer： 解析 ─────────────────────── 完成 → [执行]
          └──[下载]──┘
async： 解析 ─────停──[执行]── 继续解析
          └──[下载]┘

普通脚本，下载和执行都在解析的路上，解析只能等着。

defer 的下载和解析同时进行，执行被推到解析完成以后，所以完全不打断解析。

async 的下载也是同时进行的，可是一下载完就插队执行，执行的这段时间解析还是要停下来。而且执行时机取决于下载快慢，所以顺序没法保证。

写法和要注意的地方

HTML
<head>
  <script src="/app.js" defer></script>
  <script type="module" src="/main.js"></script>
  <script src="https://analytics.example.com/a.js" async></script>
</head>

defer 和 async 只对外部脚本生效，写在内联脚本上没有用。内联的模块脚本是例外，可以加 async。

模块脚本跨源加载时，服务器需要返回 CORS 响应头，不然加载不了。

用 JavaScript 动态创建的 <script>，默认就是 async 的。需要它们按顺序执行时，设置 script.async = false。

用了 defer，为什么页面还是卡

defer 只解决了下载阻塞解析的问题，脚本执行时仍然占着主线程。一个很大的打包文件，就算用了 defer，执行的那段时间用户点什么都没反应。

所以减少首屏的 JavaScript、按路由拆分代码，比调整这几个属性更重要。

想提前下载脚本怎么办

<link rel="modulepreload" href="/chunk.js"> 提前下载并解析模块依赖，等真正用到时就不用再等。

<link rel="preload" as="script"> 提前下载普通脚本，但只下载不执行。

常见追问

脚本放在 body 末尾，和放在 head 里加 defer，有什么区别？

两种都不阻塞解析。区别在于下载开始的时间。放在 head 里，浏览器一开始就发现了它，马上开始下载；放在 body 末尾，要等前面的 HTML 都读完才发现。所以 defer 通常更快。
