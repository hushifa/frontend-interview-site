迭代器、可迭代对象和 Generator 有什么关系？

可迭代对象负责提供遍历入口，迭代器负责记录当前位置并产生下一项，Generator 则用可暂停函数方便地实现这些协议。它们描述取值过程，不代表自动并行或自动收集全部数据。

参考答案

可以把可迭代对象理解成“能开始一次遍历的数据来源”，把迭代器理解成“这次遍历的游标”。前者提供入口，后者记住当前进度；二者可以由同一个对象实现，也可以分别实现。

for...of、数组展开、数组解构等语法不是只认识数组，它们会按迭代协议请求数据。普通对象即使有很多属性，也不自动拥有这种遍历方式；要处理它的记录字段，可以先用 Object.entries 等明确转换。

两个协议各自要求什么

可迭代对象提供 Symbol.iterator 方法。消费者调用它，得到一个迭代器。

迭代器提供 next() 方法，每次返回一个结果对象。done 表示是否结束，value 是本次结果。done:false 时消费者继续处理 value；done:true 表示遍历已经结束，value 可以表示终止结果，但一般 for...of 不会把这个终止值当成普通元素输出。

JavaScript
function range(start, end) {
  if (!Number.isSafeInteger(start) || !Number.isSafeInteger(end)) {
    throw new TypeError('区间端点必须是安全整数');
  }
  return {
    [Symbol.iterator]() {
      let current = start;
      return {
        next() {
          if (current >= end) return { done: true, value: undefined };
          return { done: false, value: current++ };
        },
      };
    },
  };
}

const numbers = range(2, 5);
console.log([...numbers].join(',')); // 2,3,4
console.log([...numbers].join(',')); // 2,3,4
const iterator = numbers[Symbol.iterator]();
const first = iterator.next();
console.log(first.value); // 2
console.log(first.done); // false

这里是 start 到 end、不包含 end 的整数区间。每次调用 Symbol.iterator 都创建一份 current，所以可以重新遍历，也可以同时有多个互不干扰的游标。

返回的游标只实现了 next，没有给自己定义 Symbol.iterator，因此它是迭代器，但不能直接假定它也是可迭代对象。许多内置迭代器会额外让 iterator[Symbol.iterator]() 返回自身，从而同时满足两种协议。

Generator 用函数暂停点保存遍历状态

手写游标需要自己维护当前位置。Generator 通过 function*、yield 和 next，把暂停位置与局部变量状态一起保存下来：

JavaScript
function* sequence() {
  console.log('开始执行');
  const reply = yield 1;
  console.log(reply);
  return 9;
}

const sequenceIterator = sequence();
console.log('已创建');
console.log(sequenceIterator.next().value); // 1
console.log(sequenceIterator.next('收到').value); // 9
console.log(sequenceIterator.next().done); // true
// 输出顺序：已创建 → 开始执行 → 1 → 收到 → 9 → true

调用 sequence() 先得到生成器对象，函数体还没有开始运行。第一次 next 才执行到 yield 1，向调用方交出 { value: 1, done: false }，并暂停在这个位置。

第二次 next('收到') 恢复执行，使前一个 yield 表达式得到 '收到'，然后继续到 return 9，产生 { value: 9, done: true }。生成器结束后，后续 next 通常继续得到 done:true。

第一下 next 传入的参数没有一个已经暂停的 yield 表达式来接收，因此不能把它当成 Generator 函数的初始化参数；初始化参数应在调用 sequence(...) 时传入。

可重复的数据来源与一次性的游标要区分

Generator 对象同时是迭代器和可迭代对象，它的 Symbol.iterator 返回自身。已经消费过的进度不会因为又写了一次 for...of 或展开语法就重置。

如果需要重新遍历，通常重新调用 Generator 函数，得到一个新生成器。前面的 range 则通过每次提供新游标实现重复遍历。接口使用者应该知道拿到的是可重复来源，还是正在消费中的一次性流程。

JavaScript
function* words() {
  yield '第一项';
  yield* ['第二项', '第三项'];
  return '结束标记';
}

console.log([...words()].join(',')); // 第一项,第二项,第三项

yield* 把遍历委托给另一个可迭代对象。return 的结束标记没有出现在展开结果中，因为它伴随 done:true。若需要结束标记作为普通数据，就应显式 yield 它，而不是指望所有消费者都会使用终止 value。

惰性减少的是不必要的提前工作

生成器可以在消费者请求下一项时才计算，不必一开始就构造整个数组。大区间、分阶段处理、树遍历等场景可以因此减少一次性分配，也能在只需要前几项时提前停止。

但如果消费端立刻执行 [...iterator]，仍然会把全部结果放进数组；无限生成器这样展开还会一直执行。惰性也不等于低内存保证，生成器暂停时仍可能保留它需要访问的大型状态。

Generator 不是线程。next 恢复后，内部同步代码仍然占用当前执行线程，直到下一个 yield、return 或异常。一次 next 中做大量计算，仍可能阻塞页面。

资源清理和异步数据是下一层协议

迭代器可以额外提供 return、throw 等方法。for...of 提前退出时会在相应条件下尝试关闭迭代器，生成器中的 finally 常用于处理清理；但手动 next 后弃置、生产者 next 自身失败等情况需要单独理解，不能宣称任何退出都自动释放资源。

异步数据源则可以实现 Symbol.asyncIterator，让 next 返回可等待的结果，由 for await...of 消费。普通 Generator 不会仅因 yield 一个 Promise 就变成线程或并发池；是否等待、以何种顺序消费，取决于使用的是同步还是异步协议及消费者写法。
