迭代器、可迭代对象和 Generator 有什么关系？

可迭代对象能交出一个迭代器，迭代器每调用一次 next() 就给出下一个值。for...of、展开、解构都靠这套约定取值。Generator 函数用 yield 一步一步产出值，自动满足这套约定。

参考答案

简答

for...of、展开、解构能遍历数组、字符串、Map、Set，是因为它们都遵守同一套约定，叫迭代协议。普通对象没有遵守，所以不能直接 for...of。

这套约定有两个角色。可迭代对象有一个 [Symbol.iterator]() 方法，每次调用都返回一个新的迭代器。迭代器有一个 next() 方法，每调用一次返回 { value, done }，并记住遍历到了哪里。

手写这两层比较麻烦，Generator 函数可以自动搞定。它调用后返回一个生成器对象，既是迭代器，又是可迭代对象，[Symbol.iterator]() 返回它自己，所以只能遍历一次。它是惰性执行的，第一次 next() 才开始运行函数体，每到一个 yield 就暂停。

ES2025 又在迭代器上加了 Iterator helpers，也就是 map、filter、take、drop、flatMap、reduce、toArray 等方法，可以直接链式调用，而且也是惰性的。

怎样让自己的对象能被 for...of 遍历

下面手写一个 range，返回从 start 到 end 前一个数的序列。注意它被展开了两次，结果都一样。

JavaScript
function range(start, end) {
  if (!Number.isSafeInteger(start) || !Number.isSafeInteger(end)) {
    throw new TypeError('区间端点必须是安全整数');
  }
  return {
    [Symbol.iterator]() {
      let current = start;
      return {
        next() {
          if (current >= end) return { done: true, value: undefined };
          return { done: false, value: current++ };
        },
      };
    },
  };
}

const numbers = range(2, 5);
console.log([...numbers].join(',')); // 2,3,4
console.log([...numbers].join(',')); // 2,3,4
const iterator = numbers[Symbol.iterator]();
const first = iterator.next();
console.log(first.value); // 2
console.log(first.done); // false

展开语法做的事情是：调用 numbers[Symbol.iterator]() 拿到一个迭代器，然后不停调用 next()，直到 done 为 true。

为什么能展开两次？因为每次展开都会重新调用 [Symbol.iterator]()，拿到一个新的迭代器，current 从 start 重新开始。遍历的位置记在迭代器里，不在 numbers 上，所以可迭代对象本身可以反复遍历。

最后几行手动调用一次 next()，可以看到它返回的就是 { value: 2, done: false }。

Generator 是怎样一步一步执行的

JavaScript
function* sequence() {
  console.log('开始执行');
  const reply = yield 1;
  console.log(reply);
  return 9;
}

const it = sequence();
console.log('已创建');
console.log(it.next().value);     // 开始执行 → 1
console.log(it.next('收到').value); // 收到 → 9
console.log(it.next().done);      // true

调用 sequence() 时，函数体一行都没执行，所以“已创建”先打印。第一次 next() 才开始运行，打印“开始执行”，走到 yield 1 暂停，把 1 交出来。

第二次调用 next('收到')，传进去的参数就成了上一个 yield 表达式的值，所以 reply 是“收到”。函数继续运行到 return 9，结束。第一次 next 传的参数没有对应的 yield 来接，会被忽略。

return 的值会和 done: true 一起返回，但 for...of 和展开语法看到 done: true 就停了，不会包含这个值。想把遍历交给另一个可迭代对象，可以写 yield* iterable。

还要知道，生成器不是线程。调用 next() 以后，函数体在主线程上同步运行，直到下一个 yield 才把控制权交回来。

Iterator helpers 怎样处理无限序列

JavaScript
function* naturals() {
  let n = 1;
  while (true) yield n++;
}

const result = naturals()
  .filter((n) => n % 2 === 0)
  .map((n) => n * n)
  .take(3)
  .toArray();
console.log(result); // [4, 16, 36]

naturals() 是一个无限序列，while (true) 永远不会结束，可这段代码很快就返回了 [4, 16, 36]。

因为这些方法是惰性的。filter、map、take 都只是返回一个新的迭代器，不会马上计算。只有 toArray 开始要值时，才一个一个往回取，take(3) 拿够 3 个就停，后面的数根本不会生成。同样会真正消费数据的方法还有 reduce、forEach、some、every、find。除了上面用到的，还有 drop 跳过前 n 项，flatMap 把每项返回的迭代器展开。

这些方法在迭代器上，不在数组上。数组要先调用 values() 拿到迭代器才能用。只有 next() 方法的对象，可以用 Iterator.from(obj) 包装一下再用。

实际开发里用在哪里

最常见的是惰性序列，比如分页数据、树的遍历、无限生成 ID，需要多少取多少。另一个用途是让自定义的数据结构支持 for...of 和展开。生成器还可以写状态机，用暂停的位置代替手写的状态变量。

要小心 [...iterator] 会一次取出所有值，对无限序列来说永远不会结束。提前退出时怎么清理，见《JavaScript 迭代器关闭和 return 方法有什么作用？》；数据是异步到达的，见《异步迭代器和 for await...of 适合处理什么数据？》。

常见追问

怎样让普通对象可以 for...of？

给它加一个生成器方法：*[Symbol.iterator]() { yield* Object.entries(this); }，这样每次遍历拿到的就是 [键, 值]。

生成器的 throw() 做什么？

它在生成器暂停的那个 yield 处抛出一个错误。如果生成器里面在那里写了 try/catch，就能接住这个错误并继续执行。
