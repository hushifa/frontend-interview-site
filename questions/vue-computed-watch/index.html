computed、watch 和 watchEffect 应该如何选择？

computed 从响应式数据推导新值并缓存，不应有副作用；watch 监听明确的来源，变化时执行副作用，能拿到新旧值；watchEffect 立即执行并自动追踪同步读取的数据。派生数据用 computed，副作用用 watch 或 watchEffect。

参考答案

简答

  • computed：返回一个只读 ref，依赖不变时直接返回缓存结果；getter 应是纯计算，不发请求、不修改其他状态。
  • watch(source, callback)：只在指定来源变化时执行回调，回调参数是新值和旧值；默认懒执行，加 immediate: true 可以立即执行一次。
  • watchEffect(fn)：立即执行，自动追踪执行期间同步读取的响应式数据；await 之后读取的数据不会被追踪。
  • 侦听器里清理上一次的副作用（取消请求）：Vue 3.5 起用 onWatcherCleanup，旧写法是回调的第三个参数 onCleanup。
  • 能用 computed 表达的就不要用 watch 去同步另一份状态。

computed：派生数据

JavaScript
const items = ref([{ price: 10, count: 2 }, { price: 5, count: 1 }]);
const total = computed(() => items.value.reduce((s, i) => s + i.price * i.count, 0));

不要写成 watch(items, () => { total.value = ... }, { deep: true })，那样多了一份需要同步的状态。

watch：对指定变化做副作用

JavaScript
import { ref, watch, onWatcherCleanup } from 'vue';

const userId = ref(1);
const user = ref(null);

watch(
  userId,
  async (id) => {
    const controller = new AbortController();
    onWatcherCleanup(() => controller.abort());
    const res = await fetch(`/api/users/${id}`, { signal: controller.signal });
    user.value = await res.json();
  },
  { immediate: true },
);

userId 快速变化时，上一次请求被取消，旧结果不会覆盖新结果。注意 onWatcherCleanup 必须在第一个 await 之前调用。

侦听来源的写法

JavaScript
const state = reactive({ keyword: '', page: 1 });

watch(() => state.keyword, (kw) => { state.page = 1; }); // getter
watch([() => state.keyword, () => state.page], ([kw, page]) => search(kw, page)); // 多个来源
watch(state, () => save(state)); // reactive 对象，默认深层侦听

侦听 reactive 对象的某个属性必须写成 getter，watch(state.keyword, ...) 传入的只是一个字符串。

watchEffect：自动追踪

JavaScript
watchEffect(() => {
  document.title = `${unread.value} 条未读 - ${siteName.value}`;
});

依赖多、且都在同步代码中读取时，watchEffect 更简洁。依赖不明显或需要旧值时，用 watch 更清楚。

回调执行时机

默认情况下，侦听器回调在父组件更新之后、本组件 DOM 更新之前执行。需要在回调中读取更新后的 DOM，设置 flush: 'post'（或用 watchPostEffect）；需要同步触发，设置 flush: 'sync'，但要谨慎使用。

常见追问

  • 怎么停止侦听？watch 和 watchEffect 返回停止函数；在 setup 中同步创建的侦听器会在组件卸载时自动停止，异步创建的要手动停止。
  • computed 可以写吗？可以传入 { get, set } 创建可写 computed，常用于包装 v-model，见《组件 v-model 的本质是什么？》。
