computed、watch 和 watchEffect 应该如何选择？

要从已有数据算出一个新值，用 computed，它会缓存结果；数据变了要去做一件事，比如发请求，用 watch 或 watchEffect。watch 盯着你指定的数据，watchEffect 自动追踪它用到的数据。

参考答案

简答

先看要干什么。如果是根据已有数据算出一个新值，比如购物车总价，就用 computed。如果是数据变了以后去做一件事，比如发请求、改 document.title，就用 watch 或 watchEffect，这类“计算之外的动作”叫副作用。

computed 返回一个只读 ref，依赖没变就直接返回缓存的结果，所以它的 getter 应该是纯计算，不发请求，也不改别的状态。

watch(source, callback) 只盯你指定的来源，回调能拿到新值和旧值，默认第一次不执行，加 immediate: true 才会立刻跑一次。watchEffect(fn) 会立刻执行一次，执行时同步读到了哪些响应式数据，就自动追踪哪些；await 之后读的不算。

有两点要注意。能用 computed 表达的，就别用 watch 去同步另一份状态。侦听器里发请求时，要清理上一次的请求，Vue 3.5 起用 onWatcherCleanup，旧写法是回调的第三个参数 onCleanup。

派生数据为什么用 computed

购物车的总价完全由商品列表决定，这种值叫派生数据：

JavaScript
const items = ref([{ price: 10, count: 2 }, { price: 5, count: 1 }]);
const total = computed(() => items.value.reduce((s, i) => s + i.price * i.count, 0));

有人会写成 watch(items, () => { total.value = ... }, { deep: true })。结果是对的，可是多了一份 total 要你手动维护。哪天漏了一个更新路径，两边就对不上了。computed 直接声明“总价等于这个算式”，Vue 负责在依赖变化时重新算，没变时直接用缓存。

用 watch 在数据变化时发请求

userId 变了就重新拉用户信息，这是典型的副作用：

JavaScript
import { ref, watch, onWatcherCleanup } from 'vue';

const userId = ref(1);
const user = ref(null);

watch(
  userId,
  async (id) => {
    const controller = new AbortController();
    onWatcherCleanup(() => controller.abort());
    const res = await fetch(`/api/users/${id}`, { signal: controller.signal });
    user.value = await res.json();
  },
  { immediate: true },
);

如果 userId 从 1 快速变到 2，请求 1 可能比请求 2 晚回来，把正确结果盖掉。所以每次执行前，onWatcherCleanup 注册的函数会先把上一次的请求取消。注意它必须在第一个 await 之前调用，因为它要知道自己属于哪一次执行。

watch 的来源该怎么写

JavaScript
const state = reactive({ keyword: '', page: 1 });

watch(() => state.keyword, (kw) => { state.page = 1; }); // getter
watch([() => state.keyword, () => state.page], ([kw, page]) => search(kw, page)); // 多个来源
watch(state, () => save(state)); // reactive 对象，默认深层侦听

最常见的错误是写成 watch(state.keyword, ...)。这样传进去的只是当时的一个字符串，Vue 没法知道它后来变没变。所以侦听 reactive 对象的某个属性，必须包成 getter 函数。

watchEffect 适合什么情况

JavaScript
watchEffect(() => {
  document.title = `${unread.value} 条未读 - ${siteName.value}`;
});

这里用到了两个数据，watchEffect 自动把它们都追踪上，写起来比 watch([unread, siteName], ...) 简洁。可是如果依赖藏得深、不好一眼看出来，或者你需要旧值，就用 watch，来源写得明明白白。

回调在什么时候执行

默认情况下，侦听器回调在父组件更新之后、本组件 DOM 更新之前执行。所以在回调里读本组件的 DOM，拿到的还是旧的。要读更新后的 DOM，设置 flush: 'post'，或者直接用 watchPostEffect。也可以设 flush: 'sync' 让它同步触发，但每次改数据都立刻执行，要谨慎使用。

常见追问

怎么停止侦听？

watch 和 watchEffect 都返回一个停止函数，调用它就行。在 setup 里同步创建的侦听器会在组件卸载时自动停止；在异步回调里创建的不会，要自己手动停。

computed 可以写入吗？

可以，传入 { get, set } 就能创建可写的 computed，常用来包装 v-model，见《组件 v-model 的本质是什么？》。
