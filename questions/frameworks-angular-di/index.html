Angular 依赖注入的层级和作用域怎样理解？

组件需要一个服务时，Angular 根据 token 在注入器树中查找 provider：先从当前元素注入器向上找组件和指令的 providers，再到环境注入器（路由、应用根）。服务是否为单例，取决于 provider 注册在哪一层。

参考答案

简答

依赖注入就是组件不自己 new 服务，而是说“我要一个 AuthService”，由 Angular 去找一个给它。负责找和创建的叫注入器，告诉注入器“这个东西怎么创建”的配置叫 provider。

服务是不是全局只有一个，看 provider 注册在哪一层。写 @Injectable({ providedIn: 'root' }) 就注册在应用根上，全应用共享一个实例，没人用时还能被 tree-shaking 删掉。注册在组件的 providers 里，每个组件实例和它的后代各有一份，组件销毁时服务也销毁。注册在路由的 providers 里，就由这个路由和它的子路由共享。

查找的顺序是：先从当前组件开始，沿着父组件一路往上找元素注入器；找不到再去环境注入器，依次是路由、应用根、平台。都没找到就报错，除非标了可选。

获取依赖推荐用 inject() 函数，它能用在字段初始化、工厂函数和路由守卫里。

三种作用域分别是什么样

先看全局单例和组件级别的写法：

TypeScript
// 全局单例
@Injectable({ providedIn: 'root' })
export class AuthService {}

// 每个编辑器组件各自一个
@Injectable()
export class EditorState {
  readonly dirty = signal(false);
}

@Component({
  selector: 'app-editor',
  providers: [EditorState],
  template: `<app-toolbar /><app-canvas />`,
})
export class EditorComponent {}

如果页面上放了两个 <app-editor>，它们里面的 toolbar 和 canvas 会拿到同一个 EditorState 吗？不会。toolbar 往上找，最先碰到的是自己所在那个编辑器的 providers，所以拿到的是这个编辑器的那份。两个编辑器各有一份，互不影响。

路由级别的写法是这样：

TypeScript
// 路由级共享
export const routes: Routes = [
  {
    path: 'admin',
    providers: [AdminApi],
    loadChildren: () => import('./admin/routes'),
  },
];

AdminApi 属于这个路由的环境注入器，admin 下面的页面共享一个实例。

不是类的依赖怎么注入

配置对象、字符串这类东西没有类可以当标识，就用 InjectionToken 造一个：

TypeScript
export const API_BASE = new InjectionToken<string>('API_BASE');

bootstrapApplication(App, {
  providers: [{ provide: API_BASE, useValue: 'https://api.example.com' }],
});

export class UserApi {
  private base = inject(API_BASE);
}

useValue 是直接给一个值。provider 还有几种写法：useClass 换一个实现类，测试时常用；useFactory 根据别的依赖现算出来；useExisting 给已有的依赖起个别名。

怎样控制查找范围

默认是一路往上找，inject() 的选项可以改变这个行为：

TypeScript
inject(Logger, { optional: true }); // 找不到返回 null
inject(Logger, { self: true }); // 只在当前元素注入器找
inject(Logger, { skipSelf: true }); // 从父级开始找
inject(Logger, { host: true }); // 查找到宿主组件为止

容易出错的地方

第一种是重复注册。一个服务已经写了 providedIn: 'root'，又在某个组件的 providers 里注册了一次，这个组件下面就会拿到第二个实例。两边的状态不同步，查起来很费劲。

第二种是懒加载路由里注册的服务，在这个路由外面是注入不到的，因为外面的查找路线根本经过不了它。

第三种是 inject() 的调用位置。它只能在注入上下文里调用，也就是构造期间、工厂函数里。在 ngOnInit 或者异步回调里调会报错。特殊场景可以用 runInInjectionContext 处理。

常见追问

providers 和 viewProviders 有什么区别？

viewProviders 里的服务只对组件自己的模板可见。通过内容投影传进来的子内容，也就是写在组件标签中间的那部分，拿不到它。

和 Vue 的 provide/inject 像吗？

像，都是沿着组件树往上找。不同的是 Angular 在组件树之外还有一层环境注入器，而且有类型化的 token 体系。
