Angular 依赖注入的层级和作用域怎样理解？

Angular 根据 token 在注入器树中查找 provider：先从当前元素注入器向上找组件和指令的 providers，再到环境注入器（路由、应用根）。服务是否为单例，取决于 provider 注册在哪一层。

参考答案

简答

  • @Injectable({ providedIn: 'root' }) 在应用根注入器注册，全应用共享一个实例，并且没有被使用时可以被 tree-shaking 移除。
  • 在组件的 providers 中注册，每个组件实例（及其后代）得到独立的服务实例，组件销毁时服务也销毁。
  • 在路由配置的 providers 中注册，实例属于该路由的环境注入器，供该路由及其子路由共享。
  • 查找顺序：元素注入器（当前组件 → 父组件 → …）→ 环境注入器（路由 → 应用根 → 平台）；都找不到就报错，除非标记为可选。
  • 推荐用 inject() 函数获取依赖，它可以在构造阶段的字段初始化、工厂函数和路由守卫中使用。

三种作用域

TypeScript
// 全局单例
@Injectable({ providedIn: 'root' })
export class AuthService {}

// 每个编辑器组件各自一个
@Injectable()
export class EditorState {
  readonly dirty = signal(false);
}

@Component({
  selector: 'app-editor',
  providers: [EditorState],
  template: `<app-toolbar /><app-canvas />`,
})
export class EditorComponent {}

页面上有两个 <app-editor> 时，各自的 toolbar 和 canvas 注入的是自己父编辑器的 EditorState，互不影响。

TypeScript
// 路由级共享
export const routes: Routes = [
  {
    path: 'admin',
    providers: [AdminApi],
    loadChildren: () => import('./admin/routes'),
  },
];

注入令牌

非类的依赖（配置对象、字符串）用 InjectionToken：

TypeScript
export const API_BASE = new InjectionToken<string>('API_BASE');

bootstrapApplication(App, {
  providers: [{ provide: API_BASE, useValue: 'https://api.example.com' }],
});

export class UserApi {
  private base = inject(API_BASE);
}

provider 还可以写成 useClass（替换实现，常用于测试）、useFactory（根据其他依赖创建）、useExisting（别名）。

查找修饰

TypeScript
inject(Logger, { optional: true }); // 找不到返回 null
inject(Logger, { self: true }); // 只在当前元素注入器找
inject(Logger, { skipSelf: true }); // 从父级开始找
inject(Logger, { host: true }); // 查找到宿主组件为止

常见问题

  • 在组件 providers 里又注册了一次 providedIn: 'root' 的服务，会创建第二个实例，导致状态不同步。
  • 懒加载路由中注册的服务，在路由外部注入不到。
  • inject() 只能在注入上下文中调用（构造期间、工厂函数中），在 ngOnInit 或异步回调中调用会报错，可以用 runInInjectionContext 处理特殊场景。

常见追问

  • providers 和 viewProviders 的区别？viewProviders 中的服务只对组件自己的模板可见，通过内容投影传入的子内容拿不到。
  • 和 Vue 的 provide/inject 有什么相似之处？都是沿组件树向上查找，Angular 额外有环境注入器和类型化的 token 体系。
