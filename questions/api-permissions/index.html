Permissions.query 是申请权限，还是查询权限？

navigator.permissions.query() 只查询当前授权状态（granted、denied、prompt），不会弹出授权框；真正请求权限要调用对应 API，例如 getUserMedia 或 Notification.requestPermission。

参考答案

简答

  • navigator.permissions.query({ name }) 返回 PermissionStatus，state 为 granted、denied 或 prompt，不会弹窗。
  • 申请权限要调用功能本身的 API，浏览器在需要时弹出授权框。
  • PermissionStatus 的 change 事件可以监听用户在浏览器设置里修改授权。
  • 各浏览器支持查询的权限名称不同，不支持的名称会让 Promise 以 TypeError reject。

示例：根据状态决定界面

JavaScript
async function getCameraPermission() {
  try {
    const status = await navigator.permissions.query({ name: 'camera' });
    status.addEventListener('change', () => updateCameraButton(status.state));
    return status.state;
  } catch {
    return 'unknown';
  }
}

async function openCamera() {
  return navigator.mediaDevices.getUserMedia({ video: true });
}
  • granted：可以直接调用功能。
  • prompt：先用页面上的说明告诉用户为什么需要，再由用户点击触发 getUserMedia。
  • denied：浏览器不会再弹窗，只能引导用户去浏览器设置里打开。
  • unknown：查询不可用，直接调用功能并处理失败。

申请权限的对应 API

权限申请方式
摄像头、麦克风navigator.mediaDevices.getUserMedia()
地理位置navigator.geolocation.getCurrentPosition()
通知Notification.requestPermission()
剪贴板读取navigator.clipboard.readText()
持久存储navigator.storage.persist()

注意事项

  • 只有在用户执行了相关操作时才申请，页面一打开就弹授权框，用户更可能拒绝，被拒后很难再恢复。
  • 查询结果是 granted 也要处理调用失败：设备可能被其他程序占用，iframe 也可能被 Permissions-Policy 禁止。
