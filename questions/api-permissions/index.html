Permissions.query 是申请权限，还是查询权限？

Permissions.query 查询当前上下文对某项能力的权限状态，常见结果是 granted、denied 或 prompt。它本身通常不是弹出授权框的统一申请入口，实际请求权限由相应功能 API 的流程决定。

参考答案

Permissions.query 查询当前上下文对某项能力的权限状态，常见结果是 granted、denied 或 prompt。它本身通常不是弹出授权框的统一申请入口，实际请求权限由相应功能 API 的流程决定。

权限状态综合考虑安全上下文、Permissions Policy、用户设置以及其他约束。即使此前获准，后续调用仍可能因环境变化或设备不可用而失败，因此业务必须处理实际调用结果。

不同浏览器支持的 permission descriptor 并不一致，对未知名称查询可能失败。页面应在用户真正需要功能时解释用途，并提供拒绝后的替代路径，不能通过反复弹窗把 denied 当成可无限重试的状态。

使用 Web API 前要确认安全上下文、权限、用户手势、浏览器支持和可用的降级路径。请求、监听器、流、对象 URL 或设备句柄都应有明确的结束和清理逻辑，不能把“调用成功”当成整个任务已经完成。

接口返回的异常、取消和用户拒绝应分别处理。浏览器端的取消只代表客户端停止等待，涉及写入、上传或设备操作时还要查询实际状态。

实际接入设备、文件或权限 API 时，用户拒绝、浏览器不支持和页面失去焦点都属于正常分支。界面要让用户知道当前阶段和下一步操作，代码则要确保失败后可以再次尝试而不是卡在半完成状态。
