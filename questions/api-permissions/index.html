Permissions.query 是申请权限，还是查询权限？

只是查询。navigator.permissions.query() 告诉你当前是已允许、已拒绝还是待询问，不会弹授权框；真正申请权限要调用功能本身，比如 getUserMedia。

参考答案

简答

是查询。navigator.permissions.query({ name: 'camera' }) 返回一个 PermissionStatus，它的 state 是 granted（已允许）、denied（已拒绝）或 prompt（还没问过），整个过程不会弹窗。

真正申请权限，要调用功能本身的 API。比如摄像头调 getUserMedia()，通知调 Notification.requestPermission()，浏览器在需要时才弹授权框。

查询的用处是提前决定界面怎么显示：已允许就直接用，待询问就先解释为什么需要，已拒绝就引导用户去浏览器设置里打开。PermissionStatus 还有 change 事件，用户在设置里改了授权，页面能收到。

要注意，各浏览器支持查询的权限名不一样，不支持的名称会让 Promise 以 TypeError reject，所以要 catch。查到 granted 也不代表一定能用，调用失败照样要处理。

根据权限状态决定界面

下面先查询摄像头权限，查询失败就返回 unknown。

JavaScript
async function getCameraPermission() {
  try {
    const status = await navigator.permissions.query({ name: 'camera' });
    status.addEventListener('change', () => updateCameraButton(status.state));
    return status.state;
  } catch {
    return 'unknown';
  }
}

async function openCamera() {
  return navigator.mediaDevices.getUserMedia({ video: true });
}

拿到状态以后，界面按四种情况处理。granted 可以直接调用功能。prompt 先在页面上告诉用户为什么需要摄像头，再让用户点击按钮触发 getUserMedia。denied 时浏览器不会再弹窗了，只能引导用户去浏览器设置里打开。unknown 说明查询不可用，就直接调用功能，并处理失败。

为什么 prompt 时不直接弹？因为页面一打开就弹授权框，用户不知道要干什么，更容易拒绝。一旦拒绝，状态就变成 denied，浏览器不再弹窗，很难恢复。

各种权限怎么申请

申请都是通过功能本身。摄像头和麦克风用 navigator.mediaDevices.getUserMedia()；地理位置用 navigator.geolocation.getCurrentPosition()；通知用 Notification.requestPermission()；剪贴板读取用 navigator.clipboard.readText()；持久存储用 navigator.storage.persist()。

为什么查到 granted 还会失败

权限只是“浏览器允许了”，并不保证功能一定能用。设备可能正被其他程序占用，摄像头打不开；页面在 iframe 里，也可能被 Permissions-Policy 禁止。所以调用时照样要 try/catch。

常见追问

为什么 query({ name: 'xxx' }) 会抛 TypeError？

因为这个浏览器不支持查询这种权限名。各浏览器支持的名称列表不一样，所以 query 一定要包在 try/catch 里，失败时退回“直接调用功能并处理错误”。

用户拒绝以后，还能再弹一次授权框吗？

一般不能。状态变成 denied 后，浏览器不会再弹窗，页面只能提示用户去浏览器设置里手动打开。所以申请时机很重要，要在用户执行相关操作时再申请。
