如何利用 Map 实现固定容量的 LRU 缓存？

LRU 是缓存满了时，淘汰最久没用过的那一条。JavaScript 的 Map 按插入顺序遍历，每次用到一个键就先删再插，把它挪到最后，排在最前面的就是该淘汰的。经典写法是哈希表加双向链表，两种实现效果一样。

参考答案

简答

LRU 的意思是“最近最少使用”：缓存满了，就把最久没被用过的那一条删掉。

用 Map 实现很方便，因为 Map 是按键第一次插入的顺序遍历的。但要注意，对已有的键再 set 一次，它的位置不会变。所以每次用到一个键，都要先 delete 再 set，把它挪到最后。这样排在最前面的，就是最久没用的，超出容量时删掉 keys().next().value 就行。get 命中和 set 都算用了一次，都要挪。

判断有没有命中要用 has，不能看 get 返回的是不是 undefined，因为缓存的值本身就可能是 undefined。

复杂度方面，V8 的 Map 是哈希表，get、set、delete 平均是常数时间，但语言规范只要求平均比线性快，不保证严格 O(1)。如果面试要求手写，常用的是哈希表加双向链表：哈希表负责快速找到节点，链表负责记录先后顺序，每次操作只改几个指针。

用 Map 实现

JavaScript
class LRUCache {
  constructor(capacity) {
    if (!Number.isInteger(capacity) || capacity < 1) {
      throw new RangeError('容量必须为正整数');
    }
    this.capacity = capacity;
    this.items = new Map();
  }

  get(key) {
    if (!this.items.has(key)) return undefined;
    const value = this.items.get(key);
    this.items.delete(key);
    this.items.set(key, value);
    return value;
  }

  set(key, value) {
    // 已有的键也先删除，插入后位于末尾。
    this.items.delete(key);
    this.items.set(key, value);
    if (this.items.size > this.capacity) {
      this.items.delete(this.items.keys().next().value);
    }
  }
}

keys().next().value 是什么意思？keys() 返回一个迭代器，按顺序给出所有键，next() 只取第一个。所以它拿到的就是排在最前面、最久没用的那个键。

下面验证一下淘汰顺序：

JavaScript
const cache = new LRUCache(2);
cache.set('a', 1);
cache.set('b', 2);
console.log(cache.get('a')); // 1，a 移到末尾
cache.set('c', 3); // 淘汰 b
console.log(cache.get('b')); // undefined
console.log([...cache.items.keys()]); // ['a', 'c']

先放了 a 和 b，a 本来是最老的。可是读了一次 a 以后，a 挪到了最后，b 就成了最老的。所以放 c 时被淘汰的是 b，不是 a。

用哈希表加双向链表实现

JavaScript
class Node {
  constructor(key, value) {
    this.key = key;
    this.value = value;
    this.prev = null;
    this.next = null;
  }
}

class LinkedLRU {
  constructor(capacity) {
    this.capacity = capacity;
    this.map = new Map();
    // 哨兵节点让头尾的插入删除不需要特殊判断。
    this.head = new Node();
    this.tail = new Node();
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }

  #remove(node) {
    node.prev.next = node.next;
    node.next.prev = node.prev;
  }

  #append(node) {
    node.prev = this.tail.prev;
    node.next = this.tail;
    this.tail.prev.next = node;
    this.tail.prev = node;
  }

  get(key) {
    const node = this.map.get(key);
    if (!node) return undefined;
    this.#remove(node);
    this.#append(node);
    return node.value;
  }

  set(key, value) {
    let node = this.map.get(key);
    if (node) {
      node.value = value;
      this.#remove(node);
    } else {
      node = new Node(key, value);
      this.map.set(key, node);
    }
    this.#append(node);
    if (this.map.size > this.capacity) {
      const oldest = this.head.next;
      this.#remove(oldest);
      this.map.delete(oldest.key);
    }
  }
}

链表从头到尾就是从最老到最新。用到一个节点，就把它从原位置摘下来，接到尾巴上；要淘汰，就删掉头后面的第一个。

head 和 tail 是两个不存数据的空节点，叫哨兵节点。有了它们，链表永远不会是真的空的，任何节点前后都有邻居，摘下和接上时就不用判断“它是不是第一个、是不是最后一个”。

为什么节点里还要存 key？因为淘汰时我们拿到的是链表节点，要同时从 Map 里删掉它，就得知道它的键是什么。

实测用 300 组随机操作，对比两种实现，get 的结果完全一致。

常见追问

两种实现怎么选？

业务代码用 Map 版本，代码短，性能也够用。想展示数据结构功底时，写链表版本。

要支持过期时间怎么办？

每个条目多存一个过期时刻。get 的时候发现已经过期了，就删掉它，当作没命中。

浏览器里哪些地方用到 LRU？

内存里的接口响应缓存、图片解码缓存，还有路由组件缓存。比如 Vue 的 KeepAlive 设置了 max 以后，就是按 LRU 淘汰的。
