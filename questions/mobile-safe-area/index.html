移动端安全区域怎样避免内容被刘海和底部手势条遮挡？

背景可以铺满屏幕，文字和按钮要躲开刘海和手势条。用 CSS 环境变量 env() 保护固定控件、滚动末尾和横屏边缘，动态工具栏和键盘要另外处理。

参考答案

简答

现在的手机屏幕有刘海、圆角和底部手势条，这些地方放内容会被挡住。屏幕上不会被挡的那块区域，就叫安全区域。

想让页面铺满整个屏幕，要先在 viewport meta 里加 viewport-fit=cover。加了以后，用 env(safe-area-inset-top) 这类变量拿到每条边被挡住的距离，给内容加上对应的内边距。

原则是背景可以铺满，只有文字、按钮这些要看清、要点到的内容需要避开。最容易出问题的是底部固定栏、列表最后一项，以及横屏时的左右两侧。

要注意，地址栏伸缩和虚拟键盘不算安全区域，得用动态视口单位或 VisualViewport 另外处理。

怎样让页面铺满屏幕

HTML
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />

不写 viewport-fit=cover 时，浏览器会自己在页面四周留出安全区域，这时 env() 的值都是 0。写了以后页面占满屏幕，避让的工作就交给开发者了。

常见的几种写法

下面这段 CSS 分别处理底部工具栏、列表末尾和顶部。

CSS
.toolbar {
  position: fixed;
  inset-inline: 0;
  bottom: 0;
  padding-bottom: calc(12px + env(safe-area-inset-bottom, 0px));
  padding-inline: max(16px, env(safe-area-inset-left, 0px)) max(16px, env(safe-area-inset-right, 0px));
  background: #fff;
}

.list {
  padding-bottom: calc(64px + env(safe-area-inset-bottom, 0px));
}

.header {
  padding-top: env(safe-area-inset-top, 0px);
}

底部工具栏的背景一直铺到屏幕底边，按钮靠 padding-bottom 躲开手势条，所以看起来不会有一截空白。

列表的问题是最后一项会被固定的工具栏挡住。所以列表底部要留出“工具栏高度 + 安全区域”的空间。

横屏时刘海跑到了左边或右边。左右内边距用 max()，取“正常边距”和“安全区域”里大的那个，这样没刘海的一侧也有正常的边距。

env() 的第二个参数是回退值，浏览器不支持这个变量时就用它。

地址栏和键盘为什么要另外处理

移动浏览器的地址栏会随着滚动收起和展开。100vh 是按地址栏收起时的高度算的，地址栏展开时，页面底部就可能被挡住。可以改用 100dvh，它会跟着地址栏变；或者 100svh，它按地址栏展开时的高度算。

虚拟键盘弹出时，安全区域不会变，所以底部固定栏可能被键盘盖住。处理方法见《移动端虚拟键盘出现时怎样避免布局被遮挡？》。

怎样测试

iOS 模拟器里选带刘海和灵动岛的机型，竖屏横屏都测一遍。Android 设备上打开全面屏手势，测底部区域。

Chrome DevTools 的设备模拟没法准确模拟安全区域，所以要以真机或模拟器为准。

常见追问

constant() 还需要写吗？

不需要了。constant() 是 iOS 11.0 的旧写法，iOS 11.2 起已经改成 env()。

WebView 里安全区域不生效怎么办？

要让原生那边允许 WebView 的内容延伸到安全区域外面。否则原生已经替你留好了空间，env() 拿到的值就是 0。
