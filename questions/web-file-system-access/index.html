File System Access API 的权限和文件句柄怎样管理？

showOpenFilePicker 等方法让用户选择本地文件或目录，网页得到文件句柄后可以读写；这部分只在 Chromium 桌面浏览器中可用。所有主流浏览器都支持的是源私有文件系统（OPFS），它不对应用户可见的文件。

参考答案

简答

  • showOpenFilePicker()、showSaveFilePicker()、showDirectoryPicker() 弹出系统文件选择器，返回 FileSystemFileHandle 或 FileSystemDirectoryHandle。
  • 这些选择器方法只有 Chromium 桌面浏览器支持，Firefox、Safari 和移动端都不支持。
  • 句柄可以存进 IndexedDB，下次打开页面后要调用 queryPermission()，必要时在用户手势中用 requestPermission() 重新授权。
  • 写入用 createWritable()，写入的内容在 close() 之后才落到原文件，中途失败不会留下半个文件。
  • navigator.storage.getDirectory() 返回的 OPFS 所有主流浏览器都支持，适合应用自己的数据文件，用户在系统里看不到这些文件。

打开并保存文件

JavaScript
let handle;

async function openFile() {
  [handle] = await showOpenFilePicker({
    types: [{ description: '文本', accept: { 'text/plain': ['.txt', '.md'] } }],
  });
  const file = await handle.getFile();
  return file.text();
}

async function save(text) {
  if (!handle) handle = await showSaveFilePicker({ suggestedName: 'note.md' });
  if ((await handle.queryPermission({ mode: 'readwrite' })) !== 'granted') {
    if ((await handle.requestPermission({ mode: 'readwrite' })) !== 'granted') {
      throw new Error('没有写入权限');
    }
  }
  const writable = await handle.createWritable();
  await writable.write(text);
  await writable.close();
}

createWritable() 返回的流先写到临时位置，close() 时才替换原文件；close() 之前出错或调用 abort()，原文件保持不变。

用户取消选择器时，Promise 以 AbortError reject，应当静默处理。

降级

不支持时：

  • 打开文件：<input type="file">。
  • 保存文件：生成 Blob，用 <a download> 下载。

const supportsPicker = 'showOpenFilePicker' in window;

OPFS

JavaScript
const root = await navigator.storage.getDirectory();
const fileHandle = await root.getFileHandle('cache.db', { create: true });
  • 不需要用户授权，数据按源隔离，受存储配额限制。
  • 在 Worker 中可以用 createSyncAccessHandle() 同步读写，性能很高，SQLite 的 Wasm 版本就用它存储数据库。

安全限制

  • 浏览器禁止选择系统目录等敏感位置。
  • 每次都要由用户选择，网页不能自己指定路径读取文件。
