File System Access API 的权限和文件句柄怎样管理？

showOpenFilePicker 等方法让用户选一个本地文件或目录，网页拿到"文件句柄"后就能读写，但只有 Chromium 桌面浏览器支持。所有主流浏览器都支持的是 OPFS，它是网站私有的文件空间，用户在系统里看不到。

参考答案

简答

做一个网页版编辑器，想要“打开本地文件，改完直接保存回去”，就用 File System Access API。showOpenFilePicker()、showSaveFilePicker()、showDirectoryPicker() 弹出系统的文件选择框，用户选完，网页拿到一个文件句柄（FileSystemFileHandle 或 FileSystemDirectoryHandle），可以理解成“这个文件的遥控器”。

这些选择器方法只有 Chromium 桌面浏览器支持，Firefox、Safari 和手机上都没有，所以要准备降级。

句柄可以存进 IndexedDB，下次打开页面还能用。但权限不一定还在，要先 queryPermission() 查询，必要时在用户点击里用 requestPermission() 重新申请。写入用 createWritable()，内容在 close() 之后才真正写到原文件，中途失败不会留下半个文件。

另外还有一个 OPFS（源私有文件系统），用 navigator.storage.getDirectory() 获取。所有主流浏览器都支持，适合存应用自己的数据文件，但用户在系统里看不到这些文件。

打开并保存文件

下面打开一个文本文件，保存时写回同一个文件。

JavaScript
let handle;

async function openFile() {
  [handle] = await showOpenFilePicker({
    types: [{ description: '文本', accept: { 'text/plain': ['.txt', '.md'] } }],
  });
  const file = await handle.getFile();
  return file.text();
}

async function save(text) {
  if (!handle) handle = await showSaveFilePicker({ suggestedName: 'note.md' });
  if ((await handle.queryPermission({ mode: 'readwrite' })) !== 'granted') {
    if ((await handle.requestPermission({ mode: 'readwrite' })) !== 'granted') {
      throw new Error('没有写入权限');
    }
  }
  const writable = await handle.createWritable();
  await writable.write(text);
  await writable.close();
}

为什么保存前还要查权限？因为打开文件时用户只给了读权限，写入要另外申请 readwrite。句柄从 IndexedDB 里取出来时，权限也可能已经失效了。所以先查，不够就申请。

为什么中途失败不会弄坏原文件？因为 createWritable() 返回的流先写到一个临时位置，close() 的时候才替换原文件。close() 之前出了错，或者主动调用 abort()，原文件保持不变。

还有一种情况：用户在选择框里点了取消，Promise 会以 AbortError reject。这不是真错误，应当静默处理。

不支持时怎么降级

先检测：

JavaScript
const supportsPicker = 'showOpenFilePicker' in window;

不支持的浏览器里，打开文件用 <input type="file">；保存文件就生成一个 Blob，用 <a download> 下载。区别是用户每次保存都会得到一个新下载的文件，没法写回原文件。

OPFS 是什么

OPFS 是浏览器给每个网站分配的私有文件空间：

JavaScript
const root = await navigator.storage.getDirectory();
const fileHandle = await root.getFileHandle('cache.db', { create: true });

它不需要用户授权，数据按源隔离，受存储配额限制。在 Worker 里还可以用 createSyncAccessHandle() 同步读写，性能很高，SQLite 的 Wasm 版本就是用它存数据库的。

安全上有哪些限制

浏览器禁止选择系统目录等敏感位置。而且每次都必须由用户自己选，网页不能自己指定一个路径去读文件。

常见追问

句柄存进 IndexedDB 以后，下次能直接写吗？

不一定。句柄还在，但权限可能已经没了。要先 queryPermission()，不是 granted 就在用户点击时调用 requestPermission() 重新申请。

OPFS 和选择器打开的文件有什么区别？

选择器打开的是用户磁盘上看得见的真实文件，只有 Chromium 桌面支持。OPFS 是网站私有的空间，所有主流浏览器都支持，但用户在系统文件管理器里看不到。
