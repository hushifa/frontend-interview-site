Vue 模板编译如何减少运行时更新工作？

Vue 的编译器可以分析模板中的静态部分和动态绑定，再把提示写入生成的渲染代码。运行时利用这些信息跳过不必要的比较，不必每次都把所有属性当成未知变化处理。

参考答案

Vue 的编译器可以分析模板中的静态部分和动态绑定，再把提示写入生成的渲染代码。运行时利用这些信息跳过不必要的比较，不必每次都把所有属性当成未知变化处理。

典型方式包括缓存静态节点、为动态属性生成 patch flags，以及在稳定结构中收集动态节点。比如只有 class 会变化的元素，运行时可以依据标记集中处理相关更新。

这些优化依赖编译器能识别的结构，手写渲染函数或高度动态的内容不能一概假定获得相同提示。Vue 仍有运行时响应式和渲染工作，不是“编译后零成本”。业务中的巨大 DOM、昂贵计算和不合理组件边界仍需要实际分析。

Vue 题目可以沿着依赖收集、更新调度、组件渲染和副作用生命周期来理解。响应式引用记录的是读取关系，不代表所有嵌套对象都会以同样方式被追踪；具体行为还取决于使用的 API 和 Vue 版本。

落地时把派生状态、用户输入和副作用分开，避免用一个 watch 或可写变量反复同步同一事实。组件卸载、异步竞态、SSR 和第三方 DOM 操作都需要单独验证。

实际组件中，先画出数据从哪里来、在哪里被修改、哪些值只是派生结果。这样可以避免把同一份数据同时交给 props、ref、store 和 watch，减少更新顺序变化后出现的互相覆盖。
