Vue 模板编译如何减少运行时更新工作？

Vue 编译器分析模板，复用静态节点、给动态节点打上 patch flag、把动态节点收集到 block 的扁平数组中。更新时运行时只比较这些动态节点的动态部分，跳过静态结构。这是 Vue 3 比纯虚拟 DOM 方案更新更快的主要原因。

参考答案

简答

  • 静态节点缓存：完全不变的节点只创建一次，后续渲染直接复用同一个 vnode。
  • Patch flags：编译器为动态节点标记哪些部分是动态的（文本、class、style、props 等），更新时只比较这些部分。
  • Block tree：每个 block 把内部所有动态节点收集到一个扁平数组 dynamicChildren，更新时直接遍历这个数组，不必递归整棵树。
  • 结构会变化的指令（v-if、v-for）各自开启新的 block，以保证扁平数组的结构稳定。
  • 手写渲染函数或 JSX 拿不到这些编译信息，只能走完整的 diff。

编译结果示意

vue
<template>
  <div>
    <h1>标题</h1>
    <p :class="cls">{{ msg }}</p>
  </div>
</template>

编译后大致是（Vue 3.4 及以前的静态提升写法，示意）：

JavaScript
const _hoisted_1 = createElementVNode('h1', null, '标题', -1 /* HOISTED */);

function render(ctx) {
  return (openBlock(), createElementBlock('div', null, [
    _hoisted_1,
    createElementVNode('p', { class: normalizeClass(ctx.cls) }, toDisplayString(ctx.msg),
      3 /* TEXT, CLASS */),
  ]));
}

Vue 3.5 起静态节点改为放进 _cache 缓存，输出里标注为 CACHED，作用相同：静态部分只创建一次。

更新时：h1 是同一个对象，直接跳过；p 的 flag 是 TEXT | CLASS，只比较文本和 class，不检查其他属性。

可以在 Vue SFC Playground 的 JS 标签页查看任意模板的编译结果。

Block 为什么能跳过遍历

vue
<div>
  <header>…很多静态节点…</header>
  <span>{{ a }}</span>
  <footer>…<em>{{ b }}</em>…</footer>
</div>

根 block 的 dynamicChildren 只有 span 和 em 两项。更新时运行时直接比较这两项，嵌套多深都不需要逐层进入。

v-if 的不同分支结构不同，所以每个分支是一个独立 block；v-for 的列表长度会变，也作为一个 fragment block 处理，内部按 key 比较。

其他优化

  • 事件处理函数缓存：@click="onClick" 会被缓存，子组件不会因为每次收到新函数而更新。
  • v-once 只渲染一次，v-memo 在指定依赖不变时跳过整个子树，适合大列表中的条目。

编译优化不能解决的问题

编译优化减少的是比较开销。组件数量过多、一次渲染上万个 DOM 节点、计算属性很重，仍需要虚拟列表、拆分组件、shallowRef 等手段，见《Vue 大型页面应从哪些方面优化更新开销？》。

常见追问

  • 和 React 的差别？React 的 JSX 是普通 JS，编译期难以确定哪些是静态的，默认每次比较整棵子树；React Compiler 通过记忆化达到类似目的，但实现路径不同。
  • Vapor Mode 是什么？Vue 正在开发的一种不使用虚拟 DOM、直接生成 DOM 操作代码的编译模式，正式状态以官方发布为准。
