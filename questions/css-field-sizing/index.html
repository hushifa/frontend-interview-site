field-sizing: content 会怎样改变表单控件尺寸？

field-sizing: content 让输入框、文本域、下拉框跟着内容自动变大变小，不用再写 JavaScript 读 scrollHeight。一定要同时设置最小和最大尺寸。

参考答案

简答

表单控件默认是固定大小的，这对应默认值 fixed。改成 field-sizing: content 后，控件会按里面的内容或占位文字伸缩：textarea 打字越多越高，单行 input 越打越宽，select 按选中项的宽度变化。

以前做自动增高的输入框，要监听输入事件，再读 scrollHeight 去改高度，现在一行 CSS 就够了。

一定要配上 min-* 和 max-*。没内容时控件可能缩得很小，内容很长时又会无限撑开。另外设了 content 以后，rows、cols、size 这些属性就不起作用了，想固定某个方向，要明确写宽或高。

它从 2026 年 6 月起进入 Baseline。旧浏览器里控件保持固定尺寸，照样能用。

自动增高的 textarea

CSS
textarea {
  field-sizing: content;
  min-block-size: 3lh;
  max-block-size: 12lh;
}

lh 是一个单位，等于当前的行高，所以 3lh 就是三行的高度。内容少时至少显示 3 行，写到超过 12 行就不再长高，出现滚动条。

按内容变宽的输入框

CSS
.tag-input {
  field-sizing: content;
  min-inline-size: 8ch;
  max-inline-size: 100%;
}

这种写法适合输入标签、表格里的行内编辑。ch 约等于一个“0”字符的宽度，8ch 保证空着时也有个能点的大小。

要留意布局会不会跟着晃。输入框变宽会把同一行的其他元素往后推，放在 flex 容器里时，要确认换行的表现符合预期。

体验和无障碍上要注意什么

占位文字也会参与尺寸计算。空输入框会按 placeholder 的宽度显示，所以占位文字不要写太长。

自动伸缩不影响 <label> 的关联。控件的名称和错误提示，还是照常提供。

用户放大页面后，最大尺寸要还能装下内容，别让文字被截断。

常见追问

浏览器不支持时，要不要写 JavaScript 回退？

大多数时候不用。固定尺寸的 textarea 加上滚动条照样能用。确实需要时，先用 CSS.supports('field-sizing', 'content') 判断，不支持再加载回退逻辑。
