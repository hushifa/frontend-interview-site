怎样实现有明确失败语义的异步并发池？

并发池就是"最多同时跑 limit 个任务，跑完一个再接下一个"。它接收还没启动的任务函数，同时开 limit 个循环去领任务，结果按原来的顺序存。有任务失败时整体失败，不再领新任务，已经开始的任务要靠 AbortSignal 自己停。

参考答案

简答

并发池的作用是：一堆异步任务，最多同时跑 limit 个，跑完一个再接下一个。

关键是传进来的必须是任务函数，比如 () => fetch(url)，而不是 fetch(url) 的结果。因为 Promise 一创建，请求就已经发出去了，池子只有拿到函数，才能决定什么时候启动。

实现上，同时开 Math.min(limit, 任务数) 个执行循环。它们共用一个 next 下标，每次同步地领 next++，所以同一个任务不会被领两次。结果写到 results[index]，输出顺序和输入一致，跟谁先完成没关系。

失败时要说清楚语义：某个任务失败，就设一个 failed 标记，整体以这个错误拒绝，其他循环跑完手上的任务后就不再领新的。但已经开始的任务不会自动停，要靠 AbortSignal 自己中断。另外，并发池限制的是同时在跑的数量，不是每秒请求数，限速要另外做。

实现

JavaScript
async function runPool(tasks, limit) {
  if (!Array.isArray(tasks)) throw new TypeError('任务必须是数组');
  if (!Number.isInteger(limit) || limit < 1) {
    throw new RangeError('并发数必须为正整数');
  }

  // 复制任务列表，并把稀疏数组中的空位变成 undefined，方便统一校验。
  const queue = Array.from(tasks);
  if (queue.some((task) => typeof task !== 'function')) {
    throw new TypeError('每个任务都必须是函数');
  }

  const results = new Array(queue.length);
  let next = 0;
  let failed = false;

  async function worker() {
    while (!failed && next < queue.length) {
      const index = next++;
      try {
        results[index] = await queue[index]();
      } catch (error) {
        failed = true;
        throw error;
      }
    }
  }

  await Promise.all(Array.from({ length: Math.min(limit, queue.length) }, worker));
  return results;
}

几个循环同时在领 next，会不会领到同一个？不会。JavaScript 是单线程的，const index = next++ 这一行是同步执行的，中间不会被别的循环插进来。只有到了 await，才会切到别的循环。

为什么要用 results[index] 而不是 results.push？因为任务完成的先后是不确定的，push 会按完成顺序排。按下标写，输出顺序就和输入顺序一致。

参数校验放在最前面，在启动任何任务之前。任务里同步抛出的错误，也会被 try/catch 接住。空任务列表会直接返回 []。

下面验证一下最多同时跑几个：

JavaScript
let active = 0;
let maximum = 0;

const jobs = [40, 10, 5, 20].map((delay, index) => async () => {
  active++;
  maximum = Math.max(maximum, active);
  try {
    await new Promise((resolve) => setTimeout(resolve, delay));
    return index;
  } finally {
    active--;
  }
});

runPool(jobs, 2).then((result) => {
  console.log(result); // [0, 1, 2, 3]
  console.log(maximum); // 2
});

任务完成的顺序是乱的，但结果仍然是 [0, 1, 2, 3]，同时在跑的最多是 2 个。

一个任务失败了，会发生什么

假设有四个任务 a、b、c、d，并发数是 2，b 在 10 毫秒时失败。过程是这样的：

0 毫秒时，两个循环分别领了 a 和 b。a 先完成，它所在的循环接着领了 c。随后 b 失败，failed 变成 true，整体 Promise 拒绝。可是 c 已经开始了，它会继续跑完；之后循环检查到 failed，就不再领 d。

实际跑一遍，started 是 ['a', 'b', 'c']。所以“失败后停止”的意思是不再领新任务，已经开始的任务和它们产生的副作用，不会被自动撤销。

如果要真的中断已经开始的任务，可以让所有任务共用一个 AbortController，失败时统一取消：

JavaScript
const controller = new AbortController();
const tasks = urls.map((url) => () =>
  fetch(url, { signal: controller.signal }).then((response) => {
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json();
  }),
);

try {
  await runPool(tasks, 4);
} catch (error) {
  controller.abort(error);
  throw error;
}

注意任务里检查了 response.ok。fetch 碰到 404、500 不会拒绝，不检查的话，失败的请求会被当成成功的结果。

常见追问

想拿到全部任务的结果，不因为一个失败就停下来，怎么办？

在每个任务里自己捕获错误，返回 { status: 'rejected', reason }，这样池子看到的全是成功。效果就像带并发限制的 Promise.allSettled。

任务数量是动态增加的怎么办？

把 queue 换成可以随时 push 的队列。执行循环发现队列空了，就等新任务进来，而不是直接退出。

并发数怎么选？

浏览器对同一个域名的 HTTP/1.1 连接数有限制，Chrome 是 6 个。HTTP/2 可以多路复用，没有这个限制，但服务端仍然有容量上限。要按接口的承载能力和实际测出来的耗时来调。
