怎样实现有明确失败语义的异步并发池？

并发池接收尚未启动的任务函数，同时启动 limit 个执行循环，每个循环领取下一个任务、等待完成后再领取，结果按输入下标保存。任一任务失败时整体拒绝，所有循环停止领取新任务，已经开始的任务需要通过 AbortSignal 自行停止。

参考答案

简答

  • 传入的是任务函数 () => fetch(url)，不是 fetch(url) 返回的 Promise；Promise 创建时请求已经发出，池子只有拿到函数才能控制启动时机。
  • 启动 Math.min(limit, 任务数) 个执行循环，它们共享一个 next 下标，每次同步领取 next++，所以同一个任务不会被领取两次。
  • 结果写入 results[index]，输出顺序与输入一致，与完成先后无关。
  • 某个任务失败时设置 failed 标记，整体 Promise 以该错误拒绝，其他循环在完成当前任务后停止领取。失败被观察到之前，别的循环可能已经领取了新任务。
  • 并发池限制的是同时在途的任务数，不是每秒请求数；需要限制速率时要另外实现令牌桶等机制。

实现

JavaScript
async function runPool(tasks, limit) {
  if (!Array.isArray(tasks)) throw new TypeError('任务必须是数组');
  if (!Number.isInteger(limit) || limit < 1) {
    throw new RangeError('并发数必须为正整数');
  }

  // 复制任务列表，并把稀疏数组中的空位变成 undefined，方便统一校验。
  const queue = Array.from(tasks);
  if (queue.some((task) => typeof task !== 'function')) {
    throw new TypeError('每个任务都必须是函数');
  }

  const results = new Array(queue.length);
  let next = 0;
  let failed = false;

  async function worker() {
    while (!failed && next < queue.length) {
      const index = next++;
      try {
        results[index] = await queue[index]();
      } catch (error) {
        failed = true;
        throw error;
      }
    }
  }

  await Promise.all(Array.from({ length: Math.min(limit, queue.length) }, worker));
  return results;
}
JavaScript
let active = 0;
let maximum = 0;

const jobs = [40, 10, 5, 20].map((delay, index) => async () => {
  active++;
  maximum = Math.max(maximum, active);
  try {
    await new Promise((resolve) => setTimeout(resolve, delay));
    return index;
  } finally {
    active--;
  }
});

runPool(jobs, 2).then((result) => {
  console.log(result); // [0, 1, 2, 3]
  console.log(maximum); // 2
});

参数校验发生在启动任何任务之前。任务同步抛错也会被 try/catch 捕获。空任务列表直接返回 []。

失败时会发生什么

四个任务、并发数 2，第二个任务在 10 毫秒时失败：

  1. 0 毫秒：两个循环分别领取任务 a 和 b。
  2. 10 毫秒：a 先完成，它所在的循环领取 c；随后 b 失败，failed 变为 true，整体拒绝。
  3. c 已经开始，会继续执行到结束；之后循环检查到 failed，不再领取 d。

实测 started 为 ['a', 'b', 'c']。所以"失败后停止"指的是停止领取新任务，已经开始的任务和它们的副作用不会自动撤销。

需要真正中断时，让任务共用一个 AbortController：

JavaScript
const controller = new AbortController();
const tasks = urls.map((url) => () =>
  fetch(url, { signal: controller.signal }).then((response) => {
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json();
  }),
);

try {
  await runPool(tasks, 4);
} catch (error) {
  controller.abort(error);
  throw error;
}

fetch 对 404、500 这类响应不会拒绝，任务里要检查 response.ok，否则失败的请求会被当成成功结果。

常见追问

  • 想要全部任务的结果，不因失败而停止？ 在任务里捕获错误，返回 { status: 'rejected', reason }，效果类似 Promise.allSettled 加并发限制。
  • 任务数量是动态的怎么办？ 把 queue 换成可以随时 push 的队列，执行循环在队列为空时等待新任务，而不是直接退出。
  • 并发数怎么选？ 浏览器对同一域名的 HTTP/1.1 连接数有限制（Chrome 为 6 个），HTTP/2 下多路复用没有这个限制，但服务端仍有容量上限。按接口的承载能力和实测耗时调整。
