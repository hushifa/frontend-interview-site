为什么 TypeScript 不能替代接口数据校验？

TypeScript 类型在编译后被删除，JSON.parse、fetch 返回的数据不受任何检查，as User 或 get<User>() 只是声明预期。应在网络响应、本地存储、URL 参数等信任边界把数据当作 unknown，用 Zod、Valibot 等 schema 库或手写守卫解析，再从 schema 推导类型。

参考答案

简答

  • 类型只存在于编译期，后端改字段、缓存存着旧格式、第三方接口异常，都发生在编译器看不到的地方。
  • JSON.parse(text) as User、fetch<User>() 不会生成校验代码，后续代码可能在很深的地方才崩溃。
  • 在信任边界把输入当作 unknown，用 schema 解析出可信数据，内部代码再依赖类型。
  • 用 schema 推导类型（z.infer<typeof User>），避免类型和校验规则写两遍后不一致。
  • 网络请求要分三步检查：HTTP 状态、JSON 语法、数据结构。

断言不是检查

TypeScript
type User = { id: string; name: string; role: 'reader' | 'editor' };

function readUnchecked(json: string): string {
  const user = JSON.parse(json) as User;
  return user.name.toUpperCase(); // name 是数字或缺失时运行时报错
}

手写解析

TypeScript
type ParseResult<T> = { ok: true; value: T } | { ok: false; issues: string[] };

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

function parseUser(input: unknown): ParseResult<User> {
  if (!isRecord(input)) return { ok: false, issues: ['必须是对象'] };
  const { id, name, role } = input;
  if (typeof id !== 'string') return { ok: false, issues: ['id 必须是字符串'] };
  if (typeof name !== 'string' || !name.trim()) return { ok: false, issues: ['name 不能为空'] };
  if (role !== 'reader' && role !== 'editor') return { ok: false, issues: ['role 不合法'] };
  return { ok: true, value: { id, name: name.trim(), role } };
}

返回新对象只复制白名单字段，多余字段不会流进内部状态。

用 schema 库

TypeScript
import { z } from 'zod';

const User = z.object({
  id: z.string(),
  name: z.string().trim().min(1),
  role: z.enum(['reader', 'editor']),
});
type User = z.infer<typeof User>;

async function loadUser(url: string, signal?: AbortSignal): Promise<User> {
  const response = await fetch(url, { signal: signal ?? null });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const result = User.safeParse(await response.json());
  if (!result.success) throw new Error('用户数据不符合契约', { cause: result.error });
  return result.data;
}

选择库时要确认：多余字段是拒绝、保留还是剥离（Zod 的 object 默认剥离）；是否允许 '1' 自动转成数字；缺失字段是否填默认值。

哪些地方需要校验

  • 接口响应、WebSocket 消息、postMessage 收到的数据。
  • localStorage / IndexedDB 中恢复的数据，旧版本格式需要迁移。
  • URL 查询参数、表单输入。

内部函数之间不必重复校验。前端校验用于尽早发现问题和改善交互，服务端仍要独立校验，字段合法也不代表用户有权限。

常见追问

  • 能根据 TS 类型自动生成校验吗？类型在运行时不存在，需要从 schema 推导类型，或用 typia 等编译插件从类型生成代码。
  • 校验失败怎样处理？记录字段路径和接口版本，向用户显示可恢复的错误，不要静默返回空数据。
