什么时候应该 mock，mock 太多有什么问题？

mock 用来替换慢、不稳定或不受控的外部边界，例如网络、时间、随机数和第三方服务；mock 掉被测代码自己的模块，测试就只验证了 mock 本身。每个测试后要清理 mock，并让模拟数据与真实契约保持一致。

参考答案

简答

  • 适合 mock：HTTP 请求、当前时间、随机数、浏览器 API（地理位置、剪贴板）、支付等第三方服务。
  • 不适合 mock：被测模块内部的函数、纯计算逻辑、和被测代码一起交付的子组件。
  • mock 越多，测试越接近“复述实现”：重构后测试失败，真实 bug 却测不出来。
  • mockClear 只清调用记录；mockReset 还清除自定义实现，vi.fn() 变成返回 undefined，vi.fn(impl) 和 spyOn 回到原实现；mockRestore 再把 spyOn 的对象恢复成原方法。
  • 模拟数据要来自真实契约（OpenAPI 类型、录制的响应），否则接口改了测试仍会通过。

选择 mock 的边界

TypeScript
// 被测函数
export async function loadUser(id: string, fetcher = fetch) {
  const response = await fetcher(`/api/users/${id}`);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}
TypeScript
import { expect, test, vi } from 'vitest';

test('非 2xx 响应时抛错', async () => {
  const fetcher = vi.fn().mockResolvedValue(new Response(null, { status: 404 }));
  await expect(loadUser('1', fetcher)).rejects.toThrow('HTTP 404');
  expect(fetcher).toHaveBeenCalledWith('/api/users/1');
});

通过参数注入依赖，比用 vi.mock 替换整个模块更直接。模拟返回的是真实的 Response 对象，ok 和 status 的行为与浏览器一致。

模块 mock

TypeScript
vi.mock('./analytics', () => ({ track: vi.fn() }));

vi.mock 会被提升到文件顶部，在所有 import 之前执行。工厂里不能直接使用外部变量，需要时用 vi.hoisted 声明。

清理

TypeScript
// vitest.config.ts
export default defineConfig({
  test: {
    restoreMocks: true,
  },
});

开启 restoreMocks 后，每个测试前自动调用 mockRestore，避免一个测试设置的返回值或替换的全局方法影响下一个测试。修改了 globalThis、Date 或环境变量时，用 vi.stubGlobal、vi.stubEnv 并配合 unstubGlobals、unstubEnvs。

用 MSW 模拟网络层

组件内部直接调用 fetch 时，可以用 MSW 在网络层拦截，组件代码不用改，同一套处理器还能用于开发环境和浏览器测试：

TypeScript
import { http, HttpResponse } from 'msw';
import { setupServer } from 'msw/node';

const server = setupServer(
  http.get('/api/users/:id', ({ params }) =>
    HttpResponse.json({ id: params.id, name: '张三' }),
  ),
);

常见追问

  • 怎样判断 mock 过多？如果改了一个内部函数名，要同时改很多测试的 mock，或者测试里的 mock 设置比断言还长，就说明边界选得太靠里了。
