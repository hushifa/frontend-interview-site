变异测试如何发现“覆盖率很高但测试没测到重点”？

变异测试自动对源代码做小改动（把 > 改成 >=、删掉一行、把 true 改成 false），然后运行测试；测试失败说明变异被“杀死”，测试仍通过说明断言没有覆盖这处逻辑。

参考答案

简答

  • 每个变异体是源代码的一个小改动，例如算术运算符、比较运算符、条件、字面量、删除语句。
  • 测试失败称为“杀死”变异体，测试通过称为“存活”；变异分数 = 被杀死的数量 / 总数。
  • 存活的变异体指出了具体哪一行、哪种改动没被断言发现，比覆盖率更能说明测试质量。
  • 有些变异和原代码行为完全相同（等价变异），它们必然存活，需要人工判断后忽略。
  • 变异测试要多次运行测试套件，耗时长，通常只对核心模块或变更的文件运行。

示例

TypeScript
export function canCheckout(total: number, limit: number) {
  return total > 0 && total <= limit;
}
TypeScript
test('总额在限额内可以结账', () => {
  expect(canCheckout(50, 100)).toBe(true);
  expect(canCheckout(0, 100)).toBe(false);
});

覆盖率是 100%。变异测试会生成例如把 <= 改成 < 的变异体，canCheckout(50, 100) 仍为 true，测试仍通过，变异体存活。这说明“总额刚好等于限额”的边界没有测试。补上 expect(canCheckout(100, 100)).toBe(true) 后，这个变异体被杀死。

在项目中使用

bash
npm install --save-dev @stryker-mutator/core @stryker-mutator/vitest-runner
npx stryker run
json
{
  "testRunner": "vitest",
  "mutate": ["src/domain/**/*.ts"],
  "thresholds": { "high": 80, "low": 60, "break": 50 },
  "incremental": true
}
  • mutate 限定在纯逻辑模块，界面胶水代码的变异多数不值得处理。
  • incremental 只重新测试变化过的代码，适合在 CI 中运行。
  • 报告会列出每个存活的变异体和对应的代码位置。

怎样处理存活的变异体

  1. 是真实的测试遗漏：补边界值或补断言。
  2. 是等价变异：改动后程序的可观察行为完全不变，例如把 i < arr.length 改成 i !== arr.length，而 i 每次只加 1。用 // Stryker disable next-line EqualityOperator: 原因 标记，写明被禁用的变异器和理由。
  3. 是不重要的代码：从 mutate 范围中排除。

常见追问

  • 变异分数要达到多少？和覆盖率一样不宜追求固定数字。关注核心逻辑中存活的变异体，每个都给出“补测试”或“可以忽略”的结论，比提高总分更有意义。
