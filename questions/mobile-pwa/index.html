PWA 由哪些能力组成，是否所有浏览器体验都一致？

PWA 就是让网站能像应用一样安装、离线打开。讲清 Web App Manifest、Service Worker 和 HTTPS 各管什么，比较 Chromium 与 Safari/iOS 在安装、推送和后台能力上的差异，以及怎样做渐进增强。

参考答案

简答

PWA 是让一个网站能像应用一样装到桌面或主屏幕上、断网也能打开的一组能力，不是某一项单独的技术。

它主要靠三样东西：Web App Manifest 写名称、图标和启动方式；Service Worker 负责离线缓存和拦截网络请求；HTTPS 是前提，没有它 Service Worker 用不了。

各平台体验并不一致。Chromium 浏览器有 beforeinstallprompt，可以做自定义安装按钮；iOS 没有，只能让用户从分享菜单“添加到主屏幕”。iOS 16.4 起支持 Web Push，但只对添加到主屏幕的应用有效。后台同步这类能力主要在 Chromium 里能用。

所以要做渐进增强：先保证它是个正常可用的网站，再逐项检测能力，支持的才启用。

PWA 由哪几部分组成

先看 Manifest。它是一个 JSON 文件，告诉浏览器“装好以后叫什么、用什么图标、从哪个地址打开”。

json
// manifest.webmanifest
{
  "name": "前端面试题库",
  "short_name": "题库",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#2563eb",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
HTML
<link rel="manifest" href="/manifest.webmanifest" />

display: "standalone" 表示装好以后打开时不显示浏览器地址栏，看起来像独立应用。

第二部分是 Service Worker。它是一段在页面背后运行的脚本，能拦截请求、缓存资源、接收推送，离线能力就靠它。注册、更新和缓存策略见《Service Worker 的安装、激活与缓存更新有哪些坑？》。

第三部分是 HTTPS。Service Worker 和大多数相关 API 只在安全上下文里能用，本地开发用的 localhost 是例外。

怎样做一个安装按钮

Chromium 浏览器在页面满足安装条件时，会发一个 beforeinstallprompt 事件。下面的代码先把它拦下来存着，等用户点按钮时再弹出安装提示。

JavaScript
let deferred = null;

window.addEventListener('beforeinstallprompt', (event) => {
  event.preventDefault();
  deferred = event;
  installButton.hidden = false;
});

installButton.addEventListener('click', async () => {
  if (!deferred) return;
  deferred.prompt();
  await deferred.userChoice;
  deferred = null;
  installButton.hidden = true;
});

可是这段代码只在 Chromium 系浏览器里有效。iOS 上收不到这个事件，就可以改成显示一段说明：“点击分享按钮，选择‘添加到主屏幕’”。

另外，用 matchMedia('(display-mode: standalone)') 可以判断当前是不是已经在安装后的窗口里运行，是的话就别再提示安装了。

怎样做渐进增强

渐进增强的意思是：先做出一个所有浏览器都能正常用的网站，再在支持的环境里加上更好的能力。

所以第一步是保证网站在普通浏览器标签里完整可用。然后逐项检测能力，比如 'serviceWorker' in navigator、'PushManager' in window、'sync' in registration，检测到了才启用对应功能。离线时也要给出明确提示，说清哪些内容能离线看，哪些操作要联网。

常见追问

PWA 能上架应用商店吗？

Android 可以用 Trusted Web Activity 打包以后上架 Google Play。iOS 要上 App Store，需要提供原生应用的价值，只把网站包一层壳通常过不了审核，具体以 Apple 的审核指南为准。

安装后的 PWA 怎么更新？

页面代码和资源的更新由 Service Worker 的更新流程决定。Manifest 里的部分字段，比如图标和名称，由浏览器定期检查更新。
