SSR 和 SSG 中的缓存层应该怎样区分？

服务端渲染常同时涉及 HTTP 缓存（浏览器和 CDN，由 Cache-Control 控制）、请求内去重、框架跨请求的数据缓存和客户端状态缓存。每一层的作用范围和失效方式不同；个性化内容不能进入共享缓存，缓存键必须包含所有影响结果的因素。

参考答案

简答

  • HTTP 缓存：浏览器和 CDN 按 Cache-Control、ETag、Vary 复用整个响应，public 可以被 CDN 共享，private 只能存在用户浏览器中。
  • 请求内去重：如 React cache、Next.js 对 fetch 的记忆，只在一次渲染中有效。
  • 框架数据缓存：如 Next.js 的 'use cache'、Nuxt 的 cachedEventHandler，跨请求保存，需要按时间或标签失效。
  • 客户端状态缓存：如 TanStack Query、Pinia 中保存的数据，存在浏览器内存里，登出时要清空。
  • 个性化内容（含用户名、权限、订单）不能以 public 缓存；缓存键要包含用户、语言、权限等所有影响结果的因素。

四层对比

层存在哪里范围如何失效
HTTP / CDN浏览器、CDN 节点按 URL 和 Varymax-age 到期、清除 CDN、改 URL
请求内去重服务端内存一次请求请求结束
框架数据缓存服务端内存或共享存储跨请求、跨用户时间、标签、路径失效
客户端状态浏览器内存当前标签页重新获取、手动清除

公共页面

http
Cache-Control: public, max-age=60, stale-while-revalidate=300

文章、商品详情等对所有人相同的页面，CDN 缓存 60 秒，之后 5 分钟内可以先返回旧内容，同时在后台重新获取。

个性化页面

http
Cache-Control: private, no-store

如果页面大部分是公共内容，只有头像、购物车数量是个性化的，可以把页面作为公共缓存，个性化部分在客户端单独请求，或使用框架的部分预渲染，让个性化部分在请求时生成。

不要只靠 Vary: Cookie 让 CDN 区分用户：Cookie 中常有各种无关字段，缓存几乎无法命中；一旦 CDN 配置忽略了 Vary，就会把一个人的页面发给其他人。

静态资源

带内容哈希的 JS、CSS 文件名（app.3f9a1c.js）内容变化就会换名字，可以长期缓存：

http
Cache-Control: public, max-age=31536000, immutable

HTML 文件名不变，应设置较短的缓存或每次重新验证，否则用户拿到的旧 HTML 会引用已经删除的旧资源。

发布和回滚

  • 发布后清除 CDN 中的 HTML 缓存，保留一段时间的旧版本静态资源，正在使用旧页面的用户按需加载代码块时才不会 404。
  • 回滚代码时，框架的数据缓存和 CDN 缓存可能仍保存着新版本生成的内容，需要一起清除。

常见追问

  • 怎么确认响应命中了哪层缓存？查看响应头中的 Age、Cache-Status，以及 CDN 自定义的命中头。
  • SSG 页面需要缓存策略吗？需要，构建出的 HTML 仍要设置合适的 Cache-Control，内容更新后也要清除 CDN。
