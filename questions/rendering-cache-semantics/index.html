SSR 和 SSG 中的缓存层应该怎样区分？

服务端渲染常常同时涉及 HTTP 缓存（浏览器和 CDN，由 Cache-Control 控制）、请求内去重、框架跨请求的数据缓存和客户端状态缓存。每一层的作用范围和失效方式不同；个性化内容不能进入共享缓存，缓存键必须包含所有影响结果的因素。

参考答案

简答

说“SSR 有缓存”，其实可能指四个不同的地方。第一层是 HTTP 缓存：浏览器和 CDN 按 Cache-Control、ETag、Vary 复用整个响应。public 表示 CDN 可以共享，private 表示只能存在用户自己的浏览器里。

第二层是请求内去重，比如 React 的 cache、Next.js 对 fetch 的记忆，只在一次渲染里有效。第三层是框架的数据缓存，比如 Next.js 的 'use cache'、Nuxt 的 cachedEventHandler，跨请求保存，要按时间或标签失效。第四层是客户端状态缓存，比如 TanStack Query、Pinia 里的数据，存在浏览器内存里，用户登出时要清空。

每层的范围和失效方式都不一样，所以出问题时要先搞清楚是哪一层。

最要紧的一条：带用户名、权限、订单这些个性化内容的响应，不能用 public 缓存。缓存键要包含用户、语言、权限等所有会影响结果的因素，否则一个人的页面可能发给另一个人。

四层放在一起比

层存在哪里范围如何失效
HTTP / CDN浏览器、CDN 节点按 URL 和 Varymax-age 到期、清除 CDN、改 URL
请求内去重服务端内存一次请求请求结束
框架数据缓存服务端内存或共享存储跨请求、跨用户时间、标签、路径失效
客户端状态浏览器内存当前标签页重新获取、手动清除

注意框架数据缓存那一行的范围是“跨用户”。这就是为什么个性化数据放进去会出事。

公共页面怎么设

文章、商品详情这种对所有人都一样的页面，可以这样设：

http
Cache-Control: public, max-age=60, stale-while-revalidate=300

意思是 CDN 可以缓存 60 秒。过了 60 秒以后的 5 分钟内，CDN 可以先把旧内容返回给用户，同时在后台去取新的。这样用户不用等，内容也不会太旧。

个性化页面怎么设

http
Cache-Control: private, no-store

如果一个页面大部分是公共内容，只有头像、购物车数量是个人的，整页都不缓存就太浪费了。可以把页面当公共内容缓存，个性化的部分在客户端单独请求；或者用框架的部分预渲染，让个性化部分在请求时生成。

有人会想用 Vary: Cookie 让 CDN 按用户区分缓存，这不可靠。Cookie 里通常有各种和页面无关的字段，每个人都不一样，缓存几乎命中不了。更危险的是，一旦 CDN 配置忽略了 Vary，就会把一个人的页面发给其他人。

静态资源怎么设

打包出来的 JS、CSS 文件名里带了内容哈希，比如 app.3f9a1c.js，内容一变名字就变。所以同一个名字的文件永远不会变，可以放心长期缓存：

http
Cache-Control: public, max-age=31536000, immutable

HTML 就不一样了，它的文件名不变。如果也长期缓存，用户拿到的是旧 HTML，里面引用的是已经删掉的旧资源，页面就坏了。所以 HTML 要设短缓存，或者每次都重新验证。

发布和回滚时要注意什么

发布后要清掉 CDN 里的 HTML 缓存，但旧版本的静态资源要保留一段时间。因为有用户还开着旧页面，他们按需加载代码块时请求的是旧文件，删了就会 404。

回滚代码时，框架的数据缓存和 CDN 缓存里可能还存着新版本生成的内容，要一起清掉，否则回滚了也看不出效果。

常见追问

怎么确认响应命中了哪一层缓存？

看响应头里的 Age、Cache-Status，还有 CDN 自己定义的命中头。

SSG 页面还需要缓存策略吗？

需要。构建出来的 HTML 照样要设合适的 Cache-Control，内容更新以后也要清 CDN。
