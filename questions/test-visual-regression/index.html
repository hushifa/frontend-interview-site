视觉回归测试如何减少无意义的截图差异？

截图测试比较页面和基线图片的像素差异；要稳定，需要固定浏览器和系统环境、等字体和数据就绪、屏蔽动态内容，并用 threshold、maxDiffPixels 等容差区分抗锯齿噪声和真实变化。

参考答案

简答

  • await expect(page).toHaveScreenshot() 首次运行时没有基线，测试会失败并写入当前截图作为基线，人工确认后再提交；之后每次与基线逐像素比较；基线文件名包含浏览器和平台，例如 landing-chromium-linux.png。
  • 不同系统、浏览器版本、字体和显卡的渲染都有差异，基线应在固定的 CI 环境（例如官方 Docker 镜像）中生成和比较。
  • 截图默认禁用动画（animations: 'disabled'）并隐藏光标；时间、随机数据、广告等用 mask 遮住，或固定数据后再截图。
  • threshold（默认 0.2）是单个像素允许的颜色差异，maxDiffPixels 和 maxDiffPixelRatio 是允许不同的像素数量或比例。
  • 有意的界面变化用 npx playwright test --update-snapshots 更新基线，并在代码评审中检查新图。

示例

TypeScript
import { test, expect } from '@playwright/test';

test('价格页', async ({ page }) => {
  await page.clock.setFixedTime(new Date('2026-01-01T10:00:00'));
  await page.route('**/api/plans', (route) =>
    route.fulfill({ path: 'fixtures/plans.json' }),
  );
  await page.goto('/pricing');
  await expect(page.getByRole('heading', { name: '选择套餐' })).toBeVisible();

  await expect(page).toHaveScreenshot('pricing.png', {
    fullPage: true,
    mask: [page.getByTestId('live-chat')],
    maxDiffPixelRatio: 0.01,
  });
});

toHaveScreenshot 会等待页面连续两次截图一致后再比较，可以减少截到渲染中间状态的情况。

三个容差怎样选

选项含义适合
threshold单个像素的颜色差异容忍度，0 最严格，1 最宽松抗锯齿、渐变的细微色差
maxDiffPixels允许不同的像素个数小组件，少量像素噪声
maxDiffPixelRatio允许不同的像素比例（0–1）整页截图，尺寸不固定

容差设得太大会漏掉真实问题，比如按钮少了 1px 边框。先通过固定环境和数据消除噪声，再用最小的容差。全局默认值可以在 playwright.config.ts 的 expect.toHaveScreenshot 中设置。

让截图稳定

  • 字体：使用本地托管的 Web 字体，避免系统字体差异。
  • 时间：用 page.clock 固定时间。
  • 数据：用 page.route 返回固定响应。
  • 布局：固定视口大小，必要时用 stylePath 注入只在截图时生效的样式，隐藏滚动条或 iframe。
  • 图片：等待图片加载完成后再截图。

组件级截图

页面截图覆盖整体布局，组件截图更快、失败更容易定位：

TypeScript
await expect(page.getByRole('dialog')).toHaveScreenshot('confirm-dialog.png');

用 Storybook 管理组件状态时，每个 story 固定一组 props 和数据，相当于一个视觉用例。Storybook 官方的像素比较依赖 Chromatic 云服务；不用云服务时，可以让 Playwright 逐个打开 story 的独立 iframe 页面截图：

TypeScript
import { expect, test } from '@playwright/test';

const stories = ['datepicker--closed', 'datepicker--open', 'datepicker--invalid'];

for (const id of stories) {
  test(`视觉：${id}`, async ({ page }) => {
    await page.goto(`/iframe.html?id=${id}&viewMode=story`);
    await expect(page.locator('#storybook-root')).toHaveScreenshot(`${id}.png`);
  });
}

story ID 由 Storybook 按标题和导出名生成，以实际构建出的 index.json 为准；从这个文件读取列表，也能避免新增状态后忘记登记。状态按风险选取：关闭、展开、错误、禁用、长文案和窄容器，比穷举所有组合更有价值。

基线管理

  • 基线绑定运行环境，固定在 CI 使用的同一个容器镜像中生成，开发者本机生成的图片和 CI 不一致。
  • 浏览器或字体升级会带来大量合理差异，单独提交一次基线更新，不和业务改动混在一起。
  • 只更新本次明确改动的组件状态，不顺手接受其他失败；提交说明写清改了哪些状态、主题和视口。
  • 第一次生成的基线也要人工确认，工具只记录当前外观，不知道设计是否正确。
  • 删除组件或状态时同步删除旧基线。

常见追问

  • 截图测试失败了怎么看？打开 HTML 报告，会并排显示期望图、实际图和差异图。先判断是有意修改、环境噪声还是真实回归，再决定更新基线还是修代码。
