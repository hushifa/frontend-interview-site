一个可访问的模态对话框需要具备哪些行为？

模态对话框打开后，用户只能和它交互。它要有名称和 dialog 角色，打开时焦点移入、背景不可操作，Tab 只在对话框内循环，Esc 可关闭，关闭后焦点回到触发元素；原生 dialog 的 showModal() 已提供大部分行为。

参考答案

简答

模态对话框就是打开以后，用户只能和它交互、背后的页面暂时不能用的弹窗。它首先要有名称，用 aria-labelledby 指向标题，读屏打开时会读出来。

打开时，焦点要移进对话框。通常落在第一个可操作的元素上；内容很长时可以落在标题或对话框本身（加 tabindex="-1"）；删除这类破坏性确认框，可以先聚焦“取消”。打开期间，背景不能交互、读屏浏览不到，Tab 也不会跑到背景里。

关闭时，按 Esc 能关，关闭后焦点回到打开它的按钮。如果那个按钮已经被删掉了，就移到一个合理的位置。

这些行为原生 <dialog> 的 showModal() 大多已经做好了：显示在最上层、背景变成惰性、Esc 关闭、恢复焦点。所以优先用它。

原生 dialog 怎么写

下面是一个编辑资料的对话框，点按钮时用 showModal() 打开。

HTML
<button id="open">编辑资料</button>

<dialog id="edit" aria-labelledby="edit-title">
  <h2 id="edit-title">编辑资料</h2>
  <form method="dialog">
    <label>昵称 <input name="nickname" autofocus></label>
    <button value="cancel" formnovalidate>取消</button>
    <button value="save">保存</button>
  </form>
</dialog>
JavaScript
document.querySelector('#open').addEventListener('click', () => {
  document.querySelector('#edit').showModal();
});

autofocus 指定打开时焦点落在昵称输入框上。form method="dialog" 让表单里的按钮直接关闭对话框。

背景为什么点不到？因为 showModal() 会让对话框以外的内容变成惰性，效果相当于给背景加了 inert：不能聚焦、不能点击、读屏也看不到。

自己实现时要补什么

有时候用不了原生 dialog，比如维护旧组件库。这时要自己补齐几件事：容器写上 role="dialog"、aria-modal="true" 和 aria-labelledby；打开时给背景容器加 inert，关闭时移除；监听 Esc 关闭；打开前记下 document.activeElement，关闭后调用它的 focus()；把对话框渲染到 body 下，免得被祖先的 overflow 或层叠上下文影响。

这里最常见的误解是以为加了 aria-modal="true" 就够了。它只是告诉辅助技术“背景现在不可用”，并不会真的阻止交互，键盘照样能 Tab 到背景里。所以必须配合 inert 一起用。

其他细节

点遮罩关闭可以用 closedby="any"。不过表单里有未保存的内容时，应该先确认再关。closedby 目前不是 Baseline，用之前要检测 'closedBy' in HTMLDialogElement.prototype。不支持时就监听 click，在 event.target === dialog 时调用 close()，因为点到遮罩时事件目标就是 dialog 本身。

打开对话框时通常要阻止背景滚动，可以写 html:has(dialog[open]) { overflow: hidden; }。对话框里出现错误提示或异步结果时，用 live region 播报。

最后，不需要挡住背景的提示，用 popover 或非模态对话框就行，不要什么都做成模态。

常见追问

警告类对话框有什么不同？

需要用户马上确认的消息，用 role="alertdialog"，再用 aria-describedby 指向消息内容。这样读屏打开时会把消息一起读出来。
