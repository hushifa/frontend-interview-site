为什么字符串 length 不一定等于用户看到的字符数？

JavaScript 字符串的 length 是 UTF-16 码元数。一个 emoji 可能占两个码元，一个"字符"可能由多个码点组成。按用户看到的字符截断要用 Intl.Segmenter 的字素簇分割，分词用 word 粒度，字节数用 TextEncoder 统计，比较前按需 normalize。

参考答案

简答

  • 有四种单位：UTF-16 码元（length、slice 用的）、码点（[...text] 遍历出来的）、字素簇（用户眼中的一个字符）、UTF-8 字节（存储和传输大小）。
  • '😀'.length 是 2，'👨‍👩‍👧‍👦'.length 是 11，但它们在屏幕上都是一个字符。
  • 按"可见字符"截断要用 Intl.Segmenter 的 grapheme 粒度，slice 可能切开代理对，[...text] 可能拆散组合字符和 emoji 序列。
  • 中文、日文、泰文的词之间没有空格，分词用 Intl.Segmenter 的 word 粒度并过滤 isWordLike。
  • '\u00E9' 和 'e\u0301' 都显示为 é 但不相等，比较或去重前用 normalize('NFC')。

四种计数（Node 22 实测）

JavaScript
const graphemes = new Intl.Segmenter('zh-CN', { granularity: 'grapheme' });

for (const text of ['A', '😀', 'e\u0301', '👨‍👩‍👧‍👦']) {
  console.log(text.length, [...text].length, [...graphemes.segment(text)].length);
}
// 1 1 1
// 2 1 1
// 2 2 1
// 11 7 1

'你'.length; // 1
new TextEncoder().encode('你').length; // 3，UTF-8 字节

限制"昵称最多 20 个字符"时，先定义字符指字素簇，前后端用同一规则校验。数据库字段按字节限制时，用字节数校验。

按字素簇截断

JavaScript
function truncateText(text, limit) {
  if (!Number.isInteger(limit) || limit < 0) {
    throw new RangeError('保留数量必须是非负整数');
  }
  let count = 0;
  for (const part of graphemes.segment(text)) {
    if (count === limit) return text.slice(0, part.index) + '…';
    count += 1;
  }
  return text;
}

truncateText('A👨‍👩‍👧‍👦B', 2); // 'A👨‍👩‍👧‍👦…'
truncateText('A😀', 2); // 'A😀'，刚好两个，不加省略号
truncateText('你好世界', 2); // '你好…'

part.index 是原字符串里的 UTF-16 下标，可以直接交给 slice。循环找到截断点就返回，不必把整段文本转成数组。

这里 limit 是保留的原文字素簇数，省略号不计入；limit 为 0 且文本非空时只返回省略号。产品要求总长度包含省略号时，要另外定义额度。HTML 摘要不能按源码截断，否则会切坏标签和实体，先提取纯文本再处理。

没有 Intl.Segmenter 时可以用维护中的兼容实现。Array.from 只按码点切割，会拆散组合字符和 emoji 序列，不能当作字素簇的降级方案。

分词

JavaScript
const words = new Intl.Segmenter('en', { granularity: 'word' });
[...words.segment('Hello, world!')]
  .filter((s) => s.isWordLike)
  .map((s) => ({ text: s.segment, index: s.index }));
// [{ text: 'Hello', index: 0 }, { text: 'world', index: 7 }]

const zh = new Intl.Segmenter('zh', { granularity: 'word' });
[...zh.segment('我喜欢国际化')].filter((s) => s.isWordLike).map((s) => s.segment);
// ['我', '喜欢', '国际', '化']（结果取决于运行时的分词数据）

分词结果依赖运行时的语言数据，不保证符合业务词典或搜索引擎的切词规则。

granularity: 'sentence' 按句子切分，缩写、引号和复杂标点要用目标语言的样本验证。

做搜索高亮时，用 index 和 segment.length 定位原文区间，用文本节点和 <mark> 渲染，不要拼进 innerHTML。如果匹配前做了大小写折叠或规范化，字符串长度可能变化，要维护新旧位置的映射，不能用新字符串的下标切原文。

规范化

JavaScript
const composed = '\u00E9';
const decomposed = 'e\u0301';
composed === decomposed; // false
composed.normalize('NFC') === decomposed.normalize('NFC'); // true

规范化只处理 Unicode 规定的等价写法，不会把西里尔字母 а 和拉丁字母 a 当成同一个字符，防范仿冒用户名要另外检查。

常见追问

  • 输入框实时限制长度会有什么问题？ 中文输入法组合过程中（compositionstart 到 compositionend）不要截断，否则会打断输入。
  • Intl.Segmenter 能决定文字在屏幕上占多宽吗？ 不能。宽度由字体和渲染决定，要测量实际布局。
