text-wrap: balance 和 pretty 应该怎样使用？

解释 text-wrap 的 balance 与 pretty 如何影响标题和段落换行，说明它们不是固定宽度或溢出修复工具，并覆盖语言、性能、响应式布局、SSR 和兼容回退。

参考答案

简答

  • balance 让短的多行文本（标题、卡片标题）各行长度更均衡，pretty 让正文尽量避免末行只剩一个词的孤行。
  • 两者都是排版提示，由浏览器按当前宽度和字体计算，不是插入固定 <br>，也不会缩小字体或修复溢出。
  • 窗口、字体、翻译和文字放大都会触发重新分行，布局要能容纳行数变化。
  • 不支持的浏览器忽略它们，回到普通换行，天然是渐进增强。
CSS
.article-title {
  max-inline-size: 26ch;
  text-wrap: balance;
}

.article p {
  max-inline-size: 68ch;
  text-wrap: pretty;
}

balance 不是让每行一样长

浏览器在不超过容器宽度的前提下找较平衡的分法，最终结果仍取决于词长、标点、语言和字体。本来只能放一行的文字不会被拆成两行；比整行还长的 URL 或代码也不会被它解决，仍要配合 overflow-wrap 或横向滚动。

给标题设合理的 max-inline-size，比按某种语言写死 <br> 更能适应响应式和翻译。ch 只是近似字符宽度，对中文和 Emoji 并不精确，当作设计范围即可。

pretty 不保证出版级排版

pretty 的具体算法由浏览器决定，不替代 hyphens、语言标签、列宽和编辑审校。中文、日文和阿拉伯文的断行规则与英文不同，不能拿英文截图推断所有语言的效果。

语言标记会影响结果

HTML
<h1 lang="zh-CN">让组件在不同屏幕上保持清晰的层次</h1>
<p lang="en">A responsive layout should remain readable at every width.</p>

lang 帮浏览器和读屏器选择断行与发音规则，动态切换语言时要同步更新。不要用 JavaScript 按字数切字符串插 <br>，这会破坏复制、搜索、读屏和翻译。

布局要容纳重新分行

  • 卡片和按钮为标题预留合理的行数，不要把高度硬编码成一行；
  • 需要严格对齐的列表可以用 line-clamp 限制行数，但被隐藏的文字要能通过详情或可访问名称获取；
  • 字体加载策略要结合 CLS 一起评估。

平衡算法会尝试多种分法，短标题成本很小；大量长段落、实时变化的内容或动画中的宽度不宜无条件使用。

兼容回退

CSS
.title {
  overflow-wrap: break-word;
}

@supports (text-wrap: balance) {
  .title {
    text-wrap: balance;
  }
}

验收覆盖不同容器宽度、字体加载前后、长德语与 RTL、文字放大，以及不支持该属性的浏览器。代码、URL、表格和严格格式的协议文本应使用更明确的换行策略，而不是 balance 或 pretty。
