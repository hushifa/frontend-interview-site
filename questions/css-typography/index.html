Web 排版中的行高、行宽和断行怎样处理？

行高写不带单位的数字，正文一行控制在 60 到 75 个字母或 30 到 40 个汉字，长单词和中文断行用 overflow-wrap、word-break 处理，可变字体优先用 font-weight 这类常规属性控制。

参考答案

简答

行高要写不带单位的数字，比如 line-height: 1.6。这样每个子元素按自己的字号重新算行高。写成 px 或 em，父元素算好的固定值会原样传给子元素，大标题就会挤在一起。

正文一行不要太长，用 max-inline-size: 65ch 这类写法限制，大约 60 到 75 个字母或 30 到 40 个汉字。行太长，读者读完一行很难找到下一行的开头。

断行有几个常用属性。长网址撑破布局用 overflow-wrap: anywhere；word-break: break-all 会在任意字母之间断开，影响英文阅读。word-break: keep-all 让中日韩文字按词或标点断行，line-break: strict 控制标点不出现在行首。

可变字体优先用 font-weight、font-stretch、font-style 控制。font-variation-settings 是底层属性，会覆盖这些常规属性，而且多次声明时是整体替换，不会按轴合并。

行高为什么要写无单位数字

CSS
body {
  font-size: 1rem;
  line-height: 1.6;
}

h1 {
  font-size: 2.5rem;
  line-height: 1.2;
}

假如 body 写的是 line-height: 24px，h1 又没有自己写行高，会怎样？h1 字号是 40px，继承来的行高却只有 24px，标题一换行，两行字就叠在一起了。

原因是 px 和 em 的行高在父元素上就算成了固定的像素值，子元素继承的是这个结果。无单位的 1.6 继承下去的是比例，每个元素按自己的字号乘一遍。

长内容怎么断行

CSS
.content {
  overflow-wrap: anywhere;
}

.cjk-title {
  word-break: keep-all;
}

.code {
  white-space: pre;
  overflow-x: auto;
}

overflow-wrap 有 break-word 和 anywhere 两个值，都是只在找不到别的断点时才把单词断开。区别在于，anywhere 产生的断点会算进元素的最小内容宽度。所以在 flex 和 grid 项目里，anywhere 能让项目缩下去，不容易撑开容器；break-word 不行。

代码块一般不让它自动换行，用 white-space: pre 保留原样，横向滚动。

英文想要加连字符，用 hyphens: auto，但必须写对 lang 属性，浏览器才知道按哪种语言的规则断词。

中英文混排的字体栈

CSS
body {
  font-family: system-ui, -apple-system, 'Segoe UI', 'PingFang SC',
    'Microsoft YaHei', sans-serif;
}

为什么先写西文字体？浏览器按顺序找字形。西文字体里有字母和数字，没有汉字。所以英文和数字用西文字形显示，汉字找不到，就落到后面的中文字体。反过来写，中文字体里也有字母，英文就全变成中文字体里的字母了。

中文网页字体体积很大，正文通常直接用系统字体。字体加载策略见《font-display 怎样影响字体加载期间的文字显示？》。

可变字体

CSS
@font-face {
  font-family: 'Inter';
  src: url('/inter.woff2') format('woff2');
  font-weight: 100 900;
}

strong {
  font-weight: 650;
}

一个可变字体文件里包含了连续的粗细变化。在 @font-face 里声明 font-weight 的范围是 100 到 900，范围内的任意数值都能用，比如 650。

只有字体的自定义轴，比如 GRAD，才需要用 font-variation-settings。

常见追问

为什么文字和容器底部之间总有一点空隙，看着不居中？

行高多出来的空间是平均分在字形上下的，再加上字体自身上下的留白，视觉上就不居中。text-box: trim-both cap alphabetic 可以把多余的空白裁掉，支持情况要先查兼容表。
