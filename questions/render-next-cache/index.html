Next.js App Router 中的几层缓存怎样区分？

Next.js 16 新项目默认开启 Cache Components：数据和组件默认不缓存，用 'use cache' 显式缓存，用 cacheLife 设置时长、cacheTag 打标签，修改后用 updateTag 或 revalidateTag 失效；需要请求数据的部分放进 Suspense 流式输出。未开启时沿用旧模型，fetch 默认不缓存，通过 force-cache 和路由段配置控制。

参考答案

简答

  • Next.js 16 引入 Cache Components（cacheComponents: true），用推荐配置创建的新 App Router 项目默认开启。
  • 在 Cache Components 下，数据请求和组件默认在请求时执行；在函数或组件顶部写 'use cache' 才缓存结果，参数和闭包变量自动成为缓存键。
  • 用 cacheLife('hours') 等配置设置缓存时长，用 cacheTag('posts') 打标签；修改数据后在 Server Action 中调用 updateTag（立即失效）或 revalidateTag(tag, 'max')（先返回旧数据、后台刷新）。
  • 读取 cookies()、headers()、searchParams 或未缓存数据的组件要包在 <Suspense> 中：构建时生成包含静态和已缓存内容的外壳，Suspense 内的部分在请求时流式输出，这种方式称为部分预渲染（PPR）。
  • 未开启 Cache Components 的项目使用旧模型：Next 15 起 fetch 默认不缓存，用 cache: 'force-cache'、next.revalidate、unstable_cache 和路由段配置控制。

Cache Components 示例

TSX
// app/blog/page.tsx
import { Suspense } from 'react';
import { cookies } from 'next/headers';
import { cacheLife, cacheTag } from 'next/cache';

export default function BlogPage() {
  return (
    <>
      <h1>博客</h1>
      <Posts />
      <Suspense fallback={<p>加载偏好…</p>}>
        <Preferences />
      </Suspense>
    </>
  );
}

async function Posts() {
  'use cache';
  cacheLife('hours');
  cacheTag('posts');
  const posts = await db.post.findMany();
  return <ul>{posts.map((p) => <li key={p.id}>{p.title}</li>)}</ul>;
}

async function Preferences() {
  const theme = (await cookies()).get('theme')?.value ?? 'light';
  return <p>主题：{theme}</p>;
}
  • 标题和 Posts 的结果进入静态外壳，可以直接从 CDN 返回。
  • Preferences 读取 cookie，在请求时生成，通过流式响应填充到 fallback 的位置。

缓存存在哪里

  • 预渲染的 HTML：构建时或 ISR 时生成，可以由 CDN 提供。
  • 服务端缓存：默认在每个实例的内存中，Serverless 环境下可能不持久；'use cache: remote' 使用共享的缓存处理器。
  • 浏览器：客户端导航或预取得到的结果，在 cacheLife 的 stale 时间内被复用。'use cache: private' 的结果只保存在浏览器中，可以读取 cookie。

每次部署后缓存都会重新开始，因为缓存键包含构建 ID。

旧模型（未开启 Cache Components）

TypeScript
await fetch(url); // Next 15 起默认不缓存
await fetch(url, { cache: 'force-cache' }); // 缓存
await fetch(url, { next: { revalidate: 3600, tags: ['posts'] } }); // 定时失效 + 标签

export const dynamic = 'force-dynamic'; // 路由段配置：每次请求都渲染
export const revalidate = 60; // 路由默认的重新验证时间

非 fetch 的数据源用 unstable_cache 包装。在 Next 14 中，fetch 默认是缓存的，从 14 升级到 15 时要注意这个变化。

个性化数据

读取 cookie 或用户身份的组件不要用普通的 'use cache' 缓存成共享结果；把用户 ID 作为参数传给缓存函数时，它会成为缓存键的一部分，或者使用 'use cache: private'。CDN 层的个性化缓存问题见《SSR 和 SSG 中的缓存层应该怎样区分？》。

常见追问

  • 'use cache' 和 React cache 的区别？React cache 只在一次请求内去重，'use cache' 跨请求持久化，见《React 的 cache API 解决什么问题？》。
  • Math.random()、Date.now() 怎么处理？需要每次请求不同的值，先 await connection() 并放进 Suspense；希望所有用户共享同一个值，放进 'use cache' 中。
