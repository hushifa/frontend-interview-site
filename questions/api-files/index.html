File、Blob 和 object URL 怎样用于文件预览？

Blob 是一段二进制数据，File 是带文件名的 Blob。预览时用 URL.createObjectURL() 生成一个临时地址给 img 用，用完要 revokeObjectURL() 释放。

参考答案

简答

上传头像前先在页面上预览，就会用到这三样东西。Blob 是一段不可变的二进制数据，有 size 和 type。File 继承自 Blob，多了文件名 name 和修改时间 lastModified。

网页不能自己去读本地路径，只有用户通过 <input type="file">、拖放或粘贴交出来的文件，网页才拿得到。

预览时用 URL.createObjectURL(file)，它返回一个 blob: 开头的短地址，直接赋给 img.src 就能显示，不用读成 base64。要读内容就用 blob.text()、blob.arrayBuffer() 或 blob.stream()。

要注意 object URL 会一直占着内存，直到调用 URL.revokeObjectURL() 或页面卸载。还有 file.type 是按扩展名猜的，不可信，服务端必须重新校验。

做一个图片预览

下面监听文件选择框，用户选了图片就显示出来。

JavaScript
let previewUrl;

input.addEventListener('change', () => {
  const file = input.files?.[0];
  if (!file) return;
  if (!file.type.startsWith('image/')) {
    showError('请选择图片文件');
    return;
  }

  if (previewUrl) URL.revokeObjectURL(previewUrl);
  previewUrl = URL.createObjectURL(file);
  preview.src = previewUrl;
});

为什么每次换图前要先 revokeObjectURL？因为 object URL 只是一个指向内存数据的“门牌号”，只要门牌号还在，浏览器就不敢回收那块数据。用户换十次图，不释放就会占着十份图片的内存。所以每次换图先释放上一张，组件卸载时也要释放。

File 就是带名字的 Blob

下面用 Node 也能跑，看看 File 和 Blob 的关系。

JavaScript
const file = new File(['你好'], 'a.txt', { type: 'text/plain' });
console.log(file instanceof Blob); // true
console.log(file.size, file.name); // 6 a.txt
console.log(await file.slice(0, 3).text()); // 你

size 是 6 而不是 2，因为它数的是字节，一个汉字用 UTF-8 编码占 3 个字节。slice(0, 3) 切出前 3 个字节，正好是“你”。

slice 返回一个新的 Blob，不复制数据，所以大文件切片上传就是用 file.slice(start, end) 一块一块地传。

object URL 和 data URL 怎么选

data URL 是把文件内容编码成 base64 字符串，用 FileReader.readAsDataURL() 生成。它要先把整个文件读完，长度大约是文件大小的 1.33 倍，好处是它就是普通字符串，不用手动释放。

object URL 用 URL.createObjectURL() 同步生成，立即返回，地址很短，但要手动释放。

所以预览大图、视频用 object URL；需要把数据嵌进 HTML 或者存起来时，才用 data URL。

常见追问

前端检查了文件类型，服务端还要查吗？

要。file.type 是浏览器根据扩展名推断的，把 exe 改名成 png 就能骗过去。前端检查只是给用户一个提示，服务端必须重新校验文件内容。

怎样让用户下载一段前端生成的文本？

用 new Blob([text], { type: 'text/plain' }) 生成 Blob，再用 object URL 赋给 <a download> 的 href，点击后释放这个地址。
