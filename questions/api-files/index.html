File、Blob 和 object URL 是什么关系？object URL 什么时候释放？

Blob 是一段不可变的二进制数据，File 是带文件名和修改时间的 Blob。URL.createObjectURL() 给 Blob 生成一个 blob: 开头的临时地址，每调用一次都生成新地址；只要地址还有效，背后的数据就不能被回收，要在资源不再被用户访问时调用 revokeObjectURL()，否则要等文档卸载才释放。

参考答案

简答

Blob 是一段不可变的二进制数据，有 size 和 type。File 继承自 Blob，多了文件名 name 和修改时间 lastModified，所以凡是收 Blob 的 API 都能直接收 File。

网页不能自己去读本地路径，只有用户通过 <input type="file">、拖放或粘贴交出来的文件，网页才拿得到。要读内容就用 blob.text()、blob.arrayBuffer() 或 blob.stream()；要切一段就用 blob.slice()，它返回新的 Blob。

URL.createObjectURL(blob) 给这份数据生成一个 blob:<origin>/<uuid> 形式的地址，可以交给 img、video、<a download> 这类只认 URL 的 API。它只是一个指向内存数据的标识，不包含数据本身。

要注意它的生命周期：每调用一次都会生成一个新地址，只要还有一个地址有效，背后的数据就不能被垃圾回收。浏览器会在文档卸载时自动释放，单页应用里要自己在资源不再被用户访问时调用 URL.revokeObjectURL()。

File 就是带名字的 Blob

下面用 Node 也能跑，看看 File 和 Blob 的关系。

JavaScript
const file = new File(['你好'], 'a.txt', { type: 'text/plain' });
console.log(file instanceof Blob); // true
console.log(file.size, file.name); // 6 a.txt
console.log(await file.slice(0, 3).text()); // 你

size 是 6 而不是 2，因为它数的是字节，一个汉字用 UTF-8 编码占 3 个字节。slice(0, 3) 切出前 3 个字节，正好是“你”。

Blob 不可变，slice 不会改原来的 Blob，而是返回一个新的 Blob。大文件切片上传就是用 file.slice(start, end) 一块一块地传。

type 也值得多看一眼。用户选的文件，file.type 是浏览器根据扩展名推断的，把 exe 改名成 png 就能骗过去，所以服务端必须按文件内容重新校验。

object URL 的生命周期

object URL 从 createObjectURL 生成开始有效，到下面两件事之一发生为止：调用 URL.revokeObjectURL(url)，或者创建它的文档卸载。

MDN 对内存管理写了三点。第一，同一个对象调用两次 createObjectURL，会得到两个不同的地址，每个都要单独释放。第二，只要有一个地址还有效，背后的对象就不能被回收，可能造成内存泄漏。第三，也不能释放得太早：图片 load 后立刻 revoke，用户就没法右键保存或在新标签打开这张图。所以长期运行的页面，应该在资源已经不再被用户访问时释放，比如图片从 DOM 上移除的时候。

revokeObjectURL 本身很宽容：传入无效地址、不是 object URL 的字符串，或者已经释放过的地址，它什么都不做，不会报错。所以清理时不必先判断地址是否还有效。

下载一段前端生成的文本，就是一个完整的生命周期：

JavaScript
const blob = new Blob([text], { type: 'text/plain' });
const url = URL.createObjectURL(blob);
const link = document.createElement('a');
link.href = url;
link.download = 'notes.txt';
link.click();
URL.revokeObjectURL(url);

上传前预览图片怎样接入文件选择框、换图时怎样释放上一个地址，以及和 FileReader 生成的 data URL 怎么选，见《图片上传前怎样本地预览？FileReader 和 URL.createObjectURL 有什么区别？》。

常见追问

object URL 能发给别人或存起来下次用吗？

不能。它的有效期跟着创建它的文档，文档卸载就失效；背后的数据在当前浏览器里，别的设备也打不开。要长期保存，得存 Blob 本身，比如放进 IndexedDB。

Service Worker 里能用 createObjectURL 吗？

不能。MDN 写明 createObjectURL 和 revokeObjectURL 在 Web Worker 里可用，但 Service Worker 除外，原因是 Blob 的生命周期问题和潜在的泄漏。
