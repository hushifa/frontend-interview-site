可选链和空值合并为什么不能简单替换为 && 和 ||？

?? 只在左侧为 null 或 undefined 时取右侧，|| 遇到 0、''、false 也会取右侧。?. 只在左侧为 null 或 undefined 时短路并返回 undefined，&& 遇到任何假值都短路并返回该假值。两者都不会吞掉属性读取或函数调用中抛出的异常。

参考答案

简答

  • a ?? b：仅当 a 是 null 或 undefined 时返回 b；a || b：a 为任意假值时都返回 b。
  • a?.b：a 为 null 或 undefined 时整条链短路，返回 undefined；a && a.b 在 a 为 0、'' 时返回这个假值。
  • ?. 还能用于调用和索引：fn?.()、obj?.[key]。
  • 短路会跳过整条链后面的表达式，包括参数求值。
  • ?? 不能和 ||、&& 直接混写，必须加括号。

示例

JavaScript
console.log(0 ?? 10); // 0
console.log(0 || 10); // 10
const user = null;
console.log(user?.profile?.name ?? '匿名'); // 匿名

数量、页码、开关等字段的合法值可能是 0 或 false，用 || 设置默认值会把它们覆盖掉。

可选链的范围

JavaScript
const data = { list: [] };
data.list?.[0]?.name;  // undefined
data.callback?.();     // undefined，不会抛 "not a function"
data.missing.deep;     // TypeError，没有写 ?.

let count = 0;
null?.method(count++);
console.log(count); // 0，参数没有求值
  • ?. 只检查它左边那一个值。a?.b.c 中，a 存在而 b 为 undefined 时，.c 仍然抛错。
  • fn?.() 只在 fn 为 null 或 undefined 时短路；fn 是其他非函数值时照样抛 TypeError。
  • 可选链不能用于赋值左侧：obj?.a = 1 是语法错误。
  • getter 或函数内部抛出的异常不会被吞掉。

混用规则

JavaScript
const value = (a || b) ?? c; // 必须加括号

a ?? b || c 直接写是语法错误，这是为了避免优先级歧义。

赋值运算符

  • a ??= b：a 为空值时才赋值。
  • a ||= b：a 为假值时才赋值。
  • a &&= b：a 为真值时才赋值。

它们都是短路的，条件不满足时不会对 a 执行写入，也不会触发 setter。

常见追问

  • 可选链会掩盖 bug 吗？会。必须存在的数据不要加 ?.，否则错误会以 undefined 的形式传到更远处才暴露。
  • document.all ?? 1 返回什么？document.all 是历史特殊对象，typeof 为 'undefined' 但它不是 undefined，?? 返回它本身。
