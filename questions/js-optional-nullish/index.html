可选链和空值合并为什么不能简单替换为 && 和 ||？

?? 和 ?. 只把 null 和 undefined 当成"没有值"，而 || 和 && 会把 0、空字符串、false 也当成没有。所以合法值是 0 或 false 时，用 || 设默认值会出错。

参考答案

简答

区别在于什么算“没有值”。a ?? b 只在 a 是 null 或 undefined 时才用 b；a || b 只要 a 是假值就用 b，0、空字符串、false 都算。

可选链也一样。a?.b 在 a 是 null 或 undefined 时，整条链停下来，返回 undefined；而 a && a.b 在 a 是 0 或空字符串时，返回的是这个假值本身。?. 还能用在函数调用和方括号取值上，比如 fn?.()、obj?.[key]。

有两点要注意。第一，短路会跳过整条链后面的所有部分，连函数参数都不会求值。第二，?? 不能直接和 ||、&& 混在一起写，必须加括号。

另外它们都不会吞掉异常，属性读取或函数调用里真的抛了错，照样会抛出来。

为什么用 || 设默认值会出错

JavaScript
console.log(0 ?? 10); // 0
console.log(0 || 10); // 10
const user = null;
console.log(user?.profile?.name ?? '匿名'); // 匿名

同样是 0 后面跟默认值 10，?? 保留了 0，|| 却换成了 10。

|| 判断的是真假，0 是假值，所以被当成“没有”。可是数量、页码、开关这些字段，合法值本来就可能是 0 或 false，用 || 设默认值就会把它们覆盖掉。?? 只关心是不是 null 或 undefined，正好符合“没传就用默认值”的意思。

最后一行是两者配合的常见写法：user 是 null，?. 让整条链返回 undefined，再由 ?? 换成“匿名”。

可选链能管到哪一步

JavaScript
const data = { list: [] };
data.list?.[0]?.name;  // undefined
data.callback?.();     // undefined，不会抛 "not a function"
data.missing.deep;     // TypeError，没有写 ?.

let count = 0;
null?.method(count++);
console.log(count); // 0，参数没有求值

data.callback?.() 没有报错，因为 callback 是 undefined，调用被跳过了。可是 data.missing.deep 报了 TypeError，因为没有写 ?.，从 undefined 上读 deep 当然报错。

最后一段可以看出短路有多彻底。null?.method(count++) 不光没调用 method，连参数 count++ 都没执行，count 还是 0。

使用时要清楚它的范围。?. 只检查它左边紧挨着的那个值。a?.b.c 里，如果 a 存在而 b 是 undefined，读 .c 照样报错，要写成 a?.b?.c。fn?.() 也只在 fn 是 null 或 undefined 时跳过，fn 是数字这种别的非函数值，还是会抛 TypeError。可选链不能放在赋值左边，obj?.a = 1 是语法错误。另外 getter 或函数内部抛出的异常，也不会被吞掉。

?? 和 || 为什么不能直接混写

JavaScript
const value = (a || b) ?? c; // 必须加括号

直接写 a ?? b || c 是语法错误。因为很难一眼看出到底先算哪个，规范干脆要求加括号，把意思写明白。

??= 这类赋值运算符怎样用

a ??= b 表示 a 是 null 或 undefined 时才把 b 赋给它。a ||= b 是 a 为假值时才赋值，a &&= b 是 a 为真值时才赋值。

它们也是短路的。条件不满足时，不只是值没变，而是根本没有对 a 做写入操作，所以如果 a 是一个带 setter 的属性，setter 也不会被触发。

常见追问

可选链会掩盖 bug 吗？

会。本来一定该有的数据，如果也加上 ?.，它缺失时不会马上报错，而是变成 undefined 一路传下去，到很远的地方才出问题，更难查。所以必须存在的数据不要加 ?.。

document.all ?? 1 返回什么？

返回 document.all 本身。它是一个历史遗留的特殊对象，typeof 结果是 'undefined'，但它并不真的是 undefined，所以 ?? 不会换成 1。
