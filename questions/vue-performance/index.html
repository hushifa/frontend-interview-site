Vue 大型页面应从哪些方面优化更新开销？

先用工具找到慢在哪，再对症下手：让子组件只收到真正变化的 props，派生数据放 computed，大块只读数据别做深层响应式，长列表用虚拟滚动，不变的子树用 v-memo 跳过。

参考答案

简答

第一步是测量，不是猜。用 Vue DevTools 的性能时间线看哪些组件渲染得多、耗时长，用浏览器 Performance 面板看长任务、布局和绘制。

最常见的问题是 props 不稳定。比如把整个 activeId 传给每一行，选中项一变，所有行的 props 都变了，所有行都要更新。改成只传“这一行是否选中”，就只有两行更新。

数据层面，大块只读数据，比如接口返回的十万行表格、第三方库的实例，用 shallowRef 或 markRaw，省掉深层代理的开销。长列表用虚拟滚动，只渲染看得见的几十行。模板里的计算放进 computed，v-once 让内容只渲染一次，v-memo 在依赖不变时跳过子树。

要分清两类问题。路由懒加载、defineAsyncComponent 拆包解决的是首屏下载慢；输入卡顿要靠上面的更新优化，两者分开评估。

为什么 props 要稳定

看两种传 props 的写法：

vue
<!-- 不好：activeId 变化时所有行的 props 都变了 -->
<Row v-for="item in list" :key="item.id" :item="item" :active-id="activeId" />

<!-- 好：只有选中状态变化的两行更新 -->
<Row v-for="item in list" :key="item.id" :item="item" :active="item.id === activeId" />

子组件要不要重新渲染，取决于它收到的 props 有没有变。第一种写法里，每一行都收到 activeId，它一变，一千行就全部更新。第二种写法里，每行收到的是一个布尔值，选中项从 A 换到 B 时，只有 A 从 true 变 false、B 从 false 变 true，其他行的值没变，就不用更新。

大块数据为什么不要深层响应式

ref 默认会把里面的对象深层转成响应式，十万行数据的每个属性都要包一层代理。如果这些数据只是拿来展示，很少逐个修改，这份开销就是白花的：

JavaScript
import { shallowRef, triggerRef } from 'vue';

const rows = shallowRef([]);

async function load() {
  rows.value = await fetchRows(); // 10 万行，只代理外层
}

function rename(index, name) {
  rows.value[index].name = name;
  triggerRef(rows); // 手动触发更新
}

shallowRef 只关心 .value 本身有没有被换掉。所以改了某一行的 name，Vue 不知道，得调用 triggerRef 手动通知。更推荐的做法是整体替换：rows.value = rows.value.with(index, { ...rows.value[index], name })，换了一个新数组，Vue 自然就知道了。

v-memo 怎么跳过子树

vue
<div v-for="item in list" :key="item.id" v-memo="[item.id === selectedId]">
  <ExpensiveCard :item="item" :selected="item.id === selectedId" />
</div>

v-memo 后面的数组是依赖。重新渲染时，如果某一项的依赖值和上次一样，Vue 直接跳过这一项的整个子树。所以 selectedId 变化时，只有选中状态改变的两项重新渲染。

它的风险在于依赖必须写全。影响渲染的值漏写了一个，那个值变了界面也不会更新。

模板里的计算为什么要放进 computed

vue
<!-- 不好：每次渲染都排序 -->
<li v-for="u in users.slice().sort(byName)" :key="u.id">{{ u.name }}</li>
JavaScript
const sortedUsers = computed(() => users.value.slice().sort(byName));

写在模板里，组件因为任何原因重新渲染，都要重新排一次序。放进 computed 以后，只有 users 变了才重新计算，其他时候直接用缓存。

加载速度怎么优化

路由用懒加载，比如 component: () => import('./pages/Report.vue')；很少显示的大组件用 defineAsyncComponent(() => import('./Editor.vue'))，用到时才下载。服务端渲染的场景里，Vue 3.5 起可以给异步组件设置惰性 hydration，比如 hydrateOnVisible()，滚动到可见时再激活。

这些减少的是首屏下载量，对输入卡顿没有帮助。

常见追问

组件拆得太多会变慢吗？

会有开销。每个组件实例都有创建和更新的成本，纯展示的小片段不必都拆成组件。
