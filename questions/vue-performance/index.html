Vue 大型页面应从哪些方面优化更新开销？

参考答案

先用性能工具定位耗时来自脚本、布局还是网络，再决定优化。组件层面可减少不必要的响应式深度、保持 props 稳定、拆分更新范围，并对大列表考虑虚拟化。

shallowRef、shallowReactive 适合明确接受浅层追踪的外部大型数据结构，但内部变更不再自动触发深层追踪，需要按约定替换根值。v-once 和 v-memo 也有适用条件，错误使用可能让界面停止更新。

优化不能破坏业务正确性。服务端渲染、静态生成和代码分割解决首屏交付问题，与组件更新优化是不同层次。应比较真实交互路径的性能，而不是只看首次渲染的单次计时。

组件层面的落地

Vue 题目可以沿着依赖收集、更新调度、组件渲染和副作用生命周期来理解。响应式引用记录的是读取关系，不代表所有嵌套对象都会以同样方式被追踪；具体行为还取决于使用的 API 和 Vue 版本。

落地时把派生状态、用户输入和副作用分开，避免用一个 watch 或可写变量反复同步同一事实。组件卸载、异步竞态、SSR 和第三方 DOM 操作都需要单独验证。
