线上报错怎样用 Source Map 还原，又不把 map 文件公开？

构建时生成不带 sourceMappingURL 注释的 hidden source map，按发布版本上传到错误监控服务或内网存储，部署产物里删掉 .map；前端上报原始堆栈，由服务端按版本和文件名还原到源码位置。

参考答案

简答

线上代码是压缩过的，报错堆栈里只有 app.3f2a.js:1:20345 这种位置，看不出是哪行源码。Source Map 就是压缩代码和源码之间的对照表。浏览器通过产物末尾的 //# sourceMappingURL= 注释，或者 SourceMap 响应头找到它；按 ECMA-426 规范，两者都有时以响应头为准。

可是 map 文件公开出去，别人也能拿来还原我们的源码。所以生产环境用 hidden source map：照常生成 .map 文件，但产物里不写那行注释，浏览器就不会自动加载。

生成以后，.map 只上传到错误监控服务或者内网存储，部署前从产物目录里删掉。要注意，光没有注释不等于安全，文件留在服务器上，别人猜到路径照样能下载。

还原放在服务端做。前端上报原始堆栈和发布版本号，服务端按版本找到对应的 map，把压缩后的行列号映射回源码位置。

为什么不能直接公开 map

Source Map 的原理、sourcesContent 为什么会暴露源码、按版本上传的基本流程，见《Source Map 如何帮助定位压缩后代码的错误？》。这里只讲监控这一侧的取舍。

有一种折中是 nosources-source-map，它不含源码内容，只保留映射，所以可以部署。用它的话，监控平台能还原出源文件名和行列号，但看不到源码片段；文件名和目录结构还是会暴露。

如果想在告警里直接看到出错的那几行代码，就只能用含源码的 hidden map，并且不部署。

构建怎么配置

webpack 和 Vite 都有现成的选项：

JavaScript
// webpack.config.js
export default {
  mode: 'production',
  devtool: 'hidden-source-map',
};
JavaScript
// vite.config.js
export default {
  build: { sourcemap: 'hidden' },
};

Vite 的 'hidden' 和 true 一样会输出独立的 map 文件，区别只是去掉了产物里的注释。

版本为什么必须一一对应

前端 SDK 上报的版本号，要和上传 map 时的版本号完全相同，比如都用 Git 提交哈希。

为什么这么严格？因为同名文件在不同的构建里内容可能不同。用错了 map，还原出来的位置看起来很合理，其实是错的，比报不出来更容易误导人。文件名带内容哈希能降低这种风险。

部署前要从 dist 删掉所有 *.map。

还原是怎么完成的

上报的堆栈长这样：at a (https://cdn.example.com/app.3f2a.js:1:20345)。服务端根据版本和文件 URL 找到对应的 map，用 source-map 这类库查第 1 行第 20345 列，得到源文件、原始行列号和函数名。

前提是上报了原始的 error.stack。如果是跨域脚本，报错只剩 Script error.，连行列号都没有，就没法还原了，要先解决跨域问题，见《前端怎样全局捕获 JS 错误、Promise 拒绝和资源加载失败？》。

常见追问

开发者调试线上问题时能看到源码吗？

能。在 DevTools 里手动关联本地或者内网的 map 文件就行，不需要把 map 公开。

第三方库的报错能还原吗？

只要构建时生成的 map 包含这些模块就能。没有打包进来、直接从外部 CDN 加载的脚本，要它自己提供 map。

只限制 map 文件的访问 IP 可以吗？

可以当作补充，但最简单可靠的做法还是不部署。
