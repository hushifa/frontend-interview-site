fetchpriority 能解决资源加载优先级问题吗？

fetchpriority 只能调整已经被发现的资源有多急，最常见的用法是给首屏主图设 high、给轮播里看不到的图设 low。资源发现得太晚、被懒加载或者网络本身慢，它都管不了。

参考答案

简答

浏览器会给每个资源排一个优先级，决定先下谁。fetchpriority 就是让你提个建议，取值有 high、low、auto，能用在 <img>、<link>、<script> 和 fetch() 上。

最常见的用途是首屏主图。以 Chromium 为例，它一开始用较低优先级请求图片，等确定图片在视口里才提上去。给主图加 fetchpriority="high"，就能从一开始就高优先级请求，常用来改善 LCP。

但它只是个提示，浏览器可以不听；而且它不改变资源被发现的时间。

所以资源如果藏在 CSS 或 JS 里、发现得很晚，要先用 preload 让浏览器早点知道它。首屏图片也不要加 loading="lazy"。

怎么用

HTML
<img src="/hero.avif" alt="产品主图" fetchpriority="high" width="1200" height="600" />

<!-- 轮播中初始不可见的图片 -->
<img src="/slide-2.avif" alt="" fetchpriority="low" />

<!-- 背景图在 CSS 中，先预加载再提升 -->
<link rel="preload" as="image" href="/bg.avif" fetchpriority="high" />

<script src="/analytics.js" async fetchpriority="low"></script>
JavaScript
// 预取下一步可能用到的数据，不和当前关键请求抢带宽
fetch('/api/recommendations', { priority: 'low' });

注意名字不一样：HTML 属性叫 fetchpriority，fetch() 里的选项叫 priority。

背景图那一行值得多看一眼。背景图写在 CSS 里，浏览器要等 CSS 下载解析完才知道它，这时光设优先级没用，因为还没发现。所以先用 preload 让它被提前发现，再用 fetchpriority 提高优先级。

它解决不了哪些问题

问题应该怎么做
主图由 JS 渲染后才插入服务端渲染或 preload
首屏图片加了 loading="lazy"去掉懒加载
图片太大压缩、选 AVIF/WebP、用 srcset
页面 TTFB 很慢优化服务端或用 Early Hints
主线程阻塞导致渲染慢拆分长任务，减少阻塞脚本

这些问题的共同点是，慢的原因不在“排队顺序”上。发现得晚、文件太大、服务器慢、主线程忙，调优先级都救不了。

为什么不能到处设 high

优先级是相对的。把很多资源都设成 high，等于谁都没提高，还会挤占 CSS 和关键脚本的位置。只给一两个真正决定首屏的资源加。

怎么验证

在 DevTools Network 面板打开 Priority 列，对比加属性前后资源的初始优先级和开始时间，再看 LCP 有没有变好。

常见追问

和 preload 有什么区别？

preload 解决的是“什么时候发现”，fetchpriority 解决的是“发现以后有多急”，两者可以一起用。

不支持的浏览器会怎样？

会忽略这个属性，按默认优先级加载，不会出错。
