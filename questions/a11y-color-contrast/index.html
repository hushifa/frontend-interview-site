无障碍色彩对比和状态表达应该怎样设计？

浅灰字配白底，很多人就看不清了。WCAG 要求正文文字和背景对比度至少 4.5:1，大号文字至少 3:1，图标、边框、焦点指示等非文本元素至少 3:1；错误、选中等状态不能只靠颜色区分。

参考答案

简答

设计稿上常见的浅灰字配白底，视力不好的人或者在阳光下看手机的人，很可能看不清。WCAG 用对比度来量化这件事。按 1.4.3（AA 级），普通文字和背景的对比度至少 4.5:1，大号文字至少 3:1。大号指 18pt，或者 14pt 加粗，大约是 24px 或 18.66px 加粗。

不只是文字。按 1.4.11（AA 级），理解界面要用到的图形和控件边界，比如输入框边框、图标、焦点环、图表线条，也要至少 3:1。按 1.4.1（A 级），颜色不能是传达信息的唯一方式，错误字段除了变红，还要有文字或图标。

有个例外：WCAG 不要求禁用的控件满足对比度。不过产品上通常还是要让用户看得出它不可用。

要注意，深色模式、悬停、聚焦这些状态都会换颜色，每一种都要单独检查。Windows 的高对比度模式，也就是 forced-colors，也要看一遍。

对比度怎么算

公式是：对比度 = (L1 + 0.05) / (L2 + 0.05)。L1 是较亮颜色的相对亮度，L2 是较暗颜色的相对亮度。相对亮度可以理解为“这个颜色在人眼里有多亮”，绿色占的权重最大。

下面把公式写成代码，算两组常见的颜色。

JavaScript
function luminance(hex) {
  const [r, g, b] = hex.match(/\w\w/g).map((c) => {
    const v = parseInt(c, 16) / 255;
    return v <= 0.04045 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}

function contrast(a, b) {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);
}

contrast('#767676', '#ffffff'); // 约 4.54，正文刚好达标
contrast('#000000', '#ffffff'); // 21

黑配白是最大值 21。#767676 这种灰配白底是 4.54，刚好过 4.5。再浅一点，正文就不达标了。

实际工作中不用自己算，开发者工具的取色器或设计工具插件会直接显示是否达到 AA 和 AAA。

关键是每一种实际出现的颜色组合都要算。悬停、聚焦、选中和深色模式都会换颜色，所以要分别检查。WCAG 1.4.3 对禁用控件不作要求，但禁用状态完全看不出来，同样会让用户困惑。

状态为什么不能只靠颜色

色盲用户分不清红和绿。如果错误只靠边框变红来表示，他们根本发现不了。下面的写法在颜色之外还给了图标和文字。

HTML
<label for="email">邮箱</label>
<input id="email" aria-invalid="true" aria-describedby="email-error">
<p id="email-error" class="error">
  <svg aria-hidden="true">…</svg>
  请输入有效的邮箱地址
</p>

aria-invalid 告诉读屏这个字段有错，aria-describedby 把错误文字关联到输入框上，聚焦时会一起读出来。

正文里的链接也是一样。如果只靠颜色和周围文字区分，链接颜色和周围文字的对比度要至少 3:1，并且在悬停和聚焦时加上下划线。最简单的做法是一直保留下划线。

高对比度模式下会发生什么

Windows 的高对比度模式会把背景色和阴影换成系统颜色。所以只靠背景色表示的选中状态，在这种模式下会直接消失。

CSS
@media (forced-colors: active) {
  .chip[aria-pressed='true'] {
    outline: 2px solid CanvasText;
  }
}

改法是在这种模式下补上边框或轮廓，并使用 CanvasText、Highlight 这类系统颜色关键字，它们会跟着用户选的配色走。

常见追问

APCA 能代替 WCAG 的公式吗？

不能。APCA 是社区提出的一种新对比度算法，常被拿来讨论 WCAG 3 该怎么算对比度。可是 WCAG 3 目前还是工作草案，草案里写明对比度算法还没有确定，也没有说要采用 APCA。所以现在做合规，仍然按 WCAG 2.2 的比例来。
