为什么需要提交 lockfile？npm ci 和 npm install 有何区别？

package.json 写的是版本范围，lockfile 记录实际依赖树。文中讲 npm install 何时更新锁文件、npm ci 的一致性检查，以及工具版本、平台和安装脚本为什么要单独控制。

参考答案

简答

package.json 里写的通常是版本范围，比如 ^1.2.0。今天装和下个月装，拿到的版本可能不一样，这就是“本地能跑、CI 失败”的常见原因。

lockfile 把整棵依赖树里每个包的确切版本、下载地址和完整性哈希都记下来。提交以后，所有人和 CI 装出来的结果就一致了。

npm install 可能按范围重新解析并更新锁文件。npm ci 严格按锁文件安装，锁文件和 package.json 对不上就直接报错，而且会先删掉已有的 node_modules，所以适合 CI 和生产构建。

要注意，锁文件不固定 Node.js 版本、包管理器版本和平台相关的原生依赖，这些要单独约束。

版本范围和实际版本

先看一个普通的依赖声明：

json
{ "dependencies": { "dayjs": "^1.11.0" } }

^1.11.0 允许 1.x 里任何不低于 1.11.0 的版本。今天装可能是 1.11.10，下个月可能就是 1.11.13。这还只是直接依赖，间接依赖的范围更多，变化面更大。

所以没有锁文件时，两个人在不同时间安装，拿到的依赖树可能不一样。

lockfile，比如 package-lock.json、pnpm-lock.yaml、yarn.lock，就是把某一次解析的结果固定下来。它还记录了下载地址和 integrity 哈希，安装时会校验包的内容有没有被替换。

npm install 和 npm ci 有什么不同

锁文件不存在时，npm install 会解析依赖并生成一个，npm ci 直接报错。

锁文件和 package.json 不一致时，npm install 按 package.json 重新解析并更新锁文件，npm ci 报错退出。

已经有 node_modules 时，npm install 增量更新，npm ci 先删掉再重新装。

所以 npm install 可能会修改 package.json 或锁文件，npm ci 不会。

其他包管理器也有对应的做法：pnpm 是 pnpm install --frozen-lockfile，在 CI 环境里默认开启；Yarn 是 yarn install --immutable。

什么时候更新锁文件

新增、删除、升级依赖时，用 npm install <pkg> 或 npm update 更新锁文件，然后和代码一起提交、评审。

遇到合并冲突，不要手工编辑锁文件。先解决 package.json 的冲突，再重新运行安装，让工具生成锁文件。

库项目也应该提交锁文件，保证自己的开发和测试能复现。不过发布到 npm 以后，使用者不会读取库的 package-lock.json。

锁文件管不到哪些东西

Node.js 和包管理器的版本，锁文件管不到，要用 engines、.nvmrc、packageManager 字段固定。

安装脚本也管不到。postinstall 可能下载二进制文件，甚至执行任意代码，结果受网络和系统影响。CI 可以用 --ignore-scripts 配合白名单降低风险。

平台差异同样如此。可选依赖和原生模块会按操作系统和 CPU 选择不同的包。

常见追问

为什么 CI 要用 npm ci？

因为它保证构建用的就是评审过的那棵依赖树。依赖声明和锁文件不一致时，它会尽早失败，而不是悄悄装出另一套依赖。

锁文件能防止供应链攻击吗？

能防一部分：已经固定的包如果被悄悄替换，哈希校验会失败。但它挡不住你主动升级到一个恶意版本，所以升级时仍然要审查。
