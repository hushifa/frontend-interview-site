为什么需要提交 lockfile？npm ci 和 npm install 有何区别？

解释版本范围与实际依赖树的差别，说明 npm install 何时更新锁文件、npm ci 的一致性检查，以及工具版本、平台和安装脚本仍需单独控制的原因。

参考答案

package.json 可以允许一个版本范围，但真正安装时必须选择具体版本，依赖内部又有自己的依赖范围。两个人在不同时间重新解析，可能得到不同的传递依赖，即使顶层 package.json 一行没变。

lockfile 记录实际解析的版本、依赖关系和相应完整性等信息，让后续安装能复用这次选择。它使“这个提交使用了哪一棵依赖树”成为可追踪的构建输入，而不必把整个 node_modules 提交到仓库。

package.json 与锁文件各管什么

package.json 说明项目声明依赖什么、允许什么范围，以及包的脚本和其他契约。package-lock.json 则具体记录 npm 解析出的树。

把直接依赖全部写成精确版本，也不能完全替代锁文件，因为传递依赖仍可能存在范围与不同组合。反过来，只有锁文件也不够，项目仍需要表达自己的直接依赖和运行要求。

通常应一起提交清单与对应锁文件。评审依赖变更时，不仅看顶层版本，还要检查锁文件中哪些间接包、来源或 peer 关系发生了变化。

npm install 不是每次都丢弃锁文件

日常添加、移除和更新依赖时使用 npm install 等命令，npm 会根据清单、已有锁文件和当前选项解析安装，并在需要时更新锁文件。

如果已有锁定版本仍满足声明，install 通常会复用相应结果，不是每执行一次就无条件升级所有依赖。显式安装新版本、修改范围或更新相关配置，则可能改变树和锁文件。

因此不要把 install 简化为“安装最新”，也不要把它用于要求绝不修改构建输入的 CI 后还忽略工作区差异。

npm ci 做了哪些更严格的事情

npm ci 需要现有的 package-lock.json 或 npm-shrinkwrap.json，并要求它与相应清单匹配。它用于按已确认的结果进行完整安装，不是添加某个新依赖的命令。

主要区别是：

  • 清单与锁定结果不一致时失败，而不是顺手更新锁文件。
  • 安装前移除现有 node_modules，再按相关锁定结果安装。
  • 不写回 package.json 或锁文件。

所以它适合自动化构建与测试，但也意味着不能把它当成“保留现有依赖目录的小修复”。在自己的工作目录执行前，应知道正在操作哪个项目。

CI 失败后，不应为了过关直接改成 install 并忽略新产生的锁文件。先确认清单、锁文件和安装配置是否来自同一次明确的依赖变更。

安装选项也是依赖树的输入

例如生成锁文件时使用了影响 peer 解析或本地链接方式的选项，CI 却没有采用相同设置，就可能得到错误或不同处理。相关项目级配置应明确记录，而不是只存在于某台机器的全局配置里。

Node 与 npm 版本、操作系统、CPU 架构、可选依赖和原生模块构建，也会影响实际安装与运行。锁文件并不意味着在任何平台上 node_modules 都逐字节完全相同。

安装脚本还可能下载文件、编译本地模块或依赖环境变量。固定依赖树不能自动固定这些外部步骤，项目应说明允许哪些脚本及其构建条件。

锁文件不等于依赖安全证明

完整性信息帮助校验取得的包内容是否符合记录，不代表这个包本身没有漏洞或恶意行为。合法发布的错误版本也可以被完整地锁定下来。

缓存可以加快下载，但不能替代锁文件；清理缓存也不应该成为每次安装失败的默认动作。先看错误属于网络、认证、解析冲突、脚本执行还是运行环境，处理方式才会有针对性。

同一个项目通常应明确主用的包管理器与锁文件，避免多个工具轮流生成不同解析结果，再误以为它们具有相同语义。

库项目与应用项目还有一个区别

库项目提交 package-lock.json，可以固定库自身开发和测试环境，但它通常不会作为发布库的锁定树控制消费者的整个安装。消费者会按自己的清单、解析规则与锁文件选择依赖。

npm-shrinkwrap.json 有不同的可发布与锁定用途，不能把它与普通 package-lock 在分发时的行为完全混为一谈。

因此发布库还要正确声明 dependencies、peerDependencies、兼容范围和公开产物。你本机的锁文件能安装成功，不代表另一个独立消费者环境就一定能使用这个包。

锁文件冲突怎样处理更清楚

合并冲突时应先确定 package.json 中期望的依赖，再用项目约定的包管理器和配置重新生成或协调锁定结果，并检查差异。不要随意删除整份锁文件、重新解析所有包，却只把它描述成“解决文本冲突”。

最终在干净环境执行相应冻结安装和项目检查，才能证明这次提交的依赖选择可以被复现。锁文件让这个过程可检查，但不会替代对构建与业务行为的验证。
