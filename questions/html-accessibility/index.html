为什么可点击的元素应该优先使用 button？

从键盘、语义和辅助技术理解原生 HTML 的价值。

参考答案

button 自带按钮语义、焦点行为和键盘激活支持。用 div 模拟按钮，需要自行补充角色、焦点、Enter 与空格键行为等，容易遗漏。

导航到另一个地址用 <a href="…">；触发当前页面操作用 <button type="button">。图标按钮应有可访问名称，例如 aria-label。

同时保证可见的焦点样式、合理的触控面积和足够的颜色对比度。原生语义是基础，ARIA 用于补充无法通过原生 HTML 表达的信息。

实际排查时先看语义结构和布局上下文，再查看计算后的样式、盒模型、层叠来源和绘制结果。把视觉问题拆成结构、尺寸、定位和绘制几步，通常比反复修改一个 CSS 属性更容易定位原因。

交付前还要检查键盘操作、响应式断点、文本放大、打印和减少动画偏好。兼容性结论应以目标浏览器和特性检测为前提，不要把某个浏览器的偶发现象当成通用规则。

实际项目里，先用一个最小 DOM 结构复现问题，再分别修改结构、布局和样式来源。这样能区分是选择器没有命中、布局上下文不同，还是元素已经绘制但被遮挡；修复后再回到真实页面验证长文本和窄屏。
