原型链、class 和继承之间是什么关系？

每个对象通过内部 [[Prototype]] 链接到另一个对象，读属性时沿链查找直到 null。class 是建立在原型上的语法：方法放在 prototype 上共享，extends 同时连接实例原型和构造函数，并额外带来严格模式、必须 new 调用、私有字段等语义。

参考答案

简答

  • 每个对象有内部原型 [[Prototype]]，用 Object.getPrototypeOf 读取；读属性先找自身，再沿原型链找，直到 null。
  • Fn.prototype 是构造函数上的普通属性，new Fn() 创建的实例以它为原型；两者不是一回事。
  • class 的方法定义在 prototype 上供实例共享，static 成员挂在构造函数上；extends 让子类 prototype 和子类构造函数分别继承父类的对应对象。
  • 派生类构造函数必须先调用 super() 才能使用 this。
  • #x 私有字段是每个实例自己的，但只能在类体内访问，不走原型查找，也不能用 obj['#x'] 读取。

实例状态与共享方法

JavaScript
class Counter {
  constructor(value = 0) {
    this.value = value;
  }

  increment() {
    this.value += 1;
    return this.value;
  }

  static from(value) {
    return new Counter(value);
  }
}

const first = Counter.from(1);
const second = new Counter(5);

console.log(Object.getPrototypeOf(first) === Counter.prototype); // true
console.log(Object.hasOwn(first, 'value')); // true
console.log(Object.hasOwn(first, 'increment')); // false
console.log(first.increment === second.increment); // true
console.log(first.increment()); // 2
console.log(second.value); // 5

查找链是 first → Counter.prototype → Object.prototype → null。increment 来自原型，但调用时 this 仍是 first。from 属于 Counter 本身，first.from 不存在。

写入会遮蔽原型属性

JavaScript
const defaults = { theme: 'light' };
const settings = Object.create(defaults);

settings.theme = 'dark';
console.log(defaults.theme); // light
delete settings.theme;
console.log(settings.theme); // light

给继承来的数据属性赋值，会在对象自身新建属性，原型不变。例外：原型上是 setter 时调用 setter，原型上是只读属性时赋值失败（严格模式抛错）。Object.hasOwn 只看自身，in 包含原型链。

extends 做了什么

JavaScript
class User {
  constructor(name) { this.name = name; }
  describe() { return this.name; }
}

class Student extends User {
  constructor(name, course) {
    super(name);
    this.course = course;
  }
  describe() {
    return `${super.describe()}：${this.course}`;
  }
}

console.log(Object.getPrototypeOf(Student.prototype) === User.prototype); // true
console.log(Object.getPrototypeOf(Student) === User); // true

第一条链让实例方法可以继承，第二条链让静态方法可以继承。super.describe() 调用父类方法，this 仍是当前实例。

class 与构造函数写法的区别

  • 类体默认严格模式。
  • 不能不带 new 调用，否则抛 TypeError。
  • 类声明有 TDZ，不能在声明前使用。
  • 方法不可枚举，for...in 不会列出。
  • 类字段（count = 0、handle = () => {}）在构造时成为实例自身属性，每个实例一份。

instanceof

a instanceof B 检查 B.prototype 是否在 a 的原型链上，可被 Symbol.hasInstance 自定义。不同 iframe 的 Array.prototype 不同，判断数组用 Array.isArray。

常见追问

  • 手写 new 做了什么？以 Fn.prototype 为原型创建对象，用它作 this 调用 Fn，如果返回的是对象则用返回值，否则返回新对象。
  • 为什么不建议修改 __proto__？它是历史兼容接口，运行时改原型会让引擎优化失效；创建时用 Object.create 指定原型。
  • 继承和组合怎么选？继承适合稳定的"是一种"关系，层级深了会难以维护，仅为复用代码时优先组合。
