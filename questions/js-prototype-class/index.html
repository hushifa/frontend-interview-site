原型链、class 和继承之间是什么关系？

每个对象都连着一个原型对象，自己身上找不到的属性，就沿着原型一路往上找。class 是在原型上搭起来的写法，方法放在原型上让所有实例共用，另外还多了必须 new 调用、私有字段等规则。

参考答案

简答

每个对象都有一个内部原型，写作 [[Prototype]]，可以用 Object.getPrototypeOf 读到。读一个属性时，先在对象自己身上找，找不到就去原型上找，再找不到就去原型的原型上找，一直到 null，这条路线就是原型链。

容易混的是 Fn.prototype。它只是构造函数上一个普通的属性，用 new Fn() 创建的实例，会把它当成自己的原型。所以函数的 prototype 属性和对象的内部原型不是一回事。

class 就是在原型上搭起来的。方法定义在 prototype 上，所有实例共用一份；static 成员挂在构造函数本身上。extends 会连两条链：子类的 prototype 连到父类的 prototype，子类构造函数连到父类构造函数。子类构造函数里必须先调用 super()，才能用 this。

class 还带来了原型之外的规则，比如私有字段 #x。它是每个实例自己的，但只能在类的内部访问，不走原型查找，也不能用 obj['#x'] 读到。

方法在实例上还是在原型上

下面定义一个计数器类，然后检查实例自己有哪些属性，方法又是从哪来的。

JavaScript
class Counter {
  constructor(value = 0) {
    this.value = value;
  }

  increment() {
    this.value += 1;
    return this.value;
  }

  static from(value) {
    return new Counter(value);
  }
}

const first = Counter.from(1);
const second = new Counter(5);

console.log(Object.getPrototypeOf(first) === Counter.prototype); // true
console.log(Object.hasOwn(first, 'value')); // true
console.log(Object.hasOwn(first, 'increment')); // false
console.log(first.increment === second.increment); // true
console.log(first.increment()); // 2
console.log(second.value); // 5

value 是 first 自己的属性，因为它是在构造函数里用 this.value 赋值的。increment 却不是 first 自己的，可 first.increment() 照样能调用。

因为 first 的原型是 Counter.prototype，increment 就定义在那里。first 身上找不到，就沿原型链找到了。查找路线是 first → Counter.prototype → Object.prototype → null。两个实例用的是同一个 increment 函数，所以 first.increment === second.increment。

方法虽然来自原型，调用时 this 还是 first，所以改的是 first 自己的 value，second.value 还是 5。static 方法 from 挂在 Counter 本身上，实例访问 first.from 是找不到的。

给对象赋值会改到原型吗

JavaScript
const defaults = { theme: 'light' };
const settings = Object.create(defaults);

settings.theme = 'dark';
console.log(defaults.theme); // light
delete settings.theme;
console.log(settings.theme); // light

settings.theme 本来是从 defaults 继承的。给它赋值 'dark' 以后，defaults.theme 还是 'light'，原型没变。

因为赋值不会去改原型，而是在 settings 自己身上新建一个 theme，把原型上的那个挡住了，这叫遮蔽。删掉自己的 theme 以后，挡着的东西没了，读到的又是原型上的 'light'。

有两个例外。原型上的属性如果是 setter，赋值会调用这个 setter；原型上的属性如果是只读的，赋值会失败，严格模式下还会抛错。判断属性在哪里时，Object.hasOwn 只看自己，in 会连原型链一起看。

extends 连了哪两条链

JavaScript
class User {
  constructor(name) { this.name = name; }
  describe() { return this.name; }
}

class Student extends User {
  constructor(name, course) {
    super(name);
    this.course = course;
  }
  describe() {
    return `${super.describe()}：${this.course}`;
  }
}

console.log(Object.getPrototypeOf(Student.prototype) === User.prototype); // true
console.log(Object.getPrototypeOf(Student) === User); // true

第一条链让 Student.prototype 的原型指向 User.prototype，所以学生实例能用到 User 的实例方法。第二条链让 Student 构造函数的原型指向 User，所以 User 上的静态方法，Student 也能直接调用。

子类重写 describe 后，用 super.describe() 可以调用父类的版本，这时 this 仍然是当前这个学生实例。

class 和构造函数写法有什么区别

既然 class 建立在原型上，那它和以前的构造函数写法是不是完全一样？不是，它多了一些规则。

类的内部默认是严格模式。类不能不带 new 直接调用，否则抛 TypeError。类声明有暂时性死区，不能在声明之前使用。类的方法是不可枚举的，for...in 不会把它们列出来。

还有类字段，比如 count = 0 或 handle = () => {}。它们和方法不同，不在原型上，而是在创建实例时成为实例自己的属性，每个实例各有一份。

instanceof 是怎么判断的

a instanceof B 检查的是：B.prototype 在不在 a 的原型链上。这个行为可以用 Symbol.hasInstance 自定义。

因为它依赖原型，所以跨 iframe 时会出问题。不同 iframe 有各自的 Array.prototype，从别的 iframe 传过来的数组，instanceof Array 会是 false。判断数组要用 Array.isArray。

常见追问

new 做了哪些事？

先创建一个新对象，它的原型是 Fn.prototype。然后把这个对象当作 this 调用 Fn。如果 Fn 返回了一个对象，就用这个返回值，否则返回新创建的对象。

为什么不建议修改 __proto__？

__proto__ 是为了兼容老代码保留的接口。运行时修改对象的原型，会让引擎之前做的优化失效。需要指定原型时，在创建对象时就用 Object.create 指定。

继承和组合怎么选？

继承适合稳定的“是一种”关系，比如学生是一种用户。层级一深就很难维护，如果只是想复用一段代码，优先用组合，把功能做成独立的对象或函数拿来用。
