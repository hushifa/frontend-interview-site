AudioContext 与音频节点图怎样组织音频处理？

Web Audio 使用音频节点图表达音源、处理与输出之间的连接。AudioContext 管理相关音频处理环境，音源可以经过增益、滤波等节点后连接到输出，不需要把全部处理写成 JavaScript 定时循环。

参考答案

Web Audio 用音频节点图表达声音从哪里来、经过什么处理、最后输出到哪里。AudioContext 管理处理环境和音频时间线，节点之间通过 connect 连接，而不是靠页面不断手动计算每个扬声器采样值。

例如背景音可以经过 GainNode 调音量，再连接到 destination；麦克风也可以接入分析或效果节点，但取得麦克风权限仍是独立的媒体采集步骤。

音源、处理节点和输出各有职责

OscillatorNode 生成波形，AudioBufferSourceNode 播放已经解码的缓冲，媒体元素或 MediaStream 也可通过相应节点接入。GainNode 调整增益，滤波和分析节点完成其他处理，destination 通常连接当前音频输出。

节点图可以分支或混合，不是一条只能串行通过的链。创建了节点却没连接到输出，不代表一定能听到声音；节点没有输入、上下文暂停或增益为零也会影响结果。

用音频时间线调度，不靠 setTimeout 卡节拍

下面函数接收由应用管理的、正在运行的 AudioContext，调度一段短提示音：

JavaScript
function scheduleTone(context) {
  const source = context.createOscillator();
  const gain = context.createGain();
  const start = context.currentTime + 0.02;
  source.frequency.value = 440;
  gain.gain.setValueAtTime(0, start);
  gain.gain.linearRampToValueAtTime(0.08, start + 0.01);
  gain.gain.linearRampToValueAtTime(0, start + 0.18);
  source.connect(gain);
  gain.connect(context.destination);
  source.addEventListener('ended', () => {
    source.disconnect();
    gain.disconnect();
  }, { once: true });
  source.start(start);
  source.stop(start + 0.2);
  return source;
}

currentTime 以秒为单位，属于音频上下文的时钟。start/stop 和 AudioParam 自动化安排在这条时间线上，减少主线程计时器抖动对声音的影响。短淡入淡出也避免增益突然跳变造成明显咔哒声。

这不是精确外部设备同步方案；输出延迟、设备和上下文状态仍需考虑。应用应先确保用户允许播放，再调用，不应加载页面就自动发声。

自动播放限制可能让上下文暂停

浏览器可能把未经用户交互的 AudioContext 保持为 suspended。通常在明确点击后创建或 resume，并检查结果与 state，而不是不断重建上下文碰运气。

应用可复用一个合适的上下文管理多个声音，不需要每次点击都创建新 AudioContext。用户暂停时可以停止特定音源或按需求 suspend；完全结束不再使用时调用 close 释放相关系统资源。

suspend 是暂停时间线推进，close 是结束上下文，不能混用。关闭上下文也不等于 JavaScript 中所有节点和缓冲引用立刻消失，应用仍应释放不再使用的引用。

音源节点往往是一次性的

OscillatorNode、AudioBufferSourceNode 等源节点 start 后不能拿同一个实例反复重新 start。重复播放通常新建 source，但可以复用已经解码的 AudioBuffer 和合适的处理链。

stop 结束音源，disconnect 断开图连接，二者职责不同。把麦克风节点 disconnect 也不等于停止 MediaStreamTrack；若不再采集，仍需停止自己持有的轨道。

若用户在音源尚未开始或仍播放时取消，可以对返回的 source 调用合适的 stop，并处理结束清理；复杂播放器应集中管理所有活动源，避免漏掉后台仍在运行的节点。

分析数据与音频处理线程也要区分

AnalyserNode 可以提供频域或时域数据供可视化，Canvas 绘制可跟随页面动画帧，但音频节拍不应反过来依赖绘图帧率。

需要自定义低延迟处理时可评估 AudioWorklet。处理代码不在普通页面 DOM 环境中，应避免阻塞、分配大量临时对象或做网络等待，并使用明确的消息或参数接口与主线程协作。

音频验证应覆盖暂停恢复、设备切换、页面离开和多次播放，避免自动发声与过大音量。离线渲染可以验证信号处理逻辑，不能证明真实设备延迟和听感完全正确。
