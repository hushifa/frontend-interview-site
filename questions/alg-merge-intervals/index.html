如何合并时间区间？相邻区间算不算重叠？

以视频已看过的片段为例，按左闭右开区间合并：先按起点排序，再一个个和结果里最后一个区间比较。首尾正好相接的区间要不要合并，看业务：统计看了多少时要合并，判断预约冲突时不算冲突。

参考答案

简答

先把区间按起点从小到大排序，然后依次处理：当前区间的起点没超过结果里最后一个区间的终点，说明两个连上了，就把最后一个区间延长；否则当作一个新区间追加进去。

相邻算不算重叠，取决于区间怎么定义。我用左闭右开 [start, end)，包含起点、不包含终点。这样 [0, 10) 和 [10, 20) 首尾相接，但没有公共的时间点。下面的实现默认把相接的也合并，条件是 start <= last[1]；可以通过选项改成只合并真正重叠的，条件是 start < last[1]。

延长时要取 Math.max(last[1], end)，因为后一个区间可能整个被前一个包住了，比如 [0, 30) 里有个 [5, 10)。时间复杂度是 O(n log n)，主要花在排序上。要先复制再排序，不修改调用方传进来的数组。

换到预约场景，判断两个预约冲不冲突要用严格的 <，首尾相接的预约不算冲突。

实现

JavaScript
function mergeIntervals(intervals, { mergeTouching = true } = {}) {
  const sorted = intervals
    .map(([start, end]) => {
      if (!Number.isFinite(start) || !Number.isFinite(end) || start > end) {
        throw new RangeError(`非法区间：[${start}, ${end})`);
      }
      return [start, end];
    })
    // 空区间不覆盖任何时间，直接丢弃。
    .filter(([start, end]) => start < end)
    .sort((a, b) => a[0] - b[0]);

  const result = [];
  for (const [start, end] of sorted) {
    const last = result.at(-1);
    const overlaps = last && (mergeTouching ? start <= last[1] : start < last[1]);
    if (overlaps) last[1] = Math.max(last[1], end);
    else result.push([start, end]);
  }
  return result;
}

console.log(mergeIntervals([[20, 25], [0, 10], [8, 15]])); // [[0, 15], [20, 25]]
console.log(mergeIntervals([[0, 10], [10, 20]])); // [[0, 20]]
console.log(mergeIntervals([[0, 10], [10, 20]], { mergeTouching: false })); // [[0, 10], [10, 20]]
console.log(mergeIntervals([[0, 30], [5, 10]])); // [[0, 30]]

为什么要先排序？排好以后，能和当前区间重叠的，只可能是结果里的最后一个。不排序的话，每个区间都要和前面所有的比一遍。

第一个例子里，排序后是 [0,10)、[8,15)、[20,25)。8 没超过 10，所以前两个合并成 [0,15)；20 超过了 15，单独成一段。

最后一个例子说明了 Math.max 的作用。[5,10) 被 [0,30) 整个包住，如果直接用 end 去更新，终点就从 30 缩回 10，错了。

map 那一步不只是校验，还给每个区间复制了一个新数组。所以后面改 last[1] 时，改的是副本，不会动到调用方的数据。实测用 2000 组随机区间，检查“合并前后覆盖的时间点一样”和“结果里的区间互不相接”，都通过了。

相接的区间，什么时候合并

场景相接区间 [0,10) 和 [10,20)
统计观看进度应合并为 [0, 20)，用户连续看完了 20 秒
会议室预约不冲突，前一场结束时下一场开始

判断预约冲突甚至不用合并，排好序以后，看相邻两个有没有交叉就行：

JavaScript
function hasConflict(bookings) {
  const sorted = [...bookings].sort((a, b) => a[0] - b[0]);
  for (let i = 1; i < sorted.length; i++) {
    if (sorted[i][0] < sorted[i - 1][1]) return true;
  }
  return false;
}

console.log(hasConflict([[9, 10], [10, 11]])); // false
console.log(hasConflict([[9, 11], [10, 12]])); // true

9 点到 10 点、10 点到 11 点，前一场刚结束下一场才开始，所以不冲突。9 点到 11 点和 10 点到 12 点，中间有一个小时重叠，就冲突了。

如果问题变成“有冲突时最少取消几场预约，剩下的才互不冲突”，就不是合并了，而是贪心的区间调度：按结束时间排序，每次留下结束最早的那场，写法和正确性论证见《贪心算法怎样做跳跃游戏、无重叠区间？怎么判断贪心是对的？》。

常见追问

区间是带小数的秒数怎么办？

浮点数有误差，本来应该相接的两个区间，中间可能出现 10.000000001 这样的小缝。可以先换算成整数毫秒再合并。

新加一个区间，要整体重新算吗？

不用。结果已经是有序的，可以用二分查找找到插入的位置，只合并受影响的那几个相邻区间，见《二分查找怎样定位时间轴边界？为什么重复值和空数组容易写错？》。

观看进度的百分比怎么算？

合并以后把每个区间的长度加起来，再除以视频总时长。
