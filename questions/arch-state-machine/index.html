怎样避免加载、成功和失败状态互相矛盾？

多个独立布尔值容易形成无意义组合，例如同时 loading、success 和 error。先列出允许的业务状态，再定义各状态能够接收的事件和转换，可以减少互相矛盾的界面。

参考答案

多个独立布尔值可以表达“加载中”“成功”“失败”，却也允许出现 loading=true、success=true、error=true 这种业务上不存在的组合。状态机的第一步不是安装库，而是先列出真实状态和能触发变化的事件：例如 idle → loading → success，失败时进入 error，重试时再回到 loading。

简单流程用可辨识联合或枚举就够了：

TypeScript
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; message: string };

渲染代码可以根据 status 选择界面，而不是同时猜测多个布尔值。复杂流程还要考虑并行任务、超时、取消和重复事件；这时应画出每个事件在每个状态下的合法转换，并明确旧请求的结果是否仍有资格更新当前状态。

派生信息尽量从当前状态计算，避免把“是否显示重试按钮”“是否禁用提交”再复制成独立状态。状态机只能帮助表达转换，不能替代服务端权限、提交幂等、网络恢复和错误记录；这些边界仍应由相应层负责。
