跨窗口 postMessage 怎样避免把消息发给错误对象？

发消息时 targetOrigin 写具体的源，不用 '*'；收消息时先核对 event.origin 和 event.source，再检查消息格式。消息内容一律当不可信数据处理。

参考答案

简答

postMessage 是两个窗口之间传消息的接口，比如父页面和它嵌的 iframe。它本身允许跨源，所以发的一方和收的一方都要确认对方是谁。

发送时，第二个参数 targetOrigin 写准确的源，比如 'https://app.example.com'。如果目标窗口已经跳到了别的源，浏览器就不投递，数据不会落到错误的页面手里。写成 '*' 就等于放弃了这层保护，敏感数据绝不能这样发。

接收时，先完整比较 event.origin，不能用 includes 或 endsWith 做模糊匹配；再比较 event.source 是不是预期的那个窗口。

要注意，来源对了也不代表内容可信。还要校验消息的结构和取值范围，不能把内容交给 eval、innerHTML，或者直接拿来当跳转地址。

发送：写清楚发给谁

JavaScript
iframe.contentWindow.postMessage(
  { type: 'theme:set', version: 1, theme: 'dark' },
  'https://charts.example.com',
);

第二个参数为什么这么重要？因为 iframe.contentWindow 只是一个窗口的引用，窗口里现在装的是哪个页面，发送方并不知道。iframe 可能已经被导航到了别的网站。写了具体的源，浏览器会在投递前核对，对不上就丢弃。

接收：先看是谁发的，再看发了什么

JavaScript
const frame = document.querySelector('#chart-frame');
const CHART_ORIGIN = 'https://charts.example.com';

function onMessage(event) {
  if (event.origin !== CHART_ORIGIN) return;
  if (event.source !== frame.contentWindow) return;

  const data = event.data;
  if (data?.type !== 'chart:resize' || data.version !== 1) return;
  if (!Number.isInteger(data.height) || data.height < 100 || data.height > 1200) return;

  frame.style.height = `${data.height}px`;
}

window.addEventListener('message', onMessage);

这里检查了三层。origin 是发送方的源，只包含协议、主机和端口，不含路径。可是同一个源下可能开着好几个窗口，所以再用 source 确认是不是我们嵌的那个 iframe。最后检查消息本身，类型、版本、数字范围都要对。

还有一点是设计上的：这个接收方只允许对方调整高度，不提供“执行任意命令”这类接口。能做的事越少，被利用的空间就越小。

为什么不能用 includes 判断来源

下面这个例子可以直接在 Node 里运行，看看模糊匹配会放过什么：

JavaScript
const origin = 'https://example.com.attacker.test';
console.log(origin.includes('example.com')); // true
console.log(origin === 'https://example.com'); // false

example.com.attacker.test 是攻击者自己注册的域名，可它包含 example.com 这几个字，includes 就判断为通过了。所以来源必须用完整的字符串精确比较，或者和一个白名单集合比较。

还有哪些常见漏洞

收到消息就执行 location.href = data.url，攻击者可以把它变成开放重定向，或者传一个 javascript: 地址执行脚本。把 data.html 直接写进 innerHTML，就形成了 DOM 型 XSS。回复消息时用 '*'，用户数据可能发给了一个已经跳到别处的窗口。

需要长期双向通信时

如果两个窗口要频繁来回传消息，可以用 MessageChannel 建一条专用通道。握手时校验一次来源，之后通过 port 收发，不用每条消息都在全局的 message 事件上重新匹配。

JavaScript
const { port1, port2 } = new MessageChannel();
frame.contentWindow.postMessage({ type: 'connect' }, CHART_ORIGIN, [port2]);
port1.onmessage = (event) => console.log('来自图表', event.data);

port2 作为第三个参数被转交给 iframe，之后只有拿到它的那一方能往 port1 发消息。

常见追问

同源页面之间也要校验吗？

要。同源窗口之间确实可以直接访问彼此，但 message 事件可能来自任何持有你窗口引用的页面，不一定是同源的。

postMessage 能传哪些数据？

结构化克隆算法支持的类型都可以，比如普通对象、数组、Date、Map。函数和 DOM 节点不能传。
