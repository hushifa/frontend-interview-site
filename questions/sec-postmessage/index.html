跨窗口 postMessage 怎样避免把消息发给错误对象？

发送时 targetOrigin 写成具体的源，不用 '*'；接收时校验 event.origin 和 event.source，再校验消息结构，只执行白名单内的操作。消息内容一律当作不可信数据。

参考答案

简答

  • targetOrigin 写准确的源，例如 'https://app.example.com'。目标窗口已导航到别的源时，浏览器不会投递，防止数据泄露给错误的页面。
  • 用 '*' 等于放弃这层保护，敏感数据绝不能这样发送。
  • 接收方完整比较 event.origin，不能用 includes 或 endsWith 做模糊匹配；再比较 event.source 是否是预期的窗口。
  • 来源正确也要校验消息结构和取值范围，不把内容交给 eval、innerHTML 或用作跳转地址。

发送

JavaScript
iframe.contentWindow.postMessage(
  { type: 'theme:set', version: 1, theme: 'dark' },
  'https://charts.example.com',
);

接收

JavaScript
const frame = document.querySelector('#chart-frame');
const CHART_ORIGIN = 'https://charts.example.com';

function onMessage(event) {
  if (event.origin !== CHART_ORIGIN) return;
  if (event.source !== frame.contentWindow) return;

  const data = event.data;
  if (data?.type !== 'chart:resize' || data.version !== 1) return;
  if (!Number.isInteger(data.height) || data.height < 100 || data.height > 1200) return;

  frame.style.height = `${data.height}px`;
}

window.addEventListener('message', onMessage);
  • origin 只是源（协议、主机、端口），不含路径。
  • 同一源可能有多个窗口，source 用来确认是哪一个。
  • 消息只允许调整高度，不提供"执行任意命令"这类接口。

常见漏洞

  • 用 event.origin.includes('example.com') 判断，example.com.attacker.test 也能通过。
  • 收到消息就跳转 location.href = data.url，可被利用成开放重定向或 javascript: 执行。
  • 把 data.html 写进 innerHTML，形成 DOM 型 XSS。
  • 回复时用 '*'，把用户数据发给了已经导航到别处的窗口。

需要双向长期通信时

用 MessageChannel 建立专用通道：握手时校验一次来源，之后通过 port 收发，避免每条消息都在全局 message 事件上匹配。

JavaScript
const { port1, port2 } = new MessageChannel();
frame.contentWindow.postMessage({ type: 'connect' }, CHART_ORIGIN, [port2]);
port1.onmessage = (event) => console.log('来自图表', event.data);

常见追问

  • 同源页面之间也要校验吗？要。同源窗口可以直接访问彼此，但 message 事件可能来自任何持有窗口引用的页面。
  • 能传哪些数据？结构化克隆支持的类型，函数和 DOM 节点不能传。
