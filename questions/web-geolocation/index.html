Geolocation API 的权限和定位精度怎样处理？

navigator.geolocation 在 HTTPS 页面里经用户同意后返回经纬度和误差范围。要处理拒绝、定位失败和超时三种错误，按需设置精度和缓存参数，持续定位用完要 clearWatch。

参考答案

简答

做“附近的门店”时，用 navigator.geolocation 拿用户位置。它只在 HTTPS 等安全上下文里可用，第一次调用时浏览器会弹授权框。

有两个方法：getCurrentPosition 获取一次；watchPosition 持续获取，会返回一个 ID，不用时用 clearWatch 停掉。

结果里除了经纬度，还有 coords.accuracy，它是误差半径，单位是米，数字越大越不准。失败有三种错误码：1 用户拒绝，2 获取不到位置，3 超时。enableHighAccuracy: true 可能会启用 GPS，更准，但更慢、更耗电。

要注意时机和隐私。在用户点了“使用我的位置”之后再请求，用户拒绝了要给手动选城市的办法；上传时只传业务需要的精度。

封装一个定位函数

下面把回调式的 API 包成 Promise，并把错误码翻译成用户能看懂的话。

JavaScript
function locate({ timeout = 10000 } = {}) {
  return new Promise((resolve, reject) => {
    if (!('geolocation' in navigator)) {
      reject(new Error('当前浏览器不支持定位'));
      return;
    }
    navigator.geolocation.getCurrentPosition(
      ({ coords }) => resolve({ lat: coords.latitude, lng: coords.longitude, accuracy: coords.accuracy }),
      (error) => {
        const messages = { 1: '你拒绝了定位权限', 2: '暂时无法获取位置', 3: '定位超时' };
        reject(new Error(messages[error.code] ?? error.message));
      },
      { enableHighAccuracy: false, timeout, maximumAge: 60000 },
    );
  });
}

第三个参数是定位选项。timeout 是最多等多久。maximumAge: 60000 表示一分钟内的缓存位置也可以用，这样返回更快，适合“附近门店”这种不需要很精确的场景。

为什么要把 accuracy 也返回出去？因为定位可能误差很大。界面上可以把它展示出来，或者据此判断这个位置能不能用，比如误差上千米就提示用户手动选择。

为什么室内定位不准

没有 GPS 信号时，浏览器会根据 Wi-Fi 和 IP 来估算位置，误差可能是几百米到几公里。这时 accuracy 会很大，所以一定要看它。

隐私方面要注意什么

精确位置是敏感数据。只上传业务需要的精度，比如只需要城市，就把坐标四舍五入到城市级别再传。

用户拒绝以后，浏览器不会再弹窗了，页面要提供手动选择城市或输入地址的方式。所以也不要页面一打开就请求定位，用户不知道为什么，更容易拒绝。

在 iframe 里使用，还要父页面用 allow="geolocation" 授权。

常见追问

IP 定位和 Geolocation 有什么区别？

IP 定位在服务端完成，根据请求的 IP 地址查，不需要用户授权，但一般只能到城市级别。Geolocation 在浏览器里，要用户授权，有 GPS 或 Wi-Fi 时能精确得多。

watchPosition 用完不停会怎样？

会一直定位，持续耗电。离开页面或不再需要时，要用它返回的 ID 调用 clearWatch 停掉。
