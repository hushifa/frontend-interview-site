为什么 Vue 提倡 props 单向数据流？

props 从父组件流向子组件，子组件不能直接修改 prop，要修改就 emit 事件交给父组件处理。这样数据只有一个所有者，出问题时能追溯来源。Vue 3.5 起解构 defineProps 的结果仍保持响应式。

参考答案

简答

  • 父组件更新时，子组件的 props 会被刷新为最新值；子组件直接给 prop 赋值，Vue 会在开发环境警告，而且下次父组件更新就会被覆盖。
  • 子组件想修改数据，就 emit 一个事件，由拥有数据的父组件决定是否修改。
  • 只需要 prop 作为初始值、之后在子组件内独立编辑：复制到本地 ref。
  • 需要基于 prop 转换展示：用 computed。
  • prop 是对象或数组时，子组件修改其内部属性不会报警告，但会直接改到父组件的数据，应避免。

两种合理的"修改"

vue
<!-- 作为初始值，之后独立编辑 -->
<script setup>
import { ref } from 'vue';
const props = defineProps({ initialTitle: String });
const title = ref(props.initialTitle);
</script>
vue
<!-- 基于 prop 派生 -->
<script setup>
import { computed } from 'vue';
const props = defineProps({ price: Number });
const display = computed(() => `¥${props.price.toFixed(2)}`);
</script>

第一种写法中，父组件之后修改 initialTitle 不会影响本地 title。命名带上 initial 前缀能表达这个意图。

通过事件修改

vue
<!-- Counter.vue -->
<script setup>
defineProps({ count: { type: Number, required: true } });
const emit = defineEmits(['update:count']);
</script>

<template>
  <button @click="emit('update:count', count + 1)">{{ count }}</button>
</template>

父组件写 <Counter v-model:count="n" />，或者显式监听 @update:count。v-model 就是这个约定的简写，见《组件 v-model 的本质是什么？》。

Vue 3.5 的响应式 props 解构

vue
<script setup>
import { watch } from 'vue';

const { size = 'medium', count } = defineProps(['size', 'count']);

watch(() => count, (n) => console.log(n)); // 侦听解构的 prop 要用 getter
</script>

Vue 3.5 起，编译器把解构出的变量自动改写为 props.xxx，因此保持响应式，还可以直接用 JS 默认值语法。不过把 count 直接传给 watch(count) 或普通函数时，传入的只是当前值；要用 getter 包一层。

prop 校验

JavaScript
defineProps({
  status: {
    type: String,
    required: true,
    validator: (v) => ['draft', 'published'].includes(v),
  },
});

校验只在开发环境给出警告，不阻止渲染。使用 TypeScript 时可以写 defineProps<{ status: 'draft' | 'published' }>()。

常见追问

  • 布尔 prop 有什么特殊规则？声明为 Boolean 的 prop，写 <Comp disabled /> 等于 true，不传等于 false。
  • 没声明的属性去哪了？会作为 fallthrough attributes 加到组件根元素上，可用 inheritAttrs: false 关闭并通过 $attrs 手动绑定。
