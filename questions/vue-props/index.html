为什么 Vue 提倡 props 单向数据流？

props 只能从父组件流向子组件，子组件想改，就发事件让父组件改。这样每份数据只有一个主人，出了问题能顺着找到是谁改的。

参考答案

简答

单向数据流的意思是，数据从父组件通过 props 传给子组件，子组件只读不改。子组件想改，就 emit 一个事件，由拥有这份数据的父组件决定改不改。

这样做是为了让每份数据只有一个主人。如果任何子组件都能直接改，数据出错时就很难查是谁改的。而且直接给 prop 赋值，Vue 会在开发环境警告，下次父组件更新时这个值还会被覆盖回去。

实际开发中有两种合理的“修改”。只把 prop 当初始值、之后自己编辑，就复制到本地 ref；要根据 prop 换个格式显示，就用 computed。

有一个坑要注意。prop 是对象或数组时，子组件改它的内部属性不会触发警告，但其实是直接改了父组件的数据，这种写法应该避免。

子组件需要“改” prop 时怎么办

第一种情况，prop 只是初始值，之后子组件自己编辑：

vue
<!-- 作为初始值，之后独立编辑 -->
<script setup>
import { ref } from 'vue';
const props = defineProps({ initialTitle: String });
const title = ref(props.initialTitle);
</script>

这样复制以后，父组件再改 initialTitle，本地的 title 不会跟着变。这正是想要的效果，所以命名时加个 initial 前缀，把这个意图说清楚。

第二种情况，基于 prop 派生出一个展示用的值：

vue
<!-- 基于 prop 派生 -->
<script setup>
import { computed } from 'vue';
const props = defineProps({ price: Number });
const display = computed(() => `¥${props.price.toFixed(2)}`);
</script>

display 跟着 price 自动更新，子组件没有改动任何 prop。

通过事件让父组件修改

如果子组件确实需要改父组件的数据，就发事件：

vue
<!-- Counter.vue -->
<script setup>
defineProps({ count: { type: Number, required: true } });
const emit = defineEmits(['update:count']);
</script>

<template>
  <button @click="emit('update:count', count + 1)">{{ count }}</button>
</template>

父组件写 <Counter v-model:count="n" />，或者显式监听 @update:count。子组件只是说“我想把它改成这个值”，真正改 n 的是父组件。v-model 就是这个约定的简写，见《组件 v-model 的本质是什么？》。

Vue 3.5 起解构 props 还是响应式的

vue
<script setup>
import { watch } from 'vue';

const { size = 'medium', count } = defineProps(['size', 'count']);

watch(() => count, (n) => console.log(n)); // 侦听解构的 prop 要用 getter
</script>

按普通 JavaScript 的理解，解构出来的 count 是一个普通变量，应该不会再变。可是 Vue 3.5 起，编译器会把模板和代码里用到的 count 自动改写成 props.count，所以它仍然是响应式的，还能直接用 JS 的默认值语法。

不过这个改写有边界。把 count 直接传给 watch(count) 或者普通函数时，传进去的只是当时的值，所以要像上面那样用 getter 包一层。

prop 校验

JavaScript
defineProps({
  status: {
    type: String,
    required: true,
    validator: (v) => ['draft', 'published'].includes(v),
  },
});

校验失败只会在开发环境给出警告，不会阻止渲染。用 TypeScript 时可以直接写 defineProps<{ status: 'draft' | 'published' }>()。

常见追问

布尔类型的 prop 有什么特殊规则？

声明为 Boolean 的 prop，写 <Comp disabled /> 就等于传了 true，完全不写等于 false。

传了但没声明成 prop 的属性去哪了？

它们叫透传属性（fallthrough attributes），会自动加到组件的根元素上。可以用 inheritAttrs: false 关掉，再通过 $attrs 手动绑定到想要的元素上。
