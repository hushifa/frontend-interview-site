映射类型与 Partial、Pick、Omit 如何用于接口建模？

映射类型根据键集合生成新的属性类型，工具类型封装了常见的选取、排除和修饰符变换。它们通常只改变顶层静态结构，不会执行字段过滤、默认值填充或深度冻结。

参考答案

简答

  • 映射类型用 [K in keyof T] 遍历键并变换属性，可以加减 readonly 和 ? 修饰符。
  • Partial、Required、Readonly、Pick、Omit、Record 都是基于映射类型的内置工具。
  • Omit 不检查要删除的键是否存在，联合类型上使用会丢失分支差异。
  • 用 as 子句可以在映射时重命名或过滤键。

一个 User 类型可能包含 ID、姓名、个人资料和内部字段。更新接口、展示组件和公开响应各需要不同部分，如果每个地方复制一份完整字段列表，很容易改了一处漏掉另一处。

映射类型可以从已有键和属性类型推导新结构。它表达的是“这些字段在另一个契约里是什么样”，不负责修改真实对象或执行数据转换。

从遍历键到生成属性

TypeScript
type BooleanFlags<T> = {
  [Key in keyof T]: boolean;
};

type Features = { search: () => void; exportFile: () => void };
const enabled: BooleanFlags<Features> = {
  search: true,
  exportFile: false,
};
console.log(enabled.search); // true

keyof T 提供键集合，映射逐个生成同名属性，并把属性类型统一改为 boolean。这并没有调用 Features 中的函数，只是在类型层建立一组对应开关。

如果写 T[Key]，则可以沿用原属性类型，再改变可选、只读等修饰符。内置的很多工具类型都基于类似思路。

常见工具怎样选择

工具类型层的作用不会自动完成的工作
Partial顶层属性变为可选不会让深层字段全部可选
Required去掉顶层可选修饰不会给缺失字段填默认值
Readonly增加对应只读约束不会执行运行时深冻结
Pick<T, K>选择指定字段不会从对象里复制这些字段
Omit<T, K>排除指定字段不会删除对象上的真实字段
Record<K, V>用键集合 K 建立值类型为 V 的结构不会在运行时创建这些键

Pick 的键需要来自目标类型，能帮助发现选取字段的拼写错误。Omit 的键约束更宽，省略一个本来不存在的名字未必报错，因此它不是万能的字段名检查器。

更新接口先限制能改哪些字段

TypeScript
type User = {
  readonly id: string;
  name: string;
  profile: { city: string; postalCode: string };
  password: string;
};

type UserPatch = Partial<Pick<User, 'name' | 'profile'>>;
const rename: UserPatch = { name: 'Lin' };

// @ts-expect-error 更新契约没有开放 id
const changeId: UserPatch = { id: 'user_2' };

// @ts-expect-error Partial 只作用于顶层，profile 一旦提供仍需完整结构
const incompleteProfile: UserPatch = { profile: { city: '上海' } };

直接 Partial 会把 ID、密码等字段也放进更新契约，可能偏离真实权限。先 Pick 出允许更新的部分，再决定是否可选，通常更贴近接口意图。

如果业务允许只更新 profile.city，应明确为 profile 定义部分更新结构，并说明服务器采用替换还是合并语义。类型里写了深层可选，并不自动实现递归合并算法。

Partial 还允许空对象。如果业务要求至少更新一个字段，应该增加类型建模或运行时检查，不能把“字段都可选”误当成“至少有一个字段”。

Omit 不是运行时脱敏

TypeScript
const full: User = {
  id: 'user_1',
  name: 'Lin',
  profile: { city: '上海', postalCode: '200000' },
  password: '示例占位值',
};

const visibleType: Omit<User, 'password'> = full;
console.log(Object.hasOwn(visibleType, 'password')); // true

function toPublicUser(user: User): Pick<User, 'id' | 'name'> {
  return { id: user.id, name: user.name };
}
console.log(Object.keys(toPublicUser(full)).join(',')); // id,name

第一步只是让变量的静态类型不再提供 password 这个成员，真实对象仍是 full。直接 JSON.stringify 这个引用，仍可能包含敏感字段。

第二步真正创建了只包含白名单字段的新对象，才完成实际数据选择。对于公开响应、日志或持久化数据，应把运行时映射与类型契约共同设计，而不是靠一个 Omit 或断言完成过滤。

修饰符可以明确增加或移除

TypeScript
type MutableRequired<T> = {
  -readonly [Key in keyof T]-?: T[Key];
};

type Draft = { readonly title?: string };
const completed: MutableRequired<Draft> = { title: '初稿' };
completed.title = '定稿';
console.log(completed.title); // 定稿

-readonly 移除只读修饰，-? 移除可选修饰。它们改变的是所生成类型的约束，不会给某个已冻结对象解除运行时冻结，也不会把缺失属性补到原对象上。

可选属性是否允许显式写入 undefined，还受 exactOptionalPropertyTypes 等选项影响。解释工具类型结果时，应把原属性形式与编译配置一起考虑。

键重映射可以生成另一套命名接口

TypeScript
type Getters<T> = {
  [Key in keyof T as Key extends string ? `get${Capitalize<Key>}` : never]: () => T[Key];
};

type UserGetters = Getters<Pick<User, 'id' | 'name'>>;
const access: UserGetters = {
  getId: () => full.id,
  getName: () => full.name,
};
console.log(access.getName()); // Lin

as 子句决定输出键，never 可以排除不适用的键。这里排除非字符串键，再把 id、name 映射成 getId、getName。真正的方法仍由对象实现，类型系统没有替你生成函数体。

当 T 是联合类型时，还要留意工具是否按成员分发。比如普通 Omit 可能只围绕联合的公共键处理，不能默认保留每个分支所有特有字段；确实需要逐分支变换时，应显式设计分布式条件类型，并验证结果。

工具类型的目的应该是让契约同步变化，而不是把所有接口都从一个巨大基础类型层层变换出来。若公开模型与内部模型职责不同，适当独立定义或显式映射，往往比复杂的 Pick、Omit、Partial 叠加更清楚。
