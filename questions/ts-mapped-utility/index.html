映射类型与 Partial、Pick、Omit 如何用于接口建模？

映射类型就是遍历一个类型的所有键，生成一个新类型；Partial、Pick、Omit 这些内置工具都是这么写出来的。它们只改顶层、只改类型，Omit 不会真的删掉对象上的字段。

参考答案

简答

映射类型可以理解成类型层面的 for 循环：{ [K in keyof T]: X } 把 T 的每个键都拿出来，生成一个新属性，T[K] 是原来那个属性的类型。还能顺便改修饰符，-readonly、-? 去掉只读和可选，+readonly、+? 加上（加号可省略），用 as 子句还能改名或过滤键。

Partial、Required、Readonly、Pick、Omit、Record 都是这样写出来的。建模时常见的用法是先 Pick 出允许修改的字段，再套 Partial，得到一个更新接口的参数类型。

要注意三点。第一，Partial、Readonly 这些只改顶层，嵌套对象不受影响。第二，Pick 要求键必须存在，Omit 却接受任意字符串，拼错了不报错；用在联合类型上还会丢掉分支差异。第三，它们只改类型，Omit<User, 'password'> 类型的变量运行时可能还带着 password，要真去掉字段必须构造新对象。

内置工具是怎么写出来的

把几个内置工具自己写一遍，就能看清映射类型的用法：

TypeScript
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyRequired<T> = { [K in keyof T]-?: T[K] };
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };
type MyPick<T, K extends keyof T> = { [P in K]: T[P] };
type MyRecord<K extends PropertyKey, V> = { [P in K]: V };
type MyOmit<T, K extends PropertyKey> = Pick<T, Exclude<keyof T, K>>;

MyPartial 遍历所有键，每个属性加上 ?。MyRequired 用 -? 把问号去掉。MyPick 只遍历你给的那几个键。MyOmit 稍微绕一点：先用 Exclude 从所有键里去掉不要的，再 Pick 剩下的。注意它的 K 约束是 PropertyKey，不是 keyof T，这就是 Omit 拼错键也不报错的原因。

怎样设计一个更新接口的参数

TypeScript
type User = {
  readonly id: string;
  name: string;
  profile: { city: string; postalCode: string };
  password: string;
};

type UserPatch = Partial<Pick<User, 'name' | 'profile'>>;

const rename: UserPatch = { name: 'Lin' };
// @ts-expect-error 更新契约没有开放 id
const changeId: UserPatch = { id: 'user_2' };
// @ts-expect-error Partial 只作用于顶层，profile 提供时仍需完整
const incompleteProfile: UserPatch = { profile: { city: '上海' } };

先 Pick 再 Partial，意思是“只能改 name 和 profile，而且可以只改其中一个”。如果直接写 Partial<User>，id 和 password 也会被放进更新参数里，这通常不是你想要的。

第三个例子可能出乎意料：UserPatch 都是可选的了，为什么 profile 只写 city 还报错？因为 Partial 只把顶层的 profile 变成了可选，profile 里面的 city、postalCode 还是必需的。需要深层可选时，要自己写一个递归的 DeepPartial。

为什么 Omit 不能用来脱敏

TypeScript
declare const full: User;
const visible: Omit<User, 'password'> = full; // 运行时仍是 full，带着 password

function toPublicUser(user: User): Pick<User, 'id' | 'name'> {
  return { id: user.id, name: user.name }; // 白名单构造新对象
}

visible 的类型里没有 password，可它和 full 是同一个对象，password 一直都在。类型只是让你“看不见”它，把 visible 发给接口或写进日志，密码照样出去。所以真要去掉敏感字段，必须像 toPublicUser 这样，按白名单把需要的字段复制到一个新对象里。

Omit 用在联合类型上会怎样

TypeScript
type Shape = { kind: 'circle'; radius: number } | { kind: 'square'; side: number };
type NoKind = Omit<Shape, 'kind'>; // {}，只保留了公共键

type DistributiveOmit<T, K extends PropertyKey> = T extends unknown ? Omit<T, K> : never;
type Fixed = DistributiveOmit<Shape, 'kind'>; // { radius: number } | { side: number }

本来只想去掉 kind，结果得到了空对象 {}。原因是 keyof 一个联合，只能拿到各分支共有的键，这里只有 kind，去掉以后就什么都不剩了。改法是借助分布式条件类型，让 Omit 对每个分支分别执行，再合起来。

用 as 改名或过滤键

TypeScript
type Getters<T> = {
  [K in keyof T as K extends string ? `get${Capitalize<K>}` : never]: () => T[K];
};
type UserGetters = Getters<Pick<User, 'id' | 'name'>>;
// { readonly getId: () => string; getName: () => string }，同态映射保留 id 的 readonly

type OnlyStrings<T> = { [K in keyof T as T[K] extends string ? K : never]: T[K] };

as 后面写的是新的键名。Getters 把 id 变成 getId，值变成返回原类型的函数。id 原来是 readonly，结果里 getId 也是 readonly，因为这种基于 keyof T 的映射（叫同态映射）会保留原来的修饰符。as 的结果是 never 时，这个键就被删掉，OnlyStrings 就是这样只留下值为字符串的属性。

常见追问

Record<string, T> 和索引签名有什么不同？

基本是一样的。但 Record<'a' | 'b', T> 就不同了，它要求 a 和 b 两个键都必须存在。

为什么 Object.keys(obj) 返回 string[]，而不是 (keyof T)[]？

因为 TypeScript 是结构类型，一个对象实际上可以带着类型里没声明的额外键。如果返回 (keyof T)[]，就等于承诺没有别的键，这个承诺不一定成立。
