怎样验证一个页面可以只用键盘操作？

拔掉鼠标，只用键盘把所有流程走一遍，检查每个功能都能用键盘完成、没有焦点陷阱、焦点顺序合理、焦点始终可见且不被遮挡；对应 WCAG 2.1.1、2.1.2、2.4.3、2.4.7 和 2.2 新增的 2.4.11。

参考答案

简答

最直接的验证方法，就是不用鼠标，只用键盘把页面上所有流程走一遍。要检查的事情，WCAG 里有五条对应的标准。

第一条是 2.1.1 键盘（A 级）：所有功能都能用键盘完成，悬停才出现的菜单、拖拽排序也要有键盘方式。第二条是 2.1.2 无键盘陷阱（A 级）：焦点进了某个组件，还得能用键盘出来。模态对话框限制焦点是允许的，因为能用 Esc 或按钮关掉。

第三条是 2.4.3 焦点顺序（A 级）：Tab 的顺序和阅读顺序一致，不要用正数 tabindex 打乱顺序。第四条是 2.4.7 焦点可见（AA 级）：当前焦点要有明显的指示，不要只写一句 outline: none。

第五条是 WCAG 2.2 新增的 2.4.11 焦点不被遮挡（AA 级）：获得焦点的元素，不能被固定头部、底栏或浮层完全挡住。

具体怎么走一遍

按下面的顺序检查。

  1. 从地址栏开始按 Tab，确认第一个焦点是“跳到主内容”链接或页面主导航。
  2. 依次 Tab 经过所有交互元素，焦点顺序和视觉顺序一致，没有跳到隐藏的元素上。
  3. 每个控件用它该用的键操作：按钮用 Enter 和空格，链接用 Enter，复选框用空格，单选组和菜单用方向键。
  4. 打开弹窗、下拉菜单，确认焦点进去了，Esc 能关闭，关闭后焦点回到触发的地方。
  5. 页面滚动时，被聚焦的元素不会藏在固定头部下面。
  6. 提交表单出错时，焦点移到第一个错误或错误汇总上。

焦点样式怎么写

下面两段 CSS 分别解决“看得见”和“不被挡住”。

CSS
:focus-visible {
  outline: 2px solid currentColor;
  outline-offset: 2px;
}

html {
  scroll-padding-block-start: 80px;
}

很多人去掉焦点环，是嫌鼠标点按钮时出现一个框不好看。:focus-visible 正好解决这个矛盾：浏览器只在需要时显示它，键盘操作时显示，鼠标点击按钮时一般不显示。

scroll-padding-block-start 是给固定头部留位置的。页面滚动到焦点元素时，顶部会预留 80px，元素就不会被头部盖住，满足 2.4.11。这个值按实际头部高度设置。

复合组件里怎么移动

单选组、标签页、菜单、树这类组件，里面可能有很多项。如果每一项都占一个 Tab 位置，用户要按很多次 Tab 才能走出去。

所以它们的规则是：Tab 只进入和离开组件一次，组件内部用方向键移动。实现方式叫“漫游 tabindex”，当前项设 tabindex="0"，其余项设 tabindex="-1"，按方向键时把这两个值换过来。

键盘之外还有什么要测

能用键盘操作只是一部分。WCAG 2.2 还新增了 2.5.7 拖拽动作（AA 级）：用拖拽完成的功能，必须有单指针的替代方式，比如排序列表提供“上移”“下移”按钮。这一条帮的是没法精确拖动的鼠标和触屏用户，和键盘要求是两回事。

常见追问

tabindex 的几个值怎么用？

0 把元素加进自然的 Tab 顺序；-1 允许用脚本聚焦，但不进 Tab 顺序；大于 0 的值会打乱顺序，不要用。
