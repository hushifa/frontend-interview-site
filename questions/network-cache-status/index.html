Cache-Status 响应头能帮助诊断哪些缓存问题？

RFC 9211 定义的 Cache-Status 让每一层缓存在响应上写一条记录，说明是否命中、为什么转发到上游、是否存储。比只看 Age 或厂商私有头（如 X-Cache）更标准，适合排查 CDN 多层缓存。

参考答案

简答

  • 每个缓存在响应上追加一个成员，顺序从离源站最近的缓存到离用户最近的缓存。
  • hit 表示直接用缓存应答；fwd 表示转发给了上游，并给出原因，如 uri-miss（没有副本）、stale（副本过期）、vary-miss（Vary 不匹配）、bypass（配置绕过）。
  • fwd-status 是上游返回的状态码，ttl 是剩余新鲜时间，stored 表示这次响应是否被存下，key 可以暴露缓存键。
  • 它是诊断信息，不保证每层都写；Cache-Control 决定缓存行为，Age 只说明副本在缓存里待了多久。

读一个例子

http
Cache-Status: OriginShield; fwd=stale; fwd-status=304; stored, EdgePOP; hit; ttl=120
  • OriginShield 发现副本过期，向源站验证，源站回 304，副本被更新并存储。
  • EdgePOP 直接命中，还有 120 秒新鲜期。

用它排查的问题

现象关注的参数
发版后用户仍拿到旧内容哪一层是 hit、ttl 还剩多少
命中率低fwd=uri-miss 是否频繁，key 是否包含了不该有的查询参数或头
不同语言内容串了fwd=vary-miss 是否出现，Vary 是否设置
本应缓存却没缓存stored 缺失，结合 detail 找原因

使用限制

  • 需要 CDN 或代理实现了该头，很多厂商仍只提供私有头。
  • 生产环境暴露 key、detail 可能泄露内部结构，可以只对带调试标记的请求返回，或在边缘剥离。
  • 浏览器缓存不会写 Cache-Status，浏览器是否命中缓存要看 DevTools 的 Size 列（memory cache、disk cache）。

常见追问

  • 和 Age 有什么区别？Age 说明副本存在多久，不说明哪一层命中、为什么转发。
  • 和 Server-Timing 有什么区别？Server-Timing 报告服务端耗时，可被 Resource Timing 读取；Cache-Status 报告缓存决策。
