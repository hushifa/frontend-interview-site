视频播放进度怎样用二分查找定位当前章节？

章节按开始时间排好序，播放到第 t 秒时，用 upperBound 找第一个开始时间大于 t 的章节，再减 1 就是当前章节。结果为 -1 说明还没进第一章，章节列表为空时也自然得到 -1；两个章节开始时间相同时，减 1 落在靠后的那一章，前一章长度为 0、不会被选中。

参考答案

简答

视频有几个章节，开始时间分别是 0、10、20、40 秒，进度条拖到第 25 秒，要高亮“第 3 章”。章节可能有几百个，播放时每秒都要算，所以不逐个比较，而是在开始时间数组上做二分。

当前章节是“开始时间小于等于 t 的最后一个章节”。换个说法，先找第一个开始时间大于 t 的章节，也就是 upperBound(starts, t)，它前面那一个就是答案，所以结果是 upperBound(starts, t) - 1。

几个业务边界都能直接从这个式子读出来。正好播到某章开头，这一章算进来；t 小于第一章的开始时间，或者章节列表是空的，结果是 -1，界面上就不高亮任何章节；t 超过最后一章的开始时间，结果是最后一章。

要注意数据里可能有两个章节开始时间相同，比如编辑器里误加了一个空章节。这时减 1 落在靠后的那一章，前一章长度为 0，永远不会被高亮。二分边界的通用写法和左闭右开模板见《二分查找有哪些常见变体？怎样找边界、在旋转数组里查找？》。

定位当前章节

JavaScript
function upperBound(values, target) {
  let left = 0;
  let right = values.length;
  while (left < right) {
    const middle = left + Math.floor((right - left) / 2);
    if (values[middle] <= target) left = middle + 1;
    else right = middle;
  }
  return left;
}

function currentChapter(starts, seconds) {
  return upperBound(starts, seconds) - 1;
}

const starts = [0, 10, 20, 40]; // 各章节开始的秒数
console.log(currentChapter(starts, 25)); // 2，第 20 秒开始的章节
console.log(currentChapter(starts, 20)); // 2，正好在章节开头
console.log(currentChapter(starts, 99)); // 3，最后一章
console.log(currentChapter([5, 10], 3)); // -1，还没进第一章
console.log(currentChapter([], 3)); // -1，没有章节

upperBound 返回第一个大于目标的位置，等于目标的元素被归到左边，所以“正好在第 20 秒”也会越过下标 2，停在下标 3，减 1 后仍然是第 20 秒开始的那一章。如果换成找第一个大于等于目标的位置，会停在下标 2，减 1 变成 1，正好在开头时就会显示成上一章。

为什么空数组不用特殊判断？right 一开始就是 0，不进循环，返回 0，减 1 得到 -1，和“还没进第一章”是同一个结果。界面只要处理 -1 一种情况。

开始时间重复时会怎样

JavaScript
const withEmpty = [0, 10, 10, 30]; // 下标 1 是一个误加的空章节
console.log(currentChapter(withEmpty, 10)); // 2
console.log(currentChapter(withEmpty, 15)); // 2

两个章节都从第 10 秒开始，upperBound 会越过所有等于 10 的元素，所以减 1 总是落在靠后的下标 2。下标 1 那一章的时长是 0，任何进度都不会选中它。

这通常符合预期，但要和产品确认。如果希望显示的是靠前那一章，或者希望在保存时就提示“章节开始时间重复”，应该在录入章节时校验，而不是在播放时改二分的写法。

开始时间没排序的话，二分的结果没有意义。章节数据从接口来时，最好在拿到后先按开始时间排序一次，之后每次定位都是 O(log n)。

常见追问

拖动进度条时每帧都算一次，会不会太慢？

不会。O(log n) 意味着一千个章节最多比较 10 次左右。正常播放时，还可以先检查 t 是否仍在当前章节范围内，在的话直接复用上次的结果，只有跳出范围才重新二分。

章节是对象数组怎么办？

把比较换成读字段，比如 chapters[middle].start <= target，其他逻辑不变。

章节要频繁插入怎么办？

有序数组每插一个，后面的元素都要往后挪，代价是 O(n)。章节数量通常只有几十个，直接插入再排序就够了。区间合并里的应用见《如何合并时间区间？相邻区间算不算重叠？》。
