二分查找怎样定位时间轴边界？为什么重复值和空数组容易写错？

以视频章节定位为例，用左闭右开区间写 lowerBound 和 upperBound：lowerBound 找第一个大于等于目标的位置，upperBound 找第一个大于目标的位置。两个组合起来，能找出当前在哪一章、统计重复值有几个，空数组和找不到的情况也自然处理好了。

参考答案

简答

我会写两个函数。lowerBound 返回第一个 >= target 的下标，upperBound 返回第一个 > target 的下标。目标比所有元素都大，就返回数组长度；空数组返回 0。

搜索区间用左闭右开 [left, right)，right 一开始是 values.length，循环条件是 left < right。这样写，空数组和“插在最后面”这两种情况都不用单独处理。

有重复值时，lowerBound 正好落在第一个重复值上，upperBound - lowerBound 就是重复了几个。放到视频章节上，章节按开始时间排好序，当前播放到第 t 秒，所在章节就是 upperBound(starts, t) - 1，结果是 -1 说明还没进第一章。

中点要写成 left + Math.floor((right - left) / 2)。(left + right) >> 1 看起来更短，但 left + right 超过 2³¹ − 1 时，位运算会先转成 32 位整数，结果就错了。

lowerBound

JavaScript
function lowerBound(values, target) {
  let left = 0;
  let right = values.length;
  while (left < right) {
    const middle = left + Math.floor((right - left) / 2);
    if (values[middle] < target) left = middle + 1;
    else right = middle;
  }
  return left;
}

console.log(lowerBound([10, 20, 20, 40], 20)); // 1
console.log(lowerBound([10, 20, 20, 40], 25)); // 3
console.log(lowerBound([10, 20, 20, 40], 50)); // 4
console.log(lowerBound([], 20)); // 0

找 20，有两个 20，返回的是第一个的下标 1。找 25，没有，返回的是它应该插入的位置 3。找 50，比所有都大，返回长度 4。空数组根本不进循环，直接返回 0。

怎么确信它是对的？抓住一句话：left 左边的元素都 < target，right 和它右边的元素都 >= target。这叫循环不变量，也就是每一轮循环前后都成立的条件。

一开始 left 左边什么都没有，right 右边也什么都没有，条件自然成立。每一轮，如果 values[middle] < target，说明 middle 也属于左边，left 移到 middle + 1；否则 middle 属于右边，right 移到 middle。两种情况条件都还成立，而且区间至少缩小一格。等到 left === right，它就是左右两边的分界点，也就是第一个 >= target 的位置。

upperBound 和章节定位

JavaScript
function upperBound(values, target) {
  let left = 0;
  let right = values.length;
  while (left < right) {
    const middle = left + Math.floor((right - left) / 2);
    if (values[middle] <= target) left = middle + 1;
    else right = middle;
  }
  return left;
}

const starts = [0, 10, 20, 40]; // 各章节开始的秒数
console.log(upperBound(starts, 25) - 1); // 2，第 20 秒开始的章节
console.log(upperBound(starts, 20) - 1); // 2，正好在章节开头
const values = [10, 20, 20, 40];
console.log(upperBound(values, 20) - lowerBound(values, 20)); // 2

和 lowerBound 比，只差了一个符号：< 换成了 <=。等于目标的元素也被归到左边了，所以停下来的位置是第一个大于目标的。

为什么章节定位用 upperBound 再减 1？播放到第 25 秒，第一个开始时间大于 25 的章节是下标 3（第 40 秒），往前一个就是当前章节，下标 2。正好播到第 20 秒时，用 upperBound 能把“刚好开始”的那一章算进来，结果还是 2。如果换成 lowerBound，会找到下标 2 再减 1 变成 1，就错了。

实测用 2000 组随机的有序数组，和线性查找的结果对比，全部一致。

容易写错的地方

写法问题
right = values.length - 1 配合 left < right永远不会返回 values.length，目标比所有元素都大时结果错误
找到相等元素就直接返回有重复值时返回的位置不确定
left = middle（左闭右开写法里）区间可能不再缩小，陷入死循环
对未排序的数组使用结果没有意义，二分的前提是有序

常见追问

时间复杂度是多少？

O(log n)。一百万个元素，最多比较 20 次左右。

数组里是对象怎么办？

把比较换成一个函数传进来，比如 (item) => item.start < target，其他逻辑不变。

数组要频繁插入怎么办？

有序数组每插一个，后面的元素都要往后挪，代价是 O(n)。插入很频繁的话，考虑平衡树或者跳表。区间合并里的应用见《如何合并时间区间？相邻区间算不算重叠？》。
