页面导航的关键阶段怎样用 Navigation Timing 分析？

PerformanceNavigationTiming 记录一次文档导航从重定向、DNS、连接、请求响应到 DOM 解析和 load 的时间点；按相邻时间点相减得到各阶段耗时，TTFB 是 responseStart 减 startTime。

参考答案

简答

  • 用 performance.getEntriesByType('navigation')[0] 拿到当前文档导航的记录。时间值相对于 performance.timeOrigin（startTime 为 0），单位是毫秒，不是 Unix 时间戳。
  • 各阶段耗时由相邻时间点相减：DNS 是 domainLookupEnd - domainLookupStart，TCP 是 secureConnectionStart - connectStart（HTTPS 时），TLS 是 connectEnd - secureConnectionStart。
  • TTFB（首字节时间）是 responseStart，包含重定向、DNS、连接和服务端处理时间。
  • loadEventEnd 在 load 回调执行完才有值，在 load 事件里读取会得到 0，应延后读取或用 PerformanceObserver。
  • type 字段区分 navigate、reload、back_forward，从 bfcache 恢复不会产生新记录。

时间线

代码
startTime → redirectStart/End → fetchStart → domainLookupStart/End
→ connectStart → secureConnectionStart → connectEnd
→ requestStart → responseStart → responseEnd
→ domInteractive → domContentLoadedEventStart/End → domComplete → loadEventStart/End

采集示例

JavaScript
new PerformanceObserver((list) => {
  const [nav] = list.getEntries();
  const https = nav.secureConnectionStart > 0;
  report({
    type: nav.type,
    redirect: nav.redirectEnd - nav.redirectStart,
    dns: nav.domainLookupEnd - nav.domainLookupStart,
    tcp: (https ? nav.secureConnectionStart : nav.connectEnd) - nav.connectStart,
    tls: https ? nav.connectEnd - nav.secureConnectionStart : 0,
    ttfb: nav.responseStart,
    download: nav.responseEnd - nav.responseStart,
    domContentLoaded: nav.domContentLoadedEventEnd,
    load: nav.loadEventEnd,
  });
}).observe({ type: 'navigation', buffered: true });
  • buffered: true 让晚于导航注册的观察者也能拿到记录。
  • PerformanceObserver 在记录完成后才回调，此时 loadEventEnd 已有值。

读数时的注意事项

  • 字段值不能直接传给 new Date()；要和日志时间对齐时，用 performance.timeOrigin + 相对值。
  • domContentLoaded 和 load 都不等于业务就绪，首屏数据是否渲染完成要用 performance.mark() 自己记录。
  • 预渲染页面被激活时，activationStart 大于 0，此前的阶段用户看不到；计算用户感知的耗时要减去 activationStart，并和普通导航分组统计。
  • 连接复用或命中缓存时，DNS 和 TCP 的耗时为 0，这是正常的。
  • 跨源重定向时，redirectStart 和 redirectEnd 为 0，看不到重定向耗时。
  • 单次数值波动很大，线上要汇总后看 75 分位，并按设备、网络类型分组。
  • SPA 的路由切换不是文档导航，不会产生新的 Navigation Timing 记录，需要自己用 performance.mark() 和 measure() 记录。

常见追问

  • 和 Resource Timing 的关系：PerformanceNavigationTiming 继承自 PerformanceResourceTiming，所以也有 transferSize、nextHopProtocol 等字段。
  • serverTiming 字段：服务端通过 Server-Timing 响应头传递的各阶段耗时，可以和前端数据对齐分析。
