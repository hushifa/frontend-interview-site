webpack 的 entry、output、loader 和 plugin 分别负责什么？

entry 是依赖入口，output 决定产物，loader 做模块转换，plugin 通过生命周期钩子扩展构建。文中用一个完整配置讲 loader 顺序、publicPath、mode 和排错方法。

参考答案

简答

webpack 从 entry 指定的文件出发，顺着 import 和 require 一层层找下去，把用到的模块都找出来，这叫依赖图。output 决定打包结果写到哪里、叫什么名字，以及浏览器从哪个路径加载，也就是 publicPath。

loader 负责把 CSS、图片、TypeScript 这类非 JS 文件转换成 webpack 能处理的模块，一次处理一个文件。plugin 则通过钩子介入整个构建过程，能生成 HTML、提取 CSS、注入变量、分析产物。

所以两者的区别是，loader 面向单个文件，plugin 面向整个构建。

要注意，use 数组里的 loader 是从右往左执行的，写反了就会出错。

先看一个完整配置

下面的配置处理 JS、CSS、文本和图片，并生成 HTML。后面逐个看每部分在做什么。

JavaScript
// webpack.config.js
const path = require('node:path');
const HtmlWebpackPlugin = require('html-webpack-plugin');
const MiniCssExtractPlugin = require('mini-css-extract-plugin');

module.exports = (env, argv) => ({
  mode: argv.mode ?? 'development',
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
    publicPath: '/',
    clean: true,
  },
  module: {
    rules: [
      { test: /\.css$/, use: [MiniCssExtractPlugin.loader, 'css-loader'] },
      { test: /\.txt$/, type: 'asset/source' },
      { test: /\.png$/, type: 'asset/resource' },
    ],
  },
  plugins: [
    new HtmlWebpackPlugin({ template: './src/index.html' }),
    new MiniCssExtractPlugin({ filename: '[name].[contenthash].css' }),
  ],
});

entry 和 output 管什么

entry 是起点。可以有多个入口，每个入口会生成独立的 chunk，chunk 就是打包出来的一块代码。

output 里的 [contenthash] 会让文件名跟着内容变化。内容不变，文件名就不变，浏览器可以长期缓存。

publicPath 决定运行时加载异步块和资源用的 URL 前缀。部署到子目录时，必须把它改成对应的路径，否则浏览器会去错误的地址请求，结果就是 404。

loader 为什么要注意顺序

看 CSS 那条规则：use: [MiniCssExtractPlugin.loader, 'css-loader']。loader 从右往左执行，所以先跑 css-loader，它把 CSS 里的 @import 和 url() 解析成依赖；然后 MiniCssExtractPlugin.loader 把结果提取成独立的 CSS 文件。

顺序反过来，提取的那一步拿到的就不是它能处理的东西，构建会出错。

另外，webpack 5 内置了资源模块，就是配置里的 asset/resource、asset/source、asset/inline，它们取代了以前的 file-loader、raw-loader、url-loader。

plugin 能做什么 loader 做不到的事

HtmlWebpackPlugin 在构建结束时生成 HTML，并插入带哈希的脚本标签。这件事 loader 做不了，因为它要等所有文件名都确定以后才能做。

所以 plugin 能做 loader 做不到的事，原因在于它面向整个编译过程，而不是单个文件。

mode 有什么作用

mode: 'production' 会开启压缩、tree shaking、作用域提升，并把 process.env.NODE_ENV 设成 'production'。'development' 保留可读的代码，构建也更快。

出问题时怎样排查

用 --stats verbose，或者输出 stats JSON，可以看到每个模块被哪个 loader 处理、进了哪个 chunk。

如果报 “You may need an appropriate loader”，说明某类文件没有匹配到任何规则，去检查 test 和 include。

如果开发服务器正常、部署后资源 404，多半是 publicPath 和实际部署路径不一致。

常见追问

loader 和 plugin 的根本区别是什么？

loader 是一个转换函数，进去一个文件，出来一个模块。plugin 是订阅编译事件的对象，可以访问和修改整个编译结果。

现在还需要学 webpack 吗？

需要。很多存量项目和企业内部工具链还在用它。而且理解了它的模型，再看 Vite、Rspack 这些工具也更容易。
