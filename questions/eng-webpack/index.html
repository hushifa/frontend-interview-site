webpack 的 entry、output、loader 和 plugin 分别负责什么？

用文本模块的完整构建例子串起依赖入口、产物、模块转换和生命周期扩展，说明 loader 顺序、publicPath、模式及排错方法。

参考答案

简答

  • entry 是依赖图的起点，webpack 从这里递归分析所有 import/require。
  • output 决定产物写到哪里、叫什么名字，以及浏览器从哪个路径加载（publicPath）。
  • loader 把非 JS 文件（CSS、图片、TypeScript）转换成 webpack 能处理的模块，一次处理一个文件。
  • plugin 通过钩子介入整个构建生命周期，可以生成 HTML、提取 CSS、注入变量、分析产物。
  • use 数组里的 loader 从右往左（从下往上）执行。

一个完整配置

JavaScript
// webpack.config.js
const path = require('node:path');
const HtmlWebpackPlugin = require('html-webpack-plugin');
const MiniCssExtractPlugin = require('mini-css-extract-plugin');

module.exports = (env, argv) => ({
  mode: argv.mode ?? 'development',
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
    publicPath: '/',
    clean: true,
  },
  module: {
    rules: [
      { test: /\.css$/, use: [MiniCssExtractPlugin.loader, 'css-loader'] },
      { test: /\.txt$/, type: 'asset/source' },
      { test: /\.png$/, type: 'asset/resource' },
    ],
  },
  plugins: [
    new HtmlWebpackPlugin({ template: './src/index.html' }),
    new MiniCssExtractPlugin({ filename: '[name].[contenthash].css' }),
  ],
});

各部分的分工

entry：可以有多个入口，每个入口生成独立的 chunk。

output：[contenthash] 让文件名随内容变化，配合长期缓存；publicPath 决定运行时加载异步块和资源的 URL 前缀，部署到子目录时必须改成对应路径，否则会 404。

loader：css-loader 把 CSS 中的 @import 和 url() 解析成依赖，MiniCssExtractPlugin.loader 再把结果提取成独立的 CSS 文件。顺序反过来就会出错。webpack 5 内置的资源模块（asset/resource、asset/source、asset/inline）取代了以前的 file-loader、raw-loader、url-loader。

plugin：HtmlWebpackPlugin 在构建结束时生成 HTML 并插入带哈希的脚本标签。plugin 能做 loader 做不到的事，因为它面向整个编译过程，而不是单个文件。

mode 的作用

mode: 'production' 会开启压缩、tree shaking、作用域提升，并把 process.env.NODE_ENV 设为 'production'；'development' 保留可读代码，构建更快。

排错方法

  • 用 --stats verbose 或输出 stats JSON 查看每个模块被哪个 loader 处理、进入了哪个 chunk。
  • 报 "You may need an appropriate loader" 时，说明某类文件没有匹配到任何规则，检查 test 和 include。
  • 开发服务器能用、部署后资源 404，多半是 publicPath 和实际部署路径不一致。

常见追问

  • loader 和 plugin 的根本区别？loader 是"文件进、模块出"的转换函数；plugin 是订阅编译事件的对象，可以访问和修改整个编译结果。
