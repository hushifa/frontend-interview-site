useSyncExternalStore 为什么要求稳定的快照？

useSyncExternalStore 用来把 React 之外的数据（浏览器状态、自己写的 store）接进组件。React 靠比较前后两次读到的值是不是同一个来决定要不要更新，所以数据没变时必须返回同一个引用，否则会无限渲染。

参考答案

简答

有些数据不在 React 里，比如浏览器是否在线、一个自己写的全局 store。useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?) 就是把这种外部数据接进组件的官方方式。subscribe 负责在数据变化时通知 React，getSnapshot 负责返回当前的数据，这个值叫快照。

React 收到通知后，会再调一次 getSnapshot，用 Object.is 跟上一次比较，不同才重新渲染。所以数据没变时，getSnapshot 必须返回同一个引用。如果每次都返回一个新对象，React 每次都认为变了，就会无限渲染。

它比用 useEffect 订阅好在两点：渲染时同步读数据，第一次渲染就有值；并发渲染时保证同一次渲染里所有组件读到同一份快照，不会出现一屏上新旧数据混着显示的“撕裂”。Zustand、react-redux 内部都用它。

要注意，subscribe 要定义在组件外面保持引用稳定；服务端渲染要提供 getServerSnapshot，返回值两端要一致。

先接一个浏览器 API

下面把 navigator.onLine 接进 React，网络断开或恢复时组件自动更新。

JSX
import { useSyncExternalStore } from 'react';

function subscribe(callback) {
  window.addEventListener('online', callback);
  window.addEventListener('offline', callback);
  return () => {
    window.removeEventListener('online', callback);
    window.removeEventListener('offline', callback);
  };
}

export function useOnlineStatus() {
  return useSyncExternalStore(
    subscribe,
    () => navigator.onLine,
    () => true, // 服务端假定在线
  );
}

subscribe 收到 React 给的 callback，在网络状态变化时调用它，并返回一个取消订阅的函数。getSnapshot 返回布尔值，布尔值没变 Object.is 就相等，天然稳定。

为什么 subscribe 写在组件外面？如果写在组件里，每次渲染都是一个新函数，React 会以为订阅方式变了，反复取消再重新订阅。

数据没变却返回新对象会怎样

下面这个最小 store 模拟 React 的判断逻辑，可以直接用 node 运行，看看两种 getSnapshot 的区别。

JavaScript
function createStore(initial) {
  let state = initial;
  const listeners = new Set();
  return {
    getSnapshot: () => state,
    subscribe(listener) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
    setState(update) {
      state = { ...state, ...update }; // 生成新对象，引用变化才会触发更新
      listeners.forEach((l) => l());
    },
  };
}

const store = createStore({ items: [{ id: 1, active: true }] });

const stable = () => store.getSnapshot();
const unstable = () => store.getSnapshot().items.filter((i) => i.active);

console.log(Object.is(stable(), stable()));     // true
console.log(Object.is(unstable(), unstable())); // false

const before = stable();
store.subscribe(() => console.log('通知：数据变了'));
store.setState({ coupon: 'A' });               // 通知：数据变了
console.log(Object.is(before, stable()));      // false

在组件里，把 store 的两个方法交给 Hook 即可：

JavaScript
const snapshot = useSyncExternalStore(store.subscribe, store.getSnapshot);

stable 直接返回保存的 state，只要没调 setState，两次读到的就是同一个对象。unstable 每次都跑一遍 filter，内容一样，但每次都是新数组，Object.is 永远是 false。

放进 React 里，这就意味着 React 每次检查都发现“变了”，于是重新渲染，渲染时又读到一个新数组，又认为变了，最后就是无限循环，React 会报错。

反过来，setState 里要生成新对象并通知订阅者。引用变了，React 才知道该更新；引用没变，React 就跳过。如果直接改 state.coupon = 'A'，引用没变，组件就不会更新。

需要派生数据怎么办

上面的 filter 是很常见的需求。改法有两种：在 store 内部把派生结果缓存起来，原始数据不变就返回同一个结果；或者先用 useSyncExternalStore 取到稳定的原始快照，再在组件里用 useMemo 计算。

下面两段写在组件里，不能单独运行：

JSX
// 错误：每次都返回新数组，Object.is 永远为 false
const items = useSyncExternalStore(subscribe, () => store.getState().items.filter((i) => i.active));

和用 useEffect 订阅有什么区别

用 useEffect 订阅再 setState，第一次渲染时还拿不到数据，要等 Effect 跑完再渲染一次。而且在并发渲染中，React 可能渲染到一半暂停，这期间外部数据变了，前后组件就读到不同的值，出现撕裂。

useSyncExternalStore 在渲染时同步读取快照，外部数据的更新也以同步优先级处理，所以没有这些问题。

常见追问

能和 Transition 配合，让外部数据的更新不阻塞输入吗？

不能。外部数据变化总是以同步优先级渲染，没法标成 Transition。

平时写业务需要用它吗？

一般不用。只是在 React 内部共享状态，用 state 和 Context 就够了。这个 Hook 主要给状态库作者，以及接入浏览器 API 时使用。
