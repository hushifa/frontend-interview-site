useSyncExternalStore 为什么要求稳定的快照？

useSyncExternalStore 用 subscribe 和 getSnapshot 两个函数把外部数据源接入 React。React 用 Object.is 比较前后快照判断是否需要更新，数据没变时 getSnapshot 必须返回同一个引用，否则会无限重新渲染。

参考答案

简答

  • 签名：useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?)。
  • subscribe(callback) 在外部数据变化时调用 callback，并返回取消订阅的函数。
  • getSnapshot() 返回当前数据；React 用 Object.is 比较新旧快照，不同才重新渲染。数据没变却每次返回新对象，会导致无限渲染。
  • 它在并发渲染中保证同一次渲染里所有组件读到同一份快照，避免"撕裂"（同一屏显示新旧两份数据）。
  • getServerSnapshot 用于服务端渲染和 hydration，返回值必须两端一致。

订阅浏览器 API

JSX
import { useSyncExternalStore } from 'react';

function subscribe(callback) {
  window.addEventListener('online', callback);
  window.addEventListener('offline', callback);
  return () => {
    window.removeEventListener('online', callback);
    window.removeEventListener('offline', callback);
  };
}

export function useOnlineStatus() {
  return useSyncExternalStore(
    subscribe,
    () => navigator.onLine,
    () => true, // 服务端假定在线
  );
}

subscribe 定义在组件外部，引用稳定。如果写在组件里，每次渲染都会生成新函数，React 会反复取消并重新订阅。

一个最小的 store

JavaScript
function createStore(initial) {
  let state = initial;
  const listeners = new Set();
  return {
    getSnapshot: () => state,
    subscribe(listener) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
    setState(update) {
      state = { ...state, ...update }; // 生成新对象，引用变化才会触发更新
      listeners.forEach((l) => l());
    },
  };
}

export const cartStore = createStore({ items: [], coupon: null });

// 组件中
const cart = useSyncExternalStore(cartStore.subscribe, cartStore.getSnapshot);

getSnapshot 直接返回保存的 state，数据没变就是同一个引用。

快照不能每次新建

JavaScript
// 错误：每次都返回新数组，Object.is 永远为 false
const items = useSyncExternalStore(subscribe, () => store.getState().items.filter((i) => i.active));

需要派生数据时，在 store 内部缓存派生结果，或者先取稳定的原始快照，再在组件里用 useMemo 计算。

和 useEffect 订阅的区别

用 useEffect 订阅后 setState，第一次渲染拿不到数据，而且并发渲染中可能出现撕裂。useSyncExternalStore 在渲染时同步读取快照，更新也以同步优先级处理。Zustand、Redux（react-redux）等库内部都基于它实现。

常见追问

  • 外部数据变化总会以同步优先级渲染，所以不能和 Transition 配合实现"非阻塞更新"。
  • 只是在 React 内部共享状态，用 state、Context 即可，这个 Hook 主要给库作者和浏览器 API 接入使用。
