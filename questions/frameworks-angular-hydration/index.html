Angular Hydration 解决什么问题？

Hydration 让客户端 Angular 复用服务端渲染出的 DOM，而不是销毁后重新创建，从而避免页面闪烁、减少重复工作。它要求服务端和客户端渲染出相同的 DOM 结构，直接操作 DOM 的代码需要改写或跳过。

参考答案

简答

  • 没有 hydration 时，客户端启动会丢弃服务端 HTML 再重新渲染，可能出现闪烁，也会影响 LCP、CLS 等指标。
  • 用 provideClientHydration() 开启后，Angular 匹配现有 DOM 节点，只挂载事件监听和状态。
  • 服务端和客户端渲染出的 DOM 必须一致；不一致时 Angular 会报 hydration 错误，并回退为重新渲染该部分。
  • 直接用 document、innerHTML 或第三方库修改 DOM 会导致不一致，应改用 Angular API，或给组件加 ngSkipHydration 跳过。
  • 事件重放（withEventReplay()）记录脚本加载完成前用户的点击，hydration 完成后重新派发；增量 hydration（withIncrementalHydration()）配合 @defer 按需激活部分区域。

开启

TypeScript
import { bootstrapApplication, provideClientHydration, withEventReplay } from '@angular/platform-browser';

bootstrapApplication(App, {
  providers: [provideClientHydration(withEventReplay())],
});

常见的不一致来源

TypeScript
@Component({
  template: `<p>{{ now }}</p>`,
})
export class Clock {
  now = new Date().toLocaleTimeString(); // 服务端和客户端时间不同
}
  • 时间、随机数：服务端生成后通过 TransferState 或接口数据传给客户端，或者只在浏览器中更新（afterNextRender）。
  • 浏览器专属 API：window、localStorage 在服务端不存在，放进 afterNextRender 中执行。
  • 无效的 HTML 嵌套，例如 <p> 里放 <div>：浏览器解析时会自动修正结构，导致和 Angular 预期的 DOM 不一致。

跳过某个组件

HTML
<legacy-chart ngSkipHydration />

该组件会在客户端重新渲染，适合暂时无法改造的第三方组件。只能加在组件宿主元素上。

增量 hydration

HTML
@defer (hydrate on viewport) {
  <app-comments />
}

服务端照常输出评论区的 HTML，客户端在它进入视口时才加载代码并 hydration。首屏需要下载和执行的 JavaScript 更少。

常见追问

  • HTTP 请求会在客户端重复吗？开启 hydration 后，HttpClient 默认缓存服务端发出的 GET 请求结果并传给客户端，客户端不会再请求一次。
  • 和 React hydration 有什么共同点？都要求两端结构一致，原理类似，见《Hydration mismatch 为什么发生，应该怎样修复？》。
