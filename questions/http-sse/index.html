SSE 的事件格式、自动重连和 Last-Event-ID 是怎样工作的？

SSE 是一个 text/event-stream 的普通 HTTP 响应，服务器按 id、event、data、retry 字段逐条写事件；EventSource 断线后按 retry 间隔自动重连，并用 Last-Event-ID 请求头告诉服务器最后收到哪条，服务器据此补发。

参考答案

简答

后台任务跑了一分钟，页面要实时显示进度。用 SSE 时，浏览器发一个普通请求，服务器返回 Content-Type: text/event-stream，但不结束响应，而是一条一条往里写事件。

每个事件由几行字段组成：data 是内容，event 是事件类型，id 是编号，retry 设置重连间隔，空行表示一个事件结束。浏览器的 EventSource 负责解析，按类型派发给监听函数。

断线时 EventSource 会自动重连，并在请求头 Last-Event-ID 里带上最后收到的编号。服务器保留一段历史，按这个编号补发漏掉的事件，就能做到断线续传。

要注意，服务器返回非 200 状态码或者 Content-Type 不对时，浏览器会直接关闭连接，不再重连。EventSource 也只能发 GET、不能自定义请求头。SSE 和轮询、WebSocket 怎么选，见《短轮询、长轮询、SSE 和 WebSocket 有什么区别？怎么选？》。

服务器发出来的事件长什么样

格式很简单，每行一个字段，空行表示一个事件结束：

text
id: 42
event: progress
data: {"percent": 60}

data: 第一行
data: 第二行

retry: 5000

第一个事件有编号 42，类型是 progress。第二个事件没写 event，类型就是默认的 message，会触发 onmessage；它有两行 data，浏览器用换行把它们拼成一段。最后一段只有 retry，作用是把重连间隔设成 5000 毫秒，它本身不派发事件。

以 : 开头的行是注释，浏览器会忽略。服务器常隔一段时间发一行注释当心跳，防止中间的代理觉得连接空闲把它断掉。

浏览器怎么接收

JavaScript
const source = new EventSource('/api/tasks/7/events');

source.addEventListener('progress', (event) => {
  const { percent } = JSON.parse(event.data);
  console.log('进度', percent, '最后事件 ID', event.lastEventId);
});

source.addEventListener('done', () => source.close());

source.onerror = () => {
  // readyState 为 CONNECTING 表示浏览器正在自动重连
  if (source.readyState === EventSource.CLOSED) console.log('连接已关闭');
};

为什么 onerror 触发了，连接却还在？因为网络断开时浏览器会触发 error，同时把 readyState 设为 CONNECTING，等一段时间后自动重连。只有 readyState 变成 CLOSED 才是真的关了。HTML 标准规定，响应状态码不是 200，或者 Content-Type 不是 text/event-stream，浏览器就会让连接失败并不再重连。所以服务器想让客户端停止重连，可以返回 204 这类非 200 状态。

怎样做到断线不丢消息

EventSource 会记住最后一个事件的 id，重连时放进 Last-Event-ID 请求头。服务器要做的是给每个事件编号，并保留最近一段历史，收到带这个头的请求就从下一条开始补发。

所以编号要能比较先后，比如自增序号或带时间的 ID。历史保留多久要看业务，客户端离线太久、历史已经清掉时，服务器应该让客户端重新拉一次完整状态，而不是假装补齐了。

EventSource 不够用时怎么办

EventSource 只能发 GET，不能自定义请求头，只能带 Cookie（跨源时设 withCredentials）。调大模型接口这类场景，经常要 POST 请求体或者 Authorization 头。这时就改用 fetch，读 response.body 这个流，自己按上面的格式解析事件。代价是重连、Last-Event-ID 和续传也要自己写。

还有一个坑。MDN 提醒，不用 HTTP/2 时，浏览器对同一个域名的 SSE 连接数有限，上限是 6 个，多个标签页一起开就会占满。HTTP/2 一条连接里能跑很多个请求，默认上限要大得多。

常见追问

服务器怎样控制重连间隔？

发一行 retry: 毫秒数，浏览器之后的重连就按这个间隔等待。不发时用浏览器的默认值。

WebSocket 的重连怎么做？

WebSocket 没有内置重连，要自己做退避重连和补发，见《WebSocket 适合什么场景，连接断开后怎样恢复？》。
