HTTP Range 请求适合什么场景？

Range 请求只拿文件的一段字节，用在断点续传、视频拖动和读大文件的局部。服务器支持就回 206，不支持就回完整的 200，范围不对回 416；续传时带上 If-Range，防止文件更新后新旧内容拼在一起。

参考答案

简答

下载一个大文件下到一半断了，没必要从头再来，只要把剩下的部分要回来。Range 请求就是干这个的：请求头写 Range: bytes=0-1023，表示只要第 0 到第 1023 字节，两头都包含。

服务器用 Accept-Ranges: bytes 表示支持。支持的话，返回 206 Partial Content，并用 Content-Range: bytes 0-1023/5000 说明给的是哪一段、文件一共多大。

有两种情况要处理。服务器不支持或者忽略了 Range，会直接返回 200 和完整内容，客户端必须检查状态码，不然会把整个文件当成一段。范围超出文件大小，返回 416 Range Not Satisfiable，Content-Range: bytes */5000 告诉你实际大小。

续传时还要带 If-Range: "etag"。文件没变，服务器回 206；文件变了，就回完整的 200。这样不会把旧文件的前半段和新文件的后半段拼成一个坏文件。

Range 有哪几种写法

http
Range: bytes=0-1023      # 前 1024 字节
Range: bytes=1024-       # 从 1024 到末尾
Range: bytes=-500        # 最后 500 字节
Range: bytes=0-99,200-299 # 多段，响应为 multipart/byteranges

注意 -500 不是“到第 500 字节”，而是“最后 500 字节”。多段请求时，响应是 multipart/byteranges 格式，几段内容包在一起返回。

下载一段时要检查什么

下面的函数请求一段字节，并检查服务器给的到底是不是这一段：

JavaScript
async function fetchRange(url, start, end, etag) {
  const headers = { Range: `bytes=${start}-${end}` };
  if (etag) headers['If-Range'] = etag;

  const response = await fetch(url, { headers });

  if (response.status === 200) {
    return { restart: true, response }; // 不支持 Range 或文件已变化
  }
  if (response.status !== 206) {
    throw new Error(`下载失败：${response.status}`);
  }

  const match = /^bytes (\d+)-(\d+)\/(\d+|\*)$/.exec(response.headers.get('Content-Range') ?? '');
  if (!match || Number(match[1]) !== start) {
    throw new Error('返回的范围与请求不一致');
  }

  return {
    restart: false,
    data: new Uint8Array(await response.arrayBuffer()),
    total: match[3] === '*' ? null : Number(match[3]),
    etag: response.headers.get('ETag'),
  };
}

收到 200 时不能当成功拼接，因为可能是服务器不支持 Range，也可能是 If-Range 发现文件变了，两种情况都只能从头下载。

收到 206 也不要直接信，要解析 Content-Range，确认起点和你请求的一样。总大小那一位可能是 *，表示服务器也不知道总长度。这个正则可以在 Node 里单独试一下：

JavaScript
const pattern = /^bytes (\d+)-(\d+)\/(\d+|\*)$/;
console.log(pattern.exec('bytes 0-1023/5000').slice(1)); // [ '0', '1023', '5000' ]
console.log(pattern.exec('bytes 0-1023/*').slice(1)); // [ '0', '1023', '*' ]
console.log(pattern.exec('bytes */5000')); // null

最后一种是 416 的格式，不会出现在 206 里，所以匹配失败是对的。

跨源请求时，Range 头会触发预检，除非是简单的单段范围。服务器还要用 Access-Control-Expose-Headers 暴露 Content-Range 和 ETag，脚本才能读到。

实际用在哪些地方

最常见的是断点续传下载：记下已经下了多少字节，重连后从断点继续。

音视频也离不开它。<video> 拖动进度条时，浏览器会自动发 Range 请求。服务器不支持的话，视频就没法拖。

还有大文件的局部读取，比如只读 ZIP 的目录区、PDF 的某一页、Parquet 文件的元数据，不用把整个文件下下来。

还有哪些坑

If-Range 要用强 ETag，弱 ETag 不能用于范围请求，因为弱 ETag 只保证意思一样，不保证字节一样。

内容经过 gzip 等压缩时，范围算的是压缩后的字节，所以大文件下载一般不做动态压缩。

CDN 要能正确缓存和切分范围响应，有些 CDN 需要单独开启这个功能。

常见追问

和分片上传有什么关系？

Range 是用来下载的。上传的分片由应用自己的协议或者对象存储的接口定义，见《浏览器分片上传如何实现可靠的暂停与续传？》。

浏览器下载管理器的续传也用它吗？

是的，前提是服务器支持 Range，并且提供了 ETag 这类验证器。
