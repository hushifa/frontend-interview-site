HTTP Range 请求适合什么场景？

Range 请求只取资源的一段字节，用于断点续传、视频拖动和读取大文件的局部。服务器支持时返回 206 和 Content-Range，不支持时返回完整的 200，范围无效时返回 416；配合 If-Range 防止文件更新后把新旧内容拼在一起。

参考答案

简答

  • 请求头 Range: bytes=0-1023 表示取第 0 到 1023 字节，两端都包含。
  • 服务器用 Accept-Ranges: bytes 声明支持；返回 206 Partial Content 和 Content-Range: bytes 0-1023/5000。
  • 服务器忽略 Range 时返回 200 和完整内容，客户端必须检查状态码，否则会把整个文件当成一段。
  • 范围超出文件大小返回 416 Range Not Satisfiable，Content-Range: bytes */5000 给出实际大小。
  • 续传时带 If-Range: "etag"：文件没变返回 206，变了返回完整的 200，避免拼出损坏的文件。

写法

http
Range: bytes=0-1023      # 前 1024 字节
Range: bytes=1024-       # 从 1024 到末尾
Range: bytes=-500        # 最后 500 字节
Range: bytes=0-99,200-299 # 多段，响应为 multipart/byteranges

校验一段下载

JavaScript
async function fetchRange(url, start, end, etag) {
  const headers = { Range: `bytes=${start}-${end}` };
  if (etag) headers['If-Range'] = etag;

  const response = await fetch(url, { headers });

  if (response.status === 200) {
    return { restart: true, response }; // 不支持 Range 或文件已变化
  }
  if (response.status !== 206) {
    throw new Error(`下载失败：${response.status}`);
  }

  const match = /^bytes (\d+)-(\d+)\/(\d+|\*)$/.exec(response.headers.get('Content-Range') ?? '');
  if (!match || Number(match[1]) !== start) {
    throw new Error('返回的范围与请求不一致');
  }

  return {
    restart: false,
    data: new Uint8Array(await response.arrayBuffer()),
    total: match[3] === '*' ? null : Number(match[3]),
    etag: response.headers.get('ETag'),
  };
}

跨源请求时，Range 头会触发预检（除非是简单的单段范围），服务器还要用 Access-Control-Expose-Headers 暴露 Content-Range 和 ETag，脚本才能读到。

场景

  • 断点续传下载：记录已下载字节数，重连后从断点继续。
  • 视频和音频：<video> 拖动进度条时，浏览器自动发 Range 请求，服务器不支持会导致无法拖动。
  • 大文件局部读取：只读 ZIP 的目录区、PDF 的某一页、Parquet 文件的元数据。

注意

  • If-Range 应该用强 ETag，弱 ETag 不能用于范围请求。
  • 内容经过 gzip 等压缩时，范围是针对编码后的字节，大文件下载通常不做动态压缩。
  • CDN 要正确缓存和切分范围响应，部分 CDN 需要单独开启。

常见追问

  • 和分片上传有什么关系？Range 用于下载；上传的分片由应用协议或对象存储接口定义，见《浏览器分片上传如何实现可靠的暂停与续传？》。
  • 浏览器下载管理器的续传也用它吗？是的，前提是服务器支持 Range 并提供验证器。
