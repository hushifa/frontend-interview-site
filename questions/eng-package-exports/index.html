package.json 的 exports 和 imports 分别解决什么问题？

exports 决定包对外公开哪些入口，imports 给包内部提供

参考答案

简答

exports 写在 package.json 里，规定别人能从这个包导入哪些路径。写了它以后，没列出来的内部文件就导入不了，包的公开接口就清楚了。

它还能按条件选文件，比如 import 时给 ESM 版本，require 时给 CommonJS 版本，这叫条件导出。imports 则是给包自己内部用的别名，以 # 开头，用来代替很长的相对路径。

有了 exports，Node.js 和现代打包工具都会优先用它，main 只留给不认识 exports 的旧工具。

要注意，增加或删除 exports 的条目，会改变别人能导入的路径，属于要谨慎处理的 API 变更。

一个双入口包长什么样

下面这个工具包同时提供 ESM 和 CommonJS 两个版本，还公开了一个 date 子路径。

json
{
  "name": "@acme/utils",
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./date": {
      "types": "./dist/date.d.ts",
      "import": "./dist/date.js",
      "require": "./dist/date.cjs"
    },
    "./package.json": "./package.json"
  },
  "imports": {
    "#internal/*": "./src/internal/*.js"
  },
  "main": "./dist/index.cjs"
}

使用者写 import { x } from '@acme/utils'，拿到的是 dist/index.js；写 require('@acme/utils')，拿到的是 dist/index.cjs。同一个入口，按导入方式给了不同的文件。

import '@acme/utils/date' 可以用，因为它列在 exports 里。可是 import '@acme/utils/dist/internal.js' 会报 ERR_PACKAGE_PATH_NOT_EXPORTED，因为这个路径没有公开。

包自己的代码里可以写 import { helper } from '#internal/helper'，imports 会把它映射到 ./src/internal/helper.js，不用再写 ../../。

条件为什么要注意顺序

条件是按对象里书写的顺序匹配的，第一个满足的就生效，后面的不再看。

所以 types 要放在第一位，TypeScript 才能找到声明文件。default 要放在最后当兜底，放前面的话它总会先匹配上。node、browser、development、production 这些条件满不满足，由运行环境或打包工具决定，比如 Vite 会根据目标环境设置相应的条件。

另外，TypeScript 要按 exports 来解析，moduleResolution 需要设成 node16、nodenext 或 bundler。

和 type、main 是什么关系

"type": "module" 让包里的 .js 文件按 ESM 解析，这时 CommonJS 文件要用 .cjs 扩展名。反过来，"type": "commonjs" 时，ESM 文件要用 .mjs。

main 是旧的单入口字段。有 exports 时它会被忽略，保留它只是为了兼容不支持 exports 的旧工具。

同时发布两个版本有什么风险

同一个包的 ESM 版本和 CommonJS 版本，可能在一个应用里同时被加载。这时它们各自有一份模块状态，比如单例、缓存、instanceof 用到的类，就会出现两份，互相不认识。

如果包有模块级的状态，可以让两个入口共用同一份实现，或者干脆只提供 ESM。Node.js 22.12+ 和 20.19+ 已经支持用 require() 加载同步的 ESM 模块，所以新包只发布 ESM 的成本比以前低了。

常见追问

为什么加了 exports 以后，别人的代码报错了？

因为对方深层导入了一个没有公开的文件。要么把这些路径加进 exports，要么把这次改动当成破坏性变更，发布大版本。

./package.json 为什么要单独导出？

有些工具会读取包的 package.json。有了 exports 以后，没导出的路径都会被拒绝，包括 package.json 本身，所以要单独列出来。
