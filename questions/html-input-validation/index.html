原生表单校验能解决什么，不能解决什么？

用 required、type、pattern、min、max 这些属性，浏览器能在提交前检查有没有填、格式对不对、在不在范围内。两个字段之间的比较和需要请求服务器的检查要自己写，服务端校验永远不能省。

参考答案

简答

给输入框写上规则，浏览器会在提交前帮你检查，这叫约束校验。内置的规则有 required、type="email" 或 url、pattern、min/max/step、minlength/maxlength。不满足时，提交会被拦下来并显示浏览器的提示，input.validity 能告诉你具体是哪一条没通过。

想要自定义错误，用 setCustomValidity('消息')。要注意必须传空字符串才能清除，否则控件会一直是无效状态。显示错误样式时用 :user-invalid，它只在用户操作过以后才匹配，不会像 :invalid 那样一打开页面就满屏红色。

原生校验做不到的事情也要清楚：需要请求服务器的检查，比如用户名有没有被占用；依赖业务数据的规则，比如库存和权限。

最重要的一点，前端校验只是为了体验。请求完全可以绕过页面直接发给服务器，所以服务端必须重新校验。

用页面里的文字代替浏览器气泡

HTML
<form id="signup" novalidate>
  <label for="email">邮箱</label>
  <input id="email" name="email" type="email" required aria-describedby="email-error">
  <p id="email-error" class="error"></p>
  <button>注册</button>
</form>
JavaScript
form.addEventListener('submit', (event) => {
  const input = form.elements.email;
  const error = document.querySelector('#email-error');

  if (!input.checkValidity()) {
    event.preventDefault();
    error.textContent = input.validity.valueMissing
      ? '请填写邮箱'
      : '邮箱格式不正确';
    input.setAttribute('aria-invalid', 'true');
    input.focus();
  } else {
    error.textContent = '';
    input.removeAttribute('aria-invalid');
  }
});

表单上写了 novalidate，那 required 和 type="email" 还有用吗？有用。novalidate 只是关掉浏览器自动拦截和气泡提示，规则本身还在，checkValidity() 照常工作。这样就能自己决定什么时候检查、错误文字写什么、显示在哪里。

validity.valueMissing 表示没填，据此给出不同的提示。aria-invalid 告诉读屏这个字段有错，aria-describedby 让读屏接着读出错误文字。

两个字段之间的比较怎么做

内置规则只看单个字段。“两次密码要一致”这种规则，用 setCustomValidity 自己补：

JavaScript
confirm.addEventListener('input', () => {
  confirm.setCustomValidity(
    confirm.value === password.value ? '' : '两次密码不一致',
  );
});

一致时一定要传空字符串，把错误清掉。不然用户改对了，字段还是无效，表单永远提交不了。

为什么多数产品不用浏览器的默认提示

浏览器默认气泡的样式和显示时机都没法定制。默认文案跟着浏览器语言走，文字可以用 setCustomValidity() 替换，样式却改不了。读屏体验在不同浏览器里也不一致。所以多数产品会改成上面那种页面里的自定义提示。

错误提示要照顾无障碍

错误文字放在页面里，用 aria-describedby 关联到对应的控件。

提交失败时，把焦点移到第一个出错的字段。或者在表单顶部列出所有错误，每条链接到对应的字段。

不要只靠红色边框表示错误，一定要有文字说明。

常见追问

pattern 里要不要写 ^ 和 $？

不用。pattern 默认就要求匹配整个值，并且是用 v 标志来编译正则的。
