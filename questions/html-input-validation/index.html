原生表单校验能解决什么，不能解决什么？

required、type、pattern、min/max 等约束和 Constraint Validation API 能在提交前检查格式和范围；跨字段规则、异步检查要自己补，服务端校验永远不能省。

参考答案

简答

  • 内置约束：required、type="email"/url、pattern、min/max/step、minlength/maxlength。
  • 不满足约束时，提交会被阻止并显示浏览器提示；input.validity 给出具体哪条失败。
  • setCustomValidity('消息') 设置自定义错误，传空字符串才会清除，否则控件一直无效。
  • :user-invalid 只在用户交互过后才匹配，比 :invalid 更适合显示错误样式，不会一打开页面就满屏红色。
  • 前端校验只是体验优化，请求可以绕过页面直接发送，服务端必须重新校验。

自定义提示

HTML
<form id="signup" novalidate>
  <label for="email">邮箱</label>
  <input id="email" name="email" type="email" required aria-describedby="email-error">
  <p id="email-error" class="error"></p>
  <button>注册</button>
</form>
JavaScript
form.addEventListener('submit', (event) => {
  const input = form.elements.email;
  const error = document.querySelector('#email-error');

  if (!input.checkValidity()) {
    event.preventDefault();
    error.textContent = input.validity.valueMissing
      ? '请填写邮箱'
      : '邮箱格式不正确';
    input.setAttribute('aria-invalid', 'true');
    input.focus();
  } else {
    error.textContent = '';
    input.removeAttribute('aria-invalid');
  }
});

novalidate 关闭浏览器的气泡提示，改用页面内的错误文字。约束依然存在，checkValidity() 照常工作。

跨字段规则

JavaScript
confirm.addEventListener('input', () => {
  confirm.setCustomValidity(
    confirm.value === password.value ? '' : '两次密码不一致',
  );
});

原生校验做不到的

  • 异步检查，例如“用户名已被占用”，需要请求服务器。
  • 依赖业务数据的规则，例如库存、权限。
  • 浏览器默认气泡的样式、时机和语言无法定制，读屏体验也不一致，多数产品会改用自定义提示。

错误提示的无障碍

  • 错误文字放在页面里，通过 aria-describedby 关联到控件。
  • 提交失败时把焦点移到第一个错误字段，或在表单顶部列出错误并链接到各字段。
  • 不要只用红色边框表示错误，要有文字说明。

常见追问

  • pattern 要不要写 ^ 和 $？不用，pattern 默认匹配整个值，并且使用 v 标志编译正则。
