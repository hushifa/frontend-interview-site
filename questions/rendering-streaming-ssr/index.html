React 流式 SSR 解决什么问题？

流式 SSR 先把 Suspense 边界以外的页面外壳发送给浏览器，慢的部分先显示 fallback，数据就绪后再以 HTML 片段和内联脚本补上。用户能更早看到内容，客户端也可以按区域逐步 hydration。React 19.2 在此基础上新增了 resume 系列 API，用于部分预渲染。

参考答案

简答

  • 传统 SSR 要等整页数据都准备好才能发送 HTML，最慢的请求决定首字节时间。
  • 流式 SSR 以 <Suspense> 为边界：外壳先发送，边界内的内容就绪后再流式补上，替换掉 fallback。
  • Node 中用 renderToPipeableStream，Web Streams 环境（Deno、边缘运行时）用 renderToReadableStream。
  • 状态码只能在开始发送前确定，所以在 onShellReady 或 onShellError 中设置；边界内出错时 React 发送 fallback，并在客户端重试渲染该部分。
  • React 19.2 新增 resume、resumeToPipeableStream 等 API：prerender 现在可以返回 postponed 状态，构建时预渲染静态部分，请求时再从中断处继续渲染动态部分。

示例

JSX
function App() {
  return (
    <html>
      <body>
        <Header />
        <Suspense fallback={<p>评论加载中…</p>}>
          <Comments />
        </Suspense>
      </body>
    </html>
  );
}
JavaScript
import { renderToPipeableStream } from 'react-dom/server';

app.get('*', (req, res) => {
  let didError = false;
  const { pipe, abort } = renderToPipeableStream(<App />, {
    bootstrapScripts: ['/main.js'],
    onShellReady() {
      res.statusCode = didError ? 500 : 200;
      res.setHeader('Content-Type', 'text/html');
      pipe(res);
    },
    onShellError() {
      res.statusCode = 500;
      res.send('<h1>出错了</h1>');
    },
    onError(err) {
      didError = true;
      console.error(err);
    },
  });
  setTimeout(() => abort(), 10_000);
});
  • onShellReady：外壳渲染完成，开始发送。
  • onShellError：外壳渲染失败，还没有发送任何内容，可以返回备用页面。
  • onAllReady：全部内容完成，适合给爬虫或静态生成使用，此时没有渐进效果。
  • abort()：超时后把剩余边界的 fallback 发送出去，由客户端继续渲染。

浏览器收到什么

  1. 外壳 HTML，Comments 的位置是 fallback。
  2. 评论数据就绪后，同一个响应中追加一段隐藏的 HTML 和一小段内联脚本，脚本把它移到 fallback 的位置。
  3. 客户端 JS 加载后，React 可以先 hydration 已到达的部分；用户点击某个未 hydration 的区域时，优先 hydration 该区域。

状态码与边界放置

由于外壳发出后就不能再改状态码，决定 404、重定向的数据应在外壳中加载（不放进 Suspense），例如"文章是否存在"。评论、推荐这类不影响状态码的内容放进 Suspense。

React 19.2 起，服务端渲染的 Suspense 边界会被短暂地批量显示，与客户端行为保持一致。

部分预渲染

JavaScript
import { prerender } from 'react-dom/static';
import { resume } from 'react-dom/server';

// 构建时
const { prelude, postponed } = await prerender(<App />, { signal });
// 请求时
const stream = await resume(<App />, postponed);

构建时得到的 prelude 是可以缓存到 CDN 的静态 HTML，postponed 记录了哪些部分需要在请求时完成。Next.js 的 Cache Components 就基于这种模式，见《Next.js App Router 中的几层缓存怎样区分？》。

React 19.2 也让 Web Streams 版本的 API 可以在 Node 中使用，但官方仍推荐在 Node 中使用 Node Streams 版本，速度更快且支持压缩。

常见追问

  • 流式输出对 SEO 有影响吗？主流爬虫能处理流式 HTML；需要保证完整内容时，可以对爬虫使用 onAllReady。
  • 中间代理会缓冲响应吗？某些代理或压缩配置会等待完整响应再转发，部署时要确认流式输出确实生效。
