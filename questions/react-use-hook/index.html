React use API 可以读取哪些值？

use 在渲染中读取 React 支持的资源，常见的是 Promise 与 Context；canary 版本还支持 browser()。它配合 Suspense 和错误边界工作，不是对任意值或普通异步函数的自动缓存器。

参考答案

简答

use 在渲染中读取资源，目前支持 Promise 和 Context；canary 版本还支持 browser()。读取未完成的 Promise 会挂起组件，由最近的 Suspense 显示 fallback，rejected 时交给 Error Boundary。与其他 Hook 不同，use 可以在条件和循环中调用。传给 use 的 Promise 必须是缓存的同一个实例，不能每次渲染都新建。

use 让组件在渲染时表达“我需要读取这个资源的结果”。读取 Promise 时，未完成就参与 Suspense 等待，成功后返回兑现值，拒绝则按错误路径交给边界；读取 Context 时，则取得最近 Provider 提供的值。

它不是一个能接受任何对象的通用解包函数，也不等于在事件处理器里 await 一个请求。

Promise 要在重新渲染之间保持正确身份

下面在用户点击时创建 Promise，把它存到已存在的父组件状态中，再交给 Suspense 内部的组件读取。延迟只是演示，不包含网络请求。

JSX
import { createContext, Suspense, use, useState } from 'react';

function Message({ messagePromise }) {
  const message = use(messagePromise);
  return <p>{message}</p>;
}

export default function PromiseReader() {
  const [messagePromise, setMessagePromise] = useState(null);
  const [revision, setRevision] = useState(0);

  function load() {
    const promise = new Promise(resolve => {
      setTimeout(() => resolve('消息已就绪'), 300);
    });
    setMessagePromise(promise);
  }

  return (
    <section>
      <button type="button" onClick={load}>读取消息</button>
      <button type="button" onClick={() => setRevision(value => value + 1)}>无关重渲染</button>
      <p>版本：{revision}</p>
      <Suspense fallback={<p role="status">等待消息</p>}>
        {messagePromise ? <Message messagePromise={messagePromise} /> : <p>尚未读取</p>}
      </Suspense>
    </section>
  );
}

点击后，Message 读取尚未完成的 Promise，最近的 Suspense 显示等待提示。Promise 就绪后，React 再尝试渲染 Message，use 返回字符串。

此时触发父组件的无关更新，不会每次新建一个不同 Promise，因为真正的创建发生在事件处理器中，状态持有的是同一个引用。点击“读取消息”则有意创建一份新资源。

为什么不能每次渲染都直接创建请求 Promise

如果组件一渲染就执行一个总会返回新 Promise 的请求函数，再立即 use 它，重新尝试渲染时可能又换成另一个未完成对象，导致重复请求或未缓存 Promise 的诊断。

把它随手放进同一个会在首次挂起时被重新尝试的组件 useMemo，也不是通用保证：首次尚未提交的缓存可能被丢弃。应由合适的数据源、框架缓存、服务器传入的资源，或已经明确持有身份的上层逻辑提供 Promise。

use 本身不定义过期时间、请求去重、权限边界或刷新策略。对服务器读取和客户端重新获取，应按环境选择数据层，而不是把所有 Promise 都存到一个永久模块级 Map 中。

也不要读取或修改 Promise 上看似存在的 status、value 字段来绕过 use。这些不是普通 Promise 的公共契约，React 需要通过自己的读取流程协调 Suspense 与重试。

Context 读取允许条件调用，但仍有上下文要求

以下组件沿用前面的导入：

JSX
const ThemeContext = createContext('light');

function ThemeLabel({ visible }) {
  if (!visible) return null;
  const theme = use(ThemeContext);
  return <p data-theme={theme}>当前主题：{theme}</p>;
}

export function ThemeDemo() {
  const [dark, setDark] = useState(false);
  const [visible, setVisible] = useState(true);
  return (
    <ThemeContext value={dark ? 'dark' : 'light'}>
      <button type="button" onClick={() => setDark(value => !value)}>切换主题</button>
      <button type="button" onClick={() => setVisible(value => !value)}>切换可见性</button>
      <ThemeLabel visible={visible} />
    </ThemeContext>
  );
}

use 与大多数常规 Hook 的调用限制不同，可以出现在这种条件路径中，也可以在符合规则的循环中使用。但它仍必须在组件或 Hook 的 React 执行上下文中调用，不能当成普通工具函数在 onClick 里随意读资源。

Context 值来自上方最近的 Provider，没有 Provider 时才使用创建时的默认值。它不能读取当前组件稍后 return 出来的 Provider，也不能让真正的 Server Component 直接消费客户端 Context。

不要用 try/catch 包住 use 来处理等待

use 需要把等待或错误交给 React 协议处理。把它包在普通 try/catch 中，可能把框架用于协调渲染的流程截断，因此应使用 Suspense 与 Error Boundary，而不是捕获后自己猜测抛出的值。

若某种拒绝属于可接受的业务降级，可以在创建资源时把拒绝转换成明确的替代结果，再让 use 读取这份稳定 Promise。不要在每次渲染里重新调用 catch 创建新 Promise，又回到身份不稳定的问题。

拒绝后的重试也需要更换或刷新真正的数据资源。仅让组件多渲染一次，并不意味着已经缓存的失败 Promise 自动变成新的请求。

服务端读取与客户端读取需要分清

支持 Server Components 的环境中，服务器可以创建 Promise 并把允许的结果跨边界传给 Client Component，客户端 use 再与 Suspense 协作。跨边界值仍受序列化协议约束，不能把任意函数或运行时实例当成普通资源值传递。

在适合 async Server Component 的地方，await 通常更自然：它在等待后继续当前执行，而 use 的挂起可能使组件从头重新尝试。选择应结合框架和组件种类，不是把所有 await 都替换成 use。

Canary 中的浏览器专属资源

react.dev 当前记录了 react-dom 导出的 browser()，目前只出现在 canary 版本（示例固定为 19.3 canary），稳定版不能使用。use(browser('原因')) 在服务端渲染时挂起，HTML 输出最近 Suspense 的回退内容；到浏览器中返回 undefined，组件正常渲染。组件外面必须有 Suspense 边界，在 RSC 应用中只能写在 Client Component 里。

这与 Promise、Context 是不同的资源语义。不要据此推断 use 能识别任意自制的“资源对象”，也不要以为导入浏览器 API 的模块副作用已经被边界隔离。

最终应先明确资源由谁创建、身份能否稳定、何时刷新、失败怎样恢复，再用 use 读取它。这样 Suspense 等待的是一个有清楚生命周期的资源，而不是每次渲染临时产生的新任务。
