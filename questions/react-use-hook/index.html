React use API 可以读取哪些值？

use 可以在渲染时读 Promise 或 Context。Promise 还没完成时组件进入等待，由外层 Suspense 显示加载提示，失败交给 Error Boundary。它能写在 if 里，但传进去的 Promise 必须缓存，不能在渲染时新建。

参考答案

简答

use 能读两种东西。use(context) 跟 useContext 一样，读最近的 Context 值。use(promise) 读一个 Promise 的结果。

读 Promise 时，如果它还没完成，组件就会暂停渲染，这叫挂起，最近的 Suspense 会显示 fallback。完成后组件继续渲染，use 返回结果；失败了，错误交给最近的 Error Boundary。

它的特别之处是它不是 Hook，可以写在 if 和循环里。但也只能在组件或 Hook 中调用，而且不能包在 try/catch 里。

最要注意的是 Promise 必须在多次渲染之间保持同一个实例，通常来自 Server Component 传下来的 props、数据请求库或缓存。在渲染里写 use(fetch(url)) 会不断重新请求。另外，Server Components 里直接用 await 就行，use(context) 也不能在 Server Components 里用。

服务端发请求，客户端读结果

常见用法是在 Server Component 里发起请求，但不等它，把 Promise 直接传给客户端组件：

JSX
// app/page.jsx（Server Component）
import { Suspense } from 'react';
import { Comments } from './comments';

export default async function Page({ params }) {
  const { id } = await params; // Next.js 15 起 params 是 Promise
  const commentsPromise = getComments(id); // 不 await，立即开始请求
  return (
    <Suspense fallback={<p>评论加载中…</p>}>
      <Comments commentsPromise={commentsPromise} />
    </Suspense>
  );
}

客户端组件用 use 读它：

JSX
// app/comments.jsx
'use client';

import { use } from 'react';

export function Comments({ commentsPromise }) {
  const comments = use(commentsPromise);
  return <ul>{comments.map((c) => <li key={c.id}>{c.text}</li>)}</ul>;
}

为什么不在 Page 里 await 完再传？因为那样整个页面都要等评论回来。现在页面其他部分先显示，评论区先显示“评论加载中”，数据到了再填进去。注意 Promise 的结果要从服务端传到客户端，所以必须可序列化。

在提前 return 之后读 Context

useContext 是 Hook，必须在顶层调用。use 没有这个限制：

JSX
function Heading({ children }) {
  if (children == null) return null;
  const theme = use(ThemeContext); // 提前 return 之后调用，useContext 做不到
  return <h1 style={{ color: theme.color }}>{children}</h1>;
}

use 能这样写，是因为它读的是你传进去的 Context 本身，不需要靠调用顺序去找自己的状态，详见《为什么 Hook 通常必须在组件顶层调用？》。

为什么 Promise 必须缓存

下面这种写法看起来很自然，却永远加载不出来：

JSX
// 错误：每次渲染都创建新 Promise，组件反复挂起
function Profile({ id }) {
  const user = use(fetch(`/api/users/${id}`).then((r) => r.json()));
}

第一次渲染时创建了一个 Promise，没完成，组件挂起。等 React 重新渲染这个组件，又执行了一遍 fetch，得到另一个新的 Promise，还是没完成，又挂起。就这样一直在等新请求，React 会警告 “A component was suspended by an uncached promise”。

客户端组件里要发请求，可以在事件处理器或路由 loader 里创建 Promise，存进 state；或者用支持 Suspense 的数据请求库，由它负责缓存。

失败了怎么处理

在 Suspense 外面再包一层 Error Boundary，Promise 失败时显示错误界面：

JSX
<ErrorBoundary fallback={<p>加载失败</p>}>
  <Suspense fallback={<p>加载中…</p>}>
    <Comments commentsPromise={commentsPromise} />
  </Suspense>
</ErrorBoundary>

如果不想显示错误界面，可以在创建 Promise 的地方加 .catch(() => [])，失败时给一个兜底值。

常见追问

和 await 有什么区别？

await 只能在 async 函数里用，而客户端组件不能是 async 函数。use 让普通的组件函数也能“等”一个 Promise。

数据要刷新怎么办？

在 startTransition 里创建一个新的 Promise 存进 state，组件读到新 Promise。因为在 Transition 里，等待期间会保留旧内容，不会退回 fallback。
