怎样正确消费 Fetch 返回的 ReadableStream？

response.body 是字节流，用 for await 或 getReader() 逐块读取，配合 TextDecoderStream 解码文本；按行或按事件解析时要缓存跨块的残余数据，并在取消或出错时释放流。

参考答案

简答

  • response.body 是 ReadableStream<Uint8Array>，数据到一块就能处理一块，不必等整个响应下载完。
  • 文本流用 pipeThrough(new TextDecoderStream()) 解码，多字节字符被拆在两块之间也能正确处理。
  • 块的边界和业务上的"行"或"消息"无关，解析时要把最后一段不完整的数据留到下一块拼接。
  • 用 AbortController 取消 fetch，流会随之出错并停止；只读部分数据时要调用 reader.cancel() 释放连接。

按行解析 NDJSON

JavaScript
async function* readLines(response) {
  const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
  let buffer = '';
  let finished = false;
  try {
    while (true) {
      const { value, done } = await reader.read();
      if (done) break;
      buffer += value;
      const lines = buffer.split('\n');
      buffer = lines.pop();
      for (const line of lines) if (line.trim()) yield JSON.parse(line);
    }
    if (buffer.trim()) yield JSON.parse(buffer);
    finished = true;
  } finally {
    // 调用方提前 break 或解析出错时取消流，停止下载；releaseLock 本身不会取消
    if (!finished) await reader.cancel().catch(() => {});
    reader.releaseLock();
  }
}

const controller = new AbortController();
const response = await fetch('/api/export', { signal: controller.signal });
if (!response.ok) throw new Error(`HTTP ${response.status}`);
for await (const row of readLines(response)) appendRow(row);
  • lines.pop() 取出最后一段可能不完整的内容，留在 buffer 里。
  • 流结束后处理没有换行结尾的最后一行。
  • 消费方提前 break 时，生成器的 finally 会执行，释放读取锁。

其他读取方式

  • 不需要逐块处理时，直接 response.text() 或 response.json() 更简单。
  • 显示下载进度：读取每块的 value.byteLength 累加，和 Content-Length 比较。响应被压缩时，Content-Length 是压缩后的大小，与读到的字节数不一致。
  • 支持异步迭代的环境可以直接 for await (const chunk of stream)。

常见追问

  • 一个流能读两次吗：不能，读取时会被锁定。需要两份时用 tee()，见《ReadableStream 的 tee 分流有什么代价？》。
  • SSE 能这样解析吗：可以，按空行分隔事件，但更推荐用成熟的解析库处理 data:、id: 和重连字段。
