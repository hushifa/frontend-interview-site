useRef、useEffect 和 useLayoutEffect 有什么差别？

useRef 保存跨渲染的可变引用，不负责触发界面更新；Effect 与 Layout Effect 则安排外部同步，后者会在绘制前执行并阻塞绘制。是否需要测量与同步视觉修正，决定应该采用哪种时机。

参考答案

这三个 Hook 不是三个可以互换的生命周期函数。useRef 提供一个存放可变值的容器；useEffect 与 useLayoutEffect 则让 React 在相应阶段运行设置和清理逻辑。

常见组合是：用 ref 找到已提交的 DOM，再用合适的 Effect 测量或同步它。不能因为都有 use 前缀，就认为 ref 修改会自动触发 Effect 或重新渲染。

ref 保存对象，但不负责刷新界面

JSX
import { useRef, useState, useLayoutEffect } from 'react';

export default function FocusInput() {
  const inputRef = useRef(null);

  return (
    <section>
      <label>
        搜索
        <input ref={inputRef} />
      </label>
      <button type="button" onClick={() => inputRef.current?.focus()}>
        聚焦输入框
      </button>
    </section>
  );
}

组件存活期间，useRef 返回的 ref 对象可以跨渲染保持。React 把实际输入 DOM 关联到 current，事件处理器就可以执行 focus 这样的命令式操作。

首次渲染期间，DOM 还没有提交，current 可能是 null；卸载时也要考虑引用被清除。不能在组件函数刚开始执行时，就假定 ref.current 已经指向这轮要显示的节点。

修改 ref.current 不会请求重新渲染。计时器 ID、外部实例等不直接决定显示的值可以放这里；如果值变化应该立即改变文字或组件结构，通常应放在 state，而不是等别的更新顺便把 ref 显示出来。

两种 Effect 的关键差别是绘制时机

useEffect 适合订阅、网络和其他不需要同步阻塞绘制的外部关系。它在提交之后运行，但不保证所有场景都严格晚于浏览器 paint。

useLayoutEffect 在相关 DOM 已经应用后、浏览器重新绘制前执行。它适合必须先测量再修正位置的情况，例如避免浮层先画错位置再跳动，但其中的代码和同步更新会延迟绘制。

因此 Layout Effect 不是“更高级的 Effect”。如果任务不需要挡住用户看到画面，就不应为了一点模糊的时序安全感把所有 Effect 都改成它。

测量应包括后续尺寸变化，而不只读一次

下面的组件沿用前面的导入，先在布局阶段测量标题，再使用 ResizeObserver 观察字体、内容布局等造成的尺寸变化：

JSX
export function MeasuredTitle({ text, width = 240 }) {
  const titleRef = useRef(null);
  const [height, setHeight] = useState(0);

  useLayoutEffect(() => {
    const node = titleRef.current;
    if (!node) return;

    function measure() {
      const nextHeight = Math.round(node.getBoundingClientRect().height);
      setHeight(previous => previous === nextHeight ? previous : nextHeight);
    }

    measure();
    const observer = new ResizeObserver(measure);
    observer.observe(node);
    return () => observer.disconnect();
  }, [text, width]);

  return (
    <section>
      <div ref={titleRef} style={{ width, fontSize: 20, lineHeight: '24px' }}>
        {text}
      </div>
      <output aria-label="标题高度">{height}</output>
    </section>
  );
}

text 或 width 改变后，新 DOM 提交，再测量这一轮的高度；观察器处理后续尺寸变化。清理会断开上一轮观察，避免重复订阅。

示例把测量结果显示在独立区域，没有反过来用这个高度不断改变被测量元素自身尺寸。真实浮层定位若形成“测量改变尺寸、尺寸又触发测量”的反馈循环，需要调整算法或约束，不能只靠加 Layout Effect 解决。

getBoundingClientRect 会反映相应布局与变换后的几何结果。字体加载、图片尺寸、容器宽度和缩放都可能改变结果，所以一次挂载测量并不总够用。ResizeObserver 也不能替代对滚动位置、视口位置和所有定位条件的观察。

不要在渲染里用 ref 绕过状态模型

组件渲染应主要根据 props、state、context 计算 UI。随意读取或写入 ref.current 来影响渲染，会让结果依赖未被 React 调度管理的可变信息，尤其在重试或中断计算时更难推理。

对于可预测、只在初始化时建立的纯粹值，可以按官方规则使用受控的 ref 初始化模式。但不要把网络连接、订阅或需要清理的副作用藏进这种“只初始化一次”的分支。

useRef(createValue()) 的参数表达式仍可能在每次渲染时求值，React 忽略后续初始值不代表这个函数没被调用。把函数本身传给 useRef，也不会像 useState 的惰性初始化那样自动调用它，而是把函数作为 current 保存。

DOM ref 与自定义组件边界

给原生 input 传 ref，React 可以关联到该 DOM。给自定义组件传 ref，则需要组件按所用 React 版本的约定接收并继续暴露合适目标，不能期待 React 自动找到任意深处的输入框。

较新 React 与旧版 forwardRef 用法存在差异，应按版本和组件 API 处理。若组件只希望暴露 focus、reset 等有限能力，可以设计相应命令式接口，而不必把全部内部 DOM 结构都泄漏给调用者。

服务端没有真实布局可以测量

useLayoutEffect 不在服务端执行，服务端也没有浏览器 DOM 尺寸。依赖测量才能确定位置的组件，需要合理的初始布局、客户端边界或相应回退，不能把服务端算出的 0 当作真实测量结果。

开发 Strict Mode 还会检查设置与清理的配对，观察器和事件都应能正确断开。最后用浏览器工具确认布局、绘制与交互成本：如果只是延迟问题换成了同步阻塞，画面不闪了但操作更卡，也不能算完成优化。
