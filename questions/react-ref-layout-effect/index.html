useRef、useEffect 和 useLayoutEffect 有什么差别？

useRef 用来存一个跨渲染不变、改了也不触发渲染的值；useEffect 在 DOM 更新后执行，通常在浏览器画完之后；useLayoutEffect 在浏览器画之前执行，适合测量布局并马上修正，但会推迟画面显示。

参考答案

简答

useRef 返回一个 { current } 对象，组件存在多久，它就是同一个对象。常用来拿 DOM 节点，或者存定时器 ID 这种不用显示的值。改 current 不会让组件重新渲染。

useEffect 和 useLayoutEffect 都在 React 把改动写进 DOM 之后执行，区别在于跟浏览器绘制的先后。useEffect 通常在浏览器把画面画出来以后才执行，不挡着画面。useLayoutEffect 在绘制之前同步执行，你可以读到元素的真实尺寸，在用户看到之前把位置改对。

所以 useLayoutEffect 适合“先测量、再定位”的场景，比如提示框、弹出菜单。可是它会推迟绘制，所以默认用 useEffect，只有画面出现闪烁时才换。

还要注意，渲染期间不要读写 ref.current（初始化除外），否则渲染结果就不只由 props 和 state 决定了。

用 useLayoutEffect 给提示框定位

提示框要显示在按钮上方，可是放不下时得改放到下方。放不放得下，要先知道提示框有多高，而高度只有渲染出来才量得到。

JSX
import { useLayoutEffect, useRef, useState } from 'react';

function Tooltip({ anchorRect, children }) {
  const ref = useRef(null);
  const [height, setHeight] = useState(0);

  useLayoutEffect(() => {
    setHeight(ref.current.getBoundingClientRect().height);
  }, [children]);

  const spaceAbove = anchorRect.top;
  const top = spaceAbove > height ? anchorRect.top - height : anchorRect.bottom;

  return (
    <div ref={ref} style={{ position: 'fixed', left: anchorRect.left, top }}>
      {children}
    </div>
  );
}

过程是这样的：第一次渲染时 height 还是 0，按这个值算出位置并提交到 DOM。接着 useLayoutEffect 执行，量到真实高度，调用 setHeight。因为这一切都发生在浏览器绘制之前，React 会同步再渲染一次，用户只看到最终的正确位置。

如果换成 useEffect，浏览器可能已经把高度为 0 时的错误位置画了出来，下一帧才跳到正确位置，用户就会看到提示框闪一下。

用 ref 存不需要显示的值

下面是一个秒表。定时器 ID 只在开始和停止时用，不显示在页面上，所以放在 ref 里。

JSX
function Stopwatch() {
  const intervalRef = useRef(null);
  const [seconds, setSeconds] = useState(0);

  function start() {
    clearInterval(intervalRef.current);
    intervalRef.current = setInterval(() => setSeconds((s) => s + 1), 1000);
  }

  function stop() {
    clearInterval(intervalRef.current);
  }

  return (
    <>
      <span>{seconds}s</span>
      <button onClick={start}>开始</button>
      <button onClick={stop}>停止</button>
    </>
  );
}

为什么不用 state 存 ID？因为改 state 会触发重新渲染，而 ID 变了页面上什么都不用变，白白多渲染一次。要显示的 seconds 才放进 state。

那为什么不用普通变量？组件每次渲染都会重新执行一遍，普通变量每次都会被重新初始化，上一次存的 ID 就丢了。ref 能在多次渲染之间保持同一个值。

服务端渲染时怎么办

服务端不执行任何 Effect，也没有布局信息可测。所以依赖 useLayoutEffect 测量的组件，服务端渲染出的 HTML 只能是测量之前的样子。常见做法是让这类组件只在客户端渲染，或者首屏先显示一个不依赖测量的占位。

React 19 里 ref 有什么变化

函数组件现在可以直接把 ref 当 prop 接收，新代码不再需要 forwardRef。另外，ref 回调可以返回一个清理函数，节点卸载时 React 会调用它。

常见追问

useLayoutEffect 和 useEffect 的清理时机一样吗？

一样，都是在下一次执行之前和组件卸载时清理。区别只在执行的阶段，一个在绘制前，一个通常在绘制后。

提交阶段这几件事的先后顺序是什么？

先改 DOM，然后设置 ref、执行 useLayoutEffect，接着浏览器绘制，最后执行 useEffect（点击这类交互触发的更新，useEffect 也可能在绘制前执行）。详见《React 的渲染阶段与提交阶段有什么区别？》。
