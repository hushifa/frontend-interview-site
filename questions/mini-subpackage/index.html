小程序的分包、独立分包和分包预下载分别解决什么问题？

分包让小程序启动时只下载必需的部分，其余用到再下。讲清 subPackages 的配置与引用规则、独立分包的启动特性与限制、preloadRule 预下载配置，以及分包异步化的作用。

参考答案

简答

小程序第一次打开要先下载代码包，包越大等得越久。分包就是把页面按功能拆成一个主包和多个分包，启动时只下主包，进到某个分包的页面时再下那个分包。官方说这是优化启动耗时效果最明显的手段。

分包有引用规则：分包之间不能互相引用 JS、template 和资源，只能用主包和自己的内容；tabBar 页面必须放在主包。

独立分包更进一步，它不依赖主包也能运行。从独立分包的页面启动时，连主包都不下载，适合活动页、广告页这类独立场景。代价是用不了主包的内容，getApp() 也可能拿不到 App。

分包预下载是在 app.json 里配 preloadRule，进入某个页面时提前把之后可能用到的分包下好，减少第一次进分包页面的等待。另外还有分包异步化，它把粒度细到组件和文件，让主包里的部分组件和逻辑也能拆到分包里异步加载。

普通分包怎么配

下面的配置有两个分包，packageA 和 packageB：

json
{
  "pages": ["pages/index", "pages/logs"],
  "subPackages": [
    { "root": "packageA", "pages": ["pages/cat", "pages/dog"] },
    { "root": "packageB", "name": "pack2", "pages": ["pages/apple"] }
  ]
}

subPackages 配置的路径以外，所有目录都会打进主包。分包的根目录也不能嵌套在另一个分包里。另外，tabBar 页面必须放在主包。

引用规则要记清楚。packageA 不能 require packageB 的 JS，也不能引用 packageB 的 template 和资源，但可以用主包和自己的内容。用了分包异步化时，JS 不受这个限制。

所以代码该放哪里，要看谁在用。多个分包都要用的工具代码放主包。只在某个分包用到的组件和插件，就在那个分包里引用，不要写进 app.json 的全局 usingComponents，否则它会跟着主包一起下载和注入，白白增加启动负担。

独立分包有什么不一样

在分包配置里加上 "independent": true，它就成了独立分包，一个小程序可以有多个。

因为它要能单独运行，所以不能依赖主包和其他分包的 JS、template、wxss、自定义组件、插件。分包异步化场景下，JS、自定义组件和插件除外。主包的 app.wxss 对它也无效，独立分包里也不能定义 App。

最容易出问题的是 getApp()。从独立分包启动时，App 还没注册，getApp() 会返回 undefined。这时可以用 getApp({ allowDefault: true }) 拿到一个默认实现，等主包加载以后，里面的属性会合并到真正的 App 上。

生命周期也会推迟。App 的 onLaunch 和第一次 onShow，要等用户第一次进入主包或普通分包的页面时才调用。独立分包里想监听应用的生命周期，可以用 wx.onAppShow、wx.onAppHide。

还有兼容问题。在不支持独立分包的旧版微信上，独立分包会被当成普通分包，主包的 app.wxss 可能影响它的样式。所以独立分包不要依赖 app.wxss。

分包预下载怎么配

json
{
  "preloadRule": {
    "pages/index": { "network": "all", "packages": ["important"] },
    "indep/index": { "packages": ["__APP__"] }
  }
}

key 是触发预下载的页面路径。比如用户进了 pages/index，就开始下 important 这个分包。packages 里填分包的 root 或 name，__APP__ 表示主包，所以第二条的意思是：用户在独立分包页面时，提前把主包下好。

network 默认是 wifi，设成 all 表示任何网络下都预下载。

预下载目前只能通过配置使用，不能用 API 触发。同一个分包里的页面共享预下载的大小限额，官方文档写的是 2M，打包时由开发者工具校验。

常见追问

分包能放多少代码？

官方文档写明，整个小程序所有分包加起来不超过 30M，服务商代开发的小程序不超过 20M；单个分包或主包不能超过 2M。具体以微信开放文档《分包加载》为准。

图片要放进分包吗？

代码包里的图片、字体这类资源很难再压缩，对下载耗时的影响比代码还大。所以官方建议放到 CDN 上用 URL 引用，包里只留小图标。
