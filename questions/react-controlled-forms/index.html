React 里复杂表单怎样组织？校验、提交状态和错误怎么处理？

字段多的表单先决定状态放哪里：只在提交时要值的字段用非受控加 FormData，要联动或实时校验的字段才用受控。受控字段用一个对象 state 统一管理，能从已有值算出来的结果在渲染时计算，不另存 state。React 19 的 form action 配合 useActionState 拿到提交结果和 isPending，抛出的错误交给 Error Boundary。中文输入法组合期间不要改写输入框的值。

参考答案

简答

一个注册表单有十几个字段，有的只是提交时才要值，有的要边输边校验，还有的会决定别的字段显不显示。组织这种表单，第一步是决定每个字段的值放在哪里。

只在提交时要值的字段，用非受控加 FormData，不用给每个字段建 state。要实时校验、格式化或联动的字段，才用受控。受控的字段多了，可以放进一个对象 state 里统一更新；像“按钮能不能点”“哪些字段报错”这种能从已有值算出来的结果，react.dev 建议在渲染时直接算，不要另存一份 state。

提交用 React 19 的 <form action>，函数直接收到 FormData。配合 useActionState，能拿到上一次提交返回的结果，比如服务端的错误信息，还有一个 isPending 表示正在提交。Action 里抛出的错误会交给最近的 Error Boundary。

还要注意中文输入法。拼音还没选字时，受控输入框的 onChange 也会触发，在里面截断、过滤，就可能把没打完的拼音改掉。

字段的值放在哪里

受控和非受控的概念见《React 中的受控组件和非受控组件是什么？》。到了复杂表单，问题变成每个字段该选哪种。判断方法是看什么时候需要这个值：

什么时候用到这个值写法
只在提交时非受控，写 name 和 defaultValue，提交时从 FormData 取
输入时要实时校验或格式化受控
会决定别的字段显示什么受控
第三方组件只能操作 DOM非受控加 ref

为什么不全部写成受控？受控输入框每敲一个字，state 所在的组件就重新渲染一次。字段都放在表单顶层的话，敲一个字整个表单都要渲染，字段多了会卡。只把真正需要实时处理的字段做成受控，其他交给浏览器保管，渲染范围就小得多。

受控字段多了怎样管理

下面的表单有三个受控字段，放在一个对象里：

JSX
function SignupForm() {
  const [values, setValues] = useState({ email: '', password: '', confirm: '' });

  function handleChange(e) {
    const { name, value } = e.target;
    setValues({ ...values, [name]: value });
  }

  const errors = {
    email: values.email && !values.email.includes('@') ? '邮箱格式不对' : '',
    confirm: values.confirm && values.confirm !== values.password ? '两次密码不一致' : '',
  };
  const canSubmit = values.email && values.password && !errors.email && !errors.confirm;

  return (
    <form>
      <input name="email" value={values.email} onChange={handleChange} />
      {errors.email && <p>{errors.email}</p>}
      <input name="password" type="password" value={values.password} onChange={handleChange} />
      <input name="confirm" type="password" value={values.confirm} onChange={handleChange} />
      {errors.confirm && <p>{errors.confirm}</p>}
      <button disabled={!canSubmit}>注册</button>
    </form>
  );
}

一个 handleChange 按 name 更新对应的字段。更新对象时要写 { ...values, [name]: value }，react.dev 提醒过，对象 state 不能只传改动的那一个字段，否则其他字段就丢了。

errors 和 canSubmit 为什么不放进 state？它们完全由 values 决定。react.dev 的原则是，能在渲染时从 props 或已有 state 算出来的信息，就不要放进 state。另存一份的话，每次改 values 都要记得同步改它们，忘一次界面就不一致了。

提交状态和服务端错误怎么处理

提交时要做三件事：按钮显示“提交中”、防止重复点击、把服务端返回的错误显示出来。React 19 里用 useActionState 可以一起处理：

JSX
import { useActionState } from 'react';

async function signup(prevState, formData) {
  const response = await fetch('/api/signup', { method: 'POST', body: formData });
  if (!response.ok) return { error: '注册失败，请稍后再试' };
  return { error: '' };
}

function SignupForm() {
  const [state, formAction, isPending] = useActionState(signup, { error: '' });

  return (
    <form action={formAction}>
      <input name="email" type="email" required />
      <input name="password" type="password" required />
      {state.error && <p role="alert">{state.error}</p>}
      <button disabled={isPending}>{isPending ? '提交中…' : '注册'}</button>
    </form>
  );
}

useActionState 返回三个值：当前状态、要传给 action 的函数、是否有提交还在进行的 isPending。按 react.dev 的说明，传给它的函数第一个参数是上一次的状态，第二个参数是表单的 FormData，返回值会成为新的状态，所以错误信息直接从 state.error 读。多次提交会按顺序排队执行，每次都拿到上一次的结果。

预期内的失败，比如账号已存在，用返回值表达。真正的异常，action 里抛出的错误会交给最近的 Error Boundary 显示后备界面。另外，Action 成功后，表单里的非受控字段会被自动重置。

中文输入法会出什么问题

用拼音打字时，字还没选定，输入框里是拼音字母，这个阶段叫组合输入。受控输入在组合过程中也会触发 onChange。

如果在 onChange 里做“去掉非数字”“截断长度”这类改写，就可能把还没打完的拼音改掉，打断输入。需要时监听 compositionstart 和 compositionend，组合期间先原样保存，等 compositionend 触发、文字选定后再处理。

常见追问

字段很多时要不要用表单库？

可以。React Hook Form 这类库以非受控为主，用 ref 注册字段，输入时不触发整个表单渲染，校验规则也集中管理。思路和上面一样：只有需要实时处理的值才进 React 状态。

怎么重置表单？

非受控字段调用表单 DOM 的 form.reset()，或者给表单换一个 key，让 React 卸载后重新挂载。受控字段把 state 设回初始值。
