路由并发导航和权限变化应该怎样处理？

用户快速切换页面时，旧导航的请求可能比新导航晚返回，把页面覆盖掉。每次导航要能取消旧请求，并在写入结果前确认它仍属于当前导航。前端守卫只控制界面跳转，权限变化后要清空缓存的数据，接口必须由服务端校验。

参考答案

简答

用户从报表 A 快速切到报表 B，A 的请求比 B 晚回来，结果页面上显示的却是 A 的数据。这种请求先后顺序打乱导致的问题，叫竞态。

解决办法有两道保护。每次导航创建一个 AbortController，新导航开始时取消上一个；写入结果前再检查一下导航序号，防止取消不及时。React Router 的 loader、TanStack Router 这些框架已经内置了这种处理：新导航开始时取消旧的 loader，只提交最新导航的结果。

要注意，取消请求只是让客户端不再等，已经到达服务器的写操作不会被撤销。写操作要靠幂等键，防止重复执行。

权限变化，比如登出、切换账号、角色变更之后，要清空缓存的路由数据和客户端状态，再重新导航。前端守卫只管界面，每个接口仍然要在服务端鉴权。

手写一个只认最新导航的加载器

先看代码，注意 id === seq 这个判断：

JavaScript
function createNavigator(load, commit) {
  let seq = 0;
  let controller;

  return async function navigate(location) {
    controller?.abort();
    controller = new AbortController();
    const id = ++seq;
    try {
      const data = await load(location, controller.signal);
      if (id === seq) commit(location, data);
    } catch (err) {
      if (err.name !== 'AbortError' && id === seq) commit(location, { error: err });
    }
  };
}

既然已经 abort() 了，为什么还要比较序号？用一个不理会取消信号的加载函数试试：

JavaScript
// 模拟一个不理会 signal 的加载函数：A 慢、B 快
const delays = { A: 50, B: 10 };
const load = (loc) =>
  new Promise((resolve) => setTimeout(() => resolve(`报表 ${loc.id}`), delays[loc.id]));
const navigate = createNavigator(load, (loc, data) => console.log('显示', data));

navigate({ id: 'A' });
navigate({ id: 'B' });
// 输出：显示 报表 B

A 的请求虽然被 abort() 了，可加载函数没理会信号，50 毫秒后照样返回了结果。这时 seq 已经是 2，A 的 id 是 1，对不上，所以 A 的结果被丢掉，只显示了 B。

所以 abort() 是为了让旧请求停下、节省网络；id === seq 是第二道保护，用来兜住那些没法取消、或者在取消前就已经完成的异步工作。

实际使用时，load 一般是把 signal 传给 fetch：

JavaScript
const navigate = createNavigator(
  (loc, signal) => fetch(`/api/reports/${loc.id}`, { signal }).then((r) => r.json()),
  (loc, data) => render(loc, data),
);

React Router 里怎么写

JSX
export async function loader({ params, request }) {
  const res = await fetch(`/api/reports/${params.id}`, { signal: request.signal });
  if (res.status === 404) throw new Response('未找到', { status: 404 });
  return res.json();
}

关键是把 request.signal 传给 fetch。新导航开始时，React Router 会中止这个信号，旧请求就停了。

搜索框怎样避免一堆导航

搜索词放在 URL 里时，每输入一个字都可能触发一次导航。通常把三种手段组合起来用。

先防抖，等用户停下 300 毫秒左右再更新 URL。更新地址时用 replace，不然每个字符都会多出一条历史记录，用户按后退要按很多次。最后依靠上面的取消机制，丢弃过期的结果。

权限变化后要做什么

JavaScript
async function logout() {
  await fetch('/api/logout', { method: 'POST' });
  queryClient.clear(); // 清空数据缓存
  router.navigate('/login', { replace: true });
}

为什么登出时一定要清缓存？如果只跳转不清，下一个人在同一个浏览器登录后，点后退可能还会看到上一个用户的数据。

开着多个标签页时，一个标签页登出了，其他标签页也要跟着登出。可以用 BroadcastChannel 或 storage 事件来同步。

路由守卫管到哪一步

前端守卫负责的是“没权限就不显示这个页面、跳到登录页”，这是体验。

真正的保护在服务端。每个 loader 调用的接口、每个写操作，都要校验会话和权限。服务端返回 401 或 403 时，前端再做相应的跳转。

常见追问

用户提交表单后马上离开页面，请求会被取消吗？

要看具体实现。框架通常不会取消正在进行的 action。而且就算取消了，服务器也可能已经写入了，所以写接口要支持幂等。

后退时要重新请求吗？

可以先显示缓存的数据，再在后台刷新。这就是 stale-while-revalidate 策略。
