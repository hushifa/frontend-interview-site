哪些 AI 能力可以直接在浏览器中运行？

浏览器可以用 ONNX Runtime Web、Transformers.js 等运行时执行小型文本、图像和音频模型，通过 WebGPU 或 WASM 计算。能否落地取决于模型大小、算子支持、设备内存和首次下载成本；本地推理也不自动等于离线或隐私。

参考答案

简答

  • 适合浏览器的是小模型任务：文本分类、向量生成、图像分类与分割、语音识别、小型文本生成。大模型的权重和内存需求通常超出普通设备。
  • 运行时负责执行模型，输入要严格匹配模型的张量名、形状、类型和预处理方式；文本还需要配套的 tokenizer。
  • WebGPU 吞吐通常更高，但要求浏览器、显卡和模型算子都支持；WASM 走 CPU，兼容面更广。两者都要做能力检测并准备回退。
  • 首次使用要下载几十 MB 到上 GB 的权重，界面要分别显示下载、初始化和推理阶段。
  • 输入不离开设备是优势，但模型下载、遥测等请求仍会联网；离线使用还要求权重已缓存且没有被浏览器清理。

最小示例

JavaScript
import * as ort from 'onnxruntime-web';

const session = await ort.InferenceSession.create('/models/classifier.onnx', {
  executionProviders: ['webgpu', 'wasm'], // 按顺序尝试，不支持时回退
});

async function classify(pixels) {
  // 输入名、形状和归一化方式都由具体模型决定
  const input = new ort.Tensor('float32', pixels, [1, 3, 224, 224]);
  const outputs = await session.run({ images: input });
  return outputs.logits.data;
}

会话创建一次后复用，不要每次推理都重新加载模型。Transformers.js 在此基础上封装了 tokenizer 和常见任务（pipeline('sentiment-analysis') 等），适合快速接入现成模型。

选型时检查什么

项目问题
模型体积用户能接受多大的首次下载？是否需要量化版本？
算子目标后端是否支持模型用到的全部算子？不支持的会回退 CPU 或直接报错
内存低端手机能否加载？加载失败时有没有云端或降级路径？
质量量化后在真实样本上的准确率是否可接受？
许可证模型权重能否商用和再分发？这和运行时库的开源许可是两回事

界面与资源管理

  • 分别显示"下载模型 xx%""初始化""推理中"，不要一直显示"思考中"。
  • 推理放进 Worker，避免阻塞输入和滚动，细节见《浏览器端 AI 为什么用了 WebGPU 或 Worker 仍可能卡顿？》。
  • 不再使用时释放会话和张量；限制同时加载的模型数量。
  • 用 Cache Storage 或 OPFS 缓存权重，但浏览器在存储压力下可能清理它们，下次启动要能重新下载。
  • 本地推理只说明输入在设备上计算。模型文件从 CDN 下载、运行时或页面的统计上报仍会发出网络请求，宣称"离线"或"数据不出设备"前要检查实际请求。

常见追问

  • navigator.gpu 存在就能用 WebGPU 推理吗？ 不一定。还要能拿到适配器和设备，模型算子也要被 WebGPU 后端支持，最好用真实模型做一次启动探测。
  • 本地推理的输出可以直接信任吗？ 不可以。输出照样可能出错，涉及账号、支付或写操作时仍要服务端校验。
