RAG 应用中，前端除了展示答案还需要关注什么？

RAG 是先查出用户有权看的资料，再让模型照着资料回答。前端要把"没查到资料"和"生成失败"分开显示，引用要对应到这次真实查到的记录，并让用户能点开看原文和版本。

参考答案

简答

RAG 不是把资料训练进模型，而是每次回答之前，先去资料库里查出相关的片段，放进这次请求里让模型参考。查的方式可以是关键词、向量，或者两者结合。

所以回答好不好取决于两步：资料有没有找对，模型有没有老老实实照着资料说。界面上要把“没找到资料”和“生成失败”分开显示。

引用要对得上。模型输出的是引用 ID，前端拿它去本次检索结果里找；找不到的显示为无效引用，模型自己编的 URL 不要渲染。而且有引用不代表引用真的支持这句话，要让用户能展开看原文片段和更新时间，自己核对。

权限要在检索时就过滤好。检索出来的文档里也可能藏着提示词注入，要当成不可信内容处理。

引用怎么对应到真实的资料

下面是引用的数据结构，以及前端怎么查找它：

TypeScript
type Citation = {
  id: string; // 本次检索内唯一
  documentId: string;
  title: string;
  version?: string;
  excerpt: string;
  updatedAt?: string;
};

function resolveCitation(id: string, retrieved: Map<string, Citation>) {
  return retrieved.get(id) ?? null; // 找不到就显示"无效引用"
}

为什么不直接显示模型给的链接？因为模型可能编。它可能写出一个看起来很像样、但根本不存在的文档地址。前端只认这次检索真实返回的记录，模型只负责说“我用了第几条”，标题、链接、原文都从检索记录里取。

文档有多个版本时，引用要指向具体的版本和位置，不要只链到一个会变的首页，不然过几天用户点进去，内容已经对不上了。

还有一点：如果服务端只能给出“整段回答参考了哪些来源”，界面就不要假装成每一句都有对应引用。

每种情况界面显示什么

情况展示
检索中“正在查找资料”，可以显示检索范围
没有足够资料说明没找到，建议换个问法或选择其他数据源，不要让模型凭常识编答案
检索成功、生成失败保留已找到的来源，提供重试
回答完成引用标号可点击展开片段，显示文档标题、版本和更新时间

不要显示“可信度 98%”这种没有计算依据的数字，它会让用户误以为答案经过了验证。

权限为什么要在检索时就过滤

如果先把所有资料都交给模型，再叮嘱它“别把用户没权限的内容说出来”，那权限其实早就越界了，模型已经看到了，说不说只能看运气。所以检索阶段就要按用户、租户、文档权限过滤。

用户点开引用查看原文时，还要再校验一次权限。文档被删了或者权限被撤销了，显示“无法访问”。

别忘了，文档标题和文件名本身也可能是敏感信息，比如“某某裁员名单.xlsx”。

常见追问

用户反馈“答案不对”，怎么定位问题？

一段段查：需要的文档有没有被查出来；排序有没有把错误的片段排到前面；回答是不是真的被片段支持；引用有没有指向正确的版本。所以反馈记录要和这次的检索结果、片段版本关联起来，不然没法复现。

检索出来的内容让模型“忽略之前的指令”怎么办？

这就是间接提示词注入，处理方法见《提示词注入与普通 XSS 有什么区别？》。
