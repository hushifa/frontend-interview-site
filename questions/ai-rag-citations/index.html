RAG 应用中，前端除了展示答案还需要关注什么？

RAG 先检索用户有权访问的资料，再让模型基于这些资料回答。前端要分开展示检索失败和生成失败，把引用绑定到真实的检索记录，并让用户能查看原文片段和版本。

参考答案

简答

  • RAG 不是把资料训练进模型，而是每次回答前检索相关片段，放进本次请求的上下文。检索可以用关键词、向量或混合方式。
  • 回答质量取决于两段：资料有没有找对，模型有没有忠实使用资料。界面要分别显示"没找到资料"和"生成失败"。
  • 模型输出引用 ID，前端把它映射到本次检索返回的记录上；不在本次结果里的 ID 显示为无效，不渲染模型自己编的 URL。
  • 有引用不等于引用支持这句话，界面提供可展开的原文片段和更新时间，让用户自己核对。
  • 权限过滤在检索阶段完成。检索到的文档也可能含有提示词注入，按不可信内容处理。

引用怎样绑定

TypeScript
type Citation = {
  id: string; // 本次检索内唯一
  documentId: string;
  title: string;
  version?: string;
  excerpt: string;
  updatedAt?: string;
};

function resolveCitation(id: string, retrieved: Map<string, Citation>) {
  return retrieved.get(id) ?? null; // 找不到就显示"无效引用"
}

文档有多个版本时，引用要指向具体版本和位置，不要只链接到会变化的首页。

如果服务端只能给出"整段回答用了哪些来源"，界面就不要伪装成逐句引用。

界面状态

情况展示
检索中"正在查找资料"，可以显示检索范围
没有足够资料说明没找到，建议换个问法或选择其他数据源，不要让模型凭常识编答案
检索成功、生成失败保留已找到的来源，提供重试
回答完成引用标号可点击展开片段，显示文档标题、版本和更新时间

不要显示没有计算依据的"可信度 98%"。

权限

  • 检索时就按用户、租户、文档权限过滤。把所有资料都交给模型、再要求它别泄露，权限早已越界。
  • 用户点开引用查看原文时再校验一次权限；文档删除或权限撤销后显示"无法访问"。
  • 文档标题和文件名本身也可能是敏感信息。

常见追问

  • 用户反馈"答案不对"，怎么定位？ 分开检查：必要文档有没有召回、排序是否把错误片段放前面、回答是否被片段支持、引用是否指向正确版本。反馈记录要关联本次检索结果和片段版本。
  • 检索内容让模型"忽略之前的指令"怎么办？ 见"提示词注入与普通 XSS 有什么区别？"。
