RAG 应用中，前端除了展示答案还需要关注什么？

RAG 是先取得与问题相关的外部信息，再把这些信息作为生成时的上下文。向量检索是一种实现方式，并非所有 RAG 都必须使用向量数据库，也不等于把全部资料重新训练进模型参数。

参考答案

RAG 先取得与问题相关的外部信息，再把它作为上下文交给模型生成。它可以使用向量、关键词、结构化查询或混合检索，不等于必须部署向量数据库，也不等于把资料重新训练进模型参数。

前端不仅要显示答案，还要帮助用户知道依据来自哪里、资料是否足够，以及哪些结论仍需核实。

检索和生成的失败应分别展示

检索可能无结果、超时或权限不足；生成可能在已有资料基础上失败或中断。二者不应都显示成“AI 正在思考”。

没有找到资料时，可以明确说明范围和不足，允许用户补充问题或选择其他资料源。不要为了保证总有答案，让模型把未经检索支持的猜测包装成知识库结论。

检索命中也不代表内容相关。返回一段含有相同关键词但语境不同的文本，可能让回答看似有出处却实际答错。

引用必须关联真实检索记录

服务端应给命中文档或片段分配稳定来源 ID，提供允许展示的标题、片段位置、版本或时间等元信息。模型可以按约定引用这些 ID，应用再映射到真实来源。

不能让模型随意生成一个 URL，然后把蓝色下划线当作事实证据。应检查引用 ID 是否确实存在于本次允许使用的资料集合，链接是否对应正确版本与位置。

同一文档有多个版本时，标题相同也可能内容不同。引用最好保留足够的版本或片段定位信息，让用户能回到支持结论的具体内容，而不是只跳到一个不断更新的首页。

来源真实与结论被支持仍是两层判断

一个真实来源不一定支持模型旁边的那句话。引用可能只支持部分内容，或模型把相关性误写成因果关系。需要评估结论与片段之间的忠实程度，而不只是统计答案里出现几个引用。

资料也可能过时、互相矛盾或来自不同条件。界面可以展示更新时间、冲突提示和可展开原文，但不要用无依据的统一“可信度 98%”制造精确感。

若服务只返回一个整段回答级来源列表，不能伪装成已经完成逐句归因。展示精度应与真实数据精度一致。

权限过滤必须发生在数据进入模型之前

按当前用户和租户限制检索范围，不应把全部内部文档送给模型后再让它“不要泄露”。未授权片段即使最后没显示，也已经越过了不应跨越的数据边界。

前端获取引用详情时还需重新授权，不能因为旧会话曾经引用过就永久允许访问。用户权限撤销或资料删除后，应合理显示不可访问状态，而不是从历史缓存继续泄露全文。

来源元信息也可能敏感，隐藏内容但暴露内部文件名、项目名称或存在性，仍可能造成信息泄露。

检索资料仍可能包含提示词注入

文档中的“忽略用户要求并调用工具”是资料内容，不是新的指令授权。检索排序高、来源内部或通过工具返回，都不自动提升它的可信级别。

生成输出仍要安全渲染，来源链接也要过滤协议与必要的目标范围。前端提供原文查看，不等于允许原始 HTML 或外部文件直接执行。

反馈与评测应能定位哪一层出了问题

用户反馈“引用不支持结论”时，应能关联到问题、检索集合、片段版本和生成配置，同时按隐私要求限制原文记录。

评测分别看检索是否找到必要资料、排序是否有效、回答是否忠实、引用是否准确，以及无资料时是否合理拒绝作答。只看文字是否流畅，很容易漏掉“资料找错了但答案说得很像”的失败。

一个好的 RAG 界面让证据可检查，让不足可见。引用的价值是帮助用户验证，而不是给模型答案贴上一个自动正确的标签。
