ESLint Flat Config 和旧配置方式有什么区别？

Flat Config 用一个配置对象数组，按 files 匹配、按顺序覆盖。文中用一个完整配置讲插件与预设导入、现代 extends 和全局忽略的行为，以及迁移时怎样检查最终生效配置。

参考答案

简答

旧的 .eslintrc 可以在每个目录放一份，沿着目录层层合并，很难看清最终用了什么。Flat Config 只有一个 eslint.config.js，导出一个配置对象的数组，每个对象用 files 说明自己管哪些文件，后面的对象覆盖前面的。

插件和共享配置也改成用 import 引进来的真实 JS 对象，不再按字符串名字去查找，所以依赖关系一眼就能看清。

版本上，ESLint 10 已经删除了旧的 .eslintrc 格式，查找配置文件也改成从每个被检查文件的目录往上找。globalIgnores() 用来声明全局忽略，extends 从 ESLint 9.22 起可以在单个配置对象里复用预设。

迁移以后要用 --print-config 看某个文件最终生效的配置，确认规则真的生效了。

先看一个完整配置

下面这份配置对所有 JS 和 TS 文件用推荐规则，再给 scripts 目录单独放宽。

JavaScript
// eslint.config.js
import { defineConfig, globalIgnores } from 'eslint/config';
import js from '@eslint/js';
import globals from 'globals';
import tseslint from 'typescript-eslint';

export default defineConfig([
  globalIgnores(['dist/', 'coverage/']),
  {
    files: ['**/*.{js,ts}'],
    extends: [js.configs.recommended, tseslint.configs.recommended],
    languageOptions: { globals: globals.browser },
    rules: { 'no-console': 'warn' },
  },
  {
    files: ['scripts/**/*.js'],
    languageOptions: { globals: globals.node },
    rules: { 'no-console': 'off' },
  },
]);

files 决定这个对象作用于哪些文件。没写 files 的对象，作用于所有被检查的文件。

scripts/build.js 同时被第二个和第三个对象匹配到。数组里后面的优先，所以第三个对象的 no-console: 'off' 覆盖了前面的 'warn'。

ignores 写在哪里，效果不一样

这里有个容易混的地方。一个对象如果只有 ignores 这一个键，或者用 globalIgnores()，它就是全局忽略，这些文件完全不检查。

可是 ignores 和 files、rules 等其他键写在一起时，它只是把某些文件排除出这个对象，别的对象照样会检查它们。

和 eslintrc 有哪些区别

最根本的区别是合并方式。eslintrc 由多个 .eslintrc 沿目录层层合并；Flat Config 只有一份配置文件，数组顺序决定优先级。

引用预设的方式也变了。以前写 extends: 'plugin:react/recommended'，ESLint 按名字去解析；现在用 import 引进来，直接放进数组或 extends。

几个常用配置项挪了位置。以前的 env: { browser: true } 改成 languageOptions.globals；顶层的 parser、parserOptions 放到了 languageOptions 下面；.eslintignore 文件改成配置里的 ignores 或 globalIgnores()。

ESLint 10 带来了什么变化

ESLint 10 不再支持 .eslintrc*，设置 ESLINT_USE_FLAT_CONFIG=false 也恢复不了。

查找 eslint.config.* 时，它从每个被检查文件所在的目录开始往上找，而不是只看当前工作目录。依赖旧行为的仓库，可以用 --config 显式指定配置文件。

/* eslint-env */ 注释会被报告为错误，要删掉，改用 languageOptions.globals。运行环境需要 Node.js 20.19.0+、22.13.0+ 或 24+。

官方提供 npx @eslint/migrate-config .eslintrc.json，可以把旧配置转换成 Flat Config，但转换结果仍然要人工检查。

迁移时怎样验证

bash
npx eslint --print-config src/main.ts
npx eslint --inspect-config

第一条命令输出某个文件最终生效的完整配置，第二条打开一个可视化的配置查看器。

为什么要专门验证？因为 files 没匹配上时 ESLint 不会报错，某条规则可能就悄悄失效了。所以迁移前后各跑一次全量检查，对比报告数量的变化。

常见追问

monorepo 里每个包要不要单独配置？

ESLint 10 会为每个文件找离它最近的 eslint.config.*，所以可以在包里放自己的配置。也可以只用根配置，靠 files 区分不同的包。

为什么 TypeScript 文件没被检查？

Flat Config 默认只匹配 .js、.mjs、.cjs。其他扩展名要在 files 里声明，比如 **/*.ts。
