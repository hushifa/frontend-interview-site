ESLint Flat Config 和旧配置方式有什么区别？

通过可运行的配置说明匹配对象、顺序覆盖、插件与预设导入，澄清现代 extends 和全局忽略的行为，并解释迁移时怎样检查最终生效配置。

参考答案

简答

  • Flat Config 用一个 eslint.config.js 导出配置对象数组，按 files 匹配文件，后面的对象覆盖前面的。
  • 插件和共享配置通过 import 引入真实的 JS 对象，不再按字符串名称查找，依赖关系一目了然。
  • ESLint 10 已删除旧的 .eslintrc 格式；配置文件改为从每个被检查文件所在目录向上查找。
  • globalIgnores() 声明全局忽略，extends 可以在单个配置对象里复用预设（ESLint 9.22+）。
  • 迁移后用 --print-config 查看某个文件的最终配置，确认规则真正生效。

一个完整配置

JavaScript
// eslint.config.js
import { defineConfig, globalIgnores } from 'eslint/config';
import js from '@eslint/js';
import globals from 'globals';
import tseslint from 'typescript-eslint';

export default defineConfig([
  globalIgnores(['dist/', 'coverage/']),
  {
    files: ['**/*.{js,ts}'],
    extends: [js.configs.recommended, tseslint.configs.recommended],
    languageOptions: { globals: globals.browser },
    rules: { 'no-console': 'warn' },
  },
  {
    files: ['scripts/**/*.js'],
    languageOptions: { globals: globals.node },
    rules: { 'no-console': 'off' },
  },
]);
  • files 决定对象作用于哪些文件；没写 files 的对象作用于所有被检查的文件。
  • 两个对象都匹配 scripts/build.js 时，后一个的 no-console: 'off' 覆盖前一个。
  • 只含 ignores 的对象（或 globalIgnores()）是全局忽略；和其他键写在一起的 ignores 只是把文件排除出这个对象。

和 eslintrc 的主要区别

eslintrcFlat Config
多个 .eslintrc 沿目录层层合并一份配置文件，数组顺序决定优先级
extends: 'plugin:react/recommended' 按名称解析import 进来直接放进数组或 extends
env: { browser: true }languageOptions.globals
parser、parserOptions 在顶层放在 languageOptions 下
.eslintignore 文件配置中的 ignores / globalIgnores()

ESLint 10 的变化

  • 不再支持 .eslintrc*，设置 ESLINT_USE_FLAT_CONFIG=false 也无法恢复。
  • 查找 eslint.config.* 时，从每个被检查文件的目录开始向上查找，而不是只看当前工作目录。依赖旧行为的仓库可以用 --config 显式指定。
  • /* eslint-env */ 注释会被报告为错误，应删除并改用 languageOptions.globals。
  • 需要 Node.js 20.19.0+、22.13.0+ 或 24+。

官方提供 npx @eslint/migrate-config .eslintrc.json 把旧配置转换成 Flat Config，转换结果仍需人工检查。

迁移时怎样验证

bash
npx eslint --print-config src/main.ts
npx eslint --inspect-config

第一条输出某个文件最终生效的完整配置，第二条打开可视化的配置查看器。迁移前后各跑一次全量检查，对比报告数量的变化，避免某条规则因为 files 没匹配上而悄悄失效。

常见追问

  • monorepo 里每个包要不要单独配置？ESLint 10 会为每个文件找最近的 eslint.config.*，可以在包内放配置；也可以在根配置里用 files 区分。
  • 为什么 TypeScript 文件没被检查？Flat Config 默认只匹配 .js、.mjs、.cjs，其他扩展名要在 files 中声明。
