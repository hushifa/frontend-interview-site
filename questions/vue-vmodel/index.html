组件 v-model 的本质是什么？

组件 v-model 把一个当前值 prop 与对应更新事件连接起来，默认使用 modelValue 和 update:modelValue。它简化的是父子通信约定，不取消状态所有权，输入时机、默认值和修饰符仍需组件明确支持。

参考答案

父组件写一个 v-model，看起来像把自己的变量直接交给子组件任意修改。实际关系更明确：父级把当前值作为 prop 传下去，子级在希望更新时发出约定事件，父级的绑定处理再更新自己的状态。

默认模型使用 modelValue 与 update:modelValue。所谓双向绑定，是这两条路径被简写连接起来，不是让子组件获得修改父级任意变量的权限。

用显式 prop、事件与可写 computed 实现

vue
<!-- TextField.vue -->
<script setup>
import { computed } from 'vue';

const props = defineProps({
  modelValue: { type: String, default: '' },
});
const emit = defineEmits(['update:modelValue']);

const value = computed({
  get: () => props.modelValue,
  set: next => emit('update:modelValue', next),
});
</script>

<template>
  <label>姓名<input v-model="value" /></label>
</template>
vue
<!-- Parent.vue -->
<script setup>
import { ref } from 'vue';
import TextField from './TextField.vue';

const name = ref('Lin');
</script>

<template>
  <section>
    <TextField v-model="name" />
    <p>父级姓名：{{ name }}</p>
    <button type="button" @click="name = 'Chen'">父级改值</button>
  </section>
</template>

输入时，原生 input 的 v-model 写入可写 computed；computed 的 setter 不直接修改 prop，而是发出 update:modelValue；父级绑定处理更新 name，再把新值传回来。

点击父级按钮时，name 改变，子级 computed 的 getter 读取新的 prop，输入框也跟着更新。可写 computed 在这里是一个访问桥梁，不是另一份需要与父级反复同步的独立数据副本。

也可以手工写 value 绑定与输入事件，但需要正确处理输入法组合等细节。示例在内部继续使用原生 v-model，以复用它对输入事件的相应处理。

编译后的约定并不神秘

组件上的 v-model 大致展开为传入 modelValue，并注册 update:modelValue 处理函数，把事件载荷写回父级绑定表达式。父级需要的是可赋值的合适表达式，不能把任意只读计算结果都当成可以写回的目标。

如果父级需要校验、格式化或拒绝更新，可以显式管理这条事件路径。但拒绝后的界面反馈、输入框当前 DOM 值和草稿状态也要设计，不能只让监听器什么都不做，就假定所有控件都会自动呈现正确回退。

当交互是“编辑草稿，最后保存或取消”，它也未必适合每次输入都立即修改父级真实值。可以使用独立草稿与提交事件，明确区分编辑过程和正式确认。

命名模型用于多组独立的值

v-model:title 对应 title prop 与 update:title 事件，而不是继续使用默认 modelValue。一个组件可以定义多组命名模型，例如区间的 start、end，或姓名的 firstName、lastName。

每组模型仍需要明确允许的值、更新时机与组合约束。若 start 与 end 必须一起满足范围规则，拆成两个更新事件可能出现中间状态，应考虑原子更新对象或更合适的提交接口，而不是仅为语法方便拆分。

Vue 3.4 起的 defineModel 编译宏可以简化模型声明，生成相应 prop 与更新事件关系。它不是运行时魔法，也不改变父级是值来源、子级发出更新意图这一原则。

默认值不会自动写回父级

如果父级绑定值是 undefined，子组件却通过模型默认值显示 1，两边初始理解可能不同：子级看见默认值，不代表父级变量已经被改成 1。

应在合适的所有者处初始化，或明确一个双方都理解的空值约定。组件 API 还要说明 null、空字符串、空数组与“未提供”是否不同，不能全靠默认值把差异掩盖掉。

直接修改对象模型的嵌套属性，也不一定经过希望观察的更新事件。对象引用可能被共享，因此复杂模型应明确是否采用不可变更新、草稿提交或受控的深层操作。

原生控件与自定义组件的绑定规则不同

原生文本输入通常通过 value 与 input 事件同步，复选框和单选框关注 checked，select 又有相应选择规则。Vue 的 v-model 指令会根据控件类型处理，不是简单给所有元素都绑定同一个事件名。

对于需要输入法的文字，原生 v-model 通常在组合输入阶段暂缓模型更新，结束后再同步。自行包装输入时如果忽略这一点，可能把尚未完成的拼音或组合字符当成最终值处理，破坏编辑体验。

.lazy、.trim、.number 等原生修饰符也有具体语义。.number 不保证每个状态都是 number，例如无法解析或清空时仍可能保留相应字符串。业务解析应与用户编辑中的临时值区分。

组件自己的修饰符需要按其 API 支持，尤其自定义的 capitalize 等行为，需要通过模型转换或相应实现明确处理。不能只在组件调用处写一个新后缀，就期待 Vue 自动知道业务转换规则。

类型、事件声明与实际行为应一致

defineProps、defineEmits 或 defineModel 可以帮助描述类型和开发期约定，但不会替代任意外部输入的业务验证，也不自动保存数据到服务器。

验证一个模型组件时，应同时从两个方向操作：用户输入是否正确更新父级，父级改值是否正确反映到子级；再检查清空、重置、默认值、输入法、禁用和记录切换。两条路径都明确，v-model 才是简洁的数据流接口，而不是隐藏状态覆盖的来源。
