Object.keys、for...in 和 Reflect.ownKeys 会返回哪些属性？

枚举属性时要区分自身与继承、字符串与 Symbol、可枚举与不可枚举。不同 API 选择不同范围，普通对象的键顺序也有明确规则；读取键与读取属性值又可能触发不同代码。

参考答案

对象里“有哪些属性”不是一个只有单一答案的问题。某个属性可能在对象自身，也可能在原型上；键可以是字符串或 Symbol；属性还可以被标记为不可枚举。

Object.keys、for...in、Reflect.ownKeys 选择的范围不同，所以同一个对象得到不同结果是正常的。调用前先确定你需要的是业务记录字段、继承能力，还是完整的自身属性清单。

用一个对象同时观察三种属性维度

JavaScript
const key = Symbol('内部标记');
const object = Object.create({ inherited: 1 });
object.visible = 2;
Object.defineProperty(object, 'hidden', { value: 3 });
object[key] = 4;

console.log(Object.keys(object).join(',')); // visible
console.log(Reflect.ownKeys(object).length); // 3
console.log(Object.hasOwn(object, 'inherited')); // false

visible 是自身、可枚举的字符串属性。hidden 也是自身字符串属性，但 defineProperty 新建它时没有设置 enumerable:true，因此不可枚举。key 是自身可枚举的 Symbol 属性。inherited 在原型上，不属于对象自身。

Object.keys 只选中 visible；Reflect.ownKeys 包含 visible、hidden 和 Symbol 键，却不会加上原型中的 inherited。因此“ownKeys 更全面”指它包含完整的自身键，不是把整个原型链都展开。

常用 API 分别覆盖什么范围

for...in是是是否否

表中的 for...in 还要考虑同名属性遮蔽、遍历过程中修改对象等规则，并不是把每层的可枚举键数组直接拼起来。数组的 for...of 则是另一个概念：它使用迭代协议取得元素值，不是逐个枚举普通对象属性名。

如果需要完整的自身描述符，Object.getOwnPropertyDescriptors 可以同时提供键对应的 value/get/set 及属性标志。拿到这些信息不等于已经复制了对象的内部槽或类私有状态。

属性不可枚举，不代表不能访问

JavaScript
const item = {};
Object.defineProperty(item, 'secret', { value: 7 });

console.log(item.secret); // 7
console.log(Object.hasOwn(item, 'secret')); // true
console.log('secret' in item); // true
console.log(Object.keys(item).length); // 0

enumerable 控制它是否参加相应的枚举操作，不控制访问权限。Symbol 键也不是秘密字段：Reflect.ownKeys 或 Object.getOwnPropertySymbols 仍然可以发现它们。

Object.hasOwn 检查属性是否属于自身，不会把原型上同名属性算进来；in 则会沿原型链检查。比起直接调用 object.hasOwnProperty，Object.hasOwn 还避免了对象没有该方法或自己覆盖了同名字段的问题。

原型上的同名字段可能被非枚举属性遮住

JavaScript
const prototype = { name: '原型名字', other: 1 };
const child = Object.create(prototype);
Object.defineProperty(child, 'name', { value: '自身名字' });

const keys = [];
for (const key in child) keys.push(key);
console.log(keys.join(',')); // other

child.name 自身不可枚举，所以不会被输出；原型上的可枚举 name 也不会绕过这个同名遮蔽重新出现。因此需要分析具体属性关系，不能只说“for...in 把所有原型上的可枚举属性都无条件列出来”。

在普通业务记录转换中，Object.entries 往往比 for...in 更贴近“只处理自己提供的字段”的意图。如果确实使用 for...in，又只想处理自身字段，应明确通过 Object.hasOwn 过滤。

普通对象的顺序不是纯粹的插入顺序

JavaScript
const record = {};
record.z = 1;
record[10] = 2;
record[2] = 3;
record['01'] = 4;
record.a = 5;
const marker = Symbol('标记');
record[marker] = 6;

console.log(Object.keys(record).join(',')); // 2,10,z,01,a
console.log(Reflect.ownKeys(record).at(-1) === marker); // true

delete record.z;
record.z = 7;
console.log(Object.keys(record).join(',')); // 2,10,01,a,z

普通对象自身键的常见顺序是：属于数组索引形式的字符串键按数值升序；其他字符串键按建立顺序；Symbol 键再按建立顺序。'01' 不是与 '1' 相同的索引形式，所以保留在普通字符串键的那一组。

更新已有普通字符串属性通常不改变其位置；删除后重新建立，才成为这一组中的新项。Proxy 的 ownKeys、自身对象的特殊内部行为和原型链遍历还可能涉及其他规则，所以要先限定对象种类与使用的 API。

如果业务必须按插入顺序管理任意键，Map 的语义通常更明确，不必把对象键顺序当成队列或排序模型。

拿键、读值、复制和序列化不是同一个操作

对普通对象，Object.keys 只列键，不需要执行对应 getter；Object.values、Object.entries 和对象展开读取值时，则可能执行 getter。面对 Proxy，枚举还可能触发 ownKeys、getOwnPropertyDescriptor 等 trap，不能把这些操作都当成纯粹读取内存。

JSON.stringify 也不是 Reflect.ownKeys 的序列化版本。它会按 JSON 规则过滤和转换内容，可能调用 toJSON，通常不会保留 Symbol 键、不可枚举属性或全部继承行为。

因此需要导出用户资料时，最好按明确字段映射；需要诊断对象时，再使用更完整的反射接口；需要复制普通属性描述符时，按描述符处理。把所有场景统一成一个 for...in，最容易把范围差异隐藏起来。
