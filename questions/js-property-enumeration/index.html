Object.keys、for...in 和 Reflect.ownKeys 会返回哪些属性？

这几个方法的区别在于管不管继承来的属性、不可枚举的属性和 Symbol 键。Object.keys 只要自己的、可枚举的字符串键，for...in 会带上原型链上的，Reflect.ownKeys 拿到自己的全部键。

参考答案

简答

区分这几个方法，要看三件事：属性是自己的还是继承的，是不是可枚举，键是字符串还是 Symbol。

Object.keys，还有 Object.values、Object.entries，只返回自己的、可枚举的、字符串键。for...in 在这基础上还会带上原型链上可枚举的字符串键。Object.getOwnPropertyNames 返回自己所有的字符串键，不可枚举的也算；Object.getOwnPropertySymbols 返回自己的 Symbol 键。Reflect.ownKeys 最全，自己的所有键都返回，等于前面这两个加起来。

键的顺序也有规则：像数组下标那样的整数键按数值从小到大排在前面，其他字符串键按创建顺序，Symbol 键排在最后，也按创建顺序。

同一个对象，不同方法拿到什么

下面这个对象有四种属性：继承来的、普通的、不可枚举的、Symbol 键的。

JavaScript
const key = Symbol('内部标记');
const object = Object.create({ inherited: 1 });
object.visible = 2;
Object.defineProperty(object, 'hidden', { value: 3 });
object[key] = 4;

console.log(Object.keys(object).join(',')); // visible
console.log(Reflect.ownKeys(object).length); // 3
console.log(Object.hasOwn(object, 'inherited')); // false

Object.keys 只拿到了 visible。inherited 是从原型继承来的，hidden 用 defineProperty 创建，默认不可枚举，Symbol 键也不算，所以都被排除了。

Reflect.ownKeys 拿到 3 个：visible、hidden 和那个 Symbol 键。它不管可不可枚举，也包括 Symbol，但还是只看自己的属性，不含 inherited。Object.hasOwn 返回 false 也说明了这一点。

如果用 for (const k in object) 遍历，会得到 visible 和 inherited，它会去原型链上找可枚举的属性。

最后一行容易记错：展开语法和 Object.assign 会复制自己的可枚举属性，字符串键和 Symbol 键都会复制。

键为什么不按写的顺序排

JavaScript
const o = { b: 1, 2: 1, a: 1, 1: 1 };
console.log(Object.keys(o)); // ['1', '2', 'b', 'a']

写的顺序是 b、2、a、1，结果 '1' 和 '2' 跑到了最前面。因为整数键总是按数值升序排在前面，剩下的字符串键才按创建顺序。所以需要完全由自己控制顺序时，用 Map 或者数组。

怎样判断属性存不存在

Object.hasOwn(obj, key) 只看自己的属性，用来代替 obj.hasOwnProperty(key)。用 Object.create(null) 创建的对象没有原型，也就没有 hasOwnProperty 方法，Object.hasOwn 照样能用。

key in obj 会连原型链一起查。obj.key !== undefined 不可靠，属性存在但值恰好是 undefined 时，它会判断错。

取键会不会触发 getter

Object.keys 只读取键，不会调用 getter。Object.entries、JSON.stringify 和展开语法要读取值，所以会触发 getter。如果对象是 Proxy，Object.keys 会触发 ownKeys 和 getOwnPropertyDescriptor 这两个陷阱。

常见追问

为什么 class 的方法不出现在 Object.keys 里？

因为方法定义在原型上，不是实例自己的属性，而且 class 的方法本身就是不可枚举的。

for...of 能遍历普通对象吗？

不能，普通对象不是可迭代对象。要遍历键值对，就写 for (const [k, v] of Object.entries(obj))。
