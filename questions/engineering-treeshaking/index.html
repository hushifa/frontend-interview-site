Tree shaking 如何工作？为什么有些代码无法移除？

Tree shaking 删掉没被使用、也没有副作用的代码。文中从导出使用关系和模块副作用两类分析讲起，解释 ESM、sideEffects 和纯调用标注的作用，以及为什么要看真实构建结果验证。

参考答案

简答

Tree shaking 就是构建时找出没被用到的代码并删掉。它依赖 ES 模块的静态 import 和 export，因为这种写法在不运行代码的情况下就能看出谁用了谁。

一段代码能删，要同时满足两个条件：它的导出没人用，而且执行它没有副作用。副作用指执行时会影响外部，比如改全局变量、打印日志、引入 CSS。

库可以帮打包工具做判断。package.json 里写 sideEffects: false，表示“整个模块没人用时可以跳过”；/*#__PURE__*/ 标注单个调用没有副作用。CommonJS 的导出是运行时才确定的，通常没法精确摇树。

要注意，只有生产构建才会真正删除代码，效果要看产物验证，不能光凭源码判断。

两类分析：导出级和模块级

先看一个工具模块，它有两个导出，顶层还有一行打印。

JavaScript
// utils.js
export function used() { return 1; }
export function unused() { return 2; }
console.log('utils loaded'); // 副作用
JavaScript
// main.js
import { used } from './utils.js';
used();

第一类是导出级的分析。unused 没被任何地方导入，所以可以删掉。

第二类是模块级的分析。假如 main.js 一个导出都不用，整个 utils.js 能不能跳过？不能，因为顶层的 console.log 是副作用，删掉模块就少了这行输出。所以打包工具默认会保留这个模块。

为什么有些代码删不掉

最常见的是顶层副作用，比如修改全局对象、注册 polyfill、给原型加方法、引入 CSS。打包工具没法确认删了是否安全，只能留着。

其次是看不出纯不纯的函数调用。比如 export const Button = styled.button(...) 是一次函数调用，工具不知道它会不会改外部状态。库可以在调用前加 /*#__PURE__*/，告诉工具“返回值没人用时，这次调用可以删”。

CommonJS 也是一个原因。module.exports = {...} 和动态 require 让工具没法静态确定用到了哪些导出。所以选依赖时优先用提供 ESM 入口的版本，比如 lodash-es。

还有整体导入后动态访问。写了 import * as utils 再调用 utils[name]()，工具不知道 name 是什么，只能全部保留。

最后是类和对象的方法。一个类只要被用到，它的方法通常都会保留。

sideEffects 字段怎样写

json
{
  "name": "my-lib",
  "sideEffects": ["*.css", "./src/polyfill.js"]
}

写成 false，表示所有模块都没有副作用，没被用到的模块可以整个跳过。写成数组，就是列出确实有副作用的文件，其余的可以跳过。

声明错了会出问题。比如 CSS 文件被标成无副作用，import './style.css' 这种不取任何导出的导入就可能被删掉，样式就丢了。所以上面的例子把 *.css 列了进去。

怎样验证效果

要运行生产构建，因为开发模式通常不删代码。然后用产物分析工具，看某个库最后占了多少体积。

也可以直接在产物里搜索本应被删掉的函数名或字符串。webpack 的 optimization.usedExports 会在产物里留下 unused harmony export 注释，能帮你定位。

常见追问

Tree shaking 和压缩是什么关系？

打包工具负责标记哪些导出没被使用，真正把代码删掉，通常是压缩器做的，比如 Terser、esbuild、Oxc。

为什么还需要按需引入插件？

有些旧库只提供 CommonJS，或者靠副作用注册组件，tree shaking 处理不了。按需插件会把整体导入改写成单个文件的导入，绕开这个问题。
