Tree shaking 如何工作？为什么有些代码无法移除？

理解静态模块结构、使用关系和副作用分析。

参考答案

Tree shaking 基于模块导入导出关系和静态分析，移除确认不需要的代码。ES Modules 的静态结构便于分析，但是否能删除还受副作用、打包器配置和代码写法影响。

工程工具要分别评估开发启动、增量更新、生产构建和部署产物，不能用一个指标代表全部体验。锁文件、Node 版本、构建目标、环境变量和缓存策略应能在 CI 中复现。

模块顶层修改全局对象、注册监听或导入样式可能有副作用，不能仅因为导出未使用就删除整个模块。错误设置包的 sideEffects: false 可能导致必要的初始化或样式被移除。

应结合构建产物分析验证结果，不能把“用了 ESM”直接等同于“所有未使用代码都会被移除”。

升级工具时先看迁移说明和产物差异，再在真实项目中验证插件、Source Map、代码分割和失败日志。把配置写进仓库，才能让本地和发布环境得到同一套结果。

实际工程问题最好从产物和日志开始验证：看依赖是否锁定、构建是否可复现、代码是否被正确分包、失败是否能定位到具体步骤。开发服务器的速度不能代表最终页面的下载和执行成本。
