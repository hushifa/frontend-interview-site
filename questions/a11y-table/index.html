数据表格怎样设计才方便键盘和读屏用户理解？

读屏用户看不到表格全貌，只能一格一格听。数据表要用原生 table，caption 给出表名，th 加 scope 标明是行表头还是列表头；读屏在单元格间移动时会读出对应表头。不要用 div 拼表格，也不要用 table 做布局。

参考答案

简答

看得见的用户扫一眼就知道某个数字属于哪一行哪一列，读屏用户却只能一格一格地听。所以数据表要用原生 <table>，并把表头关系写清楚，读屏才能在每个单元格前读出对应的表头。

具体来说，<caption> 是表格的名称，进入表格时读出。列表头写 <th scope="col">，行表头写 <th scope="row">，读屏在单元格之间移动时，会读出类似“列名，行名，值”的内容。多级表头用 scope="colgroup" 和 colspan；关系再复杂，就用 headers 属性逐个关联，或者干脆拆成几个简单的表。

可排序的列，在表头里放一个按钮，并给 th 设置 aria-sort="ascending" 或 "descending"。

还要注意窄屏。表格可以放进能横向滚动的容器里，但容器要加 tabindex="0"、role="region" 和名称，否则键盘用户滚不动它。

基本结构

下面是一张季度销售表，外面套了一个可以横向滚动的容器。

HTML
<div role="region" aria-labelledby="sales-caption" tabindex="0" class="table-scroll">
  <table>
    <caption id="sales-caption">2026 年季度销售额（万元）</caption>
    <thead>
      <tr>
        <th scope="col">地区</th>
        <th scope="col">
          <button>第一季度</button>
        </th>
        <th scope="col" aria-sort="descending">
          <button>第二季度</button>
        </th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">华东</th>
        <td>120</td>
        <td>150</td>
      </tr>
    </tbody>
  </table>
</div>

读屏移到 150 这一格时，会结合“第二季度”和“华东”这两个表头一起读，用户就知道这是华东第二季度的数字。这就是 scope 的作用。

“华东”用的是 th scope="row" 而不是 td，因为它是这一行的表头。第二季度表头上的 aria-sort="descending" 告诉读屏这列当前按降序排列，表头里的按钮负责触发排序。

外层容器为什么要 tabindex="0"？因为普通的 div 不能聚焦，键盘用户就没法用方向键滚动它。加上 role="region" 和名称，读屏也知道这块区域是什么。

多级表头

表头有两层时，上层用 colgroup 表示它管着下面好几列。

HTML
<thead>
  <tr>
    <td></td>
    <th scope="colgroup" colspan="2">上半年</th>
  </tr>
  <tr>
    <th scope="col">地区</th>
    <th scope="col">Q1</th>
    <th scope="col">Q2</th>
  </tr>
</thead>

“上半年”横跨 Q1 和 Q2 两列，scope="colgroup" 让读屏知道这两列都属于上半年。

常见错误

用 CSS Grid 加 div 显示表格数据，读屏就没法按行和列导航了。确实需要 div 结构时，要把 role="table"、row、columnheader、cell 全部补上。

反过来，给布局用的表格加 th，读屏会把它当成数据表来读。布局用 CSS 做，不要用 table。

还有一种是让每个单元格都能聚焦，用户按 Tab 要按几百次。普通数据表只让单元格里的链接和按钮能聚焦。

可编辑的表格是另一回事

像电子表格那样用方向键在格子间移动、按 Enter 编辑的表格，是 role="grid"。它要实现漫游焦点、方向键、Enter 编辑等一整套键盘行为，复杂得多，参考 APG 的 Grid 模式。

常见追问

窄屏下把表格改成卡片可以吗？

可以，但每张卡片要把表头文字一起显示出来，比如“第二季度：150”。否则读屏用户只听到一个数字，不知道它是哪一列的。
