AI 生成的 Markdown 应该怎样安全地渲染？

模型输出应按不可信内容处理。不要直接把生成文本作为 HTML 交给 dangerouslySetInnerHTML，也不要把生成的 JSX、MDX 或脚本直接编译执行。展示代码与执行代码是不同的权限边界。

参考答案

模型输出应按不可信文本处理。它可能引用网页中的攻击内容，也可能生成看起来合理但危险的链接、HTML 或代码。提示模型“不要输出危险内容”可以表达偏好，不能成为浏览器执行权限的防线。

安全渲染的第一条边界是：展示文字与执行内容分开。代码块里出现 JavaScript，只表示要显示代码，不代表用户已经允许执行。

从受限 Markdown 开始，而不是默认开放 HTML

react-markdown 默认提供相应的安全行为，但插件、自定义组件和 URL 转换可以改变边界。不要把模型文本先转换成未经净化的 HTML，再直接交给 dangerouslySetInnerHTML。

下面示例明确忽略原始 HTML，只允许 HTTP/HTTPS 链接，并把图片显示为替代文字，避免自动向第三方图片地址发请求：

JSX
import Markdown from 'react-markdown';

function safeHref(href) {
  if (!href) return null;
  try {
    const url = new URL(href, 'https://app.example.com/');
    return ['https:', 'http:'].includes(url.protocol) ? url.href : null;
  } catch {
    return null;
  }
}

export function Answer({ text }) {
  return (
    <Markdown
      skipHtml
      components={{
        a: ({ href, children }) => {
          const url = safeHref(href);
          return url
            ? <a href={url} target="_blank" rel="noopener noreferrer">{children}</a>
            : <span>{children}</span>;
        },
        img: ({ alt }) => <span>{alt || '图片未自动加载'}</span>,
      }}
    >
      {text}
    </Markdown>
  );
}

相对链接的基地址需要换成应用明确选择的可信来源，而不是模型给出的任意 base。例子只限制协议，不证明 HTTP/HTTPS 目标站点可信；涉及钓鱼风险时还应显示域名、限制来源或提供外链提示。

保留库默认 URL 处理，不用“原样返回所有 URL”的 urlTransform 绕过它。自定义组件也不应该把所有输入属性不加区分地 spread 到危险元素上。

需要原始 HTML 时，净化顺序很重要

如果产品确实需要部分 HTML，应明确允许的标签、属性和 URL 协议，使用维护的净化工具处理最终可能进入 DOM 的结构。启用 rehype-raw 等解析步骤后，安全边界已经不同，不能沿用“默认安全”的结论。

净化之后再运行会插入危险标签或属性的插件，可能重新打开漏洞。应审查整个插件链与自定义渲染，而不是只确认依赖列表里出现了 sanitize。

CSS、SVG、iframe、公式和图表都有自己的能力与攻击面，允许某个标签不等于接受它的所有属性。不要为解决一个样式问题开放整个原始 HTML 集合。

富内容解释器需要独立权限与资源限制

MDX 可以包含 JSX 与表达式，不能把模型输出当作可信 MDX 直接编译运行。Mermaid、数学公式和代码沙盒也不是纯 Markdown 的同一层能力，需要核对库的安全配置、内容大小和执行隔离。

若用户主动要求运行代码，应采用明确的受限执行环境与确认流程。把代码放进 iframe 并不天然安全，来源、sandbox、网络权限和消息通道仍需设计。

外部图片即使不执行脚本，也可能泄露访问时机和网络信息。允许加载时，可采用用户确认、来源白名单或受控代理，并限制图片体积；不能把“没有 XSS”当作没有其他风险。

流式半成品不能靠关闭过滤修复

模型可能先输出半个链接、代码围栏或表格，后续才补齐。逐 token 完整解析还可能造成重复计算和布局跳动。

可以按合理频率批量更新，对未完成块使用保守展示，并在结束后完成渲染。不要为了让半截 HTML 看起来正常，临时允许未净化的内容进入 DOM。

还要限制总输出、代码块与插件处理成本，避免巨大文本或病态结构拖垮页面。安全渲染只保护展示边界，不能替代服务端工具授权、数据权限和提示词注入防御。
