AI 生成的 Markdown 应该怎样安全地渲染？

模型输出是不可信内容。默认关闭原始 HTML、只放行 http/https 链接、谨慎处理外部图片；确实需要 HTML 时对整条插件链的最终结果做净化；流式输出要按帧合并、保守处理未闭合的块。

参考答案

简答

  • 模型可能复述网页里的恶意内容，或在注入攻击下生成钓鱼链接和 HTML，所以它的输出按用户输入对待。
  • 默认关闭原始 HTML，链接只允许 http: 和 https:，外部图片默认不加载。
  • 外部图片也是风险：图片 URL 可以把对话里的数据带到攻击者服务器。
  • 需要 HTML 时，用维护中的净化库处理最终进入 DOM 的结构；之后的插件不能再插入未净化的内容。
  • 代码块只展示，不执行；MDX、Mermaid、代码沙盒等能力要单独评估权限。

受限渲染示例

JSX
import Markdown from 'react-markdown';

function safeHref(href) {
  if (!href) return null;
  try {
    // 基地址由应用指定，不使用模型提供的值
    const url = new URL(href, 'https://app.example.com/');
    return ['http:', 'https:'].includes(url.protocol) ? url.href : null;
  } catch {
    return null;
  }
}

export function Answer({ text }) {
  return (
    <Markdown
      skipHtml
      components={{
        a: ({ href, children }) => {
          const url = safeHref(href);
          return url ? (
            <a href={url} target="_blank" rel="noopener noreferrer">
              {children}
            </a>
          ) : (
            <span>{children}</span>
          );
        },
        img: ({ alt }) => <span>[图片：{alt || '未命名'}]</span>,
      }}
    >
      {text}
    </Markdown>
  );
}
  • react-markdown 默认不渲染原始 HTML，并会过滤 javascript: 等危险协议。自定义 urlTransform 或启用 rehype-raw 会改变这个默认行为。
  • http/https 只排除了危险协议，不代表链接可信。可以在链接旁显示域名，或在跳转前提示。
  • 图片可以改成"点击加载"，或只允许受控代理和白名单域名。

需要 HTML 时

先列出允许的标签、属性和 URL 协议，再用 rehype-sanitize、DOMPurify 等维护中的工具净化。顺序很重要：净化之后的插件如果又添加了 HTML 或属性，前面的净化就失效了。SVG、iframe、内联样式各自有新的攻击面，不要为了一个样式需求放开全部 HTML。

流式渲染

  • 模型会先输出半个链接、未闭合的代码围栏或表格。每个 token 都重新解析会导致布局跳动和大量重复计算，可以按动画帧合并更新。
  • 未闭合的块先按纯文本显示，结束后再完整渲染。
  • 限制总长度、代码块数量和嵌套深度，防止超长输出拖垮页面。

常见追问

  • 在提示词里要求"不要输出 HTML"不就够了吗？ 不够。那只是让模型尽量遵守，攻击者可以通过注入改变它，浏览器端的限制才是边界。
  • 用户想运行模型生成的代码怎么办？ 放进隔离的沙盒（跨源 iframe 或 Worker），限制网络和资源，并在用户明确点击后才运行。
