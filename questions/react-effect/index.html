useEffect 的依赖数组和清理函数应该怎么写？

Effect 用来让组件与外部系统保持同步。依赖数组列出 Effect 读取的所有响应式值，清理函数撤销上一轮同步。由渲染计算得出的值和由用户操作触发的逻辑不应放进 Effect。

参考答案

简答

  • Effect 用于和外部系统同步，例如订阅、计时器、网络连接、非 React 组件。
  • 依赖数组必须包含 Effect 内读取的所有 props、state 和组件内定义的值，由 eslint-plugin-react-hooks 检查。
  • 依赖变化时，React 先运行上一轮的清理函数，再用新值运行 Effect；卸载时也会运行清理。
  • 开发环境的严格模式会额外执行一次"挂载 → 清理 → 挂载"，用来暴露没写清理的 Effect。
  • 能在渲染时算出的值直接计算，用户点击触发的逻辑写在事件处理器里，都不需要 Effect。

一个完整的同步

JSX
import { useEffect, useState } from 'react';

function ChatRoom({ roomId, serverUrl }) {
  const [messages, setMessages] = useState([]);

  useEffect(() => {
    const connection = createConnection(serverUrl, roomId);
    connection.on('message', (msg) => setMessages((list) => [...list, msg]));
    connection.connect();
    return () => connection.disconnect();
  }, [roomId, serverUrl]);

  return <MessageList items={messages} />;
}

切换 roomId 时，React 先断开旧房间，再连接新房间。依赖数组描述的是"哪些值变了需要重新同步"，不是"想在什么时候执行"。

三种依赖写法

写法执行时机
不传数组每次提交后都执行
[]只在挂载后执行，卸载时清理
[a, b]挂载后执行，之后 a 或 b 变化（Object.is 比较）时重新执行

不要为了"少执行"删掉依赖。Effect 用到的值没写进数组，它就会读到旧渲染里的值。依赖太多时，应改代码结构：

  • 只在 Effect 里用的对象或函数，挪到 Effect 内部创建。
  • 基于前值更新状态，用函数式更新 setX(x => ...)，就不必依赖 x。
  • 只想读最新值、不想因它重连的逻辑，提取成 useEffectEvent（React 19.2 起稳定）。

请求数据时处理竞态

JSX
useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/users/${id}`, { signal: controller.signal })
    .then((res) => res.json())
    .then(setUser)
    .catch((err) => {
      if (err.name !== 'AbortError') setError(err);
    });
  return () => controller.abort();
}, [id]);

快速切换 id 时，旧请求在清理中被取消，不会覆盖新结果。实际项目更推荐用框架的数据加载或 TanStack Query 这类库，它们处理了缓存和去重。

不需要 Effect 的情况

  • 由 props 或 state 推导的值：在渲染中直接计算，开销大时用 useMemo。
  • 提交表单、点击购买：写在事件处理器里，因为它们由具体操作触发，不是"显示这个组件就要做"。
  • props 变化时重置状态：给组件换 key，而不是在 Effect 里 setState。

执行时机

Effect 在提交之后执行。由用户点击等离散事件触发的更新，React 可能在浏览器绘制前就同步执行 Effect；其他情况通常在绘制后执行。需要在绘制前测量布局、避免闪烁时，用 useLayoutEffect。

常见追问

  • 为什么开发环境 Effect 执行两次？严格模式故意模拟一次卸载再挂载，正确写了清理的 Effect 用户看不出区别。
  • Effect 里能直接写 async 函数吗？不能把 async 函数传给 useEffect，因为它返回 Promise 而不是清理函数；在内部定义 async 函数再调用。
