Pointer Events 为什么适合统一鼠标、触摸和触控笔交互？

鼠标、手指、触控笔都用同一套事件处理。讲清 pointerdown、pointermove、pointerup、pointerId 和 pointer capture，避免为不同输入设备维护重复逻辑。

参考答案

简答

以前做拖动，要同时监听 mousedown 和 touchstart 两套事件。Pointer Events 把鼠标、手指和触控笔统一成一套：pointerdown、pointermove、pointerup、pointercancel，写一遍就够了。

每个接触点都有自己的 pointerId，多根手指时按 ID 区分；pointerType 告诉你是 mouse、touch 还是 pen。

做拖动时常用 setPointerCapture，意思是把这根指针“抓住”，之后它的事件都发给当前元素，手指移出元素也不会断。

要注意的是，触摸时浏览器可能把手势拿去滚动或缩放，并发一个 pointercancel，代码要处理这个取消。哪些手势留给页面，要用 CSS 的 touch-action 提前说好。普通按钮继续用 click 就行。

为什么不再分开监听

旧做法要同时监听 touchstart 和 mousedown。可是手指点完以后，浏览器还会补发一组模拟的鼠标事件，所以还得想办法防止同一个操作执行两次。

Pointer Events 把这些合成一套模型，就没有这个麻烦了。触控笔的压力 pressure、倾斜角度 tiltX 这些信息，也放在同一个事件对象里。

写一个拖动滑块

下面的滑块只跟踪第一个按下的指针。重点看 pointerdown 里的捕获，和最后三个结束事件。

JavaScript
function makeDraggable(handle, onMove) {
  let activeId = null;
  let startX = 0;

  handle.addEventListener('pointerdown', (event) => {
    if (activeId !== null || event.button !== 0) return;
    activeId = event.pointerId;
    startX = event.clientX;
    handle.setPointerCapture(event.pointerId);
  });

  handle.addEventListener('pointermove', (event) => {
    if (event.pointerId !== activeId) return;
    onMove(event.clientX - startX);
  });

  const end = (event) => {
    if (event.pointerId !== activeId) return;
    activeId = null;
  };
  handle.addEventListener('pointerup', end);
  handle.addEventListener('pointercancel', end);
  handle.addEventListener('lostpointercapture', end);
}
CSS
.handle { touch-action: none; }

activeId 已经有值时，别的手指按下来会被忽略，所以第二根手指不会打乱拖动。event.button !== 0 用来过滤鼠标右键。

捕获以后，就算指针移出了 handle，pointermove 和 pointerup 还是发给它。pointerup 之后浏览器会自动释放捕获。

结束为什么要监听三个事件？因为拖动不一定是正常松手结束的。浏览器接管手势会发 pointercancel，捕获丢了会发 lostpointercapture，这些情况都要把状态清掉。

滑块要接管所有触摸移动，所以设成 touch-action: none。

touch-action 是怎么分工的

touch-action 告诉浏览器：在这个元素上，哪些手势你来处理，剩下的交给页面。

值浏览器保留的手势
auto全部（默认）
pan-y只有纵向滚动，横向移动和双指缩放交给页面
pan-y pinch-zoom纵向滚动和双指缩放，横向移动交给页面
none都不保留，页面处理所有触摸

它必须在手势开始前就设好。在 pointerdown 里调用 preventDefault() 是阻止不了滚动的。另外只禁用真正需要的手势，禁多了用户就没法滚动或缩放页面。和滚动方向冲突的处理见《移动端手势交互怎样避免和页面滚动冲突？》。

别忘了键盘和读屏

拖动只是一种输入方式。滑块还应该支持方向键调值，并使用原生的 <input type="range"> 或正确的 ARIA 角色，这样读屏用户也能操作。

常见追问

为什么拖动时偶尔会突然停住？

多半是浏览器开始滚动了，发了 pointercancel，之后就不会再有 move 事件。先检查元素上的 touch-action 有没有设对。

pointerleave 和捕获有什么关系？

捕获期间，事件都派发给捕获它的元素，指针移出去也不会触发 pointerleave，要等释放捕获以后才会。所以拖动不会因为手指移出元素而中断。
