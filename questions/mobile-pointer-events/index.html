Pointer Events 为什么适合统一鼠标、触摸和触控笔交互？

理解 pointerdown、pointermove、pointerup、pointerId 和 pointer capture，避免为不同输入设备维护重复逻辑。

参考答案

Pointer Events 为鼠标、触摸和触控笔提供统一事件模型，并通过 pointerId 区分多指或多支输入。拖拽、绘图和手势可以共享大部分处理逻辑，同时读取 pointerType、压力等设备信息。

在“Pointer Events 为什么适合统一鼠标、触摸和触控笔交互？”这个问题中，先区分设备输入、浏览器能力、权限、软键盘和平台生命周期，再用真实设备测试旋转、弱网、后台恢复和拒绝授权。这里的 Pointer Events、移动端、拖拽 不是孤立的 API 名称，而是会共同影响输入、过程和最终结果。

移动端问题要把浏览器能力、触摸或触控笔输入、屏幕尺寸、软键盘、权限和平台容器分开处理。桌面浏览器上的成功路径不能代表真实设备上的手势、旋转、弱网和后台恢复。

当元素需要在指针移动时继续接收事件，可以调用 setPointerCapture(pointerId)；结束或取消时要释放相关状态并处理 pointercancel。触摸交互还要配合 touch-action 告诉浏览器哪些手势由页面处理，不能简单地对所有移动事件调用 preventDefault。

实现时要处理按下后离开元素、窗口失焦、多指交错、取消和重复结束事件。拖拽状态应以 pointerId 为依据，并在清理时恢复样式和捕获状态。

实现时优先使用特性检测和可取消的生命周期处理，并为不支持的能力提供可完成任务的降级方案。上传、定位、分享和传感器 API 还要明确用户授权和隐私边界。

实际移动端测试要包含真实触摸、键盘弹出、旋转、后台恢复和弱网，而不是只把桌面窗口缩窄。平台权限和系统回收也会让一个看似同步的流程中途暂停。
