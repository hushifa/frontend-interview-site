Pointer Events 为什么适合统一鼠标、触摸和触控笔交互？

理解 pointerdown、pointermove、pointerup、pointerId 和 pointer capture，避免为不同输入设备维护重复逻辑。

参考答案

如果拖拽同时支持鼠标、手指和触控笔，分别维护 mouse 与 touch 两套事件很容易漏掉取消、多指和兼容鼠标事件。Pointer Events 提供统一的按下、移动、抬起与取消模型，再通过属性表达输入设备差异。

统一模型不等于假设所有设备相同。鼠标通常能悬停，触摸没有同样的悬停过程，触控笔还可能提供压力、倾角等数据，这些都应按能力处理。

用 pointerId 关联一次操作

pointerdown 开始一段输入，pointermove 更新位置，pointerup 表示正常结束。pointerId 区分同时活动的指针，不能只维护一个“鼠标是否按下”的全局布尔值来处理多指。

即使只支持单指拖拽，也应记录当前接受的 pointerId，忽略其他指针。pointerType 可区分 mouse、touch、pen 等类型；isPrimary 表达对应输入类型的主指针，不保证整个系统永远只有一个主指针。

捕获让拖拽越过元素边缘后仍可继续

下面演示单指水平位移的输入层。onMove 接收相对按下位置的位移；onEnd 的取消标记交给业务决定提交还是回退：

JavaScript
function bindHorizontalDrag(element, onMove, onEnd) {
  let activeId = null;
  let startX = 0;
  const controller = new AbortController();
  const options = { signal: controller.signal };

  element.addEventListener('pointerdown', (event) => {
    if (activeId !== null || event.button !== 0) return;
    element.setPointerCapture(event.pointerId);
    activeId = event.pointerId;
    startX = event.clientX;
  }, options);

  element.addEventListener('pointermove', (event) => {
    if (event.pointerId === activeId) onMove(event.clientX - startX);
  }, options);

  function finish(event) {
    if (event.pointerId !== activeId) return;
    const id = activeId;
    activeId = null;
    if (element.hasPointerCapture(id)) element.releasePointerCapture(id);
    onEnd({ cancelled: event.type !== 'pointerup' });
  }

  element.addEventListener('pointerup', finish, options);
  element.addEventListener('pointercancel', finish, options);
  element.addEventListener('lostpointercapture', finish, options);

  return () => {
    controller.abort();
    if (activeId !== null) {
      const id = activeId;
      activeId = null;
      if (element.hasPointerCapture(id)) element.releasePointerCapture(id);
      onEnd({ cancelled: true });
    }
  };
}

setPointerCapture 把后续相关指针事件的目标绑定到该元素，即使指针移出边界也能继续收到事件。先清空 activeId 再释放捕获，可以避免 lostpointercapture 又触发一次结束回调。

这不是完整拖拽组件：拖动阈值、最终位置约束、点击抑制和状态渲染仍需业务实现。onMove 应轻量，复杂更新可按动画帧合并，避免每个移动事件都触发布局测量。

touch-action 决定浏览器可以接管哪些手势

如果是横向拖动控件，仍希望页面可以纵向滚动，可考虑在目标区域预先设置：

CSS
.drag-handle {
  touch-action: pan-y pinch-zoom;
}

浏览器仍可接管纵向平移与缩放；当它决定接管手势时，页面可能收到 pointercancel。若绘图画布确实需要完全处理触摸，可在有限区域使用 none，但不应为了一个控件禁用整页缩放和滚动。

touch-action 应在手势开始前确定，事件进行中再改通常不会改变已经作出的手势决策。不要只依赖对每个 move 调用 preventDefault 来代替它。

取消不是不重要的边角情况

浏览器滚动接管、系统中断、捕获丢失或组件卸载都可能让操作没有正常 pointerup。只在 pointerup 清理，会留下拖拽中的样式或错误状态。

取消与正常完成应区分，例如排序列表取消时恢复原位置，而不是把最后一个中间位置提交。若交互依赖窗口焦点，也要按产品需要处理失焦等退出路径。

Pointer Events 只覆盖指针输入，不自动提供键盘可访问性。拖动滑块、排序或调整数值还应提供适合键盘及辅助技术的操作方式。验证应覆盖真实触摸、触控笔或鼠标的目标设备，合成事件只能检查处理逻辑，不能证明手势仲裁与硬件压力数据一致。
