Pointer Events 为什么适合统一鼠标、触摸和触控笔交互？

理解 pointerdown、pointermove、pointerup、pointerId 和 pointer capture，避免为不同输入设备维护重复逻辑。

参考答案

简答

  • Pointer Events 用同一组事件（pointerdown、pointermove、pointerup、pointercancel）处理鼠标、触摸和触控笔，不必分别监听 mouse 和 touch 事件。
  • 每个接触点有独立的 pointerId，多指操作时按 ID 区分；pointerType 区分 mouse、touch、pen。
  • setPointerCapture 让后续事件都发给当前元素，手指移出元素范围也不会丢失拖动。
  • 触摸时浏览器可能接管手势（滚动、缩放）并发送 pointercancel，交互必须处理取消；用 CSS touch-action 告诉浏览器哪些手势留给页面。
  • 原有的 click 事件仍然会触发，按钮类交互继续用 click 即可。

为什么不再分开监听

旧做法同时监听 touchstart 和 mousedown，还要防止触摸后浏览器补发的模拟鼠标事件导致重复执行。Pointer Events 把这些统一成一套模型，触控笔的压力（pressure）、倾斜角度（tiltX）等信息也放在同一个事件对象里。

一个拖动滑块

JavaScript
function makeDraggable(handle, onMove) {
  let activeId = null;
  let startX = 0;

  handle.addEventListener('pointerdown', (event) => {
    if (activeId !== null || event.button !== 0) return;
    activeId = event.pointerId;
    startX = event.clientX;
    handle.setPointerCapture(event.pointerId);
  });

  handle.addEventListener('pointermove', (event) => {
    if (event.pointerId !== activeId) return;
    onMove(event.clientX - startX);
  });

  const end = (event) => {
    if (event.pointerId !== activeId) return;
    activeId = null;
  };
  handle.addEventListener('pointerup', end);
  handle.addEventListener('pointercancel', end);
  handle.addEventListener('lostpointercapture', end);
}
CSS
.handle { touch-action: none; }
  • 只跟踪第一个按下的指针，其他手指的事件被忽略。
  • event.button !== 0 过滤掉鼠标右键。
  • 捕获后即使指针移出 handle，pointermove 和 pointerup 仍发给它；pointerup 后浏览器自动释放捕获。
  • 滑块需要接管所有触摸移动，所以设为 touch-action: none。

touch-action

值浏览器保留的手势
auto全部（默认）
pan-y只有纵向滚动，横向移动和双指缩放交给页面
pan-y pinch-zoom纵向滚动和双指缩放，横向移动交给页面
none都不保留，页面处理所有触摸

touch-action 必须在手势开始前就设置好，在 pointerdown 里调用 preventDefault() 不能阻止滚动。只禁用真正需要的手势，否则用户无法滚动或缩放页面。和滚动方向冲突的手势处理见《移动端手势交互怎样避免和页面滚动冲突？》。

键盘和无障碍

拖动只是一种输入方式。滑块应同时支持方向键调整值，并使用原生 <input type="range"> 或正确的 ARIA 角色，读屏用户才能操作。

常见追问

  • 为什么拖动时偶尔会停住？浏览器开始滚动并发送了 pointercancel，检查 touch-action 是否设置正确。
  • pointerleave 和捕获有什么关系？捕获期间事件都派发给捕获元素，指针移出它的范围也不会触发 pointerleave，直到释放捕获；拖动因此不会中断。
