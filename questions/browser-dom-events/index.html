addEventListener 的 capture、once、passive 和 signal 有什么作用？

capture 让监听器在事件往下传时就触发，once 让它只执行一次，passive 告诉浏览器不会阻止默认行为，滚动能马上开始，signal 能用 AbortController 一次移除一组监听器。

参考答案

简答

addEventListener 的第三个参数可以传一个对象，常用的有四个选项。capture: true 让监听器在捕获阶段触发，默认是在冒泡阶段。once: true 让监听器执行一次就自动移除。

passive: true 是告诉浏览器“我不会调用 preventDefault()”。这样浏览器处理滚动时不用等监听器跑完，滚动可以马上开始，页面更流畅。

signal 接收一个 AbortSignal，调用 abort() 以后，用这个 signal 注册的监听器都会被移除，适合组件卸载时一次清理一组监听器。

要注意，在 window、document 这些对象上注册 touchstart、touchmove、wheel 时，passive 默认就是 true，想阻止滚动得显式写 passive: false。

事件是怎么传的

点击一个按钮，事件会走三段路。先是捕获阶段，从 window 一层层往下传到按钮的父元素。然后是目标阶段，到达按钮本身。最后是冒泡阶段，从按钮一层层往上传回 window。

默认情况下监听器在冒泡阶段触发。加了 capture: true，就改成在往下传的路上触发，所以外层元素能比里层先拿到事件。

移除监听器时有个细节：removeEventListener 要传入同一个函数和同样的 capture 值才能移除。once、passive 不参与匹配，写不写都一样。

passive 为什么能让滚动更流畅

touchstart、touchmove、wheel 的监听器里可能会调用 preventDefault() 来阻止滚动。浏览器不知道你会不会这么做，所以只能等监听器执行完，才能决定滚不滚。监听器一慢，滚动就卡。

声明 passive: true，等于提前承诺不会阻止，浏览器就能不等监听器，立刻开始滚动。

DOM 规范还规定了一条默认值：在 window、document、documentElement 或 body 上注册 touchstart、touchmove、wheel、mousewheel 时，passive 默认为 true。这时调用 preventDefault() 会被忽略。所以如果确实要阻止滚动，得显式写 passive: false。

用 signal 一次清理一组监听器

拖拽功能通常要注册三个监听器。卸载时一个个 removeEventListener，就得把每个函数的引用都存好。用 signal 就简单多了：

JavaScript
function bindDrag(element) {
  const controller = new AbortController();
  const { signal } = controller;

  element.addEventListener('pointerdown', onDown, { signal });
  window.addEventListener('pointermove', onMove, { signal, passive: true });
  window.addEventListener('pointerup', onUp, { signal });

  return () => controller.abort();
}

三个监听器都用同一个 signal 注册。组件卸载时调用返回的函数，abort() 一下，三个一起移除。

还有一个边界：如果传进去的 signal 已经 abort 过了，监听器根本不会被注册。

常见追问

stopPropagation() 和 stopImmediatePropagation() 有什么区别？

stopPropagation() 阻止事件继续传到其他元素，但同一个元素上后面的监听器还会执行。stopImmediatePropagation() 连同一个元素上后面的监听器也一起拦住。

preventDefault() 和 stopPropagation() 有关系吗？

没关系，互不影响。preventDefault() 取消的是默认行为，比如链接跳转；stopPropagation() 停止的是事件传播。调用一个不会影响另一个。
