addEventListener 的 capture、once、passive 和 signal 有什么作用？

capture 决定在捕获阶段还是冒泡阶段触发，once 让监听器只执行一次，passive 声明不会调用 preventDefault，signal 用 AbortController 统一移除监听器。

参考答案

简答

  • capture: true 让监听器在捕获阶段触发，默认在冒泡阶段。
  • once: true 让监听器执行一次后自动移除。
  • passive: true 声明监听器不会调用 preventDefault()，浏览器可以不等它执行完就开始滚动。
  • signal 接收一个 AbortSignal，abort() 后监听器被移除，适合一次清理一组监听器。

事件传播的三个阶段

  1. 捕获阶段：从 window 向下传到目标的父元素。
  2. 目标阶段：到达目标元素。
  3. 冒泡阶段：从目标向上传回 window。

removeEventListener 必须传入相同的函数和相同的 capture 值才能移除，once、passive 不参与匹配。

passive

touchstart、touchmove、wheel 的监听器可能调用 preventDefault() 阻止滚动，浏览器原本要等监听器执行完才能决定是否滚动。声明 passive: true 后滚动可以立即开始。

DOM 规范规定：在 window、document、documentElement 或 body 上注册 touchstart、touchmove、wheel、mousewheel 时，passive 默认为 true。此时调用 preventDefault() 会被忽略，需要阻止滚动时要显式写 passive: false。

signal 统一清理

JavaScript
function bindDrag(element) {
  const controller = new AbortController();
  const { signal } = controller;

  element.addEventListener('pointerdown', onDown, { signal });
  window.addEventListener('pointermove', onMove, { signal, passive: true });
  window.addEventListener('pointerup', onUp, { signal });

  return () => controller.abort();
}

组件卸载时调用返回的函数，三个监听器一起移除，不需要保留每个函数的引用。传入已经 abort 的 signal 时，监听器不会被注册。

常见追问

  • stopPropagation() 和 stopImmediatePropagation()：前者阻止事件继续传到其他元素，后者还会阻止同一元素上后续的监听器。
  • preventDefault() 和 stopPropagation() 互不影响：一个取消默认行为，一个停止传播。
