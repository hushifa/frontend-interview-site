Web Worker 可以解决哪些主线程卡顿？

Web Worker 在独立线程运行脚本，适合解析、压缩、加密、大数据计算等 CPU 密集任务；它不能访问 DOM，通信靠 postMessage 的结构化克隆或转移。

参考答案

简答

  • Worker 在后台线程执行脚本，长时间的计算不会阻塞主线程的输入响应和渲染。
  • Worker 不能操作 DOM，界面更新仍由主线程完成。
  • 主线程和 Worker 用 postMessage 通信，数据默认被结构化克隆；ArrayBuffer 等可以转移所有权，避免复制。
  • 适合 JSON 解析、图片处理、压缩加密、搜索索引等 CPU 密集任务；网络请求本身是异步的，放进 Worker 通常没有收益。

基本用法

JavaScript
// main.js
const worker = new Worker(new URL('./parse.worker.js', import.meta.url), { type: 'module' });

worker.onmessage = (event) => render(event.data);
worker.onerror = (event) => console.error(event.message);

const buffer = await file.arrayBuffer();
worker.postMessage(buffer, [buffer]);
JavaScript
// parse.worker.js
self.onmessage = (event) => {
  const text = new TextDecoder().decode(event.data);
  self.postMessage(JSON.parse(text));
};

postMessage(buffer, [buffer]) 转移之后，主线程里的 buffer.byteLength 变为 0，不能再使用。

通信成本

  • 结构化克隆要遍历并复制数据，传一个很大的对象本身也可能耗时几十毫秒，这部分成本在发送方线程上。
  • 函数、DOM 节点、带原型的类实例方法无法克隆。
  • 返回结果也要克隆一次。数据量大时，传 ArrayBuffer 并转移所有权，或只返回主线程需要的部分。

Worker 的种类

  • Dedicated Worker：只属于创建它的页面，最常用。
  • SharedWorker：同源的多个页面共享一个实例。
  • Service Worker：拦截网络请求，用于离线缓存和推送，生命周期由浏览器管理。

常见追问

  • Worker 能用哪些 API：fetch、IndexedDB、WebSocket、OffscreenCanvas、定时器等，不能用 document、window 和 localStorage。
  • 怎样取消任务：调用 worker.terminate() 立即终止线程；只想取消单个任务时，在消息里带任务 ID，Worker 在循环中检查取消标记。
  • 多个任务怎么调度：创建固定数量的 Worker 组成池，数量参考 navigator.hardwareConcurrency。
