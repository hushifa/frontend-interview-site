WebRTC 的 perfect negotiation 如何避免协商碰撞？

perfect negotiation 给双方分配礼貌和不礼貌两个角色，两边同时发出 offer 时，不礼貌方忽略对方的 offer，礼貌方通过隐式回滚接受对方的 offer；双方代码相同，只是 polite 取值不同。

参考答案

简答

  • 双方同时添加轨道或重新协商时，会各自发出 offer，这叫协商碰撞（glare）。
  • 一方设为 polite = true，另一方为 false，例如先连上信令服务器的一方是礼貌方。
  • 判断碰撞用自己维护的 makingOffer 和 isSettingRemoteAnswerPending，不要只看 signalingState，它是异步变化的。
  • 碰撞时不礼貌方忽略收到的 offer；礼貌方直接 setRemoteDescription(offer)，浏览器会隐式回滚自己的 offer，然后应答。
  • 被忽略的 offer 附带的 ICE 候选，addIceCandidate 报错时要忽略。

完整代码

JavaScript
// 两端代码相同，只有 polite 不同：一端为 true，另一端为 false。
const polite = isFirstToJoin;
let makingOffer = false;
let ignoreOffer = false;
let isSettingRemoteAnswerPending = false;

pc.onnegotiationneeded = async () => {
  try {
    makingOffer = true;
    await pc.setLocalDescription();
    signaler.send({ description: pc.localDescription });
  } catch (error) {
    console.error(error);
  } finally {
    makingOffer = false;
  }
};

pc.onicecandidate = ({ candidate }) => signaler.send({ candidate });

signaler.onmessage = async ({ data: { description, candidate } }) => {
  try {
    if (description) {
      const readyForOffer =
        !makingOffer && (pc.signalingState === 'stable' || isSettingRemoteAnswerPending);
      const offerCollision = description.type === 'offer' && !readyForOffer;

      ignoreOffer = !polite && offerCollision;
      if (ignoreOffer) return;

      isSettingRemoteAnswerPending = description.type === 'answer';
      await pc.setRemoteDescription(description);
      isSettingRemoteAnswerPending = false;

      if (description.type === 'offer') {
        await pc.setLocalDescription();
        signaler.send({ description: pc.localDescription });
      }
    } else if (candidate) {
      try {
        await pc.addIceCandidate(candidate);
      } catch (error) {
        if (!ignoreOffer) throw error;
      }
    }
  } catch (error) {
    console.error(error);
  }
};

关键点解释

  • 不传参数的 setLocalDescription()：浏览器根据当前状态自动创建 offer 或 answer，省去 createOffer 和状态判断。
  • makingOffer：从开始创建 offer 到发送出去之间，signalingState 可能还是 stable，单看状态会漏判碰撞。
  • isSettingRemoteAnswerPending：本端正在应用对方的 answer 时，状态仍是 have-local-offer，但协商马上就会回到 stable，这时收到新 offer 不算碰撞。
  • 隐式回滚：礼貌方在 have-local-offer 状态下调用 setRemoteDescription(offer)，现代浏览器会自动回滚本地 offer，不需要手动传 { type: 'rollback' }。

为什么双方代码一样

两边只有 polite 不同，其他逻辑完全相同。任何一方都可以在任何时候添加或移除轨道、重启 ICE，negotiationneeded 会自动触发协商，碰撞由角色决定谁让步。
