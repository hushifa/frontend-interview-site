为什么 100% 代码覆盖率也可能漏掉严重问题？

覆盖率只说明哪些代码在测试中执行过，不说明结果被断言过；没写的分支、边界值、并发和外部系统问题都不在统计范围内。覆盖率适合发现完全没测的代码，不适合当质量目标。

参考答案

简答

  • 执行到不等于验证到：测试调用了函数但没有断言返回值，覆盖率照样是 100%。
  • 覆盖率只统计已有的代码，漏写的逻辑（例如缺少空值判断）没有对应代码，也就不会显示为未覆盖。
  • 行覆盖率高时分支覆盖率可能很低，a && b 只测了一种情况也算这一行已覆盖。
  • 报告只包含被加载的文件；没有任何测试导入的文件可能根本不在报告里，需要配置 coverage.include。
  • 用覆盖率找出没测的高风险代码，用变异测试检查断言是否有效。

执行但没验证

TypeScript
export function discount(price: number, vip: boolean) {
  return vip ? price * 0.8 : price;
}
TypeScript
test('计算折扣', () => {
  discount(100, true);
  discount(100, false);
});

两个分支都执行了，覆盖率 100%，但把 0.8 改成 0.5 测试也能通过。

漏写的逻辑

TypeScript
export function average(values: number[]) {
  return values.reduce((sum, v) => sum + v, 0) / values.length;
}

test('求平均值', () => {
  expect(average([1, 2, 3])).toBe(2);
});

覆盖率 100%，但空数组返回 NaN 的问题完全没有被发现，因为处理空数组的代码根本不存在。

配置

TypeScript
// vitest.config.ts
export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      include: ['src/**/*.{ts,tsx}'],
      thresholds: { branches: 80 },
    },
  },
});

include 让没有被测试导入的文件也出现在报告里，显示为 0%。门槛可以防止覆盖率明显下降，但单纯追求数字会催生“只调用、不断言”的测试。

覆盖率看不到的问题

  • 并发和竞态：两个请求返回顺序颠倒。
  • 浏览器差异和布局问题。
  • 与真实后端的契约不一致。
  • 性能和内存泄漏。

常见追问

  • 覆盖率目标定多少合适？没有统一的数字。核心业务逻辑和工具函数追求高分支覆盖，界面胶水代码依靠组件和端到端测试，比统一要求 100% 更有效。断言质量可以用变异测试检查，见《变异测试如何发现“覆盖率很高但测试没测到重点”？》。
