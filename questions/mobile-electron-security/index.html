Electron 应用的主进程、渲染进程和 IPC 有哪些安全边界？

区分 Electron 主进程与渲染进程的权限，说明 preload、contextIsolation、IPC 校验和远程内容风险，避免把桌面应用当成普通浏览器页面。

参考答案

Electron 渲染进程看起来像网页，但应用通常还拥有文件系统、进程和系统 API 能力。若把不可信网页直接放进拥有 Node.js 权限的渲染进程，一个 XSS 就可能升级成读取文件或执行命令的问题。

因此要把“显示界面”和“执行高权限操作”分开。主进程管理窗口和系统能力，渲染进程负责 UI，preload 通过受限 API 连接两者。

默认收紧渲染进程权限

JavaScript
const win = new BrowserWindow({
  webPreferences: {
    preload: path.join(__dirname, 'preload.js'),
    contextIsolation: true,
    nodeIntegration: false,
    sandbox: true,
  },
});

contextIsolation 让 preload 和页面脚本使用不同的 JavaScript 全局环境；nodeIntegration: false 不把 Node 能力直接暴露给网页；sandbox 进一步限制渲染进程。具体选项和版本行为要按当前 Electron 版本核对，不能只复制一段配置就宣布安全。

不要为了让旧代码运行而打开 nodeIntegration，也不要把完整的 ipcRenderer、remote 或 require 挂到 window 上。页面脚本一旦被注入，就可能调用这些高权限入口。

preload 只暴露最小、参数化的能力

JavaScript
// preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('settings', {
  chooseFile: () => ipcRenderer.invoke('settings:choose-file'),
  saveTheme: (theme) => {
    if (!['light', 'dark', 'system'].includes(theme)) {
      throw new TypeError('主题值无效');
    }
    return ipcRenderer.invoke('settings:save-theme', theme);
  },
});

这里暴露的是有限的业务函数，不是一个可以传任意频道和任意参数的通用 IPC 代理。主进程仍要验证参数、当前窗口、用户权限和文件路径；渲染进程的校验只能改善错误提示，不能成为安全边界。

主进程处理器也要限制能力：

JavaScript
ipcMain.handle('settings:save-theme', (event, theme) => {
  if (!['light', 'dark', 'system'].includes(theme)) {
    throw new Error('非法主题');
  }
  const sender = BrowserWindow.fromWebContents(event.sender);
  if (!sender) throw new Error('未知窗口');
  return saveThemeForWindow(sender.id, theme);
});

IPC 消息是跨边界输入，必须做运行时验证。不要相信频道名称、渲染进程传来的用户 ID 或窗口里隐藏的权限字段；重要操作还要在服务端或主进程的受控配置中确认。

远程页面和本地页面不能混在同一信任等级

如果应用加载远程 URL，远程内容可能更新、被劫持或包含第三方脚本。不要让它共享本地页面的高权限 preload；更稳妥的方案是使用独立窗口、严格允许列表、CSP、导航拦截和最小权限。

外部链接应在系统浏览器中打开或经过明确的安全处理，不能允许任意导航到一个仍拥有本地桥接 API 的页面。will-navigate、新窗口和重定向都要处理，不能只检查首次 URL。

Markdown、网页内容和用户输入仍要按不可信内容渲染。Electron 应用不会因为打包成桌面程序就自动免疫 XSS；反而因为权限更大，注入后的影响可能更严重。

文件、命令和更新都是高风险能力

主进程若根据渲染进程传来的路径读取文件，必须使用用户选择的句柄、允许目录和规范化检查，避免路径穿越与符号链接问题。调用外部命令时优先使用固定可执行文件和参数数组，不要把输入拼进 shell 字符串。

自动更新要验证下载来源、签名、版本和失败回滚；“有 HTTPS”不等于更新包本身已经可信。更新失败不能让应用陷入无限重试，也不能在未验证的情况下执行下载内容。

日志和崩溃报告要过滤文件路径、令牌和个人数据。桌面应用通常能访问更多本地信息，诊断上报的隐私边界也更大。

IPC 设计还要考虑生命周期和拒绝服务

窗口关闭后，渲染进程可能仍有待完成的 IPC；处理器要能识别销毁窗口、取消长任务和释放监听。渲染进程可以快速发送大量消息，因此主进程要限制消息大小、频率和并发，不能让一个窗口占满文件、CPU 或网络资源。

测试要覆盖 XSS 内容、恶意 IPC 参数、导航到外部来源、窗口关闭、文件路径边界、命令失败和更新失败。开发环境中关闭安全选项可能方便调试，但生产配置必须单独验证；Electron 的安全边界来自权限设计和隔离，而不是“它能运行网页”这一事实。
