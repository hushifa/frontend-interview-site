Electron 应用的主进程、渲染进程和 IPC 有哪些安全边界？

区分 Electron 主进程与渲染进程的权限，说明 preload、contextIsolation、IPC 校验和远程内容风险，避免把桌面应用当成普通浏览器页面。

参考答案

简答

  • 主进程运行 Node.js，能访问文件系统和操作系统；渲染进程显示网页内容，应当只有普通网页的权限。
  • 渲染进程通过 preload 脚本用 contextBridge 暴露少量明确的函数，再由主进程经 IPC 执行特权操作。
  • 保持默认的安全设置：nodeIntegration: false（5.0 起默认）、contextIsolation: true（12.0 起默认）、sandbox: true（20.0 起默认）。
  • 主进程要校验每条 IPC 消息的发送方（senderFrame 的 origin）和参数，不能信任渲染进程传来的任何内容。
  • 用 setWindowOpenHandler 拦截新窗口，外部链接交给系统浏览器打开前要校验协议和地址；用 Fuses 关闭 runAsNode 等打包后不需要的能力。

为什么渲染进程要按"不可信"对待

渲染进程显示的内容可能包含第三方脚本、用户生成的富文本，或者加载了远程页面。只要出现一处 XSS，攻击者就能执行渲染进程里的任何能力。如果渲染进程能直接调用 require('child_process')，XSS 就变成了在用户电脑上执行任意命令。

preload 只暴露最小能力

JavaScript
// preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('api', {
  saveNote: (id, text) => ipcRenderer.invoke('note:save', { id, text }),
});
  • 暴露具体业务函数，不要暴露 ipcRenderer 本身或通用的 invoke(channel, ...args)，否则页面可以调用任意通道。
  • contextIsolation 让 preload 和页面运行在不同的 JavaScript 上下文，页面无法篡改 preload 中的对象。

主进程校验发送方和参数

JavaScript
// main.js
const { ipcMain, app } = require('electron');
const path = require('node:path');
const fs = require('node:fs');

const ALLOWED_ORIGINS = new Set(['app://bundle']);

function isTrustedSender(event) {
  const frame = event.senderFrame;
  return frame !== null && ALLOWED_ORIGINS.has(frame.origin);
}

ipcMain.handle('note:save', async (event, payload) => {
  if (!isTrustedSender(event)) throw new Error('拒绝来自未知页面的请求');

  const { id, text } = payload ?? {};
  if (typeof id !== 'string' || !/^[a-z0-9-]{1,64}$/.test(id)) throw new Error('非法 ID');
  if (typeof text !== 'string' || text.length > 100_000) throw new Error('非法内容');

  const file = path.join(app.getPath('userData'), 'notes', `${id}.md`);
  await fs.promises.writeFile(file, text, 'utf8');
});
  • iframe 和子窗口也能发送 IPC，所以要检查 senderFrame。官方示例比较的是 origin 而不是 URL，因为 about:blank、blob: 等地址看不出实际控制者；frame 已销毁时 senderFrame 为 null。
  • ID 用白名单格式校验，防止 ../../ 路径穿越写到任意位置。
  • 示例中的 app://bundle 假设应用用自定义协议加载本地页面，需要和实际加载方式一致。

新窗口和外部链接

JavaScript
win.webContents.setWindowOpenHandler(({ url }) => {
  const { protocol, hostname } = new URL(url);
  if (protocol === 'https:' && hostname === 'docs.example.com') {
    setImmediate(() => shell.openExternal(url));
  }
  return { action: 'deny' };
});

shell.openExternal 遇到不受信任的地址（如 file: 或自定义协议）可能被用来执行命令，所以只放行明确允许的地址。同样要监听 will-navigate，阻止主窗口被导航到外部页面。

其他要点

  • 尽量不加载远程内容；必须加载时，用独立的 BrowserWindow 或 WebContentsView，不给它 preload 能力。
  • 为本地页面设置 CSP，限制脚本来源。
  • 使用 @electron/fuses 在打包时关闭 runAsNode、nodeCliInspect 等，防止应用被当作 Node.js 解释器执行任意脚本。
  • 及时升级 Electron，它内置的 Chromium 会持续修复安全漏洞。

常见追问

  • 打开 nodeIntegration 有多危险？它会让该渲染进程不再运行在沙箱中，页面脚本可以直接使用 Node.js API，渲染进程中的任何 XSS 都能执行系统命令。
  • preload 里能用 Node API 吗？开启沙箱后 preload 只能使用一部分 Electron 和 Node 模块，文件读写等操作应放到主进程。
