flex-basis、flex-grow、flex-shrink 如何分配空间？

flex-basis 提供主轴基础尺寸，flex-grow 分配正剩余空间，flex-shrink 按收缩系数乘基础尺寸分摊负剩余空间；内容最小尺寸和 min/max 约束仍可能改变最终结果。

参考答案

Flex 可以把一行项目理解成“先确定各自的起点，再处理多出来或不够用的空间”。flex-basis 决定起点，flex-grow 决定有空余时怎么增加，flex-shrink 决定空间不足时怎么减少。

它们处理的是主轴尺寸。flex-direction: row 的常见横排页面中是宽度；改成 column 后则通常是高度。换行布局中，每一行分别分配空间，上一行的项目宽度不会自动成为下一行的统一列宽。

从基础尺寸开始

CSS
.item {
  flex: 1 1 200px;
}

三个值依次是 grow、shrink、basis。这表示以 200px 为基础，允许增长，也允许收缩，并不是承诺最终宽度永远是 200px。

flex-basis: auto 会参考主轴对应的尺寸属性，例如横向布局里的 width；如果该尺寸也是 auto，就进一步根据内容确定基础尺寸。明确写了非 auto 的 flex-basis 时，计算基础尺寸主要使用它，而不能把另一个 width 当成最终固定宽度。

多出的空间怎么分

假设容器内容宽度是 600px，两个项目的基础宽度都是 100px，没有外边距、边框、内边距和间隙，也没有最小/最大尺寸干预。剩余空间是 600 - 100 - 100 = 400px。

A 的 flex-grow 是 1，B 是 3，则多出的 400px 按 1:3 分配：

项目基础宽度分到的空间最终宽度
A100px100px200px
B100px300px400px

注意分配比例作用于增加量，不是最终宽度。因此 grow 为 1 和 3，不代表两个项目最终宽度就是 1:3。

当增长系数总和小于 1 时，Flex 还有部分填充规则，可能留下未分配空间。例如单个项目 flex-grow: 0.5 不一定吃完所有空余。上面的比例计算以常见的系数总和不小于 1 为前提。

不够用的空间为什么不是平均减

换一个例子：容器只有 300px，A 的基础宽度为 200px，B 为 400px，两者的 flex-shrink 都为 1。总共需要收缩 300px。

收缩的权重需要乘上基础尺寸：A 是 1 × 200，B 是 1 × 400，所以减少量按 1:2 分配。A 减少 100px 后剩 100px，B 减少 200px 后剩 200px。

可以在横排浏览器页面中运行这个完整的简化例子：

HTML
<div class="shrink-demo">
  <div class="a">A</div>
  <div class="b">B</div>
</div>
CSS
.shrink-demo {
  display: flex;
  width: 300px;
}

.shrink-demo > div {
  min-width: 0;
}

.shrink-demo .a {
  flex: 0 1 200px;
  background: #e2e8f0;
}

.shrink-demo .b {
  flex: 0 1 400px;
  background: #cbd5e1;
}

如果两项的 shrink 不同，继续按“收缩系数 × 基础尺寸”计算相对权重。设置为 0 就是不参与收缩，但不意味着其他项目一定能挤出足够空间，容器仍可能溢出。

真实算法还会处理 min-width、max-width 等限制：某项达到限制后会被冻结，剩下的空间重新分配。不能忽略约束，把上面的算式当成所有页面的完整求解公式。

flex: 1 之后为什么长文字还是撑开容器

常见的 Flex 项目默认 min-width: auto，其自动最小尺寸可能受内容影响。一个不能断开的长网址或 white-space: nowrap 的标题，就可能使它不能缩到你希望的宽度。

CSS
.row {
  display: flex;
  gap: 1rem;
}

.content {
  flex: 1;
  min-width: 0;
}

.title {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}

.actions {
  flex: 0 0 auto;
}

假设 .content 与 .actions 是 .row 的直接子项，.title 在 .content 内。min-width: 0 允许内容区真正缩小；标题的三个溢出属性才负责把放不下的文字显示成省略号。只写省略号而没有解决父级最小宽度，可能没有效果。纵向 Flex 滚动区域中则经常需要检查相应的 min-height: 0。

常见简写可这样区分：flex: initial 是 0 1 auto，可以缩小但不主动增长；flex: auto 是 1 1 auto，从自身尺寸出发伸缩；flex: none 是 0 0 auto，不参与伸缩。

浏览器中 flex: 1 通常展开为 1 1 0%。在主轴尺寸明确的常见布局中，零基础尺寸有助于按增长系数分配空间；但 0% 和明确的 0px 并不总是等价。容器主轴尺寸不确定时，百分比基础尺寸可能按内容处理。再加上内容最小尺寸、内边距等因素，不能把 flex: 1 简化成“永远等宽”。
