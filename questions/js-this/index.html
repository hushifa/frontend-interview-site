普通函数和箭头函数的 this 有什么区别？

普通函数的 this 通常由调用方式决定，箭头函数沿用外层词法作用域的 this。方法脱离对象后直接调用会失去接收者；严格模式下访问 undefined 的属性会抛错，而不是返回 undefined。

参考答案

简答

  • 普通函数的 this 由调用方式决定：方法调用指向对象，直接调用在严格模式下是 undefined。
  • 箭头函数没有自己的 this，沿用定义处外层的 this。
  • call、apply、bind 可以指定普通函数的 this，对箭头函数无效。
  • 把方法作为回调传出时 this 会丢失，可以用 bind 或箭头函数包装。

普通函数里的 this 可以理解成调用时传入的一个隐含参数。函数写在哪个对象里，不足以决定 this；还要看最后怎样调用它。 箭头函数则没有自己的 this，会沿着创建位置的词法作用域使用外层的 this。

例如，user.read() 是带接收者的调用，接收者是 user。但 const read = user.read; read() 先取出函数，再直接调用；函数本身没有变化，原来的接收者却没有一起带过来。

先看一个可以实际运行的例子

JavaScript
'use strict';

const obj = {
  value: 42,
  read() {
    return this.value;
  },
  later() {
    return () => this.value;
  },
};

console.log(obj.read()); // 42

const read = obj.read;
try {
  read();
} catch (error) {
  console.log(error.name); // TypeError
}

console.log(read.call({ value: 7 })); // 7

const later = obj.later();
console.log(later.call({ value: 7 })); // 42
obj.value = 99;
console.log(later()); // 99

read() 直接调用时，严格模式函数的 this 是 undefined。但是函数体执行的是 this.value，相当于访问 undefined.value，因此会抛出 TypeError。只有函数体直接 return this，才会返回 undefined。这两个结论不能混写。

read.call({ value: 7 }) 显式提供接收者，所以能读取到 7。obj.later() 的 this 是 obj，里面创建的箭头函数沿用这个 this；以后即使用 call 提供另一个对象，也不会换掉它的接收者。

最后输出 99，是因为箭头函数保留了访问 obj 的方式，并没有把当时的 obj.value 数字复制一份。调用时仍然会读取对象上的当前属性值。

普通函数有哪些调用方式

调用形式对普通、未绑定函数的影响
obj.fn()接收者是 obj，即便函数来自原型链
fn()严格模式下 this 是 undefined
fn.call(obj, a, b)立即调用，以 obj 为 this，参数逐个传入
fn.apply(obj, [a, b])立即调用，以 obj 为 this，参数由数组或类数组提供
fn.bind(obj)返回一个绑定函数，以后普通调用时使用绑定的 obj
new Fn()若 Fn 可构造，调用时 this 指向新创建的实例

非严格普通函数还有转换规则：null、undefined 会被替换成全局对象，原始值会被装箱。ES 模块和类中的代码处于严格模式，实际项目不要依赖老式脚本的全局对象兜底。

bind 不会修改原函数，而是生成包装后的函数。已绑定的普通函数再次使用 call 或 apply，不能改掉先前绑定的接收者；但若绑定目标可构造，new 调用绑定函数时会使用新实例，忽略绑定的 this，绑定参数仍可生效。箭头函数本身不可构造，给它 bind 也不会获得构造能力。

为什么对象属性里的箭头函数容易误用

JavaScript
function makeCounter() {
  'use strict';
  return {
    count: 0,
    read: () => this.count,
  };
}

对象字面量不会创建一个供箭头函数使用的 this 作用域。这里的 read 用的是 makeCounter 执行时的 this，不是返回对象的 this。如果直接调用 makeCounter()，外层 this 是 undefined，之后执行 counter.read() 就会报错。

要读取返回对象本身，可以把 read 写成普通方法 read() { return this.count; }。如果希望无论怎样传递函数都绑定到同一个实例，类字段箭头函数则是另一种合理用法：它在实例初始化上下文中取得实例的 this。代价是每个实例通常有自己的函数对象，而不是共享原型上的方法函数。

回调会怎样丢失接收者

setTimeout(obj.read, 0)、items.map(obj.read) 都是在传函数值，没有传递原先的 obj.read() 调用表达式。回调最终怎样被调用，取决于接收它的 API。不要一概断言所有回调里的 this 都是 undefined，不同 API 可能提供不同接收者。

需要保留对象时，可以用 const boundRead = obj.read.bind(obj)，或者传 () => obj.read()。前者固定原函数和接收者；后者到执行时再读取 obj.read，如果方法后来被替换，行为也会不同。

事件监听尤其要留意函数身份：addEventListener 时临时调用一次 bind，移除时再调用一次 bind，得到的是两个不同函数，无法靠第二个函数移除第一个监听器。应保存同一引用用于注册与清理。

箭头函数也没有自己的 arguments，需要参数列表时通常用剩余参数 (...args)。它适合让回调继续使用外层上下文；普通方法适合由调用者提供接收者。选择依据是函数需要哪一种语义，而不是哪一种语法更短。
