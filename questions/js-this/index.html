普通函数和箭头函数的 this 有什么区别？

普通函数的 this 由调用方式决定：方法调用、直接调用、call/apply/bind、new 各不相同。箭头函数没有自己的 this，沿用定义时外层作用域的 this，call 和 bind 也改不了它。

参考答案

简答

  • 普通函数的 this 在调用时确定：obj.fn() 是 obj，直接调用 fn() 在严格模式下是 undefined，new 调用是新实例。
  • call、apply 临时指定 this，bind 返回固定了 this 的新函数；优先级为 new > bind > call/apply > 方法调用 > 直接调用。
  • 箭头函数没有自己的 this，按词法作用域读取定义位置外层的 this，call、bind 都改不了；箭头函数也不能用 new 调用。
  • 方法被单独取出后直接调用会丢失接收者，常见于回调和解构。

示例

JavaScript
'use strict';

const obj = {
  value: 42,
  read() {
    return this.value;
  },
  later() {
    return () => this.value;
  },
};

console.log(obj.read()); // 42

const read = obj.read;
try {
  read();
} catch (error) {
  console.log(error.name); // TypeError
}

console.log(read.call({ value: 7 })); // 7

const later = obj.later();
console.log(later.call({ value: 7 })); // 42
obj.value = 99;
console.log(later()); // 99
  • read() 直接调用，严格模式下 this 是 undefined，读取属性抛 TypeError。非严格模式下 this 是全局对象，结果是 undefined 而不是报错。ES 模块和 class 内部默认是严格模式。
  • later() 返回的箭头函数在 later 执行时定义，this 固定为 obj。call 传入的对象被忽略；之后修改 obj.value，箭头函数读到的是新值。

箭头函数外层作用域的 this

DOM 事件监听器用普通函数时，this 是 currentTarget；用箭头函数时是外层的 this。

回调中丢失 this

JavaScript
class Timer {
  count = 0;
  start() {
    setInterval(this.tick, 1000); // tick 内 this 为 undefined
  }
  tick() {
    this.count += 1;
  }
}

修复方式：

  • 传入箭头函数：setInterval(() => this.tick(), 1000)。
  • 构造时绑定：this.tick = this.tick.bind(this)。
  • 把方法写成类字段箭头函数：tick = () => { this.count += 1; }。代价是每个实例都有一份函数，且不在原型上，子类无法通过 super.tick() 调用。

常见追问

  • 对象字面量里的箭头函数方法 { fn: () => this } 的 this 是什么？是对象字面量外层的 this，不是这个对象。
  • 为什么箭头函数不适合作为原型方法？它拿不到调用者，也不能被 new 调用。
