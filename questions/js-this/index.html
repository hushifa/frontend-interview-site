普通函数和箭头函数的 this 有什么区别？

普通函数的 this 看它是怎么被调用的，谁调用它，this 一般就是谁。箭头函数没有自己的 this，用的是定义它的地方外层的 this，call 和 bind 也改不了。

参考答案

简答

普通函数的 this 不是写代码时定的，而是调用的时候才定。写成 obj.fn()，this 就是 obj；直接写 fn()，严格模式下 this 是 undefined；用 new 调用，this 是新创建的实例。

想手动指定也可以。call、apply 是这一次调用临时指定 this，bind 是返回一个把 this 固定住的新函数。几种情况同时出现时，优先级是 new 最高，然后是 bind，然后是 call、apply，再是 obj.fn() 这种方法调用，最后是直接调用。

箭头函数不一样，它自己没有 this。在箭头函数里写 this，就像读一个外层变量，读的是定义它的位置外层的 this。所以 call、bind 都改不了它，它也不能用 new 调用。

最常踩的坑是把方法单独拿出来用，比如当成回调传给 setInterval，或者从对象里解构出来。这时候调用的地方没有 obj. 了，this 就丢了。

先看一个例子

下面这个例子把几种调用方式放在一起。注意看同一个 read 方法，换一种调用方式，结果就不一样。

JavaScript
'use strict';

const obj = {
  value: 42,
  read() {
    return this.value;
  },
  later() {
    return () => this.value;
  },
};

console.log(obj.read()); // 42

const read = obj.read;
try {
  read();
} catch (error) {
  console.log(error.name); // TypeError
}

console.log(read.call({ value: 7 })); // 7

const later = obj.later();
console.log(later.call({ value: 7 })); // 42
obj.value = 99;
console.log(later()); // 99

obj.read() 返回 42，这很好理解，前面有 obj.，this 就是 obj。

可是把它赋给 read 再调用，就报了 TypeError。函数还是同一个函数，变的只是调用方式。read() 前面什么都没有，严格模式下 this 就是 undefined，读 undefined.value 当然报错。如果不是严格模式，this 会变成全局对象，结果是返回 undefined，不会报错。要注意 ES 模块和 class 里面默认就是严格模式。

再用 read.call({ value: 7 })，this 被临时指定成了传进去的对象，所以得到 7。

最后看箭头函数。later 返回的箭头函数，是在 obj.later() 执行的时候定义的，那时外层 later 的 this 是 obj，所以箭头函数里的 this 也是 obj。用 call 传别的对象进去，它直接忽略，还是返回 42。之后把 obj.value 改成 99，再调用就读到 99，因为它拿到的是 obj 这个对象，读的是对象上当前的值。

普通函数的 this 怎么判断

判断普通函数的 this，只看调用的那一行怎么写的，跟函数定义在哪里没有关系。按优先级从高到低排一下：

调用方式this
new Fn()新创建的实例
fn.bind(o)()o（再次 bind 无效）
fn.call(o) / fn.apply(o)o
obj.fn()obj
fn()严格模式 undefined，否则全局对象
箭头函数外层作用域的 this

表里有两处值得用代码确认一下：bind 过的函数再 bind 一次没用，而 new 能盖过 bind。

JavaScript
function Person(name) {
  this.name = name;
}

const bound = Person.bind({ tag: '绑定的对象' });
const p = new bound('Tom');
console.log(p.name); // Tom
console.log(p instanceof Person); // true

function readTag() {
  return this.tag;
}

const once = readTag.bind({ tag: '第一次' });
const again = once.bind({ tag: '第二次' });
console.log(again()); // 第一次
console.log(once.call({ tag: 'call' })); // 第一次

new bound('Tom') 还是创建了一个新的 Person 实例，bind 时传的对象被忽略了，这说明 new 的优先级更高。once 已经绑定了第一个对象，之后再 bind、再 call，this 都改不动，读到的还是“第一次”。

DOM 事件监听也遵守这套规则。监听函数用普通函数写，浏览器调用它时会把 this 设成 currentTarget，也就是绑定监听的那个元素；用箭头函数写，this 就是外层的 this，跟元素无关。

箭头函数的 this 为什么改不了

箭头函数没有自己的 this。它里面写的 this，跟普通的外层变量一样，是顺着代码写的位置往外找的，这就是词法作用域。找到哪个函数的 this，就用哪个。

所以箭头函数的 this 在它定义的时候就跟外层绑在一起了，调用时用 call、apply、bind 传什么都没用。它也没有能给 new 用的构造行为，new 一个箭头函数会直接报 TypeError。

对象里的箭头函数方法不指向对象

这是一个常见误解。看下面的例子：

JavaScript
'use strict';

const user = {
  name: '小明',
  arrow: () => this === user,
  normal() {
    return this.name;
  },
};

console.log(user.arrow()); // false
console.log(user.normal()); // 小明

很多人以为 arrow 写在 user 里，this 就是 user。可它返回的是 false，this 根本不是 user。

原因是对象字面量的大括号不是函数，不会产生自己的 this。箭头函数往外找，找到的是对象外面那一层的 this。这个例子放在 Node 的 CommonJS 文件里运行，外层 this 是 module.exports；放在 ES 模块顶层，外层 this 是 undefined。不管哪种，都不是 user。

改法很简单：对象的方法用普通的方法写法 normal() {}，需要 this 指向对象时不要用箭头函数。

回调里 this 丢了怎么办

把方法当回调传出去，是丢 this 最常见的场景。

JavaScript
class Timer {
  count = 0;
  start() {
    setInterval(this.tick, 1000); // tick 内 this 为 undefined
  }
  tick() {
    this.count += 1;
  }
}

setInterval(this.tick, 1000) 传进去的只是函数本身，没有带上 this。一秒后定时器调用它，相当于直接调用 tick()，class 里又是严格模式，所以 this 是 undefined，this.count 就报错了。

有三种常见改法：

  • 传一个箭头函数进去：setInterval(() => this.tick(), 1000)。箭头函数的 this 是 start 的 this，也就是实例，里面再用 this.tick() 正常调用。
  • 在构造函数里绑定：this.tick = this.tick.bind(this)，之后传 this.tick 就不会丢了。
  • 把方法写成类字段箭头函数：tick = () => { this.count += 1; }。代价是每个实例都会有一份自己的函数，而且它不在原型上，子类没法用 super.tick() 调用它。

常见追问

对象字面量里写 { fn: () => this }，这个 this 是什么？

是这个对象字面量外层的 this，不是这个对象本身。因为对象的大括号不会产生新的 this，箭头函数会继续往外找。

为什么箭头函数不适合做原型方法？

原型方法要靠 this 拿到是哪个实例在调用它，可箭头函数的 this 在定义时就定死了，拿不到调用者。而且箭头函数不能用 new 调用，也不能当构造函数用。
