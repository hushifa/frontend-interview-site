属性测试和示例测试应该怎样搭配？

示例测试用具体输入和输出说明接口；属性测试描述对一类输入都成立的规律，由 fast-check 等工具生成大量数据去推翻它，失败时自动缩减成简单反例。前者适合可读的契约，后者适合发现没想到的边界。

参考答案

简答

  • 示例测试：chunk([1, 2, 3], 2) 应得到 [[1, 2], [3]]。直观，但只检查了想到的情况。
  • 属性测试：对任意数组和任意正整数 size，结果展平后等于原数组、每组长度不超过 size。工具会尝试数百组输入。
  • 一个属性往往不够：直接返回 [items] 也满足“展平后相等”，需要多个属性共同约束。
  • 失败时工具会把输入缩减成更小的反例，并给出 seed，用同一 seed 可以复现。
  • 生成器决定了测试覆盖的输入范围，生成器之外的输入（例如非法参数）仍需要单独的示例测试。

示例

JavaScript
function chunk(items, size) {
  if (!Number.isInteger(size) || size <= 0) {
    throw new RangeError('分组大小必须是正整数');
  }
  const result = [];
  for (let index = 0; index < items.length; index += size) {
    result.push(items.slice(index, index + size));
  }
  return result;
}
JavaScript
import fc from 'fast-check';
import assert from 'node:assert/strict';

fc.assert(
  fc.property(
    fc.array(fc.integer(), { maxLength: 100 }),
    fc.integer({ min: 1, max: 20 }),
    (items, size) => {
      const groups = chunk(items, size);
      assert.deepEqual(groups.flat(), items);
      assert.equal(groups.length, Math.ceil(items.length / size));
      for (const group of groups.slice(0, -1)) {
        assert.equal(group.length, size);
      }
      for (const group of groups) {
        assert.ok(group.length > 0 && group.length <= size);
      }
    },
  ),
);

四条断言分别约束内容和顺序、组数、前面每组都满、每组非空且不超过上限。合在一起，错误的实现很难全部满足。

常见的属性写法

  • 往返：decode(encode(x)) 等于 x，适合序列化、URL 编码。
  • 不变量：排序后长度不变、元素相同、相邻元素有序。
  • 和简单实现对比：优化后的算法结果等于朴素实现的结果。
  • 幂等：normalize(normalize(x)) 等于 normalize(x)。

生成器

  • 直接生成合法输入，比生成后用 filter 丢弃大部分更高效，缩减效果也更好。
  • 字符串业务要包括空字符串、emoji、组合字符，fc.string({ unit: 'grapheme' }) 可以生成多码点字符。
  • 状态机和交互逻辑可以用 fc.commands 生成操作序列，检查任意操作顺序后状态仍然合法。

局限

随机检查有限次数不是证明。生成器没有覆盖的输入、只在极小概率出现的组合，仍可能藏着问题。发现的反例应该固定成示例测试，防止回归。

常见追问

  • 在 Vitest 里怎么用？可以直接在 test 里调用 fc.assert，也可以使用 @fast-check/vitest 提供的 test.prop 写法。
