怎样实现只在停止调用后执行的防抖函数？

尾沿防抖在最后一次调用之后等待一段时间，期间没有新调用才执行。每次调用都清除旧计时器重新计时，执行时使用最后一次调用的参数和 this，并提供 cancel 取消待执行的调用。防抖只减少尚未开始的工作，已经发出的请求还要用 AbortController 或请求序号处理。

参考答案

简答

  • 每次调用先 clearTimeout 旧计时器再重新设置，只有最后一次调用的计时器能走完，执行时使用这次的参数和 this。
  • 包装函数用普通函数定义，才能拿到调用方传入的 this 并用 fn.apply(this, args) 转发。
  • 计时器回调里先把 timer 置空再调用 fn，fn 内部再次调用包装函数时，新计时器不会被误清。
  • 包装函数在 fn 执行前就已返回，所以返回 undefined；fn 抛出的错误也不会传回调用处。
  • 搜索框适合防抖；旧请求可能比新请求更晚返回，需要用 AbortController 取消，或比较请求序号丢弃过期结果。

时间线

等待 100 毫秒，调用发生在 0、60、120 毫秒：

调用时刻参数结果
0 毫秒A计划在 100 毫秒执行
60 毫秒B取消 A，改为 160 毫秒执行
120 毫秒C取消 B，改为 220 毫秒执行

之后没有新调用，大约 220 毫秒执行 C。持续不断地调用时，这个版本会一直不执行；需要"最长等待一段时间也要执行一次"时，要加 maxWait 选项，或改用节流。

实现

JavaScript
function debounce(fn, wait) {
  if (typeof fn !== 'function') throw new TypeError('需要传入函数');
  if (!Number.isInteger(wait) || wait < 0 || wait > 2_147_483_647) {
    throw new RangeError('等待时间必须是计时器范围内的非负整数毫秒');
  }

  let timer;

  function wrapped(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = undefined;
      fn.apply(this, args);
    }, wait);
  }

  wrapped.cancel = () => {
    clearTimeout(timer);
    timer = undefined;
  };

  return wrapped;
}

参数校验在创建计时器之前完成：等待时间超过 2147483647 毫秒时，计时器会被当作 1 毫秒处理，所以直接拒绝。

JavaScript
const receiver = {
  name: '最终输入',
  print: debounce(function (text) {
    console.log(`${this.name}：${text}`);
  }, 100),
};

receiver.print('A');
receiver.print('B');

等待结束后只输出 最终输入：B。同一个包装函数被多个对象共享时，它们共用一个计时器，调用会相互合并；每个输入框应该各自创建实例。

搜索框中的完整处理

JavaScript
let controller;

const search = debounce(async (keyword) => {
  controller?.abort();
  controller = new AbortController();
  try {
    const response = await fetch(`/api/search?q=${encodeURIComponent(keyword)}`, {
      signal: controller.signal,
    });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    render(await response.json());
  } catch (error) {
    if (error.name !== 'AbortError') showError(error);
  }
}, 300);

input.addEventListener('input', (event) => search(event.target.value));
  • 传给防抖函数的是当时的字符串，不是事件对象。延迟执行时 event.currentTarget 已经变成 null。
  • 新请求开始前取消上一次请求，旧响应不会覆盖新结果。
  • 异步函数里自己捕获错误，否则会产生未处理的 Promise 拒绝。

在 React、Vue 组件里使用时，防抖实例要在组件生命周期内保持不变（例如放进 useRef 或 setup 中只创建一次），组件卸载时调用 cancel。

常见追问

  • 防抖和节流怎么选？ 只关心最终结果用防抖，例如搜索、窗口大小变化后重新计算布局；需要持续反馈用节流，例如滚动加载、拖拽。两者对比见《怎样实现首沿节流？它与尾沿节流、防抖有什么区别？》。
  • 能让防抖函数返回 Promise 吗？ 可以，但要先定义被合并掉的那些调用怎么办：一起等待最后一次的结果，还是直接拒绝。这已经是另一种接口设计。
  • 首沿防抖是什么？ 第一次调用立即执行，之后在安静期结束前的调用都被忽略，适合防止按钮重复提交。
