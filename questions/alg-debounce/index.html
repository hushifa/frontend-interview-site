怎样实现只在停止调用后执行的防抖函数？

防抖就是"等你停下来再执行"：最后一次调用之后等一段时间，这段时间里没有新调用才真正执行。每次调用都清掉旧定时器重新计时，执行时用最后一次的参数和 this，还要提供 cancel。防抖只能少发还没开始的请求，已经发出去的请求要用 AbortController 或请求序号处理。

参考答案

简答

防抖就是“等用户停下来再执行”。比如搜索框，用户一直在打字就先不搜，停下来 300 毫秒没再输入，才发请求。

实现的关键是每次调用都先 clearTimeout 掉旧的定时器，再重新设一个。这样只有最后一次调用的定时器能走完，执行时用的也是这次的参数和 this。包装函数要用普通函数写，才能拿到调用方的 this，再用 fn.apply(this, args) 转给原函数。

有两个细节。定时器回调里要先把 timer 清空再调用 fn，这样 fn 内部如果又调用了包装函数，新设的定时器不会被误清掉。另外，包装函数在 fn 执行之前就已经返回了，所以它的返回值是 undefined，fn 抛的错也传不回调用的地方。

防抖只能减少还没开始的工作。已经发出去的请求，旧的可能比新的回来得还晚，要用 AbortController 取消，或者比较请求序号把过期结果丢掉。

先看时间线

假设等待时间是 100 毫秒，调用分别发生在 0、60、120 毫秒：

调用时刻参数结果
0 毫秒A计划在 100 毫秒执行
60 毫秒B取消 A，改为 160 毫秒执行
120 毫秒C取消 B，改为 220 毫秒执行

每次新调用都把执行时间往后推。之后没有新调用了，大约在 220 毫秒执行 C。

这也意味着，如果调用一直不停，这个版本就永远不会执行。如果需要“最多等这么久，也要执行一次”，就要加一个 maxWait 选项，或者改用节流。

实现

JavaScript
function debounce(fn, wait) {
  if (typeof fn !== 'function') throw new TypeError('需要传入函数');
  if (!Number.isInteger(wait) || wait < 0 || wait > 2_147_483_647) {
    throw new RangeError('等待时间必须是计时器范围内的非负整数毫秒');
  }

  let timer;

  function wrapped(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = undefined;
      fn.apply(this, args);
    }, wait);
  }

  wrapped.cancel = () => {
    clearTimeout(timer);
    timer = undefined;
  };

  return wrapped;
}

timer 保存在闭包里，所以每次调用 wrapped 操作的都是同一个定时器，这才能做到“清掉上一个”。

定时器回调用的是箭头函数，它没有自己的 this，用的是外层 wrapped 的 this。所以 fn.apply(this, args) 里的 this，就是调用 wrapped 时的那个对象。

为什么要校验等待时间不超过 2147483647？因为超过这个数，浏览器和 Node 会把定时器当成 1 毫秒处理，等于马上执行，完全违背了本意，所以直接拒绝。

验证 this 和参数

JavaScript
const receiver = {
  name: '最终输入',
  print: debounce(function (text) {
    console.log(`${this.name}：${text}`);
  }, 100),
};

receiver.print('A');
receiver.print('B');

等待结束后只输出一次 最终输入：B。A 那次被取消了，this 也正确地指向了 receiver。

要注意，同一个包装函数被多个对象共用时，它们也共用一个定时器，调用会互相合并。所以每个输入框要各自创建一个防抖实例。

搜索框里的完整写法

防抖只是少发请求，可是发出去的请求返回顺序不确定。用户先搜“a”再搜“ab”，“a”的结果可能后回来，把“ab”的结果盖掉。下面的写法把这个问题也处理了：

JavaScript
let controller;

const search = debounce(async (keyword) => {
  controller?.abort();
  controller = new AbortController();
  try {
    const response = await fetch(`/api/search?q=${encodeURIComponent(keyword)}`, {
      signal: controller.signal,
    });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    render(await response.json());
  } catch (error) {
    if (error.name !== 'AbortError') showError(error);
  }
}, 300);

input.addEventListener('input', (event) => search(event.target.value));

每次发新请求前，先取消上一次的请求，旧的响应就不会覆盖新的结果。

为什么传给 search 的是 event.target.value，而不是整个 event？因为执行是延迟的，等到真正执行时，event.currentTarget 已经变成 null 了。所以要在触发的那一刻就把需要的字符串取出来。

异步函数里的错误要自己捕获。被取消的请求会抛 AbortError，这是正常的，不用提示；其他错误才显示出来。不捕获的话，会产生未处理的 Promise 拒绝。

在 React、Vue 组件里用时，防抖实例要在组件的整个生命周期里保持不变，比如放进 useRef，或者在 setup 里只创建一次。不然每次渲染都创建一个新的，定时器就不是同一个了。组件卸载时记得调用 cancel。

常见追问

防抖和节流怎么选？

只关心最后的结果，就用防抖，比如搜索、窗口大小变了以后重新算布局。需要过程中持续有反馈，就用节流，比如滚动加载、拖拽。两者的对比见《怎样实现首沿节流？它与尾沿节流、防抖有什么区别？》。

能让防抖函数返回 Promise 吗？

可以，但要先想清楚被合并掉的那些调用怎么办：是一起等最后一次的结果，还是直接拒绝。这已经是另一种接口设计了。

首沿防抖是什么？

第一次调用马上执行，之后在安静期结束前的调用都被忽略。适合防止按钮被重复点击提交。
