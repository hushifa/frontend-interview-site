Web Bluetooth API 的安全和兼容性边界是什么？

Web Bluetooth 让网页连接低功耗蓝牙设备并读写 GATT 特征值；它只在 Chromium 系浏览器的安全上下文中可用，必须由用户手势触发设备选择器，网页拿不到设备列表。

参考答案

简答

  • Web Bluetooth 只支持低功耗蓝牙（BLE），通过 GATT 服务和特征值读写数据，不支持经典蓝牙的音频等设备。
  • 目前只有 Chromium 系浏览器支持，Firefox 和 Safari 不支持，iOS 上的浏览器都不可用。
  • 必须在 HTTPS 页面中，由点击等用户手势调用 navigator.bluetooth.requestDevice()，浏览器弹出选择器，用户选中后网页才能拿到这一台设备。
  • 可以用 Permissions-Policy 的 bluetooth 指令在 iframe 中禁用。

连接流程

JavaScript
async function readBattery() {
  if (!('bluetooth' in navigator)) throw new Error('当前浏览器不支持 Web Bluetooth');

  const device = await navigator.bluetooth.requestDevice({
    filters: [{ services: ['battery_service'] }],
  });
  const server = await device.gatt.connect();
  const service = await server.getPrimaryService('battery_service');
  const characteristic = await service.getCharacteristic('battery_level');
  const value = await characteristic.readValue();
  return value.getUint8(0);
}
  • filters 决定选择器里显示哪些设备；只有在 filters 或 optionalServices 中声明的服务，之后才能访问。
  • 订阅设备推送：characteristic.startNotifications()，再监听 characteristicvaluechanged。
  • 监听 device 的 gattserverdisconnected 事件处理断线重连。

安全边界

  • 网页无法扫描附近设备，只能拿到用户在选择器里选中的那一台。
  • 浏览器维护一份 GATT 黑名单，禁止访问可能危害安全的服务（例如 HID 的部分服务）。
  • 写特征值能控制物理设备，应用层仍要校验写入内容。

选型

只服务 Chromium 桌面和 Android 用户（例如内部工具、设备配置页）时可以使用；面向所有用户的产品，需要提供原生 App 或其他降级方案。
