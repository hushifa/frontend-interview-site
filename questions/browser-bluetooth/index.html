Web Bluetooth API 的安全和兼容性边界是什么？

Web Bluetooth 让网页连上低功耗蓝牙设备并读写数据。只有 Chromium 系浏览器在 HTTPS 下支持，而且必须由用户点击后亲自在弹窗里选设备。

参考答案

简答

Web Bluetooth 能让网页直接连上手环、体重秤这类低功耗蓝牙设备，读电量、改配置。它只支持低功耗蓝牙，也就是 BLE，数据通过 GATT 服务和特征值来读写，蓝牙耳机这类经典蓝牙设备不行。

安全上，网页不能自己扫描附近有哪些设备。必须在 HTTPS 页面里，由用户点击触发 navigator.bluetooth.requestDevice()，浏览器弹出选择器，用户选中哪一台，网页才能拿到哪一台。

兼容性是最大的限制。目前只有 Chromium 系浏览器支持，Firefox 和 Safari 都不支持，iOS 上的浏览器全都用不了。

所以它适合内部工具、设备配置页这种只面向 Chrome 和 Android 用户的场景。面向所有用户的产品，还得准备原生 App 之类的降级方案。

连上一台设备要几步

先说两个名词。GATT 是低功耗蓝牙设备组织数据的方式：设备上有若干“服务”，比如电池服务；每个服务下面有若干“特征值”，比如电量。读写数据就是读写某个特征值。

下面是读取设备电量的完整流程：

JavaScript
async function readBattery() {
  if (!('bluetooth' in navigator)) throw new Error('当前浏览器不支持 Web Bluetooth');

  const device = await navigator.bluetooth.requestDevice({
    filters: [{ services: ['battery_service'] }],
  });
  const server = await device.gatt.connect();
  const service = await server.getPrimaryService('battery_service');
  const characteristic = await service.getCharacteristic('battery_level');
  const value = await characteristic.readValue();
  return value.getUint8(0);
}

顺序是：让用户选设备，连上设备的 GATT 服务器，拿到电池服务，拿到电量特征值，读出来。

filters 决定选择器里列出哪些设备。还有一点容易漏：之后能访问哪些服务，取决于你在 filters 或 optionalServices 里声明过哪些。没声明的服务，连上了也访问不了。

如果设备会主动推数据，比如心率，就调用 characteristic.startNotifications()，再监听 characteristicvaluechanged 事件。设备断开时，device 上会触发 gattserverdisconnected，在这里处理重连。

浏览器挡住了哪些风险

最重要的一条是网页拿不到设备列表。它只能拿到用户在选择器里亲手选的那一台，所以没法偷偷扫描用户身边有什么设备。

浏览器还维护了一份 GATT 黑名单，禁止访问可能危害安全的服务，比如 HID 的部分服务。

可是浏览器只管“能不能连”，不管“写进去的东西对不对”。写特征值能直接控制物理设备，所以应用自己仍然要校验写入的内容。

如果页面嵌了 iframe，不想让它用蓝牙，可以用 Permissions-Policy 的 bluetooth 指令禁用。

常见追问

网页能不能自动连上附近的设备？

不能。必须由用户点击之类的手势触发 requestDevice()，浏览器弹出选择器，用户自己选中设备，网页才拿得到这一台。网页没法扫描或者列出附近的设备。

蓝牙耳机能用 Web Bluetooth 控制吗？

一般不行。Web Bluetooth 只支持低功耗蓝牙，通过 GATT 读写数据，不支持经典蓝牙的音频这类设备。
