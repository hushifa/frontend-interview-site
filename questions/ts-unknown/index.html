any、unknown 和 never 分别适合什么场景？

any 关闭类型检查并会沿赋值和属性访问扩散；unknown 能接收任意值，但使用前必须收窄，适合外部输入；never 表示不可能出现的值，用于穷尽检查和总是抛错的函数。void 表示调用方不使用返回值，与 never 不同。

参考答案

简答

  • any：任何操作都允许，读取它的属性结果还是 any，错误会传播到别处。只在迁移旧代码等场景局部使用。
  • unknown：任何值都能赋给它，但不能直接读属性或调用，必须先用 typeof、in、类型守卫等收窄。外部输入、catch 中的错误应按 unknown 处理。
  • never：没有任何值属于它。函数总是抛错或死循环时返回 never；联合的所有分支都处理完后剩下的类型是 never。
  • void：函数正常结束但不返回有意义的值。
  • any 可以赋给任何类型，unknown 只能赋给 unknown 和 any，never 可以赋给任何类型。

any 会扩散

TypeScript
function unsafeName(value: any) {
  return value.profile.name.toUpperCase(); // 不报错，返回 any
}
const name: number = unsafeName({}); // 也不报错

开启 noImplicitAny（strict 的一部分）可以禁止参数被隐式推断为 any。typescript-eslint 的 no-unsafe-* 规则可以追踪 any 的传播。

unknown 要求先证明

TypeScript
function readName(value: unknown): string {
  if (
    typeof value !== 'object' || value === null ||
    !('name' in value) || typeof value.name !== 'string'
  ) {
    throw new TypeError('输入必须包含字符串 name');
  }
  return value.name.trim();
}

useUnknownInCatchVariables（strict 的一部分）让 catch (e) 中的 e 为 unknown，访问 e.message 前要判断 e instanceof Error。JSON.parse 的返回类型是 any，建议立刻赋给 unknown 变量再校验。

value as User 跳过了证明过程，不是 unknown 的使用方式，见《为什么 TypeScript 不能替代接口数据校验？》。

never

TypeScript
function fail(message: string): never {
  throw new Error(message);
}

type Shape = { kind: 'circle' } | { kind: 'square' };
function area(shape: Shape) {
  switch (shape.kind) {
    case 'circle': return 1;
    case 'square': return 2;
    default: {
      const unreachable: never = shape; // 新增分支未处理时这里报错
      return unreachable;
    }
  }
}

string & number 也是 never。条件类型中，never 作为裸类型参数时会得到 never，见《条件类型、infer 和分布式条件类型如何理解？》。

void 与 never

voidnever
函数能否正常返回能不能
典型例子事件回调、console.log抛错函数、process.exit
async 版本Promise<void>Promise<never>

返回类型为 () => void 的回调类型，允许传入有返回值的函数，返回值被忽略，所以 arr.forEach(x => list.push(x)) 不会报错。

常见追问

  • {} 和 object 是什么？{} 接受除 null、undefined 外的所有值；object 只接受非原始值。
  • 为什么不能用 any 消除报错？报错往往说明代码确实有未处理的情况，any 让它在运行时才暴露。
