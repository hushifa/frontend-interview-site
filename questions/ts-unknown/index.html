any、unknown 和 never 分别适合什么场景？

分清绕过检查、未知输入和不可能出现的值。

参考答案
  • any 会绕过大量类型检查，适合迁移时的临时边界，但会削弱安全性。
  • unknown 可以接收任意值，使用前必须做类型收窄，适合外部 JSON 等未知输入。
  • never 表示不可能出现的值，常用于永不正常返回的函数和穷尽性检查。
TypeScript
function assertNever(value: never): never {
  throw new Error(`未预期的值： ${value}`);
}

类型声明不会验证运行时数据。即使把接口响应断言为某个类型，仍需要在不可信边界进行实际校验。

类型与运行时边界

TypeScript 的类型检查发生在编译期，运行时仍然执行生成的 JavaScript；类型声明不会自动校验接口返回值、用户输入或第三方数据。回答类型题时应明确哪些保证来自编译器，哪些需要运行时校验或测试补上。

公共类型还要考虑调用方的错误提示、类型推导速度、模块发布方式和版本兼容。复杂类型可以用类型测试验证，但不要为了表达一个简单约束引入难以维护的递归类型。
