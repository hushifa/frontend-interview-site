requestIdleCallback 适合做什么？为什么不能用它保证任务一定执行？

requestIdleCallback 让浏览器在闲下来时帮你跑一些不急的活，比如预取和上报。页面一直忙或在后台时它可能迟迟不执行，Safari 也不支持，所以只能放可推迟、可丢弃的任务。

参考答案

简答

有些工作不急，比如预取下一页、上报统计、提前算好一些数据。requestIdleCallback 就是让浏览器在一帧的工作做完、还有空余时间时，再调用你的回调。回调里用 deadline.timeRemaining() 能知道这次还剩多少毫秒，最多 50 毫秒。

可是“空闲”不是一定会有的。主线程一直很忙时，回调可能一直不执行。传了 timeout 的话，超时后会强制执行，这时 deadline.didTimeout 是 true。

兼容性上，MDN 标为 Limited availability，Safari 不支持，需要降级。

还有一点，回调里不要改 DOM，否则布局变化会在空闲期之后带来额外工作。要改 DOM，放进 requestAnimationFrame。

先看一个分块处理队列的例子

下面把一组任务交给空闲时间去跑，每次空闲能跑多少跑多少：

JavaScript
function runWhenIdle(tasks, { timeout = 2000 } = {}) {
  let handle;
  let cancelled = false;

  const schedule = (callback) =>
    'requestIdleCallback' in window
      ? requestIdleCallback(callback, { timeout })
      : setTimeout(() => {
          const end = performance.now() + 8;
          callback({ didTimeout: false, timeRemaining: () => Math.max(0, end - performance.now()) });
        }, 1);

  const step = (deadline) => {
    if (cancelled) return;
    do {
      tasks.shift()?.();
    } while (tasks.length > 0 && deadline.timeRemaining() > 1 && !deadline.didTimeout);

    if (tasks.length > 0) handle = schedule(step);
  };

  handle = schedule(step);
  return () => {
    cancelled = true;
    if ('cancelIdleCallback' in window) cancelIdleCallback(handle);
    else clearTimeout(handle);
  };
}

step 每次被调用时，只要还有剩余时间就一直取任务来跑。时间用完了还没跑完，就再调度下一轮，直到队列清空。

为什么用 do...while，不用普通的 while？如果是超时强制触发的，didTimeout 是 true，普通 while 一个任务都不会跑，队列就永远不动了。do...while 保证每次至少处理一个，队列一定会往前走。

不支持的浏览器走 setTimeout 分支，模拟出一个 8 毫秒的预算，每次至少推进一块就让出主线程。

返回的取消函数会把 cancelled 设成 true，并取消已经排上的那一轮，之后所有轮次都停下。

为什么不能指望它一定执行

页面在后台、用户一直在滚动、或者动画把每一帧都占满了，空闲期可能很少，甚至完全没有。

更要紧的是，用户关闭页面时，还没执行的回调直接就丢了。所以必须完成的上报不能交给它，而应该在 visibilitychange 变成 hidden 时，用 sendBeacon 或者 fetch(..., { keepalive: true }) 发出去。

常见追问

它和 scheduler.postTask(fn, { priority: 'background' }) 有什么区别？

postTask 能设置优先级，还能用 AbortSignal 取消任务，但它同样不是所有浏览器都支持。详见《scheduler.postTask 怎样表达前端任务优先级？》。

React 为什么不用 requestIdleCallback 做调度？

因为它的触发频率不稳定，什么时候有空闲说不准。React 用 MessageChannel 实现了自己的调度器。
