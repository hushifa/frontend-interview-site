requestIdleCallback 适合做什么？为什么不能用它保证任务一定执行？

requestIdleCallback 在浏览器空闲时执行低优先级工作，回调通过 timeRemaining() 得到剩余时间；页面一直繁忙或在后台时回调可能长时间不执行，Safari 也不支持，所以只适合可推迟、可丢弃的任务。

参考答案

简答

  • 浏览器在一帧的工作完成、还有空余时间时调用回调，deadline.timeRemaining() 返回本次可用的毫秒数，最多 50ms。
  • 适合预取、上报统计、预计算等不影响当前交互的工作。
  • 主线程一直繁忙时回调可能一直不执行；传入 timeout 后，超时会强制执行，此时 deadline.didTimeout 为 true。
  • MDN 标为 Limited availability，Safari 不支持，需要降级。
  • 回调里不要修改 DOM，布局变化会在空闲期之后造成额外的工作；DOM 修改放进 requestAnimationFrame。

分块处理队列

JavaScript
function runWhenIdle(tasks, { timeout = 2000 } = {}) {
  let handle;
  let cancelled = false;

  const schedule = (callback) =>
    'requestIdleCallback' in window
      ? requestIdleCallback(callback, { timeout })
      : setTimeout(() => {
          const end = performance.now() + 8;
          callback({ didTimeout: false, timeRemaining: () => Math.max(0, end - performance.now()) });
        }, 1);

  const step = (deadline) => {
    if (cancelled) return;
    do {
      tasks.shift()?.();
    } while (tasks.length > 0 && deadline.timeRemaining() > 1 && !deadline.didTimeout);

    if (tasks.length > 0) handle = schedule(step);
  };

  handle = schedule(step);
  return () => {
    cancelled = true;
    if ('cancelIdleCallback' in window) cancelIdleCallback(handle);
    else clearTimeout(handle);
  };
}
  • 用 do...while 保证每次回调至少处理一个任务，即使是超时触发，队列也会向前推进。
  • 剩余任务通过 step 递归调度，直到队列清空。
  • 返回的取消函数会停止之后所有轮次。
  • 降级分支用 setTimeout 并给一个 8ms 的预算，每次至少推进一块后让出主线程。

为什么不能依赖它

  • 页面在后台、用户持续滚动或动画占满每一帧时，空闲期可能很少甚至没有。
  • 用户关闭页面时，没执行的回调直接丢失。必须完成的上报应在 visibilitychange 变为 hidden 时用 sendBeacon 或 fetch(..., { keepalive: true }) 发送。

常见追问

  • 和 scheduler.postTask(fn, { priority: 'background' }) 的区别：后者能设置优先级、用 AbortSignal 取消，但同样不是所有浏览器都支持，见《scheduler.postTask 怎样表达前端任务优先级？》。
  • React 为什么不用它做调度：触发频率不稳定，React 用 MessageChannel 实现了自己的调度器。
