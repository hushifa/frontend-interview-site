前端任务怎样按优先级排队？二叉堆为什么不需要每次完整排序？

以资源加载队列为例，用最小堆实现优先队列：插入时往上浮，取出时把最后一个元素挪到堆顶再往下沉，都是 O(log n)，比每次插入都整体排序省得多。同优先级要按提交顺序取，需要额外加一个序号。优先队列只管谁先谁后，不管并发数量和取消。

参考答案

简答

比如图片加载，视口里的要先加载，下一页的可以晚点。这就需要一个优先队列：每次取出的都是优先级最高的任务。常用的实现是二叉堆。

二叉堆是一棵用数组存的完全二叉树。下标 i 的父节点是 (i - 1) >> 1，子节点是 2i + 1 和 2i + 2。最小堆的规则是每个父节点都不大于它的子节点，所以堆顶就是最小的。

插入时把新元素放到数组末尾，跟父节点比，比父节点小就交换，一路往上浮。取出时拿走堆顶，把末尾元素挪到堆顶，跟较小的子节点比，一路往下沉。两种操作都是 O(log n)，看一眼堆顶是 O(1)。为什么不用每次排序？因为堆只保证堆顶最小，不要求整体有序。

有两点要注意。堆不是稳定的，同优先级的任务想按提交顺序取，要给每个任务加一个递增序号，作为第二比较条件。另外，优先队列只决定下一个执行谁，同时跑几个、怎么取消，要由调度器另外处理。

实现

JavaScript
class PriorityQueue {
  #heap = [];
  #sequence = 0;

  get size() {
    return this.#heap.length;
  }

  // 数字越小优先级越高；优先级相同时先提交的排在前面。
  #before(a, b) {
    return a.priority < b.priority || (a.priority === b.priority && a.sequence < b.sequence);
  }

  #swap(i, j) {
    [this.#heap[i], this.#heap[j]] = [this.#heap[j], this.#heap[i]];
  }

  push(value, priority) {
    if (!Number.isFinite(priority)) throw new TypeError('优先级必须为有限数值');
    const heap = this.#heap;
    heap.push({ value, priority, sequence: this.#sequence++ });
    let index = heap.length - 1;
    while (index > 0) {
      const parent = (index - 1) >> 1;
      if (!this.#before(heap[index], heap[parent])) break;
      this.#swap(index, parent);
      index = parent;
    }
  }

  peek() {
    return this.#heap[0]?.value;
  }

  pop() {
    const heap = this.#heap;
    if (heap.length === 0) return undefined;
    const top = heap[0];
    const last = heap.pop();
    if (heap.length > 0) {
      heap[0] = last;
      let index = 0;
      while (true) {
        const left = index * 2 + 1;
        const right = left + 1;
        let best = index;
        if (left < heap.length && this.#before(heap[left], heap[best])) best = left;
        if (right < heap.length && this.#before(heap[right], heap[best])) best = right;
        if (best === index) break;
        this.#swap(index, best);
        index = best;
      }
    }
    return top.value;
  }
}

const queue = new PriorityQueue();
queue.push('下一页图片', 5);
queue.push('视口图片 A', 1);
queue.push('视口图片 B', 1);
console.log(queue.pop()); // 视口图片 A
console.log(queue.pop()); // 视口图片 B
console.log(queue.pop()); // 下一页图片
console.log(queue.pop()); // undefined

所有比较都通过 #before 来做：先比优先级，优先级一样再比 sequence。“视口图片 A”和“B”优先级都是 1，A 先提交，序号小，所以 A 先出来。如果没有序号，它俩谁先出来是不确定的。

pop 为什么要把最后一个元素挪到堆顶，而不是直接删掉堆顶？因为直接删掉第一个，整个数组要往前挪，树的结构也全乱了。拿末尾元素来补，数组只少了最后一位，树形状不变，再把它往下沉到合适的位置就好。下沉时要和两个子节点里较小的那个换，这样换上来的新父节点才比另一个子节点也小。

实测用 500 组随机的插入和取出，和“按优先级、再按序号排序后取第一个”的朴素做法对比，结果一致。另外 >> 1 只在堆长度小于 2³¹ 时正确，对前端的任务队列来说不构成限制。

和排序数组比一比

操作每次插入后排序有序数组二分插入二叉堆
插入O(n log n)查找 O(log n)，移动元素 O(n)O(log n)
取最小O(1)（从末尾取）O(1)O(log n)

取最小时堆虽然慢一点，但任务是不断加进来、又不断被取走的，两种操作加起来，堆的总成本最低。

放进调度器里用

JavaScript
async function runQueue(queue, limit) {
  let active = 0;
  return new Promise((resolve) => {
    const next = () => {
      if (queue.size === 0 && active === 0) return resolve();
      while (active < limit && queue.size > 0) {
        const task = queue.pop();
        active++;
        // 同步抛错也转成拒绝；失败只记录，不中断队列，也不产生未处理拒绝。
        Promise.resolve()
          .then(task)
          .catch((error) => console.error('任务失败', error))
          .finally(() => {
            active--;
            next();
          });
      }
    };
    next();
  });
}

优先队列决定顺序，limit 控制同时跑几个。每个任务结束时调一次 next，空出来的位置就交给下一个优先级最高的任务。

为什么写 Promise.resolve().then(task)，而不是直接 task()？因为任务函数可能同步就抛错了。放进 then 里，同步的错误也会变成拒绝，被后面的 catch 接住。单个任务失败只记录错误，队列继续跑，全部结束后 runQueue 兑现。如果要汇总失败，可以在 catch 里把错误收集起来，最后一起返回。

用户滚走了，某张图片不再需要了怎么办？堆本身不支持删除中间的任意元素，所以要在任务里检查取消标记，或者用 AbortController 中止请求。

常见追问

怎么支持修改优先级？

一种办法是维护一个“值到堆下标”的映射，改完以后按新优先级往上浮或往下沉。更简单的办法是直接插入一个新条目，旧条目出队时发现已经失效了，就跳过。

浏览器有原生的优先级调度吗？

scheduler.postTask 提供 user-blocking、user-visible、background 三个优先级；fetch 的 priority 选项可以提示网络请求的优先级。两者都只在部分浏览器里支持，用之前要做特性检测。
