原型污染为什么常出现在动态属性赋值和深合并中？

当属性路径由外部输入控制时，obj[key1][key2] = value 或递归深合并可能经由 __proto__ 或 constructor.prototype 写到 Object.prototype 上，让所有普通对象"继承"攻击者的值。防御是限制可写的键、用无原型对象或 Map，以及只按白名单提取字段。

参考答案

简答

  • obj['__proto__'] 对普通对象指向 Object.prototype，继续赋值就修改了所有对象共享的原型。
  • 入口通常是按路径设置值的工具函数、递归深合并、查询字符串解析成嵌套对象。
  • JSON.parse 只会创建一个名为 __proto__ 的自身属性，不会污染；危险发生在之后把它交给不安全的合并逻辑。
  • 后果：if (user.isAdmin) 这类读取继承属性的判断被绕过，或者配置默认值被篡改，在 Node 中可能进一步导致代码执行。
  • 防御：拒绝 __proto__、constructor、prototype 键；用 Object.create(null) 或 Map 存放动态键；按 schema 显式提取字段。

演示

JavaScript
const record = {};
record['__proto__']['demoPermission'] = 'admin';
console.log(Object.hasOwn(record, 'demoPermission')); // false
console.log({}.demoPermission); // admin
delete Object.prototype.demoPermission;

一个不安全的深合并：

JavaScript
function merge(target, source) {
  for (const key of Object.keys(source)) {
    if (typeof source[key] === 'object' && source[key] !== null) {
      target[key] ??= {};
      merge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
  return target;
}

const input = JSON.parse('{"__proto__":{"preview":true}}');
console.log({}.preview); // undefined，JSON.parse 本身没有污染
merge({}, input);
console.log({}.preview); // true，合并时 target['__proto__'] 指向了 Object.prototype

防御

JavaScript
const BLOCKED = new Set(['__proto__', 'constructor', 'prototype']);

function safeMerge(target, source) {
  for (const key of Object.keys(source)) {
    if (BLOCKED.has(key)) continue;
    const value = source[key];
    if (typeof value === 'object' && value !== null && !Array.isArray(value)) {
      // 目标缺少该键或是原始值时，换成新对象再递归
      if (!Object.hasOwn(target, key) || typeof target[key] !== 'object' || target[key] === null) {
        target[key] = {};
      }
      safeMerge(target[key], value);
    } else {
      target[key] = value;
    }
  }
  return target;
}
  • 动态键的字典用 Object.create(null) 或 Map，没有原型链可走。
  • 接口参数按 schema 校验后只取已知字段，比任何黑名单都可靠。
  • 权限判断用 Object.hasOwn 或显式默认值，不依赖继承属性。
  • Object.freeze(Object.prototype) 可以作为加固手段，但可能破坏会修改内置原型的第三方库，要充分测试。

常见追问

  • 对象展开 { ...input } 安全吗？展开会把 __proto__ 作为普通自身属性复制，不会改原型，但危险键仍在，之后交给不安全的合并仍然有风险。
