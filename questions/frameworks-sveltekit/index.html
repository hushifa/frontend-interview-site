SvelteKit 的路由、load 和服务端边界怎样协作？

SvelteKit 用目录结构定义路由。+page.js 中的 load 在服务端和浏览器都可能运行，+page.server.js 中的 load 和表单 actions 只在服务端运行，可以访问数据库和密钥。load 返回的数据会发送到浏览器，部署能力由 adapter 决定。

参考答案

简答

SvelteKit 的路由就是目录。src/routes/blog/[slug]/+page.svelte 对应 /blog/:slug，+layout.svelte 是共享布局。页面要的数据由同目录下的 load 函数提供。

load 放在哪个文件里，决定它在哪里跑。放在 +page.js 里叫通用 load，第一次访问时在服务端跑，之后客户端导航时在浏览器里跑，所以不能用密钥。放在 +page.server.js 里叫服务端 load，只在服务端跑，可以查数据库。但它的返回值会序列化后发给浏览器，所以只返回页面要用的字段。

表单提交交给 +page.server.js 里的 actions。配合 use:enhance 可以无刷新提交，浏览器没开 JavaScript 时，它也能当普通表单用。

另外 +server.js 用来写 API 端点。代码最终跑在哪里由 adapter 决定，比如 node、static、vercel。用 adapter-static 时，服务端代码在运行时是执行不了的。

服务端 load 返回什么

下面是账户页的服务端 load。

JavaScript
// src/routes/account/+page.server.js
import { error } from '@sveltejs/kit';

export async function load({ locals }) {
  if (!locals.user) error(401, '请先登录');
  return {
    user: { id: locals.user.id, displayName: locals.user.displayName },
  };
}

locals.user 是在 hooks.server.js 里根据会话 cookie 设置的。这里没有直接 return { user: locals.user }，而是挑了两个字段。原因是返回值最终会发到浏览器，如果把整条用户记录返回，密码哈希、令牌这些东西也会跟着出去。

表单 action 怎样处理提交

JavaScript
// src/routes/todos/+page.server.js
import { fail } from '@sveltejs/kit';

export const actions = {
  create: async ({ request, locals }) => {
    if (!locals.user) return fail(401, { message: '请先登录' });
    const data = await request.formData();
    const text = String(data.get('text') ?? '').trim();
    if (!text) return fail(400, { text, message: '内容不能为空' });
    await db.todo.create({ text, userId: locals.user.id });
  },
};

页面这边用一个普通的 <form> 指向这个 action：

svelte
<!-- +page.svelte -->
<script>
  import { enhance } from '$app/forms';
  let { form } = $props();
</script>

<form method="POST" action="?/create" use:enhance>
  <input name="text" value={form?.text ?? ''} />
  {#if form?.message}<p role="alert">{form.message}</p>{/if}
  <button>添加</button>
</form>

校验失败时，fail 返回的数据会通过 form 这个 prop 传回页面，所以能显示错误信息，还能把用户刚才输入的内容填回去。提交成功后，SvelteKit 会重新运行页面的 load，列表自然就是最新的。

load 什么时候会重新运行

  • 路由参数或 url 变了，并且 load 里读了它们。
  • 调用了 invalidate(url) 或 invalidateAll()。
  • action 提交之后。

这里有个安全上的坑。父布局的 load 不一定在每次子页面导航时都重新执行，所以不能只在布局里检查权限。每个服务端 load、action 和端点都要自己检查一遍。

还有哪些要注意

不要在服务端模块的顶层变量里存当前用户的数据。服务端一个进程会同时处理很多请求，顶层变量是大家共享的，一个用户的数据可能被另一个用户读到。

在 load 里请求数据，要用 SvelteKit 传进来的 fetch。它会转发 cookie，SSR 时还会把响应内联进页面，这样客户端 hydration 时就不用再请求一次。

多个互不依赖的请求，用 Promise.all 并行发。await parent() 会让当前 load 等父级 load 完成，所以只在真的需要父级数据时才调用，否则就白白串行了。

常见追问

和 Next.js App Router 有什么区别？

SvelteKit 用 load 函数显式加载数据，没有 Server Components。Next.js 是在 Server Component 里直接 await 数据。

预渲染怎么开启？

在页面或布局里导出 export const prerender = true，构建时就会生成静态 HTML。
