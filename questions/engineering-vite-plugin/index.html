Vite 插件的 resolveId、load 和 transform 分别做什么？

resolveId 负责解析导入路径，load 负责提供源码，transform 负责改写源码。文中用一个虚拟版本模块讲内部 ID、返回值、开发和构建钩子、Source Map，以及插件为什么要按环境验证。

参考答案

简答

代码里写了一个 import，Vite 要做三件事：先弄清楚它指的是哪个模块，再拿到这个模块的源码，最后对源码做加工。这三步分别对应 resolveId、load 和 transform 三个钩子。

resolveId 把导入路径变成一个模块 ID，不归它管就返回 null，交给下一个插件。load 根据 ID 返回源码，常用来做虚拟模块，也就是磁盘上不存在、由插件生成的模块。transform 拿到源码后改写，比如编译语法、注入代码。

这三个钩子对每个模块按解析、加载、转换的顺序执行，开发服务器和生产构建都会调用。

要注意两点。虚拟模块的内部 ID 一般加 \0 前缀，免得别的插件把它当成真实文件；transform 改动比较大时，要返回 Source Map，不然报错位置会错乱。

用一个虚拟模块看前两个钩子

下面的插件提供一个虚拟模块 virtual:build-info，业务代码导入它就能拿到构建时间。

JavaScript
// vite.config.js
import { defineConfig } from 'vite';

function buildInfo() {
  const publicId = 'virtual:build-info';
  const internalId = '\0' + publicId;

  return {
    name: 'build-info',
    resolveId(id) {
      if (id === publicId) return internalId;
      return null;
    },
    load(id) {
      if (id !== internalId) return null;
      return `export const builtAt = ${JSON.stringify(new Date().toISOString())};`;
    },
  };
}

export default defineConfig({ plugins: [buildInfo()] });
JavaScript
// 业务代码
import { builtAt } from 'virtual:build-info';
console.log(builtAt);

磁盘上并没有这个文件，那它是怎样被导入的？

遇到 import 'virtual:build-info' 时，Vite 依次调用各个插件的 resolveId，这个插件认出了它，返回内部 ID。接着 Vite 对这个 ID 调用 load，插件直接返回一段 ES 模块源码。这段源码再经过所有插件的 transform，最后交给浏览器或打包器。

transform 怎样改写代码

下面的插件只在构建时生效，把代码里的 __DEBUG__ 换成 false。

JavaScript
function stripDebug() {
  return {
    name: 'strip-debug',
    apply: 'build',
    transform(code, id) {
      if (!id.endsWith('.js') || !code.includes('__DEBUG__')) return null;
      return { code: code.replaceAll('__DEBUG__', 'false'), map: null };
    },
  };
}

开头先用 id 和内容过滤，只处理需要的文件。因为 transform 会对每个模块调用，不过滤就会拖慢所有模块。

返回 null 表示不处理。返回字符串，或者 { code, map }，表示用新代码替换源码。

为什么这里 map 可以写 null？因为这次替换不增删行，代码的行列结构基本没变。如果改写会增删行，就要借助 magic-string 这类工具生成 Source Map，否则报错位置会对不上。

还要注意哪些地方

插件的执行时机可以调。apply: 'serve' 或 'build' 让插件只在开发或构建时生效；enforce: 'pre' 或 'post' 调整它相对于 Vite 核心插件的顺序。

Vite 还有自己特有的钩子。config、configResolved 用来读取或修改配置，configureServer 给开发服务器加中间件，transformIndexHtml 改写 HTML，handleHotUpdate 自定义热更新。

resolveId、load、transform 本身是 Rollup 的通用钩子，Vite 在开发和构建中都按相同的语义调用它们，所以很多 Rollup 插件可以直接用。

可是开发和构建的过程并不一样。开发时模块是一个个按需转换的，构建时是整体打包，同一个插件在两种模式下看到的模块顺序和路径格式可能不同。所以两种模式都要测试。

常见追问

resolveId 返回的 ID 一定是文件路径吗？

不一定。它可以是任意字符串，只要后面的 load 能认出来就行，虚拟模块就是这样做的。

为什么 \0 前缀很重要？

这是一个约定。其他插件和 Vite 内部看到以 \0 开头的 ID，就会跳过，不会尝试从磁盘读取它，也不会再去转换这个路径。
