怎样手写 call、apply 和 bind？用 new 调用 bind 返回的函数会怎样？

call 和 apply 的手写思路是把函数临时挂到目标对象上调用一次再删掉，两者只是传参方式不同；bind 返回一个固定了 this 和前几个参数的新函数。用 new 调用 bind 出来的函数时，绑定的 this 不起作用，按原函数创建实例，预设的参数照样生效。

参考答案

简答

call 和 apply 都是马上调用函数，并指定这一次的 this，区别只是参数怎么传：call(thisArg, 1, 2) 一个个传，apply(thisArg, [1, 2]) 放在数组里传。手写的思路是利用“obj.fn() 里的 this 就是 obj”这条规则，把函数临时挂到 thisArg 上调用，调用完再删掉。挂的时候用 Symbol 做属性名，免得覆盖对象原有的属性。

bind 不会马上调用，而是返回一个新函数。新函数的 this 被固定住，调用时预设的参数放在前面，新传的参数接在后面。

有个特殊情况：用 new 调用 bind 出来的函数，绑定的 this 会被忽略，等于用预设参数去 new 原函数。得到的实例，instanceof 原函数和绑定函数都是 true。手写时用 new.target 判断是不是被 new 调用的，再用 Reflect.construct 来构造。

要注意，手写的 call 只能模拟非严格模式的行为：thisArg 是 null 或 undefined 时用全局对象，原始值会被包装成对象。严格模式函数本来会原样收到 this，挂属性的写法做不到这一点。

手写 call 和 apply

调用 obj.fn() 时，fn 里的 this 就是 obj。所以想让函数以某个对象为 this 运行，最直接的办法就是把函数挂到这个对象上，用 对象.函数() 的方式调一次。

JavaScript
Function.prototype.myCall = function (thisArg, ...args) {
  if (typeof this !== 'function') throw new TypeError('not a function');
  // 模拟非严格模式：null/undefined 指向全局对象，原始值被包装
  const context = thisArg == null ? globalThis : Object(thisArg);
  const key = Symbol('fn');
  context[key] = this;
  try {
    return context[key](...args);
  } finally {
    delete context[key];
  }
};

Function.prototype.myApply = function (thisArg, args) {
  return this.myCall(thisArg, ...(args ?? []));
};

function show(a, b) {
  return [this.name, a, b];
}
console.log(show.myCall({ name: 'x' }, 1, 2)); // [ 'x', 1, 2 ]
console.log(show.myApply({ name: 'y' }, [3])); // [ 'y', 3, undefined ]

myCall 里的 this 是谁？是调用它的那个函数，也就是 show。因为写的是 show.myCall(...)，前面是 show.。

为什么用 Symbol('fn') 做属性名？如果用一个普通字符串，比如 'fn'，万一对象本来就有 fn 属性，就被覆盖掉了，最后还会被 delete 删掉。每个 Symbol 都是唯一的，不会和已有属性撞上。

finally 的作用是，就算函数抛错，临时属性也一定会被删掉。

这种写法也有局限。对象被冻结了，属性加不上去，就没法调用。还有严格模式的差别，下面单独看。

手写版和原生版在严格模式下不一样

下面用一个严格模式函数，分别用原生 call 和手写的 myCall 传入数字 5：

JavaScript
function strictFn() {
  'use strict';
  return typeof this;
}
console.log(strictFn.call(5));   // number
console.log(strictFn.myCall(5)); // object

原生 call 传给严格模式函数的 this 就是原始值 5，所以是 number。手写版必须先 Object(5) 把它包装成对象，才能往上挂属性，所以得到的是 object。这是挂属性写法的固有限制，面试时说清楚就行。

手写 bind

bind 要处理两种调用方式：普通调用和 new 调用。

JavaScript
Function.prototype.myBind = function (thisArg, ...preset) {
  const target = this;
  if (typeof target !== 'function') throw new TypeError('not a function');

  function bound(...args) {
    // 被 new 调用时忽略绑定的 this，按原函数构造
    if (new.target) {
      return Reflect.construct(target, [...preset, ...args], new.target);
    }
    return target.apply(thisArg, [...preset, ...args]);
  }

  // 让 instanceof bound 与原生行为一致；箭头函数等没有 prototype
  if (target.prototype) bound.prototype = target.prototype;
  return bound;
};

普通调用时，用 apply 把绑定的 thisArg 和拼好的参数传给原函数。

new.target 是什么？函数被 new 调用时，它指向被 new 的那个函数；普通调用时它是 undefined。所以用它就能分辨这次是不是 new 调用。

如果是 new 调用，就用 Reflect.construct 按原函数去构造，效果和 new target(...参数) 一样，绑定的 thisArg 完全不用。

用 new 调用绑定函数会怎样

下面分别用手写版和原生版试一下：

JavaScript
function Point(x, y) {
  this.x = x;
  this.y = y;
}

const Bound = Point.myBind({ ignored: true }, 10);
const p = new Bound(20);
console.log(p); // Point { x: 10, y: 20 }
console.log(p instanceof Point, p instanceof Bound); // true true

const NativeBound = Point.bind({}, 10);
const q = new NativeBound(20);
console.log(q instanceof Point, q instanceof NativeBound); // true true

{ ignored: true } 果然被忽略了，p 是一个正常的 Point 实例，预设的 10 也生效了，成了 x。

那 q instanceof NativeBound 为什么也是 true？原生的绑定函数其实没有 prototype 属性，instanceof 碰到绑定函数时，会转而去检查它的目标函数，也就是 Point 的 prototype。手写版没法做到这种特殊处理，所以把 bound.prototype 直接指向原函数的 prototype，判断结果就一样了。

常见追问

绑定过的函数再 bind 一次，能改变 this 吗？

不能。this 第一次就固定了，再 bind 只能继续往后追加预设参数。

箭头函数能用 call 改变 this 吗？

不能。箭头函数没有自己的 this，用的是外层的，传进去的 thisArg 会被忽略。

原生 bind 返回的函数，name 和 length 是什么？

name 是“bound 原函数名”，比如 bound Point。length 是原函数的形参个数减去预设参数的个数，最小为 0，上面的 NativeBound 就是 1。手写版用的是剩余参数，length 是 0，name 是 bound。需要一致的话，可以用 Object.defineProperty 改写这两个属性。
