代码分割与懒加载适合哪些场景？

代码分割把产物拆成多个文件，懒加载让一部分等到需要时才加载。文中用动态导入 import() 的例子讲模块缓存、取消边界和生命周期，以及预加载、错误恢复和旧版本资源问题。

参考答案

简答

代码分割是把打包产物拆成多个文件，懒加载是让其中一部分等到真正需要时才下载执行。两者通常一起用。

适合拆出去的是首屏用不到的内容，比如其他路由、弹窗、富文本编辑器、图表、管理后台。写法是用 import()，它返回一个 Promise，同一个模块只加载一次，之后再调用拿到的是同一个模块。

拆出去以后，要处理加载中的状态和失败重试，还可以提前预加载，减少用户等待。

有一个坑要注意：发布新版本后，停留在旧页面的用户可能去请求已经删掉的旧文件。所以部署时要保留旧资源，或者加载失败时提示刷新。

动态导入怎么写

下面的例子在用户点按钮时才加载编辑器，并处理了加载中和失败的情况。

JavaScript
button.addEventListener('click', async () => {
  button.disabled = true;
  try {
    const { openEditor } = await import('./editor.js');
    openEditor();
  } catch (error) {
    showToast('编辑器加载失败，请重试');
  } finally {
    button.disabled = false;
  }
});

构建工具看到 import('./editor.js')，会把 editor 和只有它用到的依赖拆成一个单独的 chunk。前提是路径能被静态分析，完全用变量拼出来的路径，构建工具不知道该拆哪个文件。

模块加载成功以后会被缓存，所以再点一次按钮不会重新下载。

可是加载失败的 Promise 不会自动重试。React 的 lazy 这类封装通常也会把失败的结果缓存下来，所以要么自己写重试逻辑，要么让用户刷新页面。

另外，import() 本身没法取消。如果组件在加载完成前就卸载了，要在回调里先判断组件是否还在，再决定用不用这个结果。

什么时候不该拆

首屏必须立刻渲染的组件不该拆。拆出去只会多一次请求，反而推迟 LCP。

很小的模块也不该拆，额外一次请求的开销比省下的字节还大。

几乎每个页面都用到的共享代码，应该留在公共块里。

怎样用预加载减少等待

懒加载的代价是用户要等下载。所以可以在用户意图明显时提前加载，比如鼠标悬停或聚焦到链接上就调用 import()。浏览器空闲时，也可以预加载下一步可能用到的路由。

Vite 会为动态导入的 chunk 自动生成依赖预加载。这样不用等入口下载完，再一个个串行请求它的依赖。

发布后为什么会出现旧 chunk 404

chunk 的文件名带哈希，每次构建后可能都会变。用户一直停在旧页面，点某个功能时，浏览器请求的还是旧文件名。如果部署时把旧文件删了，加载就会失败。

常见的改法有两种。一是部署时把上一两个版本的静态资源保留一段时间。二是捕获 chunk 加载失败，Vite 会派发 vite:preloadError 事件，然后提示用户刷新，或者自动重新加载一次。

常见追问

路由级懒加载和组件级懒加载怎么选？

路由是最自然的边界，先做路由级。页面里体积大、又不一定会用到的组件，再单独拆。

懒加载会影响 SEO 吗？

首屏的核心内容不应该懒加载。预渲染或 SSR 的页面，要确保关键内容就在 HTML 里。
