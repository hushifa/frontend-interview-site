代码分割与懒加载适合哪些场景？

区分拆成多个文件与延后启动加载，用动态导入示例说明模块缓存、取消边界和生命周期，并解释预加载、错误恢复与旧版本资源问题。

参考答案

简答

  • 代码分割把产物拆成多个文件；懒加载决定其中一部分等到需要时才下载执行，两者通常配合使用。
  • 适合首屏用不到的内容：其他路由、弹窗、富文本编辑器、图表、管理后台等。
  • import() 返回 Promise，同一模块只加载一次，之后重复调用拿到同一个模块实例。
  • 要处理加载中状态、失败重试，以及提前预加载以减少用户等待。
  • 发布新版本后旧页面可能请求已删除的旧 chunk，部署时要保留旧资源或在失败时提示刷新。

动态导入的基本形式

JavaScript
button.addEventListener('click', async () => {
  button.disabled = true;
  try {
    const { openEditor } = await import('./editor.js');
    openEditor();
  } catch (error) {
    showToast('编辑器加载失败，请重试');
  } finally {
    button.disabled = false;
  }
});

构建工具看到 import('./editor.js') 会把 editor 及其独占依赖拆成单独的 chunk。路径必须能被静态分析，完全由变量拼出的路径无法拆分。

  • 模块加载成功后会被缓存，再次点击不会重新下载。
  • 加载失败的 Promise 不会自动重试；React 的 lazy 等封装通常也会缓存失败结果，需要自己实现重试逻辑或让用户刷新。
  • import() 本身不能取消。组件在加载完成前卸载时，要在回调里判断组件是否仍然存在，再决定是否使用结果。

什么时候不该拆

  • 首屏必须立即渲染的组件：拆出去只会多一次请求，推迟 LCP。
  • 很小的模块：额外请求的开销大于节省的字节。
  • 几乎每个页面都会用到的共享代码：应留在公共块里。

预加载减少等待

  • 用户意图明显时提前加载，例如鼠标悬停或聚焦到链接上就调用 import()。
  • 浏览器空闲时预加载下一步可能用到的路由。
  • Vite 会为动态导入的 chunk 自动生成依赖预加载，避免下载完入口后再串行请求依赖。

发布后的旧 chunk 404

带哈希的 chunk 名在每次构建后可能改变。用户停留在旧页面时点击某个功能，浏览器会请求旧文件名，如果部署时把旧文件删了，就会加载失败。

常见做法：

  1. 部署时保留上一两个版本的静态资源一段时间。
  2. 捕获 chunk 加载失败（Vite 会派发 vite:preloadError 事件），提示用户刷新或自动重新加载一次。

常见追问

  • 路由级懒加载和组件级懒加载怎么选？路由是最自然的边界，先做路由级；页面内体积大且不一定使用的组件再单独拆。
  • 懒加载会影响 SEO 吗？首屏核心内容不应懒加载；预渲染或 SSR 页面要确保关键内容在 HTML 中。
