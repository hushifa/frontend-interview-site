Declarative Shadow DOM 适合解决什么问题？

以前 Shadow DOM 只能用 JavaScript 创建，服务端渲染的组件在脚本加载前没有样式。声明式写法把 Shadow Root 直接写进 HTML，组件脚本加载后要复用这个根，不能重建。

参考答案

简答

用 Web Component 做服务端渲染时有个问题：Shadow DOM 只能用 JavaScript 的 attachShadow() 创建，所以脚本加载之前，页面上的组件没有样式和内部结构。

Declarative Shadow DOM 就是把 Shadow Root 直接写在 HTML 里。在宿主元素里放一个 <template shadowrootmode="open">，HTML 解析器看到它，就把模板内容直接挂成 Shadow Root，不用等脚本。

这样首屏一出来就有带样式的组件，对 SEO 和无 JavaScript 的场景也友好。现在主流浏览器都支持 shadowrootmode，旧的 shadowroot 属性已废弃。

要注意的是组件脚本加载后，要先读取已有的根再决定要不要 attachShadow()，因为对已有声明式根调用它会把内容清空。另外 innerHTML 不处理这个属性，动态插入要用 setHTMLUnsafe() 或 Document.parseHTMLUnsafe()。

在 HTML 里写出 Shadow Root

下面是一张用户卡片，样式和结构都写在 <template shadowrootmode="open"> 里。

HTML
<user-card>
  <template shadowrootmode="open">
    <style>
      :host { display: block; border: 1px solid #ddd; padding: 12px; }
    </style>
    <strong class="name"><slot name="name"></slot></strong>
    <button type="button">关注</button>
  </template>
  <span slot="name">张三</span>
</user-card>

浏览器解析到这里，就把 template 的内容变成 user-card 的 Shadow Root。所以页面在 JavaScript 加载前就显示带样式的卡片，“张三”也已经通过插槽显示在 .name 里了。

组件脚本加载后怎样接手

组件脚本到了以后，要接手已经存在的 Shadow Root，而不是重新创建一个。

JavaScript
class UserCard extends HTMLElement {
  #internals = this.attachInternals();

  constructor() {
    super();
    const root = this.#internals.shadowRoot ?? this.attachShadow({ mode: 'open' });
    if (!root.querySelector('.name')) {
      root.innerHTML = '<strong class="name"><slot name="name"></slot></strong><button type="button">关注</button>';
    }
    this.button = root.querySelector('button');
  }

  connectedCallback() {
    this.button.addEventListener('click', () => this.follow());
  }
}

customElements.define('user-card', UserCard);

为什么要先判断？因为已有声明式根时，attachShadow() 不会报错，而是把这个根的所有内容清空再返回它，服务端渲染好的结构就丢了。所以先读已有的根。open 模式可以读 this.shadowRoot，closed 模式外部读不到，要用 ElementInternals.shadowRoot，例子里统一用了后者。

客户端用 JavaScript 新建的 user-card 没有声明式根，shadowRoot 是空的，就走 attachShadow() 分支，自己生成内容。

为什么动态插入的 HTML 没有生效

用 innerHTML 插入一段带 <template shadowrootmode> 的 HTML，浏览器不会处理这个属性，它只是一个普通的 template。这是为了安全，避免旧代码意外创建 Shadow Root。要让它生效，改用 setHTMLUnsafe() 或 Document.parseHTMLUnsafe()。

适合哪些场景，有什么代价

它适合需要服务端渲染、在意首屏和 SEO 的 Web Component，也适合给多种框架共用的设计系统组件，要求没有 JavaScript 时也能基本展示。

代价是每个组件实例都要把 <style> 写进模板，HTML 会变大。可以在组件升级后改用 adoptedStyleSheets 共享样式。另外，声明式根只解决了结构和样式，事件监听仍要等脚本执行后才绑定，所以按钮在此之前点击是没反应的。

常见追问

attachShadow() 的其他选项在声明式写法里怎么写？

用 template 上的属性。shadowrootdelegatesfocus 对应 delegatesFocus，shadowrootclonable 对应 clonable。

脚本加载前，组件能交互吗？

能看不能用。样式和结构已经在了，但事件监听要等组件脚本执行后才绑上，在那之前点击按钮没有效果。
