Declarative Shadow DOM 适合解决什么问题？

Declarative Shadow DOM 用 <template shadowrootmode> 在 HTML 里直接声明 Shadow Root，服务端渲染的 Web Component 在脚本加载前就有样式和内容；组件升级时要复用已有的根，不能重新创建。

参考答案

简答

  • 传统 Shadow DOM 只能在 JavaScript 里用 attachShadow() 创建，服务端渲染的 HTML 在脚本执行前没有组件样式和结构。
  • 声明式写法：在宿主元素里放 <template shadowrootmode="open">，HTML 解析器直接把模板内容附加成 Shadow Root。
  • 组件脚本加载后，应先读取 this.shadowRoot（closed 模式用 ElementInternals.shadowRoot）复用已有的根，没有时才调用 attachShadow()。
  • innerHTML 不处理 shadowrootmode，动态插入要用 setHTMLUnsafe() 或 Document.parseHTMLUnsafe()。
  • 主流浏览器都已支持 shadowrootmode，旧的 shadowroot 属性已废弃。

HTML

HTML
<user-card>
  <template shadowrootmode="open">
    <style>
      :host { display: block; border: 1px solid #ddd; padding: 12px; }
    </style>
    <strong class="name"><slot name="name"></slot></strong>
    <button type="button">关注</button>
  </template>
  <span slot="name">张三</span>
</user-card>

页面在 JavaScript 加载前就显示带样式的卡片，插槽内容也已经投影进去。

组件升级

JavaScript
class UserCard extends HTMLElement {
  #internals = this.attachInternals();

  constructor() {
    super();
    const root = this.#internals.shadowRoot ?? this.attachShadow({ mode: 'open' });
    if (!root.querySelector('.name')) {
      root.innerHTML = '<strong class="name"><slot name="name"></slot></strong><button type="button">关注</button>';
    }
    this.button = root.querySelector('button');
  }

  connectedCallback() {
    this.button.addEventListener('click', () => this.follow());
  }
}

customElements.define('user-card', UserCard);
  • 已有声明式根时，attachShadow() 不会报错，而是清空这个根的所有内容再返回它，服务端渲染的结构就丢了。所以要先判断。
  • 页面上客户端新建的 user-card 没有声明式根，走 attachShadow() 分支，自己生成内容。

适用场景

  • 需要服务端渲染、在意首屏和 SEO 的 Web Component。
  • 设计系统组件同时供多种框架使用，并要求无 JavaScript 时也有基本展示。

注意事项

  • 每个组件实例都要把 <style> 写进模板，HTML 体积会增加；可以在升级后改用 adoptedStyleSheets 共享样式。
  • 声明式根里的事件监听仍要等脚本执行后才绑定，按钮在此之前点击无效。
  • shadowrootdelegatesfocus 和 shadowrootclonable 属性分别对应 attachShadow() 的 delegatesFocus 和 clonable 选项。
