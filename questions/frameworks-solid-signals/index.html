Solid 的 Signals 和 React 状态更新有什么不同？

React 通常重新执行组件函数并协调视图，Solid 通过 signal 读取建立细粒度依赖，更新时只触发相关计算和 DOM。两者 JSX 相似，但状态读取、派生和清理规则不同。

参考答案

相同的 JSX 不代表相同的更新模型

React 通常在状态变化后重新执行组件函数，得到新的界面描述，再协调实际 DOM。Solid 的组件函数通常在实例建立时执行，之后由编译器和响应式系统更新真正读取了 signal 的表达式。

因此把 React 中“组件函数每次都会重新计算局部变量”的直觉搬到 Solid，容易得到初始化快照而不是持续响应式值。

signal 的读取方式决定是否建立依赖

JavaScript
import { createRoot, createSignal, createMemo } from 'solid-js';

createRoot((dispose) => {
  const [count, setCount] = createSignal(1);
  const doubled = createMemo(() => count() * 2);
  const initial = count();

  console.log(doubled(), initial); // 2, 1
  setCount((value) => value + 1);
  console.log(doubled(), initial); // 4, 1
  dispose();
});

count() 读取当前值，setCount 更新它；createMemo 在追踪上下文中读取 count()，所以会重新计算；initial 只是执行那一行时保存的数字，不会自己变化。

关键不是“是否放进函数”，而是读取发生时是否处在受追踪的计算中。createMemo、createEffect 和编译后的 JSX 表达式会记录同步读取。setTimeout 或 await 之后的读取，不应默认认为属于原来的依赖收集。

分支还会改变依赖集合：当前分支没有读到的 signal，不会因为它变化就强制重跑。需要排除某个读取时可以使用 untrack，但应明确这样做不会自动更新。

JSX 表达式和组件主体的边界不同

模板中直接写 count()，编译器可以把依赖绑定到局部 DOM；组件主体中先写 const text = count()，再渲染 text，通常得到的是初始化值。Props 也要保持响应式读取，随意解构可能切断后续更新关系。

createMemo 适合昂贵或需要缓存的派生计算，内部应保持纯计算，不要通过写状态制造循环。Signal 存对象时，直接修改内部字段并用同一引用写回，也不能假设存在深层代理；复杂嵌套状态应评估 Solid Store 或明确替换引用。

effect 负责同步外部系统

createEffect 适合订阅、DOM API、计时器和网络等副作用，并用 onCleanup 清理：

JavaScript
createEffect(() => {
  const queryValue = query();
  const controller = new AbortController();

  fetch(`/api/search?q=${encodeURIComponent(queryValue)}`, {
    signal: controller.signal,
  })
    .then((response) => response.json())
    .then((data) => {
      if (!controller.signal.aborted) setResults(data);
    });

  onCleanup(() => controller.abort());
});

组件销毁或依赖变化时取消旧请求，但第三方 Promise 不一定真正停止；旧结果提交前仍要检查任务身份或取消状态。测试中手动创建 createRoot 时，也必须调用 dispose，否则订阅和 effect 可能泄漏。

不要机械复制 React Hook 的依赖数组和闭包补丁。Solid 的依赖追踪、批处理和 owner 生命周期有自己的规则。batch 可以合并下游更新，但不会让计算自动移出主线程，也不能替代请求取消。

细粒度不等于没有性能成本

一个 memo 里遍历几十万条数据、一次更新造成大量 DOM 变化或第三方图表重绘，仍然会慢。列表规模、对象身份、数据结构和外部库成本不会因为没有常规虚拟 DOM 就消失。

迁移到 Solid 时，重点重新理解读取发生的位置、派生和副作用的生命周期，以及哪些数据需要共享。纯业务函数通常容易复用，依赖 React 渲染时机、组件重执行或 Hook 语义的代码则要重新设计和验证。
