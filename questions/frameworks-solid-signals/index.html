Solid 的 Signals 和 React 状态更新有什么不同？

React 在状态变化后重新执行组件函数并协调虚拟 DOM；Solid 的组件函数只执行一次，之后靠 signal 的读取关系直接更新对应的 DOM 节点。所以在 Solid 中要在 JSX、createMemo 或 createEffect 里调用 signal 才能建立依赖，解构 props 会丢失响应性。

参考答案

简答

React 里状态一变，整个组件函数会重新执行一遍，再比较虚拟 DOM 找出要改的地方。Solid 不一样，组件函数只在创建时执行一次，之后再也不执行。谁读了 signal，signal 变的时候就只更新谁，比如 JSX 里的 {count()} 会被编译成只更新这一个文本节点。这叫细粒度响应式。

写法上，const [count, setCount] = createSignal(0)，count() 是读取函数，setCount 用来改值。

因为组件只执行一次，有两个坑。在组件主体里写 const n = count()，拿到的只是初始值，之后不会变；要在 JSX、createMemo、createEffect 这些会追踪的地方读取。同样，解构 props，比如 const { name } = props，读出来的也是当时的值，会丢掉响应性，要写 props.name，或者用 splitProps、mergeProps。

好处是没有依赖数组，也没有过期闭包的问题。但只有同步读取会被追踪，await 之后的读取不算。下面的示例都基于 Solid 1.x。

同一个计数器，两种执行方式

先看 React 版本。每次点击，render 都会打印一次：

JSX
// React：每次点击，Counter 整个函数重新执行
function Counter() {
  const [count, setCount] = useState(0);
  console.log('render'); // 每次点击都打印
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

再看 Solid 版本，写法几乎一样，但 setup 只打印一次：

JSX
// Solid：Counter 只执行一次
import { createSignal } from 'solid-js';

function Counter() {
  const [count, setCount] = createSignal(0);
  console.log('setup'); // 只打印一次
  return <button onClick={() => setCount(count() + 1)}>{count()}</button>;
}

既然 Solid 的函数不再执行，按钮上的数字怎么变的？因为 JSX 里写的是 count()，编译后这个位置会订阅 count。count 变了，只有这个文本节点被更新，组件函数本身没再运行。

这也解释了为什么 Solid 没有过期闭包。React 每次渲染都产生新的 count 变量，旧回调会拿着旧值；Solid 只有一个 signal，每次调用 count() 读到的都是当前值。

派生值怎么写

JSX
const [items, setItems] = createSignal([]);
const total = createMemo(() => items().reduce((s, i) => s + i.price, 0));
const count = () => items().length; // 便宜的派生可以直接写成函数

createMemo 会缓存结果，多处读取只算一次，适合计算比较重的派生。像取数组长度这种便宜的计算，写成普通函数就行。它在 JSX 里被调用时，内部读了 items()，同样会被追踪。

副作用怎样清理

JSX
import { createEffect, createSignal, onCleanup } from 'solid-js';

function Search() {
  const [query, setQuery] = createSignal('');
  const [results, setResults] = createSignal([]);

  createEffect(() => {
    const q = query();
    const controller = new AbortController();
    fetch(`/api/search?q=${encodeURIComponent(q)}`, { signal: controller.signal })
      .then((r) => (r.ok ? r.json() : Promise.reject(new Error(`HTTP ${r.status}`))))
      .then(setResults)
      .catch((err) => {
        if (err.name !== 'AbortError') console.error(err);
      });
    onCleanup(() => controller.abort());
  });

  return <input value={query()} onInput={(e) => setQuery(e.currentTarget.value)} />;
}

effect 第一行同步读了 query()，所以 query 就成了它的依赖，不用写依赖数组。query 一变，先执行 onCleanup 注册的函数，取消旧请求，再重新运行 effect。实际项目里，异步数据通常用 createResource 来处理。

条件和列表为什么要用专门的组件

在 React 里可以直接写 {user ? <A /> : <B />}，因为组件会重新执行。Solid 的组件不重新执行，所以条件渲染和列表要交给 Solid 提供的控制流组件：

JSX
<Show when={user()} fallback={<p>请登录</p>}>
  {(u) => <p>你好，{u().name}</p>}
</Show>

<For each={todos()}>{(todo) => <li>{todo.text}</li>}</For>

<For> 按对象引用复用 DOM 节点，相当于自动带了 key。

常见追问

嵌套对象怎么处理？

用 createStore 创建深层响应式对象，再用 setStore('user', 'name', 'Lin') 这样按路径更新。

和 Vue 的响应式像吗？

原理接近，都是读取时收集依赖、写入时通知。区别在于 Vue 组件还有渲染函数和虚拟 DOM，Solid 直接更新 DOM。
