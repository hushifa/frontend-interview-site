移动端虚拟键盘出现时怎样避免布局被遮挡？

区分布局视口和可视视口，用 VisualViewport、interactive-widget 和 VirtualKeyboard API 适配输入框与底部操作栏，并说明各方案的浏览器支持边界。

参考答案

简答

  • 键盘弹出时，多数移动浏览器默认只缩小可视视口（visual viewport），布局视口不变，所以 position: fixed; bottom: 0 的元素会被键盘挡住。
  • window.visualViewport 提供可视区域的尺寸和偏移，监听它的 resize 和 scroll 事件可以让底部栏贴在键盘上方，主流移动浏览器都支持。
  • viewport meta 的 interactive-widget=resizes-content 让键盘弹出时缩小布局视口，Chrome for Android 和 Firefox for Android 支持，Safari 不支持。
  • VirtualKeyboard API（navigator.virtualKeyboard）只在 Chromium 中可用，适合需要精确控制键盘区域的场景。
  • 输入框聚焦时用 scrollIntoView 确保它在可视区域内，并在真机上测试 iOS 和 Android。

两个视口

  • 布局视口：CSS 布局的基准，fixed 定位相对它计算。
  • 可视视口：用户当前实际看到的区域，键盘弹出、双指缩放时会变小或移动。

键盘弹出后可视视口变矮，但布局视口高度不变，固定在布局视口底部的元素就落在了键盘下面。

用 VisualViewport 跟随键盘

JavaScript
const bar = document.querySelector('.bottom-bar');
const vv = window.visualViewport;

function update() {
  const keyboard = window.innerHeight - vv.height - vv.offsetTop;
  bar.style.transform = `translateY(${-Math.max(0, keyboard)}px)`;
}

if (vv) {
  vv.addEventListener('resize', update);
  vv.addEventListener('scroll', update);
}

innerHeight 是布局视口高度，减去可视视口高度和偏移，就是被键盘占据的高度。用 transform 移动比修改 bottom 更不容易引起布局抖动。

声明式方案：interactive-widget

HTML
<meta name="viewport" content="width=device-width, initial-scale=1, interactive-widget=resizes-content" />
值键盘弹出时
resizes-visual（默认）只缩小可视视口
resizes-content布局视口也缩小，fixed 元素和 dvh 自动避开键盘
overlays-content都不缩小，键盘覆盖在内容上

不支持的浏览器（如 Safari）忽略这个参数，仍需 VisualViewport 方案兜底。

VirtualKeyboard API

JavaScript
if ('virtualKeyboard' in navigator) {
  navigator.virtualKeyboard.overlaysContent = true;
}
CSS
.chat {
  display: grid;
  grid-template-rows: 1fr auto env(keyboard-inset-height, 0px);
  height: 100dvh;
}

开启 overlaysContent 后浏览器不再调整视口，由页面用 env(keyboard-inset-*) 自己留出键盘空间。这个 API 是实验性的，只在 Chromium 系浏览器的安全上下文中可用。

输入框被挡住

JavaScript
input.addEventListener('focus', () => {
  setTimeout(() => input.scrollIntoView({ block: 'center' }), 300);
});

键盘动画结束后可视视口才稳定，延迟后再滚动更可靠。滚动容器内的输入框还要确认容器本身的高度会随键盘变化。

测试要点

  • iOS Safari、Android Chrome 和目标 App 的 WebView 分别测试，WebView 的行为还受原生配置影响。
  • 测试横屏、外接键盘、第三方输入法（高度不同）以及键盘收起后布局是否恢复。

常见追问

  • 为什么 100vh 的页面键盘弹出后还能滚动？vh 不随键盘变化，用 dvh 或配合 interactive-widget 处理。
  • 安全区域和键盘有什么关系？两者独立，底部栏同时要避开手势条和键盘，见《移动端安全区域怎样避免内容被刘海和底部手势条遮挡？》。
