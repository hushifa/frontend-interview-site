移动端虚拟键盘出现时怎样避免布局被遮挡？

键盘弹出时，用户能看到的区域变小了，页面布局却没变。区分布局视口和可视视口，用 VisualViewport、interactive-widget 和 VirtualKeyboard API 适配输入框与底部操作栏，并说明各方案的浏览器支持边界。

参考答案

简答

手机上点输入框，键盘弹起来，底部的操作栏经常被盖住。原因是多数移动浏览器默认只缩小“用户能看到的区域”，也就是可视视口，而页面布局用的布局视口不变。position: fixed; bottom: 0 是按布局视口算的，所以落到了键盘下面。

最通用的办法是 window.visualViewport。它能告诉你可视区域的尺寸和偏移，监听它的 resize 和 scroll，就能算出键盘高度，把底部栏挪上来。主流移动浏览器都支持。

另外两种办法支持范围小一些。viewport meta 里写 interactive-widget=resizes-content，键盘弹出时连布局视口一起缩小，Chrome 和 Firefox 的 Android 版支持，Safari 不支持。VirtualKeyboard API 只在 Chromium 里能用，适合要精确控制键盘区域的场景。

最后别忘了，输入框聚焦时用 scrollIntoView 保证它能被看到，并且要在 iOS 和 Android 真机上测。

两个视口有什么区别

布局视口是 CSS 布局的基准，fixed 定位就是相对它算的。可视视口是用户当前实际看到的那块区域，键盘弹出、双指缩放时它会变小或者移动。

键盘弹出以后，可视视口变矮了，布局视口的高度却没变。所以固定在布局视口底部的元素，就跑到了键盘下面。

用 VisualViewport 让底部栏跟着键盘

下面的代码算出键盘挡住的高度，再把底部栏往上移这么多。

JavaScript
const bar = document.querySelector('.bottom-bar');
const vv = window.visualViewport;

function update() {
  const keyboard = window.innerHeight - vv.height - vv.offsetTop;
  bar.style.transform = `translateY(${-Math.max(0, keyboard)}px)`;
}

if (vv) {
  vv.addEventListener('resize', update);
  vv.addEventListener('scroll', update);
}

innerHeight 是布局视口的高度，减去可视视口的高度和它的偏移，剩下的就是被键盘占掉的高度。

为什么用 transform 而不改 bottom？因为 transform 不会引起重新布局，更不容易抖动。

能不能让浏览器自己缩小布局

可以在 viewport meta 里加 interactive-widget：

HTML
<meta name="viewport" content="width=device-width, initial-scale=1, interactive-widget=resizes-content" />

它有三个取值：

值键盘弹出时
resizes-visual（默认）只缩小可视视口
resizes-content布局视口也缩小，fixed 元素和 dvh 自动避开键盘
overlays-content都不缩小，键盘覆盖在内容上

写了 resizes-content，布局视口跟着变矮，固定元素自然就避开了键盘，不用写 JS。可是 Safari 这类不支持的浏览器会直接忽略它，所以还得用 VisualViewport 方案兜底。

VirtualKeyboard API 怎么用

这个 API 反过来做：让浏览器完全不管视口，由页面自己给键盘留位置。

JavaScript
if ('virtualKeyboard' in navigator) {
  navigator.virtualKeyboard.overlaysContent = true;
}
CSS
.chat {
  display: grid;
  grid-template-rows: 1fr auto env(keyboard-inset-height, 0px);
  height: 100dvh;
}

打开 overlaysContent 以后，浏览器不再调整视口，键盘直接盖在内容上。页面用 env(keyboard-inset-height) 拿到键盘高度，在网格最后一行把空间留出来。这个 API 是实验性的，只在 Chromium 系浏览器的安全上下文里能用。

输入框本身被挡住怎么办

JavaScript
input.addEventListener('focus', () => {
  setTimeout(() => input.scrollIntoView({ block: 'center' }), 300);
});

为什么要延迟？因为键盘弹出有动画，动画结束可视视口才稳定，这时再滚动更可靠。如果输入框在一个滚动容器里，还要确认容器的高度会随键盘变化，否则滚了也看不到。

测试时要注意什么

iOS Safari、Android Chrome 和你的 App 里的 WebView 要分别测，WebView 的表现还受原生配置影响。横屏、外接键盘、第三方输入法（高度各不相同）也要测，并且看键盘收起后布局能不能恢复。

常见追问

为什么 100vh 的页面，键盘弹出后还能滚动？

因为 vh 不随键盘变化，页面还是原来那么高，可视区域却变小了。可以改用 dvh，或者配合 interactive-widget 处理。

安全区域和键盘有什么关系？

两者互不相干。底部栏既要避开手势条，也要避开键盘，两件事要分别处理，见《移动端安全区域怎样避免内容被刘海和底部手势条遮挡？》。
