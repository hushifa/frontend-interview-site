模型提出工具调用后，前端应该怎样展示和确认？

工具调用是模型提出的带参数请求。前端要把一次 Agent 运行拆成步骤，用服务端事件驱动状态，在副作用前展示真实参数请用户确认，执行端重新授权，并用调用 ID 处理结果未知。

参考答案

简答

  • 模型返回的工具调用只是建议，执行前要经过参数校验、用户确认和服务端授权三道关。
  • 一次 Agent 运行由多个步骤组成，每个步骤有稳定 ID 和自己的状态；状态由执行端事件驱动，模型说"已保存"不算数。
  • 确认卡片展示真正会执行的参数，例如收件人、路径、金额；确认记录绑定调用 ID、参数摘要和过期时间，参数一变就要重新确认。
  • 请求发出后连接中断时，结果是"未知"而不是"失败"，先用原调用 ID 查询状态，再决定是否重试。

运行、步骤和状态

用户点一次"执行"产生一次运行，运行里包含模型请求、检索、工具调用、等待审批等步骤，步骤之间可能并行：

TypeScript
type StepStatus =
  | 'receiving-args' // 参数还在流式接收
  | 'needs-approval'
  | 'executing'
  | 'succeeded'
  | 'failed'
  | 'cancelled'
  | 'unknown'; // 请求已发出但没收到结果

type Step = {
  id: string; // 工具步骤即 callId，同时作为幂等键
  kind: 'model' | 'retrieval' | 'tool';
  status: StepStatus;
  args?: unknown;
  result?: { summary: string; evidence?: string }; // 记录 ID、文件版本等
  error?: { code: string; retryable: boolean };
  version: number; // 每次状态变化加 1，用于丢弃迟到事件
};

一条进度条无法表达"检索已完成、写文件在等批准"这种并行状态，所以按步骤展示。一步在等批准时，只读检索可以继续，依赖这次批准的写入、发送或删除不能提前执行。

状态只由执行端事件推进，例如 step.started、step.waiting-approval、step.succeeded。模型流式输出的说明文字可以展示，但不改变步骤状态。参数接收完整并通过 Schema 校验之前，不显示批准按钮。

确认卡片展示什么

  • 发邮件：收件人、主题、正文摘要、附件、发件账号，是否发往外部域名。
  • 删除：具体资源和数量。
  • 支付：金额、币种、收款方。

影响风险的字段不能折叠隐藏。模型生成的 URL、文件名按不可信文本渲染。

用户点击确认后，前端只是把审批 ID 交给服务端。服务端执行前重新检查用户身份、租户、资源权限、工具白名单，以及审批是否过期、参数摘要是否和审批时一致。浏览器提交的 approved: true 不能跳过这些检查。

结果未知时怎样重试

JavaScript
async function retryStep(callId, approval) {
  const { status, error } = await getExecutionStatus(callId);
  if (status === 'succeeded' || status === 'executing') return { status };
  if (status === 'failed' && !error?.retryable) return { status: 'failed' };
  if (status !== 'failed') return { status: 'unknown' }; // 查不到确定结果，交给用户决定

  // 审批过期或参数变化，回到待确认
  const { argsDigest } = await getCall(callId);
  if (approval.expiresAt <= Date.now() || argsDigest !== approval.argsDigest) {
    return { status: 'needs-approval' };
  }
  return executeAgain({ callId, approvalId: approval.id });
}

重试沿用原 callId，服务端据此去重，避免重复发信或重复下单。每次尝试另记一条 attempt 记录，界面能显示"第一次失败、第二次成功"，排查时也能还原过程。取消只能阻止还没开始的步骤，已经完成的外部写入要走业务的撤销或补偿流程。

刷新与失败展示

  • 刷新页面后先拉取运行的服务端快照，再从快照版本继续订阅事件。事件带运行 ID、步骤 ID 和版本号，重复或迟到的事件不能把已完成的步骤改回执行中。
  • 展示历史步骤不会重新执行工具。
  • 失败按原因区分：参数错误、权限不足、用户拒绝、外部服务失败、结果未知，并附上诊断 ID。
  • 成功时展示真实证据，例如外部记录 ID、文件版本、链接，以及修改摘要、验证命令和未完成事项。
  • 原始工具日志默认折叠，并按权限脱敏，不向普通用户展示环境变量、完整请求头或内部路径。

常见追问

  • 只读工具也要确认吗？ 由产品策略决定。只读检索通常自动执行；任何写入、发送、删除或花钱的操作都需要确认。
  • 一次批准能覆盖后续所有调用吗？ 可以提供"本次会话内允许此工具"之类的选项，但范围要写清楚，服务端照样逐次授权。
