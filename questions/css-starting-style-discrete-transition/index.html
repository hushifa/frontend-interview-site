@starting-style 和离散属性过渡解决了什么问题？

元素从 display: none 出现时没有起点，过渡播不出来，@starting-style 就是给它补一个起点。transition-behavior: allow-discrete 让 display 这类属性等动画结束再切换，这样进入和退出动画都能用纯 CSS 做。

参考答案

简答

transition 要有“从哪里变到哪里”。元素从 display: none 变成可见时，它之前根本没被渲染，没有上一帧的样式，所以过渡不会触发，元素直接出现。@starting-style 就是给它补上这个起点。

退出也有问题。display 这种只能直接切换、没有中间值的属性叫离散属性，默认在过渡一开始就切换，元素瞬间变成 none，退出动画看不到。加上 allow-discrete，display 会等退出动画结束才变成 none。popover 和模态 dialog 还要多过渡一个 overlay，不然元素会提前离开顶层。

写法上要注意，@starting-style 和原规则的优先级一样，单独写的时候要放在原规则后面，嵌套写法没有这个问题。

@starting-style 自 2024 年 8 月起进入 Baseline，不支持的浏览器里元素直接出现、直接消失，功能不受影响。

Popover 的进入和退出动画

CSS
[popover] {
  opacity: 0;
  transform: translateY(8px);
  transition:
    opacity 200ms,
    transform 200ms,
    overlay 200ms allow-discrete,
    display 200ms allow-discrete;
}

[popover]:popover-open {
  opacity: 1;
  transform: none;

  @starting-style {
    opacity: 0;
    transform: translateY(8px);
  }
}

打开时，浏览器先按 @starting-style 里的值算一次，把它当成起点，再过渡到打开的样式，所以能看到淡入上移。

关闭时，元素从打开状态过渡回 [popover] 的基础样式，不是回到 @starting-style。因为加了 allow-discrete，display 和 overlay 等 200ms 后才切换，这期间淡出动画能完整播完。

::backdrop 不能在里面嵌套 @starting-style，要单独写一块，放在 [popover]:popover-open::backdrop 规则后面。dialog 的写法一样，选择器换成 dialog 和 dialog[open]。

以前为什么难做

没有这两个特性时，常见写法是先去掉 display: none，等浏览器算完一次样式，再加上可见状态的类。

很多人以为用一次 requestAnimationFrame 就行，结果过渡还是不播。因为 rAF 回调运行在同一帧的样式计算之前，起点和终点被合并成一次计算，浏览器只看到了终点。实际要用两次 rAF，或者在中间读一下 offsetHeight 强制算样式。

退出时还要监听 transitionend 再设置 display: none，还得处理动画到一半用户又点开的情况。

现在这些都交给 CSS，JavaScript 只负责切换状态，比如调用 showPopover()。

动态插入的元素

CSS
.toast {
  opacity: 1;
  transition: opacity 150ms;

  @starting-style {
    opacity: 0;
  }
}

新插入页面的 .toast 会从透明淡入，这对动态插入的节点同样有效。

可是删除节点时，仍然没有退出动画，因为节点直接就不在页面上了。需要退出效果的话，先切换到一个隐藏状态，等 transitionend 以后再删除节点。

常见追问

怎么和 prefers-reduced-motion 配合？

在减少动态效果的媒体查询里，把 transition 设成 none。状态切换还是正常的，只是没有动画。
