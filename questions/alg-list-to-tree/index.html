怎样在 O(n) 时间内把扁平列表转成树，再把树转回列表？

先遍历一遍，用 Map 按 id 把所有节点建好；再遍历一遍，按 parentId 从 Map 里找到父节点，挂到它的 children 上，找不到父节点的当作根。两遍各是 O(n)，而且不管输入顺序。树转回列表用一个栈做前序遍历，顺便记下每个节点的父 id。

参考答案

简答

最直接的写法是对每个节点，都去整个列表里找它的子节点，这样是 O(n²)。改进办法是先用一个 Map 按 id 建索引，找父节点就变成了 O(1)，总共是 O(n)。

顺序上，要先把所有节点都建好，再去连父子关系。这样就算子节点在列表里排在父节点前面，也能正确挂上去。parentId 是根标记，或者指向一个不存在的节点时，都把它放进根数组，不然这些孤儿节点就丢了。另外要复制一份节点再加 children，不要改调用方传进来的数据。

树转回列表，用一个栈做前序遍历，入栈时把父 id 一起带上。用显式的栈而不是递归，层级很深时也不会栈溢出。

列表转树

JavaScript
function listToTree(list, { rootId = null } = {}) {
  const nodes = new Map();
  for (const item of list) nodes.set(item.id, { ...item, children: [] });

  const roots = [];
  for (const node of nodes.values()) {
    const parent = node.parentId === rootId ? undefined : nodes.get(node.parentId);
    // 根节点和父节点不存在的孤儿节点都放在第一层
    if (parent) parent.children.push(node);
    else roots.push(node);
  }
  return roots;
}

为什么一定要分两遍？如果只遍历一遍、边建节点边挂，那子节点排在父节点前面时，去 Map 里找父节点，父节点还没建出来，就挂不上了。分两遍，第二遍时所有节点都已经在 Map 里了，顺序就无所谓了。

{ ...item, children: [] } 是复制了一个新对象，所以调用方传进来的原数据不会被加上 children。

同一个父节点下的子节点，顺序和它们在原列表里一样，因为 Map 是按插入顺序遍历的。还要注意，如果 id 有重复，后出现的会覆盖前面的，要在调用前自己校验数据。

树转列表

JavaScript
function treeToList(roots) {
  const result = [];
  // 反向入栈，保证出栈顺序与原来的兄弟顺序一致
  const stack = [...roots].reverse().map((node) => [node, null]);
  while (stack.length) {
    const [node, parentId] = stack.pop();
    const { children = [], ...rest } = node;
    result.push({ ...rest, parentId });
    for (let i = children.length - 1; i >= 0; i--) stack.push([children[i], node.id]);
  }
  return result;
}

栈里存的不只是节点，而是 [节点, 父 id] 这样一对。为什么要一起存？因为节点出栈的时候，我们需要知道它的父亲是谁，而这个信息是在父节点把它压进栈时才知道的。

子节点为什么倒着压栈？因为栈是后进先出，倒着压，第一个子节点就会最先弹出来，输出顺序和原来的兄弟顺序一致。

每个节点进栈、出栈各一次，所以是 O(n)。

要注意一点：这里的父 id 来自遍历时的位置，不是节点上原来的 parentId。所以孤儿节点转回来以后，parentId 会变成 null。

验证一下

JavaScript
const list = [
  { id: 3, parentId: 1, name: 'c' },
  { id: 1, parentId: null, name: 'a' },
  { id: 2, parentId: 1, name: 'b' },
  { id: 4, parentId: 9, name: 'orphan' },
  { id: 5, parentId: 3, name: 'e' },
];

const tree = listToTree(list);
// a 的 children 为 [c, b]，c 的 children 为 [e]，orphan 是第二个根

console.log(treeToList(tree).map((n) => `${n.id}:${n.parentId}`).join(' '));
// 1:null 3:1 5:3 2:1 4:null

列表里 c 排在 a 前面，照样挂到了 a 下面。orphan 的父 id 是 9，列表里没有 9，所以它成了第二个根。转回列表时，它的 parentId 从 9 变成了 null，原因就是上面说的那一点。

常见追问

数据里有环怎么办？

比如 A 的父是 B、B 的父是 A。它俩都能找到父节点，所以都不会进根数组，结果转出来的树里就没有它们了。要在连接之前检测环，或者转换完以后检查一下节点总数对不对得上。

要按 sort 字段排序怎么办？

树建好以后，对每个节点的 children 排一次序。复杂度会变成 O(n log n)。
