Proxy 与 Reflect 能实现什么，存在哪些限制？

Proxy 能拦截对一个对象的读、写、删除、遍历等操作，Reflect 用来在拦截后执行原本的默认行为。Vue 3 的响应式就靠它们。限制是必须遵守一些规则，而且拦截不到私有字段和 Map 这类对象的内部数据。

参考答案

简答

new Proxy(target, handler) 会返回一个代理对象，对它做的读属性、写属性、in、delete、遍历、调用，都会先进入 handler 里对应的函数，这些函数叫陷阱。所以可以在里面记录、校验、改写这些操作。

Reflect 上的方法和陷阱一一对应，比如 Reflect.get、Reflect.set，用来在陷阱里执行原本的默认行为。转发时要把 receiver 也传进去，这样 getter 里的 this 才会是代理，而不是原对象。

它有几个限制。陷阱的结果必须遵守一些规则，叫不变式，比如一个属性不可配置又不可写，get 就必须返回它的真实值，否则抛 TypeError。代理和原对象是两个不同的对象，直接改原对象不会经过陷阱。

还有，私有字段 #x 和 Map、Set、Date 这类对象的内部数据，都不经过陷阱，要把方法绑定到原对象上才能用。

先看一个记录读取、校验写入的例子

下面的代理会把每次读取的属性名记下来，并且在写入价格时做校验。注意读 total 时一共记了几个属性。

JavaScript
const reads = [];
const target = {
  price: 10,
  get total() {
    return this.price * 2;
  },
};

const product = new Proxy(target, {
  get(object, key, receiver) {
    reads.push(String(key));
    return Reflect.get(object, key, receiver);
  },
  set(object, key, value, receiver) {
    if (key === 'price' && (!Number.isFinite(value) || value < 0)) {
      throw new RangeError('价格必须是非负有限数值');
    }
    return Reflect.set(object, key, value, receiver);
  },
});

console.log(product.total); // 20
console.log(reads.join(',')); // total,price
product.price = 12;
console.log(target.price); // 12
console.log(product === target); // false

只读了一次 product.total，记录里却有 total 和 price 两个。

这是 receiver 的作用。Reflect.get(object, key, receiver) 会让 total 的 getter 以 receiver，也就是代理为 this 执行。getter 里读 this.price，读的是代理的 price，所以又进了一次 get 陷阱。如果写成 return object[key]，getter 的 this 就是原对象，读 price 不经过代理，这次读取就漏掉了。

Vue 3 的响应式正是依赖这一点：计算属性里用到了哪些属性，都要被记录下来，之后这些属性变了才能通知更新。

写入时，product.price = 12 通过了校验，改到了原对象上，所以 target.price 是 12。但 product 和 target 不是同一个对象，比较结果是 false。

set 陷阱要返回 true 表示写入成功。返回 false 的话，严格模式下会抛 TypeError。

陷阱为什么不能随便返回值

JavaScript
const locked = {};
Object.defineProperty(locked, 'id', { value: 7, writable: false, configurable: false });

const proxy = new Proxy(locked, { get: () => 8 });
try {
  console.log(proxy.id);
} catch (error) {
  console.log(error.name); // TypeError
}

get 陷阱想把 id 改成 8，结果读取直接抛了 TypeError。

因为 id 在原对象上是不可写、不可配置的，语言保证它的值永远是 7。代理如果能返回别的值，这个保证就被破坏了，所以引擎会检查陷阱的结果，违反就报错。这类规则叫不变式。

类似的规则还有：ownKeys 返回的键必须包含所有不可配置的键；原对象不可扩展时，ownKeys 必须正好返回原对象的那些键，不能多也不能少。

为什么代理 Map 会报错

JavaScript
const map = new Map();
const values = new Proxy(map, {
  get(target, key) {
    const value = Reflect.get(target, key);
    return typeof value === 'function' ? value.bind(target) : value;
  },
});
values.set('a', 1); // 不绑定时抛 TypeError

如果不做 bind，values.set('a', 1) 会抛 TypeError。

Map 的数据不存在普通属性里，而是存在引擎内部的槽里。Map.prototype.set 要求 this 必须是真正带这个内部槽的 Map。不绑定时，this 是代理，代理没有内部槽，于是报错。改法就是像上面这样，把取到的方法绑定到原来的 map 上。Vue 对 Map、Set 这类集合类型用的是专门的处理器。

用 Proxy 做响应式还要做什么

Proxy 只解决了“拦截”这一步，一套完整的响应式还要做很多事。嵌套对象要在 get 时才包装成代理，这样不用一开始就把整棵树都包一遍；还要用 WeakMap 缓存原对象到代理的对应关系，保证同一个对象每次拿到的都是同一个代理。数组的 push 会同时读写 length，要避免因此重复触发更新。依赖收集、批量调度更新、清理过时的依赖，这些也都是代理之外的工作。

常见追问

用 Object.defineProperty 实现响应式有什么不足？

它只能劫持已经存在的属性。新增属性、删除属性、通过下标修改数组都劫持不到，需要额外的 API，所以 Vue 2 才提供了 Vue.set。

Proxy.revocable 做什么？

它返回 { proxy, revoke }。调用 revoke() 以后，对这个代理的任何操作都会抛 TypeError。适合把访问权临时交给第三方代码，用完就收回。
