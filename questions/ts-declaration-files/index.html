.d.ts 声明文件提供了什么，不能保证什么？

.d.ts 只描述 JavaScript 已有的导出和全局变量的类型，编译后不产生代码。声明与实现是否一致由发布者负责：声明写了导出，运行时不一定真有。包通过 exports 的 types 条件或 types 字段暴露声明，没有自带类型的库用 @types 包，全局变量用 declare 声明。

参考答案

简答

  • .d.ts 只包含类型声明（declare function、interface、type 等），不能写实现。
  • 声明写错时，编译器会放过错误调用或拒绝正确调用，运行时才暴露问题；skipLibCheck 只跳过检查声明文件本身，不会修正它。
  • 查找顺序：相对导入找同名 .d.ts；包看 exports 中的 types 条件，再看 types 字段；都没有时查 @types/包名。
  • 没有 import/export 的 .d.ts 是全局声明文件；有的话是模块，需要用 declare global 扩展全局类型。
  • declare module '*.svg' 只解释资源导入的类型，真正处理文件的是构建工具。

给 JS 模块写声明

JavaScript
// format-count.js
export function formatCount(value) {
  if (!Number.isSafeInteger(value) || value < 0) {
    throw new RangeError('数量必须是非负安全整数');
  }
  return `${value} 项`;
}
TypeScript
// format-count.d.ts
/** 将非负安全整数格式化为数量文案。 */
export declare function formatCount(value: number): string;
TypeScript
// consumer.ts
import { formatCount } from './format-count.js';

const label = formatCount(3); // string
// @ts-expect-error 声明要求 number
formatCount('3');

number 类型不排除负数和小数，业务校验仍在 JS 实现中。JSDoc 注释会出现在编辑器提示里。

全局与资源声明

TypeScript
// env.d.ts，没有 import/export，属于全局
declare const APP_VERSION: string;

declare module '*.svg' {
  const url: string;
  export default url;
}

APP_VERSION 需要构建工具（如 Vite 的 define）真正注入，否则运行时是 ReferenceError。

生成声明

  • TS 源码开启 declaration 自动生成；只要声明不要 JS 时加 emitDeclarationOnly。
  • JS 项目可以用 allowJs + checkJs + declaration 从 JSDoc 生成。
  • isolatedDeclarations（5.5）要求导出都有显式类型，使其他工具不做类型检查也能生成声明。
  • 生成后检查一遍：是否暴露了内部类型，是否引用了只在本仓库存在的 paths 别名。

声明错误的常见原因

  • 类型包版本与运行库版本不一致（@types/x@2 配 x@3）。
  • ESM/CommonJS 格式不一致，例如 CommonJS 包的声明写成 export default，见《TypeScript 库发布时怎样组织类型声明和入口？》。
  • 声明使用了消费者没有安装的依赖类型。

常见追问

  • 第三方库类型有误怎么办？先确认版本匹配；临时在项目中用模块增补修正，并给类型包提交修复。
  • /// <reference types="node" /> 做什么？在声明文件中引入某个类型包的全局声明，应用代码中更推荐在 tsconfig 的 types 中配置。
