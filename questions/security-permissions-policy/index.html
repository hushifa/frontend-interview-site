Permissions Policy 怎样限制页面和 iframe 的设备能力？

页面用 Permissions-Policy 响应头声明自己和哪些来源的 iframe 能用摄像头、麦克风、定位这类能力，iframe 还要在 allow 属性里被单独委托。策略只决定有没有资格，真正使用还要用户点同意。

参考答案

简答

页面里嵌了广告、统计、视频会议各种第三方 iframe，你不希望广告能调摄像头。Permissions Policy 就是用响应头声明：哪些来源有资格用哪些能力。比如 Permissions-Policy: camera=(self "https://meet.example"), geolocation=()，摄像头只给本站和会议组件，定位谁都不给，() 表示所有文档都禁止。

跨源 iframe 默认没有大多数强能力，要两边都同意才行。顶层页面的策略要允许这个来源，嵌入时还要在 <iframe allow="camera"> 里把能力委托给它。

它的用途是关掉页面用不到的能力，限制第三方 iframe 的权限，减少被滥用的可能。被策略禁用时，相关的 API 会直接失败或拒绝，通常不会弹权限提示。

要注意，策略只是一道门槛，过了门槛浏览器还会要求安全上下文，并弹窗让用户授权。它只能限制或委托，不能替用户授予权限。

怎么写

http
Permissions-Policy: camera=(self "https://meet.example"), microphone=(self "https://meet.example"), geolocation=(), payment=()
HTML
<!-- 会议组件：委托摄像头和麦克风 -->
<iframe src="https://meet.example/room/42" allow="camera; microphone"></iframe>

<!-- 广告：不委托任何能力 -->
<iframe src="https://ads.example/slot" sandbox="allow-scripts"></iframe>

会议组件能用摄像头，是因为响应头允许了 https://meet.example，同时 iframe 的 allow 里写了 camera，两个条件都满足。广告 iframe 两个条件都不满足，所以调摄像头会直接失败。

允许列表的几种写法：

写法含义
feature=*所有来源都可以
feature=(self)只有本页面的源
feature=(self "https://a.example")本源和指定来源
feature=()全部禁用

怎么检查和排查

JavaScript
// 当前文档是否被策略允许使用某项能力（部分浏览器提供）
document.featurePolicy?.allowsFeature('camera');

// 用户授权状态
const status = await navigator.permissions.query({ name: 'geolocation' });
console.log(status.state); // granted / denied / prompt

这两行查的是两件不同的事。第一行问“策略允不允许”，第二行问“用户同没同意”。document.featurePolicy 是旧名字下的接口，不是所有浏览器都有，不要拿它当唯一的判断依据。

摄像头打不开时，按顺序检查：

  1. 页面是否是 HTTPS。
  2. 最终响应是否带了预期的 Permissions-Policy（CDN 或代理可能覆盖）。
  3. iframe 的 allow 属性是否包含该能力。
  4. 用户是否拒绝过授权，或系统层面禁用了设备。

和其他机制有什么区别

sandbox 控制的是脚本、表单、导航这些通用能力，Permissions Policy 控制的是摄像头、定位这类具体的设备和浏览器功能，两者经常一起用，就像上面的广告 iframe。CSP 管资源加载和脚本执行，不管设备能力。旧的 Feature-Policy 头已经被 Permissions-Policy 取代了，两者语法不同，不能直接照抄。

常见追问

能用它强制给页面授予权限吗？

不能。它只能限制或者委托，最终给不给权限由用户决定。

跨源隔离也是靠它吗？

不全是。像高精度计时、SharedArrayBuffer 这些能力还依赖 COOP 和 COEP，不是只靠 Permissions Policy 就能打开。
