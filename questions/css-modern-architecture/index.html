CSS Modules、层叠层和自定义属性怎样帮助维护样式？

CSS Modules 在构建时生成唯一类名避免命名冲突，@layer 显式规定覆盖顺序，自定义属性传递可被继承和覆盖的设计值；三者分别处理命名、优先级和主题。

参考答案

简答

  • CSS Modules 把 .button 编译成类似 .button_a1b2 的类名，解决的是全局命名冲突，不影响优先级和继承。
  • @layer reset, base, components, utilities; 先声明顺序，后面的层覆盖前面的层，与选择器优先级无关。
  • 自定义属性（--color-primary）会继承，可以在任意祖先上重新赋值，适合主题、密度和组件可配置项。
  • 三者可以组合：组件样式用 Modules 写并放进 components 层，颜色和间距从自定义属性读取。
  • 它们都不是完全隔离：继承属性、全局元素选择器仍会影响组件，需要更强的封装时用 Shadow DOM：外部选择器无法匹配影子树内的元素，但继承属性和自定义属性仍会传入。

层叠层管理覆盖

CSS
@layer reset, vendor, components, utilities;

@import url('vendor.css') layer(vendor);

@layer components {
  .button {
    padding: 8px 16px;
  }
}

@layer utilities {
  .hidden {
    display: none;
  }
}

第三方库放进 vendor 层后，业务组件不需要更高的选择器优先级就能覆盖它。未分层的样式优先于所有层，临时修复可以写在层外，但应尽快归位。

自定义属性做主题

CSS
:root {
  --surface: white;
  --text: #1a1a1a;
}

[data-theme='dark'] {
  --surface: #121212;
  --text: #eee;
}

.card {
  background: var(--surface);
  color: var(--text);
  padding: var(--card-padding, 16px);
}

var() 的第二个参数是回退值。组件把可配置项暴露成自定义属性，使用方在外层赋值即可，不需要覆盖组件内部的选择器。

CSS Modules

JavaScript
import styles from './Button.module.css';

export function Button() {
  return <button className={styles.button}>保存</button>;
}

Vite、webpack 等工具都内置支持。用 :global(.x) 可以写全局类，composes 可以复用其他模块的类。

常见追问

  • 和 Tailwind 冲突吗？Tailwind 4 本身就把样式放在 theme、base、components、utilities 层里，自定义样式放进对应层即可按预期覆盖。
