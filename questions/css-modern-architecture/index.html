CSS Modules、层叠层和自定义属性怎样帮助维护样式？

三者各管一件事。CSS Modules 把类名编译成唯一的，解决重名；@layer 规定谁覆盖谁，解决优先级打架；自定义属性传可继承、可覆盖的设计值，用来做主题。

参考答案

简答

样式难维护，通常是三类问题：类名重了，覆盖不了别人的样式，主题改起来要改一大片。这三样工具正好一个管一类。

CSS Modules 在构建时把 .button 编译成类似 .button_a1b2 的类名，解决全局重名，但不影响优先级和继承。@layer 先声明 reset, base, components, utilities 这样的顺序，后面的层覆盖前面的层，跟选择器优先级无关。自定义属性，比如 --color-primary，会继承，能在任意祖先上重新赋值，适合做主题、密度和组件的可配置项。

三者可以一起用：组件样式用 Modules 写，放进 components 层，颜色和间距从自定义属性读。

要注意它们都不是完全隔离的，继承属性和全局元素选择器还是会影响组件。需要更强的封装就用 Shadow DOM，外面的选择器匹配不到影子树里的元素，不过继承属性和自定义属性仍然会传进去。

用层叠层管理谁覆盖谁

CSS
@layer reset, vendor, components, utilities;

@import url('vendor.css') layer(vendor);

@layer components {
  .button {
    padding: 8px 16px;
  }
}

@layer utilities {
  .hidden {
    display: none;
  }
}

第一行定好了顺序。第三方库通过 @import ... layer(vendor) 整个放进 vendor 层。

这样有什么好处？第三方库里可能写着 .lib .btn.primary 这种很长的选择器。以前想覆盖它，只能写一个优先级更高的选择器，越写越长。现在 components 层排在 vendor 后面，业务组件随便写个 .button 就能覆盖，不用比优先级。

没放进任何层的样式，比所有层都优先。临时修复可以先写在层外面，但要尽快放回该放的层里，不然层的顺序就失去意义了。

用自定义属性做主题

CSS
:root {
  --surface: white;
  --text: #1a1a1a;
}

[data-theme='dark'] {
  --surface: #121212;
  --text: #eee;
}

.card {
  background: var(--surface);
  color: var(--text);
  padding: var(--card-padding, 16px);
}

.card 只读变量，不关心现在是什么主题。外层加上 data-theme='dark'，变量换了值，继承下来，卡片自然变成深色。

var() 的第二个参数是回退值。--card-padding 没人设置时就用 16px。组件这样把可配置项暴露出来，用的人在外层赋值就行，不用去覆盖组件内部的选择器。

CSS Modules 怎么用

JavaScript
import styles from './Button.module.css';

export function Button() {
  return <button className={styles.button}>保存</button>;
}

styles.button 拿到的就是编译后的唯一类名，别的文件里也有 .button 也不会冲突。Vite、webpack 这些工具都内置支持。确实要写全局类时用 :global(.x)，想复用其他模块的类用 composes。

常见追问

这套做法和 Tailwind 冲突吗？

不冲突。Tailwind 4 本身就把样式放在 theme、base、components、utilities 这几个层里，自己的样式放进对应的层，就能按预期覆盖。
