interpolate-size 和 calc-size() 怎样实现 auto 高度动画？

解释 intrinsic size 关键字为什么过去不能直接参与 CSS 过渡，说明 interpolate-size、calc-size() 与展开面板的配合方式，以及布局成本、可访问状态和兼容回退。

参考答案

折叠面板、帮助说明和菜单经常需要从“没有高度”展开到内容的自然高度。过去 CSS 不能直接可靠地在 height: 0 和 height: auto 之间插值，因为 auto 不是一个确定的数值，而是要经过内容、字体、内边距和布局上下文计算出来的 intrinsic size。开发者通常只能用 JavaScript 读取 scrollHeight，或者用一个足够大的 max-height 猜测上限。

现代 CSS 提供 interpolate-size，允许在数值和部分 intrinsic size 关键字之间插值：

CSS
:root {
  interpolate-size: allow-keywords;
}

.details {
  height: 0;
  overflow: clip;
  transition: height 260ms ease;
}

.details[open] {
  height: auto;
}

在支持的浏览器中，面板可以从 0 平滑过渡到内容计算出的自然高度。interpolate-size 通常继承，放在根元素可以让子树沿用策略；也可以只在特定组件上启用，避免无意影响整个页面。

为什么 auto 过去不能直接动画

数值到数值的过渡可以按时间计算中间值，例如 0px 到 300px。auto 则不是一个固定长度：内容变多、字体加载完成、容器宽度变化或内边距改变，都可能让它重新计算。浏览器过去没有统一的中间值定义，因此常见结果是直接跳到最终高度。

interpolate-size: allow-keywords 并不是让所有 CSS 关键字都自动可动画。支持的关键字、属性和浏览器版本需要查目标环境；不支持的组合仍可能离散切换。auto 的最终值还会受到 min/max 约束、盒模型、网格或 flex 布局影响，不能把动画时长和视觉位移当成固定像素关系。

calc-size() 可以对 intrinsic size 做计算

当需要在自然高度基础上增加或限制空间时，可以使用 calc-size()：

CSS
.details[open] {
  height: calc-size(auto, size + 1rem);
}

calc-size() 的语法和支持范围比普通 calc() 更特殊，它允许在 intrinsic size 关键字上进行受支持的计算。不要把 calc(auto + 1rem) 当成等价写法；普通 calc() 并不能任意把 auto 当成数值参与运算。

实际组件通常还要把最大高度和溢出策略写清楚。可以让自然高度负责展开，再让外层布局或内部滚动容器限制过长内容；不要为了追求一行 CSS 而写出目标浏览器不支持的混合计算表达式。

CSS
.accordion-panel {
  interpolate-size: allow-keywords;
  height: 0;
  max-block-size: 60vh;
  overflow: clip;
  transition: height 220ms ease;
}

.accordion-panel[data-expanded='true'] {
  height: auto;
  overflow: auto;
}

展开状态不能只由 CSS 视觉决定

一个面板看起来展开，不代表读屏器和键盘用户知道状态。按钮应使用 aria-expanded 和 aria-controls，内容区域要有稳定的 ID：

HTML
<button
  type="button"
  aria-expanded="false"
  aria-controls="shipping-help"
  data-toggle="shipping-help"
>
  了解配送方式
</button>
<section id="shipping-help" hidden>
  配送时间会根据地区和库存变化。
</section>
JavaScript
const button = document.querySelector('[data-toggle]');
const panel = document.querySelector(`#${button.getAttribute('aria-controls')}`);

button.addEventListener('click', () => {
  const expanded = button.getAttribute('aria-expanded') === 'true';
  button.setAttribute('aria-expanded', String(!expanded));
  panel.hidden = expanded;
});

如果使用 hidden，面板在隐藏时不会参与布局和辅助技术树，直接从 hidden 变为可见可能需要配合 @starting-style 和离散过渡；如果只用 height: 0，内容可能仍被读屏器读取，也可能仍能获得焦点。选择“保留在 DOM 但不可交互”还是“完全隐藏”，要根据组件语义和动画需求决定。interpolate-size 只处理尺寸，不会替你同步 hidden、inert、ARIA 和焦点。

auto 高度动画会触发布局

高度变化会影响后续内容的位置，通常需要重新计算布局和绘制。它和只改变 transform 的合成动画成本不同，不能因为动画由 CSS 声明就认为不会触发 layout。一个长页面里同时展开多个面板，可能造成较多布局工作和明显的输入延迟。

可以采用以下策略降低成本：

  • 只对用户主动展开的局部内容使用动画，不让大量列表同时自动展开；
  • 限制面板最大高度，超出部分在内部滚动；
  • 让图片、字体和异步内容尺寸尽量稳定，避免动画过程中自然高度不断变化；
  • 对低端设备和 prefers-reduced-motion: reduce 提供无动画路径；
  • 用 Performance 面板测量布局、绘制和输入延迟，不用属性名称推断性能。

如果展开后内容还会异步加载，动画可能先到一个高度，再因数据到达继续移动。可以先显示稳定的占位区域，或在内容准备好后开始过渡；不要为了让动画“完整”而阻塞用户查看已经可用的文字。

不要把 max-height 猜测当作等价回退

旧浏览器常见回退是：

CSS
.legacy-panel {
  max-height: 0;
  overflow: hidden;
  transition: max-height 240ms ease;
}

.legacy-panel.is-open {
  max-height: 40rem;
}

它可以提供视觉效果，但时长与真实内容高度不成比例：短内容可能很快完成，长内容可能提前截断或看起来慢；当内容超过 40rem 时会被隐藏。若使用这个回退，必须设置足够明确的内容上限、可滚动策略和无动画可用路径，不能把一个任意大数字宣传成自然高度动画。

另一种回退是 JavaScript 读取 scrollHeight，把当前数值写入 height，在 transition 结束后恢复 auto。这种方式需要处理字体变化、窗口调整、内容异步更新、取消动画和组件卸载，且读取与写入布局属性可能造成强制同步布局。现代浏览器增强与旧浏览器回退应由组件封装，不要让业务页面到处复制一套时序代码。

与 display 和 starting-style 的关系

如果元素从 display: none 变为可见，仅有 interpolate-size 还不够，因为没有可见的起始样式。可以结合 @starting-style 和 transition-behavior: allow-discrete，让显示状态和高度/透明度一起处理：

CSS
.panel {
  display: none;
  height: 0;
  opacity: 0;
  overflow: clip;
  transition:
    height 220ms ease,
    opacity 160ms ease,
    display 220ms allow-discrete;
}

.panel[data-open='true'] {
  display: block;
  height: auto;
  opacity: 1;
}

@starting-style {
  .panel[data-open='true'] {
    height: 0;
    opacity: 0;
  }
}

这仍然需要按目标浏览器测试，尤其是 display 的离散切换时机、内容可访问性和关闭后的清理。很多组件更适合保留节点并使用 hidden/inert 状态管理，而不是把每个生命周期都压缩成一个 CSS 选择器。

兼容性、降级和验收

interpolate-size 和 calc-size() 属于较新的 CSS 能力，支持范围需要查兼容性数据。可以把它们作为增强，旧浏览器继续使用固定高度、max-height 或无动画展开：

CSS
.panel {
  height: 0;
  overflow: hidden;
}

@supports (interpolate-size: allow-keywords) {
  :root {
    interpolate-size: allow-keywords;
  }

  .panel[data-open='true'] {
    height: auto;
  }
}

能力检测通过也不代表所有 intrinsic 关键字和组合属性都支持，仍要在目标浏览器中测试。验收至少包括：

  • 空内容、短内容、超长内容、异步内容和图片/字体加载；
  • 展开、收起、快速重复点击、页面卸载和导航取消；
  • 键盘、读屏、aria-expanded、焦点、hidden 和 inert；
  • 窄屏、文字放大、RTL、低端设备和减少动态效果偏好；
  • 不支持新 CSS 能力的浏览器，以及 max-height/JavaScript 回退的截断和性能。

interpolate-size 解决的是“浏览器怎样在数值和自然尺寸之间计算中间状态”，不是一个完整的手风琴组件。内容语义、可访问状态、布局成本、异步生命周期和兼容回退仍需要由组件设计负责。
