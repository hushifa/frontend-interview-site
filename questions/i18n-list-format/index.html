Intl.ListFormat 怎样生成自然的列表文案？

使用语言相关的连接词和列表类型展示人员、标签或选项，避免手动拼接逗号和“以及”。

参考答案

简答

  • Intl.ListFormat 按语言生成列表连接词，type 区分“和”“或”等关系。
  • 每一项要先格式化成文字，人名取展示名，金额先用 NumberFormat 格式化。
  • 每项需要单独渲染（例如加链接）时用 formatToParts。
  • 测试覆盖空列表、一项、两项和多项，不要锁死所有标点。

把三个参与者显示成自然语言，不只是 names.join(', ')。不同语言会使用不同标点、连接词和最后一项的连接方式；“甲和乙”与“甲或乙”表达的业务含义也不同。

Intl.ListFormat 根据 locale、连接类型和风格生成列表文案，让应用不用为每个语言手写最后一个逗号的规则。

先决定列表表达什么关系

JavaScript
const names = ['Alice', 'Bob', 'Carol'];
const together = new Intl.ListFormat('en-US', {
  type: 'conjunction',
  style: 'long',
});
const alternatives = new Intl.ListFormat('en-US', {
  type: 'disjunction',
  style: 'long',
});

console.log(together.format(names)); // Alice, Bob, and Carol
console.log(alternatives.format(names)); // Alice, Bob, or Carol
console.log(together.format([])); // 空字符串
console.log(together.format(['Alice'])); // Alice

conjunction 表示并列的“和”，disjunction 表示选择的“或”，unit 用于单位式列表。style 的 long、short、narrow 控制风格，但不是任意截断字符的长度限制，不同语言可能没有明显不同的缩写结果。

如果列表为空，API 返回空字符串，不会替产品决定显示“暂无参与者”还是隐藏整行。缺省状态应在业务层处理。它也不会自动去重、排序或删掉空字符串，输入清理要先完成。

每一项应先变成合适的文字

ListFormat 接收字符串序列，不能直接把用户对象或数值数组交给它期待自动翻译。人员列表先取展示名，金额列表先用 NumberFormat 格式化每个金额，再交给列表格式化器。

unit 类型也不会自动把 1 变成“一小时”，不会替你处理测量单位换算或复数词形。它只连接已经准备好的各项文本。

同样，不要先用英文拼接“3 more”，再期待 ListFormat 把这部分变成中文。超长列表的“其他 3 人”应作为独立的本地化消息设计，而且省略位置和总人数要与产品语义一致。

每个名字需要链接时，用 formatToParts

JavaScript
const formatter = new Intl.ListFormat('en-US', {
  style: 'long',
  type: 'conjunction',
});
const parts = formatter.formatToParts(['Alice', 'Bob']);
console.log(parts);
// [
//   { type: 'element', value: 'Alice' },
//   { type: 'literal', value: ' and ' },
//   { type: 'element', value: 'Bob' }
// ]

element 是输入项，literal 是本地化连接片段。界面可以把 element 渲染为链接，把 literal 渲染为普通文本，同时保留语言要求的顺序和标点。

若需要把名字关联回用户 ID，应按输入项出现顺序维护映射，不要用显示名称当唯一键；两个用户可能同名。也不要给拼接后的整句再按逗号切开，名字自己就可能包含逗号。

ListFormat 不做 HTML 转义。React 中可把 value 作为普通文本子节点；原生 DOM 则使用文本节点或 textContent，不要因为字符串来自格式化 API 就把它当作安全 HTML。

测试语义与边界，而不是锁死所有标点

至少覆盖空列表、一项、两项、多项、重复名称和目标语言。运行时的 ICU/CLDR 数据更新可能调整标点或空格，服务端和浏览器版本不同也可能出现细节差异。

如果快照测试需要严格一致，应固定测试运行时；跨环境测试可以检查所有项都保留、顺序正确、parts 拼接与 format 一致等契约，而不是把某个版本的空格当成永远不变的标准。

ListFormat 适合把短列表写进自然语言句子。很长的成员名单通常更适合可访问的列表结构、分页或折叠，不应该因为有格式化 API 就把几十个链接挤成一行。
