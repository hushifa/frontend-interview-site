Intl.ListFormat 怎样生成自然的列表文案？

Intl.ListFormat 按语言生成“A、B 和 C”“A, B, or C”这样的列表文案，type 区分“和”“或”。输入要先格式化成字符串；每项需要单独渲染（如链接）时用 formatToParts。

参考答案

简答

显示参与者名单时，很多人直接写 names.join(', ')。可是各语言的连接词和标点不一样，英文是“Alice, Bob, and Carol”，中文是“张三、李四和王五”。Intl.ListFormat 就是按语言把一组字符串连成自然的一句话。

用 type 选连接方式。'conjunction' 是“和”，'disjunction' 是“或”，'unit' 用来写“5 小时 30 分”这类单位列表。

它只接受字符串。对象要先取出显示名，数字要先用 NumberFormat 格式化。需要给每一项加链接时，用 formatToParts()，它会把列表项和连接词分开返回。

要注意，空数组返回空字符串，这时显示“暂无参与者”还是隐藏整行，由业务决定。去重和排序也要在传进去之前做好。

基本用法

下面同一组名字，分别用“和”与“或”连接，再看中文和边界情况。结果是 Node 22 实测的。

JavaScript
const names = ['Alice', 'Bob', 'Carol'];
new Intl.ListFormat('en', { type: 'conjunction' }).format(names); // 'Alice, Bob, and Carol'
new Intl.ListFormat('en', { type: 'disjunction' }).format(names); // 'Alice, Bob, or Carol'
new Intl.ListFormat('zh-CN').format(['张三', '李四', '王五']); // '张三、李四和王五'
new Intl.ListFormat('en').format([]); // ''
new Intl.ListFormat('en').format(['Alice']); // 'Alice'

英文最后一项前面有个逗号再加“and”，中文用顿号和“和”，这些细节手写 join 都照顾不到。只有一项时直接返回这一项，空数组返回空字符串。

还有一个 style 选项，可选 long、short、narrow。它改变的是连接词的写法，不是把列表截短。

每一项要渲染成链接怎么办

format() 返回的是一整句字符串，没法给某个名字单独加链接。这时要用 formatToParts()。

JSX
function UserList({ users, locale }) {
  const parts = new Intl.ListFormat(locale).formatToParts(users.map((u) => u.name));
  let index = 0;
  return parts.map((part, i) =>
    part.type === 'element' ? (
      <a key={i} href={`/users/${users[index++].id}`}>
        {part.value}
      </a>
    ) : (
      <span key={i}>{part.value}</span>
    ),
  );
}

formatToParts() 返回一个数组，type 是 element 的是列表项，其余是连接词和标点。

怎样知道某个 element 对应哪个用户？靠顺序。element 一定按输入顺序出现，所以用计数器映射回用户 ID 就行。不要用名字去找，因为可能有重名。也不要把拼好的整句按逗号拆开，名字里本身就可能有逗号。

另外，ListFormat 不做 HTML 转义，结果要当普通文本渲染。

列表很长时怎么办

“Alice、Bob 和其他 3 人”这种文案，要单独设计一条带复数的翻译消息。不要拼一个英文的“3 more”塞进列表里，换了语言就不通了。

成员有几十个时，与其拼成一句话，不如用真正的列表元素，加上分页或折叠。

常见追问

测试时能直接比对输出字符串吗？

固定运行时版本时可以。跨环境时，CLDR 数据可能会调整标点和空格，直接比字符串容易误报。更稳妥的是检查每一项都在、顺序正确，并且 formatToParts 的各段拼起来等于 format 的结果。

它和 Array.prototype.toLocaleString() 有什么区别？

toLocaleString() 只是把每一项本地化后用逗号连起来，没有“和”“或”这样的连接词。要生成能读的句子，还是用 ListFormat。
