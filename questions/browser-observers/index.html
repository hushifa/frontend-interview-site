IntersectionObserver 适合做什么，能否证明用户看到了内容？

IntersectionObserver 异步通知元素与根区域的几何交叉，适合预加载和无限列表触发；几何相交不等于用户真正看到、停留或读懂了内容。

参考答案

它解决的是持续测量的成本

图片接近视口时提前加载、列表滚到底时请求下一页，都需要知道目标是否接近一个区域。传统做法是在 scroll 事件里遍历元素并同步调用 getBoundingClientRect()，元素多时容易增加布局计算和主线程压力。

IntersectionObserver 让浏览器观察目标与根区域的几何关系，异步把变化记录交给回调。它适合触发预加载、观察无限列表哨兵和做粗粒度可见性统计，但它不会持续报告每个像素，也不会判断用户是否真的阅读。

root、rootMargin 和 threshold 是三种不同控制

root 决定参考区域。默认 null 通常表示视口；内部滚动列表则应指定滚动容器。祖先的裁剪和 CSS 布局仍会影响最终交叉结果。

rootMargin 扩大或缩小用于判断的根边界。例如 200px 0px 会在目标还没真正进入屏幕时触发，适合提前下载图片，但不能把它当成曝光数据。

threshold 是交叉比例跨越的阈值，可以是一个值或数组。比例是交叉面积相对目标边界矩形面积，不是占整个屏幕的比例。目标比根大很多时，可能永远达不到 1；等待文章完整进入小视口并不合理。

调用 observe() 后通常会先收到当前状态的记录，包括元素在屏幕外的情况。回调必须检查 isIntersecting 和实际比例，不能因为回调执行就认为元素已经可见。边界刚好接触时 isIntersecting 也可能为 true，但交叉面积仍是 0。

用观察器触发一次预加载

JavaScript
function observeNearViewport(elements, onNear) {
  const targets = [...elements];
  if (!('IntersectionObserver' in globalThis)) {
    targets.forEach(onNear);
    return () => {};
  }

  const observer = new IntersectionObserver((entries) => {
    for (const entry of entries) {
      if (!entry.isIntersecting) continue;
      observer.unobserve(entry.target);
      onNear(entry.target);
    }
  }, { rootMargin: '200px 0px', threshold: 0 });

  targets.forEach((target) => observer.observe(target));
  return () => observer.disconnect();
}

“一次”来自主动 unobserve()，不是 threshold 自带单次语义。组件卸载时要断开观察器；断开不会取消已经启动的 fetch，也不会撤销已经加上的 class，网络任务仍要有自己的 AbortController。

普通图片优先考虑 <img loading="lazy">。只有需要提前距离、内部滚动容器或与业务状态协调时，才值得维护自定义观察器。

无限列表要处理重复触发和过期结果

末尾哨兵进入区域可以触发下一页请求，但请求未完成时它可能仍在区域内，不能依赖 observer 自动再次回调。应维护 loading、hasMore 和当前筛选条件，防止重复请求；筛选改变后，旧请求返回的数据不能追加到新列表。

如果追加数据后哨兵仍可见，应该由分页状态决定是否继续加载，并设置请求上限或让用户点击“加载更多”。失败时提供重试和错误状态，不要让列表无限空白等待。

几何可见不是有效曝光

一个元素可能被固定层遮挡、透明、处于后台标签页，或者只在屏幕边缘闪过。IntersectionObserver 默认也不知道用户是否真的看到了或理解了内容。若业务定义“面积至少 50%，前台停留 1 秒”，需要组合比例、页面可见性、持续计时和去重：

JavaScript
function qualifies(entry) {
  return document.visibilityState === 'visible'
    && entry.isIntersecting
    && entry.intersectionRatio >= 0.5;
}

进入后启动的计时在离开、切后台或组件销毁时必须取消；恢复页面后按业务规则重新计算。trackVisibility 等能力有额外支持和性能边界，不能当作“用户阅读证明”。

观察器回调仍在主线程执行。不要在其中同步解析大 JSON、批量改 DOM 或制造请求风暴。需要逐帧动画、像素级测量或精确滚动进度时，应使用更合适的机制，而不是把异步交叉通知当作滚动时钟。
