IntersectionObserver 适合做什么，能否证明用户看到了内容？

IntersectionObserver 在元素进入或离开视口时通知你，适合懒加载、无限滚动和曝光统计。它只算位置有没有重叠，不能证明元素没被挡住、用户真的看到了。

参考答案

简答

图片滚到快进入屏幕时再加载，列表滚到底部时自动加载下一页，这类需求都要知道“某个元素有没有进入视口”。IntersectionObserver 就是干这个的：元素和视口（或者指定的容器）重叠的比例跨过你设的阈值时，它会异步回调通知你。

以前的做法是监听 scroll，再调用 getBoundingClientRect() 算位置，这会在主线程上强制同步布局。IntersectionObserver 不会。

常见用途是图片懒加载、无限滚动的触底检测、广告曝光统计。

要注意，它只算几何上有没有重叠。元素被别的元素盖住、是透明的、或者页面在后台，它都可能报告为“相交”。所以它不能证明用户真的看到了。

三个参数分别管什么

root 是参照的容器，默认是视口。

rootMargin 用来扩大或缩小参照区域。比如写 '200px 0px'，元素离视口还有 200px 时就算进入了，适合提前加载。

threshold 是触发回调的重叠比例，可以写成数组，比如 [0, 0.5, 1]，每跨过一个值回调一次。

用它做图片懒加载

JavaScript
const observer = new IntersectionObserver(
  (entries) => {
    for (const entry of entries) {
      if (!entry.isIntersecting) continue;
      const img = entry.target;
      img.src = img.dataset.src;
      observer.unobserve(img);
    }
  },
  { rootMargin: '200px 0px' },
);

document.querySelectorAll('img[data-src]').forEach((img) => observer.observe(img));

真实地址先放在 data-src 里。图片进入视口前 200px 时，把它赋给 src 开始加载，然后 unobserve 停止观察，避免重复处理。

不过普通图片直接写原生的 loading="lazy" 就行。只有需要自己控制加载时机时，才值得用 IntersectionObserver。

曝光统计为什么不能只看“相交”

广告曝光常见的口径是“至少 50% 面积进入视口，并且持续 1 秒”。做法是设 threshold: 0.5，进入时开始计时，离开时取消；页面切到后台时（visibilitychange）暂停计时；同一个元素只上报一次。

可是即使这样，IntersectionObserver 也只知道位置重叠了。元素被弹窗盖住、opacity 是 0，它照样报告为相交。

如果要排除被遮挡的情况，IntersectionObserver v2 提供了 trackVisibility 和 isVisible。但它目前只有 Chromium 支持，计算成本也更高。

常见追问

IntersectionObserver 的回调什么时候触发？

调用 observe() 以后会立刻回调一次，报告元素当前的状态。之后只在重叠比例跨过阈值时才回调。

元素宽高为 0 时，intersectionRatio 是多少？

只要和参照区域相交，intersectionRatio 是 1，不相交是 0。所以判断有没有进入视口，应该看 isIntersecting，不要只看比例。
