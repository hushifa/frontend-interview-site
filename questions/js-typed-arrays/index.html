ArrayBuffer、TypedArray 和普通数组有什么区别？

ArrayBuffer 只是一段原始字节，自己不能读写；TypedArray 按固定的数字类型去读写这段字节，长度固定，写入的值会被强制转换。普通数组能放任何值，长度也能随意变。

参考答案

简答

ArrayBuffer 只是一块字节存储，它自己没有读写方法，要通过 TypedArray 或 DataView 这样的“视图”去读写。

TypedArray 有很多种，比如 Uint8Array、Float32Array，每种都按固定的数字类型解读字节。写进去的值会被转换成这个类型，比如往 Uint8Array 写 256 会变成 0，往 Uint8ClampedArray 写 256 会变成 255。它的长度固定，没有 push，Array.isArray 判断它也是 false。

多个视图可以指向同一块缓冲区。所以要分清 subarray 和 slice：前者返回共享同一块缓冲区的新视图，改它会影响原数据；后者复制出一份独立的数据。

普通的 ArrayBuffer 创建后长度固定。ES2024 起，可以用 new ArrayBuffer(len, { maxByteLength }) 创建能调整大小的缓冲区。

subarray 和 slice 有什么不同

JavaScript
const bytes = new Uint8Array([1, 2, 3]);
const shared = bytes.subarray(1);
const copied = bytes.slice(1);
shared[0] = 9;

console.log(bytes[1]); // 9
console.log(copied[0]); // 2
console.log(Array.isArray(bytes)); // false

改的是 shared[0]，可 bytes[1] 也变成了 9。

因为 subarray 没有复制数据，它只是在同一块缓冲区上开了一个新窗口，从第 1 个字节开始看。shared[0] 和 bytes[1] 其实是同一个字节。slice 则把数据复制了一份，copied 和原数据互不影响，所以还是 2。

这和普通数组的 slice 一样都是复制，名字相似的 subarray 却是共享，处理大块二进制数据时要特别留意。

写进去的值为什么变了

JavaScript
const u8 = new Uint8Array(1);
u8[0] = 256;
console.log(u8[0]); // 0，按 2^8 取模

const clamped = new Uint8ClampedArray(1);
clamped[0] = 256;
console.log(clamped[0]); // 255，钳制到范围内

const i8 = new Int8Array([200]);
console.log(i8[0]); // -56

Uint8Array 每个元素只有 8 位，范围是 0 到 255。写入 256 超出了范围，它不报错，而是按 256 取余数，得到 0。

Uint8ClampedArray 处理方式不同，超出范围的值会被压到边界上，256 变成 255。Canvas 的 ImageData 用的就是它，颜色值超过 255 就当 255，比绕回 0 合理得多。

Int8Array 是有符号的，范围是 -128 到 127。200 的二进制按有符号数解读，就成了 -56。

和普通数组比较

普通数组TypedArray
元素任意值固定数值类型
长度可变固定
push / pop有没有
越界写入扩展数组被忽略
用途通用文件、网络、WebGL、音视频、WASM

普通数组什么都能放，越界写入时会自动变长。TypedArray 越界写入会被直接忽略。它适合处理文件、网络数据、WebGL、音视频和 WebAssembly 这类本来就是字节的数据。

视图怎样从缓冲区中间开始

JavaScript
const buffer = new ArrayBuffer(8);
const all = new Uint8Array(buffer);
const tail = new Uint16Array(buffer, 4, 2); // 从第 4 字节开始，2 个元素
tail[0] = 0xffff;
console.log(all[4], all[5]); // 255 255

tail 从第 4 个字节开始，取 2 个 16 位元素。往 tail[0] 写 0xffff，用按字节看的 all 去读，第 4、5 两个字节都变成了 255，说明它们确实指向同一块内存。

起始位置有要求：byteOffset 必须是元素大小的整数倍，Uint16Array 的元素占 2 字节，就只能从偶数位置开始，否则抛 RangeError。另外多字节的类型按平台字节序读写，几乎都是小端，需要指定字节序时要用 DataView。

缓冲区能变大，也能转移

new ArrayBuffer(8, { maxByteLength: 64 }) 创建的缓冲区，之后可以调用 resize() 改变长度。创建 TypedArray 时不传长度，它的长度就会跟着缓冲区一起变。

buffer.transfer()（ES2024）会把内容移到一个新的缓冲区，原来的缓冲区就变成已分离状态，长度为 0，不能再用。给 Worker 发数据时，postMessage(data, [buffer]) 也是把缓冲区转移过去，省掉了复制大块数据的开销。

常见追问

怎样把 TypedArray 转成普通数组？

用 Array.from(view) 或者 [...view]。

SharedArrayBuffer 有什么使用前提？

页面需要开启跨源隔离，也就是同时设置 COOP 和 COEP 响应头。多个线程同时读写它时，要配合 Atomics 做同步。
