标准盒模型和 border-box 有什么区别？

content-box 把声明尺寸分配给内容区，border-box 把内边距和边框也计入声明尺寸；外边距始终在外面。最终尺寸仍需结合布局约束、最小尺寸与实际内容计算。

参考答案

一个元素写了 width: 300px，浏览器画出来却可能宽 342px。原因不一定是 width 没生效，而是声明的 300px 只分配给了内容区域，内边距和边框还需要额外占空间。

CSS 盒子从里到外可以分成内容区、padding、border、margin。box-sizing 决定 width、height 等尺寸约束主要针对哪一层盒子，并不会把这几层本身删除。

用同一组数值算两遍

HTML
<div class="box content">content-box</div>
<div class="box border">border-box</div>
CSS
.box {
  width: 300px;
  padding: 20px;
  border: 1px solid #64748b;
  margin: 10px;
}

.content {
  box-sizing: content-box;
}

.border {
  box-sizing: border-box;
}

先限定为普通布局、没有其他最小最大宽度或 Flex 收缩的情况：

项目content-boxborder-box
声明 width300px300px
内容区宽度300px258px
左右 padding 合计40px40px
左右 border 合计2px2px
border box 宽度342px300px
再计入左右 margin 后的水平占用362px320px

content-box 下，300 + 40 + 2 = 342；border-box 下，先从 300 中扣掉 40 和 2，剩余 258 给内容。两种模式都没有把 margin 放进 width。

所以 border-box 更容易表达“这个组件包含边框和留白后，总共宽 300px”。它并不是没有 padding，而是把 padding 算在同一份宽度预算中。

为什么 100% 加 padding 经常溢出

一个普通块盒子写 width: 100% 时，百分比通常根据包含块的宽度计算。假设父级内容区为 500px，在 content-box 下，子级再加左右各 20px padding，就会至少需要 540px，加边框后还会更宽。

改为 border-box 后，500px 包含了 padding 和 border，通常能解决这一类溢出。常见的全局约定是：

CSS
*,
*::before,
*::after {
  box-sizing: border-box;
}

伪元素也会生成盒子，所以一并设置可以减少装饰结构里的尺寸意外。box-sizing 的初始值是 content-box，不过浏览器默认样式可能已经为部分控件设置 border-box，不能假定所有元素最终计算值都与初始值相同。

普通非替换块在正常流中的 width: auto，本来就会结合 margin、padding、border 分配可用宽度。它和“明确写 100% 后再向外加 padding”不是同一个计算过程，因此并不是每个撑满父级的块都需要声明 width:100%。

border-box 为什么仍然可能比 width 大

内容区尺寸不能被减成负数。假设 width: 10px，左右 padding 已经共 40px，边框又共 2px，即使使用 border-box，浏览器也不能把内容区算成 -32px。内容区会以 0 为下限，最终盒子仍需要容纳这些内边距和边框。

此外，width 不总是最终使用宽度的唯一来源：

  • min-width、max-width 可以限制结果。
  • Flex 项可能增长、收缩，且自动最小尺寸受内容影响。
  • Grid 轨道分配和项目对齐会改变可用空间。
  • 长文本、不换行内容和图片可能超出内容区，形成溢出，即便盒子自身宽度没变。

因此“border-box 下最终一定等于 CSS 文件里的 width”仍然是过度概括。应区分盒子的布局尺寸变大，还是内容在固定盒子里面溢出。

两列、间隙和测量还要另算

两个 border-box 元素各写 width:50%，已经分完父级宽度；如果中间再加 gap 或外边距，仍然可能超出。border-box 不会自动从每个 50% 中扣除额外间隙。Grid 的 fr、Flex 的空间分配或明确的 calc 才负责这一层安排。

调试时看 DevTools 的盒模型和计算样式，而不只看规则中的 width。getBoundingClientRect().width 通常反映变换后的 border box 几何范围，包含 padding、border，但不包含 margin；如果有 scale 或 rotate，它也不能直接当成未变换时的内容宽度。

布局计算、绘制变换与滚动条也会影响不同 DOM 测量接口的结果。先说清自己要测哪一层盒子，再选择接口，才能避免把正常的盒模型差异误判成浏览器计算错误。
