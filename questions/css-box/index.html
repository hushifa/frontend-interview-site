标准盒模型和 border-box 有什么区别？

默认的 content-box 里，width 只管内容区，加上内边距和边框后盒子会变宽；border-box 里 width 就是盒子的宽度。两种模式都不算外边距。

参考答案

简答

每个元素都是一个盒子，从里到外是内容区、内边距、边框和外边距。两种盒模型的区别在于，width 到底量的是哪一部分。

默认的 content-box 叫标准盒模型，width 只是内容区的宽度。写了 width: 200px 再加内边距和边框，盒子实际会比 200px 宽。border-box 里，width 包含了内边距和边框，盒子就是 200px，内容区自己变窄。

外边距在两种模式下都不算在 width 里。

项目里通常全局设成 border-box，这样写多少就是多少，算布局时不用再加加减减。

同样的样式，两种模式差多少

CSS
.box {
  width: 200px;
  padding: 20px;
  border: 5px solid;
}

在 content-box 下，内容区是 200px。左右内边距一共 40px，左右边框一共 10px，所以盒子总宽是 200 + 40 + 10 = 250px。

在 border-box 下，盒子总宽就是 200px。内边距和边框从里面扣，内容区剩下 200 − 40 − 10 = 150px。

那内边距和边框加起来比 width 还大呢？border-box 下内容区宽度变成 0，不会是负数，盒子会被撑到内边距加边框的宽度。

为什么项目里都全局设 border-box

CSS
*,
*::before,
*::after {
  box-sizing: border-box;
}

想象一个两栏布局，每栏 width: 50%，再各加 padding: 16px。在 content-box 下，每栏都比 50% 宽，两栏加起来超出父元素，第二栏就掉到下一行去了。用 border-box，内边距算在 50% 里面，两栏刚好放下。

写了 width，为什么最终尺寸还是不对

min-width、max-width 也按 box-sizing 来解释，和 width 一样。

flex 和 grid 的项目尺寸会被容器重新分配，width 只是一个参考值，最后多宽要看容器怎么分。

内容过长也会撑开盒子，比如一个很长的网址。这时可以加 min-width: 0 或者 overflow-wrap: anywhere。

还有行内元素，比如 <span>，设置 width 和 height 都不生效。要先改成 inline-block 或块级元素。

常见追问

怪异模式下的盒模型是什么样的？

页面缺少 DOCTYPE 时，浏览器会进入怪异模式，兼容很老的页面写法。这时部分元素会按类似 border-box 的方式计算宽度。所以现代页面开头都要写 <!DOCTYPE html>，避免进入怪异模式。
