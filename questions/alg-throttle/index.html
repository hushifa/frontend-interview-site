怎样实现首沿节流？它与尾沿节流、防抖有什么区别？

节流限制函数在每个时间窗口内最多执行一次。首沿节流在窗口开始时立即执行并丢弃窗口内的其他调用；尾沿节流在窗口结束时用最后一次调用的参数执行；防抖则要等调用停止一段时间后才执行。节流限制的是开始执行的频率，不等待异步操作完成。

参考答案

简答

  • 首沿节流：第一次调用立即执行并开启一个 wait 毫秒的窗口，窗口内的调用直接丢弃，窗口结束后下一次调用再次立即执行。
  • 尾沿节流：第一次调用开启窗口但不执行，窗口内持续记录最新的参数，窗口结束时执行一次，结束时间不会因新调用而推后。
  • 防抖每次调用都重新计时，持续调用期间一直不执行；节流在持续调用期间也会按固定节奏执行。
  • 首沿节流要在调用 fn 之前设置 blocked，这样 fn 内部再次调用或同步抛错时，窗口仍然生效。
  • 节流只控制开始执行的频率。fn 返回的 Promise 还没完成时，下一个窗口照样会再次调用它；需要限制同时进行的数量，要用并发控制。

三种策略的对比

策略执行典型场景
首沿节流0 毫秒执行 A，B、C 被丢弃按钮防连点、立即响应的快捷键
尾沿节流100 毫秒执行 C滚动时更新位置，需要拿到最新值
尾沿防抖160 毫秒执行 C搜索框输入停止后再请求

Lodash 的 throttle 默认同时启用首沿和尾沿，只调用一次时只在首沿执行。用库之前要看清它的选项。

首沿节流实现

JavaScript
function throttle(fn, wait) {
  if (typeof fn !== 'function') throw new TypeError('需要传入函数');
  if (!Number.isInteger(wait) || wait < 0 || wait > 2_147_483_647) {
    throw new RangeError('等待时间必须是计时器范围内的非负整数毫秒');
  }

  let blocked = false;
  let timer;

  function wrapped(...args) {
    if (blocked) return;

    blocked = true;
    timer = setTimeout(() => {
      blocked = false;
      timer = undefined;
    }, wait);

    return fn.apply(this, args);
  }

  wrapped.cancel = () => {
    clearTimeout(timer);
    blocked = false;
    timer = undefined;
  };

  return wrapped;
}
  • timer 只用于 cancel 时清除窗口；窗口期间的状态由 blocked 判断。
  • 窗口内被丢弃的调用返回 undefined，只有真正执行的那次返回 fn 的结果。
  • cancel 立即结束当前窗口，之后的调用会马上执行。

尾沿节流实现

JavaScript
function throttleTrailing(fn, wait) {
  let timer;
  let lastArgs;
  let lastThis;

  function wrapped(...args) {
    lastArgs = args;
    lastThis = this;
    // 窗口已经开启时只更新参数，不推迟结束时间。
    if (timer !== undefined) return;
    timer = setTimeout(() => {
      const callThis = lastThis;
      const callArgs = lastArgs;
      timer = lastArgs = lastThis = undefined;
      fn.apply(callThis, callArgs);
    }, wait);
  }

  wrapped.cancel = () => {
    clearTimeout(timer);
    timer = lastArgs = lastThis = undefined;
  };

  return wrapped;
}

每 25 毫秒调用一次、共调用 10 次，等待 100 毫秒，本机实测执行了 3 次，分别拿到第 4、8、10 次调用的参数：每个窗口从它的第一次调用开始计时，结束时使用窗口内最新的参数。如果每次调用都 clearTimeout 再重新计时，就变成了防抖，持续调用期间一次都不会执行。

和 requestAnimationFrame 的关系

滚动、拖拽这类和画面更新相关的事件，可以用 requestAnimationFrame 合并：同一帧内只处理最后一次事件，执行频率自动和屏幕刷新率一致，页面在后台时还会暂停。这比固定毫秒数的节流更贴合渲染节奏。

常见追问

  • 节流函数里的 this 怎样保持？ wrapped 用普通函数定义，调用时用 fn.apply(this, args) 转发；箭头函数没有自己的 this，不能用来定义 wrapped。
  • 为什么等待时间要校验范围？ 浏览器和 Node.js 的计时器把超过 2147483647 毫秒的延迟当作 1 毫秒处理，非整数或负数也会产生不直观的行为，所以实现在创建计时器之前拒绝这些值。
  • 防抖怎样实现？ 见《怎样实现只在停止调用后执行的防抖函数？》。
