BroadcastChannel 适合解决什么跨标签通信问题？

BroadcastChannel 让同源的标签页、iframe 和 Worker 通过同名频道广播消息，适合同步登录状态、主题和缓存失效；它不保证送达，没有历史消息，也不提供互斥。

参考答案

简答

  • 同源的上下文用相同名称创建 BroadcastChannel，一方 postMessage，其他所有方收到 message 事件，发送方自己收不到。
  • 消息用结构化克隆传递，可以发送对象。
  • 适合广播"已退出登录""主题已切换""某条数据已更新"这类通知。
  • 消息只发给当前打开的上下文，后打开的页面收不到之前的消息；需要互斥时用 Web Locks。

示例：同步退出登录

JavaScript
const channel = new BroadcastChannel('auth');

channel.addEventListener('message', (event) => {
  if (event.data.type === 'logout') {
    clearLocalSession();
    location.assign('/login');
  }
});

function logout() {
  clearLocalSession();
  channel.postMessage({ type: 'logout' });
  location.assign('/login');
}

页面卸载或组件销毁时调用 channel.close()。

和其他方案对比

方案特点
BroadcastChannel一对多广播，API 最简单
storage 事件只能借 localStorage 写入触发，数据要序列化成字符串
SharedWorker有一个共享的中心，可以保存状态、做协调
Service Worker clients能找到所有受控页面，也能处理推送
postMessage需要拿到目标窗口引用，可以跨源

注意事项

  • 只在同源之间工作。不同子域之间需要用 postMessage 或服务端转发。
  • 新打开的页面要自己读取当前状态，例如从 localStorage 或服务端获取，不能依赖广播。
  • 多个标签页同时收到消息后都去刷新数据，可能造成请求风暴，可以只让一个标签页刷新再广播结果。
