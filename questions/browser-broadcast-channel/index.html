BroadcastChannel 的消息怎样发送和接收，有哪些限制？

同一存储分区内的同源页面和 Worker 用同一个名字建频道，postMessage 用结构化克隆把消息发给其他所有订阅者，发送方自己收不到。函数这类不能克隆的数据会抛 DataCloneError，关闭后再发会抛 InvalidStateError，收到无法反序列化的消息会触发 messageerror。它不存历史消息，也没有互斥能力。

参考答案

简答

用户在一个标签页点了退出登录，其他标签页也要跳到登录页。BroadcastChannel 的用法是：每个页面用同一个名字 new BroadcastChannel('auth')，第一个用这个名字的页面会创建底层频道，后面的加入进来；一方 postMessage，其他所有订阅者收到 message 事件，发送方自己收不到。

消息用结构化克隆传过去，可以直接发对象，不用自己 JSON.stringify。可是函数、DOM 节点这类不能克隆的数据会让 postMessage 抛出 DataCloneError；频道 close() 之后再发会抛出 InvalidStateError；接收方收到无法反序列化的消息，会触发 messageerror 而不是 message。

它的范围比“同源”还窄一点：MDN 说明实际是按存储分区隔离，嵌在别的站点里的同源 iframe 和顶层打开的同源页面互相收不到。

要注意它只是广播。消息只发给当时开着的页面，不存历史；也没有互斥能力，“只让一个标签页去做”要用 Web Locks。

频道怎样建立和关闭

JavaScript
const channel = new BroadcastChannel('auth');

channel.addEventListener('message', (event) => {
  if (event.data.type === 'logout') {
    clearLocalSession();
    location.assign('/login');
  }
});

function logout() {
  clearLocalSession();
  channel.postMessage({ type: 'logout' });
  location.assign('/login');
}

为什么 logout 里要自己跳转，不等消息？因为发送方自己收不到自己发的消息。MDN 还提到，你不需要保存其他页面或 Worker 的引用，它们只要用同一个名字创建自己的对象就算订阅了。

API 本身不规定消息格式，所以要自己约定字段，比如上面的 type。页面卸载或组件销毁时调用 channel.close()，它会断开和底层频道的连接，对象才能被垃圾回收。

哪些消息发不出去

结构化克隆能处理对象、数组、Map、Date 这些，但处理不了函数。下面在 Node 里试两种出错的情况：

JavaScript
const channel = new BroadcastChannel('auth');

try {
  channel.postMessage({ onLogout() {} });
} catch (error) {
  console.log(error.name); // DataCloneError
}

channel.close();
try {
  channel.postMessage({ type: 'logout' });
} catch (error) {
  console.log(error.name); // InvalidStateError
}

第一次失败是因为消息里有一个方法，函数不能克隆，所以抛出 DataCloneError，消息一个字也没发出去。第二次是频道已经关了，按 MDN 的说明会抛出 InvalidStateError。所以消息只放纯数据，关闭后的对象不要再用。

还有一种错误发生在接收方。比如发送 SharedArrayBuffer，而收发双方不在同一个 agent cluster 里，不能共享内存，接收方就会收到 messageerror 事件。需要的话单独监听它，否则这种消息会被悄悄丢掉。

后打开的页面怎么办

广播是“发出去就完了”，消息不会存下来。用户退出登录之后再新开一个标签页，这个页面什么都收不到。所以新页面要自己去读当前状态，比如从 localStorage 或服务端获取，不能指望广播。

另一个坑是请求风暴。比如广播“数据更新了”，十个标签页同时收到，同时去请求接口。更好的做法是只让一个标签页去刷新，再把结果广播出去。

BroadcastChannel 和 storage 事件、SharedWorker、Service Worker、窗口 postMessage 怎样选，见《浏览器多个标签页之间怎样通信？》。

常见追问

BroadcastChannel 能保证每个页面都收到消息吗？

不能。它只发给当时开着的页面，不存历史消息。后打开的页面要自己从 localStorage 或服务端读取当前状态。

多个标签页抢着做同一件事，能用 BroadcastChannel 协调吗？

不适合。它没有互斥能力，大家都能同时收到消息。要保证只有一个标签页去做，比如刷新令牌，用 Web Locks。

两个子域能用 BroadcastChannel 通信吗？

不能。频道名只在同源（准确地说是同一存储分区）的页面之间共享，a.example.com 和 b.example.com 不同源。要跨源，只能用窗口引用加 postMessage，或经服务端转发。
