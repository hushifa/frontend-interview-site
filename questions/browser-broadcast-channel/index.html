BroadcastChannel 适合解决什么跨标签通信问题？

同源的几个标签页用同一个名字建频道，一个发消息，其他都能收到，适合同步退出登录、切换主题。它不保证送达，也不存历史消息。

参考答案

简答

用户开了三个标签页，在其中一个点了退出登录，另外两个也应该马上跳到登录页。BroadcastChannel 就是干这个的：同源的标签页、iframe、Worker 用同一个名字创建频道，一方 postMessage，其他所有方都会收到 message 事件。

它用起来很简单，消息走结构化克隆，可以直接发对象。发送方自己收不到自己发的消息。

适合广播“已退出登录”“主题切换了”“某条数据更新了”这类通知。

要注意它只是广播。消息只发给当时开着的页面，后打开的页面收不到之前的消息；它也不管谁先谁后，需要“只让一个标签页去做”时要用 Web Locks。

先看一个同步退出登录的例子

JavaScript
const channel = new BroadcastChannel('auth');

channel.addEventListener('message', (event) => {
  if (event.data.type === 'logout') {
    clearLocalSession();
    location.assign('/login');
  }
});

function logout() {
  clearLocalSession();
  channel.postMessage({ type: 'logout' });
  location.assign('/login');
}

当前页面调用 logout()，自己先清掉会话，再往 auth 频道里发一条消息。其他标签页收到后，也清会话、跳登录页。

为什么 logout 里要自己跳转，不等消息？因为发送方自己收不到自己发的消息。下面这段在 Node 里同一个频道名建了两个对象，a 发消息，只有 b 收到：

JavaScript
const a = new BroadcastChannel('auth');
const b = new BroadcastChannel('auth');
a.onmessage = (e) => console.log('a 收到', e.data);
b.onmessage = (e) => { console.log('b 收到', e.data); a.close(); b.close(); };
a.postMessage({ type: 'logout' });
// b 收到 { type: 'logout' }

页面卸载或组件销毁时，记得调用 channel.close()。

后打开的页面怎么办

广播是“发出去就完了”，消息不会存下来。用户退出登录之后再新开一个标签页，这个页面什么都收不到。所以新页面要自己去读当前状态，比如从 localStorage 或服务端获取，不能指望广播。

另一个坑是请求风暴。比如广播“数据更新了”，十个标签页同时收到，同时去请求接口。更好的做法是只让一个标签页去刷新，再把结果广播出去。

它也只在同源之间工作。不同子域之间要通信，得用 postMessage 或者服务端转发。

和其他通信方案怎么选

方案特点
BroadcastChannel一对多广播，API 最简单
storage 事件只能借 localStorage 写入触发，数据要序列化成字符串
SharedWorker有一个共享的中心，可以保存状态、做协调
Service Worker clients能找到所有受控页面，也能处理推送
postMessage需要拿到目标窗口引用，可以跨源

只是发个通知，BroadcastChannel 最省事。需要一个地方保存共享状态，用 SharedWorker。要跨源，就只能用窗口的 postMessage。

常见追问

BroadcastChannel 能保证每个页面都收到消息吗？

不能。它只发给当时开着的页面，不存历史消息。后打开的页面要自己从 localStorage 或服务端读取当前状态。

多个标签页抢着做同一件事，能用 BroadcastChannel 协调吗？

不适合。它没有互斥能力，大家都能同时收到消息。要保证只有一个标签页去做，比如刷新令牌，用 Web Locks。
