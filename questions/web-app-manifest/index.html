Web App Manifest 主要描述哪些 PWA 信息？

Manifest 是一个 JSON 文件，写着应用的名字、图标、启动地址、显示方式和主题色，浏览器据此提供"安装到桌面"的体验。离线能力靠 Service Worker，不归它管。

参考答案

简答

把网站装到手机桌面上，图标是什么、名字叫什么、打开时有没有地址栏，这些都写在 Web App Manifest 里。它是一个 JSON 文件，用 <link rel="manifest" href="/manifest.webmanifest"> 引入。

常用字段有 name、short_name、icons、start_url、scope、display、theme_color、background_color 和 id。比如 display: standalone 让应用在独立窗口里运行，没有浏览器地址栏。

图标一般提供 192×192 和 512×512 两种，这是 Chromium 安装条件的要求。purpose: "maskable" 的图标允许系统裁成圆形、圆角方形等各种形状。

要注意 manifest 只描述“怎么安装、怎么启动”。离线访问、推送这些能力要靠 Service Worker。另外最好显式写 id，不然改了 start_url，浏览器会当成另一个应用。

一个完整的 manifest

下面是题库网站的 manifest：

json
{
  "id": "/",
  "name": "前端面试题库",
  "short_name": "题库",
  "start_url": "/?source=pwa",
  "scope": "/",
  "display": "standalone",
  "theme_color": "#1f6feb",
  "background_color": "#ffffff",
  "icons": [
    { "src": "/icons/192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icons/512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/icons/maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}

name 是完整名称，short_name 用在桌面图标下面这种空间小的地方。start_url 带了 ?source=pwa，这样服务端就能统计有多少次是从桌面图标启动的。

为什么要显式写 id

id 是应用的唯一标识。不写的话，浏览器会用 start_url 来算。问题是，以后你改了 start_url，比如换了统计参数，浏览器算出来的 id 也变了，就会把它当成另一个应用。所以建议显式写 id，并且一直不改。

其他字段是做什么的

scope 是应用的导航范围，点到范围外的链接，会在浏览器里打开，而不是在应用窗口里。display 可以选 fullscreen、standalone、minimal-ui、browser，想按优先级列出更多模式，用 display_override。shortcuts 是长按图标时出现的快捷入口。

关于图标尺寸，规范本身没有规定，192×192 和 512×512 是 Chromium 安装条件的要求。maskable 图标的意思是四周留了安全区，系统怎么裁都不会裁到主体；普通图标如果被裁成圆形，就会缺边。

各平台有什么不同

Chromium 浏览器在满足安装条件后会显示安装入口，并触发 beforeinstallprompt 事件，页面可以借此做一个自己的“安装”按钮。

iOS Safari 不支持 beforeinstallprompt，用户只能通过分享菜单里的“添加到主屏幕”安装。iOS 还会读取 <meta name="apple-mobile-web-app-title"> 这类专用标签和 apple-touch-icon 图标。

常见追问

修改 manifest 后，已安装的应用会更新吗？

浏览器会定期检查。什么时候更新、更新哪些字段，由浏览器决定，名称和图标的变化可能还要用户确认。

有了 manifest 就能离线使用吗？

不能。manifest 只描述安装和启动方式，离线访问要靠 Service Worker 缓存资源。
