React 18 项目升级到 React 19，怎样分步迁移并验证行为？

先升级到 React 18.3 处理弃用警告，再升级到 19 并运行官方 codemod。主要破坏性变更包括移除 ReactDOM.render、所有组件的 propTypes 检查、函数组件的 defaultProps、string ref、legacy context；ref 可以直接作为 prop。使用 Server Components 时要升级到修复了 CVE-2025-55182 的补丁版本。

参考答案

简答

  • 先升级到 React 18.3：它和 18.2 行为相同，但会对 19 中移除的 API 给出警告，便于提前修复。
  • 再升级 react、react-dom 以及 @types/react、@types/react-dom 到 19，运行官方 codemod 处理机械性改动。
  • 主要移除项：ReactDOM.render / hydrate、所有组件的 propTypes 检查、函数组件的 defaultProps、string ref、legacy context（contextTypes）、react-dom/test-utils。
  • 新能力：ref 可以作为普通 prop 传给函数组件，forwardRef 不再必需；<Context value> 可以直接作为 Provider；ref 回调可以返回清理函数。
  • 使用 Server Components 的项目，react-server-dom-* 要升级到已修复 CVE-2025-55182 的最新补丁版本；纯客户端应用不受这个漏洞影响。

分步流程

  1. 升级到 react@18.3，在开发环境运行并修复所有弃用警告。

  2. 检查依赖：组件库、表单库、路由库、测试库是否已声明支持 React 19。

  3. 升级到 19，运行 codemod：

    bash
    npx codemod@latest react/19/migration-recipe
npx types-react-codemod@latest preset-19 ./src

  4. 运行单元测试、端到端测试，检查 SSR 页面的 hydration 警告。

  5. 手动检查关键交互：表单提交、弹窗、焦点管理。

常见改动

JSX
// 旧
ReactDOM.render(<App />, container);
// 新
import { createRoot } from 'react-dom/client';
createRoot(container).render(<App />);
JSX
// 旧：函数组件 defaultProps 在 19 中失效
function Button({ size }) {}
Button.defaultProps = { size: 'md' };
// 新：使用参数默认值
function Button({ size = 'md' }) {}
JSX
// 旧
const Input = forwardRef((props, ref) => <input ref={ref} {...props} />);
// 新
function Input({ ref, ...props }) {
  return <input ref={ref} {...props} />;
}
JavaScript
// 旧
import { act } from 'react-dom/test-utils';
// 新
import { act } from 'react';

容易忽略的变化

  • ref 回调写成箭头函数隐式返回时，返回值会被当作清理函数。ref={(el) => (this.el = el)} 在 TypeScript 中会报错，改成带花括号的函数体。
  • useRef 在 TypeScript 中必须传入初始值，useRef<T>() 改为 useRef<T>(null)。
  • 渲染期间的错误不再重复抛出，而是通过 createRoot 的 onUncaughtError、onCaughtError 上报，错误监控代码可能需要调整。
  • canary 时期的 useFormState 改名为 useActionState。
  • JSX 中的 element.ref 访问已弃用，改为 element.props.ref。

安全补丁

2025 年 12 月披露的 CVE-2025-55182 影响 react-server-dom-webpack、react-server-dom-parcel、react-server-dom-turbopack 的 19.0.0、19.1.0、19.1.1、19.2.0，可导致未授权远程代码执行，首批修复版本是 19.0.1、19.1.2、19.2.1。之后还有相关的后续公告，官方建议升级到这些包的最新版本。使用 Next.js 等框架时，按框架的安全公告升级。

常见追问

  • 不升级 Server Components 能用 19 吗？可以，客户端应用只升级 react 和 react-dom 即可。
  • 升级后可以马上用 React Compiler 吗？可以单独评估，它也支持 React 17、18，见《React Compiler 解决了哪些优化问题？》。
