React 18 项目升级到 React 19，怎样分步迁移并验证行为？

先升级到 React 18.3 把弃用警告处理掉，再升级到 19 并运行官方 codemod。主要破坏性变更包括移除 ReactDOM.render、所有组件的 propTypes 检查、函数组件的 defaultProps、string ref、legacy context；ref 可以直接作为 prop。使用 Server Components 时要升级到修复了 CVE-2025-55182 的补丁版本。

参考答案

简答

我会分两步升。第一步先升到 React 18.3，它的行为和 18.2 一样，只是对 19 里要删掉的 API 多给了警告。把这些警告修完，再升 19 就不会一下子冒出一堆问题。

第二步把 react、react-dom 和对应的 @types 包升到 19，跑官方 codemod，机械性的改动交给工具。19 里删掉的主要有：ReactDOM.render 和 hydrate、所有组件的 propTypes 检查、函数组件的 defaultProps、string ref、legacy context，还有 react-dom/test-utils。

也有新东西可以用：ref 能直接当普通 prop 传给函数组件，forwardRef 不再必需；<Context value> 可以直接当 Provider；ref 回调可以返回清理函数。

还有一件不能漏的事：如果项目用了 Server Components，react-server-dom-* 要升到修复了 CVE-2025-55182 的最新补丁版本。纯客户端应用不受这个漏洞影响。

分几步走

升级的顺序是这样的：

  1. 升级到 react@18.3，在开发环境运行，修掉所有弃用警告。

  2. 检查依赖：组件库、表单库、路由库、测试库有没有声明支持 React 19。

  3. 升级到 19，运行 codemod：

    bash
    npx codemod@latest react/19/migration-recipe
npx types-react-codemod@latest preset-19 ./src

  4. 跑单元测试和端到端测试，检查 SSR 页面有没有 hydration 警告。

  5. 手动过一遍关键交互：表单提交、弹窗、焦点管理。

之所以先查依赖，是因为自己的代码可以改，第三方库不支持 19 的话只能等它升级，这一步决定了能不能升。

代码里常见的几处改动

最先碰到的通常是入口。ReactDOM.render 已经删掉了，要换成 createRoot：

JSX
// 旧
ReactDOM.render(<App />, container);
// 新
import { createRoot } from 'react-dom/client';
createRoot(container).render(<App />);

函数组件的 defaultProps 在 19 里不再生效，代码不会报错，只是默认值没了，所以容易漏。改成参数默认值：

JSX
// 旧：函数组件 defaultProps 在 19 中失效
function Button({ size }) {}
Button.defaultProps = { size: 'md' };
// 新：使用参数默认值
function Button({ size = 'md' }) {}

ref 现在可以直接作为 prop 收到，forwardRef 可以去掉：

JSX
// 旧
const Input = forwardRef((props, ref) => <input ref={ref} {...props} />);
// 新
function Input({ ref, ...props }) {
  return <input ref={ref} {...props} />;
}

测试里的 act 改从 react 导入：

JavaScript
// 旧
import { act } from 'react-dom/test-utils';
// 新
import { act } from 'react';

哪些变化容易被忽略

有一个坑跟 ref 回调有关。19 允许 ref 回调返回一个清理函数，所以箭头函数隐式返回的值会被当成清理函数。像 ref={(el) => (this.el = el)} 这种写法，返回的是赋值结果，TypeScript 会报错，要改成带花括号的函数体。

TypeScript 里 useRef 现在必须传初始值，useRef<T>() 要改成 useRef<T>(null)。

错误处理也变了。渲染时出的错不再重复抛出，而是通过 createRoot 的 onUncaughtError、onCaughtError 上报。如果错误监控是靠捕获重复抛出的错误来工作的，就要跟着调整。

另外还有两处改名或弃用：canary 时期的 useFormState 改名为 useActionState；在 JSX 元素上访问 element.ref 已经弃用，改成 element.props.ref。

安全补丁为什么要单独查

2025 年 12 月披露的 CVE-2025-55182 影响 react-server-dom-webpack、react-server-dom-parcel、react-server-dom-turbopack 的 19.0.0、19.1.0、19.1.1、19.2.0，可以导致未授权远程代码执行。首批修复版本是 19.0.1、19.1.2、19.2.1，之后还有相关的后续公告，官方建议升到这些包的最新版本。

这些包负责 Server Components 的传输，所以只有用了 Server Components 才受影响。用 Next.js 等框架时，按框架自己的安全公告升级。

常见追问

不用 Server Components，能升 19 吗？

可以。纯客户端应用只升级 react 和 react-dom 就行，react-server-dom-* 那些包跟它没关系。

升级后可以马上用 React Compiler 吗？

可以单独评估，它不绑定 19，也支持 React 17 和 18，详见《React Compiler 解决了哪些优化问题？》。
