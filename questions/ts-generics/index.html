泛型解决了什么问题？如何约束泛型？

泛型用类型参数把输入、输出和多个参数之间的类型关系保留下来，调用时通常由编译器推断。extends 约束类型参数至少要具备的结构，K extends keyof T 配合 T[K] 可以安全读取属性。类型参数可以有默认值；const 类型参数（5.0）保留字面量，NoInfer（5.4）阻止某个位置参与推断。

参考答案

简答

  • 泛型让类型在调用时确定，保留"输入什么类型就返回什么类型"这类关系；用 any 会丢掉这种关系。
  • T extends { length: number } 约束 T 必须有 length，函数内部可以使用它；满足约束的新对象不一定是调用方选择的 T。
  • K extends keyof T 让 key 只能是 T 的键，返回 T[K] 精确对应该键的属性类型。
  • 能推断时不必手写类型实参；只出现一次的类型参数通常没有意义。
  • <T = string> 设置默认值；<const T> 保留字面量类型；NoInfer<T> 让某个参数只做检查、不参与推断。

保留关系

TypeScript
function identity<T>(value: T): T {
  return value;
}
const result = identity(['HTML', 'CSS']); // string[]

约束

TypeScript
function longer<T extends { length: number }>(first: T, second: T): T {
  return first.length >= second.length ? first : second;
}
longer('HTML', 'TypeScript'); // string
longer([1], [1, 2]);          // number[]
TypeScript
function ensureLength<T extends { length: number }>(value: T, minimum: number): T {
  if (value.length >= minimum) return value;
  // @ts-expect-error 仅有 length 的对象不一定是调用方选择的 T
  return { length: minimum };
}

调用方可能把 T 定为 string，{ length: 5 } 不是字符串。

keyof 与索引访问

TypeScript
function getProperty<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}
const user = { name: 'Lin', age: 24 };
const age = getProperty(user, 'age'); // number
// @ts-expect-error missing 不是 user 的键
getProperty(user, 'missing');

默认值、const 与 NoInfer

TypeScript
type ApiResponse<T = unknown> = { data: T; status: number };
const raw: ApiResponse = { data: null, status: 200 }; // T 为 unknown

function routes<const T extends readonly string[]>(paths: T): T {
  return paths;
}
const r = routes(['/a', '/b']); // readonly ['/a', '/b']

function createState<T extends string>(states: T[], initial: NoInfer<T>) {
  return initial;
}
// @ts-expect-error 'c' 不在 states 推断出的 'a' | 'b' 中
createState(['a', 'b'], 'c');

没有 NoInfer 时，'c' 也会参与推断，T 变成 'a' | 'b' | 'c'，错误被隐藏。

边界

  • 泛型不做运行时检查。fetchJson<User>(url) 内部若只是 as T，类型参数只是调用方的期望；应该接收一个解析函数 (input: unknown) => T。
  • 读取数组首项应返回 T | undefined。
  • 一个类型参数只出现一次（如 <T>(x: T): void）时，直接写 unknown 更清楚。

常见追问

  • 泛型约束和函数重载怎么选？输入输出有统一的关系用泛型；几种离散的调用形式各自返回不同类型用重载，见《函数重载、联合参数与泛型怎样选择？函数类型何时可赋值？》。
  • 为什么 TSX 里写 <T>(x: T) => x 报错？会被当成 JSX 标签，写成 <T,> 或 <T extends unknown>。
