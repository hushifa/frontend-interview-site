AbortController 能取消什么，不能取消什么？

AbortController 通过 signal 通知接收方取消，fetch、addEventListener 和支持 signal 的 API 会响应；它不能中断正在执行的同步代码，也不能撤销服务端已经执行的操作。

参考答案

简答

  • controller.abort(reason) 让 controller.signal 变为已取消并触发 abort 事件，监听这个 signal 的 API 自行停止。
  • fetch 被取消后 Promise 以 AbortError（或传入的 reason）reject；addEventListener 传入 signal 后，取消时监听器被移除。
  • 它不能打断正在运行的同步循环，也不会让服务端撤销已经开始执行的写操作。
  • AbortSignal.timeout(ms) 创建超时自动取消的 signal，AbortSignal.any([...]) 合并多个 signal。

取消过期的搜索请求

JavaScript
let controller;

async function search(keyword) {
  controller?.abort();
  controller = new AbortController();

  try {
    const response = await fetch(`/api/search?q=${encodeURIComponent(keyword)}`, {
      signal: AbortSignal.any([controller.signal, AbortSignal.timeout(5000)]),
    });
    return await response.json();
  } catch (error) {
    if (error.name === 'AbortError') return null;
    throw error;
  }
}

超时触发时错误名是 TimeoutError，用户主动取消是 AbortError，可以分开处理。

让自己的函数支持取消

JavaScript
function wait(ms, { signal } = {}) {
  return new Promise((resolve, reject) => {
    signal?.throwIfAborted();
    const onAbort = () => {
      clearTimeout(timer);
      reject(signal.reason);
    };
    // 正常结束时移除监听，复用同一个 signal 时不会累积
    const timer = setTimeout(() => {
      signal?.removeEventListener('abort', onAbort);
      resolve();
    }, ms);
    signal?.addEventListener('abort', onAbort, { once: true });
  });
}

长时间的同步计算要在循环中主动检查 signal.aborted 或调用 signal.throwIfAborted()。

不能取消的情况

  • 请求已经到达服务端：取消只是浏览器不再等待响应。下单、支付等写操作需要用幂等键防止重试导致重复执行。
  • 已经开始的同步代码。
  • 不接受 signal 的第三方 API。

常见追问

  • 一个 controller 能重复使用吗：不能，取消后 signal 永久处于已取消状态，每次新操作要新建一个。
  • React 中的用法：在 useEffect 中创建 controller，清理函数里调用 abort()。
