怎样手写深拷贝？和 structuredClone 有什么区别？

深拷贝就是把对象里每一层都复制一份，改副本不影响原对象。手写时递归复制，用 WeakMap 记下复制过的对象来处理循环引用，Date、RegExp、Map、Set 单独处理，用 Reflect.ownKeys 才能拷到 Symbol 键。structuredClone 原生支持循环引用和大多数内置类型，但会丢掉 Symbol 键和原型，碰到函数会报 DataCloneError。

参考答案

简答

深拷贝就是把对象里每一层都复制一份，改副本不会影响原对象。手写的思路是递归：原始值和函数直接返回，对象就新建一个，再把每个属性递归复制过去。

难点是循环引用，比如 obj.self = obj，直接递归会无限循环。解决办法是用一个 WeakMap 记下“这个对象已经复制过了，副本是谁”，再碰到就直接返回副本。而且副本要在递归子属性之前就登记进去，不然子属性指回自己时还是会死循环。

还有几类要特别处理。Date、RegExp、Map、Set 的数据不在普通属性上，要按类型新建，Map 的键和值都要递归复制。Object.keys 和 for...in 拿不到 Symbol 键，要用 Reflect.ownKeys。用 Object.create(原型) 创建副本，类实例的方法就能保留下来。

structuredClone 是浏览器和 Node 自带的深拷贝，能处理循环引用、Date、Map、Set 这些。但它不复制 Symbol 键，类实例会变成普通对象，碰到函数或 DOM 节点会抛出 DataCloneError。

实现

JavaScript
function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value;
  if (seen.has(value)) return seen.get(value);

  if (value instanceof Date) return new Date(value.getTime());
  if (value instanceof RegExp) {
    const copy = new RegExp(value.source, value.flags);
    copy.lastIndex = value.lastIndex;
    return copy;
  }
  if (value instanceof Map) {
    const copy = new Map();
    seen.set(value, copy);
    value.forEach((v, k) => copy.set(deepClone(k, seen), deepClone(v, seen)));
    return copy;
  }
  if (value instanceof Set) {
    const copy = new Set();
    seen.set(value, copy);
    value.forEach((v) => copy.add(deepClone(v, seen)));
    return copy;
  }

  const copy = Array.isArray(value) ? [] : Object.create(Object.getPrototypeOf(value));
  // 先登记再递归，子属性引用自身时能拿到这个副本
  seen.set(value, copy);
  for (const key of Reflect.ownKeys(value)) {
    const descriptor = Object.getOwnPropertyDescriptor(value, key);
    if (descriptor.enumerable) copy[key] = deepClone(value[key], seen);
  }
  return copy;
}

第一行就把原始值和函数挡在外面了。typeof 函数得到的是 'function'，不是 'object'，所以函数会被原样返回，副本和原对象共用同一个函数。

为什么 seen.set 要写在循环之前？以 source.self = source 为例。复制 source 时，先建好空的 copy 并登记；接着复制 self 属性，又碰到 source，这时 seen 里已经有它了，直接返回 copy。如果登记写在循环之后，复制 self 时 seen 里还没有，就会再从头复制一遍，永远停不下来。

Map 和 Set 分支里也是先登记再递归，道理一样。

为什么用 WeakMap 而不是 Map？这个表只在这次拷贝期间用，键都是对象。WeakMap 不会阻止这些对象被垃圾回收。

验证一下

下面这个对象里，日期、Map、Set、Symbol 键、嵌套数组、循环引用都有：

JavaScript
const id = Symbol('id');
const source = {
  date: new Date(0),
  map: new Map([['k', { n: 1 }]]),
  set: new Set([1]),
  [id]: 'sym',
  list: [1, { x: 2 }],
};
source.self = source;

const copy = deepClone(source);
console.log(copy.self === copy); // true
console.log(copy.date !== source.date && copy.date instanceof Date); // true
console.log(copy.map.get('k') !== source.map.get('k')); // true
console.log(copy[id]); // 'sym'

const native = structuredClone(source);
console.log(native.self === native); // true
console.log(native[id]); // undefined

copy.self === copy 说明循环引用被正确还原了：副本的 self 指向副本自己，而不是原对象。Map 里的值也是新对象，Symbol 键也拷过来了。

structuredClone 也正确处理了循环引用，可是 native[id] 是 undefined，Symbol 键被丢掉了。

和 structuredClone 的区别

情况deepClone（上面实现）structuredClone
循环引用支持支持
Date、RegExp、Map、Set支持支持
Symbol 键复制丢弃
类实例的原型保留变成普通对象
函数共享原函数抛出 DataCloneError
ArrayBuffer、TypedArray、Blob 等未处理支持

可以看出两者各有长短。实际项目里，复制纯数据优先用 structuredClone。它和 JSON 方案、浅拷贝怎么选，见《浅拷贝、深拷贝和 structuredClone 如何选择？》。

常见追问

为什么函数不复制？

函数可能用到闭包里的变量，这些变量没办法可靠地复制出来，所以一般直接共用原函数。

getter 和不可枚举属性怎么办？

上面的实现会读取 getter 当前的值，存成普通属性，并跳过不可枚举的属性。如果要完整保留属性描述符，可以改用 Object.defineProperty，把复制后的描述符写进去。

数据很深的时候会不会栈溢出？

会有这个风险。递归受调用栈深度的限制，特别深的结构可以改成用一个数组当栈，自己循环处理。
