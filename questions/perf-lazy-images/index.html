懒加载为什么有时反而让首屏和首次交互变慢？

懒加载把下载和执行推迟到需要的时候，减少了首屏的工作，但用户马上就要用的内容会因此在首次使用时多等一轮。首屏 LCP 图片加 loading="lazy" 会推迟它的请求；点击后才依次下载组件、数据和依赖，会形成串行瀑布。

参考答案

简答

  • 懒加载没有减少总工作量，只是把它挪到后面；挪给"用户马上要用的东西"就会变慢。
  • 首屏图片（尤其是 LCP 元素）不要加 loading="lazy"，浏览器要等布局确定它在视口内才开始请求。
  • 所有图片都写 width、height（或 aspect-ratio），懒加载的图片到达时才不会撑开布局造成 CLS。
  • 点击后才开始的"下载组件 → 请求数据 → 加载依赖"是串行的，可以在用户表现出意图时（悬停、聚焦、即将进入视口）提前并行预取。
  • 动态导入可能失败，特别是发布新版本后旧的分块被删除，要有错误提示和重试。

图片

HTML
<!-- 首屏主图：立即加载并提高优先级 -->
<img src="/hero.avif" width="1200" height="600" fetchpriority="high" alt="产品主图" />

<!-- 首屏以下：懒加载，预留尺寸 -->
<img
  src="/card-640.avif"
  srcset="/card-640.avif 640w, /card-1280.avif 1280w"
  sizes="(max-width: 700px) 100vw, 640px"
  width="1280"
  height="720"
  loading="lazy"
  alt="组件布局示例"
/>

原生懒加载会在图片接近视口前提前开始加载，具体距离由浏览器决定。iframe 也支持 loading="lazy"，适合页面下方的视频和地图嵌入。

代码

JavaScript
const button = document.querySelector('#open-editor');
let editorModule;

// 用户表现出意图时开始下载，不必等到点击
const preload = () => (editorModule ??= import('./editor.js'));
button.addEventListener('pointerenter', preload, { once: true });
button.addEventListener('focus', preload, { once: true });

button.addEventListener('click', async () => {
  try {
    const { openEditor } = await preload();
    openEditor();
  } catch {
    editorModule = undefined;
    showError('加载失败，请刷新页面后重试');
  }
});

触屏设备没有悬停，预取只能是加速手段，不能作为功能可用的前提。

什么该懒加载

适合不适合
首屏以下的图片、视频、地图首屏主图、Logo
低频的弹窗、编辑器、图表库几乎每个用户都会打开的模块
只在特定路由使用的代码很小的高频组件，拆分后请求开销大于收益

常见追问

  • 怎么判断懒加载是否有收益？对比冷缓存首屏的 LCP，以及首次使用该功能时的等待时间，只看分块数量变多没有意义。
  • 发布新版本后旧分块 404 怎么办？保留旧版本的静态资源一段时间，加载失败时提示刷新。
