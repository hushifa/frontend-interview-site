Vue 插件如何向应用提供可复用能力？

插件通过 app.use 在应用范围安装能力，可以注册组件、指令或依赖。配置、状态与资源应按应用实例组织，重复安装不等于动态更新配置，SSR 与应用卸载也需要明确的生命周期。

参考答案

插件适合安装一组应用级能力，例如格式化服务、路由、国际化或全局组件。它可以是一个安装函数，也可以是具有 install 方法的对象，接收 app 与调用方提供的选项。

插件不是给所有组件随意增加隐藏全局变量的理由。最好明确暴露一个小接口，说明配置何时生效、状态属于哪个应用、资源何时释放。

通过应用级 provide 暴露服务

下面示例面向 Vue 3.5 及以上，用 app.onUnmount 清理可选的浏览器监听。状态在每次 install 中创建，不放在模块级单例里。

JavaScript
// localePlugin.js
import { readonly, ref } from 'vue';

export const localeKey = Symbol('区域服务');
const supported = new Set(['zh-CN', 'en-US', 'de-DE']);

export const localePlugin = {
  install(app, options = {}) {
    const initial = options.locale ?? 'zh-CN';
    if (!supported.has(initial)) throw new RangeError('不支持的区域配置');
    const locale = ref(initial);

    function setLocale(value) {
      if (!supported.has(value)) throw new RangeError('不支持的区域配置');
      locale.value = value;
    }

    function formatNumber(value) {
      return new Intl.NumberFormat(locale.value).format(value);
    }

    app.provide(localeKey, { locale: readonly(locale), setLocale, formatNumber });

    if (options.followBrowser && typeof window !== 'undefined') {
      function syncLanguage() {
        if (supported.has(navigator.language)) setLocale(navigator.language);
      }
      window.addEventListener('languagechange', syncLanguage);
      app.onUnmount(() => window.removeEventListener('languagechange', syncLanguage));
    }
  },
};

消费者注入同一份键，读取区域并通过明确方法修改：

vue
<!-- LocalePanel.vue -->
<script setup>
import { computed, inject } from 'vue';
import { localeKey } from './localePlugin.js';
const service = inject(localeKey, null);
if (!service) throw new Error('需要安装区域插件');
const selected = computed({
  get: () => service.locale.value,
  set: value => service.setLocale(value),
});
</script>

<template>
  <section>
    <label>区域
      <select v-model="selected">
        <option value="zh-CN">中文区域</option>
        <option value="en-US">美国区域</option>
        <option value="de-DE">德国区域</option>
      </select>
    </label>
    <p>{{ service.formatNumber(1234.5) }}</p>
  </section>
</template>
JavaScript
// main.js
import { createApp } from 'vue';
import LocalePanel from './LocalePanel.vue';
import { localePlugin } from './localePlugin.js';

const app = createApp(LocalePanel);
app.use(localePlugin, { locale: 'zh-CN', followBrowser: true });
app.mount('#app');

这个例子只演示数字格式化，不是完整国际化系统。formatNumber 在组件渲染中读取响应式 locale，选择新区域后可以重新显示对应格式；消费者无需把内部 ref 当作可随意写入的全局变量。

同一插件的重复安装有明确范围

Vue 会避免同一个应用重复安装同一个插件对象或函数。第二次 app.use 不应被当作更新配置的方法；需要动态配置，应像示例的 setLocale 那样提供正式接口。

同一个插件可以被不同应用安装。由于 locale 在 install 内部创建，两个应用可以有不同初始区域，不会因为导入了同一模块就自动共享用户状态。

如果每次都通过工厂产生一个新的插件对象，身份又不同，不能期待框架把所有看起来相似的对象都判为同一次安装。

初始化和清理属于插件契约

插件如果注册浏览器事件、创建定时器或连接外部服务，就应提供相应释放路径。当前应用 API 可以登记卸载回调，但还要考虑安装失败、应用尚未挂载或提前取消初始化等情况。

示例先验证配置，再建立状态和监听；浏览器专属逻辑也有环境判断。真实复杂初始化应避免执行到一半失败后留下已创建资源，必要时显式管理清理栈或可释放服务。

app.use 调用安装函数不等于会自动等待任意异步准备工作。若某个服务必须就绪后才能挂载，应由应用启动流程明确等待，或在组件层提供可解释的准备状态。

globalProperties 适合有限的兼容接口

app.config.globalProperties 可以向组件实例或模板提供全局能力，但大量隐式的 $xxx 会让依赖来源不清楚，也给单独测试组件增加负担。

script setup 不会因为存在全局属性，就自动在 JavaScript 作用域里多出一个同名变量。组合式代码通常更适合显式 inject 或导入清楚的服务接口。

TypeScript 项目还需要为公开的注入键或全局实例能力提供相应类型，但声明只描述接口，不会替代实际安装。类型补全出现一个方法，不意味着运行时插件一定已执行。

SSR 与测试隔离不能依赖模块单例

服务器可能为不同用户处理多个请求。如果插件把可变用户状态放在模块顶层，请求之间可能意外共享。应按应用或请求创建状态，并清楚区分可以共享的静态配置和不该共享的用户数据。

mounted、unmounted 等客户端生命周期不能替代服务器请求资源管理。示例在服务器不注册 window 监听，真正的服务端连接和缓存则需要自己的作用域。

测试时应创建独立 app，验证配置、注入、重复安装与卸载，并确认没有残留监听。对于不需要应用级安装的纯函数，直接导出通常更简单；只有确实需要统一注册或配置时，再使用插件这一层。
