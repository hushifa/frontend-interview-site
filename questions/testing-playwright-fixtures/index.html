Playwright fixtures 解决了什么测试维护问题？

理解 fixture 的依赖、作用域和自动清理，用共享测试上下文减少重复登录与环境初始化。

参考答案

Fixture 用于声明测试所需的上下文和生命周期，例如页面、已认证状态、测试数据或 API 客户端。测试只声明需要哪些 fixture，框架负责按依赖建立和清理，能够减少每个用例重复编写初始化代码。

作用域要谨慎选择：测试级 fixture 更容易隔离，worker 级 fixture 可以复用昂贵资源但必须避免共享可变业务状态。fixture 中的失败应尽早暴露，清理逻辑要放在资源使用之后，并保证失败时也能执行。

Fixture 不是全局变量替代品。每个测试仍应明确自己的前置条件，避免通过隐藏状态让用例依赖执行顺序；并行运行时尤其要隔离账号、数据和文件目录。
