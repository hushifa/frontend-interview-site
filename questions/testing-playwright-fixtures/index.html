Playwright fixtures 解决了什么测试维护问题？

fixture 把测试需要的准备和清理封装起来，测试按名字声明依赖，Playwright 只在需要时创建，并在 await use() 之后自动清理；test 作用域每个测试一份，worker 作用域在同一工作进程内共享。

参考答案

简答

  • 内置的 page、context、request 都是 fixture，每个测试拿到全新的实例。
  • 自定义 fixture 用 test.extend：await use(value) 之前是准备，之后是清理，测试失败也会执行清理。
  • fixture 按需创建：测试参数里没写的 fixture 不会被初始化。
  • fixture 可以依赖其他 fixture，Playwright 按依赖顺序创建、按相反顺序拆除。
  • { scope: 'worker' } 让同一个工作进程中的测试共享一份，适合启动成本高、测试不会修改的资源，例如只读的测试账号；会被修改的数据应该用 test 作用域。

自定义 fixture

TypeScript
import { test as base, expect } from '@playwright/test';

type Fixtures = {
  todo: { id: string; title: string };
};

export const test = base.extend<Fixtures>({
  todo: async ({ request }, use) => {
    const response = await request.post('/api/test/todos', {
      data: { title: '测试任务' },
    });
    const todo = await response.json();

    await use(todo);

    await request.delete(`/api/test/todos/${todo.id}`);
  },
});

test('完成任务', async ({ page, todo }) => {
  await page.goto(`/todos/${todo.id}`);
  await page.getByRole('checkbox', { name: todo.title }).check();
  await expect(page.getByText('已完成')).toBeVisible();
});

和在 beforeEach 里创建、afterEach 里删除相比，准备和清理写在一起，只有用到 todo 的测试才会创建它。

worker 作用域

TypeScript
export const test = base.extend<{}, { account: { email: string } }>({
  account: [
    async ({}, use, workerInfo) => {
      const email = `user-${workerInfo.workerIndex}@test.local`;
      await createAccount(email);
      await use({ email });
      await deleteAccount(email);
    },
    { scope: 'worker' },
  ],
});

每个工作进程一个账号，并行的进程之间互不干扰。同一进程里的测试是串行执行的，所以它们共享这个账号时，不能有测试修改它的状态。

自动 fixture

{ auto: true } 让 fixture 对每个测试自动运行，即使测试没有声明它，适合统一的日志收集或在失败时附加额外信息。

和普通辅助函数怎么选

只是封装一组操作（例如“填写登录表单”）用普通函数或页面对象即可。需要生命周期管理（创建后必须清理）或要在多个测试间按作用域共享时，才用 fixture。
