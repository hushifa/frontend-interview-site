strict、noUncheckedIndexedAccess 和 target 如何配置？

tsconfig 分别控制检查强度、语法输出、可用的类型声明和模块解析。TypeScript 6.0 起 strict 默认开启、target 默认为最新 ES、module 默认 esnext、types 默认空数组，并弃用了 ES5、node10 解析、baseUrl 等；TypeScript 7.0 删除了这些选项。target 和 lib 只影响类型和语法转换，不会注入 polyfill。

参考答案

简答

  • strict 是一组检查（strictNullChecks、noImplicitAny、strictFunctionTypes 等）的总开关，TypeScript 6.0 起默认为 true；但 noUncheckedIndexedAccess、exactOptionalPropertyTypes 不在其中，需要单独开启。
  • target 决定输出的语法版本，lib 决定能使用哪些内置 API 的类型；两者都不会补充运行时缺少的 API。
  • module 和 moduleResolution 要和真实运行环境一致：交给打包工具用 bundler，Node.js 直接运行用 nodenext。
  • TypeScript 6.0 把 types 默认值改为 []，Node、测试框架的全局类型需要在 types 中显式列出。
  • TypeScript 7.0 删除了 target: es5、moduleResolution: node10/classic、baseUrl、outFile、downlevelIteration、module: amd/umd/system，以及把 esModuleInterop 设为 false。

打包工具项目的起点

json
{
  "compilerOptions": {
    "target": "es2022",
    "lib": ["es2023", "dom", "dom.iterable"],
    "module": "esnext",
    "moduleResolution": "bundler",
    "types": ["vite/client"],
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "verbatimModuleSyntax": true,
    "noEmit": true
  },
  "include": ["src"]
}

noEmit: true 表示 tsc 只做类型检查，转换交给 Vite 或 esbuild。strict 写出来是为了兼容 6.0 之前的版本。

索引访问

TypeScript
const list: string[] = [];
const first = list[0];
first.toUpperCase();

默认配置下 first 的类型是 string，上面的代码能通过检查，运行时却抛错。开启 noUncheckedIndexedAccess 后 first 是 string | undefined，必须先判断。它对 Record<string, T> 的读取同样生效；for...of 和数组方法的回调参数不受影响。

精确可选属性

TypeScript
type P = { name?: string };
const p: P = { name: undefined }; // exactOptionalPropertyTypes 下报错

开启后，"属性缺失"和"属性值为 undefined"被区分开。这影响 'name' in p、Object.keys 和 PATCH 请求中"不修改"与"清空"的语义。确实需要显式 undefined 时写 name?: string | undefined。

target 与 lib

  • target: es2022 时，可选链、类字段等原样输出；改成 es2015 会被降级。
  • lib 中包含 es2023 只说明可以调用 findLast，目标浏览器没有该方法时仍会运行时出错，需要 core-js 等 polyfill。
  • 不写 lib 时根据 target 推导默认值；写了就完全替换，DOM 项目要记得加 dom。

TypeScript 6/7 的默认值变化

选项6.0 前默认6.0 起默认
strictfalsetrue
targetes5最新 ES 版本（当前为 es2025）
module视 target 而定esnext
types自动包含所有 @types/*[]
rootDir推断tsconfig 所在目录
noUncheckedSideEffectImportsfalsetrue

6.0 中可以用 "ignoreDeprecations": "6.0" 暂时屏蔽弃用错误，7.0 中这些选项直接报 TS5108 / TS5102。迁移 baseUrl 的方式是改写 paths 为相对 tsconfig 的路径，或改用 package.json 的 imports（#src/*）。

在存在 tsconfig 的目录执行 tsc foo.ts 会报 TS5112，需要加 --ignoreConfig。

检查与构建分开

Vite、esbuild、SWC 只删除类型，不做类型检查，所以构建成功不代表类型正确。CI 中要单独运行 tsc --noEmit（多项目用 tsc -b）。

常见追问

  • skipLibCheck 要不要开？大多数应用项目开启，可以跳过 node_modules 中 .d.ts 的检查以加快速度；库作者应关闭以发现自己声明中的错误。
  • Node.js 原生运行 TS 要哪些选项？erasableSyntaxOnly、verbatimModuleSyntax、module: nodenext、rewriteRelativeImportExtensions，见《import type 和 verbatimModuleSyntax 如何影响模块输出？》。
