px、rem、em、百分比和动态视口单位怎么选？

选择尺寸单位先确定参照：px 是 CSS 像素，rem 与根字体相关，em 与局部字体相关，百分比由属性决定参照，svh、lvh、dvh 则区分浏览器界面变化下的视口尺寸。

参考答案

选择单位并不是给它们排一个“先进程度”。真正要问的是：这个尺寸应该跟谁一起变化？细边框可能需要稳定的 CSS 像素，按钮内边距适合随按钮文字变化，文章宽度与页面区域相关，全屏面板则与视口相关。

px 不是物理屏幕上的一个发光点

CSS 的 px 是参考像素单位。高像素密度设备上，一个 CSS 像素可能对应多个设备像素；浏览器缩放也会影响这种关系。因此不能看到 width: 100px 就推断它一定占用 100 个物理像素。

px 也不等于“用户不能缩放”。正常的页面缩放会放大以 px 设置的内容。但如果大量文字写死 px，它们通常不会像依赖根字体的 rem 一样，直接跟随用户修改的默认字体大小。是否尊重字体偏好、是否允许页面缩放，是相关但不同的问题。

rem 和 em 的差别，主要在参照对象

rem 通常相对根元素的计算字体大小。假设根字体为 16px，1.5rem 就是 24px；改成 20px，同一个值变成 30px。

em 在 font-size 上相对继承来的字体大小，通常就是父级字体；用在多数其他长度属性上，则相对元素自己的计算字体大小。

CSS
.frame {
  font-size: 20px;
}

.card {
  font-size: 1.5em;
  padding: 1em;
  border-radius: 0.5rem;
}

如果 .card 在 .frame 内，而且根字体是 16px，卡片字体为 30px，内边距也是 30px，圆角则为 8px。这里两个 em 没有使用同一个直接参照：字体先根据父级计算，内边距再根据卡片自己的字体计算。

嵌套时重复写 font-size: 1.2em 会逐层放大。例如两层都是 1.2 倍，最终是 1.44 倍。想让全站字号和间距相对统一，可更多使用 rem；希望组件内的按钮 padding 跟着该按钮字号缩放，则 em 很合适。

根元素自己的 font-size 使用 rem 时，要根据初始字体大小解析，不能让根字体依赖自己形成循环。也不要为了方便换算就假定所有用户根字体永远为 16px，或通过禁止缩放来维持设计稿比例。

百分比没有统一的“父级同方向尺寸”规则

百分比的参照由属性定义决定，常见例子如下：

写法需要确认的参照
width: 50%通常根据包含块宽度计算，不一定是直接父元素的内容宽度
height: 100%受包含块高度是否明确及具体布局规则影响
font-size: 120%相对继承来的字体大小
横排布局的 padding-top: 10%根据包含块宽度计算，不是高度
transform: translateX(50%)相对变换参考盒的宽度，通常是元素自身的 border box

这解释了为什么父级高度由内容撑开时，给子级写 height: 100% 不一定能得到“占满屏幕”。先确认布局是否提供了可解析的高度，而不是继续给所有祖先堆 100%。

它也解释了经典居中方法中两种百分比的不同：left: 50% 根据定位包含块偏移，translateX(-50%) 再根据元素自己的宽度往回移动一半。

移动端为什么 100vh 有时太高

浏览器地址栏、工具栏展开或收起后，用户实际能看到的页面区域会变化。较大的视口高度能覆盖工具栏收起后的空间，但在工具栏仍显示时，元素底部可能被挡住。

现代视口单位把这些情况分开：

  • svh：小视口高度的百分之一，按浏览器动态界面展开时的较小空间计算。布局较稳定，界面收起后可能留出额外空间。
  • lvh：大视口高度的百分之一，按动态界面收起时的较大空间计算。展开界面时，部分内容可能超出可见区域。
  • dvh：动态视口高度的百分之一，随相关浏览器界面变化调整，能更贴近当前空间，但也可能在滚动时引发布局尺寸变化。

当前常见实现中的 vh 对应大视口单位，不能依赖它自动解决工具栏遮挡。需要稳定的开屏区可以考虑 min-height: 100svh；需要跟随当前视口的面板可以考虑 dvh，但要评估调整尺寸时的体验。

CSS
.page-shell {
  min-height: 100vh;
  min-height: 100dvh;
}

不支持 dvh 的环境会忽略第二条，保留第一条。这里用 min-height 而非固定 height，让长内容仍然有机会撑高页面，不会仅因超出一屏就被限制在固定高度里。

虚拟键盘不一定按同样方式改变这些单位，取决于浏览器的布局视口、视觉视口和交互策略。不能把 100dvh 当成所有设备上的避让键盘方案；底部输入框还要实测键盘弹起、缩放和安全区域。安全区域内边距 env(safe-area-inset-bottom) 解决的也是另一类边缘遮挡问题。

响应式通常需要组合单位和约束

CSS
.article {
  width: min(100% - 2rem, 48rem);
  margin-inline: auto;
}

.article h1 {
  font-size: clamp(1.75rem, 1.25rem + 2vw, 3rem);
}

文章宽度在小容器中保留左右空间，在大容器中限制最大阅读宽度。标题大小在给定上下限之间随视口调整，而不是无限放大。

clamp() 的上下限也可能限制文字放大效果，因此仍需检查用户放大字号与缩放页面后的可读性。把所有 px 换成 rem，或者给所有宽度写百分比，都不能自动完成响应式；长文本、换行、溢出和布局切换仍需要独立设计。
