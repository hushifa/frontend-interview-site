为什么 z-index 设置很大，元素还是被遮挡？

z-index 只在同一个层叠上下文里面比。父级这一整层排得低，子元素的 z-index 写得再大，也越不过外面的兄弟。

参考答案

简答

可以把层叠上下文想成一个整体图层。里面的元素先在图层内部排好先后，然后整个图层作为一个整体，再和外面的兄弟比。

所以父元素 z-index: 1，旁边的元素 z-index: 2，子元素写 z-index: 9999 也只是在父元素里面最高，整体还是被盖住。

很多属性都会创建层叠上下文：定位元素加上不是 auto 的 z-index、opacity 小于 1、transform、filter、isolation: isolate、flex 或 grid 项目加 z-index、position: fixed 或 sticky。

另外两点要注意。z-index 只对定位元素、flex 项目和 grid 项目生效，普通的静态块写了也没用。还有，元素看起来被遮住，也可能是被祖先的 overflow 裁掉了，跟 z-index 没关系。

下拉菜单为什么被内容盖住

HTML
<header style="position: relative; z-index: 1">
  <div class="dropdown" style="position: absolute; z-index: 9999">菜单</div>
</header>
<main style="position: relative; z-index: 2">内容</main>

菜单 z-index: 9999，main 只有 2，菜单却被 main 盖住了。

原因是 header 有定位又有 z-index: 1，它创建了一个层叠上下文，菜单被关在里面。.dropdown 和 main 根本不在同一个上下文里直接比。真正比的是 header 的 1 和 main 的 2，header 整体输了，里面的菜单再高也没用。

改法有三种。提高 header 的 z-index，让它整体排到 main 上面。或者去掉 main 不必要的 z-index，让它不再创建上下文。或者把下拉菜单渲染到更外层，或者改用 popover，它会进入顶层（top layer），排在所有层叠上下文之上。

同一个上下文里，谁画在上面

同一个层叠上下文里，从下往上依次是：上下文根元素的背景和边框，负 z-index 的子上下文，普通的块，浮动元素，行内内容，z-index: auto 或 0 的定位元素，最后是正 z-index 的子上下文。

所以没写 z-index 的定位元素，也会盖在普通块和浮动元素上面。

遇到遮挡怎么排查

从被遮住的元素往上找，看是哪个祖先创建了层叠上下文。浏览器开发者工具的 3D View 或 Layers 面板能直接看到层次。

再检查祖先有没有 overflow: hidden，元素可能是被裁掉了，不是被盖住了。

写组件时，可以用 isolation: isolate 主动给组件创建一个上下文。它没有别的副作用，组件内部的 z-index 就不会和外面冲突。

常见追问

项目里的 z-index 怎么管理才不乱？

定义少量有名字的层级变量，比如 --z-dropdown、--z-modal，大家都用变量，不随手写数字。弹层尽量用 dialog 和 popover，它们进顶层，不用跟别人比 z-index。
