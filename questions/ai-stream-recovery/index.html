AI 流式输出断线后，怎样恢复同一条生成任务？

断线恢复需要服务端把一次生成保存为可查询的运行，事件带递增序号；客户端记录最后应用的序号，重连时按游标补发并去重。恢复失败时要让用户明确选择重新生成。

参考答案

简答

  • 恢复的前提是服务端把每次生成保存为一个运行（run），有 ID、状态和按序号保存的事件日志。
  • 客户端记录最后一个已经应用的事件序号，重连时带上它，服务端只补发后面的事件。
  • 客户端按"运行 ID + 事件序号"去重，序号必须连续，出现缺口就停止并拉取快照。
  • 恢复和重新生成是两件事。日志过期或运行失败时，展示已收到的部分并让用户选择重新生成，不要自动重发。
  • 最终消息用运行 ID 做幂等写入，重复的完成事件不会生成两条消息。

服务端保存什么

text
runId = run_123
1 message-start
2 text-delta "你"
3 text-delta "好"
4 message-complete

事件日志保留一段时间（例如几分钟到几小时），过期后运行标记为"不可恢复"。运行 ID 不可预测，每次查询都校验它属于当前用户。

重连请求

http
GET /api/runs/run_123/events?after=3
Accept: text/event-stream

服务端补发序号大于 3 的事件。如果运行在断线期间已经完成，补发剩余事件后就结束；日志已过期则返回当前状态和最终消息（如果有）。

SSE 的 Last-Event-ID 请求头可以承载这个游标，但只有服务端真的保存了事件并按 ID 补发，它才有意义。用 fetch 实现 SSE 时，浏览器不会自动带这个头，要自己传。

客户端应用事件

JavaScript
function applyEvent(state, event) {
  if (state.status !== 'streaming' || event.runId !== state.runId) return state;
  if (event.seq <= state.lastSeq) return state; // 重复事件
  if (event.seq !== state.lastSeq + 1) return { ...state, status: 'gap' };

  switch (event.type) {
    case 'text-delta':
      return { ...state, text: state.text + event.delta, lastSeq: event.seq };
    case 'message-complete':
      return { ...state, status: 'completed', lastSeq: event.seq };
    default:
      return { ...state, lastSeq: event.seq }; // 本例不渲染的事件只推进游标
  }
}
  • 按事件身份去重，不按文本内容去重，因为模型可能合法地输出相同片段。
  • 序号是本应用自定义的连续整数。SSE 规范里的 id 是字符串，没有连续性保证，需要在协议适配层转换。
  • 出现 gap 时关闭连接，拉取运行快照（已累积文本和最新序号），再从快照位置重新订阅。
  • 游标存进 IndexedDB 时，要和对应的文本一起保存。只存了游标、没存文本，刷新后会跳过那一段。

界面状态

情况界面
正在重连保留已有文字，显示"连接中断，正在恢复"
恢复成功继续追加，无需用户操作
运行已完成直接显示最终消息
日志过期或运行失败保留部分文字并标注"未完成"，提供"重新生成"按钮

重新生成会创建新运行，消息记录里保存新旧运行的关系。

重连使用指数退避，避免服务端恢复时大量客户端同时涌入。

常见追问

  • 只把最后一段文字发给服务端让它"接着写"行不行？ 那是一次新生成，结果可能和原来的回答对不上，还会重复计费。
  • 取消怎么记录？ 取消请求针对运行 ID，服务端写入终止事件，其他标签页恢复时也能看到"已停止"。
