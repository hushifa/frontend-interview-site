什么是闭包？它有哪些实际应用？

闭包是函数与其创建时词法环境的组合，外层函数返回后内层函数仍能读写这些绑定。常用于私有状态、工厂函数和回调；陈旧值与内存占用都源于旧环境仍被引用。

参考答案

简答

  • 闭包是函数加上它创建时所在的词法环境；外层函数返回后，内层函数仍能访问这些绑定。
  • 变量查找按函数定义位置进行，与在哪里调用无关。
  • 闭包捕获的是绑定本身，读到的是绑定的当前值，不是创建时的快照。
  • 常见用途：私有状态、工厂函数、事件回调和偏函数。
  • 闭包只让被引用的环境保持可达；监听器或定时器不清理时，它们引用的数据才会一直留在内存里。

函数返回后状态为什么还在

JavaScript
function createCounter() {
  let count = 0;

  return {
    increment() {
      count += 1;
      return count;
    },
    read() {
      return count;
    },
  };
}

const first = createCounter();
const second = createCounter();

console.log(first.increment()); // 1
console.log(first.increment()); // 2
console.log(first.read());      // 2
console.log(second.increment()); // 1

每次调用 createCounter 都会创建新的词法环境。increment 和 read 共享同一个 count，first 与 second 之间互不影响。外部只能通过返回的方法操作 count，这就是用闭包实现私有状态。

捕获的是绑定，不是值

JavaScript
let label = '旧值';
const read = () => label;
label = '新值';
console.log(read()); // 新值

React 等框架里的"陈旧闭包"是另一种情况：每次渲染都会创建新的函数和新的 state 常量，旧回调引用的是旧渲染的绑定，所以读到旧值。解决方法是让回调随依赖重新创建，或改用函数式更新、ref 读取最新值。

循环中的闭包问题本质是 var 只有一个函数级绑定，详见《var、let、const 和暂时性死区有什么关系？》。

常见用途

  • 私有状态：计数器、缓存、一次性初始化（once）。
  • 工厂与配置：createLogger(prefix) 返回带前缀的日志函数。
  • 回调保留上下文：事件处理函数访问创建时的参数。
  • 偏函数与柯里化：const add5 = (x) => add(5, x)。

闭包与内存

闭包本身不是内存泄漏。引擎只需保留仍被内层函数引用的环境；只要持有闭包的对象（监听器、定时器、全局缓存）被移除，整个环境就可以被回收。排查泄漏时看的是"谁还引用着这个函数"，而不是"有没有闭包"。

常见追问

  • 闭包里修改外层变量会影响其他闭包吗？会，共享同一个环境的闭包读写同一个绑定。
  • 模块作用域和闭包是什么关系？ES 模块的顶层绑定也是一个词法环境，导出的函数同样闭包了模块内的私有变量。
