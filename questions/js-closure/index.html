什么是闭包？它有哪些实际应用？

闭包就是函数记住了它定义时能访问的变量，外层函数执行完以后，内层函数还能继续用这些变量。常用来做私有状态和工厂函数。

参考答案

简答

一个函数在另一个函数里面定义，并且用到了外层函数的变量，这就形成了闭包。

一般来说，函数执行完，它的局部变量就用不到了。但如果外层函数把内层函数返回出去，内层函数又用到了外层的变量，这些变量就会一直保留，内层函数之后还能读、还能改。

最典型的用途是做私有变量。比如写一个计数器，count 放在外层函数里，外面没法直接改，只能通过返回的 increment 方法去加。另外工厂函数、事件回调、防抖节流，里面都用到了闭包。

有两点要注意。第一，闭包保存的是变量本身，不是当时的值，变量后来改了，闭包读到的就是新值。第二，闭包本身不等于内存泄漏，只有当闭包一直被定时器、事件监听这类东西引用着、没有清理时，它用到的数据才会一直留在内存里。

先看一个例子

下面写一个计数器。count 定义在 createCounter 里面，返回的两个方法都用到了它。

JavaScript
function createCounter() {
  let count = 0;

  return {
    increment() {
      count += 1;
      return count;
    },
    read() {
      return count;
    },
  };
}

const first = createCounter();
const second = createCounter();

console.log(first.increment()); // 1
console.log(first.increment()); // 2
console.log(first.read());      // 2
console.log(second.increment()); // 1

createCounter() 执行完以后，按理说 count 就该没了。可是调用 first.increment()，它还能接着往上加，这就是闭包在起作用。

first 里的 increment 和 read 是同一次调用创建的，所以它们操作的是同一个 count，加完以后 read 读到的是 2。second 是另一次调用，有自己的一份 count，所以它从 1 开始，跟 first 互不影响。

外面的代码没办法直接改 count，只能通过这两个方法。很多地方说“用闭包实现私有变量”，指的就是这种写法。

为什么内层函数能找到外层的变量

函数里用到一个变量，JavaScript 会先在函数自己里面找，找不到就去定义它的那个外层函数里找，再找不到就继续往外，一直找到全局。

这条查找路线是按函数写在哪里定下来的，跟它后来在哪里被调用没有关系，这叫词法作用域。所以 increment 不管被拿到哪里去调用，它找 count 时走的都是同一条路，最后都能找到 createCounter 里的那个 count。

闭包记住的是变量，不是当时的值

JavaScript
let label = '旧值';
const read = () => label;
label = '新值';
console.log(read()); // 新值

read 创建的时候 label 还是“旧值”，但它记住的是 label 这个变量本身。后来变量被改成“新值”，再调用 read，读到的自然就是新值。

React 里为什么会读到旧值

既然闭包记住的是变量，那 React 里为什么经常读到旧的 state？先看一个例子：

JSX
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1);
    }, 1000);
    return () => clearInterval(id);
  }, []);

  return <p>{count}</p>;
}

本来想让数字每秒加 1，结果页面上的数字变成 1 之后就再也不动了。

原因在于，React 每渲染一次，就会把 Counter 这个函数重新执行一遍。每执行一遍，都会得到一个新的 count。第一次渲染时 count 是 0，第二次渲染时是另一个值为 1 的 count。它们是两个不同的变量，不是同一个变量被改了。

定时器回调是第一次渲染时创建的，它记住的是第一次渲染的那个 count，值一直是 0。依赖数组写的是 []，这个回调后来也没有被换掉，所以每秒执行的都是 setCount(0 + 1)，数字就停在了 1。

最简单的改法是用函数式更新，不去读外面的 count，让 React 把最新的值传进来：

JSX
setCount((current) => current + 1);

另外两种办法是：把 count 写进依赖数组，让 effect 跟着重新创建回调；或者用 useRef 保存最新值，在回调里读 ref.current。

for 循环里的闭包

还有一道经典题：for 循环里用 var 声明变量，每个定时器回调最后都输出同一个数。原因是 var 在整个函数里只有一个变量，所有回调共用它，详见《var、let、const 和暂时性死区有什么关系？》。

闭包在实际开发中用在哪里

最常见的是做私有状态，比如上面的计数器，还有缓存、只执行一次的 once 函数，都是把数据藏在闭包里，外面只能通过返回的函数访问。

工厂函数也离不开闭包。比如 createLogger('[订单]') 返回一个打印日志的函数，每次打印都自动带上“[订单]”这个前缀，因为前缀被闭包记住了。

防抖和节流同样如此。定时器的 ID 保存在闭包里，函数被连续调用时，每次操作的都是同一个定时器，所以才能做到“等用户停下来再执行”。

闭包会导致内存泄漏吗

闭包本身不会。只要闭包这个函数不再被用到，它记住的变量就会和它一起被回收。

真正出问题的情况是，闭包被一个一直存在的东西拿着不放。比如给 window 加了事件监听却没有移除，或者开了 setInterval 却没有清除，那这个回调函数就一直活着，它用到的数据也就一直释放不掉。所以排查内存问题时，要找的是“谁还在引用这个函数”，而不是“这里有没有用闭包”。

常见追问

同一个外层函数返回的多个闭包，会互相影响吗？

如果是同一次调用返回的，会。就像例子里的 increment 和 read，它们用的是同一个 count，一个改了另一个就能读到。如果是外层函数调用了两次，就是两份独立的变量，互不影响。

ES 模块和闭包有什么关系？

模块的最外层也是一个作用域。模块里没有导出的变量，外面拿不到，但模块导出的函数可以用它们。所以导出的函数其实就是闭包，它记住了模块里的私有变量。

怎样避免闭包带来的内存问题？

关键是用完就断开引用。组件卸载时移除事件监听、清掉定时器；缓存要设置上限或者过期时间；不要让长期存在的闭包引用用不到的大对象。
