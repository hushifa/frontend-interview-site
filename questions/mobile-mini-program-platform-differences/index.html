Web、微信小程序和跨端框架的运行边界有什么不同？

从运行环境、组件模型、网络权限、生命周期和发布约束比较 Web、小程序与跨端框架，帮助面试时说明选型依据和迁移成本。

参考答案

简答

  • 小程序分为逻辑层和视图层，业务 JS 不运行在浏览器文档中，没有 document、window，不能用依赖 DOM 的库。
  • 组件、样式和网络请求都使用平台规定的语法和 API，请求域名要在后台配置白名单。
  • 跨端框架（Taro、uni-app 等）把一套代码编译到多个平台，能复用业务逻辑和大部分组件，但平台能力、审核和性能差异依旧存在。
  • 小程序有应用、页面、组件三层生命周期，页面隐藏时可能仍留在页面栈中，资源要按显示/隐藏暂停和恢复。
  • 小程序和 App 要经过平台审核才能发布，回滚也比 Web 慢，核心规则必须放在服务端。

运行环境

组件和样式

小程序使用 WXML 模板和 WXSS 样式，支持的选择器和 CSS 能力是浏览器的子集。Web 组件库通常依赖 DOM 查询、Portal、全局事件和浏览器焦点模型，不能直接搬进小程序。

跨端框架可以统一组件名，但属性默认值、事件冒泡和尺寸测量时机仍可能不同。实际做法是统一设计 token 和交互规范，各平台实现自己的组件适配层。

网络请求和登录

  • 小程序用 wx.request 发请求，域名必须是在后台配置过的 HTTPS 域名，没有 CORS 但也没有浏览器 Cookie 自动管理。
  • 登录用 wx.login 拿到临时 code，发给服务端换取用户标识和会话，服务端不能信任前端传来的用户 ID 或平台标识。
  • 流式响应、文件上传、WebSocket 在不同平台的支持和限制不同，请求封装要统一超时、取消和错误格式，并为不支持的能力提供降级。

生命周期

小程序页面跳转后，上一页通常留在页面栈中只是被隐藏。在 onHide 不暂停的定时器、WebSocket、定位监听会继续运行；返回后再次在 onShow 注册又会重复。资源应在显示时创建或恢复、隐藏时暂停、onUnload 时释放。

性能

逻辑层和视图层通过序列化消息通信，传输的数据越大越慢，性能要用开发者工具和真机测量，见《setData 为什么会慢？如何优化小程序的数据更新？》。

能力和权限

相机、相册、定位、蓝牙等能力的授权时机和被拒绝后的再次申请规则各平台不同。在适配层统一返回"成功 / 用户取消 / 权限拒绝 / 不支持 / 失败"几种结果，业务代码按结果处理，不要散落各平台的错误码判断。权限说明在用户需要该功能时再出现。

选型

  • 内容、表单、列表为主的业务：跨端框架复用率高，适合多端同时上线。
  • 需要 SEO、复杂 DOM 编辑器或浏览器扩展：以 Web 为主。
  • 重度依赖系统能力或高性能动画：评估原生或 React Native 等方案。

面试中可以说明复用的是哪部分（业务规则、数据模型、请求层、设计 token），哪部分需要按平台实现，以及审核和回滚对发布流程的影响。

常见追问

  • 小程序里能用 npm 包吗？可以使用不依赖 DOM 和 Node 内置模块的包，需要经过开发者工具构建 npm。
  • 小程序和 H5 能共享登录态吗？不能直接共享 Cookie，通常由服务端把小程序会话换成 H5 可用的短期凭证，再通过 web-view 打开 H5。
