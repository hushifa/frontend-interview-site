IndexedDB 为什么比 localStorage 更适合大型离线数据？

IndexedDB 提供异步的对象存储、索引和事务，能保存结构化数据，适合离线记录与较大缓存。localStorage 是同步键值存储，通常以字符串处理数据，大量读写可能影响主线程响应。

参考答案

IndexedDB 提供异步的对象存储、索引和事务，能保存结构化数据，适合离线记录与较大缓存。localStorage 是同步键值存储，通常以字符串处理数据，大量读写可能影响主线程响应。

浏览器问题通常同时涉及页面生命周期、事件循环、渲染调度和资源状态。排查时先记录触发顺序和页面可见性，再用 Performance、Network 或对应的 Application 面板确认事实，不要只根据某一次 console 输出推断机制。

使用 IndexedDB 时需要规划数据库版本、对象仓库和索引；升级期间还要处理其他标签页持有旧连接导致的阻塞。事务有生命周期限制，不应假设任意异步等待之后它仍然活跃。

浏览器配额、用户清理和存储回收会影响可用数据，因此本地存储不等于永久备份。业务关键数据要有同步或导出方案，并处理写入失败、版本迁移失败和不可用环境。

跨浏览器或跨页面场景要考虑特性检测、恢复路径和清理时机。只在首次加载事件里写逻辑，往往会漏掉回退、前进、恢复和后台切换等状态。

实际项目里，页面不只有首次打开这一种生命周期。回退恢复、标签页切换、网络变化和窗口失焦都可能让旧状态重新出现；相关逻辑要能重复执行，也要能在页面销毁或状态过期时清理。
