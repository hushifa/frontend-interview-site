IndexedDB 为什么比 localStorage 更适合大型离线数据？

IndexedDB 是浏览器里的异步数据库，能存对象和文件、建索引查询，容量比 localStorage 大得多。代价是 API 偏底层，要处理版本升级和事务。

参考答案

简答

做一个离线笔记应用，要存几千条笔记和图片。localStorage 不合适：它是同步的，数据一大，读写就会卡住页面；而且只能存字符串，容量通常也就 5MB 左右。

IndexedDB 是浏览器里的数据库。它是异步的，读写不阻塞主线程；能直接存对象、Blob、ArrayBuffer，不用转成字符串；还能建索引、按范围查询。

所有读写都在事务里进行，失败时整体回滚。容量由浏览器的存储配额决定，通常比 localStorage 大得多。

代价是 API 比较底层。要注意两个坑：事务会自动提交，中间不能 await 网络请求；升级数据库版本时，其他标签页的旧连接会挡住升级。

先认识几个概念

数据库有名字和版本号，用 indexedDB.open(name, version) 打开。版本号变大时会触发 upgradeneeded 事件，建表、建索引只能在这个事件里做。

IndexedDB 里的“表”叫对象仓库（object store），每条记录用 keyPath 指定的字段或者自增主键来标识。索引让你能按别的字段查，比如按 updatedAt 排序。

所有读写都要先开一个事务，指定是 readonly 还是 readwrite，以及要操作哪些对象仓库。

先看一个例子

下面打开笔记数据库，再保存一条笔记：

JavaScript
function openDB() {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open('notes', 2);
    request.onupgradeneeded = () => {
      const db = request.result;
      if (!db.objectStoreNames.contains('notes')) {
        const store = db.createObjectStore('notes', { keyPath: 'id' });
        store.createIndex('byUpdatedAt', 'updatedAt');
      }
    };
    request.onsuccess = () => {
      const db = request.result;
      // 其他标签页要升级版本时关闭旧连接，避免阻塞对方
      db.onversionchange = () => db.close();
      resolve(db);
    };
    request.onerror = () => reject(request.error);
    request.onblocked = () => reject(new Error('其他标签页仍在使用旧版本数据库'));
  });
}

async function saveNote(note) {
  const db = await openDB();
  return new Promise((resolve, reject) => {
    const tx = db.transaction('notes', 'readwrite');
    tx.objectStore('notes').put(note);
    tx.oncomplete = () => resolve();
    tx.onerror = () => reject(tx.error);
    tx.onabort = () => reject(tx.error ?? new Error('事务已中止'));
  });
}

代码不短，因为原生 API 全是事件回调，要自己包成 Promise。实际项目一般用 idb 这类封装库，少写很多样板代码。

为什么事务里不能 await 网络请求

事务有个规则：当它没有待处理的请求时，就会自动提交。你在事务中间 await fetch()，等待网络的这段时间里事务没有请求要处理，于是先提交了。等数据回来再往里写，就会抛 TransactionInactiveError。

所以要先把网络数据取回来，再开事务写进去。

版本升级为什么会卡住

假设用户开着两个标签页，你上线了新版本，新标签页要把数据库从版本 1 升到 2。可是旧标签页还连着版本 1，升级就会被挡住，触发 blocked。

解决办法就是例子里那行：旧连接监听 versionchange，收到后调用 db.close()，把路让出来。

数据一定能保住吗

不一定。存储压力大时，浏览器可能清理数据。重要数据可以调用 navigator.storage.persist() 申请持久化，同时在服务端留备份。部分浏览器在隐私模式下容量很小，或者窗口一关数据就清掉了。

常见追问

有了 IndexedDB，还用 localStorage 吗？

用。少量、同步读一下就够的配置，比如主题，用 localStorage 更省事。

IndexedDB 能跨源共享吗？

不能。它和 localStorage 一样按源隔离，每个源只能访问自己的数据库。
