StorageManager 能告诉我们浏览器存储的哪些信息？

navigator.storage 能估算当前网站用了多少空间、还能用多少，能申请让数据不被浏览器自动清除，还能打开 OPFS 文件系统。返回的数字都是估算值。

参考答案

简答

离线应用要下载几百兆数据，下载前得先知道空间够不够。navigator.storage.estimate() 返回 { usage, quota }，也就是当前网站在 IndexedDB、Cache Storage、OPFS 这些地方的估算用量，以及可用的配额。

默认情况下，浏览器对存储是“尽力而为”的，存储压力大时可能把你的数据清掉。persist() 用来申请持久存储，persisted() 查询是否已经拿到了。

另外 getDirectory() 返回源私有文件系统的根目录，也就是 OPFS，适合存大文件和数据库文件。

要注意，这些数字都是估算值。不同浏览器的配额策略不一样，不能当成精确容量来用。

先看怎么查询和申请

JavaScript
async function checkStorage() {
  const { usage = 0, quota = 0 } = await navigator.storage.estimate();
  const persisted = await navigator.storage.persisted();
  return {
    usedMB: Math.round(usage / 1024 / 1024),
    quotaMB: Math.round(quota / 1024 / 1024),
    persisted,
  };
}

async function requestPersistence() {
  if (!navigator.storage?.persist) return false;
  if (await navigator.storage.persisted()) return true;
  return navigator.storage.persist();
}

checkStorage 把用量和配额换算成 MB，顺便查一下是不是已经持久化了。requestPersistence 先看浏览器支不支持，已经拿到了就不再申请。

估算值为什么不能全信

下载大量离线数据前，可以先算一下剩余空间 quota - usage，不够就提示用户。可是写入时仍然要处理 QuotaExceededError，因为估算值和实际能写进去的空间可能不一样。

quota 也不等于你硬盘的真实剩余空间。浏览器是故意这么做的，防止网站通过它探测用户的磁盘有多大。

申请持久存储会发生什么

不同浏览器处理方式不同。Chrome 会根据用户和这个网站的互动程度，自动决定给不给，不会弹窗。Firefox 会弹出提示，问用户同不同意。

拿到持久存储也不是万无一失。用户仍然可以在浏览器设置里手动清除数据，所以重要数据还得在服务端留备份。

常见追问

无痕模式下配额会怎样？

通常会小很多，而且窗口一关，数据就被清除了。

存储空间是按什么划分的？

按源划分。在第三方 iframe 里，还会按顶层站点再分区，同一个源嵌在不同网站里，用的是不同的存储。
