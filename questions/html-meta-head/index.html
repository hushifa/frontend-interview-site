head 中哪些信息会影响页面体验与收录？

head 里的信息各管一摊：charset 和 viewport 管显示，title 和 description 管搜索结果长什么样，canonical 和 robots 管收不收录，Open Graph 管分享卡片。每个页面都要写和自己内容对应的值。

参考答案

简答

先说显示。<meta charset="utf-8"> 要放在 head 最前面，不然中文可能是乱码。<meta name="viewport" content="width=device-width, initial-scale=1"> 让手机按设备宽度来布局。不要加 user-scalable=no 或 maximum-scale=1，这会让用户没法放大页面。

再说搜索结果。<title> 是标签页上的名字，也是搜索结果的标题，每个页面都要不一样。description 常被用作搜索结果里的摘要，不过搜索引擎可能会自己改写。

然后是收录。同一份内容可能有好几个网址，比如带了筛选参数、分页参数、追踪参数，<link rel="canonical"> 指明哪个是首选地址。<meta name="robots" content="noindex"> 是不让搜索引擎收录，测试环境的 noindex 千万不能带到正式环境。

最后，分享到社交平台时显示的卡片，由 Open Graph 的 og: 系列标签决定。

一个完整的 head

HTML
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>闭包是什么？ - 前端面试题</title>
  <meta name="description" content="闭包是函数和其创建时词法环境的组合……">
  <link rel="canonical" href="https://example.com/questions/js-closure">

  <meta property="og:title" content="闭包是什么？">
  <meta property="og:description" content="闭包是函数和其创建时词法环境的组合……">
  <meta property="og:image" content="https://example.com/og/js-closure.png">
  <meta property="og:url" content="https://example.com/questions/js-closure">

  <link rel="icon" href="/favicon.svg" type="image/svg+xml">
  <meta name="theme-color" content="#ffffff">
</head>

从上往下是：编码、视口、标题和摘要、规范地址、分享卡片，最后是图标和浏览器主题色。注意 canonical、og:image、og:url 写的都是完整的绝对地址。

最容易犯的错误

单页应用所有路由共用一个 title 和 description，搜索结果里每一条看起来都一样。要在切换路由时更新它们，或者把每个页面预渲染出来。

canonical 写成相对地址，或者所有页面都指向首页。搜索引擎会以为这些页面都是首页的重复，其他页面就不收录了。

og:image 用了相对路径。社交平台抓取时不知道相对于哪里，图片显示不出来，必须用绝对 URL。

在 robots.txt 里禁止抓取某个页面，同时又想靠 noindex 把它从搜索结果里移除。这两个是冲突的：爬虫不能抓这个页面，也就读不到上面的 noindex，页面反而可能一直留在结果里。

还有哪些相关的写法

<html lang="zh-CN"> 写在 html 标签上，不在 head 里。它影响读屏怎么发音、怎么断词，以及浏览器要不要提示翻译。

preconnect、preload 这些资源提示也放在 head 里，但它们影响的是加载速度，跟收录没关系。

结构化数据用 <script type="application/ld+json"> 写，能帮搜索引擎生成带评分、价格这类信息的富摘要。

常见追问

keywords 还有用吗？

主流搜索引擎早就不把 <meta name="keywords"> 当排名依据了，可以不写。
