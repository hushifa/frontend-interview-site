async/await 如何处理异常和并发？

async 函数总是返回 Promise，异步代码里 throw 就等于返回一个失败的 Promise，用 await 加 try/catch 就能像同步代码一样捕获。几个任务是不是并行，要看它们什么时候开始，而不是什么时候 await。

参考答案

简答

async 函数调用时，会先同步执行到第一个 await，然后马上返回一个 Promise。函数里 return 的值让这个 Promise 成功，throw 的错误让它失败，也就是拒绝。

await 一个失败的 Promise，错误会在 await 这一行抛出来，所以可以直接用 try/catch 接住。但有个细节：在 try 里写 return p，p 失败时本地的 catch 接不到，错误会直接交给调用方；写成 return await p 才能在本地捕获。

并发的关键是任务什么时候启动。先把几个任务都启动，再用 Promise.all 一起等，是并行；一个 await 完再 await 下一个，就是串行。

另外 fetch 遇到 404、500 不会拒绝，只有网络层失败才会，所以要自己检查 response.ok。

async 函数什么时候开始执行，什么时候暂停

下面的例子用日志标出执行顺序，注意“函数内”和“调用后”谁先出现。

JavaScript
console.log('调用前');

async function task() {
  console.log('函数内');
  await 42;
  console.log('恢复');
  return 7;
}

const promise = task();
console.log('调用后');
promise.then(value => console.log(value));
// 输出顺序：调用前 → 函数内 → 调用后 → 恢复 → 7

很多人以为调用 async 函数时，函数体会“异步地”执行，可“函数内”其实紧跟在“调用前”后面。async 函数在第一个 await 之前是同步运行的。

遇到 await 以后，这个函数暂停，控制权回到调用方，所以接着打印“调用后”。等调用方的同步代码跑完，函数才在微任务里恢复，打印“恢复”。微任务就是当前同步代码执行完后立刻处理的一批回调，详见《事件循环中，任务和微任务按什么顺序执行？》。注意 await 42 等的只是个普通值，恢复也一样要排到微任务里，不会立刻接着执行。

所以 await 暂停的只是这个函数，线程并没有停。反过来，第一个 await 之前如果有耗时的计算，它照样会卡住调用方。

为什么 return p 时 catch 接不到错误

JavaScript
function failLater() {
  return Promise.reject(new Error('任务失败'));
}

async function directReturn() {
  try {
    return failLater();
  } catch {
    return '当前函数已捕获';
  }
}

async function awaitedReturn() {
  try {
    return await failLater();
  } catch {
    return '当前函数已捕获';
  }
}

async function demonstrate() {
  const direct = await directReturn().catch(error => `外层接到：${error.message}`);
  console.log(direct); // 外层接到：任务失败
  console.log(await awaitedReturn()); // 当前函数已捕获
}

demonstrate();

两个函数只差一个 await，可 directReturn 的 catch 完全没起作用，错误跑到了外层。

原因是 return failLater() 把 Promise 原样交了出去，这一行本身没有出错，try 就正常结束了。Promise 后来失败时，已经离开了 try，失败只能落到 async 函数返回的那个 Promise 上，由调用方处理。return await 会在 try 里面等结果，失败就在这一行抛出，本地 catch 才能接住。

finally 也有同样的问题。直接 return p 时，finally 会在 p 完成之前就运行，所以资源要保留到任务结束，就得写 return await。如果不在 try 里，这两种写法效果一样。

怎样让几个请求并行

JavaScript
async function loadUser() {
  return { id: 1 };
}

async function loadPermissions() {
  return ['read'];
}

async function initialize() {
  const [user, permissions] = await Promise.all([
    loadUser(),
    loadPermissions(),
  ]);
  console.log(`${user.id}:${permissions.join(',')}`); // 1:read
}

initialize();

两个函数在构造数组的时候就都调用了，请求已经一起发出去，Promise.all 只是负责等它们都完成。如果写成 await loadUser(); await loadPermissions();，第二个要等第一个结束才开始，就变成了串行。

并行写的时候还有几点要注意。第一，后一个请求如果要用前一个的结果，比如需要 user.id，那就只能串行。第二，不要写成先 const a = loadA(); const b = loadB();，再分别 await a; await b;。如果 b 在 await a 期间就失败了，这时还没有人处理它，会先报一次未处理的拒绝，所以并行任务启动后应该马上交给 Promise.all 或 allSettled。第三，任务很多时一下全部启动可能压垮服务，要用并发池限制同时进行的数量。第四，Promise.all 失败以后，其他任务其实还在运行，要停下它们，得给它们传 AbortSignal。

请求失败要分几种情况处理

JavaScript
async function getJson(url, signal) {
  const response = await fetch(url, { signal });
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  try {
    return await response.json();
  } catch (error) {
    throw new Error('响应不是合法 JSON', { cause: error });
  }
}

一次请求可能在好几个地方失败：网络断了、用户取消（错误名是 AbortError）、服务器返回 HTTP 错误、响应不是合法 JSON、业务校验没通过。这几种的处理方式不一样，比如用户取消通常不用提示，网络失败可以让用户重试，所以要分开抛、分开处理。包装错误时把原来的错误放进 cause，排查时还能看到最初的原因。

常见追问

顶层 await 能用在哪里？

能用在 ES 模块的最顶层，浏览器控制台里也可以直接写。经典脚本和 CommonJS 模块里不行，只能在 async 函数里用。

await 一个 thenable 会怎样？

thenable 就是带 then 方法的对象。await 会调用它的 then 方法，按它给出的结果恢复执行，跟等一个真正的 Promise 一样。
