async/await 如何处理异常和并发？

async 函数总是返回 Promise，内部 throw 会变成拒绝；await 让拒绝在当前位置抛出，可用 try/catch 捕获。try 中直接 return 一个 Promise 不会被本地 catch 拦截，需要 return await。异步任务是否并行取决于何时启动，而不是何时 await。

参考答案

简答

  • async 函数调用时同步执行到第一个 await，然后返回一个 Promise；return 的值使它兑现，throw 使它拒绝。
  • await 后面的代码总是在微任务中恢复，即使等待的是普通值。
  • 在 try 里写 return await p，p 的拒绝才会进入本地 catch；直接 return p 会让拒绝绕过本地 catch，交给调用方。
  • 先启动再统一等待是并行（Promise.all([a(), b()])），逐个 await a(); await b() 是串行。
  • fetch 遇到 404、500 不会拒绝，要检查 response.ok。

执行顺序

JavaScript
console.log('调用前');

async function task() {
  console.log('函数内');
  await 42;
  console.log('恢复');
  return 7;
}

const promise = task();
console.log('调用后');
promise.then(value => console.log(value));
// 输出顺序：调用前 → 函数内 → 调用后 → 恢复 → 7

await 暂停的是这个函数的执行，线程继续执行调用方的同步代码。第一个 await 之前的耗时计算仍会阻塞调用方。

return 与 return await

JavaScript
function failLater() {
  return Promise.reject(new Error('任务失败'));
}

async function directReturn() {
  try {
    return failLater();
  } catch {
    return '当前函数已捕获';
  }
}

async function awaitedReturn() {
  try {
    return await failLater();
  } catch {
    return '当前函数已捕获';
  }
}

async function demonstrate() {
  const direct = await directReturn().catch(error => `外层接到：${error.message}`);
  console.log(direct); // 外层接到：任务失败
  console.log(await awaitedReturn()); // 当前函数已捕获
}

demonstrate();

finally 也一样：直接 return p 时，finally 会在 p 完成之前运行，需要资源保留到任务结束就要 return await。不在 try 中时，两种写法效果相同。

串行与并行

JavaScript
async function loadUser() {
  return { id: 1 };
}

async function loadPermissions() {
  return ['read'];
}

async function initialize() {
  const [user, permissions] = await Promise.all([
    loadUser(),
    loadPermissions(),
  ]);
  console.log(`${user.id}:${permissions.join(',')}`); // 1:read
}

initialize();

两个函数在构造数组时就都已调用，Promise.all 只负责等待。注意：

  • 有依赖关系（需要 user.id）的请求只能串行。
  • 先 const a = loadA(); const b = loadB(); 再分别 await a; await b; 时，如果 b 在 await a 期间拒绝，会先触发未处理拒绝警告。并行任务应立即交给 Promise.all 或 allSettled。
  • 任务很多时一次全部启动可能压垮服务，需要并发池。
  • Promise.all 失败后其他任务仍在运行，要停止它们需传入 AbortSignal。

请求的错误层次

JavaScript
async function getJson(url, signal) {
  const response = await fetch(url, { signal });
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  try {
    return await response.json();
  } catch (error) {
    throw new Error('响应不是合法 JSON', { cause: error });
  }
}

网络失败、用户取消（AbortError）、HTTP 错误、解析错误、业务校验失败应分别处理，cause 保留原始错误。

常见追问

  • 顶层 await 能用在哪里？ES 模块顶层，以及浏览器控制台；经典脚本和 CommonJS 不行。
  • await 一个 thenable 会怎样？会调用它的 then 方法，按其结果恢复。
  • 同步错误、定时器回调错误和全局兜底，见《同步错误、Promise 拒绝和全局异常应该怎样处理？》。
