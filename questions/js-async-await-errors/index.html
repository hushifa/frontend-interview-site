async/await 如何处理异常和并发？

async 函数始终返回 Promise。await 暂停的是当前异步函数后续逻辑，不会阻塞整个线程；等待的 Promise 拒绝时，会在 await 位置抛出异常，可由 try/catch 处理。

参考答案

调用 async 函数时，函数会立刻返回一个 Promise；执行到 await 时，只是把当前函数后面的逻辑拆成一次后续恢复，并把控制权交还给事件循环，不会阻塞整个 JavaScript 线程。等待的 Promise 成功，await 表达式得到它的值；Promise 拒绝，异常会在 await 这一行抛出，因此可以用普通的 try/catch 处理。

JavaScript
async function loadUser(id) {
  try {
    const response = await fetch(`/api/users/${id}`);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } catch (error) {
    // 这里可以区分网络失败、业务错误或用户主动取消
    throw new Error('用户信息加载失败', { cause: error });
  }
}

彼此独立的任务如果这样写，会一个完成后才开始下一个：

JavaScript
const user = await loadUser(id);
const permissions = await loadPermissions(id);

如果两个请求互不依赖，可以先创建 Promise，再并行等待：

JavaScript
const [user, permissions] = await Promise.all([
  loadUser(id),
  loadPermissions(id),
]);

Promise.all 在任意一个任务拒绝时会尽快拒绝，但不会自动取消其他已经开始的任务；提交、搜索和上传场景需要另行考虑 AbortController、幂等性和过期结果。任务很多或服务端有速率限制时，不能简单地一次创建几百个 Promise，而应使用并发池或分批处理。

在 try 中，return await task() 会把拒绝留在当前 try/catch 的范围内；直接 return task() 则把 Promise 交给外层，当前函数已经离开 try。finally 一定会执行，其中的 return 或新的 throw 可能覆盖原来的结果，所以通常只在 finally 中做清理。取消客户端等待也不等于服务端写入已经撤销，写操作必须能查询状态或安全重试。
