为什么 Hook 通常必须在组件顶层调用？

React 不认 Hook 的名字，只按调用顺序把每个 Hook 对应到它保存的状态。放进条件、循环或写在提前 return 后面，顺序一乱，状态就对错了。use 是唯一可以条件调用的例外。

参考答案

简答

一个组件里写了好几个 useState、useEffect，React 并不知道哪个是哪个，它只记“第 1 个 Hook、第 2 个 Hook……”，按调用顺序把每个 Hook 和内部保存的状态对上。

所以每次渲染，Hook 的调用顺序必须完全一样。如果把 Hook 放进 if、循环、嵌套函数，或者写在提前 return 的后面，某次渲染少调或多调一个，后面的状态就全对错了位置。

这条规则让 Hook 不需要传 key，自定义 Hook 也能随便组合。另外 Hook 只能在函数组件或以 use 开头的自定义 Hook 里调用。自定义 Hook 复用的是逻辑，两个组件用同一个 Hook，各自有独立的状态。

有一个例外：use(promise) 和 use(Context) 不是 Hook，可以写在条件和循环里，但也只能在组件或 Hook 中调用。

顺序乱了会发生什么

下面的组件在没有用户时先 return，Hook 写在后面：

JSX
function Profile({ user }) {
  if (!user) return null; // 错误：提前 return 在 Hook 之前
  const [tab, setTab] = useState('posts');
  useEffect(() => { document.title = user.name; }, [user.name]);
  // ...
}

第一次渲染 user 是 null，组件直接返回，一个 Hook 都没调。等 user 变成对象，这次渲染调了两个 Hook，比上次多了。React 发现对不上，会报错 “Rendered more hooks than during the previous render”。

改法是把所有 Hook 挪到提前 return 前面，条件写进 Hook 里面：

JSX
function Profile({ user }) {
  const [tab, setTab] = useState('posts');
  useEffect(() => {
    if (user) document.title = user.name;
  }, [user]);
  if (!user) return null;
  // ...
}

现在不管 user 是不是空，每次渲染都调同样两个 Hook，顺序永远一致。

真的需要“有条件地用 Hook”怎么办

有两种思路。条件只影响要不要做某件事，就把 if 写进 Effect 的函数体里，像上面那样。

如果是一整块逻辑要不要启用，就把它拆成子组件，用条件渲染决定渲不渲染这个子组件。子组件内部照常在顶层调 Hook，它要么整个存在，要么整个不存在，顺序不会乱。

自定义 Hook 复用的是逻辑，不是状态

下面写一个开关 Hook，同一个组件里调用两次：

JSX
function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = useCallback(() => setOn((v) => !v), []);
  return [on, toggle];
}

function Panel() {
  const [open, toggleOpen] = useToggle();
  const [pinned, togglePinned] = useToggle(true);
  // open 和 pinned 互不影响
}

useToggle 本质上就是把 useState 和 useCallback 打了个包。调用两次，就等于在 Panel 里按顺序调了两组 Hook，各有各的状态。所以切换 open 不会影响 pinned。

如果想让多个组件共享同一份状态，自定义 Hook 做不到，要把状态提升到共同的父组件，或者用 Context、外部 store。

让工具帮你检查

eslint-plugin-react-hooks 的 rules-of-hooks 规则会检查 Hook 的调用位置，exhaustive-deps 检查依赖数组。新版的推荐预设还带上了 React Compiler 相关的规则，项目里应该默认开着。

常见追问

React 为什么不按名字保存状态？

按顺序存储，Hook 就不用传一个 key 进去。自定义 Hook 也能任意组合，不用担心两个 Hook 内部用了同一个名字而冲突。

use 为什么可以条件调用？

因为它读的是你传进去的东西本身，也就是那个 Promise 或 Context，不需要靠调用顺序去找自己的状态。
