为什么 Hook 通常必须在组件顶层调用？

React 按 Hook 的调用顺序把每个 useState、useEffect 对应到组件内部保存的状态槽。条件、循环或提前 return 改变了调用顺序，状态就会对错位置。条件逻辑应写在 Hook 内部，use API 是唯一可以条件调用的例外。

参考答案

简答

  • React 不知道每个 Hook 的"名字"，只按调用顺序把第 1 个、第 2 个 Hook 和内部保存的状态对应起来。
  • 每次渲染的 Hook 调用顺序必须一致，所以不能在条件、循环、嵌套函数或提前 return 之后调用 Hook。
  • Hook 只能在函数组件或自定义 Hook（名称以 use 开头）中调用，不能在普通函数或类组件里调用。
  • 自定义 Hook 复用的是逻辑，不是状态：两个组件调用同一个 Hook，各自有独立的 state。
  • use(promise) 和 use(Context) 不是 Hook，可以写在条件和循环里，但仍然只能在组件或 Hook 中调用。

顺序错位会发生什么

JSX
function Profile({ user }) {
  if (!user) return null; // 错误：提前 return 在 Hook 之前
  const [tab, setTab] = useState('posts');
  useEffect(() => { document.title = user.name; }, [user.name]);
  // ...
}

user 从 null 变成对象时，这次渲染比上次多调用了两个 Hook，React 会报错 "Rendered more hooks than during the previous render"。正确写法是把所有 Hook 放在提前 return 之前：

JSX
function Profile({ user }) {
  const [tab, setTab] = useState('posts');
  useEffect(() => {
    if (user) document.title = user.name;
  }, [user]);
  if (!user) return null;
  // ...
}

条件写在 Hook 内部或组件边界上

  • 条件同步：把 if 写进 Effect 的函数体里。
  • 条件使用整块逻辑：把逻辑拆成子组件，用条件渲染决定是否渲染这个子组件，子组件内部照常调用 Hook。

自定义 Hook

JSX
function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = useCallback(() => setOn((v) => !v), []);
  return [on, toggle];
}

function Panel() {
  const [open, toggleOpen] = useToggle();
  const [pinned, togglePinned] = useToggle(true);
  // open 和 pinned 互不影响
}

需要多个组件共享同一份状态时，把状态提升到共同的父组件，或使用 Context 和外部 store。

工具检查

eslint-plugin-react-hooks 的 rules-of-hooks 规则会检查调用位置，exhaustive-deps 检查依赖数组。新版的推荐预设还包含 React Compiler 相关规则，应在项目中默认开启。

常见追问

  • 为什么 React 不按名字保存状态？按顺序存储让 Hook 不需要传入 key，也便于自定义 Hook 任意组合而不产生命名冲突。
  • use 为什么可以条件调用？它读取的是传入的资源本身（Promise 或 Context），不依赖调用顺序来定位状态。
