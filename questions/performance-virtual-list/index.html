动态高度的虚拟列表怎样处理测量、滚动锚点和焦点？

行高不固定时，先用估计高度计算位置，行挂载后用 ResizeObserver 测量真实高度并按数据 ID 缓存，再修正后续行的偏移。前方内容高度变化时，要按锚点行补偿滚动位置；被卸载的行会丢失焦点和输入状态，需要单独保留。

参考答案

简答

  • 固定行高可以直接算出位置（原理见《虚拟列表通过什么方式减少渲染成本？》）；动态高度要维护"每行高度"的缓存和前缀和。
  • 未测量的行用估计高度，挂载后测量真实高度，更新缓存和总高度。
  • 高度缓存按数据 ID 存，排序、筛选、插入后索引会变，按索引存会错位。
  • 前方的行变高或在顶部插入数据时，记录锚点行的 ID 和它离视口顶部的距离，测量完成后补偿 scrollTop，否则内容会跳动。
  • 正在编辑或获得焦点的行离开窗口会被卸载，要把状态提升到列表外，或暂时保留这一行。

测量与定位

JavaScript
const heights = new Map(); // String(id) -> 实测高度；dataset 读出的总是字符串，两边统一成字符串
const ESTIMATE = 60;

function layout(items) {
  const offsets = new Array(items.length + 1);
  offsets[0] = 0;
  for (let i = 0; i < items.length; i += 1) {
    offsets[i + 1] = offsets[i] + (heights.get(String(items[i].id)) ?? ESTIMATE);
  }
  return offsets; // offsets[i] 是第 i 行的顶部，offsets[length] 是总高度
}

function findStart(offsets, scrollTop) {
  if (offsets.length < 2) return 0; // 空列表
  let low = 0;
  let high = offsets.length - 2;
  while (low < high) {
    const mid = (low + high + 1) >> 1;
    if (offsets[mid] <= scrollTop) low = mid;
    else high = mid - 1;
  }
  return low;
}

const observer = new ResizeObserver((entries) => {
  for (const entry of entries) {
    const id = entry.target.dataset.id;
    heights.set(id, entry.borderBoxSize[0].blockSize);
  }
  scheduleRelayout(); // 在下一帧统一重新计算，避免反复读写布局
});

数据量很大时，每次全量计算前缀和成本较高，可以只从变化的那一行往后更新，或使用树状数组。

滚动锚点

JavaScript
function captureAnchor(viewport, offsets, items) {
  const index = findStart(offsets, viewport.scrollTop);
  return { id: items[index].id, delta: viewport.scrollTop - offsets[index] };
}

function restoreAnchor(viewport, offsets, items, anchor) {
  const index = items.findIndex((item) => item.id === anchor.id);
  if (index >= 0) viewport.scrollTop = offsets[index] + anchor.delta;
}
  • 聊天记录向上加载历史消息时，插入前记录锚点，插入并测量后恢复。
  • 浏览器有原生的滚动锚定（CSS overflow-anchor），但虚拟列表通过绝对定位或 transform 摆放行，原生锚定通常不起作用，需要自己补偿，并对容器设置 overflow-anchor: none 避免两者冲突。
  • 用户正在拖动滚动条时不要强行修正位置。

焦点和无障碍

  • 键盘移动到未挂载的行时，先滚动到目标位置，等行渲染后再调用 focus()。
  • 为行设置 aria-setsize、aria-posinset，让读屏器知道总数和当前位置。
  • aria-activedescendant 指向的元素必须真实存在于 DOM 中。
  • 编辑中的草稿保存在按 ID 索引的状态里，行卸载再挂载时恢复。

不适合虚拟化的场景

浏览器的页面查找（Ctrl+F）、全选复制、打印只能处理已挂载的行。需要这些能力的长文档、报表，用分页、分段渲染或 content-visibility: auto 更合适。

常见追问

  • 图片加载后行高变化怎么办？给图片设置 width、height 或 aspect-ratio 预留空间，减少测量后的跳动。
  • 估计高度怎么选？用已测量行的平均值动态更新，总高度会更接近真实值，滚动条跳动更小。
