动态高度的虚拟列表怎样处理测量、滚动锚点和焦点？

行高不固定时，先用估计高度算位置，行挂载后用 ResizeObserver 测出真实高度，按数据 ID 缓存，再修正后面各行的偏移。前面的内容高度变了，要按锚点行补偿滚动位置；被卸载的行会丢掉焦点和输入状态，要单独保留。

参考答案

简答

行高固定时，第几行在哪个位置直接乘一下就出来了，原理见《虚拟列表通过什么方式减少渲染成本？》。可是聊天记录、评论这种列表，每行高度都不一样，而且不渲染出来就不知道多高。

做法是先猜。没测过的行用一个估计高度算位置，行挂载以后用 ResizeObserver 测出真实高度，存进缓存，再重新算后面各行的位置和总高度。缓存要按数据 ID 存，因为排序、筛选、插入以后下标会变，按下标存就错位了。

测量会带来一个问题：前面的行从估计值变成真实高度，后面的内容就会整体移动，用户看到的内容会跳。解决办法是记一个锚点，也就是视口顶部那一行的 ID 和它离视口顶部的距离，测量完以后把 scrollTop 补回去。

还要注意，正在编辑或者获得焦点的行一旦滚出窗口就会被卸载，焦点和输入内容都会丢。所以要把这些状态提到列表外面，或者暂时保留这一行。

怎样根据缓存的高度算位置

思路是维护一个前缀和数组 offsets：offsets[i] 是第 i 行的顶部位置，等于前面所有行高加起来。下面是计算和查找的代码：

JavaScript
const heights = new Map(); // String(id) -> 实测高度；dataset 读出的总是字符串，两边统一成字符串
const ESTIMATE = 60;

function layout(items) {
  const offsets = new Array(items.length + 1);
  offsets[0] = 0;
  for (let i = 0; i < items.length; i += 1) {
    offsets[i + 1] = offsets[i] + (heights.get(String(items[i].id)) ?? ESTIMATE);
  }
  return offsets; // offsets[i] 是第 i 行的顶部，offsets[length] 是总高度
}

function findStart(offsets, scrollTop) {
  if (offsets.length < 2) return 0; // 空列表
  let low = 0;
  let high = offsets.length - 2;
  while (low < high) {
    const mid = (low + high + 1) >> 1;
    if (offsets[mid] <= scrollTop) low = mid;
    else high = mid - 1;
  }
  return low;
}

const observer = new ResizeObserver((entries) => {
  for (const entry of entries) {
    const id = entry.target.dataset.id;
    heights.set(id, entry.borderBoxSize[0].blockSize);
  }
  scheduleRelayout(); // 在下一帧统一重新计算，避免反复读写布局
});

findStart 用二分查找，找最后一个顶部不超过 scrollTop 的行，它就是视口里第一个可见的行。比如四行里第二行实测是 100px、其余按估计的 60px，offsets 就是 [0, 60, 160, 220, 280]，滚动到 150px 时找到的是下标 1。

为什么键要统一成字符串？因为 dataset.id 读出来永远是字符串。如果存的时候用数字 2，取的时候用字符串 '2'，Map 会认为这是两个不同的键，缓存就永远查不到。

ResizeObserver 的回调里只写缓存，重新计算放到下一帧统一做，这样多行同时测完也只算一次。

数据量很大时，每次全量重算前缀和的成本会比较高，可以只从变化的那一行往后更新，或者用树状数组。

怎样让内容不跳

在高度变化或者插入数据之前，先记下锚点；变化完以后，按锚点把滚动位置补回去：

JavaScript
function captureAnchor(viewport, offsets, items) {
  const index = findStart(offsets, viewport.scrollTop);
  return { id: items[index].id, delta: viewport.scrollTop - offsets[index] };
}

function restoreAnchor(viewport, offsets, items, anchor) {
  const index = items.findIndex((item) => item.id === anchor.id);
  if (index >= 0) viewport.scrollTop = offsets[index] + anchor.delta;
}

delta 是视口顶部比锚点行顶部多滚了多少。恢复时用新的 offsets 找到这一行现在的位置，再加上 delta，用户看到的画面就和之前一样。锚点用 ID 而不是下标，是因为在顶部插入数据以后，同一行的下标就变了。

最典型的场景是聊天记录往上加载历史消息：插入前记录锚点，插入并测量完以后恢复。

浏览器其实有原生的滚动锚定，就是 CSS 的 overflow-anchor。可是虚拟列表通常用绝对定位或者 transform 摆放行，原生锚定一般不起作用，所以要自己补偿，并且给容器设 overflow-anchor: none，避免两者打架。

另外，用户正在拖滚动条时不要强行修正位置，否则滚动条会在手底下乱跳。

焦点和读屏器怎么处理

键盘移动到一个还没挂载的行时，要先滚动到目标位置，等这一行渲染出来，再调用 focus()。

给每行设置 aria-setsize 和 aria-posinset，读屏器才知道一共有多少行、当前是第几行。如果用了 aria-activedescendant，它指向的元素必须真实存在于 DOM 里。

编辑中的草稿保存在按 ID 索引的状态里，行卸载再挂载回来时恢复。

什么时候不该虚拟化

浏览器的页面查找（Ctrl+F）、全选复制、打印，都只能处理已经挂载的行。如果长文档、报表需要这些能力，用分页、分段渲染或者 content-visibility: auto 更合适。

常见追问

图片加载完行高又变了，怎么办？

给图片设置 width、height 或 aspect-ratio，先把位置留好，测量以后跳动就小了。

估计高度应该怎么选？

用已经测过的行的平均高度动态更新估计值。这样总高度更接近真实值，滚动条的跳动也更小。
