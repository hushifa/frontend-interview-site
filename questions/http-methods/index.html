HTTP 方法的安全性和幂等性是什么意思？

安全方法只读不改，比如 GET；幂等方法执行一次和执行多次效果一样，比如 PUT、DELETE。POST 和 PATCH 不保证幂等，重试前要靠幂等键防止重复。

参考答案

简答

安全的意思是只读，不改服务器上的资源。GET、HEAD、OPTIONS、TRACE 都是安全方法。

幂等的意思是同一个请求发一次和发十次，对服务器的效果一样。所有安全方法都是幂等的，另外 PUT 和 DELETE 也是。

这两个概念有用，是因为浏览器、代理和客户端库会依赖它们。比如网络断了，客户端敢自动重试幂等请求；可是 POST 和 PATCH 不保证幂等，超时后自动重试 POST，可能就下了两次单。

要注意，这些是协议约定，得服务端按约定去实现。拿 GET 去做删除，就破坏了约定。

为什么这些约定很重要

很多工具会默认相信这些语义。连接中断时，客户端可以自动重试幂等请求，因为多发一次也没关系。

预取、爬虫和聊天软件的链接预览会随手访问 GET 链接。如果某个 GET 链接有副作用，比如“点一下就删除”，它可能被这些工具意外触发。

缓存也主要只针对 GET 和 HEAD 的响应。

幂等看的是效果，不是响应

很多人会把幂等理解成“每次返回的结果一样”，这是不对的。

比如 DELETE /orders/1，第一次返回 204，第二次返回 404。响应不同，但服务器的状态一样，订单都不存在了，所以它仍然是幂等的。

PUT /users/1 是用完整的内容覆盖资源，重复执行结果一样。PATCH 是否幂等要看补丁内容：{"name": "A"} 发几次结果都是 A，是幂等的；“计数加一”每发一次就多一，就不是。

怎样让 POST 也能安全重试

办法是让客户端给这次操作生成一个唯一的键，叫幂等键，服务器按键去重。

JavaScript
const key = crypto.randomUUID();

async function createOrder(payload) {
  return fetch('/api/orders', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Idempotency-Key': key,
    },
    body: JSON.stringify(payload),
  });
}

注意 key 是在函数外面生成的，重试时用的是同一个键。服务器第一次处理后把“键 → 结果”存起来，同一个键再来，就直接返回存好的结果，不会再下一次单。

Idempotency-Key 这个请求头目前还是 IETF 草案，不过很多支付类 API 已经在用同名的约定。

常见追问

GET 能带请求体吗？

规范没有定义 GET 请求体的含义，很多服务器和代理会忽略或拒绝它，所以不要依赖。

表单为什么只支持 GET 和 POST？

HTML 表单的 method 只定义了这两个值，再加一个对话框用的 dialog。其他方法要用 fetch 发。
