隐式类型转换有哪些容易踩坑的规则？

不同运算会把值转成不同类型。条件判断转布尔，减乘除转数字，加号只要有一边是字符串就拼接。对象要先转成原始值再参与运算。

参考答案

简答

隐式转换就是运算时 JavaScript 自动帮你换类型，换成什么取决于运算本身。if 判断换成布尔，-、*、/ 换成数字，所以 '5' - 2 是 3。

最容易错的是加号。+ 先把两边都转成原始值，有一边是字符串就拼接，否则才做数字加法，所以 [] + 1 得到的是字符串 '1'。对象转原始值时，会依次尝试 Symbol.toPrimitive、valueOf、toString；在需要字符串的场合，会先试 toString。

判断真假也要注意。假值只有 undefined、null、false、0、-0、0n、NaN 和空字符串，空数组、空对象、'0'、'false' 全都是真值。

字符串转数字时，Number 要求整个字符串都是数字，空字符串得 0；parseInt 只读开头的数字部分，'12px' 得 12。两者都不能当输入校验用。

哪些值是假值

JavaScript
console.log(Boolean([])); // true
console.log(Boolean('0')); // true
console.log(Number('')); // 0
console.log(parseInt('12px', 10)); // 12

空数组是真值，字符串 '0' 也是真值，因为它们不在那 8 个假值里。

实际写代码时，这会带来一个常见 bug：if (count) 本来想判断“有没有数量”，结果合法的 0 也被当成“没有”。所以判断数组是否为空要看 length，判断字段是否缺失用 value == null 或 ??，它们只把 null 和 undefined 当成缺失。

加号为什么有时拼接有时相加

JavaScript
console.log('5' + 2); // 52
console.log('5' - 2); // 3
console.log([] + 1);  // 1，字符串
console.log(typeof ([] + 1)); // string
console.log(1 + true); // 2
console.log(1 + null); // 1
console.log(1 + undefined); // NaN

同样是 '5' 和 2，加号得到 '52'，减号得到 3。减号只有减法一个意思，只能转数字；加号既能拼字符串又能做加法，所以要先看两边。

[] + 1 的过程是：[] 先转原始值，得到空字符串 ''；这时有一边是字符串了，就拼接成 '1'。如果两边都不是字符串，就都转成数字相加，true 转成 1，null 转成 0，undefined 转成 NaN。

还有两种类型比较特殊。BigInt 和 Number 混在一起做算术会抛 TypeError，比如 1n + 1；但 BigInt 和字符串相加还是会拼接。Symbol 不能被隐式转成字符串或数字，强行转会抛错。

对象怎样变成原始值

对象参与运算前，要先变成原始值。对象可以用 Symbol.toPrimitive 自己决定怎么变：

JavaScript
const price = {
  [Symbol.toPrimitive](hint) {
    return hint === 'string' ? '10 元' : 10;
  },
};

console.log(Number(price)); // 10
console.log(String(price)); // 10 元
console.log(price + 2); // 12

hint 是引擎传进来的提示，告诉对象“现在更想要什么类型”，可能是 'number'、'string' 或 'default'。Number(price) 传 'number'，String(price) 传 'string'，而 + 和 == 传的是 'default'，所以这里 price + 2 走了返回 10 的分支，得到 12。

大多数对象没有 Symbol.toPrimitive。这时在数字和默认场合，先调 valueOf，在字符串场合先调 toString。普通对象的 valueOf 返回对象自己，不是原始值，于是接着调 toString，得到 '[object Object]'。Date 是个例外，它在默认场合按字符串处理。

== 会怎样转换类型

JavaScript
console.log(0 == ''); // true
console.log(false == '0'); // true
console.log([] == false); // true
console.log([] == []); // false
console.log(null == 0); // false

MDN 列出的 == 规则可以按顺序记：两边类型相同时，直接按 === 比，所以两个对象只看是不是同一个，[] == [] 是 false。一边是 null 或 undefined 时，只有另一边也是 null 或 undefined 才相等，所以 null == 0 是 false。一边是对象、另一边是原始值时，先把对象转成原始值。然后布尔值转成数字，字符串和数字比较时把字符串转成数字。

所以 [] == false 的过程是：[] 转原始值得到空字符串，false 转成 0，空字符串再转数字也是 0，结果相等。可是 Boolean([]) 是 true，空数组明明是真值，却“等于” false，这就是 == 让人困惑的地方。

因此日常都用 ===。唯一常见的有意用法是 value == null，它能同时匹配 null 和 undefined。

Number 和 parseInt 有什么不同

输入NumberparseInt(x, 10)
'' / ' '0NaN
'12px'NaN12
'1e3'10001
'0x10'160

Number 看整个字符串，只要有一个字符不合法就是 NaN，但空字符串和纯空格例外，会得到 0。parseInt 从头开始读，读到不认识的字符就停，所以 '1e3' 只读出 1。parseInt 要始终传第二个参数 10，明确按十进制解析。

这两个函数都太宽松了，不能拿来校验用户输入。在入口处应该先按业务格式校验，再转换：

JavaScript
function parseCount(raw) {
  const text = String(raw).trim();
  if (!/^(0|[1-9][0-9]*)$/.test(text)) {
    throw new RangeError('请输入不带前导零的非负整数');
  }
  const value = Number(text);
  if (!Number.isSafeInteger(value)) {
    throw new RangeError('数量超出安全整数范围');
  }
  return value;
}

先用正则确认是不带前导零的非负整数，转换后再检查是否超出安全整数范围。在数据入口统一转换一次，后面的代码就只用处理确定的类型。

常见追问

[] == ![] 为什么是 true？

先算右边，[] 是真值，所以 ![] 是 false，false 再转成数字 0。左边的 [] 转原始值得到空字符串，再转数字也是 0。两边都是 0，所以相等。

{} + [] 在控制台里为什么是 0？

因为写在行首的 {} 被当成了一个空代码块，不是对象。实际计算的只有 +[]，空数组转成数字是 0。
