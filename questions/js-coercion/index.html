隐式类型转换有哪些容易踩坑的规则？

不同运算触发不同转换：条件判断转布尔，减乘除转数字，+ 先把两侧转成原始值，有一侧是字符串就拼接，否则做数值加法。对象先经 Symbol.toPrimitive、valueOf、toString 转原始值。Number 和 parseInt 的解析规则也不同。

参考答案

简答

  • 假值只有 undefined、null、false、0、-0、0n、NaN、''；空数组、空对象、'0'、'false' 都是真值。
  • + 先把两侧转成原始值，结果有一侧是字符串就拼接，否则做数值加法；所以 [] + 1 是 '1'。
  • -、*、/ 没有拼接语义，总是转数字：'5' - 2 是 3。
  • 对象转原始值依次尝试 Symbol.toPrimitive、valueOf、toString（字符串场景先试 toString）。
  • Number 要求整个字符串是数值，'' 得 0；parseInt 读取前缀，'12px' 得 12。

真假值

JavaScript
console.log(Boolean([])); // true
console.log(Boolean('0')); // true
console.log(Number('')); // 0
console.log(parseInt('12px', 10)); // 12

if (count) 会把合法的 0 当成"没有"。判断数组是否为空看 length，判断字段是否缺失用 value == null 或 ??。

加号

JavaScript
console.log('5' + 2); // 52
console.log('5' - 2); // 3
console.log([] + 1);  // 1，字符串
console.log(typeof ([] + 1)); // string
console.log(1 + true); // 2
console.log(1 + null); // 1
console.log(1 + undefined); // NaN

[] 转原始值得到 ''，'' + 1 拼接成 '1'。两侧都不是字符串时转数字相加：true 为 1，null 为 0，undefined 为 NaN。

BigInt 与 Number 混合算术会抛 TypeError（1n + 1）；BigInt 与字符串相加仍会拼接。Symbol 不能隐式转成字符串或数字，会抛错。

对象转原始值

JavaScript
const price = {
  [Symbol.toPrimitive](hint) {
    return hint === 'string' ? '10 元' : 10;
  },
};

console.log(Number(price)); // 10
console.log(String(price)); // 10 元
console.log(price + 2); // 12

hint 是 'number'、'string' 或 'default'，+ 和 == 传 'default'。没有 Symbol.toPrimitive 时，数字和默认场景先调 valueOf，字符串场景先调 toString；普通对象的 valueOf 返回自身，所以最终用 toString 得到 '[object Object]'。Date 的默认场景按字符串处理。

parseInt 始终传第二个参数。两者都不是输入校验，入口处应按业务格式用正则或 schema 校验后再转换。

输入边界示例

JavaScript
function parseCount(raw) {
  const text = String(raw).trim();
  if (!/^(0|[1-9][0-9]*)$/.test(text)) {
    throw new RangeError('请输入不带前导零的非负整数');
  }
  const value = Number(text);
  if (!Number.isSafeInteger(value)) {
    throw new RangeError('数量超出安全整数范围');
  }
  return value;
}

在数据入口统一转换一次，内部代码只处理确定的类型。

常见追问

  • [] == ![] 为什么是 true？![] 是 false，转成 0；[] 转成 '' 再转 0。
  • {} + [] 在控制台为什么是 0？行首的 {} 被解析成代码块，实际计算的是 +[]。
