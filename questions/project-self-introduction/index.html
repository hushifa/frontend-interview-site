前端面试的自我介绍应该怎样准备？

自我介绍控制在一到两分钟，按“我是谁 → 做过什么、技术栈和擅长方向 → 一两个有代表性的项目和成果 → 为什么想来这个岗位”的顺序讲。目的是给面试官留下追问的线索，所以只讲自己能深入展开的内容，并按岗位要求调整重点。

参考答案

本题是回答思路与示例，不对应某个官方规范。示例中的经历和数字只用来演示怎样表达。

简答

面试一开始说“先做个自我介绍吧”，面试官往往一边听一边看简历，在找接下来要问什么。所以自我介绍不是把简历念一遍，而是主动把话题引到你最擅长、最能讲深的地方。

时间控制在一到两分钟，按四部分讲。先用一句话说清楚你是谁：几年经验、做过什么方向，比如“我做了三年前端，主要负责电商后台和移动端 H5”。再说技术栈和擅长的方向，挑和岗位相关的说，不要罗列所有用过的技术。然后讲一两个代表性的项目，每个说清楚你负责什么、解决了什么问题、结果如何。最后说为什么对这个岗位感兴趣。

讲到的每一点都可能被追问，所以只说自己能讲清楚的。比如提到“做过性能优化”，就要准备好具体做了什么、数据怎么测的。

要注意，不同岗位要调整重点。面基础架构岗多讲工程化和工具建设，面业务岗多讲复杂业务和用户体验，面 AI 应用岗就把相关项目放在前面。

一个示例

面试官您好，我叫小王，做了三年前端开发，现在在一家电商公司负责商家后台和营销活动页。

技术上主要用 Vue 3 和 TypeScript，也写过一段时间 React。比较擅长的方向是性能优化和组件封装。

最近一个比较有代表性的项目是活动页的性能优化。活动页在移动端首屏比较慢，我通过资源瀑布图定位到首屏大图发现得晚、主包里包含了用不到的图表库，做了图片格式和加载优先级的调整，以及按需加载，真实用户数据里的 LCP 从 4 秒左右降到了 2 秒。另外我把后台常用的表格和表单封装成了团队的组件库，现在有十几个页面在用。

了解到贵公司这个岗位主要做 C 端性能和体验，和我之前的方向比较契合，所以很希望有机会加入。

这段介绍里埋了几个追问点：性能优化怎么定位的、组件库怎么设计的、Vue 和 React 的区别。面试官大概率会从里面挑一个往下问，你就能把话题带到准备充分的地方。性能优化那段怎样展开，见《讲一次你做过的性能优化，应该从哪些方面讲？》。

常见的问题

一是太长，讲了五分钟还在讲第一份工作，面试官会失去耐心。可以提前计时练几遍。

二是太空，“我学习能力强、有责任心、热爱技术”这样的话谁都能说，没有信息量。用一件具体的事来体现，比说形容词有力得多。

三是和简历对不上。简历写的是负责某个项目，介绍时却说只是参与，或者反过来，会让面试官怀疑真实性。

常见追问

没有工作经验的应届生怎么介绍？

把实习、课程设计、个人项目和开源贡献当作项目经历来讲，重点同样是你做了什么、遇到了什么问题、怎样解决的。学过的知识也要能落到具体做过的东西上，比如“自己用 Vite 和 React 做了一个博客，部署在静态托管上”。

要不要介绍兴趣爱好？

时间有限时不必。如果兴趣和技术相关，比如写技术博客、参加开源，可以一句话带过，它能说明你对技术的投入。
