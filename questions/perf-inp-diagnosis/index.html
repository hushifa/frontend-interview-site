INP 很高时，如何定位到底是哪一段交互变慢？

INP 衡量点击、轻触和按键到下一帧绘制的延迟，≤200ms 为良好、>500ms 为较差，按 75 分位评估，2024 年取代 FID 成为 Core Web Vitals。每次交互分为输入延迟、处理时间、呈现延迟三段，先用 Event Timing 或 web-vitals 库找到最慢的交互和慢在哪段，再针对性优化。

参考答案

简答

  • 阈值：≤200ms 良好，200–500ms 需要改进，>500ms 较差，按页面访问的 75 分位评估。
  • 统计范围：页面生命周期内的点击、轻触和键盘交互，不包括滚动和缩放；交互达到 50 次及以上的页面取 98 分位，相当于每 50 次交互剔除一个最差值。
  • 三个阶段：输入延迟（等主线程空闲）、处理时间（事件回调执行）、呈现延迟（回调结束到下一帧绘制）。
  • 输入延迟高找长任务；处理时间高减少同步工作和更新范围；呈现延迟高检查样式、布局和 DOM 规模。
  • 生产环境用 web-vitals 库的 attribution 版本采集，开发环境用 DevTools Performance 面板复现。

采集

JavaScript
import { onINP } from 'web-vitals/attribution';

onINP(({ value, rating, attribution }) => {
  sendToAnalytics({
    value: Math.round(value),
    rating,
    target: attribution.interactionTarget,
    type: attribution.interactionType,
    inputDelay: Math.round(attribution.inputDelay),
    processing: Math.round(attribution.processingDuration),
    presentation: Math.round(attribution.presentationDelay),
  });
});

不用库时，可以直接观察 Event Timing：

JavaScript
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (!entry.interactionId) continue;
    console.log(entry.name, {
      inputDelay: entry.processingStart - entry.startTime,
      processing: entry.processingEnd - entry.processingStart,
      presentation: entry.startTime + entry.duration - entry.processingEnd,
    });
  }
}).observe({ type: 'event', durationThreshold: 16, buffered: true });

一次交互会产生多个事件条目（如 pointerdown、pointerup、click），共用一个 interactionId，整页 INP 的计算规则比较复杂，生产环境优先使用 web-vitals 库。duration 精度为 8ms，阶段拆分只是估算。

按阶段优化

输入延迟高：交互发生时主线程被别的任务占用。

  • 找出交互前后的长任务和长动画帧，见《如何用 Long Animation Frames API 定位卡顿来源？》。
  • 拆分初始化和第三方脚本，非关键工作推迟到空闲时段。

处理时间高：事件回调本身慢。

  • 回调里先更新能立即给出反馈的状态，其余工作用 scheduler.yield() 或 setTimeout 延后，见《什么是长任务，为什么会影响交互响应？怎样观测和拆分？》。
  • 减少一次交互触发的组件重渲染范围，排序、过滤等纯计算移到 Worker。

呈现延迟高：回调结束后渲染慢。

  • DOM 太大：虚拟列表、content-visibility。
  • 布局抖动：避免写样式后立即读 offsetHeight 等布局属性，先批量读再批量写。
  • 复杂选择器、大面积重绘：简化样式。

一个容易误解的点

INP 只算到下一帧绘制。点击后立即显示加载状态，下一帧很快出现，INP 就可能良好，即使数据两秒后才返回。端到端完成时间是另一个业务指标，需要单独测量。

常见追问

  • 为什么实验室测不到高 INP？Lighthouse 等工具不模拟用户交互，INP 必须靠真实用户数据或手动录制；实验室可以用 Total Blocking Time 作为参考。
  • 只优化事件回调够吗？不够。输入延迟和呈现延迟常常占主要部分。
