条件类型、infer 和分布式条件类型如何理解？

条件类型 T extends U ? X : Y 按类型的可赋值关系选择结果，infer 在匹配的结构中声明待推断的类型变量。条件左侧是裸类型参数时，传入联合会对每个成员分别计算；用 [T] extends [U] 包裹可以整体判断。never 作为分布式参数时结果仍是 never。

参考答案

简答

  • T extends U ? X : Y：T 能赋值给 U 时得到 X，否则得到 Y。这里的 extends 是可赋值判断，不是继承。
  • infer R 在匹配成功时推断出某一部分类型，内置的 ReturnType、Parameters、Awaited 都基于它。
  • 条件左侧是裸类型参数 T 时，传入 A | B 会分别计算再合并结果，这叫分布式条件类型；Exclude、Extract、NonNullable 依赖它。
  • 写成 [T] extends [U] 不再分布，把联合作为整体判断。
  • never 被视为空联合，分布式条件类型对它的结果是 never；判断是否为 never 要用 [T] extends [never]。

基本用法

TypeScript
type MessageOf<T> = T extends { message: unknown } ? T['message'] : never;
type A = MessageOf<{ message: string }>; // string
type B = MessageOf<{ id: number }>;      // never

infer

TypeScript
type ElementOf<T> = T extends readonly (infer Item)[] ? Item : never;
type C = ElementOf<number[]>;              // number
type D = ElementOf<readonly ['ok', 1]>;    // 'ok' | 1

type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type E = MyReturnType<(id: number) => string>; // string

type UnwrapPromise<T> = T extends Promise<infer V> ? UnwrapPromise<V> : T;
type F = UnwrapPromise<Promise<Promise<number>>>; // number

infer 可以加约束：T extends [infer H extends string, ...unknown[]] ? H : never。对重载函数使用 ReturnType 时，取的是最后一个重载签名。

分布式

TypeScript
type ToArray<T> = T extends unknown ? T[] : never;
type G = ToArray<string | number>; // string[] | number[]

type ToArrayTogether<T> = [T] extends [unknown] ? T[] : never;
type H = ToArrayTogether<string | number>; // (string | number)[]

type MyExclude<T, U> = T extends U ? never : T;
type I = MyExclude<'a' | 'b' | 'c', 'a'>; // 'b' | 'c'

只有"条件左侧直接是被实例化的类型参数"才会分布，T[] extends ... 或 [T] extends ... 都不会。

never 与 any

TypeScript
type IsNeverWrong<T> = T extends never ? true : false;
type IsNever<T> = [T] extends [never] ? true : false;
type J = IsNeverWrong<never>; // never
type K = IsNever<never>;      // true

any 作为被检查类型时，结果是两个分支的联合：any extends string ? 1 : 2 得到 1 | 2。

使用建议

递归条件类型能处理嵌套结构（如深层 Readonly），但会拖慢类型检查、让错误信息难以阅读。内置工具类型能满足时优先使用；业务代码中一个简单的重载或联合往往比复杂的类型体操更好维护。

常见追问

  • 怎样把联合转成交叉？利用函数参数位置的逆变推断：(U extends any ? (x: U) => void : never) extends (x: infer I) => void ? I : never。
  • 模板字面量能 infer 吗？能：T extends ${infer Head}/${infer Rest} ? Head : T 可以拆分路径。
