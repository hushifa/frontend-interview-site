useTransition 和 useDeferredValue 能优化哪些卡顿？

Transition 把一次状态更新标记为可以被打断的低优先级更新，让输入、点击等紧急更新先响应；useDeferredValue 返回一个滞后于原值的副本，用它渲染开销大的部分。它们优化的是渲染调度，不能拆分单个耗时的同步函数，也不会减少网络请求。

参考答案

简答

  • const [isPending, startTransition] = useTransition()：包在 startTransition 里的状态更新是低优先级的，渲染过程中如果有新的紧急更新，React 会中断它、先处理紧急更新。
  • useDeferredValue(value)：先用旧值渲染，再在后台用新值重新渲染；新值渲染期间又有新输入，React 会放弃这次渲染。
  • 适合"输入框要立即响应，下面的大列表可以晚一点更新"这类场景。
  • 输入框自身的 value 不能放在 Transition 里，否则输入会卡住；只把派生的耗时渲染放进去。
  • 它们中断的是 React 的渲染工作，单个组件内部几百毫秒的同步计算仍会阻塞主线程；也不会自动防抖网络请求。

useDeferredValue：输入和列表分开

JSX
import { memo, useDeferredValue, useState } from 'react';

const SlowList = memo(function SlowList({ query }) {
  const items = filterLargeList(query); // 渲染很慢
  return <ul>{items.map((i) => <li key={i.id}>{i.title}</li>)}</ul>;
});

export default function Search() {
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);
  const stale = query !== deferredQuery;

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <div style={{ opacity: stale ? 0.6 : 1 }}>
        <SlowList query={deferredQuery} />
      </div>
    </>
  );
}

SlowList 必须用 memo 包裹。否则每次 query 变化，父组件重新渲染时也会以旧的 deferredQuery 再渲染一次 SlowList，延迟就没有意义。

useTransition：切换标签页

JSX
function Tabs() {
  const [tab, setTab] = useState('about');
  const [isPending, startTransition] = useTransition();

  function select(next) {
    startTransition(() => setTab(next));
  }

  return (
    <>
      <TabButton onClick={() => select('posts')}>文章</TabButton>
      <TabButton onClick={() => select('contact')}>联系</TabButton>
      {isPending && <Spinner />}
      {tab === 'posts' ? <SlowPosts /> : tab === 'contact' ? <Contact /> : <About />}
    </>
  );
}

点击"文章"后再快速点"联系"，React 会放弃未完成的"文章"渲染，直接渲染"联系"。

和 Suspense 配合

在 Transition 中切换到会挂起的内容时，React 会继续显示当前已有的内容，而不是切回 Suspense 的 fallback。路由跳转通常利用这一点：新页面数据准备好之前，旧页面保持可见。

多个 Transition 共用一个 isPending

同一个 useTransition 返回的 isPending 只表示"是否有进行中的 Transition"，分不出是哪一个。需要按条目显示加载状态（例如每行的保存按钮），要自己按 ID 记录状态，或者给每个条目各自调用一次 useTransition。

和防抖的区别

防抖 / 节流Transition / 延迟值
作用对象函数调用次数渲染优先级
有固定延迟是否，设备快就几乎没有延迟
能减少请求能不能

搜索请求仍应防抖或用数据请求库去重；Transition 负责让渲染结果不阻塞输入。

常见追问

  • startTransition 里能 await 吗？React 19 起可以传 async 函数，但 await 之后的 setState 需要再包一层 startTransition 才会被标记为 Transition。
  • 不需要 isPending 时，可以直接从 react 导入 startTransition。
