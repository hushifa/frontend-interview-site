WebSocketStream 怎样处理消息类型与关闭生命周期？

WebSocketStream 把 WebSocket 改成用 Promise 和流来操作，读得慢时浏览器会自动少收，这叫背压。它是非标准的实验性 API，只有 Chromium 支持，生产环境要保留 WebSocket 回退。

参考答案

简答

普通 WebSocket 用 onmessage 接收，服务端推多快，回调就触发多快。如果每条消息处理得很慢，消息就会在内存里越堆越多。WebSocketStream 换了一种方式：new WebSocketStream(url) 以后等 opened，拿到 readable 和 writable 两个流，自己按需 read()。

读得慢时，浏览器会停止从网络接收，让服务端那边也慢下来，这叫背压。每次读到的都是一条完整的消息，消息边界由 WebSocket 协议保证，不用自己拼。文本消息读出来是字符串，二进制消息是 Uint8Array；写入字符串就发文本帧，写入 ArrayBuffer 或类型化数组就发二进制帧。

背压也有边界：它不限制单条消息的大小，write() 兑现也不代表对端已经收到。

最大的限制是兼容性。MDN 标为实验性、非标准，目前只有 Chromium 支持，用之前要检测 'WebSocketStream' in globalThis，并保留普通 WebSocket 的回退。

先看一个完整的连接

JavaScript
async function connect(url, onMessage) {
  const wss = new WebSocketStream(url);
  wss.closed
    .then(({ closeCode, reason }) => console.log('连接关闭', closeCode, reason))
    .catch((error) => console.warn('连接异常断开', error));

  let readable, writable;
  try {
    ({ readable, writable } = await wss.opened);
  } catch (error) {
    throw new Error('连接建立失败', { cause: error });
  }
  const writer = writable.getWriter();
  const reader = readable.getReader();

  (async () => {
    while (true) {
      const { value, done } = await reader.read();
      if (done) break;
      await onMessage(typeof value === 'string' ? JSON.parse(value) : value);
    }
  })().catch((error) => console.warn('读取中断', error));

  return {
    send: (data) => writer.write(JSON.stringify(data)),
    close: () => wss.close({ closeCode: 1000, reason: 'done' }),
  };
}

opened 兑现以后拿到两个流。读的那一段是个循环：读一条，await onMessage 处理完，再读下一条。

背压就藏在这个 await 里。onMessage 是异步的，处理完一条才去读下一条。处理变慢，读取就跟着变慢，浏览器就会自动减少从网络接收。

closed 管关闭。正常关闭时它以 { closeCode, reason } 兑现，异常断开时 reject。创建时也可以传 { signal }，在连接建立之前取消。

为什么 opened 和 closed 都要处理拒绝？因为连接随时可能异常断开，不处理就会冒出未处理的 Promise 拒绝。

背压管不到哪些事

背压只控制接收的速度，不限制单条消息有多大。服务端仍要限制消息体积，业务层也仍要做限流。

writer.write() 兑现，只表示数据交给浏览器去发了，不代表对端已经收到，更不代表已经处理。需要确认的话，让应用层回一个 ACK。

关闭方面，close() 没有返回表示完成的 Promise，关闭结果要看 closed。另外 reader.releaseLock() 和 writer.releaseLock() 只是释放流的锁，不会关闭连接；要关连接，得调 wss.close()。

和普通 WebSocket 对比

WebSocketWebSocketStream

不支持的浏览器怎么办

JavaScript
const supportsStream = 'WebSocketStream' in globalThis;
const client = supportsStream ? await connect(url, handle) : connectLegacy(url, handle);

connectLegacy 用普通 WebSocket 实现同样的接口。服务端协议不用改，两种客户端都能连上。基础的 WebSocket 握手和心跳见《WebSocket 适合什么场景，连接断开后怎样恢复？》。

常见追问

writer.write() 的 Promise 兑现了，是不是说明服务端收到了？

不是。它只表示数据已经交给浏览器去发送。要确认对端收到或处理了，得在应用层让对方回 ACK。

调用 reader.releaseLock() 会关闭连接吗？

不会。它只是释放流的锁，让别的代码能读。关闭连接要调用 wss.close()，关闭结果看 closed。
