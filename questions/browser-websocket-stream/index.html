WebSocketStream 怎样处理消息类型与关闭生命周期？

WebSocketStream 用 Promise 和 Streams 封装 WebSocket，opened 提供 readable 和 writable，读取自带背压；它是非标准的实验性 API，只有 Chromium 支持，生产环境要保留 WebSocket 回退。

参考答案

简答

  • new WebSocketStream(url) 后等待 opened，得到 { readable, writable, protocol, extensions }。
  • 文本消息读出来是字符串，二进制消息是 Uint8Array；写入字符串发送文本帧，写入 ArrayBuffer 或类型化数组发送二进制帧。
  • 每次读取得到一条完整消息，消息边界由 WebSocket 协议保证，不需要自己拼接。
  • 读取慢时浏览器停止从网络接收，形成背压；背压不限制单条消息大小，write() 兑现也不代表对端已收到。
  • MDN 标为实验性、非标准，目前只有 Chromium 支持，使用前检测 'WebSocketStream' in globalThis。

示例

JavaScript
async function connect(url, onMessage) {
  const wss = new WebSocketStream(url);
  wss.closed
    .then(({ closeCode, reason }) => console.log('连接关闭', closeCode, reason))
    .catch((error) => console.warn('连接异常断开', error));

  let readable, writable;
  try {
    ({ readable, writable } = await wss.opened);
  } catch (error) {
    throw new Error('连接建立失败', { cause: error });
  }
  const writer = writable.getWriter();
  const reader = readable.getReader();

  (async () => {
    while (true) {
      const { value, done } = await reader.read();
      if (done) break;
      await onMessage(typeof value === 'string' ? JSON.parse(value) : value);
    }
  })().catch((error) => console.warn('读取中断', error));

  return {
    send: (data) => writer.write(JSON.stringify(data)),
    close: () => wss.close({ closeCode: 1000, reason: 'done' }),
  };
}
  • onMessage 是异步的，处理完一条才读下一条，处理变慢时浏览器自动减少接收。
  • closed 在连接关闭时以 { closeCode, reason } 完成，异常断开时 reject。
  • 创建时可以传 { signal }，在连接建立前取消。
  • opened 和 closed 都要处理拒绝，否则异常断开会产生未处理的 Promise 拒绝。

背压与关闭的边界

  • 背压只控制接收速度，不限制单条消息的大小。服务端仍要限制消息体积，业务层仍要限流。
  • writer.write() 兑现只表示数据已交给浏览器发送，不代表对端已收到或已处理；需要确认时由应用层回 ACK。
  • close() 没有返回完成的 Promise，关闭结果看 closed。
  • reader.releaseLock() 和 writer.releaseLock() 只释放锁，不会关闭连接；关闭用 wss.close()。

和 WebSocket 对比

WebSocketWebSocketStream
接收onmessage 事件，来多少推多少按需 read()，自带背压
发送背压自己检查 bufferedAmountwriter.write() 的 Promise 等待
关闭onclose 事件closed Promise
兼容性所有浏览器仅 Chromium，非标准

回退写法

JavaScript
const supportsStream = 'WebSocketStream' in globalThis;
const client = supportsStream ? await connect(url, handle) : connectLegacy(url, handle);

connectLegacy 用 WebSocket 实现相同的接口。服务端协议不变，两种客户端都能连接。基础的 WebSocket 握手和心跳见《WebSocket 适合什么场景，连接断开后怎样恢复？》。
