Pinia 中 state、getter 和 action 应如何分工？

state 保存原始数据，getter 是带缓存的派生值，action 封装修改数据的业务操作，可以是异步的。从 store 解构 state 和 getter 要用 storeToRefs 保持响应性。SSR 中每个请求要使用独立的 Pinia 实例。

参考答案

简答

  • state：需要保存和维护的原始数据，例如收藏的题目 ID 列表。
  • getters：从 state 推导的值，例如收藏数量，结果会被缓存，不要再单独存一份。
  • actions：封装修改 state 的业务操作，可以是 async 函数，组件只调用 action，不关心实现。
  • 解构时：state 和 getter 用 storeToRefs(store)，否则得到的是普通值；action 可以直接从 store 解构。
  • 组合式写法（setup store）没有内置 $reset，需要自己实现；SSR 中每个请求都要创建新的 createPinia() 实例。

组合式写法

JavaScript
// stores/bookmarks.js
import { defineStore } from 'pinia';
import { computed, ref } from 'vue';

export const useBookmarksStore = defineStore('bookmarks', () => {
  const ids = ref([]);
  const count = computed(() => ids.value.length);
  const has = (id) => ids.value.includes(id);

  async function toggle(id) {
    const prev = ids.value;
    ids.value = has(id) ? prev.filter((x) => x !== id) : [...prev, id];
    try {
      const res = await fetch(`/api/bookmarks/${id}`, { method: 'PUT' });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
    } catch {
      ids.value = prev; // 失败时恢复
    }
  }

  function $reset() {
    ids.value = [];
  }

  return { ids, count, has, toggle, $reset };
});

ref 对应 state，computed 对应 getter，普通函数对应 action。要被 DevTools 和 SSR 识别为 state，所有 state 都必须从 setup 函数返回。

在组件中使用

vue
<script setup>
import { storeToRefs } from 'pinia';
import { useBookmarksStore } from '@/stores/bookmarks';

const store = useBookmarksStore();
const { count } = storeToRefs(store); // 保持响应性
const { toggle } = store; // action 直接解构
</script>

<template>
  <span>已收藏 {{ count }} 题</span>
  <button @click="toggle(42)">收藏第 42 题</button>
</template>

直接写 const { count } = store 得到的是一个数字，之后不会更新。

直接修改与 $patch

JavaScript
store.ids.push(7); // 可以直接修改
store.$patch((state) => {
  state.ids.push(7);
  state.ids.push(8);
}); // 多处修改合并为一次

Pinia 允许组件直接改 state，但有业务规则（校验、请求、日志）的修改应放进 action，便于统一维护。

SSR

JavaScript
// 每个请求
const pinia = createPinia();
app.use(pinia);
// 渲染后把 pinia.state.value 序列化到页面，客户端用它初始化

不要在模块顶层创建 Pinia 实例或在 store 外部定义共享的 ref，否则所有请求共享同一份数据，会把一个用户的数据显示给另一个用户。Nuxt 的 @pinia/nuxt 模块已经处理了这些。

持久化

需要把 state 保存到 localStorage 时，可以用 pinia-plugin-persistedstate 等插件，或者在 store.$subscribe 中写入。不要持久化令牌等敏感信息，也要处理旧版本数据结构的兼容。

常见追问

  • 和 Vuex 的区别？Pinia 没有 mutations，action 可以直接修改 state；每个 store 独立定义，天然支持代码分割；TypeScript 类型推导更好。Pinia 是 Vue 官方推荐的状态管理库。
  • store 之间能互相调用吗？可以在一个 store 的 action 或 getter 中调用另一个 store 的 useXxxStore()。
