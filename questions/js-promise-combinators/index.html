Promise.all、allSettled、race 和 any 如何选择？

四个组合方法只定义"何时完成、结果是什么"。all 全部成功才成功、遇到首个拒绝即拒绝；allSettled 等全部敲定并返回状态；race 跟随首个敲定的结果；any 等首个成功，全部失败时以 AggregateError 拒绝。它们都不会启动、限流或取消任务。

参考答案

简答

  • all：全部成功时按输入顺序返回结果数组；任一拒绝立刻拒绝。适合"缺一不可"。
  • allSettled：等全部敲定，返回 { status, value | reason } 数组，自身不会拒绝。适合批量操作后汇总成败。
  • race：跟随第一个敲定的 Promise，成功失败都算。常用于超时竞争。
  • any：第一个成功即成功；全部失败时以 AggregateError 拒绝，errors 按输入顺序保存原因。适合多源择优。
  • 空输入：all、allSettled 立即以 [] 成功，any 立即以 AggregateError 拒绝，race 永远挂起。

对比示例

JavaScript
async function compare() {
  const tasks = [
    Promise.reject(new Error('A失败')),
    Promise.resolve('B成功'),
  ];

  try {
    await Promise.all(tasks);
  } catch (error) {
    console.log(`all:${error.message}`); // all:A失败
  }

  const settled = await Promise.allSettled(tasks);
  console.log(settled.map(item => item.status).join(',')); // rejected,fulfilled
  console.log(settled.map(item =>
    item.status === 'fulfilled' ? item.value : item.reason.message,
  ).join('|')); // A失败|B成功

  try {
    await Promise.race(tasks);
  } catch (error) {
    console.log(`race:${error.message}`); // race:A失败
  }

  console.log(`any:${await Promise.any(tasks)}`); // any:B成功
}

compare();

组合方法不负责的事

  • 启动：传进去时请求已经发出。Promise.all(urls.map(fetch)) 会同时发出全部请求，需要限流时用并发池，见《怎样实现有明确失败语义的异步并发池？》。
  • 取消：all 拒绝或 race 超时后，其余任务仍在运行。需要停止时给每个任务传同一个 AbortSignal，在失败时调用 controller.abort()。
  • 未处理拒绝：all 拒绝后，其余 Promise 再拒绝不会触发 unhandledrejection，因为组合方法已经给它们挂了处理器。

超时写法

JavaScript
function withTimeout(promise, ms) {
  return Promise.race([
    promise,
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error('超时')), ms)),
  ]);
}

更好的写法是让底层请求也停止：fetch(url, { signal: AbortSignal.timeout(ms) })。

常见追问

  • all 返回的结果顺序？按输入顺序，与完成先后无关。
  • 输入里有非 Promise 值怎么办？会被 Promise.resolve 包装，当作已成功。
  • any 和 race 的区别？race 被第一个失败打断，any 会忽略失败继续等成功。
