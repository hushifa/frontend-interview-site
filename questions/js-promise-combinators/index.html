Promise.all、allSettled、race 和 any 如何选择？

四个方法都是把一组 Promise 合成一个，区别在于什么时候结束、结果是什么。all 要全部成功，allSettled 等全部结束，race 看谁先结束，any 看谁先成功；它们都不会帮你启动、限流或取消任务。

参考答案

简答

这四个方法都是把一组 Promise 合成一个新的 Promise，区别只在于新的 Promise 什么时候结束、结束时给什么结果。

Promise.all 要求全部成功，成功时按传入的顺序返回结果数组，只要有一个失败就立刻失败，适合“缺一不可”的场景，比如页面要同时拿到几份数据才能渲染。Promise.allSettled 会等所有 Promise 都有结果，不管成功失败，返回每一个的状态和值，它自己不会失败，适合批量操作后汇总成败。Promise.race 谁先有结果就跟谁，成功失败都算，常用来做超时。Promise.any 等第一个成功的，失败的先不管，全部失败时才以 AggregateError 失败，适合多个来源里取最快的那个可用结果。

传空数组时也不一样：all 和 allSettled 立刻以 [] 成功，any 立刻以 AggregateError 失败，race 会一直挂着，永远不结束。

要注意，这几个方法只负责“等结果”。任务在传进去之前就已经开始跑了，它们不会帮你限制并发数，也不会在失败或超时后把其他任务停下来。

先看一个对比

下面用同一组任务分别跑四个方法：第一个失败，第二个成功。注意看每个方法怎么对待那个失败。

JavaScript
async function compare() {
  const tasks = [
    Promise.reject(new Error('A失败')),
    Promise.resolve('B成功'),
  ];

  try {
    await Promise.all(tasks);
  } catch (error) {
    console.log(`all:${error.message}`); // all:A失败
  }

  const settled = await Promise.allSettled(tasks);
  console.log(settled.map(item => item.status).join(',')); // rejected,fulfilled
  console.log(settled.map(item =>
    item.status === 'fulfilled' ? item.value : item.reason.message,
  ).join('|')); // A失败|B成功

  try {
    await Promise.race(tasks);
  } catch (error) {
    console.log(`race:${error.message}`); // race:A失败
  }

  console.log(`any:${await Promise.any(tasks)}`); // any:B成功
}

compare();

all 遇到 A 失败，整体就失败了，B 成功了也没用。

allSettled 没有走 catch，它把两个结果都交了回来。每一项是一个对象：成功的是 { status: 'fulfilled', value }，失败的是 { status: 'rejected', reason }。所以遍历时先看 status，再决定读 value 还是 reason。

race 也失败了，因为 A 先有结果，而 race 不挑成功失败，谁先结束就跟谁。any 则跳过了 A 的失败，拿到了 B 的成功。race 和 any 最大的区别就在这里：race 会被第一个失败打断，any 会忽略失败继续等成功。

结果顺序和完成先后有关系吗

没有关系。all 和 allSettled 返回的数组，顺序跟传进去的顺序一致，不是谁先完成谁排前面。

JavaScript
const wait = (ms, value) =>
  new Promise((resolve) => setTimeout(() => resolve(value), ms));

Promise.all([wait(30, '慢'), wait(10, '快'), 3]).then((result) => {
  console.log(result); // [ '慢', '快', 3 ]
});

“快”先完成，可它还是排在第二个位置，因为它是第二个传进去的。另外数组里的 3 不是 Promise，组合方法会用 Promise.resolve 把它包一层，当作一个已经成功的 Promise 处理，所以结果里直接就是 3。

全部失败和空数组会怎样

any 只有在所有 Promise 都失败时才会失败，这时给出的错误是 AggregateError，它的 errors 属性按传入顺序保存了每一个失败原因。空数组则是几个方法差别最大的地方。

JavaScript
Promise.any([
  Promise.reject(new Error('甲')),
  Promise.reject(new Error('乙')),
]).catch((error) => {
  console.log(error.name); // AggregateError
  console.log(error.errors.map((item) => item.message)); // [ '甲', '乙' ]
});

Promise.all([]).then((value) => console.log('all', value)); // all []
Promise.allSettled([]).then((value) => console.log('allSettled', value)); // allSettled []
Promise.any([]).catch((error) => console.log('any', error.name)); // any AggregateError

空数组时 all 和 allSettled 没有需要等的东西，所以立刻以 [] 成功；any 一个成功都等不到，所以立刻失败。race 没有写在这里，因为它传空数组时既不成功也不失败，then 和 catch 都不会被调用。

这几个方法不负责的事

很多误用都来自以为组合方法会“管理”任务。其实它们只是在等结果。

第一，它们不负责启动。传进去的 Promise 在创建时就已经开始执行了。Promise.all(urls.map(fetch)) 里，map 那一刻所有请求就都发出去了。所以要限制同时发几个请求，得自己写并发池，详见《怎样实现有明确失败语义的异步并发池？》。

第二，它们不负责取消。all 失败了，或者 race 超时了，其他任务其实还在跑，请求还在下载。需要真正停下来时，可以给每个任务传同一个 AbortSignal，在失败时调用 controller.abort()。

第三，关于未处理的失败。all 已经因为第一个失败而失败后，其他 Promise 再失败，不会触发 unhandledrejection 事件，因为组合方法已经给每个传入的 Promise 挂好了处理函数。

用 race 做超时

race 最常见的用法是让请求和一个定时器赛跑，定时器先结束就当作超时。

JavaScript
function withTimeout(promise, ms) {
  return Promise.race([
    promise,
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error('超时')), ms)),
  ]);
}

这个写法能让调用方及时拿到“超时”错误，可是原来的请求并没有停，还在后台继续跑。按上一节说的，race 不负责取消。如果底层是 fetch，更好的写法是让请求本身到时间就中止：fetch(url, { signal: AbortSignal.timeout(ms) })。

常见追问

all 返回的结果是什么顺序？

按传入的顺序，跟谁先完成没有关系。第一个传进去的结果就在第一个位置。

输入里有不是 Promise 的值怎么办？

会被 Promise.resolve 包一层，当作已经成功的 Promise，结果里就是这个值本身。

any 和 race 有什么区别？

race 看谁先结束，第一个结束的是失败，整体就失败。any 只看成功，会跳过失败继续等，全部失败了才以 AggregateError 失败。
