逻辑属性为什么比固定写 left、right 更适合国际化？

逻辑属性按文字的行内方向与块方向表达边缘和尺寸，能够跟随 writing-mode 与 direction 映射到实际物理方向，减少从左到右、从右到左和竖排布局之间的重复样式。

参考答案

简答

  • 逻辑属性按书写模式和文字方向表达方向，例如 border-inline-start 在 LTR 中是左边，在 RTL 中是右边。
  • inline 是一行文字延伸的轴，block 是行与段落堆叠的轴，竖排时不再对应水平和垂直。
  • padding-inline: a b 的顺序是 start、end，不是固定的左、右。
  • HTML 内容用 dir 表达方向、用 lang 表达语言，同一份样式就能服务不同阅读方向。

给正文开头加一条装饰线，中文页面通常会写 border-left。页面翻译成阿拉伯语后，正文从右向左阅读，装饰线往往也应移到右边。若一直使用物理方向，就要为 RTL 再写一套覆盖规则。

逻辑属性允许直接表达“正文起始侧的边框”：border-inline-start。浏览器再根据元素的书写模式和文字方向，决定这条边实际位于左边、右边，还是竖排时的上边或下边。

inline 和 block 到底指哪两个方向

inline 是一行文字延伸的轴，block 是一行接一行、一个段落接一个段落堆叠的轴。这两个词描述的是方向，和元素是否写了 display: inline 或 display: block 不是一回事。

writing-mode 决定横排还是竖排等书写模式，direction 决定相应的行内文字方向。下面列出三种明确设置下的映射：

模式inline-startinline-endblock-startblock-end
horizontal-tb、ltr左右上下
horizontal-tb、rtl右左上下
vertical-rl、ltr上下右左

因此不能永远把 inline 翻译成“水平”、把 block 翻译成“垂直”。在 vertical-rl 中，每一列文字沿纵向排列，下一列在前一列左侧。

同一份样式服务不同阅读方向

HTML
<section class="note" dir="ltr" lang="zh-CN">
  <h2>学习安排</h2>
  <p>每天阅读一个专题，再用小例子验证理解。</p>
</section>

<section class="note" dir="rtl" lang="ar">
  <h2>خطة التعلم</h2>
  <p>اقرأ موضوعًا كل يوم.</p>
</section>
CSS
.note {
  box-sizing: border-box;
  max-inline-size: 40rem;
  margin-inline: auto;
  margin-block: 1rem;
  padding-block: 1rem;
  padding-inline: 1.5rem;
  border-inline-start: 4px solid #2563eb;
  text-align: start;
}

.note h2 {
  margin-block: 0 0.5rem;
}

.note p {
  margin: 0;
}

第一块内容的装饰线在左侧，第二块在右侧；text-align: start 也随文字方向对齐到开头。对 HTML 内容，应优先用 dir 属性表达方向，用 lang 表达语言。lang="ar" 本身不会自动替你设置整个布局的 dir="rtl"。

padding-inline 同时控制行内两侧，padding-block 控制块方向两侧。需要两侧不同值时，像 padding-inline: 1rem 2rem 这样的顺序是 start、end，不是固定的左、右。

常见属性怎样对应

横排从左到右时，可以用下面的对应关系帮助理解，但写完后要记得它们会随书写模式变化：

物理写法对应的逻辑表达
width、heightinline-size、block-size
min-width、max-widthmin-inline-size、max-inline-size
margin-leftmargin-inline-start
padding-toppadding-block-start
rightinset-inline-end
text-align: lefttext-align: start

inset-inline-end 仍然是定位偏移属性，需要配合 position 等布局条件使用；换了名字不会让普通流元素自动移动。inline-size 也仍然受 box-sizing、最小最大尺寸、Flex/Grid 等规则影响，不是绕过盒模型的新尺寸单位。

为什么不应该机械替换所有 left 和 right

逻辑方向适合表达阅读与内容流相关的设计：正文缩进、列表间距、按钮旁的说明、侧边栏起始侧边框等。某个图像热点必须固定在图片物理左上角，或者画布坐标确实以屏幕左上角为原点，就仍然可能适合物理属性。

逻辑属性也不会自动镜像所有东西。translateX() 中的 X 是物理横轴，背景位置、渐变角度、某些图标方向等还需按语义单独处理。前进后退箭头可能需要随阅读方向调整，但播放、时钟或品牌标志通常不能无脑翻转。

不要为了 RTL 再随意加 row-reverse 或大量 order。Flex 的 row 本来就沿行内轴排列，已经受 direction 影响；再反转一次可能抵消需要的效果。视觉顺序变化还可能与 DOM 阅读顺序和键盘焦点顺序不一致。

最后，物理属性和逻辑属性有机会映射到同一条边。例如横排 LTR 下同时设置 margin-left 和 margin-inline-start，它们会按层叠规则竞争，并不是逻辑属性天然更优先。迁移时应移除不再需要的旧声明，在 LTR、RTL 以及实际支持的竖排模式下分别核对。
