Intl.Locale 解决什么问题？语言标签应该怎样建模？

Intl.Locale 解析和规范化 BCP 47 语言标签，拆出语言、文字、地区和 Unicode 扩展。maximize 和 minimize 补全或精简子标签；资源匹配要自己实现回退链；书写方向用 getTextInfo 或 textInfo 检测。

参考答案

简答

  • 语言标签由语言、文字、地区等子标签组成，例如 zh-Hant-TW 是"中文、繁体字、台湾"。Intl.Locale 把它解析成 language、script、region 等属性。
  • 语言、地区和时区是三件事：在日本的英语用户可能要英文界面、日元、东京时区，不要用一个字段推断另外两个。
  • maximize() 按 likely-subtags 数据补全（zh → zh-Hans-CN），minimize() 去掉可推断的部分，两者都不是翻译。
  • 选择翻译资源要自己写回退链，例如 zh-Hant-HK → zh-Hant → zh → 默认语言，Intl.Locale 只负责解析。
  • 书写方向用 getTextInfo().direction 检测，Node 22 只有旧的 textInfo 属性，两者都要做能力检测。

解析与规范化

JavaScript
const locale = new Intl.Locale('zh-Hant-TW');
locale.language; // 'zh'
locale.script; // 'Hant'
locale.region; // 'TW'
locale.baseName; // 'zh-Hant-TW'

new Intl.Locale('zh').maximize().toString(); // 'zh-Hans-CN'
new Intl.Locale('zh-Hans-CN').minimize().toString(); // 'zh'
Intl.getCanonicalLocales(['EN-us', 'zh-cn', 'iw']); // ['en-US', 'zh-CN', 'he']
new Intl.Locale('not a tag'); // RangeError

规范化会修正大小写，也会把弃用的代码替换掉（iw → he）。存储用户偏好时保存规范化后的结果。

语言标签的地区子标签只描述语言变体，不代表用户所在地、货币或时区。在日本的英语用户可能要英文界面、日元和东京时区，这三项要分别保存，不要从一个字段推断另外两个。

Unicode 扩展

JavaScript
const thai = new Intl.Locale('th-TH', { calendar: 'buddhist', numberingSystem: 'thai' });
thai.toString(); // 'th-TH-u-ca-buddhist-nu-thai'

扩展键（ca 日历、nu 数字系统、hc 时制等）由规范定义，不能随意添加。把这样的 locale 传给 Intl.DateTimeFormat，就会使用对应的日历和数字。

资源回退

JavaScript
function pickLocale(requested, available, fallback = 'en') {
  for (const tag of requested) {
    const current = new Intl.Locale(tag).maximize();
    const candidates = [current.baseName, `${current.language}-${current.script}`, current.language];
    const hit = candidates.find((c) => available.includes(c));
    if (hit) return hit;
  }
  return fallback;
}

pickLocale(['zh-HK'], ['zh-Hant', 'zh-Hans', 'en']); // 'zh-Hant'

zh-HK 补全后是 zh-Hant-HK，于是先匹配到繁体资源，而不是只按语言 zh 匹配到简体。Intl.DateTimeFormat.supportedLocalesOf() 只能告诉你运行时支持哪些格式化语言，不知道你有哪些翻译文件。

书写方向

JavaScript
function getDirection(tag) {
  const locale = new Intl.Locale(tag);
  if (typeof locale.getTextInfo === 'function') return locale.getTextInfo().direction;
  if (locale.textInfo) return locale.textInfo.direction; // 旧版访问器
  return null; // 不支持时由应用的语言配置决定
}

getDirection('ar'); // 'rtl'

常见追问

  • navigator.language 能直接当界面语言吗？ 可以作为默认值，但要允许用户手动切换并保存选择。navigator.languages 提供按偏好排序的完整列表。
  • SSR 时怎样决定语言？ 优先读取用户保存的设置，其次是 URL 或 Accept-Language，服务端选定后把结果传给客户端，避免两端各自判断。
