垃圾回收为什么无法自动解决所有内存泄漏？

垃圾回收只回收从根出发不可达的对象。前端常见泄漏是"业务上已经不用、但仍被引用"：未移除的监听器、未清除的定时器、无上限的缓存、长期订阅。循环引用本身不会泄漏。排查用堆快照比较对象数量和保留路径。

参考答案

简答

  • 现代引擎使用标记清除：从全局对象、调用栈等根出发标记所有可达对象，未被标记的被回收。
  • 两个对象互相引用但从根不可达时会被回收，循环引用不是泄漏原因。
  • 泄漏是"可达但不再需要"：未移除的事件监听器、未清除的定时器、只增不减的 Map 缓存、未取消的订阅、全局变量。
  • WeakMap 和 WeakRef 不阻止目标被回收，但回收时机不确定；FinalizationRegistry 的回调可能不执行。
  • 排查方法：重复同一操作，比较 DevTools 堆快照中对象数量的增长，并查看到 GC 根的保留路径。

监听器与定时器

JavaScript
function attachPreview(button, panel) {
  function onClick() {
    panel.textContent = '预览已更新';
  }

  button.addEventListener('click', onClick);
  const timer = setInterval(() => {
    panel.dataset.checkedAt = String(Date.now());
  }, 1000);

  return function dispose() {
    button.removeEventListener('click', onClick);
    clearInterval(timer);
  };
}

panel 从页面移除后，定时器回调仍引用它，定时器又被浏览器持有，所以 panel 一直可达。创建资源的函数返回 dispose，在组件卸载时调用。

也可以用 AbortController 一次移除多个监听器：

JavaScript
const controller = new AbortController();
button.addEventListener('click', onClick, { signal: controller.signal });
window.addEventListener('resize', onResize, { signal: controller.signal });
controller.abort(); // 两个监听器同时移除

其他常见来源

  • 缓存没有容量上限：用 LRU 或 WeakMap（键是对象时）。
  • 被移出 DOM 的节点仍被 JS 变量或数组引用（DevTools 中显示为 Detached）。
  • 闭包持有不必要的大对象：闭包只保留它实际引用的变量，但同一作用域内的多个闭包可能共享环境。
  • 控制台 console.log 打印的对象会被 DevTools 保留，排查时关闭控制台或清空。

排查流程

  1. 在 Chrome DevTools 的 Memory 面板拍一次堆快照。
  2. 重复执行怀疑泄漏的操作（打开再关闭弹窗）若干次，再拍快照。
  3. 选择 Comparison 视图，按 # Delta 排序，找数量持续增长的构造函数。
  4. 选中对象查看 Retainers，沿保留路径找到本应断开的引用。

Retained size 是释放该对象后能回收的总内存，比 Shallow size 更能反映影响。内存没有立刻回落不一定是泄漏，引擎会保留已申请的堆以复用；判断依据是相同操作下对象数持续增长。

弱引用

  • WeakMap：把元数据附加在对象上，对象被回收后条目自动消失。
  • WeakRef：deref() 可能返回 undefined，用于可以丢失的缓存。
  • FinalizationRegistry：回收后的回调时间不确定，不能用于关闭连接、取消订阅等必须执行的清理。

文件句柄、网络连接、订阅这类外部资源要显式释放，GC 只管内存。

常见追问

  • React 中怎样避免？在 useEffect 返回清理函数；异步请求结束时组件已卸载，用 AbortController 取消。
  • 引用计数为什么被淘汰？无法回收循环引用。
