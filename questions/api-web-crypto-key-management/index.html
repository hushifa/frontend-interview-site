Web Crypto API 如何正确管理浏览器端密钥？

crypto.subtle 提供哈希、签名、加解密和密钥派生，只在安全上下文中可用；密钥用 CryptoKey 表示，生成时设 extractable 为 false 可以防止导出，非导出密钥可以存进 IndexedDB 在页面间复用。

参考答案

简答

  • crypto.getRandomValues() 生成安全随机数，不要求安全上下文；crypto.randomUUID() 只在安全上下文（HTTPS 或 localhost）可用；crypto.subtle 提供 digest、sign、encrypt、deriveKey 等方法。
  • 整个 crypto.subtle 只在安全上下文中可用，getRandomValues() 不受这一限制。
  • 密钥是 CryptoKey 对象，extractable: false 的密钥无法用 exportKey() 导出，脚本也拿不到原始字节。
  • CryptoKey 可以被结构化克隆，直接存进 IndexedDB，下次打开页面仍能使用而且仍不可导出。
  • 浏览器端加密不能防御 XSS：攻击者的脚本无法导出密钥，但可以直接调用它加解密。

示例：AES-GCM 加密本地数据

JavaScript
async function createKey() {
  return crypto.subtle.generateKey({ name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt']);
}

async function encrypt(key, text) {
  const iv = crypto.getRandomValues(new Uint8Array(12));
  const data = new TextEncoder().encode(text);
  const cipher = await crypto.subtle.encrypt({ name: 'AES-GCM', iv }, key, data);
  return { iv, cipher };
}

async function decrypt(key, { iv, cipher }) {
  const plain = await crypto.subtle.decrypt({ name: 'AES-GCM', iv }, key, cipher);
  return new TextDecoder().decode(plain);
}
  • AES-GCM 的 IV 每次加密都必须不同，12 字节随机值，和密文一起保存。IV 不需要保密。
  • 解密时数据被篡改或密钥不对，decrypt 会 reject，不会返回错误的明文。

从密码派生密钥

JavaScript
async function keyFromPassword(password, salt) {
  const base = await crypto.subtle.importKey('raw', new TextEncoder().encode(password), 'PBKDF2', false, ['deriveKey']);
  return crypto.subtle.deriveKey(
    { name: 'PBKDF2', salt, iterations: 600000, hash: 'SHA-256' },
    base,
    { name: 'AES-GCM', length: 256 },
    false,
    ['encrypt', 'decrypt'],
  );
}

盐值随机生成并保存，迭代次数要足够大以增加暴力破解成本。从已有的高熵密钥派生子密钥用 HKDF，不需要大量迭代。

适用边界

  • 适合：端到端加密的聊天、本地加密的离线数据、校验下载文件的哈希、在浏览器中验证签名。
  • 不适合代替 HTTPS，也不应该在前端保存服务端的私钥或 API 密钥。
  • 密钥丢失（用户清除了站点数据）时加密数据无法恢复，需要设计备份或重新同步的流程。
