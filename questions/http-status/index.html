常见 HTTP 状态码应该怎样在前端区分处理？

2xx 成功、3xx 重定向、4xx 客户端问题、5xx 服务端问题。前端要按具体状态码决定行为：401 重新登录、403 提示无权限、429 和 503 按 Retry-After 退避、其他 4xx 不要重试。

参考答案

简答

  • 401 表示没有有效身份，引导登录或刷新令牌；403 表示身份已知但无权限，重新登录也没用。
  • 429 和 503 是暂时性的，按 Retry-After 等待后重试；400、404、422 这类重试也不会成功。
  • 204 没有正文，直接调用 response.json() 会报错。
  • 301、302、307、308 会被 fetch 自动跟随，脚本通常看不到；304 由浏览器缓存处理。

常用状态码

状态码含义前端处理
200成功读取正文
201已创建可读 Location 头获取新资源地址
202已接受，尚未处理完轮询任务状态或等待推送
204成功，无正文不解析正文
301 / 308永久重定向308 保持方法和请求体
302 / 307临时重定向307 保持方法和请求体
304未修改浏览器复用缓存
400请求格式错误修正请求，不重试
401未认证登录或刷新令牌
403已认证但无权限提示无权限
404资源不存在显示空状态
409冲突，如版本过期提示刷新后重试
422语义校验失败显示字段错误
429请求过多按 Retry-After 退避
500服务器内部错误提示稍后再试，可有限重试幂等请求
502 / 504网关错误或超时可有限重试幂等请求
503暂时不可用按 Retry-After 退避

301 和 302 在历史上会被客户端把 POST 改成 GET，307 和 308 明确要求不改方法，所以接口重定向优先用后两个。

统一处理示例

JavaScript
async function request(url, init) {
  const response = await fetch(url, init);
  if (response.ok) return response.status === 204 ? null : response.json();

  switch (response.status) {
    case 401:
      redirectToLogin();
      break;
    case 429:
    case 503: {
      const seconds = Number(response.headers.get('Retry-After'));
      throw Object.assign(new Error('稍后重试'), { retryAfter: seconds || 5 });
    }
  }
  throw Object.assign(new Error(`HTTP ${response.status}`), { status: response.status });
}

Retry-After 也可能是 HTTP 日期格式，生产代码要两种都解析。fetch 本身的错误处理见《为什么 fetch 收到 404 不一定进入 catch？》。

常见追问

  • 业务错误该用 200 加错误码，还是用 4xx？用 HTTP 状态码表达协议层结果，监控、缓存和网关能正确识别；业务细节放在响应体里。
  • 跨源重定向会怎样？fetch 跟随时会重新做 CORS 检查，重定向目标也必须允许该来源。
