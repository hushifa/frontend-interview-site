BFC 解决哪些布局问题，什么时候用 flow-root？

BFC 是块级格式化上下文。新建 BFC 可以包住内部浮动、避开外部浮动，并阻止父子外边距折叠；display: flow-root 是专门用来创建 BFC 的写法。

参考答案

简答

  • BFC 内部的块盒按垂直方向排列，浮动只影响同一个 BFC 里的内容。
  • 新建 BFC 有三个常用效果：高度包含内部浮动；不与外部浮动重叠；和子元素之间不发生外边距折叠。
  • 创建方式包括 display: flow-root、overflow 非 visible/clip、浮动、绝对定位、display: inline-block、flex 和 grid 项目、contain: layout 等。
  • 只想创建 BFC 时用 display: flow-root，它没有 overflow: hidden 裁剪阴影和弹层的副作用。

包含浮动

CSS
.media {
  display: flow-root;
}

.media img {
  float: left;
  margin-inline-end: 12px;
}

父元素不是 BFC 时，浮动的图片不参与父元素的高度计算，父元素的背景和边框会比图片矮。加上 flow-root 后，父元素的高度包含浮动。

避开外部浮动

CSS
.aside {
  float: left;
  width: 200px;
}

.main {
  display: flow-root;
}

普通块会延伸到浮动元素下方，只有文字绕开浮动。.main 成为 BFC 后，整个盒子会缩到浮动旁边，形成两栏。

外边距折叠

相邻块之间、父元素和第一个或最后一个子元素之间的垂直外边距会折叠。父元素成为 BFC 后，子元素的外边距留在父元素内部。父元素加 padding、border 也能阻止父子折叠，不一定需要 BFC。

flex 和 grid 容器的项目之间不发生外边距折叠，这也是现代布局里很少遇到折叠问题的原因。

为什么少用 overflow: hidden

overflow: hidden 能创建 BFC，但会裁剪超出的内容，例如阴影、下拉菜单、position: absolute 的提示。overflow: auto 可能出现意外的滚动条。用 flow-root 表达意图更直接。

常见追问

  • 现在还需要 BFC 吗？新布局多用 flex 和 grid，浮动主要用于文字环绕。理解 BFC 仍有助于排查旧代码和外边距问题。
