BFC 解决哪些布局问题，什么时候用 flow-root？

BFC 是一块独立的布局区域，里面的浮动和外边距不会影响外面。它能让父元素包住浮动、避开旁边的浮动、阻止父子外边距折叠；只想要 BFC 时用 display: flow-root。

参考答案

简答

可以把 BFC 理解成页面上一块独立的布局区域，全称是块级格式化上下文。区域里的块从上往下排，里面的浮动只影响这块区域里的内容。

新建一个 BFC 常用来解决三个问题：父元素包不住浮动的子元素，高度塌了；一个块想躲开旁边的浮动，而不是钻到它下面；父元素和子元素的上下外边距折叠到了一起。

创建 BFC 的办法很多，比如 display: flow-root、overflow 不是 visible 或 clip、浮动、绝对定位、inline-block、flex 和 grid 的项目、contain: layout。

只是想要 BFC 的话，用 display: flow-root。以前常用的 overflow: hidden 会把阴影、下拉菜单这些超出的内容裁掉。

父元素为什么包不住浮动的图片

下面是常见的“图片在左、文字在右”的媒体块：

CSS
.media {
  display: flow-root;
}

.media img {
  float: left;
  margin-inline-end: 12px;
}

如果去掉 display: flow-root，文字很短而图片很高时，父元素的背景和边框会比图片矮一截，图片露到外面。

原因是普通的父元素算高度时，不把浮动的子元素算进去。父元素成为 BFC 以后，规则变了，它的高度会把内部的浮动包进来。这就是以前说的“清除浮动”。

怎样让一个块躲开旁边的浮动

CSS
.aside {
  float: left;
  width: 200px;
}

.main {
  display: flow-root;
}

.main 如果只是普通的块，它的盒子其实会一直延伸到浮动元素下面，只有里面的文字绕开浮动。给它加背景色就能看出来，背景压在了浮动元素底下。

.main 成为 BFC 后，BFC 不能和外面的浮动重叠，所以整个盒子会缩到浮动元素旁边，两栏布局就出来了。

外边距折叠是怎么回事

上下相邻的两个块，一个 margin-bottom: 20px，一个 margin-top: 30px，它们之间的距离是 30px，不是 50px。两个垂直外边距合成了一个，这叫外边距折叠。父元素和它第一个或最后一个子元素之间也会这样，子元素的 margin-top 会“跑到”父元素外面去。

父元素成为 BFC 后，子元素的外边距就留在父元素里面了。不过要阻止父子折叠，不一定非得用 BFC，给父元素加 padding 或 border 也可以。

flex 和 grid 容器里的项目之间不会发生外边距折叠，这也是现在写布局很少碰到这个问题的原因。

为什么不推荐用 overflow: hidden 创建 BFC

overflow: hidden 确实能创建 BFC，但它的本职是裁剪超出的内容。卡片的阴影、展开的下拉菜单、position: absolute 的提示框，只要超出父元素就会被切掉。换成 overflow: auto，又可能冒出意外的滚动条。

flow-root 就是专门用来创建 BFC 的，没有这些副作用，读代码的人也一眼能看出意图。

常见追问

现在都用 flex 和 grid 了，还需要了解 BFC 吗？

新写的布局确实多用 flex 和 grid，浮动主要留给文字环绕图片。但理解 BFC 还是有用的，维护旧代码、排查外边距为什么跑出去，都离不开它。
