React Server Functions/Actions 的边界是什么？

Server Function 是标了 'use server'、只在服务端执行的函数，客户端拿到的只是一个引用，调用时框架发请求去服务端执行。参数和返回值必须能序列化，而且每个 Server Function 都等于一个公开接口，认证、授权和校验都要自己做。

参考答案

简答

在函数体或文件顶部写上 'use server'，打包工具就会把这个函数留在服务端，客户端只拿到一个引用。客户端调用它时，框架发一个请求到服务端，执行完再把结果送回来。这种函数叫 Server Function；传给 <form action> 或在 Action 里调用时，通常叫 Server Action。

因为中间隔了一次网络传输，参数和返回值必须能被 React 序列化。基本类型、普通对象、数组、Date、FormData、Promise 都可以；类实例和普通函数不行，Server Function 本身除外。

它的好处是写表单提交、改数据时不用自己定义接口和写 fetch。它需要框架支持，比如 Next.js App Router。

最要注意的是安全。每个 Server Function 都相当于一个任何人都能调用的 HTTP 接口，必须在函数内部做认证、授权和参数校验，不能指望“按钮只对管理员显示”。另外要用打过安全补丁的版本，2025 年 12 月披露的 CVE-2025-55182 影响 react-server-dom-* 的多个 19.x 版本。

先看一个发帖的例子

服务端的 Action 放在单独的文件里，文件顶部写 'use server'：

JSX
// app/actions.js
'use server';

import { z } from 'zod';
import { auth } from './auth';
import { db } from './db';

const schema = z.object({ title: z.string().min(1).max(100) });

export async function createPost(prevState, formData) {
  const session = await auth();
  if (!session) return { error: '请先登录' };

  const parsed = schema.safeParse({ title: formData.get('title') });
  if (!parsed.success) return { error: '标题长度应为 1–100 个字符' };

  await db.post.create({ data: { title: parsed.data.title, authorId: session.userId } });
  return { error: null };
}

客户端组件直接导入它，交给 useActionState：

JSX
// app/new-post.jsx
'use client';

import { useActionState } from 'react';
import { createPost } from './actions';

export function NewPost() {
  const [state, action, pending] = useActionState(createPost, { error: null });
  return (
    <form action={action}>
      <input name="title" />
      <button disabled={pending}>发布</button>
      {state.error && <p role="alert">{state.error}</p>}
    </form>
  );
}

客户端看起来是直接导入了一个函数，但打包后它拿到的只是引用。db、auth 这些服务端代码不会进入浏览器的包。

注意 createPost 一上来就检查登录、校验标题，而且 authorId 是从服务端的会话里取的，不是从表单里拿的。因为任何人都能绕过页面，直接构造请求调用这个函数。如果 authorId 由表单提交，用户改一下就能冒充别人发帖。

闭包里的变量也会发到客户端

在 Server Component 里直接内联定义 Server Function 时，它用到的外部变量会被序列化后发给客户端，调用时再传回服务端。

这意味着用户能看到这些值。所以不要在闭包里捕获密钥或者不想让用户看到的数据，需要保密的值放在函数内部重新读取。

和 Server Components 有什么区别

两者都在服务端运行，但方向相反。Server Component 在服务端渲染、输出 UI，客户端不能主动调用它。Server Function 是客户端可以调用的服务端函数，主要用来改数据。

还有一个常见误会：'use server' 不是用来标记 Server Component 的。Server Component 不需要任何指令。详见《React Server Components 和 SSR 是同一件事吗？》。

常见追问

改完数据以后页面怎么刷新？

由框架提供。例如在 Next.js 里，在 Action 中调用 revalidatePath 或 updateTag，让相关页面重新获取数据。

能用 Server Function 读数据吗？

不推荐。框架通常一次只处理一个 Action，用它读数据会排队变慢。读数据应该放在 Server Component 或数据加载层里。
