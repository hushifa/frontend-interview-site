WebGL 着色器如何工作？如何避免把 GPU 当成黑盒？

顶点着色器决定每个顶点画在哪，片元着色器决定每个片元是什么颜色，之后还有深度测试和混合。讲清坐标空间、属性与 uniform 的区别、片元阶段的分辨率成本和精度，并给出一个完整的三角形绘制示例。

参考答案

简答

着色器是跑在 GPU 上的小程序，WebGL 画一个图形要写两段。顶点着色器对每个顶点跑一次，算出它在屏幕上的位置，输出裁剪空间坐标 gl_Position。GPU 再把三角形拆成一个个片元，片元可以先理解成“候选像素”，片元着色器对每个片元跑一次，算出颜色。之后还要经过深度测试和混合，才真正写进画面。

数据有三种入口：顶点属性，每个顶点各不相同，放在缓冲区里；uniform，一次绘制里所有顶点共用，比如矩阵、时间；还有纹理，也就是图片或查找表。

画面不对时，多半是坐标空间没理清。模型、世界、视图、裁剪空间之间的矩阵顺序要写清楚。

还要注意两点。片元着色器的执行次数跟像素数成正比，全屏特效在高分辨率屏上很费。另外 GLSL 的编译和链接错误不会变成 JavaScript 异常，要自己去读 getShaderInfoLog()、getProgramInfoLog()。

两段着色器长什么样

下面是 WebGL 1（GLSL ES 1.00）的写法。先看顶点着色器：

glsl
// 顶点着色器
attribute vec2 a_position;
attribute vec3 a_color;
uniform mat3 u_transform;
varying mediump vec3 v_color;

void main() {
  vec3 p = u_transform * vec3(a_position, 1.0);
  gl_Position = vec4(p.xy, 0.0, 1.0);
  v_color = a_color;
}

再看片元着色器：

glsl
// 片元着色器
precision mediump float;
varying mediump vec3 v_color;

void main() {
  gl_FragColor = vec4(v_color, 1.0);
}

a_position、a_color 是顶点属性，每个顶点一份。u_transform 是 uniform，所有顶点共用。v_color 是从顶点着色器传给片元着色器的值。

可是顶点只有三个，片元却有成百上千个，每个片元的 v_color 从哪来？答案是 GPU 会在三角形内部插值。所以每个片元拿到的，是三个顶点颜色按距离混合的结果。

WebGL 2 用 #version 300 es，把 attribute/varying 换成 in/out。片元输出也要自己声明一个 out vec4，不再用 gl_FragColor。

完整画一个三角形要哪些步骤

下面的函数编译着色器、上传顶点、画一个三角形，最后读回画布中心的像素：

JavaScript
function compile(gl, type, source) {
  const shader = gl.createShader(type);
  gl.shaderSource(shader, source);
  gl.compileShader(shader);
  if (!gl.getShaderParameter(shader, gl.COMPILE_STATUS)) {
    throw new Error(gl.getShaderInfoLog(shader));
  }
  return shader;
}

function drawTriangle(canvas, vertexSource, fragmentSource) {
  const gl = canvas.getContext('webgl');
  if (!gl) throw new Error('无法创建 WebGL 上下文');

  const program = gl.createProgram();
  gl.attachShader(program, compile(gl, gl.VERTEX_SHADER, vertexSource));
  gl.attachShader(program, compile(gl, gl.FRAGMENT_SHADER, fragmentSource));
  gl.bindAttribLocation(program, 0, 'a_position'); // 让位置属性占用 0 号位置
  gl.linkProgram(program);
  if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
    throw new Error(gl.getProgramInfoLog(program));
  }
  gl.useProgram(program);

  const buffer = gl.createBuffer();
  gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
  gl.bufferData(gl.ARRAY_BUFFER, new Float32Array([-1, -1, 1, -1, 0, 1]), gl.STATIC_DRAW);
  gl.enableVertexAttribArray(0);
  gl.vertexAttribPointer(0, 2, gl.FLOAT, false, 0, 0);

  const color = gl.getAttribLocation(program, 'a_color');
  gl.vertexAttrib3f(color, 1, 0, 0); // 不启用数组时，所有顶点共用这个常量值
  gl.uniformMatrix3fv(gl.getUniformLocation(program, 'u_transform'), false,
    new Float32Array([1, 0, 0, 0, 1, 0, 0, 0, 1]));

  gl.viewport(0, 0, canvas.width, canvas.height);
  gl.drawArrays(gl.TRIANGLES, 0, 3);

  const pixel = new Uint8Array(4);
  gl.readPixels(canvas.width / 2, canvas.height / 2, 1, 1, gl.RGBA, gl.UNSIGNED_BYTE, pixel);
  return pixel;
}

步骤是：编译两段着色器，链接成一个程序；把三个顶点的坐标上传到缓冲区，告诉 GPU 怎么读；设好颜色和矩阵；最后 drawArrays 画出来。

注意 compile 和链接后的检查。GLSL 写错了，compileShader 不会抛异常，只会把状态标成失败，所以要主动检查，再把日志读出来。

颜色这里没用缓冲区，而是 vertexAttrib3f 设了一个常量，所以三个顶点都是红色。矩阵是单位矩阵，坐标原样输出。三个顶点 (-1, -1)、(1, -1)、(0, 1) 构成的三角形盖住了画布中心，所以 readPixels 读出的中心像素是红色 [255, 0, 0, 255]。

坐标是怎样一步步变到屏幕上的

text
裁剪坐标 = 投影矩阵 × 视图矩阵 × 模型矩阵 × 模型坐标

模型矩阵把模型放进世界，视图矩阵相当于摆相机，投影矩阵决定透视效果。GPU 拿到裁剪坐标后做透视除法，得到标准化设备坐标，范围是 -1 到 1，再由 viewport 映射成像素。

WebGL 的矩阵按列主序传入，所以要和 JavaScript 端数学库的约定一致，不然矩阵会被转置。调试时可以先用单位矩阵画一个三角形，确认能画出来，再一个个把变换加进去。

性能和精度要注意什么

几何数据一次上传到缓冲区，每帧只更新 uniform。不要每帧重建缓冲区，也不要每个小物体都用一个单独的程序。相同材质的对象合并起来画，或者用实例化绘制。

mediump 的精度在不同设备上不一样。坐标很大的场景会出现抖动，可以改用 highp，或者让坐标相对于相机来算，让数值变小。

纹理里的颜色多数是 sRGB，参与光照计算之前要先转到线性空间，否则算出来的亮度会偏。

安全上要注意什么

不要把用户输入拼进 GLSL 源码里。用户的数据要通过属性、uniform 或纹理传进去。模型和纹理还要限制尺寸，防止把显存耗光。

常见追问

为什么要把位置属性绑定到 0 号？

在部分 WebGL 1 实现上，0 号属性如果没有启用数组，会走一条慢路径。把最常用的位置属性固定在 0 号，就能避开这个问题。

透明物体为什么显示错乱？

因为混合的结果依赖绘制顺序。透明物体通常要从远到近排序再画，并关掉深度写入。
