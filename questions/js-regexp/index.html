正则表达式在前端使用时需要注意什么？

前端写正则常踩四个坑。带 g 的正则反复 test 会记住上次的位置；用户输入拼进正则前要转义；处理 emoji 这类字符要加 u 标志；嵌套的量词可能让匹配卡死页面。

参考答案

简答

第一个坑是状态。带 g 或 y 标志的正则对象会记住上次匹配到哪里，存在 lastIndex 上，test、exec 会从这个位置开始找并更新它，所以同一个正则反复 test 会得到交替的结果。另外，校验整个输入时要加 ^ 和 $，不然只要包含一段能匹配的内容就返回 true。

第二个坑是拼接。把用户输入拼进正则之前，要把 .、* 这些有特殊含义的字符转义，ES2025 提供了 RegExp.escape。

第三个是 Unicode。emoji 这类字符在 JavaScript 里占两个位置，不加 u 或 v 标志时，. 只能匹配半个；\p{...} 这种按字符属性匹配的写法也需要这两个标志。

最后是性能。(a+)+ 这种嵌套量词，在匹配失败时可能要尝试指数级的组合。正则运行在主线程上，跑久了页面就卡死，这叫 ReDoS。

同一个正则为什么第二次就不匹配了

JavaScript
const pattern = /a/g;
console.log(pattern.test('a')); // true
console.log(pattern.test('a')); // false
console.log(pattern.lastIndex); // 0

同一个正则，同一个字符串，第一次是 true，第二次却是 false。

原因是带 g 的正则会记录位置。第一次匹配成功后，lastIndex 变成了 1，表示下次从第 1 个字符开始找。第二次从位置 1 开始，后面没有字符了，找不到，于是返回 false，同时把 lastIndex 重置为 0。所以第三次又会是 true，结果来回交替。

改法很简单：只判断匹不匹配时，不要加 g。String.prototype.match、matchAll、replace 这些字符串方法不受这个问题影响。

校验时为什么要加 ^ 和 $

JavaScript
/\d+/.test('abc123');    // true，包含数字
/^\d+$/.test('abc123');  // false，整串必须是数字

/\d+/ 的意思是“包含至少一个数字”，'abc123' 里有数字，所以通过了。想校验“整串都是数字”，要用 ^ 和 $ 把开头和结尾都锁住。

用户输入拼进正则为什么要转义

JavaScript
const keyword = 'a.b';
new RegExp(keyword).test('axb');                 // true，. 匹配任意字符
new RegExp(RegExp.escape(keyword)).test('axb');  // false

用户想搜的是字面的 a.b，可是 . 在正则里表示任意一个字符，'axb' 也被匹配上了。用 RegExp.escape 把 . 转义以后，它就只匹配真正的点号。

RegExp.escape 是 ES2025 的特性，MDN 标注为 Baseline 2025，也就是 2025 年 5 月起主流浏览器的最新版都能用。需要兼容旧环境时，用 core-js 这类 polyfill，或者自己转义 [.*+?^${}()|[\]\\] 这些字符。

emoji 为什么匹配不上

JavaScript
/^.$/.test('😀');    // false，emoji 是两个 UTF-16 码元
/^.$/u.test('😀');   // true
/\p{Script=Han}/u.test('汉'); // true

/^.$/ 表示“正好一个字符”，可一个 emoji 却匹配失败了。因为 JavaScript 字符串按 UTF-16 码元存储，常用汉字占一个码元，emoji 这类字符要占两个。不加 u 时，. 只匹配一个码元，也就是半个 emoji。加上 u 后，正则按完整的字符来匹配，就对了。

\p{Script=Han} 表示“汉字”，这种按 Unicode 属性匹配的写法，也要加 u 才能用。ES2024 的 v 标志是 u 的升级版，还支持字符类之间的集合运算，比如 [\p{L}--[a-z]] 表示“所有字母，去掉小写的 a 到 z”。

具名捕获组怎样用

JavaScript
const { year, month } = /(?<year>\d{4})-(?<month>\d{2})/.exec('2026-10').groups;

用 (?<名字>...) 给捕获组起名字，结果的 groups 上就能按名字取，不用记第几组。在 replace 里可以用 $<year> 引用。ES2025 起，不同的分支里可以用同一个组名。

怎样避免正则卡死页面

JavaScript
/^(a+)+$/.test('a'.repeat(30) + 'b'); // 可能耗时数分钟

30 个 a 加一个 b，看着很短，却可能跑几分钟。

因为结尾的 b 让匹配注定失败，而引擎在宣布失败前，要把 30 个 a 在内外两层 + 之间的所有拆分方式都试一遍，组合数是指数级的。这个过程叫回溯，这种被恶意输入拖垮的情况叫 ReDoS。

防护办法有三个。第一，避免嵌套量词和可能重叠的分支，比如 (a+)+ 其实就等于 a+。第二，匹配之前先限制输入长度。第三，正则或文本不可信时，放到 Worker 里执行，超时就调用 terminate() 结束它。setTimeout 是打断不了正在运行的同步匹配的，因为它的回调要等主线程空下来才能执行。

常见追问

replace 和 replaceAll 有什么区别？

replace 第一个参数传字符串时，只替换第一个匹配。replaceAll 会替换全部，它传正则时，正则必须带 g，否则报错。

s 标志做什么？

默认情况下 . 不匹配换行符，加上 s 以后，. 也能匹配换行。

d 标志做什么？

加上 d 以后，匹配结果会多一个 indices 属性，记录每个捕获组在原字符串里的起止位置。
