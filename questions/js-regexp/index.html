正则表达式在前端使用时需要注意什么？

前端正则常见问题有四类：带 g 或 y 标志的正则在 test/exec 间共享 lastIndex；用户输入拼进正则前要转义（ES2025 的 RegExp.escape）；处理非 ASCII 文本要加 u 或 v 标志；嵌套量词可能导致灾难性回溯（ReDoS）。

参考答案

简答

  • 带 g 或 y 标志的正则对象有状态：test、exec 会从 lastIndex 开始匹配并更新它，复用同一个对象会得到交替的结果。
  • 校验整个输入要加 ^ 和 $；不加时只要包含匹配片段就返回 true。
  • 把用户输入拼进正则前必须转义元字符，ES2025 提供 RegExp.escape。
  • 处理 emoji 或其他非 BMP 字符时加 u 或 v 标志，\p{...} 属性类也需要它们。
  • (a+)+ 这类嵌套量词在不匹配时会指数级回溯，正则运行在主线程上，会冻结页面。

lastIndex 的状态

JavaScript
const pattern = /a/g;
console.log(pattern.test('a')); // true
console.log(pattern.test('a')); // false
console.log(pattern.lastIndex); // 0

第一次匹配后 lastIndex 变为 1，第二次从位置 1 开始找不到，返回 false 并把 lastIndex 重置为 0。只判断是否匹配时不要加 g；String.prototype.match、matchAll、replace 不受这个问题影响。

校验与搜索

JavaScript
/\d+/.test('abc123');    // true，包含数字
/^\d+$/.test('abc123');  // false，整串必须是数字

动态拼接要转义

JavaScript
const keyword = 'a.b';
new RegExp(keyword).test('axb');                 // true，. 匹配任意字符
new RegExp(RegExp.escape(keyword)).test('axb');  // false

RegExp.escape 是 ES2025 特性，MDN 标注为 Baseline 2025（2025 年 5 月起主流浏览器最新版可用）。需要兼容旧环境时用 core-js 等 polyfill，或自行转义 [.*+?^${}()|[\]\\]。

Unicode

JavaScript
/^.$/.test('😀');    // false，emoji 是两个 UTF-16 码元
/^.$/u.test('😀');   // true
/\p{Script=Han}/u.test('汉'); // true

v 标志（ES2024）是 u 的升级版，支持字符类集合运算，如 [\p{L}--[a-z]]。

具名捕获组

JavaScript
const { year, month } = /(?<year>\d{4})-(?<month>\d{2})/.exec('2026-10').groups;

replace 中用 $<year> 引用。ES2025 起不同分支可以使用同名捕获组。

ReDoS

JavaScript
/^(a+)+$/.test('a'.repeat(30) + 'b'); // 可能耗时数分钟

不匹配时引擎会尝试所有拆分方式。防护措施：

  • 避免嵌套量词和可重叠的分支，例如把 (a+)+ 改成 a+。
  • 限制输入长度后再匹配。
  • 对不受信任的正则或长文本，放到 Worker 里执行，超时后 terminate()。setTimeout 无法打断正在运行的同步匹配。

常见追问

  • replace 和 replaceAll 的区别？replace 传字符串只替换第一个；replaceAll 传正则时必须带 g。
  • s 标志做什么？让 . 也匹配换行符。
  • d 标志做什么？在结果的 indices 属性中返回每个捕获组的起止位置。
