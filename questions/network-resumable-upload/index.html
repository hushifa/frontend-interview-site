浏览器分片上传如何实现可靠的暂停与续传？

服务端创建上传会话并记录已收到的分片；浏览器用 File.slice 切片、限制并发上传、失败重试。暂停就是取消进行中的请求，续传时先向服务端查询已完成的分片，只补传缺失部分，全部完成后由服务端合并并校验。

参考答案

简答

  • 以服务端的上传会话为准：会话 ID、文件大小、分片大小、已收到的分片编号。浏览器本地记录只用来加速，不能作为依据。
  • file.slice() 只是创建引用，不会把整个文件读进内存。
  • 每个分片的上传是幂等的：同一编号重复上传覆盖旧数据，所以超时后可以安全重试。
  • 暂停用 AbortController 取消进行中的请求；续传先查询服务端已完成的分片，再补传。
  • 合并时校验总大小和整体哈希；页面刷新后需要用户重新选择文件，浏览器不会保留文件访问权限。

流程

  1. POST /uploads，提交文件名、大小、分片大小，得到 uploadId。
  2. 并发上传分片 PUT /uploads/:id/parts/:index。
  3. 暂停：abort 所有进行中的请求。
  4. 续传：GET /uploads/:id 得到已完成分片，只上传其余的。
  5. POST /uploads/:id/complete，服务端合并、校验、返回最终文件地址。

上传器

JavaScript
async function uploadFile(file, uploadId, { partSize, concurrency = 3, signal }) {
  const total = Math.ceil(file.size / partSize);
  const { done } = await fetch(`/uploads/${uploadId}`, { signal }).then((r) => r.json());
  const pending = [];
  for (let i = 0; i < total; i += 1) if (!done.includes(i)) pending.push(i);

  async function sendPart(index) {
    for (let attempt = 0; ; attempt += 1) {
      const body = file.slice(index * partSize, (index + 1) * partSize);
      const response = await fetch(`/uploads/${uploadId}/parts/${index}`, {
        method: 'PUT',
        body,
        signal,
      });
      if (response.ok) return;
      // 401、403、413 等客户端错误重试无效，直接失败
      if (response.status < 500 && response.status !== 429) {
        throw new Error(`分片 ${index} 被拒绝：${response.status}`);
      }
      if (attempt >= 3) throw new Error(`分片 ${index} 多次失败`);
      await new Promise((resolve) => setTimeout(resolve, 1000 * 2 ** attempt));
    }
  }

  async function worker() {
    while (pending.length > 0) await sendPart(pending.shift());
  }

  await Promise.all(Array.from({ length: Math.min(concurrency, pending.length) }, worker));
  const res = await fetch(`/uploads/${uploadId}/complete`, { method: 'POST', signal });
  if (!res.ok) throw new Error(`合并失败：HTTP ${res.status}`);
  return res.json();
}

fetch 本身因为网络中断而拒绝时，sendPart 会直接抛出，这里没有重试网络错误；实际项目里可以在外层捕获后提示用户点击续传，或者对非 AbortError 的错误同样退避重试。

细节

  • 进度：fetch 不提供上传进度事件，按完成的分片数计算；需要单个分片内的细粒度进度时用 XMLHttpRequest.upload.onprogress。
  • 分片大小：太小请求数多，太大失败后重传成本高，通常取几 MB，按网络情况调整。
  • 完整性：分片请求带上分片哈希，服务端校验；合并后校验整体哈希。整体哈希可以在 Worker 中计算，避免阻塞页面。
  • 秒传：上传前用文件哈希查询服务端是否已有相同文件。哈希只能作为去重依据，权限仍要校验。
  • 清理：服务端为未完成的会话设置过期时间，到期删除分片。

常见追问

  • 刷新页面后怎么续传？把 uploadId 和文件名、大小、修改时间存在 localStorage，用户重新选择同一文件后匹配会话。
  • 直传对象存储怎么做？会话和分片签名由业务服务器管理，见《浏览器直传对象存储时，如何设计安全的分片上传？》。
