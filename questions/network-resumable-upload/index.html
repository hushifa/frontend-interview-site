浏览器分片上传如何实现可靠的暂停与续传？

把大文件切成小块分别上传，服务端记下收到了哪些块。暂停就是取消进行中的请求；续传时先问服务端缺哪些，只补传缺的，最后由服务端合并并校验。

参考答案

简答

上传一个 2GB 的视频，传到 90% 断网了，用户肯定不想从头再来。做法是把文件切成几 MB 一块，一块一块传，服务端记下收到了哪些块。

这里以服务端的上传会话为准：会话 ID、文件大小、分片大小、已收到的分片编号都记在服务端。浏览器本地的记录只用来加速，不能当依据。切片用 file.slice()，它只是创建一个引用，不会把整个文件读进内存。

每个分片的上传是幂等的，同一编号重复上传会覆盖旧数据，所以超时了可以放心重试。暂停就用 AbortController 取消进行中的请求；续传时先问服务端哪些已经完成，只补传剩下的。

最后合并时要校验总大小和整体哈希。还有一点要注意：页面刷新后，用户得重新选一次文件，浏览器不会替你保留文件的访问权限。

先看 slice 切出来是什么

用一个 10 字节的 Blob 模拟文件，每块 4 字节。这段可以在 Node 18 以上运行：

JavaScript
const file = new Blob(['abcdefghij']); // 10 字节
const partSize = 4;
const total = Math.ceil(file.size / partSize);
for (let index = 0; index < total; index += 1) {
  const part = file.slice(index * partSize, (index + 1) * partSize);
  console.log(index, part.size, await part.text());
}
// 0 4 abcd
// 1 4 efgh
// 2 2 ij

最后一块只有 2 字节。slice 的结束位置超过文件末尾也没关系，它会自动截到末尾，所以不用单独处理最后一块。浏览器里的 File 继承自 Blob，用法一样。

整个流程

  1. POST /uploads，提交文件名、大小、分片大小，拿到 uploadId。
  2. 并发上传分片 PUT /uploads/:id/parts/:index。
  3. 暂停：abort 所有进行中的请求。
  4. 续传：GET /uploads/:id 拿到已完成的分片，只上传其余的。
  5. POST /uploads/:id/complete，服务端合并、校验，返回最终的文件地址。

上传器怎么写

JavaScript
async function uploadFile(file, uploadId, { partSize, concurrency = 3, signal }) {
  const total = Math.ceil(file.size / partSize);
  const { done } = await fetch(`/uploads/${uploadId}`, { signal }).then((r) => r.json());
  const pending = [];
  for (let i = 0; i < total; i += 1) if (!done.includes(i)) pending.push(i);

  async function sendPart(index) {
    for (let attempt = 0; ; attempt += 1) {
      const body = file.slice(index * partSize, (index + 1) * partSize);
      const response = await fetch(`/uploads/${uploadId}/parts/${index}`, {
        method: 'PUT',
        body,
        signal,
      });
      if (response.ok) return;
      // 401、403、413 等客户端错误重试无效，直接失败
      if (response.status < 500 && response.status !== 429) {
        throw new Error(`分片 ${index} 被拒绝：${response.status}`);
      }
      if (attempt >= 3) throw new Error(`分片 ${index} 多次失败`);
      await new Promise((resolve) => setTimeout(resolve, 1000 * 2 ** attempt));
    }
  }

  async function worker() {
    while (pending.length > 0) await sendPart(pending.shift());
  }

  await Promise.all(Array.from({ length: Math.min(concurrency, pending.length) }, worker));
  const res = await fetch(`/uploads/${uploadId}/complete`, { method: 'POST', signal });
  if (!res.ok) throw new Error(`合并失败：HTTP ${res.status}`);
  return res.json();
}

一开始先问服务端哪些分片已经完成，把剩下的放进 pending。这样首次上传和续传走的是同一套代码，首次上传时 done 是空数组而已。

并发是怎么控制的？开 concurrency 个 worker，每个 worker 从 pending 里取一个传一个，传完再取下一个。所以同时在传的分片最多就这么几个。

重试也区分了情况。5xx 和 429 是暂时的，等 1 秒、2 秒、4 秒再试，最多重试 3 次；其他 4xx 重试也没用，直接失败。暂停时外面调 controller.abort()，所有带着这个 signal 的请求都会被取消。

但要注意，fetch 本身因为网络中断而失败时，sendPart 会直接抛出，这段代码没有重试网络错误。实际项目里可以在外层捕获后提示用户点续传，或者对不是 AbortError 的错误同样退避重试。

还有哪些细节

进度怎么算？fetch 不提供上传进度事件，所以按完成的分片数算。需要单个分片内更细的进度，就用 XMLHttpRequest.upload.onprogress。

分片多大合适？太小请求数太多，太大失败后重传成本高，一般取几 MB，按网络情况调。

完整性怎么保证？分片请求带上分片的哈希，服务端校验；合并后再校验整体哈希。整体哈希可以放在 Worker 里算，不卡页面。

秒传是怎么回事？上传前先用文件哈希问服务端有没有相同的文件，有就不用传了。但哈希只能当去重依据，权限还是要校验。

最后别忘了清理。服务端给没完成的会话设过期时间，到期就把分片删掉。

常见追问

刷新页面后怎么续传？

把 uploadId 和文件名、大小、修改时间存进 localStorage。用户重新选了同一个文件后，用这些信息匹配到原来的会话。
