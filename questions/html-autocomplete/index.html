HTML autocomplete 属性怎样帮助表单体验和隐私？

autocomplete 用一组标准词告诉浏览器和密码管理器这个输入框是填什么的，比如 email、new-password、one-time-code。它只是提示，填进来的数据还是要校验。

参考答案

简答

autocomplete 告诉浏览器这个输入框是填什么的，用的是一组标准的词，叫令牌。写对了，浏览器能一键填好姓名、地址、电话，手机上能少打很多字。

登录表单用 username 和 current-password；注册和改密码用 new-password，浏览器会据此建议生成一个强密码。短信验证码用 one-time-code，iOS Safari 能从短信里把验证码提取出来填进去。令牌还能组合，比如 shipping postal-code、billing street-address，区分收货和账单。

有人为了“安全”写 autocomplete="off"。但它只是提示，浏览器对登录框通常会忽略。而且不要为了安全关掉密码填充，这样用户只会改用更好记的弱密码。

要注意，它只是提示，不是限制。自动填进来的数据，服务端还是要校验。

登录表单

HTML
<form>
  <label>
    邮箱
    <input type="email" name="email" autocomplete="username" required>
  </label>
  <label>
    密码
    <input type="password" name="password" autocomplete="current-password" required>
  </label>
  <button>登录</button>
</form>

账号字段明明是邮箱，为什么写 username 而不是 email？因为对密码管理器来说，它是“跟这个密码配对的账号”。写 username，密码管理器才能正确保存和填充这对账号密码。

地址和支付

HTML
<input name="name" autocomplete="name">
<input name="tel" type="tel" autocomplete="tel">
<input name="address" autocomplete="shipping street-address">
<input name="postal" autocomplete="shipping postal-code">
<input name="cc" autocomplete="cc-number" inputmode="numeric">
<input name="exp" autocomplete="cc-exp">

同一个页面上既有收货地址又有账单地址时，要用 shipping 和 billing 区分开。不区分的话，浏览器分不清两组字段，会把它们都填成一样的值。

和无障碍有什么关系

WCAG 1.3.5“识别输入用途”要求，收集用户个人信息的字段要标明用途，autocomplete 就是满足它的标准做法。

WCAG 2.2 新增的 3.3.7“冗余输入”要求，同一个流程里已经填过的信息，不要再让用户重复输入。自动填充也能帮助满足这一条。

和隐私有什么关系

自动填充有可能把信息填进页面上看不见的字段里。所以不要在表单里放隐藏的输入框去偷偷收集额外信息。

在共享设备上，要不要保存数据由用户自己决定。网站能做的，是不阻止正常的填充，并提供退出登录。

常见追问

为什么 autocomplete="off" 对密码框不起作用？

浏览器认为，阻止保存密码反而会降低安全性，用户会去用弱密码或者重复用同一个密码。所以主流浏览器对登录字段会忽略这个值。
