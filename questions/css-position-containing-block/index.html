absolute、fixed 和 sticky 的定位参照是什么？

absolute 相对其绝对定位包含块定位，fixed 通常相对视口但可能受 transform 等祖先影响，sticky 则同时受最近滚动容器和自身包含块边界约束。三者不能统一理解成相对父元素。

参考答案

简答

  • 定位错位先找包含块：absolute 通常相对最近建立定位包含块的祖先的 padding box。
  • 非 none 的 transform、某些 contain 和 will-change 也会建立包含块，甚至让 fixed 元素不再相对视口。
  • sticky 在流中占位，需要设置所在轴的偏移（如 top: 0），并受最近滚动容器和自身包含块范围限制。
  • sticky 不生效时检查偏移、祖先的 overflow 和可活动空间。

top: 0 只说明“距离某个参照区域的顶部为 0”，没有说明这个区域是谁。定位错位时，首先要找的是包含块：浏览器用来计算元素尺寸和位置的参照矩形。它不一定是 DOM 的直接父元素，也不一定是整个屏幕。

absolute：找建立绝对定位包含块的祖先

常见做法是在卡片上设置 position: relative，让右上角的徽章相对卡片定位：

HTML
<article class="card">
  <span class="badge">新内容</span>
  <h2>CSS 定位</h2>
  <p>徽章跟随卡片，正文正常参与排版。</p>
</article>
CSS
.card {
  position: relative;
  padding: 3rem 1rem 1rem;
  border: 1px solid #cbd5e1;
}

.badge {
  position: absolute;
  top: 0.75rem;
  right: 0.75rem;
}

.card 仍然占据正常流中的位置，单独设置 position: relative 而不偏移，不会把它移走；.badge 脱离正常流，不会为自己预留一行。卡片顶部的内边距是特意给徽章腾出的空间。

对于这种普通块级定位祖先，绝对定位包含块通常由祖先的 padding box 边缘形成。top: 0 不是“放到祖先内容区文字起点”，不能忽略祖先的内边距和边框。

如果没有相应祖先，绝对定位会回到初始包含块。只记“最近非 static 祖先”仍然不够：transform 非 none、某些 contain、相关 will-change 等条件，也可能建立绝对定位包含块，即便祖先本身没有改 position。

fixed：通常固定在视口，但有例外

CSS
.help {
  position: fixed;
  right: 1rem;
  bottom: 1rem;
}

没有特殊祖先时，帮助按钮通常固定在视口右下角，随页面滚动不会像普通内容那样滚走。它也脱离正常流，因此需要确保不会挡住最后一段内容或表单操作。

但如果按钮被放进下面这样的祖先：

CSS
.panel {
  transform: translateZ(0);
}

这个非 none 的 transform 会为固定定位后代建立包含块。即使 translateZ(0) 看起来没有移动任何东西，按钮也可能变成相对 .panel 定位，随这个面板一起滚动。

这也是“给祖先加了一个性能优化样式，悬浮按钮突然不悬浮”的常见原因。contain: layout、contain: paint 等条件也需要检查；filter、perspective 相关行为还要结合目标浏览器确认。仅在父级加 position: relative，则不会像 transform 一样自动把普通 fixed 后代的参照改到父级。

组件库把浮层通过 Portal 挂到更靠外的容器，常常是为了避开这样的祖先条件。但 Portal 只改变挂载位置，不会自动解决所有遮挡、裁剪和交互问题。

sticky：在流中占位，再受滚动阈值约束

sticky 最适合章节标题、表头、目录等“开始跟着内容走，到了某个位置再暂时停住”的元素。

HTML
<div class="reader">
  <section>
    <h2 class="chapter-title">第一章</h2>
    <p>这里放置足够长的章节内容，使 reader 产生滚动。</p>
  </section>
</div>
CSS
.reader {
  max-height: 24rem;
  overflow: auto;
}

.chapter-title {
  position: sticky;
  top: 0;
  margin: 0;
  padding: 0.75rem;
  background: white;
  z-index: 1;
}

当 .reader 的实际内容超过限高时，它成为可滚动区域。标题先按正常流排版，占位不消失；滚动到顶部阈值后，浏览器调整标题的视觉位置，使其在允许范围内贴住这个滚动区域顶部。

它不是一触发就永久变成 fixed。标题还要留在自身包含块的边界范围内，章节滚动到结尾时，不能无限停留在上方。示例如果只有一小段文字、不足以滚动，就看不到吸顶过程。

sticky 没生效，应该检查什么

先检查希望吸附的轴上有没有非 auto 的偏移，比如垂直方向的 top: 0。只写 position: sticky，该轴两端偏移仍为 auto，不会得到期待的粘性效果。

然后沿祖先检查 overflow。最近带滚动机制的祖先可能是 overflow: auto、scroll 或 hidden 的盒子，即使它当前并没有实际滚动。一个为了裁切内容而加入的 overflow: hidden 容器，就可能让 sticky 不再跟随页面滚动。单独设置某一轴的 overflow 还可能影响另一轴的计算值，要看 DevTools 的计算结果，而不只看源码。

overflow: clip 单独使用时不建立滚动容器，与 hidden 不同，但它仍会裁切内容，也不支持相同的程序化滚动用途，不能不分析需求就直接替换。

最后检查空间：如果粘性元素被 Grid/Flex 拉伸得和可活动区域一样高，或者父级本来就没有足够长度，就可能没有可见的移动区间。按布局需要调整 align-self: start 等约束，比随意加大 z-index 更有效。

包含块回答“相对哪里定位”，滚动容器回答“哪块区域在滚”，层叠上下文回答“谁画在谁上面”，裁剪回答“哪些部分不允许画出来”。四者可能来自同一个祖先，但不是同一个概念，应分别定位问题。
