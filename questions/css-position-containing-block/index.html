absolute、fixed 和 sticky 的定位参照是什么？

absolute 找最近的定位祖先当参照；fixed 一般相对视口，但祖先有 transform、filter 这类属性时会改为相对这个祖先；sticky 在最近的滚动容器里吸住，而且跑不出自己的父元素。

参考答案

简答

定位元素写 top: 0，这个 0 是从哪里算起的？这个“参照框”叫包含块。absolute 的包含块是最近一个 position 不是 static 的祖先，取它的内边距盒；一个都找不到，就用初始包含块。

fixed 默认相对视口。但只要祖先设置了 transform、perspective、filter、contain: paint，或者对应的 will-change，它就改为相对这个祖先定位，这是全屏遮罩只盖住一小块的常见原因。

sticky 是在最近的滚动祖先里，滚到 top 这类阈值时吸住，但吸附范围不会超出自己的父元素。

百分比的 top、width 也是按包含块算的。浮层被裁或者位置不对时，先在开发者工具里找到它的包含块是谁。

absolute：为什么父元素要写 relative

CSS
.card {
  position: relative;
}

.card .badge {
  position: absolute;
  inset-block-start: 8px;
  inset-inline-end: 8px;
}

角标要放在卡片右上角。如果 .card 没写 position: relative，角标会一直往上找定位祖先，可能找到页面最外层，跑到整个页面的右上角去。

.card 写 position: relative 但不写偏移，它自己不会动。这么写只是为了让它成为角标的包含块。

fixed：全屏遮罩为什么只盖住了一块

CSS
.modal-wrapper {
  transform: translateZ(0);
}

.modal-wrapper .overlay {
  position: fixed;
  inset: 0;
}

.overlay 本来要盖住整个视口，结果只盖住了 .modal-wrapper 那一块。

原因是祖先有 transform。祖先一旦设置了 transform，它就成了里面 fixed 元素的包含块，inset: 0 是相对它算的。这种 transform 往往不是自己写的，而是动画库加上去的。

改法是把浮层渲染到 body 下面，React 里用 Portal 就是做这个。或者直接用 <dialog> 和 popover，它们会进入顶层，不受祖先样式影响。

sticky 为什么不生效

CSS
.table-head {
  position: sticky;
  top: 0;
}

写了这几行，表头却不吸顶，通常是下面几个原因。

第一，没有写 top、bottom 这类阈值，浏览器不知道什么时候该吸住。

第二，某个祖先设置了 overflow: hidden 或 auto。这个祖先就成了滚动容器，sticky 改为相对它吸附。可是它自己可能根本不滚动，真正在滚的是外面的页面，于是看起来就没效果。

第三，父元素和 sticky 元素一样高。sticky 不能跑出父元素，父元素没有多余的高度，就没有可以吸附的距离。

第四，在 flex 或 grid 里，sticky 元素被拉伸得和父元素一样高，跟第三种是一回事。加上 align-self: start 就好。

常见追问

overflow: clip 和 hidden 对 sticky 有区别吗？

有。hidden 会创建滚动容器，sticky 会改为相对它吸附。clip 只裁剪，不创建滚动容器，所以 sticky 还是相对外层真正在滚动的祖先吸附。
