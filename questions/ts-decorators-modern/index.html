TypeScript 新装饰器与 experimentalDecorators 有何区别？

TypeScript 5.0 起默认支持 TC39 装饰器提案：装饰器接收 (value, context) 两个参数，通过返回值替换成员、通过 context.addInitializer 注册初始化逻辑。旧的 experimentalDecorators 接收 (target, key, descriptor)，支持参数装饰器和 emitDecoratorMetadata。两者不兼容，依赖旧语义的框架（如 NestJS、TypeORM）不能直接切换。

参考答案

简答

  • 不开 experimentalDecorators 时，TypeScript 5.0+ 使用标准装饰器；开启后使用旧实现，两者签名不同。
  • 标准装饰器：(value, context) => 替换值 | void，context 提供 kind、name、static、private、addInitializer、metadata。
  • 旧装饰器：方法装饰器收 (target, propertyKey, descriptor)，通过修改描述符替换方法。
  • 标准装饰器没有参数装饰器，也不生成 design:type 等反射元数据；依赖这些的 DI 框架需要旧模式。
  • 装饰器是运行时代码，在类定义时执行；不会改变类的类型，增加的成员需要另外声明。装饰器语法不可擦除，Node.js 类型剥离无法运行。

标准方法装饰器

TypeScript
function logged<This, Args extends unknown[], Result>(
  method: (this: This, ...args: Args) => Result,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Result>,
) {
  const name = String(context.name);
  return function (this: This, ...args: Args): Result {
    console.log(`调用 ${name}`);
    return method.apply(this, args);
  };
}

class Counter {
  value = 0;

  @logged
  add(step: number): number {
    this.value += step;
    return this.value;
  }
}

new Counter().add(2); // 输出：调用 add

包装函数必须是普通函数并转发 this。被装饰的方法如果返回 Promise，日志会在异步工作完成之前打印。

旧方法装饰器

TypeScript
// 需要 "experimentalDecorators": true
function legacyLogged(
  _target: object,
  name: string | symbol,
  descriptor: PropertyDescriptor,
): void {
  const original = descriptor.value;
  descriptor.value = function (this: unknown, ...args: unknown[]) {
    console.log(`旧方案调用 ${String(name)}`);
    return original.apply(this, args);
  };
}

把这个函数用在标准模式下，TypeScript 报 TS1241：运行时只会传 2 个参数。

addInitializer：自动绑定

TypeScript
function bound<This>(
  method: (this: This, ...args: never[]) => unknown,
  context: ClassMethodDecoratorContext<This>,
) {
  context.addInitializer(function (this: This) {
    (this as Record<string | symbol, unknown>)[context.name] = method.bind(this);
  });
}

初始化器在每个实例构造时运行，所以 const fn = obj.method 后仍能拿到正确的 this。

对比

标准装饰器experimentalDecorators
方法装饰器参数(value, context)(target, key, descriptor)
参数装饰器无有
反射元数据context.metadata / Symbol.metadata（TS 5.2）emitDecoratorMetadata + reflect-metadata
accessor 字段支持不支持

迁移时先确认框架要求的模式；两种模式不能在同一个项目里混用。

常见追问

  • 装饰器的执行顺序？同一成员上多个装饰器从下往上应用，@a @b method 先应用 b 再应用 a，最终调用时 a 的包装在最外层。
  • 浏览器能直接运行吗？装饰器提案还未进入 TC39 已完成提案列表，目前需要 TypeScript、Babel 或 esbuild 转换。
