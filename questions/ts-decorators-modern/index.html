TypeScript 新装饰器与 experimentalDecorators 有何区别？

TypeScript 5.0 起默认支持标准装饰器，它接收 (value, context) 两个参数；旧的 experimentalDecorators 接收 (target, key, descriptor)，还支持参数装饰器和反射元数据。两套写法不兼容，依赖旧语义的框架不能直接切换。

参考答案

简答

装饰器就是写在类或类成员上面的 @xxx，它是一个函数，类定义的时候会被调用，可以包装或替换被装饰的东西。TypeScript 现在有两套：5.0 起，不开 experimentalDecorators 就用 TC39 标准装饰器；开了就用旧实现，两者签名不同。

标准装饰器接收 (value, context)。value 是原来的方法，返回一个新函数就能替换它；context 提供 kind、name、static、private、addInitializer、metadata 这些信息。旧装饰器的方法装饰器接收 (target, propertyKey, descriptor)，靠修改属性描述符来替换方法。

区别最大的是生态。标准装饰器没有参数装饰器，也不会生成 design:type 这类反射元数据，所以 NestJS、TypeORM 这类依赖注入框架还得用旧模式，不能直接切换。

还要注意，装饰器是运行时代码，它不会改变类的类型，加出来的成员要另外声明。装饰器语法也不能被直接擦掉，Node.js 的类型剥离运行不了它。

标准方法装饰器长什么样

下面写一个 logged，每次调用方法前打印一行日志。

TypeScript
function logged<This, Args extends unknown[], Result>(
  method: (this: This, ...args: Args) => Result,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Result>,
) {
  const name = String(context.name);
  return function (this: This, ...args: Args): Result {
    console.log(`调用 ${name}`);
    return method.apply(this, args);
  };
}

class Counter {
  value = 0;

  @logged
  add(step: number): number {
    this.value += step;
    return this.value;
  }
}

new Counter().add(2); // 输出：调用 add

logged 拿到原来的 add 和一个 context，返回一个新函数，类里的 add 就被换成了这个新函数。方法名从 context.name 读出来。

这里返回的包装函数必须是普通函数，并用 method.apply(this, args) 把 this 转发过去。要是写成箭头函数，this 就不是实例了，原方法里的 this.value 会出错。还有一点：如果被装饰的方法返回 Promise，日志是在调用时打印的，那时异步工作还没完成。

旧装饰器为什么不能直接拿来用

TypeScript
// 需要 "experimentalDecorators": true
function legacyLogged(
  _target: object,
  name: string | symbol,
  descriptor: PropertyDescriptor,
): void {
  const original = descriptor.value;
  descriptor.value = function (this: unknown, ...args: unknown[]) {
    console.log(`旧方案调用 ${String(name)}`);
    return original.apply(this, args);
  };
}

旧写法要三个参数，通过改 descriptor.value 换掉方法。在标准模式下用它，TypeScript 会报 TS1241，因为标准装饰器运行时只传两个参数，第三个 descriptor 根本拿不到。

addInitializer 能做什么

context.addInitializer 可以注册一段在每个实例构造时执行的代码。用它可以实现自动绑定 this：

TypeScript
function bound<This>(
  method: (this: This, ...args: never[]) => unknown,
  context: ClassMethodDecoratorContext<This>,
) {
  context.addInitializer(function (this: This) {
    (this as Record<string | symbol, unknown>)[context.name] = method.bind(this);
  });
}

每创建一个实例，初始化器就把绑定好的方法放到实例自己身上。所以把方法单独拿出来，比如 const fn = obj.method，再调用也能拿到正确的 this。

两套装饰器对比

标准装饰器experimentalDecorators
方法装饰器参数(value, context)(target, key, descriptor)
参数装饰器无有
反射元数据context.metadata / Symbol.metadata（TS 5.2）emitDecoratorMetadata + reflect-metadata
accessor 字段支持不支持

迁移前先确认框架要求哪种模式。两种模式不能在同一个项目里混用。

常见追问

多个装饰器的执行顺序是怎样的？

同一个成员上的多个装饰器从下往上应用。写 @a @b method，先应用 b，再应用 a，所以最后调用时 a 的包装在最外层，先执行。

浏览器能直接运行装饰器吗？

目前还不行。装饰器提案曾在 Stage 3 停留多年，因为迟迟没有引擎实现，2026 年 5 月 TC39 会议把它和装饰器元数据一起退回 Stage 2.7，提案细节还可能调整。现在需要 TypeScript、Babel 或 esbuild 转换以后才能运行。
