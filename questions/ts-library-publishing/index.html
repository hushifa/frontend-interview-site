TypeScript 库发布时怎样组织类型声明和入口？

用 package.json 的 exports 为每个入口声明 types 和 JavaScript 条件，types 放在最前；声明文件的模块格式必须和对应 JS 一致，ESM 用 .d.ts/.d.mts，CommonJS 用 .d.cts。发布前用 npm pack 生成的包在独立项目里按包名安装验证，可借助 publint 和 Are the Types Wrong 检查。

参考答案

简答

  • exports 中每个条件对象把 types 写在第一位，TypeScript 按顺序匹配条件。
  • 声明格式随 JS 格式：.js 在 "type": "module" 包中是 ESM，其声明 .d.ts 也按 ESM 解释；CommonJS 入口要配 .d.cts。
  • 设置 exports 后，未列出的子路径不能被消费者导入，公开子路径要逐个声明。
  • .d.ts 不能引用 paths 别名或只在仓库中存在的类型，引用的第三方类型包要放进 dependencies 或 peerDependencies。
  • 用 npm pack 生成的包在独立项目中安装，分别用 moduleResolution: bundler 和 nodenext 检查。

只发 ESM

json
{
  "name": "@example/count-label",
  "version": "1.0.0",
  "type": "module",
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  }
}

tsconfig 使用 module: nodenext、declaration: true、outDir: dist。现在的 Node.js 允许 require 加载不含顶层 await 的 ESM，新库只发 ESM 通常就够了。

双格式

json
{
  "exports": {
    ".": {
      "import": {
        "types": "./dist/esm/index.d.mts",
        "default": "./dist/esm/index.mjs"
      },
      "require": {
        "types": "./dist/cjs/index.d.cts",
        "default": "./dist/cjs/index.cjs"
      }
    }
  }
}

两份 JS 都要配各自的声明。只写一份 .d.ts 同时给两种格式用，CommonJS 消费者会得到错误的默认导出类型（Are the Types Wrong 称为 "Masquerading as ESM"）。同一进程同时加载两份代码时，单例、instanceof 判断会失效，这叫双包风险。

子路径

json
{
  "exports": {
    ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" },
    "./utils": { "types": "./dist/utils.d.ts", "default": "./dist/utils.js" },
    "./package.json": "./package.json"
  }
}

import '@example/count-label/dist/internal.js' 会因不在 exports 中而失败，这让内部文件可以自由重构。

发布前检查

  1. npm pack --dry-run 查看实际打包的文件。
  2. npx publint 检查 exports 和文件是否对应。
  3. npx @arethetypeswrong/cli --pack 检查各种解析模式下的类型是否正确。
  4. 在独立项目中 npm install ../count-label-1.0.0.tgz，用包名导入，运行 tsc --noEmit 和实际代码。

类型也是版本契约

删除导出类型、收窄参数、改变重载顺序都可能让消费者编译失败，应按语义化版本计入破坏性变更。复杂的公开类型可以写类型测试锁定，见《TypeScript 复杂类型应该怎样测试？》。

常见追问

  • 还需要顶层 types 字段吗？只为不支持 exports 的旧解析模式（node10）保留；TypeScript 7 已删除该模式。
  • typesVersions 用来做什么？为不同 TypeScript 版本提供不同声明，现在多用于兼容旧解析模式下的子路径。
