数组常用方法怎样选择，哪些会修改原数组？

数组方法应按转换、筛选、查找、判断和累积的意图选择，并区分修改数组结构与复制数组容器。返回新数组不代表深拷贝，也不代表会等待异步回调。

参考答案

选择数组方法时，先说清想得到什么结果。如果要把每项变成另一种表示，用 map；只留下满足条件的项，用 filter；找到一个就够了，用 find。方法名能直接表达意图，比把所有遍历都塞进 reduce 或 forEach 更容易维护。

另一层问题是：这个方法会不会改变原数组？界面状态、缓存和多人共享的数据里，意外修改原数组往往比循环写得长一点更难排查。

常见任务和对应返回值

想做的事情常用方法返回什么
逐项转换map新数组，通常保留原有位置关系
筛选部分元素filter通过条件的元素组成的新数组
找第一个匹配值find元素或 undefined
找第一个匹配位置findIndex索引或 -1
至少有一个满足some布尔值，可以提前结束
所有被检查项都满足every布尔值，可以提前结束
累积出一个结果reduce由累加器定义的结果
对每项执行副作用forEachundefined，不收集回调返回值

只是检查是否存在时，没必要用 filter 先建立完整数组再判断 length。需要可以随时 break 的逐项业务流程时，普通 for...of 也很合适，代码不必为了“函数式”而变得难读。

sort 会原地修改，toSorted 返回新数组

JavaScript
const values = [10, 2, 1];
const numeric = values.toSorted((a, b) => a - b);

console.log(values.join(','));  // 10,2,1
console.log(numeric.join(',')); // 1,2,10
console.log(values.sort() === values); // true
console.log(values.join(',')); // 1,10,2

sort 默认将相应元素转为字符串后按 UTF-16 码元顺序比较，不是按数值大小，所以 10 会排在 2 前面。数字升序可以提供 (a, b) => a - b；比较函数应表达小于、等于、大于，而不是随便返回一个布尔值。

sort 会修改原数组并返回这个数组本身；toSorted 执行相应的复制排序。现代标准要求排序稳定，但稳定性不代表一个不满足比较规则的函数也能得到可靠结果。

类似地，reverse、splice、push、pop、shift、unshift、fill、copyWithin 都会改变原数组的内容或结构。toReversed、toSpliced、with 等提供对应的一些复制操作，具体可用性要按项目目标环境确认。

slice 通常用于复制一段，不会像 splice 那样从原数组删除元素。splice 的返回值是被删除项组成的数组，不是“修改后的完整数组”，这也是经常混淆的地方。

新数组不代表里面的对象也复制了

JavaScript
const source = [{ id: 1, score: 10 }];
const selected = source.filter(() => true);
selected[0].score = 20;
console.log(source[0].score); // 20

const updated = source.map(row =>
  row.id === 1 ? { ...row, score: 30 } : row,
);
console.log(source[0].score);  // 20
console.log(updated[0].score); // 30

filter 创建了新的数组容器，但元素仍然是原对象引用，因此修改 selected[0].score 也会影响 source。map、slice、展开语法以及多数数组复制方法，同样不能自动完成深拷贝。

第二段为要修改的那项建立新对象，其他不变项目可以共享引用，这是常见的不可变状态更新方式。若对象内部还有嵌套数据，需要按实际修改路径继续复制。

说 map “不修改原数组”，指方法自身不会像 sort 那样重排原容器。回调仍然可以直接修改原数组或元素对象，语言不会阻止这些副作用。不能只看到用了 map，就认定整段代码不可变。

空数组和空位各有规则

[].some(...) 为 false，[].every(...) 为 true，因为没有任何被检查元素违反条件。如果业务要求“至少有一个项目，并且全部通过”，还必须单独检查 length。

reduce 在没有初始值且没有可用元素时会抛 TypeError。求和时给出初始值 0，既清楚也能处理空数组；但初始值具体是什么，应由累积结果的类型决定。

稀疏数组的空位与显式的 undefined 不完全一样：

JavaScript
const sparse = [, 2];
console.log(sparse.length); // 2
console.log(0 in sparse); // false
console.log(0 in sparse.map(value => value * 2)); // false
console.log(0 in [...sparse]); // true
console.log(sparse.includes(undefined)); // true
console.log(sparse.indexOf(undefined)); // -1

map、forEach、filter 等对普通稀疏数组会跳过不存在的索引，map 的结果可保留相应空位。展开与数组迭代器会把这种位置读取为 undefined，使结果变成实际存在的元素。includes 会按相应规则把空位当作 undefined，而 indexOf 会跳过不存在的索引。

find 及其相关方法对空位的访问规则又不同，不能背成“所有数组方法都会跳过空位”。原型上的索引属性也可能影响属性存在性检查，因此这里以没有相关原型污染的普通数组为前提。日常业务尽量避免用 delete 制造空洞；删除项目通常使用 splice 或对应复制操作。

async 回调不会让 forEach 自动等待

forEach 直接忽略回调的返回值。给回调加 async，会得到每次调用的 Promise，但 forEach 不会收集并等待这些 Promise；写 await array.forEach(...) 也只是在等待它返回的 undefined，不能等待所有任务完成。

若需要并行等待，可以明确使用 Promise.all 收集结果：

JavaScript
async function double(value) {
  return value * 2;
}

async function calculate() {
  const values = [1, 2, 3];
  const results = await Promise.all(values.map(double));
  console.log(results.join(',')); // 2,4,6
}

calculate();

真实任务可能拒绝，调用方应处理错误。Promise.all 不会自动取消其他已开始的操作，也不会限制并发数量；任务多时需要单独的并发控制。

若后一步必须等前一步完成，用 async 函数中的 for...of 配合 await 更直接。最后还应避免在遍历过程中随意改动数组长度或删除未访问项，不同方法对初始长度和当前位置的处理会让结果不直观；确需这样做时，先定义清楚遍历语义。
