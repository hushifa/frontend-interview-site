数组常用方法怎样选择，哪些会修改原数组？

先想清楚要做什么，转换用 map，筛选用 filter，查找用 find 或 some，汇总用 reduce。sort、reverse、splice 这类方法会直接改原数组，想保留原数组就用 toSorted、toReversed 这些返回副本的版本。

参考答案

简答

选数组方法，先看自己要做什么。每一项都要变个样，用 map；只留一部分，用 filter；找第一个符合条件的，用 find；只想知道有没有，用 some；要算出一个总数，用 reduce。

会改原数组的方法要单独记住：push、pop、shift、unshift、splice、sort、reverse、fill、copyWithin。map、filter、slice、concat、flat 返回新数组，ES2023 还给 sort、reverse、splice 配了不改原数组的版本 toSorted、toReversed、toSpliced，以及替换单个元素的 with。

要注意，新数组只是新的容器，里面的对象还是原来那几个，改元素的属性照样会影响原数组。

还有两个常见坑。sort 不传比较函数时按字符串排，数字排序要写 (a, b) => a - b。forEach 不会等 async 回调，要等待就用 for...of 加 await，或者 Promise.all。

按要做的事选方法

大部分数组方法的区别，就在于“回调返回的东西被拿去做什么”。下面这张表按目的列出来：

只想判断有没有，就用 some，不要写 filter(...).length > 0。some 找到一个就停，filter 却要把整个数组走完，还白白造出一个新数组。

sort 为什么会把 10 排在 2 前面

先看 sort 和 toSorted 放在一起的效果，注意 values 本身有没有变。

JavaScript
const values = [10, 2, 1];
const numeric = values.toSorted((a, b) => a - b);

console.log(values.join(','));  // 10,2,1
console.log(numeric.join(',')); // 1,2,10
console.log(values.sort() === values); // true
console.log(values.join(',')); // 1,10,2

toSorted 排完以后，values 还是 10,2,1，结果放在新数组 numeric 里。

可是调用 values.sort() 以后，结果是 1,10,2，10 跑到了 2 前面。原因是 sort 不传比较函数时，会把元素都转成字符串再比。字符串是一位一位比的，'10' 的第一位 '1' 比 '2' 小，所以排在前面。改法就是传比较函数 (a, b) => a - b，按数值比。

values.sort() === values 是 true，说明 sort 是在原数组上排好，再把原数组返回。规范还要求排序是稳定的，也就是比较结果相等的元素，排序后保持原来的先后顺序。

fill 和 copyWithin 也一样，原地修改并返回原数组。splice 比较特别，它返回的是被删掉的那些元素，而不是修改后的数组；名字很像的 slice 则不改原数组，只是截出一段新数组。concat 把几个数组拼成新数组，flat 把嵌套数组展开成新数组。

返回新数组，为什么原数据还是被改了

JavaScript
const source = [{ id: 1, score: 10 }];
const selected = source.filter(() => true);
selected[0].score = 20;
console.log(source[0].score); // 20

const updated = source.map(row =>
  row.id === 1 ? { ...row, score: 30 } : row,
);
console.log(source[0].score);  // 20
console.log(updated[0].score); // 30

selected 是 filter 返回的新数组，可改了 selected[0].score，source[0].score 也变成了 20。

因为新数组只是一个新的“盒子”，盒子里放的还是原来那个对象。两个数组的第 0 项指向同一个对象，从哪边改都一样。这种只复制最外一层的做法叫浅拷贝。

想改某一项又不影响原数据，就像第二段那样，只给要改的那一项创建新对象 { ...row, score: 30 }，其他项直接复用。这叫不可变更新，React 里更新列表状态就是这么写的。

空数组和稀疏数组的边界

空数组有几个反直觉的结果。[].some(fn) 是 false，因为一个满足的都没有；[].every(fn) 却是 true，因为找不到不满足的。空数组调用 reduce 又不传初始值，会直接抛 TypeError，所以求和要写成 reduce((s, x) => s + x, 0)。

稀疏数组是中间有空位的数组，比如 [, 2]。map、forEach、filter 会跳过空位，展开语法和 for...of 却会把空位读成 undefined，同一个数组用不同方法遍历，结果不一致。所以删除元素不要用 delete arr[i]，它会留下空位，应该用 splice 或 filter。

forEach 为什么不等 async 回调

JavaScript
async function double(value) {
  return value * 2;
}

async function calculate() {
  const values = [1, 2, 3];
  const results = await Promise.all(values.map(double));
  console.log(results.join(',')); // 2,4,6
}

calculate();

forEach 只管把回调调用一遍，不看回调的返回值。async 回调返回的是 Promise，forEach 拿到以后直接丢掉，自己马上返回 undefined，所以后面的代码不会等这些任务完成。

map 不一样，它会把每个 Promise 收集进数组。交给 Promise.all 等待，就是几个任务一起跑，也就是并行。如果要一个做完再做下一个，就写 for (const x of arr) await task(x)。另外 forEach 也不能用 break 提前结束，需要中途停下时同样改用 for...of。

怎样按字段分组

Object.groupBy（ES2024）按回调的返回值把元素分组：

JavaScript
const items = [
  { name: 'a', type: 'js' },
  { name: 'b', type: 'css' },
  { name: 'c', type: 'js' },
];
const groups = Object.groupBy(items, (item) => item.type);
console.log(groups.js.map((item) => item.name)); // ['a', 'c']

它返回的对象没有原型，也就是原型为 null，所以不能调用 groups.hasOwnProperty，判断某个键在不在要用 Object.hasOwn。分组的键不是字符串时，比如要按对象分组，就用 Map.groupBy，它返回一个 Map。

如果数据是一项一项异步到达的，可以用 Array.fromAsync（ES2026），它会逐个等待异步可迭代对象里的值，最后收集成数组。

常见追问

map 回调里修改了元素，算不算修改原数组？

map 本身不会改原数组这个容器，但回调拿到的是原来的元素。如果元素是对象，回调里改了它的属性，原数组里的对象也就被改了，语言不会拦着。所以 map 回调里最好只返回新值，不去改传进来的元素。

for...in 能遍历数组吗？

能，但不推荐。它拿到的键是字符串 '0'、'1'，而且会把原型链上可枚举的属性也遍历出来。遍历数组用 for...of 或者数组方法。
