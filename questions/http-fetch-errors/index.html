为什么 fetch 收到 404 不一定进入 catch？

fetch 只有在拿不到响应时才会失败，比如断网、被 CORS 拦截、请求被取消。404、500 都算正常拿到了响应，要自己检查 response.ok 再抛错。

参考答案

简答

fetch() 返回的 Promise，只要收到了 HTTP 响应就会成功，哪怕状态码是 404 或 500。在 fetch 看来，服务器回了话，请求就算完成了。

它只在拿不到可用响应时才失败：网络断了、DNS 解析失败、被 CORS 或 CSP 拦住、被 AbortController 取消。这时会抛 TypeError 或者 AbortError。

所以判断 HTTP 是否成功，要看 response.ok，它在状态码是 200 到 299 时为 true。不成功就自己抛错。

还要注意，读正文是另一个会失败的地方。response.json() 遇到不是 JSON 的正文会报错，而且正文只能读一次。

先看 404 时 fetch 拿到的是什么

下面直接构造一个 404 响应，看看它的样子。这段可以在 Node 18 以上运行。

JavaScript
const response = new Response('Not Found', { status: 404 });
console.log(response.ok, response.status); // false 404

这个对象就是 404 时 fetch 交给你的东西。它是个正常的 Response，Promise 照样兑现，只是 ok 为 false。代码里如果只写了 try...catch，没检查 ok，就会把错误页当成功数据去处理。

一个完整的封装

所以实际项目里一般会包一层，把三类失败分开：HTTP 错误、取消或超时、网络和解析失败。

JavaScript
async function getJSON(url, { signal } = {}) {
  const response = await fetch(url, { signal });

  if (!response.ok) {
    const text = await response.text();
    const error = new Error(`HTTP ${response.status}`);
    error.status = response.status;
    error.body = text;
    throw error;
  }

  if (response.status === 204) return null;
  return response.json();
}

const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 8000);

try {
  const data = await getJSON('/api/items', { signal: controller.signal });
  console.log(data);
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('已取消或超时');
  } else if (error.status) {
    console.log('服务器返回错误', error.status);
  } else {
    console.log('网络或解析失败', error);
  }
} finally {
  clearTimeout(timer);
}

!response.ok 时先把正文读成文本存起来，因为后端的错误信息往往在正文里。204 表示没有正文，直接调 json() 会报错，所以单独处理。

超时也可以不自己写定时器，直接用 AbortSignal.timeout(8000)。这时超时抛出的错误名是 TimeoutError，不是 AbortError，判断时要注意。

为什么正文只能读一次

Response 的正文是一个流，叫 ReadableStream，数据读走就没了。读过一次以后 bodyUsed 变成 true，再读就会失败。

JavaScript
const ok = new Response('{"a":1}');
console.log(await ok.json()); // { a: 1 }
console.log(ok.bodyUsed); // true
try {
  await ok.text();
} catch (error) {
  console.log(error.name); // TypeError
}

真需要读两次，比如一份给日志、一份给业务，就在读之前先调 response.clone()。

常见追问

为什么 CORS 错误拿不到具体原因？

浏览器故意不把跨源失败的细节告诉脚本，免得泄露别的站点的信息。具体原因只能在 DevTools 的 Network 和控制台里看。

业务错误码放在 200 响应里怎么办？

封装时同时检查 response.ok 和业务字段，两类错误分开处理。

axios 为什么 404 会进 catch？

axios 默认用 validateStatus 把 2xx 以外的状态都当错误。这是库自己的约定，不是 HTTP 的行为。
