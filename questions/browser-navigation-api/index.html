Navigation API 解决了传统 SPA 路由的哪些问题？

Navigation API 用一个 navigate 事件接住链接点击、表单提交、前进后退和脚本跳转，调用 intercept() 交给前端处理，还能知道导航何时完成。MDN 标为 Baseline 2026。

参考答案

简答

用 History API 写 SPA 路由，要做三件分散的事：自己拦截链接点击，监听 popstate 处理前进后退，再包一层 history.pushState。Navigation API 把这些合成了一个入口：navigation 上的 navigate 事件，同文档里能拦截的导航都会经过它。

在事件里调用 event.intercept({ handler })，就是告诉浏览器“这次导航我自己处理”。URL 立刻更新，handler 返回的 Promise 结束时，导航才算完成。

它还补上了 History API 没有的东西：navigation.navigate() 返回 committed 和 finished 两个 Promise，能知道导航什么时候完成、有没有失败；导航被打断时，event.signal 会被 abort，旧请求可以跟着取消。

要注意，有些导航不该拦截，要提前放行，比如 canIntercept 为 false、只是改了 hash、或者是下载。MDN 标为 Baseline 2026，也就是 2026 年 1 月起主流浏览器都能用，旧浏览器还得回退到 History API。

先看一个例子

下面只接管 /articles/ 下的导航，其他的交给浏览器：

JavaScript
navigation.addEventListener('navigate', (event) => {
  if (!event.canIntercept || event.hashChange || event.downloadRequest !== null) return;
  if (event.formData) return;

  const url = new URL(event.destination.url);
  if (!url.pathname.startsWith('/articles/')) return;

  event.intercept({
    async handler() {
      const article = await loadArticle(url.pathname, { signal: event.signal });
      renderArticle(article);
      event.scroll();
    },
  });
});

开头那几个 return 都是在放行。canIntercept 为 false 说明这次导航没法拦，比如跨源；hashChange 为 true 只是页内锚点跳转；downloadRequest 不为 null 是下载链接。这些都交给浏览器自己处理。

formData 不为 null 表示这是一次 POST 表单提交。这里也放行了；如果想在前端处理，就读 event.formData 自己发 POST 请求。

event.signal 和 event.scroll() 是干什么的

用户点了一篇文章，还没加载完又点了另一篇。第一次导航被打断，它的 event.signal 就会 abort。把 signal 传给请求，旧请求就跟着取消，不会把旧文章渲染出来。用户点浏览器的停止按钮也一样。

滚动方面，浏览器默认等 handler 完成后再恢复滚动位置。主要内容渲染完就调用 event.scroll()，可以提前处理滚动。

比 History API 多了什么

能力History APINavigation API
拦截链接点击自己监听 clicknavigate 事件统一处理
前进后退popstate，拿不到目标前的状态同一个 navigate 事件
导航完成和失败无navigatesuccess、navigateerror、finished
历史条目只能拿到当前状态navigation.entries()、currentEntry、traverseTo(key)

最实用的是导航状态。以前没办法知道“这次跳转什么时候算完”，现在有 finished Promise，以及 navigatesuccess、navigateerror 事件。历史记录也能看了，navigation.entries() 列出条目，traverseTo(key) 跳到指定的那一条。

有哪些限制

页面第一次加载时不会触发 navigate，所以客户端渲染的应用还要单独做初始化。

历史条目只能看到当前 frame 里同源的那部分，也不能删除或者重新排列。

preventDefault() 只对 cancelable 为 true 的导航有效。前进后退这类导航能不能取消，要看 event.cancelable。

兼容旧浏览器时，先检测 'navigation' in window，不支持就沿用 History API 的路由。

常见追问

页面刚打开时会触发 navigate 事件吗？

不会。navigate 只在页面加载完之后的导航里触发，所以客户端渲染的应用首次进入时，要自己根据当前 URL 渲染一次。

用户连续点了两个链接，第一个请求怎么办？

第一次导航被打断时，它的 event.signal 会 abort。只要把这个 signal 传给 fetch，旧请求就会被取消，不会拿旧数据覆盖新页面。
