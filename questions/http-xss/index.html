XSS 和 CSRF 有什么区别？分别如何防范？

XSS 是攻击者让恶意脚本在你的页面里执行，能读取页面数据并以用户身份操作；CSRF 是别的网站诱导浏览器向你的站点发请求，借用自动携带的 Cookie。XSS 靠输出编码、净化和 CSP 防，CSRF 靠 SameSite、CSRF 令牌和来源校验防。

参考答案

简答

  • XSS：攻击者的代码在你的源下运行，同源策略对它无效，能读 DOM、发请求、读非 HttpOnly 的 Cookie。
  • CSRF：攻击代码在别的网站上，读不到你的页面，只能"盲发"请求，依赖浏览器自动带上用户的 Cookie。
  • 防 XSS：默认用文本方式输出（textContent、框架的插值），富文本用 DOMPurify 这类库净化，再加 CSP 和 Trusted Types 兜底。
  • 防 CSRF：会话 Cookie 设 SameSite=Lax 或 Strict，修改操作校验 CSRF 令牌或 Origin、Sec-Fetch-Site 请求头，GET 不做修改。
  • 存在 XSS 时 CSRF 防护基本失效，因为恶意脚本可以先读到令牌再发请求。

XSS 的三种类型

类型恶意内容从哪来例子
存储型存在数据库里，展示给其他用户评论里写入 <img src=x onerror=...>
反射型URL 参数，服务端原样输出搜索页直接输出 ?q= 的值
DOM 型前端代码把可控数据写进危险接口el.innerHTML = location.hash.slice(1)

防 XSS

JavaScript
// 安全：按文本处理
comment.textContent = userInput;

// 必须渲染 HTML 时先净化
import DOMPurify from 'dompurify';
container.innerHTML = DOMPurify.sanitize(userHtml);
  • 框架默认转义插值，危险在逃生口：React 的 dangerouslySetInnerHTML、Vue 的 v-html。
  • href 也是入口：javascript: URL 会执行脚本，链接地址要校验协议只允许 http:、https:。
  • CSP 限制脚本来源，即使注入成功也不能执行，见《CSP 的 nonce、hash 与 Report-Only 如何使用？》。
  • 会话 Cookie 设 HttpOnly，减少脚本直接读取令牌，但不能阻止脚本在页面里以用户身份发请求。

防 CSRF

http
Set-Cookie: __Host-session=abc; Secure; HttpOnly; SameSite=Lax; Path=/
  • SameSite=Lax 时跨站的 POST、fetch 请求不带 Cookie，只有顶层导航的 GET 会带上。
  • 服务端对修改操作检查 Origin 是否是自己的站点，或检查 Sec-Fetch-Site 是否为 same-origin。
  • 需要更强保证或兼容旧浏览器时使用 CSRF 令牌，见《Double Submit Cookie 能怎样防御 CSRF？》。
  • 同站不等于同源：evil.example.com 和 app.example.com 是同站，SameSite 拦不住来自子域名的请求。

常见追问

  • 用 localStorage 存令牌、请求头携带，是不是就没有 CSRF 了？是的，浏览器不会自动带上它；但一旦有 XSS，令牌会被直接读走。
  • CORS 能防 CSRF 吗？不能。简单请求可以跨源发出，CORS 只限制读取响应。
