Agent 前端界面怎样展示计划、工具调用和人工确认？

建模 Agent 的消息、步骤、工具状态和审批状态，避免只显示一段不可解释的最终文本。

参考答案

Agent 界面不能只显示一段最终文本，因为一次执行可能包含多种不同性质的状态：用户消息、模型输出、计划步骤、工具调用、工具结果、人工审批、重试、取消和最终回答。每个步骤都需要稳定 ID、开始时间、结束时间和当前状态，流式更新、刷新恢复和错误定位才有依据。

可以把一次执行建模成“会话 → 运行 → 步骤”的关系。步骤状态至少要能区分等待、执行中、成功、失败、已取消和等待审批；模型输出的增量片段也应归属于某个消息或步骤，不能直接把每个网络片段当成一条完整消息。

工具调用的界面还要告诉用户它准备调用什么、参数范围是什么、可能产生什么副作用，以及是否需要确认。例如读取天气和删除文件的风险完全不同；涉及写入、发送或删除时，确认之前不能提前执行。工具返回的数据也要显示来源和处理状态，不能因为它来自工具就自动变成系统指令。

前端状态不是 Agent 的唯一事实来源。服务端应保存会话和执行状态，客户端刷新、断线或切换设备后重新同步；重新连接时要处理重复事件和缺失事件，避免一条工具调用在界面上显示两次，或把未完成步骤误显示为成功。

模型输出、检索文档和工具结果都属于不可信输入。密钥、权限和真正的工具执行必须留在受控服务端，前端负责展示进度、请求确认、处理取消和恢复错误。这样用户才能分清“模型建议做什么”和“系统实际上已经做了什么”。
