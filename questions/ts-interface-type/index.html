type 和 interface 有哪些区别？

描述普通对象时两者差不多。interface 能同名合并，适合可扩展的对象契约；type 能写联合、元组、条件类型等 interface 写不了的东西。

参考答案

简答

描述一个普通对象或函数签名时，type 和 interface 基本一样，都按结构比较，编译后也都会被删掉。

区别主要在能力上。只有 type 能写联合（比如 'a' | 'b'）、元组、条件类型、映射类型，以及给 typeof 的结果起别名。只有 interface 能同名合并，写两次同名 interface，成员会合到一起，所以常用来扩展第三方类型，比如 Window；同名的 type 会报重复声明。

组合类型时也有差别。interface B extends A 如果属性类型冲突，在声明处就报错；用 A & B 交叉，冲突的属性会悄悄变成 never，到用的时候才发现。

实际项目里，常见约定是对象契约用 interface，其他用 type。团队里保持一致，比选哪个更重要。

两者都能写的

TypeScript
interface User {
  name: string;
  age?: number;
}

type UserRecord = {
  name: string;
  age?: number;
};

interface Formatter {
  (value: number): string;
}
type FormatFunction = (value: number) => string;

对象和函数签名，两种写法都行，效果一样。要注意它们都只在编译期存在，编译后就没了，所以不能 new User()，也不能写 value instanceof User。

只有 type 能做的

TypeScript
type UserId = string;
type Point = readonly [number, number];
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
type Keys = keyof User;
type Getters = { [K in keyof User & string as `get${Capitalize<K>}`]: () => User[K] };

给原始类型起别名、元组、联合、keyof 的结果、映射类型，这些都不是“一个对象有哪些属性”，interface 没法表达，只能用 type。

同名 interface 会合并

TypeScript
interface ReadingOptions {
  theme: 'light' | 'dark';
}
interface ReadingOptions {
  fontSize: number;
}
const options: ReadingOptions = { theme: 'light', fontSize: 16 };

两段声明被合成了一个，所以 options 要同时有 theme 和 fontSize。合并时同名属性的类型必须一致，不然报错。更多合并规则和模块增补见《TypeScript 声明合并和模块扩展有哪些边界？》。

extends 和交叉类型，冲突时有什么不同

TypeScript
interface TextValue {
  value: string;
}

// @ts-expect-error 子接口不能把 value 改成不兼容的 number
interface NumberValue extends TextValue {
  value: number;
}

type ImpossibleValue = TextValue & { value: number };
// @ts-expect-error value 是 string & number，即 never
const impossible: ImpossibleValue = { value: 1 };

用 extends 把 value 改成 number，在声明 NumberValue 的那一行就报错，一眼能看出问题在哪。

用交叉类型 & 就不一样了。声明 ImpossibleValue 时什么都不报，因为交叉的意思是“同时满足两边”，value 要同时是 string 和 number，结果就成了 never。直到真的去创建对象时才报错，而且错误离原因很远。多层交叉还会让错误信息难读、类型检查变慢，所以需要组合对象类型时，优先用 interface extends。

其他小差别

class X implements T 对 interface 和对象形式的 type 都能用，它只做检查，不生成代码。另外在编辑器里悬停时，interface 显示的是名字，type 有时会展开成完整的结构。

常见追问

怎样让两个都是 string 的 ID 不能互相赋值？

用品牌类型，比如 type UserId = string & { readonly __brand: 'UserId' }。普通字符串没有这个品牌字段，就不能直接当 UserId 用。

interface 能 extends 一个 type 吗？

能，只要这个 type 是对象类型。如果它是联合类型，就不行。
