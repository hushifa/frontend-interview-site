CSS @property 如何让自定义属性参与类型校验和动画？

解释普通 CSS 自定义属性为什么按 token 保存、不能可靠插值，说明 @property 的 syntax、inherits 和 initial-value，以及注册属性在主题、动画、组件封装和兼容性中的实际边界。

参考答案

CSS 自定义属性常被当成“可以保存任何值的变量”：

CSS
:root {
  --progress: 0%;
}

.bar {
  width: var(--progress);
  transition: --progress 300ms ease;
}

如果脚本把 --progress 从 0% 改成 100%，很多人期待它像普通长度一样平滑变化。但没有注册的自定义属性通常按一串 token 保存，浏览器不知道它是百分比、颜色还是其他语法，无法可靠地对两个值做类型化插值。结果可能是直接跳到终点，或者 transition 根本没有产生期望的动画。

@property 为自定义属性声明语法、是否继承和初始值，让浏览器能在计算值阶段按指定类型处理它。它不是 JavaScript 变量声明，也不是给所有 CSS 值增加运行时类型检查的万能机制。

三个描述决定属性的语义

一个注册属性至少需要 syntax、inherits 和 initial-value：

CSS
@property --progress {
  syntax: '<percentage>';
  inherits: false;
  initial-value: 0%;
}

.bar {
  width: var(--progress);
  transition: --progress 300ms ease;
}

.bar[data-progress='done'] {
  --progress: 100%;
}
  • syntax 说明允许的值类型。<percentage> 只接受百分比；<length>、<color>、<number> 等类型有不同的计算和插值规则。
  • inherits: false 表示子元素不会自动继承父元素的自定义属性；true 则与普通自定义属性一样参与继承。
  • initial-value 是属性没有有效指定值时使用的初始值。某些语法要求提供可 computationally independent（可计算独立）的初始值，不能随意使用依赖上下文的表达式。

注册后，--progress 的动画有了明确的百分比空间。若把值设成 50px，它不符合语法，声明会成为无效值并回退到适用的初始或继承结果；这和普通未注册属性把任意字符串保存下来不同。

inherits 改变的不只是写法

普通自定义属性默认继承：

CSS
.card {
  --accent: tomato;
}

.card button {
  color: var(--accent);
}

如果将 --accent 注册为 inherits: false，button 不会自动得到 .card 的值，而会使用注册时的 initial-value，除非在按钮自身或更合适的组件边界重新设置。这对组件内部的进度、角度和局部动画状态很有用，可以避免父级主题变量意外污染内部状态；但主题色、字体和密度 token 通常需要继承，不能为了“类型安全”全部设为 false。

CSS
@property --card-scale {
  syntax: '<number>';
  inherits: false;
  initial-value: 1;
}

@property --theme-accent {
  syntax: '<color>';
  inherits: true;
  initial-value: #2563eb;
}

属性注册是全局 CSS 环境中的名字约定。不同组件库如果注册了同一个 --progress，它们共享同一个语义和注册规则，可能产生冲突。因此应给组件私有属性使用稳定前缀，并在设计系统中记录哪些 token 是公共主题变量、哪些是组件内部状态。

语法匹配不等于业务值校验

syntax: '<length>' 能排除明显不是长度的 CSS 值，但不能验证“这个宽度是否适合当前卡片”或“这个颜色是否满足对比度”。var() 的 fallback 也要理解清楚：

CSS
@property --gap {
  syntax: '<length>';
  inherits: false;
  initial-value: 0px;
}

.grid {
  gap: var(--gap, 1rem);
}

当 --gap 没有值或值无效时，var() 的备用值可能被采用；但如果属性已经有一个语法有效、却不符合业务约束的值，CSS 不会替你做范围检查。需要限制 0 到 2rem、禁止负值或根据用户权限决定上限时，仍要在组件 API、TypeScript 或运行时逻辑中验证。

此外，注册自定义属性不会让 var(--x) 在所有属性中都自动安全。最终使用位置仍要满足目标属性的语法，变量展开后的无效值可能使整条声明失效。复杂 fallback 和多层变量组合应在真实主题、浏览器开发者工具和组件测试中检查。

颜色和长度的动画要考虑插值空间

注册后，颜色可以参与 CSS 动画，但动画具体使用的颜色空间和浏览器实现仍应结合 CSS Color 规范和目标浏览器验证。不要仅因为声明写了 <color> 就认为过渡符合品牌设计要求；设计系统可能需要明确使用 color-mix() 或其他颜色空间控制效果。

CSS
@property --card-color {
  syntax: '<color>';
  inherits: false;
  initial-value: transparent;
}

.card {
  background: var(--card-color);
  transition: --card-color 200ms ease;
}

.card[data-active='true'] {
  --card-color: rgb(219 234 254);
}

动画只改变视觉值，不会自动改变内容状态、可访问名称或点击行为。比如用颜色表示错误时，仍需配合文字、图标、aria-invalid 或其他语义；用自定义属性控制 display 也不能绕过焦点管理和 DOM 生命周期。

与 JavaScript 注册 API 的关系

CSS.registerProperty() 可以在脚本中完成类似注册：

JavaScript
if ('registerProperty' in CSS) {
  CSS.registerProperty({
    name: '--progress',
    syntax: '<percentage>',
    inherits: false,
    initialValue: '0%',
  });
}

同一个属性不能先在 CSS 中注册、又在 JavaScript 中重复注册；重复注册通常会抛出错误。组件库如果选择脚本注册，需要保证只执行一次，并在 SSR、热更新和多个副本加载时避免重复调用。更适合静态设计系统的公共属性通常写在 CSS 中，便于构建工具、审查工具和源码阅读者发现；只有注册值依赖运行时模块或确实需要脚本控制时才考虑 API。

脚本注册也不是“检测到不支持就可以忽略所有逻辑”。不支持 CSS.registerProperty 的浏览器仍应使用普通自定义属性的最终值，让组件可用；只把平滑插值作为增强能力，并在 CSS 或脚本中提供静态回退。

兼容性、主题和性能边界

@property 和注册 API 属于较新的 CSS Houdini 能力，目标浏览器的支持情况需要查 MDN 兼容性数据并实际测试。未注册属性在不支持的环境中仍可作为普通自定义属性使用，但依赖类型化动画、无效值回退或非继承行为的效果可能不同。组件不能把这些增强特性当成唯一的布局或业务逻辑来源。

注册大量属性本身通常不是性能瓶颈，真正需要关注的是它们控制了什么：如果每帧改变会触发布局的 <length>，可能比只改变 transform 或 opacity 成本更高；如果属性值被多个大型子树继承，主题切换会扩大样式重新计算范围。应通过 Performance 面板测量实际样式、布局和绘制成本，而不是因为使用了 Houdini 就默认更快。

面试中完整的回答应包含三个层次：普通自定义属性是可继承的 token，不保证类型化插值；@property 通过 syntax、inherits、initial-value 建立明确语义；即使完成注册，组件仍要处理回退、命名冲突、兼容性、无障碍表达和动画属性的性能。它适合把可复用的 CSS 状态变成可计算、可动画的值，但不能替代组件状态模型和业务校验。
