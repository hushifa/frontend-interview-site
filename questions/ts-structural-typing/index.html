结构类型、可选属性和额外属性检查有哪些区别？

TypeScript 按结构判断兼容性，只要具备目标要求的成员即可赋值，不看类型名称。新鲜的对象字面量直接赋给有类型的目标时会额外检查多余属性，经变量中转则不会。类型标注不会删除运行时多出的字段。需要名义区分时用品牌类型。

参考答案

简答

  • 结构类型：A 拥有 B 要求的全部成员（类型兼容），A 就能赋给 B，名字不同也没关系。
  • 额外属性检查只针对直接写出的对象字面量，greet({ name, role }) 报错，先赋给变量再传就不报。
  • 类型变窄不会删除字段，Object.keys 仍能看到未声明的属性，所以它返回 string[]。
  • 类的 private、protected 成员和 #私有字段 会让结构相同的类不兼容。
  • 两个都是 string 的 ID 默认可以互换，需要区分时用品牌类型，并通过校验函数创建。

额外属性检查

TypeScript
type Named = { name: string };

function greet(person: Named): string {
  return person.name;
}

const detailed = { name: 'Lin', role: 'admin' };
greet(detailed); // 允许

// @ts-expect-error 对象字面量包含未声明的 role
greet({ name: 'Lin', role: 'admin' });

const narrowed: Named = detailed;
console.log(Object.keys(narrowed)); // ['name', 'role']

直接写出的字面量多出字段，通常是拼写错误或接口理解错误，所以编译器报错。变量可能在其他地方被正常使用，多出字段是合理的。

要把数据真正限制为某些字段（如发给接口、写日志），需要复制白名单字段生成新对象。

品牌类型

TypeScript
declare const userIdBrand: unique symbol;
type UserId = string & { readonly [userIdBrand]: true };

function makeUserId(value: string): UserId {
  if (!/^user_[0-9]+$/.test(value)) throw new TypeError('用户 ID 格式不正确');
  return value as UserId;
}

function openUser(id: UserId): void {}

openUser(makeUserId('user_1'));
// @ts-expect-error 普通字符串不是 UserId
openUser('order_1');

品牌只存在于类型层，运行时仍是普通字符串。唯一的 as 放在校验函数里，其他地方无法绕过。

类的私有成员

TypeScript
class A { private x = 1; }
class B { private x = 1; }
// @ts-expect-error 私有成员来自不同声明，不兼容
const a: A = new B();

函数兼容

参数少的函数可以赋给参数多的函数类型，例如 arr.forEach((x) => ...) 忽略了 index 参数。参数类型的兼容方向见《函数重载、联合参数与泛型怎样选择？函数类型何时可赋值？》。

可选属性与 exactOptionalPropertyTypes 的关系见《strict、noUncheckedIndexedAccess 和 target 如何配置？》。

常见追问

  • 为什么 {} 能接受字符串？string 具有 {} 要求的全部成员（没有成员），且 {} 只排除 null 和 undefined。
  • 怎样关闭额外属性检查？加索引签名 [key: string]: unknown，但这会扩大可接受的范围，拼写错误也不再报错。
