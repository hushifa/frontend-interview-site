结构类型、可选属性和额外属性检查有哪些区别？

TypeScript 判断能不能赋值，看的是结构，只要有目标要求的成员就行，不看类型叫什么名字。直接写出的对象字面量多了字段会报错，经过变量中转就不会。

参考答案

简答

TypeScript 判断 A 能不能赋给 B，看的是结构：A 有 B 要求的全部成员，而且类型兼容，就能赋值，两个类型名字不同也没关系，这叫结构类型。

不过有个例外叫额外属性检查。直接写出来的对象字面量，比如 greet({ name, role })，多了目标里没有的字段会报错；先赋给变量再传，就不报。因为直接写的字面量多出字段，多半是拼错了。

要注意，类型变窄不会删掉字段，多出来的属性运行时还在，Object.keys 照样能看到，这也是它返回 string[] 的原因。另外类的 private、protected 成员和 #私有字段，会让结构相同的两个类互不兼容。

两个都是 string 的 ID 默认可以互换。需要区分时用品牌类型，并且只通过校验函数来创建。

额外属性检查什么时候生效

TypeScript
type Named = { name: string };

function greet(person: Named): string {
  return person.name;
}

const detailed = { name: 'Lin', role: 'admin' };
greet(detailed); // 允许

// @ts-expect-error 对象字面量包含未声明的 role
greet({ name: 'Lin', role: 'admin' });

const narrowed: Named = detailed;
console.log(Object.keys(narrowed)); // ['name', 'role']

同样多一个 role，传变量不报错，直接写字面量却报错，看起来不一致。原因是两种情况的含义不同：直接写出来的字面量只在这里用一次，多出的字段没人能读到，多半是拼写错误或者理解错了接口；而变量可能在别处正常使用 role，多带一个字段很合理。

最后两行说明另一件事：narrowed 的类型是 Named，可它和 detailed 是同一个对象，role 还在。类型标注只是让你看不见多出的字段，不会删掉它。所以要把数据真正限制在某些字段，比如发给接口、写日志，需要按白名单复制出一个新对象。

两个 string 怎样区分开

用户 ID 和订单 ID 都是字符串，结构类型下它们可以随便互换，传错了也不报错。品牌类型就是给其中一个加一个只在类型里存在的标记：

TypeScript
declare const userIdBrand: unique symbol;
type UserId = string & { readonly [userIdBrand]: true };

function makeUserId(value: string): UserId {
  if (!/^user_[0-9]+$/.test(value)) throw new TypeError('用户 ID 格式不正确');
  return value as UserId;
}

function openUser(id: UserId): void {}

openUser(makeUserId('user_1'));
// @ts-expect-error 普通字符串不是 UserId
openUser('order_1');

普通字符串没有那个标记，所以不能直接当 UserId 传。标记只存在于类型层，运行时 UserId 仍是普通字符串。整个程序里唯一的 as UserId 放在 makeUserId 里，并且先做了格式校验，其他地方就没法绕过校验造出一个 UserId。

类的私有成员会打破结构类型

TypeScript
class A { private x = 1; }
class B { private x = 1; }
// @ts-expect-error 私有成员来自不同声明，不兼容
const a: A = new B();

A 和 B 的结构一模一样，却不能互相赋值。因为对 private、protected 成员，TypeScript 要求它们来自同一个声明，这时比较就不只看结构了。

函数和可选属性

函数也按结构比较。参数少的函数可以赋给参数多的函数类型，所以 arr.forEach((x) => ...) 不写 index 也没问题。参数类型的兼容方向见《函数重载、联合参数与泛型怎样选择？函数类型何时可赋值？》。

可选属性和 exactOptionalPropertyTypes 的关系见《strict、noUncheckedIndexedAccess 和 target 如何配置？》。

常见追问

为什么 {} 类型能接收字符串？

{} 没有要求任何成员，string 当然满足“拥有全部要求的成员”。{} 只排除 null 和 undefined。

怎样关闭额外属性检查？

给类型加索引签名 [key: string]: unknown。但这会扩大能接受的范围，拼写错误也不再报错，要谨慎使用。
