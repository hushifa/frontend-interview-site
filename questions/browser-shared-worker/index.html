SharedWorker 和 Dedicated Worker 有什么区别？

Dedicated Worker 只属于创建它的页面；SharedWorker 由同源的多个页面共享同一个实例，通过 MessagePort 通信，适合多标签页共用一条连接或一份状态。MDN 标为 Baseline 2026。

参考答案

简答

  • Dedicated Worker 跟随创建它的页面，页面关闭它就终止。
  • SharedWorker 由同源、同脚本 URL、同名称的所有页面共享一个实例，最后一个连接的页面关闭后才终止。
  • 每个页面通过 worker.port 通信，Worker 里在 connect 事件中拿到每个页面的端口。
  • 适合多个标签页共用一个 WebSocket 连接、一份内存缓存或统一的请求去重。
  • MDN 标为 Baseline 2026（2026 年 5 月起主流浏览器可用），旧浏览器需要降级。

示例：多标签页共用一个 WebSocket

JavaScript
// shared.worker.js
const ports = new Set();
const socket = new WebSocket('wss://example.com/live');

socket.onmessage = (event) => {
  for (const port of ports) port.postMessage(event.data);
};

self.onconnect = (event) => {
  const port = event.ports[0];
  ports.add(port);
  port.onmessage = (message) => {
    if (message.data.type === 'close') ports.delete(port);
    else socket.send(JSON.stringify(message.data));
  };
};
JavaScript
// 页面
const worker = new SharedWorker(new URL('./shared.worker.js', import.meta.url), {
  type: 'module',
  name: 'live',
});
worker.port.onmessage = (event) => render(event.data);
window.addEventListener('pagehide', () => worker.port.postMessage({ type: 'close' }));

页面关闭时端口没有自动通知，所以页面在 pagehide 主动告知 Worker 移除端口。页面直接崩溃时这条消息发不出去，ports 里会残留失效端口，向失效端口发消息不会报错，影响有限。

注意事项

  • 用 addEventListener('message', ...) 时要调用 port.start()，用 onmessage 赋值则自动开始。
  • SharedWorker 的 console.log 不在页面控制台里，Chrome 中要到 chrome://inspect/#workers 调试。
  • 修改了 Worker 脚本后，只要还有页面连着旧实例，新页面仍会连到旧实例。

和其他方案对比

  • 只需要广播通知：BroadcastChannel 更简单。
  • 需要拦截请求、离线缓存：Service Worker。
  • 需要一个共享的状态中心或共享连接：SharedWorker。
