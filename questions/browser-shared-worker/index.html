SharedWorker 和 Dedicated Worker 有什么区别？

Dedicated Worker 只属于创建它的那个页面；SharedWorker 被同源的多个页面共用一个实例，适合多个标签页共用一条 WebSocket 连接或一份状态。MDN 标为 Baseline 2026。

参考答案

简答

用户开了五个标签页，每个页面都建一条 WebSocket 连接，服务端就得扛五条连接。如果让这五个页面共用一条，就要一个大家都能访问的“中心”，SharedWorker 就是这个中心。

平时说的 Worker 一般是 Dedicated Worker，它跟着创建它的页面走，页面关了它就终止。SharedWorker 不一样，同源、同脚本 URL、同名称的所有页面共用一个实例，最后一个连着它的页面关掉以后，它才终止。

通信方式也不同。每个页面通过 worker.port 和它说话，Worker 那边在 connect 事件里拿到每个页面的端口。

它适合多个标签页共用一条 WebSocket、一份内存缓存，或者统一做请求去重。MDN 标为 Baseline 2026，也就是 2026 年 5 月起主流浏览器都能用，旧浏览器还要降级。

先看多标签页共用一条 WebSocket

Worker 这边，维护一个端口集合，把服务端推来的消息转发给每个页面：

JavaScript
// shared.worker.js
const ports = new Set();
const socket = new WebSocket('wss://example.com/live');

socket.onmessage = (event) => {
  for (const port of ports) port.postMessage(event.data);
};

self.onconnect = (event) => {
  const port = event.ports[0];
  ports.add(port);
  port.onmessage = (message) => {
    if (message.data.type === 'close') ports.delete(port);
    else socket.send(JSON.stringify(message.data));
  };
};

每当有页面连上来，就会触发一次 connect，从 event.ports[0] 拿到这个页面的端口，存进集合。页面发来的消息转给服务端；页面说要关闭，就把它的端口删掉。

页面这边，创建 SharedWorker 并通过 port 收发消息：

JavaScript
// 页面
const worker = new SharedWorker(new URL('./shared.worker.js', import.meta.url), {
  type: 'module',
  name: 'live',
});
worker.port.onmessage = (event) => render(event.data);
window.addEventListener('pagehide', () => worker.port.postMessage({ type: 'close' }));

为什么页面要主动说“我要走了”

页面关闭时，端口不会自动通知 Worker。所以页面要在 pagehide 里主动发一条 close，让 Worker 把它的端口移出集合。

如果页面是直接崩溃的，这条消息发不出去，ports 里会残留一个失效的端口。好在往失效端口发消息不会报错，影响有限。

用的时候容易踩的坑

如果用 addEventListener('message', ...) 监听端口，要手动调用 port.start()；用 onmessage 赋值则会自动开始。

SharedWorker 里的 console.log 不会出现在页面的控制台里。在 Chrome 里要到 chrome://inspect/#workers 去调试。

还有一个更新的坑。你改了 Worker 脚本，可只要还有页面连着旧实例，新打开的页面仍然会连到旧实例上。

和其他方案怎么选

只需要广播一下通知，用 BroadcastChannel 更简单。需要拦截网络请求、做离线缓存，用 Service Worker。需要一个共享的状态中心或者共享连接，才用 SharedWorker。

常见追问

SharedWorker 什么时候终止？

最后一个连着它的页面关闭以后才终止。只要还有一个页面连着，它就一直活着，所以改了脚本以后，新页面也可能连到旧实例上。

为什么用 addEventListener 监听端口收不到消息？

因为用 addEventListener('message', ...) 时，端口不会自动开始接收，要手动调用 port.start()。用 onmessage 赋值就会自动开始。
