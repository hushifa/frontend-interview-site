WebAssembly 能替代 JavaScript 吗？适合哪些工作？

WebAssembly 是浏览器中运行的二进制指令格式，适合把 C、C++、Rust 等已有代码或计算密集任务带到网页；它不能直接操作 DOM，和 JavaScript 互相调用有开销，通常与 JavaScript 配合而不是替代。

参考答案

简答

  • WebAssembly（Wasm）是紧凑的二进制格式，由浏览器编译成机器码执行，性能稳定，适合大量数值计算。
  • 它运行在和 JavaScript 相同的沙箱里，遵守同样的安全限制。
  • Wasm 不能直接访问 DOM 和大多数 Web API，需要通过 JavaScript 胶水代码调用。
  • 适合：图像和视频处理、音频编解码、压缩、加密、游戏引擎、CAD、把已有的 C++ 或 Rust 库移植到网页。
  • 不适合：普通的界面逻辑和频繁操作 DOM 的代码，跨边界调用和数据复制的开销会抵消收益。

加载

JavaScript
const { instance } = await WebAssembly.instantiateStreaming(fetch('/image.wasm'), {
  env: { log: (value) => console.log(value) },
});

const result = instance.exports.blur(ptr, width, height);
  • instantiateStreaming 边下载边编译，服务端要返回 Content-Type: application/wasm。
  • 第二个参数是导入对象，Wasm 通过它调用 JavaScript 提供的函数。

数据传递

Wasm 函数的参数和返回值以数值类型为主：i32、f32、f64 对应 JavaScript 的 Number，i64 对应 BigInt；externref 可以原样传递 JavaScript 引用，但 Wasm 不能读取其内部结构。传图片这类数据时：

  1. Wasm 暴露一块线性内存（WebAssembly.Memory），JavaScript 用 Uint8Array 视图写入。
  2. 把数据所在的偏移量（指针）和长度作为数字传给 Wasm 函数。
  3. Wasm 在内存中处理完，JavaScript 再从内存读出结果。

所以收益来自"一次传入大量数据、在 Wasm 里做很多计算"，而不是频繁调用小函数。Rust 的 wasm-bindgen、C++ 的 Emscripten 会生成这些胶水代码。

和 Worker 一起使用

Wasm 默认在主线程执行，长时间计算同样会卡住页面。重计算应放到 Web Worker 中运行；多线程 Wasm 依赖 SharedArrayBuffer，需要页面处于跨源隔离状态。

常见追问

  • Wasm 一定比 JavaScript 快吗：不一定。JIT 优化后的 JavaScript 在很多场景已经很快，Wasm 的优势在启动后的性能稳定和无需 GC 的数值计算。
  • WasmGC：让 Kotlin、Dart 等带垃圾回收的语言可以编译到 Wasm 而不用自带 GC，主流浏览器已支持。
