双指针有哪些常见题型？

双指针就是用两个下标在数组上配合移动，把两层循环降成一次遍历。常见的有两种：快慢指针同向走，比如移动零；左右指针从两头往中间走，比如盛水最多的容器、三数之和。三数之和先排序，固定一个数后用左右指针找另外两个，还要跳过重复值，整体 O(n²)。

参考答案

简答

双指针就是用两个下标在同一个数组上一起移动。比如“把数组里的 0 都挪到末尾，其他数保持原来的顺序”，用一个指针往前扫，另一个指针记住下一个非零数该放的位置，扫一遍就完成，不用每遇到一个 0 就把后面的元素整体挪一格。

它能省时间，是因为每一步都能根据当前的情况排除掉一批不用再看的组合，两个指针都只往一个方向走、不回头，总共只走 O(n) 步。

常见题型分两种。快慢指针同向走，用来原地整理数组，比如移动零、有序数组去重。左右指针从两头往中间走，用来在有序数组或首尾之间找答案，比如盛水最多的容器、有序数组的两数之和、三数之和、判断回文串。

要注意，左右指针往往依赖数组有序，三数之和就得先排序。排序本身是 O(n log n)，JavaScript 的 sort 默认按字符串比较，排数字一定要传比较函数。三数之和还要在固定的数和左右指针三处都跳过重复值，否则结果里会有重复的三元组。

快慢指针：移动零

fast 往前扫每一个元素，slow 指向下一个非零数该放的位置。看循环里只在遇到非零数时才交换、才让 slow 前进。

JavaScript
function moveZeroes(nums) {
  let slow = 0;
  for (let fast = 0; fast < nums.length; fast++) {
    if (nums[fast] !== 0) {
      [nums[slow], nums[fast]] = [nums[fast], nums[slow]];
      slow++;
    }
  }
  return nums;
}

console.log(moveZeroes([0, 1, 0, 3, 12]).join(',')); // 1,3,12,0,0
console.log(moveZeroes([0, 0, 1]).join(',')); // 1,0,0
console.log(moveZeroes([1, 2]).join(',')); // 1,2
console.log(moveZeroes([]).length); // 0

为什么非零数的相对顺序不会乱？slow 左边始终是已经按原顺序排好的非零数，fast 每遇到一个非零数，就把它换到 slow 的位置。slow 和 fast 之间的都是 0，所以交换只是把一个 0 换到后面去。没有 0 的时候 slow 和 fast 一直相等，交换的是元素自己，结果不变。

交换用的是解构赋值 [a, b] = [b, a]，不需要临时变量。

左右指针：盛水最多的容器

题目给一组高度，任选两根柱子和 x 轴围成容器，求最多能装多少水。容量等于矮的那根乘以两根之间的距离。看指针每次移动的是哪一边。

JavaScript
function maxArea(height) {
  let left = 0;
  let right = height.length - 1;
  let best = 0;
  while (left < right) {
    const area = Math.min(height[left], height[right]) * (right - left);
    best = Math.max(best, area);
    if (height[left] < height[right]) left++;
    else right--;
  }
  return best;
}

console.log(maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7])); // 49
console.log(maxArea([1, 1])); // 1
console.log(maxArea([4, 3, 2, 1, 4])); // 16
console.log(maxArea([5])); // 0

为什么每次移动矮的那一边就够了？假设左边比右边矮。左边这根柱子跟右边任何一根更靠里的柱子配对，距离都更短，高度又不会超过左边这根，所以容量不可能超过当前值。这些组合全都可以排除，左指针放心右移。移动高的那一边则没有这个保证，可能错过答案。

第一个例子里，下标 1（高 8）和下标 8（高 7）之间距离 7，容量 7 × 7 = 49。[4, 3, 2, 1, 4] 的答案来自首尾两根，4 × 4 = 16。只有一根柱子时循环不执行，结果是 0。

三数之和：排序后固定一个，再用左右指针

题目要找出所有和为 0 且不重复的三元组。先排序，然后固定第一个数 sorted[i]，在它右边用左右指针找另外两个数。重点看三处跳过重复值的地方。

JavaScript
function threeSum(nums) {
  const sorted = [...nums].sort((a, b) => a - b);
  const result = [];
  for (let i = 0; i < sorted.length - 2; i++) {
    if (sorted[i] > 0) break;
    if (i > 0 && sorted[i] === sorted[i - 1]) continue;
    let left = i + 1;
    let right = sorted.length - 1;
    while (left < right) {
      const sum = sorted[i] + sorted[left] + sorted[right];
      if (sum < 0) left++;
      else if (sum > 0) right--;
      else {
        result.push([sorted[i], sorted[left], sorted[right]]);
        while (left < right && sorted[left] === sorted[left + 1]) left++;
        while (left < right && sorted[right] === sorted[right - 1]) right--;
        left++;
        right--;
      }
    }
  }
  return result;
}

const show = (triples) => JSON.stringify(triples);
console.log(show(threeSum([-1, 0, 1, 2, -1, -4]))); // [[-1,-1,2],[-1,0,1]]
console.log(show(threeSum([0, 0, 0, 0]))); // [[0,0,0]]
console.log(show(threeSum([-2, 0, 0, 2, 2]))); // [[-2,0,2]]
console.log(show(threeSum([0, 1, 1]))); // []

为什么要先排序？排好序以后，和太小就让左指针右移换一个更大的数，和太大就让右指针左移换一个更小的数，每一步都知道往哪边走。固定一个数以后内层只要 O(n)，外层循环 n 次，整体 O(n²)，比暴力枚举三层循环的 O(n³) 快。

为什么比较函数不能省？MDN 说明，不传比较函数时，sort 会把元素转成字符串、按 UTF-16 编码单元排序，在 Node.js 22.23 里 [-1, -4, 2].sort() 的结果还是 [-1, -4, 2]，因为字符串“-1”排在“-4”前面。这里还用 [...nums] 复制了一份，因为 sort 会原地修改数组。

去重分三处。外层 sorted[i] === sorted[i - 1] 时跳过，因为同一个值作为第一个数已经找过了。找到一组答案后，左右指针各自跳过和当前值相同的数，否则 [-2, 0, 0, 2, 2] 会把 [-2, 0, 2] 记两次。sorted[i] > 0 时直接结束，因为后面的数都不小于它，三个正数加起来不可能是 0。

边界用例怎么验证

上面三段代码另外用随机数组跟暴力解法做了对比：在 Node.js 22.23 里跑了一遍：生成 3000 组长度 0 到 8、元素在 -4 到 4 之间的数组，移动零对比“过滤非零数再补 0”的结果，盛水容器对比两层循环，三数之和对比三层循环加 Set 去重，结果全部一致。空数组、全是 0、只有一个元素、全是重复值这些情况都在随机范围里覆盖到了。

常见追问

双指针和滑动窗口是什么关系？

滑动窗口是同向双指针的一种，两个指针之间夹着一段连续区间，右指针扩张、左指针收缩。见《滑动窗口怎样求无重复字符的最长子串？》。

两数之和为什么一般用哈希表，不用双指针？

原题要返回下标，数组又是无序的。排序会打乱下标，要额外记录原始位置，还多出 O(n log n)。用 Map 一次遍历就是 O(n)，见《两数之和怎样从 O(n²) 优化到 O(n)？哈希表在算法题里怎么用？》。如果题目给的就是有序数组，左右指针不需要额外空间，更合适。

有序数组怎么原地去重？

还是快慢指针。slow 指向最后一个保留的元素，fast 往前扫，遇到和 nums[slow] 不同的数，就让 slow 前进一格并把这个数写过去。最后前 slow + 1 个元素就是去重后的结果。
