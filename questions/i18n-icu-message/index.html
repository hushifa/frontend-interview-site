ICU MessageFormat 为什么适合复杂国际化文案？

ICU MessageFormat 在一条完整消息里写变量、plural 和 select 分支，翻译者能按目标语言调整整句词序。JavaScript 中要用 FormatJS 等库解析；用户内容只能作为变量值传入，不能拼进模板。

参考答案

简答

  • name + ' 上传了 ' + count + ' 个文件' 把句子切成碎片，翻译者无法调整词序，也处理不了单复数。ICU 把整句写成一条消息，代码只传变量。
  • plural 按语言的复数类别选分支，=0 这类写法精确匹配数值，# 代表格式化后的数字，other 必须存在。
  • select 按字符串值选分支，适合状态、性别等有限选项，未知值进 other。
  • offset:1 适合"你和其他 N 人"：类别和 # 都按减去 1 之后的值计算，精确匹配仍比较原值。
  • 浏览器没有内置的 ICU 消息解析器，需要 FormatJS（intl-messageformat）等库，最好在构建时校验消息语法。

plural

text
{count, plural, =0 {No files uploaded.} one {# file uploaded.} other {# files uploaded.}}

中文翻译只需要自己语言的类别：

text
{count, plural, =0 {尚未上传文件。} other {已上传 # 个文件。}}

每种语言有哪些类别由 CLDR 规定，可以用 new Intl.PluralRules(locale).resolvedOptions().pluralCategories 查看，见《Intl.PluralRules 怎样帮助实现国际化复数？》。

select

text
{status, select, pending {正在等待上传。} failed {上传失败。} other {查看上传结果。}}

每个分支写完整的句子，不要先选一个动词再拼名词。分支可以嵌套变量和 plural，但维度组合多了翻译量会成倍增加，必要时拆成独立消息。

offset

text
{count, plural, offset:1
  =0 {还没有人参加。}
  =1 {你已参加。}
  other {你和其他 # 人已参加。}}

count 为 3 时，没有命中 =0、=1，按 3 − 1 = 2 选类别，# 显示 2。调用方传总人数，不要自己先减 1。

在 JavaScript 中使用

JavaScript
import { IntlMessageFormat } from 'intl-messageformat';

const message = new IntlMessageFormat(
  '{count, plural, one {# file} other {# files}}',
  'en',
);
message.format({ count: 3 }); // '3 files'
  • 构建时解析所有消息，语法错误、变量名不一致（中文用 count、英文写成 total）在 CI 中报错。
  • {、}、# 和单引号有语法含义，显示这些字符要按 ICU 的引用规则转义。

安全

用户名等内容作为变量值传给 format()。如果先拼进模板再解析，用户输入里的花括号会改变消息结构。富文本用库的标签映射功能（<b>{name}</b> 映射成组件），不要把结果交给 innerHTML。

常见追问

  • MessageFormat 2 是什么？ Unicode 制定的新一代消息语法，和 ICU MessageFormat 1 的语法不兼容，不要在同一个项目里混用。
  • 组件库里的文案怎样翻译？ 组件接收已经格式化好的字符串或消息键，由应用的消息层统一处理。
