设计 token 为什么比散落的颜色变量更适合大型前端项目？

设计 token 是给设计决策起名字的数据，分基础值、语义和组件三层，组件只引用语义层，换主题只改映射。Web 端常输出成 CSS 自定义属性，要注意继承时的求值边界，也别加没用的抽象层。

参考答案

简答

设计 token 就是给设计决策起了名字的数据，比如颜色、间距、字号。它们写在一份来源里，再由工具生成 CSS、iOS、Android 各个平台的代码。

token 通常分层。最底下是基础 token，比如 blue-600，只表示一个具体的值；上面是语义 token，比如 color-action-primary，表示“主操作用的颜色”；必要时再加组件 token，比如 button-bg。

分层的好处是，组件只引用语义 token。换主题、做深色模式时，只改语义层指向哪个基础值，组件代码一行都不用动。在 Web 端，token 最常见的输出形式就是 CSS 自定义属性，也就是 CSS 变量，可以在运行时切换主题。

要注意别过度设计。分层要有实际用处，不需要给每个组件都建一层 token。

散落的变量有什么问题

下面三处其实都是“主操作色”，写法却各不相同：

CSS
.button { background: #2563eb; }
.link   { color: #2563eb; }
.badge  { background: var(--blue); }

要改品牌色或者加深色模式时，只能全局搜索。更麻烦的是，搜出来的 #2563eb 里，哪些是主操作色，哪些只是碰巧也用了这个蓝色，根本分不清。

分层以后是什么样

下面把基础值和语义分开写，再加一个深色主题：

CSS
:root {
  /* 基础 token：可用的原始值 */
  --blue-600: #2563eb;
  --blue-400: #60a5fa;
  --gray-50: #f9fafb;
  --gray-900: #111827;

  /* 语义 token：表达用途 */
  --color-action-primary: var(--blue-600);
  --color-surface: var(--gray-50);
  --color-text: var(--gray-900);
}

[data-theme='dark'] {
  --color-action-primary: var(--blue-400);
  --color-surface: var(--gray-900);
  --color-text: var(--gray-50);
}

.button {
  background: var(--color-action-primary);
  color: var(--color-surface);
}

深色主题只覆盖了语义层，把“主操作色”指向另一个蓝色。.button 没有任何修改，颜色就跟着变了。

在子树里改基础 token，为什么不生效

自定义属性是在使用它的元素上计算的，计算好的值再继承给子元素。

上面的例子里，--color-action-primary: var(--blue-600) 定义在 :root 上，所以在 :root 就已经算成了 #2563eb，子元素继承的是这个算好的颜色值。

这时如果你在某个子树里重新定义 --blue-600，想让这一块换个颜色，会发现子树里的 --color-action-primary 不跟着变。原因就是它早在 :root 上解析完了，继承下来的是结果，不是那句 var(--blue-600)。

改法是在这个元素上直接重新声明语义 token，比如在这块区域上写 --color-action-primary: ...。

token 从哪里来

大型项目通常把 token 写在 JSON 里，用 Style Dictionary 这类工具生成 CSS 变量、Sass 变量、TypeScript 常量和移动端资源，这样各平台用的是同一份来源。

W3C 社区组 Design Tokens Community Group 在 2025 年 10 月发布了 token 格式规范的首个稳定版。有了统一格式，设计工具和代码工具就能互相交换 token。

怎样避免过度抽象

只有一个组件用到的值，不必做成全局 token。组件 token 也只在一种情况下才加：需要单独调整某个组件，又不想影响其他组件。

起名字要描述用途，比如 color-danger，不要描述外观，比如 color-red。否则哪天危险色改成了橙色，名字就错了。

常见追问

token 和 Tailwind 的主题配置是什么关系？

Tailwind 的主题配置本身就是一套 token，可以和其他平台一样，由同一份来源生成。

怎么防止开发者在业务代码里直接写颜色值？

用 Stylelint 加规则，禁止业务样式里出现硬编码的颜色。
