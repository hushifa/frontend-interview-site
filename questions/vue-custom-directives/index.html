Vue 自定义指令适合什么场景？

自定义指令用来复用对 DOM 元素的直接操作，比如自动聚焦、点击外部关闭。它通过 mounted、unmounted 等钩子拿到元素，卸载时要记得清理；要渲染结构或管理状态，就该用组件或组合式函数。

参考答案

简答

自定义指令就是自己写一个 v-xxx，把对 DOM 元素的直接操作封装起来复用。比如 v-focus 让输入框一出现就自动聚焦，v-click-outside 点击元素外面时关闭菜单。

它是一个对象，里面写和组件类似的钩子：created、beforeMount、mounted、beforeUpdate、updated、beforeUnmount、unmounted。每个钩子拿到 (el, binding, vnode, prevVnode)，其中 binding 里有绑定值 value、旧值 oldValue、参数 arg（v-x:arg）和修饰符 modifiers（v-x.foo）。在 <script setup> 里，以 v 开头的驼峰变量，比如 vFocus，可以直接当 v-focus 用。

最要注意的是清理。在 mounted 里加的事件监听、观察器，必须在 unmounted 里移除。另外，只写了 mounted 的指令，绑定值后来变了也不会生效，要配上 updated。

指令只适合“直接摆弄 DOM”这件事。要渲染额外的结构，用组件；要管理状态、复用业务逻辑，用组合式函数。也不推荐把指令用在组件上，它会作用在组件根元素上，多根组件则会被忽略并警告。

最简单的例子：自动聚焦

vue
<script setup>
const vFocus = { mounted: (el) => el.focus() };
</script>

<template>
  <input v-focus />
</template>

mounted 时元素已经插入页面，所以这时调用 focus() 才有效。

点击外部关闭：为什么要把函数存在元素上

JavaScript
// directives/clickOutside.js
export const clickOutside = {
  mounted(el, binding) {
    el._onClickOutside = (event) => {
      if (!el.contains(event.target)) binding.value(event);
    };
    document.addEventListener('pointerdown', el._onClickOutside);
  },
  unmounted(el) {
    document.removeEventListener('pointerdown', el._onClickOutside);
    delete el._onClickOutside;
  },
};
vue
<div v-if="open" v-click-outside="() => (open = false)">菜单内容</div>

监听器挂在 document 上，元素卸载了它也不会自己消失。可是 removeEventListener 必须传入当初添加的同一个函数才能移除，mounted 和 unmounted 又是两个不同的函数，拿不到对方的局部变量。所以这里把处理函数存到元素上，卸载时从元素上取回同一个引用。

绑定值变了怎么办

下面是一个图片懒加载指令，图片进入视口才设置 src：

JavaScript
export const lazySrc = {
  mounted(el, { value }) {
    el._observer = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) {
        el.src = el.dataset.src;
        el._observer.disconnect();
      }
    });
    el.dataset.src = value;
    el._observer.observe(el);
  },
  updated(el, { value, oldValue }) {
    if (value !== oldValue) {
      el.dataset.src = value;
      if (el.src) el.src = value; // 已加载过的图片直接换地址
    }
  },
  unmounted(el) {
    el._observer?.disconnect();
  },
};

如果只写 mounted，图片地址后来换了，指令完全不知道，页面还显示旧图。所以要在 updated 里比较新旧值，自己处理变化。顺带一提，实际项目里 <img loading="lazy"> 已经能满足大部分懒加载需求。

想全局使用，在应用上注册一次：

JavaScript
app.directive('click-outside', clickOutside);

哪些需求不该用指令

需要渲染额外的 DOM 结构，比如 tooltip 的浮层，用组件。需要管理状态或复用业务逻辑，用组合式函数。

权限控制隐藏按钮也不建议用指令。用指令直接把 DOM 节点删掉，对应的组件实例并不会被卸载，还在后台运行。用 v-if 加一个权限判断函数，既清楚又能正确卸载。

常见追问

指令的函数简写是什么意思？

app.directive('color', (el, binding) => {...}) 直接传一个函数，等于同时定义了 mounted 和 updated，适合挂载和更新时做同一件事的指令。

服务端渲染时指令会执行吗？

操作 DOM 的钩子不会在服务端执行。如果指令需要往 HTML 里输出属性，要用 getSSRProps 钩子提供。
