Vue 自定义指令适合什么场景？

自定义指令用于复用普通元素上的底层 DOM 行为，例如聚焦或观察尺寸。它需要处理绑定值变化与资源释放，不应替代组件结构、状态逻辑，也不会自动找到自定义组件内部的目标元素。

参考答案

简答

自定义指令用于复用直接操作 DOM 的底层逻辑，例如自动聚焦、点击外部关闭、观察元素尺寸。常用钩子有 mounted、updated、beforeUnmount，绑定值变化时要在 updated 中处理，卸载时要释放监听器和观察器。用在组件上时，指令作用于组件根元素，多根组件会失效并警告。能用组件或组合式函数解决的问题，不要用指令。

当一段复用逻辑主要围绕“这个真实 DOM 元素怎样操作”，自定义指令通常合适。例如聚焦、接入观察器或与只接受元素的第三方工具协作。

如果需求是复用一块界面结构，组件更清楚；如果主要是响应式状态和业务计算，组合函数更自然。不要把请求、表单状态和一整套页面逻辑都藏进一个看似简短的 v-xxx。

指令钩子拿到的是绑定元素和绑定信息

mounted 可以在元素挂载后建立行为，updated 可以读取本轮绑定值，unmounted 可以释放资源。还有创建、挂载前、更新前和卸载前等钩子，应根据需要操作 DOM 的时机选择。

binding.value 是表达式结果，oldValue 在更新钩子中提供旧值，arg 与 modifiers 则表达参数和修饰符。updated 被调用不意味着 value 一定变化，指令应按自己的成本与契约判断是否需要重新设置。

用指令管理一个尺寸观察器

JavaScript
// vMeasure.js
const records = new WeakMap();

export const vMeasure = {
  mounted(element, binding) {
    const record = { callback: binding.value, observer: null };
    const observer = new ResizeObserver(() => {
      const current = records.get(element);
      if (!current || typeof current.callback !== 'function') return;
      const rect = element.getBoundingClientRect();
      current.callback({ width: rect.width, height: rect.height });
    });
    record.observer = observer;
    records.set(element, record);
    observer.observe(element);
  },
  updated(element, binding) {
    const record = records.get(element);
    if (record) record.callback = binding.value;
  },
  unmounted(element) {
    records.get(element)?.observer.disconnect();
    records.delete(element);
  },
};

每个元素有自己的记录，更新绑定时替换回调，不重复创建观察器。回调执行时再取当前记录，卸载后记录已删除，就不继续给失效使用者写入结果。

WeakMap 只是管理元素与记录的关联，不能代替 observer.disconnect。观察器和其他宿主资源可能仍持有元素，资源释放必须显式完成。

在组件中局部使用

vue
<!-- MeasurePanel.vue -->
<script setup>
import { ref } from 'vue';
import { vMeasure } from './vMeasure.js';

const width = ref(240);
const size = ref({ width: 0, height: 0 });

function recordSize(next) {
  if (size.value.width !== next.width || size.value.height !== next.height) {
    size.value = next;
  }
}
</script>

<template>
  <section>
    <div v-measure="recordSize" :style="{ width: `${width}px`, padding: '8px', border: '1px solid' }">
      被观察的内容
    </div>
    <p>实际宽度：{{ size.width }}</p>
    <button type="button" @click="width = width === 240 ? 320 : 240">改变宽度</button>
  </section>
</template>

script setup 中以 v 开头的指令绑定可以被模板识别，vMeasure 对应 v-measure。也可以通过应用级 directive 注册，但没有共享需要时，局部使用更容易看出依赖。

测量返回的是 getBoundingClientRect 对应的几何宽高，包含边框、内边距和变换影响，不一定等于 CSS 中写的 width。结果显示在独立区域，避免直接用测量值反复改变被测元素自身尺寸形成反馈循环。

更新回调与重新初始化不是一回事

绑定函数可能随着父级逻辑变化。示例只更新记录中的 callback，下一次尺寸变化就使用新函数，不需要先断开再观察同一个元素。

如果需求是绑定更新后立即报告当前尺寸，则应明确增加一次读取；当前例子不承诺“换回调就马上触发尺寸事件”。对不同第三方库，配置变化可能确实需要重新初始化，也应在 updated 中有针对性地处理。

初次 ResizeObserver 通知有自己的调度时机，不能把 observe 调用完成当作同步得到最终尺寸。后续字体、内容和布局还可能变化，是否需要这些变化决定了为什么采用观察器。

不要与模板争夺同一份 DOM 状态

Vue 模板负责的文本、class、style 或子节点，如果被指令悄悄替换，后续 patch 可能与指令相互覆盖。指令应有明确的负责范围，避免把整个组件结构改写成框架不知道的另一棵树。

聚焦指令也不应在每次 updated 时无条件 focus，否则普通状态更新就可能抢走用户焦点。应按绑定变化或明确操作意图执行，而不是把“更新了”当成用户要求重新聚焦。

事件监听需要移除同一函数引用，观察器需要断开，第三方实例需要调用对应销毁方法。需要仍存在 DOM 才能正确释放的资源，可以根据接口选择 beforeUnmount 等更早阶段。

组件边界与 SSR 需要额外考虑

不建议把自定义指令直接当成深入自定义组件内部的选择器。它依赖组件根节点，多根组件或根结构变化时可能不符合预期，也不会自动知道哪个后代 input 才是目标。

更稳妥的方式是在需要操作的普通元素上使用指令，或让组件提供明确的 ref/方法接口。组件的 attrs 与根继承规则也不应被指令绕过。

服务端没有真实浏览器 DOM，普通 DOM 指令钩子不会按客户端方式执行。确实需要在 SSR 输出某些属性时，可以按 Vue 的服务端指令接口提供 getSSRProps，并保持逻辑不依赖浏览器资源。

验证指令时应覆盖首次挂载、绑定值变化、元素尺寸或交互变化、卸载和重新挂载。一个 mounted 能跑通，不足以证明指令在真实组件生命周期中没有重复资源或旧回调。
