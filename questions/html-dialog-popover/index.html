dialog 和 Popover API 应该怎样使用？

要挡住页面、让用户必须先处理的，用 dialog 的 showModal()；下拉菜单、提示气泡这类不挡页面的浮层，用 popover 属性。两者都会显示在最上层，不受父元素 z-index 影响。

参考答案

简答

选哪个，先问一句：这个浮层打开时，要不要挡住页面其他部分？

要挡住，用 dialog.showModal()。它打开的是模态对话框，页面其他部分不能操作，按 Esc 能关闭，还有 ::backdrop 遮罩。dialog.show() 打开的是非模态对话框，不进入顶层，也没有遮罩。不挡页面的下拉菜单、提示气泡，用 popover 属性。popover="auto" 点外面或按 Esc 会自动关闭，配合 popovertarget 不写 JavaScript 就能打开。

它们最大的好处是，showModal() 打开的对话框和 popover 都进入顶层（top layer），不受父元素 z-index 和 overflow 的影响，不会再被遮住或裁掉。

要注意，关闭后焦点会回到打开它的元素，但对话框里的初始焦点、对话框的名称，仍然要自己设置好。

一个确认删除的对话框

HTML
<button id="open">删除</button>

<dialog id="confirm" aria-labelledby="confirm-title">
  <h2 id="confirm-title">删除这条记录？</h2>
  <form method="dialog">
    <button value="cancel">取消</button>
    <button value="ok">删除</button>
  </form>
</dialog>
JavaScript
const dialog = document.querySelector('#confirm');
document.querySelector('#open').addEventListener('click', () => dialog.showModal());
dialog.addEventListener('close', () => {
  if (dialog.returnValue === 'ok') deleteRecord();
});

这里没有给两个按钮写点击事件，怎么知道用户点了哪个？关键在 method="dialog"。这种表单提交时不会发网络请求，而是关闭对话框，并把被点按钮的 value 存进 dialog.returnValue。所以在 close 事件里看 returnValue 是不是 'ok' 就行了。

aria-labelledby 把标题关联成对话框的名称，读屏打开对话框时会读出“删除这条记录？”。

想要点击遮罩就关闭，可以用 closedby="any" 属性。不支持的浏览器里，监听对话框的 click 事件，判断点击目标是不是 dialog 本身。

Popover：不写 JavaScript 的浮层

HTML
<button popovertarget="menu">更多</button>
<div id="menu" popover>
  <button>重命名</button>
  <button>复制</button>
</div>

点“更多”就会打开菜单，再点外面或按 Esc 就关闭，一行脚本都没写。

popover 有两种。popover="auto" 是默认的，打开一个会自动关掉其他 auto popover，点外面就关闭。popover="manual" 只能用代码或按钮关闭，适合通知这类不该被随手点掉的东西。

浮层放在哪里，用锚点定位来做，见《CSS Anchor Positioning 适合解决哪些浮层布局问题？》。

要注意，popover 不是菜单组件，也不会自动加 role。做菜单时，方向键导航和对应的 ARIA 角色还是要自己实现。

场景怎么对应

确认删除、填写表单这种必须先处理完的，用 showModal()。

下拉菜单、提示气泡、各种选择器，用 popover。

页面角落的聊天窗口，既不挡页面，又不该点外面就关，用 dialog.show() 或者 popover="manual"。

常见追问

对话框和 popover 怎样做进入和退出动画？

用 @starting-style 和 transition-behavior: allow-discrete，见《@starting-style 和离散属性过渡解决了什么问题？》。
