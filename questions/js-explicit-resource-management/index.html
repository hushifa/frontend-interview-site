using 和 await using 解决什么资源清理问题？

using 声明在离开块作用域时自动调用资源的 [Symbol.dispose]()，await using 调用并等待 [Symbol.asyncDispose]()，多个资源按声明逆序释放，替代手写 try/finally。释放与主逻辑都出错时，错误被包装成 SuppressedError。该特性在 TC39 列为 2027 版，MDN 标注为非 Baseline，部分浏览器尚不支持。

参考答案

简答

  • using x = resource 在所在块结束时调用 x[Symbol.dispose]()，无论正常结束、return 还是抛错。
  • await using 在离开作用域时调用并等待 x[Symbol.asyncDispose]()，只能用在 async 函数或模块顶层。
  • 多个资源按声明的相反顺序释放。
  • 主逻辑和释放都抛错时，最终抛出 SuppressedError：error 是释放时的错误，suppressed 是被它压住的错误。
  • 资源数量不固定时用 DisposableStack / AsyncDisposableStack。

释放顺序

JavaScript
function resource(name) {
  console.log(`获取${name}`);
  return {
    [Symbol.dispose]() {
      console.log(`释放${name}`);
    },
  };
}

function work() {
  using first = resource('A');
  using second = resource('B');
  console.log('执行工作');
}

work();
// 输出：获取A → 获取B → 执行工作 → 释放B → 释放A

等价于嵌套两层 try/finally。using 只认 Symbol.dispose，不会调用名为 close 的普通方法；值为 null 或 undefined 时跳过，其他缺少该方法的值会抛 TypeError。

await using

JavaScript
async function work() {
  await using connection = await openConnection();
  return connection.query('select 1');
}

右侧的 await 等待获取资源，左侧的 await using 表示退出时等待异步释放。

错误合并

JavaScript
function fail() {
  using resource = {
    [Symbol.dispose]() {
      throw new Error('释放失败');
    },
  };
  throw new Error('工作失败');
}

try {
  fail();
} catch (error) {
  console.log(error.name); // SuppressedError
  console.log(error.error.message); // 释放失败
  console.log(error.suppressed.message); // 工作失败
}

一个资源释放失败后，剩下的资源仍会继续释放。

DisposableStack

JavaScript
function openAll(paths) {
  using stack = new DisposableStack();
  const files = paths.map((path) => stack.use(openFile(path)));
  const owned = stack.move(); // 全部成功，转移所有权给调用方
  return { files, [Symbol.dispose]: () => owned.dispose() };
}

中途某个 openFile 抛错时，stack 退出作用域，已打开的文件被逆序关闭。stack.adopt(value, fn) 可以给没有实现协议的对象登记释放函数，stack.defer(fn) 登记任意清理回调。

使用边界

  • 生命周期必须和词法作用域一致。组件、订阅这类创建后长期存在的对象不适合在创建函数里 using。
  • await 永远挂起时作用域不会结束，资源也不会释放；需要配合 AbortSignal。
  • 进程被杀、页面关闭时清理不保证执行。
  • 兼容性：using 是新语法，不支持的引擎会在解析阶段报错，无法用 if 降级。TypeScript 5.2 起可以把它编译成 try/finally，同时需要 Symbol.dispose 和 DisposableStack 的 polyfill。

常见追问

  • 和 try/finally 比好在哪里？释放逻辑写在资源一侧，调用方不会忘记；多个资源不必层层嵌套。
  • 和垃圾回收的关系？没有关系。GC 回收内存的时间不确定，using 在确定的时间点释放文件句柄、锁等外部资源。
