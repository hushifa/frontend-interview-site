Node.js Worker Threads 适合解决什么问题？

Worker Threads 让 CPU 密集计算在独立线程中运行，避免阻塞主线程的事件循环。每个 Worker 有自己的 V8 实例和事件循环，通过消息通信；数据默认结构化克隆，可以转移 ArrayBuffer 的所有权，也可以用 SharedArrayBuffer 共享内存。

参考答案

简答

Node.js 的 JavaScript 跑在一个主线程上。一个请求里要做 200 毫秒的图片处理或加密计算，这 200 毫秒里别的请求全都得排队等着。Worker Threads 就是把这类 CPU 密集的计算挪到另一个线程去做，主线程只管收发消息。

反过来，普通的网络和文件 I/O 本来就由 libuv 异步处理，不占主线程，放进 Worker 通常没有收益。

每个 Worker 有独立的 V8 实例、堆和事件循环，启动有几十毫秒级的成本，所以用得频繁时要复用，做成任务池。

线程之间传数据有三种方式：postMessage 默认结构化克隆，也就是复制一份；把 ArrayBuffer 放进 transferList 可以直接转移所有权，不复制；SharedArrayBuffer 配合 Atomics 可以让两边共享同一块内存。

为什么需要 Worker

主线程同一时间只能执行一段 JavaScript。一段同步计算占着它的时候，其他请求的回调都执行不了，整体延迟就上去了。把计算放进 Worker，主线程可以继续处理别的请求。

下面这个函数在 Worker 里算 SHA-256，主线程通过 Promise 拿结果：

JavaScript
import { Worker } from 'node:worker_threads';

function hashInWorker(input) {
  return new Promise((resolve, reject) => {
    const worker = new Worker(new URL('./hash-worker.mjs', import.meta.url), {
      workerData: input,
    });
    worker.once('message', resolve);
    worker.once('error', reject);
    worker.once('exit', (code) => {
      if (code !== 0) reject(new Error(`Worker 退出码 ${code}`));
    });
  });
}
JavaScript
// hash-worker.mjs
import { parentPort, workerData } from 'node:worker_threads';
import { createHash } from 'node:crypto';

parentPort.postMessage(createHash('sha256').update(workerData).digest('hex'));

workerData 是创建时传给 Worker 的初始数据，Worker 算完用 parentPort.postMessage 把结果发回来。除了 message，还要监听 error 和 exit，否则 Worker 出错时这个 Promise 永远不会结束。

这个示例每次调用都新建一个 Worker，只适合低频任务。高频调用的做法见《Node.js 为什么要用 Worker Threads 任务池？》。

数据怎样在线程之间传递

方式特点
结构化克隆（默认）复制一份数据，支持对象、Map、Date、TypedArray 等；函数和类实例的原型不会保留
转移（transferList）ArrayBuffer、MessagePort 等可转移对象移交给另一方，原线程中的变为不可用
SharedArrayBuffer两个线程读写同一块内存，需要用 Atomics 协调读写顺序

转移是什么效果，看下面这个例子：

JavaScript
const buffer = new ArrayBuffer(8);
const { port1, port2 } = new MessageChannel();
port2.onmessage = (event) => {
  console.log(event.data.byteLength); // 8
  port2.close();
};
port1.postMessage(buffer, [buffer]);
console.log(buffer.byteLength); // 0

发送之后，原来的 buffer 长度变成了 0，接收方拿到的是完整的 8 字节。因为第二个参数把它放进了 transferList，这块内存的所有权直接交给了对方，自己这边就不能再用了。大块二进制数据用转移，可以省掉复制的成本。

能不能中途取消一个 Worker 任务

Worker 正在跑同步循环时，它没空处理收到的消息。所以“发一条取消消息”只在任务会分段让出线程时才有效。需要立刻停下时，调用 worker.terminate()，它会结束整个线程，正在执行的任务没有机会清理资源。

常见追问

Worker 和 child_process、cluster 怎么选？

见《Node.js 的子进程、Worker 和集群应该怎样选择？》。

Worker 是安全沙箱吗？

不是。Worker 和主线程在同一个进程里，文件系统和网络权限都一样，不能用来运行不可信的代码。

Worker 里能用 AsyncLocalStorage 吗？

Worker 有自己的上下文，主线程的 store 不会自动传过去，需要通过消息显式传递请求 ID 等信息。
