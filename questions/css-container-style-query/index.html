容器查询和媒体查询怎样选择？

根据组件容器还是视口决定响应式条件，理解 size query、style query 和布局边界。

参考答案

媒体查询根据视口或设备特征改变样式，适合页面级布局；容器查询根据组件所在容器的尺寸或样式改变样式，适合同一个卡片在侧栏、主栏和弹窗中复用。

在“容器查询和媒体查询怎样选择？”这个问题中，先确认元素的语义和布局上下文，再检查最终计算样式、盒模型和层叠来源；最后用窄屏、长文本和键盘操作验证结果。这里的 CSS、容器查询、响应式布局 不是孤立的 API 名称，而是会共同影响输入、过程和最终结果。

实际排查时先看语义结构和布局上下文，再查看计算后的样式、盒模型、层叠来源和绘制结果。把视觉问题拆成结构、尺寸、定位和绘制几步，通常比反复修改一个 CSS 属性更容易定位原因。

使用 size query 前通常要声明查询容器，否则子元素无法按预期读取容器尺寸。组件应定义自己的布局边界，避免查询结果依赖过远的祖先结构。style query 还要确认目标浏览器支持和语法范围。

容器查询不是把所有媒体查询替换掉。页面导航、主题和设备能力仍适合媒体查询；组件内部尺寸适配则使用容器查询更能降低耦合。

交付前还要检查键盘操作、响应式断点、文本放大、打印和减少动画偏好。兼容性结论应以目标浏览器和特性检测为前提，不要把某个浏览器的偶发现象当成通用规则。

实际项目里，先用一个最小 DOM 结构复现问题，再分别修改结构、布局和样式来源。这样能区分是选择器没有命中、布局上下文不同，还是元素已经绘制但被遮挡；修复后再回到真实页面验证长文本和窄屏。
