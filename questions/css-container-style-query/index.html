容器样式查询怎样根据父级配置改变组件样式？

容器样式查询通过 style() 判断祖先容器的样式条件，常见用法是查询自定义属性，把密度、主题等配置传给内部组件。它与查询容器宽高的尺寸查询不同。

参考答案

简答

  • 尺寸查询问容器有多大，样式查询问容器上的某项样式是否满足条件，常见写法是 style(--属性: 值)。
  • MDN 目前写明样式查询只支持自定义属性；只做样式查询时不需要设置 container-type。
  • 未注册的自定义属性按字面比较，#0000ff 与 blue 不一定匹配，开关值应使用约定好的关键字。
  • 只传一个值时直接用 CSS 变量或后代选择器更简单；一个语义配置要触发多条规则时样式查询才更有价值。

同一组工具按钮，在文章页希望留白舒适，在数据表格旁希望紧凑。两处区域的宽度可能完全一样，因此尺寸查询不能表达这个区别。这里的依据是父级选择的“显示密度”，可以使用容器样式查询，让内部组件读取祖先的配置。

尺寸查询问“容器有多大”，样式查询问“容器上的某项样式是否满足条件”。 常见实现是通过 style(--自定义属性: 值) 查询 CSS 自定义属性。MDN 目前写明：样式查询唯一支持的特性是自定义属性（可带值或不带值），style(font-weight: bold) 这类对普通属性的查询还没有任何浏览器支持。样式查询也不需要设置 container-type，任何元素都可以作为样式容器。

一个紧凑工具栏的例子

HTML
<section class="workspace" data-density="compact">
  <div class="toolbar" aria-label="文档操作">
    <button type="button">保存</button>
    <button type="button">预览</button>
  </div>
</section>
CSS
.workspace {
  container-name: workspace;
  --density: comfortable;
}

.workspace[data-density="compact"] {
  --density: compact;
}

.toolbar {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
}

.toolbar button {
  font: inherit;
  padding: 0.75rem 1rem;
}

@container workspace style(--density: compact) {
  .toolbar {
    gap: 0.375rem;
  }

  .toolbar button {
    padding: 0.5rem 0.75rem;
  }
}

外层的 data-density 把配置写成 --density: compact。查询找到名为 workspace 的祖先，读取它的自定义属性；条件满足后，内部工具栏缩小间距和按钮内边距。移除 data-density="compact"，就回到基础布局。

这里没有 container-type: inline-size，因为我们没有查询宽度。仅做这种样式查询，不需要为了建立尺寸容器而给布局增加尺寸包含。container-name 的作用是明确读取哪一层祖先，特别适合页面上有多个可嵌套的配置区域时使用。

规则仍然作用于容器里的元素，不能用这条查询让 .workspace 依据自己的 --density 再改变自己的该属性。选中 .workspace 时，查询会寻找它的祖先，而不是把它自身当作查询来源。

为什么不直接使用 CSS 变量

如果只需要改变一个间距，变量往往更简单：

CSS
.workspace {
  --toolbar-gap: 0.75rem;
}

.workspace[data-density="compact"] {
  --toolbar-gap: 0.375rem;
}

.toolbar {
  gap: var(--toolbar-gap, 0.75rem);
}

这已经足以解决“传一个值”的问题。样式查询更适合一个语义配置需要触发多条规则的情况，例如 compact 同时影响间距、说明文字的展示方式和工具栏布局。它让组件解释配置，而不是要求父级了解每个内部选择器。

如果父子结构固定、没有复用需要，.workspace[data-density="compact"] .toolbar 也完全合理。不能因为语法新，就把简单的后代选择器全部改成样式查询。

自定义属性的值如何比较

未注册的自定义属性通常不会被当成颜色、长度等具体类型理解。比如 --accent: #0000ff 与查询中的 style(--accent: blue)，不能只因为肉眼看到同一种蓝色，就认为一定匹配。通过 @property 注册类型会影响计算与比较规则，也会影响初始值和继承。

对于密度、主题模式等开关，用 compact、comfortable 这样约定明确的值更容易维护。普通自定义属性默认会继承；如果不用容器名称，最近的祖先也可能已经继承了该值，因此要区分“值从哪儿继承”与“查询选中了哪个祖先”。

兼容性要按 style() 的具体功能核对，支持尺寸查询不代表支持所有样式查询。在目标浏览器实测上述 data-density 切换；不支持时保留舒适的基础布局即可。若紧凑模式是必要功能，则使用类名或属性选择器作为实现或回退，不要让关键内容依赖查询成功才出现。
