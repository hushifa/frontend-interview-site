MutationObserver 和 ResizeObserver 分别观察什么？

MutationObserver 看 DOM 有没有被改，比如节点增删、属性和文字变化；ResizeObserver 看元素尺寸有没有变。尺寸变了 DOM 不一定变，两者不能互相替代。

参考答案

简答

两个都是“观察器”，区别在看什么。MutationObserver 看的是 DOM 有没有被改：子节点增删（childList）、属性变化（attributes）、文字变化（characterData），加上 subtree: true 就连所有后代一起看。

它的回调不是每改一次就调一次，而是放在微任务里批量执行，一次把这段时间的所有变化记录交给你。

ResizeObserver 看的是元素尺寸。窗口缩放、字体加载完、父容器变宽都会让元素变大变小，可这些时候 DOM 一点都没改，MutationObserver 是察觉不到的。所以两者不能互相替代。

要注意，在 MutationObserver 回调里又改被观察的 DOM，会产生新记录、再触发回调，容易形成循环。观察范围也要尽量小。

用 MutationObserver 处理新插入的图片

下面观察一个容器，有新的 img[data-src] 插进来就懒加载它。

JavaScript
const observer = new MutationObserver((records) => {
  for (const record of records) {
    for (const node of record.addedNodes) {
      if (node instanceof Element && node.matches('img[data-src]')) lazyLoad(node);
    }
  }
});

observer.observe(container, { childList: true, subtree: true });

为什么回调收到的是一个数组？因为它是批量的。同一段同步代码里插了十个节点，回调只执行一次，records 里有十条记录。这样比每次修改都回调一次省得多。

addedNodes 里可能有文本节点，所以要先判断 node instanceof Element 再调用 matches。

观察时的几个常用选项

如果只关心某几个属性，用 attributeFilter: ['class']，其他属性变化就不会产生记录。想知道属性改之前是什么，加 attributeOldValue: true，记录里会带上旧值。

observer.takeRecords() 能把还没交给回调的记录立刻取出来，常在 disconnect() 停止观察前调用，免得漏掉最后几条。

该用哪一个

第三方脚本往页面里插了节点、富文本编辑器的内容变了，这些是 DOM 结构变化，用 MutationObserver。容器宽度变了要重新布局图表，这是尺寸变化，用 ResizeObserver。如果要知道元素有没有进入视口，两个都不对，要用 IntersectionObserver。

ResizeObserver 的具体用法见《ResizeObserver 为什么可能出现循环通知错误？》。

常见追问

观察整个 document.body 有什么问题？

每次 DOM 变化都要生成记录。在更新很频繁的页面上，这个开销很明显。所以观察范围要尽量小，能观察一个容器就不要观察整个 body。

自己框架渲染的组件，需要用 MutationObserver 监听变化吗？

通常不需要。组件自己就知道什么时候更新，直接在更新逻辑里处理就行。MutationObserver 更适合观察不受你控制的 DOM，比如第三方脚本插入的内容。
