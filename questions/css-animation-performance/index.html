transition、animation 和 requestAnimationFrame 怎么选？

transition 处理两个状态之间的过渡，animation 处理关键帧过程，requestAnimationFrame 用于由 JavaScript 按时间计算每一帧。性能取决于每帧触发的是布局、绘制还是合成。

参考答案

简答

  • 两个明确状态之间的反馈用 transition；多关键帧、循环或独立启动的过程用 animation。
  • 物理计算、Canvas 绘制或跟随拖拽时用 requestAnimationFrame，并按时间戳计算进度，不要每帧固定加一个值。
  • 性能看每帧做了什么：改宽高会触发布局，改背景会重绘，transform 和 opacity 通常可以只在合成阶段处理。
  • 需要暂停、反向或等待结束，又不想手写逐帧循环时，用 Web Animations API。
  • 所有方式都要为 prefers-reduced-motion 提供静态替代。

transition

CSS
.action {
  transition: transform 180ms ease;
}

.action:hover,
.action:focus-visible {
  transform: translateY(-2px);
}

@media (prefers-reduced-motion: reduce) {
  .action {
    transition: none;
  }
}

transition 只在样式值发生变化时运行。明确列出要过渡的属性，transition: all 容易把布局属性也带进动画。

animation

CSS
@keyframes pulse {
  50% { opacity: 0.5; }
}

.pending {
  animation: pulse 1.2s ease-in-out infinite;
}

animation-fill-mode 只决定动画区间外是否保留关键帧样式，不会改写元素的基础样式。动画结束后需要的稳定状态，应由类名或样式单独维护。

requestAnimationFrame

rAF 在下一次渲染前调用一次回调，要继续就在回调里再申请。下面的函数把元素横向移动到 distance，返回取消函数：

JavaScript
function animateTranslate(element, distance, duration = 300) {
  if (!Number.isFinite(distance) ||
      !Number.isFinite(duration) || duration < 0) {
    throw new RangeError('位移必须是有限数值，时长必须是非负有限数值');
  }

  const reduceMotion = matchMedia('(prefers-reduced-motion: reduce)').matches;
  if (duration === 0 || reduceMotion) {
    element.style.transform = `translateX(${distance}px)`;
    return () => {};
  }

  let frameId = null;
  let startedAt;
  let cancelled = false;

  function frame(now) {
    if (cancelled) return;
    startedAt ??= now;
    const progress = Math.min((now - startedAt) / duration, 1);
    element.style.transform = `translateX(${distance * progress}px)`;

    if (progress < 1) frameId = requestAnimationFrame(frame);
    else frameId = null;
  }

  frameId = requestAnimationFrame(frame);
  return function cancel() {
    cancelled = true;
    if (frameId !== null) cancelAnimationFrame(frameId);
    frameId = null;
  };
}

进度由时间差除以总时长得到，60Hz 和 120Hz 屏幕在相同时间内走到相同位置。如果写成“每帧加 2px”，速度会随刷新率变化。

后台标签页的 rAF 通常暂停，回到前台后这段代码会按已流逝时间直接跳到对应位置。业务需要“后台暂停计时”时，要自己记录暂停时段。

性能

  • 布局属性（width、top、margin）的动画每帧都可能重新布局。
  • transform、opacity 在合适条件下由合成器处理，主线程繁忙时仍可能流畅。
  • will-change 会提前创建合成层，占用显存，只在测量证明需要时短期使用。
  • 在 rAF 回调里交替读取布局和写样式，会造成强制同步布局。先集中读，再集中写。

用浏览器 Performance 面板查看每帧的布局、绘制和合成耗时，再决定是否需要改写。

常见追问

  • CSS 动画一定比 JS 动画快吗？不一定。两者改同样的属性时成本相近，差别在于 CSS 和 WAAPI 的 transform、opacity 动画可以交给合成器，不受主线程阻塞影响。
