HTML 语义化对阅读、搜索与无障碍有什么价值？

语义化是用元素表达内容的角色，例如标题、导航、列表、按钮；浏览器、读屏软件和搜索引擎据此理解结构，代码也更易维护。语义元素不能代替正确的交互和内容。

参考答案

简答

  • 读屏用户常按标题、地标、链接列表跳转；用 h1–h6、nav、main 等元素，这些跳转才能用。
  • 原生元素自带行为：button 可用键盘激活，a href 可在新标签打开，label 扩大点击区域。
  • 搜索引擎用标题和结构理解页面主题，阅读模式和翻译工具也依赖语义。
  • 选择元素按含义而不是外观，外观交给 CSS。
  • div 和 span 没有语义，适合纯布局；需要语义时先找原生元素，没有合适元素再考虑 ARIA。

页面结构

HTML
<body>
  <header>
    <a href="/">站点名</a>
    <nav aria-label="主导航">
      <ul>
        <li><a href="/questions">题库</a></li>
        <li><a href="/resources">资源</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <article>
      <h1>闭包是什么？</h1>
      <section aria-labelledby="usage">
        <h2 id="usage">常见用途</h2>
        <p>……</p>
      </section>
    </article>
  </main>

  <footer>……</footer>
</body>
  • main 每页一个，是“跳到主内容”的目标。
  • 页面有多个 nav 时，用 aria-label 区分。
  • section 只有带名称时才成为地标；没有标题的分组用 div。

标题层级

标题按层级嵌套，不要为了字号跳级，例如 h2 下直接用 h4。需要小字号的二级标题，用 CSS 调整。每页通常只有一个 h1。

常见追问

  • 语义化和 SEO 的关系有多大？搜索引擎能处理不规范的页面，语义化不会直接提高排名，但清晰的标题和结构有助于正确理解内容和生成摘要。
