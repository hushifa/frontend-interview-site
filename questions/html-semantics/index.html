HTML 语义化对阅读、搜索与无障碍有什么价值？

语义化就是按内容的角色选元素，标题用 h1 到 h6，导航用 nav，按钮用 button。读屏软件、浏览器和搜索引擎靠这些元素理解页面结构，代码也更好维护。

参考答案

简答

语义化就是按内容是什么来选元素，而不是按它长什么样。标题用 h1 到 h6，导航用 nav，列表用 ul，按钮用 button。外观交给 CSS。

最直接的受益者是读屏用户。他们常常按标题、按地标、按链接列表在页面里跳着找内容，地标就是 nav、main 这类表示页面区域的元素。页面全是 div，这些跳转就用不了。原生元素还自带行为，button 能用键盘触发，a href 能在新标签页打开，label 能扩大点击区域。

搜索引擎也用标题和结构理解页面在讲什么，阅读模式和翻译工具同样依赖语义。

div 和 span 没有语义，适合纯粹做布局。需要语义时，先找有没有合适的原生元素，实在没有再考虑 ARIA。不过语义元素代替不了正确的交互和内容本身。

一个页面的基本结构

HTML
<body>
  <header>
    <a href="/">站点名</a>
    <nav aria-label="主导航">
      <ul>
        <li><a href="/questions">题库</a></li>
        <li><a href="/resources">资源</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <article>
      <h1>闭包是什么？</h1>
      <section aria-labelledby="usage">
        <h2 id="usage">常见用途</h2>
        <p>……</p>
      </section>
    </article>
  </main>

  <footer>……</footer>
</body>

main 每个页面只有一个，它是“跳到主内容”的目标。读屏用户不用每次都从导航听起。

页面上有好几个 nav 时，比如主导航和页脚导航，用 aria-label 给它们起不同的名字，读屏用户才分得清。

section 有点特别，只有带了名字，比如这里用 aria-labelledby 关联了标题，它才会成为地标。没有标题的分组，直接用 div 就好。

标题层级为什么不能跳

读屏用户会用标题列表了解页面大纲，就像看书的目录。h2 下面直接用 h4，目录里就少了一级，看起来像漏了内容。

所以标题要按层级来。觉得 h3 字号太大想用 h4，正确的做法是继续用 h3，再用 CSS 改字号。每个页面通常只有一个 h1。

常被用错的元素

执行一个操作，用 button，而不是给 div 加 onclick。

跳转到别的页面，用 a href，而不是在 button 里写 location.href。

列表用 ul 或 ol，不是一串 div。数据表格用 table 加 th，不是用 grid 拼出来的样子像表格的东西。

强调用 strong 或 em，不要只用 b、i 或者加粗样式。

常见追问

语义化对 SEO 的帮助有多大？

搜索引擎能处理写得不规范的页面，语义化不会直接提高排名。但清晰的标题和结构，能帮助搜索引擎正确理解内容、生成更准确的摘要。
