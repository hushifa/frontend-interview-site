Node.js 的 package exports 会怎样影响模块解析？

package.json 的 exports 声明包的公开入口，未列出的子路径无法被导入。条件导出让同一入口按 import、require、node、default 等条件指向不同文件。exports 不改变文件的模块格式，ESM 与 CommonJS 互操作还受 require(esm) 支持版本的影响。

参考答案

简答

  • 包配置了 exports 后，Node.js 只允许导入其中列出的路径，导入未导出的子路径会抛出 ERR_PACKAGE_PATH_NOT_EXPORTED；exports 优先于 main。
  • 条件导出按对象键的书写顺序匹配，第一个满足的条件生效，default 应放在最后。
  • 文件的模块格式由扩展名和最近 package.json 的 type 决定，exports 只负责选路径。
  • Node.js 20.19+、22.12+ 默认允许 require() 加载 ES 模块；模块图里有顶层 await 时会抛出 ERR_REQUIRE_ASYNC_MODULE。
  • Node.js 原生 ESM 中的相对导入必须写完整的文件扩展名。

一个双格式包

json
{
  "name": "demo-kit",
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./format": "./dist/format.js",
    "./internal/*": null
  }
}

在 Node.js 22 中实测：

导入方式结果
import 'demo-kit'加载 dist/index.js
require('demo-kit')加载 dist/index.cjs
import 'demo-kit/format'加载 dist/format.js
import 'demo-kit/dist/internal.js'ERR_PACKAGE_PATH_NOT_EXPORTED

"./internal/*": null 显式排除一组子路径。types 条件供 TypeScript 使用，按 TypeScript 的要求放在第一个。

exports 是模块解析层面的封装：代码仍然可以用绝对路径直接读取包里的文件，它不能用来隐藏秘密。

条件的匹配规则

Node.js 内置认识 import、require、module-sync、node、default 等条件。解析时从上到下检查对象键，第一个匹配的条件生效。default 总能匹配，放在前面会让后面的分支永远选不中。

打包工具会额外识别 browser、development 等条件。同一个包在 Vite 里能用，不代表 Node.js 直接运行时会选到同一个文件，发布前要在两种环境里分别测试。

模块格式与 require(esm)

.mjs 总是 ESM，.cjs 总是 CommonJS，.js 由最近的 package.json 的 type 决定。把 ESM 文件放在 require 条件下面，并不会把它变成 CommonJS。

Node.js 20.19+ 和 22.12+ 默认允许 require() 同步加载 ES 模块，可以用 process.features.require_module 检测：

JavaScript
// sync.mjs: export const v = 2;
// tla.mjs:  export const v = await Promise.resolve(1);
require('./sync.mjs').v; // 2
require('./tla.mjs');    // 抛出 ERR_REQUIRE_ASYNC_MODULE

这让很多库可以只发布 ESM。仍需支持更早版本时，才需要同时提供 CommonJS 产物。同时发布两种格式时，要注意"双包风险"：同一进程里 import 和 require 可能各加载一份实现，模块级状态、单例和 instanceof 判断会出现两套。

包内部别名

包内代码之间的别名用 imports 字段定义，键以 # 开头，例如 #logger，Node.js 运行时会读取它。TypeScript 的 paths 只影响类型检查，运行时不起作用。exports 与 imports 的设计细节见《package.json 的 exports 和 imports 分别解决什么问题？》。

常见追问

  • 为什么 ESM 必须写扩展名？ Node.js 的 ESM 解析按 URL 规则查找文件，不会像 CommonJS 那样依次尝试 .js、.json 和目录下的 index.js。
  • 发布前怎样验证 exports？ 在一个独立的消费项目里分别用 import、require 和 TypeScript 导入每个公开路径，并确认被排除的路径会报错。
