URLPattern 适合做路由匹配吗？

URLPattern 用类似 /users/:id 的写法匹配网址并取出参数，适合 Service Worker 路由和轻量前端路由，MDN 标为 Baseline 2025。用对象形式时基准地址要写进 baseURL 字段，不能当第二个参数传。

参考答案

简答

写路由时，经常要判断“这个网址是不是 /users/某个 id”，还要把 id 取出来。以前要自己写正则，现在浏览器有了 URLPattern。它的写法和 path-to-regexp 差不多，:id 是命名参数，* 是通配符，而且能分别匹配协议、主机、路径、查询、哈希。

用法很简单：pattern.test(url) 返回是否匹配，pattern.exec(url) 返回各部分的匹配结果和参数。

构造有两种写法。一种是字符串模式，第二个参数是基准地址；另一种是对象，基准地址写在对象的 baseURL 字段里。对象形式再传字符串第二个参数，会抛 TypeError。对象里没写的部分默认是通配符，比如不写 hostname，任何域名都能匹配。

MDN 标为 Baseline 2025，Worker 里也能用，旧浏览器可以用 urlpattern-polyfill。它只负责匹配，嵌套布局、数据加载、多条路由谁优先，还得自己处理。

基本用法

下面用两种写法创建同一个模式。

JavaScript
const pattern = new URLPattern({ pathname: '/users/:id', baseURL: 'https://example.com' });

pattern.test('https://example.com/users/42'); // true
pattern.test('https://other.com/users/42'); // false
pattern.exec('https://example.com/users/42').pathname.groups; // { id: '42' }

const relative = new URLPattern('/users/:id', 'https://example.com');
relative.test('https://example.com/users/7'); // true

为什么换了个域名就不匹配了？因为 baseURL 不只是用来补全路径，它还提供了协议和主机，所以这个模式只匹配 example.com。如果去掉 baseURL，主机没写就是通配符，other.com 也会匹配。

取参数要从 exec 结果的对应部分里拿，路径参数在 pathname.groups 里。

给参数加约束

默认情况下，:name 会匹配到下一个分隔符前最短的内容。遇到 app.8f3a.js 这种有多个点的文件名，结果就不符合预期。这时可以在参数后面加括号，写正则约束：

JavaScript
const asset = new URLPattern({ pathname: '/assets/:name([^\\/]+)\\.:ext([a-z0-9]+)' });
asset.exec('https://cdn.example.com/assets/app.8f3a.js').pathname.groups;
// { name: 'app.8f3a', ext: 'js' }

[^\/]+ 是贪婪匹配，它先吃掉尽量多的内容，再回溯，让 ext 只拿到最后一段扩展名，所以 name 是 app.8f3a。

有个坑：字符类里的 / 要写成 \/。写成 [^/]+ 时，Chrome 156 在构造阶段就抛 TypeError（invalid regular expression group）。

另外还有几个修饰符：:id? 表示可选，:path+ 表示一段或多段，:path* 表示零段或多段。

在 Service Worker 里做路由

下面只拦截同源的 /api/ 请求，走网络优先策略。

JavaScript
const apiRoute = new URLPattern({ pathname: '/api/*', baseURL: self.location.origin });

self.addEventListener('fetch', (event) => {
  if (apiRoute.test(event.request.url)) {
    event.respondWith(networkFirst(event.request));
  }
});

Service Worker 会收到页面发出的所有请求，包括第三方域名的。把 baseURL 设成当前源，第三方域名上的 /api/ 就不会被误匹配。

适合做框架路由吗

它适合 Service Worker 的缓存路由、轻量路由表，以及校验回调地址是否在允许范围内。

框架路由一般还需要嵌套布局、数据加载和优先级排序，URLPattern 只解决了匹配这一部分。多个模式都能匹配同一个地址时，它不会帮你选，要自己按注册顺序判断。

常见追问

对象形式为什么不能传第二个参数？

因为对象形式的基准地址规定写在 baseURL 字段里。再传一个字符串作第二个参数，就会抛 TypeError。字符串模式才用第二个参数当基准地址。

不写 hostname 会怎样？

对象里没写的部分默认是通配符，所以任何域名都能匹配。只想匹配自己的站点，就要写 baseURL 或 hostname。
