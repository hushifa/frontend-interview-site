URLPattern 适合做路由匹配吗？

URLPattern 用和 path-to-regexp 相近的语法匹配 URL 的各个部分并提取命名参数，适合 Service Worker 路由和轻量前端路由；MDN 标为 Baseline 2025。对象形式的基准地址要写在 baseURL 字段里，不能作为第二个参数。

参考答案

简答

  • URLPattern 分别匹配协议、主机、路径、查询、哈希等部分，:id 是命名参数，* 是通配符。
  • pattern.test(url) 返回布尔值，pattern.exec(url) 返回各部分的匹配结果和参数。
  • 构造方式：字符串模式加第二个参数作基准地址，或对象形式把 baseURL 写在对象里；对象形式再传字符串第二个参数会抛 TypeError。
  • 对象里没写的部分默认是通配符，不写 hostname 时任意域名都能匹配。
  • MDN 标为 Baseline 2025，Worker 中也可用；旧浏览器可以用 urlpattern-polyfill。

基本用法

JavaScript
const pattern = new URLPattern({ pathname: '/users/:id', baseURL: 'https://example.com' });

pattern.test('https://example.com/users/42'); // true
pattern.test('https://other.com/users/42'); // false
pattern.exec('https://example.com/users/42').pathname.groups; // { id: '42' }

const relative = new URLPattern('/users/:id', 'https://example.com');
relative.test('https://example.com/users/7'); // true

baseURL 提供了协议和主机，所以只匹配 example.com。

带约束的参数

JavaScript
const asset = new URLPattern({ pathname: '/assets/:name([^\\/]+)\\.:ext([a-z0-9]+)' });
asset.exec('https://cdn.example.com/assets/app.8f3a.js').pathname.groups;
// { name: 'app.8f3a', ext: 'js' }
  • 括号里是正则约束，[^\/]+ 贪婪匹配，回溯后让 ext 只拿到最后一段扩展名。字符类里的 / 要写成 \/；写成 [^/]+ 时 Chrome 156 在构造阶段就抛 TypeError（invalid regular expression group）。
  • 不加约束时，:name 默认匹配到下一个分隔符前的最短内容，多段扩展名的结果不符合预期。
  • :id? 可选，:path+ 一段或多段，:path* 零段或多段。

Service Worker 路由

JavaScript
const apiRoute = new URLPattern({ pathname: '/api/*', baseURL: self.location.origin });

self.addEventListener('fetch', (event) => {
  if (apiRoute.test(event.request.url)) {
    event.respondWith(networkFirst(event.request));
  }
});

把 baseURL 设为当前源，只拦截同源的 /api/ 请求，第三方域名上的 /api/ 不会被误匹配。

适合与不适合

  • 适合：Service Worker 缓存路由、轻量路由表、校验回调地址是否在允许范围内。
  • 框架路由通常还需要嵌套布局、数据加载和优先级排序，URLPattern 只解决匹配部分。
  • 多个模式都能匹配时，按注册顺序判断，自己决定优先级。
