怎样用显式栈实现树的前序遍历？

前序遍历是先访问当前节点，再从左到右把每棵子树完整走一遍。用数组当栈代替递归，树很深时也不会把调用栈撑爆；因为栈是后进先出，子节点要倒着放进去。时间复杂度 O(n)，栈最多占多少看树的形状。

参考答案

简答

前序遍历的顺序是：先访问当前节点，再走第一棵子树，再走第二棵子树。一棵子树全部走完，才轮到下一个兄弟。比如结果是 A、B、D、E、C、F。

为什么不用递归？递归要靠函数调用栈记住“走完这棵子树要回到哪里”，树很深时会抛出 RangeError: Maximum call stack size exceeded。显式栈是自己用一个数组存待访问的节点，深度只受内存限制。

写的时候要注意，栈是后进先出的，所以子节点要从最后一个开始压，第一个子节点才会最先弹出来。每个节点进栈出栈各一次，时间复杂度是 O(n)。这个实现一次把所有子节点都压进去，所以在很宽的树上，栈最多可能放 O(n) 个节点。

还有一个前提：输入必须是树。同一个节点如果被好几个父节点引用，会被重复访问；有环的话会无限循环。遍历图要用一个访问集合去重。

实现

JavaScript
function preorder(root) {
  if (root == null) return [];
  const stack = [root];
  const values = [];

  while (stack.length > 0) {
    const node = stack.pop();
    if (node === null || typeof node !== 'object') {
      throw new TypeError('树节点必须是对象');
    }

    const children = node.children ?? [];
    if (!Array.isArray(children)) {
      throw new TypeError('children 必须是数组');
    }

    values.push(node.value);
    for (let index = children.length - 1; index >= 0; index--) {
      stack.push(children[index]);
    }
  }

  return values;
}

逻辑很短：弹出一个节点，记下它的值，再把它的子节点倒着压进栈。下面用一棵小树试一下：

JavaScript
const tree = {
  value: 'A',
  children: [
    { value: 'B', children: [{ value: 'D' }, { value: 'E' }] },
    { value: 'C', children: [{ value: 'F' }] },
  ],
};

console.log(preorder(tree).join('、'));
console.log(preorder(null));

输出是 A、B、D、E、C、F 和 []。这个函数只读树，不会修改 children 数组；如果 value 是对象，返回的是原对象的引用，不是副本。

栈里到底发生了什么

把每一步栈的状态列出来，栈顶写在右边：

弹出压入弹出后栈的状态
AC、B[C, B]
BE、D[C, E, D]
D无[C, E]
E无[C]
CF[F]
F无[]

可以看到，B 的两个孩子压进来以后，它们在 C 的上面，所以会先于 C 弹出。这就保证了“B 这棵子树走完，才轮到 C”。

如果按正序压，先压 B 再压 C，C 就在栈顶，会比 B 先弹出来，结果就变成 A、C、F、B、E、D，顺序反了。

和递归写法比一比

JavaScript
function preorderRecursive(node, values = []) {
  if (node == null) return values;
  values.push(node.value);
  for (const child of node.children ?? []) preorderRecursive(child, values);
  return values;
}

递归更直观，适合深度可控的树，比如组件树、菜单。处理用户导入的、层级不确定的数据时，用显式栈更稳。递归最多能支持多深，跟引擎、每一层调用占多少空间有关，没有一个统一的层数。

其他遍历顺序

顺序访问规则典型用途
前序节点 → 子树复制树、序列化、渲染目录
后序子树 → 节点计算文件夹总大小、按依赖顺序释放资源
层序按深度一层层访问，用队列找最浅的匹配节点、按层展示

常见追问

树有十万个节点，放在主线程遍历会卡吗？

遍历本身是同步计算，时间太长就会挡住用户交互。可以分批处理，中间让出主线程，或者把数据交给 Worker 去算。

怎么把扁平的 { id, parentId } 列表转成树？

先用 Map 按 id 建索引，再遍历一次，把每个节点挂到父节点的 children 上，复杂度是 O(n)。详细写法见《怎样在 O(n) 时间内把扁平列表转成树，再把树转回列表？》。
