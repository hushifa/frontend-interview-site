Intl.Segmenter 怎样处理用户看到的字符和词？

使用语言相关的分词与字符分割，避免把 JavaScript 的字符串 length 当成用户感知长度。

参考答案

简答

  • Intl.Segmenter 按字素簇、词或句切分文本，比 string.length 更接近用户看到的字符。
  • 截断摘要时按字素簇截断，避免拆散 emoji 或组合字符。
  • 按词切分的结果里包含空格和标点，可以用 isWordLike 区分。
  • 高亮时使用原字符串的 index；它不负责排版宽度和换行。

Intl.Segmenter 根据语言和指定粒度划分字符串。它适合处理两个经常被简单切割弄错的需求：摘要不能截断一个 emoji，统计词数不能只按空格拆分。

它支持 grapheme、word、sentence 三种粒度，分别接近字素簇、词边界和句子边界。选择哪一种取决于功能，不是精度越细越好。

截断摘要时保留完整字素簇

下面把 limit 定义为“保留多少个原文字素簇”，省略号不计入这个额度：

JavaScript
const graphemes = new Intl.Segmenter('zh-CN', {
  granularity: 'grapheme',
});

function truncateText(text, limit) {
  if (!Number.isInteger(limit) || limit < 0) {
    throw new RangeError('保留数量必须是非负整数');
  }

  let count = 0;
  for (const part of graphemes.segment(text)) {
    if (count === limit) {
      return text.slice(0, part.index) + '…';
    }
    count += 1;
  }
  return text;
}

console.log(truncateText('A👨‍👩‍👧‍👦B', 2)); // A👨‍👩‍👧‍👦…
console.log(truncateText('A😀', 2)); // A😀
console.log(truncateText('', 0)); // 空字符串

遇到第 limit + 1 个片段，才确定需要省略号；长度刚好等于 limit 时不额外添加。part.index 是原字符串的 UTF-16 下标，可以直接交给 slice，避免自己累加时混淆码点和码元。

这个循环不必先把整段文本转换为数组，找到截断点就能结束。limit 为 0 且文本非空时返回省略号；若产品希望总长度包含省略号，应另外定义额度，不能在实现后让用户猜规则。

按词分割时还会得到空格和标点

JavaScript
const words = new Intl.Segmenter('en', { granularity: 'word' });
const result = [...words.segment('Hello, world!')]
  .filter((part) => part.isWordLike)
  .map((part) => ({ text: part.segment, index: part.index }));

console.log(result);
// [{ text: 'Hello', index: 0 }, { text: 'world', index: 7 }]

segment 返回可迭代结果，包含片段文本、起始位置以及原字符串等信息。word 粒度还提供 isWordLike，用来区分常见的词样片段与空白、标点；不能把所有片段数量直接当词数。

中文、日文、泰文等语言不依赖空格分隔每个词，Segmenter 比 split(' ') 更适合做语言相关边界处理。不过分词依赖运行时语言数据，不是理解句意的自然语言模型，也不能保证符合某个业务词典或搜索引擎的切词规则。

高亮时保留原始片段与索引

如果根据词边界构建搜索高亮，使用片段的 index 和 segment.length 对应原字符串范围，不要先删除标点或规范化全文后，再拿新字符串的下标切旧字符串。

大小写折叠、Unicode 规范化和字符替换可能改变匹配方式甚至长度。若业务先做这些转换，应维护位置映射，或者选择能保留原始范围的搜索方案。

渲染高亮应输出文本节点和明确的标记元素，不要把用户文本拼进 innerHTML。Segmenter 负责划分，不负责 HTML 转义或净化。

它不负责所有文字布局问题

sentence 粒度用于句子边界，但缩写、引用和复杂标点仍需结合目标语言样本验证。grapheme 分割也不保证某段文字能放进固定宽度容器，字符宽度、字体和换行属于排版问题。

对 HTML 摘要，不能把整段源码直接分割后截断，否则可能把标签或实体切坏。可以先提取纯文本，或者使用理解 DOM 结构的摘要策略。

浏览器支持及 Unicode/ICU 数据版本也要核对。缺少原生支持时可以使用维护的兼容实现；Array.from 只能提供码点级切割，不能宣称是等价的字素簇降级。测试应覆盖组合重音、肤色 emoji、连接 emoji 和目标语言的实际词句。
