OffscreenCanvas 什么时候能减少主线程绘制压力？

OffscreenCanvas 让 Canvas 在 Worker 里绘制，主线程忙的时候动画和图表照样流畅。它只在绘制本身很重时才划算，画得很轻时，线程间传消息的开销反而更大。

参考答案

简答

页面上有一张几十万个点的图表，每次重绘都要几十毫秒，主线程一忙，滚动和点击就卡。OffscreenCanvas 能把绘制挪到 Worker 里：页面上的 <canvas> 调用 transferControlToOffscreen()，把得到的 OffscreenCanvas 交给 Worker，Worker 画的内容会直接显示在页面上。

Worker 里支持 2d、webgl、webgl2 上下文。专用 Worker 里的 requestAnimationFrame 各浏览器支持不一样，用之前做特性检测，没有就退回 setTimeout。

它适合绘制成本高的工作，比如大量数据点的图表、地图和游戏渲染、图片滤镜。也可以用 new OffscreenCanvas(w, h) 在后台生成图片，再用 convertToBlob() 导出。

要注意 Worker 访问不了 DOM，鼠标事件要在主线程监听再发过去。转移以后主线程也不能再改这个 canvas 的尺寸。如果每帧画的东西很少，或者每帧都要传大量数据，用它反而更慢。

把绘制交给 Worker

主线程这边负责三件事：转移 canvas、转发鼠标事件、通知尺寸变化。

JavaScript
// main.js
const canvas = document.querySelector('canvas');
const offscreen = canvas.transferControlToOffscreen();
const worker = new Worker(new URL('./chart.worker.js', import.meta.url), { type: 'module' });

const { width, height } = canvas.getBoundingClientRect();
worker.postMessage(
  { type: 'init', canvas: offscreen, dpr: devicePixelRatio, width, height },
  [offscreen],
);

canvas.addEventListener('pointermove', (event) => {
  worker.postMessage({ type: 'pointer', x: event.offsetX, y: event.offsetY });
});

new ResizeObserver(([entry]) => {
  const { width, height } = entry.contentRect;
  worker.postMessage({ type: 'resize', width, height });
}).observe(canvas);

postMessage 的第二个参数 [offscreen] 表示转移，而不是复制。转移以后这个对象就归 Worker 了，主线程不能再用它。

Worker 这边按消息类型处理：

JavaScript
// chart.worker.js
let ctx;
let canvas;
let dpr = 1;

self.onmessage = ({ data }) => {
  if (data.type === 'init') {
    canvas = data.canvas;
    dpr = data.dpr;
    ctx = canvas.getContext('2d');
    // 首次 resize 之前按实际尺寸绘制，而不是默认的 300×150
    canvas.width = data.width * dpr;
    canvas.height = data.height * dpr;
    ctx.scale(dpr, dpr);
  } else if (data.type === 'resize') {
    canvas.width = data.width * dpr;
    canvas.height = data.height * dpr;
    ctx.scale(dpr, dpr);
  } else if (data.type === 'pointer') {
    drawHighlight(ctx, data.x, data.y);
  }
};

为什么尺寸要发消息让 Worker 改？因为转移以后，主线程不能再对这个 <canvas> 调用 getContext()，也不能直接改它的 width、height，只有 Worker 能改。

为什么每次 resize 都要重新 scale？因为修改 canvas.width 会把上下文的变换重置掉，之前的 scale(dpr, dpr) 就没了，不重新设置，高清屏上画出来会模糊。

什么时候用了也没用

如果每帧只画几个图形，绘制本身很快，那卡顿其实来自主线程上的其他代码，把绘制挪走也解决不了。

如果绘制依赖大量主线程的数据，每帧都要传过去，克隆数据的成本可能比绘制本身还高，反而更慢。

兼容性怎么处理

OffscreenCanvas 已在主流浏览器中可用。用之前检测 'transferControlToOffscreen' in HTMLCanvasElement.prototype，不支持就在主线程绘制。

常见追问

Worker 里能直接监听鼠标事件吗？

不能。Worker 访问不了 DOM，也收不到页面上的事件。要在主线程监听，再用 postMessage 把坐标发给 Worker。

不显示在页面上，只想在后台生成一张图可以吗？

可以。直接 new OffscreenCanvas(w, h) 创建一个，画完调用 convertToBlob() 导出成图片，不需要页面上有 <canvas>。
