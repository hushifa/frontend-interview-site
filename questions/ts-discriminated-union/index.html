如何用可辨识联合避免不合理的状态组合？

用一个共同的字面量字段（status、kind）区分各个状态分支，每个分支只携带自己需要的数据，就不会出现"加载中同时出错"这类组合。switch 判别字段时 TypeScript 自动收窄，default 中用 never 做穷尽检查。联合只描述合法形态，状态迁移和竞态仍要单独处理。

参考答案

简答

  • 三个布尔值 isLoading、isSuccess、isError 有 8 种组合，大部分是非法状态；联合只列出合法的几种。
  • 每个分支有字面量类型的判别字段，并带上该状态必需的数据，例如 success 分支必有 data。
  • 按判别字段 switch 或 if 后，TypeScript 把整个对象收窄到对应分支。
  • default 中把值传给参数类型为 never 的函数，新增分支后漏处理的地方会编译报错。
  • 联合不限制状态如何迁移，旧请求结果覆盖新请求这类竞态需要请求 ID 或取消来解决。

示例

TypeScript
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error };

function assertNever(value: never): never {
  throw new Error(`未处理的状态：${JSON.stringify(value)}`);
}

function describe(state: RequestState<readonly string[]>): string {
  switch (state.status) {
    case 'idle':
      return '尚未加载';
    case 'loading':
      return '加载中';
    case 'success':
      return `${state.data.length} 项`;
    case 'error':
      return state.error.message;
    default:
      return assertNever(state);
  }
}

对比 { status: ...; data?: T; error?: Error }：后者在 success 分支中 data 仍是可选的，到处需要 data!。

构造非法对象会报错

TypeScript
// @ts-expect-error success 分支必须提供 data
const missingData: RequestState<string> = { status: 'success' };

如果业务确实需要"刷新时显示旧数据"，就新增一个分支 { status: 'refreshing'; data: T }，而不是把 loading 断言成 success。新增后所有 switch 中的 assertNever 会提示需要更新的位置。

保留判别关系

TypeScript
const state = { status: 'loading' } as const;

不加 as const 或类型标注时，status 会被推断成 string，不再能赋给联合。TypeScript 4.6 起，对 const { status, data } = state 解构出的变量判断 status 也能收窄 data，但解构成 let 时不行。

联合不等于状态机

  • 连续搜索 A、B，A 的慢响应后到时，两个结果都是合法的 success，但界面显示了旧结果。需要在请求发起时记录 ID，或用 AbortController 取消旧请求。
  • 加载状态、编辑状态、在线状态是独立维度，不要强行塞进一个联合。
  • 外部 JSON 中的 status: 'success' 不会自动带上 data，要先校验。Error 对象经过 JSON 序列化会丢失，跨网络传错误码和消息。

常见追问

  • 判别字段必须叫 type 或 kind 吗？任何名字都行，只要每个分支是不同的字面量类型。
  • React 中怎样用？useReducer 的 state 和 action 都适合用可辨识联合，reducer 的 switch 自动收窄 action 的 payload。
