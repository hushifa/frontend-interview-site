React Native 与浏览器里的 React 有哪些共同点和差异？

React Native 写法和 React 一样，组件、状态和 Hooks 都能用，但画出来的是平台原生视图。要用 View、Text 等组件和 JS 样式对象，没有 DOM 和 CSS 层叠。

参考答案

简答

React Native 就是用写 React 的方式做手机 App。组件、props、state、Hooks、Context 这些概念完全一样，状态管理和数据请求的库大多也能直接用。

不同的地方在渲染。浏览器里的 React 渲染成 DOM，React Native 渲染成 iOS、Android 的原生视图。所以没有 div、span，也没有浏览器 API，要用 View、Text、Image 这些组件，文字必须放在 Text 里。

样式也不一样。它用 JS 对象写样式，没有选择器，也没有样式继承，Text 嵌套是例外。布局默认是 Flexbox，而且 flexDirection 默认是 column，也就是纵向排列。

另外，长列表要用 FlatList 按需渲染；导航、手势、动画通常要靠 React Navigation、Reanimated 这类社区库。

同一个组件两边怎么写

下面是同一张卡片，先看 Web 版：

JSX
// Web
function Card({ title, onPress }) {
  return (
    <button className="card" onClick={onPress}>
      <h2>{title}</h2>
    </button>
  );
}

再看 React Native 版：

JSX
// React Native
import { Pressable, Text, StyleSheet } from 'react-native';

function Card({ title, onPress }) {
  return (
    <Pressable style={styles.card} onPress={onPress} accessibilityRole="button">
      <Text style={styles.title}>{title}</Text>
    </Pressable>
  );
}

const styles = StyleSheet.create({
  card: { padding: 16, borderRadius: 8, backgroundColor: '#fff' },
  title: { fontSize: 18, fontWeight: '600' },
});

组件的逻辑没变，接收 title 和点击回调。可是标签换成了 Pressable 和 Text，事件从 onClick 变成 onPress，样式从 class 变成 JS 对象，按钮语义要用 accessibilityRole 自己声明。

两边具体差在哪里

React DOMReact Native
渲染目标浏览器 DOM原生视图（UIView、android.view.View）
基础元素div、span、imgView、Text、Image
样式CSS，选择器和层叠JS 对象，无选择器，无层叠
布局默认块级流式布局Flexbox，纵向排列
尺寸单位px、rem、% 等无单位数字（密度无关像素）和 %
事件onClick、DOM 事件onPress、手势响应系统
平台 APIWeb API原生模块
发布部署即更新应用商店审核；JS 部分可借助 OTA 方案更新

表里最后一行容易被忽略。网页部署完用户刷新就是新版本，App 却要过应用商店审核。所以有了 OTA 方案，意思是不发新包，只把 JS 部分从网络上更新下来。

长列表为什么要用 FlatList

JSX
<FlatList
  data={items}
  keyExtractor={(item) => item.id}
  renderItem={({ item }) => <Card title={item.title} />}
/>

FlatList 只渲染屏幕可见区域附近的条目。ScrollView 会把所有子元素一次性渲染出来。所以长列表如果用 ScrollView，内存占用会很大，应该改用 FlatList。

iOS 和 Android 不一样怎么办

同一个组件在两个平台上，外观或行为可能不同，比如阴影属性、键盘遮挡、返回按钮。这时可以用 Platform.OS 判断平台，或者用 .ios.js / .android.js 文件后缀分别写两份实现。

能和 Web 共享代码吗

业务逻辑、请求层、状态管理可以放进一个共享包，两端一起用。

React Native for Web 还能把 RN 组件渲染到浏览器里，适合同时做移动端和 Web 的产品。不过 Web 端的 SEO 和语义化要额外操心。

新架构的原理，比如 JSI、Fabric、TurboModules，见《React Native 原生桥接和新架构应该怎样理解？》。

常见追问

React Native 是 WebView 吗？

不是。界面是由原生视图组成的，JS 只负责描述界面长什么样和处理业务逻辑。

用 Expo 还是裸 React Native？

Expo 提供开箱即用的原生模块、构建和更新服务。React Native 官方文档也推荐用框架，比如 Expo，来开始新项目。
