React Native 与浏览器里的 React 有哪些共同点和差异？

React Native 复用 React 的组件、状态和 Hooks，但渲染目标是平台原生视图，用 View、Text 等组件和 JS 样式对象，没有 DOM 和 CSS 层叠。

参考答案

简答

  • 共同点：组件、props、state、Hooks、Context 等 React 概念完全一样，状态管理和数据请求库大多可以复用。
  • 差异在渲染层：React Native 把组件渲染成 iOS、Android 的原生视图，没有 DOM，不能用 div、span 和浏览器 API。
  • 基础组件是 View、Text、Image、ScrollView、TextInput 等，文字必须放在 Text 里。
  • 样式用 JS 对象，布局默认 Flexbox 且 flexDirection 默认是 column，没有选择器和样式继承（Text 嵌套除外）。
  • 列表用 FlatList 按需渲染，导航、手势、动画通常依赖 React Navigation、Reanimated 等社区库。

同一个组件的两种写法

JSX
// Web
function Card({ title, onPress }) {
  return (
    <button className="card" onClick={onPress}>
      <h2>{title}</h2>
    </button>
  );
}
JSX
// React Native
import { Pressable, Text, StyleSheet } from 'react-native';

function Card({ title, onPress }) {
  return (
    <Pressable style={styles.card} onPress={onPress} accessibilityRole="button">
      <Text style={styles.title}>{title}</Text>
    </Pressable>
  );
}

const styles = StyleSheet.create({
  card: { padding: 16, borderRadius: 8, backgroundColor: '#fff' },
  title: { fontSize: 18, fontWeight: '600' },
});

组件逻辑一样，标签、事件名、样式写法和无障碍属性都不同。

主要差异

React DOMReact Native
渲染目标浏览器 DOM原生视图（UIView、android.view.View）
基础元素div、span、imgView、Text、Image
样式CSS，选择器和层叠JS 对象，无选择器，无层叠
布局默认块级流式布局Flexbox，纵向排列
尺寸单位px、rem、% 等无单位数字（密度无关像素）和 %
事件onClick、DOM 事件onPress、手势响应系统
平台 APIWeb API原生模块
发布部署即更新应用商店审核；JS 部分可借助 OTA 方案更新

列表性能

JSX
<FlatList
  data={items}
  keyExtractor={(item) => item.id}
  renderItem={({ item }) => <Card title={item.title} />}
/>

FlatList 只渲染可见区域附近的条目，ScrollView 会一次渲染全部子元素，长列表用后者会占用大量内存。

平台差异

同一组件在 iOS 和 Android 上外观或行为可能不同，例如阴影属性、键盘遮挡、返回按钮。可以用 Platform.OS 或 .ios.js / .android.js 文件后缀分别实现。

和 Web 共享代码

  • 业务逻辑、请求层、状态管理可以放在共享包中供两端使用。
  • React Native for Web 可以把 RN 组件渲染到浏览器，适合同时面向移动和 Web 的产品，但 Web 端的 SEO 和语义化需要额外关注。
  • 新架构的原理（JSI、Fabric、TurboModules）见《React Native 原生桥接和新架构应该怎样理解？》。

常见追问

  • RN 是 WebView 吗？不是，界面由原生视图组成，JS 只负责描述界面和处理逻辑。
  • 用 Expo 还是裸 RN？Expo 提供开箱即用的原生模块、构建和更新服务，React Native 官方文档也推荐用框架（如 Expo）开始新项目。
