虚拟列表通过什么方式减少渲染成本？

虚拟列表用一个与完整列表等高的占位容器保留滚动范围，只渲染视口及上下少量缓冲区内的行，随滚动替换内容。它减少的是 DOM 数量和每次更新的渲染工作，不会减少已加载到内存的数据，也不会加快过滤计算。

参考答案

简答

  • 一万行全部渲染，创建 DOM、样式计算和布局的成本都随行数增长；虚拟化后同时存在的只有几十行。
  • 固定行高时，首个可见行 = Math.floor(scrollTop / rowHeight)，总高度 = 行数 × 行高。
  • overscan 在可见区上下多渲染几行，减少快速滚动时的空白，太大又会抵消收益。
  • 行的 key 和选中、编辑状态必须跟随数据 ID，不能用窗口内的下标。
  • 页面查找、打印、读屏器访问未挂载的行都会受影响，短列表不必虚拟化。

计算可见窗口

JavaScript
function getWindow({ count, rowHeight, scrollTop, viewportHeight, overscan = 2 }) {
  const totalHeight = count * rowHeight;
  const top = Math.min(Math.max(0, scrollTop), Math.max(0, totalHeight - viewportHeight));
  const first = Math.floor(top / rowHeight);
  const last = Math.ceil((top + viewportHeight) / rowHeight);
  const start = Math.max(0, first - overscan);
  const end = Math.min(count, last + overscan);
  return { start, end, offset: start * rowHeight, totalHeight };
}

console.log(getWindow({ count: 10000, rowHeight: 40, scrollTop: 800, viewportHeight: 400 }));
// { start: 18, end: 32, offset: 720, totalHeight: 400000 }

end 不包含在内，渲染 items.slice(start, end)。

结构

HTML
<div class="viewport" style="height: 400px; overflow: auto">
  <div style="height: 400000px; position: relative">
    <div style="transform: translateY(720px)">
      <!-- 第 18 到 31 行 -->
    </div>
  </div>
</div>

滚动事件里只更新 start、end，每帧最多计算一次（可以在 requestAnimationFrame 里处理）。行高必须真的等于 rowHeight，包括边框和外边距，否则越往下误差越大。行高不固定的情况见《动态高度的虚拟列表怎样处理测量、滚动锚点和焦点？》。

它不解决什么

问题对应方案
数据量太大，下载慢、占内存分页或按需加载
每次输入都全量过滤排序很慢优化算法、索引、Worker 或服务端查询
屏幕外内容的渲染成本content-visibility: auto 也能跳过渲染，但节点仍在 DOM 中

常见追问

  • 用现成的库还是自己写？生产环境优先用 TanStack Virtual、react-window 这类成熟库，它们处理了测量、滚动到指定项等细节。
  • 列表多大才需要？没有固定数字，以实测为准：DOM 节点数导致滚动掉帧或交互延迟明显时再引入。
