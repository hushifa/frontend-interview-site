什么是 XS-Leaks？前端如何减少跨站状态被推断？

XS-Leaks 不读跨站响应的内容，而是看浏览器能观察到的差异，比如加载成功还是失败、花了多久，从而猜出用户在目标网站的状态。防护靠 SameSite Cookie、COOP、frame-ancestors、CORP 和 Fetch Metadata 拦截跨站请求。

参考答案

简答

攻击者的网站向目标网站发请求，或者把目标页面嵌进来，然后观察结果有什么不同，以此推断用户在目标网站上的状态，比如有没有登录、搜索有没有结果。这叫 XS-Leaks，跨站泄露。

同源策略能阻止攻击者读响应内容，但阻止不了这些副作用被观察到。常见的信号有 <img>、<script> 的 onload 和 onerror、请求耗时、window.length 也就是 iframe 数量、弹窗有没有跳转、缓存是否命中。

这类攻击通常要求请求带上用户的 Cookie，所以 SameSite=Lax 或 Strict 是第一道防线。再往上，COOP 切断攻击者通过 window.open 拿到的窗口引用，frame-ancestors 阻止被嵌入，CORP 阻止资源被跨站加载，服务端还可以检查 Sec-Fetch-Site 拒绝跨站的非导航请求。

要注意，CORS 配得再严格也防不住它，因为 XS-Leaks 根本不读内容。

先看一个例子

下面是攻击者页面上的代码。它看不到头像长什么样，只关心图片加载成功还是失败：

JavaScript
// 攻击者页面
const img = new Image();
img.onload = () => report('已登录');   // 登录后返回头像
img.onerror = () => report('未登录');  // 未登录时 302 到登录页（HTML，不是图片）
img.src = 'https://target.example/api/me/avatar';

用户登录了，接口返回一张图片，触发 onload；没登录，接口跳到登录页，返回的是 HTML，不是图片，触发 onerror。攻击者一个字节的内容都没读到，可是从“成功还是失败”这一个信号里，就知道了用户的登录状态。

同样的思路能走得更远。如果搜索接口在“有结果”和“无结果”时返回不同的状态码，攻击者就可以一个字符一个字符地试，慢慢探测出私密数据。

怎么防

http
Set-Cookie: __Host-session=...; Secure; HttpOnly; SameSite=Lax; Path=/
Cross-Origin-Opener-Policy: same-origin
Content-Security-Policy: frame-ancestors 'self'
Cross-Origin-Resource-Policy: same-origin

为什么 SameSite 排在第一？因为上面例子里的请求如果不带 Cookie，接口对所有人都返回“未登录”，差异就消失了。COOP 让别的网站打开你的页面时拿不到窗口引用，window.length 这类探测就用不了。frame-ancestors 不让别人嵌入你的页面。CORP 不让别的网站把你的资源当 <img>、<script> 加载。

服务端还可以加一层资源隔离，下面是中间件示意：

JavaScript
function isolationPolicy(req, res, next) {
  const site = req.headers['sec-fetch-site'];
  if (!site || site === 'same-origin' || site === 'same-site' || site === 'none') return next();
  // 允许跨站的顶层页面导航，例如用户点击外部链接进入
  if (req.headers['sec-fetch-mode'] === 'navigate' && req.method === 'GET') return next();
  res.status(403).end();
}

Sec-Fetch-Site 这类请求头叫 Fetch Metadata，是浏览器自动加上的，告诉服务端这个请求从哪来。这段代码放行同源、同站和用户直接输入地址的请求，跨站的只放行顶层的 GET 导航，其余一律 403。

可是缺少这些请求头的旧浏览器会被直接放行，所以它只是增强措施，不能替代鉴权和 CSRF 防护。

让响应难以区分

另一个思路是让有差异的地方变得没差异。敏感接口在有权限和无权限时，返回相同的状态码和结构，避免“存在不存在”本身泄露信息。私有响应不要进入共享缓存，因为缓存命中与否也可能是一个信号。

那要不要把所有响应都填充到相同大小，或者人为加点延迟？不必。这样代价高，也很难完全消除差异。更有效的是从源头上阻止请求带上凭据、阻止页面被嵌入。

常见追问

XS-Leaks 和 CORS 有什么关系？

CORS 决定的是脚本能不能读取响应内容。XS-Leaks 根本不读内容，只看副作用，所以 CORS 配得再严格也防不住它。

跨源隔离（COOP 加 COEP）有什么帮助？

COOP 单独就能阻断窗口引用这类探测。和 COEP 一起用，还会限制跨源资源的嵌入。具体配置见《crossOriginIsolated 为 true 需要哪些条件？》。
