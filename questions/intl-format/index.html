为什么日期、金额和排序不应该手动拼接格式？

日期顺序、数字分隔符、货币符号位置和字母顺序都随地区变化。用 Intl.NumberFormat、DateTimeFormat、Collator 按 locale 格式化和排序；存储和接口传原始值，格式化后的字符串只用于显示。

参考答案

简答

  • 1234.5 在美国写作 1,234.5，在德国写作 1.234,5，在印度写作 1,234.5 但大数会写成 12,34,567。手动拼接只能照顾到一种习惯。
  • 金额格式化要同时给出 locale 和货币代码：locale 决定写法，货币决定符号和默认小数位。格式化不做汇率换算。
  • 日期格式由 locale 决定，时区要单独指定；中文 locale 不会自动使用中国时区。
  • 排序用 Intl.Collator，numeric: true 让 item2 排在 item10 前面。
  • 存储和接口传数值、货币代码和明确语义的时间，格式化后的字符串不要再解析回来。

金额（Node 22 实测）

JavaScript
new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' }).format(1234.5); // '$1,234.50'
new Intl.NumberFormat('de-DE', { style: 'currency', currency: 'EUR' }).format(1234.5); // '1.234,50 €'
new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' }).format(1234.5); // '¥1,234.50'
new Intl.NumberFormat('zh-CN', { notation: 'compact' }).format(12345678); // '1235万'
  • 欧元前面的空格是不换行空格，测试里不要用普通空格比较。
  • NumberFormat 只做显示舍入。金额计算用最小货币单位的整数或十进制库，避免浮点误差。

日期

JavaScript
const instant = new Date('2026-01-01T00:00:00Z');
new Intl.DateTimeFormat('en-GB', {
  dateStyle: 'short',
  timeStyle: 'short',
  timeZone: 'Asia/Shanghai',
}).format(instant); // '01/01/2026, 08:00'

new Intl.DateTimeFormat('zh-CN', { dateStyle: 'long', timeZone: 'UTC' }).format(instant); // '2026年1月1日'

SSR 时显式传入 timeZone。服务端默认 UTC、浏览器用本地时区，会导致水合时文本不一致。时区建模见"时间戳、时区和只有日期的业务值应该怎样区分？"。

排序

JavaScript
['item10', 'item2', 'item1'].sort(); // ['item1', 'item10', 'item2']
['item10', 'item2', 'item1'].sort(new Intl.Collator('en', { numeric: true }).compare);
// ['item1', 'item2', 'item10']

['a', 'B', 'c', 'Ä'].sort(new Intl.Collator('de').compare); // ['a', 'Ä', 'B', 'c']
['张三', '李四', '王五', '阿明'].sort(new Intl.Collator('zh-CN').compare);
// ['阿明', '李四', '王五', '张三']，按拼音

默认的 sort() 按 UTF-16 码元比较，大写字母排在所有小写字母前面。sensitivity: 'base' 时 a 和 Á 比较结果为 0，适合搜索匹配，不适合判断账号是否重复。

分段加样式

JavaScript
new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' }).formatToParts(1234.5);
// [{ type: 'currency', value: '$' }, { type: 'integer', value: '1' }, { type: 'group', value: ',' }, ...]

要单独给货币符号加样式时用 formatToParts()，不要用 split(',') 拆字符串。

大量格式化时复用同一个 formatter 实例，创建实例的开销比调用 format() 大。

常见追问

  • toLocaleString() 和 Intl.NumberFormat 有什么区别？ 结果相同，toLocaleString() 每次调用都要处理选项；循环中格式化大量数据时，复用 Intl.NumberFormat 实例更快。
  • 用户输入的本地化数字怎样解析？ Intl 没有通用的反向解析器。输入框尽量使用 inputmode="decimal" 并约定格式，或者用 formatToParts 取得当前 locale 的分隔符后自己解析。
