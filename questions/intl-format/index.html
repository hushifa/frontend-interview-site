为什么日期、金额和排序不应该手动拼接格式？

不同语言和地区的日期顺序、数字分隔、货币展示和文字排序规则不同。Intl.DateTimeFormat、NumberFormat、Collator 等 API 根据语言环境与选项提供本地化处理。

参考答案

简答

  • 日期顺序、数字分隔符、货币和排序规则都随语言和地区变化。
  • 金额格式化要同时指定货币代码和显示地区。
  • 日期的显示格式和时区要分别控制；排序使用 Intl.Collator。
  • 格式化后的字符串只用于展示，接口和存储传数值和明确语义的数据。

同一个数值 1234.5，在不同地区可能写成 1,234.5 或 1.234,5；同一个日期也可能采用月在前、日在前或不同历法。手动拼接容易把开发者所在地区的习惯误当成统一规则。

Intl 把这些地区规则交给运行时的国际化数据处理。应用仍要提供正确的数据语义：语言地区、货币代码、时区和希望显示的精度，不是调用一次 toLocaleString 就完成了所有国际化。

金额要同时指定货币和显示地区

JavaScript
const amount = 1234.5;
const dollars = new Intl.NumberFormat('en-US', {
  style: 'currency',
  currency: 'USD',
});
const euros = new Intl.NumberFormat('de-DE', {
  style: 'currency',
  currency: 'EUR',
});

console.log(dollars.format(amount)); // $1,234.50
console.log(euros.format(amount)); // 1.234,50 €

locale 决定数字分隔、符号位置等展示习惯，currency 决定货币身份及相关默认精度。第二行没有把美元换算成欧元，只是把同一个数值按欧元格式展示；汇率换算必须另行处理。

也不能给所有金额统一保留两位小数。不同货币有不同常用小数位要求，业务舍入策略还可能更严格。NumberFormat 负责展示舍入，不解决浮点算术精度；资金计算应采用明确的最小货币单位、十进制定点或合适的精确计算方案。

示例中的欧元前可能是不可换行空格。不同 ICU/CLDR 版本也可能调整格式细节，不要用普通空格猜测所有输出。

日期格式与时区分别控制

JavaScript
const instant = new Date('2026-01-01T00:00:00Z');
const format = new Intl.DateTimeFormat('en-GB', {
  timeZone: 'Asia/Shanghai',
  year: 'numeric',
  month: '2-digit',
  day: '2-digit',
  hour: '2-digit',
  minute: '2-digit',
  hourCycle: 'h23',
});

console.log(format.format(instant)); // 01/01/2026, 08:00

en-GB 控制显示惯例，Asia/Shanghai 控制这个瞬间对应的当地时间。选了中文 locale 不代表自动切换到中国时区，选了英文也不代表使用 UTC。

服务端渲染时尤其要显式传入约定设置。服务端用 UTC，浏览器用用户本地时区，可能导致首次 HTML 与客户端内容不同。可以统一首屏设置，或明确将用户本地格式化放到客户端阶段，不能依赖部署机器的默认配置。

排序也不是比较编码值就够了

JavaScript
const labels = ['item10', 'item2', 'item1'];
const collator = new Intl.Collator('en', { numeric: true });
console.log([...labels].sort(collator.compare));
// ['item1', 'item2', 'item10']

numeric 让数字片段按自然数字顺序比较。其他语言中的重音、大小写和字母顺序也可能与默认 sort 不同，可根据场景选择 locale、sensitivity 等选项。

compare 的结果只保证负数、零或正数，不保证一定为 -1 或 1。适合展示的忽略重音比较，也不应直接用于账号唯一性或权限标识判断；“显示排序相近”不等于业务上是同一个人。

格式化字符串不要反过来当数据协议

1,234 在不同规则下可能表达不同数值，日期字符串同样存在歧义。存储和接口应传数值、货币代码以及明确语义的日期时间数据，展示时再格式化。Intl 没有提供通用的本地化数字反向解析器。

如果需要单独给货币符号或日期部分加样式，使用 formatToParts 获取带类型的片段，不要靠 split(',') 或固定下标拆字符串。循环展示大量数据时，可以复用同一组选项的 formatter；切换 locale、时区或精度时，再更新对应实例。
