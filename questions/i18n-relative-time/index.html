Intl.RelativeTimeFormat 怎样正确显示相对时间？

Intl.RelativeTimeFormat 只负责把“数值 + 单位”格式化成“5 分钟前”“明天”这样的文字，时间差和单位选择要应用自己计算。numeric auto 输出“昨天”等自然说法；排序和刷新要基于时间戳，SSR 要固定基准时间。

参考答案

简答

评论列表里显示“5分钟前”“昨天”，用的就是 Intl.RelativeTimeFormat。可它只管格式化：format(-5, 'minute') 在中文下输出“5分钟前”，至于两个时间到底差了多少，它不会算。

所以应用要先自己算出时间差，再决定用秒、分、小时还是天，以及怎么取整，最后才交给它显示。

想说得更自然，就加 numeric: 'auto'，-1 天、0 天、1 天会变成“昨天”“今天”“明天”。默认的 'always' 一律用数字。

要注意两点。列表排序、刷新判断都要基于原始时间戳，不要用显示出来的字符串。SSR 时服务端和客户端的“现在”不一样，相对时间会对不上，常见做法是服务端先输出绝对时间，客户端水合后再替换。

先看输出

下面是几种常见写法的结果，都是 Node 22 实测的。

JavaScript
const zh = new Intl.RelativeTimeFormat('zh-CN');
zh.format(-5, 'minute'); // '5分钟前'
zh.format(-3, 'hour'); // '3小时前'

const zhAuto = new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' });
zhAuto.format(-1, 'day'); // '昨天'
zhAuto.format(0, 'day'); // '今天'

const en = new Intl.RelativeTimeFormat('en');
en.format(-1, 'day'); // '1 day ago'
new Intl.RelativeTimeFormat('en', { numeric: 'auto' }).format(2, 'day'); // 'in 2 days'
new Intl.RelativeTimeFormat('en', { style: 'short' }).format(-3, 'month'); // '3 mo. ago'

负数表示过去，正数表示将来。numeric: 'auto' 只在有现成说法时才替换，所以 2 天后没有专门的词，仍然是“in 2 days”。style: 'short' 会把单位缩写成“mo.”。

时间差和单位要自己算

下面这个函数先算出相差多少秒，再从大到小挑一个合适的单位。

JavaScript
const UNITS = [
  ['year', 365 * 24 * 3600],
  ['month', 30 * 24 * 3600],
  ['day', 24 * 3600],
  ['hour', 3600],
  ['minute', 60],
  ['second', 1],
];

function formatRelative(timestamp, now, locale) {
  const seconds = Math.round((timestamp - now) / 1000);
  const rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' });
  for (const [unit, size] of UNITS) {
    if (Math.abs(seconds) >= size || unit === 'second') {
      return rtf.format(Math.round(seconds / size), unit);
    }
  }
}

这里的“月”和“年”用固定秒数近似，适合“大约多久以前”这种展示。

可是“昨天”如果要严格按日历算，这个办法就不够了。比如昨晚 23 点到今早 1 点只差 2 小时，按秒数算是“2小时前”，按日历却应该是“昨天”。这种情况要先按用户时区比较日期，再算相差几天。

显示、刷新和 SSR

相对时间不够精确，所以旁边最好附上绝对时间，例如 <time datetime="2026-10-28T09:00:00Z" title="2026年10月28日 17:00">。

刷新频率按时间差定：一分钟以内每 10 秒刷新一次，一小时以内每分钟刷新一次，更早的不必自动刷新。这些刷新不需要读屏器每次都播报，所以不要把相对时间放进 live region。

列表排序、是否需要刷新，都用原始时间戳判断。显示出来的字符串随语言变化，不能再解析回去。

SSR 时还有一个坑。服务端渲染时的“现在”和客户端水合时的“现在”不同，“3分钟前”可能变成“4分钟前”，文字对不上就会水合不一致。常见做法是服务端只输出绝对时间，客户端水合后再换成相对时间。

和 Temporal 是什么关系

Temporal 已进入 TC39 第 4 阶段。它负责带时区和日历的日期计算，例如按日历日相减；算出来的结果，仍然交给 Intl.RelativeTimeFormat 显示。Node 22 还没有 Temporal，用之前要做能力检测，或者引入 polyfill。

常见追问

想单独高亮数字部分怎么办？

用 formatToParts()。它会把结果拆成几段，数字那一段的 type 是 'integer'，其余是普通文字，可以分别加样式。

为什么不用 moment 的 fromNow()？

用现成的库也可以。只是 Intl 是运行时内置的，不增加包体积，语言数据也由运行时维护，不用自己跟着更新。
