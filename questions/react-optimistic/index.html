useOptimistic 的临时状态怎样与真实结果收敛？

useOptimistic 让你在请求还没返回时，先把预期结果显示出来。请求结束后临时状态自动消失，界面回到真实状态，所以成功时要更新真实状态，失败时只需提示错误。

参考答案

简答

发消息、点赞这种操作，如果等服务器返回才显示，用户会觉得卡。乐观更新的意思是先假定会成功，立刻把结果显示出来。useOptimistic(state, updateFn) 就是做这个的，它返回一个用来显示的 optimisticState 和一个 addOptimistic 函数。

调用 addOptimistic(value) 时，React 用 updateFn(currentState, value) 算出临时状态，叠在真实的 state 上显示。这个临时状态只在当前这次 Action 进行期间存在。Action 一结束，React 就把它丢掉，重新显示传进来的 state。

所以收敛的方式很简单：成功时把真实结果写进 state，临时状态消失后正好被真实数据替换；失败时什么都不用回滚，临时状态自己就没了，只需提示错误。

要注意，addOptimistic 必须在 Action 或 startTransition 里调用。它适合成功率高、失败可以撤回的操作，支付、扣库存这类还是应该等服务端确认。

先看一个发消息的例子

下面的聊天框点了发送，消息会立刻以半透明显示，等服务器返回后变成正常的消息。

JSX
import { useOptimistic, useState, startTransition } from 'react';

export default function Chat({ initialMessages }) {
  const [messages, setMessages] = useState(initialMessages);
  const [error, setError] = useState('');
  const [optimisticMessages, addOptimistic] = useOptimistic(
    messages,
    (current, text) => [...current, { id: `temp-${Date.now()}`, text, sending: true }],
  );

  function send(formData) {
    const text = String(formData.get('text'));
    setError('');
    startTransition(async () => {
      addOptimistic(text);
      try {
        const saved = await postMessage(text); // 返回 { id, text }
        startTransition(() => setMessages((list) => [...list, saved]));
      } catch {
        setError('发送失败，请重试');
      }
    });
  }

  return (
    <>
      <ul>
        {optimisticMessages.map((m) => (
          <li key={m.id} style={{ opacity: m.sending ? 0.5 : 1 }}>{m.text}</li>
        ))}
      </ul>
      {error && <p role="alert">{error}</p>}
      <form action={send}>
        <input name="text" required />
        <button>发送</button>
      </form>
    </>
  );
}

页面上显示的是 optimisticMessages，不是 messages。点发送后，addOptimistic(text) 让列表末尾多出一条 sending: true 的临时消息。

成功的话，setMessages 把服务器返回的消息写进真实状态。Action 结束时临时消息被丢掉，列表里留下的是真实那条，看起来就是“半透明变成了不透明”。

失败的话，没有人改 messages。Action 结束，临时消息消失，列表回到发送前的样子，再显示错误提示。

注意 await 之后的 setMessages 又包了一层 startTransition。这是目前的要求：Action 里 await 之后的状态更新，要再包一次才会算在这个 Transition 里。

为什么成功了也必须更新真实状态

很多人第一次用会漏掉 setMessages，结果消息先出现，过一会儿又消失了。

原因是临时状态只活到 Action 结束。它从来没有写进 messages，Action 一结束，React 显示的就是没变过的 messages。所以 useOptimistic 只负责“等待期间显示什么”，真正的数据还得你自己存。

还有哪些细节要注意

临时消息的 id 是 temp-...，真实消息的 id 是服务器给的，两者不同。用它当 key 时，成功后这一行会被重新挂载。如果这一行有自己的状态要保留，可以由客户端生成 ID，一起提交给服务器使用。

几个请求同时进行时，每个 addOptimistic 都叠加在最新的真实状态上，不会互相覆盖。

乐观更新只是一种显示策略。服务端照样要做校验、幂等和冲突处理。

常见追问

跟自己 setState 再手动回滚比，好在哪里？

不用自己记旧值、写回滚逻辑。手动回滚还可能把这期间别的更新也一起覆盖掉，useOptimistic 没有这个问题，因为临时状态始终是叠在真实状态上的。

能在表单之外用吗？

可以，只要在 startTransition 里调用 addOptimistic 就行。
