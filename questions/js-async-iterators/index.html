异步迭代器和 for await...of 适合处理什么数据？

数据一项一项陆续到达时，比如分页接口、流式响应，就用 for await...of 一项一项等着处理。它是串行的，提前 break 会等生产者清理完再继续。

参考答案

简答

有些数据不是一次拿全的，而是“下一项过一会儿才到”，比如分页接口要一页一页请求，流式响应一块一块到达。处理这类数据，就用异步迭代器加 for await...of。

异步迭代器和普通迭代器很像，区别是它的 next() 返回的是 Promise，等 Promise 完成才知道下一项是什么。最简单的写法是 async function*，里面既能 await 又能 yield。浏览器的 ReadableStream 和 Node.js 的 Readable 流本身就支持 for await。

for await...of 每次等一项处理完，才去要下一项，所以它是串行的，不会并发。

提前 break 时，它会调用并等待迭代器的 return()，异步生成器就能在 finally 里做清理。还要注意，生产者如果自己偷偷预取、无限缓冲，或者消费者把每一项都存进数组，内存照样会涨。

先看一个分页的例子

下面的生成器先给出第一页，等一下再给出第二页。注意两行输出之间是要等待的。

JavaScript
async function* pages() {
  yield [1, 2];
  await Promise.resolve();
  yield [3];
}

async function readPages() {
  for await (const page of pages()) {
    console.log(page.join(','));
  }
}

readPages();
// 输出：1,2
// 随后输出：3

for await 每一轮先等 next() 返回的 Promise 完成，拿到一页再执行循环体。生成器走到 await 时暂停，循环就在那里等着，等它 yield 出第二页，才打印 3。

真实场景里，每一页要请求接口，下一页的地址在上一页的响应里：

JavaScript
async function* fetchAll(url, signal) {
  while (url) {
    const response = await fetch(url, { signal });
    const { items, next } = await response.json();
    yield* items;
    url = next;
  }
}

调用方只管 for await (const item of fetchAll(url))，不用关心分页。而且生成器只有在被要下一项时才继续执行，所以消费者 break 以后，就不会再请求下一页。

怎样一块一块读取流

JavaScript
async function readText(response) {
  const decoder = new TextDecoder();
  let text = '';
  for await (const chunk of response.body) {
    text += decoder.decode(chunk, { stream: true });
  }
  return text + decoder.decode();
}

response.body 是 ReadableStream，每次循环拿到一块字节。这里有个容易忽略的地方：网络分块不会按行切，也不会按字符切。一个汉字在 UTF-8 里占 3 个字节，可能一半在这块、一半在下一块。所以 decode 要带 { stream: true }，让解码器把不完整的字节先留着，等下一块来了拼起来再解。最后不带参数调用一次 decode()，把剩下的输出来。

用 for await 读 ReadableStream 时，提前 break 默认会取消整个流。如果只想停止读取、不想取消流，可以改成遍历 stream.values({ preventCancel: true })，这样退出时只释放读取锁。

为什么说它是串行的

for await 一定要等这一项的循环体执行完，才会去要下一项。要是每一项都要发请求，又想同时处理几项，不能在循环体里启动任务却不等它，那样任务失败时，错误不会被循环捕获。正确的做法是在循环里把任务交给一个限制并发数量的并发池。

它能防止内存涨爆吗

数据生产得比消费快时，要有办法让生产方慢下来，这叫背压。

异步生成器天然带这个效果。消费者调用 next()，生成器才往下跑，到 yield 又停下，所以不会提前生产一大堆。可是如果生产者内部自己预取数据，或者用一个没有上限的队列缓冲，内存还是会涨。消费者把每一项都 push 进数组，也等于又把全部数据攒了起来。

怎样中途取消

break 只能写在循环体里，循环体执行的时候才能退出。如果 next() 一直卡在一个网络请求上，循环体根本不会执行，break 也就没机会发生。这时要用 AbortSignal 去取消底层请求，就像上面 fetchAll 接收 signal 那样。各种关闭方式的区别见《JavaScript 迭代器关闭和 return 方法有什么作用？》。

常见追问

Array.fromAsync(iterable) 做什么？

它把异步可迭代对象收集成一个数组，是 ES2026 的方法。它也是一项一项等待的，跟 for await 一样不会并发。

同步可迭代对象能用 for await 吗？

能，每一项都会被 await 一下，所以可以写 for await (const x of [promiseA, promiseB])。但要小心，这些 Promise 早就都启动了，如果前面一项还在等，后面某一项先失败了，它可能会先被报成未处理的拒绝。
