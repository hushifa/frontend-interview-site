什么是 Web 缓存投毒？如何避免把用户数据缓存给别人？

缓存投毒是让 CDN 等共享缓存存下一份被攻击者影响的响应，再分发给其他用户；缓存欺骗则是诱导共享缓存存下某个用户的私有响应。根源都是影响响应的输入没有进入缓存键，或私有响应缺少 private、no-store。

参考答案

简答

  • 缓存键通常只有方法、主机和路径（可能加部分查询参数）。源站如果根据不在键里的输入（如 X-Forwarded-Host）生成内容，攻击者就能让缓存存下恶意版本。
  • 缓存欺骗：攻击者诱导用户访问 /account/profile.css，路由把它当成 /account/profile 返回个人数据，CDN 按 .css 后缀缓存，攻击者再去读取。
  • 私有响应一律 Cache-Control: private, no-store 或 private，CDN 规则要尊重源站头部。
  • Vary 只用来声明哪些请求头会改变响应，它不是权限控制；Vary: Cookie 会让缓存几乎失效。
  • CDN 和源站对 URL 的规范化（大小写、尾斜杠、编码、路径参数）要一致。

投毒示例

源站用请求头拼出资源地址：

JavaScript
// 有问题的写法
const host = req.headers['x-forwarded-host'] ?? req.headers.host;
res.send(`<script src="https://${host}/app.js"></script>`);

攻击者发送带 X-Forwarded-Host: evil.example 的请求，CDN 按 / 缓存了这份响应，之后所有访问首页的用户都会加载攻击者的脚本。

修复：

  • 资源地址用配置里的固定域名，不读请求头。
  • 必须使用某个请求头时，把它加入缓存键或 Vary，并校验取值白名单。
  • 在 CDN 边缘剥掉不需要的请求头。

欺骗示例与防护

text
https://app.example/account/settings/avatar.png

如果应用路由忽略多余路径段，返回的是账户设置页；CDN 看到 .png 按静态资源缓存。

  • 应用对不存在的路径返回 404，不做宽松匹配。
  • 个性化响应设置 Cache-Control: private, no-store。
  • CDN 按源站的 Cache-Control 决定是否缓存，而不是按扩展名强制缓存。
  • 对带 Authorization 或会话 Cookie 的请求默认不缓存。

其他容易被缓存的内容

  • 错误页和重定向：一次 500 或指向攻击者域名的 302 被缓存后影响所有人。
  • 带个人信息的 JSON 接口。
  • 依赖 Accept-Language、设备类型的页面，缺少 Vary 时会串内容。

验证和应急

  • 用 Age、Cache-Status 或厂商缓存头确认响应是否来自共享缓存，见《Cache-Status 响应头能帮助诊断哪些缓存问题？》。
  • 测试时给 URL 加随机参数（cache buster），避免污染真实缓存。
  • 发现泄露后先修复源站头部，再清除 CDN 缓存，已缓存的副本不会因源站修改自动消失。

常见追问

  • 和普通的缓存配置错误有什么区别？配置错误是被动串内容，投毒是攻击者主动构造请求让缓存存下恶意响应。
  • 前端能做什么？不要让页面输出依赖未验证的请求头或 URL 片段，接口按约定返回正确的缓存头。
