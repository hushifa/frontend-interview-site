AI 对话前端为什么不能直接内置服务商 API 密钥？

浏览器收到的代码、构建变量和网络请求都能被用户检查。长期 API 密钥、模型权限、额度和工具授权必须放在受控服务端，纯静态前端只能负责交互。

参考答案

浏览器不是秘密保存环境

页面必须把 JavaScript 发送给用户，用户可以查看构建产物、修改运行时变量、复制网络请求和重放接口。因此把长期服务商密钥放进 VITE_*、混淆字符串、关闭 Source Map 或私有源码仓库，都不会改变它最终出现在用户机器上的事实。

一旦浏览器用这个密钥访问模型服务，Authorization 头和请求参数也能被检查。CORS 只限制浏览器读取跨源响应，不能阻止用户把已经拿到的密钥放进自己的服务器或命令行中使用。

常见的职责分层

text
浏览器：收集输入、展示流式输出、停止和重试、显示审批内容
受控服务：认证用户、校验租户和额度、保存长期密钥、选择模型、执行工具
模型服务：处理请求并返回输出

浏览器调用项目自己的受控 API，服务端再使用长期凭据访问模型。受控服务可以是独立后端、函数或现有平台，不一定要使用某个全栈框架，但必须在服务器侧执行真正的授权和成本控制。

只加一个代理还不够。没有登录校验、速率限制、输入大小限制和输出预算的代理，会变成任何人都能滥用的免费模型接口。模型名称、工具名、目标 URL 和系统提示也不能完全由客户端决定。

纯静态网站有哪些边界

纯静态站点不能在访问时运行自己的服务器代码，但仍可以调用另行部署的受控 API，也可以使用适合设备的本地模型。静态部署限制的是站点自身的服务端能力，不等于 AI 功能只能把长期密钥写在前端。

如果产品允许用户输入自己的服务商凭据，要明确说明它可能被 XSS、浏览器扩展、网络日志或误操作暴露，并尽量不持久化。某些服务提供短期、受限的客户端凭据，可以由受控端按用户权限签发，限制有效期、用途和资源；这和把普通长期密钥改个变量名完全不同。

工具、检索和输出仍然需要服务端边界

模型返回的工具名和参数只是拟议动作，不能直接转换成数据库、文件系统或网络调用。服务端要重新检查用户身份、资源权限、参数白名单、资源版本和审批记录，审批还要绑定具体调用、参数摘要和有效期。

检索文本和模型输出也不能直接作为 HTML、SQL、脚本或文件路径使用。服务端保存了密钥，不代表已经解决提示词注入、输出注入和越权读取；这些仍需要独立的输入、工具和渲染防护。

流式错误、日志和缓存不能泄露数据

前端可以展示用户能理解的“请求被拒绝”“额度不足”或“结果待核对”，同时携带内部错误 ID。不要原样返回服务端堆栈、认证头、完整系统提示和敏感附件。

服务端日志也要按必要范围记录，不能为了排查流式问题把全部用户输入和令牌打印到第三方平台。会话、缓存、检索结果和工具输出按用户与租户隔离，并设置保留和删除策略。

判断一个规则是否必须放在服务端，可以问：如果用户修改浏览器代码或直接构造请求，这条规则还成立吗？凡是涉及费用、权限、长期秘密和不可逆副作用的限制，都不能只依赖前端按钮和提示。
