AI 对话前端为什么不能直接内置服务商 API 密钥？

浏览器收到的代码、构建变量和网络请求都能被用户查看和复用。长期 API 密钥、额度和工具授权必须放在受控服务端；纯静态站点可以调用另行部署的接口，或使用服务端签发的短期受限凭据。

参考答案

简答

  • 写进前端的密钥最终都会到达用户浏览器：VITE_* 环境变量、代码混淆、关掉 Source Map 都改变不了这一点。
  • 拿到密钥的人可以在自己的服务器上直接调用模型 API，CORS 拦不住。
  • 正确做法是浏览器调用自己的服务端接口，服务端认证用户、检查额度，再用密钥请求模型服务。
  • 只做转发的代理同样会被滥用，服务端还要做登录校验、限流、输入大小限制，并自己决定模型和工具。
  • 纯静态站点可以调用另行部署的函数或后端；实时语音等场景可以由服务端签发短期、限定用途的客户端令牌。

职责划分

text
浏览器：收集输入、展示流式输出、停止和重试、展示工具确认
自己的服务端：认证用户、检查租户和额度、保存密钥、选择模型、执行工具
模型服务：处理请求、返回输出

模型名、系统提示、可用工具和目标 URL 由服务端决定，不接受客户端随意指定。

判断一条规则放在哪里

问一句：如果用户改了前端代码或直接用 curl 发请求，这条规则还成立吗？费用、权限、长期密钥和不可逆操作的限制，都必须在服务端执行。

前端可以做的：

  • 提前提示输入过长、额度快用完。
  • 展示用户能理解的错误（"额度不足""请求被拒绝"），附带内部错误 ID，不展示服务端堆栈或请求头。

用户自带密钥

有的产品允许用户填写自己的服务商密钥。这时要告诉用户密钥可能因 XSS、浏览器扩展或共用设备而泄露，尽量只放在内存里，不写入 localStorage。

常见追问

  • 服务端拿了密钥，提示词注入的问题就解决了吗？ 没有。密钥只解决身份和计费问题，模型输出和工具调用仍要单独校验，见《提示词注入与普通 XSS 有什么区别？》。
  • 短期令牌和长期密钥有什么不同？ 短期令牌由服务端按用户权限签发，有效期短、用途受限，泄露后影响有限；长期密钥能调用账户下的全部能力。
