前端页面如何支持从右到左的语言？

阿拉伯语、希伯来语页面用 dir="rtl" 声明方向、lang 声明语言，布局用 CSS 逻辑属性，方向不确定的文本用 bdi 或 dir="auto" 隔离；图标按语义决定是否镜像，还要检查键盘顺序和挂到 body 的浮层。

参考答案

简答

阿拉伯语、希伯来语是从右往左写的，简称 RTL。支持它，第一步是在 <html> 上同时写 lang="ar" 和 dir="rtl"。lang 说明是什么语言，dir 说明文字往哪个方向排，写了一个不会自动推出另一个。

布局不要写死左右，改用逻辑属性，比如 margin-inline-start、padding-inline、inset-inline-end、text-align: start。它们说的是“开始那一边”“结束那一边”，方向一换自动跟着换，不用再写一套样式。

用户名、产品名、数字这类方向不确定的内容，用 <bdi> 或 dir="auto" 隔离开，不要手动反转字符串，代码块保持 dir="ltr"。图标要按含义判断：表示前进、返回的箭头要镜像，品牌标志、播放按钮、数字不镜像，不要整页 scaleX(-1)。

还要注意，Flex 和 Grid 会随方向自动调整顺序，如果再加 row-reverse，顺序又被反了回去。

怎样声明方向

在根元素上写语言和方向。

HTML
<html lang="ar" dir="rtl">

用户切换语言时，这两个属性要一起更新。通过 portal 挂到 body 下的弹窗和提示框最容易漏掉，要确认它们也继承了正确的方向。

用逻辑属性写布局

下面这张卡片没有出现 left 和 right。

CSS
.card {
  padding-inline: 1rem;
  border-inline-start: 3px solid currentColor;
  text-align: start;
}

.card__action {
  margin-inline-start: auto; /* LTR 下推到右边，RTL 下推到左边 */
}

.close-button {
  position: absolute;
  inset-inline-end: 0.75rem;
  inset-block-start: 0.75rem;
}

inline-start 到底是哪边？在水平书写的页面里，从左往右写时它是左边，从右往左写时它是右边。所以同一份样式，换个 dir 就自动镜像了。

确实要固定在物理位置的装饰，比如一张始终在左上角的背景图，仍然可以用 left、right。

混合方向的文本怎么处理

阿拉伯文里夹着英文用户名时，排版很容易乱。

HTML
<p>
  المستخدم <bdi>Alice_42</bdi> علّق
</p>
<pre dir="ltr"><code>const total = price * count;</code></pre>

问题出在用户名里的数字和下划线。浏览器排双向文本时，会根据周围的文字猜它们的方向，结果可能把用户名和旁边的阿拉伯文排错位置。<bdi> 让里面的文本自己单独判断方向，不影响外面。代码块则直接用 dir="ltr" 固定成从左往右。

这里还有一个安全问题。双向控制字符（比如 U+202E）能让文本显示的顺序和实际顺序不同，被人用来伪装文件名或代码。<bdi> 只解决排版，管不了这个。所以显示用户提供的标识符时，要检测并过滤这些控制字符。

交互也要检查

视觉上从右往左排列以后，Tab 顺序也应该从右往左。可是用 order 或 row-reverse 调出来的位置，不会改变 Tab 顺序，所以优先保持 DOM 顺序本身合理。

滑块、标签页、菜单的左右方向键，在 RTL 下语义也是反的，要按各组件的交互模式处理。

测试时用真实的阿拉伯文和希伯来文，再混入数字、英文和长文本，比只看占位文字可靠得多。

常见追问

direction: rtl 和 dir="rtl" 有什么区别？

dir 是 HTML 语义，会影响双向文本算法和无障碍信息；CSS 的 direction 只是样式。所以优先用 dir。

怎样根据语言自动得到方向？

用 Intl.Locale 的 getTextInfo()，它会返回这种语言的书写方向，详见《Intl.Locale 解决什么问题？语言标签应该怎样建模？》。
