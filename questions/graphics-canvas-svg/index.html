Canvas 和 SVG 怎样选择？

SVG 把图形保留为 DOM 元素，可以用 CSS 和事件直接操作；Canvas 2D 把绘制命令变成像素，图形对象和命中检测由应用管理。对象数量、更新频率、交互、清晰度和无障碍共同决定选型。

参考答案

简答

  • SVG 是保留模式：每个圆、路径都是 DOM 元素，可以改属性、加 CSS、监听事件，浏览器负责重绘和命中。
  • Canvas 2D 是即时模式：画完只剩像素，要拖动某个图形，应用自己保存坐标、计算命中并重绘。
  • 图标、流程图、几百到几千个元素的交互图表适合 SVG；上万个点、粒子动画、绘图板、像素处理适合 Canvas。
  • Canvas 要按 devicePixelRatio 设置内部尺寸才清晰，宽高各翻倍像素数就变成四倍，内存随之增加。
  • 两者都不会自动无障碍：SVG 要加标题和角色，Canvas 要另外提供文字或 HTML 替代。

同一个圆

HTML
<svg viewBox="0 0 200 100" role="img" aria-labelledby="t">
  <title id="t">蓝色圆形</title>
  <circle cx="50" cy="50" r="20" fill="royalblue" />
</svg>
JavaScript
const ctx = document.querySelector('canvas').getContext('2d');
ctx.fillStyle = 'royalblue';
ctx.beginPath();
ctx.arc(50, 50, 20, 0, Math.PI * 2);
ctx.fill();
// 页面里只有一个 canvas 元素，querySelector 找不到这个圆

对比

SVGCanvas 2D
图形对象DOM 元素应用自己维护
交互直接绑定事件自己做命中检测
缩放矢量，任意放大都清晰位图，需要按缩放重绘
大量对象DOM 和样式成本高只受绘制成本影响
像素访问不支持getImageData
导出序列化 XMLtoBlob、toDataURL

两者之间没有固定的对象数量分界，用真实数据在目标设备上测试。

Canvas 清晰度

JavaScript
function setupCanvas(canvas, cssWidth, cssHeight) {
  const dpr = window.devicePixelRatio || 1;
  canvas.style.width = `${cssWidth}px`;
  canvas.style.height = `${cssHeight}px`;
  canvas.width = Math.round(cssWidth * dpr);
  canvas.height = Math.round(cssHeight * dpr);
  const ctx = canvas.getContext('2d');
  ctx.scale(dpr, dpr); // 之后按 CSS 像素坐标绘制
  return ctx;
}

混合方案

复杂编辑器常用 Canvas 绘制画布内容，用 HTML 做工具栏、输入框和属性面板，用 SVG 画选择框和控制点。图表可以用 Canvas 绘制大量数据点，再提供一个 HTML 数据表作为无障碍替代，见《前端图表如何同时满足无障碍和高性能？》。

安全

  • 用户上传的 SVG 可以包含脚本和外部引用，不要直接内联插入页面，用 <img> 引用或先净化。
  • Canvas 绘制了没有 CORS 授权的跨源图片后会被"污染"，getImageData 和 toBlob 会抛出 SecurityError。

常见追问

  • Canvas 卡了怎么办？ 分层（静态背景一层、动态内容一层）、只重绘变化区域、把绘制移到 Worker 里的 OffscreenCanvas。
  • WebGL 也是画在 canvas 上，它属于哪一边？ 它是 canvas 的另一种上下文，绘制模型和 Canvas 2D 完全不同，适合更大规模的绘制，见《什么场景值得用 WebGL？GPU 加速有哪些成本？》。
