浏览器从 HTML 到页面显示，经历哪些主要步骤？

浏览器先把 HTML 和 CSS 解析成 DOM 和 CSSOM，合成渲染树，再算布局、绘制、合成到屏幕上。CSS 会阻塞渲染，同步脚本会阻塞 HTML 解析。

参考答案

简答

浏览器拿到 HTML 以后，先把它解析成一棵节点树，叫 DOM；把 CSS 解析成样式规则，叫 CSSOM。两者合起来得到渲染树，然后算每个元素的位置和大小，这叫布局；再把文字、颜色画出来，这叫绘制；最后把各个图层叠在一起显示到屏幕上，这叫合成。

这个过程会被阻塞。CSS 会阻塞渲染，因为没有样式就不知道页面长什么样；没有 async、defer 或 type="module" 的同步脚本会阻塞 HTML 解析。

为了少等，浏览器有个预加载扫描器，解析被阻塞时，它继续往后扫，提前请求后面的资源。

页面显示出来以后，改了布局相关的属性要重新布局；只改 transform、opacity，通常只需要合成，成本最低。

解析：为什么脚本会卡住页面

HTML 解析器是边下载边解析的，DOM 一点点长出来。遇到外链样式表，浏览器去下载，再解析成 CSSOM。DOM 可以增量构建，CSSOM 却要等样式表完整解析完，因为后面的规则可能覆盖前面的规则。

遇到同步的 <script>，解析器就停下来，等脚本下载并执行完再继续。为什么要停？因为脚本可能用 document.write 改 HTML，也可能读样式。又因为脚本可能读样式，它前面的样式表也得先加载完。所以就有了这句话：“CSS 阻塞脚本执行，脚本阻塞 HTML 解析”。

解析停下来的时候，预加载扫描器（preload scanner）会继续往后扫标记，提前请求图片、脚本和样式。可是用 JavaScript 动态插入的资源它看不到。所以关键资源应该直接写在 HTML 里，或者用 <link rel="preload"> 声明。

渲染树之后还有哪几步

渲染树只包含要显示的节点。display: none 的元素不进入渲染树；visibility: hidden 的元素会进入，还占着位置，只是看不见。

接着是布局（Layout，也叫 Reflow），算出每个盒子的位置和尺寸。然后是绘制（Paint），把文字、颜色、边框、阴影记录成绘制指令，按图层分别绘制。最后是合成（Composite），合成线程把各个图层按顺序叠起来输出到屏幕。

页面显示以后再改样式，要走哪几步取决于改了什么。改几何属性，比如宽高、边距、字体大小，要重新布局；只改颜色、背景，需要重绘；只改 transform、opacity，而且元素已经在独立图层上，就可以只在合成线程完成，不占用主线程。

script 的几种加载方式

写法下载执行时机
<script>阻塞解析下载完立即执行
async并行下载完立即执行，顺序不保证
defer并行HTML 解析完成后、DOMContentLoaded 之前按顺序执行
type="module"并行默认同 defer

async 和 defer 都不阻塞解析，区别在执行时机。async 下载完就执行，几个脚本谁先下载完谁先跑；defer 等 HTML 解析完，再按书写顺序执行。脚本之间有依赖时用 defer。

常见追问

DOMContentLoaded 和 load 有什么区别？

DOMContentLoaded 在 HTML 解析完、defer 脚本执行完以后触发。load 还要等图片、样式这些子资源全部加载完，所以更晚。

为什么以前要把 <script> 放在 body 末尾？

为了不阻塞前面内容的解析，让页面先显示出来。现在更推荐在 head 里用 defer，既不阻塞解析，又能尽早开始下载。
