as const、类型注解和 satisfies 有什么不同？

类型注解让变量直接变成注解的类型，具体信息会丢；as const 把值推断成最窄的只读字面量；satisfies 检查值符不符合某个类型，同时保留它自己推断出的具体类型。

参考答案

简答

三种写法都在回答“这个值的类型是什么”，只是取舍不同。类型注解 const x: T = value，之后 x 就按 T 来用，value 里更具体的信息被丢掉了。as const 让值推断得最窄：字符串、数字变成字面量，数组变成只读元组，对象属性变成 readonly。

satisfies（4.9）是两者之间的折中。value satisfies T 检查 value 能不能赋给 T，拼错的键、缺失的键都会报错，但变量的类型仍然是 value 自己推断出来的具体类型。

固定的配置表常写成 as const satisfies T，既拿到字面量类型，又有结构检查。另外 as T 是断言，会跳过编译器证明不了的关系，作用和这三者都不同。

要注意，这三个都只在编译期起作用。as const 不会冻结对象，satisfies 也不会校验运行时的数据。

注解会丢掉什么

TypeScript
type Color = 'red' | 'green';
type RGB = readonly [number, number, number];

const annotated: Record<Color, string | RGB> = {
  red: [255, 0, 0],
  green: '#00ff00',
};
// annotated.green 是 string | RGB，必须先判断才能调用 toUpperCase

我们明明写的是 green: '#00ff00'，一个字符串。可因为注解了 Record<Color, string | RGB>，之后编译器只认这个注解，annotated.green 的类型是 string | RGB，直接调用 toUpperCase 会报错。

satisfies 怎样两头都要

TypeScript
const palette = {
  red: [255, 0, 0],
  green: '#00ff00',
} satisfies Record<Color, string | RGB>;

palette.green.toUpperCase(); // green 是 string
palette.red.join(',');       // red 是 [number, number, number]

同样的值换成 satisfies，结构照样被检查：少写一个颜色、键名拼错都会报错。可 palette 本身的类型没被改写，green 就是 string，red 就是元组，都能直接用。

satisfies 的目标类型还会参与推断，这一点容易让人意外：

TypeScript
const request = { method: 'GET' } satisfies { method: 'GET' | 'POST' };
// @ts-expect-error method 被推断为 'GET'，不能再赋成 'POST'
request.method = 'POST';

因为目标里 method 是字面量联合，编译器把 'GET' 推断成了字面量类型 'GET'，而不是 string，所以之后不能改成 'POST'。如果这个变量之后要换成另一个合法值，就该用类型注解。

as const 做了什么，没做什么

TypeScript
const point = [10, 20] as const;                         // readonly [10, 20]
const options = { mode: 'compact', enabled: true } as const;
// @ts-expect-error 只读
options.mode = 'comfortable';

加了 as const，point 不再是 number[]，而是只读元组 readonly [10, 20]；options.mode 是 'compact'，而且只读，赋值就报错。

可是 as const 只是类型上的只读，它不会调用 Object.freeze，运行时照样能改。它引用的外部可变对象也不会跟着变成只读：

TypeScript
const values = [1, 2];
const config = { values } as const;
config.values.push(3); // values 的类型是 number[]，允许

as const 只作用于写在它前面的那个字面量。values 是另一个变量，早就推断成了 number[]，所以 push 不报错。

组合使用

TypeScript
type Route = { path: string; method: 'GET' | 'POST' };

const routes = [
  { path: '/questions', method: 'GET' },
  { path: '/feedback', method: 'POST' },
] as const satisfies readonly Route[];

type Path = (typeof routes)[number]['path']; // '/questions' | '/feedback'

as const 保留了每个 path 的字面量，satisfies 保证每一项都符合 Route，最后能从里面提取出所有路径的联合类型。目标要写成 readonly Route[]，因为 as const 产生的是只读元组，赋不给可变的 Route[]。

怎么选

需求写法
变量之后会被赋成同一契约的其他值类型注解
固定常量，需要字面量类型as const
检查结构，同时保留推断satisfies
固定配置表并提取键或值的类型as const satisfies

常见追问

怎样用 as const 代替 enum？

写成 const Status = { Ok: 'ok', Fail: 'fail' } as const; type Status = (typeof Status)[keyof typeof Status];。它是普通对象加类型，编译时类型能直接擦掉，适合 Node.js 的类型剥离。

satisfies 会做额外属性检查吗？

会。对象字面量里写了目标类型中没有的键，同样会报错。
