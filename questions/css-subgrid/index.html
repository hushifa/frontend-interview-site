subgrid 如何让嵌套组件对齐父网格？

普通嵌套 Grid 独立计算轨道，subgrid 则复用网格项跨越的父网格轨道，让保留组件包裹结构的后代参与共享对齐。列与行可以分别选择是否使用子网格。

参考答案

把几张卡片放在 Grid 中，很容易让卡片外框一样高。但如果每张卡片内部又各自设置三行“标题、说明、按钮”，它们的内部行高仍然分别计算：一张标题只有一行，另一张有三行，正文的起点就可能对不齐。

原因是 Grid 默认只直接管理自己的网格项，嵌套 Grid 有自己的轨道系统。父级把卡片放进网格，不会自动继续穿过卡片包装层，把内部标题和别的卡片标题放在同一条轨道上。

subgrid 允许嵌套网格在指定轴上采用父网格的轨道，而不是重新定义一套。这样既保留卡片的 DOM 和语义边界，也能让内部内容参与共享的轨道尺寸计算。

让两张卡片的标题、正文和按钮分别对齐

HTML
<div class="catalog">
  <article class="course">
    <h2>HTML 入门</h2>
    <p>认识元素、表单与文档结构。</p>
    <button type="button">查看课程</button>
  </article>
  <article class="course">
    <h2>从布局计算到合成：浏览器渲染专题</h2>
    <p>结合长文本、图片和动画理解页面怎样显示，以及如何定位性能问题。</p>
    <button type="button">查看课程</button>
  </article>
</div>
CSS
.catalog {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 1rem;
}

.course {
  display: grid;
  grid-template-rows: auto 1fr auto;
  gap: 1rem;
  padding: 1rem;
  border: 1px solid #cbd5e1;
}

.course h2,
.course p {
  margin: 0;
  overflow-wrap: anywhere;
}

.course button {
  justify-self: start;
  align-self: start;
}

@supports (grid-template-rows: subgrid) {
  .course {
    grid-row: span 3;
    grid-template-rows: subgrid;
  }
}

@media (max-width: 36rem) {
  .catalog {
    grid-template-columns: minmax(0, 1fr);
  }
}

支持 subgrid 时，每张卡片在父级中跨越三条行轨道，再把这些轨道交给自己的三个直接子项。并排两张卡片共用同一组父行：标题所在行要容纳较高的标题，正文行要容纳相应内容，所以各部分的边界可以一起对齐。

其中 grid-row: span 3 很重要。它告诉父级给这张卡片分配三条行轨道，grid-template-rows: subgrid 才有这三条轨道可采用。只写 subgrid、却不安排父级跨度，不能期待自动生成任意数量的内部行。

不支持时，@supports 中的规则不会生效，卡片仍采用独立的 auto 1fr auto 三行布局，内容可读，按钮也可以靠各自中间行扩展保持底部排列，只是标题、正文之间不保证跨卡片精确对齐。

为什么这不同于给标题固定高度

把所有标题固定为 3rem，只是猜它们最多需要这么高。语言变长、用户放大字号或容器变窄时，标题就可能溢出。subgrid 让实际内容共同参与轨道尺寸计算，标题行可以随较长内容增长，而不用在 JavaScript 中测量最高标题再写回样式。

但“共享”也有范围。列表出现多排卡片时，后一排通常占用另外三条父行轨道，因此后一排的标题高度与前一排可以不同。subgrid 不会自动把整个列表中所有标题都统一成同一个高度。

只共享列，还是同时共享行

可以只写 grid-template-columns: subgrid，让表单行里的标签、输入框、提示对齐父级列，同时用自己的行布局。也可以只共享行，如上面的卡片例子，或者两个方向都采用 subgrid。

共享某个轴后，该轴可用的轨道数量由网格项跨越的父轨道决定。假设它跨越父网格的三列，它的列子网格就是这三列，不是整个父网格的全部列。

子网格内部的数字网格线编号从自身的起点重新算起。一个放在父级第 4 到第 7 条线之间的子网格，内部仍可以使用 grid-column: 1 / -1 表示铺满自己的显式列范围；不要直接把父级数字编号复制进来。父级命名线则能够传入子网格，还可以补充局部名字。

间距和额外内容有哪些限制

子网格在共享轴上默认采用父级的间距，也可以显式设置不同的 gap。间距变化不会把它变回完全独立的网格，但会影响内部项目相对共享网格线的边缘位置，所以要检查实际对齐效果。

subgrid 轴上不能像普通 Grid 那样无限追加隐式轨道。如果上面的卡片增加第四个直接子项，却仍然只跨三行，不应该期待自动得到第四条独立子网格行；自动放置可能把额外内容挤到已有轨道里。应明确增加跨度，或把新增内容包进既有区域。未采用 subgrid 的另一个轴仍可按普通网格规则处理。

它也不会自动穿透任意深度的包装层。需要共享对齐的后代应参与当前子网格布局；中间再多一层普通容器，就要决定该层是否也应成为嵌套子网格。设计时先确定需要共享的是哪几条轨道，再安排组件结构，比把所有嵌套 Grid 都改成 subgrid 更清楚。
