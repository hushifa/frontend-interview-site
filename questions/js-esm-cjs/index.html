ES Modules 和 CommonJS 有哪些关键区别？

ESM 的 import 在代码运行前就确定好依赖，导入的变量会跟着导出方实时变化。CommonJS 的 require 是运行到那一行才执行的函数，拿到的是当时的 module.exports。新版 Node.js 也允许 require 加载 ESM。

参考答案

简答

最根本的区别是加载时机。ESM 的 import 是静态声明，代码还没运行，引擎就先把整个依赖关系理清楚、连接好。CommonJS 的 require 只是一个普通函数，执行到那一行才去加载。

拿到的东西也不同。ESM 导入的是对导出变量的只读引用，导出方改了值，导入方能马上看到，这叫实时绑定。require 返回的是 module.exports 这个对象，从里面解构出来的变量，只是当时的值。

ESM 还有几个特点：支持顶层 await，默认是严格模式，没有 require 和 __dirname，可以用 import.meta.dirname 代替。在 Node.js 里，.mjs 是 ESM，.cjs 是 CommonJS，.js 看最近的 package.json 里 type 字段怎么写。

两者可以互相加载。Node.js 22.12+ 和 20.19+ 默认允许 require 一个 ESM 模块，但如果它的依赖里有顶层 await，会抛 ERR_REQUIRE_ASYNC_MODULE。

什么是实时绑定

下面两个文件，一个导出计数器，一个导入后调用 increment。注意第二次打印的 count。

JavaScript
// counter.mjs
export let count = 0;
export function increment() {
  count += 1;
}
JavaScript
// main.mjs
import { count, increment } from './counter.mjs';
console.log(count); // 0
increment();
console.log(count); // 1

main.mjs 里的 count 并没有被重新赋值，可它从 0 变成了 1。因为 ESM 导入的不是值的副本，而是指向 counter.mjs 里那个变量的引用，那边改了，这边读到的就是新值。

这个引用是只读的。导入方如果写 count = 5，会抛 TypeError，只有导出它的模块自己能改。

CommonJS 拿到的是什么

同样的计数器，用 CommonJS 写：

JavaScript
// counter.cjs
exports.count = 0;
exports.increment = () => {
  exports.count += 1;
};
JavaScript
// main.cjs
const counter = require('./counter.cjs');
const { count } = counter;
counter.increment();
console.log(count); // 0
console.log(counter.count); // 1

调用 increment 以后，解构出来的 count 还是 0，counter.count 却是 1。

require 返回的是 module.exports 这个对象。通过对象去读属性，读到的是最新的值；可解构的时候，count 已经被复制成了一个普通变量，之后对象上的属性怎么变，它都不会跟着变。所以常说的“CommonJS 是值拷贝、ESM 是引用”只说对了一半，CommonJS 拿到的对象本身是共享的。

还有一点：exports 只是 module.exports 的一个别名。写 exports = {...} 只是让这个别名指向了新对象，真正导出的 module.exports 没变。

ESM 的 import 不能写在 if 里，需要按条件加载时，用 import() 函数，它返回一个 Promise。

两种模块怎样互相加载

ESM 导入 CommonJS 时，默认导入拿到的就是 module.exports，Node.js 还会静态分析出一部分命名导出，让你能写 import { x } from。

CommonJS 加载 ESM 有两种方法。await import('./x.mjs') 一直都能用。新版本里也可以直接 require('./x.mjs')，返回的是模块命名空间对象，默认导出在它的 .default 属性上。想知道当前环境支不支持，可以检查 process.features.require_module。

反过来，ESM 里需要用 require 时，可以用 createRequire(import.meta.url) 造一个出来。

路径写法也有区别。Node.js 原生 ESM 的相对导入必须写扩展名，比如 ./counter.mjs。浏览器里直接写包名 import 'lodash' 是不行的，需要 import map 或者构建工具来解析。

循环依赖会怎样

两个模块互相导入，叫循环依赖。两种格式都允许，但都不保证你用的时候对方已经执行完了。

在 ESM 里，访问对方还没初始化的 let 或 const 导出，会抛 ReferenceError。在 CommonJS 里，你会拿到对方一个还没填完的 module.exports，某些属性是 undefined。

修复办法是把两边共用的部分抽到第三个模块里，或者不要在模块顶层就读取，延迟到函数被调用时再去读。

常见追问

一个包同时支持两种格式，怎样配置？

用 package.json 的 exports 字段，给 import 和 require 两种条件分别指定入口文件，详见《Node.js 的 package exports 会怎样影响模块解析？》。

为什么打包工具更喜欢 ESM？

因为 ESM 的导入导出在代码运行前就能确定，打包工具可以分析出哪些导出没人用，直接删掉，这就是 Tree shaking。CommonJS 的 require 可以写在任何地方、用任何变量，很难静态分析。
