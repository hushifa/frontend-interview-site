ES Modules 和 CommonJS 有哪些关键区别？

ESM 用静态 import/export，先解析和链接整个依赖图再执行，导入的是只读的实时绑定，支持顶层 await。CommonJS 的 require 是运行时同步调用，返回 module.exports 当时的值。Node.js 22.12+ 与 20.19+ 默认允许 require 加载不含顶层 await 的 ESM。

参考答案

简答

  • ESM 的 import 是静态声明，引擎在执行前构建依赖图并完成链接；CommonJS 的 require 是执行到那一行才调用的普通函数。
  • ESM 导入的是导出变量的实时只读绑定；require 返回 module.exports 对象，解构出来的是当时的值。
  • ESM 支持顶层 await，默认严格模式，没有 require、__dirname，用 import.meta.dirname 替代。
  • Node.js 中 .mjs 是 ESM、.cjs 是 CommonJS，.js 由最近的 package.json 的 type 决定。
  • require(esm) 在 Node.js 22.12+、20.19+ 默认可用，模块图里有顶层 await 时抛 ERR_REQUIRE_ASYNC_MODULE。

实时绑定

JavaScript
// counter.mjs
export let count = 0;
export function increment() {
  count += 1;
}
JavaScript
// main.mjs
import { count, increment } from './counter.mjs';
console.log(count); // 0
increment();
console.log(count); // 1

导入方不能给 count 赋值，会抛 TypeError。

CommonJS 返回对象

JavaScript
// counter.cjs
exports.count = 0;
exports.increment = () => {
  exports.count += 1;
};
JavaScript
// main.cjs
const counter = require('./counter.cjs');
const { count } = counter;
counter.increment();
console.log(count); // 0
console.log(counter.count); // 1

通过对象读取能看到变化，解构出来的变量不会变。所以"CommonJS 是值拷贝、ESM 是引用"只说对了一半。exports 只是 module.exports 的别名，写 exports = {...} 不会改变导出。

互操作

  • ESM 导入 CommonJS：默认导入得到 module.exports，Node 会静态分析出部分命名导出。
  • CommonJS 加载 ESM：await import('./x.mjs') 始终可用；require('./x.mjs') 返回模块命名空间对象，默认导出在 .default 上。可用 process.features.require_module 检测是否支持。
  • ESM 中需要 require 时用 createRequire(import.meta.url)。
  • Node 原生 ESM 的相对导入必须写扩展名；浏览器中的裸包名需要 import map 或构建工具。

循环依赖

两种格式都允许循环依赖，但都不保证对方已经执行完。ESM 中访问尚未初始化的 let/const 导出会抛 ReferenceError；CommonJS 会拿到对方尚未填充完的 module.exports。修复办法是把共享部分抽到第三个模块，或延迟到函数调用时再读取。
