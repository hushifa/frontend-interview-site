Playwright 接口模拟怎样覆盖稳定的成功和失败场景？

参考答案

可以在页面发出请求之前注册 route，通过 fulfill 返回受控数据，测试成功、空结果、错误提示等界面行为。也可以先 route.fetch 获取真实响应，再修改部分内容，不过此时测试仍依赖实际服务。

模拟范围应明确匹配预期 URL、方法和载荷，避免过宽拦截把错误接口路径也伪装成成功。除了返回数据，测试应断言用户最终可见的状态，以及重试、取消或重复提交等相关行为。

Mock 能提高稳定性，但通过 Mock 不代表真实服务契约一定匹配。仍需保留适量真实集成验证。用 HAR 录制网络数据时还要检查 Cookie、令牌和个人数据，不能把未经处理的真实会话记录直接提交仓库。
