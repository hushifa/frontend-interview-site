Playwright 接口模拟怎样覆盖成功和失败场景？

page.route 在请求发出前拦截，用 fulfill 返回固定响应、abort 模拟网络失败、continue 或 fallback 放行；多个处理器按注册的相反顺序执行，route.fetch 可以基于真实响应做修改。

参考答案

简答

  • 拦截要在 page.goto() 或触发请求的操作之前注册，否则页面加载时的请求已经发出。
  • route.fulfill() 返回自定义响应，不访问网络；route.abort() 让请求失败；route.continue() 直接发往网络；route.fallback() 交给前一个匹配的处理器。
  • 多个处理器匹配同一请求时，后注册的先执行，所以测试里可以覆盖 beforeEach 中的默认模拟。
  • HTTP 错误（status: 500）和网络失败（abort()）是两种不同的情况，前端的处理通常也不同，要分别测试。
  • page.route 只影响当前页面，context.route 还会作用于弹出窗口；页面注册了 Service Worker 时，请求可能绕过拦截，可以把 serviceWorkers 设为 'block'。

成功和失败

TypeScript
import { test, expect } from '@playwright/test';

test.beforeEach(async ({ page }) => {
  await page.route('**/api/orders', (route) =>
    route.fulfill({ json: [{ id: 1, title: '键盘' }] }),
  );
});

test('显示订单', async ({ page }) => {
  await page.goto('/orders');
  await expect(page.getByText('键盘')).toBeVisible();
});

test('服务端错误时显示重试按钮', async ({ page }) => {
  await page.route('**/api/orders', (route) =>
    route.fulfill({ status: 500, json: { message: 'internal error' } }),
  );
  await page.goto('/orders');
  await expect(page.getByRole('button', { name: '重试' })).toBeVisible();
});

test('断网时提示检查网络', async ({ page }) => {
  await page.route('**/api/orders', (route) => route.abort('internetdisconnected'));
  await page.goto('/orders');
  await expect(page.getByText('网络连接失败')).toBeVisible();
});

第二、三个测试里新注册的处理器先于 beforeEach 中的执行，覆盖了默认的成功响应。

检查请求本身

TypeScript
test('提交订单时发送正确的数据', async ({ page }) => {
  await page.goto('/checkout');
  const requestPromise = page.waitForRequest('**/api/orders');
  await page.getByRole('button', { name: '提交' }).click();
  const request = await requestPromise;
  expect(request.postDataJSON()).toMatchObject({ productId: 1, quantity: 2 });
});

waitForRequest 要在点击之前调用，避免请求在监听开始前就完成。

修改真实响应

TypeScript
await page.route('**/api/profile', async (route) => {
  const response = await route.fetch();
  const json = await response.json();
  await route.fulfill({ response, json: { ...json, vip: true } });
});

这依赖真实后端可用，适合在测试环境里验证某个字段对界面的影响。

模拟的风险

模拟数据是手写的，接口变了测试仍会通过。可以从 OpenAPI 生成模拟数据，或用契约测试保证前后端一致，见《前端契约测试应该验证什么？》。routeFromHAR 能把录制的真实流量作为模拟数据回放。

常见追问

  • 和 MSW 有什么区别？MSW 在应用内部通过 Service Worker 或 Node 拦截，同一套模拟可用于开发、单元测试和 E2E；Playwright 的 route 只在 Playwright 测试中可用，但可以拦截任何请求，包括第三方资源。
