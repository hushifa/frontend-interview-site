WebCodecs 适合哪些浏览器端音视频场景？

WebCodecs 把浏览器的编码器和解码器直接交给页面，能一帧一帧地控制，适合剪辑、转码和逐帧分析。它不解析容器、不管播放时钟和网络；使用时要管理解码队列、及时关闭帧，并按配置检测编解码器支持。

参考答案

简答

浏览器本来就能解码视频，<video> 用的就是它。WebCodecs 是把这些编码器、解码器直接交给页面，让你一帧一帧地处理。所以普通播放用 <video>，自适应流媒体用 MSE，实时通话用 WebRTC，只有要逐帧处理、在浏览器里剪辑或转码时才用 WebCodecs。

视频数据可以分三层：最外面是容器，比如 MP4、WebM；里面是编码块 EncodedVideoChunk；解码出来是原始帧 VideoFrame。WebCodecs 只管后两层，解析和封装容器要靠别的库。

用的时候有两个坑。decode() 是异步提交的，喂得太快队列和内存会暴涨，要根据 decodeQueueSize 控制速度。VideoFrame 占很大一块内存甚至 GPU 资源，用完必须调用 close()。

还要注意，支持哪些编解码器因浏览器和设备而异，要用 VideoDecoder.isConfigSupported() 按具体配置检测。

一条解码管道怎么写

下面的代码先检测配置，再一块块喂数据给解码器，每解出一帧就画出来并立刻关闭。

JavaScript
const decoder = new VideoDecoder({
  output(frame) {
    try {
      drawFrame(frame);
    } finally {
      frame.close(); // 不关闭会很快耗尽内存
    }
  },
  error: reportDecodeError,
});

const config = { codec: 'vp09.00.10.08', codedWidth: 1280, codedHeight: 720 };
const { supported } = await VideoDecoder.isConfigSupported(config);
if (!supported) throw new Error('当前设备不支持该配置');
decoder.configure(config);

function waitForDequeue() {
  return new Promise((resolve) => decoder.addEventListener('dequeue', resolve, { once: true }));
}

for (const chunk of chunks) {
  while (decoder.decodeQueueSize > 8) await waitForDequeue(); // 背压
  decoder.decode(chunk);
}
await decoder.flush(); // 一批数据结束时调用，不要每帧调用

frame.close() 放在 finally 里，是为了画的时候就算出错，这一帧也能被关掉。

循环里的 while 是在做背压。意思是下游处理不过来时，让上游先停一停。decodeQueueSize 是还在排队等解码的块数，超过 8 就等一个 dequeue 事件，有空位了再继续喂。

flush() 会等队列里的数据全部解完，所以只在一批数据结束时调一次，每帧都调会把流水线卡住。

这里的 chunks 来自容器解析库，比如 mp4box.js。WebCodecs 不能直接吃一个完整的 MP4 文件。

时间戳要注意什么

编码块和帧的 timestamp 单位是微秒。误传成毫秒，播放速度就全错了。

含 B 帧的视频，解码顺序和显示顺序不一样，所以显示时要按时间戳排序。

实时预览跟不上时，可以丢掉过期的帧；离线导出就不能丢，要处理完全部帧，并显示进度。

怎样放到 Worker 里，又怎样取消

解码器和编码器都能在专用 Worker 里用，配合 OffscreenCanvas 绘制，就不会占主线程。

可是如果把每一帧都传回主线程，Worker 的好处就被抵消了。所以只传进度或者缩略图。

取消导出时，要停止读取上游数据，不再提交新块，关闭还没处理的帧，最后调用 decoder.close() 和 encoder.close()。

兼容性和降级

AV1 解码支持得比较广，硬件编码的支持还比较有限；H.265 在苹果平台之外支持缺口明显。

还要注意，isConfigSupported() 返回支持，不代表一定能稳定实时处理，要用真实素材测性能和耗电。不支持时，可以降级到服务端转码，或者让用户换个格式。

常见追问

WebCodecs 和 MediaRecorder 有什么区别？

MediaRecorder 直接把媒体流录成文件，简单，但能控制的东西少。WebCodecs 给你每一帧和每个编码块，码率、关键帧、处理流程都能自己决定。

怎样防止恶意视频把页面拖垮？

限制文件大小、时长、分辨率和处理时间，超出就中止。
