WebCodecs 适合哪些浏览器端音视频场景？

WebCodecs 暴露浏览器的编码器和解码器，提供帧级控制，适合剪辑、转码和逐帧分析。它不解析容器、不管播放时钟和网络；使用时要管理解码队列、及时关闭帧，并按配置检测编解码器支持。

参考答案

简答

  • 普通播放用 <video>，自适应流媒体用 MSE，实时通话用 WebRTC。需要逐帧处理、浏览器内剪辑或转码时才用 WebCodecs。
  • 数据分三层：容器（MP4、WebM）、编码块（EncodedVideoChunk）、原始帧（VideoFrame）。WebCodecs 只处理后两层，解析和封装容器要用其他库。
  • decode() 是异步提交，输入太快会让队列和内存暴涨，要根据 decodeQueueSize 做背压。
  • VideoFrame 占用大块内存甚至 GPU 资源，用完必须调用 close()。
  • 支持的编解码器因浏览器和设备而异，用 VideoDecoder.isConfigSupported() 按具体配置检测。

解码管道

JavaScript
const decoder = new VideoDecoder({
  output(frame) {
    try {
      drawFrame(frame);
    } finally {
      frame.close(); // 不关闭会很快耗尽内存
    }
  },
  error: reportDecodeError,
});

const config = { codec: 'vp09.00.10.08', codedWidth: 1280, codedHeight: 720 };
const { supported } = await VideoDecoder.isConfigSupported(config);
if (!supported) throw new Error('当前设备不支持该配置');
decoder.configure(config);

function waitForDequeue() {
  return new Promise((resolve) => decoder.addEventListener('dequeue', resolve, { once: true }));
}

for (const chunk of chunks) {
  while (decoder.decodeQueueSize > 8) await waitForDequeue(); // 背压
  decoder.decode(chunk);
}
await decoder.flush(); // 一批数据结束时调用，不要每帧调用

chunks 来自容器解析库（例如 mp4box.js），WebCodecs 不能直接吃一个完整的 MP4 文件。

时间戳

编码块和帧的 timestamp 以微秒为单位，误传毫秒会导致播放速度错误。含 B 帧的视频，解码顺序和显示顺序不同，要按时间戳排序显示。

实时预览跟不上时丢弃过期帧；离线导出则要处理全部帧并显示进度。

Worker 与取消

  • 解码器和编码器可以在专用 Worker 中使用，配合 OffscreenCanvas 绘制，避免占用主线程。
  • 把每一帧都传回主线程会抵消 Worker 的收益，只传进度或缩略图。
  • 取消导出时：停止读取上游数据、不再提交新块、关闭未消费的帧、调用 decoder.close() 和 encoder.close()。

兼容与降级

AV1 解码支持较广，硬件编码支持仍然有限；H.265 在苹果平台之外支持缺口明显。isConfigSupported() 通过不代表一定能稳定实时处理，要用真实素材测试性能和耗电。不支持时降级到服务端转码，或让用户选择其他格式。

常见追问

  • WebCodecs 和 MediaRecorder 有什么区别？ MediaRecorder 直接把媒体流录制成文件，简单但控制少；WebCodecs 给出每一帧和每个编码块，可以自己决定码率、关键帧和处理流程。
  • 怎样防止恶意视频拖垮页面？ 限制文件大小、时长、分辨率和处理时间，超出就中止。
