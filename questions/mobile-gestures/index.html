移动端手势交互怎样避免和页面滚动冲突？

手指一动，浏览器想滚动、页面想横滑，就会打架。用横滑删除卡片讲 touch-action、移动阈值和方向锁定怎么配合，怎样处理取消与多指，以及为手势提供可点击的替代操作。

参考答案

简答

手指在屏幕上一滑，浏览器想拿它去滚动页面，页面上的卡片又想拿它做横滑删除，两边抢同一个动作，这就是冲突。

解决办法是提前分好工。给卡片写 touch-action: pan-y pinch-zoom，意思是纵向滚动和双指缩放归浏览器，横向移动归页面。然后手指移动超过一个小阈值，比如 10px，再判断方向并锁定，免得手抖一下就被当成横滑。

浏览器一旦决定接管去滚动，会发一个 pointercancel，卡片要在这里回到原位。

还要注意，手势是藏起来的操作，用户不一定知道能滑。所以要同时给一个能点的“删除”按钮，这也是 WCAG 2.5.1 和 2.5.7 的要求。

先看横滑删除卡片怎么写

下面这段代码给卡片绑定横滑。要看的是三件事：什么时候开始判断方向，什么时候接管指针，什么时候复位。

JavaScript
function bindSwipe(card, { threshold = 10, onSwipe }) {
  let id = null;
  let startX = 0;
  let startY = 0;
  let locked = null; // 'x' 或 'y'

  const reset = () => {
    id = null;
    locked = null;
    card.style.transform = '';
  };

  card.addEventListener('pointerdown', (e) => {
    if (id !== null || !e.isPrimary) return;
    id = e.pointerId;
    startX = e.clientX;
    startY = e.clientY;
  });

  card.addEventListener('pointermove', (e) => {
    if (e.pointerId !== id) return;
    const dx = e.clientX - startX;
    const dy = e.clientY - startY;

    if (!locked) {
      if (Math.hypot(dx, dy) < threshold) return;
      locked = Math.abs(dx) > Math.abs(dy) ? 'x' : 'y';
      if (locked === 'x') card.setPointerCapture(id);
    }
    if (locked === 'x') card.style.transform = `translateX(${dx}px)`;
  });

  card.addEventListener('pointerup', (e) => {
    if (e.pointerId !== id) return;
    const dx = e.clientX - startX;
    const swiped = locked === 'x' && Math.abs(dx) > card.offsetWidth / 3;
    reset();
    if (swiped) onSwipe(dx > 0 ? 'right' : 'left');
  });

  card.addEventListener('pointercancel', reset);
}
CSS
.card { touch-action: pan-y pinch-zoom; }

手指刚按下时，代码只记下起点，什么都不做。移动距离没超过阈值，也直接返回，所以轻点卡片时 click 还能正常触发。

超过阈值以后才比较横向和纵向谁大，锁定一个方向。锁成横向，就调用 setPointerCapture，意思是“之后这根手指的事件都交给卡片”，手指滑出卡片也不会丢。锁成纵向，代码就不管了，因为 touch-action 已经允许浏览器纵向滚动。

isPrimary 用来只跟踪第一根手指，第二根手指按上来不会打断当前手势。松手时，位移超过卡片宽度的三分之一才算滑成功，否则复位。

为什么不只写 pan-y

只写 pan-y，浏览器就只保留纵向滚动，双指缩放也交给页面了。页面又没处理缩放，结果用户没法放大看内容。所以要加上 pinch-zoom，把缩放留给浏览器。

为什么要处理 pointercancel

浏览器可能在中途决定这个手势归它，比如开始滚动。这时它会发 pointercancel，之后不会再有 pointerup。如果不处理，卡片就停在半路。所以代码把 pointercancel 也接到 reset 上，让卡片回到原位。

其他常见情况怎么处理

松手后的惯性和动画，可以用 CSS transition 让卡片滑出或回弹。速度可以按最后几次 pointermove 的位移和时间来估算。

自己实现双指缩放时，要记下两个 pointerId 的位置，用两点距离的比值算缩放比例。这时浏览器不该再插手，所以设成 touch-action: none。

系统手势页面是拦不住的。比如 iOS 从屏幕左边缘右滑是返回，所以关键手势不要放在屏幕边缘。

还有滚动穿透：弹层里滚到底了还继续滑，背景页面会跟着滚。给弹层容器设 overscroll-behavior: contain 就能挡住。

为什么一定要有替代操作

手势是隐藏的交互，用户不一定知道可以滑。读屏用户和用开关设备的用户也很难做出滑动。所以卡片上要有看得见的、或者能从菜单里找到的“删除”按钮，手势只当快捷方式。

WCAG 2.5.1 要求依赖路径或多点的手势，要有单指、不需要走路径的替代方式。WCAG 2.2 新增的 2.5.7 要求拖动操作提供单指点击的替代方式。

常见追问

为什么不在 pointermove 里调用 preventDefault() 阻止滚动？

因为滚不滚是在手势开始时，由 touch-action 决定的。手势开始以后再调用 preventDefault() 已经晚了，没有效果。所以要提前用 CSS 把分工写好。

用手势库还是自己写？

简单的横滑可以自己写。缩放、旋转、多种手势组合这类复杂情况，可以用成熟的库。但不管用不用库，touch-action 还是得自己设对。
