移动端手势交互怎样避免和页面滚动冲突？

用横滑删除卡片说明 touch-action、移动阈值和方向锁定的配合，处理取消与多指情况，并为手势提供可点击的替代操作。

参考答案

简答

  • 冲突的根源是浏览器和页面都想处理同一个触摸移动：浏览器要滚动，页面要横滑或拖动。
  • 用 touch-action 提前划分：横滑卡片设 pan-y pinch-zoom，纵向滚动和双指缩放留给浏览器，横向移动交给页面。
  • 移动距离超过阈值（如 10px）后再判断方向并锁定，避免轻微抖动被误判为手势。
  • 浏览器接管滚动时会发送 pointercancel，卡片要回到原位。
  • 每个手势都要有可点击的替代操作（如"删除"按钮），满足 WCAG 2.5.1 对路径手势的要求。

横滑删除卡片

JavaScript
function bindSwipe(card, { threshold = 10, onSwipe }) {
  let id = null;
  let startX = 0;
  let startY = 0;
  let locked = null; // 'x' 或 'y'

  const reset = () => {
    id = null;
    locked = null;
    card.style.transform = '';
  };

  card.addEventListener('pointerdown', (e) => {
    if (id !== null || !e.isPrimary) return;
    id = e.pointerId;
    startX = e.clientX;
    startY = e.clientY;
  });

  card.addEventListener('pointermove', (e) => {
    if (e.pointerId !== id) return;
    const dx = e.clientX - startX;
    const dy = e.clientY - startY;

    if (!locked) {
      if (Math.hypot(dx, dy) < threshold) return;
      locked = Math.abs(dx) > Math.abs(dy) ? 'x' : 'y';
      if (locked === 'x') card.setPointerCapture(id);
    }
    if (locked === 'x') card.style.transform = `translateX(${dx}px)`;
  });

  card.addEventListener('pointerup', (e) => {
    if (e.pointerId !== id) return;
    const dx = e.clientX - startX;
    const swiped = locked === 'x' && Math.abs(dx) > card.offsetWidth / 3;
    reset();
    if (swiped) onSwipe(dx > 0 ? 'right' : 'left');
  });

  card.addEventListener('pointercancel', reset);
}
CSS
.card { touch-action: pan-y pinch-zoom; }
  • 移动不足阈值时什么都不做，点击卡片仍正常触发 click。
  • 锁定为横向后才捕获指针，之后的移动都由卡片处理。
  • 锁定为纵向时不做处理；touch-action 已允许浏览器纵向滚动。
  • 只跟踪主指针（isPrimary），第二根手指不会打断当前手势。
  • 松手时位移超过卡片宽度的三分之一才算滑动成功，否则复位。

只写 pan-y 会把双指缩放也交给页面，用户就无法放大查看内容，所以保留 pinch-zoom。

其他常见问题

  • 惯性和动画：松手后用 CSS transition 让卡片滑出或回弹，速度可以按最后几次 pointermove 的位移和时间估算。
  • 双指缩放：自己实现缩放时，记录两个 pointerId 的位置，用两点距离的比值计算缩放比例，并设置 touch-action: none。
  • 系统手势：iOS 从屏幕左边缘右滑是返回，页面无法阻止，关键手势不要放在屏幕边缘。
  • 滚动穿透：弹层内滚动到底时继续滑动会带动背景滚动，可以给弹层容器设置 overscroll-behavior: contain。

替代操作

手势是隐藏的交互，用户不一定知道可以滑动，读屏用户和使用开关设备的用户也难以完成。卡片上应提供可见或可通过菜单访问的"删除"按钮，手势只作为快捷方式。WCAG 2.2 的 2.5.7 也要求拖动操作提供单指点击的替代方式。

Pointer Events 的基础模型和指针捕获见《Pointer Events 为什么适合统一鼠标、触摸和触控笔交互？》。

常见追问

  • 为什么不在 pointermove 里 preventDefault() 阻止滚动？滚动是否发生由 touch-action 在手势开始时决定，之后调用无效。
  • 用手势库还是自己写？简单横滑可以自己实现；复杂手势（缩放、旋转、多手势组合）可以用成熟库，但仍要设置正确的 touch-action。
