Map、Set、WeakMap 与普通对象各有什么用途？

普通对象适合表达记录，Map 适合动态键值集合，Set 适合唯一值集合，WeakMap 适合把元数据与对象生命周期关联。弱集合不提供枚举与容量控制，也不能自动解决所有引用保留问题。

参考答案

如果数据是“一个用户有 id、姓名和角色”，普通对象很自然；如果是“运行过程中不断按任意键加入、查找、删除条目”，Map 通常更合适；如果只关心“哪些值已经出现过”，就考虑 Set。

WeakMap 的区别不是更快或更高级，而是它不应仅因为对象被当作键，就单独阻止那个对象被回收。它解决生命周期关联问题，不是所有缓存的默认选择。

Map 可以用对象做键，但比较的是身份

JavaScript
const key = {};
const values = new Map([[key, 1]]);
console.log(values.get(key)); // 1
console.log(values.get({}));  // undefined

第二次传入的是一个新建空对象，即便外观与 key 一样，也不是同一个键。如果希望按用户 ID 查询，应把稳定 ID 作为键，而不是每次临时拼出一个新对象。

Map 的键可以是任意值，比较使用 SameValueZero：NaN 可以匹配另一个 NaN，正负零视为同一个键，对象仍然按身份匹配。数字 1 与字符串 '1' 则是不同键。

普通对象的属性键只能是字符串或 Symbol。用其他值做方括号属性名时，会发生相应的键转换：数字 1 和字符串 '1' 都会落到属性 '1'，两个普通对象也可能都转成 '[object Object]'，造成覆盖。

记录与动态字典，需要的接口不同

需求更直接的选择
一组约定好的字段，频繁用 obj.name 访问普通对象
任意值为键，频繁加入删除并获取条目数量Map
保存不重复的值、快速表达成员关系Set
给某个对象附加外部元数据，不独自延长键的生命周期WeakMap
只标记对象是否属于某一集合，且不需要枚举WeakSet

Map 有 size、has、get、set、delete 与可迭代条目等接口。普通对象有原型与属性描述符机制，可以表达更丰富的对象模型，但把它当任意外部键的字典时，需要考虑继承属性和特殊属性名。

例如检查对象自身是否有字段，应使用 Object.hasOwn，而不把继承来的名字也算进去。Object.create(null) 可以建立没有原型的字典，但它没有普通对象继承的方法，也不因此获得 Map 的任意类型键和迭代接口。

插入顺序不会随着每次访问自动刷新

JavaScript
const scores = new Map([
  ['a', 1],
  ['b', 2],
]);

scores.set('a', 3);
console.log([...scores.keys()].join(',')); // a,b

scores.delete('a');
scores.set('a', 4);
console.log([...scores.keys()].join(',')); // b,a

Map 按键的插入顺序迭代。更新已有键的值不会改变位置，读取也不会把它移到末尾；删除后重插才会更新顺序。这是用 Map 实现 LRU 缓存时必须主动维护的一步。

普通对象也有规定的属性枚举顺序，不能简单说“对象完全无序”。但整数索引形式的字符串键、其他字符串键和 Symbol 键遵循不同的次序规则，各个枚举 API 还会过滤不同属性，因此不能把它等同于 Map 的插入顺序模型。

Set 去重不是按业务字段去重

JavaScript
const values = new Set([1, 1, '1', NaN, NaN]);
console.log(values.size); // 3

const users = new Set([{ id: 1 }, { id: 1 }]);
console.log(users.size); // 2

数字 1、字符串 '1' 和 NaN 分别占一个成员。两个用户对象则身份不同，所以都保留。若要按 id 去重，应先定义重复时保留哪一份数据，再使用以 id 为键的 Map 等结构，而不是以为 Set 会递归比较对象内容。

Set 的 add 返回集合本身，delete 返回是否删除了条目；判断是否存在使用 has。它可以迭代，但不是按整数位置访问的数组，没有自然的 values[0] 或数组式索引接口。

WeakMap 怎样与对象生命周期关联

JavaScript
const metadata = new WeakMap();

function register(element, description) {
  metadata.set(element, { description });
}

function describe(element) {
  return metadata.get(element)?.description;
}

const element = {};
register(element, '编辑器容器');
console.log(describe(element)); // 编辑器容器

这里的 element 可以换成实际 DOM 元素等对象。元数据放在外部 WeakMap 中，不必向对象本身添加可能冲突的属性。只要代码还持有 element，就能查询元数据；当键对象不再被其他有效引用保留时，WeakMap 的这个关联不会单独阻止它被垃圾回收。

现代标准允许对象以及非注册 Symbol 作为弱键。普通字符串、数字不行，Symbol.for 创建的注册 Symbol 也不能按同样方式用作弱键；Symbol 弱键的实际支持仍应与目标运行环境核对。日常对象元数据场景并不需要依赖 Symbol 键。

WeakMap 没有 size，也不能列出所有键或条目，因为这会把垃圾回收导致的键存活变化暴露给程序。它提供已知键的 get、has、set、delete，不提供“列出当前所有还没被回收的对象”这种可预测接口。

弱引用不等于所有相关对象都会立即消失

如果键仍被数组、全局缓存、DOM 树或事件监听关系引用，它仍然可能存活。把元数据改存在 WeakMap，不会自动清理其他位置的强引用，也不会自动取消对象关联的定时器或请求。

只由弱映射关联产生的“值再引用键”循环，不应独自把键永久保留下来；但如果那个值对象也被外部代码强引用，并通过它再次到达键，就形成了另一条有效保留路径。判断泄漏需要看整个可达关系，不能只看某一个容器的名字里有没有 Weak。

回收时机由引擎决定，不能写测试要求“变量设为 null 后下一行 WeakMap 就删掉了”。需要主动过期、限制条目数量、遍历统计或按字符串 ID 查询的缓存，通常应使用 Map 配合显式策略。

性能与序列化也要按约定处理

Map 实现需要提供平均次线性的访问性能，常见实现可有很高的查找效率，但语言规范并不承诺所有引擎所有操作严格 O(1)，也不保证在每一种负载下都比对象快。先根据语义选结构，再测量真正的瓶颈。

普通 JSON.stringify 不会自动把 Map、Set 的内部条目变成你想要的 JSON。需要明确转换为条目数组或业务对象，再定义还原规则。Object.fromEntries 能把条目变成对象，但对象属性键的限制仍在，不能借此无损保留任意对象键的身份。
