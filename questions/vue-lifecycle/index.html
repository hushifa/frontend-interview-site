Vue 生命周期中何时访问 DOM、发请求和清理资源？

setup 最先执行，适合创建状态和发请求，但这时还没有 DOM；要操作 DOM 等 onMounted；定时器和订阅在 onUnmounted 里清掉。服务端渲染时挂载钩子不会执行。

参考答案

简答

一个组件从创建到销毁，顺序是 setup → onBeforeMount → onMounted，数据变化时走 onBeforeUpdate → onUpdated，最后是 onBeforeUnmount → onUnmounted。

三件事分别放在三个地方。发请求、创建响应式状态放在 setup 里，越早开始越好，但这时 DOM 还不存在，模板 ref 是 null。要聚焦、测量尺寸、初始化图表这类需要 DOM 的操作，放进 onMounted，这时组件已经插入页面。定时器、事件监听、WebSocket 在 onUnmounted 里清理，不然组件没了它们还在跑。

服务端渲染时只执行 setup（以及 onServerPrefetch），挂载和更新钩子都不会执行，所以访问 window、document 的代码要放进 onMounted。

还要注意，钩子要在 setup 里同步注册。普通的 async setup() 或异步回调里，await 之后再注册就关联不到组件了；<script setup> 是例外，编译器会在顶层 await 后恢复当前组件，但为了统一，最好都写在 await 之前。被 KeepAlive 缓存的组件切走时不卸载，触发的是 onDeactivated 和 onActivated。

一个组件里三件事各放哪

下面的组件要请求统计数据并画一张图。请求放在 setup 里立刻发，画图要等 DOM，清理放在卸载时：

vue
<script setup>
import { onMounted, onUnmounted, ref } from 'vue';

const props = defineProps({ id: Number });
const chartEl = ref(null);
const data = ref(null);
let chart;

// setup 阶段就开始请求，不必等到挂载
const controller = new AbortController();
fetch(`/api/stats/${props.id}`, { signal: controller.signal })
  .then((r) => r.json())
  .then((json) => {
    data.value = json;
    chart?.setData(json);
  })
  .catch((err) => {
    if (err.name !== 'AbortError') console.error(err);
  });

onMounted(() => {
  chart = createChart(chartEl.value); // 需要 DOM
  if (data.value) chart.setData(data.value);
});

onUnmounted(() => {
  controller.abort();
  chart?.destroy();
});
</script>

<template>
  <div ref="chartEl" />
</template>

为什么两个地方都要写 setData？因为请求和挂载谁先完成说不准。请求先回来，图表还没创建，chart?. 什么也不做，等 onMounted 时再把数据塞进去；挂载先完成，图表先建好，等数据回来再 setData。两边都检查对方是否就绪，哪种顺序都不会漏。

卸载时 abort() 也是必要的：用户很快离开了页面，请求还没回来，就直接取消，免得回来以后往一个已经销毁的图表里写数据。

父子组件谁先谁后

挂载时的顺序是：父 setup → 子 setup → 子 onMounted → 父 onMounted。因为父组件渲染时才创建子组件，子组件都挂好了，父组件才算挂载完成。所以在父组件的 onMounted 里，子组件已经全部挂载。卸载时也一样，子组件的 onUnmounted 先于父组件执行。

为什么钩子不能在 await 之后注册

JavaScript
// 错误：await 之后注册，钩子无法关联到当前组件
const user = await fetchUser();
onMounted(() => {});

onMounted 要知道“现在是哪个组件在初始化”，Vue 只在 setup 同步执行期间记着这个组件。await 之后代码在稍后的微任务里继续执行，这时已经没有“当前组件”了，钩子就挂不上去。<script setup> 的顶层 await 是例外，编译器会在 await 后帮你恢复当前组件，所以那里注册也能生效，但为了统一，仍然建议放在 await 之前。组合式函数里的钩子也遵循同样的规则。

被 KeepAlive 缓存的组件

被缓存的组件切走时不会卸载，所以 onUnmounted 不执行，触发的是 onDeactivated；切回来时触发 onActivated。离开时需要暂停的资源，应该写在这对钩子里，见《KeepAlive 与 Teleport 有哪些使用边界？》。

常见追问

onUpdated 里能修改状态吗？

最好不要。改了状态会再次触发更新，更新完又进 onUpdated，可能造成无限循环。

组件里的错误怎么捕获？

用 onErrorCaptured，它能捕获后代组件抛出的错误。回调返回 false 可以阻止错误继续向上传播。
