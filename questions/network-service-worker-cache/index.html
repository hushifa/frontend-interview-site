Service Worker 缓存更新为什么容易出现旧版本？

新 Service Worker 安装后默认要等所有旧页面关闭才激活，期间旧 Worker 继续用旧缓存响应；importScripts 引入的脚本被 HTTP 缓存、缓存名不随版本变化、activate 时没清旧缓存，都会让用户长期停在旧版本。

参考答案

简答

  • 生命周期是 install → waiting → activate。只要还有页面被旧 Worker 控制，新 Worker 就停在 waiting。
  • 浏览器检查更新时会逐字节比对 sw.js。updateViaCache 默认是 imports：sw.js 本身不走 HTTP 缓存，但 importScripts() 引入的脚本会走，被引入的文件不带版本号时更新可能不生效。
  • Cache Storage 与 HTTP 缓存相互独立，清浏览器 HTTP 缓存不会清 Cache Storage，必须在代码里删除旧缓存。
  • 缓存名带上版本号，在 activate 时删除其他版本；HTML 用网络优先，带哈希的静态资源用缓存优先。
  • skipWaiting() 能立即激活，但已打开的旧页面可能用新 Worker 请求已被删除的旧资源，最好提示用户刷新。

示例

JavaScript
// sw.js
const VERSION = 'v42';
const STATIC_CACHE = `static-${VERSION}`;
const PRECACHE = ['/', '/assets/app.3f9a1c.js', '/assets/app.8b2e.css'];

self.addEventListener('install', (event) => {
  event.waitUntil(caches.open(STATIC_CACHE).then((cache) => cache.addAll(PRECACHE)));
});

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) =>
      Promise.all(keys.filter((key) => key !== STATIC_CACHE).map((key) => caches.delete(key))),
    ),
  );
});

self.addEventListener('fetch', (event) => {
  const { request } = event;
  const url = new URL(request.url);
  if (request.method !== 'GET' || url.origin !== self.location.origin) return;

  if (request.mode === 'navigate') {
    // HTML：网络优先，离线时回退缓存
    event.respondWith(fetch(request).catch(() => caches.match('/')));
    return;
  }

  if (url.pathname.startsWith('/assets/')) {
    event.respondWith(caches.match(request).then((hit) => hit ?? fetch(request)));
  }
});

self.addEventListener('message', (event) => {
  if (event.data === 'SKIP_WAITING') self.skipWaiting();
});

只拦截同源的 GET 请求和明确的静态目录，接口请求交给网络，避免把个人数据存进 Cache Storage。

提示用户更新

JavaScript
const registration = await navigator.serviceWorker.register('/sw.js');

registration.addEventListener('updatefound', () => {
  const worker = registration.installing;
  worker.addEventListener('statechange', () => {
    if (worker.state === 'installed' && navigator.serviceWorker.controller) {
      showUpdateBanner(() => worker.postMessage('SKIP_WAITING'));
    }
  });
});

let refreshing = false;
navigator.serviceWorker.addEventListener('controllerchange', () => {
  if (refreshing) return;
  refreshing = true;
  location.reload();
});

navigator.serviceWorker.controller 存在说明这是更新，不是首次安装。

排查

  • DevTools Application → Service Workers：查看 waiting 状态，可勾选 Update on reload 调试。
  • Application → Cache Storage：确认旧版本缓存是否被删除。
  • 紧急下线：部署一个只做清理和 registration.unregister() 的 sw.js，或返回 Clear-Site-Data: "storage"。
