CSS Anchor Positioning 适合解决哪些浮层布局问题？

锚点定位让提示框、下拉菜单这类浮层直接贴着某个元素放，空间不够时还能自动换个方向，大部分情况不用再用 JavaScript 算坐标。

参考答案

简答

做提示框或下拉菜单时，以前要用 JavaScript 读按钮的位置，再算出浮层的坐标。锚点定位让 CSS 直接完成这件事：按钮用 anchor-name 起个名字，浮层用 position: absolute 或 fixed，再用 position-anchor 指向这个名字。

光关联还不会移动浮层，还要说明放在哪里。简单的用 position-area: top 这类写法，精细的用 anchor() 取锚点的边，或者用 anchor-center 居中对齐。

它最省事的地方是自动换位置。position-try-fallbacks: flip-block 表示上面放不下就翻到下面，不用自己判断溢出。

要注意两点。列表里多个元素用同一个锚点名时，浮层默认绑到源码里最后一个，要用 anchor-scope 把名字限定在每一行里。另外 anchor-name 自 2026 年 1 月才进入 Baseline，较新的部分支持程度不一，旧浏览器要准备回退。

先看最基本的写法

下面给“保存”按钮加一个提示框，提示框放在按钮上方。

HTML
<button class="save">保存</button>
<div class="tip" role="tooltip">保存后会同步到所有设备</div>
CSS
.save {
  anchor-name: --save;
}

.tip {
  position: absolute;
  position-anchor: --save;
  position-area: top;
  margin-block-end: 8px;
  position-try-fallbacks: flip-block;
}

按钮叫 --save，提示框通过 position-anchor 认它当锚点。position-area 可以这样理解：把锚点想成一个 3×3 网格正中间的那一格，top 就是放在锚点上方那一整行，所以水平方向会跨满整行。

如果按钮贴着视口顶部，上面放不下怎么办？flip-block 会把浮层沿块方向翻过去，放到按钮下方。这一步以前要靠监听滚动、比较坐标来做。

需要更精细地控制位置时

position-area 只能选格子。想要“离按钮底边 6px”这种具体距离，就用 anchor()。它返回的是一个长度，所以能放进 calc() 里算：

CSS
.tip {
  position: absolute;
  position-anchor: --save;
  top: calc(anchor(bottom) + 6px);
  justify-self: anchor-center;
}

anchor(bottom) 取的是锚点底边的位置，加 6px 后就是浮层的顶边。justify-self: anchor-center 让浮层在水平方向和锚点居中对齐。

列表里每行都有菜单，为什么都指向最后一行

表格每一行都有一个“更多”按钮，按钮都叫 --row-action。结果所有菜单都跑到最后一个按钮旁边去了。

原因是锚点名默认在整个文档里都能看到。同名的锚点有好几个时，浮层绑定源码顺序里最后一个。

改法是在行元素上加 anchor-scope，让这个名字只在本行里面有效，每行的菜单就只能找到本行的按钮：

CSS
.row {
  anchor-scope: --row-action;
}

.row .more {
  anchor-name: --row-action;
}

.row .menu {
  position: absolute;
  position-anchor: --row-action;
  position-area: bottom span-right;
}

和 Popover 怎么配合

用 popovertarget 打开的 popover 会自动有一个隐式锚点，就是触发它的那个按钮。所以这时可以不写 anchor-name。不过 popover 默认是在屏幕中间显示的，要先把默认的居中样式清掉：

CSS
[popover] {
  inset: auto;
  margin: 0;
  position-area: bottom;
}

两者各管一件事。Popover 负责显示在顶层、点外面自动关闭和焦点行为，锚点定位只负责摆在哪里。

浏览器不支持时怎么办

不支持锚点定位的浏览器会把浮层当成普通的绝对定位来处理。所以先写一个能用的普通定位，再用 @supports (anchor-name: --a) 加上锚点定位的写法。如果要支持旧浏览器，场景又比较复杂，仍然可以用 Floating UI 这类库来算位置。

还有一个容易踩的坑：锚点必须被渲染出来。锚点是 display: none 时，浮层会退回去，按最近的定位祖先来放。

常见追问

锚点滚出视口以后，浮层要不要跟着隐藏？

可以用 position-visibility: anchors-visible。锚点滚出视口时，浮层就自动隐藏，不会孤零零地悬在那里。

用了锚点定位，tooltip 的无障碍问题就解决了吗？

没有。锚点定位只管位置。用 aria-describedby 关联说明文字、支持键盘触发、按 Esc 关闭，这些还要自己单独实现。
