Angular Zoneless 模式会改变哪些更新假设？

Zoneless 模式不再用 Zone.js 拦截所有异步任务来触发变更检测，而是依靠 Signal 更新、模板事件、markForCheck 等明确通知。Angular v21 起新项目默认 zoneless；原来依赖"任何异步回调后自动刷新"的代码需要改写。

参考答案

简答

  • Angular v21 起默认 zoneless；v20 需要在启动时加 provideZonelessChangeDetection()。如果项目中存在 provideZoneChangeDetection()，它会覆盖默认值，恢复 Zone.js 模式。
  • 以下操作会触发变更检测：模板读取的 Signal 被修改、模板或宿主上绑定的事件回调、ChangeDetectorRef.markForCheck()（AsyncPipe 会自动调用）、ComponentRef.setInput()。
  • setTimeout、fetch、第三方库回调中直接修改普通字段，不再自动刷新界面。
  • Reactive Forms 的 setValue、patchValue 不会自动安排检测，需要配合 Signal 或 markForCheck()。
  • NgZone.onStable、onMicrotaskEmpty 不会再触发；SSR 中需要等待的异步工作要用 PendingTasks 登记。

改写示例

TypeScript
// Zone.js 模式下能工作，zoneless 下界面不更新
export class ClockComponent {
  time = new Date();
  constructor() {
    setInterval(() => (this.time = new Date()), 1000);
  }
}
TypeScript
// zoneless 写法：用 Signal
import { Component, DestroyRef, inject, signal } from '@angular/core';

@Component({ selector: 'app-clock', template: `{{ time() | date: 'mediumTime' }}` })
export class ClockComponent {
  readonly time = signal(new Date());

  constructor() {
    const id = setInterval(() => this.time.set(new Date()), 1000);
    inject(DestroyRef).onDestroy(() => clearInterval(id));
  }
}

迁移步骤

  1. v20 项目在 bootstrapApplication 的 providers 中加入 provideZonelessChangeDetection()。
  2. 把在异步回调里修改、并在模板中显示的状态改成 Signal，或在修改后调用 markForCheck()。
  3. 推荐组件使用 OnPush，它要求的通知方式与 zoneless 一致，能提前暴露问题；但 OnPush 不是必须的。
  4. 从 angular.json 的 build 和 test 目标的 polyfills 中删除 zone.js 和 zone.js/testing，然后卸载 zone.js。
  5. 把依赖 onStable 的逻辑改成 afterNextRender 或 afterEveryRender。

SSR 中等待异步任务

Zone.js 模式下，服务端会等所有宏任务完成再序列化 HTML。zoneless 下需要显式登记：

TypeScript
import { PendingTasks, inject } from '@angular/core';

const tasks = inject(PendingTasks);
tasks.run(async () => {
  this.data.set(await loadData());
});

Router 导航和 HttpClient 请求 Angular 已经自动登记。

收益

  • 少了 Zone.js 的包体积和对所有异步 API 的补丁。
  • 变更检测只在有明确通知时运行，调用栈更清晰，也不会因为第三方库的频繁回调而反复检测。

常见追问

  • 测试有什么变化？TestBed 默认也是 zoneless，依赖 Zone.js 行为的测试需要在 providers 中加 provideZoneChangeDetection()。
  • NgZone.runOutsideAngular 还需要吗？不必删除。zoneless 应用里它不会造成问题；库被仍运行 Zone.js 的应用引用时，删掉它反而可能拖慢性能。
