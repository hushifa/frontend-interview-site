Angular Zoneless 模式会改变哪些更新假设？

Zoneless 模式不再用 Zone.js 拦截所有异步任务来触发变更检测，而是依靠 Signal 更新、模板事件、markForCheck 等明确的通知。Angular v21 起新项目默认 zoneless；原来依赖“任何异步回调后自动刷新”的代码需要改写。

参考答案

简答

以前 Angular 靠 Zone.js 知道什么时候该刷新界面。Zone.js 给 setTimeout、fetch、事件这些异步 API 都打了补丁，任何异步回调跑完，Angular 就做一次变更检测，也就是检查界面要不要更新。Zoneless 就是去掉 Zone.js，改成“有人明确通知才检查”。

Angular v21 起默认就是 zoneless；v20 要在启动时加 provideZonelessChangeDetection()。如果项目里写了 provideZoneChangeDetection()，它会覆盖默认值，回到 Zone.js 模式。

会触发检查的通知有这几种：模板读取的 Signal 被修改；模板或宿主上绑定的事件回调；调用 ChangeDetectorRef.markForCheck()，AsyncPipe 会自动调它；还有 ComponentRef.setInput()。反过来，在 setTimeout、fetch 或第三方库回调里直接改普通字段，界面就不会自动刷新了。

还有几处要注意：Reactive Forms 的 setValue、patchValue 不会自动安排检查，要配合 Signal 或 markForCheck()；NgZone.onStable、onMicrotaskEmpty 不会再触发；SSR 里需要等待的异步工作要用 PendingTasks 登记。

为什么界面不更新了

下面这个时钟在 Zone.js 模式下没问题，换成 zoneless 以后，时间就停住不动了。

TypeScript
// Zone.js 模式下能工作，zoneless 下界面不更新
export class ClockComponent {
  time = new Date();
  constructor() {
    setInterval(() => (this.time = new Date()), 1000);
  }
}

this.time 其实每秒都在变，只是没人告诉 Angular。以前 Zone.js 会在 setInterval 回调跑完后自动触发检查，现在没有它了，Angular 不知道要更新。

改法是把 time 换成 Signal。Signal 被修改时会主动通知 Angular：

TypeScript
// zoneless 写法：用 Signal
import { Component, DestroyRef, inject, signal } from '@angular/core';

@Component({ selector: 'app-clock', template: `{{ time() | date: 'mediumTime' }}` })
export class ClockComponent {
  readonly time = signal(new Date());

  constructor() {
    const id = setInterval(() => this.time.set(new Date()), 1000);
    inject(DestroyRef).onDestroy(() => clearInterval(id));
  }
}

顺便用 DestroyRef 在组件销毁时清掉定时器，原来的写法漏了这一步。

迁移分几步

  1. v20 项目在 bootstrapApplication 的 providers 里加 provideZonelessChangeDetection()。
  2. 找出在异步回调里修改、又在模板里显示的状态，改成 Signal，或者改完后调用 markForCheck()。
  3. 推荐组件用 OnPush。它要求的通知方式和 zoneless 一样，能提前暴露问题，但不是必须的。
  4. 从 angular.json 里 build 和 test 目标的 polyfills 中删掉 zone.js 和 zone.js/testing，再卸载 zone.js。
  5. 依赖 onStable 的逻辑改用 afterNextRender 或 afterEveryRender。

SSR 怎样知道什么时候渲染完

服务端渲染要等数据都到了才能输出 HTML。Zone.js 模式下，服务端会等所有宏任务完成再序列化，因为 Zone.js 知道还有哪些任务没完成。zoneless 下没人跟踪这些任务了，需要自己登记：

TypeScript
import { PendingTasks, inject } from '@angular/core';

const tasks = inject(PendingTasks);
tasks.run(async () => {
  this.data.set(await loadData());
});

Router 导航和 HttpClient 请求，Angular 已经自动登记了，不用自己处理。

换来了什么

一是少了 Zone.js 的包体积，也不用再给所有异步 API 打补丁。二是变更检测只在有明确通知时运行，调用栈更清楚，第三方库频繁触发回调时也不会跟着反复检测。

常见追问

测试有什么变化？

TestBed 默认也是 zoneless。依赖 Zone.js 行为的测试，要在 providers 里加 provideZoneChangeDetection()。

NgZone.runOutsideAngular 还要留着吗？

不必删。在 zoneless 应用里它不会造成问题。如果你写的是库，被仍在用 Zone.js 的应用引用时，删掉它反而可能拖慢性能。
