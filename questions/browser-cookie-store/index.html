Cookie Store API 应该怎样安全地管理浏览器 Cookie？

Cookie Store API 用 Promise 读写 Cookie 并能监听变化，只在 HTTPS 下可用；它读不到 HttpOnly Cookie，适合管理主题、语言等非敏感 Cookie。

参考答案

简答

  • cookieStore.get()、set()、delete() 都返回 Promise，替代手动拼接和解析 document.cookie 字符串。
  • 它只在安全上下文（HTTPS 或 localhost）中可用，写入的 Cookie 一定带 Secure；MDN 标为 Baseline 2025。
  • 过期时间用 expires 传毫秒时间戳，没有 maxAge 选项；sameSite 默认是 strict。
  • 读不到 HttpOnly Cookie，登录会话应由服务端设置 HttpOnly Cookie。
  • 可以监听 change 事件，Service Worker 中也能通过 cookieStore 使用。

写入和读取

JavaScript
async function setTheme(theme) {
  await cookieStore.set({
    name: 'theme',
    value: theme,
    expires: Date.now() + 365 * 24 * 60 * 60 * 1000,
    path: '/',
    sameSite: 'lax',
  });
}

async function getTheme() {
  const cookie = await cookieStore.get('theme');
  return cookie?.value ?? 'system';
}

set() 失败时 Promise 会 reject，不需要再读回来确认。

监听变化

JavaScript
cookieStore.addEventListener('change', (event) => {
  for (const cookie of event.changed) {
    if (cookie.name === 'theme') applyTheme(cookie.value);
  }
  for (const cookie of event.deleted) {
    if (cookie.name === 'theme') applyTheme('system');
  }
});

服务端通过 Set-Cookie 修改非 HttpOnly 的 Cookie 时，这个事件也会触发。

降级

JavaScript
function setThemeFallback(theme) {
  document.cookie = `theme=${encodeURIComponent(theme)}; Max-Age=31536000; Path=/; SameSite=Lax; Secure`;
}

const save = 'cookieStore' in globalThis ? setTheme : setThemeFallback;

两条路径要写入同样的过期时间和属性，否则用户在不同浏览器得到的 Cookie 行为不一致。

常见追问

  • 和 localStorage 怎么选：服务端渲染时需要读取的偏好用 Cookie，纯前端使用的数据用 localStorage，避免每次请求都携带。
  • 能不能用它做认证：不能。脚本能读写的 Cookie 一旦遇到 XSS 就会泄露。
