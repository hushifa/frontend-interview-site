Cookie Store API 应该怎样安全地管理浏览器 Cookie？

Cookie Store API 用 Promise 读写 Cookie，还能监听变化，替代手动拼 document.cookie 字符串。它只在 HTTPS 下可用，读不到 HttpOnly Cookie，适合管主题、语言这类不敏感的 Cookie。

参考答案

简答

以前在前端读写 Cookie，只能操作 document.cookie 这个字符串，自己拼、自己解析。Cookie Store API 换成了 cookieStore.get()、set()、delete() 这几个返回 Promise 的方法，还能监听 Cookie 的变化。

它只在安全上下文里能用，也就是 HTTPS 或 localhost，写进去的 Cookie 一定带 Secure。Chromium、Firefox 140、Safari 18.4 起都支持基本读写，但部分方法和事件仍有差异，MDN 兼容表把整套 API 列为尚未全面可用，所以要保留降级方案。

参数上有几个细节：过期时间用 expires 传毫秒时间戳，没有 maxAge；sameSite 默认是 strict。

最重要的边界是，它读不到 HttpOnly Cookie。所以它适合管理主题、语言这种不敏感的 Cookie，登录会话还是应该由服务端设置 HttpOnly Cookie。

怎样写入和读取

下面把用户选的主题存一年，再读出来：

JavaScript
async function setTheme(theme) {
  await cookieStore.set({
    name: 'theme',
    value: theme,
    expires: Date.now() + 365 * 24 * 60 * 60 * 1000,
    path: '/',
    sameSite: 'lax',
  });
}

async function getTheme() {
  const cookie = await cookieStore.get('theme');
  return cookie?.value ?? 'system';
}

和 document.cookie 比，不用再手动拼 ; Path=/ 这类字符串，也不用自己按分号切开去找值。

可是 await 成功不一定代表写进去了。参数不合法时 Promise 会 reject；但如果是被浏览器策略拒绝，会不会 reject 没有统一保证。所以关键的 Cookie 写完以后，可以再 get() 一次确认。

怎样知道 Cookie 变了

JavaScript
cookieStore.addEventListener('change', (event) => {
  for (const cookie of event.changed) {
    if (cookie.name === 'theme') applyTheme(cookie.value);
  }
  for (const cookie of event.deleted) {
    if (cookie.name === 'theme') applyTheme('system');
  }
});

change 事件把变化分成两组：changed 是新增或修改的，deleted 是被删掉的。不光脚本改 Cookie 会触发，服务端用 Set-Cookie 改了非 HttpOnly 的 Cookie，这个事件也会触发。Service Worker 里也能通过 cookieStore 用这套 API。

不支持的浏览器怎么办

JavaScript
function setThemeFallback(theme) {
  document.cookie = `theme=${encodeURIComponent(theme)}; Max-Age=31536000; Path=/; SameSite=Lax; Secure`;
}

const save = 'cookieStore' in globalThis ? setTheme : setThemeFallback;

降级就是回到 document.cookie。要注意两条路径写入的过期时间和属性得一致，否则用户换个浏览器，Cookie 的行为就不一样了。

常见追问

Cookie Store API 能用来管理登录状态吗？

不能。脚本能读写的 Cookie，一旦页面有 XSS 就会被偷走。它本身也读不到 HttpOnly Cookie。登录会话应该由服务端下发 HttpOnly Cookie。

主题偏好放 Cookie 还是 localStorage？

看服务端要不要用。服务端渲染时需要知道主题，就放 Cookie，请求会带上它。纯前端用的数据放 localStorage，避免每次请求都多带一份。
