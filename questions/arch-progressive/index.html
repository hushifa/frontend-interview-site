渐进增强和优雅降级怎样影响前端方案选择？

渐进增强先保证最基础的版本能用，再在支持的环境里加功能；优雅降级先做完整体验，再给弱环境准备退路。判断能力要用特性检测，脚本运行失败也算能力不足，增强层不能破坏基础功能。

参考答案

简答

渐进增强是先做一个最基础、最朴素也能用的版本，比如纯 HTML 的内容、原生的链接和表单，然后在支持的环境里再叠加样式和脚本功能。优雅降级反过来，先做完整体验，再给能力不够的环境准备退路。

两者的区别在出发点。渐进增强从核心任务出发，所以核心任务始终可用；优雅降级从完整体验出发，退路是后补的，容易漏掉。

判断环境支不支持某个功能，要用特性检测，也就是直接检查这个能力在不在，比如 'share' in navigator、CSS 的 @supports，而不是看浏览器名字和版本号。

要注意，“能力不足”不只是浏览器老。脚本加载失败、超时、运行报错，也是能力不足。所以基础功能不应该完全依赖 JS 成功执行。

一个搜索表单怎样做渐进增强

先写一个不需要任何脚本就能用的表单：

HTML
<form action="/search" method="get" id="search">
  <input name="q" type="search" required aria-label="搜索题目" />
  <button>搜索</button>
</form>

再用脚本把它增强成在当前页显示结果：

JavaScript
const form = document.querySelector('#search');
form.addEventListener('submit', async (event) => {
  event.preventDefault();
  try {
    await showResultsInline(new FormData(form).get('q'));
  } catch {
    form.submit(); // 增强失败时回到原生提交
  }
});

没有 JS 时，表单照常提交到 /search，由服务端或预渲染页面返回结果。有 JS 时，结果直接显示在当前页，体验更好。

那 JS 执行出错怎么办？catch 里调用 form.submit()，回到原生提交。这样最坏情况也就是退回到没有脚本的体验，而不是用户点了按钮毫无反应。

为什么检测能力，不检测浏览器

下面两段分别在 JS 和 CSS 里做特性检测：

JavaScript
if ('share' in navigator) {
  shareButton.hidden = false;
} else {
  copyLinkButton.hidden = false;
}
CSS
.layout { display: block; }

@supports (display: grid) {
  .layout { display: grid; grid-template-columns: 1fr 3fr; }
}

支持分享 API 就显示“分享”按钮，不支持就显示“复制链接”。支持 Grid 就用两栏布局，不支持就保持普通的块布局。

为什么不直接判断“是不是 Chrome 某某版本”？因为同一个浏览器，不同版本、不同设置的能力并不一样，比如企业策略可能禁用了某些 API。直接检查能力本身，才是准确的。

增强层反而破坏基础功能的情况

增强的本意是让体验更好，可写得不好会把原本能用的东西弄坏。常见的几种：

  • 用 <div onclick> 代替链接做导航。JS 加载前点不了，也没法在新标签页打开。
  • 所有内容都靠客户端渲染。脚本加载慢或失败时，页面就是一片空白。
  • 用自定义下拉框替换原生 <select>，却没实现键盘操作。
  • 加载脚本前先用 CSS 把内容隐藏起来。脚本一失败，内容就永远不显示了。

这些问题的共同点是，增强层替换掉了原生能力，却没把原生能力的全部行为补回来。

对方案选择有什么影响

内容型网站，比如文档、博客、电商详情页，适合预渲染加渐进增强。首屏不依赖脚本，搜索引擎收录也更可靠。

复杂的交互应用，比如在线编辑器、设计工具，核心功能本身就离不开 JS。这时更现实的做法是明确支持哪些浏览器，对不支持的环境给出提示。

新的 CSS 特性和 Web API，先用特性检测包起来，只在支持的环境里启用。

常见追问

SSR 就是渐进增强吗？

不完全是。SSR 提供了基础 HTML，内容能先显示出来。但如果按钮、表单这些交互要等水合完成才能工作，那水合之前它们还是不可用的。要做到渐进增强，还得配合原生表单和链接。

这样做会增加多少成本？

主要成本是坚持用语义化 HTML 和原生控件。而这本身也是无障碍的要求，并不算额外的负担。
