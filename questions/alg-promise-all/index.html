怎样实现保持输入顺序的 Promise.all 教学版本？

Promise.all 接收一个可迭代对象，返回的 Promise 在全部输入兑现后以按输入顺序排列的结果数组兑现，任一输入拒绝就立即拒绝。实现的关键是在登记每一项时固定它的下标，用计数器判断是否全部完成，并用 Promise.resolve 统一处理普通值、Promise 和 thenable。

参考答案

简答

  • 结果数组按输入顺序排列，与完成先后无关：每一项在登记时就固定了自己的下标，完成后写入 results[position]。
  • 每一项都用 Promise.resolve(item) 包装，普通值、原生 Promise 和带 then 方法的对象（thenable）都能统一处理。
  • 计数器 remaining 从 1 开始，遍历结束后再减 1。这样空输入能正确兑现为 []，也不会在遍历中途因为前面的项已完成而提前兑现。
  • 任意一项拒绝就用它的原因拒绝；其余已经开始的任务会继续运行，Promise.all 无法取消它们。
  • 输入可以是数组、Set、字符串或生成器等同步可迭代对象，遍历过程中抛出的错误会让返回的 Promise 拒绝。

实现

JavaScript
function promiseAll(iterable) {
  return new Promise((resolve, reject) => {
    const results = [];
    let remaining = 1;
    let index = 0;

    for (const item of iterable) {
      const position = index++;
      remaining++;

      Promise.resolve(item).then((value) => {
        results[position] = value;
        if (--remaining === 0) resolve(results);
      }, reject);
    }

    if (--remaining === 0) resolve(results);
  });
}
JavaScript
let finishFirst;
let finishSecond;

const first = new Promise((resolve) => { finishFirst = resolve; });
const second = new Promise((resolve) => { finishSecond = resolve; });
const combined = promiseAll([first, second, 42]);

finishSecond('B');
finishFirst('A');
console.log(await combined);

第二项先完成，输出仍是 ['A', 'B', 42]（示例使用顶层 await，需要在 ES 模块或异步函数中运行）。

实现细节

为什么 remaining 从 1 开始？ 多出来的 1 代表"遍历还没结束"。如果从 0 开始，空输入时永远不会兑现；而且某项在遍历中途就完成时，计数可能提前归零。遍历结束后减去这个 1，空输入在这一步直接兑现。

为什么在 executor 里遍历？ new Promise 的 executor 中同步抛出的错误会自动变成拒绝，所以传入 null（不可迭代）或生成器中途抛错时，返回的 Promise 会拒绝，而不是同步抛出。

为什么用 Promise.resolve 而不是直接调用 item.then？ 普通值没有 then 方法；不规范的 thenable 可能多次调用回调，Promise.resolve 会把它转成一个只结算一次的原生 Promise。

reject 被调用多次会怎样？ Promise 只会结算一次，后续调用被忽略，所以多项拒绝时结果是第一个被处理的拒绝。

和其他组合方法对比

方法兑现条件拒绝条件
Promise.all全部兑现任一拒绝
Promise.allSettled全部结算（不论成功失败）不会拒绝
Promise.race第一个结算的是兑现第一个结算的是拒绝
Promise.any任一兑现全部拒绝，原因是 AggregateError

常见追问

  • Promise.all 能限制并发吗？ 不能。传进来的 Promise 在创建时已经开始执行，Promise.all 只等待结果。需要限制并发时传入任务函数，见《怎样实现有明确失败语义的异步并发池？》。
  • 和原生实现还有哪些差别？ 原生实现用 this 作为构造器（支持子类），并通过 this.resolve 处理每一项；这个教学版本固定使用内建 Promise。
