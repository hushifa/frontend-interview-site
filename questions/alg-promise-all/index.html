怎样实现保持输入顺序的 Promise.all 教学版本？

Promise.all 接收一组输入，全部成功时按输入顺序返回结果数组，有一个失败就立刻失败。实现的关键是登记每一项时就记住它的下标，用计数器判断是不是全完成了，并用 Promise.resolve 统一处理普通值、Promise 和 thenable。

参考答案

简答

Promise.all 等所有输入都成功了，返回一个结果数组；只要有一个失败，就立刻用它的原因失败。

结果数组的顺序和输入顺序一致，跟谁先完成没关系。做法是每一项在登记的时候就记住自己的下标，完成以后写进 results[position]。每一项都用 Promise.resolve(item) 包一下，这样普通值、原生 Promise、带 then 方法的对象（也就是 thenable）都能统一处理。

什么时候算全部完成？用一个计数器 remaining，它从 1 开始，遍历结束后再减 1。这样空输入能正确返回 []，也不会因为前面的项早早完成，在遍历到一半时就提前兑现。

要注意，有一项失败时，其他已经开始的任务还会继续跑，Promise.all 没法取消它们。另外输入不一定是数组，Set、字符串、生成器这些可迭代对象都行，遍历过程中抛的错会让返回的 Promise 失败。

实现

JavaScript
function promiseAll(iterable) {
  return new Promise((resolve, reject) => {
    const results = [];
    let remaining = 1;
    let index = 0;

    for (const item of iterable) {
      const position = index++;
      remaining++;

      Promise.resolve(item).then((value) => {
        results[position] = value;
        if (--remaining === 0) resolve(results);
      }, reject);
    }

    if (--remaining === 0) resolve(results);
  });
}

const position = index++ 这一行很关键。每次循环都会创建一个新的 position，回调通过闭包记住的是自己那一份。所以不管哪个先完成，都会写回自己原来的位置。

下面让第二项先完成，看看结果的顺序：

JavaScript
let finishFirst;
let finishSecond;

const first = new Promise((resolve) => { finishFirst = resolve; });
const second = new Promise((resolve) => { finishSecond = resolve; });
const combined = promiseAll([first, second, 42]);

finishSecond('B');
finishFirst('A');
console.log(await combined);

虽然 B 先完成，输出仍然是 ['A', 'B', 42]。第三项 42 是个普通值，被 Promise.resolve 包成了一个已完成的 Promise。这个例子用了顶层 await，要在 ES 模块或者异步函数里运行。

几个读者常问的细节

为什么 remaining 要从 1 开始？ 多出来的这个 1，代表“遍历还没结束”。如果从 0 开始，会有两个问题。一是空输入时根本不进循环，remaining 一直是 0，可也没有任何回调会去调 resolve，结果永远不兑现。二是如果某一项在遍历过程中就完成了，计数可能提前归零。从 1 开始，遍历结束时再把这个 1 减掉，空输入在这一步就直接兑现了。

为什么要在 new Promise 的回调里遍历？ 因为这个回调里同步抛出的错误，会自动变成 Promise 的失败。所以传进来一个 null（不能遍历），或者生成器遍历到一半抛错了，返回的 Promise 会失败，而不是直接同步抛错给调用方。

为什么用 Promise.resolve，不直接调 item.then？ 普通值根本没有 then 方法。而且有些不规范的 thenable 可能会把回调调好几次，Promise.resolve 会把它转成一个只结算一次的原生 Promise。

reject 被调用好几次会怎样？ Promise 只会结算一次，后面的调用都被忽略。所以好几项都失败时，最终的原因是第一个被处理的那个失败。

和其他组合方法比一比

方法兑现条件拒绝条件
Promise.all全部兑现任一拒绝
Promise.allSettled全部结算（不论成功失败）不会拒绝
Promise.race第一个结算的是兑现第一个结算的是拒绝
Promise.any任一兑现全部拒绝，原因是 AggregateError

常见追问

Promise.all 能限制并发吗？

不能。传进来的 Promise 在创建的时候就已经开始执行了，Promise.all 只是在等结果。要限制并发，得传任务函数进去，见《怎样实现有明确失败语义的异步并发池？》。

这个版本和原生实现还有什么区别？

原生实现用 this 作为构造器，所以支持子类，每一项也是通过 this.resolve 处理的。这个教学版本固定用的是内建的 Promise。
