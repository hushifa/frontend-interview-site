CSS @scope 能解决哪些样式隔离问题？

@scope 把选择器限定在某个根元素的子树内，并可以用下限排除内部区域；它不增加优先级，冲突时按作用域根的远近决定胜负。

参考答案

简答

  • @scope (.card) to (.content) 只匹配 .card 内部、且不在 .content 内的元素，适合“组件样式不要漏进插槽内容”的场景。
  • 作用域内的普通选择器相当于前面加了 :where(:scope)，不增加优先级；显式写 :scope 会加一个类选择器的优先级。
  • 层叠时先比较重要性、层和优先级，再比较作用域根的远近（scoping proximity），最后才比较源码顺序。
  • 自 2026 年 3 月起 @scope 进入 Baseline，旧浏览器会整体忽略这条规则。
  • 它只限制选择器的匹配范围；Shadow DOM 则让外部选择器匹配不到影子树内的元素。

上限和下限

CSS
@scope (.card) to (.card-content) {
  img {
    border-radius: 8px;
  }

  :scope {
    padding: 16px;
  }
}

卡片自身的图片会有圆角，用户放进 .card-content 的图片不受影响。以前要做到这一点，通常靠 BEM 命名或更长的子选择器。

远近规则

CSS
@scope (.light) {
  p { color: black; }
}

@scope (.dark) {
  p { color: white; }
}
HTML
<div class="dark">
  <div class="light">
    <p>黑色文字</p>
  </div>
</div>

两条规则优先级相同，.light 离 <p> 只有一层，所以它胜出，即使 .dark 写在后面。若某条规则的优先级更高，它仍然会赢，远近只在优先级相同时起作用。

内联作用域

在 <style> 里直接写不带前导的 @scope，作用域根就是这个 <style> 的父元素：

HTML
<section>
  <style>
    @scope {
      h2 { font-size: 1.25rem; }
    }
  </style>
  <h2>只影响本区块的标题</h2>
</section>

和其他方案对比

  • CSS Modules 在构建时改写类名，任何浏览器都可用，但需要构建工具。
  • Shadow DOM 的封装更强，外部选择器默认匹配不到内部元素，但继承属性（如 color、font）和自定义属性仍会传入，代价是主题和全局样式需要通过自定义属性或 ::part 传入。
  • @scope 不需要构建，也不改变 DOM 结构，适合给普通 HTML 组件限定范围。

MDN 提示 @scope 内 & 的优先级在不同引擎和版本中有差异，依赖它的写法要查兼容表。

常见追问

  • @scope 和层叠层怎样配合？层先于优先级和远近比较，可以把组件样式放进 @layer components，再在层内用 @scope 限定范围。
