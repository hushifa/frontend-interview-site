CSS @scope 能解决哪些样式隔离问题？

@scope 让一段样式只在某个元素里面生效，还能把里面的某块区域排除掉。它不会提高优先级，两条规则打平时，离元素更近的作用域赢。

参考答案

简答

写卡片组件时，想给卡片里的图片加圆角，但用户放进卡片正文的图片不要受影响。@scope (.card) to (.card-content) 就能做到：只匹配 .card 里面、又不在 .card-content 里面的元素。

它不会提高优先级。作用域里的普通选择器，相当于前面加了 :where(:scope)，优先级不变；明确写出 :scope 才会加一个类选择器的优先级。

两条规则冲突时，先比重要性、层和优先级，都打平了，再比作用域根离元素有多近，这叫作用域远近（scoping proximity），最后才比源码顺序。

@scope 自 2026 年 3 月起进入 Baseline，旧浏览器会把整条规则忽略掉。另外它只是限制选择器的匹配范围，不像 Shadow DOM 那样让外部选择器完全匹配不到里面的元素。

上限和下限

CSS
@scope (.card) to (.card-content) {
  img {
    border-radius: 8px;
  }

  :scope {
    padding: 16px;
  }
}

.card 是上限，也就是作用域的根；.card-content 是下限，到这里就停。所以卡片自己的图片有圆角，用户放进 .card-content 的图片不受影响。:scope 指的就是作用域根 .card 本身。

以前要做到这一点，通常靠 BEM 命名，比如 .card__img，或者写更长的子选择器。

两个作用域打架时听谁的

CSS
@scope (.light) {
  p { color: black; }
}

@scope (.dark) {
  p { color: white; }
}
HTML
<div class="dark">
  <div class="light">
    <p>黑色文字</p>
  </div>
</div>

文字是黑色的。按以前的规则，两条优先级相同，后写的 .dark 应该赢，文字该是白色。

可是 @scope 多了一步比较：看谁的作用域根离 <p> 更近。.light 是 <p> 的父元素，只隔一层；.dark 隔了两层。所以 .light 赢，跟书写顺序无关。这正符合直觉，浅色区域里的文字就该按浅色主题来。

不过远近只在优先级打平时才起作用。如果某条规则的优先级更高，它还是会赢。

直接写在 style 标签里

在 <style> 里写不带括号的 @scope，作用域根就是这个 <style> 的父元素：

HTML
<section>
  <style>
    @scope {
      h2 { font-size: 1.25rem; }
    }
  </style>
  <h2>只影响本区块的标题</h2>
</section>

和 CSS Modules、Shadow DOM 怎么选

CSS Modules 在构建时改写类名，所有浏览器都能用，但需要构建工具。

Shadow DOM 隔离得最彻底，外面的选择器默认匹配不到里面的元素。不过 color、font 这类继承属性和自定义属性还是会传进去。代价是外部的全局类和元素选择器进不去，主题要靠继承属性、自定义属性或 ::part 传进去。

@scope 不需要构建，也不改变 DOM 结构，适合给普通的 HTML 组件限定样式范围。

还有一点：MDN 提示，@scope 里 & 的优先级在不同浏览器引擎和版本里不一样，依赖它的写法要先查兼容表。

常见追问

@scope 和层叠层怎么配合？

层的比较比优先级和远近都早。所以可以先把组件样式放进 @layer components，再在层里用 @scope 限定范围，层管先后，@scope 管范围。
