DataView 怎样读取指定字节序的二进制数据？

DataView 可以从一段二进制数据的任意位置读写数字，每次都能指定字节顺序，不指定就按大端。网络协议常用大端，所以解析协议时用它，并先检查长度够不够。

参考答案

简答

一个大于 1 字节的数字，比如 0x1234，存进内存时要拆成两个字节，先放高位还是先放低位，就叫字节序。先放高位是大端，先放低位是小端。

DataView 用 getUint16(offset, littleEndian) 这类方法，在任意字节位置读写数字，不要求位置对齐。第二个参数不传或者传 false 就按大端，传 true 按小端。

为什么要用它？因为 TypedArray 只能按当前平台的字节序读写，主流平台都是小端，而网络协议和很多文件格式用的是大端。解析这类数据，就得用 DataView 明确指定。

要注意，读取超过视图末尾会抛 RangeError，所以解析前先检查 byteLength。另外 ES2025 新增了 Float16Array、getFloat16、setFloat16 和 Math.f16round，MDN 标注为 Baseline 2025。

大端和小端读出来有什么不同

先按大端写入 0x1234，再看看字节怎么排，以及按两种字节序读回来的结果。

JavaScript
const buffer = new ArrayBuffer(2);
const view = new DataView(buffer);
view.setUint16(0, 0x1234); // 未传 littleEndian，按大端写入

console.log(new Uint8Array(buffer).join(',')); // 18,52
console.log(view.getUint16(0)); // 4660，也就是 0x1234
console.log(view.getUint16(0, true)); // 13330，也就是 0x3412

逐个字节看，是 18 和 52，也就是 0x12 和 0x34。大端把高位字节 0x12 放在前面，低位 0x34 放在后面。

同样两个字节，按大端读回来是 4660，就是原来的 0x1234。按小端读，会把第一个字节当成低位，得到 0x3412，也就是 13330。所以字节序读错了，数字就全错了，而且不会报错。

怎样解析一个协议头

假设协议头是这样的：1 字节版本号，1 字节类型，再跟着 4 字节、大端的无符号长度。

JavaScript
function parseHeader(buffer) {
  const view = new DataView(buffer);
  if (view.byteLength < 6) throw new RangeError('协议头不完整');

  const header = {
    version: view.getUint8(0),
    type: view.getUint8(1),
    length: view.getUint32(2),
  };
  if (view.byteLength < 6 + header.length) throw new RangeError('消息体不完整');
  return header;
}

长度字段从第 2 个字节开始，不是 4 的倍数，TypedArray 的视图要求按元素大小对齐，这里就用不了，而 DataView 可以从任意位置读。getUint32(2) 不传第二个参数，正好按大端读。读之前先检查长度够不够 6 字节，读完头部再检查消息体是不是完整。

解析时还有几个细节。getInt* 和 getUint* 对同样的字节理解不同，0xff 用 getUint8 读是 255，用 getInt8 读是 -1。64 位整数用 getBigUint64 或 getBigInt64，返回的是 BigInt。另外，从一个 Uint8Array 创建视图时，要带上它的偏移和长度：new DataView(u8.buffer, u8.byteOffset, u8.byteLength)。只传 u8.buffer 的话，视图会覆盖整个底层缓冲区，读到的位置就错了。

Float16 是做什么的

半精度浮点数只占 2 个字节，精度低但省空间，用在 WebGPU、机器学习模型权重这类要节省带宽的地方。

JavaScript
if (typeof Float16Array === 'function') {
  const half = new Float16Array([1.1]);
  console.log(half[0]); // 1.099609375，半精度只有约 3 位有效数字
}

存进去的是 1.1，读出来却是 1.099609375，因为半精度只有大约 3 位有效数字。Node.js 22 还没有 Float16Array，所以用之前要先像上面这样检测一下。

常见追问

怎样判断当前平台是不是小端？

写一个 Uint16Array([1])，再按字节看它的第一个字节。new Uint8Array(new Uint16Array([1]).buffer)[0] === 1 为真，说明低位放在前面，就是小端。

二进制里的文本怎么读？

用 TextDecoder：new TextDecoder('utf-8').decode(new Uint8Array(buffer, offset, length))，先截出文本所在的那段字节，再解码。
