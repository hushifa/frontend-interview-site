Vue 2 响应式有哪些限制？如何绕过？

Vue 2 只能在初始化时给已有属性装上监听，所以新加或删掉对象属性、用下标改数组、改数组长度，它都发现不了。绕过办法是 Vue.set、Vue.delete 和 splice。

参考答案

Vue 2 已于 2023-12-31 停止维护，本题以 Vue 2.7 为准。

简答

Vue 2 的响应式靠 Object.defineProperty，在初始化时给每个已经存在的属性装上 getter 和 setter。所以初始化之后新加的属性、被删掉的属性，它都检测不到。

数组也有两个盲区：items[i] = v 用下标赋值，和 items.length = n 改长度，都不会触发更新。

绕过的办法是用 Vue 提供的 API。新增属性用 Vue.set 或 vm.$set，删除用 Vue.delete，它们会把新属性变成响应式并通知更新，但都不能用在 Vue 实例或根级 $data 上。数组改下标或截断用 splice。

那为什么 push 能触发更新？因为 Vue 2 替换了响应式数组的原型，push、pop、shift、unshift、splice、sort、reverse 这 7 个方法被包了一层，执行完原方法后会通知更新，还会把新插入的元素也变成响应式。

对象的新增和删除属性

官方文档说明，Vue 在实例初始化时做 getter/setter 转换，属性必须一开始就在 data 里才是响应式的。Vue 也不允许在已创建的实例上动态添加根级响应式属性，需要的话应该在 data 里预先声明，可以先设成空值。

JavaScript
Vue.set(vm.user, 'age', 18); // 或 this.$set(this.user, 'age', 18)
Vue.delete(vm.user, 'age'); // 或 this.$delete(...)

// 一次加多个属性：用新对象替换，而不是 Object.assign 到原对象
this.user = Object.assign({}, this.user, { a: 1, b: 2 });

为什么一次加多个属性要换成新对象？因为 Object.assign(this.user, {...}) 是在原对象上直接加属性，跟 this.user.a = 1 一样检测不到。而 this.user = 新对象 是给 user 这个已有属性赋值，会经过它的 setter，新对象也会被转成响应式。

set 在源码里分几种情况处理：

  • 属性已经存在：直接赋值后返回，由原有的 setter 负责通知。
  • 目标不是响应式对象（没有 __ob__）：只赋值，不通知。
  • 目标是 Vue 实例或根 $data（ob.vmCount > 0）：开发环境警告并返回。
  • 其他情况：用 defineReactive 定义新属性，再调用 ob.dep.notify()。这个 dep 就是读取这个对象时，由 childOb.dep.depend() 收集的依赖。

数组的下标和 length

JavaScript
vm.items[1] = 'x'; // 不是响应式
vm.items.length = 2; // 不是响应式

Vue.set(vm.items, 1, 'x'); // 或 vm.items.splice(1, 1, 'x')
vm.items.splice(2); // 截断数组

为什么数组下标检测不到？因为 Vue 2 没有给数组的每个下标定义 getter/setter。length 更特殊，它本身是不可配置的属性，没法用 defineProperty 改成访问器。所以对数组下标，Vue.set 内部是先扩展 length，再调用 target.splice(key, 1, val)，靠被拦截的 splice 来触发更新。

7 个方法是怎么被拦截的

array.ts 以 Array.prototype 为原型创建了一个 arrayMethods 对象，在上面为 7 个方法定义包装函数。每个包装函数做三件事：

  1. 调用原来的方法，拿到结果。
  2. 找出新插入的元素：push、unshift 的全部参数，splice 从第 3 个起的参数。调用 ob.observeArray(inserted) 把它们变成响应式。
  3. 调用 ob.dep.notify()，通知依赖这个数组的 Watcher。

Observer 处理数组时，把数组的原型换成 arrayMethods；环境不支持 __proto__ 时，就把这些方法逐个定义到数组上。

filter、concat、slice 这类返回新数组的方法不会被拦截，用返回值替换原数组就行。官方文档说明 Vue 会尽量复用已有的 DOM，所以替换数组并不会导致整个列表重新渲染。

实际跑一下

下面先用三种检测不到的方式修改，再用 $set 和 splice 修改，看 watcher 的回调有没有被触发：

JavaScript
// 用 Node 运行，vue@2.7.16
const Vue = require('vue');
const vm = new Vue({ data: { user: { name: 'a' }, items: ['a', 'b', 'c'] } });
const log = [];
vm.$watch(() => JSON.stringify(vm.user), (v) => log.push('user:' + v));
vm.$watch(() => vm.items.join(), (v) => log.push('items:' + v));

vm.user.age = 1;
vm.items[1] = 'x';
vm.items.length = 2;
Vue.nextTick(() => {
  console.log(log); // []，三次修改都未被检测到
  vm.$set(vm.user, 'city', 'x');
  vm.items.splice(1, 1, 'y');
  Vue.nextTick(() => console.log(log));
  // [ 'user:{"name":"a","age":1,"city":"x"}', 'items:a,y' ]
});

第一次打印是空数组，三次修改都没被发现。第二次打印出了两条记录，而且 user 里也有 age: 1。这说明之前的修改其实已经写进对象了，只是 Vue 不知道；$set 触发重新计算时，才一起读到。

items 是 a,y 也是同样的道理：length = 2 当时已经把数组截断成了 ['a', 'x']，只是没有通知，splice 再把第二项换成 y。

常见追问

age 已经用普通赋值加上了，再用 this.$set(this.user, 'age', 2) 为什么还是不更新？

因为属性已经存在时，set 只做普通赋值。而这个 age 是普通赋值加上的，没有 setter，赋值了也不会通知。

Vue 3 还有这些限制吗？

没有了，见《defineProperty 和 Proxy 实现的响应式有什么区别？》。
