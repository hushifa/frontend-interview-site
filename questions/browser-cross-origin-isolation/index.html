crossOriginIsolated 为 true 需要哪些条件？

页面同时返回 COOP same-origin 和 COEP require-corp（或 credentialless）两个响应头，并且没被 Permissions-Policy 禁用，crossOriginIsolated 才是 true，这时才能用 SharedArrayBuffer。

参考答案

简答

想在页面里用 SharedArrayBuffer，先得让 crossOriginIsolated 变成 true，也就是让页面处于“跨源隔离”状态。条件是文档响应同时带两个头：Cross-Origin-Opener-Policy: same-origin，和 Cross-Origin-Embedder-Policy: require-corp 或 credentialless。另外 Permissions-Policy 不能禁用 cross-origin-isolated，而且这两个头只在 HTTPS 或 localhost 下生效。

为什么要这么麻烦？因为共享内存能做出很精确的计时器，配合 Spectre 这类侧信道攻击，能读到同一进程里的其他数据。隔离就是保证进程里没有别的源的敏感数据。

满足条件后，除了 SharedArrayBuffer，还能用 performance.measureUserAgentSpecificMemory()，performance.now() 的精度也会更高。

落地时要注意副作用：COOP 会切断和跨源弹窗的联系，第三方登录、支付弹窗可能失效；COEP 会挡住没有授权的第三方资源。

两个头各管什么

COOP 管的是窗口关系。设成 same-origin 以后，本页和跨源窗口不会再放在同一个浏览上下文组里。通俗点说，本页用 window.open 打开一个跨源页面，或者被跨源页面打开，对方拿到的 window.opener 都是 null。攻击页面拿不到本页的窗口引用，就没法和本页共享进程。

COEP 管的是页面能嵌入哪些跨源资源。它有两个可选值。require-corp 比较严：跨源资源要么带 Cross-Origin-Resource-Policy: cross-origin 头，要么通过 CORS 加载（标签上加 crossorigin），否则就被挡住。credentialless 宽松一些：跨源的 no-cors 请求不带 Cookie 等凭据，资源不需要额外的头。第三方资源不归你管的时候，credentialless 更容易落地。

配置好以后怎么用

响应头这样写：

http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: credentialless

代码里先检查再用，不满足就退回普通的 ArrayBuffer：

JavaScript
if (crossOriginIsolated) {
  const shared = new SharedArrayBuffer(1024);
  worker.postMessage(shared);
} else {
  console.warn('页面未处于跨源隔离状态，回退到普通 ArrayBuffer');
}

为什么要检查？因为头配错一个、或者被 Permissions-Policy 禁用，crossOriginIsolated 就是 false。即使两个头都正确，cross-origin-isolated 被禁用时结果仍然是 false。

上线时会碰到哪些问题

最常见的是第三方登录和支付弹窗。它们靠 window.opener 把结果传回来，COOP same-origin 一开，这条路就断了。办法是把登录放在不需要隔离的页面上，或者改用重定向流程。

第二个是第三方图片、脚本、iframe 被挡。require-corp 下，没有 CORP 头的资源都加载不了。可以改用 credentialless，或者给资源加 crossorigin，让对方返回 CORS 头。嵌入的跨源 iframe 本身也要满足 COEP 的要求。

为了不在上线时才发现问题，可以先发 Cross-Origin-Embedder-Policy-Report-Only，它只报告会被挡住的资源，不真的挡。

常见追问

为什么要跨源隔离才能用 SharedArrayBuffer？

共享内存可以做出高精度计时器，配合 Spectre 类侧信道攻击，能读到同一进程里的其他数据。跨源隔离保证进程里没有别的源的敏感数据，浏览器才敢开放这个能力。

两个头都配对了，crossOriginIsolated 还是 false，可能是什么原因？

先看是不是 HTTPS 或 localhost，这两个头只在安全上下文里生效。再看 Permissions-Policy 有没有禁用 cross-origin-isolated，被禁用时结果也是 false。
