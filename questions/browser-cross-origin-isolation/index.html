crossOriginIsolated 为 true 需要哪些条件？

顶层文档同时返回 COOP same-origin 和 COEP require-corp（或 credentialless），且没有被 Permissions-Policy 禁用时，crossOriginIsolated 为 true，页面才能使用 SharedArrayBuffer 等能力。

参考答案

简答

  • 文档响应头要有 Cross-Origin-Opener-Policy: same-origin。
  • 同时要有 Cross-Origin-Embedder-Policy: require-corp 或 credentialless。
  • Permissions-Policy 没有禁用 cross-origin-isolated。COOP 和 COEP 头只在安全上下文（HTTPS 或 localhost）下生效。
  • 满足后可以使用 SharedArrayBuffer、performance.measureUserAgentSpecificMemory()，performance.now() 的精度也更高。

两个头各管什么

COOP（Cross-Origin-Opener-Policy）：same-origin 让本页和跨源窗口不在同一个浏览上下文组里。跨源的 window.open 打开者或被打开者拿到的 window.opener 为 null，攻击页面就无法通过窗口引用和本页共享进程。

COEP（Cross-Origin-Embedder-Policy）：限制页面能加载哪些跨源子资源。

  • require-corp：跨源资源必须带 Cross-Origin-Resource-Policy: cross-origin，或通过 CORS 加载（crossorigin 属性），否则被阻止。
  • credentialless：跨源的 no-cors 请求不带 Cookie 等凭据，资源不需要额外的头。第三方资源不受控时更容易落地。

配置示例

http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: credentialless
JavaScript
if (crossOriginIsolated) {
  const shared = new SharedArrayBuffer(1024);
  worker.postMessage(shared);
} else {
  console.warn('页面未处于跨源隔离状态，回退到普通 ArrayBuffer');
}

落地时的问题

  • 第三方登录弹窗和支付弹窗：COOP same-origin 会切断与跨源弹窗的 window.opener 通信。可以把登录页放在不需要隔离的页面上，或者改用重定向流程。
  • 第三方图片、脚本、iframe：require-corp 下没有 CORP 头的资源会被阻止，可以改用 credentialless，或给资源加 crossorigin 并由对方返回 CORS 头。
  • iframe 嵌入：被嵌入的跨源 iframe 本身也要满足 COEP 的要求。
  • 上线前：先用 Cross-Origin-Embedder-Policy-Report-Only 收集会被阻止的资源。

常见追问

  • 为什么需要隔离才能用 SharedArrayBuffer：共享内存能做出高精度计时器，配合 Spectre 类侧信道读取同进程数据，隔离保证进程里没有跨源的敏感数据。
  • Permissions-Policy 可以禁用这项能力：即使两个头都正确，cross-origin-isolated 被禁用时结果仍是 false。
