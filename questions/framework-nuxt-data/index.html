Nuxt 的 useFetch 和 useAsyncData 怎样避免重复请求？

服务端渲染时请求到的数据会写进页面 payload，客户端 hydration 时直接复用，不再请求一次。相同 key 的调用共享同一份 data、error 和 status。Nuxt 4 中 data 默认是 shallowRef、初始值是 undefined，共享 key 的调用要使用一致的 handler、transform 等选项。

参考答案

简答

用户第一次打开页面时，useFetch 或 useAsyncData 在服务端执行，拿到的数据会被序列化，放进页面里一起发给浏览器，这份数据叫 payload。客户端 hydration 时直接读 payload，所以不会再请求一遍。之后在客户端导航到这个页面，请求才在浏览器里发。

数据是按 key 存的。useFetch 会根据 URL 和选项自动生成 key，useAsyncData 建议自己传 key。相同 key 的调用共享同一份 data、error 和 status。

Nuxt 4 有两个默认值要记住：data 和 error 初始是 undefined；deep 默认是 false，也就是 data 是 shallowRef，改它内部的属性不会触发更新。

另外，共享同一个 key 的几处调用，handler、deep、transform、pick、getCachedData、default、middleware 这些选项要保持一致，不一致开发环境会警告。

先看基本用法

下面是一个文章详情页，根据路由参数请求文章。

vue
<script setup lang="ts">
const route = useRoute();

const { data: post, status, error, refresh } = await useFetch(
  () => `/api/posts/${route.params.id}`,
  { pick: ['id', 'title', 'body'] },
);
</script>

<template>
  <p v-if="status === 'pending'">加载中…</p>
  <p v-else-if="error">加载失败：{{ error.message }}</p>
  <article v-else-if="post">
    <h1>{{ post.title }}</h1>
    <div>{{ post.body }}</div>
  </article>
</template>

URL 写成了一个函数，而不是直接拼好的字符串。这样路由参数变了，useFetch 能感知到并自动重新请求。pick 只保留需要的三个字段，因为 payload 会跟着 HTML 发给浏览器，字段越少页面越小。

为什么不会重复请求

如果在组件里直接调用请求函数，服务端渲染时执行一次，客户端 hydration 时组件再执行一次，接口就被打了两遍。useFetch 的做法是：服务端请求完，把结果按 key 存进 payload；客户端执行到同一个调用时，先按 key 去 payload 里找，找到了就直接用。

所以 key 很重要。两处调用 key 一样，就会拿到同一份数据；这也是为什么共享 key 的调用选项必须一致，否则两处对“这份数据长什么样”的理解就不一样了。

status 有哪些取值

值含义
idle还没执行，例如设置了 immediate: false，或 server: false 时的服务端渲染阶段
pending请求中
success成功
error失败

用了 immediate: false 时，请求不会马上发，状态停在 idle。模板如果只处理了 pending、error 和有数据三种情况，这时就会什么都不显示，所以要记得处理 idle。

常用选项

  • lazy: true：不阻塞导航，先渲染页面再加载数据，需要自己显示加载状态。
  • server: false：只在客户端请求，适合依赖浏览器信息或不需要 SEO 的数据。
  • watch: [source]：额外指定变化时重新请求的来源。
  • dedupe：已经有请求在进行，又被触发一次时怎么办。默认 'cancel' 取消旧请求，'defer' 则复用进行中的请求。
  • getCachedData(key, nuxtApp)：自定义缓存读取，返回非空值时跳过请求。

在别的组件里读同一份数据

既然数据按 key 存，别处也可以按 key 拿：

TypeScript
const { data } = useNuxtData('post-42');

比如列表页已经加载过这篇文章，详情页可以先把缓存显示出来，再去刷新。

权限边界要注意什么

服务端请求时，useFetch 调用自己的内部 API 会转发一部分请求头，但调用第三方接口不会自动带上 cookie。/server/api 里的接口仍然要自己校验身份，不能因为是“服务端调用”就放松。

还有一点，payload 里的数据最终会发到浏览器，任何人打开页面源码都能看到。所以不要把敏感字段放进去，这也是要用 pick 精简字段的另一个原因。

常见追问

useFetch 和 $fetch 有什么区别？

$fetch 只是一个请求函数。在组件里直接调用，服务端和客户端会各请求一次。useFetch 在它外面加了 payload 复用和状态管理。所以渲染要用的数据用 useFetch，点击按钮提交数据这种事件处理里用 $fetch。

为什么改了 data.value.title，界面没变？

因为 Nuxt 4 里 data 默认是 shallowRef，只有整体替换才会触发更新。要么写 data.value = { ...data.value, title }，要么在选项里设置 deep: true。
