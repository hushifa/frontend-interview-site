Nuxt 的 useFetch 和 useAsyncData 怎样避免重复请求？

服务端渲染时请求的数据会写进页面 payload，客户端 hydration 时直接复用，不再请求一次。相同 key 的调用共享同一份 data、error 和 status。Nuxt 4 中 data 默认是 shallowRef、初始值是 undefined，共享 key 的调用必须使用一致的 handler、transform 等选项。

参考答案

简答

  • 首次访问页面时，useAsyncData / useFetch 在服务端执行，结果序列化进 payload；客户端 hydration 时读取 payload，不重复请求。
  • 之后在客户端导航到该页面，请求在浏览器中执行。
  • 数据按 key 存储：useFetch 根据 URL 和选项自动生成 key，useAsyncData 推荐显式传 key。相同 key 的调用共享 data、error、status。
  • Nuxt 4 的默认值：data 和 error 初始为 undefined；deep 默认 false，即 data 是 shallowRef，修改内部属性不会触发更新。
  • 共享同一 key 的调用，handler、deep、transform、pick、getCachedData、default、middleware 必须一致，否则开发环境会警告。

基本用法

vue
<script setup lang="ts">
const route = useRoute();

const { data: post, status, error, refresh } = await useFetch(
  () => `/api/posts/${route.params.id}`,
  { pick: ['id', 'title', 'body'] },
);
</script>

<template>
  <p v-if="status === 'pending'">加载中…</p>
  <p v-else-if="error">加载失败：{{ error.message }}</p>
  <article v-else-if="post">
    <h1>{{ post.title }}</h1>
    <div>{{ post.body }}</div>
  </article>
</template>
  • URL 写成 getter，路由参数变化时自动重新请求。
  • pick 只保留需要的字段，减少 payload 体积。

status 的取值

值含义
idle还没执行，例如设置了 immediate: false，或 server: false 时的服务端渲染阶段
pending请求中
success成功
error失败

使用 immediate: false 时，模板要处理 idle 状态，否则页面会显示空白。

常用选项

  • lazy: true：不阻塞导航，先渲染页面再加载数据，需要自己显示加载状态。
  • server: false：只在客户端请求，适合依赖浏览器信息或不需要 SEO 的数据。
  • watch: [source]：额外指定变化时重新请求的来源。
  • dedupe：已有请求进行中又被触发时的策略，默认 'cancel' 取消旧请求，'defer' 则复用进行中的请求。
  • getCachedData(key, nuxtApp)：自定义缓存读取，返回非空值时跳过请求。

在别处读取同一份数据

TypeScript
const { data } = useNuxtData('post-42');

例如列表页已经加载过文章，详情页可以先显示缓存，再刷新。

权限边界

服务端请求时，useFetch 调用内部 API 会转发部分请求头，但调用第三方接口不会自动带 cookie。/server/api 中的接口仍需自己校验身份，payload 中的数据会被发送到浏览器，不要放入敏感字段。

常见追问

  • useFetch 和 $fetch 的区别？$fetch 只是请求函数，在组件中直接调用会在服务端和客户端各请求一次；useFetch 负责 payload 复用和状态管理。事件处理器中提交数据用 $fetch。
  • 为什么修改 data.value.title 界面没变？Nuxt 4 默认 shallowRef，整体替换 data.value = {...}，或设置 deep: true。
