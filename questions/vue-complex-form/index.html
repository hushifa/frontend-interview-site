Vue 复杂表单怎样组织状态、校验和提交？

复杂表单要把编辑中的草稿、已保存的基线和提交过程分开管理。错误在失焦或提交后才显示，提交期间防止重复提交，失败保留草稿，成功后以服务端返回的数据作为新基线。

参考答案

简答

  • 分开三类状态：draft（正在编辑）、baseline（上次保存的值，用于判断是否修改、支持重置）、提交状态（pending、服务端错误）。
  • 校验结果用 computed 从草稿推导，不单独存储；错误在字段失焦或尝试提交后才显示。
  • 提交期间禁用按钮并在函数入口检查 pending，防止重复提交。
  • 提交失败时保留草稿，把服务端返回的字段错误显示在对应字段旁边。
  • 提交成功后用服务端返回的记录更新草稿和基线，因为服务端可能做了规范化。

示例

vue
<script setup>
import { computed, reactive, ref } from 'vue';

const baseline = reactive({ name: '', seats: '1' });
const draft = reactive({ ...baseline });
const touched = reactive({ name: false, seats: false });
const attempted = ref(false);
const pending = ref(false);
const serverErrors = reactive({ name: '', form: '' });

const errors = computed(() => ({
  name: draft.name.trim() ? '' : '请输入姓名',
  seats: /^[1-9]$/.test(draft.seats) ? '' : '人数请输入 1 到 9 的整数',
}));
const visibleError = (field) =>
  (touched[field] || attempted.value) && (errors.value[field] || serverErrors[field]);
const dirty = computed(() => draft.name !== baseline.name || draft.seats !== baseline.seats);

async function submit() {
  if (pending.value) return;
  attempted.value = true;
  serverErrors.name = serverErrors.form = '';
  if (errors.value.name || errors.value.seats) return;

  pending.value = true;
  try {
    const result = await save({ name: draft.name.trim(), seats: Number(draft.seats) });
    if (!result.ok) {
      serverErrors.name = result.fieldErrors?.name ?? '';
      serverErrors.form = result.message ?? '保存失败';
      return;
    }
    Object.assign(draft, { name: result.record.name, seats: String(result.record.seats) });
    Object.assign(baseline, draft);
    attempted.value = touched.name = touched.seats = false;
  } finally {
    pending.value = false;
  }
}

function reset() {
  Object.assign(draft, baseline);
  serverErrors.name = serverErrors.form = '';
}
</script>

<template>
  <form novalidate @submit.prevent="submit">
    <label for="name">姓名</label>
    <input id="name" v-model="draft.name" :aria-invalid="!!visibleError('name')"
      aria-describedby="name-error" @blur="touched.name = true" @input="serverErrors.name = ''" />
    <p id="name-error">{{ visibleError('name') }}</p>

    <label for="seats">人数</label>
    <input id="seats" v-model="draft.seats" inputmode="numeric" :aria-invalid="!!visibleError('seats')"
      aria-describedby="seats-error" @blur="touched.seats = true" />
    <p id="seats-error">{{ visibleError('seats') }}</p>

    <p v-if="serverErrors.form" role="alert">{{ serverErrors.form }}</p>
    <button :disabled="pending">{{ pending ? '保存中…' : '保存' }}</button>
    <button type="button" :disabled="!dirty || pending" @click="reset">重置</button>
  </form>
</template>

要点：

  • 人数在草稿中保持字符串，提交时才转成数字，避免用户删空输入框时变成 0。
  • 字段级的服务端错误（如"姓名已被占用"）放在对应字段下，用户修改姓名时清除；与字段无关的错误放在表单级提示里。
  • 重置回到基线，而不是清空。

异步校验

检查用户名是否可用这类异步校验，要丢弃过期的结果：

JavaScript
import { watch, onWatcherCleanup } from 'vue';

watch(() => draft.name, async (name) => {
  if (!name.trim()) return; // 空值交给必填校验，不发请求
  const controller = new AbortController();
  onWatcherCleanup(() => controller.abort()); // Vue 3.5 起可用
  try {
    const res = await fetch(`/api/check-name?q=${encodeURIComponent(name)}`, { signal: controller.signal });
    serverErrors.name = (await res.json()).taken ? '姓名已被占用' : '';
  } catch (err) {
    if (err.name !== 'AbortError') throw err;
  }
});

用户继续输入时，上一次请求被取消，不会用旧结果覆盖新输入。实际使用时再加上防抖。

何时用表单库

字段多、动态增删字段、跨字段校验复杂时，可以用 VeeValidate、FormKit 等库，配合 Zod 这类 schema 统一前后端校验规则。上面的状态划分仍然适用，库只是帮你实现了它。

常见追问

  • 离开页面时提醒未保存？用 dirty 判断，在路由守卫或 beforeunload 中提示。
  • 为什么不在 watch 里同步草稿和基线？两份数据相互复制容易产生循环和覆盖，基线只在保存成功时更新。
