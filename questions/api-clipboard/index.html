异步 Clipboard API 为什么会出现权限或用户激活错误？

navigator.clipboard 只在安全上下文中可用；写入通常要求用户激活，读取需要权限或用户确认，页面不在焦点、iframe 未授权时都会被拒绝。

参考答案

简答

  • navigator.clipboard 只在 HTTPS 或 localhost 下存在。
  • writeText() 一般要在点击等用户操作中调用，否则可能被拒绝；页面没有焦点时也会失败。
  • readText() 涉及隐私，Chromium 会请求 clipboard-read 权限，Firefox 和 Safari 会在页面上显示粘贴确认。
  • 在 iframe 里使用要由父页面授权：<iframe allow="clipboard-read; clipboard-write">。
  • 写入失败要给用户手动复制的降级方式。

复制按钮

JavaScript
copyButton.addEventListener('click', async () => {
  try {
    await navigator.clipboard.writeText(codeBlock.textContent);
    showToast('已复制');
  } catch (error) {
    selectText(codeBlock);
    showToast('复制失败，请按 Ctrl+C 手动复制');
  }
});

await 之后再调用 writeText() 时，用户激活可能已经过期，例如先等待网络请求再复制。需要先请求数据的场景，可以传入 Promise 给 ClipboardItem：

JavaScript
button.addEventListener('click', () => {
  const item = new ClipboardItem({
    'text/plain': fetch('/api/share-link').then((r) => r.text()).then((t) => new Blob([t], { type: 'text/plain' })),
  });
  return navigator.clipboard.write([item]);
});

write() 在点击处理函数中同步调用，数据随后到达。

读取剪贴板

更推荐监听 paste 事件，从 event.clipboardData 读取用户主动粘贴的内容，不需要额外权限：

JavaScript
editor.addEventListener('paste', (event) => {
  const files = [...event.clipboardData.files];
  if (files.length > 0) {
    event.preventDefault();
    uploadImages(files);
  }
});

常见错误

错误原因
navigator.clipboard 是 undefined页面不是安全上下文
NotAllowedError没有用户激活、页面不在焦点或权限被拒绝
iframe 中失败父页面没有通过 allow 授权

写入图片等富格式时，image/png 支持较好，其他格式支持情况因浏览器而异，可以用 ClipboardItem.supports(type) 检测。
