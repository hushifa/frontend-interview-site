异步 Clipboard API 为什么会出现权限或用户激活错误？

剪贴板里可能有密码等隐私，所以浏览器管得很严：只在 HTTPS 或 localhost 下能用，写入一般要在用户点击里调用，读取要用户授权或确认。

参考答案

简答

做“复制”按钮时，经常遇到 navigator.clipboard 是 undefined，或者调用时抛 NotAllowedError。原因是剪贴板里可能有用户的密码、隐私，浏览器不让网页随便碰。

第一道限制是安全上下文，navigator.clipboard 只在 HTTPS 或 localhost 下存在。第二道是用户激活，也就是“用户刚刚点了一下”，writeText() 一般要在点击这类操作里调用，页面没有焦点也会失败。读取更严，Chromium 会请求 clipboard-read 权限，Firefox 和 Safari 会在页面上显示粘贴确认。

在 iframe 里用，还要父页面用 allow="clipboard-read; clipboard-write" 授权。

实际开发中有两点。一是先 await 网络请求再复制，用户激活可能已经过期，可以把 Promise 交给 ClipboardItem。二是写入失败要给用户手动复制的办法。读取用户粘贴的内容，更推荐监听 paste 事件。

写一个复制按钮

下面是一个带降级的复制按钮，失败时选中文本，提示用户自己按快捷键。

JavaScript
copyButton.addEventListener('click', async () => {
  try {
    await navigator.clipboard.writeText(codeBlock.textContent);
    showToast('已复制');
  } catch (error) {
    selectText(codeBlock);
    showToast('复制失败，请按 Ctrl+C 手动复制');
  }
});

这里 writeText() 是在点击处理函数里直接调用的，用户激活还有效，所以一般能成功。失败的情况多半是页面不在焦点，或者浏览器策略拒绝了，所以 catch 里一定要有退路。

为什么先请求数据再复制会失败

用户激活，指的是浏览器记录“用户刚刚操作过”，它只在操作后的一小段时间里有效。如果点击后先 await fetch(...) 等分享链接回来，再调用 writeText()，这时激活可能已经过期，就会被拒绝。

改法是在点击里同步调用 write()，数据用 Promise 的形式交给 ClipboardItem，等它自己到达：

JavaScript
button.addEventListener('click', () => {
  const item = new ClipboardItem({
    'text/plain': fetch('/api/share-link').then((r) => r.text()).then((t) => new Blob([t], { type: 'text/plain' })),
  });
  return navigator.clipboard.write([item]);
});

write() 是在点击处理函数中同步调用的，浏览器认这次操作，数据随后到达也没关系。

读取剪贴板，优先用 paste 事件

readText() 要权限或确认，体验不好。更推荐的做法是监听 paste 事件，用户自己按了粘贴，从 event.clipboardData 里读，不需要额外权限：

JavaScript
editor.addEventListener('paste', (event) => {
  const files = [...event.clipboardData.files];
  if (files.length > 0) {
    event.preventDefault();
    uploadImages(files);
  }
});

这样能拿到用户粘贴的图片文件，比如截图直接粘进编辑器上传。

遇到错误怎么排查

如果 navigator.clipboard 是 undefined，说明页面不是安全上下文，先检查是不是 HTTPS 或 localhost。如果抛 NotAllowedError，原因是没有用户激活、页面不在焦点，或者权限被拒绝。如果只在 iframe 中失败，多半是父页面没有通过 allow 授权。

写入图片等富格式时，image/png 支持较好，其他格式各浏览器不一样，可以先用 ClipboardItem.supports(type) 检测。

常见追问

为什么 localhost 能用，部署到内网 HTTP 地址就不能用了？

因为 localhost 被当作安全上下文，普通 HTTP 地址不是。navigator.clipboard 只在安全上下文中存在，所以内网 HTTP 地址上它是 undefined，要换成 HTTPS。

怎样读取用户粘贴的图片？

监听 paste 事件，从 event.clipboardData.files 里拿文件。这是用户主动粘贴，不需要申请读取权限。
