Vue Suspense 适合处理什么异步组件边界？

Suspense 在子树中的异步依赖（顶层有 await 的 setup、异步组件）全部完成前显示 fallback 插槽。它不追踪组件里普通的 fetch 调用，自身不处理错误，并且在 Vue 文档中仍标为实验性功能。

参考答案

简答

  • <Suspense> 有 #default 和 #fallback 两个插槽，默认内容中的异步依赖都解析完之前显示 fallback。
  • 能被等待的异步依赖有两种：<script setup> 中有顶层 await 的组件，以及 defineAsyncComponent 创建的异步组件。
  • 在 onMounted 或普通函数中发起的请求不会被 Suspense 追踪。
  • Suspense 不捕获错误，用父组件的 onErrorCaptured 或错误边界组件处理异步 setup 的失败。
  • 首次解析之后，只有 #default 的根节点被替换时才会重新进入等待；timeout 属性控制等待多久后才切换到 fallback。

示例

vue
<!-- UserProfile.vue -->
<script setup>
const props = defineProps({ id: Number });
const res = await fetch(`/api/users/${props.id}`);
if (!res.ok) throw new Error('用户加载失败');
const user = await res.json();
</script>

<template>
  <h2>{{ user.name }}</h2>
</template>
vue
<!-- Page.vue -->
<script setup>
import { onErrorCaptured, ref } from 'vue';
import UserProfile from './UserProfile.vue';

const error = ref(null);
onErrorCaptured((err) => {
  error.value = err;
  return false; // 不再向上传播
});
</script>

<template>
  <p v-if="error" role="alert">{{ error.message }}</p>
  <Suspense v-else>
    <UserProfile :id="1" />
    <template #fallback>
      <p>加载中…</p>
    </template>
  </Suspense>
</template>

页面中有多个异步子组件时，它们共用一个 fallback，全部完成后一起显示。

再次进入等待

vue
<Suspense timeout="200">
  <component :is="currentTab" />
  <template #fallback><Spinner /></template>
</Suspense>

切换 currentTab 时根节点被替换，Suspense 重新等待。在 timeout 时间内完成就直接显示新内容，超过才显示 fallback，避免快速加载时闪一下 loading。等待期间旧内容继续显示。

和路由、KeepAlive 嵌套

vue
<RouterView v-slot="{ Component }">
  <KeepAlive>
    <Suspense>
      <component :is="Component" />
      <template #fallback>加载中…</template>
    </Suspense>
  </KeepAlive>
</RouterView>

官方推荐的嵌套顺序是 RouterView → Transition → KeepAlive → Suspense。

不用 Suspense 的做法

很多项目在组件内部用状态管理 loading 和 error，或用 Nuxt 的 useAsyncData、TanStack Query 这类工具。这样不依赖实验性 API，但每个组件要自己显示加载状态。

常见追问

  • 顶层 await 之后还能注册生命周期钩子吗？可以，<script setup> 编译时会保存并恢复当前组件实例。在普通 async setup() 中则不行。
  • 和 React Suspense 的区别？React 由组件"抛出 Promise"（use、lazy）触发挂起；Vue 由异步 setup 和异步组件触发，两者都不追踪普通的 fetch。
