Vue Suspense 适合处理什么异步组件边界？

Suspense 等子树里的异步组件都准备好之前，先显示一个加载中的占位内容。它只认顶层有 await 的 setup 和异步组件，不管普通的 fetch，也不处理错误，官方文档里仍标为实验性功能。

参考答案

简答

<Suspense> 用来统一处理加载状态。它有两个插槽，#default 放真正的内容，#fallback 放加载中的占位。默认内容里的异步依赖还没全部完成时，就显示 fallback。

它能等的异步依赖只有两种：<script setup> 里有顶层 await 的组件，以及用 defineAsyncComponent 创建的异步组件。在 onMounted 或者普通函数里发的请求，它是不知道的。

好处是一个页面有好几个异步子组件时，它们共用一个 fallback，全部好了再一起显示，不会东一块西一块地跳出来。

要注意三点。Suspense 自己不捕获错误，要用父组件的 onErrorCaptured 处理。首次加载完以后，只有 #default 的根节点被换掉时才会重新进入等待。另外它在 Vue 文档里仍标为实验性功能。

先看一个例子

UserProfile 在 setup 顶层直接 await 请求，Page 用 Suspense 包住它，同时用 onErrorCaptured 接住错误：

vue
<!-- UserProfile.vue -->
<script setup>
const props = defineProps({ id: Number });
const res = await fetch(`/api/users/${props.id}`);
if (!res.ok) throw new Error('用户加载失败');
const user = await res.json();
</script>

<template>
  <h2>{{ user.name }}</h2>
</template>
vue
<!-- Page.vue -->
<script setup>
import { onErrorCaptured, ref } from 'vue';
import UserProfile from './UserProfile.vue';

const error = ref(null);
onErrorCaptured((err) => {
  error.value = err;
  return false; // 不再向上传播
});
</script>

<template>
  <p v-if="error" role="alert">{{ error.message }}</p>
  <Suspense v-else>
    <UserProfile :id="1" />
    <template #fallback>
      <p>加载中…</p>
    </template>
  </Suspense>
</template>

UserProfile 的 setup 里有 await，它要等请求回来才能渲染。在这期间 Suspense 显示“加载中…”。请求失败时 setup 抛出错误，Suspense 不会处理，错误往上传到 Page 的 onErrorCaptured，由它显示错误信息。

切换内容时怎样避免闪一下 loading

vue
<Suspense timeout="200">
  <component :is="currentTab" />
  <template #fallback><Spinner /></template>
</Suspense>

切换 currentTab 时，根节点被换掉了，Suspense 会重新进入等待。这时旧内容继续显示，新内容在 timeout 设定的 200 毫秒内准备好，就直接换上去；超过 200 毫秒才切到 fallback。这样加载很快时，用户不会看到 loading 一闪而过。

和路由、KeepAlive 一起用

vue
<RouterView v-slot="{ Component }">
  <KeepAlive>
    <Suspense>
      <component :is="Component" />
      <template #fallback>加载中…</template>
    </Suspense>
  </KeepAlive>
</RouterView>

几个内置组件嵌套时有固定顺序，官方推荐的是 RouterView → Transition → KeepAlive → Suspense，上面省略了 Transition。

不用 Suspense 怎么做

很多项目在组件内部用状态管理 loading 和 error，或者用 Nuxt 的 useAsyncData、TanStack Query 这类工具。这样不依赖实验性 API，代价是每个组件都要自己显示加载状态。

常见追问

顶层 await 之后还能注册生命周期钩子吗？

在 <script setup> 里可以，编译器会在 await 前后保存并恢复当前组件实例。在普通的 async setup() 函数里就不行。

和 React Suspense 有什么区别？

React 是组件“抛出 Promise”来触发挂起，比如 use 和 lazy。Vue 是靠异步 setup 和异步组件触发。两者都不追踪普通的 fetch 调用。
