前端路由除切换组件外还需要管理什么？

路由让 URL 成为界面状态的来源，路径和查询参数决定显示什么，刷新、分享、前进后退都能恢复。hash 模式不需要服务器配置；history 模式地址更干净，但服务器要把未知路径回退到入口页。导航时还要处理参数校验、数据加载、错误页、标题、焦点和滚动位置。

参考答案

简答

路由不只是“地址变了换个组件”。它真正的作用，是让 URL 成为界面状态的来源：看路径和查询参数就知道该显示什么，所以刷新、分享链接、前进后退，都能回到同一个界面。

哪些状态该进 URL？页面身份，比如 /questions/42；可以分享的筛选、排序和页码，比如 ?tag=react&page=2。弹窗里还没提交的输入、鼠标悬停这类临时状态，就不用放。

实现上有两种模式。hash 模式地址形如 /#/questions/42，hash 部分不会发给服务器，监听 hashchange 就行，不需要服务器配置。history 模式用 history.pushState 改地址、监听 popstate 响应前进后退，地址更干净，但刷新时服务器会收到完整路径，要回退到 index.html。

还要注意两件事。查询参数是外部输入，页码可能是负数或者根本不是数字，标签可能不存在，都要解析和校验。导航之后要更新 document.title、把焦点移到新内容、处理滚动位置，否则用屏幕阅读器的用户不知道页面已经变了。

history 模式的最小实现

JavaScript
// history 模式的最小实现
function navigate(path) {
  history.pushState(null, '', path);
  render(path);
}

window.addEventListener('popstate', () => render(location.pathname));

document.addEventListener('click', (e) => {
  const a = e.target.closest('a[href^="/"]');
  if (!a || e.metaKey || e.ctrlKey || e.shiftKey || e.altKey || e.button !== 0) return; // 保留新标签页、新窗口和下载
  if (a.target && a.target !== '_self') return;
  if (a.hasAttribute('download')) return;
  e.preventDefault();
  navigate(a.getAttribute('href'));
});

为什么 navigate 里改完地址还要自己调用 render？因为 pushState 不会触发 popstate，只有浏览器的前进后退才会触发它。不手动渲染，地址变了页面却不动。

点击拦截那段会放过按着修饰键的点击、非左键点击、target 不是当前窗口的链接和下载链接，这些都交给浏览器原本的行为。两种模式的细节和服务器回退配置，见《hash 路由和 history 路由的原理是什么？服务器要怎样配置回退？》。

查询参数为什么要校验

URL 是用户可以随手改的，所以查询参数要当成外部输入看待。下面的函数把参数解析成安全的值：

JavaScript
function parseQuery(search, knownTags) {
  const params = new URLSearchParams(search);
  const page = Number(params.get('page'));
  const tag = params.get('tag');
  return {
    page: Number.isInteger(page) && page > 0 ? page : 1,
    tag: knownTags.includes(tag) ? tag : null,
  };
}

const tags = ['react', 'vue'];
console.log(parseQuery('?page=2&tag=react', tags)); // { page: 2, tag: 'react' }
console.log(parseQuery('?page=-3&tag=angular', tags)); // { page: 1, tag: null }
console.log(parseQuery('?page=abc', tags)); // { page: 1, tag: null }

页码是 -3 或 abc 时，Number 转出来要么是负数，要么是 NaN，都过不了检查，于是回到默认的第 1 页。标签不在已知列表里，就当作没选。

参数不合法时，除了用默认值，必要时还可以用 history.replaceState 把地址改成规范的形式。这样同一个内容不会有好几种 URL。

导航时还要做哪些事

数据加载：进入路由时开始请求，用户快速切换时取消旧请求，见《路由并发导航和权限变化应该怎样处理？》。

错误与 404：参数指向的数据不存在时，显示 404 页面。如果是 SSR 或静态托管，还要返回真实的 404 状态码，见《前端渲染方式怎样影响 SEO 和部署？》。

标题与焦点：更新 document.title，把焦点移到新页面的 <h1> 上，<h1> 要加 tabindex="-1" 才能被脚本聚焦；也可以用 aria-live 区域播报。这是因为单页应用切换页面时浏览器不会重新加载，读屏软件不会自动告诉用户“到了新页面”。

滚动：进入新页面滚到顶部，后退时恢复原来的位置。Vue Router 用 scrollBehavior 配置，React Router 用 <ScrollRestoration> 组件。

路由守卫能保护什么

前端路由守卫，比如没登录就跳到登录页，只是改善体验。用户完全可以绕过页面直接调接口，所以权限必须由服务端在每个请求里校验。

常见追问

pushState 和 replaceState 有什么区别？

pushState 新增一条历史记录，replaceState 替换当前这条。修正参数、筛选条件实时变化这类不希望堆出一串历史的场景，用 replaceState。

Navigation API 是什么？

它是浏览器提供的较新的路由 API，用一个 navigate 事件统一拦截链接点击、表单提交和前进后退。有了它，就不用再手动拦截点击、监听 popstate 了。
