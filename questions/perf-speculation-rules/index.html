Speculation Rules API 的预取和预渲染有什么区别？

用 <script type="speculationrules"> 告诉浏览器哪些链接可以提前处理。prefetch 只下载目标页面的 HTML，不下载子资源；prerender 在看不见的地方把页面完整加载并执行，点过去几乎立刻显示。eagerness 控制触发时机。它不是 Baseline，不支持的浏览器会忽略规则。

参考答案

简答

Speculation Rules 是让页面提前告诉浏览器：用户接下来很可能点这些链接，你可以先准备。准备的程度有两种。

prefetch 是预取，只把目标页面的 HTML 取回来，不取图片、脚本这些子资源，成本低，可以用得比较广。prerender 是预渲染，把目标页面的文档和所有子资源都加载好，JavaScript 也执行了，用户点过去几乎立刻显示，但资源消耗接近渲染一个 iframe，只适合用户很可能访问的页面。

什么时候开始准备由 eagerness 控制。immediate 是立即；eager 在有一点迹象时就开始，比如鼠标移向链接、短暂悬停；moderate 是桌面端悬停约 200 毫秒或者按下指针时；conservative 是按下指针或触摸时。列表规则默认 immediate，文档规则默认 conservative。

要注意两点。第一，预渲染默认只限同源，同站跨源需要目标页面返回 Supports-Loading-Mode: credentialed-prerender，跨站不支持。第二，预渲染的页面会真的执行代码，统计、广告曝光这类副作用要等页面真正被用户看到再执行。

规则怎么写

规则写在一个特殊的 <script> 标签里，内容是 JSON。下面的例子对 /questions/ 下的链接做预渲染，排除带 .no-prerender 类的链接，同时立即预取目录页：

HTML
<script type="speculationrules">
  {
    "prerender": [
      {
        "where": {
          "and": [
            { "href_matches": "/questions/*" },
            { "not": { "selector_matches": ".no-prerender" } }
          ]
        },
        "eagerness": "moderate"
      }
    ],
    "prefetch": [{ "urls": ["/questions/"], "eagerness": "immediate" }]
  }
</script>

urls 写死网址列表，叫列表规则；where 按条件匹配页面上的链接，叫文档规则。两者默认的 eagerness 不一样，前面简答里说过。

为什么一定要排除某些链接？因为预取和预渲染都会真的发请求。退出登录、加入购物车这类一访问就改变状态的链接，提前请求一次就出事了，所以必须排除。

页面开了 CSP 的话，内联规则需要 'inline-speculation-rules'、nonce 或 hash 才能生效。规则也可以不写在页面里，而是通过响应头 Speculation-Rules: "/rules.json" 下发，这个文件的类型是 application/speculationrules+json。

预渲染的副作用怎么处理

预渲染的页面用户还没看到，代码却已经跑了。如果在这时候发送页面浏览统计，用户最后没点过去，统计就多算了一次。所以要判断页面是否正在预渲染，等它真正显示时再执行：

JavaScript
function whenVisible(callback) {
  if (document.prerendering) {
    document.addEventListener('prerenderingchange', callback, { once: true });
  } else {
    callback();
  }
}

whenVisible(() => sendPageView());

document.prerendering 为 true 说明还在预渲染，页面被激活时会触发 prerenderingchange。

浏览器自己也会拦一部分。预渲染期间，地理位置、通知、getUserMedia 这类 API 会延迟到激活后才执行。

服务器那边，可以通过请求头 Sec-Purpose: prefetch 或 Sec-Purpose: prefetch;prerender 认出这是推测请求。页面激活以后，想知道它是不是经过了预渲染，可以看 performance.getEntriesByType('navigation')[0].activationStart > 0。

浏览器不支持怎么办

MDN 标注它为实验性、有限可用。可以这样检测：

JavaScript
if (HTMLScriptElement.supports?.('speculationrules')) {
  // 动态插入规则
}

不过不检测也不会出错，不支持的浏览器会直接忽略规则，页面照常工作。下一页的资源可以用 <link rel="prefetch"> 作为降级。

即使支持，浏览器也可能不执行，比如开了省电、省流量模式，或者内存不足。所以它只能当作加速手段。

怎样验证有没有生效

DevTools 的 Application 面板里有 Speculative loads 视图，能看到规则和每个 URL 的状态。

还要注意状态码：目标页面返回 2xx 以外的状态码时，预取或预渲染不会生效，204 和 205 还会阻止预渲染。

效果最终要看真实用户数据，对比经过预渲染的导航和普通导航的 LCP。

常见追问

和 <link rel="prefetch"> 有什么区别？

<link rel="prefetch"> 可以预取任意资源，结果放进 HTTP 缓存。Speculation Rules 针对的是整页导航，结果存在按文档隔离的内存缓存里。

会不会浪费流量？

prerender 会，因为它把整个页面都加载了，用户不点就白费了。所以要配合 moderate 或 conservative，并且限制匹配范围。
