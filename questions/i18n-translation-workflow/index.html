前端翻译工作流怎样避免把文案写死在组件里？

组件里只写稳定的消息键并传入变量，翻译放在按语言拆分的消息目录里，由消息格式库处理插值和复数。统一定义语言回退链，在 CI 中检查缺失键和占位符，异步加载语言包时防止旧请求覆盖新选择。

参考答案

简答

组件里不要直接写“保存资料”，而是写一个消息键，比如 profile.save，再由翻译目录给出各语言的文字。键表达的是用途，以后改了中文原文，其他语言也不会失去对应关系。

带变量和复数的句子，交给 ICU MessageFormat 这类消息格式处理，不要用字符串拼接，因为各语言的词序和复数规则都不一样。

找不到翻译时怎么办，要统一定义回退链，例如 zh-Hant-TW → zh-Hant → zh → 默认语言。缺失的键在开发和 CI 中直接报错，生产环境回退，但不能显示空字符串。CI 还要检查每种语言的键是否齐全、占位符是否一致、消息语法能否解析。

最后要注意切换语言。语言包是异步加载的，旧请求晚到时不能覆盖用户的新选择；切换后还要同步更新 <html lang> 和 dir。

消息目录长什么样

每种语言一个文件，键相同，值是各自的翻译。

json
// zh-CN.json
{
  "profile.save": "保存资料",
  "search.resultCount": "找到 {count, plural, other {# 条结果}}"
}
json
// en.json
{
  "profile.save": "Save profile",
  "search.resultCount": "{count, plural, one {# result} other {# results}} found"
}

同一个 search.resultCount，中文只写了 other，英文写了 one 和 other。这是因为中文只有一个复数类别，每种语言的翻译者按自己语言的规则填分支就行。英文还把“found”挪到了句尾，这种词序调整只有整句交给翻译时才做得到。复数和消息格式的细节见《ICU MessageFormat 为什么适合复杂国际化文案？》和《Intl.PluralRules 怎样帮助实现国际化复数？》。

反过来看，下面这种写法把词序、空格和复数全写死了，换任何一种语言都得改代码：

JavaScript
// 不要这样做：词序、空格和复数都写死了
`${userName} 有 ${count} 条消息`;

找不到翻译时怎么回退

下面沿着回退链逐个查，查到就返回。

JavaScript
function lookup(key, chain, catalogs) {
  for (const locale of chain) {
    const message = catalogs[locale]?.[key];
    if (message !== undefined) return message;
  }
  reportMissing(key, chain[0]); // 开发环境直接抛错，生产环境上报
  return catalogs.en[key] ?? key;
}

全都查不到时，先上报缺失，再用默认语言兜底，最后连默认语言都没有就显示键本身。这样页面上至少不会出现空白。

还有一点，键名不要包含用户输入，也不要动态拼接路径。否则工具没法静态找出哪些键在用，下面的 CI 检查也就失效了。

CI 里检查什么

CI 一般做三件事。第一，以默认语言为基准，列出其他语言缺了哪些键、多了哪些键。第二，比对占位符，英文里有 {count}，德文翻译里也必须有。第三，用消息格式库把每条消息解析一遍，语法错误直接让构建失败。

翻译者可以调整句子顺序，但不能删掉业务需要的变量，第二项检查就是为此准备的。

切换语言时的竞态

用户连续点两种语言时，先发出的请求可能后返回，把新选择覆盖掉。下面用一个版本号来防止这种情况。

JavaScript
let loadVersion = 0;

async function switchLocale(locale) {
  const version = ++loadVersion;
  const catalog = await import(`./locales/${locale}.json`);
  if (version !== loadVersion) return; // 用户已经切到别的语言
  applyCatalog(locale, catalog.default);
  document.documentElement.lang = locale;
  document.documentElement.dir = getDirection(locale);
}

每次切换都把版本号加一。请求回来时，如果版本号已经不是最新的，说明用户又切走了，这次结果直接丢掉。生效时顺便更新 lang 和 dir。

SSR 或静态生成时，服务端和客户端要用同一个初始语言和同一份目录，否则水合时文字对不上。另外，语言包会下发到客户端，里面不要放内部备注或密钥。

日期、数字、货币和列表不属于翻译，用 Intl 来格式化，见《为什么日期、金额和排序不应该手动拼接格式？》。

常见追问

翻译里需要加粗或链接怎么办？

用消息库提供的富文本标签，比如把 <b>{name}</b> 映射成组件。不要把翻译当 HTML 直接插进页面。

怎样提前发现布局问题？

用伪本地化和多语言测试矩阵，在拿到真实翻译之前就能看到溢出和写死的文字，见《国际化页面怎样做跨地区测试，避免上线后才发现布局和时间错误？》。
