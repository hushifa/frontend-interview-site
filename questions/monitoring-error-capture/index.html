前端怎样全局捕获 JS 错误、Promise 拒绝和资源加载失败？

window.onerror 和 error 事件捕获运行时异常，unhandledrejection 捕获没处理的 Promise 拒绝，资源加载失败要在捕获阶段监听；跨域脚本的报错只剩 Script error.，要加 crossorigin 并配 CORS 响应头才能拿到详情。

参考答案

简答

前端错误监控要覆盖三类错误，各有各的入口。脚本运行时抛的错，会以 ErrorEvent 派发到 window 上，用 window.onerror 或 addEventListener('error') 就能捕获。

Promise 被拒绝了又没人处理，不会触发 error，而是触发 unhandledrejection，拒绝的原因在 event.reason 里。

图片、脚本、样式表加载失败也会触发 error 事件，但它派发在元素上，而且不冒泡，所以全局捕获时必须在 window 上用捕获阶段监听。

还有一个常见坑：脚本放在 CDN 等其他源上时，它抛的错浏览器只给一句 Script error.，行列号是 0，error 是 null。要拿到详情，脚本标签要加 crossorigin，服务端还要返回 Access-Control-Allow-Origin。

运行时错误

先看最常用的 onerror 写法：

JavaScript
window.onerror = (message, source, lineno, colno, error) => {
  report({ type: 'js', message, source, lineno, colno, stack: error?.stack });
};

为什么它能收到五个参数？因为 onerror 是个特例，它是唯一接收多个参数的事件处理属性。换成 addEventListener('error', handler) 就只收到一个 ErrorEvent，字段分别是 message、filename、lineno、colno、error。

onerror 返回 true 可以阻止控制台打印默认报错，但抛错的那段脚本该中止还是中止。

要注意，全局监听只能收到“没人管”的错误。被 try/catch 包住的，或者被框架错误边界吞掉的错误，不会到达全局事件，需要在框架层另外上报，比如 React 的错误边界、Vue 的 app.config.errorHandler。

Promise 拒绝

JavaScript
window.addEventListener('unhandledrejection', (event) => {
  report({ type: 'promise', reason: String(event.reason), stack: event.reason?.stack });
});

事件对象是 PromiseRejectionEvent，有 promise 和 reason 两个属性。为什么要写 String(event.reason) 和 event.reason?.stack？因为 reason 不一定是 Error，reject('超时') 传的就是字符串，也可能是普通对象，上报前要做类型判断。

如果一个 Promise 先被拒绝了，后来才挂上处理函数，浏览器会再触发一次 rejectionhandled，可以用来修正“未处理”的统计。调用 preventDefault() 只是取消控制台的默认输出。另外，来自跨域脚本的拒绝不会触发这个事件。

资源加载失败

资源错误不冒泡，所以要在 window 上用捕获阶段拦截，第三个参数传 true：

JavaScript
window.addEventListener(
  'error',
  (event) => {
    if (event instanceof ErrorEvent) return; // 运行时错误交给上面的逻辑
    const el = event.target;
    report({ type: 'resource', tag: el.tagName, url: el.src || el.href });
  },
  true, // 资源错误不冒泡，只能在捕获阶段拿到
);

为什么开头要判断 ErrorEvent？因为运行时错误也会触发 window 上的 error，捕获阶段两种都会收到。运行时错误是 ErrorEvent，资源错误只是普通的 Event，这样就能分开。

资源错误是普通 Event，所以拿不到 HTTP 状态码。需要状态码或耗时的话，可以结合 Resource Timing 的数据来分析。还要注意，fetch 失败不属于资源错误，它表现为 Promise 拒绝，应该在请求封装层统一处理。

跨域脚本为什么只剩 Script error.

脚本放在其他源时，浏览器为了避免跨源信息泄露，会把错误详情屏蔽掉。要拿到详情，需要页面和 CDN 双方配合。页面这边给脚本加 crossorigin：

HTML
<script src="https://cdn.example.com/app.js" crossorigin="anonymous"></script>

CDN 那边要返回 Access-Control-Allow-Origin: https://www.example.com，也可以写 *，但 * 不能和 use-credentials 一起用。

这两步缺一不可。如果只加了属性，服务端却没返回这个响应头，脚本会整个加载失败，比拿不到错误详情还糟。CORS 的原理见《什么是跨域？CORS 为什么需要服务端配合？》。

常见追问

为什么同一个错误被报了两次？

通常是 onerror 和 addEventListener('error') 都注册了，或者框架的错误处理和全局监听都上报了。可以按错误指纹去重。

压缩后的堆栈怎么看？

上报原始堆栈，在服务端用 Source Map 还原，详见《线上报错怎样用 Source Map 还原，又不把 map 文件公开？》。

浏览器扩展注入的脚本报错怎么办？
