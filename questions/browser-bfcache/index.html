bfcache 与 HTTP 缓存有什么区别？

HTTP 缓存存的是一个个响应文件，bfcache 存的是整个页面在内存里的样子，点后退时页面连同 JS 状态直接恢复。用了 unload 监听器或 no-store 等情况，页面可能进不了 bfcache。

参考答案

简答

用户点了后退，页面一下子就回来了，滚动位置、输入框里的字、JS 里的变量都还在，这就是 bfcache，也叫往返缓存。浏览器在用户离开时把整个页面冻结在内存里，后退或前进时直接解冻。

HTTP 缓存不一样，它存的是一个个响应，比如 HTML、JS、图片。命中缓存能省掉下载，可页面还是要重新解析、重新执行脚本、重新渲染。

所以从 bfcache 回来时，load 不会再触发，触发的是 pageshow，而且 event.persisted 是 true。页面可能在缓存里待了好几分钟，回来后要刷新登录状态、购物车这类会过期的数据。

要注意，有些写法会让页面进不了 bfcache。常见的是注册了 unload 监听器、离开时还开着 IndexedDB 连接或请求、主文档带 Cache-Control: no-store。具体原因可以在 DevTools 里查。

两种缓存到底差在哪

HTTP 缓存bfcache
保存内容单个响应整个页面和 JS 状态
存放位置磁盘或内存内存
适用导航所有请求只有后退、前进
恢复时脚本重新执行不重新执行，从冻结点继续

HTTP 缓存省的是网络，bfcache 省的是整个加载过程。命中 HTTP 缓存时，脚本还会从头跑一遍，所以页面状态是全新的。命中 bfcache 时，脚本根本不重跑，代码从冻结的那一刻接着往下走，所以你离开前的状态全都还在。

页面从 bfcache 回来时要做什么

因为不会重新执行脚本，写在 load 里的初始化逻辑这时不会跑。要处理恢复，就监听 pageshow，用 persisted 判断是不是从 bfcache 回来的。

JavaScript
window.addEventListener('pageshow', (event) => {
  if (event.persisted) {
    refreshCartCount();
    reconnectRealtime();
  }
});

window.addEventListener('pagehide', (event) => {
  closeRealtime();
});

离开时在 pagehide 里把实时连接关掉，回来时在 pageshow 里重新连上，顺便把购物车数量这类可能已经过期的数据刷新一下。页面可能在缓存里停了几分钟，这期间服务端的数据早就变了。

怎样让页面能进入 bfcache

最常见的问题是用了 unload。桌面版 Chrome 和 Firefox 看到页面注册了 unload 监听器，就会放弃缓存这个页面。Chrome 也在逐步弃用 unload 事件。所以离开页面时要做的事，改放到 pagehide 或 visibilitychange 里。

离开时还开着的连接也会挡住缓存。打开着的 IndexedDB 连接、进行中的 fetch 或 XHR、没关的 WebSocket 或 WebRTC 连接，在部分浏览器里都会让页面进不了 bfcache。所以在 pagehide 里把 WebSocket、WebRTC 关掉，把进行中的 IndexedDB 事务结束掉。

主文档带 Cache-Control: no-store 也会阻止缓存，不过 Chrome 正在逐步放宽这一条。普通页面不要设这个头，只在确实含敏感信息的页面上用。

另外，页面保留着 window.opener 引用关系时，也可能进不了 bfcache，具体规则各浏览器不一样。

怎么知道页面为什么没被缓存

打开 Chrome DevTools，进 Application → Back/forward cache，点测试按钮，它会列出这个页面不能缓存的具体原因。线上想收集数据，可以读 PerformanceNavigationTiming.notRestoredReasons，这个字段目前只有 Chromium 支持。

常见追问

从 bfcache 恢复时，load 事件会触发吗？

不会。页面没有重新加载，脚本也没重跑，所以 load 和 DOMContentLoaded 都不会再来。要处理恢复，监听 pageshow，看 event.persisted 是不是 true。

为什么不能在 unload 里做清理？

因为桌面版 Chrome 和 Firefox 只要看到页面注册了 unload 监听器，就不会把它放进 bfcache，Chrome 也在逐步弃用这个事件。清理工作放到 pagehide 或 visibilitychange 里就行。
