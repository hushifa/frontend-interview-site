bfcache 与 HTTP 缓存有什么区别？

HTTP 缓存保存的是响应资源，bfcache 保存的是整个页面在内存中的快照，用户点后退或前进时直接恢复，JavaScript 状态也保留；unload 监听器、Cache-Control no-store 等会让页面无法进入 bfcache。

参考答案

简答

  • HTTP 缓存保存单个资源的响应，恢复页面时仍要重新解析、执行脚本和渲染。
  • bfcache（往返缓存）把离开时的整个页面连同 JavaScript 堆冻结在内存里，后退或前进时直接恢复，几乎瞬间显示。
  • 从 bfcache 恢复时不触发 load，而是触发 pageshow，event.persisted 为 true。
  • 常见的阻止原因有：注册了 unload 监听器、离开时还有未关闭的 WebSocket 或 IndexedDB 事务、主文档带 Cache-Control: no-store（Chrome 正在逐步放宽这一条）。

对比

HTTP 缓存bfcache
保存内容单个响应整个页面和 JS 状态
存放位置磁盘或内存内存
适用导航所有请求只有后退、前进
恢复时脚本重新执行不重新执行，从冻结点继续

恢复时要处理的事

JavaScript
window.addEventListener('pageshow', (event) => {
  if (event.persisted) {
    refreshCartCount();
    reconnectRealtime();
  }
});

window.addEventListener('pagehide', (event) => {
  closeRealtime();
});

页面可能在 bfcache 里停留几分钟，恢复后要刷新登录状态、购物车数量这类会过期的数据，并重新建立离开时关闭的连接。

让页面能进入 bfcache

  • 不用 unload，改用 pagehide 或 visibilitychange。Chrome 正在逐步弃用 unload 事件。
  • 在 pagehide 里关闭 WebSocket、WebRTC 连接，结束进行中的 IndexedDB 事务。
  • 不要给普通页面设置 Cache-Control: no-store；只在确实含敏感信息的页面使用。
  • 页面保留着 window.opener 引用关系时，可能无法进入 bfcache，具体规则因浏览器而异；用 Chrome DevTools 的 Back/forward cache 面板查看实际原因。

排查

Chrome DevTools → Application → Back/forward cache，点击测试后会列出不能缓存的具体原因。线上可以用 PerformanceNavigationTiming.notRestoredReasons（Chromium 支持）收集原因。
