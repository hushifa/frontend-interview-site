CSS 滚动驱动动画适合什么场景？

普通动画随时间播放，滚动驱动动画随滚动播放：滚到哪里，动画就播到哪里。适合阅读进度条、元素滚进视口时淡入这类效果。它还不是 Baseline，要做成渐进增强。

参考答案

简答

普通动画按时间往前走。滚动驱动动画把进度换成了滚动进度，滚到一半动画就播到一半，往回滚动画就倒着放。

用 animation-timeline 指定跟着什么走。scroll() 跟着滚动容器的滚动位置，适合阅读进度条；view() 跟着元素穿过视口的进度，适合元素滚进来时淡入。animation-range 可以只截取其中一段，比如 entry 0% cover 40%，表示从元素开始进入视口，到覆盖视口 40% 时动画完成。

如果只动 transform 和 opacity，浏览器通常可以交给合成线程处理，主线程忙的时候受影响也小，具体看浏览器实现。

要注意，animation-timeline 目前支持有限，不支持的浏览器会忽略它。所以要保证元素在那些浏览器里显示的是最终状态，而不是一直停在隐藏状态。

阅读进度条

CSS
@keyframes grow {
  from { transform: scaleX(0); }
  to { transform: scaleX(1); }
}

.progress {
  position: fixed;
  inset-block-start: 0;
  inset-inline: 0;
  block-size: 4px;
  transform-origin: 0 50%;
  background: steelblue;
  animation: grow linear both;
  animation-timeline: scroll(root);
}

页面顶部一条 4px 高的条，scroll(root) 让它跟着整个页面的滚动走。滚到顶是 0，条看不见；滚到底是 1，条铺满整行。

为什么 animation 里没写时长？因为进度由滚动决定，时长对滚动时间线没有意义。

还有一个顺序上的坑：animation-timeline 要写在 animation 简写的后面。简写会把没写的子属性都重置一遍，animation-timeline 也在其中，写在前面就被覆盖了。

卡片滚进视口时淡入

CSS
@keyframes reveal {
  from { opacity: 0; transform: translateY(24px); }
}

@supports (animation-timeline: view()) {
  .card {
    animation: reveal linear both;
    animation-timeline: view();
    animation-range: entry 0% cover 30%;
  }
}

为什么要套 @supports？动画的起点是透明的，要是浏览器不认识滚动时间线，这个起点状态就不该冒出来。整个规则放进 @supports 以后，不支持的浏览器根本不会应用这个动画，卡片直接正常显示，不会出现永远透明看不见的内容。

和 IntersectionObserver 有什么区别

IntersectionObserver 是在元素进入视口时触发一次回调，适合“出现以后播放一次”的动画和图片懒加载。

滚动驱动动画的进度和滚动位置一一对应，往回滚就倒回去。所以它适合进度条、视差这类要跟着滚动连续变化的效果。

要注意什么

用户开启了减少动态效果时，用 prefers-reduced-motion 把这些动画关掉。

不要用滚动动画来隐藏关键内容或者改变布局。读屏用户和不支持的浏览器都会受影响。

常见追问

JavaScript 里能用滚动时间线吗？

可以。new ScrollTimeline({ source }) 和 ViewTimeline 创建出来的时间线，可以传给 Web Animations API 的 timeline 选项。
