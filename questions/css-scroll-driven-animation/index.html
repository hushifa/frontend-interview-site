CSS 滚动驱动动画适合什么场景？

滚动驱动动画用 animation-timeline 把关键帧进度绑定到滚动位置（scroll()）或元素在视口中的可见进度（view()），适合阅读进度条和随滚动出现的效果；它目前不是 Baseline，需要渐进增强。

参考答案

简答

  • 普通动画按时间推进；滚动驱动动画的进度等于滚动进度，往回滚动画就倒放。
  • animation-timeline: scroll() 跟随滚动容器的滚动位置，view() 跟随元素穿过视口的进度。
  • animation-range 截取时间线的一段，例如 entry 0% cover 40% 表示从元素进入视口到覆盖 40% 时完成。
  • 只动画 transform、opacity 时，浏览器通常可以交给合成线程处理，主线程繁忙时受影响较小，具体取决于浏览器实现。
  • animation-timeline 属于有限可用，不支持的浏览器忽略它；要让元素在那里保持最终状态，而不是停在隐藏状态。

阅读进度条

CSS
@keyframes grow {
  from { transform: scaleX(0); }
  to { transform: scaleX(1); }
}

.progress {
  position: fixed;
  inset-block-start: 0;
  inset-inline: 0;
  block-size: 4px;
  transform-origin: 0 50%;
  background: steelblue;
  animation: grow linear both;
  animation-timeline: scroll(root);
}

animation-duration 对滚动时间线没有意义，示例简写里不写时长。注意 animation-timeline 要写在 animation 简写之后，否则会被简写重置。

动画只涉及 transform、opacity 时，浏览器通常可以把滚动驱动动画放到合成线程，主线程繁忙时受到的影响较小；其他属性仍要在主线程计算，具体行为由浏览器实现决定。

进入视口时淡入

CSS
@keyframes reveal {
  from { opacity: 0; transform: translateY(24px); }
}

@supports (animation-timeline: view()) {
  .card {
    animation: reveal linear both;
    animation-timeline: view();
    animation-range: entry 0% cover 30%;
  }
}

放在 @supports 里，不支持的浏览器直接显示卡片，不会出现永远透明的内容。

和 IntersectionObserver 的区别

IntersectionObserver 在元素进入视口时触发一次回调，适合“出现后播放一次”的动画和懒加载。滚动驱动动画的进度和滚动位置一一对应，适合进度条、视差这类需要随滚动连续变化的效果。

注意

  • 用户开启减少动态效果时，用 prefers-reduced-motion 关闭这些动画。
  • 不要用滚动动画隐藏关键内容或改变布局，读屏用户和不支持的浏览器都会受影响。

常见追问

  • 能在 JavaScript 里用吗？可以，new ScrollTimeline({ source }) 和 ViewTimeline 可以传给 Web Animations API 的 timeline 选项。
