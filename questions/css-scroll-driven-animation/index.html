CSS 滚动驱动动画适合什么场景？

滚动驱动动画把关键帧进度连接到滚动位置或元素穿越滚动区域的进度，适合阅读进度和随滚动变化的视觉反馈。它不等于滚动到某点后启动一次独立计时动画。

参考答案

普通 CSS 动画主要随时间前进：启动后，即使用户不滚动，过一秒也会走到一秒对应的关键帧。滚动驱动动画换了一种进度来源：滚到哪里，动画就走到哪里。滚动停止，进度通常停在当前位置；向回滚动，动画也可以向回变化。

这很适合顶部阅读进度条、与滚动位置绑定的图示、元素进入阅读区域时的轻微渐显。它不适合直接替代“进入视口后播放一次，之后不回退”的逻辑，后者通常需要 Intersection Observer 配合状态和普通动画。

两种时间轴，回答不同问题

scroll() 创建滚动进度时间轴，关注某个滚动容器从起点到终点滚了多少。例如根文档在所选轴上滚到可滚动范围的一半，动画就大致来到一半。页面总高度包含当前视口，可滚动距离不能直接等同于整个文档高度。

view() 创建可见进度时间轴，关注目标元素穿过最近相关滚动区域的过程。默认范围从它开始进入到完全离开，并不是“Intersection Observer 的可见面积比例”。一个元素完全位于视口中时，进度也不一定等于 100%。

animation-timeline 把关键帧动画与这条时间轴连接起来；关键帧仍然通过 @keyframes 定义。命名的 scroll-timeline、view-timeline 可以用于更复杂的共享关系，但需要同时考虑名字的作用域和元素之间的结构。

用根文档滚动驱动阅读进度条

页面先有一个纯装饰的进度条元素，文章需要足够长，确实能够产生根文档滚动：

HTML
<div class="reading-progress" aria-hidden="true"></div>
<main>
  <h1>浏览器渲染专题</h1>
  <p>这里放置实际的长篇文章内容。</p>
</main>
CSS
.reading-progress {
  display: none;
}

@keyframes reading-progress {
  from { transform: scaleX(0); }
  to { transform: scaleX(1); }
}

@supports (animation-timeline: scroll(root block)) {
  @media (prefers-reduced-motion: no-preference) {
    .reading-progress {
      display: block;
      position: fixed;
      top: 0;
      left: 0;
      width: 100%;
      height: 3px;
      background: #2563eb;
      transform-origin: left center;
      pointer-events: none;
      z-index: 10;
      animation: reading-progress linear both;
      animation-duration: auto;
      animation-timeline: scroll(root block);
    }
  }
}

root 明确选择根滚动容器，block 选择块方向，在常见横排页面中就是垂直滚动方向。linear 让关键帧变化与时间轴进度线性对应；scaleX 改变视觉长度，不需要每次滚动都修改元素布局宽度。

这里的 animation-duration: auto 对进度时间轴采用其相应范围，并不是让动画固定播放若干秒。both 指定填充行为，不能理解为“自动往返播放”。

特别注意声明顺序：animation 简写会把之前的 animation-timeline 重置为 auto。因此时间轴应放在简写后面，否则可能悄悄变回默认时间驱动动画。animation-range 等相关属性也应检查是否被后续简写重置。

元素进入动画怎样限定范围

若把下面规则用于文章中的插图，动画会跟随该插图进入滚动区域的过程：

CSS
.illustration {
  opacity: 1;
  transform: none;
}

@keyframes reveal-illustration {
  from {
    opacity: 0.6;
    transform: translateY(1rem);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

@supports (animation-timeline: view()) and (animation-range: entry 0% cover 30%) {
  @media (prefers-reduced-motion: no-preference) {
    .illustration {
      animation: reveal-illustration linear both;
      animation-duration: auto;
      animation-timeline: view();
      animation-range: entry 0% cover 30%;
    }
  }
}

animation-range 把动画限制在命名范围之间的部分进度。这里从进入开始，到 cover 穿越范围的 30% 结束，让渐显较早完成；它不表示“30% 的图片面积已经可见”。元素高度、滚动区域大小都会影响具体对应的滚动距离。

基础样式保持内容可见，而且动画起始透明度也不是 0。浏览器不支持、用户要求减少动画或增强规则不生效时，插图仍然能阅读。不能先在基础样式里隐藏所有内容，再期待所有设备都能成功播放进入动画。

嵌套滚动与动态内容为什么会影响结果

scroll() 默认查找最近的相应滚动祖先；如果文章外面套了一层 overflow: auto，进度可能绑定到那一层，而不是整页。该区域没有足够的可滚动距离时，时间轴也可能无法产生有效进度。选择根滚动、最近滚动或自身滚动，需要与实际布局一致。

图片迟到、折叠内容展开、列表继续加载，会改变可滚动距离。同一个 scrollTop 对应的百分比因此可能变化，进度条出现跳动不一定是浏览器算错。应预留图片空间，并确认“当前已加载内容进度”是否就是产品想表达的含义。

如果动画本身不断改变决定滚动范围的布局尺寸，也会增加计算和反馈复杂度。优先用 transform、opacity 这类通常不需要重排的属性，但它们也不保证在所有情况下都零成本或始终运行在合成线程。

CSS 声明时间轴可以减少手写滚动事件和频繁 DOM 读写，却不自动保证流畅。仍应测量实际绘制成本，并按目标浏览器核对 animation-timeline、animation-range 等具体能力。业务状态、阅读完成判定和统计数据也不应只靠这个装饰动画推导。
