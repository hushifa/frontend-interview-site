import type 和 verbatimModuleSyntax 如何影响模块输出？

import type 整条导入在编译后删除，模块不会被加载。开启 verbatimModuleSyntax 后，TypeScript 按源码写法保留导入：没有 type 修饰的名字一律保留，只用作类型却没标 type 会报错；import { type A } 只删除 A，留下 import {} 仍会执行模块副作用。Node.js 类型剥离、esbuild 等单文件转换器依赖这种显式标注。

参考答案

简答

  • import type { User } from './model' 编译后整条删除，model 不会因此被加载执行。
  • verbatimModuleSyntax 下，import { type User } from './model' 会编译成 import {} from './model'，模块仍被加载并执行顶层代码。
  • 开启 verbatimModuleSyntax 后，只用作类型却没写 type 的导入报 TS1484，从而保证源码中的导入与输出一一对应。
  • Node.js 类型剥离、esbuild、SWC 逐文件转换，无法判断导入的名字是不是类型，所以项目需要开启 verbatimModuleSyntax，配合 TS 5.8 的 erasableSyntaxOnly。
  • 需要执行副作用（注册插件、引入样式）时写 import './register.js'，不要依赖其他导入碰巧被保留。

三种写法的输出

TypeScript
// model.ts
export interface User {
  name: string;
}
export const version = '1.0';
console.log('model 已执行');
源码verbatimModuleSyntax: true 的输出
import type { User } from './model.js'删除
import { type User } from './model.js'import {} from './model.js'
import { User } from './model.js'报错 TS1484
import { version, type User } from './model.js'import { version } from './model.js'

未开启时，TypeScript 会分析每个导入是否只作类型用，自动删掉未作为值使用的导入（导入省略），上面前三行都会被删除。

为什么单文件转换器需要它

TypeScript
import { User } from './model.ts';

Node.js 直接运行这一行时报 SyntaxError：model.ts 并没有导出名为 User 的值。转换器只看到当前文件，不知道 User 是接口。写成 import type 或 import { type User } 后才能运行。

Node.js 原生运行 TypeScript

Node.js 22.18+、23.6+ 默认开启类型剥离，24.12+、25.2+ 标为稳定。它的限制：

  • 只删除类型，不转换语法：enum、带运行时代码的 namespace、构造函数参数属性、import x = require() 会报错；装饰器无法解析。
  • 不读取 tsconfig，paths 不生效，用 package.json 的 imports（#src/*）替代。
  • 导入必须写 .ts 扩展名。
  • 不处理 node_modules 中的 .ts 文件。

推荐的类型检查配置：

json
{
  "compilerOptions": {
    "noEmit": true,
    "target": "esnext",
    "module": "nodenext",
    "rewriteRelativeImportExtensions": true,
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true
  }
}

erasableSyntaxOnly 让 tsc 对上述不可擦除语法报 TS1294。

其他细节

  • import type 导入的类只能用作类型，不能 new，也不能用于 instanceof。
  • export type { User } 只导出类型；重新导出类型时也要标 type。
  • verbatimModuleSyntax 不会把 ESM 语法改写成 require，CommonJS 文件中写 import 会报错，要用 import x = require() 或把文件改成 ESM。

常见追问

  • 和 isolatedModules 的关系？isolatedModules 只禁止单文件无法正确转换的写法；verbatimModuleSyntax 规定导入导出按写法保留，取代了旧的 importsNotUsedAsValues 和 preserveValueImports。两者常一起开启。
  • 会影响 tree shaking 吗？import {} 会让打包器认为模块可能有副作用，除非包在 package.json 中声明了 "sideEffects": false。
