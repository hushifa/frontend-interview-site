import type 和 verbatimModuleSyntax 如何影响模块输出？

import type 整条导入编译后会被删掉，模块不会被加载。开启 verbatimModuleSyntax 后，TypeScript 按你写的样子保留导入，只当类型用却没标 type 的导入会报错，Node.js 类型剥离和 esbuild 这类工具靠的就是这种标注。

参考答案

简答

import type { User } from './model' 表示只导入类型，编译后整条语句被删掉，model 不会因此被加载执行。而开启 verbatimModuleSyntax 后，import { type User } from './model' 只删掉 User 这个名字，留下 import {} from './model'，模块还是会被加载，顶层代码照样执行。

verbatimModuleSyntax 的意思是“导入按原样保留”：没标 type 的名字一律保留，所以只当类型用却没写 type 的导入会报 TS1484。这保证了源码里的导入和输出一一对应。

为什么需要它？Node.js 类型剥离、esbuild、SWC 都是一个文件一个文件地转换，看不到别的文件，判断不了导入的名字是不是类型。所以要靠你显式标出来，通常再配合 TS 5.8 的 erasableSyntaxOnly。

要注意，需要执行副作用，比如注册插件、引入样式，就直接写 import './register.js'，不要指望别的导入碰巧被保留下来。

几种写法分别输出什么

先看一个既有类型、又有值、还有副作用的模块：

TypeScript
// model.ts
export interface User {
  name: string;
}
export const version = '1.0';
console.log('model 已执行');

不同的导入写法，在 verbatimModuleSyntax: true 下输出不同：

源码verbatimModuleSyntax: true 的输出
import type { User } from './model.js'删除
import { type User } from './model.js'import {} from './model.js'
import { User } from './model.js'报错 TS1484
import { version, type User } from './model.js'import { version } from './model.js'

第一种整条删掉，“model 已执行”不会打印。第二种只删名字，留下的空导入仍会加载 model，所以会打印。第四种只删 User，保留 version。

如果不开这个选项，TypeScript 会自己分析每个导入是不是只当类型用，把没当值用的导入删掉，这叫导入省略。这时前三行都会被删掉，有没有副作用就取决于编译器的分析，不直观。

为什么单文件转换器离不开它

TypeScript
import { User } from './model.ts';

用 Node.js 直接运行这一行会报 SyntaxError，说 model.ts 没有导出名为 User 的值。原因是 Node 只是把类型删掉，它只看当前文件，不知道 User 是个接口，就把它当成值去导入，而运行时的 model.ts 里根本没有这个值。写成 import type 或 import { type User }，Node 才知道要删掉它。

Node.js 直接运行 TypeScript 有哪些限制

Node.js 22.18+、23.6+ 默认开启类型剥离，24.12+、25.2+ 标记为稳定。它的做法是只把类型删掉，所以有这些限制：

  • 只删类型，不转换语法。enum、带运行时代码的 namespace、构造函数参数属性、import x = require() 都会报错；装饰器无法解析。
  • 不读取 tsconfig，所以 paths 不生效，可以用 package.json 的 imports（#src/*）替代。
  • 导入必须写 .ts 扩展名。
  • 不处理 node_modules 里的 .ts 文件。

配合它做类型检查，推荐这样配置：

json
{
  "compilerOptions": {
    "noEmit": true,
    "target": "esnext",
    "module": "nodenext",
    "rewriteRelativeImportExtensions": true,
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true
  }
}

erasableSyntaxOnly 会让 tsc 对上面那些不能直接擦掉的语法报 TS1294，在写代码时就发现问题，而不是等到运行。

其他细节

用 import type 导入的类只能当类型用，不能 new，也不能用来做 instanceof。只导出类型时写 export type { User }，重新导出类型也要标 type。

另外，verbatimModuleSyntax 不会把 ESM 语法改写成 require。在 CommonJS 文件里写 import 会报错，要么用 import x = require()，要么把文件改成 ESM。

常见追问

它和 isolatedModules 是什么关系？

isolatedModules 只是禁止那些单文件转换不了的写法。verbatimModuleSyntax 更进一步，规定导入导出按写法保留，它取代了旧的 importsNotUsedAsValues 和 preserveValueImports。两个选项经常一起开。

会影响 tree shaking 吗？

会有一点。留下来的 import {} 会让打包器认为这个模块可能有副作用，不敢删掉，除非包在 package.json 里声明了 "sideEffects": false。
