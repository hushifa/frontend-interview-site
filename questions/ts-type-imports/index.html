import type 和 verbatimModuleSyntax 如何影响模块输出？

import type 明确表达只在类型层面使用的依赖，整条纯类型导入会在输出中擦除。verbatimModuleSyntax 让导入导出的保留规则更直接：没有 type 修饰的内容按相应模块语法保留，类型部分被移除。

参考答案

import type 明确表达只在类型层面使用的依赖，整条纯类型导入会在输出中擦除。verbatimModuleSyntax 让导入导出的保留规则更直接：没有 type 修饰的内容按相应模块语法保留，类型部分被移除。

需要注意整条 import type 与在普通 import 中只写 type 成员并不完全相同：后者可能留下空导入，从而仍保留模块求值。如果依赖模块的注册副作用，应显式写副作用导入，不能寄希望于某个类型引用碰巧留下。

启用该选项后，ESM 语法不会在配置指向 CommonJS 时被悄悄改写为 require。应统一文件扩展名、package.json 的 type、模块设置与运行环境。它提高可预测性，但不代替打包器的 Tree shaking 或运行时模块解析。

TypeScript 的类型检查发生在编译期，运行时仍然执行生成的 JavaScript；类型声明不会自动校验接口返回值、用户输入或第三方数据。回答类型题时应明确哪些保证来自编译器，哪些需要运行时校验或测试补上。

公共类型还要考虑调用方的错误提示、类型推导速度、模块发布方式和版本兼容。复杂类型可以用类型测试验证，但不要为了表达一个简单约束引入难以维护的递归类型。

实际项目里，类型最容易在接口边界失效：后端返回、localStorage、URL 参数和第三方库都不是编译器可以直接信任的输入。把类型声明、运行时校验和错误处理放在同一条数据流上，类型才真正能降低维护成本。
