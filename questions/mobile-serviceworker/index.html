Service Worker 的安装、激活与缓存更新有哪些坑？

Service Worker 有独立的安装、等待和激活生命周期，注册成功不代表立即控制页面；更新要处理等待中的新版本、缓存清理和新旧资源混用。

参考答案

简答

  • 生命周期是 注册 → 安装（install）→ 等待（waiting）→ 激活（activate）→ 控制页面；首次注册的页面默认不受控，刷新后才被控制。
  • 新版本安装完成后会等待，直到所有使用旧版本的页面关闭才激活；这是保护机制，避免同一页面中途换了缓存逻辑。
  • skipWaiting() 让新版本立即激活，clients.claim() 让它立即控制已打开的页面，但可能导致旧页面加载到新版本的资源。
  • 在 activate 阶段删除旧版本的缓存，缓存名带版本号便于区分。
  • updateViaCache 默认是 'imports'：检查更新时主脚本绕过 HTTP 缓存，importScripts() 引入的脚本仍走缓存，所以被导入的脚本要带版本号。

生命周期示例

JavaScript
// sw.js
const CACHE = 'app-v3';
const PRECACHE = ['/', '/index.html', '/assets/app.3f9a.js', '/assets/app.8c21.css'];

self.addEventListener('install', (event) => {
  event.waitUntil(caches.open(CACHE).then((cache) => cache.addAll(PRECACHE)));
});

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) =>
      Promise.all(keys.filter((key) => key !== CACHE).map((key) => caches.delete(key))),
    ),
  );
});

self.addEventListener('fetch', (event) => {
  if (event.request.method !== 'GET') return;
  event.respondWith(caches.match(event.request).then((hit) => hit ?? fetch(event.request)));
});
  • install 中预缓存失败（任何一个文件 404），整个安装失败，旧版本继续工作。
  • activate 时删除其他版本的缓存。
  • 非 GET 请求直接交给网络，不缓存。

更新流程

浏览器在作用域内的页面导航时检查 Service Worker 脚本是否有变化（逐字节比较）；距上次检查超过 24 小时后，push、sync 等功能性事件也会触发检查；页面还可以调用 registration.update() 主动检查。有变化就安装新版本。新版本进入 waiting 状态，旧页面继续由旧版本控制。

JavaScript
// 页面中：发现新版本时提示用户刷新
const reg = await navigator.serviceWorker.register('/sw.js');

reg.addEventListener('updatefound', () => {
  const worker = reg.installing;
  worker?.addEventListener('statechange', () => {
    if (worker.state === 'installed' && navigator.serviceWorker.controller) {
      showUpdateBanner(() => worker.postMessage({ type: 'SKIP_WAITING' }));
    }
  });
});

let reloaded = false;
navigator.serviceWorker.addEventListener('controllerchange', () => {
  if (reloaded) return;
  reloaded = true;
  location.reload();
});
JavaScript
// sw.js
self.addEventListener('message', (event) => {
  if (event.data?.type === 'SKIP_WAITING') self.skipWaiting();
});
  • navigator.serviceWorker.controller 存在说明这是更新而不是首次安装。
  • 用户点击"刷新"后新版本才激活，激活后页面重新加载，避免新旧资源混用。
  • reloaded 标记防止重复刷新。

常见坑

问题原因处理
改了代码用户一直看到旧版新版本在等待，或 index.html 被缓存优先策略返回提示刷新；HTML 用网络优先
直接 skipWaiting 后页面报错旧页面请求的旧 chunk 已被删除缓存激活后刷新页面，或保留旧资源
Service Worker 不更新改的是 importScripts() 引入的脚本，URL 没变；或注册时设了 updateViaCache: 'all'被导入的脚本带版本号，主脚本保持固定 URL
开发时缓存干扰调试旧 Service Worker 仍在控制DevTools 中勾选 Update on reload 或注销
作用范围不对默认作用域是脚本所在目录把 sw.js 放在根目录或设置 scope

缓存策略选择

  • HTML 入口：网络优先，离线时回退缓存。
  • 带哈希的静态资源：缓存优先，文件名变化即视为新资源。
  • API 数据：网络优先或"先返回缓存再后台更新"，并按用户或租户区分。

常见追问

  • 怎样彻底移除 Service Worker？部署一个新版本，在 activate 中删除所有缓存并调用 self.registration.unregister()。
  • 要不要用 Workbox？它封装了预缓存清单、缓存策略和过期清理，能减少手写错误，原理仍是上面的生命周期。
