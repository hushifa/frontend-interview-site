CORS 携带凭据时有哪些限制？

跨源请求要带 Cookie，前端要设 credentials 为 include，服务端要返回具体的 Allow-Origin 和 Allow-Credentials: true。就算 CORS 通过了，Cookie 也可能因为 SameSite 或浏览器的第三方 Cookie 策略没被发出去。

参考答案

简答

页面在 app.example.com，接口在 api.example.com，这是跨源请求。fetch 默认的 credentials 是 'same-origin'，跨源时不带 Cookie，要显式设成 'include'；XMLHttpRequest 则是设 withCredentials = true。

服务端也要配合。它必须返回 Access-Control-Allow-Credentials: true，并且 Access-Control-Allow-Origin 要写具体的源，不能是 *。同样，Allow-Headers、Allow-Methods、Expose-Headers 在带凭据时也都不能用 *。通常的做法是按白名单回显请求的 Origin，再加上 Vary: Origin。

带不带凭据本身不影响要不要预检，是否预检仍然看请求方法、请求头和 Content-Type。

要注意，CORS 只决定页面能不能读到响应，Cookie 能不能发出去是另一回事，取决于 SameSite、Secure 和浏览器对第三方 Cookie 的策略。

前后端各要写什么

JavaScript
const response = await fetch('https://api.example.com/profile', {
  credentials: 'include',
});
http
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
Vary: Origin

为什么要加 Vary: Origin？因为服务端是按请求的 Origin 回显的，不同来源拿到的响应头不一样。不加的话，缓存可能把给 A 网站的响应发给 B 网站，B 就读不了，或者反过来。

如果请求需要预检，预检响应也要带上这两个头：

http
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
Access-Control-Allow-Methods: PUT
Access-Control-Allow-Headers: content-type, x-csrf-token

CORS 配好了，Cookie 为什么还是没带上

这是最常见的困惑。原因是 CORS 管的是“读响应”，而 Cookie 发不发由另一套规则决定。

原因说明
SameSiteapp.example.com 调 api.example.com 是同站，Lax 可以带；调 api.other.com 是跨站，需要 SameSite=None; Secure
第三方 Cookie 被浏览器限制跨站时 Safari 默认阻止，Firefox 按顶层站点分区，Chrome 用户可能手动屏蔽
Cookie 的 Domain、Path 不匹配检查 Application 面板中 Cookie 的属性
非 HTTPSSecure Cookie 只在 HTTPS 发送

最稳妥的办法是让 API 和页面同站，比如都放在 example.com 下，或者通过同源的反向代理访问 API，这样就绕开了第三方 Cookie 的问题。

配置不当会有什么风险

最危险的是不加白名单，收到什么 Origin 就回显什么，同时又允许凭据。这样任何网站都能以用户的身份读取接口数据。

白名单要用完整的源精确匹配。不要用 endsWith('example.com')，因为 evilexample.com 也是以 example.com 结尾的。Origin: null 可能来自沙箱 iframe 或本地文件，攻击者很容易构造出来，不要放进白名单。

最后，CORS 通过不等于请求合法。CORS 是浏览器保护用户的机制，修改操作仍然需要 CSRF 防护和服务端鉴权。

常见追问

为什么预检请求不带 Cookie？

规范规定预检请求永远不带凭据。所以预检接口不能要求登录，否则预检就过不去。

用 Authorization 头代替 Cookie 呢？

它是标准请求头，但不在 CORS 的安全列表里，所以会触发预检，需要在 Allow-Headers 里列出来。好处是它不受 SameSite 影响，要不要带完全由前端代码决定。
