什么是跨域？CORS 为什么需要服务端配合？

协议、主机、端口任一不同就是跨源。浏览器默认不让脚本读取跨源响应，CORS 让服务器用响应头声明允许哪些来源读取；它保护的是用户浏览器里的数据，不是服务器的访问控制。

参考答案

简答

  • 同源要求协议、主机、端口完全一致。跨源请求通常能发出去，被拦住的是脚本读取响应。
  • 服务器返回 Access-Control-Allow-Origin 等响应头，浏览器据此决定是否把响应交给脚本，所以必须由服务端配置。
  • 非简单请求（如 PUT、Content-Type: application/json、自定义请求头）会先发 OPTIONS 预检，预检通过才发真实请求。
  • CORS 不是鉴权。curl 或服务端脚本不受它约束，接口仍要自己校验身份和权限。

为什么要同源策略

浏览器会自动带上 Cookie。如果任意网站的脚本都能读取其他站点的响应，恶意页面就能以用户身份读取邮箱、银行页面的内容。同源策略限制的是"读"，CORS 是在这个限制上按服务器意愿开口子。

简单请求与预检

简单请求需同时满足：方法是 GET、HEAD 或 POST；只用浏览器允许的请求头；Content-Type 只能是 text/plain、multipart/form-data 或 application/x-www-form-urlencoded。

不满足时浏览器先发：

http
OPTIONS /api/items HTTP/1.1
Origin: https://app.example
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: content-type

服务器回应：

http
Access-Control-Allow-Origin: https://app.example
Access-Control-Allow-Methods: GET, PUT
Access-Control-Allow-Headers: content-type
Access-Control-Max-Age: 600
Vary: Origin

Access-Control-Max-Age 让浏览器缓存预检结果；按请求回显 Origin 时要加 Vary: Origin，避免 CDN 把一个来源的响应头缓存给另一个来源。

排查要点

  • 控制台报 CORS 错误时先看 Network：预检返回 404/401/500 也会表现为 CORS 失败。
  • 脚本读不到自定义响应头时，服务器要用 Access-Control-Expose-Headers 暴露。
  • 携带 Cookie 的跨源请求有额外限制，见《CORS 携带凭据时有哪些限制？》。

常见追问

  • 简单请求被 CORS 拦截，服务器有没有执行？执行了，只是脚本拿不到结果。所以有副作用的接口不能靠 CORS 防跨站伪造，要靠 CSRF 防护。
  • 开发环境怎么绕过？用开发服务器代理把请求变成同源，生产环境再正确配置响应头。
  • mode: 'no-cors' 有什么用？只能发简单请求，拿到的是不可读的不透明响应，适合打点等不关心结果的场景。
