流和背压为什么能避免一次性读入大文件？

流把数据分成小块依次处理，内存占用由缓冲区大小决定，而不是由文件大小决定。背压让写入端在缓冲区满时通知上游暂停；用 stream.pipeline 连接各个流，可以同时得到背压传递、错误传播和统一清理。

参考答案

简答

  • 流按块读写，同一时刻只在内存里保留缓冲区中的若干块，适合大文件、网络响应和压缩这类数据量不可控的场景。
  • 背压是写入端处理不过来时让上游暂停的机制：write() 返回 false 表示缓冲区已超过 highWaterMark，应等 drain 事件再继续写。
  • stream.pipeline 自动处理背压，任一环节出错时会销毁链路上的所有流并把错误交给调用方。
  • 可读流支持 for await...of 逐块消费，循环体里的 await 本身就形成背压。

一次性读取的问题

fs.readFile 会把整个文件放进一个 Buffer。文件有几个 GB 时，进程内存随之上涨，还可能超过 Buffer 的长度上限；请求并发时问题会成倍放大。流把读取拆成默认 64KB（文件流）的块，处理完一块再读下一块，内存占用和文件大小基本无关。

背压怎样发生

写入目标（磁盘、网络、压缩）通常比读取慢。如果不管写入端的状态一直往里写，数据就会堆在可写流的内部缓冲区里，效果和一次性读入差不多。

可写流用 write() 的返回值通知上游：

JavaScript
function writeMany(writable, chunks) {
  let index = 0;
  function writeNext() {
    while (index < chunks.length) {
      const ok = writable.write(chunks[index++]);
      if (!ok) {
        writable.once('drain', writeNext);
        return;
      }
    }
    writable.end();
  }
  writeNext();
}

false 不代表写入失败，这块数据已经进入缓冲区；它只是要求调用方暂停，等 drain 后再写。

用 pipeline 连接

JavaScript
import { createReadStream, createWriteStream } from 'node:fs';
import { Transform } from 'node:stream';
import { pipeline } from 'node:stream/promises';
import { createGzip } from 'node:zlib';

const upper = new Transform({
  transform(chunk, _encoding, callback) {
    callback(null, chunk.toString().toUpperCase());
  },
});

await pipeline(
  createReadStream('in.txt'),
  upper,
  createGzip(),
  createWriteStream('out.gz'),
);

pipeline 做了三件事：下游缓冲区满时暂停上游；任一流出错时销毁其余流，避免文件句柄泄漏；全部完成或出错时让 Promise 结束。旧写法 a.pipe(b).pipe(c) 能传递背压，但不会传播错误，中间某个流出错时其他流不会被关闭。

上面的 Transform 直接对块调用 toString()，多字节 UTF-8 字符恰好被切在块边界时会出现乱码。处理文本时应给可读流设置 encoding，或使用 string_decoder。

用异步迭代消费

JavaScript
let lines = 0;
for await (const chunk of createReadStream('in.txt', { encoding: 'utf8' })) {
  lines += chunk.split('\n').length - 1;
}

循环体在 await 时不会读取下一块，所以这种写法天然带背压。循环中途 break 或抛错时，流会被销毁。

常见追问

  • HTTP 响应也是流吗？ 是。http.ServerResponse 是可写流，IncomingMessage 是可读流，可以直接放进 pipeline。
  • highWaterMark 是硬上限吗？ 不是。它是 write() 开始返回 false 的阈值，不理会返回值继续写，缓冲区会超过它。
  • Web Streams 和 Node 流怎么转换？ 用 Readable.fromWeb()、Readable.toWeb() 等方法；fetch 返回的 response.body 是 Web ReadableStream。
