srcset、sizes 和 picture 怎样减少图片浪费？

srcset 提供多个候选资源，使用宽度描述符时，sizes 告诉浏览器图像在布局中预计占用的宽度，浏览器结合设备像素比等条件选择候选。sizes 描述的是展示尺寸，不是文件大小。

在“srcset、sizes 和 picture 怎样减少图片浪费？”这个问题中，先确认元素的语义和布局上下文，再检查最终计算样式、盒模型和层叠来源；最后用窄屏、长文本和键盘操作验证结果。这里的 响应式图片、srcset、picture 不是孤立的 API 名称，而是会共同影响输入、过程和最终结果。

实际排查时先看语义结构和布局上下文，再查看计算后的样式、盒模型、层叠来源和绘制结果。把视觉问题拆成结构、尺寸、定位和绘制几步，通常比反复修改一个 CSS 属性更容易定位原因。

picture 可以按媒体条件或格式提供 source，适合艺术裁切和格式回退。img 仍负责替代文本及最终回退。显式 width 和 height 或合理 aspect-ratio 能预留布局空间，减少偏移。

首屏关键图片不宜统一设置懒加载；非首屏图片可按需延迟。图片过大、错误的 sizes 和高成本格式转换都可能抵消优化，应结合实际请求与 LCP 测量验证。

交付前还要检查键盘操作、响应式断点、文本放大、打印和减少动画偏好。兼容性结论应以目标浏览器和特性检测为前提，不要把某个浏览器的偶发现象当成通用规则。

实际项目里，先用一个最小 DOM 结构复现问题，再分别修改结构、布局和样式来源。这样能区分是选择器没有命中、布局上下文不同，还是元素已经绘制但被遮挡；修复后再回到真实页面验证长文本和窄屏。
