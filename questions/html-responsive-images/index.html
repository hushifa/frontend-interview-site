srcset、sizes 和 picture 怎样减少图片浪费？

srcset 列出同一张图的几种尺寸，sizes 告诉浏览器图片在页面上显示多宽，浏览器据此挑一个刚好够清楚的最小文件。要换图片格式或者在不同屏幕上换裁切，用 picture。

参考答案

简答

同一张图，手机上显示 390px 宽，桌面上显示 720px 宽，都下载 1920px 的大图就浪费了。srcset 把几种尺寸都列出来，比如 a-480.jpg 480w, a-960.jpg 960w，w 表示这个文件实际有多宽。

光有文件宽度还不够，浏览器还得知道图片显示多宽。因为浏览器要在 CSS 加载之前就开始选图，那时它还不知道布局，所以要用 sizes 告诉它，比如 (width > 800px) 50vw, 100vw。浏览器用显示宽度乘以设备像素比，挑出足够清晰的最小文件。

显示尺寸固定的图片，比如头像，用 1x、2x 描述就够了，不需要 sizes。想提供 AVIF 这种新格式，或者手机上换一张裁成方形的图，用 <picture> 加 <source>。

要注意，<picture> 最后的 <img> 是回退，必须保留。首屏的大图不要懒加载。

浏览器到底会选哪张

HTML
<img
  src="/hero-960.jpg"
  srcset="/hero-480.jpg 480w, /hero-960.jpg 960w, /hero-1920.jpg 1920w"
  sizes="(width > 1024px) 50vw, 100vw"
  width="1920"
  height="1080"
  alt="团队在办公室讨论"
>

手机宽 390px，像素比是 3。屏幕不到 1024px，按 100vw 算，图片显示 390px，需要 390 × 3 ≈ 1170px 的文件。960w 不够，所以选 1920w。

桌面宽 1440px，像素比是 1。超过 1024px，按 50vw 算，图片显示 720px，需要 720px 的文件，选 960w 就够了。

如果不写 sizes 会怎样？浏览器默认按 100vw 算。桌面上就会以为图片要显示 1440px 宽，去下载 1920w 的大图，可实际只显示了一半。

width 和 height 写的是图片的原始尺寸。浏览器据此提前算出宽高比，图片还没到就占好位置，下面的内容不会跳。

picture：换格式和换裁切

HTML
<picture>
  <source media="(width < 600px)" type="image/avif" srcset="/hero-square.avif">
  <source media="(width < 600px)" srcset="/hero-square.jpg">
  <source type="image/avif" srcset="/hero.avif">
  <source type="image/webp" srcset="/hero.webp">
  <img src="/hero.jpg" alt="团队在办公室讨论" width="1920" height="1080">
</picture>

浏览器从上往下看，用第一个条件满足的 <source>。

所以顺序很重要。带 media 的方形裁切必须排在前面。假如把通用的 /hero.avif 放到第一个，支持 AVIF 的手机一看格式满足，就直接选中了横版大图，后面的方形版本根本轮不到。

alt、loading 这些属性只写在 <img> 上，<source> 只负责提供候选文件。

加载顺序怎么安排

首屏的大图通常是 LCP 元素，也就是首屏最大的那块内容。它不要加 loading="lazy"，可以加 fetchpriority="high" 让它优先下载。

首屏以下的图片加 loading="lazy"，滚到附近才下载。

decoding="async" 允许浏览器异步解码图片，减少对主线程的阻塞。

常见追问

CSS 背景图怎么做响应式？

用 image-set()，比如 background-image: image-set('a.avif' type('image/avif'), 'a.jpg' type('image/jpeg'))，浏览器会挑它支持的格式。
