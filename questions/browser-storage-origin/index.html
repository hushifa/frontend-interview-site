同源、同站点与跨域分别是什么意思？

同源要求协议、主机、端口都相同；同站点只比较协议和可注册域（eTLD+1），不看端口和子域；跨域通常指跨源，是同源策略和 CORS 讨论的对象。

参考答案

简答

  • 源（origin）由协议、主机、端口三部分组成，三者都相同才是同源。
  • 站点（site）由协议和可注册域（eTLD+1）组成，不包含端口，子域不同也算同站点。
  • 同源策略限制脚本读取跨源资源的内容、访问跨源窗口的 DOM，以及读取跨源存储。
  • Cookie 的 SameSite、浏览器的进程隔离按"站点"划分；CORS、localStorage、IndexedDB 按"源"划分。

例子

以 https://app.example.com 为基准：

URL同源同站点
https://app.example.com/path是是
https://api.example.com否，主机不同是
https://app.example.com:8443否，端口不同是
http://app.example.com否，协议不同否，协议不同
https://example.org否否

可注册域依据公共后缀列表（Public Suffix List）计算。github.io 在列表里，所以 a.github.io 和 b.github.io 是不同站点。

同源策略限制什么

  • 脚本读取跨源 fetch 的响应内容，除非服务端用 CORS 头授权。
  • 访问跨源 iframe 或 window.open 打开窗口的 DOM 和大部分属性。
  • 读取其他源的 localStorage、IndexedDB 和 Cookie（Cookie 按域和路径规则）。

它不限制：<img>、<script>、<link> 加载跨源资源，表单提交到跨源地址。这也是 CSRF 存在的原因。

常见追问

  • document.domain 还能用吗：现代浏览器默认禁用修改 document.domain 来放宽同源检查，不要再依赖它。
  • 跨源窗口怎样安全通信：用 postMessage，接收方校验 event.origin。
  • 为什么跨站 iframe 会放到独立进程，见《浏览器为什么要拆分进程？前端如何理解故障隔离边界？》。
