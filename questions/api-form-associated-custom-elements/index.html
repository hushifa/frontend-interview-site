表单关联自定义元素怎样参与原生提交和校验？

自定义元素默认不会被 form 当成控件。声明 static formAssociated = true 并调用 attachInternals()，就能设置提交值和校验状态，像原生 input 一样参与提交、重置和禁用。

参考答案

简答

自己写一个评分组件 <star-rating> 放进 <form>，默认情况下表单根本不认它：提交时没有它的值，required 也不起作用。

要让表单认它，在类上声明 static formAssociated = true，构造时调用 this.attachInternals()，拿到一个 ElementInternals 对象。它相当于浏览器给组件开的一个“表单接口”：setFormValue(value) 设置提交的值，setValidity(flags, message, anchor) 设置校验状态。

接上以后，组件就有了原生控件的能力：FormData 能拿到它的值，表单校验会检查它，浏览器还会在重置、禁用、恢复状态时调用 formResetCallback、formDisabledCallback、formStateRestoreCallback。无障碍属性也可以用 internals.role、internals.ariaDisabled 设置，不用写在宿主元素上。

最容易漏的是：元素一连接到页面就要同步一次校验状态。否则用户什么都不点直接提交，表单会以为它是有效的。

写一个必填的评分组件

下面的组件只做一件事：保存一个评分值，必填且为空时报错。

JavaScript
class StarRating extends HTMLElement {
  static formAssociated = true;
  static observedAttributes = ['required'];
  #internals = this.attachInternals();
  #value = '';

  connectedCallback() {
    this.#internals.role = 'radiogroup';
    this.#sync();
  }

  attributeChangedCallback() {
    this.#sync();
  }

  set value(next) {
    this.#value = String(next);
    this.#sync();
  }

  get value() {
    return this.#value;
  }

  formResetCallback() {
    this.value = '';
  }

  formDisabledCallback(disabled) {
    this.#internals.ariaDisabled = String(disabled);
  }

  #sync() {
    this.#internals.setFormValue(this.#value);
    if (this.hasAttribute('required') && this.#value === '') {
      this.#internals.setValidity({ valueMissing: true }, '请选择评分');
    } else {
      this.#internals.setValidity({});
    }
  }
}

customElements.define('star-rating', StarRating);
HTML
<form>
  <star-rating name="score" required></star-rating>
  <button>提交</button>
</form>

所有改动都汇总到 #sync()：先用 setFormValue 告诉表单当前值，再根据是否必填设置校验状态。setValidity({ valueMissing: true }, '请选择评分') 表示“缺值”，第二个参数是提示文字；传空对象 {} 表示有效。

所以用户不选就点提交，浏览器检查到 valueMissing，会阻止提交并显示“请选择评分”。选了以后提交成功，FormData 里就有 score 字段。

为什么 connectedCallback 里也要调用 #sync()？因为初始值是空的，如果不在一开始就标记成“缺值”，用户不操作直接提交，表单拿到的是默认的有效状态，就放行了。同理，去掉 required 属性时 attributeChangedCallback 会重新同步，空值就能提交了。

错误提示显示在哪里

浏览器原生的错误气泡会指向 setValidity 的第三个参数，通常传 Shadow DOM 里一个可以聚焦的元素，比如第一颗星。

如果想自己显示错误文字，就监听 invalid 事件，从 this.#internals.validationMessage 读出提示写进错误区域，再调用 event.preventDefault() 关掉原生气泡。

接上以后能获得哪些原生能力

form.elements 和 new FormData(form) 都能拿到它。放在 <fieldset disabled> 里时，浏览器会通过 formDisabledCallback 通知它被禁用了。表单的 checkValidity()、reportValidity()，以及元素的 :invalid 伪类，都会用到它的校验状态。浏览器前进后退和自动填充时，会通过 formStateRestoreCallback 把值恢复回来。

有一点不会自动获得：元素自己的 checkValidity() 方法。如果需要，在类上定义一个，转调 internals.checkValidity()。

常见追问

不加 formAssociated 直接调用 setFormValue 会怎样？

不行。只有声明了 static formAssociated = true 的元素，ElementInternals 上的表单相关方法才能用，否则浏览器会抛错，表单也不会把它当控件。

为什么无障碍属性写在 internals 上，而不是宿主元素的 attribute 上？

写在 internals 上是组件内部的默认语义，不会出现在页面的 HTML 属性里，也不会被使用者误删。使用者如果自己在宿主元素上写了 role，以使用者写的为准。
