useActionState 如何把异步 Action 的结果变成组件状态？

useActionState 把一个可能是异步的函数包起来，函数每次的返回值就是新的状态，还顺带给你一个"是否在提交中"的标记。多次提交会排队，后一次能拿到前一次的结果。

参考答案

简答

写表单时，经常要处理“提交 → 等接口返回 → 显示成功或失败”。useActionState 就是干这个的：你给它一个处理函数和初始状态，它返回当前状态、一个可以直接传给 <form action> 的 dispatch 函数，以及表示是否在提交中的 isPending。

处理函数叫 Action，它收到两个参数：上一次的状态和本次提交的数据。它返回什么，新状态就是什么，返回 Promise 也可以。多次提交会按顺序排队，后一次拿到的是前一次的结果。

它的用处是把“提交结果”直接变成组件状态，不用自己写 loading、error 两三个 state。React 19 里它取代了早期的 useFormState。

要注意两点。第一，表单 Action 只要没有抛错，React 就会重置非受控的输入框，哪怕返回的是“失败”，所以要把用户输入放进返回值再回填。第二，可预期的错误应该返回，不要 throw，抛出的错误会交给 Error Boundary，还会取消后面排队的调用。

先看一个订阅表单

下面这个表单提交邮箱。subscribe 是 Action，它返回的对象就是新的 state。

JSX
import { useActionState } from 'react';

async function subscribe(prevState, formData) {
  const email = String(formData.get('email') ?? '').trim();
  if (!email.includes('@')) {
    return { ok: false, message: '邮箱格式不正确', email };
  }
  const res = await fetch('/api/subscribe', {
    method: 'POST',
    body: JSON.stringify({ email }),
    headers: { 'Content-Type': 'application/json' },
  });
  if (!res.ok) return { ok: false, message: '订阅失败，请稍后重试', email };
  return { ok: true, message: '订阅成功', email: '' };
}

export default function SubscribeForm() {
  const [state, formAction, isPending] = useActionState(subscribe, {
    ok: false,
    message: '',
    email: '',
  });

  return (
    <form action={formAction}>
      <input name="email" type="email" defaultValue={state.email} aria-describedby="msg" />
      <button disabled={isPending}>{isPending ? '提交中…' : '订阅'}</button>
      <p id="msg" role="status">{state.message}</p>
    </form>
  );
}

完整的签名是 useActionState(action, initialState, permalink?)。dispatch 传给 <form action> 时，Action 的第二个参数就是表单的 FormData。React 会把这次调用放在 Transition 里执行（Transition 就是“不着急、可以在后台进行的更新”），所以执行期间 isPending 是 true，按钮可以显示“提交中”。

看代码时你可能会问：失败了为什么还要把 email 放进返回值？因为 Action 只要没有抛错，React 就认为它完成了，会重置非受控字段，输入框会被清空。把用户输入带回来，再用 defaultValue 填回去，用户就不用重新输入。

失败为什么要返回，不要 throw

“邮箱格式不对”“接口返回失败”都是能预料的情况，返回一个带错误信息的对象，界面直接显示就行。

如果在 Action 里 throw，这个错误会交给最近的 Error Boundary，整块区域变成错误界面。而且排在后面的调用会被取消。所以 throw 只留给真正意料之外的错误。

多次提交是怎么排队的

用户连续点了几次，React 不会让几次调用同时跑，而是一个接一个执行。后一次调用拿到的 prevState，就是前一次的返回值。这样状态的变化顺序跟提交顺序一致，不会出现后发的请求先回来、把结果覆盖掉的情况。

不用表单也能调用

dispatch 也可以在按钮点击里手动调用，但要放进 startTransition，否则 isPending 不会更新：

JSX
import { startTransition } from 'react';

function onClick() {
  startTransition(() => dispatch({ type: 'increment' }));
}

这时 Action 收到的第二个参数就是你传的 { type: 'increment' }。

和 Server Functions 一起用

在支持 React Server Components 的框架里，Action 可以是标了 'use server' 的 Server Function，也就是在服务端执行的函数。

第三个参数 permalink 是给“JavaScript 还没加载完”准备的。这时用户提交表单，浏览器会按普通表单跳转到这个 URL，由服务端处理后返回页面。这种“没有 JS 也能用、有了 JS 体验更好”的做法叫渐进增强。

常见追问

和 useFormStatus 有什么区别？

useActionState 管的是 Action 的结果，在渲染表单的组件里用。useFormStatus 只让表单里面的子组件知道父表单是不是在提交，拿不到结果。详见《React useFormStatus 适合管理什么表单状态？》。

想让结果立刻显示，不等接口返回怎么办？

配合 useOptimistic 先显示一个临时状态，接口返回后再换成真实结果。详见《useOptimistic 的临时状态怎样与真实结果收敛？》。

校验和权限检查它会帮我做吗？

不会。它只负责把返回值变成状态，校验、权限、错误信息都要在 Action 里自己写。
