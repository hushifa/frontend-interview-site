搜索建议什么时候适合用 Trie？前缀树怎样处理重复词和 Unicode？

以命令面板的前缀搜索为例，用 Map 节点实现 Trie：每个节点代表一个前缀，terminal 标记表示有个词在这里结束。查一个前缀要走几步只看前缀多长，跟总共有多少词无关。插入前要统一 Unicode 编码和大小写；要模糊匹配或按热度排序时，Trie 就不够用了。

参考答案

简答

Trie 也叫前缀树。它的每条边是一个字符，从根走到某个节点，经过的字符连起来就是一个前缀。节点上有个 terminal 标记，用来区分“这里是一个完整的词”和“只是路过”。

它的好处是，判断一个前缀存不存在，只要走 m 步，m 是前缀的长度，跟总共有多少词无关。要列出所有建议，就再把这个前缀下面的子树遍历一遍。同一个词重复插入不会多出节点，只要看 terminal 是不是已经是 true。

Unicode 有两个坑。第一，看起来一样的 café，可能有两种编码，所以插入和查询前都要用 normalize('NFC') 统一一下。第二，emoji 在 UTF-16 里占两个码元，要用 for...of 按码点遍历，不然会被拆成两半。

也不是什么时候都要用 Trie。词条只有几百个时，filter 加 startsWith 就够快了。需要容错、拼写纠正或者匹配中间的子串时，Trie 做不了，要用模糊搜索库或倒排索引。

实现

JavaScript
class Trie {
  #root = { terminal: false, children: new Map() };

  #normalize(word) {
    return word.normalize('NFC').toLocaleLowerCase('en');
  }

  insert(word) {
    const key = this.#normalize(word);
    if (key === '') return false;
    let node = this.#root;
    for (const char of key) {
      if (!node.children.has(char)) {
        node.children.set(char, { terminal: false, children: new Map() });
      }
      node = node.children.get(char);
    }
    if (node.terminal) return false;
    node.terminal = true;
    // 保存原始写法，用于展示。
    node.word = word;
    return true;
  }

  #find(prefix) {
    let node = this.#root;
    for (const char of this.#normalize(prefix)) {
      node = node.children.get(char);
      if (!node) return undefined;
    }
    return node;
  }

  has(word) {
    return this.#find(word)?.terminal === true;
  }

  suggest(prefix, limit = 5) {
    const start = this.#find(prefix);
    if (!start) return [];
    const result = [];
    const stack = [start];
    while (stack.length > 0 && result.length < limit) {
      const node = stack.pop();
      if (node.terminal) result.push(node.word);
      // 反向入栈，让字符较小的子节点先被访问，结果按字典序输出。
      const children = [...node.children].sort(([a], [b]) => (a < b ? 1 : -1));
      for (const [, child] of children) stack.push(child);
    }
    return result;
  }
}

const commands = new Trie();
for (const word of ['Open File', 'Open Folder', 'Open Recent', 'Save', 'Open File']) {
  commands.insert(word);
}
console.log(commands.suggest('open f')); // ['Open File', 'Open Folder']
console.log(commands.has('open')); // false，只是前缀
console.log(commands.suggest('x')); // []

用户输入的是小写的 open f，也匹配到了 Open File。这是因为插入和查询都经过 #normalize，统一转成了小写。可是建议里显示的还是原来的大小写，因为词尾节点上另外存了一份原始写法 node.word。

has('open') 是 false。open 这条路径是存在的，但它只是 Open File 的前缀，节点上的 terminal 不是 true。

Open File 插了两次，第二次返回 false，不会出现重复的建议。limit 的作用是找够了就停，前缀很短、词条又很多时，也不用把整棵子树走完。

Unicode 的两个问题

问题例子处理
同一个字形有多种编码é 可以是一个码点，也可以是 e 加组合重音符插入和查询都做 NFC 归一化
一个字符占两个 UTF-16 码元'👍🏽'.length 是 4，[...'👍🏽'].length 是 2用 for...of 按码点遍历

第一行是什么意思？é 有两种存法，一种是一个现成的 é 字符，另一种是普通的 e 后面跟一个“加重音”的符号。屏幕上看着一模一样，但在 Trie 里走的是不同的路径，用户怎么输都可能匹配不上。NFC 归一化会把它们统一成同一种。

第二行里，👍🏽 是一个带肤色的点赞，它本身由两个码点组成：点赞和肤色修饰。按码点遍历时，它会变成两条边，但不会被拆成半个字符，对前缀匹配没有影响。如果要按用户眼里的“一个字”来计数，用 Intl.Segmenter。

大小写转换为什么固定写 en？因为在土耳其语环境下，I 转小写会变成没有点的 ı，同一个命令在不同用户的电脑上就匹配不上了。

什么时候不用 Trie

词条很少时不用。几百条数据，直接 startsWith 一个个比，耗时可以忽略，代码也简单得多。

需要按热度或最近使用排序时，光靠 Trie 不行。它只能按字典序遍历，要么在节点上额外存权重，要么先取出候选再排序。

需要模糊匹配时也不行。用户输入 opn fl，也希望匹配到 Open File，这需要子序列匹配或者编辑距离，VS Code 的命令面板就是这样做的。

常见追问

空间复杂度是多少？

最坏情况是所有词条的字符数加起来。词之间共享的前缀越多越省空间。中文这种字符集很大、前缀很少重合的场景，节点数会接近总字符数。

怎么删除一个词？

先把它词尾节点的 terminal 改成 false，再从下往上，把既没有子节点、也不是别的词结尾的节点删掉。
