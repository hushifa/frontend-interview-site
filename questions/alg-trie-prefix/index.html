搜索建议什么时候适合用 Trie？前缀树怎样处理重复词和 Unicode？

以命令面板的前缀搜索为例，用 Map 节点实现 Trie：每个节点代表一个前缀，terminal 标记表示某个词在这里结束。查询前缀的耗时只与前缀长度有关，与词条总数无关。插入前统一 Unicode 归一化和大小写；需要模糊匹配或按热度排序时，Trie 就不够用了。

参考答案

简答

  • Trie 的每条边是一个字符，从根到某个节点的路径就是一个前缀；节点上的 terminal 标记区分"这是一个完整的词"和"只是路径经过"。
  • 判断前缀是否存在只需走 m 步（m 是前缀长度），与词条总数无关；列出所有建议还要遍历该前缀下的子树。
  • 重复插入同一个词不会新增节点，只需检查 terminal 是否已经为 true。
  • 插入和查询前都用 normalize('NFC') 归一化，否则字形相同的 café 可能有两种编码；用 for...of 按码点遍历，避免把 emoji 的代理对拆开。
  • 词条只有几百个时，filter 加 startsWith 已经足够快；需要容错、拼写纠正或子串匹配时，应使用模糊搜索库或倒排索引。

实现

JavaScript
class Trie {
  #root = { terminal: false, children: new Map() };

  #normalize(word) {
    return word.normalize('NFC').toLocaleLowerCase('en');
  }

  insert(word) {
    const key = this.#normalize(word);
    if (key === '') return false;
    let node = this.#root;
    for (const char of key) {
      if (!node.children.has(char)) {
        node.children.set(char, { terminal: false, children: new Map() });
      }
      node = node.children.get(char);
    }
    if (node.terminal) return false;
    node.terminal = true;
    // 保存原始写法，用于展示。
    node.word = word;
    return true;
  }

  #find(prefix) {
    let node = this.#root;
    for (const char of this.#normalize(prefix)) {
      node = node.children.get(char);
      if (!node) return undefined;
    }
    return node;
  }

  has(word) {
    return this.#find(word)?.terminal === true;
  }

  suggest(prefix, limit = 5) {
    const start = this.#find(prefix);
    if (!start) return [];
    const result = [];
    const stack = [start];
    while (stack.length > 0 && result.length < limit) {
      const node = stack.pop();
      if (node.terminal) result.push(node.word);
      // 反向入栈，让字符较小的子节点先被访问，结果按字典序输出。
      const children = [...node.children].sort(([a], [b]) => (a < b ? 1 : -1));
      for (const [, child] of children) stack.push(child);
    }
    return result;
  }
}

const commands = new Trie();
for (const word of ['Open File', 'Open Folder', 'Open Recent', 'Save', 'Open File']) {
  commands.insert(word);
}
console.log(commands.suggest('open f')); // ['Open File', 'Open Folder']
console.log(commands.has('open')); // false，只是前缀
console.log(commands.suggest('x')); // []

第二次插入 Open File 返回 false，不会产生重复建议。limit 让遍历在找够建议后停止，前缀很短、词条很多时也不会遍历整棵子树。

Unicode 的两个问题

问题例子处理
同一个字形有多种编码é 可以是一个码点，也可以是 e 加组合重音符插入和查询都做 NFC 归一化
一个字符占两个 UTF-16 码元'👍🏽'.length 是 4，[...'👍🏽'].length 是 2用 for...of 按码点遍历

肤色修饰的 emoji 由两个码点组成，按码点遍历仍会拆成两条边，对前缀匹配没有影响。需要按用户感知的字符计数时，用 Intl.Segmenter。大小写转换固定了 en 区域，避免土耳其语环境下 I 转成无点的 ı。

什么时候不用 Trie

  • 词条少：线性 startsWith 实现简单，几百条数据的耗时可以忽略。
  • 需要按热度或最近使用排序：Trie 只能按字典序遍历，要在节点上额外存储权重，或者取出候选后再排序。
  • 需要模糊匹配：用户输入 opn fl 也想匹配 Open File，这需要子序列匹配或编辑距离，VS Code 的命令面板就是这样。

常见追问

  • 空间复杂度？ 最坏是所有词条字符数之和。共享前缀越多越省；中文这类字符集大、前缀共享少的场景，节点数接近总字符数。
  • 怎样删除词条？ 把 terminal 改为 false，再从下往上删除没有子节点、也不是词尾的节点。
