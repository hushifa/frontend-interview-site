TypeScript 声明合并和模块扩展有哪些边界？

同名的 interface 会自动合成一个，declare module 和 declare global 可以给已有的模块或全局对象补类型。这些写法只补类型，真正的实现要另外写，并且确保那段代码被加载。

参考答案

简答

声明合并就是同一个名字声明了好几次，TypeScript 把它们拼成一个。最常见的是同名 interface，成员会合到一起；同名属性的类型必须相同，同名方法会变成重载，后写的重载排在前面。namespace 还能和同名的函数、类、枚举合并，给它们加静态成员。

在此基础上可以扩展别人的类型。declare module './x' 给已有模块补类型，叫模块增补，它只能改已有的导出，不能新增顶层导出。declare global 用来在模块文件里扩展全局类型，比如给 Window 加字段。

有用的地方是给库预留的扩展点补字段，比如 Vue 的 ComponentCustomProperties、Express 的 Request。

最要注意的是，这些扩展都只是类型。运行时的实现得另外写，还要通过副作用导入确保它真的执行了。另外带运行时代码的 namespace 不能被直接擦掉，开启 erasableSyntaxOnly 或用 Node.js 直接运行时会报错。

同名 interface 会合成一个

TypeScript
interface PanelOptions {
  title: string;
}
interface PanelOptions {
  width: number;
}
const panel: PanelOptions = { title: '阅读设置', width: 320 };

两段 PanelOptions 分开写，用的时候却要求同时有 title 和 width，因为编译器把它们合并了。要是第二段也写了 title: number，就会报错，同名属性的类型必须一致。

函数和 namespace 合并

想给一个函数挂上 version 这样的静态属性，老写法是用同名 namespace：

TypeScript
function formatLabel(value: string): string {
  return value.trim();
}
namespace formatLabel {
  export const version = '1.0.0';
}

这样写类型上没问题，可 namespace 不是纯类型，它会被编译成一个立即执行函数，给函数对象赋值。所以只删类型的工具处理不了它：开启 erasableSyntaxOnly（TS 5.8+）时报 TS1294，Node.js 直接运行也会失败。换成下面这种只用普通 JS 的写法就没问题：

TypeScript
export const formatLabel = Object.assign(
  (value: string) => value.trim(),
  { version: '1.0.0' },
);

只有类型的 namespace 和 declare namespace 可以直接擦掉，不受这个限制。

模块增补：补了类型，实现呢

下面给一个已有的 Counter 类补一个 reset 方法，分三个文件来看。

TypeScript
// counter.ts
export class Counter {
  value = 0;
  increment(): void {
    this.value += 1;
  }
}
TypeScript
// counter-reset.ts
import { Counter } from './counter.js';

declare module './counter.js' {
  interface Counter {
    reset(): void;
  }
}

Counter.prototype.reset = function () {
  this.value = 0;
};
TypeScript
// main.ts
import { Counter } from './counter.js';
import './counter-reset.js';

const counter = new Counter();
counter.increment();
counter.reset();

counter-reset.ts 做了两件事：declare module 里那段告诉编译器 Counter 多了个 reset，下面那行给原型赋值才是真正的实现。

现在试着删掉 main.ts 里的 import './counter-reset.js'。类型检查照样通过，因为增补的声明在整个项目里都可见；可运行时实现那段没有执行，counter.reset() 就会报“不是函数”。所以补类型的同时，必须确认实现文件被导入了。

还有一个容易漏的条件：增补文件自己必须是模块，也就是有 import 或 export。否则 declare module './counter.js' 会被当成声明一个全新的模块，而不是给原有模块补充。

扩展全局类型

TypeScript
// globals.d.ts
export {};
declare global {
  interface Window {
    appVersion?: string;
  }
}

export {} 让这个文件成为模块，这样才能用 declare global。写完以后 window.appVersion 不再报错，但这只是告诉编译器“它可能存在”，值要在别的代码里真正赋上去。

什么时候该用，什么时候不该用

给库预留的扩展点补字段是正当用法，比如 Vue 的 ComponentCustomProperties、Express 的 Request。不要用增补去掩盖版本不兼容：库已经删掉了某个方法，你把类型补回来，错误只是推迟到了运行时。全局扩展影响整个项目，也容易和别的库冲突，能不用就少用。

常见追问

type 能合并吗？

不能。同名的 type 会报重复标识符的错误，这也是它和 interface 的区别之一，见《type 和 interface 有哪些区别？》。

类和接口能合并吗？

能。同名的 interface 会给类的实例类型补成员，但它不提供实现，跟模块增补一样，需要另外给原型或实例赋值。
