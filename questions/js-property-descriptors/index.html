属性描述符、Object.freeze 和只读有什么区别？

属性描述符控制单个属性能否写入、枚举和重新配置。preventExtensions、seal、freeze 依次加强对整个对象的限制，但都只作用于一层。const 约束的是变量绑定，TypeScript readonly 只在编译期检查。

参考答案

简答

  • 数据属性有 value、writable、enumerable、configurable；访问器属性用 get、set 代替前两个。
  • Object.defineProperty 未写明的特性默认为 false；普通赋值创建的属性三个特性都是 true。
  • preventExtensions 禁止新增属性，seal 再禁止删除和重新配置，freeze 再把数据属性设为不可写。
  • freeze 是浅冻结，嵌套对象仍可修改；严格模式下写入被冻结的属性抛 TypeError，非严格模式静默失败。
  • const 只禁止重新赋值绑定，TypeScript 的 readonly 只在编译期检查，运行时都不冻结对象。

浅冻结

JavaScript
const item = Object.freeze({ nested: { count: 0 } });
item.nested.count += 1;
console.log(item.nested.count); // 1

item.nested 这个属性不能改指向，但它指向的对象没被冻结。需要深冻结时递归调用 Object.freeze，并注意跳过已冻结对象以处理循环引用。

描述符

JavaScript
const config = {};
Object.defineProperty(config, 'version', { value: 1 });

console.log(Object.getOwnPropertyDescriptor(config, 'version'));
// { value: 1, writable: false, enumerable: false, configurable: false }
console.log(Object.keys(config)); // []
  • writable: false：不能赋值，但若 configurable: true 仍可用 defineProperty 改值。
  • enumerable: false：不出现在 Object.keys、for...in、JSON.stringify 中。
  • configurable: false：不能删除，不能改成访问器，也不能把 enumerable 改回来；仍可写时可以修改 value，或把 writable 从 true 改为 false，反向不行。

三种对象级限制

方法新增删除修改值检查
Object.preventExtensions否是是Object.isExtensible
Object.seal否否是Object.isSealed
Object.freeze否否否Object.isFrozen

访问器属性被冻结后 setter 仍可调用，setter 改的是闭包或别处的状态。Map、Set、Date 的数据存在内部槽里，Object.freeze(map) 后 map.set() 照样生效。

各层次的"只读"

机制作用对象时机
const变量绑定运行时
writable: false单个属性运行时
Object.freeze对象的一层属性运行时
TS readonly / Readonly<T>类型仅编译期

常见追问

  • 冻结对象对性能有影响吗？现代引擎上冻结本身开销很小，但深冻结大对象图需要遍历。
  • React 状态需要冻结吗？不需要，约定不直接修改即可；开发阶段可以用 Immer 等库自动冻结来发现误改。
