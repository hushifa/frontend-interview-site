属性描述符、Object.freeze 和只读有什么区别？

属性描述符管的是单个属性能不能改、能不能被遍历、能不能删。Object.freeze 把整个对象冻住，但只冻一层。const 只是不让变量重新赋值，TypeScript 的 readonly 只在编译时检查。

参考答案

简答

每个属性背后都有几个开关，合起来叫属性描述符。普通的数据属性有 value、writable（能不能改值）、enumerable（会不会被遍历出来）、configurable（能不能删、能不能改这些开关）。访问器属性用 get、set 代替前两个。直接赋值创建的属性，三个开关都是 true；用 Object.defineProperty 创建时，没写的开关默认都是 false。

想限制整个对象，有三个由弱到强的方法：preventExtensions 不让加新属性，seal 再加上不让删、不让改配置，freeze 再把所有数据属性都变成不可写。

要注意 freeze 只冻一层，嵌套的对象还能改。写入冻结的属性，严格模式下抛 TypeError，非严格模式下什么也不发生。

另外 const 只是不让变量重新赋值，TypeScript 的 readonly 只在编译时检查，它们在运行时都不会冻结对象。

冻结以后为什么还能改

JavaScript
const item = Object.freeze({ nested: { count: 0 } });
item.nested.count += 1;
console.log(item.nested.count); // 1

item 已经冻结了，可 item.nested.count 还是从 0 变成了 1。

因为 freeze 只冻结 item 自己的属性。item.nested 这个属性确实不能再指向别的对象了，但它指向的那个对象本身没有被冻结，里面的 count 照样能改。这就叫浅冻结。

需要深冻结时，就递归地对每一层调用 Object.freeze。递归时跳过已经冻结的对象，碰到循环引用才不会死循环。

用 defineProperty 创建的属性有什么不同

JavaScript
const config = {};
Object.defineProperty(config, 'version', { value: 1 });

console.log(Object.getOwnPropertyDescriptor(config, 'version'));
// { value: 1, writable: false, enumerable: false, configurable: false }
console.log(Object.keys(config)); // []

只写了 value，其他三个开关都成了 false。所以 Object.keys 返回空数组，因为这个属性不可枚举。

每个开关的效果是这样的。writable: false 时不能赋值，但如果 configurable 还是 true，仍然可以用 defineProperty 改它的值。enumerable: false 时，它不会出现在 Object.keys、for...in 和 JSON.stringify 里。

configurable: false 的限制最多：不能删除，不能改成访问器属性，enumerable 也改不回来了。不过如果它还可写，仍然可以修改 value，或者把 writable 从 true 改成 false，反过来改回 true 就不行了。

三种对象级限制怎么选

方法新增删除修改值检查
Object.preventExtensions否是是Object.isExtensible
Object.seal否否是Object.isSealed
Object.freeze否否否Object.isFrozen

冻结也有管不到的地方。访问器属性被冻结后，setter 还是能调用，它改的是闭包里或者别处的状态，不是这个属性本身。Map、Set、Date 的数据也不存在属性里，而是存在引擎内部的槽里，所以 Object.freeze(map) 以后，map.set() 照样生效。

各种“只读”分别管什么

机制作用对象时机
const变量绑定运行时
writable: false单个属性运行时
Object.freeze对象的一层属性运行时
TS readonly / Readonly<T>类型仅编译期

const 管的是变量这个名字不能重新指向别的值，对象里面怎么改它不管。TypeScript 的 readonly 编译成 JavaScript 以后就没了，运行时完全不起作用。

常见追问

冻结对象对性能有影响吗？

在现代引擎上，冻结本身的开销很小。但深冻结一个很大的对象图要把每一层都遍历一遍，这一步会有开销。

React 的状态需要冻结吗？

不需要，约定好不直接修改就行。开发阶段可以用 Immer 这类会自动冻结的库，误改时能马上发现。
