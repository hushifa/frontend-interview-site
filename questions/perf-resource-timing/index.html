Resource Timing 为什么有些跨源字段是零？

跨源资源没有返回 Timing-Allow-Origin 时，DNS、连接、请求、响应这些细分时间和 transferSize、nextHopProtocol 都会被置零或置空；encodedBodySize、decodedBodySize、responseStatus 要看是否以 CORS 模式请求并通过检查。transferSize 为 0 也可能是命中了本地缓存，要结合其他字段区分。

参考答案

简答

Resource Timing 是浏览器记录的每个资源的加载时间线，比如 DNS 查询、建立连接、下载各花了多久。可是跨源资源默认只公开 startTime、duration、responseEnd 这种粗粒度的时间，细分阶段都是 0。这是为了防止别的网站通过这些时间去探测用户的信息。

这些字段分两类权限。DNS、连接、requestStart、responseStart 这些细分时间，以及 transferSize、nextHopProtocol、serverTiming，要资源服务器返回 Timing-Allow-Origin 响应头才开放，简称 TAO。encodedBodySize、decodedBodySize、responseStatus、contentType 则受 CORS 控制，资源要以 CORS 模式请求并通过检查才有值。

还要注意，transferSize 为 0 通常有两种情况：命中了本地缓存，或者跨源资源没给 TAO 授权。连接复用只会让连接阶段的耗时为 0，不影响 transferSize。另外 transferSize 是正文大小加上一个代表响应头的固定值，不是精确的线上字节数。

为什么要把跨源的细节藏起来

设想一个恶意网站请求某个银行的图片。如果能拿到 DNS 和连接耗时，它就能推断出用户最近访问过这家银行，因为 DNS 有缓存、连接被复用了，这些阶段就会特别快。所以规范默认把细分阶段隐藏，只留下风险较低的总耗时。

怎样开放跨源细节

资源服务器在响应里加上这个头：

http
Timing-Allow-Origin: https://www.example.com

值也可以写 *，但只适合公开资源。CDN 上的字体、图片想做性能分析，就要在 CDN 上配置这个头。

encodedBodySize 这类大小字段走的是 CORS，所以光有 TAO 还不够，图片、脚本标签要加 crossorigin 属性，服务器还要返回 Access-Control-Allow-Origin。

怎样区分缓存命中和没有权限

transferSize 是 0 时，到底是缓存命中还是没权限？下面的代码先判断有没有 TAO，再看大小：

JavaScript
for (const entry of performance.getEntriesByType('resource')) {
  const crossOrigin = new URL(entry.name).origin !== location.origin;
  // 有 TAO 时连接相关字段非 0；只看 nextHopProtocol 会把缓存命中（也可能为空）误判成无 TAO
  const timingAllowed = !crossOrigin || entry.requestStart > 0 || entry.nextHopProtocol !== '';

  let source;
  if (!timingAllowed) source = '无 TAO，无法判断';
  else if (entry.transferSize === 0) source = '本地缓存';
  else if (entry.transferSize < entry.encodedBodySize) source = '验证后复用（304）';
  else source = '网络';

  console.log(entry.name, source, {
    transferSize: entry.transferSize,
    encodedBodySize: entry.encodedBodySize,
    decodedBodySize: entry.decodedBodySize,
  });
}

为什么判断 TAO 要同时看 requestStart 和 nextHopProtocol？因为浏览器没有直接告诉你“有没有授权”，只能从字段反推。没有授权时这些字段都是 0 或空字符串；同源或已授权的资源，nextHopProtocol 会是 h2、h3 这样的值。可是缓存命中时 nextHopProtocol 也可能为空，所以只看它会误判，要再加上 requestStart。这只是常用的经验方法，不是规范给出的判断方式。

另外，decodedBodySize 比 encodedBodySize 大，说明资源传输时经过了压缩。

还有哪些要注意的

资源条目的缓冲区默认是有限的，通常是 250 条。资源多的页面要用 PerformanceObserver 持续收集，或者调用 performance.setResourceTimingBufferSize() 调大。

资源如果是 Service Worker 返回的，可以看 workerStart。

deliveryType 可以标识资源来自缓存还是导航预取，它同样受 TAO 控制，各浏览器的支持情况也不一样。

常见追问

图片、脚本标签怎么用 CORS 模式请求？

在标签上加 crossorigin 属性，同时服务器要返回 Access-Control-Allow-Origin。

为什么跨源资源的 duration 也有值？

规范认为总耗时风险较低，所以保留了它。细分阶段才会泄露 DNS 缓存、连接复用这类信息，所以要授权才开放。
