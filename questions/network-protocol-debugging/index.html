前端网络问题应该怎样按协议层排查？

前端看到的"请求失败"可能出在 URL、DNS、连接与 TLS、HTTP、浏览器策略（CORS、CSP、混合内容）、缓存与 Service Worker、数据解析中的任何一层。先在 DevTools 里保存原始证据，再从下往上逐层排除。

参考答案

简答

  • 先记录事实：完整 URL、方法、状态码、请求头和响应头、Timing、控制台错误。不要先清缓存或改代码，证据会丢失。
  • 状态栏显示 (failed) 且没有状态码，多半是 DNS、连接、TLS 或浏览器策略问题，改 CORS 配置修不好证书错误。
  • 有状态码时分开看三件事：HTTP 状态、Content-Type 与正文是否符合预期、业务字段是否成功。
  • CORS 问题要分别检查预检请求和实际请求；响应可能来自缓存或 Service Worker，不一定来自服务器。

逐层排查

层典型现象证据
URL请求了错误地址、子路径部署后相对路径错Network 中的实际 URL、重定向链
DNS / 连接 / TLSERR_NAME_NOT_RESOLVED、ERR_CERT_*、超时错误码、Timing 中停在哪一段
HTTP4xx、5xx、意外的 3xx状态码、响应头、正文
浏览器策略控制台提示 CORS、CSP、混合内容、权限策略控制台消息、预检请求
缓存 / Service Worker拿到旧内容Size 列显示 (disk cache) 或 (ServiceWorker)、Age 头
数据JSON.parse 报错、字段缺失实际正文，例如登录过期返回了 HTML

几个典型场景

接口在浏览器失败、curl 成功：curl 不执行同源策略，也不带浏览器的 Cookie。先看控制台是否有 CORS 或 CSP 错误，再看预检是否返回 2xx 和正确的 Access-Control-Allow-*。

发版后部分用户仍是旧页面：检查 HTML 的 Cache-Control、CDN 命中情况，以及是否有 Service Worker 在返回缓存。Application 面板可以查看 Service Worker 状态和 Cache Storage。

流式输出一次性出现：中间的代理或 CDN 缓冲了响应，或者开启了压缩缓冲。检查代理配置（如关闭缓冲）和响应头，服务端日志显示已写出不代表浏览器已收到。

写操作超时：服务器可能已经执行成功，只是响应没回来。不要直接重试非幂等请求，先查询结果或使用幂等键。

工具分工

  • Network 面板：浏览器实际发出和收到的内容，可以导出 HAR 交给后端。
  • Console：CORS、CSP、混合内容等策略错误只在这里有详细说明。
  • Application 面板：Service Worker、Cache Storage、Cookie。
  • curl -v、openssl s_client：绕开浏览器策略，单独验证 DNS、TLS 和 HTTP。
  • 服务器、CDN 日志：确认请求是否到达、是否回源。

导出 HAR 前注意，它包含 Cookie 和令牌，分享前要脱敏。

常见追问

  • 为什么 JS 拿不到失败原因？浏览器对网络和跨源错误只给脚本一个笼统的 TypeError，避免泄露跨源信息，细节只在 DevTools 中可见。
  • (pending) 一直不结束？可能是服务器没有响应、连接数已满（HTTP/1.1 同域名约 6 个），或流式响应仍在进行。
