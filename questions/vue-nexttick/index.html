修改状态后，为什么有时需要 await nextTick()？

改了响应式数据，数据本身马上变了，可页面要等 Vue 批量更新才变。想读更新后的 DOM，比如滚到底部、聚焦新出现的输入框，就先 await nextTick()。

参考答案

简答

在 Vue 里给响应式数据赋值，JavaScript 里马上就能读到新值。可是页面上的 DOM 不会立刻变，Vue 会把更新放进一个队列，等当前代码执行完，在同一轮的微任务里统一更新。

这样做是为了合并。一个点击事件里改了十次数据，页面只需要重新渲染一次。

代价是改完数据立刻去读 DOM，读到的还是旧的。nextTick() 返回一个 Promise，在这一轮 DOM 更新完成后 resolve，所以 await nextTick() 以后再读就是新的了。典型场景有三个：新渲染出来的输入框要聚焦、列表追加后滚到底部、内容变化后测量高度。

要注意，它只等 Vue 的 DOM 更新，不等图片加载、动画结束或者网络请求。

现象：改完数据，DOM 还是旧的

下面是一个聊天列表，追加一条消息后要滚到底部：

vue
<script setup>
import { nextTick, ref } from 'vue';

const messages = ref([]);
const listEl = ref(null);

async function add(text) {
  messages.value.push(text);
  console.log(listEl.value.children.length); // 还是旧数量
  await nextTick();
  console.log(listEl.value.children.length); // 新数量
  listEl.value.scrollTop = listEl.value.scrollHeight;
}
</script>

<template>
  <ul ref="listEl" style="height: 200px; overflow: auto">
    <li v-for="(m, i) in messages" :key="i">{{ m }}</li>
  </ul>
</template>

push 之后 messages 已经多了一项，可是第一行打印出来的 li 数量还是旧的。原因就是 DOM 更新还在队列里排着。如果这时直接设 scrollTop，滚到的是旧内容的底部，新消息露不出来。等 nextTick() 之后，新的 li 已经渲染出来，scrollHeight 才包括它。

另一个常见场景：点编辑后聚焦

vue
<script setup>
import { nextTick, ref } from 'vue';

const editing = ref(false);
const input = ref(null);

async function startEdit() {
  editing.value = true;
  await nextTick();
  input.value.focus(); // v-if 渲染出 input 之后才能聚焦
}
</script>

<template>
  <input v-if="editing" ref="input" />
  <button v-else @click="startEdit">编辑</button>
</template>

editing 设成 true 的那一刻，input 还没被 v-if 渲染出来，input.value 是 null，调用 focus() 会报错。所以要等一下再聚焦。

有没有别的写法

如果是每次 DOM 更新后都要执行的逻辑，用 onUpdated，或者 watch(..., { flush: 'post' })，就不用在每个改数据的地方都写一遍 nextTick。如果只是挂载后访问一次 DOM，用 onMounted 就够了。

它是怎么实现的

Vue 用 Promise.resolve().then(flushJobs) 安排队列刷新，nextTick(fn) 则把回调排在这次刷新之后。因为用的是微任务，它会在浏览器绘制之前执行。所以在 nextTick 里读到的布局信息已经是更新后的，但用户这时还没看到新画面。

常见追问

在 nextTick 里能读到 CSS 过渡结束后的尺寸吗？

不能。nextTick 只等 DOM 更新，过渡动画还没开始播。要拿过渡结束后的尺寸，得监听 transitionend 事件。

Vue 2 的 this.$nextTick 和 Vue 3 有什么区别？

用法相同。Vue 3 改成从 vue 里导入 nextTick 函数，并且统一返回 Promise。
