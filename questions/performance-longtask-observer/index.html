Long Tasks API 怎样帮助定位主线程卡顿？

使用 PerformanceObserver 观察超过 50 毫秒的任务，理解它能说明什么、不能直接说明什么，以及如何结合 INP 诊断。

参考答案

用户说“有时点按钮没反应”，开发机却不容易复现。Long Tasks API 可以在支持的浏览器中记录主线程长时间占用的起点、持续时间和有限的归属信息，为线上排查提供线索。

它更像“这段时间主线程忙了很久”的报警器，不是直接给出慢函数调用栈的分析器。

先检测支持，再建立观察器

JavaScript
function watchLongTasks(onTask) {
  if (
    typeof PerformanceObserver === 'undefined' ||
    !PerformanceObserver.supportedEntryTypes.includes('longtask')
  ) {
    return () => {};
  }

  const observer = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      onTask({
        startTime: entry.startTime,
        duration: entry.duration,
        name: entry.name,
        containers: entry.attribution.map((item) => ({
          type: item.containerType,
          id: item.containerId,
          name: item.containerName,
        })),
      });
    }
  });
  observer.observe({ type: 'longtask', buffered: true });
  return () => observer.disconnect();
}

buffered 请求此前仍可用的条目，不保证取回页面历史上所有长任务。观察器一般在任务完成之后获得通知，因此它不能中途打断已经运行的长任务。

onTask 应尽量轻量，可以先存入有上限的队列，再批量上报。若监控回调本身进行大规模序列化或同步日志，反而会制造新的负担。组件或监控实例销毁时调用返回的函数，避免重复订阅。

attribution 不是函数堆栈

条目 name 与 attribution 主要帮助区分当前页面、子框架等浏览上下文。跨源隐私限制可能让信息非常有限；即使有 containerId，也只能帮助定位 iframe 容器，不代表它指向具体业务函数。

代码示例没有上报 containerSrc，因为完整 URL 可能含敏感参数。实际采集即使只包含容器名称，也应限制内容和收集范围。

需要定位哪个脚本或函数慢，通常还要在性能面板录制相同操作，查看任务内的调用栈、自身耗时以及样式布局事件。Long Animation Frames 等 API 在部分环境可提供额外信息，但支持度和统计含义不同，不能当作完全等价替换。

把时间区间与操作关联

startTime 与 duration 给出一个占用区间。可以与同一页面时间基准上的用户操作、路由切换或业务 mark 对齐，判断长任务是否覆盖了用户等待的阶段。

例如任务从 1000 毫秒执行到 1200 毫秒，用户在 1050 毫秒点击，那么事件可能因主线程忙而排队。但单看这个区间仍不能精确计算最终呈现时间，还要考虑事件处理与下一次绘制。

如果长任务发生在页面空闲时、没有影响用户当前任务，优先级可能低于直接阻塞输入的工作。线上分析应记录必要的页面类型和版本，避免把不同操作混在一起统计。

长任务时长、TBT 与 INP 不能互换

一个 120 毫秒长任务的 duration 是 120 毫秒。计算某些实验室指标中的阻塞部分时，可能按超过 50 毫秒的部分计为 70 毫秒，但 TBT 还有特定测量窗口和算法，不能把全天长任务简单相加就命名为 TBT。

INP 关注交互到下一次呈现的延迟，并有自身的交互选择和生命周期规则，不等于长任务总时长。多个低于长任务阈值的工作、布局与呈现延迟也可能让交互体验不佳。

因此“零 longtask 条目”只说明当前观测条件没有记录到符合阈值的任务，不能证明页面流畅；还可能是 API 不支持、观察开始较晚或数据被采样。

正确流程是用线上数据找高发场景，在受控环境复现并定位具体工作，修复后再检查交互指标及长任务分布。不要只为了让监控图表变干净而切成大量微任务，那并不保证把主线程交还给输入与渲染。
