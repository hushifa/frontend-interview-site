网页字体什么时候开始下载？怎样用 CSS Font Loading API 控制和检测加载？

写了 @font-face 不代表马上下载，多数浏览器要等页面真正用到这个字体时才去取。CSS Font Loading API 用 FontFace 对象表示一个字体，可以手动 load()、加进 document.fonts，用 status 和 Promise 知道它什么时候加载好；document.fonts.ready 等所有字体和布局完成。check() 只回答“现在画会不会触发换字体”，不能用来判断某个字体是否可用。

参考答案

简答

在 CSS 里写了一段 @font-face，浏览器并不会立刻下载这个字体。MDN 的说法是，下载时机由浏览器决定，多数浏览器等到第一次真正需要这个字体时才去取。所以字体常常发现得晚，文字会先空白或先用回退字体。

CSS Font Loading API 让 JavaScript 能自己控制这件事。new FontFace(名称, 来源, 描述符) 创建一个字体，参数写法和 @font-face 一样；调用 load() 立刻开始下载，返回一个 Promise；再用 document.fonts.add() 把它加进文档的字体集合，页面才能用它画字。

它最常用在“必须等字体好了才能做”的地方。比如在 Canvas 上画字，字体没好时画出来的是回退字体，画完也不会自动重画；又比如要测量文字宽度。这时等 font.load() 或者 document.fonts.ready 完成再画。

要注意 document.fonts.check()。它回答的是“用这个字体规格现在画字，会不会用到还没加载好的字体”，不是“这个字体能不能用”。传一个根本不存在的字体名，它也返回 true。

为什么写了 @font-face 字体还没下载

CSS
@font-face {
  font-family: 'Brand';
  src: url('/fonts/brand.woff2') format('woff2');
}

.title {
  font-family: 'Brand', sans-serif;
}

这段 CSS 只是声明“有一个叫 Brand 的字体，文件在这里”。浏览器解析完 CSS、算好样式，发现页面上确实有元素要用 Brand 画字，才发请求。页面上没有 .title 元素，这个文件就一直不会下载。

这样设计是为了不浪费流量，一个样式表里可能声明了十几种字重，用不到的不该下载。可是代价是发现得晚：要先拿到 HTML，再拿到 CSS，再算样式，才轮到字体。加载期间文字怎么显示由 font-display 决定，提前下载可以用 preload，这些优化手段见《网页字体加载怎样优化？font-display、子集化、preload 和 size-adjust 各解决什么问题？》。

src 里可以先写 local()。MDN 说明浏览器按声明的顺序尝试，用户本机装了这个字体就直接用，找不到才下载 url() 里的文件。

用 JavaScript 加载一个字体

下面加载一个字体，好了以后在 Canvas 上画字：

JavaScript
const font = new FontFace('Brand', 'url("/fonts/brand.woff2")', { weight: '400' });
document.fonts.add(font);
console.log(font.status); // unloaded

font.load().then(
  () => {
    console.log(font.status); // loaded
    const ctx = canvas.getContext('2d');
    ctx.font = '36px Brand';
    ctx.fillText('字体已加载', 20, 50);
  },
  (error) => console.error(error),
);

第一次打印为什么是 unloaded？MDN 说明，来源是 URL 的 FontFace 只会校验定义，不会自动下载，状态是 unloaded。调用 load() 以后变成 loading，下载并解析成功变成 loaded，定义无效或文件取不到就是 failed。如果来源是一个 ArrayBuffer，数据已经在手上，就会自动加载。

document.fonts.add() 这一步不能省。MDN 写明，字体可以在加入集合之前或之后加载，但必须加入集合才能用来画字。加入以后，浏览器在页面需要时也会自己去加载它。

为什么 Canvas 要等？DOM 里的文字，字体到了浏览器会自动用新字体重新排版；Canvas 画的是像素，画完就定了，字体后来到了也不会重画。所以要在 Promise 完成以后再调用 fillText。

document.fonts.ready 和 load() 有什么不同

font.load() 只关心这一个字体。document.fonts 是整个文档的字体集合，@font-face 声明的字体和用 add() 加进来的字体都在里面，它提供了几个整体的入口：

JavaScript
document.fonts.ready.then(() => {
  // 文档里的字体都加载完、布局也完成了
});

document.fonts.load('36px Brand').then((faces) => {
  // faces 是匹配到并加载完成的 FontFace 数组
});

document.fonts.addEventListener('loadingdone', (event) => {
  console.log(event.fontfaces.length);
});

ready 返回一个 Promise，MDN 说明它要等文档里的字体都加载完、布局也完成以后才完成，适合“等所有字体就绪再测量”。document.fonts.load() 接收一个和 CSS font 属性一样的字体规格，加载能匹配上的字体，结果是一个 FontFace 数组。集合上还会派发 loading、loadingdone、loadingerror 事件，事件对象的 fontfaces 是这一批相关的字体。

为什么不能用 check() 判断字体是否可用

很多人会写 if (document.fonts.check('16px Brand')) 来判断字体是否加载好。可是 MDN 专门提醒，check() 的含义是“用这个规格画字，会不会用到集合里还没加载完的字体”。

JavaScript
document.fonts.check('12px Courier');     // true：匹配到的是系统字体
document.fonts.check('12px i-dont-exist'); // true：集合里没有这个字体，也就不用等
document.fonts.check('12px molot, Courier'); // false：molot 在集合里，但还没加载

第二行最容易误解。字体名写错了，check() 反而返回 true，因为集合里没有任何一个字体需要等待。所以要确认某个字体真的可用，应该看那个 FontFace 对象的 status，或者 await font.load()。

常见追问

FontFace 的描述符写了 italic，字体就会变成斜体吗？

不会。MDN 说明，和 @font-face 一样，style、weight 这类描述符有的只是告诉浏览器“这个文件里是斜体”，用于匹配。文件本身是不是斜体，要由你保证。

字体加载失败怎么办？

font.load() 返回的 Promise 会被拒绝，status 变成 failed，集合上会触发 loadingerror。页面上的文字会继续用 font-family 里后面的回退字体，Canvas 绘制可以在失败分支里改用系统字体。
