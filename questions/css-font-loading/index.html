font-display 怎样影响字体加载期间的文字显示？

font-display 决定 Web 字体未就绪时文字是先隐藏还是先用回退字体显示，以及字体晚到时是否还要替换；配合预加载和回退字体度量调整可以减少闪烁和布局偏移。

参考答案

简答

  • 字体加载分三个阶段：阻塞期（文字不可见）、交换期（显示回退字体，字体到达后替换）、失败期（不再替换）。
  • block：约 3 秒阻塞期加无限交换期；swap：几乎无阻塞，随时替换；fallback：约 100ms 阻塞加约 3 秒交换；optional：约 100ms 阻塞，没有交换期，字体晚到就本次不用。
  • 正文通常用 swap 或 optional，避免长时间看不到文字；图标字体常用 block，避免显示成乱码。
  • 替换字体会改变字宽和行高，导致布局偏移；用 size-adjust、ascent-override 等描述符把回退字体调到接近的度量。
  • 关键字体用 <link rel="preload" as="font" crossorigin> 提前请求，crossorigin 不能省。

声明

CSS
@font-face {
  font-family: 'Brand';
  src: url('/fonts/brand.woff2') format('woff2');
  font-display: swap;
}

@font-face {
  font-family: 'Brand Fallback';
  src: local('Arial');
  size-adjust: 104%;
  ascent-override: 92%;
}

body {
  font-family: 'Brand', 'Brand Fallback', sans-serif;
}

回退字体经过调整后，替换前后每行的字数和高度接近，CLS 会明显下降。具体百分比要根据两种字体的实际度量计算，Next.js 的 next/font 和 Fontaine 等工具可以自动生成。

怎么选

值适合
swap品牌字体必须出现，能接受一次替换
optional首屏稳定优先，字体只在缓存后使用
fallback介于两者之间
block图标字体，或回退字体无法表达的内容

其他减少成本的做法

  • 只提供 WOFF2，按需拆分子集；中文字体体积大，用 unicode-range 分片或只为标题加载。
  • 预加载只给首屏真正用到的一两个字体，过多会和其他关键资源抢带宽。
  • 用 document.fonts.ready 或 FontFace.load() 在需要精确测量文字的场景（例如 Canvas 绘制）等待字体就绪。

常见追问

  • 为什么预加载要写 crossorigin？字体请求总是以 CORS 模式发出，预加载不带 crossorigin 会被当成另一个请求，浏览器会重复下载。
