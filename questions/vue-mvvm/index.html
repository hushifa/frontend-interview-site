Vue 是怎样实现 MVVM 里的数据绑定的？

Vue 借用了 MVVM 的数据绑定思想，靠三样东西实现：响应式系统在读取时收集依赖、修改时触发更新；模板在构建时或运行时编译成返回虚拟 DOM 的渲染函数，渲染作为响应式副作用执行；v-model 按元素展开成属性加事件，实现表单的双向绑定。Vue 2 文档说 Vue 只是部分受 MVVM 启发，Vue 3 文档改用声明式渲染和响应式来介绍。

参考答案

简答

写过 jQuery 的人都知道，数据变了要自己找到 DOM 去改，用户输入了还要自己去读 DOM 再写回数据。MVVM 用 ViewModel 和数据绑定替掉这部分手工活，三层怎样分工、和 MVC、MVP 有什么区别，见《MVC、MVP、MVVM 有什么区别？前端框架分别更接近哪种？》。这道题只讲 Vue 是怎样把“数据绑定”做出来的。

第一样是响应式系统。读取响应式数据时，Vue 记下当前是谁在用；修改时，通知这些使用者重新执行。开发者只管改数据，不碰 DOM。

第二样是模板编译。Vue 3 文档说，模板会被编译成渲染函数，渲染函数返回虚拟 DOM 树；编译可以在构建时提前完成，也可以用运行时编译器即时完成。渲染函数作为响应式副作用执行，它用到的数据一变，就重新生成虚拟 DOM，和旧树比较后只更新变化的部分。第三样是 v-model，它按元素类型展开成“属性加事件”，把用户输入写回数据，形成表单上的双向绑定。

不过要准确地说。Vue 2 官方文档的原话是：Vue 虽然没有完全遵循 MVVM 模式，但设计上部分受到了它的启发，所以习惯用变量名 vm（ViewModel 的缩写）表示 Vue 实例。Vue 3 的文档已经不用 MVVM 来介绍了，它把 Vue 的核心概括为声明式渲染和响应式。

用 Vue 的代码对一下

Vue 3 官方文档入门的第一个例子就能看出这三层：

JavaScript
import { createApp } from 'vue';

createApp({
  data() {
    return { count: 0 };
  },
}).mount('#app');
HTML
<div id="app">
  <button @click="count++">Count is: {{ count }}</button>
</div>

count 是数据，模板是界面，createApp 创建并挂载的组件实例把两者连起来，大致扮演 ViewModel 的角色。点按钮时，@click 改的是 count，没有任何代码去找按钮改文字，按钮上的数字却变了。

Vue 3 文档对此的说法是：声明式渲染，用基于 JavaScript 状态的模板语法描述 HTML 输出；响应式，自动追踪 JavaScript 状态的变化，在变化时高效地更新 DOM。这两点正是 MVVM 里“数据绑定”在 Vue 中的实现方式。

数据变了界面为什么会自己变

关键在 ViewModel 怎么知道“数据变了，哪块界面要更新”。下面用 Proxy 写一个极简版本：读数据时记下是谁在用，改数据时通知它们重新执行。

JavaScript
function reactive(target) {
  const subscribers = new Set();
  const proxy = new Proxy(target, {
    get(obj, key) {
      if (activeEffect) subscribers.add(activeEffect);
      return obj[key];
    },
    set(obj, key, value) {
      obj[key] = value;
      subscribers.forEach((effect) => effect());
      return true;
    },
  });
  return proxy;
}

let activeEffect = null;
function effect(fn) {
  activeEffect = fn;
  fn();
  activeEffect = null;
}

// Model
const state = reactive({ count: 0 });

// View：用一个对象代替 DOM 节点
const view = { text: '' };
effect(() => {
  view.text = `Count is: ${state.count}`;
});
console.log(view.text); // Count is: 0

// 用户点击按钮时，事件处理只改数据
function onClick() {
  state.count++;
}
onClick();
onClick();
console.log(view.text); // Count is: 2

effect 第一次执行时读了 state.count，get 就把这个“渲染函数”记了下来。后来 onClick 改了 count，set 通知它重新执行，view.text 就更新了。onClick 本身完全没碰 view。

这个例子做了很多简化：真实的 Vue 按对象和属性分别记录依赖，组件更新会被缓冲后批量执行。完整过程见《Vue 3 响应式依赖是怎样收集和触发的？》。

模板怎样变成会自动更新的界面

上面的 effect 里，“渲染函数”是手写的。真实的 Vue 里，这个函数由模板编译而来。Vue 文档描述了三步：编译，把模板编译成渲染函数，可以在构建时完成，也可以用运行时编译器在浏览器里完成；挂载，运行时渲染器调用渲染函数，遍历返回的虚拟 DOM 树，创建真实 DOM 节点；更新，挂载这一步本身作为响应式副作用执行，会追踪用到的所有响应式依赖，依赖变化时副作用重新执行，生成新的虚拟 DOM 树，和旧树比较后把必要的改动应用到真实 DOM 上。

所以前面例子里的 view.text = ... 对应的就是“渲染函数加挂载、更新”这一段，只是 Vue 比较的是两棵虚拟 DOM 树，而不是整段重写。编译器还会在渲染函数里标出哪些部分是动态的，更新时只比较这些部分。

v-model 怎样把输入写回数据

数据到界面这个方向靠的是上面的渲染副作用。界面到数据这个方向，Vue 用 v-model 简化。文档给出的等价写法是：

HTML
<input :value="text" @input="event => text = event.target.value" />
<!-- 等价于 -->
<input v-model="text" />

v-model 会按元素选择不同的属性和事件：文本类 <input> 和 <textarea> 用 value 属性和 input 事件；复选框和单选框用 checked 属性和 change 事件；<select> 用 value 和 change 事件。文档还提醒，v-model 会忽略表单元素上初始的 value、checked、selected 属性，始终以绑定的 JavaScript 状态为准。

所以双向绑定在 Vue 里是“单向渲染加事件回写”的组合：输入事件改数据，数据变化再触发渲染副作用更新界面。

为什么说 Vue 不是严格的 MVVM

经典 MVVM 里，ViewModel 是一个单独的层，View 通过绑定只和它打交道。Vue 2 文档也只说“部分受到启发”，没有把自己归为 MVVM 框架。

实际写 Vue 时，边界没那么严格。组件实例同时承担了 ViewModel 和一部分 View 的职责，模板就写在组件里；组件也可以通过模板 ref 直接操作 DOM，这在纯粹的 MVVM 里是 View 和 ViewModel 的越界。Vue 3 的组合式 API 更是把状态、计算和副作用按功能组织，不再强调分层。

所以更贴切的说法是：Vue 借用了 MVVM 的数据绑定思想，核心实现是响应式系统加模板编译。

常见追问

v-model 是双向绑定，那 Vue 是双向数据流吗？

不是。v-model 只是语法糖，在原生输入框上相当于绑定 value 加监听 input 事件，数据仍然从父组件单向流向子组件，子组件通过事件通知父组件修改，见《组件 v-model 的本质是什么？》。

模板一定要在构建时编译吗？

不一定。Vue 文档说编译可以通过构建步骤提前完成，也可以用运行时编译器即时完成。用单文件组件加构建工具时一般是提前编译；直接在 HTML 里写模板、不经过构建时，要用带编译器的 Vue 版本。也可以跳过模板，直接手写渲染函数。
