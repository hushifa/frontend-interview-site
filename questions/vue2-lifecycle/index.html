Vue 2 与 Vue 3 的生命周期如何对照？父子组件钩子按什么顺序执行？

Vue 2 的 beforeDestroy、destroyed 到 Vue 3 改名为 beforeUnmount、unmounted，组合式 API 用 onXxx 注册。父子组件不管是创建、更新还是销毁，都是父组件先开始、子组件先结束。

参考答案

Vue 2 已于 2023-12-31 停止维护，本题 Vue 2 部分以 2.7 为准。何时请求数据、何时清理资源见《Vue 生命周期中何时访问 DOM、发请求和清理资源？》，本题只讲版本对照与执行顺序。

简答

选项式 API 的钩子到 Vue 3 基本都保留了，只有两个改了名：beforeDestroy 改成 beforeUnmount，destroyed 改成 unmounted。组合式 API 用 onMounted 这类函数注册，但没有 beforeCreate 和 created 的对应函数，setup() 本身就承担了这部分工作，而且它比所有选项式钩子都早执行，包括 beforeCreate。

父子组件的顺序可以记一句话：父组件先开始，子组件先结束。创建时父组件走到 beforeMount 才开始渲染子组件，子组件全部 mounted 之后，父组件才 mounted。

更新时是父 beforeUpdate → 子 beforeUpdate → 子 updated → 父 updated。销毁时是父 beforeDestroy → 子 beforeDestroy → 子 destroyed → 父 destroyed，Vue 3 的卸载顺序一样，只是名字换成了 unmount。

原因是父组件渲染时才会去创建子组件，子组件的 DOM 放进父组件以后，父组件才算完成。

这两处改名记录在迁移指南的“Other Minor Changes”里。Vue 2.7 把组合式 API 移植回了 Vue 2，所以 onMounted、onBeforeUnmount 这些在 2.7 里也能用，方便升级前先改写。

为什么是“父先开始、子先结束”

先看挂载。父组件进入 beforeMount 以后开始执行渲染和 patch，在这个过程中遇到子组件，就把子组件的创建和挂载完整走一遍。子组件的 DOM 插进父组件的 DOM 树以后，父组件的 DOM 才算完整，这时父组件才触发 mounted。

再看更新。调度器按 watcher 的创建顺序运行渲染 watcher，父组件的 watcher 先创建，所以父组件先触发 beforeUpdate。可是 updated 是等整个队列跑完后统一调用的，Vue 2 源码里的 callUpdatedHooks 倒序遍历队列，所以子组件的 updated 反而先于父组件。

最后是销毁。父组件先触发 beforeDestroy，再递归销毁子组件，子组件都销毁完了，父组件才触发 destroyed。

实际跑一遍看看

下面给父子组件的 8 个钩子都挂上记录函数，依次触发创建、更新和销毁：

JavaScript
// vue@2.7.16，在浏览器中运行
const log = [];
const names = ['beforeCreate', 'created', 'beforeMount', 'mounted',
  'beforeUpdate', 'updated', 'beforeDestroy', 'destroyed'];
const hooks = (who) => Object.fromEntries(
  names.map((h) => [h, () => log.push(`${who} ${h}`)]),
);

const Child = { props: ['msg'], template: '<i>{{ msg }}</i>', ...hooks('子') };
const vm = new Vue({
  data: { msg: 'a' },
  components: { Child },
  template: '<div><Child :msg="msg" /></div>',
  ...hooks('父'),
}).$mount();

vm.msg = 'b';            // 触发更新
Vue.nextTick(() => vm.$destroy());

输出按阶段整理如下：

text
创建：父 beforeCreate, 父 created, 父 beforeMount,
      子 beforeCreate, 子 created, 子 beforeMount, 子 mounted, 父 mounted
更新：父 beforeUpdate, 子 beforeUpdate, 子 updated, 父 updated
销毁：父 beforeDestroy, 子 beforeDestroy, 子 destroyed, 父 destroyed

三个阶段都符合“父先开始、子先结束”。把同一段代码换成 Vue 3.5（用 beforeUnmount/unmounted，用 app.unmount() 卸载）运行，三个阶段的顺序完全一致。

常见追问

子组件的 props 变了，一定会触发父组件的 beforeUpdate 吗？

不一定。上面的例子里父组件模板读了 msg，所以父组件也会更新。如果变化的数据只有子组件用到，那就只有子组件更新。

在父组件的 mounted 里能访问子组件的 DOM 吗？

能，这时子组件已经挂载好了。但异步组件，或者 v-if 后来才渲染出来的子组件，不在此列。

Vue 3 的选项式 API 还能写 beforeDestroy 吗？

不能直接用，要改名。迁移构建 @vue/compat 会对旧名字做兼容并给出警告。
