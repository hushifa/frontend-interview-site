小程序 web-view 里的网页怎样和小程序通信？JSBridge 要做哪些安全校验？

web-view 网页只能用 JSSDK 提供的 wx.miniProgram 接口和小程序通信，postMessage 的消息只在后退、组件销毁、分享、复制链接时才送到；实时交互要靠页面跳转带参数或服务端中转。安全上要配置业务域名、校验调用来源、只开放白名单能力、逐个校验参数，关键结果以服务端为准。

参考答案

简答

小程序里的 <web-view> 组件用来承载网页。网页和小程序之间只能通过 JSSDK 提供的接口通信，官方文档写明不支持其他方式。

网页能用的有 wx.miniProgram.navigateTo、navigateBack、switchTab、reLaunch、redirectTo 这几个跳转接口，postMessage 发消息，getEnv 判断环境。最容易踩坑的是 postMessage：消息不会实时送到，组件的 bindmessage 只在小程序后退、组件销毁、分享、复制链接这几个时机触发，拿到的是多次消息组成的数组。

需要实时传数据时，常见做法是小程序打开 web-view 时把参数编码进 src，网页要回传就跳转到小程序页面并带上参数，或者两边都通过服务端中转。

安全上要把网页当成不可信输入。小程序侧先配置业务域名，网页里 iframe 的域名也要配置。在自己的 App 里实现 bridge 时，同样要只对可信来源开放、只开放白名单里的能力、逐个校验参数；支付这类关键结果以服务端校验为准。

web-view 的基本限制

先记住几条组件本身的规则，都来自微信官方文档：

  • 打开的网页需要在小程序管理后台配置业务域名，关联公众号的文章除外。个人类型的小程序暂不支持 web-view。
  • 网页内 iframe 的域名也需要配置到域名白名单。
  • 每个页面只能有一个 web-view，它会自动铺满整个页面，覆盖其他组件。
  • 链接里避免带中文字符，否则 iOS 上可能白屏，建议先 encodeURIComponent。

网页里除了 wx.miniProgram 的几个接口，只能用 JSSDK 里的部分能力，比如选择和预览图片、获取地理位置、调起扫一扫。

网页怎样把数据交给小程序

先看 postMessage 的用法：

JavaScript
// 网页侧，引入 https://res.wx.qq.com/open/js/jweixin-1.3.2.js 后调用
wx.miniProgram.postMessage({ data: { orderId: '123' } });
HTML
<!-- 小程序页面 -->
<web-view src="{{url}}" bindmessage="onMessage"></web-view>

很多人以为调用以后小程序马上能收到，实际上 onMessage 要等到用户后退、组件销毁、分享或复制链接时才触发，e.detail.data 是这期间所有 postMessage 参数组成的数组。所以它适合“离开前把结果带回去”，比如分享时用网页里的标题。

要让小程序立刻响应，就用跳转。网页调用 wx.miniProgram.navigateTo({ url: '/pages/pay/index?orderId=123' })，小程序页面在 onLoad 里读参数。反方向，小程序把数据拼进 web-view 的 src 查询参数，网页启动时读取。两边状态需要同步得更紧时，就让双方都和服务端通信。

分享时，小程序可以在 onShareAppMessage 的参数里拿到 webViewUrl，也就是当前网页的地址。

网页怎样判断自己在小程序里

同一个网页可能在普通浏览器、微信聊天、小程序里打开，调用 wx.miniProgram 之前要先判断环境。官方给了三种办法：

JavaScript
function ready() {
  if (window.__wxjs_environment === 'miniprogram') {
    // 在小程序 web-view 里
  }
}
if (!window.WeixinJSBridge || !WeixinJSBridge.invoke) {
  document.addEventListener('WeixinJSBridgeReady', ready, false);
} else {
  ready();
}

为什么要等 WeixinJSBridgeReady？因为页面脚本执行时，微信的 bridge 可能还没注入好，官方建议在这个事件回调里读 __wxjs_environment。另外也可以调用 wx.miniProgram.getEnv，回调参数的 miniprogram 为 true 就是在小程序里。微信 7.0.0 起，userAgent 里会带 miniProgram 字样。

bridge 要做哪些安全校验

不管是小程序还是自己的 App，bridge 都是把宿主能力暴露给网页。网页可能嵌了第三方 iframe，可能被导航到别的站点，也可能有 XSS。所以宿主收到的每一次调用都要当成不可信输入来处理。

校验来源。 小程序靠业务域名白名单限定能加载哪些页面。在自己的 App 里，要在处理调用时拿到发起方的 origin 再判断。Android 的 WebViewCompat.addWebMessageListener 用 allowedOriginRules 限定往哪些 origin 的 frame 注入对象，回调里还能读到 sourceOrigin 和 isMainFrame；官方说明通配符 * 会注入所有 frame，这时消息要当不可信数据处理。iOS 在处理器里读 message.frameInfo，检查 isMainFrame 和 securityOrigin 的协议、主机名、端口。Android 的 addJavascriptInterface 拿不到调用方 origin，只能靠限制加载的页面来控制。

比较来源时不能只比字符串前缀：

JavaScript
const allowed = new Set(['https://m.example.com']);

function isTrusted(origin) {
  return allowed.has(new URL(origin).origin);
}
// 'https://m.example.com.evil.com'.startsWith('https://m.example.com') 为 true，前缀比较会被绕过

用 URL 解析出 origin 再精确比较，https://m.example.com.evil.com 就不会混进来。

最小能力。 按来源开放不同的方法集合，不提供“执行任意命令”“读写任意文件”这种通用入口。

校验参数。 类型、长度、枚举值都要检查；文件路径、跳转地址同样按白名单判断。

关键结果以服务端为准。 支付、获取手机号这类操作由宿主发起并弹出原生确认，结果由服务端校验，不要相信网页传回来的“已支付”。

限制导航。 WebView 只允许跳转白名单域名，防止页面被导航到恶意站点后继续使用 bridge。

注入对象、URL 拦截这些 bridge 本身的实现方式，见《Hybrid 开发是什么？JSBridge 的 URL Scheme 拦截和注入对象有什么区别？》。Electron 里的 preload 和 IPC 是同一类问题，见《Electron 的 IPC 和 contextBridge 怎样设计？》。

常见追问

web-view 里 JSSDK 接口调用没反应怎么办？

官方文档的提示是：iOS 上如果遇到 JSSDK 接口调用无响应，可以在 web-view 的 src 后面加 #wechat_redirect。

网页怎么知道小程序切到后台了？

微信 7.0.3 起，网页里可以用 WeixinJSBridge.on('onPageStateChange', fn) 监听，回调参数的 active 表示小程序是否在前台。

addJavascriptInterface 在旧系统上有什么风险？

官方文档指出，目标 API 16（Android 4.1）及以下的应用，或者运行在 Android 4.2 以下设备上的应用，页面 JS 可以通过反射访问注入的对象，以宿主的权限执行 Java 代码。所以包含不可信内容的 WebView 不应注入对象。
