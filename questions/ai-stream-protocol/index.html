AI 流式响应为什么不能每收到一块就 JSON.parse？

reader.read 返回的是任意切分的字节块，不对应字符、SSE 事件或完整 JSON。要先流式解码，再按 SSE 协议分帧，最后解析并校验每个事件。

参考答案

简答

  • 网络可以把一条事件拆成多块，也可以把多条事件合成一块；一个中文字符或 emoji 也可能被拆在两块之间。
  • 解析分三层：字节解码成字符（TextDecoder 加 stream: true），字符按 SSE 规则分成事件，事件的 data 再解析成 JSON。
  • SSE 支持 LF 和 CRLF 换行、多行 data、注释行，只用 split('\n\n') 会漏掉这些情况，用成熟的解析器更可靠。
  • 连接结束不等于生成完成，要以协议里的结束事件为准；没有结束事件就当作截断处理。

一个可用的读取函数

下面用 eventsource-parser 4.x 的 createParser({ onEvent }) 处理 SSE 分帧。示例约定服务端最后发送 [DONE] 作为结束标记，这是本例的协议，不同服务商的结束方式不同。

JavaScript
import { createParser } from 'eventsource-parser';

async function consume(response, onEvent) {
  if (!response.ok || !response.body) throw new Error('流不可用');
  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8', { fatal: true });
  let completed = false;

  const parser = createParser({
    onEvent(event) {
      if (completed) return;
      if (event.data === '[DONE]') {
        completed = true;
        onEvent({ type: 'done' });
        return;
      }
      onEvent({ id: event.id, event: event.event, value: JSON.parse(event.data) });
    },
  });

  try {
    while (!completed) {
      const { value, done } = await reader.read();
      if (done) {
        parser.feed(decoder.decode()); // 冲刷解码器里剩余的字节
        if (!completed) throw new Error('连接结束但没有收到结束标记');
        break;
      }
      parser.feed(decoder.decode(value, { stream: true }));
    }
    await reader.cancel(); // 收到结束标记后丢弃剩余字节
  } catch (error) {
    await reader.cancel(error).catch(() => {});
    throw error;
  } finally {
    reader.releaseLock();
  }
}
  • decoder.decode(value, { stream: true }) 会把被截断的多字节字符留到下一块再输出。
  • 解析或回调出错时调用 reader.cancel() 关闭底层流；releaseLock() 只解除读取器绑定，不会关闭连接。
  • 生产环境还要限制单个事件和总字节数，防止异常流耗尽内存。

事件按类型和 ID 分别累积

一条 AI 流里通常混有文本增量、工具调用参数、引用、错误和结束事件。

  • 文本增量按消息 ID 和片段 ID 追加。
  • 工具参数按调用 ID 累积，完整并通过 Schema 校验之前不执行。半截 JSON 即使恰好能解析也不算完成。
  • 错误事件到达后，这次生成标记为失败，不再追加文本。

使用 AI SDK 这类库时，要用和服务端协议版本匹配的解码器，不要混用不同服务商的事件格式。

测试

把同一段流在任意字节位置切开再喂给解析器，覆盖：emoji 被切断、CRLF 换行、多行 data、多条事件在同一块、非法 JSON、只有半条事件就断开。只在本地"一次写出、一次读到"的环境测试，会掩盖这些问题。

常见追问

  • 为什么不直接用 EventSource？ EventSource 只支持 GET，不能自定义请求头和请求体，AI 接口通常要 POST 并带认证头，所以多用 fetch 自己解析。代价是要自己处理重连。
