参考答案

网络读取的 chunk 是字节分块，不保证对应一个字符、一条 SSE 事件或一个完整 JSON。一个消息可能跨多个块，一块也可能包含多个事件。需要按字符编码和协议边界增量解析，不能把 reader.read 的每个 value 直接当成完整消息。

AI SDK 区分纯文本流与包含多种事件的数据流。当前 UI 数据流采用 SSE 格式，文本还有开始、增量和结束等事件；工具调用、来源与错误也需要按各自类型处理。使用 HTTP 流并不意味着所有服务商的事件格式可以互换。

工程上应优先使用与服务端版本匹配的 SDK 或成熟解析器，并为截断、异常结束和未知事件设计行为。SSE 格式本身也不等于业务已经实现自动续传：恢复位置、消息去重及服务器保留状态需要额外设计。

交互状态与权限

AI 界面至少要区分用户消息、模型流、工具调用、工具结果、审批、取消、重试和最终状态。每一步都应有稳定 ID 和可恢复的状态，不能把网络片段直接拼成可信业务对象。

模型输出、检索内容和工具结果都属于不可信输入。密钥、权限和不可逆操作必须留在受控边界，前端负责展示确认和错误恢复，服务端负责最终授权、校验和执行记录。
