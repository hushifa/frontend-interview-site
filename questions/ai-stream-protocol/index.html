AI 流式响应为什么不能每收到一块就 JSON.parse？

reader.read 返回的是任意字节分块，不保证对应字符、SSE 事件或完整 JSON。必须先处理字符编码和协议分帧，再解析并校验业务事件。

参考答案

chunk 不是 token，也不是消息

网络层可以把服务端一次写出的 JSON 拆成多次读取，也可以把多次写入合并到一次读取。一个 UTF-8 中文字符或 emoji 还可能被拆在两个字节块之间。因此把每个 reader.read() 的结果直接解码并 JSON.parse，会在半个字符、半条事件和多条事件粘连时失败。

流式解析至少有三层边界：字节到字符、传输协议到事件、事件 payload 到业务对象。每层都必须完成后才能交给下一层。

SSE 的分帧不能只用 split('\n\n')

SSE 按行和空行组织事件，支持 LF、CRLF、多行 data、注释、id 和 retry 字段。一个事件的数据本身也不一定是 JSON，结束标记可能是 [DONE] 或服务商自定义文本。

可以使用成熟解析器处理字符和 SSE framing，再在业务层解析：

JavaScript
import { createParser } from 'eventsource-parser';

async function consume(response, onEvent) {
  if (!response.ok || !response.body) throw new Error('流不可用');
  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8', { fatal: true });
  const parser = createParser({
    onEvent(event) {
      if (event.data === '[DONE]') {
        onEvent({ type: 'done' });
        return;
      }
      const value = JSON.parse(event.data);
      onEvent({ id: event.id, event: event.event, value });
    },
  });

  try {
    while (true) {
      const { value, done } = await reader.read();
      if (done) {
        parser.feed(decoder.decode());
        break;
      }
      parser.feed(decoder.decode(value, { stream: true }));
    }
  } finally {
    parser.reset();
    reader.releaseLock();
  }
}

真实应用还要设置总字节数、事件大小和单个字段长度上限，避免无限流拖垮内存。onEvent 不应为每个事件启动无界异步任务；耗时处理要进入有界队列。

连接 EOF 只表示字节流结束，不证明模型正常完成。半条事件不能猜着补齐，应该标记为截断或失败；业务协议需要明确的结束事件和错误事件。

文本、工具和引用不是同一种增量

一条 AI 流可能同时包含文本 delta、工具参数、工具结果、引用、错误和结束状态。文本 part 可以追加，工具参数应该按 call ID 累积，引用要按来源 ID 关联，错误不能继续把运行标记为成功。

应用应使用 message ID、part ID 和序号定位更新目标，而不是把所有 payload 拼进一个字符串。工具参数尚未完整时，即使局部 JSON 恰好能解析，也不能提前执行有副作用操作。最终状态要等协议确认并通过 Schema 校验后冻结。

取消和断线恢复需要单独协议

fetch 读取流时可以调用 reader.cancel()，但这只影响当前连接；服务端模型和工具任务可能仍在运行。需要把取消信号传到服务端，并通过任务 ID 查询真实状态。

事件带 id 不代表服务端保留了可恢复历史。要支持续传，必须约定游标、保留期限、去重和任务身份。断线后重新发起生成可能得到另一份回答，不能伪装成原流无缝继续。原生 EventSource 具有自己的重连行为，fetch 实现 SSE 不会自动继承它。

如果使用 AI SDK 等库，应使用与服务端协议和版本匹配的解码器，不要把不同供应商的事件格式混用。协议层结束、模型完成、工具完成和消息持久化完成也可能是不同时间点。

测试要主动制造坏边界

把同一段流在任意字节位置切开，覆盖多字节字符、CRLF、多行 data、多个事件同块、空事件、非法 JSON、结束标记和尾部截断。再测试取消、重复事件、事件迟到、工具参数半截和断线恢复。

只用“服务端一次写出、客户端一次读到”的本地演示，最容易掩盖真实网络中的分块和时序问题。
