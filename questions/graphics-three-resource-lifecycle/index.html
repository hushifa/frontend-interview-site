Three.js 页面退出后为什么还占内存？怎样管理模型和渲染器的生命周期？

scene.remove 只是把对象移出场景，几何体、材质和纹理的 GPU 资源要分别 dispose，动画循环和监听器也要停掉。独占资源由页面清理，共享资源由资源管理层按引用计数释放；异步加载的结果可能在页面离开后才返回。

参考答案

简答

一个 3D 预览页，进进出出几次，内存就一直涨。原因是删掉 canvas 并不会停掉 setAnimationLoop，也不会释放 GPU 上的资源，它们都还活着。

scene.remove(mesh) 也只是让这个对象不再被画出来。几何体、材质、纹理要分别调用 geometry.dispose()、material.dispose()、texture.dispose()。而且 material.dispose() 不会顺带释放它用到的纹理。

清理要按顺序来：先停动画循环和监听，再释放资源，最后 renderer.dispose() 并移除 canvas。

要注意共享的资源。多个对象共用的材质和纹理，不能被某一个页面直接释放，要由资源管理层在最后一个使用者离开时再释放。修完以后，重复挂载、卸载几轮，看 JS 堆和 renderer.info 能不能回到稳定水平，不要求全部归零。

写一个能清理干净的预览组件

下面的函数挂载一个旋转的立方体，并返回一个 cleanup 函数。重点看 cleanup 里的顺序。

JavaScript
import * as THREE from 'three';

export function mountPreview(container) {
  const renderer = new THREE.WebGLRenderer({ antialias: true });
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  container.append(renderer.domElement);

  const scene = new THREE.Scene();
  const camera = new THREE.PerspectiveCamera(45, 1, 0.1, 100);
  camera.position.z = 4;

  const geometry = new THREE.BoxGeometry(1, 1, 1);
  const material = new THREE.MeshNormalMaterial();
  const cube = new THREE.Mesh(geometry, material);
  scene.add(cube);

  const observer = new ResizeObserver(() => {
    const width = Math.max(1, container.clientWidth);
    const height = Math.max(1, container.clientHeight);
    renderer.setSize(width, height);
    camera.aspect = width / height;
    camera.updateProjectionMatrix();
  });
  observer.observe(container);

  renderer.setAnimationLoop((time) => {
    cube.rotation.y = time * 0.0005;
    renderer.render(scene, camera);
  });

  let disposed = false;
  return function cleanup() {
    if (disposed) return;
    disposed = true;
    renderer.setAnimationLoop(null); // 先停止产生新帧
    observer.disconnect();
    scene.remove(cube);
    geometry.dispose();
    material.dispose();
    renderer.dispose();
    renderer.domElement.remove();
  };
}

为什么要先停动画循环？因为循环每一帧都在用这些资源。先释放资源、循环还在跑，下一帧可能又把资源用上，或者访问已经释放的东西。

disposed 标记保证 cleanup 调多次也只清理一次。页面卸载时调用 cleanup，之后把对它的引用也丢掉。

如果还用了 OrbitControls、后处理、动画混合器，它们各自也有 dispose()，或者有需要移除的监听器，要一起清理。

共享的资源怎么释放

两个商品页可能共用同一张环境贴图。关掉 A 页时如果直接把它释放了，B 页就得重新上传这张纹理，画面会卡一下。

所以共享资源要用引用计数来管：谁要用就加一，谁不用就减一，减到 0 才真正释放。

JavaScript
const cache = new Map(); // url -> { texture, refs }

function acquireTexture(url, loader) {
  let entry = cache.get(url);
  if (!entry) {
    entry = { texture: loader.load(url), refs: 0 };
    cache.set(url, entry);
  }
  entry.refs++;
  return entry.texture;
}

function releaseTexture(url) {
  const entry = cache.get(url);
  if (entry && --entry.refs === 0) {
    entry.texture.dispose();
    cache.delete(url);
  }
}

还有一些资源不在 mesh 的遍历路径里，比如 scene.environment、后处理用的渲染目标。遍历场景释放时找不到它们，要单独管理。

页面都关了，模型才加载完怎么办

用户离开页面以后，glTF 的请求还可能完成，回调照样会执行。所以加载完成时，先看页面是不是已经清理过了。已经清理了，就直接释放刚返回的资源，不要再加进场景：

JavaScript
loader.load(url, (gltf) => {
  if (disposed) {
    disposeObject(gltf.scene); // 遍历并释放这份模型独占的资源
    return;
  }
  scene.add(gltf.scene);
});

怎样确认真的修好了

用同一个模型重复挂载、卸载十几轮，对比前后的 JS 堆快照。

再看 renderer.info.memory 里 geometries、textures 的数量是否稳定。Three.js 内部有缓存，所以有些数字不会归零，只要不随轮数增长就行。

要注意，renderer.info 给的不是显存的字节数。像素比翻倍时，画布的像素数大约变成四倍，显存会明显增加，这在 renderer.info 里是看不出来的。

常见追问

只显示静态模型，需要一直跑动画循环吗？

不需要。可以只在相机移动或模型变化时调用一次 render()，这样省电，也省 GPU。

多个页面共用一个 renderer 怎么办？

页面卸载时只释放自己的资源。renderer 由宿主来管理，不能被某个页面销毁。
