前端文件上传有哪些安全边界？

前端的 accept、大小和类型检查只改善体验，攻击者可以直接调用接口绕过。安全边界在服务端：限制大小、按内容识别并重新编码文件、用随机名称存储、在隔离的域名下提供下载，并防止 HTML、SVG 被当作页面执行。

参考答案

简答

  • accept 属性和 file.type 来自文件扩展名或系统猜测，只能用于提示用户，不能作为安全判断。
  • 服务端校验大小上限、扩展名白名单和文件内容（魔数），图片最好重新编码，去掉隐藏数据和元信息。
  • 存储时用服务端生成的随机名称，原始文件名只作为元数据，防止路径穿越和覆盖。
  • 用户上传的文件放在独立的域名下提供，带 Content-Disposition: attachment 和 X-Content-Type-Options: nosniff，避免在主站源下被当成 HTML 执行。
  • SVG 可以包含脚本，不要直接插入页面 DOM；预览时用 <img> 加载或在服务端转成位图。

前端做什么

JavaScript
const MAX_SIZE = 10 * 1024 * 1024;
const ALLOWED = new Set(['image/png', 'image/jpeg', 'image/webp']);

input.addEventListener('change', () => {
  const file = input.files[0];
  if (!file) return;
  if (file.size > MAX_SIZE) return showError('文件不能超过 10 MB');
  if (!ALLOWED.has(file.type)) return showError('只支持 PNG、JPEG、WebP');

  preview.src = URL.createObjectURL(file);
  preview.onload = () => URL.revokeObjectURL(preview.src);
});

这些检查让用户尽早得到反馈，服务端必须重复且更严格地校验。

服务端检查清单

风险措施
超大文件、压缩炸弹限制请求体大小、解压后的总大小和文件数
伪装类型按内容识别类型，与扩展名都在白名单内才接受
路径穿越（../../etc/passwd）不用原始文件名作路径
存储型 XSS隔离域名、nosniff、强制下载或安全的 Content-Type
恶意文件病毒扫描，扫描通过前不对外可见
越权访问下载接口校验权限，或使用短期签名链接
元数据泄露去除图片的 EXIF（可能含地理位置）

预览时的风险

  • 不要把上传的 HTML 或 SVG 内容读成字符串写入 innerHTML。
  • 在 <img> 中加载的 SVG 不会执行脚本；直接在新标签页打开 SVG 文件则会在其所在的源下执行，所以文件要放在隔离域名。
  • 预览 PDF、Office 文档时同样放在隔离源或沙箱 iframe 中。

常见追问

  • 为什么要单独的域名？如果上传的 HTML 在主站源下被打开，它的脚本就能读写主站的 Cookie 和存储。
  • 大文件上传怎么做？见《浏览器直传对象存储时，如何设计安全的分片上传？》。
