媒体查询和容器查询分别适合什么场景？

媒体查询看的是整个视口和设备，适合定页面骨架；容器查询看的是组件所在容器有多宽，同一个组件放在宽栏、窄栏里能各自调整。

参考答案

简答

媒体查询问的是“整个视口多宽、设备能不能悬停、用户是不是偏好深色”，适合决定页面骨架和全局偏好。

容器查询问的是“我所在的这个容器多宽”。一张卡片可能放在宽的主栏里，也可能放在窄的侧栏里，视口宽度一样，卡片能用的空间却不一样，这时就该用容器查询。

用之前要先给祖先元素写 container-type: inline-size，把它声明成容器。查询找的是最近的、符合条件的祖先容器，元素不能查询自己。另外还有 cqi、cqw 这类容器单位，按容器尺寸算，可以用在字号和间距上。

容器尺寸查询主流浏览器都支持了，可以直接用。要注意的是声明容器有代价，容器的宽度不再由内容撑开。

同一张卡片，在不同位置自动换布局

CSS
.card-slot {
  container: card / inline-size;
}

.card {
  display: grid;
  gap: 12px;
}

@container card (inline-size > 480px) {
  .card {
    grid-template-columns: 160px 1fr;
  }
}

.card-slot 被声明成名叫 card 的容器。容器宽度超过 480px 时，卡片变成左边图片、右边文字的两列；不到 480px 就保持上下排列。

把同一个 .card 放进宽主栏，它是左右布局；放进窄侧栏，它是上下布局。不用为每个位置单独写一个类，组件自己根据空间做决定。

为什么声明成容器后，宽度变成了 0

container-type: inline-size 会给容器加上一个限制，叫尺寸包含：容器在行内方向（横排文字时就是宽度）的尺寸不再由里面的内容决定。浏览器要先知道容器多宽，才能判断里面的查询，所以不能再反过来让内容撑开它。

所以容器如果本来是 inline-block 或浮动这类靠内容撑开宽度的盒子，宽度就可能变成 0。容器最好是一个宽度由外面决定的普通块。

container-type: size 把两个方向都包含了，容器高度也不再由内容撑开，必须明确写高度，所以用得比较少。

两种查询怎么一起用

CSS
@media (prefers-reduced-motion: reduce) {
  * { transition: none; }
}

@media (width > 1024px) {
  .layout { grid-template-columns: 240px 1fr; }
}

页面分几栏、导航长什么样、用户有什么偏好，继续交给媒体查询。栏里面的组件，交给容器查询。

还有一些信息只有媒体查询能拿到，比如是否在打印，以及指针类型 hover、pointer。这些跟容器没关系，是设备的属性。

常见追问

容器样式查询又是什么？

它不看尺寸，看祖先上自定义属性的值。比如 @container style(--theme: dark)，父级设置了 --theme: dark，里面的组件就切换样式。详见《容器样式查询怎样根据父级配置改变组件样式？》。
