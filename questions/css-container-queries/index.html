媒体查询和容器查询分别适合什么场景？

媒体查询依据视口、设备能力和用户偏好，适合页面级布局；容器尺寸查询依据祖先容器的尺寸，让同一个组件在不同位置自行调整。

参考答案

简答

  • 媒体查询回答“视口多宽、设备能不能悬停、用户是否偏好深色”，适合页面骨架和全局偏好。
  • 容器查询回答“我所在的容器多宽”，适合会被放进侧栏、主栏、弹窗等不同位置的组件。
  • 容器要先用 container-type: inline-size 声明，查询的是最近的、满足条件的祖先容器，元素不能查询自己。
  • cqi、cqw 等容器单位按容器尺寸计算，可用于字号和间距。
  • 容器尺寸查询已被主流浏览器支持，可以直接使用。

示例

CSS
.card-slot {
  container: card / inline-size;
}

.card {
  display: grid;
  gap: 12px;
}

@container card (inline-size > 480px) {
  .card {
    grid-template-columns: 160px 1fr;
  }
}

同一个 .card 放在宽主栏里变为左右布局，放在窄侧栏里保持上下布局，不需要为每个位置写单独的类。

container-type 的代价

inline-size 会给容器加上行内方向的尺寸包含：容器宽度不再由内容决定。容器本身如果是 inline-block 或浮动这类靠内容撑开的盒子，宽度可能变成 0。容器通常应该是宽度由外部决定的块。

size 同时包含两个方向，容器高度也不再由内容撑开，必须显式给高度，所以较少使用。

一起使用

CSS
@media (prefers-reduced-motion: reduce) {
  * { transition: none; }
}

@media (width > 1024px) {
  .layout { grid-template-columns: 240px 1fr; }
}

页面级的栏数、导航形态和用户偏好继续用媒体查询；栏里的组件用容器查询。打印、指针类型（hover、pointer）这类设备信息只能用媒体查询。
