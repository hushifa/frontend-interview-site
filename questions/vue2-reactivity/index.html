Vue 2 的响应式原理是什么？

Vue 2 初始化时把 data 里的每个属性都改成 getter 和 setter。读属性时记下"谁用了它"，改属性时通知这些使用者重新执行，组件也就跟着重新渲染。

参考答案

Vue 2 已于 2023-12-31 停止维护，本题以 Vue 2.7 源码为准。

简答

Vue 2 在初始化组件时，会遍历 data 里的所有属性，用 Object.defineProperty 把每个属性改成 getter 和 setter，嵌套的对象也递归处理。这样读属性、改属性都会经过 Vue 自己的函数。

每个属性都配了一个依赖收集器 Dep。读属性时，getter 看看“现在是谁在求值”，这个求值者叫 Watcher，就把它记到 Dep 里。改属性时，setter 发现新值和旧值不同，就调用 dep.notify() 通知所有记下来的 Watcher。

每个组件都有一个渲染 watcher，它的求值过程就是渲染组件。渲染时读到了哪些属性，就成了哪些属性的订阅者，所以这些属性一变，组件就会重新渲染。

要注意，Watcher 被通知后不会马上执行，而是进入异步队列，同一轮里改多少次都只执行一次。

三个角色各管什么

Observer 挂在对象的 __ob__ 属性上，负责把对象的属性转换成响应式；遇到数组就替换原型，并对每一项做 observe。它自己也带一个 dep，给 Vue.set 和数组方法通知更新时用。

Dep 是装依赖的容器，subs 里保存订阅它的 Watcher。Dep.target 是全局唯一的“当前正在求值的 Watcher”，用 pushTarget 和 popTarget 维护成一个栈。

Watcher 是一段需要追踪依赖的求值逻辑。渲染 watcher、computed（叫 lazy watcher）、watch 和 $watch（叫 user watcher）都是它的实例。

官方文档是这样描述的：Vue 遍历 data 的所有属性，用 Object.defineProperty 转为 getter/setter；每个组件实例都有对应的 watcher，在渲染时把“接触过”的属性记录为依赖；之后依赖的 setter 触发时，通知 watcher 重新渲染。

依赖是怎么收集的

Vue 怎么知道组件渲染时读了哪些属性？靠的是 Watcher.get() 这个流程：

  1. pushTarget(this)，把自己设为 Dep.target。
  2. 执行 getter。渲染 watcher 的 getter 就是 vm._update(vm._render())，途中每读到一个响应式属性，那个属性的 getter 就会调用 dep.depend()。
  3. dep.depend() 调用 Dep.target.addDep(dep)，Watcher 用 newDepIds 去重后，把自己加进 dep.subs。
  4. 求值结束后 popTarget()，再调用 cleanupDeps()。这一轮没再用到的旧 dep 会把这个 Watcher 移除，所以 v-if 切走的分支，以后改了也不会再触发更新。

还有一个细节。属性值是对象或数组时，getter 还会调用 childOb.dep.depend()，数组再递归 dependArray。为什么要多这一步？因为 Vue.set 新增属性、调用数组变异方法时，没有经过任何已有属性的 setter，只能通过对象自己的 __ob__.dep 通知。提前在这里收集好，才能通知到读过这个对象的 Watcher。

更新是怎么派发的

setter 里，如果新值和旧值相同（包括都是 NaN 的情况），直接返回。否则写入新值，对新值重新 observe，然后调用 dep.notify()。notify 会遍历 subs，调用每个 Watcher 的 update()，不同的 Watcher 处理方式不同：

  • lazy watcher（computed）只把 dirty 设为 true，等下次被读取时再重新计算。
  • sync watcher 立即执行。
  • 其他 Watcher 交给 queueWatcher 去重入队，在 nextTick 中按 id 排序后批量执行。

实际跑一下

JavaScript
// 用 Node 运行，vue@2.7.16
const Vue = require('vue');
const vm = new Vue({ data: { count: 0 } });
vm.$watch('count', (v, old) => console.log(old, '->', v));

vm.count = 1;
vm.count = 2;
// 输出：0 -> 2（同一轮多次修改合并为一次回调）

改了两次，回调只执行了一次，而且直接从 0 跳到了 2。这是因为 user watcher 被通知后进了队列，第二次修改时它已经在队列里，被去重了。等 nextTick 时它才执行，这时读到的已经是最终值 2。

常见追问

为什么组件的 data 要写成函数？

每个组件实例需要一份独立的数据对象。如果 data 是一个对象，多个实例就会共用同一份被 observe 的对象，一个改了其他的也跟着变。
