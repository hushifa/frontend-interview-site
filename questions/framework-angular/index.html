Angular Signals 的依赖追踪与 computed 有什么特点？

Signal 是一个装着值的盒子，调用它就能读取，读取过程会被记录为依赖。computed 只在被读取时才惰性计算并缓存结果；effect 在依赖变化后执行副作用。linkedSignal、resource、input() 和 model() 都建立在同一套机制上。

参考答案

简答

Signal 可以理解成一个装着值的盒子。signal(0) 创建一个，count() 读取，count.set(1) 或 count.update(fn) 修改。

它的关键在于“谁读了它，它就记住谁”。computed 里读了哪些 Signal，这些 Signal 就成了它的依赖。依赖是按实际执行的那条路线收集的，条件分支没走到的 Signal 不算。computed 也是惰性的，第一次被读取时才计算，结果会缓存，依赖变了以后，下次读取才重新算。

需要把状态同步到外面，比如写 localStorage、打日志、驱动第三方库，用 effect()。不要用 effect 去同步另一个 Signal，那种情况用 computed 或 linkedSignal。

要注意，Signal 用 Object.is 判断值有没有变。直接改对象里的属性，引用没变，就不会通知；要用 update 返回一个新对象。

先看一个购物车

下面的组件里，items 是可写的 Signal，count 和 total 是从它派生出来的 computed。

TypeScript
import { Component, computed, signal } from '@angular/core';

@Component({
  selector: 'app-cart',
  template: `
    <p>共 {{ count() }} 件，合计 {{ total() }}</p>
    <button (click)="add()">加一件</button>
  `,
})
export class CartComponent {
  readonly items = signal([{ name: '书', price: 30 }]);
  readonly count = computed(() => this.items().length);
  readonly total = computed(() => this.items().reduce((s, i) => s + i.price, 0));

  add() {
    this.items.update((list) => [...list, { name: '笔', price: 5 }]);
  }
}

点击按钮时，add 没有改原来的数组，而是用 update 返回了一个新数组。因为 Signal 比较的是引用，新数组才会被当成“变了”。如果写成 this.items().push(...)，数组内容变了，引用没变，界面就不会更新。

模板读取了 count() 和 total()，所以 Angular 知道这个组件依赖它们。items 一变，Angular 只把这个组件标记为需要更新。

依赖为什么会随分支变化

computed 不是提前分析代码里写了哪些 Signal，而是在执行时记录“这一次实际读了谁”。

TypeScript
const showDetail = signal(false);
const name = signal('Lin');
const detail = signal('...');
const label = computed(() => (showDetail() ? `${name()}：${detail()}` : name()));

showDetail 是 false 时，函数只走了后半段，读了 showDetail 和 name，没读 detail。所以这时改 detail，label 不会重新计算。等 showDetail 变成 true，下一次计算读到了 detail，它才成为依赖。

默认值来自别处，用户又能改，用 linkedSignal

有一种常见需求：选项列表变了，选中项要重置成第一项；但用户也可以手动选别的。很多人会写一个 effect 去同步，其实 linkedSignal 就是为这个准备的。

TypeScript
import { linkedSignal } from '@angular/core';

const options = signal(['标准', '加急']);
const selected = linkedSignal(() => options()[0]);

selected.set('加急'); // 用户手动选择
options.set(['自提', '标准']); // 来源变化，selected 重置为 '自提'

selected 本身可写，所以用户能改。可它又跟着 options 走，来源一变就按函数重新算出默认值。

异步数据用 resource

请求数据也能接进 Signal。resource 把“参数 Signal”和“加载函数”连在一起。

TypeScript
import { resource } from '@angular/core';

const userId = signal(1);
const user = resource({
  params: () => ({ id: userId() }),
  loader: ({ params, abortSignal }) =>
    fetch(`/api/users/${params.id}`, { signal: abortSignal }).then((r) => r.json()),
});

params 里读了 userId，所以 userId 一变就会重新请求，上一次没完成的请求通过 abortSignal 取消。

请求的状态用 user.status() 读，取值有 'idle'、'loading'、'reloading'、'resolved'、'error'、'local'。这里有个坑：处于 error 状态时读 user.value() 会直接抛错，所以读之前先用 user.hasValue() 判断，它在 TypeScript 里还能当类型守卫用。

如果项目用 HttpClient，可以换成 httpResource，这样请求会经过拦截器。

组件的输入输出也是 Signal

组件的输入输出也换成了函数写法：

TypeScript
import { input, model, output } from '@angular/core';

export class Slider {
  readonly max = input(100); // 只读 Signal 输入
  readonly label = input.required<string>(); // 必填
  readonly value = model(0); // 双向绑定：[(value)]="v"
  readonly changed = output<number>();
}

input() 得到的是只读 Signal，组件内部读 this.max()。model() 是可写的，组件内部改了它，父组件用 [(value)] 绑定的值也会跟着变。

常见追问

Signal 和 RxJS 是什么关系？

Signal 表示“当前值”，随时可以同步读；Observable 表示“随时间到达的一串事件”。两者可以用 toSignal、toObservable 互转，详见《Angular 中 Observable 和 Signals 怎样协作？》。

Signals 对变更检测有什么影响？

模板读取的 Signal 变了，Angular 能精确知道是哪个组件需要检查，不用把整棵树都查一遍。这也是 zoneless 模式能成立的基础，详见《Angular Zoneless 模式会改变哪些更新假设？》。
