Angular Signals 的依赖追踪与 computed 有什么特点？

Signal 是包装值的响应式容器，读取时调用函数，读取过程会被记录为依赖。computed 根据实际读取的 Signal 惰性计算并缓存；effect 在依赖变化后执行副作用。linkedSignal、resource、input() 和 model() 都建立在同一套机制上。

参考答案

简答

  • signal(initial) 创建可写 Signal，count() 读取，count.set(v) 或 count.update(fn) 修改。
  • computed(() => ...) 是只读的派生 Signal：第一次读取时才计算，结果被缓存，依赖变化后下次读取才重新计算。
  • 依赖按实际执行路径收集：条件分支没有读取的 Signal 不会成为依赖。
  • effect() 在依赖变化后执行副作用，用于同步到 localStorage、日志、第三方库，不要用它来同步另一个 Signal。
  • Signal 用 Object.is 判断是否变化，直接修改对象内部属性不会通知；要用 update 返回新对象。

基本用法

TypeScript
import { Component, computed, signal } from '@angular/core';

@Component({
  selector: 'app-cart',
  template: `
    <p>共 {{ count() }} 件，合计 {{ total() }}</p>
    <button (click)="add()">加一件</button>
  `,
})
export class CartComponent {
  readonly items = signal([{ name: '书', price: 30 }]);
  readonly count = computed(() => this.items().length);
  readonly total = computed(() => this.items().reduce((s, i) => s + i.price, 0));

  add() {
    this.items.update((list) => [...list, { name: '笔', price: 5 }]);
  }
}

模板读取了 count() 和 total()，items 变化时 Angular 只标记这个组件需要更新。

依赖随分支变化

TypeScript
const showDetail = signal(false);
const name = signal('Lin');
const detail = signal('...');
const label = computed(() => (showDetail() ? `${name()}：${detail()}` : name()));

showDetail 为 false 时，detail 变化不会让 label 重新计算。

linkedSignal：随来源重置的可写状态

TypeScript
import { linkedSignal } from '@angular/core';

const options = signal(['标准', '加急']);
const selected = linkedSignal(() => options()[0]);

selected.set('加急'); // 用户手动选择
options.set(['自提', '标准']); // 来源变化，selected 重置为 '自提'

用于"默认值来自另一个 Signal，用户也可以修改"的场景，不用写 effect 去同步。

resource：异步数据

TypeScript
import { resource } from '@angular/core';

const userId = signal(1);
const user = resource({
  params: () => ({ id: userId() }),
  loader: ({ params, abortSignal }) =>
    fetch(`/api/users/${params.id}`, { signal: abortSignal }).then((r) => r.json()),
});
  • userId 变化时自动重新请求，旧请求通过 abortSignal 取消。
  • user.status() 的取值包括 'idle'、'loading'、'reloading'、'resolved'、'error'、'local'；user.hasValue() 可以作为类型守卫。
  • 在 error 状态读取 user.value() 会抛错，读取前先判断 hasValue()。
  • httpResource 是基于 HttpClient 的版本，请求会经过拦截器。

组件输入输出

TypeScript
import { input, model, output } from '@angular/core';

export class Slider {
  readonly max = input(100); // 只读 Signal 输入
  readonly label = input.required<string>(); // 必填
  readonly value = model(0); // 双向绑定：[(value)]="v"
  readonly changed = output<number>();
}

常见追问

  • 和 RxJS 的关系？Signal 表示"当前值"，Observable 表示"随时间到达的事件流"，可以用 toSignal、toObservable 互转，见《Angular 中 Observable 和 Signals 怎样协作？》。
  • Signals 对变更检测有什么影响？模板读取的 Signal 变化时，Angular 能精确知道哪个组件需要检查，是 zoneless 模式的基础，见《Angular Zoneless 模式会改变哪些更新假设？》。
