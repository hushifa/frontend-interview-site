Svelte 的编译思路与 Runes 模型如何理解？

Svelte 在构建时把组件编译成直接更新 DOM 的 JavaScript，不使用虚拟 DOM，但仍有一个小型运行时。Svelte 5 用 Runes 显式声明响应式：$state 声明状态，$derived 声明派生值，$effect 声明副作用，$props 接收属性。

参考答案

简答

Svelte 的思路是把工作挪到构建时。编译器先分析组件的模板和状态，生成“某个状态变了就去更新这几个 DOM 节点”的代码。所以运行时不需要虚拟 DOM，也不用比较新旧两棵树。不过它不是完全没有运行时，还有一个小型运行时负责调度和响应式。

Svelte 5 用 Runes 来声明响应式，就是几个以 $ 开头、编译器认识的特殊写法：$state 声明状态，$derived 声明派生值，$effect 执行副作用，$props 接收组件属性。

$state 包住的普通对象和数组是深层响应式的，直接写 obj.a = 1 或者 list.push(x) 都会触发更新。

要注意两点。$derived 应该是纯计算；$effect 只追踪同步读取的状态。另外 Runes 只能写在 .svelte、.svelte.js、.svelte.ts 文件里，因为它要靠编译器处理。

先看一个计数器

下面一个组件把四种 Rune 都用上了。

svelte
<script>
  let { initial = 0 } = $props();
  let count = $state(initial);
  let doubled = $derived(count * 2);

  $effect(() => {
    document.title = `计数 ${count}`;
  });
</script>

<button onclick={() => count++}>点击 {count} 次</button>
<p>两倍：{doubled}</p>

count++ 看起来只是改了一个普通变量，为什么界面会变？因为编译器看到 count 是用 $state 声明的，就把对它的读写都改写成了响应式的读写。

编译后，点击按钮只会更新按钮文字、段落文字和页面标题这三处，不会把整个组件重新执行一遍。这就是“编译成直接更新 DOM 的代码”的意思。

深层状态和快照

$state 包住数组和对象时，返回的其实是一个 Proxy，也就是一个能拦截读写的代理对象。所以直接改里面的属性也能被感知到。

svelte
<script>
  let todos = $state([{ text: '学习 Runes', done: false }]);

  function toggle(i) {
    todos[i].done = !todos[i].done; // 直接修改就会更新
  }

  function save() {
    localStorage.setItem('todos', JSON.stringify($state.snapshot(todos)));
  }
</script>

可是 Proxy 交给第三方库或者 structuredClone 时可能出问题，所以 save 里先用 $state.snapshot() 取出一份普通对象。

如果数据很大，又不需要深层追踪，可以用 $state.raw。它不会变成 Proxy，代价是只能整体替换来更新，改内部属性不会触发更新。

副作用怎样清理

$effect 可以返回一个函数，这个函数会在 effect 下一次重新执行前，以及组件销毁时调用。下面用它取消过期的搜索请求：

svelte
<script>
  let query = $state('');
  let results = $state([]);

  $effect(() => {
    const q = query.trim();
    if (!q) {
      results = [];
      return;
    }
    const controller = new AbortController();
    fetch(`/api/search?q=${encodeURIComponent(q)}`, { signal: controller.signal })
      .then((r) => r.json())
      .then((data) => (results = data))
      .catch((err) => {
        if (err.name !== 'AbortError') console.error(err);
      });
    return () => controller.abort();
  });
</script>

effect 里同步读了 query，所以 query 一变它就重新执行。重新执行之前，先调用上一次返回的清理函数，把上一次还没回来的请求取消掉，这样慢的旧结果就不会覆盖新结果。

和 Svelte 4 有什么区别

Svelte 4 靠约定隐式声明响应式，Svelte 5 改成了显式的 Runes：

Svelte 4Svelte 5
顶层 let 自动响应式$state
$: doubled = count * 2$derived
$: { ... } 副作用$effect
export let name$props()
on:clickonclick

Svelte 5 仍然能运行旧语法写的组件，但同一个组件里不能两种模式混着用。

常见追问

Svelte 真的没有运行时吗？

有，只是比较小。它负责调度和响应式系统，比 React、Vue 的运行时小。没有的是虚拟 DOM 和比较新旧树的那部分。

Svelte 和 SvelteKit 是什么关系？

Svelte 是组件框架，管组件怎么写、怎么更新。SvelteKit 在它上面提供路由、数据加载、SSR 和部署，详见《SvelteKit 的路由、load 和服务端边界怎样协作？》。
