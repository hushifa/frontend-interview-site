Svelte 的编译思路与 Runes 模型如何理解？

Svelte 把组件语法交给编译器转换为运行时代码，因此理解它需要同时考虑编译规则和响应式运行机制。现代 Svelte 使用 Runes 表达状态、派生值和副作用等意图。

参考答案

Svelte 把组件语法交给编译器分析并转换为更新代码。开发者写的模板、状态和事件不会原样成为浏览器 API，而是通过编译结果与运行时协作更新 DOM。

这与“完全没有运行时”不同。用户点击、状态依赖和后续更新仍在应用运行期间发生，编译器只是提前掌握结构并生成相应逻辑。

Runes 明确标记状态与派生关系

以下是 Svelte 5 风格的组件：

svelte
<script>
  let count = $state(0);
  let doubled = $derived(count * 2);
</script>

<button onclick={() => count += 1}>已点击 {count} 次</button>
<p>两倍计数：{doubled}</p>

$state 声明响应式状态，count 在代码中看起来仍是一个数值，不需要像 getter signal 那样调用 count()。$derived 表达从其他状态计算的结果，避免再维护一份手动同步的可写值。

Runes 是编译器识别的语法机制，不是从某个包 import 后可以在任意普通 JavaScript 文件里随便调用的函数。共享响应式逻辑可使用相应的 .svelte.js 或 .svelte.ts 文件等受支持方式，仍需遵守编译和导出规则。

简单对象与数组可以形成深层响应式代理

对数组和普通对象使用 $state，Svelte 可以代理属性读取与修改，因此修改对象字段或调用数组 push 也能触发相应更新。

但不是所有值都自动深度代理。类实例、内置集合和其他对象需要按对应能力处理，不能把 Angular 或 Solid 默认引用相等的更新规则直接搬过来，也不能反过来以为所有对象突变都必然可追踪。

从代理对象解构一个普通属性到局部变量，通常取得的是当时值，不等于保留一个永远跟随原属性的响应式链接。需要持续推导时应在相应派生表达式中读取，或明确通过函数访问。

$state.raw 适合不希望深代理的状态，但更新方式也不同，通常需要替换值；$state.snapshot 可以在需要非代理数据时取得快照，快照不是仍会自动更新的引用。

派生与副作用不要混用

$derived 或 $derived.by 适合计算显示结果。其依赖来自求值时实际读取的响应式状态，复杂表达式也应保持纯计算，不要在派生过程中发请求或修改其他状态。

$effect 用于与外部系统同步等副作用。它在浏览器相应调度时机运行，可以返回清理函数，在重新执行或销毁前清理。它不是服务端生成数据的通用入口，也不应代替所有派生状态。

异步边界后的读取不会自动等同于同一次同步依赖收集；请求仍需要取消、过期结果保护和错误状态。把 fetch 放进 effect，不会自动解决竞态。

编译模型影响写法与调试方式

Svelte 可以针对模板生成细粒度更新，但最终效果仍取决于实际依赖、列表结构和副作用。大量 DOM、复杂同步计算或重复请求不会因为用了编译器自然消失。

旧版 Svelte 常见的隐式顶层 let 响应式、$: 和旧事件语法，与 runes 模式有不同规则。迁移时要确认组件当前模式，不能把两个时代的响应式假设混成一份解释。

Svelte 解决组件层；SvelteKit 进一步提供路由、加载、服务端与部署。只使用 Svelte 不会自动获得整个应用的数据加载或服务器能力。

验证一个状态例子时，应同时考虑编译结果、首次渲染与后续交互。组件能够编译，不足以证明 SSR 数据、浏览器接管和外部副作用都正确；这些需要对应环境的测试。
