Intl.PluralRules 怎样帮助实现国际化复数？

用语言相关的复数规则选择消息分支，区分 cardinal、ordinal 与手动拼接字符串的风险。

参考答案

英文可以说 1 item、2 items，中文通常不需要随数量改变“项目”的形式，但其他语言可能有更多分支。把所有语言都写成 count === 1 ? 单数 : 复数，会把英文规则强加给其他语言。

Intl.PluralRules 的作用是根据语言和数值选择一个语法类别。它不会翻译名词，也不会自动生成完整句子；文案仍由翻译资源提供。

类别名称不是固定数值标签

JavaScript
const en = new Intl.PluralRules('en');
const zh = new Intl.PluralRules('zh-CN');
const ar = new Intl.PluralRules('ar');

console.log([0, 1, 2].map((n) => en.select(n))); // ['other', 'one', 'other']
console.log([0, 1, 2].map((n) => zh.select(n))); // ['other', 'other', 'other']
console.log([0, 1, 2, 3, 11, 100].map((n) => ar.select(n)));
// ['zero', 'one', 'two', 'few', 'many', 'other']

可能的类别有 zero、one、two、few、many、other，但每种语言只使用其中一部分。类别的含义由语言规则定义，不能把 one 永远写成 n === 1，也不能认为所有语言的 0 都会返回 zero。

如果产品希望“0 条消息”显示成“暂无消息”，这通常是一个明确的业务分支，不必等语言规则返回 zero。ICU 消息中的 =0 就能表达精确数值匹配，与名为 zero 的语法类别不同。

把分支映射到完整文案

JavaScript
const rules = new Intl.PluralRules('en');
const numbers = new Intl.NumberFormat('en');
const messages = {
  one: (value) => `You have ${value} unread message.`,
  other: (value) => `You have ${value} unread messages.`,
};

function unreadMessage(count) {
  if (!Number.isSafeInteger(count) || count < 0) {
    throw new RangeError('未读数量必须是非负安全整数');
  }
  const category = rules.select(count);
  const render = messages[category] ?? messages.other;
  return render(numbers.format(count));
}

console.log(unreadMessage(1)); // You have 1 unread message.
console.log(unreadMessage(1200)); // You have 1,200 unread messages.

示例只实现英文文案。增加语言时要连同规则和完整翻译一起切换，不能只换 PluralRules 的 locale，却继续使用英文句子。完整句子还允许翻译调整词序、动词和代词，避免只给名词末尾补一个 s。

other 用作兜底，但不应拿它掩盖目标语言本来需要的其他翻译分支。实际项目通常让成熟消息库管理这些映射。

基数和序数使用不同规则

默认 type 是 cardinal，适用于“多少个”。ordinal 适用于“第几个”，例如英语的 1st、2nd、3rd：

JavaScript
const ordinal = new Intl.PluralRules('en', { type: 'ordinal' });
const suffix = { one: 'st', two: 'nd', few: 'rd', other: 'th' };
console.log([1, 2, 3, 11, 12, 13, 21].map((n) => `${n}${suffix[ordinal.select(n)]}`));
// ['1st', '2nd', '3rd', '11th', '12th', '13th', '21st']

只看个位数会错误地把 11 写成 11st。这个后缀表仍然是英文专用，不是其他语言都能复用的序数算法。

显示精度也会影响规则选择

复数规则会考虑用于规则计算的数字表示和舍入选项。若显示时保留一位小数，规则却按另一个精度选择，可能出现数字与词形不一致。对于距离、重量等小数场景，应让 NumberFormat 与 PluralRules 使用协调的精度设置，或交给消息格式化库统一处理。

同样，区间不应简单按终点选择词形；可评估 selectRange 及目标环境支持，或使用专门的区间消息。测试应选取目标语言真正不同的类别，并覆盖零、小数、舍入边界，而不是只测 1 和 2。
