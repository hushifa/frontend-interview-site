Intl.PluralRules 怎样帮助实现国际化复数？

Intl.PluralRules 告诉你一个数字在某种语言里属于哪个复数类别（zero、one、two、few、many、other），应用再用类别去选完整的消息分支。基数和序数规则不同，显示的小数位数也会影响类别。

参考答案

简答

写英文文案时，很多人用 count === 1 ? 单数 : 复数。可这只适合英语：中文只有 other 一个类别，阿拉伯语有六个，俄语里 21 和 1 还属于同一类。Intl.PluralRules 就是按语言告诉你，一个数字属于哪个复数类别。

它的 select(n) 返回的是类别名，比如 'one'、'few'，不是文案。应用拿这个类别去查完整的翻译句子。

类别名不等于具体数值。俄语的 one 包含 1、21、31，few 包含 2、3、4、22。另外，序数（1st、2nd、3rd）的规则和基数不同，要用 type: 'ordinal'。

还有一点要注意，显示 1.0 和显示 1 的类别可能不一样，所以 PluralRules 的小数位选项要和界面实际显示的一致。

各语言的类别差多少

下面用同几个数字，看看不同语言怎么分类。结果是 Node 22 实测的。

JavaScript
[0, 1, 2].map((n) => new Intl.PluralRules('en').select(n)); // ['other', 'one', 'other']
[0, 1, 2].map((n) => new Intl.PluralRules('zh-CN').select(n)); // ['other', 'other', 'other']
[0, 1, 2, 3, 11, 100].map((n) => new Intl.PluralRules('ar').select(n));
// ['zero', 'one', 'two', 'few', 'many', 'other']
[1, 2, 5, 21].map((n) => new Intl.PluralRules('ru').select(n)); // ['one', 'few', 'many', 'one']

new Intl.PluralRules('zh-CN').resolvedOptions().pluralCategories; // ['other']

英文里 0 也是 other，所以“0 files”用复数。中文全是 other。阿拉伯语六个类别全用上了。俄语的 21 又回到了 one，因为俄语看的是末位数字，不是“是不是 1”。

最后一行的 pluralCategories 列出这种语言的全部类别。拿它可以检查每种语言的翻译有没有把需要的类别都写全。

用类别选出完整的句子

下面按类别选模板，再把格式化后的数字填进去。

JavaScript
const messages = {
  one: 'You have {count} unread message.',
  other: 'You have {count} unread messages.',
};
const rules = new Intl.PluralRules('en-US');
const number = new Intl.NumberFormat('en-US');

function unreadMessage(count) {
  const template = messages[rules.select(count)] ?? messages.other;
  return template.replace('{count}', number.format(count));
}

unreadMessage(1); // 'You have 1 unread message.'
unreadMessage(1200); // 'You have 1,200 unread messages.'

为什么每个类别都写一整句，而不是只换个词尾 s？因为别的语言里，变化的可能不只是名词，动词、形容词也要跟着变。所以一个类别对应一整句话最安全。

实际项目里，一般把这些分支直接写进 ICU 消息，见《ICU MessageFormat 为什么适合复杂国际化文案？》。

序数为什么要单独处理

英文的 1st、2nd、3rd 用的是序数规则，和上面的基数规则不同。

JavaScript
const ordinal = new Intl.PluralRules('en', { type: 'ordinal' });
const suffix = { one: 'st', two: 'nd', few: 'rd', other: 'th' };
[1, 2, 3, 11, 12, 13, 21].map((n) => `${n}${suffix[ordinal.select(n)]}`);
// ['1st', '2nd', '3rd', '11th', '12th', '13th', '21st']

注意 11、12、13 都是 th。手写 n % 10 判断时，最容易在这里写成“11st”“12nd”。type: 'ordinal' 已经把这些例外处理好了。

小数位会改变类别

同一个 1，显示方式不同，类别也不同。

JavaScript
new Intl.PluralRules('en').select(1); // 'one'
new Intl.PluralRules('en', { minimumFractionDigits: 1 }).select(1); // 'other'，对应显示 "1.0"

英文里写“1 star”，却要写“1.0 stars”。所以界面上显示“1.0”时，PluralRules 也要用同样的小数位选项，否则会选错句子。

常见追问

中文就不用处理复数了吗？

翻译目录里，中文只需要写 other 一条。可代码仍要走同一套复数逻辑，不然切换到其他语言时就会出错。

=0 和 zero 有什么区别？

=0 是 ICU 消息里的精确匹配，任何语言都能用，专门处理数量正好是 0 的情况。zero 是复数类别，只有阿拉伯语等部分语言才有。
