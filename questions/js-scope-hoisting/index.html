var、let、const 和暂时性死区有什么关系？

var 的作用范围是整个函数，声明之前读到的是 undefined。let 和 const 只在代码块里有效，声明那一行执行之前访问会直接报错，这段时间叫暂时性死区。const 只是不能重新赋值，对象内容还能改。

参考答案

简答

var 声明的变量在整个函数里都有效，叫函数作用域。进入函数时它就已经存在了，值是 undefined，所以在声明之前读取不会报错，只会拿到 undefined。

let 和 const 只在所在的代码块，也就是一对大括号里有效，叫块作用域。它们在进入代码块时其实也已经存在，但在执行到声明那一行之前不能访问，一访问就抛 ReferenceError。从块开始到声明这一段，叫暂时性死区，简称 TDZ。

const 只是禁止重新赋值，如果它指向一个对象，对象的属性照样能改。

还有两个常考点。for 循环头里用 let，每一轮都会创建一个新变量，而 var 整个循环只有一个。函数声明会整体提升，可以在声明之前调用；var fn = function () {} 只提升了变量，提前调用会报错。

声明之前读取会发生什么

JavaScript
function inspectBindings() {
  console.log(count); // undefined
  var count = 1;
  console.log(count); // 1

  try {
    console.log(score);
  } catch (error) {
    console.log(error.name); // ReferenceError
  }

  let score = 2;
  console.log(score); // 2
}

inspectBindings();

同样是在声明之前读取，var 声明的 count 读到了 undefined，let 声明的 score 却抛了 ReferenceError。

原因要从函数开始执行时说起。引擎在运行函数里的代码之前，会先把里面所有声明的变量都创建出来。var 的变量在这时就被初始化成 undefined，所以随时能读。let 和 const 的变量也被创建了，但要等执行到声明那一行才初始化，在这之前访问就会报错。

平时说的“变量提升”，只是对这种现象的一种描述，代码并没有真的被挪到函数开头。

let 到底有没有提升

很多人说 let 没有提升，下面这个例子能说明并不是这样：

JavaScript
const value = '外层';
{
  try {
    console.log(value);
  } catch (error) {
    console.log(error.name); // ReferenceError
  }
  let value = '内层';
}

如果 let 没有提升，块里第一次读 value，应该读到外层的 '外层'。可实际上抛了 ReferenceError。

因为块里的 value 从块开始就已经存在了，它把外层的同名变量挡住了。第一次读取找到的是这个还在暂时性死区里的内层变量，所以报错。

typeof 也逃不过这个规则。对一个从来没声明过的名字，typeof 会返回 'undefined'；但对一个还在暂时性死区里的变量，typeof 也会抛 ReferenceError。

const 为什么还能改对象

JavaScript
const settings = { theme: 'light' };
settings.theme = 'dark'; // 允许，修改的是对象
settings = {};           // TypeError，重新赋值绑定

const 锁住的是 settings 这个变量，让它不能再指向别的值。可它指向的那个对象本身没被锁，改属性是允许的。想让属性也不能改，要用 Object.freeze，而且它只冻结一层。

for 循环里 var 和 let 有什么不同

JavaScript
const fromVar = [];
for (var i = 0; i < 3; i++) fromVar.push(() => i);

const fromLet = [];
for (let j = 0; j < 3; j++) fromLet.push(() => j);

console.log(fromVar.map(read => read()).join(',')); // 3,3,3
console.log(fromLet.map(read => read()).join(',')); // 0,1,2

两个循环写法几乎一样，var 那组函数全都返回 3，let 那组返回 0、1、2。

var 整个循环只有一个 i，三个函数记住的都是这同一个变量。等调用它们时，循环早就跑完了，i 已经是 3。let 不一样，循环每一轮都会创建一个新的 j，每个函数记住的是自己那一轮的 j。以前没有 let 时，要用立即执行函数给每一轮造一个新作用域，现在直接用 let 就行。

var 在经典脚本最外层声明时，会变成 window 的属性，容易和别的脚本互相覆盖。const 声明时必须给初始值，因为之后不能再赋值了。

常见追问

let x = x 为什么会报错？

右边读取 x 的时候，左边这个 x 已经存在了，但还没初始化，正处在暂时性死区里，所以抛 ReferenceError。

ES 模块最外层的 var 会挂到 window 上吗？

不会。模块有自己的作用域，模块里的顶层变量只属于这个模块。
