var、let、const 和暂时性死区有什么关系？

var 是函数作用域，进入函数时就初始化为 undefined；let 和 const 是块作用域，在声明执行前处于暂时性死区，访问会抛 ReferenceError。const 只禁止重新赋值，不冻结对象。

参考答案

简答

  • var 是函数作用域，进入函数时绑定已创建并初始化为 undefined，所以声明前读取得到 undefined。
  • let、const 是块作用域，绑定在进入块时就存在，但到声明执行前处于暂时性死区（TDZ），访问抛 ReferenceError。
  • const 禁止重新赋值，对象属性仍可修改。
  • for 循环头的 let 每次迭代创建新绑定，var 整个循环只有一个绑定。
  • 函数声明会整体提升，可以在声明前调用；var fn = function () {} 只提升变量。

声明前读取

JavaScript
function inspectBindings() {
  console.log(count); // undefined
  var count = 1;
  console.log(count); // 1

  try {
    console.log(score);
  } catch (error) {
    console.log(error.name); // ReferenceError
  }

  let score = 2;
  console.log(score); // 2
}

inspectBindings();

"提升"只是对现象的描述：引擎在执行前为作用域内的所有声明创建绑定，var 同时初始化为 undefined，let/const 要等执行到声明那一行才初始化。

TDZ 会遮住外层同名变量

JavaScript
const value = '外层';
{
  try {
    console.log(value);
  } catch (error) {
    console.log(error.name); // ReferenceError
  }
  let value = '内层';
}

块内的 value 从块开始就存在，所以第一次读取命中的是还在 TDZ 里的内层绑定，而不是外层的 '外层'。这也说明 let 并非"没有提升"。

typeof 对从未声明的名字返回 'undefined'，但对 TDZ 中的名字同样抛 ReferenceError。

const 与对象

JavaScript
const settings = { theme: 'light' };
settings.theme = 'dark'; // 允许，修改的是对象
settings = {};           // TypeError，重新赋值绑定

需要防止属性被修改时用 Object.freeze，它只冻结一层。

循环中的闭包

JavaScript
const fromVar = [];
for (var i = 0; i < 3; i++) fromVar.push(() => i);

const fromLet = [];
for (let j = 0; j < 3; j++) fromLet.push(() => j);

console.log(fromVar.map(read => read()).join(',')); // 3,3,3
console.log(fromLet.map(read => read()).join(',')); // 0,1,2

var 的三个回调共享同一个 i，循环结束时是 3。let 每轮有独立的 j。以前用立即执行函数制造新作用域来解决，现在直接用 let。
