为什么前端环境变量不能存放秘密？

前端环境变量在构建时被写进发给用户的代码，谁都能看到。文中讲清构建环境与浏览器运行环境的区别、Vite 的变量前缀、字符串类型、文件优先级和 mode，以及运行时配置和服务端秘密的边界。

参考答案

简答

前端代码里读的环境变量，在构建时就被替换成了具体的值，直接写进发给用户的 JS 文件里。用户打开 DevTools 就能搜到，所以它不能放任何秘密。

Vite 只把 VITE_ 开头的变量暴露给客户端代码。这个前缀的作用是防止误暴露，它不是加密。

API 密钥、数据库口令、签名私钥这类秘密，只能留在服务端。浏览器请求自己的后端，由后端带着密钥去调第三方服务。

另外要注意，变量的值都是字符串，要自己转换和校验；改了变量要重新构建才会生效。

构建时替换意味着公开

先看源码里的一行请求，和它构建之后的样子。

JavaScript
// 源码
fetch(`${import.meta.env.VITE_API_BASE}/users`);
// 构建产物中大致变成
fetch(`${'https://api.example.com'}/users`);

很多人以为环境变量是在浏览器运行时“读取”的。其实浏览器拿到的已经是替换后的结果，变量的值就是代码里的一个字符串。

所以打开 DevTools 的 Sources 面板，或者直接下载 JS 文件，就能搜到所有被引用的变量值。混淆和压缩只会改变量名和格式，字符串的内容还在。

Vite 是怎样加载变量的

Vite 会依次加载 .env、.env.local、.env.[mode]、.env.[mode].local，越具体的文件优先级越高。带 .local 的文件放个人配置，应该加进 .gitignore。

这里的 mode 是“模式”，决定加载哪个 .env.[mode] 文件，可以用 --mode 指定。不指定时，开发是 development，构建是 production。另外，启动 Vite 时进程里已经存在的环境变量，优先级比 .env 文件还高。

只有 VITE_ 前缀的变量会出现在 import.meta.env 里，前缀可以用 envPrefix 修改。但 envPrefix 不能设成空字符串，因为那样会把所有环境变量都暴露出去，Vite 检测到 '' 会直接报错。只需要暴露个别变量时，用 define。内置的 import.meta.env.MODE、DEV、PROD、BASE_URL 可以直接用。

为什么值要自己转换

变量的值永远是字符串，这一点很容易踩坑。下面这段代码在 Node.js 里运行一下就能看到现象：

JavaScript
const raw = 'false';
console.log(Boolean(raw)); // true
console.log(raw === 'true'); // false
console.log(Number.isFinite(Number('abc'))); // false

'false' 是一个非空字符串，所以转成布尔值是 true。如果直接写 if (import.meta.env.VITE_FEATURE_X)，配置成 false 功能也会打开。改法是跟字符串比较，数字则转换后校验：

JavaScript
const timeout = Number(import.meta.env.VITE_TIMEOUT ?? 5000);
if (!Number.isFinite(timeout)) throw new Error('VITE_TIMEOUT 必须是数字');
const enabled = import.meta.env.VITE_FEATURE_X === 'true'; // 'false' 字符串本身是真值

秘密应该放在哪里

需要密钥的调用交给服务端或 BFF。BFF 是专门给前端服务的一层后端。浏览器请求自己的后端，后端带上密钥访问第三方服务，同时做鉴权、限流和参数校验。

有些第三方服务会提供“可以公开的客户端密钥”，比如地图 SDK 的浏览器 key。这种 key 的安全性不来自隐藏，而来自服务方后台的限制，所以要在后台限制来源域名和权限范围。

构建期配置和运行时配置

同一份构建产物要部署到测试和生产环境时，如果把接口地址写进构建，每个环境都得重新构建一次。

替代做法是让页面启动时读取一个运行时配置文件，比如 /config.json，由部署环境提供。这份文件同样是公开的，只能放非敏感的配置。

常见追问

把 .env 加进 .gitignore 就安全了吗？

不是。这只能防止文件被提交到仓库。只要代码引用了某个变量，构建时它的值照样会写进产物，用户照样能看到。

SSR 项目呢？

服务端代码可以读取完整的 process.env，这部分不会直接发给浏览器。但要确保这些值不会被序列化进返回给浏览器的 HTML 或数据里，否则还是泄露了。
