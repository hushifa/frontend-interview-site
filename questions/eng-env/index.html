为什么前端环境变量不能存放秘密？

区分构建环境与浏览器运行环境，解释 Vite 的变量前缀、字符串类型、文件优先级和 mode，并说明运行时配置与服务端秘密的边界。

参考答案

简答

  • 前端"环境变量"在构建时被替换成字面量，写进发给用户的 JS 文件，任何人都能看到。
  • Vite 只把 VITE_ 前缀的变量暴露给客户端代码，前缀是防误暴露的开关，不是加密。
  • 秘密（API 密钥、数据库口令、签名私钥）只能留在服务端，由服务端代为调用。
  • 变量值都是字符串，需要自己转换和校验；修改后要重新构建才生效。

构建期替换意味着公开

JavaScript
// 源码
fetch(`${import.meta.env.VITE_API_BASE}/users`);
// 构建产物中大致变成
fetch(`${'https://api.example.com'}/users`);

浏览器拿到的是替换后的结果。打开 DevTools 的 Sources 面板或直接下载 JS 文件，就能搜到所有被引用的变量值。混淆和压缩不会改变这一点。

Vite 的规则

  • .env、.env.local、.env.[mode]、.env.[mode].local 依次加载，越具体的优先级越高；.local 文件应加入 .gitignore。
  • --mode 决定加载哪个 .env.[mode]，默认开发是 development、构建是 production。
  • 启动 Vite 时已经存在的进程环境变量优先于 .env 文件。
  • 只有 VITE_ 前缀（可用 envPrefix 修改）的变量出现在 import.meta.env 中。envPrefix 不能设成空字符串，那会暴露全部环境变量，Vite 检测到 '' 会直接报错；只需暴露个别变量时用 define。
  • 内置的 import.meta.env.MODE、DEV、PROD、BASE_URL 可直接使用。
JavaScript
const timeout = Number(import.meta.env.VITE_TIMEOUT ?? 5000);
if (!Number.isFinite(timeout)) throw new Error('VITE_TIMEOUT 必须是数字');
const enabled = import.meta.env.VITE_FEATURE_X === 'true'; // 'false' 字符串本身是真值

秘密应该放在哪里

需要密钥的调用交给服务端或 BFF：浏览器请求自己的后端，后端带上密钥访问第三方服务，并做鉴权、限流和参数校验。第三方服务提供"可公开的客户端密钥"（如地图 SDK 的浏览器 key）时，要在服务方后台限制来源域名和权限范围，它的安全性来自这些限制，而不是来自隐藏。

构建期配置和运行时配置

同一个构建产物要部署到测试和生产环境时，把地址写进构建会迫使每个环境重新构建。替代做法是让页面启动时读取一个运行时配置文件（如 /config.json），由部署环境提供。这份文件同样是公开的，只放非敏感配置。

常见追问

  • .env 加进 .gitignore 就安全了吗？只防止提交到仓库，被构建引用的值照样进入产物。
  • SSR 项目呢？服务端代码可以读取完整的 process.env，但要确保这些值不会被序列化进返回给浏览器的 HTML 或数据。
