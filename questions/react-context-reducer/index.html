Context 与 useReducer 适合管理什么状态？

Context 把值传给一棵子树里任意深度的组件，useReducer 把状态更新逻辑集中到一个纯函数里。两者组合可以替代层层传 props，但 Context 值变化会让所有消费者重新渲染，高频更新的全局状态更适合专门的状态库。

参考答案

简答

  • Context 解决"跨多层传值"：Provider 下的任意后代用 useContext 读取最近的值，不必逐层传 props。
  • useReducer 解决"更新逻辑分散"：所有状态变化写在 reducer(state, action) 里，组件只负责 dispatch 动作。
  • 常见组合是把 state 和 dispatch 放进两个 Context，dispatch 的引用永远不变，只用它的组件不会因状态变化重新渲染。
  • Context 值变化时，所有读取它的组件都会重新渲染，memo 拦不住；适合主题、语言、当前用户这类低频变化的数据。
  • reducer 必须是纯函数，请求、计时器等副作用放在事件处理器或 Effect 里。

组合示例

JSX
import { createContext, use, useReducer } from 'react';

const TasksContext = createContext(null);
const TasksDispatchContext = createContext(null);

function tasksReducer(tasks, action) {
  switch (action.type) {
    case 'added':
      return [...tasks, { id: action.id, text: action.text, done: false }];
    case 'toggled':
      return tasks.map((t) => (t.id === action.id ? { ...t, done: !t.done } : t));
    case 'deleted':
      return tasks.filter((t) => t.id !== action.id);
    default:
      throw new Error(`未知动作：${action.type}`);
  }
}

export function TasksProvider({ children }) {
  const [tasks, dispatch] = useReducer(tasksReducer, []);
  // React 19 起可以直接用 <Context value>，旧写法 <Context.Provider value> 仍可用
  return (
    <TasksContext value={tasks}>
      <TasksDispatchContext value={dispatch}>{children}</TasksDispatchContext>
    </TasksContext>
  );
}

export const useTasks = () => use(TasksContext);
export const useTasksDispatch = () => use(TasksDispatchContext);

只负责添加任务的输入框调用 useTasksDispatch()，任务列表变化时它不会重新渲染。

性能注意点

  • Provider 的 value 如果每次渲染都新建对象（如 value={{ user, setUser }}），所有消费者每次都会重新渲染。用 useMemo 包裹，或像上面一样拆成多个 Context。
  • 一个大 Context 装下所有全局状态时，任何字段变化都会波及全部消费者。按更新频率和使用范围拆分。
  • 需要"只订阅状态的一部分"时，Context 做不到，这是 Zustand、Redux 等库的用武之地，它们基于 useSyncExternalStore 实现选择器订阅。

什么时候不用 Context

  • 只隔了两三层的组件，直接传 props 更清楚。
  • 可以通过组合避免传递：把需要数据的组件作为 children 传进中间层。
  • 服务端数据（列表、详情）应交给数据请求库管理缓存和失效，而不是手动放进 Context。

常见追问

  • 没有 Provider 时读到什么？读到 createContext(defaultValue) 的默认值。
  • use(Context) 和 useContext 有什么区别？功能相同，use 可以在条件语句里调用。
