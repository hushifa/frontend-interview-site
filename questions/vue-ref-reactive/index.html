Vue 3 中 ref 和 reactive 有什么区别？

ref 用 value 容器表示可替换的响应式值，reactive 用 Proxy 表示对象属性的响应式访问。解构、整个对象替换、ref 解包和浅层 API 都有各自规则，不能把它们统一理解为所有变量都会自动保持连接。

参考答案

ref 与 reactive 都可以参与 Vue 响应式，但它们提供的入口不同。ref 是一个带 value 属性的容器，适合原始值，也可以保存对象；reactive 则返回对象的响应式代理，通过属性读取与修改建立关系。

选择时可以先问：需要管理一个经常整体替换的值，还是一组希望保持同一容器身份的对象属性？这比简单规定“数字用 ref，对象必须用 reactive”更准确。

ref 可以包装原始值，也可以包装对象

JavaScript
import { reactive, ref, toRef, toRefs, isRef } from 'vue';

const count = ref(0);
count.value += 1;
console.log(count.value); // 1

const user = ref({ name: 'Lin' });
const previous = user.value;
user.value = { name: 'Chen' };
console.log(user.value.name); // Chen
console.log(user.value === previous); // false

在 JavaScript 中，读写 ref 通常通过 .value。对象值默认会经过相应的深层响应式转换，整个对象可以通过给 .value 赋新值替换，订阅这个入口的逻辑也能感知变化。

reactive 需要对象类型，例如普通对象、数组、Map 或 Set，不能直接把一个数字代理成响应式变量。它返回的 Proxy 与原对象身份不同，应一致使用代理入口，而不是一会儿改代理、一会儿绕过它改原对象。

普通解构只读取当时的值

下面继续使用前面的导入：

JavaScript
const state = reactive({ count: 0, name: 'Lin' });
const { count: detached } = state;
const linked = toRef(state, 'count');
const fields = toRefs(state);

state.count = 2;
console.log(detached); // 0
console.log(linked.value); // 2
linked.value = 3;
console.log(state.count); // 3
console.log(fields.name.value); // Lin

detached 保存的是解构时取出的普通数字，没有建立一个自动读回 state.count 的通道。toRef 则创建与指定属性连接的 ref，读取和写入会对应到源属性；toRefs 为对象当前可枚举的属性建立类似连接。

这不是所有解构都会深拷贝。若解构得到的本来是响应式子对象引用，对那个子对象的属性修改仍然可能被追踪；丢失的是通过原属性重新取值的连接。如果原来的子对象属性被替换，旧引用也不会自动变成新对象。

toRefs 只处理调用时相应可枚举属性，后面新加的名字不会自动出现在已经返回的结果里。已知某个字段需要单独连接时，toRef 通常更直接。

整个 reactive 变量重新赋值，是普通变量替换

JavaScript
let current = reactive({ count: 0 });
const originalProxy = current;
current = reactive({ count: 1 });

console.log(originalProxy.count); // 0
console.log(current.count); // 1

赋值给 current 本身不是一个被 Vue 拦截的响应式属性写入。其他地方已经保存的 originalProxy 仍然指向旧代理，之前围绕旧对象建立的关系不会仅因变量名重用就全部迁移。

这不表示任何对象都不能被替换。通过 ref.value，或通过另一个响应式对象的属性替换对象，都有可追踪的入口。若选择 reactive 管理固定容器，也可以修改其属性；关键是让变化发生在使用者实际订阅的那条路径上。

解包规则与访问位置有关

JavaScript
const nested = reactive({ amount: ref(1) });
console.log(nested.amount); // 1

const values = reactive([ref(1)]);
console.log(isRef(values[0])); // true
console.log(values[0].value); // 1

深层 reactive 普通对象属性访问可以自动解包 ref，但响应式数组元素和 Map 等集合中的 ref 并不按同样方式自动解包。不能因为对象属性里省略过 .value，就把所有位置都按同一规则处理。

模板也有自己的解包规则，常见的顶层 ref 绑定可以直接使用。普通对象里嵌套的 ref、运算表达式和最终文本插值又可能表现不同，因此不要把“模板里永远不需要 .value”作为通用结论。

Vue 3.5 的 script setup 对 defineProps 解构还提供编译期转换，这是特定语法的编译能力，不是 JavaScript 普通解构从此变成响应式。阅读旧例子时应把版本与来源区分开。

浅层 API 是另一种有意的边界

shallowRef 主要追踪 .value 替换，不会把内部对象都做同样的深层转换；shallowReactive 主要处理根层属性。它们适合明确由外部库管理或按不可变方式更新的大结构，但不是解决不明原因更新问题的快捷开关。

把深层、浅层和原始对象随意混用，容易让同一结构的不同路径具有不同追踪行为。应先定义谁负责内部变更，再决定是否只需要追踪外层引用变化。

选择依据仍然是数据流

ref 对单个值、组合函数返回值和整体替换很方便；reactive 对一组相关属性也很自然。两者都不会自动把派生结果、用户草稿和服务端数据同步成正确的业务状态。

排查“不更新”时，可以依次确认：读取的是 ref.value 还是普通拷贝，修改经过哪一个代理，是否替换了普通变量，访问位置是否自动解包，以及是否用了浅层 API。明确这些路径，比反复在 ref 与 reactive 之间切换更有效。
