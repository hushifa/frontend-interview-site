Vue 3 中 ref 和 reactive 有什么区别？

ref 能包装任何值，通过 .value 读写，可以整体替换；reactive 只能包对象，解构或整体替换都会丢失响应式。官方推荐默认用 ref。

参考答案

简答

ref 把一个值装进一个盒子里，通过 .value 读写，什么类型都能装，数字、字符串、对象都行。在模板里会自动拆开，不用写 .value。如果装的是对象，里面会用 reactive 转换。

reactive 只能用于对象、数组、Map、Set，返回原对象的深层响应式 Proxy，读写时不用 .value。

两者的差别主要在 reactive 的局限。它不能整体替换，state = {...} 以后就和原来断开了；解构出来的基本类型属性不再响应；把单个属性传给函数也会丢失响应式。需要解构时可以用 toRefs。

因为这些坑，Vue 官方建议默认用 ref。组合式函数通常也返回由多个 ref 组成的普通对象。

对比两者的行为

下面这段代码把常见的对和错都放在一起：

JavaScript
import { reactive, ref, toRefs, watch } from 'vue';

const count = ref(0);
count.value++;
count.value = 10; // 整体替换，依然响应

const user = reactive({ name: 'Lin', age: 20 });
user.age++; // 响应

let { name } = user;
name = 'Chen'; // 只改了局部变量，user.name 不变

const { age } = toRefs(user);
age.value++; // 同步修改 user.age

watch(user.name, () => {}); // 错误：传入的是字符串
watch(() => user.name, () => {}); // 正确：传入 getter

let { name } = user 为什么不响应？因为解构就是把 user.name 当时的值复制给一个新变量，这个变量是普通的字符串，和 Proxy 没有关系了，改它不会经过 Proxy 的拦截。watch(user.name) 也是同样的道理，传进去的只是字符串 'Lin'。

toRefs 能解决这个问题，它把每个属性转成一个 ref，读写 age.value 时实际上是在读写 user.age，所以两边同步。

ref 什么时候会自动拆开

在模板里，顶层的 ref 会自动拆开，直接写 {{ count }} 就行。ref 作为 reactive 对象的属性时，访问时也会自动拆开，reactive({ count }).count 拿到的就是数字。

但 ref 放在数组或 Map 里时不会自动拆开，要写 list[0].value。

浅层版本适合什么场景

shallowRef 只追踪 .value 本身有没有被换掉，不会深入转换里面的对象；shallowReactive 只追踪第一层属性。它们适合大块的不可变数据，比如接口返回的大列表、第三方类的实例，更新时整体替换：

JavaScript
const rows = shallowRef([]);
rows.value = await fetchRows(); // 触发更新
rows.value.push(item); // 不触发
rows.value = [...rows.value, item]; // 触发

push 为什么不触发？因为 push 改的是数组内部，.value 指向的还是同一个数组，shallowRef 看不到变化。换成一个新数组赋给 .value，才会触发。

背后是怎么实现的

reactive 用 Proxy 拦截 get 和 set，读的时候收集依赖，写的时候触发更新。ref 则是一个带 value getter 和 setter 的对象，因为 Proxy 只能代理对象，没法拦截数字、字符串这种基本类型。

Vue 2 用的是 Object.defineProperty，检测不到新增属性和数组下标赋值，需要 Vue.set。Vue 3 的 Proxy 没有这些限制。

常见追问

reactive 返回的对象和原对象相等吗？

不相等，返回的是一个代理。直接修改原对象不会触发更新，所以应该始终通过代理去读写。

为什么不全部用 reactive？

基本类型只能用 ref。而且整体替换、解构、跨函数传递这些场景，用 ref 更不容易出错。
