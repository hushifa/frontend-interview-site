Vue 3 中 ref 和 reactive 有什么区别？

ref 把任意值包装进一个带 .value 的对象，可以整体替换；reactive 返回对象的 Proxy，只能用于对象，解构或整体替换都会丢失响应式。官方推荐优先使用 ref。

参考答案

简答

  • ref(x) 可以包装任意类型，在 JS 中通过 .value 读写，在模板中自动解包；值是对象时，内部会用 reactive 转换。
  • reactive(obj) 只接受对象、数组、Map、Set，返回原对象的深层响应式 Proxy，读写不需要 .value。
  • reactive 的局限：不能整体替换（state = {...} 会断开连接），解构出的基本类型属性不再响应，传给函数的单个属性也会丢失响应式。
  • 需要解构 reactive 对象时用 toRefs，组合式函数通常返回包含多个 ref 的普通对象。
  • Vue 官方建议默认使用 ref。

对比

JavaScript
import { reactive, ref, toRefs, watch } from 'vue';

const count = ref(0);
count.value++;
count.value = 10; // 整体替换，依然响应

const user = reactive({ name: 'Lin', age: 20 });
user.age++; // 响应

let { name } = user;
name = 'Chen'; // 只改了局部变量，user.name 不变

const { age } = toRefs(user);
age.value++; // 同步修改 user.age

watch(user.name, () => {}); // 错误：传入的是字符串
watch(() => user.name, () => {}); // 正确：传入 getter

ref 的解包规则

  • 模板中顶层的 ref 自动解包：{{ count }}。
  • ref 作为 reactive 对象的属性时，访问时自动解包：reactive({ count }).count 返回数字。
  • ref 放在数组或 Map 中时不会自动解包，要写 list[0].value。

浅层版本

shallowRef 只追踪 .value 本身的替换，不深入转换内部对象；shallowReactive 只追踪第一层属性。用于大型不可变数据（例如接口返回的大列表、第三方类实例），更新时整体替换：

JavaScript
const rows = shallowRef([]);
rows.value = await fetchRows(); // 触发更新
rows.value.push(item); // 不触发
rows.value = [...rows.value, item]; // 触发

实现原理

  • reactive 用 Proxy 拦截 get（收集依赖）和 set（触发更新）。
  • ref 是一个带 value getter/setter 的对象，因为 Proxy 无法拦截基本类型。

Vue 2 用 Object.defineProperty 实现，无法检测新增属性和数组下标赋值，需要 Vue.set；Vue 3 的 Proxy 没有这些限制。

常见追问

  • reactive 返回的对象和原对象相等吗？不相等，修改原对象不会触发更新，应始终使用 Proxy。
  • 为什么不全部用 reactive？基本类型只能用 ref，而整体替换、解构、跨函数传递的场景 ref 更不容易出错。
