dns-prefetch、preconnect 和 preload 应该怎样选择？

从 DNS 解析、连接建立和资源获取阶段区分三种资源提示，避免把它们当成同一种加速手段。

参考答案

dns-prefetch 只提示浏览器提前解析域名；preconnect 还可以提前建立连接，可能包含 TCP 与 TLS 握手；preload 则是告诉浏览器当前页面很快需要某个具体资源，并要求正确填写 as、crossorigin 等属性。

它们解决的阶段不同。对确实会访问的第三方域名，可以少量使用 preconnect；只希望低成本提前解析时使用 dns-prefetch。preload 适合首屏确定需要、但浏览器从 HTML 结构不容易及时发现的资源，例如关键字体或脚本。预加载错误资源会抢占带宽，反而拖慢真正关键内容。

还要注意跨源字体和模块脚本的凭据模式必须与实际请求一致，否则预加载可能无法复用，形成重复请求。最终应结合浏览器 Network 面板和性能指标验证，不要看到标签存在就认为一定提速。

常见追问

  • preconnect 不能替代缓存、压缩和合理的资源加载顺序。
  • 第三方域名很多时不应全部预连接；连接本身也消耗浏览器和网络资源。

复习提示

回答时把请求、响应、缓存和连接状态分开描述，并明确哪一层负责解决问题。涉及协议或状态码时结合实际报文验证，不把框架封装后的表现直接当成 HTTP 标准。建议用一个最小示例验证“DNS、资源提示、性能”，再比较正常路径、失败路径和目标运行环境的差异。
