点击“停止生成”后，服务端一定停止调用模型吗？

不一定。界面停止显示、浏览器请求中止、服务端任务停止、模型调用中止是四件事，取消信号要一层层传下去；已经执行的工具操作也不会因此撤销。

参考答案

简答

不一定。用户点“停止”，其实涉及四层：前端不再显示新内容、浏览器中止到我们服务的请求、我们的服务端停止任务、服务端中止对模型服务商的请求。前一层停了，后一层不一定跟着停。

前端用 AbortController 中止 fetch，同时关掉写入界面的回调，这样迟到的数据也不会再显示出来。

服务端要把请求的取消信号传给调用模型的 SDK。如果生成是后台任务，用户关掉页面也要继续跑，就不能靠断连来取消，要单独提供一个按任务 ID 取消的接口。

停止以后，已经收到的文字要保留并标记为“中断”。生成过程中已经执行的工具操作，比如发出去的邮件，停止按钮是撤销不了的。

前端：中止请求，并关掉回调

下面这个函数负责启动一次生成，并返回一个 stop 方法。注意看 accepting 这个变量。

JavaScript
function startGeneration(run, onChunk) {
  const controller = new AbortController();
  let accepting = true;

  const done = run({
    signal: controller.signal,
    emit(chunk) {
      if (accepting) onChunk(chunk);
    },
  })
    .then(() => ({ status: 'completed' }))
    .catch((error) => {
      if (controller.signal.aborted) return { status: 'stopped' };
      throw error; // 真正的错误继续抛出
    })
    .finally(() => {
      accepting = false;
    });

  return {
    done,
    stop() {
      accepting = false;
      controller.abort();
    },
  };
}

controller.abort() 会让 fetch 中止，这个好理解。那为什么还要一个 accepting？

因为我们没法保证底层代码一定响应 signal。有的库忽略了它，有的数据已经在路上，中止之后回调还可能被调用。stop() 先把 accepting 设成 false，之后不管还有什么数据进来，emit 都直接丢掉，界面不会再多出一个字。

catch 里也做了区分：如果是我们自己中止的，返回 stopped；如果是网络错误这类真问题，继续往外抛，不能把它吞掉当成“用户停止”。

服务端：取消信号要一路传下去

浏览器中止 fetch 以后，服务端会看到连接断开。可是服务端代码如果没有监听这个信号，它对模型服务商的请求还会继续跑，token 照样生成、照样计费。所以服务端要拿到请求的取消信号，把它传给调用模型的 SDK。

中间如果隔着代理、边缘平台的缓冲或者任务队列，断连这件事可能根本传不到模型调用那一层。

还有一种产品设计是：用户关掉页面，任务继续跑，回来再看结果。这时断连就不能等于取消，要提供一个显式接口，比如 POST /runs/:id/cancel，返回 cancelling、cancelled 或 completed，让前端知道任务最后到底停没停。

另外要知道，服务商在收到中止之前已经生成的 token，通常仍然会计费。

停止以后，数据怎么处理

已经收到的文字要保留，消息记录里写明结束原因，比如用户停止、网络错误、服务端拒绝。这样刷新页面以后，它不会被显示成一条完整的回答。

用户停止后马上重试，新的生成要用新的请求 ID，旧请求迟到的回调直接丢弃，不然两次的内容会混在一起。

最容易被忽略的是工具调用。生成过程中如果已经发了邮件、写了文件，停止按钮撤销不了这些操作。能做的是：还没开始的步骤不再执行；正在进行的按调用 ID 去查真实结果；确实需要撤销时，调用业务自己的撤销接口。

常见追问

reader.cancel() 和 controller.abort() 有什么区别？

reader.cancel() 是不再读取响应体；abort() 是中止整个 fetch，连还没开始的响应也一起中止。不过两者影响的都只是浏览器到我们服务端这一段连接，服务端后面的模型调用停不停，要看服务端有没有把信号传下去。

停止功能要测哪些情况？

至少要测这几种：第一个字出来之前就停止、流到一半停止、停止后马上重试、模型 SDK 不支持取消、停止时工具已经执行了。
