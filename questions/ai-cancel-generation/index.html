点击“停止生成”后，服务端一定停止调用模型吗？

不一定。停止显示、取消浏览器请求、服务端停止任务和上游模型中止是四个层次，取消信号要逐层传递；已经执行的工具副作用不会因此撤销。

参考答案

简答

  • 停止有四层：前端停止显示、中止浏览器到自己服务的请求、服务端停止任务、服务端中止对模型服务商的请求。前一层停了，后一层不一定停。
  • 前端用 AbortController 中止 fetch，同时关闭结果回调，让迟到的数据不再写进界面。
  • 服务端要把请求的取消信号传给模型 SDK；生成已经转成后台任务时，需要一个按任务 ID 取消的接口。
  • 停止后保留已收到的文字并标记为中断；已经执行的工具调用要按调用 ID 查询真实状态，停止按钮不能回滚它们。

前端：中止请求并关闭回调

JavaScript
function startGeneration(run, onChunk) {
  const controller = new AbortController();
  let accepting = true;

  const done = run({
    signal: controller.signal,
    emit(chunk) {
      if (accepting) onChunk(chunk);
    },
  })
    .then(() => ({ status: 'completed' }))
    .catch((error) => {
      if (controller.signal.aborted) return { status: 'stopped' };
      throw error; // 真正的错误继续抛出
    })
    .finally(() => {
      accepting = false;
    });

  return {
    done,
    stop() {
      accepting = false;
      controller.abort();
    },
  };
}

accepting 保证即使底层代码不响应 signal，旧结果也不会继续追加到界面。

服务端：把取消传下去

  • 浏览器中止 fetch 后，服务端会看到连接关闭。服务端代码要监听请求的取消信号，并把它传给调用模型的 SDK。
  • 中间有代理、边缘平台缓冲或任务队列时，断连可能传不到模型调用这一层。
  • 有的产品希望关掉页面后任务继续跑，用户回来再看。这时断连不应等于取消，而要提供 POST /runs/:id/cancel 这样的显式接口，返回 cancelling、cancelled 或 completed。

服务商在收到中止前已经生成的 token 通常仍会计费。

停止之后的数据

  • 已收到的文字保留，消息记录里写明结束原因（用户停止、网络错误、服务端拒绝），刷新后不显示成完整回答。
  • 下一次生成用新的请求 ID，旧请求的迟到回调直接丢弃。
  • 生成过程中已经发出的工具调用（发邮件、写文件）不会被撤销。只能阻止还没开始的步骤，进行中的按调用 ID 查询结果，需要撤销时调用业务的撤销接口。

常见追问

  • reader.cancel() 和 controller.abort() 有什么区别？ reader.cancel() 取消对响应体的读取；abort() 中止整个 fetch，包括还没开始的响应。两者都只影响浏览器到服务端这一段连接。
  • 测试哪些情况？ 首字前停止、流中停止、停止后立即重试、模型 SDK 不支持取消、工具已经执行。
