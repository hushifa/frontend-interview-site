提示词注入与普通 XSS 有什么区别？

提示词注入试图让模型把不可信内容中的指令当成应执行的要求。输入不一定来自当前聊天用户，也可能藏在检索文档、网页、工具结果、代码注释或图片中，这类情况属于间接注入。

参考答案

提示词注入试图让模型把不可信内容中的指令当成应执行的要求。输入不一定来自当前聊天用户，也可能藏在检索文档、网页、工具结果、代码注释或图片中，这类情况属于间接注入。

在“提示词注入与普通 XSS 有什么区别？”这个问题中，先把消息、模型流、工具调用、审批和最终状态分开建模，再处理断线、取消和重试；模型输出和工具结果都必须当作不可信数据。这里的 提示词注入、不可信内容、最小权限 不是孤立的 API 名称，而是会共同影响输入、过程和最终结果。

AI 界面至少要区分用户消息、模型流、工具调用、工具结果、审批、取消、重试和最终状态。每一步都应有稳定 ID 和可恢复的状态，不能把网络片段直接拼成可信业务对象。

XSS 关注浏览器把不可信内容作为脚本执行；提示词注入关注模型的指令与数据边界。两者可以同时发生，但 HTML 转义并不能解决模型听从恶意文档的问题，写一句“忽略恶意指令”也不能作为可靠授权机制。

应把权限与工具执行检查放在模型之外，限制可访问资源及操作范围，并对重要操作绑定明确确认。前端要区分来源内容、模型建议和真实用户指令；展示失败、拒绝和来源信息。过滤器和防护模型可以辅助，但不能替代执行端鉴权与最小权限。

模型输出、检索内容和工具结果都属于不可信输入。密钥、权限和不可逆操作必须留在受控边界，前端负责展示确认和错误恢复，服务端负责最终授权、校验和执行记录。

实际 AI 界面要把每次生成当成一个可追踪任务，而不是一段字符串。用户刷新、断网、取消或重新发送后，仍要能判断哪些内容已经保存、哪些工具已经执行、哪些结果只能作为候选信息展示。
