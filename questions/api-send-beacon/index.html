sendBeacon 返回 true 就代表上报成功了吗？页面离开时怎样发送统计？

sendBeacon 返回 true 只表示浏览器接受了排队，不代表服务端收到；页面离开时在 visibilitychange 变为 hidden 时用 sendBeacon 或 fetch keepalive 发送，服务端要能处理重复和丢失。

参考答案

简答

  • navigator.sendBeacon(url, data) 发出 POST 请求，页面卸载后请求仍会继续发送。
  • 返回 true 只表示数据已进入浏览器的发送队列，返回 false 通常是数据过大（排队总量约 64KB 的限制）；服务端是否收到、返回什么状态，页面都无从得知。
  • 发送时机选 visibilitychange 变为 hidden，unload 和 beforeunload 在移动端经常不触发，还会影响 bfcache。
  • 需要自定义请求头或 JSON 类型时，用 fetch(url, { method: 'POST', keepalive: true })，同样有 64KB 的限制。
  • 统计数据要设计成可丢失、可去重，例如每条带唯一 ID。

示例

JavaScript
const queue = [];

function track(event) {
  queue.push({ id: crypto.randomUUID(), time: Date.now(), ...event });
}

function flush() {
  if (queue.length === 0) return;
  const body = JSON.stringify(queue.splice(0, queue.length));
  const blob = new Blob([body], { type: 'application/json' });
  if (!navigator.sendBeacon('/api/collect', blob)) {
    fetch('/api/collect', { method: 'POST', body, keepalive: true, headers: { 'Content-Type': 'application/json' } }).catch(() => {});
  }
}

document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') flush();
});
  • 用 Blob 指定 application/json 时，跨源请求会触发 CORS 预检；服务端要允许，或者改用 text/plain 避免预检。
  • sendBeacon 不能设置自定义请求头，鉴权依赖 Cookie 或 URL 里的参数。
  • 平时可以定时或攒够一定数量后发送，页面离开时只发剩余部分，单次数据更小。

为什么用 hidden 而不是 unload

用户在移动端切到后台、再从任务列表划掉应用，页面不会收到 unload。visibilitychange 到 hidden 是最后一个能可靠执行代码的时机。一个会话中页面可能多次隐藏和恢复，所以每次隐藏都发送当前队列，服务端按 ID 去重。

常见追问

  • 为什么不在离开时用同步 XHR：会阻塞页面关闭，浏览器已限制在卸载事件中使用同步 XHR。
  • fetchLater()：Chromium 中的新 API，让浏览器在页面离开时自动发送延迟请求，其他浏览器尚未支持，使用前要特性检测。
