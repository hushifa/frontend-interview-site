前端图表如何同时满足无障碍和高性能？

图表先提供标题、单位、关键结论和可展开的数据表；颜色不能是唯一编码，悬停提示不能是唯一入口。大数据量用 Canvas 或 WebGL 绘制，语义层只维护少量可访问节点，实时数据合并播报并尊重减少动态效果设置。

参考答案

简答

  • 图表旁边写出标题、单位、时间范围和一句话结论，并提供可展开的数据表，读屏用户和需要精确数值的用户都能用上。
  • 整张图作为一张图片说明时用 role="img" 加名称和描述；需要逐点探索时，交互控件放在 role="img" 外面。
  • 悬停提示不能是唯一的数据入口，键盘和触摸用户也要能查看数据点。
  • 颜色不能是唯一编码，同时用线型、形状或直接标注区分系列。
  • 数据量大时，Canvas 或 WebGL 负责绘制，语义层只为当前选中项或可见区域维护少量节点；实时数据按时间窗口合并播报。

结构示例

HTML
<section aria-labelledby="sales-title">
  <h2 id="sales-title">本季度销售额趋势</h2>
  <p id="sales-summary">4 月至 6 月持续增长，6 月比 5 月增加 12%。</p>
  <div role="img" aria-labelledby="sales-title" aria-describedby="sales-summary">
    <canvas width="640" height="320"></canvas>
  </div>
  <details>
    <summary>查看详细数据</summary>
    <table>
      <caption>按月份统计的销售额（万元）</caption>
      <thead>
        <tr><th scope="col">月份</th><th scope="col">销售额</th></tr>
      </thead>
      <tbody>
        <tr><th scope="row">4 月</th><td>80</td></tr>
        <tr><th scope="row">5 月</th><td>92</td></tr>
        <tr><th scope="row">6 月</th><td>103</td></tr>
      </tbody>
    </table>
  </details>
</section>

不要把全部数据拼进一个超长的 aria-label，读屏用户无法定位。纯装饰的图表从无障碍树中隐藏即可。

SVG 可以用 <title> 和 <desc> 提供名称和描述，网格线、坐标轴等装饰元素加 aria-hidden="true"。

键盘探索

需要逐点查看时，可以这样设计（这是一种常见方案，不是 ARIA 规定的标准）：

  • Tab 进入图表的数据选择器。
  • 方向键在数据点或系列之间移动，Home/End 跳到首尾。
  • 选中点的详情显示在图表外的固定区域。
  • Escape 关闭浮层，焦点回到触发位置。

鼠标和键盘使用同一份数据模型确定"当前点"，不要从 Canvas 像素反推。数据点成千上万时，提供按区间跳转或搜索，不要求用户逐个按方向键。

颜色与对比

  • 系列之间用实线、虚线、不同标记形状区分，或在线条末端直接写系列名。
  • 文字与背景的对比度满足 WCAG 要求（正文 4.5:1），线条、图形等非文本元素与相邻颜色的对比度至少 3:1。
  • 细线、半透明区域、重叠的点在工具检查之外还要人工看一遍。

大数据量

层负责规模
绘制层Canvas 或 WebGL 画全部数据任意多
语义层摘要、当前选中点、图例按钮少量节点
数据表完整数据，分页或按需展开不一次性全部渲染

抽样显示时要说明抽样规则，避免抽样掩盖异常值。

实时数据和动画

  • 显示更新时间和是否暂停，提供暂停按钮。
  • live region 不要每帧播报，改为定期播报摘要，例如"过去 10 秒最高 120，当前呈上升趋势"。
  • 用户开启 prefers-reduced-motion: reduce 时减少或关闭过渡动画，直接显示最终状态。

常见追问

  • 自动化检查通过了，就算完成了吗？ 不算。读屏顺序、焦点移动、缩放和动态更新要用真实读屏软件测试。
  • 少量数据的图表用什么实现？ 几十个数据点、需要逐个操作时，用 SVG 或 HTML 更简单，元素可以直接获得焦点和名称。
