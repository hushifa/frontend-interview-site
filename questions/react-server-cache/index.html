React 的 cache API 解决什么问题？

理解 React cache 的请求级记忆化边界、服务端使用限制，以及它与浏览器缓存和数据请求库的区别。

参考答案

React 的 cache 用于记忆化函数调用结果，主要服务于 React 服务端渲染场景，让同一渲染请求中相同参数的读取可以复用结果。它不是一个跨请求、跨用户的永久缓存，也不等于 HTTP 缓存或数据库缓存。

在“React 的 cache API 解决什么问题？”这个问题中，先区分渲染、提交、事件和副作用，再确定状态的唯一来源；订阅、请求和定时器都要在生命周期结束时清理。这里的 React、cache、服务端渲染 不是孤立的 API 名称，而是会共同影响输入、过程和最终结果。

React 题目需要分清渲染阶段、提交阶段、事件处理和副作用。状态更新可能合并或排队，组件也可能重新渲染多次；不要把“函数执行了一次”直接等同于“页面只更新了一次”。

缓存函数的参数必须稳定，函数本身也要在模块作用域保持同一个引用；在组件中每次重新创建函数会失去复用效果。错误通常也会被记忆化，因此要明确失败是否应该在当前渲染中共享。

服务端缓存不能拿来保存用户私密数据而不区分请求边界。实际项目还要结合框架的数据缓存、失效策略和请求取消，核对当前 React 与框架版本的支持范围。

实际设计时先确定状态的唯一来源，再决定是局部状态、Context、外部 store 还是服务端数据。清理订阅、请求和定时器，并用目标 React 版本的文档核对新 API 的约束。

实际组件中，最难排查的通常不是某个 Hook 的语法，而是状态来源重复和副作用没有清理。把服务端数据、用户输入和派生显示值分开，组件会更容易测试，也不容易在重新渲染后产生重复请求。
