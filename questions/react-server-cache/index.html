React 的 cache API 解决什么问题？

React 的 cache 只在 Server Components 里用，让同一次服务端请求里、参数相同的函数调用只真正执行一次。请求结束缓存就没了，它不是跨请求的数据缓存。

参考答案

简答

服务端渲染一个页面时，头部要用户名，侧边栏要用户头像，两个组件各查一次数据库，就重复了。cache(fn) 返回一个带缓存的新函数，同一次服务端渲染里，参数相同的调用只执行一次 fn，后面直接复用结果。

它缓存的可以是返回值、Promise，也可以是抛出的错误。因为能缓存 Promise，还可以提前调用一次、不等待，让请求早点开始。

缓存的范围是一次请求，请求结束就失效，不会在不同用户或不同请求之间共享。它只能在 Server Components 里用，客户端组件要缓存值用 useMemo。

有两个容易犯的错。每调用一次 cache 就得到一个独立的缓存，所以要在模块顶层调用一次再导出，大家导入同一个函数。参数用 Object.is 比较，每次新建的对象参数永远命中不了。

两个组件读同一个用户

先在模块顶层用 cache 包好查询函数：

JavaScript
// lib/data.js
import { cache } from 'react';
import { db } from './db';

export const getUser = cache(async (id) => {
  return db.user.findUnique({ where: { id } });
});

页面里的两个组件都调用它：

JSX
// 页面中的两个组件都调用 getUser(id)
async function Header({ id }) {
  const user = await getUser(id);
  return <h1>{user.name}</h1>;
}

async function Sidebar({ id }) {
  const user = await getUser(id);
  return <img src={user.avatar} alt="" />;
}

一次请求里，Header 先调 getUser(id)，真正查了数据库。Sidebar 再用同样的 id 调用时，直接拿到第一次的结果，只查了一次。下一个请求进来，缓存已经清空，会重新查。

这样组件各自取自己要的数据就行，不用在顶层查好再一层层往下传。

为什么会命中不了

下面两种写法看起来用了 cache，其实一次都没缓存上：

JSX
// 错误：在组件内调用 cache，每次渲染都生成新的缓存函数
async function Header({ id }) {
  const getUserCached = cache(getUserFromDb);
  const user = await getUserCached(id);
  // ...
}

// 错误：对象参数每次都是新引用，不会命中
getProduct({ id: 1 });
getProduct({ id: 1 });

第一种，cache 每调用一次就新建一个缓存。写在组件里，每次渲染都是一个新缓存，别的组件也拿不到它，等于没缓存。

第二种，缓存按参数是否 Object.is 相等来判断。两次 { id: 1 } 内容一样，但是两个不同的对象，所以被当成不同的参数。

改法是把 cache 挪到模块顶层，参数改成基本类型，比如 getProduct(1)。

提前开始请求

因为缓存的是 Promise，可以先调用、不 await，让请求在后台先跑起来：

JSX
async function Page({ id }) {
  getUser(id); // 立即开始请求
  const posts = await getPosts(id);
  const user = await getUser(id); // 复用上面的 Promise
  // ...
}

等 getPosts 的时候，用户数据也在同时加载。后面 await getUser(id) 拿到的是同一个 Promise，不会再发一次请求。

取消用不上的请求

React 19.2 新增了 cacheSignal()。它在 Server Components 里返回一个 AbortSignal，这次渲染完成、中止或失败时会触发。把它传给 fetch，就能取消已经用不上的请求：

JavaScript
import { cache, cacheSignal } from 'react';

const getData = cache((url) => fetch(url, { signal: cacheSignal() }));

和框架的缓存是什么关系

cache 只做一次请求内的去重。跨请求的数据缓存、按时间或按标签失效，是框架提供的功能，例如 Next.js 的 'use cache'、cacheLife、cacheTag。详见《Next.js App Router 中的几层缓存怎样区分？》。

常见追问

和 useMemo 有什么区别？

useMemo 在客户端，缓存的是一个组件实例在多次渲染之间的一个值。cache 在服务端，让一次请求里的多个组件共享同一个函数的结果。

缓存了错误怎么办？

同一次请求里再调用，会拿到同一个错误。下一个请求会重新执行，不受影响。
