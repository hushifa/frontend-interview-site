Vue 3 响应式依赖是怎样收集和触发的？

Vue 3 用 Proxy 拦住属性的读和写。函数执行时读了哪些属性，就记下"这个函数依赖它们"；属性被改时，再把依赖它的函数重新执行一遍。

参考答案

简答

reactive 返回的是一个 Proxy，也就是给原对象套了一层“拦截器”，读属性和写属性都会先经过它。读的时候调用 track，记下“当前正在运行的函数依赖这个属性”；写的时候调用 trigger，把依赖这个属性的函数找出来重新执行。

这些“会被重新执行的函数”在 Vue 里叫 effect，包括组件的渲染函数、computed 的 getter、watch 和 watchEffect。

依赖是按实际读到的属性记录的，不是按整个对象。而且每次 effect 重新执行都会重新收集一遍，所以条件分支切换后不再读的属性，以后改了也不会再触发它。只有在 effect 同步执行期间读到的才算，await 之后或者 setTimeout 回调里读的都不会被追踪。

组件的渲染 effect 被触发后不会马上重新渲染，而是放进队列，在同一轮微任务里批量处理，同一个组件只渲染一次。

自己写一个最小版本

先看一个几十行的简化实现，把 track、trigger 和 effect 的关系跑通：

JavaScript
let activeEffect = null;
const targetMap = new WeakMap(); // target -> key -> Set<effect>

function track(target, key) {
  if (!activeEffect) return;
  let deps = targetMap.get(target);
  if (!deps) targetMap.set(target, (deps = new Map()));
  let dep = deps.get(key);
  if (!dep) deps.set(key, (dep = new Set()));
  dep.add(activeEffect);
}

function trigger(target, key) {
  targetMap.get(target)?.get(key)?.forEach((effect) => effect());
}

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      track(target, key);
      return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
      const result = Reflect.set(target, key, value, receiver);
      trigger(target, key);
      return result;
    },
  });
}

function effect(fn) {
  const run = () => {
    activeEffect = run;
    try { fn(); } finally { activeEffect = null; }
  };
  run();
}

const state = reactive({ count: 0 });
effect(() => console.log('count =', state.count)); // count = 0
state.count++; // count = 1

effect 里的函数并没有说“我依赖 count”，Vue 是怎么知道的？关键在 activeEffect。effect 执行函数之前，先把自己登记为“当前正在运行的 effect”。函数里一读 state.count，就进了 Proxy 的 get，track 看到当前有 effect 在运行，就把它记到 count 名下。

之后 state.count++ 进了 set，trigger 找到 count 名下的那个 effect，重新执行一遍，于是打印出 count = 1。

依赖存在 targetMap 里，结构是“对象 → 属性名 → 依赖它的 effect 集合”。真实实现还处理了很多情况：嵌套对象用到时才代理、数组方法、Map/Set、清理旧依赖、避免 effect 触发自己等。

依赖会随分支变化

JavaScript
const state = reactive({ showName: true, name: 'Lin', id: 1 });
watchEffect(() => {
  console.log(state.showName ? state.name : state.id);
});

state.showName = false; // 输出 1，此后依赖 showName 和 id
state.name = 'Chen'; // 不再触发

第一次执行时 showName 是 true，函数读了 showName 和 name。把 showName 改成 false 以后，函数重新执行，这次读的是 showName 和 id，没有读 name。因为每次执行都会重新收集依赖，name 就不在依赖里了，之后改 name 不会再触发这个 effect。上面的简化版没有做这一步清理，真实的 Vue 做了。

改了三次，为什么只渲染一次

JavaScript
state.count++;
state.count++;
state.count++;

组件只会重新渲染一次。因为组件的更新任务不会立刻执行，而是放进队列，在微任务里统一处理，同一个组件在队列里只会出现一次。这也意味着改完数据立刻去读 DOM，拿到的还是旧内容，需要 await nextTick()，见《修改状态后，为什么有时需要 await nextTick()？》。

和 Vue 2 有什么不同

Vue 2 在初始化时用 Object.defineProperty 遍历对象的每个已有属性，所以新增属性、删除属性和数组下标赋值都检测不到，需要 Vue.set。Vue 3 的 Proxy 拦截的是整个对象，嵌套对象也是访问到时才转换，这些限制都没有了。

常见追问

为什么用 WeakMap 存依赖？

WeakMap 的键是弱引用。原始对象不再被别处引用时，它对应的依赖记录可以跟着被垃圾回收，不会因为存了依赖就一直留在内存里。

怎么调试依赖？

computed 和 watch 有 onTrack、onTrigger 选项，在开发环境中会告诉你收集了哪些依赖、是哪个属性触发了更新。
