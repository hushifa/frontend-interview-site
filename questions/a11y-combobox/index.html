可访问的 Combobox 需要哪些键盘和 ARIA 行为？

可编辑 Combobox 是带 role="combobox" 的输入框加一个 listbox 弹层；焦点始终留在输入框，用 aria-activedescendant 指示当前候选，方向键浏览、Enter 确认、Esc 关闭。能用原生 select 或 datalist 时优先用原生。

参考答案

简答

  • 只从固定选项中选择时用原生 <select>，不必手写 Combobox。
  • 输入框设置 role="combobox"、aria-expanded、aria-controls（指向列表）、aria-autocomplete="list"；列表是 role="listbox"，每项是 role="option"。
  • DOM 焦点留在输入框，用 aria-activedescendant 指向当前高亮的选项 ID，用户可以边浏览边继续打字。
  • 键盘：↓/↑ 打开并移动候选，Enter 确认，Esc 关闭（再按一次可清空），Tab 离开时不把每个选项都放进 Tab 顺序。
  • 输入的文字、高亮的候选、最终提交的值是三个不同的状态，异步结果返回时要丢弃过期请求。

结构

HTML
<label for="city">城市</label>
<input
  id="city"
  role="combobox"
  aria-expanded="true"
  aria-controls="city-list"
  aria-autocomplete="list"
  aria-activedescendant="city-bj"
  autocomplete="off"
>
<ul id="city-list" role="listbox" aria-label="城市">
  <li id="city-bj" role="option" aria-selected="true">北京</li>
  <li id="city-sh" role="option" aria-selected="false">上海</li>
</ul>
<p role="status" class="visually-hidden">2 个结果</p>

列表关闭时要真正隐藏（hidden），并移除 aria-activedescendant；高亮项被过滤掉后，也要清除它，不能指向不存在的节点。

三种状态

用户之前选了“上海”，现在输入“北”，按 ↓ 高亮“北京”：

  • 输入文本：“北”，用来过滤。
  • 活动候选：北京，只是浏览中。
  • 已选值：仍是上海，直到按 Enter 或点击才变成北京。

只存一个字符串会导致：方向键覆盖了用户的输入、Esc 无法恢复、慢请求返回的旧候选被当成选择。

容易出错的细节

  • 中文输入法组合时按 Enter 是确认拼音，判断 event.isComposing，组合中不要提交候选。
  • 不要拦截左右键、Home、End，它们在输入框里用于移动光标。
  • 输入框失焦时立即关闭列表，会让鼠标点击选项的 click 来不及触发。可以在选项上监听 pointerdown 并 preventDefault()，保持焦点在输入框。
  • 结果数量变化时用 role="status" 的区域简短播报，“加载中”“无结果”不要做成可选择的 option。
  • 候选文字用 textContent 插入，接口返回的内容不要当作 HTML。

和 datalist 的区别

<datalist> 能提供原生建议列表，但样式不能定制，不同浏览器的过滤和读屏行为也不一致。需要高亮匹配、分组、异步加载时，才值得自己实现，或者使用经过测试的组件库。

常见追问

  • 列表很长要虚拟滚动怎么办？aria-activedescendant 指向的节点必须在 DOM 中，滚动时不能卸载当前活动项，并给选项加 aria-setsize 和 aria-posinset 说明总数和位置。
