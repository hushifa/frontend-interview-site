可访问的 Combobox 需要哪些键盘和 ARIA 行为？

从输入框、列表框、展开状态和活动选项说明自定义下拉搜索控件的可访问实现边界。

参考答案

Combobox 不是给输入框加一个 role 就完成了。控件要表达展开状态、关联的 popup 和当前活动选项；键盘用户需要能打开、移动、选择、取消并关闭列表，焦点行为要稳定，选中值要回到输入控件。

如果使用 aria-activedescendant，被引用的活动元素必须存在且 ID 稳定；如果把焦点移动到列表项，则要处理返回输入框、Escape 和 Tab 的行为。过滤结果变化时，不应让焦点跳到不可见或已删除的元素。

原生 select 能满足需求时优先使用原生控件。自定义组件还需要测试屏幕阅读器、键盘、触摸和鼠标交互，不能只看视觉效果或自动化属性快照。

验收标准

无障碍实现要围绕任务是否能完成来验收：名称是否清楚、键盘顺序是否合理、焦点是否可见且能恢复、状态变化是否能被辅助技术感知。原生控件能提供的行为优先交给 HTML，ARIA 只补充原生语义无法表达的部分。

测试至少覆盖初始状态、展开或提交后的状态、错误状态和关闭后的焦点位置。自动化规则可以发现部分属性问题，但不能替代键盘、缩放和屏幕阅读器体验。
