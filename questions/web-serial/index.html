Web Serial API 适合怎样的硬件交互？

Web Serial 让网页通过串口和开发板、扫码枪、工控设备通信，数据用 Streams 读写。只有 Chromium 桌面浏览器支持，要在 HTTPS 页面里由用户点击后选择端口。

参考答案

简答

给 Arduino 开发板写配置、读传感器数据，以前要装一个桌面程序，现在网页用 Web Serial 就能直接和串口设备通信。用户点击按钮后，navigator.serial.requestPort() 弹出端口选择框，选好以后 port.open({ baudRate }) 打开连接。

读写都通过流：port.readable 和 port.writable 是字节流，读写的都是 Uint8Array。用户授权过的端口，下次可以用 navigator.serial.getPorts() 取回，不用每次重新选。

要注意两点。一是串口数据会被拆成任意大小的块，要自己按换行或协议的帧格式拼起来。二是关闭顺序，用了管道以后流是锁着的，顺序不对 close() 会失败。

它只有 Chromium 桌面浏览器支持，Firefox、Safari 不支持，Android 上支持有限。所以适合内部工具，比如给开发板烧录配置、连接 POS 和工业设备。

连接、读取和发送

下面连接一个 Arduino（厂商 ID 是 0x2341），按行读取数据，并能发送文本。

JavaScript
async function connect() {
  const port = await navigator.serial.requestPort({ filters: [{ usbVendorId: 0x2341 }] });
  await port.open({ baudRate: 115200 });
  return port;
}

async function readLines(port, onLine) {
  const decoder = new TextDecoderStream();
  // pipeTo 会锁住 port.readable，关闭时要等这个 Promise 结束
  const piped = port.readable.pipeTo(decoder.writable).catch(() => {});
  const reader = decoder.readable.getReader();
  port.stop = async () => {
    await reader.cancel();
    await piped;
    await port.close();
  };
  let buffer = '';
  try {
    while (true) {
      const { value, done } = await reader.read();
      if (done) break;
      buffer += value;
      const lines = buffer.split('\n');
      buffer = lines.pop();
      lines.forEach(onLine);
    }
  } finally {
    reader.releaseLock();
  }
}

async function send(port, text) {
  const writer = port.writable.getWriter();
  await writer.write(new TextEncoder().encode(text));
  writer.releaseLock();
}

filters 只让选择框显示这个厂商的设备，用户不容易选错。baudRate 是波特率，要和设备那边的设置一致，否则读到的是乱码。

为什么要自己拼行？设备发了一行“温度 25”，网页可能分两次收到“温”和“度 25”。所以用 buffer 攒着，按换行切开，最后一段可能不完整，留到下一块再拼。

为什么关闭顺序很重要

pipeTo 把 port.readable 接到解码器上，这时 port.readable 是锁定状态。端口在流被锁住时不能关闭。

所以 port.stop 按三步走：先 reader.cancel() 结束读取；再等 pipeTo 的 Promise 结束，锁随之释放；最后才调用 port.close()。顺序不对，close() 会因为流被锁定而失败。

设备被拔掉怎么办

监听 disconnect 事件：

JavaScript
navigator.serial.addEventListener('disconnect', (event) => {
  if (event.target === currentPort) showDisconnected();
});

设备被拔掉时，读取循环会抛错或者结束。界面要恢复到可以重新连接的状态。

常见追问

面向普通用户的产品能用 Web Serial 吗？

要慎重。它只在 Chromium 桌面浏览器里能用，用 Safari、Firefox 或手机的用户都用不了。面向大众的产品要准备原生客户端或配套程序，并告诉用户需要用哪个浏览器。

每次打开页面都要重新选择端口吗？

不用。用户授权过的端口，可以用 navigator.serial.getPorts() 直接取回来，再调用 open() 就能连接。
