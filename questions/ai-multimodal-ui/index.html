多模态 AI 前端界面需要怎样管理附件状态？

图片、音频和文档从选择到模型可用要经过本地预览、上传、服务端扫描与解析。每个附件独立建模状态，区分本地预览和模型实际收到的内容，并正确释放预览 URL 和媒体轨道。

参考答案

简答

  • 上传完成之后，服务端通常还要扫描、转码、提取文字，完成后模型才能使用附件。
  • 每个附件是独立任务，有自己的 ID 和状态（本地、上传中、处理中、就绪、失败），多附件时允许部分失败。
  • 本地预览是原文件，模型收到的可能是缩放、裁剪或只提取了部分页面的版本，重要的转换要告诉用户。
  • 用 URL.createObjectURL 生成的预览不再使用时要 revokeObjectURL；麦克风和摄像头的 track 要 stop()。
  • 移除附件后，旧任务的迟到结果要按附件 ID 和版本丢弃。

附件状态

TypeScript
type Attachment = {
  id: string;
  name: string;
  phase: 'local' | 'uploading' | 'processing' | 'ready' | 'failed';
  progress?: number;
  serverFileId?: string;
  error?: string;
};

async function prepareFile(file: File, update: (a: Attachment) => void) {
  let current: Attachment = { id: crypto.randomUUID(), name: file.name, phase: 'local' };
  update(current);

  try {
    current = { ...current, phase: 'uploading', progress: 0 };
    update(current);
    const uploaded = await uploadFile(file, (progress) => update({ ...current, progress }));

    current = { ...current, phase: 'processing', serverFileId: uploaded.id };
    update(current);
    await waitUntilParsed(uploaded.id);

    current = { ...current, phase: 'ready' };
    update(current);
  } catch (error) {
    // current 里保留了 serverFileId，失败后服务端可以据此清理文件
    update({ ...current, phase: 'failed', error: getErrorMessage(error) });
  }
}

current 始终保存最新状态，失败时不会丢掉已经拿到的 serverFileId。

发送按钮的规则要事先定好：等全部附件就绪才能发送，还是允许先发文字、附件在后台处理。未就绪的附件不能被悄悄丢掉。

预览与实际输入

  • 服务端可能为了尺寸和成本缩小图片，PDF 只处理前若干页，扫描件可能提取不到文字。界面上注明"已压缩到 xx 像素""仅分析前 20 页"。
  • 文件扩展名和 MIME 只用于提示，服务端要验证真实格式和大小，预览不能把上传内容当成 HTML 或脚本执行。

取消、移除与恢复

  • 取消上传、取消服务端解析、停止模型生成是不同的操作，分别处理。
  • 用户移除附件后，原来的上传可能仍然返回成功。事件带附件 ID，前端发现附件已移除就丢弃结果，并通知服务端清理。
  • 刷新页面后，从服务端查询处理状态，不要根据本地的 loading 推测。

常见追问

  • 重试上传会不会产生重复文件？ 可能。用上传会话 ID 或幂等键，让服务端识别同一个文件。
  • 没有麦克风权限怎么办？ 提供文字输入作为替代，音频输出也提供文字版本。
