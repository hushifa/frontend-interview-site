React面试题

React 面试题，涵盖 Hooks、useEffect、状态更新、组件渲染、key、Context、受控组件、Suspense、useMemo 和并发更新，复习组件开发与性能优化。共 22 道题。

  • 为什么调用 setState 后，当前变量还是旧值？

    每次渲染得到的是当前状态快照，setter 排队的是下一次状态更新，不会修改已经执行中的局部变量。替换值和函数式更新具有不同的队列含义，批处理也不等于 JavaScript 变量被异步赋值。

  • useEffect 的依赖数组和清理函数应该怎么写？

    Effect 用来让已提交的组件与外部系统同步，依赖描述同步过程读取的响应式值，清理结束上一轮同步。它不是所有计算和用户动作的默认容器，也不能靠删依赖来避免重新执行。

  • 列表中的 key 为什么不能随意使用数组下标？

    key 参与 React 对同级元素身份的识别，影响本地状态和 DOM 是否保留。下标标识的是位置，稳定 ID 标识的是记录；重排、插入或删除时，这个差别会直接影响草稿、焦点和 Effect 生命周期。

  • memo、useMemo、useCallback 各自优化什么？

    memo 尝试跳过某些父级引起的子组件计算，useMemo 复用计算结果，useCallback 复用函数身份。它们依赖正确的比较与依赖关系，不负责修复状态逻辑，也不能保证组件永远不重新渲染。

  • React 的渲染阶段与提交阶段有什么区别？

    渲染计算下一份 UI，提交把最终选择的变化应用到 DOM 等宿主环境。组件函数被调用不代表 DOM 全部重建，也不代表这次计算一定被提交；副作用必须放在合适的阶段。

  • 为什么 Hook 通常必须在组件顶层调用？

    useState、useEffect 等 Hook 需要稳定的调用结构，让 React 把不同渲染中的状态与对应位置关联。条件应放在 Hook 内部逻辑或组件边界上，自定义 Hook 复用逻辑但不自动共享实例状态，use API 的例外也有自身限制。

  • React 中的过期闭包为什么会读到旧状态？

    回调会保留创建它的那次渲染环境，后续渲染不会自动替换已注册的旧函数。修复应先明确需要旧快照、最新状态还是重新同步，再选择函数式更新、正确依赖、Effect Event 或受控的可变引用。

  • Context 与 useReducer 适合管理什么状态？

    Context 负责把某个范围内的值提供给后代，useReducer 负责集中计算状态如何随动作变化。它们可以组合，但 Context 不自动存储数据，reducer 不执行副作用，也不天然等于全局缓存或高性能状态库。

  • useRef、useEffect 和 useLayoutEffect 有什么差别？

    useRef 保存跨渲染的可变引用，不负责触发界面更新；Effect 与 Layout Effect 则安排外部同步，后者会在绘制前执行并阻塞绘制。是否需要测量与同步视觉修正，决定应该采用哪种时机。

  • useTransition 和 useDeferredValue 能优化哪些卡顿？

    Transition 标记可以让步的更新，useDeferredValue 提供某个值的可滞后版本，让紧急交互先反馈。它们调整渲染调度，不自动防抖请求、不减少所有计算，也不能抢占任意长同步函数。

  • Error Boundary 和 Suspense 分别处理什么？

    Error Boundary 为后代的相关错误提供恢复界面，Suspense 为支持其协议的等待提供加载回退。失败、等待和空数据是不同状态，边界范围、重试条件及服务端行为都需要明确设计。

  • 受控组件与非受控组件应该如何选择？

    受控输入由 React 提供当前 value 或 checked，非受控输入把当前编辑值留给 DOM。选择应围绕实时联动、提交读取和生命周期，defaultValue、重置、文件输入与输入法行为也需要分别理解。

  • useActionState 如何把异步 Action 的结果变成组件状态？

    useActionState 把一次次 Action 的返回结果接到 React 状态上，并提供对应的 pending 信息。处理函数接收前一次结果和本次载荷，正常调用按队列关联，但请求、校验、异常与服务端能力仍需各自实现。

  • useOptimistic 的临时状态怎样与真实结果收敛？

    useOptimistic 在 Action 进行期间把临时更新叠加到当前确认值上，Action 结束后仍以传入的真实值为依据。成功要更新确认数据，失败要恢复并说明原因，临时显示不能代替服务端一致性。

  • useSyncExternalStore 为什么要求稳定的快照？

    useSyncExternalStore 把外部数据源的订阅与 React 渲染协调起来，getSnapshot 应在数据未变时返回同一快照。通知、不可变快照、订阅清理和服务端初始数据分别承担不同责任，不能用一个始终新建的对象替代协议。

  • React 的 cache API 解决什么问题？

    React cache 为 Server Components 请求上下文中的函数调用提供结果复用，稳定的被缓存函数与匹配参数可以共享值、Promise 或失败。它不是普通客户端记忆化函数，也不提供跨请求持久缓存、TTL 或自动失效策略。

  • React useEffectEvent 适合解决什么依赖问题？

    Effect Event 把 Effect 内不需要重新建立外部关系的事件逻辑分离出来，在调用时读取最新渲染值。它不能隐藏真正的同步依赖，也不是可随意传给按钮、子组件或其他 Hook 的 useCallback 替代品。

  • React use API 可以读取哪些值？

    use 在渲染中读取 React 支持的资源，常见的是 Promise 与 Context；当前 React DOM 还提供浏览器专属渲染资源。它配合 Suspense 和错误边界工作，不是对任意值或普通异步函数的自动缓存器。

  • React Server Functions/Actions 的边界是什么？

    Server Function 是由支持环境提供远程调用引用的服务端异步函数，不是把任意前端函数自动搬到服务器。序列化、认证授权、数据变更与缓存刷新都有独立边界，框架的构建和运行时支持不可省略。

  • React Compiler 解决了哪些优化问题？

    React Compiler 在构建阶段分析符合 React 规则的组件与 Hook，自动添加适用的记忆化，减少重复计算和不必要渲染。它不是运行时开关，也不替代请求、布局、状态边界与真实性能测量。

  • React useFormStatus 适合管理什么表单状态？

    useFormStatus 让表单后代读取最近父级 form 的提交状态，而不是创建一份全局 loading。它适合通用提交按钮和提交中提示，结果状态、业务错误与请求取消仍需要相应逻辑。

  • React useId 解决什么 ID 生成问题？

    useId 为组件内部的可访问关联生成实例级 ID，并在匹配的服务端与客户端树中支持 hydration 一致性。它不提供业务实体身份，不适合作为列表 key 或持久化标识，多根应用还需要协调前缀。
