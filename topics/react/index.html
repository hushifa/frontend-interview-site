React面试题

React 面试题，涵盖 Hooks、useEffect、状态更新、组件渲染、key、Context、受控组件、Suspense、useMemo 和并发更新，复习组件开发与性能优化。共 45 道题。

  • 为什么调用 setState 后，当前变量还是旧值？

    每次渲染拿到的 state 是一份快照，调用 setter 只是预约下一次渲染，当前这次的变量不会变。直接传值和传函数在排队时含义不同。

  • React 的批量更新是什么？React 18 的自动批处理改变了什么？

    React 不会每调用一次 setState 就重新渲染，而是等当前事件里的代码跑完，把这期间的所有更新合并成一次渲染。React 18 之前只在 React 事件处理函数里合并，setTimeout、Promise 里每次 setState 都单独渲染；React 18 用 createRoot 后，所有地方的更新都会自动合并。需要立刻更新 DOM 时可以用 flushSync。

  • 为什么 Hook 通常必须在组件顶层调用？

    React 不认 Hook 的名字，只按调用顺序把每个 Hook 对应到它保存的状态。放进条件、循环或写在提前 return 后面，顺序一乱，状态就对错了。use 是唯一可以条件调用的例外。

  • Hooks 在 React 内部是怎样保存状态的？为什么靠调用顺序区分？

    React 为每个组件保存一组 Hook 的数据，渲染前把位置归零，每调用一次 Hook 就取下一格。useState 调用时不传名字，所以 React 只能按调用顺序把数据对上，条件里调用 Hook 会让后面的数据全部错位。

  • useMemo 和 useCallback 有什么区别？什么时候不该用？

    useMemo 调用你传的函数并缓存它的返回值，useCallback 不调用函数，直接缓存函数本身，useCallback(fn, deps) 等价于 useMemo(() => fn, deps)。只有计算明显很慢、要传给 memo 组件或者要当其他 Hook 的依赖时才有用；启用 React Compiler 后，新代码一般交给编译器，手写的只作为精确控制的手段。

  • React 中的受控组件和非受控组件是什么？

    受控和非受控说的是“重要的状态由谁决定”。受控组件的值由父组件通过 props 决定，比如带 value 和 onChange 的 input；非受控组件自己保存状态，父组件只能给初值，比如只写 defaultValue 的 input。受控更灵活，非受控更省事，同一个输入框不能在两者之间切换。

  • useRef 有哪些用途？它和 useState 有什么区别？

    useRef 返回一个在组件整个生命周期里都是同一个的 { current } 对象，改 current 不会触发重新渲染，适合保存定时器 ID、DOM 节点等不参与显示的值。useState 的值每次渲染是一份快照，改它要调用 setter 并触发渲染。渲染期间不要读写 ref.current（惰性初始化除外）；React 19 中函数组件可以直接把 ref 当作 prop 接收。

  • useReducer 什么时候比 useState 更合适？

    一个组件里有多个事件用相似的方式改同一份状态、或者下一个状态要根据多个字段一起算时，把更新逻辑集中到 reducer(state, action) 里，事件处理器只 dispatch 一个描述“发生了什么”的动作，代码更好读、好调试，reducer 还能单独测试。状态简单时 useState 代码更少，两者可以互相转换，也能在同一组件里混用。

  • useEffect 的依赖数组和清理函数应该怎么写？

    Effect 用来让组件和外部系统（订阅、定时器、网络连接）保持同步。依赖数组要写全 Effect 里用到的值，清理函数负责撤掉上一轮的同步。能在渲染时算出来的值、由用户点击触发的逻辑，都不该放进 Effect。

  • 函数组件和类组件有什么区别？

    类组件继承 Component，用 this.state、setState 和生命周期方法；函数组件就是返回 JSX 的函数，用 Hooks 管理状态和副作用。函数组件每次渲染拿到的是那一次的 props 和 state，类组件通过 this 读到的是实例上的当前值。React 推荐新代码用函数组件，类组件仍受支持，错误边界目前还要用类写。

  • 自定义 Hook 怎样设计？useRequest、usePrevious、useInterval 该怎么写？

    自定义 Hook 是名字以 use 加大写字母开头、内部调用了其他 Hook 的函数，用来复用有状态的逻辑，每个调用方各有一份独立状态。设计时名字要说清用途，参数里的响应式值写进 Effect 依赖，请求要在清理函数里忽略过期结果，定时器要在清理函数里清除，传进来的回调用 useEffectEvent 包起来，不要写 useMount 这类生命周期包装。

  • React 中的过期闭包为什么会读到旧状态？

    每次渲染创建的函数，记住的都是那一次渲染的 props 和 state。函数被定时器、订阅或依赖不全的 Effect 留下来，以后再调用时读到的还是当时的旧值。改法看需求：函数式更新、补全依赖、useEffectEvent 或 ref。

  • React Router 的原理是什么？怎样做路由守卫和懒加载？

    React Router 监听浏览器地址变化，把当前 URL 和路由配置逐层匹配，再把匹配到的组件按嵌套关系渲染出来，子路由通过 Outlet 显示。本文以 React Router v8（8.5.1）文档为准：它有声明式、数据和框架三种模式；数据模式下可以在 middleware 或 loader 里 throw redirect 做路由守卫，用路由对象的 lazy 属性按需加载组件和 loader。

  • Portal、forwardRef 和 useImperativeHandle 分别解决什么问题？

    createPortal 把子组件渲染到另一个 DOM 节点里，常用于弹窗和浮层，但它在 React 树里的位置不变，context 照常读取，事件按 React 树冒泡。forwardRef 让函数组件把 ref 转给内部的 DOM；React 19 起 ref 可以直接作为 prop 传，forwardRef 不再需要，将在未来版本弃用。useImperativeHandle 让组件只向父组件暴露自定义的几个方法，而不是整个 DOM 节点。

  • React 严格模式为什么会让组件渲染两次、Effect 执行两次？

    开发环境下，StrictMode 会把应该是纯函数的代码多调用一次，包括组件函数体、useState、useMemo、useReducer 的初始化和更新函数，还会给每个 Effect 和回调 ref 多跑一轮 setup 加 cleanup。目的是让不纯的渲染和漏写清理的 Effect 尽早暴露。这些检查只在开发环境运行，不影响生产构建。

  • useContext 怎样用？什么时候该用 Context 而不是 props？

    用 createContext 创建 Context 并给出默认值，在上层用 <SomeContext value={...}> 提供值（React 19 之前写 SomeContext.Provider），下层组件调用 useContext 读取离它最近的那个 Provider 的值，找不到 Provider 时才用默认值。Context 适合主题、语言、登录用户这类很多层都要用的数据；层级不深时先传 props 或用 children 减少层级。

  • React Context 有哪些性能问题？怎样避免不必要的重新渲染？

    Provider 的 value 用 Object.is 比较出变化后，所有读这个 Context 的组件都会重新渲染，memo 也挡不住，React 不会只通知用到某个字段的组件。常见改法是用 useMemo、useCallback 稳定 value，按变化频率拆分 Context，把 state 和 dispatch 放进两个 Context；高频数据改放外部 store，用 useSyncExternalStore 让组件只订阅自己用到的那一部分。

  • 列表中的 key 为什么不能随意使用数组下标？

    key 告诉 React 列表里每一项"是谁"，React 靠它决定复用还是重建组件。下标只代表位置，列表一插入、删除或排序，组件里的状态就会跑到别的数据上。

  • React.memo 怎样跳过组件渲染？什么情况下会失效？

    memo 包住的组件在父组件重新渲染时，会把新旧 props 逐个用 Object.is 浅比较，全都相同就跳过渲染。对象、函数、JSX children 每次渲染都是新引用，会让比较失败，需要让 props 引用保持稳定；也可以传第二个参数自定义比较。组件自己的 state 或它读的 Context 变化时，memo 拦不住。

  • React 的虚拟 DOM 是什么？Fiber 解决了什么问题？

    React 组件返回的是描述界面的 JS 对象，更新时拿新旧两份描述比较，只把差异改到真实 DOM 上。Fiber 是 React 16 的新协调器，它把每个组件对应成一个用 child、sibling、return 指针连起来的 fiber 节点，遍历从递归改成循环，渲染工作就能拆成小单元暂停、继续，并按优先级调度。

  • React 的 diff 算法怎样处理单节点和多节点？key 起什么作用？和 Vue 有什么不同？

    React 只比较同一层的节点，类型不同就整棵替换。单节点时按 key 和类型在旧子节点里找能复用的；多节点时先从左往右按位置比，遇到 key 对不上就把剩下的旧节点放进 Map，按 key 查找，并用 lastPlacedIndex 判断谁需要移动。Fiber 没有反向指针，所以 React 不做双端比较；Vue 3 从两端同步，再用最长递增子序列减少移动。

  • React 应用有哪些常见的性能优化手段？

    先用 Profiler 找到慢在哪里，再按三类处理：减少渲染次数（状态下放、children 传 JSX、memo、稳定的 key），减少每次渲染的成本（useMemo、虚拟列表、useTransition），减少加载体积（lazy 和 Suspense 按需加载）。启用 React Compiler 后，大部分手写的记忆化可以交给编译器。

  • React 的渲染阶段与提交阶段有什么区别？

    渲染阶段是 React 调用组件函数，算出界面应该变成什么样；提交阶段是把算出来的差异真正改到 DOM 上，再执行 Effect。渲染可能被打断、重来或丢弃，所以组件函数里只能做纯计算。

  • React 的合成事件是什么？和原生事件有什么区别？

    React 给事件处理函数传的是包装过的事件对象，接口和原生事件一致，原生事件在 e.nativeEvent 上。React 17 起事件监听挂在根容器上而不是 document，并去掉了事件池。onScroll 不冒泡，onChange 每次输入都触发，和原生 change 不同。

  • React 类组件有哪些生命周期？在函数组件里怎样对应？

    挂载时依次调用 constructor、getDerivedStateFromProps、render、componentDidMount；更新时调用 getDerivedStateFromProps、shouldComponentUpdate、render、getSnapshotBeforeUpdate、componentDidUpdate；卸载时调用 componentWillUnmount。函数组件里，componentDidMount、componentDidUpdate 和 componentWillUnmount 组合起来大致对应 useEffect，shouldComponentUpdate 对应 memo，错误边界目前仍只能用类组件写。

  • 高阶组件、Render Props 和自定义 Hook 怎样选择？

    三者都用来复用组件逻辑。高阶组件是接收组件、返回新组件的函数；Render Props 是把“怎么渲染”作为函数 prop 传进去；自定义 Hook 把有状态的逻辑抽成以 use 开头的函数，不增加组件层级。新代码复用逻辑首选自定义 Hook，Render Props 适合把渲染权交给使用方，高阶组件主要出现在老代码和部分库里。

  • useEffect 和 useLayoutEffect 在什么时候执行？测量 DOM 为什么要用 useLayoutEffect？

    两者都在 React 把改动提交到 DOM 之后执行，区别在和浏览器绘制的先后。useLayoutEffect 在绘制前同步执行，里面安排的状态更新也在绘制前处理完，适合先测量再定位；代价是会推迟绘制。useEffect 通常在绘制后执行，但由点击等交互触发的更新，它可能在绘制前执行。Effect 只在客户端运行，服务端没有布局信息。

  • Context 与 useReducer 适合管理什么状态？

    Context 让深层组件不用层层传 props 就能拿到数据，useReducer 把所有改状态的逻辑集中到一个函数里。两个合起来能管中小规模的共享状态，但 Context 一变所有读它的组件都会重新渲染，变化频繁的全局状态更适合用状态库。

  • React 里复杂表单怎样组织？校验、提交状态和错误怎么处理？

    字段多的表单先决定状态放哪里：只在提交时要值的字段用非受控加 FormData，要联动或实时校验的字段才用受控。受控字段用一个对象 state 统一管理，能从已有值算出来的结果在渲染时计算，不另存 state。React 19 的 form action 配合 useActionState 拿到提交结果和 isPending，抛出的错误交给 Error Boundary。中文输入法组合期间不要改写输入框的值。

  • Error Boundary 和 Suspense 分别处理什么？

    Error Boundary 管"出错了"，子组件渲染时抛错就显示备用界面；Suspense 管"还在等"，代码或数据没到就显示加载提示。两者常一起包在一块异步区域外面。

  • useTransition 和 useDeferredValue 能优化哪些卡顿？

    两者都是让 React 先处理打字、点击这类着急的更新，把渲染很慢的部分往后放、还能随时打断。它们只调整渲染的先后，拆不开单个很慢的同步函数，也不会减少网络请求。

  • useSyncExternalStore 为什么要求稳定的快照？

    useSyncExternalStore 用来把 React 之外的数据（浏览器状态、自己写的 store）接进组件。React 靠比较前后两次读到的值是不是同一个来决定要不要更新，所以数据没变时必须返回同一个引用，否则会无限渲染。

  • React use API 可以读取哪些值？

    use 可以在渲染时读 Promise 或 Context。Promise 还没完成时组件进入等待，由外层 Suspense 显示加载提示，失败交给 Error Boundary。它能写在 if 里，但传进去的 Promise 必须缓存，不能在渲染时新建。

  • React Compiler 解决了哪些优化问题？

    React Compiler 在打包时自动给组件加上缓存，相当于替你写好 memo、useMemo、useCallback。它只处理遵守 React 规则的代码，管不了渲染内容太多、接口太慢这类问题。

  • React useId 解决什么 ID 生成问题？

    useId 给每个组件实例生成一个唯一的 ID，而且服务端和客户端生成的一样，主要用来把 label、提示文字和输入框关联起来。它不能当列表 key，也不适合当业务 ID 或 CSS 选择器。

  • React useEffectEvent 适合解决什么依赖问题？

    useEffectEvent 把 Effect 里"只想读最新值、不想因为它重跑"的那部分逻辑拎出来。比如房间变了要重连，主题变了不要重连。它只能在 Effect 内部调用，不能当 useCallback 用。

  • useActionState 如何把异步 Action 的结果变成组件状态？

    useActionState 把一个可能是异步的函数包起来，函数每次的返回值就是新的状态，还顺带给你一个"是否在提交中"的标记。多次提交会排队，后一次能拿到前一次的结果。

  • useOptimistic 的临时状态怎样与真实结果收敛？

    useOptimistic 让你在请求还没返回时，先把预期结果显示出来。请求结束后临时状态自动消失，界面回到真实状态，所以成功时要更新真实状态，失败时只需提示错误。

  • React useFormStatus 适合管理什么表单状态？

    useFormStatus 让表单里面的子组件知道外层表单是不是正在提交、提交了什么，适合做通用的提交按钮。它只能在表单的子组件里用，拿不到提交结果和错误信息。

  • React Server Functions/Actions 的边界是什么？

    Server Function 是标了 'use server'、只在服务端执行的函数，客户端拿到的只是一个引用，调用时框架发请求去服务端执行。参数和返回值必须能序列化，而且每个 Server Function 都等于一个公开接口，认证、授权和校验都要自己做。

  • React 的 cache API 解决什么问题？

    React 的 cache 只在 Server Components 里用，让同一次服务端请求里、参数相同的函数调用只真正执行一次。请求结束缓存就没了，它不是跨请求的数据缓存。

  • 怎样写一个 mini React（createElement、render、useState）？

    用三个函数搭一个教学模型：createElement 把标签、属性、子节点包成一个普通对象；render 从根开始调用函数组件，把元素树展开成只含普通标签的结果树；useState 按调用顺序把状态存在组件对应的数组里，setState 改完状态就重新渲染。这只是帮助理解的模型，不是 React 源码。

  • React 是怎样调度更新的？Scheduler、时间切片和 Lane 优先级各做什么？

    Scheduler 是 React 自带的任务调度包，按优先级给任务算出过期时间，放进小顶堆，在浏览器里用 MessageChannel 安排宏任务执行，每执行约 5 毫秒就检查一次要不要让出主线程，这就是时间切片。Lane 是 reconciler 里用二进制位表示的更新优先级，点击产生 SyncLane，Transition 产生 TransitionLane，多个更新用按位或合并，lanes & -lanes 取出最高优先级。同步和默认优先级的渲染不做时间切片。

  • <Activity> 怎样在隐藏时保留状态？和条件渲染有什么区别？

    React 19.2 起可用的 <Activity mode="hidden"> 会用 display: none 隐藏子树，同时销毁其中的 Effect，但保留 React 状态和 DOM；切回 visible 时状态还在，Effect 重新创建。条件渲染 {show && <A />} 会卸载组件，状态和 DOM 都没了。隐藏时 DOM 仍在，video 这类会继续播放，需要在清理函数里暂停。

  • useInsertionEffect 为什么是给 CSS-in-JS 库用的？和 useLayoutEffect、useEffect 时机有什么不同？

    useInsertionEffect 保证在所有 layout Effect 之前执行，CSS-in-JS 库在这里插入 <style>，其他组件在 useLayoutEffect 里测量布局时样式已经到位。它不能更新 state，执行时 ref 还没绑定，DOM 也不保证已更新，只在客户端运行。应用代码基本用不到它。
