React面试题

React 面试题，涵盖 Hooks、useEffect、状态更新、组件渲染、key、Context、受控组件、Suspense、useMemo 和并发更新，复习组件开发与性能优化。共 22 道题。

  • 为什么调用 setState 后，当前变量还是旧值？

    每次渲染拿到的 state 是一份快照，setter 只是请求下一次渲染。替换更新和函数式更新在队列里的含义不同，自动批处理会合并同一事件里的多次更新。

  • useEffect 的依赖数组和清理函数应该怎么写？

    Effect 用来让组件与外部系统保持同步。依赖数组列出 Effect 读取的所有响应式值，清理函数撤销上一轮同步。由渲染计算得出的值和由用户操作触发的逻辑不应放进 Effect。

  • 列表中的 key 为什么不能随意使用数组下标？

    key 告诉 React 同级元素的身份，决定组件状态和 DOM 是复用还是重建。下标表示位置，稳定 ID 表示数据本身；列表插入、删除或排序时，用下标会把状态错配到别的条目上。

  • memo、useMemo、useCallback 各自优化什么？

    memo 在 props 浅比较相同时跳过子组件渲染，useMemo 缓存计算结果，useCallback 缓存函数引用。它们只在依赖正确、性能确有问题时有用；启用 React Compiler 后多数手写缓存可以交给编译器。

  • React 的渲染阶段与提交阶段有什么区别？

    渲染阶段调用组件函数，计算出新的元素树并和上一次比较；提交阶段把差异应用到 DOM，再运行 Effect。渲染可能被中断、重复或丢弃，所以必须是纯计算；副作用只能放在提交之后。

  • 为什么 Hook 通常必须在组件顶层调用？

    React 按 Hook 的调用顺序把每个 useState、useEffect 对应到组件内部保存的状态槽。条件、循环或提前 return 改变了调用顺序，状态就会对错位置。条件逻辑应写在 Hook 内部，use API 是唯一可以条件调用的例外。

  • React 中的过期闭包为什么会读到旧状态？

    每次渲染创建的函数都捕获了那一次渲染的 props 和 state。如果某个函数被保存下来（计时器、订阅、依赖数组不完整的 Effect），之后调用时读到的仍是创建时的旧值。修复方式取决于需求：函数式更新、补全依赖、useEffectEvent 或 ref。

  • Context 与 useReducer 适合管理什么状态？

    Context 把值传给一棵子树里任意深度的组件，useReducer 把状态更新逻辑集中到一个纯函数里。两者组合可以替代层层传 props，但 Context 值变化会让所有消费者重新渲染，高频更新的全局状态更适合专门的状态库。

  • useRef、useEffect 和 useLayoutEffect 有什么差别？

    useRef 保存跨渲染的可变值，修改它不会触发渲染；useEffect 在提交后执行，通常在浏览器绘制之后；useLayoutEffect 在绘制前同步执行，适合测量布局并立即修正，但会阻塞绘制。

  • useTransition 和 useDeferredValue 能优化哪些卡顿？

    Transition 把一次状态更新标记为可以被打断的低优先级更新，让输入、点击等紧急更新先响应；useDeferredValue 返回一个滞后于原值的副本，用它渲染开销大的部分。它们优化的是渲染调度，不能拆分单个耗时的同步函数，也不会减少网络请求。

  • Error Boundary 和 Suspense 分别处理什么？

    Error Boundary 捕获子树在渲染、生命周期中抛出的错误并显示备用界面；Suspense 在子树等待数据或代码加载时显示 fallback。两者常一起包在异步区域外，分别处理"失败"和"等待"。

  • 受控组件与非受控组件应该如何选择？

    受控组件的值由 React state 提供，每次输入都经过 onChange 更新；非受控组件的值保存在 DOM 中，用 defaultValue 设置初值，在提交时读取。需要实时校验或联动时用受控，简单表单或配合 form action 时用非受控。

  • useActionState 如何把异步 Action 的结果变成组件状态？

    useActionState 接收一个 Action 函数和初始状态，返回当前状态、可以传给 form 的 dispatch 函数和 isPending。每次调用时 Action 收到上一次的返回值和本次参数，多次调用按顺序排队执行。

  • useOptimistic 的临时状态怎样与真实结果收敛？

    useOptimistic 在 Action 或 Transition 进行期间，把临时更新叠加到传入的真实状态上显示；Action 结束后，临时状态自动丢弃，界面回到真实状态。成功时要更新真实状态，失败时只需提示错误。

  • useSyncExternalStore 为什么要求稳定的快照？

    useSyncExternalStore 用 subscribe 和 getSnapshot 两个函数把外部数据源接入 React。React 用 Object.is 比较前后快照判断是否需要更新，数据没变时 getSnapshot 必须返回同一个引用，否则会无限重新渲染。

  • React 的 cache API 解决什么问题？

    React cache 只在 Server Components 中使用，在一次服务端请求内对相同参数的函数调用去重，共享返回值、Promise 或错误。请求结束后缓存失效，它不是跨请求的数据缓存，也没有过期时间和手动失效。

  • React useEffectEvent 适合解决什么依赖问题？

    useEffectEvent 从 Effect 中提取"事件逻辑"：它总能读到最新的 props 和 state，又不需要写进依赖数组。适合"连接变了要重连，但主题变了不要重连"这类场景；它只能在 Effect 内部调用，不能代替 useCallback。

  • React use API 可以读取哪些值？

    use 在渲染中读取 Promise 或 Context。读取未完成的 Promise 时组件会挂起，由最近的 Suspense 显示 fallback，失败交给 Error Boundary。它可以在条件语句中调用，但 Promise 必须缓存，不能在渲染时新建。

  • React Server Functions/Actions 的边界是什么？

    Server Function 是用 'use server' 标记、在服务端执行的异步函数，客户端拿到的只是一个调用引用，调用时框架通过网络请求执行它。参数和返回值必须可序列化，每个 Server Function 都是一个公开接口，要自己做认证、授权和输入校验。

  • React Compiler 解决了哪些优化问题？

    React Compiler 在构建时分析遵守 React 规则的组件和 Hook，自动插入记忆化，减少不必要的重新渲染和重复计算。它需要构建工具接入，会跳过违反规则的代码，也不能解决渲染内容过多、请求慢这类问题。

  • React useFormStatus 适合管理什么表单状态？

    useFormStatus 让 form 内部的子组件读取父级 form 的提交状态（pending、data、method、action），适合做通用的提交按钮和提交提示。它只能在 form 的子组件中调用，不提供提交结果和错误信息。

  • React useId 解决什么 ID 生成问题？

    useId 为组件实例生成唯一且在服务端和客户端一致的 ID，用于 label、aria-describedby 等无障碍属性关联。它不能用作列表 key，也不适合作为业务数据的 ID 或 CSS 选择器。
