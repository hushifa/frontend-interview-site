手写与算法面试题

JavaScript 手写题与算法练习，包含防抖、节流、LRU 缓存、Promise.all、异步并发池和树的前序遍历，附代码与边界说明。共 14 道题。

  • 怎样实现只在停止调用后执行的防抖函数？

    尾沿防抖在最后一次调用之后等待一段时间，期间没有新调用才执行。每次调用都清除旧计时器重新计时，执行时使用最后一次调用的参数和 this，并提供 cancel 取消待执行的调用。防抖只减少尚未开始的工作，已经发出的请求还要用 AbortController 或请求序号处理。

  • 怎样实现首沿节流？它与尾沿节流、防抖有什么区别？

    节流限制函数在每个时间窗口内最多执行一次。首沿节流在窗口开始时立即执行并丢弃窗口内的其他调用；尾沿节流在窗口结束时用最后一次调用的参数执行；防抖则要等调用停止一段时间后才执行。节流限制的是开始执行的频率，不等待异步操作完成。

  • 如何利用 Map 实现固定容量的 LRU 缓存？

    LRU 在容量满时淘汰最久没被访问的条目。JavaScript 的 Map 按插入顺序迭代，命中或更新时先删除再插入，就把这个键移到了末尾，第一个键就是要淘汰的条目。经典写法是哈希表加双向链表，两种实现的行为相同。

  • 怎样实现保持输入顺序的 Promise.all 教学版本？

    Promise.all 接收一个可迭代对象，返回的 Promise 在全部输入兑现后以按输入顺序排列的结果数组兑现，任一输入拒绝就立即拒绝。实现的关键是在登记每一项时固定它的下标，用计数器判断是否全部完成，并用 Promise.resolve 统一处理普通值、Promise 和 thenable。

  • 怎样实现有明确失败语义的异步并发池？

    并发池接收尚未启动的任务函数，同时启动 limit 个执行循环，每个循环领取下一个任务、等待完成后再领取，结果按输入下标保存。任一任务失败时整体拒绝，所有循环停止领取新任务，已经开始的任务需要通过 AbortSignal 自行停止。

  • 怎样用显式栈实现树的前序遍历？

    前序遍历先访问当前节点，再按从左到右的顺序完整遍历每棵子树。用数组模拟栈代替递归，可以避免深层树导致调用栈溢出；因为栈后进先出，子节点要逆序入栈。时间复杂度 O(n)，栈的峰值取决于树的形状。

  • 异步请求重试应该怎样设计？

    只重试临时性失败，例如 429、502、503、504；包含首次在内限制最大尝试次数，用指数退避加随机抖动错开重试时间，遵守服务端的 Retry-After，等待期间可以取消。写操作重试前必须由服务端用幂等键保证重复提交不会产生两次副作用。

  • 前端场景中的图遍历应该怎样建模？

    模块依赖、页面跳转和组件引用都可以建模为有向图。DFS 用栈沿一条路径走到底，适合找出所有可达节点和检测循环依赖；BFS 用队列逐层扩展，能找到边数最少的路径。两者都要用访问集合避免在环上无限循环。

  • 文本编辑器为什么不能只用一个字符串保存全文？

    字符串不可变，在大文档中间插入一个字符就要复制整段内容。Piece Table 保留原始文本和一个只追加的缓冲区，用片段列表描述当前文档，插入删除只改片段；Rope 把文本拆成平衡树，适合超大文本的随机编辑。数据结构解决存储问题，渲染和协同编辑是另外的层次。

  • 如何用拓扑排序解析前端任务和模块依赖？

    拓扑排序把有依赖关系的任务排成一个序列，使每个任务都排在它依赖的任务之后，常见于构建任务编排、插件加载和 monorepo 包构建。Kahn 算法统计每个节点的入度，从无依赖的节点开始逐层输出，剩余节点无法输出时说明存在循环依赖。

  • 二分查找怎样定位时间轴边界？为什么重复值和空数组容易写错？

    以视频章节定位为例，用左闭右开区间实现 lowerBound 和 upperBound：lowerBound 返回第一个大于等于目标的位置，upperBound 返回第一个大于目标的位置。两者组合可以找出当前所在章节、统计重复值个数，并天然处理空数组和未命中。

  • 如何合并时间区间？相邻区间算不算重叠？

    以视频已观看片段为例，按左闭右开区间合并重叠片段：先按起点排序，再依次与结果中最后一个区间比较。首尾相接的区间是否合并取决于业务语义，统计覆盖范围时应合并，判断预约冲突时不算冲突。

  • 搜索建议什么时候适合用 Trie？前缀树怎样处理重复词和 Unicode？

    以命令面板的前缀搜索为例，用 Map 节点实现 Trie：每个节点代表一个前缀，terminal 标记表示某个词在这里结束。查询前缀的耗时只与前缀长度有关，与词条总数无关。插入前统一 Unicode 归一化和大小写；需要模糊匹配或按热度排序时，Trie 就不够用了。

  • 前端任务怎样按优先级排队？二叉堆为什么不需要每次完整排序？

    以资源加载队列为例，用最小堆实现优先队列：插入时上浮，取出时把末尾元素放到堆顶再下沉，两者都是 O(log n)，比每次插入后整体排序的 O(n log n) 更省。同优先级按提交顺序取出，需要额外的序号。优先队列只决定先后，不负责限制并发和取消任务。
