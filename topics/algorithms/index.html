手写与算法面试题

JavaScript 手写题与算法练习，包含防抖、节流、LRU 缓存、Promise.all、异步并发池和树的前序遍历，附代码与边界说明。共 21 道题。

  • 怎样实现只在停止调用后执行的防抖函数？

    防抖就是"等你停下来再执行"：最后一次调用之后等一段时间，这段时间里没有新调用才真正执行。每次调用都清掉旧定时器重新计时，执行时用最后一次的参数和 this，还要提供 cancel。防抖只能少发还没开始的请求，已经发出去的请求要用 AbortController 或请求序号处理。

  • 怎样实现首沿节流？它与尾沿节流、防抖有什么区别？

    节流是限制函数在每段时间里最多执行一次。首沿节流在一段时间开始时马上执行，这段时间里的其他调用都丢掉；尾沿节流在这段时间结束时，用最后一次调用的参数执行；防抖则要等调用停下来一段时间才执行。节流只管多久开始执行一次，不等异步操作做完。

  • 怎样手写 call、apply 和 bind？用 new 调用 bind 返回的函数会怎样？

    call 和 apply 的手写思路是把函数临时挂到目标对象上调用一次再删掉，两者只是传参方式不同；bind 返回一个固定了 this 和前几个参数的新函数。用 new 调用 bind 出来的函数时，绑定的 this 不起作用，按原函数创建实例，预设的参数照样生效。

  • 怎样手写 new 和 instanceof？

    new 先创建一个原型指向 Fn.prototype 的空对象，再把它当作 this 调用构造函数，构造函数返回对象就用返回值，否则用新对象。instanceof 沿着左边对象的原型链往上找，看能不能遇到右边的 prototype。

  • 怎样实现保持输入顺序的 Promise.all 教学版本？

    Promise.all 接收一组输入，全部成功时按输入顺序返回结果数组，有一个失败就立刻失败。实现的关键是登记每一项时就记住它的下标，用计数器判断是不是全完成了，并用 Promise.resolve 统一处理普通值、Promise 和 thenable。

  • 怎样手写函数柯里化和 compose？

    柯里化把一个多参数函数改成可以分几次传参的函数，参数凑够原函数的个数才真正执行，常用来预先固定一部分参数。compose 把多个单参数函数串成一个，数据从右往左依次经过每个函数。

  • 怎样手写一个符合 Promises/A+ 规范的 Promise？

    核心是三件事：状态只能从 pending 变成 fulfilled 或 rejected，而且只变一次；then 的回调总是异步执行，并返回一个新的 Promise；用一个"解决过程"处理回调的返回值，识别自己引用自己、读取 then 时报错、thenable 多次回调这些情况。下面的实现通过了 promises-aplus-tests 全部 872 个用例。

  • 怎样手写深拷贝？和 structuredClone 有什么区别？

    深拷贝就是把对象里每一层都复制一份，改副本不影响原对象。手写时递归复制，用 WeakMap 记下复制过的对象来处理循环引用，Date、RegExp、Map、Set 单独处理，用 Reflect.ownKeys 才能拷到 Symbol 键。structuredClone 原生支持循环引用和大多数内置类型，但会丢掉 Symbol 键和原型，碰到函数会报 DataCloneError。

  • 怎样手写一个支持 on、off、once 和 emit 的事件中心？

    用一个 Map 按事件名存监听器数组。emit 遍历之前先复制一份，这样执行过程中新加的监听器下一次才生效，刚被移除的这一轮仍会执行，和 Node.js 的 EventEmitter 一致。once 的监听器要在调用之前移除，回调里再 emit 同一事件才不会重复触发。

  • 怎样在 O(n) 时间内把扁平列表转成树，再把树转回列表？

    先遍历一遍，用 Map 按 id 把所有节点建好；再遍历一遍，按 parentId 从 Map 里找到父节点，挂到它的 children 上，找不到父节点的当作根。两遍各是 O(n)，而且不管输入顺序。树转回列表用一个栈做前序遍历，顺便记下每个节点的父 id。

  • 如何利用 Map 实现固定容量的 LRU 缓存？

    LRU 是缓存满了时，淘汰最久没用过的那一条。JavaScript 的 Map 按插入顺序遍历，每次用到一个键就先删再插，把它挪到最后，排在最前面的就是该淘汰的。经典写法是哈希表加双向链表，两种实现效果一样。

  • 怎样实现有明确失败语义的异步并发池？

    并发池就是"最多同时跑 limit 个任务，跑完一个再接下一个"。它接收还没启动的任务函数，同时开 limit 个循环去领任务，结果按原来的顺序存。有任务失败时整体失败，不再领新任务，已经开始的任务要靠 AbortSignal 自己停。

  • 异步请求重试应该怎样设计？

    只重试过一会儿可能自己好的失败，比如 429、502、503、504；次数要有上限，等待时间每次翻倍再加随机抖动，服务端给了 Retry-After 就照办，等待中途能取消。写操作重试前，服务端必须用幂等键保证重复提交不会做两次。

  • 怎样用显式栈实现树的前序遍历？

    前序遍历是先访问当前节点，再从左到右把每棵子树完整走一遍。用数组当栈代替递归，树很深时也不会把调用栈撑爆；因为栈是后进先出，子节点要倒着放进去。时间复杂度 O(n)，栈最多占多少看树的形状。

  • 如何合并时间区间？相邻区间算不算重叠？

    以视频已看过的片段为例，按左闭右开区间合并：先按起点排序，再一个个和结果里最后一个区间比较。首尾正好相接的区间要不要合并，看业务：统计看了多少时要合并，判断预约冲突时不算冲突。

  • 二分查找怎样定位时间轴边界？为什么重复值和空数组容易写错？

    以视频章节定位为例，用左闭右开区间写 lowerBound 和 upperBound：lowerBound 找第一个大于等于目标的位置，upperBound 找第一个大于目标的位置。两个组合起来，能找出当前在哪一章、统计重复值有几个，空数组和找不到的情况也自然处理好了。

  • 如何用拓扑排序解析前端任务和模块依赖？

    拓扑排序是把有依赖关系的任务排成一列，保证每个任务都排在它依赖的任务后面，常用在构建任务编排、插件加载、monorepo 包构建。Kahn 算法先数清每个节点还有几个依赖没完成，从没有依赖的开始一层层输出，最后还剩节点排不出来，就说明有循环依赖。

  • 前端任务怎样按优先级排队？二叉堆为什么不需要每次完整排序？

    以资源加载队列为例，用最小堆实现优先队列：插入时往上浮，取出时把最后一个元素挪到堆顶再往下沉，都是 O(log n)，比每次插入都整体排序省得多。同优先级要按提交顺序取，需要额外加一个序号。优先队列只管谁先谁后，不管并发数量和取消。

  • 搜索建议什么时候适合用 Trie？前缀树怎样处理重复词和 Unicode？

    以命令面板的前缀搜索为例，用 Map 节点实现 Trie：每个节点代表一个前缀，terminal 标记表示有个词在这里结束。查一个前缀要走几步只看前缀多长，跟总共有多少词无关。插入前要统一 Unicode 编码和大小写；要模糊匹配或按热度排序时，Trie 就不够用了。

  • 前端场景中的图遍历应该怎样建模？

    模块依赖、页面跳转、组件引用都可以看成有方向的图。DFS 用栈沿一条路走到底，适合找出所有能到达的节点、检查循环依赖；BFS 用队列一层层往外扩，能找到经过边数最少的路径。两种都要记录走过的节点，不然遇到环会无限循环。

  • 文本编辑器为什么不能只用一个字符串保存全文？

    字符串不能原地修改，在大文档中间插一个字，就要把整段内容复制一遍。Piece Table 保留原文和一个只往后追加的缓冲区，用一串片段描述当前文档，插入删除只改片段；Rope 把文本拆到一棵平衡树上，适合超大文本。存储结构只解决存的问题，渲染和多人协同是另外的事。
