无障碍面试题

Web 无障碍面试题，关注键盘操作、焦点管理、可访问名称与描述，以及模态对话框的交互设计和屏幕阅读器体验。共 11 道题。

  • 怎样验证一个页面可以只用键盘操作？

    不用鼠标走一遍所有流程，检查每个功能都能用键盘完成、没有焦点陷阱、焦点顺序合理、焦点始终可见且不被遮挡；对应 WCAG 2.1.1、2.1.2、2.4.3、2.4.7 和 2.2 新增的 2.4.11。

  • 可访问名称与描述有什么区别？

    可访问名称是控件的“叫什么”，读屏在聚焦时首先读出，来源依次是 aria-labelledby、aria-label、原生 label 或内容、title；描述是补充说明，用 aria-describedby 关联，在名称和角色之后读出。

  • 一个可访问的模态对话框需要具备哪些行为？

    模态对话框要有名称和 dialog 角色，打开时焦点移入、背景不可操作，Tab 只在对话框内循环，Esc 可关闭，关闭后焦点回到触发元素；原生 dialog 的 showModal() 已提供大部分行为。

  • aria-live 怎样用于动态状态播报？

    live region 是页面加载时就存在的容器，内容变化时读屏自动播报；polite 等用户空闲时读，assertive 立即打断。保存成功、搜索结果数用 role="status"，紧急错误用 role="alert"。

  • 可访问的 Combobox 需要哪些键盘和 ARIA 行为？

    可编辑 Combobox 是带 role="combobox" 的输入框加一个 listbox 弹层；焦点始终留在输入框，用 aria-activedescendant 指示当前候选，方向键浏览、Enter 确认、Esc 关闭。能用原生 select 或 datalist 时优先用原生。

  • 数据表格怎样设计才方便键盘和读屏用户理解？

    数据表用原生 table，caption 给出表名，th 加 scope 标明是行表头还是列表头；读屏在单元格间移动时会读出对应表头。不要用 div 拼表格，也不要用 table 做布局。

  • 可访问的树控件需要怎样处理键盘和层级状态？

    树控件用 role="tree" 和 treeitem，展开状态用 aria-expanded，子节点放在 role="group" 里；整棵树只占一个 Tab 位置，用方向键移动和展开。能用嵌套列表加 details 表达的结构，不必做成 tree。

  • 无障碍色彩对比和状态表达应该怎样设计？

    正文文字和背景对比度至少 4.5:1，大号文字至少 3:1，图标、边框、焦点指示等非文本元素至少 3:1；错误、选中等状态不能只靠颜色区分。

  • 前端怎样进行读屏器和辅助技术的实际验收？

    自动化工具（axe 等）只能发现一部分可机器判断的问题；上线前还要用键盘、读屏、放大和减少动态效果实际走一遍关键流程，并把结果记录成可复现的验收项。

  • 如何让动画尊重用户的减少动态效果设置？

    用 prefers-reduced-motion 媒体查询读取系统设置，关闭或替换大幅移动、缩放、视差和自动播放的动画；保留淡入淡出等不会引起不适的反馈，状态变化本身不能丢。

  • inert、aria-hidden、disabled 和 pointer-events 有什么区别？

    inert 让整个区域不能聚焦、点击、查找，也从无障碍树中移除；aria-hidden 只对辅助技术隐藏，键盘仍能聚焦；disabled 用于单个表单控件；pointer-events: none 只屏蔽指针，键盘照样可用。
