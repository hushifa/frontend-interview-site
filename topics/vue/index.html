Vue面试题

Vue 3 面试题，涵盖 ref、reactive、computed、watch、nextTick、Composition API、组件通信、v-model、生命周期和模板编译。共 32 道题。

  • Vue 3 中 ref 和 reactive 有什么区别？

    ref 能包装任何值，通过 .value 读写，可以整体替换；reactive 只能包对象，解构或整体替换都会丢失响应式。官方推荐默认用 ref。

  • Vue 2 的响应式原理是什么？

    Vue 2 初始化时把 data 里的每个属性都改成 getter 和 setter。读属性时记下"谁用了它"，改属性时通知这些使用者重新执行，组件也就跟着重新渲染。

  • Vue 3 响应式依赖是怎样收集和触发的？

    Vue 3 用 Proxy 拦住属性的读和写。函数执行时读了哪些属性，就记下"这个函数依赖它们"；属性被改时，再把依赖它的函数重新执行一遍。

  • defineProperty 和 Proxy 实现的响应式有什么区别？

    Vue 2 的 defineProperty 只能一个个监听已有属性，初始化时要把整个 data 走一遍；Vue 3 的 Proxy 直接代理整个对象，用到嵌套对象时才代理它，所以属性增删、数组下标、Map 和 Set 都能检测到。

  • computed、watch 和 watchEffect 应该如何选择？

    要从已有数据算出一个新值，用 computed，它会缓存结果；数据变了要去做一件事，比如发请求，用 watch 或 watchEffect。watch 盯着你指定的数据，watchEffect 自动追踪它用到的数据。

  • Options API 和 Composition API 有什么区别？Vue 组件的 data 为什么必须是函数？

    Options API 按 data、methods、computed 这些选项组织代码，通过 this 访问组件实例；Composition API 用导入的函数在 setup 里组织逻辑，同一功能的代码可以写在一起，也能抽成组合式函数复用，对 TypeScript 更友好。两者底层是同一套系统，Options API 就建在 Composition API 之上。组件的 data 写成函数，是为了每个实例都拿到独立的数据对象。

  • 修改状态后，为什么有时需要 await nextTick()？

    改了响应式数据，数据本身马上变了，可页面要等 Vue 批量更新才变。想读更新后的 DOM，比如滚到底部、聚焦新出现的输入框，就先 await nextTick()。

  • v-if 和 v-for 为什么不建议写在同一个元素上？

    Vue 2 里同一个元素上 v-for 优先级更高，每一项都会先渲染再判断；Vue 3 改成 v-if 优先，v-if 拿不到 v-for 的循环变量，直接报错。两个版本都建议过滤列表用 computed，整体显示隐藏把 v-if 放到外层或 template 上。

  • Vue 生命周期中何时访问 DOM、发请求和清理资源？

    setup 最先执行，适合创建状态和发请求，但这时还没有 DOM；要操作 DOM 等 onMounted；定时器和订阅在 onUnmounted 里清掉。服务端渲染时挂载钩子不会执行。

  • Vue 3 相比 Vue 2 有哪些主要变化？

    Vue 3 新增了 Composition API 和 script setup，响应式从 defineProperty 改为 Proxy，编译器给模板打上标记让更新只比较动态部分；组件支持多个根节点，新增 Teleport 和实验性的 Suspense；源码用 TypeScript 重写，全局 API 改成 createApp 并支持 tree-shaking。同时移除了 filters、$on/$off/$once、v-on 的 .native 修饰符等写法。

  • Vue 的 $attrs、inheritAttrs 和透传属性是怎样工作的？

    传给组件、却没有被声明成 props 或 emits 的属性和 v-on 监听器叫透传属性。组件只有一个根元素时，它们会自动加到根元素上，class 和 style 会和根元素原有的值合并。设置 inheritAttrs 为 false 可以关掉自动透传，再用 v-bind="$attrs" 绑到想要的元素上。多根节点组件不会自动透传，没有显式绑定时会有警告。

  • v-once、v-memo、shallowRef 和 markRaw 分别在什么时候用？

    v-once 和 v-memo 是模板指令，作用在渲染上：v-once 让一块内容只渲染一次，之后的更新都跳过；v-memo（3.2+）按依赖数组决定是否跳过子树更新，主要用在超过上千项的 v-for 列表。shallowRef 和 markRaw 作用在数据上：shallowRef 只追踪 .value 被整体替换，markRaw 让对象永远不被转成代理，适合第三方库实例。它们都是微优化，依赖写错就会漏掉该有的更新。

  • defineProps、defineEmits 和 defineExpose 有什么作用？

    三者都是只能在 <script setup> 里使用的编译器宏，不用导入，编译时会被替换掉。defineProps 声明组件接收的 props，defineEmits 声明会触发的事件并返回 emit 函数，两者都支持运行时声明和纯类型声明。defineExpose 决定父组件通过模板 ref 能拿到什么，因为 <script setup> 组件默认是“关闭”的，不暴露任何内部变量。

  • Vue 2 有哪些组件通信方式？哪些写法在 Vue 3 中被移除或改变？

    Vue 2 常用 props 和 $emit、.sync、$attrs/$listeners、provide/inject、EventBus 和 Vuex 通信。到了 Vue 3，$listeners 并进了 $attrs，.sync 换成 v-model:xxx，$on/$off 被删掉，EventBus 要换成 mitt 这类库。

  • 组件 v-model 的本质是什么？

    组件上的 v-model 就是"传一个 prop 加监听一个更新事件"的简写，默认是 modelValue 和 update:modelValue。数据始终归父组件，子组件只是发事件说"我想改成这个值"。

  • Vue 2 的 diff 算法是怎样比较子节点的？

    Vue 2 比较新旧两组子节点时，在两头各放一个指针，先试四种首尾配对，配不上再用 key 去找能复用的旧节点。Vue 3 先跳过首尾相同的部分，再用最长递增子序列减少移动，并靠编译信息跳过不变的内容。

  • Vue 2 的异步更新队列和 nextTick 降级策略是怎样实现的？

    Vue 2 把需要更新的 watcher 去重后放进队列，在 nextTick 里统一执行，执行前按 id 排序，保证父组件先于子组件。nextTick 优先用 Promise，不行再依次退到 MutationObserver、setImmediate、setTimeout。

  • Vue 2 与 Vue 3 的生命周期如何对照？父子组件钩子按什么顺序执行？

    Vue 2 的 beforeDestroy、destroyed 到 Vue 3 改名为 beforeUnmount、unmounted，组合式 API 用 onXxx 注册。父子组件不管是创建、更新还是销毁，都是父组件先开始、子组件先结束。

  • 为什么 Vue 提倡 props 单向数据流？

    props 只能从父组件流向子组件，子组件想改，就发事件让父组件改。这样每份数据只有一个主人，出了问题能顺着找到是谁改的。

  • v-if 和 v-show 应该怎样选择？

    v-if 条件为假时真的把元素和组件删掉，里面的状态也没了；v-show 一直渲染，只是用 display 藏起来。很少切换用 v-if，频繁切换用 v-show。

  • 插槽、作用域插槽和 provide/inject 各解决什么问题？

    插槽让父组件往子组件的指定位置塞内容；作用域插槽让子组件把数据交出来，由父组件决定怎么显示；provide/inject 让祖先组件把东西直接传给很深的后代，不用一层层传 props。

  • KeepAlive 与 Teleport 有哪些使用边界？

    KeepAlive 让切走的组件不销毁、切回来状态还在；Teleport 把一段模板渲染到页面别处，比如 body 下面，但组件关系不变。前者管状态保留，后者管 DOM 位置，定时器暂停和弹窗交互都得自己处理。

  • Vue 2 响应式有哪些限制？如何绕过？

    Vue 2 只能在初始化时给已有属性装上监听，所以新加或删掉对象属性、用下标改数组、改数组长度，它都发现不了。绕过办法是 Vue.set、Vue.delete 和 splice。

  • 组合式函数和 mixin 相比有什么维护优势？

    组合式函数就是一个普通函数，参数传进去、状态通过返回值拿出来，变量从哪来一眼就能看到。mixin 把属性直接混进组件，来源不清还容易重名，Vue 3 推荐用组合式函数复用逻辑。

  • Vue 模板编译如何减少运行时更新工作？

    Vue 编译模板时就能看出哪些地方不会变、哪些地方会变，并把这些信息写进渲染函数。更新时只比较会变的那一小部分，所以比纯虚拟 DOM 对比更省事。

  • Vue 大型页面应从哪些方面优化更新开销？

    先用工具找到慢在哪，再对症下手：让子组件只收到真正变化的 props，派生数据放 computed，大块只读数据别做深层响应式，长列表用虚拟滚动，不变的子树用 v-memo 跳过。

  • Vue 自定义指令适合什么场景？

    自定义指令用来复用对 DOM 元素的直接操作，比如自动聚焦、点击外部关闭。它通过 mounted、unmounted 等钩子拿到元素，卸载时要记得清理；要渲染结构或管理状态，就该用组件或组合式函数。

  • Vue 3 defineModel 的双向绑定边界是什么？

    defineModel 帮你自动声明 v-model 需要的 prop 和更新事件，返回一个能直接读写的 ref，给它赋值就会通知父组件。但子组件的默认值不会传回父组件，改对象模型的内部属性也不会发事件。

  • Vue 2 项目如何迁移到 Vue 3？

    先升到 Vue 2.7，用组合式 API 提前改写，清理 filters、$listeners、.sync 这些旧写法；确认组件库和浏览器支持没问题后，再用 @vue/compat 迁移构建逐个消除警告，同时升级路由和状态管理。

  • Vue 插件如何向应用提供可复用能力？

    插件是一个带 install(app, options) 方法的对象或一个函数，用 app.use 装到应用上，可以注册全局组件和指令、提供服务。状态要在 install 里创建，这样多个应用和服务端渲染时互不干扰。

  • Vue 复杂表单怎样组织状态、校验和提交？

    把正在编辑的草稿、上次保存的基线和提交过程分开管。错误等用户离开字段或点了提交再显示，提交中防重复，失败留着草稿，成功后用服务端返回的数据当新基线。

  • Vue Suspense 适合处理什么异步组件边界？

    Suspense 等子树里的异步组件都准备好之前，先显示一个加载中的占位内容。它只认顶层有 await 的 setup 和异步组件，不管普通的 fetch，也不处理错误，官方文档里仍标为实验性功能。
