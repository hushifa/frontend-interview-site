Vue面试题

Vue 3 面试题，涵盖 ref、reactive、computed、watch、nextTick、Composition API、组件通信、v-model、生命周期和模板编译。共 18 道题。

  • Vue 3 中 ref 和 reactive 有什么区别？

    ref 把任意值包装进一个带 .value 的对象，可以整体替换；reactive 返回对象的 Proxy，只能用于对象，解构或整体替换都会丢失响应式。官方推荐优先使用 ref。

  • computed、watch 和 watchEffect 应该如何选择？

    computed 从响应式数据推导新值并缓存，不应有副作用；watch 监听明确的来源，变化时执行副作用，能拿到新旧值；watchEffect 立即执行并自动追踪同步读取的数据。派生数据用 computed，副作用用 watch 或 watchEffect。

  • 修改状态后，为什么有时需要 await nextTick()？

    Vue 修改响应式数据后，数据立即改变，但 DOM 更新被放进队列，在下一个微任务中批量执行。需要读取更新后的 DOM（测量尺寸、聚焦新元素、滚动到底部）时，await nextTick() 等待这次刷新完成。

  • 为什么 Vue 提倡 props 单向数据流？

    props 从父组件流向子组件，子组件不能直接修改 prop，要修改就 emit 事件交给父组件处理。这样数据只有一个所有者，出问题时能追溯来源。Vue 3.5 起解构 defineProps 的结果仍保持响应式。

  • Vue 3 响应式依赖是怎样收集和触发的？

    Vue 3 用 Proxy 拦截属性读取和修改。effect（组件渲染函数、computed、侦听器）执行时，读取到的属性被记录为依赖；属性被修改时，通知依赖它的 effect 重新执行。依赖每次执行都会重新收集，组件更新则放进队列批量处理。

  • 组合式函数和 mixin 相比有什么维护优势？

    组合式函数是普通函数，通过参数接收输入、通过返回值暴露状态，来源一目了然，可以自由组合和重命名。mixin 把属性和方法合并进组件，来源不清、容易命名冲突、相互之间存在隐式依赖。Vue 3 推荐用组合式函数复用逻辑。

  • Vue 生命周期中何时访问 DOM、发请求和清理资源？

    setup 最先执行，用来创建状态和发起请求，此时还没有 DOM；onMounted 后可以访问 DOM；onUnmounted 时清理计时器和订阅。SSR 只执行 setup，不调用挂载钩子；被 KeepAlive 缓存的组件切换时触发 activated 和 deactivated。

  • v-if 和 v-show 应该怎样选择？

    v-if 按条件创建或销毁元素与组件，条件为假时子组件被卸载、内部状态丢失；v-show 始终渲染，只切换 CSS display。初始不需要或很少切换用 v-if，频繁切换用 v-show。

  • 插槽、作用域插槽和 provide/inject 各解决什么问题？

    插槽让父组件向子组件的指定位置传入模板内容；作用域插槽让子组件把数据交给父组件来决定如何渲染；provide/inject 让祖先组件向任意深度的后代传递依赖，不必逐层传 props。

  • KeepAlive 与 Teleport 有哪些使用边界？

    KeepAlive 缓存被切换掉的组件实例，切回时保留状态，并触发 activated 和 deactivated 钩子；Teleport 把一段模板渲染到组件之外的 DOM 位置，组件之间的逻辑关系不变。前者解决状态保留，后者解决 DOM 位置，两者都不会自动处理资源暂停或弹窗交互。

  • 组件 v-model 的本质是什么？

    组件上的 v-model 是一个 prop 加一个更新事件的语法糖，默认是 modelValue 和 update:modelValue。状态始终属于父组件，子组件只是发出"想改成这个值"的事件。Vue 3.4 起可以用 defineModel 简化子组件的写法。

  • Vue 大型页面应从哪些方面优化更新开销？

    先用 Vue DevTools 和浏览器 Performance 面板找到瓶颈。常见手段：让子组件只接收真正变化的 props、用 computed 缓存派生数据、大型只读数据用 shallowRef 或 markRaw、长列表虚拟滚动、用 v-memo 跳过不变的子树、异步组件拆分代码。

  • Vue 自定义指令适合什么场景？

    自定义指令用于复用对普通 DOM 元素的底层操作，例如自动聚焦、点击外部关闭、懒加载图片。它通过 mounted、updated、unmounted 等钩子访问元素，必须在卸载时清理资源；需要渲染结构或管理状态时应该用组件或组合式函数。

  • Vue 插件如何向应用提供可复用能力？

    插件是带 install(app, options) 方法的对象（或一个函数），通过 app.use 安装，用来注册全局组件和指令、用 app.provide 提供服务、或添加 globalProperties。插件状态应在 install 中按应用实例创建，以便 SSR 和多应用场景互不干扰。

  • Vue 模板编译如何减少运行时更新工作？

    Vue 编译器分析模板，复用静态节点、给动态节点打上 patch flag、把动态节点收集到 block 的扁平数组中。更新时运行时只比较这些动态节点的动态部分，跳过静态结构。这是 Vue 3 比纯虚拟 DOM 方案更新更快的主要原因。

  • Vue 复杂表单怎样组织状态、校验和提交？

    复杂表单要把编辑中的草稿、已保存的基线和提交过程分开管理。错误在失焦或提交后才显示，提交期间防止重复提交，失败保留草稿，成功后以服务端返回的数据作为新基线。

  • Vue Suspense 适合处理什么异步组件边界？

    Suspense 在子树中的异步依赖（顶层有 await 的 setup、异步组件）全部完成前显示 fallback 插槽。它不追踪组件里普通的 fetch 调用，自身不处理错误，并且在 Vue 文档中仍标为实验性功能。

  • Vue 3 defineModel 的双向绑定边界是什么？

    defineModel 是 Vue 3.4 起稳定的 script setup 宏，自动声明模型 prop 和更新事件，返回可读写的 ref。修改这个 ref 会 emit 更新事件；子组件的 default 值不会同步给父组件，修改对象模型的内部属性也不会触发事件。
