Vue面试题

Vue 3 面试题，涵盖 ref、reactive、computed、watch、nextTick、Composition API、组件通信、v-model、生命周期和模板编译。共 18 道题。

  • Vue 3 中 ref 和 reactive 有什么区别？

    ref 用 value 容器表示可替换的响应式值，reactive 用 Proxy 表示对象属性的响应式访问。解构、整个对象替换、ref 解包和浅层 API 都有各自规则，不能把它们统一理解为所有变量都会自动保持连接。

  • computed、watch 和 watchEffect 应该如何选择？

    computed 表达派生值，watch 对明确来源的变化执行副作用，watchEffect 自动收集同步读取的来源。它们的返回、缓存、触发与清理规则不同，应围绕数据是否需要单独保存和外部工作怎样结束来选择。

  • 修改状态后，为什么有时需要 await nextTick()？

    Vue 的响应式值会立即改变，依赖这些值的组件 DOM 通常经过队列批量更新。nextTick 等待相应 Vue 刷新完成，不等于等待网络、图片、动画或浏览器最终绘制完成。

  • 为什么 Vue 提倡 props 单向数据流？

    props 把父级状态传给子组件，事件把子组件的修改意图交回所有者。只读绑定、嵌套对象共享、本地草稿和 Vue 3.5 的 props 解构转换各有边界，不能只记成一句“子组件不能修改数据”。

  • Vue 3 响应式依赖是怎样收集和触发的？

    响应式依赖来自受追踪执行过程中的实际读取，相关修改再通知计算、侦听器或组件更新。依赖会随分支变化重新整理，通知与 DOM 刷新也有调度差别，不能把 Proxy 理解成对一切变量变化的全局观察。

  • 组合式函数和 mixin 相比有什么维护优势？

    组合式函数通过显式参数、返回值与作用域复用逻辑，更容易看出状态和副作用来源。复用代码不代表共享状态，响应式输入、返回 ref、生命周期注册和 SSR 边界仍需要清楚设计。

  • Vue 生命周期中何时访问 DOM、发请求和清理资源？

    setup 建立每个实例的响应式逻辑，挂载后才有对应 DOM，更新与卸载又有各自阶段。请求和资源应按真实生命周期安排，SSR、异步子树和 KeepAlive 也不能套用同一个“挂载一次、结束一次”的假设。

  • v-if、v-show 与列表 key 应该怎样选择？

    v-if 改变条件子树是否存在，v-show 通常保留子树并切换显示；key 决定更新时如何识别同级记录。选择要同时考虑初始成本、切换成本、状态保留、焦点和副作用生命周期。

  • 插槽、作用域插槽和 provide/inject 各解决什么问题？

    插槽决定组件区域由谁提供内容，作用域插槽让子级把渲染所需数据交给内容提供者，provide/inject 则解决跨层依赖传递。内容作用域、数据所有权和注入的响应式来源需要分别理解。

  • KeepAlive 与 Teleport 有哪些使用边界？

    KeepAlive 改变组件切换时的实例保留策略，Teleport 改变内容所在的物理 DOM 位置。一个涉及缓存与激活生命周期，一个涉及挂载目标与布局；二者都不会自动完成资源暂停、模态交互或数据持久化。

  • 组件 v-model 的本质是什么？

    组件 v-model 把一个当前值 prop 与对应更新事件连接起来，默认使用 modelValue 和 update:modelValue。它简化的是父子通信约定，不取消状态所有权，输入时机、默认值和修饰符仍需组件明确支持。

  • Vue 大型页面应从哪些方面优化更新开销？

    更新优化应先定位计算、组件更新、DOM 数量或布局绘制的真实成本，再选择稳定 props、派生数据、浅层状态或虚拟化。缓存与编译优化不能替代清楚的数据边界，也不能用错误的跳过更新换取表面流畅。

  • Vue 自定义指令适合什么场景？

    自定义指令用于复用普通元素上的底层 DOM 行为，例如聚焦或观察尺寸。它需要处理绑定值变化与资源释放，不应替代组件结构、状态逻辑，也不会自动找到自定义组件内部的目标元素。

  • Vue 插件如何向应用提供可复用能力？

    插件通过 app.use 在应用范围安装能力，可以注册组件、指令或依赖。配置、状态与资源应按应用实例组织，重复安装不等于动态更新配置，SSR 与应用卸载也需要明确的生命周期。

  • Vue 模板编译如何减少运行时更新工作？

    Vue 在模板编译时识别静态结构和动态绑定，将缓存、patch flags 与区块信息交给运行时。运行时可以更有针对性地更新，但仍需响应式调度、组件计算和实际 DOM 操作，不能理解成编译后零成本。

  • Vue 复杂表单怎样组织状态、校验和提交？

    表单需要区分编辑草稿、已确认基线、交互提示与提交生命周期。v-model 只负责值同步，异步错误、重复提交、失效清理和成功后的状态收敛必须由明确的数据流完成。

  • Vue Suspense 适合处理什么异步组件边界？

    Suspense 协调组件树中受支持的异步依赖，在准备期间显示 fallback。它不自动追踪所有请求，也不自身提供完整错误恢复；初次等待、后续切换、超时显示与资源取消需要分别设计。

  • Vue 3 defineModel 的双向绑定边界是什么？

    defineModel 在 script setup 中声明模型 prop、更新事件和对应访问引用，简化组件 v-model 的实现。模型名称、父级初始化、修饰符转换和对象更新方式仍是组件契约，不能由宏自动推断完整业务含义。
