Node.js面试题

面向前端工程师的 Node.js 面试题，涵盖 Node 事件循环、Stream 流与背压，以及编写服务时的安全边界。共 18 道题。

  • Koa 和 Express 有什么区别？中间件洋葱模型是怎样实现的？

    Express 在 Node 的 req、res 上扩展方法，自带路由、静态文件等功能；Koa 由 Express 原班团队设计，核心只有中间件机制，用 async 函数和 ctx 对象，路由等功能交给第三方模块。Koa 中间件 await next() 之后还会回到自己继续执行，形成先进后出的洋葱模型，靠 compose 递归调用 dispatch 实现。

  • Node.js 事件循环和浏览器有什么不同？nextTick 一定先于 Promise 吗？

    Node.js 由 libuv 驱动按阶段运行的事件循环，timers、poll、check 等阶段轮流执行，每个回调之后先清空 nextTick 队列再清空微任务队列。nextTick 与 Promise 的先后取决于当前代码是否已在微任务中运行，CommonJS 与 ES 模块入口的结果不同。

  • 流和背压为什么能避免一次性读入大文件？

    流把数据分成小块依次处理，内存占用取决于缓冲区大小，而不是文件大小。背压让写入端在缓冲区满时通知上游暂停；用 stream.pipeline 连接各个流，可以同时得到背压传递、错误传播和统一清理。

  • 前端工程师编写 Node 服务时需要守住哪些安全边界？

    Node 服务能访问网络、文件系统、子进程和密钥，权限比浏览器页面大得多。所有输入和权限都要在服务端重新校验；下游地址由服务端决定以防 SSRF；文件路径和命令不拼接用户输入；请求体、超时和并发都要设上限，日志里不记录凭据。

  • Node.js 的子进程、Worker 和集群应该怎样选择？

    Worker Threads 在同一进程里运行 CPU 密集的 JavaScript；child_process 启动独立进程执行外部命令或隔离代码；cluster 复制多个服务进程共享端口来利用多核。三者的隔离程度、通信成本和出故障时的影响范围不同。

  • Node.js 的 package exports 会怎样影响模块解析？

    package.json 的 exports 声明包对外公开哪些入口，没列出的子路径无法被导入。条件导出让同一入口按 import、require、node、default 等条件指向不同文件。exports 不改变文件的模块格式，ESM 与 CommonJS 互操作还受 require(esm) 支持版本的影响。

  • Node.js Worker Threads 适合解决什么问题？

    Worker Threads 让 CPU 密集计算在独立线程中运行，避免阻塞主线程的事件循环。每个 Worker 有自己的 V8 实例和事件循环，通过消息通信；数据默认结构化克隆，可以转移 ArrayBuffer 的所有权，也可以用 SharedArrayBuffer 共享内存。

  • 怎样实现一个 Node.js Worker Threads 任务池？

    任务池预先创建固定数量的 Worker，用空闲列表、等待队列和按 ID 记录的在途任务三个结构分发任务，结果按 ID 回到调用方。生产环境还要处理 Worker 崩溃后补位、排队上限、任务超时和优雅关闭，池子大小一般不超过 CPU 核数。

  • Node.js 的 cluster 模块怎样实现多进程部署？PM2 做了什么？

    cluster 让主进程 fork 多个工作进程共享同一个端口，默认（Windows 除外）由主进程按轮询把连接分给工作进程。工作进程不共享内存，会话等状态要放外部存储；进程数量和重启要应用自己管理，PM2 这类进程管理器的 cluster 模式就是在 cluster 模块之上做了这些事。

  • BFF 聚合接口怎样设计才能避免把前端耦合到后端细节？

    以题目详情页聚合多个后端服务为例，BFF 按页面定义输出契约，用整体超时和分支截止时间并行调用下游，区分核心数据与可降级数据，返回前端可恢复的错误，并在缓存、版本和观测上划清边界。

  • Node.js 服务内存泄漏怎样排查？

    先用监控确认内存持续上涨、不回落，再用 --inspect 连 Chrome DevTools，或用 --heapsnapshot-signal、v8.writeHeapSnapshot() 拿堆快照；在怀疑泄漏的操作前后各拍一张，用 Comparison 视图找数量持续增长的对象和引用它们的链。常见原因是无上限的缓存、没移除的事件监听、没清除的定时器和挂在全局上的数据。

  • Node.js 服务如何实现优雅退出？

    容器滚动发布时，旧进程收到 SIGTERM 后先让 readiness 检查失败，等负载均衡器摘除实例，再停止接收新连接、等待在途请求完成、关闭数据库和队列等资源；整个过程有一个截止时间，超时后强制退出。

  • Node.js 的 EventEmitter 有哪些需要注意的地方？

    EventEmitter 的 emit 会同步、按注册顺序调用监听器；没有 error 监听器时 emit('error') 会直接抛出，可能让进程崩溃；同一事件超过 10 个监听器会打印 MaxListenersExceededWarning，常是泄漏的信号。events.once() 把一次事件变成 Promise，events.on() 把事件流变成异步迭代器，都会在 error 时拒绝或抛出。

  • AsyncLocalStorage 如何在 Node.js 请求链路中传递上下文？

    AsyncLocalStorage 在一次异步调用链里保存上下文，深层的日志代码不用层层传参也能读到当前请求的 ID，并发请求之间互不干扰。原生 Promise、定时器和大多数核心 API 会自动传播上下文，EventEmitter 监听器、回调式库和 Worker 需要显式绑定或传递。

  • 消息队列任务怎样设计取消、超时、确认和重试？

    以前端触发的报表导出为例，异步任务要有提交与查询接口，在至少一次投递下做幂等处理，处理完成后再确认消息，用持久化状态实现取消，按有上限的退避重试并配死信队列，还要保证任务记录与消息发布之间的一致性。

  • Node.js 的 diagnostics_channel 适合解决什么问题？

    diagnostics_channel 是进程内的命名发布订阅通道，库在关键操作处发布诊断事件，APM 和日志工具订阅这些事件，不需要给库打补丁。没有订阅者时发布几乎没有开销；tracingChannel 为一次调用统一提供开始、结束和错误事件。

  • node:test 能替代 Jest 吗？

    node:test 是 Node.js 内置的测试运行器，v20 起稳定，不用装依赖就有 test/describe/it、钩子、函数和定时器 mock、快照、多种报告器，node --test 自动发现测试文件。纯 Node 的库和服务端代码可以用它替代 Jest；前端组件测试需要 jsdom 环境、模块 mock 和成熟生态，仍然是 Jest 或 Vitest 更合适。覆盖率和模块 mock 目前还是实验性功能。
