Web API面试题

Web API 面试题，涵盖 Fetch 流式读取、AbortController、Web Components、文件预览、Clipboard API、WebRTC、WebAssembly 与 DOM 观察器。共 26 道题。

  • AbortController 能取消什么，不能取消什么？

    AbortController 通过 signal 通知接收方取消，fetch、addEventListener 和支持 signal 的 API 会响应；它不能中断正在执行的同步代码，也不能撤销服务端已经执行的操作。

  • Custom Elements、Shadow DOM 和 template 分别负责什么？

    Custom Elements 定义新标签和生命周期，Shadow DOM 隔离组件内部的结构和样式，template 保存可复用但不渲染的标记；三者配合组成 Web Components，可以在任何框架中使用。

  • File、Blob 和 object URL 怎样用于文件预览？

    Blob 是不可变的二进制数据，File 是带文件名和修改时间的 Blob；URL.createObjectURL() 生成指向内存数据的临时地址用于预览，用完要调用 revokeObjectURL() 释放。

  • 怎样正确消费 Fetch 返回的 ReadableStream？

    response.body 是字节流，用 for await 或 getReader() 逐块读取，配合 TextDecoderStream 解码文本；按行或按事件解析时要缓存跨块的残余数据，并在取消或出错时释放流。

  • Permissions.query 是申请权限，还是查询权限？

    navigator.permissions.query() 只查询当前授权状态（granted、denied、prompt），不会弹出授权框；真正请求权限要调用对应 API，例如 getUserMedia 或 Notification.requestPermission。

  • 异步 Clipboard API 为什么会出现权限或用户激活错误？

    navigator.clipboard 只在安全上下文中可用；写入通常要求用户激活，读取需要权限或用户确认，页面不在焦点、iframe 未授权时都会被拒绝。

  • AudioContext 与音频节点图怎样组织音频处理？

    Web Audio 用 AudioContext 管理一张音频节点图，音源节点经过增益、滤波、分析等处理节点连到 destination 输出；AudioContext 受自动播放策略限制，需要用户手势后 resume。

  • WebRTC 为什么需要信令、STUN 和 TURN？

    WebRTC 只负责点对点传输，双方交换 SDP 和 ICE 候选需要自己实现信令通道；STUN 帮设备发现自己的公网地址，TURN 在无法直连时中转流量。

  • WebAssembly 能替代 JavaScript 吗？适合哪些工作？

    WebAssembly 是浏览器中运行的二进制指令格式，适合把 C、C++、Rust 等已有代码或计算密集任务带到网页；它不能直接操作 DOM，和 JavaScript 互相调用有开销，通常与 JavaScript 配合而不是替代。

  • ResizeObserver 为什么可能出现循环通知错误？

    ResizeObserver 在布局后报告元素尺寸变化；回调里又改变了被观察元素的尺寸时，浏览器会在同一帧内重复通知，超过限制后跳过并报告 "ResizeObserver loop completed with undelivered notifications"。

  • MutationObserver 和 ResizeObserver 分别观察什么？

    MutationObserver 观察 DOM 节点的增删、属性和文本变化，回调在微任务中批量执行；ResizeObserver 观察元素渲染尺寸的变化。尺寸变化不一定伴随 DOM 变化，两者不能互相替代。

  • MediaDevices.getUserMedia 的权限和资源生命周期怎样处理？

    getUserMedia 在安全上下文中请求摄像头或麦克风，返回 MediaStream；要区分权限拒绝、设备不存在和设备被占用等错误，不用时对每条轨道调用 stop() 释放设备，指示灯才会熄灭。

  • WebTransport 和 WebSocket 怎样选择？

    WebTransport 基于 HTTP/3 和 QUIC，支持多条独立的双向流和不可靠的数据报，没有队头阻塞；WebSocket 基于 TCP，只有一条有序可靠的消息通道，但服务端支持更广泛。MDN 标为 Baseline 2026。

  • File System Access API 的权限和文件句柄怎样管理？

    showOpenFilePicker 等方法让用户选择本地文件或目录，网页得到文件句柄后可以读写；这部分只在 Chromium 桌面浏览器中可用。所有主流浏览器都支持的是源私有文件系统（OPFS），它不对应用户可见的文件。

  • Web App Manifest 主要描述哪些 PWA 信息？

    Web App Manifest 是一个 JSON 文件，声明应用名称、图标、启动地址、显示模式和主题色，浏览器据此提供安装和启动体验；离线能力由 Service Worker 提供，manifest 本身不负责。

  • OffscreenCanvas 什么时候能减少主线程绘制压力？

    OffscreenCanvas 让 Canvas 绘制在 Worker 中进行，主线程繁忙时动画和图表仍然流畅；它适合绘制本身很重的场景，绘制轻量时线程通信反而增加开销。

  • Web Serial API 适合怎样的硬件交互？

    Web Serial 让网页通过串口与开发板、扫码枪、工控设备通信，数据通过 Streams 读写；它只在 Chromium 桌面浏览器的安全上下文中可用，需要用户手势选择端口。

  • Geolocation API 的权限和定位精度怎样处理？

    navigator.geolocation 在安全上下文中由用户授权后返回经纬度和精度半径；要处理拒绝、超时和无法定位三类错误，按需设置 enableHighAccuracy、timeout 和 maximumAge，持续定位用完要 clearWatch。

  • Web Crypto API 如何正确管理浏览器端密钥？

    crypto.subtle 提供哈希、签名、加解密和密钥派生，只在安全上下文中可用；密钥用 CryptoKey 表示，生成时设 extractable 为 false 可以防止导出，非导出密钥可以存进 IndexedDB 在页面间复用。

  • sendBeacon 返回 true 就代表上报成功了吗？页面离开时怎样发送统计？

    sendBeacon 返回 true 只表示浏览器接受了排队，不代表服务端收到；页面离开时在 visibilitychange 变为 hidden 时用 sendBeacon 或 fetch keepalive 发送，服务端要能处理重复和丢失。

  • URLSearchParams 怎样处理筛选状态、重复参数和编码？

    URLSearchParams 负责解析和序列化查询字符串，get 只取第一个值，getAll 取全部，append 和 set 分别追加和覆盖；它按 application/x-www-form-urlencoded 编码，空格会变成 +。读取的值都是字符串，需要自己校验和转换类型。

  • WebRTC 的 perfect negotiation 如何避免协商碰撞？

    perfect negotiation 给双方分配礼貌和不礼貌两个角色，两边同时发出 offer 时，不礼貌方忽略对方的 offer，礼貌方通过隐式回滚接受对方的 offer；双方代码相同，只是 polite 取值不同。

  • ReadableStream 的 tee 分流有什么代价？

    tee() 把一个流拆成两个读取相同数据的分支；两个分支的读取速度不同时，快的一边读到的数据要为慢的一边缓存在内存里。只有两个分支都取消，源流才会被取消。

  • 表单关联自定义元素怎样参与原生提交和校验？

    自定义元素声明 static formAssociated = true 并调用 attachInternals()，就能通过 ElementInternals 设置提交值、校验状态和无障碍属性，像原生控件一样参与 form 的提交、重置和禁用。

  • Declarative Shadow DOM 适合解决什么问题？

    Declarative Shadow DOM 用 <template shadowrootmode> 在 HTML 里直接声明 Shadow Root，服务端渲染的 Web Component 在脚本加载前就有样式和内容；组件升级时要复用已有的根，不能重新创建。

  • URLPattern 适合做路由匹配吗？

    URLPattern 用和 path-to-regexp 相近的语法匹配 URL 的各个部分并提取命名参数，适合 Service Worker 路由和轻量前端路由；MDN 标为 Baseline 2025。对象形式的基准地址要写在 baseURL 字段里，不能作为第二个参数。
