Web API面试题

Web API 面试题，涵盖 Fetch 流式读取、AbortController、Web Components、文件预览、Clipboard API、WebRTC、WebAssembly 与 DOM 观察器。共 26 道题。

  • AbortController 能取消什么，不能取消什么？

    AbortController 只是发一个"取消"通知，fetch、事件监听这类认识 signal 的 API 收到后自己停下。它打断不了正在跑的同步代码，也撤销不了服务端已经执行的操作。

  • Custom Elements、Shadow DOM 和 template 分别负责什么？

    Custom Elements 定义新标签和它的生命周期，Shadow DOM 把组件内部的结构和样式隔离开，template 存一段不渲染的模板。三者合起来就是 Web Components，任何框架里都能用。

  • File、Blob 和 object URL 怎样用于文件预览？

    Blob 是一段二进制数据，File 是带文件名的 Blob。预览时用 URL.createObjectURL() 生成一个临时地址给 img 用，用完要 revokeObjectURL() 释放。

  • 怎样正确消费 Fetch 返回的 ReadableStream？

    response.body 是一个字节流，数据到一块就能处理一块。文本要用 TextDecoderStream 解码，按行解析时要把没拼完的半行留到下一块，提前停止时要取消流。

  • Permissions.query 是申请权限，还是查询权限？

    只是查询。navigator.permissions.query() 告诉你当前是已允许、已拒绝还是待询问，不会弹授权框；真正申请权限要调用功能本身，比如 getUserMedia。

  • 异步 Clipboard API 为什么会出现权限或用户激活错误？

    剪贴板里可能有密码等隐私，所以浏览器管得很严：只在 HTTPS 或 localhost 下能用，写入一般要在用户点击里调用，读取要用户授权或确认。

  • AudioContext 与音频节点图怎样组织音频处理？

    Web Audio 像接音响线：音源节点经过音量、滤波、分析等节点，最后接到 destination 也就是扬声器。AudioContext 受自动播放策略限制，要在用户点击后 resume。

  • WebRTC 为什么需要信令、STUN 和 TURN？

    WebRTC 只管点对点传数据，双方先要交换媒体参数和网络地址，这条信令通道得自己做。STUN 帮设备查到自己的公网地址，TURN 在实在连不上时帮忙中转。

  • WebAssembly 能替代 JavaScript 吗？适合哪些工作？

    不能替代。WebAssembly 是浏览器里运行的二进制格式，适合把 C、C++、Rust 写的库或大量计算搬到网页；它不能直接操作 DOM，和 JavaScript 互相调用有开销，通常是两者配合。

  • ResizeObserver 为什么可能出现循环通知错误？

    ResizeObserver 在元素尺寸变化后通知你。如果回调里又改了被观察元素的尺寸，浏览器会在同一帧里反复通知，处理不完就推迟到下一帧，并报 "ResizeObserver loop completed with undelivered notifications"。

  • MutationObserver 和 ResizeObserver 分别观察什么？

    MutationObserver 看 DOM 有没有被改，比如节点增删、属性和文字变化；ResizeObserver 看元素尺寸有没有变。尺寸变了 DOM 不一定变，两者不能互相替代。

  • MediaDevices.getUserMedia 的权限和资源生命周期怎样处理？

    getUserMedia 在 HTTPS 页面里申请摄像头或麦克风，返回一个 MediaStream。要分清权限被拒、没有设备、设备被占用等错误；不用时对每条轨道调用 stop()，摄像头指示灯才会灭。

  • WebTransport 和 WebSocket 怎样选择？

    WebSocket 是一条可靠有序的通道，一条消息卡住后面都要等；WebTransport 基于 HTTP/3，能开多条互不影响的流，还能发不保证送达的数据报，但服务端支持还少。MDN 标为 Baseline 2026。

  • File System Access API 的权限和文件句柄怎样管理？

    showOpenFilePicker 等方法让用户选一个本地文件或目录，网页拿到"文件句柄"后就能读写，但只有 Chromium 桌面浏览器支持。所有主流浏览器都支持的是 OPFS，它是网站私有的文件空间，用户在系统里看不到。

  • Web App Manifest 主要描述哪些 PWA 信息？

    Manifest 是一个 JSON 文件，写着应用的名字、图标、启动地址、显示方式和主题色，浏览器据此提供"安装到桌面"的体验。离线能力靠 Service Worker，不归它管。

  • OffscreenCanvas 什么时候能减少主线程绘制压力？

    OffscreenCanvas 让 Canvas 在 Worker 里绘制，主线程忙的时候动画和图表照样流畅。它只在绘制本身很重时才划算，画得很轻时，线程间传消息的开销反而更大。

  • Web Serial API 适合怎样的硬件交互？

    Web Serial 让网页通过串口和开发板、扫码枪、工控设备通信，数据用 Streams 读写。只有 Chromium 桌面浏览器支持，要在 HTTPS 页面里由用户点击后选择端口。

  • Geolocation API 的权限和定位精度怎样处理？

    navigator.geolocation 在 HTTPS 页面里经用户同意后返回经纬度和误差范围。要处理拒绝、定位失败和超时三种错误，按需设置精度和缓存参数，持续定位用完要 clearWatch。

  • Web Crypto API 如何正确管理浏览器端密钥？

    crypto.subtle 能做哈希、签名、加解密和密钥派生，只在 HTTPS 等安全上下文中可用。生成密钥时把 extractable 设为 false，脚本就拿不到原始字节，这种密钥还能存进 IndexedDB 下次接着用。

  • sendBeacon 返回 true 就代表上报成功了吗？页面离开时怎样发送统计？

    不代表。返回 true 只说明浏览器把数据放进了发送队列，服务端收没收到页面不知道。页面离开时在 visibilitychange 变成 hidden 时发送，服务端要能接受重复和丢失。

  • URLSearchParams 怎样处理筛选状态、重复参数和编码？

    URLSearchParams 负责解析和生成查询字符串。get 只取第一个值，getAll 取全部；set 覆盖，append 追加。空格会编码成 +，读出来的值都是字符串，要自己转换和校验。

  • WebRTC 的 perfect negotiation 如何避免协商碰撞？

    两端同时发起协商会撞车。perfect negotiation 给一端"礼貌"、一端"不礼貌"的角色：撞车时不礼貌的一方不理对方的 offer，礼貌的一方回滚自己的 offer 去应答。两端代码一样，只有 polite 不同。

  • ReadableStream 的 tee 分流有什么代价？

    tee() 把一个流复制成两个分支。两边读得一快一慢时，慢的那边没读的数据全堆在内存里；只取消一边不会停掉源流，两边都取消才会。

  • 表单关联自定义元素怎样参与原生提交和校验？

    自定义元素默认不会被 form 当成控件。声明 static formAssociated = true 并调用 attachInternals()，就能设置提交值和校验状态，像原生 input 一样参与提交、重置和禁用。

  • Declarative Shadow DOM 适合解决什么问题？

    以前 Shadow DOM 只能用 JavaScript 创建，服务端渲染的组件在脚本加载前没有样式。声明式写法把 Shadow Root 直接写进 HTML，组件脚本加载后要复用这个根，不能重建。

  • URLPattern 适合做路由匹配吗？

    URLPattern 用类似 /users/:id 的写法匹配网址并取出参数，适合 Service Worker 路由和轻量前端路由，MDN 标为 Baseline 2025。用对象形式时基准地址要写进 baseURL 字段，不能当第二个参数传。
