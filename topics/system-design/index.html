场景设计面试题

前端场景设计面试题，按需求给出实现方案：大文件上传、无限滚动、搜索补全、权限系统、实时协作等。共 37 道题。

  • 前端权限控制怎样设计路由、按钮和接口三层？

    前端根据服务端下发的权限码控制路由能不能进、菜单与按钮显不显示，并在请求拦截里统一处理 401 和 403。这些都只是展示控制，可以被绕过，真正的授权必须由服务端对每个请求、每个资源校验。

  • 扫码登录是怎样实现的？

    PC 端向服务端申请一个带有效期的一次性二维码 ID，用轮询、长轮询或 WebSocket 等待状态变化；已登录的手机 App 扫码后带着自己的登录凭证确认，服务端把这个 ID 标记为已确认并给 PC 端签发新的会话。

  • 怎样实现网站的暗黑模式和主题切换？

    颜色全部写成 CSS 变量，按根元素上的 data-theme 切换两套取值；默认跟随 prefers-color-scheme，用户手动选择后存进 localStorage；用 color-scheme 让滚动条和表单控件一起变色；在 head 里用一段同步脚本提前设好主题，避免刷新时闪一下白。

  • 骨架屏怎样实现？和 loading 有什么区别？

    骨架屏是在数据回来之前，先按真实内容的布局画出灰色占位块，数据到了再替换成内容。和转圈的 loading 相比，它让用户提前看到页面结构，也因为占位尺寸和真实内容一致而减少布局跳动；但它不会让数据更快到达。

  • 前端怎样防止重复提交和接口重复请求？

    提交按钮在请求进行中禁用，并在处理函数里加一个“进行中”标记；相同参数的读请求用一个 Map 缓存进行中的 Promise，后来的调用直接复用；真正保证不重复下单要靠服务端的幂等键，前端只能减少重复。

  • 怎样实现拖拽排序？HTML5 拖放 API 和 Pointer 事件怎么选？

    拖拽排序的核心是拖动时根据指针位置算出目标下标，松手后把数据数组里的元素移过去，再由数据重新渲染列表。HTML5 拖放 API 能拖文件、能跨窗口，但拖动样式难控制；Pointer 事件配合 setPointerCapture 能完全自己控制跟随和动画，统一鼠标和触摸。两种都要提供键盘或按钮的替代操作。

  • 单点登录（SSO）怎样实现？

    SSO 让用户在统一认证中心登录一次，就能进入多个系统。同一个父域下可以共享 Cookie；跨域时通用做法是各系统跳转到认证中心，认证中心用自己域名下的会话判断是否已登录，再通过授权码把登录结果交回各系统，标准化方案是 OIDC。文中讲跳转流程、各系统自己的会话、静默登录和退出登录。

  • 前端怎样做灰度发布和 A/B 实验？

    灰度是让一部分用户先用新功能，确认没问题再放量；A/B 实验是把用户随机分成几组，对比指标判断哪个方案更好。两者都靠稳定分流：用用户 ID 加实验名做哈希分桶，同一个用户每次都落在同一组。前端要避免页面闪烁，在分组生效时上报曝光，并把分组带进埋点和错误日志。

  • 怎样实现一个全局 Toast/Message 组件？

    全局提示要能在任意代码里一行调用，所以把“提示队列”做成和界面无关的 store，提供 show、close 和 subscribe，再由一个挂在根节点的容器订阅它并渲染。还要处理同时显示的数量上限、自动关闭与悬停暂停、重复关闭，以及用 role="status" 让读屏软件播报。

  • 怎样实现瀑布流布局和图片懒加载？

    瀑布流的核心是每张卡片放进当前最矮的一列，用 JavaScript 实现时按图片宽高比算出高度再绝对定位，所以接口最好返回图片尺寸。懒加载优先用 img 的 loading="lazy"，要更早预加载或配合加载更多时用 IntersectionObserver 加 rootMargin。首屏图片不要懒加载，图片要预留尺寸，避免布局跳动。

  • 富文本编辑器的原理是什么？contenteditable 有什么问题？

    浏览器富文本编辑的基础是 contenteditable，元素加上它就能直接输入和选中。早期编辑器靠 execCommand 加粗、插入列表，但 MDN 已把它标为弃用且不标准，不同浏览器生成的 HTML 不一致。现代编辑器通常维护自己的文档模型，用 Selection 记录光标，拦截 beforeinput 等事件，由模型重新渲染 DOM；粘贴内容要清洗，输出 HTML 要防 XSS。

  • 页面水印怎样实现？怎样防止被删除？

    前端水印通常用 canvas 画出带用户名和时间的倾斜文字，转成图片铺满一个覆盖全屏、pointer-events 为 none 的图层；再用 MutationObserver 监听水印节点被删除或样式被改，发现后重新加上。但页面代码运行在用户的浏览器里，前端防删只能增加难度，真正可靠的是服务端在图片或文件里加水印。

  • 图片上传前怎样在浏览器里压缩？

    把用户选的图片解码成位图，按目标尺寸画到 canvas 上，再用 canvas.toBlob 以 JPEG 或 WebP 和指定质量导出，得到更小的 Blob 上传。createImageBitmap 可以直接从 File 解码并缩放，默认按 EXIF 方向摆正图片；导出的新图不保留原图的 EXIF 等元数据。

  • 弹窗组件怎样设计？

    弹窗组件要解决三件事：挂载位置，用原生 dialog 的 showModal 进入顶层，或者用 Portal 挂到 body 下，避免被父元素的 overflow 和层叠上下文裁掉；调用方式，除了声明式的 open 属性，再封装一个返回 Promise 的命令式 confirm()；焦点管理，打开时焦点移进弹窗、Tab 不跑出去、Esc 关闭、关闭后回到触发按钮。

  • 怎样设计一个通用的表格组件？

    通用表格用列配置描述“显示什么”，用数据数组描述“显示哪些行”，单元格内容通过 render 函数交给调用方。排序、筛选、分页的状态可以由组件内部管理，也可以受控交给外部，服务端分页时必须受控。行要有稳定的 rowKey；语义上用原生 table、th 和 scope，排序列用 aria-sort 标出；数据量大时再加虚拟滚动和固定表头。

  • 数据大屏怎样适配不同分辨率？

    大屏通常按固定设计稿（如 1920×1080）开发，再用 transform scale 整体缩放到窗口大小。按宽高中较小的比例等比缩放会在一边留白，分别按宽高缩放会拉伸变形。rem/vw 方案让布局随宽度变化，但宽高比不同时高度难以对齐。窗口或容器尺寸变化时用 resize 或 ResizeObserver 重新计算比例，用 rem、vw 等让布局尺寸真正变化的方案时，图表也要跟着重绘。

  • 怎样实现拖拽上传图片或文件？

    在放置区域监听 dragover 并调用 preventDefault，元素才会成为有效的放置目标、drop 事件才会触发；drop 里也要 preventDefault，防止浏览器直接打开文件，然后从 event.dataTransfer.files 取出文件。拖入文件夹要用 webkitGetAsEntry 递归读取。文件统一经过类型、大小、数量校验再上传；粘贴上传从 paste 事件的 clipboardData.files 取文件，同样走这套流程。

  • 动态表单怎样设计？schema 驱动、字段联动和联动校验怎么做？

    动态表单用一份 schema 描述有哪些字段、用什么组件、什么时候显示、怎样校验，渲染器按 schema 生成表单。联动写成声明式条件，比如“type 等于 company 时显示”，由引擎根据当前值算出每个字段的状态。联动校验指一个字段的规则依赖另一个字段，比如结束日期不能早于开始日期，要在依赖字段变化时重新校验，隐藏的字段不参与校验和提交。

  • 短链接系统怎样设计？短码怎样生成，跳转用 301 还是 302，访问量怎样统计？

    短链接服务把长网址存进数据库，返回一个短码，访问短码时查出长网址并返回重定向。短码常用两种生成方式：用自增 ID 转成 62 进制，不会冲突但可以被顺序猜到；对长网址做哈希再截短，同一网址得到同一短码，但要检测冲突并重试。跳转用 301 时浏览器可以缓存，后续访问不再经过服务器，统计不到；需要统计或可能修改目标时用 302 或 307。统计在跳转时异步记一条访问日志，再离线聚合。

  • 前端怎样导出 Excel、预览 PDF？数据量大时为什么要放进 Worker？

    导出 Excel 常用 SheetJS：把数组转成工作表、放进工作簿，再写成文件触发下载；只要表格文本时也可以按 RFC 4180 拼 CSV。预览 PDF 常用 pdf.js：getDocument 加载文档，getPage 取页，按视口尺寸渲染到 canvas，解析在它自己的 worker 里进行，服务器支持 Range 时还能分块加载。几万行的导出会卡住主线程，所以放进 Web Worker，生成好的数据交回主线程下载。

  • 低代码可视化搭建平台怎样设计？物料、画布、拖拽、协议和出码各负责什么？

    搭建平台围绕一份页面协议（schema）工作：物料描述组件能配置什么，画布把物料拖进来、编排成 schema，渲染器按 schema 和注册过的组件画出页面，出码模块把同一份 schema 转成源码。阿里低代码引擎把它拆成入料、编排、渲染、出码四个模块，协议的作用是让编辑器、渲染和出码能各自升级。

  • 大文件下载和流式下载怎样做？a[download]、Range 断点和 Service Worker 各适合什么场景？

    文件已经在服务器上时，交给浏览器下载最省事：服务器返回 Content-Disposition: attachment，或者用同源的 a[download]。先 fetch 成 Blob 再下载，整个文件要先读进内存。断点续传靠 Range 和 If-Range，服务器返回 206 才能接着写。showSaveFilePicker 能让用户选保存位置，再把响应流 pipeTo 写进文件，但只有部分浏览器支持。Service Worker 可以拦截下载地址，返回一个流式的 Response，让浏览器边收边存。

  • 前端怎样生成截图或分享海报？html2canvas 有哪些限制？

    html2canvas 读取 DOM 和样式，在 canvas 上重新画一遍，不是真的截屏，所以 box-shadow、filter 等部分 CSS 画不出来。版式固定的海报更适合直接用 Canvas 绘制。跨域图片要带 crossorigin 且服务端返回 CORS 头，否则画布被污染，toBlob 会抛 SecurityError。

  • 前端怎样实现图片裁剪？drawImage 的九个参数怎么用？

    用户在缩小显示的预览图上拖出裁剪框，先按 naturalWidth 和显示宽度的比例把裁剪框换算成原图像素坐标，再用 drawImage 的九参数形式把原图的这块区域画到目标尺寸的 canvas 上，最后用 toBlob 导出。预览用的 canvas 要乘 devicePixelRatio 才清晰。现代浏览器默认按 EXIF 方向摆正图片，裁剪坐标应按摆正后的尺寸计算。

  • 视频上传和播放怎样设计？怎样截取封面，HLS 直播延迟从哪里来？

    上传前可以用 object URL 把本地视频交给 video 元素，跳到某个时间点，等 seeked 事件后用 drawImage 把当前帧画到 canvas，再 toBlob 得到封面。播放 HLS 时，Safari 等支持原生 HLS 的浏览器直接设 src，其他浏览器用基于 MSE 的 hls.js。HLS 直播的延迟主要来自分片：规范要求客户端不要从离播放列表末尾不足三个目标时长的分片开始播，分片越长延迟越大；LL-HLS 用几百毫秒的部分分片和阻塞式播放列表刷新来降低延迟。

  • IM 聊天的前端怎样设计？消息顺序、去重、重发和断线重连怎么处理？

    消息顺序以服务端给每个会话分配的递增序号为准，不用客户端时间。发送时先生成客户端消息 ID 并立即显示为发送中，服务端确认后带回序号再改为已发送，超时显示失败并允许用同一个 ID 重发，服务端和客户端都按这个 ID 去重。断线后退避重连，再按本地最后的序号拉取离线消息补齐。WebSocket 不提供协议层心跳 API，要发应用层心跳。长会话用虚拟列表，并在加载历史消息时保持滚动位置。

  • 前端请求层怎样封装？拦截器、去重、错误处理和 token 刷新怎样放在一起？

    把 fetch 或 axios 包成一个统一的 request 函数，请求前统一加 token 和公共参数，响应后统一判断状态码并抛出带状态的错误；相同的 GET 请求复用进行中的 Promise；遇到 401 只刷新一次 token，再重放原请求。业务代码只拿数据或捕获错误。

  • 商品 SKU 规格选择怎样判断哪些规格可选？

    把每个有库存的 SKU 的规格组合及其所有子集预先放进一个 Set；判断某个规格按钮能不能点时，假设选中它、其他行保持当前选择，拼成键去 Set 里查，查不到就置灰。预处理一次，之后每次判断只是一次查表。

  • 弹幕系统前端怎样设计？轨道分配、防重叠和渲染性能怎样处理？

    把画面横向分成若干条轨道，新弹幕找一条“上一条尾部已经进屏、而且自己在它离屏前追不上”的轨道放进去，找不到就排队或丢弃；渲染用 DOM 加 CSS transform 动画或 Canvas 配合 requestAnimationFrame，按时间而不是帧数算位置，并控制同屏数量。

  • 树组件怎样设计？上万个节点时虚拟树怎样实现？

    树组件把嵌套数据按展开状态拍平成一维数组，每项记下层级，渲染时按层级缩进；节点很多时对这个一维数组做虚拟列表，只渲染可视区域。子节点可以展开时再懒加载。勾选联动要向下把子孙全部设成同一状态，向上按子节点重新算父节点是全选、全不选还是半选；半选用复选框的 indeterminate 属性或 aria-checked="mixed" 表达。

  • 级联选择和穿梭框组件怎样设计？

    级联选择把树形数据按层展开成几列，选中一项就用它的子节点生成下一列，值是从根到当前节点的路径数组；子节点可以在选中时懒加载，搜索时要把每条路径拍平再匹配。穿梭框是左右两个可多选列表，内部只维护“已选 ID 集合”和两侧各自的勾选项，移动时只改这个集合，所以顺序和数据都不会被打乱；两侧列表按 WAI-ARIA 的多选 listbox 模式提供键盘操作。

  • 轮播图组件怎样设计？无缝循环和自动播放要注意什么？

    无缝循环常用的做法是在首尾各复制一张，滑到复制的那张后关掉过渡、瞬间跳回真实的那张，用户看不出跳转；也可以只渲染当前和相邻几张，按下标取模。自动播放必须提供暂停和继续按钮，键盘焦点进入轮播或鼠标悬停时要停止轮播，页面隐藏时也应暂停。容器用 aria-roledescription="carousel"，每张用 role="group" 加 aria-roledescription="slide"，自动播放时 aria-live 为 off，停止后改为 polite。

  • 大文件上传怎样设计分片、断点续传、秒传和并发控制？

    用 Blob.slice 把大文件切成固定大小的分片，用文件哈希标识上传任务。上传前问服务端已有哪些分片，实现断点续传和秒传；用并发池限制同时上传的分片数，全部完成后通知服务端合并并校验。

  • 无限滚动和虚拟列表怎样选型？怎样触发加载并恢复滚动位置？

    无限滚动管“什么时候加载下一页”，虚拟列表管“数据太多时只渲染看得见的部分”，数据量大时两者组合。用 IntersectionObserver 观察列表底部的哨兵元素触发加载，返回列表时用缓存数据和记录的位置手动恢复滚动。

  • 搜索联想（自动补全）组件要处理哪些问题？

    搜索联想要处理四件事：输入防抖减少请求，用 AbortController 取消旧请求并校验返回对应的关键词避免竞态，按关键词缓存结果，再按 WAI-ARIA combobox 模式实现方向键、Enter、Escape 和 aria-expanded、aria-activedescendant 等属性。

  • 前端倒计时为什么会走慢？怎样用服务端时间校准？

    setTimeout/setInterval 只保证不早于指定延迟执行，主线程繁忙和后台标签页节流都会让每秒减一的倒计时越走越慢。应该记住目标时间点，每次重新计算剩余时间，用 performance.now 计时避开系统时钟修改，并通过接口往返估算与服务端的时间差。

  • 前端怎样应对秒杀这类高并发场景？

    前端的目标是少发请求、发对时机、给清楚的反馈。倒计时用服务端时间校准，开抢前不暴露真实下单入口；按钮点击后立即置灰并防重复提交；活动页静态化放到 CDN，只把库存、资格这类动态数据单独请求；服务端返回 429 或排队状态时，按 Retry-After 或带随机抖动的间隔重试，并显示排队提示。真正的库存扣减和限流只能在服务端保证。
