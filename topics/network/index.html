网络与安全面试题

前端网络面试题，涵盖 HTTP 缓存、HTTPS、HTTP/2 与 HTTP/3、跨域 CORS、请求状态码、Fetch 异常、WebSocket 和 SSE。共 19 道题。

  • 强缓存与协商缓存如何配合？

    HTTP 缓存先判断响应能否存储与复用，再判断是否需要向服务器验证。新鲜响应可以直接使用，验证器则让过期或要求验证的响应通过条件请求复用正文；304 不是一份新的完整资源。

  • 什么是跨域？CORS 为什么需要服务端配合？

    同源由协议、主机与端口共同决定，CORS 通过服务器响应声明允许的跨源读取。请求是否发送、预检是否通过、凭据是否附带和响应能否被脚本读取，是需要分别判断的阶段。

  • XSS 和 CSRF 有什么区别？分别如何防范？

    通过评论展示和修改资料两个场景区分脚本注入与伪造请求，解释安全渲染、富文本净化、CSP、CSRF Token、SameSite 和来源校验各自解决的问题。

  • HTTPS 相比 HTTP 提供了哪些保障？

    HTTPS 通过 TLS 保护通信内容的机密性与完整性，并验证所连接服务器的相应身份。它不证明业务可信、不自动完成用户登录，也不替代应用权限与内容安全；证书、代理终止和资源混用都需要分别判断。

  • HTTP/1.1、HTTP/2 和 HTTP/3 的主要区别是什么？

    三个版本主要改变消息传输与连接组织方式，核心 HTTP 语义仍然相通。HTTP/2 在 TCP 上多路复用，HTTP/3 在 QUIC 上组织独立流，性能收益还取决于丢包、拥塞、服务端与实际资源依赖。

  • HTTP 方法的安全性和幂等性是什么意思？

    安全性描述请求是否要求改变目标资源状态，幂等性描述重复相同请求的预期效果是否与一次相同。它们不是网络安全或必定成功的保证，响应不同也不必然破坏幂等，服务端仍需正确实现契约。

  • 常见 HTTP 状态码应该怎样在前端区分处理？

    状态码描述 HTTP 处理结果，但正文格式、业务状态、重定向与重试策略仍需单独判断。204、202、304、认证失败和限流各有不同含义，不能全部归成成功或网络异常。

  • 为什么 fetch 收到 404 不一定进入 catch？

    fetch 区分取得响应、读取正文和业务验证。404/500 通常仍会兑现请求 Promise，HTTP 失败需主动判断；网络、策略、取消与正文解析又有不同拒绝路径，响应体也不是可无限重复读取的字符串。

  • Cache-Control 的 immutable、stale-while-revalidate 和 no-store 怎样选择？

    缓存策略要分别决定存储权限、新鲜期、共享范围和允许的过期使用方式。immutable 与内容版本绑定，stale-while-revalidate 接受短暂旧数据，no-store 限制 HTTP 缓存存储，它们都需要与资源语义及发布方式匹配。
