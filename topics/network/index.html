网络面试题

前端网络面试题，涵盖 HTTP 缓存、HTTPS、HTTP/2 与 HTTP/3、跨域 CORS、请求状态码、Fetch 异常、WebSocket 和 SSE。共 35 道题。

  • 强缓存与协商缓存如何配合？

    缓存还新鲜时浏览器直接用本地副本，这是强缓存；过期了就带上 ETag 问服务器有没有变，没变回 304 继续用旧的，这是协商缓存。

  • 什么是跨域？CORS 为什么需要服务端配合？

    协议、主机、端口有一个不同就算跨源。浏览器默认不让脚本读跨源响应，CORS 是服务器用响应头告诉浏览器"允许这个来源读"；它保护的是用户浏览器里的数据，不是服务器的权限控制。

  • 跨域有哪些解决方案？JSONP 和代理是怎样工作的？

    首选服务端配置 CORS；开发环境用开发服务器代理，生产环境用 Nginx 这类反向代理，让浏览器只请求同源地址；JSONP 利用 script 标签不受同源策略限制来拿数据，只支持 GET，而且等于执行对方返回的脚本，现在基本不用；跨窗口通信用 postMessage。

  • DNS、TCP 和 TLS 握手分别会给页面增加哪些等待？

    新连接要先查 DNS、再做 TCP 握手、再做 TLS 握手，之后才能发请求。TCP 加 TLS 1.3 至少两个往返，HTTP/3 合成一个。用 Navigation Timing 的时间戳可以把每一段量出来。

  • TCP 三次握手和四次挥手是怎样进行的？为什么握手要三次？

    握手时客户端发 SYN，服务器回 SYN+ACK，客户端再回 ACK，双方都确认了对方能收能发、对齐了初始序号。三次的主要原因是防止网络里滞留的旧连接请求被误当成新连接。挥手要四次，是因为两个方向要各自关闭，先关的一方最后还要等 TIME-WAIT。

  • DNS 解析的过程是怎样的？

    浏览器先查自己的缓存，再交给操作系统查系统缓存和 hosts 文件，还没有就问递归解析器。递归解析器从根服务器开始，经顶级域服务器、权威服务器一级级问下去，拿到结果后按 TTL 缓存。浏览器对递归解析器发的是递归查询，递归解析器对各级服务器做的是迭代查询。

  • HTTPS 相比 HTTP 提供了哪些保障？

    HTTPS 就是把 HTTP 放在 TLS 加密连接里传。它保证内容别人看不到、改不了，并证明你连的就是这个域名的服务器；但它不保证网站本身可信。

  • HTTP/1.1、HTTP/2 和 HTTP/3 的主要区别是什么？

    三个版本的方法、状态码、头部含义都一样，区别在怎么传。HTTP/1.1 一个连接一次只处理一个请求；HTTP/2 一条 TCP 连接里同时跑多个请求；HTTP/3 换成基于 UDP 的 QUIC，丢包只影响出问题的那个请求。

  • TCP 和 UDP 有什么区别？

    TCP 先建连接，再按顺序、可靠地传一条字节流，丢了会重传；UDP 不建连接，一个个数据报直接发，不保证送达和顺序。HTTP/3 用的 QUIC 跑在 UDP 上，自己实现了可靠传输和加密；WebRTC 的音视频和数据通道通常也走 UDP。

  • OSI 七层和 TCP/IP 四层模型分别是什么？前端常接触哪几层？

    OSI 是 ISO/ITU 定义的七层参考模型，从下往上是物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。实际互联网用的是 TCP/IP 模型，RFC 1122 分成链路层、网际层、传输层、应用层四层。前端主要接触应用层的 HTTP、DNS、WebSocket，以及传输层的 TCP、UDP 和 TLS。

  • TCP 的拥塞控制和流量控制有什么区别？

    流量控制防止发送方把接收方的缓冲区塞满，靠接收方通告的窗口 rwnd；拥塞控制防止把网络塞满，靠发送方自己维护的拥塞窗口 cwnd。实际能发的数据量取两者较小值。拥塞控制包括慢启动、拥塞避免、快速重传和快速恢复。

  • GET 和 POST 有什么区别？

    按 HTTP 规范，GET 是安全且幂等的方法，用来读取资源，参数通常放在 URL 里，响应默认可以缓存；POST 不安全也不幂等，用来提交数据，数据放在请求体里，响应一般不缓存。“GET 有长度限制”来自浏览器和服务器对 URL 的限制，“POST 更安全”只是参数不出现在地址栏，不加密，安全要靠 HTTPS。

  • HTTP Keep-Alive 和持久连接是怎么回事？

    持久连接是指一条 TCP 连接上连续发送多个请求和响应，省掉重复的建连握手。HTTP/1.1 默认就是持久连接，Connection: close 才会关闭；HTTP/1.0 要靠 Connection: keep-alive 协商。HTTP/2 和 HTTP/3 禁止使用 Connection、Keep-Alive 这类头。

  • GraphQL 和 REST 有什么区别？前端怎样使用 GraphQL？

    REST 按资源划分多个 URL，每个接口返回的字段由服务端决定；GraphQL 只有一个端点，服务端用类型系统描述数据，客户端在查询里写明要哪些字段，一次请求可以拿到多个关联的数据。前端用 POST 把查询和变量发到 /graphql，要同时检查 HTTP 状态码和响应里的 errors，因为部分成功也会返回 2xx。代价是 HTTP 缓存不好用、服务端要处理 N+1 和查询复杂度。

  • DNS 劫持和运营商劫持是什么？HTTPS 能防住哪些？

    DNS 劫持是把域名解析成错误的 IP，让用户连到别的服务器；运营商劫持常见于明文 HTTP，在传输途中改页面、插广告或跳转。HTTPS 靠证书和完整性校验，让假服务器冒充不了域名、途中改不了内容，但挡不住解析被拦截导致打不开；HSTS 防止降级到 HTTP，DoH（RFC 8484）和 HTTPDNS 绕开被污染的本地解析，SRI 和 CSP 约束页面加载的资源。

  • 短轮询、长轮询、SSE 和 WebSocket 有什么区别？怎么选？

    短轮询是隔一段时间问一次，没数据也回空响应；长轮询是服务器把请求挂住，有数据才回；SSE 是一条一直不结束的 HTTP 响应，服务器单向推；WebSocket 是双向连接。按“谁要发消息、多实时、基础设施支持什么”来选。

  • 常见 HTTP 状态码应该怎样在前端区分处理？

    2xx 成功、3xx 重定向、4xx 是请求方的问题、5xx 是服务器的问题。前端按具体状态码处理：401 去登录，403 提示没权限，429 和 503 等一会再试，其他 4xx 不要重试。

  • CDN 的原理是什么？前端怎样用好 CDN？

    CDN 把内容的副本放在离用户近的服务器上，用户就近访问，没命中缓存时再回源站取。前端用好它的关键是缓存策略：带哈希的静态文件长期缓存，HTML 每次验证，缓存键去掉无关参数，内容出错时按 URL 或标签刷新。

  • HTTP 方法的安全性和幂等性是什么意思？

    安全方法只读不改，比如 GET；幂等方法执行一次和执行多次效果一样，比如 PUT、DELETE。POST 和 PATCH 不保证幂等，重试前要靠幂等键防止重复。

  • 为什么 fetch 收到 404 不一定进入 catch？

    fetch 只有在拿不到响应时才会失败，比如断网、被 CORS 拦截、请求被取消。404、500 都算正常拿到了响应，要自己检查 response.ok 再抛错。

  • Cache-Control 的 immutable、no-store 等指令怎样选？

    带哈希的静态资源用很长的 max-age 加 immutable；可以接受一点旧数据的用 stale-while-revalidate；敏感数据用 no-store；要求每次确认最新但允许存的用 no-cache。

  • WebSocket 适合什么场景，连接断开后怎样恢复？

    WebSocket 适合聊天、协同编辑这类低延迟、双向、高频的通信。它不自带重连和消息确认，恢复要两步：先退避重连把连接接上，再按消息序号补齐断线期间的数据。

  • SSE 的事件格式、自动重连和 Last-Event-ID 是怎样工作的？

    SSE 是一个 text/event-stream 的普通 HTTP 响应，服务器按 id、event、data、retry 字段逐条写事件；EventSource 断线后按 retry 间隔自动重连，并用 Last-Event-ID 请求头告诉服务器最后收到哪条，服务器据此补发。

  • dns-prefetch 和 preconnect 分别把连接的哪几步提前了？

    请求一个新的跨域源要先查 DNS、建 TCP 连接，HTTPS 还要做 TLS 握手。dns-prefetch 只提前做 DNS 查询；preconnect 把 DNS 和 TCP 都做完，HTTPS 源连 TLS 握手也做完。两者都只对跨域源有用，preconnect 只留给最关键的几个源，字体这类匿名 CORS 请求要加 crossorigin。

  • Service Worker 有哪些缓存策略？HTML、静态资源和接口分别怎么缓存？

    Service Worker 在 fetch 事件里决定每个请求怎么返回。安装时预缓存应用外壳；缓存优先适合带哈希的静态资源；网络优先适合 HTML 入口和要尽量新的数据；先返回缓存再后台刷新适合响应快更重要、稍旧也能接受的内容；POST 和必须最新的数据只走网络。缓存响应前要 clone，只缓存成功的响应。

  • 浏览器分片上传如何实现可靠的暂停与续传？

    把大文件切成小块分别上传，服务端记下收到了哪些块。暂停就是取消进行中的请求；续传时先问服务端缺哪些，只补传缺的，最后由服务端合并并校验。

  • fetchpriority 能解决资源加载优先级问题吗？

    fetchpriority 只能调整已经被发现的资源有多急，最常见的用法是给首屏主图设 high、给轮播里看不到的图设 low。资源发现得太晚、被懒加载或者网络本身慢，它都管不了。

  • CDN 和反向代理缓存异常应该怎样排查？

    把链路拆成浏览器、CDN 边缘、中间层、反向代理和源站，一层层对比响应头和缓存键，找出是哪一层给了旧内容或错误响应。关键证据是 Age、Cache-Status 或厂商缓存头、ETag 和 Vary。

  • 前端网络问题应该怎样按协议层排查？

    前端看到的"请求失败"可能出在地址、DNS、连接和 TLS、HTTP、浏览器策略、缓存与 Service Worker、数据解析中的任何一层。先在 DevTools 里保存证据，再一层层排除。

  • HTTP Range 请求适合什么场景？

    Range 请求只拿文件的一段字节，用在断点续传、视频拖动和读大文件的局部。服务器支持就回 206，不支持就回完整的 200，范围不对回 416；续传时带上 If-Range，防止文件更新后新旧内容拼在一起。

  • 浏览器直传对象存储时，如何设计安全的分片上传？

    业务服务器负责鉴权、创建上传会话、给每个分片签发短期上传地址，最后负责合并；浏览器直接把分片传到对象存储。安全的关键是签名范围、过期时间、存储路径由服务端决定，以及合并前校验、清理没传完的上传。

  • HTTP 内容协商会怎样影响前端资源和接口响应？

    同一个 URL 可以按请求头返回不同版本：Accept 挑格式，Accept-Language 挑语言，Accept-Encoding 挑压缩方式。服务器必须用 Vary 说明依据了哪些头，否则缓存会把一个版本发给所有人。

  • Cache-Status 响应头能帮助诊断哪些缓存问题？

    Cache-Status 让链路上每一层缓存都在响应里留一条记录，说明有没有命中、为什么去找上游、有没有存下来。它是 RFC 9211 定义的标准头，排查 CDN 多层缓存比 Age 或 X-Cache 清楚。

  • HTTP 103 Early Hints 适合怎样的加载优化？

    服务器生成 HTML 要花时间时，可以先回一个 103，带上 preconnect 和 preload 提示，让浏览器趁等待先建连、先下关键资源。它取代了已被 Chrome 移除的 HTTP/2 Server Push。

  • Compression Dictionary Transport 怎样减少重复下载？

    服务端给旧版资源加上 Use-As-Dictionary 响应头，浏览器就把它存成字典；下次请求匹配的新版本时，请求头带上 Available-Dictionary，服务端只需发送以旧版为字典压缩的差量（dcb 或 dcz 编码）。它是实验性功能，目前不是 Baseline，要能退回普通压缩。
