网络与安全面试题

前端网络面试题，涵盖 HTTP 缓存、HTTPS、HTTP/2 与 HTTP/3、跨域 CORS、请求状态码、Fetch 异常、WebSocket 和 SSE。共 19 道题。

  • 强缓存与协商缓存如何配合？

    理解 Cache-Control、ETag 与 304 的关系。

  • 什么是跨域？CORS 为什么需要服务端配合？

    明确同源的判定方式，以及预检请求的作用。

  • XSS 和 CSRF 有什么区别？分别如何防范？

    区分注入脚本执行与借用登录态发起请求。

  • HTTPS 相比 HTTP 提供了哪些保障？

    从加密、完整性和身份认证理解 TLS。

  • HTTP/1.1、HTTP/2 和 HTTP/3 的主要区别是什么？

    HTTP/1.1 支持持久连接等机制，但并发请求通常受到连接组织方式限制。HTTP/2 引入二进制帧、多路复用与头部压缩，让多个流共享连接；底层仍使用 TCP，因此传输层丢包可能影响该连接上的多个流。

  • HTTP 方法的安全性和幂等性是什么意思？

    安全方法的语义不要求修改服务端资源状态，例如 GET；幂等表示多次相同请求的预期服务端效果与一次相同。幂等不要求每次响应状态码或响应体完全相同。

  • 常见 HTTP 状态码应该怎样在前端区分处理？

    2xx 表示成功，但 204 没有响应正文，不能无条件按 JSON 解析。304 与缓存验证有关，并非完整资源正文。401 通常需要有效认证，403 表示服务端拒绝访问，不能简单统一跳到登录页。

  • 为什么 fetch 收到 404 不一定进入 catch？

    fetch 在收到 HTTP 错误状态时通常仍会兑现 Promise，因为浏览器成功获得了一个响应。网络失败或取消等情况才可能使请求 Promise 拒绝。应检查 response.ok 或具体 status，再决定业务处理。

  • WebSocket 适合什么场景，连接断开后怎样恢复？

    WebSocket 提供建立连接后的双向通信，适合聊天、协同操作和实时状态更新。连接建立成功不表示后续网络持续可靠，业务需要考虑心跳、断线检测和重新连接。

  • SSE 与 WebSocket 有什么区别？

    SSE 主要用于服务端向浏览器单向推送文本事件，浏览器可使用 EventSource 消费，响应类型通常为 text/event-stream。事件以规定的字段和空行分隔，不是随意发送文本就能正确解析。

  • dns-prefetch、preconnect 和 preload 应该怎样选择？

    从 DNS 解析、连接建立和资源获取阶段区分三种资源提示，避免把它们当成同一种加速手段。

  • HTTP Range 请求适合什么场景？

    理解字节范围请求、206 响应和断点续传的协作方式，以及前端能控制和不能控制的部分。

  • fetchpriority 能解决资源加载优先级问题吗？

    了解 fetchpriority 的提示性质、适用元素和局限，区分它与 preload、请求阻塞和浏览器调度策略。

  • Service Worker 缓存更新为什么容易出现旧版本？

    理解 install、activate、fetch、缓存版本和 skipWaiting 的关系，设计可回滚的离线资源更新策略。

  • Cache-Control 的 immutable、stale-while-revalidate 和 no-store 怎样选择？

    按资源是否可复用、是否含敏感信息和是否允许后台更新来选择 HTTP 缓存策略。

  • HTTP 103 Early Hints 适合怎样的加载优化？

    解释 103 响应如何在最终响应前提示关键资源，理解它与 preload、服务端和代理支持的关系。

  • WebSocketStream 为什么被认为能改善背压处理？

    对比传统 WebSocket 事件模型和 WebSocketStream 的 Streams 接口，说明其试验性与兼容性边界。

  • HTTP 内容协商会怎样影响前端资源和接口响应？

    理解 Accept、Accept-Language、Accept-Encoding 和 Vary 的关系，避免缓存不同版本响应时串内容。

  • Cache-Status 响应头能帮助诊断哪些缓存问题？

    使用 Cache-Status 观察缓存命中、未命中和转发链路，理解它不是浏览器缓存策略的替代品。
