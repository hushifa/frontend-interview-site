框架与选型面试题

前端框架选型面试题，了解 Angular Signals、Svelte Runes 与编译模型，并从项目约束和维护成本出发比较框架方案。共 13 道题。

  • 前端组件库怎样设计才能让业务方稳定使用？

    组件库的公共 API 不只是 props，还包括默认行为、键盘与焦点、样式扩展方式和发布产物。设计时明确受控与非受控模式、提供稳定的样式入口、把无障碍行为当作契约，再用文档、测试和语义化版本让升级可预期。

  • React 18 项目升级到 React 19，怎样分步迁移并验证行为？

    先升级到 React 18.3 把弃用警告处理掉，再升级到 19 并运行官方 codemod。主要破坏性变更包括移除 ReactDOM.render、所有组件的 propTypes 检查、函数组件的 defaultProps、string ref、legacy context；ref 可以直接作为 prop。使用 Server Components 时要升级到修复了 CVE-2025-55182 的补丁版本。

  • Nuxt 的 useFetch 和 useAsyncData 怎样避免重复请求？

    服务端渲染时请求到的数据会写进页面 payload，客户端 hydration 时直接复用，不再请求一次。相同 key 的调用共享同一份 data、error 和 status。Nuxt 4 中 data 默认是 shallowRef、初始值是 undefined，共享 key 的调用要使用一致的 handler、transform 等选项。

  • 选择前端框架时应该先比较哪些约束？

    先把产品形态、渲染方式、部署环境、关键依赖和团队经验这些硬约束列出来，排除不满足的方案；再挑一条真实的复杂业务流程做原型，比较开发效率、性能和维护成本。语法偏好和基准测试排名不应作为主要依据。

  • Svelte 的编译思路与 Runes 模型如何理解？

    Svelte 在构建时把组件编译成直接更新 DOM 的 JavaScript，不使用虚拟 DOM，但仍有一个小型运行时。Svelte 5 用 Runes 显式声明响应式：$state 声明状态，$derived 声明派生值，$effect 声明副作用，$props 接收属性。

  • SvelteKit 的路由、load 和服务端边界怎样协作？

    SvelteKit 用目录结构定义路由。+page.js 中的 load 在服务端和浏览器都可能运行，+page.server.js 中的 load 和表单 actions 只在服务端运行，可以访问数据库和密钥。load 返回的数据会发送到浏览器，部署能力由 adapter 决定。

  • Solid 的 Signals 和 React 状态更新有什么不同？

    React 在状态变化后重新执行组件函数并协调虚拟 DOM；Solid 的组件函数只执行一次，之后靠 signal 的读取关系直接更新对应的 DOM 节点。所以在 Solid 中要在 JSX、createMemo 或 createEffect 里调用 signal 才能建立依赖，解构 props 会丢失响应性。

  • Astro Islands 架构怎样减少客户端 JavaScript？

    Astro 默认把组件在服务端渲染为 HTML，不发送 JavaScript；只有加了 client:* 指令的组件才作为“岛屿”在浏览器中加载和激活。岛屿彼此独立，可以使用不同框架。适合内容为主、交互局部化的站点。

  • Angular Signals 的依赖追踪与 computed 有什么特点？

    Signal 是一个装着值的盒子，调用它就能读取，读取过程会被记录为依赖。computed 只在被读取时才惰性计算并缓存结果；effect 在依赖变化后执行副作用。linkedSignal、resource、input() 和 model() 都建立在同一套机制上。

  • Angular 依赖注入的层级和作用域怎样理解？

    组件需要一个服务时，Angular 根据 token 在注入器树中查找 provider：先从当前元素注入器向上找组件和指令的 providers，再到环境注入器（路由、应用根）。服务是否为单例，取决于 provider 注册在哪一层。

  • Angular 中 Observable 和 Signals 怎样协作？

    Observable 适合描述随时间到达的事件和异步流，可以组合、取消；Signal 适合表示随时能同步读取的当前状态。用 toSignal 把 Observable 转为 Signal 给模板用，用 toObservable 把 Signal 的变化接入 RxJS 管道。

  • Angular Hydration 解决什么问题？

    Hydration 让客户端 Angular 复用服务端渲染出的 DOM，而不是销毁后重新创建，从而避免页面闪烁、减少重复工作。它要求服务端和客户端渲染出相同的 DOM 结构，直接操作 DOM 的代码需要改写或跳过。

  • Angular Zoneless 模式会改变哪些更新假设？

    Zoneless 模式不再用 Zone.js 拦截所有异步任务来触发变更检测，而是依靠 Signal 更新、模板事件、markForCheck 等明确的通知。Angular v21 起新项目默认 zoneless；原来依赖“任何异步回调后自动刷新”的代码需要改写。
