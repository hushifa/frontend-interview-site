框架与选型面试题

前端框架选型面试题，了解 Angular Signals、Svelte Runes 与编译模型，并从项目约束和维护成本出发比较框架方案。共 10 道题。

  • Angular Signals 的依赖追踪与 computed 有什么特点？

    Signal 通过读取函数记录响应式消费者，computed 从实际读取到的 Signal 推导并缓存只读结果。依赖会随执行分支变化，但对象突变、异步边界和副作用仍需显式设计。

  • Svelte 的编译思路与 Runes 模型如何理解？

    Svelte 通过编译器把组件模板和响应式表达式转换成更新 DOM 的代码；Runes 明确区分状态、派生值和副作用，但不等于没有运行时或自动解决异步竞态。

  • 选择前端框架时应该先比较哪些约束？

    从产品形态、渲染方式、部署条件、关键依赖和团队能力出发做框架选型，用真实业务流程验证综合成本，而不是比较语法或排行榜。

  • Angular 依赖注入的层级和作用域怎样理解？

    Angular Injector 根据 token 和 provider 创建或查找依赖。服务是不是单例，取决于它注册在哪个 injector，以及组件、路由和应用之间的作用域关系。

  • SvelteKit 的路由、load 和服务端边界怎样协作？

    SvelteKit 在 Svelte 组件之上提供文件路由、load 数据加载、服务端 action 和部署适配。关键是区分代码运行位置，以及哪些返回值最终会进入浏览器。

  • Solid 的 Signals 和 React 状态更新有什么不同？

    React 通常重新执行组件函数并协调视图，Solid 通过 signal 读取建立细粒度依赖，更新时只触发相关计算和 DOM。两者 JSX 相似，但状态读取、派生和清理规则不同。

  • Astro Islands 架构怎样减少客户端 JavaScript？

    Islands 把主要内容作为服务端 HTML 输出，只为需要交互的区域加载客户端代码。收益来自清晰的交互边界和合适的激活时机，不是把整个 SPA 随意拆成多个组件。

  • Angular 中 Observable 和 Signals 怎样协作？

    Observable 适合描述随时间产生值、错误和完成的异步流，Signal 适合同步读取当前状态。Angular 可以互转，但转换会建立订阅，仍需明确生命周期、初始值、取消和错误模型。

  • Angular Hydration 解决什么问题？

    Hydration 让 Angular 客户端复用服务端已经生成的 DOM，再接管状态和事件，减少重复渲染；它要求两端结构一致，也不替代权限、缓存和第三方 DOM 管理。

  • Angular Zoneless 模式会改变哪些更新假设？

    Zoneless 不再依赖 Zone.js 广泛拦截异步任务，而是根据 Signal、事件、输入和显式通知判断哪些视图需要更新。外部回调、SSR 稳定性和测试写法都要重新检查。
