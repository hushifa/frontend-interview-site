测试面试题

前端自动化测试面试题，涵盖组件测试、Playwright 端到端测试、Mock、接口模拟、视觉回归、无障碍检查和代码覆盖率。共 14 道题。

  • 什么时候应该 mock，mock 太多有什么问题？

    mock 用来替换慢、不稳定或不受控的外部边界，比如网络、时间、随机数和第三方服务。把被测代码自己的模块也 mock 掉，测试就只验证了 mock 本身。每个测试后要清理 mock，模拟数据要和真实契约一致。

  • 前端组件测试应该围绕哪些用户行为？

    组件测试要像用户一样操作组件：找到控件、输入、提交，再断言用户能看到的结果，包括加载、成功、失败和重试。内部 state、类名和私有函数不应出现在断言里。

  • 前端单元测试怎么写？Jest 和 Vitest 有什么区别？

    单元测试挑一个纯函数或小模块，按“准备输入 → 调用 → 断言结果”写，覆盖正常值、边界值和异常。Jest 和 Vitest 的 describe/it/expect 写法几乎一样；主要差别在于 Vitest 复用 Vite 的配置和插件，默认不注入全局 API，并原生支持 ESM，Jest 对 ESM 的支持仍是实验性的，TypeScript 要经 Babel、ts-jest 或 Node 类型擦除处理。

  • 如何减少 Playwright 端到端测试的不稳定？

    用 getByRole 等面向用户的定位器和会自动重试的 web-first 断言代替固定等待，每个测试用独立的浏览器上下文和独立的后端数据，触发操作前先注册事件等待，失败时看 trace 找原因，而不是靠重试掩盖。

  • Testing Library 查询方式为什么优先按用户可见语义？

    按角色和可访问名称查询（getByRole）和用户、读屏软件找元素的方式一致，组件内部结构变了测试也不会失败，查不到时还顺带暴露了无障碍问题。按类名或 test id 查询只作为最后手段。

  • Playwright 接口模拟怎样覆盖成功和失败场景？

    用 page.route 在请求发出前拦截，fulfill 返回假数据，abort 模拟断网，continue 或 fallback 放行。多个处理器按注册的相反顺序执行，route.fetch 可以拿到真实响应再改。

  • Playwright fixtures 解决了什么测试维护问题？

    fixture 把测试需要的准备和清理封装在一起，测试按名字声明依赖，Playwright 只在需要时创建，并在 await use() 之后自动清理。test 作用域每个测试一份，worker 作用域在同一工作进程内共享。

  • 为什么 100% 代码覆盖率也可能漏掉严重问题？

    覆盖率只说明哪些代码在测试里执行过，不说明结果被断言过。没写的分支、边界值、并发和外部系统问题都不在统计范围内，所以它适合找完全没测的代码，不适合当质量目标。

  • 前端怎样测试定时器、重试和超时，避免 Fake Timers 造成假通过？

    vi.useFakeTimers 替换 setTimeout、Date 等时间 API，用 advanceTimersByTimeAsync 推进时间。推进时间要用异步版本，让 Promise 回调有机会执行；测试结束后恢复真实计时器。

  • 视觉回归测试如何减少无意义的截图差异？

    截图测试拿页面和基线图片逐像素比较。要稳定，就得固定浏览器和系统环境、等字体和数据就绪、遮住动态内容，再用 threshold、maxDiffPixels 等容差把抗锯齿噪声和真实变化分开。

  • 前端契约测试应该验证什么？

    契约测试检查前端依赖的接口形状和行为是否与后端一致，包括字段、类型、状态码和错误格式。消费者驱动的契约（如 Pact）只记录前端真正用到的部分，后端发布前验证自己没有破坏它。

  • 属性测试和示例测试应该怎样搭配？

    示例测试用具体的输入和输出说明接口；属性测试描述对一类输入都成立的规律，由 fast-check 等工具生成大量数据去推翻它，失败时自动缩减成简单反例。前者适合写成可读的契约，后者适合发现没想到的边界。

  • 变异测试如何发现“覆盖率很高但测试没测到重点”？

    变异测试自动对源代码做小改动（把 > 改成 >=、删掉一行、把 true 改成 false），然后跑测试。测试失败说明变异被“杀死”，测试仍通过说明断言没有覆盖这处逻辑。

  • 前端故障注入应该怎样设计才有价值？

    故障注入就是在测试里故意制造慢响应、错误状态码、网络中断、资源加载失败、存储不可用等情况，看页面能不能显示正确状态、允许重试并恢复。要先列出真实会发生的故障，再逐个注入并检查恢复结果。
