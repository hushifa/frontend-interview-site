JavaScript面试题

JavaScript 与 ES6+ 面试题，围绕闭包、作用域、原型链、this、事件循环、Promise、async/await、深浅拷贝和模块化，复习前端语言基础与异步编程。共 29 道题。

  • 什么是闭包？它有哪些实际应用？

    闭包让函数按创建位置的词法作用域继续访问外层绑定。它可以保存独立状态、提供受控接口和连接回调上下文，但不会默认复制变量快照，也不必然造成内存泄漏。

  • 事件循环中，任务和微任务按什么顺序执行？

    在同一个浏览器主线程执行环境中，同步代码先运行到当前执行过程结束，微任务在检查点被处理，后续任务和渲染再由宿主调度。理解入队时机比简单背诵“Promise 优先于定时器”更准确。

  • 普通函数和箭头函数的 this 有什么区别？

    普通函数的 this 通常由调用方式决定，箭头函数沿用外层词法作用域的 this。方法脱离对象后直接调用会失去接收者；严格模式下访问 undefined 的属性会抛错，而不是返回 undefined。

  • Promise.all、allSettled、race 和 any 如何选择？

    Promise 组合方法定义的是一组结果的完成条件，不负责启动限流或自动取消。all 要求全成功，allSettled 收集所有状态，race 跟随首个敲定，any 等首个成功；空输入和错误结果也各有明确规则。

  • JavaScript 的值类型与相等比较应该怎样理解？

    原始值按对应类型的值规则比较，对象则具有独立身份。严格相等、宽松相等、Object.is 和 SameValueZero 的区别主要在类型转换、NaN 与正负零，并没有哪一个默认执行深度结构比较。

  • 隐式类型转换有哪些容易踩坑的规则？

    JavaScript 会根据布尔判断、算术、拼接等不同上下文执行不同转换。理解真假值、原始值转换与数值解析的区别，比把所有转换归为同一套规则更可靠。

  • var、let、const 和暂时性死区有什么关系？

    var 的绑定通常在执行函数代码前已初始化为 undefined，let 和 const 的词法绑定则在声明初始化前不可访问。作用域、绑定初始化、重新赋值和对象修改是不同问题，应分别理解。

  • 原型链、class 和继承之间是什么关系？

    普通对象读取属性时会沿内部原型链查找。class 在这套机制上组织实例、共享方法和继承关系，同时具有严格模式、构造调用限制、字段与私有元素等自己的语义。

  • 属性描述符、Object.freeze 和只读有什么区别？

    属性描述符控制单个属性的读写、枚举和重配置；freeze 限制对象的普通属性结构，但不会递归冻结子对象或所有内部状态。const 和 TypeScript readonly 则分别约束绑定与类型检查，作用层次不同。

  • 浅拷贝、深拷贝和 structuredClone 如何选择？

    浅拷贝只建立新的外层容器，嵌套对象仍共享身份；structuredClone 可以复制受支持的对象图并处理循环引用，但不保留任意原型、函数或描述符。状态更新通常应按修改路径复制，而不是默认深拷贝整棵树。

  • Map、Set、WeakMap 与普通对象各有什么用途？

    普通对象适合表达记录，Map 适合动态键值集合，Set 适合唯一值集合，WeakMap 适合把元数据与对象生命周期关联。弱集合不提供枚举与容量控制，也不能自动解决所有引用保留问题。

  • 数组常用方法怎样选择，哪些会修改原数组？

    数组方法应按转换、筛选、查找、判断和累积的意图选择，并区分修改数组结构与复制数组容器。返回新数组不代表深拷贝，也不代表会等待异步回调。

  • async/await 如何处理异常和并发？

    async 函数返回 Promise，await 暂停当前异步执行过程并在后续恢复。错误能否被当前 catch 捕获、任务是否并发以及清理何时发生，都取决于 Promise 如何被等待和组合，而不只是有没有写 async。

  • ES Modules 和 CommonJS 有哪些关键区别？

    ESM 通过模块链接与实时绑定组织依赖，CommonJS 在执行 require 时取得 module.exports 的值。二者的加载、缓存与互操作规则依赖宿主和版本，不能只概括成“引用与拷贝”或“异步与同步”。

  • 迭代器、可迭代对象和 Generator 有什么关系？

    可迭代对象负责提供遍历入口，迭代器负责记录当前位置并产生下一项，Generator 则用可暂停函数方便地实现这些协议。它们描述取值过程，不代表自动并行或自动收集全部数据。

  • Proxy 与 Reflect 能实现什么，存在哪些限制？

    Proxy 拦截对象的内部操作，Reflect 提供对应的转发接口。正确处理 receiver 能保留访问器语义，但代理仍受不变量、对象身份、内部槽与私有品牌限制，也不会自动构成完整响应式系统。

  • 垃圾回收为什么无法自动解决所有内存泄漏？

    垃圾回收判断对象是否仍可达，业务泄漏则往往是“不再需要的对象仍被引用”。循环引用本身不必然泄漏，监听器、计时器和缓存的生命周期才是常见排查重点，必须及时释放的资源也不能依赖 GC 回调。

  • 浮点精度、安全整数和 BigInt 有哪些边界？

    Number 的二进制浮点表示会带来小数舍入和大整数区分能力的限制，BigInt 则适合精确整数但不支持任意小数。计算、输入解析、比较和序列化都需要维持一致的精度约定。

  • 正则表达式在前端使用时需要注意什么？

    正则需要同时考虑匹配范围、转义、状态、Unicode 和回溯成本。校验与搜索应采用不同的匹配意图，动态字面量应正确转义，耗时同步匹配也不能靠普通定时器强行中断。

  • 同步错误、Promise 拒绝和全局异常应该怎样处理？

    错误处理要沿真实控制流建立边界：同步异常由当前栈上的 catch 处理，异步任务需要通过 Promise 或回调传递失败，全局事件用于兜底观察。恢复、清理和诊断不能简单合并成“所有错误都返回空值”。

  • ArrayBuffer、TypedArray 和普通数组有什么区别？

    ArrayBuffer 表示字节存储，TypedArray 按固定数值类型查看其中的元素，普通数组则保存一般 JavaScript 值。视图可以共享缓冲，复制、偏移、长度和数值转换规则都需要明确。

  • DataView 怎样读取指定字节序的二进制数据？

    DataView 在缓冲区上按字节偏移读取不同数值类型，并允许逐次指定多字节值的字节序。解析时还需要验证长度、符号和视图范围，不能只靠读取方法不报错就认为协议有效。

  • using 和 await using 解决什么资源清理问题？

    显式资源管理把释放动作绑定到词法作用域退出，using 使用同步释放协议，await using 等待异步释放。它补充确定性的资源生命周期，不替代垃圾回收，也不会自动识别任意 close 方法。

  • Temporal 为什么把 Instant、PlainDate 和 ZonedDateTime 分开？

    Instant 表达时间线瞬间，PlainDate 表达不带时区的日历日期，ZonedDateTime 把瞬间与地区时区规则联系起来。分开这些语义，才能正确处理生日、预约、跨时区显示和夏令时算术。

  • 可选链和空值合并为什么不能简单替换为 && 和 ||？

    可选链只在指定位置遇到 null 或 undefined 时短路，空值合并只为这两种空值提供默认值。它们不会吞掉任意异常，也不会把 0、false、空字符串自动视为缺失。

  • Object.keys、for...in 和 Reflect.ownKeys 会返回哪些属性？

    枚举属性时要区分自身与继承、字符串与 Symbol、可枚举与不可枚举。不同 API 选择不同范围，普通对象的键顺序也有明确规则；读取键与读取属性值又可能触发不同代码。

  • JavaScript 迭代器关闭和 return 方法有什么作用？

    迭代器的 return 方法让消费者在部分提前退出路径上通知数据源结束并清理。它不是普通函数的 return 语句，也不保证所有异常、手动弃置或底层请求都会自动收尾。

  • 异步迭代器和 for await...of 适合处理什么数据？

    异步迭代把下一项数据建模为可等待的结果，适合分页、流和逐步产生的数据。for await...of 顺序消费结果，但不会自动限制生产者内部缓存，也不会替底层网络实现取消。

  • Promise.withResolvers 适合解决什么问题？怎样避免 deferred 泄漏？

    说明 Promise.withResolvers 如何把 Promise、resolve 和 reject 一起暴露出来，适合事件桥接和一次性完成信号，但不能替代队列、取消或状态机；重点讨论重复结算、异常传播、超时和资源清理。
