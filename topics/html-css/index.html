HTML / CSS面试题

HTML 与 CSS 前端基础面试题，涵盖语义化、盒模型、BFC、Flexbox、Grid、层叠与定位、响应式布局和 CSS 动画，配合示例理解页面布局与样式。共 40 道题。

  • 标准盒模型和 border-box 有什么区别？

    content-box 把声明尺寸分配给内容区，border-box 把内边距和边框也计入声明尺寸；外边距始终在外面。最终尺寸仍需结合布局约束、最小尺寸与实际内容计算。

  • Flexbox 和 Grid 应该如何选择？

    Flex 更擅长沿一个主轴按内容分配空间，Grid 更擅长让项目共享行列轨道。是否要求跨行对齐、最后一行如何分配空间、组件内部与页面骨架的关系，比简单记“一维和二维”更能帮助选择。

  • 触发操作为什么应优先使用 button，而不是可点击的 div？

    原生 button 提供按钮语义、焦点和键盘激活等基础行为，减少自行模拟交互时的遗漏。导航应使用带 href 的链接，按钮则仍需明确类型、名称、状态和焦点样式。

  • 为什么 z-index 设置很大，元素还是被遮挡？

    z-index 只在相应层叠上下文中参与排序，子元素不能用巨大数值跨过祖先与外部兄弟上下文的顺序。定位、裁剪和顶层显示机制也会影响最终结果，需要分别排查。

  • HTML 语义化对阅读、搜索与无障碍有什么价值？

    语义化通过元素表达内容角色和文档关系，让浏览器、辅助技术与维护者获得超出视觉样式的信息。它能改善结构理解，但不能替代交互实现、可访问名称或内容质量。

  • 表单的 name、value、label 与提交行为如何协作？

    label 建立控件名称与交互关联，name 决定提交字段名，value 提供当前提交值。原生表单按控件状态收集条目，同名多值、disabled、readonly 和提交按钮都需要按各自规则处理。

  • 原生表单校验能解决什么，不能解决什么？

    HTML 约束和 Constraint Validation API 可以检查必填、格式、范围等规则，并参与表单提交流程。跨字段规则需要补充逻辑，服务端校验和异步业务验证仍不能省略。

  • script 的 async、defer 和 module 有什么区别？

    async 和 defer 主要改变脚本下载与执行相对 HTML 解析的时机；module 还改变代码组织和运行语义。下载可并行不代表执行不会占用主线程，依赖关系也不能交给网络速度决定。

  • srcset、sizes 和 picture 怎样减少图片浪费？

    srcset 提供不同分辨率的候选，sizes 描述宽度候选对应的展示尺寸，picture 根据媒体条件或格式选择图片集合。它们分别解决资源大小、布局预估和裁切选择，不能互相替代。

  • head 中哪些信息会影响页面体验与收录？

    head 中的编码、标题、视口、描述、规范地址、索引指令和分享元信息承担不同职责。应根据当前页面准确输出，避免重复默认值、错误 canonical 或测试环境 noindex 泄漏到正式页面。

  • dialog 和 Popover API 应该怎样使用？

    dialog 提供对话框语义，showModal 建立模态交互并进入 top layer；Popover API 管理非模态浮层的显示与关闭。应先决定是否阻断背景交互，再设计名称、焦点、关闭路径和数据提交。

  • 层叠、优先级、继承和 !important 谁先决定样式？

    CSS 先按来源、重要性和层叠层等规则筛选声明，再比较选择器特异性、作用域接近程度和出现顺序。继承参与缺省值处理，不会把父元素选择器的权重传给子元素。

  • BFC 解决哪些布局问题，什么时候用 flow-root？

    BFC 是块级格式化上下文，规定一组块盒与浮动之间的布局关系。建立新的 BFC 可以包含内部浮动、避开同一外层上下文中的浮动，并隔开部分父子外边距折叠；flow-root 能直接表达这个目的。

  • absolute、fixed 和 sticky 的定位参照是什么？

    absolute 相对其绝对定位包含块定位，fixed 通常相对视口但可能受 transform 等祖先影响，sticky 则同时受最近滚动容器和自身包含块边界约束。三者不能统一理解成相对父元素。

  • flex-basis、flex-grow、flex-shrink 如何分配空间？

    flex-basis 提供主轴基础尺寸，flex-grow 分配正剩余空间，flex-shrink 按收缩系数乘基础尺寸分摊负剩余空间；内容最小尺寸和 min/max 约束仍可能改变最终结果。

  • Grid 的 fr、minmax、auto-fit 和 auto-fill 如何使用？

    fr 按比例分配网格剩余空间，minmax 约束轨道尺寸范围，auto-fill 与 auto-fit 自动决定重复列数；两者的关键差别是是否折叠没有项目占用的重复轨道。

  • px、rem、em、百分比和动态视口单位怎么选？

    选择尺寸单位先确定参照：px 是 CSS 像素，rem 与根字体相关，em 与局部字体相关，百分比由属性决定参照，svh、lvh、dvh 则区分浏览器界面变化下的视口尺寸。

  • 媒体查询和容器查询分别适合什么场景？

    媒体查询依据视口、设备能力或用户偏好，容器尺寸查询依据祖先容器的可用空间。前者适合页面级适配，后者让同一个组件在不同位置独立调整布局。

  • transition、animation 和 requestAnimationFrame 怎么选？

    transition 描述状态变化的过渡，animation 描述关键帧过程，requestAnimationFrame 适合由 JavaScript 根据时间计算每一帧。选择依据是行为与控制需求，性能则要结合具体属性、工作量和浏览器渲染路径判断。

  • CSS Modules、层叠层和自定义属性怎样帮助维护样式？

    CSS Modules 管理局部类名，@layer 声明覆盖次序，自定义属性传递可被层叠和继承覆盖的样式值。三者可以协作，但都不是对所有样式影响的彻底隔离。

  • font-display 怎样影响字体加载期间的文字显示？

    font-display 决定 Web 字体尚未就绪时是否暂时隐藏文字、何时显示回退字体以及之后是否允许替换。选择显示策略时，需要同时考虑可读性、字体一致性和布局偏移。

  • 逻辑属性为什么比固定写 left、right 更适合国际化？

    逻辑属性按文字的行内方向与块方向表达边缘和尺寸，能够跟随 writing-mode 与 direction 映射到实际物理方向，减少从左到右、从右到左和竖排布局之间的重复样式。

  • subgrid 如何让嵌套组件对齐父网格？

    普通嵌套 Grid 独立计算轨道，subgrid 则复用网格项跨越的父网格轨道，让保留组件包裹结构的后代参与共享对齐。列与行可以分别选择是否使用子网格。

  • 网页打印样式应该怎样单独设计？

    打印面向有限纸张与分页阅读，需要单独处理交互区域、滚动内容、固定定位、分页和资源就绪。@media print 与 @page 提供样式入口，但仍受层叠规则、浏览器和用户打印设置影响。

  • content-visibility: auto 与移除 DOM 有什么区别？

    content-visibility:auto 允许浏览器暂时跳过与用户无关的后代渲染工作，DOM 与应用状态仍在。它需要合适的占位尺寸，并不能替代虚拟列表、请求管理或 JavaScript 工作的暂停。

  • :has() 怎样根据后代或相邻元素设置样式？

    :has() 以当前元素为锚点检查相对选择器是否匹配，匹配后选中的仍是当前元素。它既能表达包含某个后代，也能表达后面紧接某个兄弟元素等关系。

  • CSS 滚动驱动动画适合什么场景？

    滚动驱动动画把关键帧进度连接到滚动位置或元素穿越滚动区域的进度，适合阅读进度和随滚动变化的视觉反馈。它不等于滚动到某点后启动一次独立计时动画。

  • 容器样式查询怎样根据父级配置改变组件样式？

    容器样式查询通过 style() 判断祖先容器的样式条件，常见用法是查询自定义属性，把密度、主题等配置传给内部组件。它与查询容器宽高的尺寸查询不同。

  • HTML autocomplete 属性怎样帮助表单体验和隐私？

    autocomplete 用有序语义令牌说明字段用途，帮助浏览器和密码管理器提供合适的填充。它是提示而非强制开关，既不替代字段标签，也不证明自动填入的数据真实有效。

  • inputmode 怎样改善移动端输入体验？

    inputmode 提示浏览器选择合适的虚拟键盘，但不改变控件的值类型，也不限制可输入的字符。字段语义、自动填充与约束校验需要分别通过 type、autocomplete 和校验规则表达。

  • Web 排版中的字体、行高和布局稳定性怎样处理？

    从字体加载和字形度量解释文字换行、布局偏移与可读性，说明 line-height、font-display、语言断词和可变字体的选型边界。

  • CSS Masonry 和传统瀑布流方案应该怎样选择？

    解释 masonry 布局试图解决的列高不齐问题，比较原生 CSS、Grid、JavaScript 和多列布局的顺序、兼容性、性能与无障碍边界。

  • CSS Anchor Positioning 适合解决哪些浮层布局问题？

    用提示框和下拉菜单说明 anchor、position-anchor、position-area 与回退位置的关系，并比较它和 JavaScript 测量定位的兼容性与交互边界。

  • CSS @scope 能解决哪些样式隔离问题？

    解释 @scope 的作用域根、边界和层叠关系，比较它与 CSS Modules、Shadow DOM 和 @layer 的区别，并说明渐进增强与组件迁移边界。

  • CSS 多栏布局和 Grid 有什么区别？怎样避免内容被跨栏切开？

    从长文章与卡片列表出发，解释多栏内容流、column-width、column-count、断栏与跨栏标题，区分视觉布局和 DOM 阅读顺序。

  • @starting-style 和离散属性过渡解决了什么问题？

    解释新元素为什么无法从 display:none 过渡到可见状态，说明 @starting-style、allow-discrete 与 opacity/transform 的配合方式，以及退出动画、DOM 时机、兼容性和渐进增强边界。

  • CSS @property 如何让自定义属性参与类型校验和动画？

    解释普通 CSS 自定义属性为什么按 token 保存、不能可靠插值，说明 @property 的 syntax、inherits 和 initial-value，以及注册属性在主题、动画、组件封装和兼容性中的实际边界。

  • field-sizing: content 会怎样改变表单控件尺寸？

    解释 field-sizing 的 fixed 与 content 模式，覆盖 textarea、自适应输入框和 select 的尺寸边界，说明 min/max 约束、布局稳定性、可访问性、兼容回退和渐进增强。

  • text-wrap: balance 和 pretty 应该怎样使用？

    解释 text-wrap 的 balance 与 pretty 如何影响标题和段落换行，说明它们不是固定宽度或溢出修复工具，并覆盖语言、性能、响应式布局、SSR 和兼容回退。

  • interpolate-size 和 calc-size() 怎样实现 auto 高度动画？

    解释 intrinsic size 关键字为什么过去不能直接参与 CSS 过渡，说明 interpolate-size、calc-size() 与展开面板的配合方式，以及布局成本、可访问状态和兼容回退。
