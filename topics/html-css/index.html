HTML / CSS面试题

HTML 与 CSS 前端基础面试题，涵盖语义化、盒模型、BFC、Flexbox、Grid、层叠与定位、响应式布局和 CSS 动画，配合示例理解页面布局与样式。共 63 道题。

  • 怎样让一个元素水平垂直居中？

    现在最常用的是 Flex 的 justify-content 加 align-items，或者 Grid 的 place-items: center，元素宽高未知也能居中。脱离文档流的元素用 absolute 配合 inset: 0 和 margin: auto，或者 top/left 50% 加 transform 往回移一半。

  • 清除浮动有哪几种方法？

    父元素算高度时不包含浮动子元素，导致高度塌陷。解决办法有三类：在浮动后面放一个 clear 元素，常用 ::after 伪元素写成 clearfix；让父元素创建 BFC，首选 display: flow-root，overflow: hidden 也行但会裁剪内容；或者不用浮动，改用 Flex 和 Grid 布局。

  • 单行和多行文本省略怎么写？

    单行省略要同时写 white-space: nowrap、overflow: hidden 和 text-overflow: ellipsis，元素还要有确定的宽度。多行省略目前通用写法是 display: -webkit-box、-webkit-box-orient: vertical 加 -webkit-line-clamp，再配 overflow: hidden。标准的 line-clamp 属性浏览器支持还有限。

  • 伪类和伪元素有什么区别？

    伪类按状态或位置选中已经存在的元素，比如 :hover、:focus-visible、:nth-child()，写一个冒号。伪元素选中元素里的某一部分，或者生成一个文档里没有的盒子，比如 ::before、::first-line、::placeholder，写两个冒号。伪元素必须放在选择器最后，::before 和 ::after 需要 content 才会生成。

  • 浏览器为什么从右往左匹配 CSS 选择器？选择器性能应该怎么看？

    浏览器计算样式时是拿着一个元素去问“哪些规则命中它”，选择器定义里元素要先命中最右边那段复合选择器，再沿父级或兄弟往左验证，所以从右往左最省事，大多数规则在最右一段就被排除。Blink 还按最右一段的 id、类名、标签把规则分桶，并用祖先过滤器提前丢掉不可能命中的后代规则。选择器性能一般不是首要瓶颈，真要优化先用 DevTools 的 Selector Stats 找出耗时的选择器，再减少被匹配的元素数量和复杂度。

  • 标准盒模型和 border-box 有什么区别？

    默认的 content-box 里，width 只管内容区，加上内边距和边框后盒子会变宽；border-box 里 width 就是盒子的宽度。两种模式都不算外边距。

  • link 和 @import 引入 CSS 有什么区别？

    link 是 HTML 元素，浏览器解析 HTML 时就能发现并下载；@import 写在 CSS 里，要等外层样式表下载解析后才发现，形成串行的请求链，延迟 CSSOM 构建。link 能用 JavaScript 增删、切换 disabled，用 media 属性做条件加载；@import 必须写在样式表开头，支持媒体查询、supports() 条件和 layer() 放入层叠层，后者是 link 做不到的。

  • BFC 解决哪些布局问题，什么时候用 flow-root？

    BFC 是一块独立的布局区域，里面的浮动和外边距不会影响外面。它能让父元素包住浮动、避开旁边的浮动、阻止父子外边距折叠；只想要 BFC 时用 display: flow-root。

  • Flexbox 和 Grid 应该如何选择？

    Flex 是让东西沿一个方向按自身大小排开，适合导航栏、按钮组；Grid 是先画好行和列再往里放，适合要上下左右都对齐的布局。

  • 层叠、优先级、继承和 !important 谁先决定样式？

    多条样式抢同一个属性时，浏览器按固定顺序比：先看来源和 !important，再看层叠层，然后才是选择器优先级、作用域远近和书写顺序。继承来的值最弱，元素只要被直接选中就轮不到它。

  • display:none、visibility:hidden 和 opacity:0 有什么区别？

    display:none 让元素不参与布局、不渲染，也会从无障碍树中移除；visibility:hidden 不绘制元素但保留它占的位置，不能获得焦点，子元素设置 visibility:visible 还能显示；opacity:0 只是完全透明，位置、点击和焦点都还在。

  • 为什么 z-index 设置很大，元素还是被遮挡？

    z-index 只在同一个层叠上下文里面比。父级这一整层排得低，子元素的 z-index 写得再大，也越不过外面的兄弟。

  • absolute、fixed 和 sticky 的定位参照是什么？

    absolute 找最近的定位祖先当参照；fixed 一般相对视口，但祖先有 transform、filter 这类属性时会改为相对这个祖先；sticky 在最近的滚动容器里吸住，而且跑不出自己的父元素。

  • 怎样实现三栏布局？圣杯布局和双飞翼布局是什么？

    三栏布局是左右两栏固定宽度、中间自适应，而且中间内容要先在 HTML 里出现、先渲染。现在用 Flex 或 Grid 几行就能写；圣杯布局和双飞翼布局是 Flex 普及前的浮动方案，都靠负 margin 把左右栏拉回中间栏两边，区别在于圣杯用父元素的 padding 留出位置，双飞翼在中间栏里套一层用 margin 留出位置。

  • CSS-in-JS 和原子化 CSS 怎么选？styled-components、Tailwind、CSS Modules 各适合什么场景？

    styled-components 在 JavaScript 里写样式，按 props 生成规则并在运行时注入；Tailwind 在构建时扫描源码里的类名，只生成用到的工具类；CSS Modules 在构建时把类名改成唯一的。选型看三点：运行时开销、能否在 React Server Components 里使用、团队写样式的习惯。vanilla-extract 这类零运行时方案在构建时产出静态 CSS。

  • rem 和 em 有什么区别？各自怎么换算？

    rem 相对根元素 html 的字号，em 相对当前元素的字号，写在 font-size 上时相对父元素字号，嵌套会层层叠加。换算公式是 px = 倍数 × 参照值，根字号 16px 时 1.5rem 是 24px。全局字号和间距用 rem，跟着组件字号缩放的内边距用 em，细边框用 px；根字号不要写死 px，否则用户调大浏览器默认字号时页面不跟着变。

  • DOCTYPE 有什么用？标准模式和怪异模式有什么区别？

    浏览器根据文档开头的 DOCTYPE 决定用哪种渲染模式。写 <!doctype html> 进入无怪异模式，也就是标准模式；缺少 DOCTYPE 会进入怪异模式，模拟老浏览器的布局行为；部分旧 DOCTYPE 会进入有限怪异模式。可以用 document.compatMode 查看当前模式。

  • transition 和 animation 有什么区别？

    transition 在属性值发生变化时，把旧值到新值的过程补成动画，只有起点和终点两个状态，需要 :hover、改类名这样的触发。animation 用 @keyframes 定义多个关键帧，元素应用后自动播放，可以设置循环次数、方向、暂停和结束后是否保留样式。两者对应的事件也不同。

  • script 的 async、defer 和 module 有什么区别？

    普通 script 会让浏览器停下解析去下载和执行；defer 边解析边下载，解析完再按顺序执行；async 边解析边下载，下载完马上执行，不保证顺序；module 默认和 defer 一样，还多了模块的规则。

  • 怎样用 CSS 画一个三角形？原理是什么？

    把元素宽高设为 0，只给边框设宽度，四条边框在角上按斜线拼接，每条边各自变成一个三角形。把不需要的三条边设为透明，就剩下一个三角形。现在也可以用 clip-path: polygon() 直接裁剪出三角形，写法更直观，还能用背景色和渐变。

  • 网页图片该选什么格式？JPEG、PNG、WebP、AVIF、SVG 怎么选？

    图标、图表这类要在任意尺寸下清晰的图优先用 SVG；照片等位图优先 WebP 或 AVIF，压缩率比 JPEG、PNG 更好，再用 picture 提供 JPEG 或 PNG 兜底。照片能接受有损压缩，截图、文字和线条图要用无损；需要透明时兜底用 PNG，因为 JPEG 没有透明通道。

  • Sass、Less 这类 CSS 预处理器解决了什么问题？原生 CSS 现在能替代它们吗？

    预处理器在构建时把带变量、嵌套、混入、函数的样式编译成普通 CSS，解决了早期 CSS 难以复用和组织的问题。现在原生 CSS 已经有自定义属性、嵌套、@layer 和 color-mix() 等能力，很多场景不再需要预处理器；但编译期的循环、条件和模块化导入仍是预处理器的优势。

  • HTML 语义化对阅读、搜索与无障碍有什么价值？

    语义化就是按内容的角色选元素，标题用 h1 到 h6，导航用 nav，按钮用 button。读屏软件、浏览器和搜索引擎靠这些元素理解页面结构，代码也更好维护。

  • 表单的 name、value、label 与提交行为如何协作？

    label 告诉用户和读屏这个控件是什么，name 是提交时的字段名，value 是提交的值。没有 name、被 disabled、没勾选的控件都不会提交，FormData 也按这套规则收集。

  • 原生表单校验能解决什么，不能解决什么？

    用 required、type、pattern、min、max 这些属性，浏览器能在提交前检查有没有填、格式对不对、在不在范围内。两个字段之间的比较和需要请求服务器的检查要自己写，服务端校验永远不能省。

  • head 中哪些信息会影响页面体验与收录？

    head 里的信息各管一摊：charset 和 viewport 管显示，title 和 description 管搜索结果长什么样，canonical 和 robots 管收不收录，Open Graph 管分享卡片。每个页面都要写和自己内容对应的值。

  • dialog 和 Popover API 应该怎样使用？

    要挡住页面、让用户必须先处理的，用 dialog 的 showModal()；下拉菜单、提示气泡这类不挡页面的浮层，用 popover 属性。两者都会显示在最上层，不受父元素 z-index 影响。

  • vw、vh、svh、lvh、dvh 有什么区别？移动端整屏高度怎么写？

    视口单位按视口尺寸的百分比计算，1vw 是视口宽度的 1%。手机浏览器的工具栏会展开收起，所以视口高度分成三种：svh 按工具栏展开时的小视口算，lvh 按收起时的大视口算，dvh 跟着当前状态变化，目前的 vh 等同于 lvh。首屏整屏用 svh，全屏应用外壳用 dvh；100vw 不扣除滚动条，相对父元素要用百分比或容器查询单位。

  • flex-basis、flex-grow、flex-shrink 如何分配空间？

    每个项目先按 flex-basis 占一个初始大小；空间有多就按 flex-grow 的比例分，空间不够就按 flex-shrink 乘 flex-basis 的比例缩。min-width 这类限制最后才起作用。

  • Grid 的 fr、minmax、auto-fit 和 auto-fill 如何使用？

    fr 按比例分剩下的空间，minmax 给列宽定上下限，repeat 加 auto-fill 或 auto-fit 能按容器宽度自动决定放几列。两者的区别是空出来的列留着还是收起来。

  • 动画为什么会卡？transform、will-change 和 requestAnimationFrame 怎样让动画流畅？

    动画卡不卡，主要看每一帧改的属性要让浏览器重做哪些步骤：改宽高和位置要重新布局，改颜色要重绘，transform 和 opacity 通常只需要合成，还可能交给合成器线程处理。必须用 JavaScript 逐帧计算时用 requestAnimationFrame，进度按时间戳算；will-change 只在测量后短期使用；开了减少动态效果的用户要给不动的版本。

  • 媒体查询和容器查询分别适合什么场景？

    媒体查询看的是整个视口和设备，适合定页面骨架；容器查询看的是组件所在容器有多宽，同一个组件放在宽栏、窄栏里能各自调整。

  • CSS Modules、层叠层和自定义属性怎样帮助维护样式？

    三者各管一件事。CSS Modules 把类名编译成唯一的，解决重名；@layer 规定谁覆盖谁，解决优先级打架；自定义属性传可继承、可覆盖的设计值，用来做主题。

  • 网页字体什么时候开始下载？怎样用 CSS Font Loading API 控制和检测加载？

    写了 @font-face 不代表马上下载，多数浏览器要等页面真正用到这个字体时才去取。CSS Font Loading API 用 FontFace 对象表示一个字体，可以手动 load()、加进 document.fonts，用 status 和 Promise 知道它什么时候加载好；document.fonts.ready 等所有字体和布局完成。check() 只回答“现在画会不会触发换字体”，不能用来判断某个字体是否可用。

  • :has() 怎样根据后代或相邻元素设置样式？

    :has() 判断一个元素里面或后面有没有某样东西，有的话选中的还是这个元素本身。这样父元素和前面的兄弟元素终于能根据后面的内容改样式了。

  • content-visibility: auto 与移除 DOM 有什么区别？

    content-visibility: auto 让浏览器先不渲染屏幕外的内容，但节点还在页面里，能查找、能聚焦、状态也不丢。它要配合 contain-intrinsic-size 给出占位高度，数据特别多时还是要用虚拟列表。

  • srcset、sizes 和 picture 怎样减少图片浪费？

    srcset 列出同一张图的几种尺寸，sizes 告诉浏览器图片在页面上显示多宽，浏览器据此挑一个刚好够清楚的最小文件。要换图片格式或者在不同屏幕上换裁切，用 picture。

  • 触发操作为什么应优先使用 button，而不是可点击的 div？

    原生 button 自带很多东西：读屏能认出是按钮、Tab 能聚焦、Enter 和空格能触发、有禁用状态和表单提交。用 div 模拟就得自己一样样补，很容易漏。跳转页面则用带 href 的 a。

  • 图标方案怎样选？iconfont、SVG Sprite 和图标组件各有什么优缺点？

    iconfont 把图标做成字体，用 CSS 的 content 插入字形，颜色和大小跟随文字，但只能单色，依赖字体文件加载，伪元素内容也不一定被读屏软件读出。SVG Sprite 把图标写成 symbol，用 use 引用，支持多色和 currentColor。图标组件把每个 SVG 编译成组件，可以按需打包。无障碍上，装饰性图标加 aria-hidden，独立的图标按钮用 aria-label 给出名称。

  • 雪碧图、SVG Sprite 和 icon font 是怎样演进的？现在还要不要合并图标？

    雪碧图把多个小图拼成一张，用 background-position 显示其中一块，目的是减少 HTTP 请求；MDN 也提醒，在 HTTP/2 下多个小请求可能反而更省带宽。icon font 把图标做成字体，颜色和大小跟随文字，但只能单色，生成内容也可能读不出来。SVG Sprite 用 symbol 定义、use 引用，矢量、可多色、可用 currentColor。现在多用 SVG Sprite 或图标组件，合并与否要看协议和缓存。

  • Grid 的 grid-template-areas 怎样画页面布局？怎样配合 auto-fill 做响应式？

    grid-template-areas 用一组字符串把网格画出来，每个名字占的格子组成一个区域，子元素用 grid-area 放进去，"." 表示空格子。每行格子数必须相同，同名格子必须拼成矩形，否则整条声明无效。每个区域还会自动生成 名字-start 和 名字-end 网格线。换布局只要在媒体查询里改字符串；卡片列表用 repeat(auto-fill, minmax()) 让列数随宽度变化。

  • inputmode 怎样改善移动端输入体验？

    inputmode 只决定手机上弹出哪种键盘，比如数字键盘、电话键盘、邮箱键盘。它不改变值的类型，也不限制能输入什么，校验还是要靠 pattern 或代码。

  • HTML autocomplete 属性怎样帮助表单体验和隐私？

    autocomplete 用一组标准词告诉浏览器和密码管理器这个输入框是填什么的，比如 email、new-password、one-time-code。它只是提示，填进来的数据还是要校验。

  • 逻辑属性为什么比固定写 left、right 更适合国际化？

    逻辑属性不写左右上下，而是写"文字开始的一侧""文字结束的一侧"。页面换成从右往左的阿拉伯语或竖排时，同一套样式会自动对应到正确的方向。

  • Web 排版中的行高、行宽和断行怎样处理？

    行高写不带单位的数字，正文一行控制在 60 到 75 个字母或 30 到 40 个汉字，长单词和中文断行用 overflow-wrap、word-break 处理，可变字体优先用 font-weight 这类常规属性控制。

  • text-wrap: balance 和 pretty 应该怎样使用？

    balance 让标题这种短文本每行差不多长；pretty 用更细的算法排正文，避免最后一行只剩一两个字。不支持的浏览器照常换行，不用写回退。

  • 网页打印样式应该怎样单独设计？

    用 @media print 单独写一套打印样式：藏掉导航和按钮，把滚动区域展开，换成适合纸张的字号和颜色；用 @page 设页边距，用 break-* 控制在哪里分页。

  • subgrid 如何让嵌套组件对齐父网格？

    普通的嵌套网格自己算自己的行列，跟外面的网格没关系；写成 subgrid 后，子网格直接用父网格的行列，所以不同卡片里的标题、按钮能对齐成一排。

  • CSS @scope 能解决哪些样式隔离问题？

    @scope 让一段样式只在某个元素里面生效，还能把里面的某块区域排除掉。它不会提高优先级，两条规则打平时，离元素更近的作用域赢。

  • 容器样式查询怎样根据父级配置改变组件样式？

    @container style() 看祖先元素上某个自定义属性的值，父级写一个配置，里面的组件就能整段切换样式。目前浏览器只支持查询自定义属性。

  • CSS Anchor Positioning 适合解决哪些浮层布局问题？

    锚点定位让提示框、下拉菜单这类浮层直接贴着某个元素放，空间不够时还能自动换个方向，大部分情况不用再用 JavaScript 算坐标。

  • @starting-style 和离散属性过渡解决了什么问题？

    元素从 display: none 出现时没有起点，过渡播不出来，@starting-style 就是给它补一个起点。transition-behavior: allow-discrete 让 display 这类属性等动画结束再切换，这样进入和退出动画都能用纯 CSS 做。

  • CSS @property 如何让自定义属性参与类型校验和动画？

    普通的自定义属性在浏览器眼里只是一串文字，不知道是颜色还是长度，所以没法做过渡。用 @property 登记它的类型、是否继承和初始值后，它就能平滑过渡，写错的值也会退回默认。

  • CSS 滚动驱动动画适合什么场景？

    普通动画随时间播放，滚动驱动动画随滚动播放：滚到哪里，动画就播到哪里。适合阅读进度条、元素滚进视口时淡入这类效果。它还不是 Baseline，要做成渐进增强。

  • CSS 多栏布局和 Grid 有什么区别？怎样避免内容被跨栏切开？

    多栏布局像报纸，一段内容填满第一栏再流到第二栏，适合长文本；Grid 是把一个个独立项目放进格子。多栏里用 break-inside 防止卡片被切成两半，用 column-span 让标题横跨所有栏。

  • CSS Masonry 和传统瀑布流方案应该怎样选择？

    原生瀑布流现在写作 display: grid-lanes，还是实验特性，要在普通 Grid 上做增强。多栏布局和 JavaScript 定位也能做，但一个顺序是竖着的，一个要反复测量高度。

  • interpolate-size 和 calc-size() 怎样实现 auto 高度动画？

    以前 height 从 0 过渡到 auto 是没有动画的，直接跳。设置 interpolate-size: allow-keywords 后就能过渡了。它还是实验特性，不支持的浏览器照样能展开收起，只是没动画。

  • field-sizing: content 会怎样改变表单控件尺寸？

    field-sizing: content 让输入框、文本域、下拉框跟着内容自动变大变小，不用再写 JavaScript 读 scrollHeight。一定要同时设置最小和最大尺寸。

  • CSS Scroll Snap 怎样实现吸附滚动？

    在滚动容器上设置 scroll-snap-type 指定方向和严格程度，在子元素上用 scroll-snap-align 指定对齐位置，滚动停下时浏览器就会停在对齐点上。scroll-padding 给固定头部留空间，scroll-snap-stop: always 防止快速滑动跳过某一项。

  • 可定制 select（appearance: base-select、::picker(select)）解决什么问题？

    原生 select 的下拉面板样式由操作系统决定，几乎改不了，所以很多项目只能自己写下拉组件。给 select 和 ::picker(select) 设置 appearance: base-select 后，可以完全自定义按钮和下拉面板，选项里还能放图标，同时保留原生 select 的键盘操作、表单提交和无障碍语义。不支持的浏览器会退回普通 select。

  • command/commandfor 怎样不写 JS 控制 dialog 和 popover？popover="hint" 和 auto、manual 有什么区别？

    给 button 写 commandfor 指向目标元素的 id，再用 command 指定动作，比如 show-modal、close、toggle-popover，点击就能打开关闭 dialog 和 popover，不用写脚本。以 -- 开头的自定义命令会在目标上触发 command 事件。popover 的 auto 可点外面关闭并互斥，manual 只能手动关闭，hint 用于悬停提示，打开时不会关掉已打开的 auto popover。

  • oklch()、color-mix() 和相对颜色语法怎样做主题色？

    oklch() 用感知亮度 L、色度 C、色相 H 描述颜色，调 L 就能得到观感上均匀变亮或变暗的颜色。color-mix() 按比例在指定色彩空间里混合颜色，常用来做悬停色和半透明色。相对颜色语法 oklch(from var(--brand) calc(l - 0.1) c h) 能从一个品牌色直接算出变体。三者都基于浏览器运行时计算，能跟着自定义属性切换主题；相对颜色语法支持得最晚，要用 @supports 或回退值。

  • Tailwind CSS v4 的 CSS-first 配置（@import "tailwindcss"、@theme）改变了什么？

    v4 把配置从 tailwind.config.js 搬进了 CSS：用 @import "tailwindcss" 代替三条 @tailwind 指令，用 @theme 定义主题变量，变量的命名空间决定会生成哪些工具类，编译后还会输出成普通 CSS 变量。源文件改为自动扫描，用 @source 补充或排除；JS 配置要用 @config 显式加载。v4 依赖 @property、color-mix() 等新特性，面向 Safari 16.4+、Chrome 111+、Firefox 128+。
