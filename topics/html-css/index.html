HTML / CSS面试题

HTML 与 CSS 前端基础面试题，涵盖语义化、盒模型、BFC、Flexbox、Grid、层叠与定位、响应式布局和 CSS 动画，配合示例理解页面布局与样式。共 30 道题。

  • 标准盒模型和 border-box 有什么区别？

    明确 width、padding 和 border 如何参与最终尺寸计算。

  • Flexbox 和 Grid 应该如何选择？

    理解层叠上下文，以及子元素无法跨越父级层叠顺序的原因。

  • HTML 语义化对阅读、搜索与无障碍有什么价值？

    语义化是用元素表达内容的角色，例如标题、导航、主内容、文章和表单，而不是只选择看起来合适的默认样式。辅助技术、搜索引擎和浏览器都能利用这些结构信息。

  • 表单的 name、value、label 与提交行为如何协作？

    表单提交的数据由成功的表单控件产生，name 是字段名，value 是当前提交值。没有 name 的控件通常不会进入原生提交数据；disabled 控件也不会提交，readonly 与 disabled 不等价。

  • script 的 async、defer 和 module 有什么区别？

    普通外部经典脚本通常阻塞 HTML 解析，直到下载和执行完成。defer 允许并行下载，在文档解析后按顺序执行，并在 DOMContentLoaded 前完成；async 下载完成即可执行，不保证与其他 async 脚本的先后顺序。

  • srcset、sizes 和 picture 怎样减少图片浪费？

    srcset 提供多个候选资源，使用宽度描述符时，sizes 告诉浏览器图像在布局中预计占用的宽度，浏览器结合设备像素比等条件选择候选。sizes 描述的是展示尺寸，不是文件大小。

  • head 中哪些信息会影响页面体验与收录？

    title 提供页面标题，description 用于描述内容，字符编码应尽早声明。viewport 控制移动端布局视口，常见设置是 width=device-width, initial-scale=1；不应为了防布局问题禁用用户缩放。

  • dialog 和 Popover API 应该怎样使用？

    dialog 用于对话框，showModal 打开模态对话框并进入顶层；Popover API 适合浮层等轻量展示，通过 Popover API 创建的浮层本身是非模态的。二者需要根据交互语义选择。

  • 层叠、优先级、继承和 !important 谁先决定样式？

    最终样式来自一套层叠排序：先考虑来源、重要性与层叠层等，再比较选择器特异性，必要时比较作用域接近程度和出现顺序。仅比较 id、class 和标签数量不足以解释所有结果。

  • BFC 解决哪些布局问题，什么时候用 flow-root？

    块级格式化上下文是部分块布局与浮动相互作用的区域。建立新的 BFC 可以包含内部浮动、限制与外部浮动的重叠，并影响跨边界的外边距折叠行为。

  • absolute、fixed 和 sticky 的定位参照是什么？

    absolute 通常相对最近建立相应包含块的祖先定位；fixed 常相对视口，但 transform、contain 等祖先条件可能改变其包含块。不能把“最近的非 static 父元素”当成覆盖所有现代 CSS 情况的唯一规则。

  • flex-basis、flex-grow、flex-shrink 如何分配空间？

    Flex 布局先基于项目的基础尺寸和约束计算剩余空间，再使用 grow 或 shrink 分配。grow 处理正剩余空间；shrink 对负空间的分配还与基础尺寸有关，不是简单把超出部分平均分摊。

  • Grid 的 fr、minmax、auto-fit 和 auto-fill 如何使用？

    fr 分配网格容器中可用的剩余空间，轨道的最小尺寸和内容贡献会影响最终结果。minmax(0, 1fr) 允许轨道小于内容的自动最小宽度，是处理长内容溢出的常见办法。

  • px、rem、em、百分比和动态视口单位怎么选？

    CSS px 是参考像素，不等于物理屏幕像素。rem 相对根元素字体大小；em 在字体大小属性上相对父级字体，在多数其他属性上相对当前元素字体，因此嵌套时要注意累积。

  • 媒体查询和容器查询分别适合什么场景？

    媒体查询根据视口、输入设备或用户偏好等环境条件选择样式；容器查询让组件根据祖先查询容器的尺寸等条件调整布局，更适合在侧栏、主内容区等不同位置复用的组件。

  • CSS Modules、层叠层和自定义属性怎样帮助维护样式？

    CSS Modules 在构建时为局部类名生成映射，减少类名冲突；层叠层用 @layer 明确不同来源样式的覆盖次序；CSS 自定义属性则让主题变量通过原生层叠和继承传播。

  • font-display 怎样影响字体加载期间的文字显示？

  • 逻辑属性为什么比固定写 left、right 更适合国际化？

    逻辑属性按照内容书写方向描述尺寸和边缘。inline 轴沿着一行文字的流向，block 轴沿着行的堆叠方向；具体映射由 writing-mode、direction 等决定，不能永远把 inline 理解成水平方向。

  • subgrid 如何让嵌套组件对齐父网格？

    普通嵌套 Grid 拥有独立轨道，内部元素不会自动对齐外层轨道。将网格项本身设为网格容器，并在 grid-template-columns 或 grid-template-rows 上使用 subgrid，可以复用它所跨越的父网格轨道。

  • 网页打印样式应该怎样单独设计？

    可以使用 @media print 或 media="print" 的样式表，为打印隐藏导航、按钮等操作区域，并调整文字、背景和布局。打印仍遵循 CSS 层叠规则，不是写了 print 就一定覆盖其他声明。

  • content-visibility: auto 与移除 DOM 有什么区别？

    content-visibility： auto 允许浏览器在内容与用户暂不相关时跳过其部分布局和绘制工作。节点仍在 DOM 中，不等于虚拟列表卸载节点，也不会自动停止订阅、网络请求和 JavaScript 计算。

  • :has() 怎样根据后代或相邻元素设置样式？

    ：has() 按相对选择器是否匹配来选择当前元素。例如 .card：has(> img) 选择有直接子图片的卡片，h1：has(+ p) 选择后面紧接段落的 h1。它不只是“父选择器”，也能表达与兄弟元素的关系。
