图形与可视化面试题

前端图形与可视化面试题，对比 Canvas、SVG、WebGL 和 WebGPU，理解绘图方案、着色器与 GPU 处理的适用场景。共 10 道题。

  • Canvas 和 SVG 怎样选择？

    SVG 把图形保留为 DOM 元素，可以用 CSS 和事件直接操作；Canvas 2D 把绘制命令变成像素，图形对象和命中检测由应用管理。对象数量、更新频率、交互、清晰度和无障碍共同决定选型。

  • 什么场景值得用 WebGL？GPU 加速有哪些成本？

    WebGL 适合大量同类图元的并行绘制，例如上万个散点、地图、粒子和三维场景。代价是着色器开发、GPU 资源管理、上下文丢失恢复和设备差异；普通图表和 UI 用 SVG、Canvas 2D 更省事。

  • WebGPU 与 WebGL 的关注点有哪些不同？

    WebGPU 是更显式的现代 GPU 接口，除渲染管线外还提供计算管线，着色器语言是 WGSL。它目前不是 Baseline、只在安全上下文可用，可以用 compatibility 功能级别覆盖较旧的图形后端；是否从 WebGL 迁移取决于设备覆盖和计算需求。

  • WebCodecs 适合哪些浏览器端音视频场景？

    WebCodecs 暴露浏览器的编码器和解码器，提供帧级控制，适合剪辑、转码和逐帧分析。它不解析容器、不管播放时钟和网络；使用时要管理解码队列、及时关闭帧，并按配置检测编解码器支持。

  • Canvas 的 transform 怎样影响坐标和绘制？

    当前变换矩阵决定后续绘制坐标如何映射到位图，translate、scale、rotate 的调用顺序会改变结果。用 save/restore 限制局部状态，用 setTransform 处理高 DPI，用完整矩阵的逆变换把指针坐标换回绘图空间。

  • WebXR 应用需要处理哪些设备与会话边界？

    WebXR 会话要先检测模式、由用户操作发起；参考空间决定坐标原点；渲染使用会话自己的 requestAnimationFrame，按设备给出的每个视图绘制；输入源会变化，会话可能结束或暂时不可见。

  • Canvas 图形命中测试应该怎样实现？

    Canvas 只有一个 DOM 元素，点中了哪个图形要应用自己判断。用 Path2D 让绘制和命中共用同一份几何，统一坐标系后用 isPointInPath 检测，重叠时从最上层往下找，对象多时先用包围盒或空间索引粗筛。

  • 前端图表如何同时满足无障碍和高性能？

    图表先提供标题、单位、关键结论和可展开的数据表；颜色不能是唯一编码，悬停提示不能是唯一入口。大数据量用 Canvas 或 WebGL 绘制，语义层只维护少量可访问节点，实时数据合并播报并尊重减少动态效果设置。

  • WebGL 着色器如何工作？如何避免把 GPU 当成黑盒？

    顶点着色器把顶点变换到裁剪空间，片元着色器计算每个片元的颜色，之后还有深度测试和混合。理解坐标空间、属性与 uniform 的区别、片元阶段的分辨率成本和精度，并给出一个完整的三角形绘制示例。

  • Three.js 页面退出后为什么还占内存？怎样管理模型和渲染器的生命周期？

    scene.remove 只是把对象移出场景，几何体、材质和纹理的 GPU 资源要分别 dispose，动画循环和监听器也要停止。独占资源由页面清理，共享资源由资源管理层按引用计数释放；异步加载的结果可能在页面离开后才返回。
