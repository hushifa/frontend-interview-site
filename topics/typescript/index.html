TypeScript面试题

TypeScript 面试题，涵盖泛型、类型收窄、联合类型、type 与 interface、映射类型、条件类型和 infer，帮助理解前端类型建模与编译配置。共 19 道题。

  • any、unknown 和 never 分别适合什么场景？

    any 关闭类型检查并会沿赋值和属性访问扩散；unknown 能接收任意值，但使用前必须收窄，适合外部输入；never 表示不可能出现的值，用于穷尽检查和总是抛错的函数。void 表示调用方不使用返回值，与 never 不同。

  • type 和 interface 有哪些区别？

    两者都能描述对象和函数结构。interface 支持同名声明合并，extends 时会检查属性冲突，适合公开、可扩展的对象契约；type 能表达联合、元组、条件类型、映射类型和原始类型别名。交叉类型遇到冲突属性不会报错，而是得到 never。

  • 泛型解决了什么问题？如何约束泛型？

    泛型用类型参数把输入、输出和多个参数之间的类型关系保留下来，调用时通常由编译器推断。extends 约束类型参数至少要具备的结构，K extends keyof T 配合 T[K] 可以安全读取属性。类型参数可以有默认值；const 类型参数（5.0）保留字面量，NoInfer（5.4）阻止某个位置参与推断。

  • 如何用可辨识联合避免不合理的状态组合？

    用一个共同的字面量字段（status、kind）区分各个状态分支，每个分支只携带自己需要的数据，就不会出现"加载中同时出错"这类组合。switch 判别字段时 TypeScript 自动收窄，default 中用 never 做穷尽检查。联合只描述合法形态，状态迁移和竞态仍要单独处理。

  • TypeScript 怎样通过控制流缩小类型？

    TypeScript 根据 typeof、instanceof、in、相等比较、真值判断和提前返回，在每条执行路径上缩小变量的类型。自定义类型守卫和断言函数可以把运行时检查的结论告诉编译器，as 断言则不做任何检查。对象属性的收窄在回调中会失效，let 变量在最后一次赋值之后创建的闭包里可以保留收窄（5.4+）。

  • 映射类型与 Partial、Pick、Omit 如何用于接口建模？

    映射类型 [K in keyof T] 遍历键生成新属性，可以用 +/- 增减 readonly 和 ? 修饰符，用 as 子句重命名或过滤键。Partial、Required、Readonly、Pick、Omit、Record 都建立在它之上，只作用于顶层，也只改变类型：Omit 不会删除对象上的真实字段。

  • 条件类型、infer 和分布式条件类型如何理解？

    条件类型 T extends U ? X : Y 按类型的可赋值关系选择结果，infer 在匹配的结构中声明待推断的类型变量。条件左侧是裸类型参数时，传入联合会对每个成员分别计算；用 [T] extends [U] 包裹可以整体判断。never 作为分布式参数时结果仍是 never。

  • as const、类型注解和 satisfies 有什么不同？

    类型注解让变量采用注解类型，具体字面量信息会丢失；as const 把表达式推断为最窄的只读字面量类型；satisfies（4.9）检查值是否符合某个类型，同时保留表达式自身推断出的具体类型。三者都只在编译期起作用，不会冻结对象或校验运行时数据。

  • 结构类型、可选属性和额外属性检查有哪些区别？

    TypeScript 按结构判断兼容性，只要具备目标要求的成员即可赋值，不看类型名称。新鲜的对象字面量直接赋给有类型的目标时会额外检查多余属性，经变量中转则不会。类型标注不会删除运行时多出的字段。需要名义区分时用品牌类型。

  • strict、noUncheckedIndexedAccess 和 target 如何配置？

    tsconfig 分别控制检查强度、语法输出、可用的类型声明和模块解析。TypeScript 6.0 起 strict 默认开启、target 默认为最新 ES、module 默认 esnext、types 默认空数组，并弃用了 ES5、node10 解析、baseUrl 等；TypeScript 7.0 删除了这些选项。target 和 lib 只影响类型和语法转换，不会注入 polyfill。

  • 为什么 TypeScript 不能替代接口数据校验？

    TypeScript 类型在编译后被删除，JSON.parse、fetch 返回的数据不受任何检查，as User 或 get<User>() 只是声明预期。应在网络响应、本地存储、URL 参数等信任边界把数据当作 unknown，用 Zod、Valibot 等 schema 库或手写守卫解析，再从 schema 推导类型。

  • 函数重载、联合参数与泛型怎样选择？函数类型何时可赋值？

    多种输入走同一逻辑、返回同一类型时用联合参数；返回类型由输入类型决定时用泛型；几种离散调用形式各自返回不同类型时用重载，实现签名对调用方不可见。函数赋值时参数按逆变检查（strictFunctionTypes），返回值按协变检查；方法简写语法的参数仍按双变检查。

  • .d.ts 声明文件提供了什么，不能保证什么？

    .d.ts 只描述 JavaScript 已有的导出和全局变量的类型，编译后不产生代码。声明与实现是否一致由发布者负责：声明写了导出，运行时不一定真有。包通过 exports 的 types 条件或 types 字段暴露声明，没有自带类型的库用 @types 包，全局变量用 declare 声明。

  • 项目引用与 tsc -b 如何管理多包类型构建？

    references 声明 TypeScript 项目之间的依赖，被引用项目开启 composite 并输出声明文件，tsc -b 按依赖顺序构建并通过 .tsbuildinfo 跳过未变化的项目。TypeScript 5.6 起上游出错时 tsc -b 仍继续构建下游，--stopBuildOnErrors 恢复旧行为。它不负责安装依赖、解析包名或打包。

  • TypeScript 新装饰器与 experimentalDecorators 有何区别？

    TypeScript 5.0 起默认支持 TC39 装饰器提案：装饰器接收 (value, context) 两个参数，通过返回值替换成员、通过 context.addInitializer 注册初始化逻辑。旧的 experimentalDecorators 接收 (target, key, descriptor)，支持参数装饰器和 emitDecoratorMetadata。两者不兼容，依赖旧语义的框架（如 NestJS、TypeORM）不能直接切换。

  • import type 和 verbatimModuleSyntax 如何影响模块输出？

    import type 整条导入在编译后删除，模块不会被加载。开启 verbatimModuleSyntax 后，TypeScript 按源码写法保留导入：没有 type 修饰的名字一律保留，只用作类型却没标 type 会报错；import { type A } 只删除 A，留下 import {} 仍会执行模块副作用。Node.js 类型剥离、esbuild 等单文件转换器依赖这种显式标注。

  • TypeScript 库发布时怎样组织类型声明和入口？

    用 package.json 的 exports 为每个入口声明 types 和 JavaScript 条件，types 放在最前；声明文件的模块格式必须和对应 JS 一致，ESM 用 .d.ts/.d.mts，CommonJS 用 .d.cts。发布前用 npm pack 生成的包在独立项目里按包名安装验证，可借助 publint 和 Are the Types Wrong 检查。

  • TypeScript 声明合并和模块扩展有哪些边界？

    同名 interface 合并成员，namespace 可以与函数、类、枚举合并来添加静态成员，declare module 和 declare global 可以给已有模块或全局对象补充类型。这些扩展只改变类型，运行时实现必须另外提供并确保被加载。含运行时代码的 namespace 不是可擦除语法，在 erasableSyntaxOnly 和 Node.js 类型剥离下会报错。

  • TypeScript 复杂类型应该怎样测试？

    公共 API 的类型应像代码一样测试：正向用例检查推断结果是否精确，负向用例用 @ts-expect-error 确认非法调用会报错，再用 Equal 类型或 expectTypeOf 检查类型完全相等以发现退化成 any。类型测试放进与发布一致的 tsc --noEmit 检查，与运行时测试互不替代。
