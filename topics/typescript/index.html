TypeScript面试题

TypeScript 面试题，涵盖泛型、类型收窄、联合类型、type 与 interface、映射类型、条件类型和 infer，帮助理解前端类型建模与编译配置。共 26 道题。

  • TypeScript 的 enum、const enum 和联合类型怎样选？

    enum 会编译成运行时对象，数字枚举还带反向映射；const enum 在使用处内联成常量，但单文件转译和发布 .d.ts 时有坑；字符串字面量联合或 as const 对象完全可擦除。开启 isolatedModules 或 erasableSyntaxOnly 的项目，优先用联合类型和 as const 对象。

  • TypeScript 中的协变和逆变是什么？

    协变是“子类型关系方向不变”，比如 Dog 能赋给 Animal，() => Dog 也能赋给 () => Animal；逆变是方向反过来，出现在函数参数位置。TypeScript 的数组按协变处理，这并不安全；strictFunctionTypes 让函数类型参数按逆变检查，但方法简写仍是双变。TypeScript 4.7 起可以用 in/out 显式标注类型参数的方差。

  • 怎样手写 MyPick、MyOmit、DeepReadonly、TupleToUnion、First、Awaited 这类类型体操？

    类型体操题大多靠三个套路：映射类型遍历键并加减修饰符，T[number] 这类索引访问取出元素类型，条件类型配合 infer 匹配结构再递归。写完要用 @ts-expect-error 和类型相等断言验证。

  • 装饰器元数据怎样支撑依赖注入？NestJS 和 Angular 是怎么做的？

    开启 experimentalDecorators 和 emitDecoratorMetadata 后，TypeScript 会给带装饰器的类生成 design:paramtypes 元数据，记录构造函数参数的类型，配合 reflect-metadata 在运行时读出来，容器就能按类型自动创建依赖，NestJS 正是这样按类型解析依赖。接口在编译后不存在，要用 @Inject(token) 指定。TS 5.0 的标准装饰器不生成这种元数据，5.2 起可以通过 context.metadata 和 Symbol.metadata 自己记录；Angular 推荐用 inject() 函数获取依赖。

  • 类型断言、非空断言、as unknown as 和 satisfies 有什么区别？

    类型断言 as T 是告诉编译器“按 T 来看这个值”，只在两种类型有关联（一方更具体或更宽泛）时才允许，编译后被删除，没有运行时检查。非空断言 x! 是去掉 null 和 undefined 的断言。as unknown as T 先转成 unknown 再转成 T，绕过“类型要有关联”的限制，几乎什么都能转。satisfies 不改变值的类型，只检查值能不能赋给目标类型，写错会报错，所以比断言安全。

  • keyof、typeof、索引访问类型和索引签名分别做什么？

    keyof 取出对象类型所有键组成的联合类型；类型位置的 typeof 从一个变量拿到它的类型；索引访问类型 T[K] 按键查出属性的类型，T[number] 能取数组元素类型。三者常组合成 keyof typeof obj 和 (typeof arr)[number]。索引签名 [key: string]: V 描述键名事先不知道的字典，所有具名属性都要符合它，读任意键默认被当成 V，开启 noUncheckedIndexedAccess 才会加上 undefined。

  • TypeScript 的 class 中 public、private、protected 和

    public 是默认可见性；protected 只能在类和子类里访问；private 只能在声明它的类里访问，但只在类型检查时生效，编译后仍是普通属性，还能用方括号绕过。#private 是 JavaScript 的私有字段，运行时也访问不到。readonly 让属性只能在声明处或构造函数里赋值。参数属性在构造函数参数前加修饰符，自动声明并赋值同名属性。abstract 类不能 new，抽象成员由子类实现；extends 继承实现，implements 只检查类是否符合接口，不改变类的类型。

  • any、unknown 和 never 分别适合什么场景？

    any 等于关掉类型检查，而且会顺着赋值扩散；unknown 什么都能接收，但用之前必须先判断类型，适合外部输入；never 表示不可能出现的值，用来做穷尽检查。

  • type 和 interface 有哪些区别？

    描述普通对象时两者差不多。interface 能同名合并，适合可扩展的对象契约；type 能写联合、元组、条件类型等 interface 写不了的东西。

  • 泛型解决了什么问题？如何约束泛型？

    泛型就是把类型也当成参数，调用时再确定，这样“传进什么类型就返回什么类型”的关系不会丢。extends 用来限制这个类型参数至少要有哪些结构。

  • 映射类型与 Partial、Pick、Omit 如何用于接口建模？

    映射类型就是遍历一个类型的所有键，生成一个新类型；Partial、Pick、Omit 这些内置工具都是这么写出来的。它们只改顶层、只改类型，Omit 不会真的删掉对象上的字段。

  • TypeScript 怎样通过控制流缩小类型？

    写了 typeof、instanceof、in 这类判断或者提前 return 以后，TypeScript 会顺着代码路径推出变量在这里只可能是哪些类型，这叫类型收窄。as 断言不做检查，只是让编译器换个角度看。

  • 如何用可辨识联合避免不合理的状态组合？

    给每种状态一个固定的标签字段，比如 status，每种状态只带自己需要的数据，就不会出现“加载中同时又出错”这种组合。按标签 switch 时 TypeScript 会自动缩小类型。

  • 结构类型、可选属性和额外属性检查有哪些区别？

    TypeScript 判断能不能赋值，看的是结构，只要有目标要求的成员就行，不看类型叫什么名字。直接写出的对象字面量多了字段会报错，经过变量中转就不会。

  • 条件类型、infer 和分布式条件类型如何理解？

    条件类型就是类型层面的三元表达式 T extends U ? X : Y，infer 用来从匹配的结构里“抠出”一部分类型。传入联合类型时，它会对每个成员分别计算再合并，这叫分布式条件类型。

  • as const、类型注解和 satisfies 有什么不同？

    类型注解让变量直接变成注解的类型，具体信息会丢；as const 把值推断成最窄的只读字面量；satisfies 检查值符不符合某个类型，同时保留它自己推断出的具体类型。

  • strict、noUncheckedIndexedAccess 和 target 如何配置？

    tsconfig 管几件不同的事：检查有多严、输出什么版本的语法、能用哪些内置 API 的类型、模块怎么解析。target 和 lib 只影响类型和语法转换，不会补上运行时缺的 API。

  • .d.ts 声明文件提供了什么，不能保证什么？

    .d.ts 是写给编译器看的“说明书”，告诉它一段 JavaScript 有哪些导出、各是什么类型，本身不产生任何代码。说明书写得对不对由发布者负责，编译器不会去核对真实实现。

  • 为什么 TypeScript 不能替代接口数据校验？

    TypeScript 的类型编译后就被删掉了，接口返回的数据长什么样，它根本看不到，as User 只是一句声明。所以外部数据进来时要当作 unknown，用 schema 或手写函数真正检查一遍。

  • 函数重载、联合参数与泛型怎样选择？函数类型何时可赋值？

    输入不同但返回同一种类型，用联合参数；返回类型跟着输入变，用泛型；几种固定的调用方式各自返回不同类型，用重载。函数之间赋值时，参数要能接受更宽的输入，返回值要更具体。

  • import type 和 verbatimModuleSyntax 如何影响模块输出？

    import type 整条导入编译后会被删掉，模块不会被加载。开启 verbatimModuleSyntax 后，TypeScript 按你写的样子保留导入，只当类型用却没标 type 的导入会报错，Node.js 类型剥离和 esbuild 这类工具靠的就是这种标注。

  • TypeScript 声明合并和模块扩展有哪些边界？

    同名的 interface 会自动合成一个，declare module 和 declare global 可以给已有的模块或全局对象补类型。这些写法只补类型，真正的实现要另外写，并且确保那段代码被加载。

  • TypeScript 库发布时怎样组织类型声明和入口？

    在 package.json 的 exports 里给每个入口同时写上类型声明和 JS 文件，types 放第一位；声明文件的模块格式要和对应的 JS 一致。发布前把打好的包装到一个独立项目里，按包名导入验证。

  • 项目引用与 tsc -b 如何管理多包类型构建？

    项目引用就是在 tsconfig 里写明“这个包依赖那个包”，tsc -b 按依赖顺序构建，没变化的包直接跳过。它只管类型检查和 tsc 输出，不管安装依赖、包名解析和打包。

  • TypeScript 新装饰器与 experimentalDecorators 有何区别？

    TypeScript 5.0 起默认支持标准装饰器，它接收 (value, context) 两个参数；旧的 experimentalDecorators 接收 (target, key, descriptor)，还支持参数装饰器和反射元数据。两套写法不兼容，依赖旧语义的框架不能直接切换。

  • TypeScript 复杂类型应该怎样测试？

    公开 API 的类型也要像代码一样写测试：检查推断结果是否精确，检查非法调用会不会报错，再用精确相等判断防止类型悄悄退化成 any。类型测试和运行时测试互相替代不了。
