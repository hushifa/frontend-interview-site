TypeScript面试题

TypeScript 面试题，涵盖泛型、类型收窄、联合类型、type 与 interface、映射类型、条件类型和 infer，帮助理解前端类型建模与编译配置。共 19 道题。

  • any、unknown 和 never 分别适合什么场景？

    any 放宽常见类型检查，unknown 要求先证明值能怎样使用，never 表示类型系统认为不可能出现的值。它们分别影响检查边界、输入处理和分支完整性，不能互相当作消除报错的替代品。

  • type 和 interface 有哪些区别？

    interface 和类型别名都能描述对象契约，主要差别在于可表达的类型形式、声明合并与组合方式。扩展冲突、联合关系和公共 API 的开放性，比简单规定“对象只准用某一种”更值得关注。

  • 泛型解决了什么问题？如何约束泛型？

    泛型用类型参数保留输入、输出与不同参数之间的关系，约束说明实现可以依赖哪些能力。满足约束不代表能随意构造任意 T，类型参数也不会在运行时校验接口数据。

  • 如何用可辨识联合避免不合理的状态组合？

    用稳定的字面量字段区分状态分支，并让分支携带自身必需的数据，可以减少布尔值和可选字段形成的无效组合。穷尽检查能发现遗漏分支，但状态迁移、异步竞态和外部输入仍需运行时设计。

  • TypeScript 怎样通过控制流缩小类型？

    类型收窄根据实际判断、赋值和可达路径排除不可能类型。正确的运行时证据、可信的类型谓词及对可变状态的认识，决定了这种分析能提供多强的保证。

  • 映射类型与 Partial、Pick、Omit 如何用于接口建模？

    映射类型根据键集合生成新的属性类型，工具类型封装了常见的选取、排除和修饰符变换。它们通常只改变顶层静态结构，不会执行字段过滤、默认值填充或深度冻结。

  • 条件类型、infer 和分布式条件类型如何理解？

    条件类型根据类型可赋值关系选择结果，infer 在匹配结构中提取组成部分。裸类型参数会对联合成员分别计算，元组包装则可改为整体判断；never、any 和重载需要单独理解。

  • as const、类型注解和 satisfies 有什么不同？

    类型注解规定变量采用的静态契约，as const 保留字面量并给相应字面结构增加只读约束，satisfies 检查兼容性同时保留表达式自身的具体推导。上下文类型仍可能影响推导，三者都不等同于运行时冻结或校验。

  • 结构类型、可选属性和额外属性检查有哪些区别？

    TypeScript 主要按成员结构判断兼容性，对象字面量还会接受额外属性检查。可选属性与显式 undefined、字段隐藏与运行时删除、结构相同与业务身份相同，都是需要分别处理的问题。

  • strict、noUncheckedIndexedAccess 和 target 如何配置？

    编译配置应分别决定检查强度、环境类型、语法输出与模块解析。strict 不包含所有严格选项，target 与 lib 不安装 polyfill，类型检查、构建转换和运行时支持需要彼此匹配。

  • 为什么 TypeScript 不能替代接口数据校验？

    静态类型约束已知代码之间的使用关系，接口响应等外部值仍需要运行时解析。校验应同时处理结构、业务约束和转换策略，成功后再向内部代码提供可信类型，并明确失败与诊断方式。

  • 函数重载、联合参数与泛型怎样选择？

    联合参数适合统一处理不同输入，泛型保留输入输出关系，重载描述不同调用形式。函数赋值还要考虑参数方向、返回值和 strictFunctionTypes，不能只看某个参数类型是否更具体。

  • .d.ts 声明文件提供了什么，不能保证什么？

    声明文件描述模块或宿主已有能力的类型契约，供编译器检查与编辑器补全使用。它不实现函数、不安装全局对象，也不保证声明与运行库版本永远一致，需要通过真实消费者验证。

  • 项目引用与 tsc -b 如何管理多包类型构建？

    references 声明 TypeScript 项目间的构建依赖，composite 为可引用项目建立明确边界，tsc -b 按依赖处理声明与增量产物。它不负责运行时包解析，也不能代替工作区或打包器配置。

  • TypeScript 新装饰器与 experimentalDecorators 有何区别？

    TypeScript 支持现代装饰器语义，也保留 experimentalDecorators 对应的旧方案。它们的参数、返回与初始化机制不同，元数据和参数装饰器能力也不能互换，迁移必须验证库与构建链。

  • import type 和 verbatimModuleSyntax 如何影响模块输出？

    import type 表达纯类型依赖，verbatimModuleSyntax 让类型修饰符直接决定相关导入导出的保留方式。整条类型导入与普通导入中的 type 成员并不完全相同，模块副作用和运行时解析仍需显式设计。

  • TypeScript 库发布时怎样组织类型声明和入口？

    库发布需要同时提供可解析的 JavaScript 入口、与模块格式匹配的声明入口，以及完整的产物依赖。应从实际安装包验证消费者，而不是只检查源码仓库里的路径别名和类型编译。

  • TypeScript 声明合并和模块扩展有哪些边界？

    声明合并让符合规则的同名声明共同描述一个实体，模块增补则补充已有模块的类型视图。接口与环境声明不会自动提供运行时方法，普通 namespace 却可能产生代码，必须区分这些层次。

  • TypeScript 复杂类型应该怎样测试？

    用正向和负向类型用例验证泛型、重载和导出 API，说明 @ts-expect-error、satisfies 与运行时测试各自能证明什么，避免把类型推导当成运行时校验。
