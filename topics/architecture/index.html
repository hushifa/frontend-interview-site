架构设计面试题

前端架构设计面试题，讨论设计系统、组件规范、异步状态建模、渐进增强与优雅降级，关注项目长期维护。共 7 道题。

  • 设计系统为什么不能只有一套视觉样式？

    从按钮和表单的实际使用说明设计系统还需要交互、语义和组件契约，并解释 token、业务组件、文档测试及版本迁移各自的职责。

  • 怎样避免加载、成功和失败状态互相矛盾？

    从合法业务状态与转换出发组织请求界面，给出能拒绝过期完成事件的纯状态转换函数，并区分互斥状态、刷新中的旧数据和外部副作用。

  • 渐进增强和优雅降级怎样影响前端方案选择？

    从最低可用任务出发区分两种设计方向，说明静态内容、原生能力、特性检测与运行时失败的关系，并解释怎样避免增强层反而破坏基础功能。

  • 前端大型项目怎样划分功能边界？

    围绕一起变化的业务能力组织模块，明确公开接口、依赖方向和状态归属，并用订单功能说明如何逐步拆分而不制造新的耦合。

  • 设计 token 为什么比散落的颜色变量更适合大型前端项目？

    用主题按钮说明基础值、语义与组件映射，解释 token 和 CSS 自定义属性的关系、继承时的求值边界，以及怎样避免无意义的抽象层。

  • 微前端适合解决什么组织和部署问题？

    从团队独立交付的需求判断微前端是否值得，比较构建集成、运行时集成与 iframe，并说明契约、依赖、故障、隔离和回滚成本。

  • 事件驱动 UI 怎样避免状态互相覆盖？

    区分命令、事件与状态所有者，用可取消的最新搜索控制器解释请求身份和过期结果，并说明重复事件、DOM 事件及隐式总线的边界。
