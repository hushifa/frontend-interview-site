工程化面试题

前端工程化面试题，涵盖 Vite、webpack、Tree shaking、代码分割、npm 与 lockfile、Monorepo、Source Map、浏览器兼容和包管理。共 30 道题。

  • 前端模块化经历了哪些阶段？IIFE、CommonJS、AMD、UMD 和 ES Modules 有什么区别？

    早期靠 script 标签和全局变量，后来用 IIFE 包一层隔离作用域；Node.js 采用同步 require 的 CommonJS，浏览器端出现异步加载的 AMD；UMD 用一段判断同时兼容 AMD、CommonJS 和全局变量；最后语言标准给出了 ES Modules。

  • 前端怎样做浏览器兼容？怎样确定要支持哪些浏览器？

    先用自己网站的访问统计和业务要求定出支持范围，写成 browserslist 配置，让 Babel、Autoprefixer 等工具共用；开发时用 @supports 和 if ('x' in obj) 做特性检测，按渐进增强先保证基础功能可用，缺失的 API 按需加 polyfill；最后在范围内的最低版本和真机上测试，并定期更新浏览器数据。

  • webpack 的 entry、output、loader 和 plugin 分别负责什么？

    entry 是依赖入口，output 决定产物，loader 做模块转换，plugin 通过生命周期钩子扩展构建。文中用一个完整配置讲 loader 顺序、publicPath、mode 和排错方法。

  • Vite 开发模式为什么启动快，生产环境为什么仍需要构建？

    开发时 Vite 靠原生 ESM 按需处理模块，加上依赖优化和 HMR，所以启动快；生产仍要打包，是为了减少请求、缩小体积、利用缓存。文中也区分了 Vite 8 和旧版本的工具链。

  • Babel 是怎样把新语法转成旧语法的？语法转换和 polyfill 有什么区别？

    Babel 先把源码解析成 AST，再由插件遍历 AST 改写节点，最后生成新代码。插件按配置顺序执行，preset 按相反顺序执行。箭头函数、可选链这类语法可以改写，Promise、Array.prototype.includes 这类 API 要靠 core-js 等 polyfill 补上。

  • webpack 的 loader 和 plugin 有什么区别？怎样手写一个？

    loader 是一个函数，接收一个文件的内容，返回转换后的内容，多个 loader 从右往左执行；plugin 是带 apply 方法的对象，通过 compiler 和 compilation 上的钩子介入整个构建，能做生成文件、改产物这类 loader 做不到的事。文中各手写一个，并讲 this.async、getOptions 和 processAssets。

  • Vite 和 webpack 有什么区别？项目里应该怎样选？

    区别主要在开发阶段：webpack 先把整个应用打包再启动开发服务器，Vite 让浏览器按原生 ESM 按需请求源码，只预构建依赖，所以启动和热更新更快。生产环境两者都要打包。webpack 配置更细、生态更久，适合已有大型项目和特殊构建需求；新项目多数可以直接用 Vite。

  • npm、yarn 和 pnpm 有什么区别？幽灵依赖是什么？

    npm 和 Yarn Classic 把依赖提升到 node_modules 根目录，形成扁平结构，代码能用到没声明的包，这就是幽灵依赖。pnpm 把文件存在内容寻址的全局仓库，用硬链接装进项目，再用符号链接只把直接依赖放到根目录，所以省磁盘、依赖也更严格。Yarn Berry 默认用 PnP，不生成 node_modules。

  • AST 在前端工程里有什么用？Babel、ESLint 和代码转换是怎样用它的？

    AST 是把代码解析成的一棵树，每个节点表示一个语法结构。Babel 按“解析 → 遍历改写 → 生成代码”转换语法，ESLint 遍历 AST 找出有问题的写法，Prettier 按 AST 重新打印代码，jscodeshift 这类 codemod 工具批量改写代码。文中手写一个遍历器，演示只读检查和改写节点。

  • Tree shaking 如何工作？为什么有些代码无法移除？

    Tree shaking 删掉没被使用、也没有副作用的代码。文中从导出使用关系和模块副作用两类分析讲起，解释 ESM、sideEffects 和纯调用标注的作用，以及为什么要看真实构建结果验证。

  • 从 0 搭建一个前端项目要做哪些事？

    先定技术栈和约束，再用官方脚手架创建项目，固定 Node 和包管理器版本，配好 TypeScript、ESLint、Prettier 和提交前检查，约定目录、环境变量和接口层，最后接上 CI、测试、构建部署和错误监控。每一步都要能被新人一条命令复现。

  • 热更新（HMR）是怎样实现的？为什么有时候会整页刷新？

    开发服务器监听文件变化，重新编译改动的模块，通过 WebSocket 通知浏览器；浏览器里的 HMR 运行时下载新模块，从改动的模块沿着导入链往上找能接受更新的模块，执行替换，页面状态得以保留。找不到能接受更新的模块，就退回整页刷新。

  • Monorepo 怎样管理版本和发包？Changesets 和 Lerna 有什么区别？

    Changesets 让开发者在提交改动时写一个 changeset 文件，说明哪些包要升 major、minor 还是 patch，以及更新日志写什么。发版时 changeset version 把这些文件合并，每个包取最高的升级类型，更新版本号、内部依赖范围和 CHANGELOG，再由 changeset publish 发布 npm 上还没有的版本。Lerna 的 lerna version 在发版时统一选版本，默认所有包共用一个版本号，也可以切到独立模式，或者用 --conventional-commits 根据提交信息推算版本。

  • ESLint、Prettier、husky 和 lint-staged 分别做什么？怎样配合？

    ESLint 按规则找出可能的 bug 和不推荐的写法，部分规则能自动修复；Prettier 不按规则，而是把整段代码重新打印成统一格式；husky 帮你配置 Git 钩子，比如在提交前执行命令；lint-staged 只对暂存区的文件运行这些检查。常见做法是 husky 的 pre-commit 钩子调用 lint-staged，lint-staged 再对改动的文件跑 ESLint 和 Prettier。

  • Rspack、Turbopack、Rolldown 这类 Rust 构建工具解决什么问题？

    它们都想解决 JavaScript 写的打包工具在大项目里太慢的问题：用 Rust 编写、利用多核并行，把常用的转换内置进来，减少调用 JavaScript 插件的开销。区别在于兼容谁：Rspack 兼容 webpack 的配置、loader 和大部分插件，方便老项目迁移；Turbopack 内置在 Next.js 里，现在是 Next.js 的默认打包工具，靠增量计算和按需打包提速，不支持 webpack 插件；Rolldown 兼容 Rollup 的插件接口，是 Vite 的底层打包工具。

  • 代码分割与懒加载适合哪些场景？

    代码分割把产物拆成多个文件，懒加载让一部分等到需要时才加载。文中用动态导入 import() 的例子讲模块缓存、取消边界和生命周期，以及预加载、错误恢复和旧版本资源问题。

  • webpack 构建慢、产物大，应该怎样优化？

    先用 speed-measure 之类的工具和 bundle 分析找到慢在哪、大在哪。提速主要靠持久化缓存（cache.type: 'filesystem'）、缩小 loader 处理范围、用 esbuild 或 SWC 替代 babel-loader、多进程处理；减小体积靠 Tree shaking、代码分割、压缩，以及把大依赖换成更小的或按需引入。

  • 编译目标、polyfill 和浏览器兼容性是什么关系？

  • Source Map 如何帮助定位压缩后代码的错误？

    Source Map 把压缩后文件里的行列映射回源码位置。前提是映射、脚本和发布版本来自同一次构建；它只改善调试，不能保密源码，也不修复异常。

  • Monorepo 与 npm workspaces 能解决什么问题？

    Monorepo 把相关项目放进一个仓库，工作区负责本地包互相链接，任务编排工具负责构建顺序和缓存。文中用应用与组件包的例子讲依赖声明、构建顺序、发布验证和逐步采用的边界。

  • pnpm workspace 怎样管理多包前端仓库？

  • 前端构建产物应该怎样分析体积？

    产物分析要把文件大小、网络传输、解析执行和真实入口联系起来，找出不必要的提前加载、重复依赖和错误分块，再用同口径数据验证收益。

  • package.json 的 exports 和 imports 分别解决什么问题？

    exports 决定包对外公开哪些入口，imports 给包内部提供
