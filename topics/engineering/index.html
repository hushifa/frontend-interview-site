工程化与性能面试题

前端工程化面试题，涵盖 Vite、webpack、Tree shaking、代码分割、npm 与 lockfile、Monorepo、Source Map、浏览器兼容和包管理。共 17 道题。

  • Tree shaking 如何工作？为什么有些代码无法移除？

    理解静态模块结构、使用关系和副作用分析。

  • LCP、INP、CLS 分别衡量什么？

    从加载、交互和视觉稳定性衡量真实用户体验。

  • 代码分割与懒加载适合哪些场景？

    平衡首屏下载量和后续交互时的等待。

  • 为什么需要提交 lockfile？npm ci 和 npm install 有何区别？

    让本地开发与自动部署尽可能使用一致的依赖树。

  • Vite 开发模式为什么启动快，生产环境为什么仍需要构建？

    Vite 的开发服务器利用浏览器原生 ESM，按请求提供和转换模块，减少启动前必须完整打包应用的工作。依赖优化与源码处理采取不同策略，以改善开发启动和模块更新体验。

  • webpack 的 entry、output、loader 和 plugin 分别负责什么？

    entry 确定依赖图入口，output 决定产物位置和命名。loader 让模块在进入后续构建流程时进行转换，例如处理不同语言或资源；plugin 可挂接构建生命周期，处理更广泛的构建任务。

  • 为什么前端环境变量不能存放秘密？

    客户端能够读取的配置最终必须交付给浏览器。Vite 默认通过 VITE 前缀暴露特定环境变量，这些值可能在构建时进入产物；即使不直接显示在界面里，也不能当作秘密。

  • Monorepo 与 npm workspaces 能解决什么问题？

    Monorepo 把多个相关包放在同一仓库中，便于跨包修改和统一协作；workspaces 为本地包的识别、链接和命令执行提供支持。仓库组织方式与包发布方式并不是同一个概念。

  • 编译目标、polyfill 和浏览器兼容性是什么关系？

    构建工具可以把部分较新语法转换成目标环境支持的形式，但语法转换不等于为所有缺失的 Web API 或内置方法补实现。例如修改 target 并不自动让旧浏览器拥有任意新 API。

  • Source Map 如何帮助定位压缩后代码的错误？

    Source Map 建立生成代码与原始源码之间的位置映射，让调试器或错误平台把压缩文件中的行列对应回开发源码。它不会改变线上实际执行的代码，也不会自动修复错误。

  • package.json 的 exports 和 imports 分别解决什么问题？

    exports 定义包对消费者公开的入口和子路径，也可按 import、require 等条件选择不同目标。在支持的 Node.js 版本中，它优先于 main。已有包新增 exports 时，原先可深层导入却未被列出的路径可能失效，…

  • 语义化版本号能否保证升级一定安全？

    语义化版本以公开 API 为依据：不兼容变更增加主版本，向后兼容的新功能增加次版本，向后兼容的问题修复增加修订版本。发布新的主版本或次版本时，较低位需要归零。

  • Vite 插件的 resolveId、load 和 transform 分别做什么？

    理解 Vite/Rollup 插件钩子的职责和执行顺序，避免把虚拟模块、源码转换和开发服务器逻辑混在一起。

  • ESLint Flat Config 和旧配置方式有什么区别？

    理解 eslint.config.js 的配置数组、插件导入和文件匹配，迁移时避免把旧的字符串扩展配置直接照搬。

  • pnpm workspace 怎样管理多包前端仓库？

    了解 workspace 协议、依赖隔离和过滤执行，设计可复现的 Monorepo 安装与构建流程。

  • 前端构建产物应该怎样分析体积？

    通过统计报告和 source map 找出大依赖、重复模块和错误引入，避免只看总 KB 数字。

  • Corepack 和 packageManager 字段怎样固定包管理器？

    通过项目声明和工具版本统一 npm、pnpm 或 Yarn 的安装方式，减少本地与 CI 的差异。
