移动端与 PWA面试题

移动端与 PWA 面试题，涵盖渐进式 Web 应用、Service Worker 缓存更新，以及 React Native 与浏览器端 React 的差异。共 18 道题。

  • 移动端怎样做屏幕适配？1px 边框为什么看起来变粗了？

    移动端适配先写 viewport meta，让布局宽度等于设备宽度；尺寸用 rem 或 vw 随屏幕缩放，或者用 Flex、Grid 和媒体查询做流式布局。1px 变粗是因为高 DPR 屏幕上 1 个 CSS 像素对应多个物理像素，常用 transform 缩放或 0.5px 来画细线。

  • Hybrid 开发是什么？JSBridge 的 URL Scheme 拦截和注入对象有什么区别？

    Hybrid 应用是在原生 App 里嵌 WebView 加载网页，网页通过 JSBridge 调用拍照、分享等原生能力。网页调原生有两种做法：跳转一个自定义协议的地址让原生在导航回调里拦截，或者由原生往页面注入对象，Android 用 addJavascriptInterface，iOS 用 WKScriptMessageHandler。原生调网页用 evaluateJavascript 执行脚本。注入对象要防止不可信页面调用。

  • Flutter、React Native 和 Web 跨端怎么选？一套代码能同时跑在 App 和浏览器里吗？

    三者画界面的方式不同。Flutter 用自己的引擎绘制，移动端编译成机器码，Web 端编译成 JavaScript 或 WebAssembly 并用 CanvasKit、Skwasm 渲染到画布上，官方说明它不适合以文字为主的静态网站和 SEO。React Native 运行时创建 Android、iOS 原生视图，Web 端要靠社区的 React Native Web。纯 Web 用 HTML 渲染，最适合内容和搜索，也能做成可安装的 PWA。选型先看 Web 端是内容页还是应用，再看团队技术栈和原生能力需求。

  • Hybrid 离线包怎样设计？WebView 怎样拦截请求、加快首屏？

    离线包是把 H5 页面的 HTML、JS、CSS 提前下载到 App 本地，WebView 请求这些资源时由原生拦截并返回本地文件，省掉网络耗时。Android 用 shouldInterceptRequest 或 WebViewAssetLoader，iOS 用 WKURLSchemeHandler 处理自定义协议。离线包要有版本号和摘要校验，校验不过就回退到线上。Android 还可以用 startUpWebView 提前在后台初始化 WebView。

  • H5 页面怎样唤起 App？URL Scheme、Universal Links 和 App Links 有什么区别？

    H5 唤起 App 有两类办法：跳转 myapp:// 这样的自定义 URL Scheme，或者用普通 https 链接，让系统验证域名归属后直接交给 App，iOS 叫 Universal Links（apple-app-site-association），Android 叫 App Links（assetlinks.json + autoVerify）。没装 App 时，https 链接会在浏览器里打开网页，网页再引导去下载页或应用商店。

  • 移动端有哪些常见兼容问题？日期解析、点击延迟、点击穿透和滚动穿透怎么处理？

    移动端高频兼容坑合集：'2026-10-30 12:30' 这种非标准日期字符串在部分浏览器里得到 Invalid Date；双击缩放带来的 300ms 点击延迟和由它引出的点击穿透；弹窗里滚到底后背景页面跟着滚；输入框被键盘遮挡。逐个讲现象、原因和官方推荐的改法。

  • 移动端页面怎样在真机上调试？Safari Web Inspector、chrome://inspect 和 vConsole 各适合什么场景？

    真机上才出现的问题，要把手机里的页面接到电脑上的开发者工具里看。iPhone 用 Mac 上的 Safari Web Inspector，Android 用 Chrome 的 chrome://inspect，App 里的 WebView 要先由原生代码打开调试开关；连不上电脑时，用 vConsole、Eruda 在页面里嵌一个控制台。

  • PWA 由哪些能力组成，是否所有浏览器体验都一致？

    PWA 就是让网站能像应用一样安装、离线打开。讲清 Web App Manifest、Service Worker 和 HTTPS 各管什么，比较 Chromium 与 Safari/iOS 在安装、推送和后台能力上的差异，以及怎样做渐进增强。

  • Service Worker 的安装、激活与缓存更新有哪些坑？

    Service Worker 有自己的安装、等待和激活生命周期，注册成功不代表马上接管页面。新版本装好后默认要等旧页面全部关闭才激活，所以用户常常停在旧版本；更新时要处理等待中的新版本、旧缓存清理、importScripts 的 HTTP 缓存和新旧资源混用。

  • 移动端手势交互怎样避免和页面滚动冲突？

    手指一动，浏览器想滚动、页面想横滑，就会打架。用横滑删除卡片讲 touch-action、移动阈值和方向锁定怎么配合，怎样处理取消与多指，以及为手势提供可点击的替代操作。

  • Flutter、React Native 和小程序跨端方案怎样选？

    三者画界面的方式不同：Flutter 不用系统控件，用自带的 Impeller 引擎自己绘制，发布时编译成机器码；React Native 用 JavaScript 写 React 组件，运行时创建对应的 Android、iOS 原生视图；小程序运行在微信等宿主 App 里，逻辑层和 WebView 视图层分开。选型先看产品要不要独立 App、靠什么渠道获客，再看团队技术栈、对原生能力和性能的要求。

  • 移动端安全区域怎样避免内容被刘海和底部手势条遮挡？

    背景可以铺满屏幕，文字和按钮要躲开刘海和手势条。用 CSS 环境变量 env() 保护固定控件、滚动末尾和横屏边缘，动态工具栏和键盘要另外处理。

  • 移动端虚拟键盘出现时怎样避免布局被遮挡？

    键盘弹出时，用户能看到的区域变小了，页面布局却没变。区分布局视口和可视视口，用 VisualViewport、interactive-widget 和 VirtualKeyboard API 适配输入框与底部操作栏，并说明各方案的浏览器支持边界。

  • Pointer Events 为什么适合统一鼠标、触摸和触控笔交互？

    鼠标、手指、触控笔都用同一套事件处理。讲清 pointerdown、pointermove、pointerup、pointerId 和 pointer capture，避免为不同输入设备维护重复逻辑。

  • React Native 与浏览器里的 React 有哪些共同点和差异？

    React Native 写法和 React 一样，组件、状态和 Hooks 都能用，但画出来的是平台原生视图。要用 View、Text 等组件和 JS 样式对象，没有 DOM 和 CSS 层叠。

  • React Native 原生桥接和新架构应该怎样理解？

    旧架构里 JS 和原生靠 Bridge 传 JSON 消息，新架构改成直接调用。讲清 JSI、TurboModules、Fabric 和 Codegen 的职责，0.76 起默认启用、0.82 起只能使用新架构的现状，以及线程、类型契约和迁移边界。

  • Web Share API 使用时要处理哪些降级？

    navigator.share 能打开系统分享面板，但要用户点击触发、要安全上下文，平台支持也不全。要区分用户取消和真正失败，并为分享按钮准备复制链接等降级方案。

  • Screen Orientation API 的锁定和解锁有什么限制？

    Screen Orientation API 能读当前是横屏还是竖屏，也能在受支持的环境里请求锁定方向，适合全屏游戏这类沉浸式场景。普通页面应该优先做响应式布局，并处理好权限、失败和退出清理。
