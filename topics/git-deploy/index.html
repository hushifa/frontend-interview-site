Git 与部署面试题

前端 Git 与部署面试题，涵盖 merge、rebase、GitHub Actions 和静态网站发布，理解提交历史、自动化流程、资源路径与缓存。共 4 道题。

  • git merge 与 rebase 应该怎样选择？

    merge 保留分叉和汇合过程，rebase 重新建立提交的父子关系。选择时要结合分支是否共享、审查需求、冲突成本和回滚方式，而不是只追求一条直线。

  • GitHub Actions 中 workflow、job、step 和 runner 是什么关系？

    用前端检查流程解释自动化层级、执行环境和数据传递，区分顺序、缓存与产物，并说明检查成功不等于已经部署。

  • 静态托管发布时为什么要检查资源路径和缓存？

    静态部署把构建文件交给托管平台，浏览器仍需按正确前缀取得入口、脚本和数据。路径、深链接、缓存和发布版本必须一起验证。

  • 静态网站发布失败时怎样安全回滚？

    回滚前先判断故障在源码、构建产物、托管配置还是缓存层，再恢复已验证版本并检查入口、资源和关键交互；撤销 Git 提交不等于线上已经恢复。
