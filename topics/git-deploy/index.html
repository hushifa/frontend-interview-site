Git 与部署面试题

前端 Git 与部署面试题，涵盖 merge、rebase、GitHub Actions 和静态网站发布，理解提交历史、自动化流程、资源路径与缓存。共 4 道题。

  • git merge 与 rebase 如何影响提交历史？

    merge 将两条历史汇合，可能产生合并提交，也可能快进；rebase 将一组提交重新应用到新的基点，通常会生成新的提交对象和哈希。两者最终文件内容可以相同，但历史结构不同。

  • GitHub Actions 中 workflow、job、step 和 runner 是什么关系？

    workflow 定义自动化流程，通过 push、pullrequest、手动触发等事件启动。一个流程包含多个 job，每个 job 在 runner 上执行一组 step；step 可以运行命令或复用 action。

  • 静态托管发布时为什么要检查资源路径和缓存？

    静态托管提供 HTML、CSS、JavaScript 等文件，不会自动运行应用的 Node 服务端。构建后的站点必须使用部署环境能够提供的路径；仓库子路径与域名根路径的区别常导致脚本或图片 404。

  • 静态网站发布失败时怎样安全回滚？

    区分源码回滚、构建产物回滚和 DNS 回滚，设计可追溯且不覆盖用户数据的静态部署恢复流程。
