国际化面试题

前端国际化面试题，围绕 Intl、日期与金额格式化、字符串字符数量、时间戳和时区，理解多语言应用的数据展示。共 12 道题。

  • 为什么字符串 length 不一定等于用户看到的字符数？

    JavaScript 字符串的 length 是 UTF-16 码元数，一个 emoji 可能占两个码元，一个“字符”也可能由多个码点组成。按用户看到的字符截断要用 Intl.Segmenter 的字素簇分割，分词用 word 粒度，字节数用 TextEncoder 统计，比较前按需 normalize。

  • 时间戳、时区和只有日期的业务值应该怎样区分？

    时间戳是一个确定的瞬间，时区决定它显示成哪个当地时间；生日这类只有日期的值不该转成 Date；未来的当地时间日程要保存本地时间加 IANA 时区。夏令时让“加一天”和“加 24 小时”结果不同，Temporal 为这三种语义提供了不同类型。

  • 为什么日期、金额和排序不应该手动拼接格式？

    日期顺序、数字分隔符、货币符号位置和字母顺序都随地区变化，手动拼接只能照顾一种习惯。用 Intl.NumberFormat、DateTimeFormat、Collator 按 locale 格式化和排序；存储和接口传原始值，格式化后的字符串只用于显示。

  • 前端翻译工作流怎样避免把文案写死在组件里？

    组件里只写稳定的消息键并传入变量，翻译放在按语言拆分的消息目录里，由消息格式库处理插值和复数。统一定义语言回退链，在 CI 中检查缺失键和占位符，异步加载语言包时防止旧请求覆盖新选择。

  • Intl.PluralRules 怎样帮助实现国际化复数？

    Intl.PluralRules 告诉你一个数字在某种语言里属于哪个复数类别（zero、one、two、few、many、other），应用再用类别去选完整的消息分支。基数和序数规则不同，显示的小数位数也会影响类别。

  • ICU MessageFormat 为什么适合复杂国际化文案？

    ICU MessageFormat 把一整句话写成一条消息，变量、plural 和 select 分支都写在里面，翻译者能按目标语言调整整句词序。JavaScript 中要用 FormatJS 等库解析；用户内容只能作为变量值传入，不能拼进模板。

  • Intl.RelativeTimeFormat 怎样正确显示相对时间？

    Intl.RelativeTimeFormat 只负责把“数值 + 单位”格式化成“5 分钟前”“明天”这样的文字，时间差和单位选择要应用自己计算。numeric auto 输出“昨天”等自然说法；排序和刷新要基于时间戳，SSR 要固定基准时间。

  • 前端页面如何支持从右到左的语言？

    阿拉伯语、希伯来语页面用 dir="rtl" 声明方向、lang 声明语言，布局用 CSS 逻辑属性，方向不确定的文本用 bdi 或 dir="auto" 隔离；图标按语义决定是否镜像，还要检查键盘顺序和挂到 body 的浮层。

  • 国际化页面怎样做跨地区测试，避免上线后才发现布局和时间错误？

    把语言、地区、时区和书写方向当作四个独立变量，按风险挑代表性组合组成测试矩阵；用伪本地化提前暴露写死宽度和字符串拼接；测试固定 locale 和时区，覆盖夏令时边界；RTL 和读屏要人工检查。

  • Intl.ListFormat 怎样生成自然的列表文案？

    Intl.ListFormat 按语言生成“A、B 和 C”“A, B, or C”这样的列表文案，type 区分“和”“或”。输入要先格式化成字符串；每项需要单独渲染（如链接）时用 formatToParts。

  • Intl.DisplayNames 怎样本地化语言、地区和货币名称？

    Intl.DisplayNames 能把 fr、JP、EUR 这样的代码翻译成当前语言的名称，按 type 区分语言、地区、文字、货币等。名称来自运行时的 CLDR 数据，只用于展示，存储和提交仍用代码，并要想好 fallback 行为。

  • Intl.Locale 解决什么问题？语言标签应该怎样建模？

    Intl.Locale 把 zh-Hant-TW 这样的 BCP 47 语言标签解析并规范化，拆出语言、文字、地区和 Unicode 扩展。maximize 和 minimize 补全或精简子标签；资源匹配要自己实现回退链；书写方向用 getTextInfo 或 textInfo 检测。
