前端监控面试题

前端监控面试题，涵盖错误采集与上报、性能埋点、Source Map 还原、白屏检测、页面离开时的上报和告警设计。共 7 道题。

  • 前端埋点有哪些方式？怎样设计一套埋点方案？

    埋点分三种：代码埋点由开发在业务代码里手动调用上报，最准确也最费人力；可视化埋点在页面上圈选元素生成配置，不用改代码；无埋点也叫全埋点，自动采集所有点击和页面浏览，事后再筛。方案设计要先定事件规范，再处理 PV、曝光、点击和停留时长，用队列批量上报，在页面隐藏时补发，并遵守隐私合规要求。

  • 错误监控平台怎样接入？以 Sentry 为例讲 SDK 初始化、Source Map 上传、release 关联和采样

    接入 Sentry 分四步：在应用最早执行的地方调用 Sentry.init，配置 dsn、release、environment；构建时用 Sentry 的打包插件生成并上传 Source Map，上传后删掉 map 文件；让 SDK 上报的 release 和上传 Source Map 时的 release 一致，Sentry 才能按版本统计错误、定位引入问题的提交；错误用 sampleRate、性能追踪用 tracesSampleRate 或 tracesSampler 采样，另外用 beforeSend 去掉敏感信息。

  • 前端怎样全局捕获 JS 错误、Promise 拒绝和资源加载失败？

    window.onerror 和 error 事件捕获运行时异常，unhandledrejection 捕获没处理的 Promise 拒绝，资源加载失败要在捕获阶段监听；跨域脚本的报错只剩 Script error.，要加 crossorigin 并配 CORS 响应头才能拿到详情。

  • 线上报错怎样用 Source Map 还原，又不把 map 文件公开？

    构建时生成不带 sourceMappingURL 注释的 hidden source map，按发布版本上传到错误监控服务或内网存储，部署产物里删掉 .map；前端上报原始堆栈，由服务端按版本和文件名还原到源码位置。

  • 页面关闭时怎样可靠上报？sendBeacon 和 keepalive 怎么选？

    在 visibilitychange 变成 hidden 时上报，不要依赖 unload/beforeunload；sendBeacon 只能发 POST，只返回是否入队；fetch keepalive 可以自定义请求、读响应；fetchLater 由浏览器在页面离开或超时时代发，目前只有 Chromium 支持。

  • 怎样检测页面白屏？常见方案有哪些误报？

    白屏检测通常在加载完成后延迟检查根节点有没有内容，或者用 elementFromPoint 采样视口里的关键点，看是不是只剩容器元素，再结合错误日志和资源失败找原因；骨架屏、慢网络、后台标签页和合法的空状态都会造成误报。

  • 前端监控数据怎样做采样、去重、聚合和告警？

    性能和行为数据按会话做一致性采样，错误数据尽量全量或单独提高采样率；客户端先限流去重，服务端按错误指纹聚合成问题；告警看错误率和影响用户数，并和发布版本关联，不要按单条错误报警。
