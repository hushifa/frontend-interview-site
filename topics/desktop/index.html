桌面端面试题

桌面端开发面试题，涵盖 Electron 进程模型与 IPC、安全边界、打包签名与自动更新、Electron 与 Tauri 选型和桌面应用性能。共 6 道题。

  • Electron 应用的主进程、渲染进程和 IPC 有哪些安全边界？

    Electron 主进程有系统权限，渲染进程只应有普通网页的权限。要靠 preload、contextIsolation、沙箱和 IPC 校验守住两者的边界，谨慎处理远程内容和外部链接，不能把桌面应用当成普通浏览器页面。

  • Electron 的主进程、渲染进程、preload 和 utility 进程分别负责什么？

    Electron 是多进程模型：主进程管应用生命周期和窗口，渲染进程显示网页，preload 在两者之间暴露有限的 API，utility 进程承担需要 Node.js 的重任务。各进程的可用 API 和生命周期不同，长计算按情况放到 utility 进程或 Web Worker。

  • Electron 的 IPC 和 contextBridge 怎样设计？

    渲染进程到主进程有单向与双向两种通信，主进程可以向指定窗口推送，渲染进程之间用 MessagePort 直接通信。preload 通过 contextBridge 只暴露窄接口，跨进程只传可序列化数据。

  • Electron 应用如何打包发布？代码签名、macOS 公证和自动更新要注意什么？

    Electron 应用的发布链路依次是打包、制作安装包、Windows 与 macOS 代码签名、Apple 公证，最后接入自动更新。自动更新可以用内置 autoUpdater，也可以用 electron-updater。

  • Electron 和 Tauri 有什么区别？桌面应用怎么选型？

    Electron 打包 Chromium 和 Node.js，Tauri 用系统 WebView 加 Rust 后端。两者在渲染引擎、后端语言、包体积、跨平台一致性、权限模型和生态上各有取舍，选型要看团队技术栈和对体积、一致性的要求。

  • Electron 应用启动慢、内存高、界面卡顿时怎么排查？

    Electron 性能问题分启动慢、主进程阻塞、渲染卡顿和内存高四类。先用 DevTools、contentTracing、app.getAppMetrics 等工具测量，再按官方性能建议优化。
