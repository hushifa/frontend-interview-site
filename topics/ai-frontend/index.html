AI 应用前端面试题

AI 前端开发面试题，涵盖大模型流式对话、SSE 与流解析、工具调用、RAG 引用、MCP、结构化输出、提示词注入和浏览器端推理。共 19 道题。

  • AI 对话前端为什么不能直接内置服务商 API 密钥？

    浏览器收到的代码、构建变量和网络请求都能被用户检查。长期 API 密钥、模型权限、额度和工具授权必须放在受控服务端，纯静态前端只能负责交互。

  • AI 流式响应为什么不能每收到一块就 JSON.parse？

    reader.read 返回的是任意字节分块，不保证对应字符、SSE 事件或完整 JSON。必须先处理字符编码和协议分帧，再解析并校验业务事件。

  • AI 聊天界面为什么不能只有 loading 一个状态？

    AI 对话需要分别表达等待、流式接收、完成、取消、失败、工具审批和持久化状态。稳定的请求、消息、片段和工具 ID 能避免并发与迟到事件串到错误回答。

  • 点击“停止生成”后，服务端一定停止调用模型吗？

    不一定。停止前端显示、取消浏览器请求、服务端停止任务和上游模型中止是不同层次，必须逐层传播取消并区分已完成、未知和仍在执行的工作。

  • 模型提出工具调用后，前端应该怎样展示和确认？

    工具调用只是模型提出的带参数请求，前端应把参数校验、用户审批、服务端授权、执行结果和结果未知分别建模。

  • 提示词注入与普通 XSS 有什么区别？

    提示词注入是把不可信内容伪装成模型应执行的指令，防护重点是数据与指令分离、最小权限和执行端授权，而不是只过滤关键词。

  • AI 生成的 Markdown 应该怎样安全地渲染？

    模型输出始终是不可信内容。安全渲染要限制 Markdown 能力、过滤 URL 和 HTML，并把展示代码、富内容解释和可执行代码分成不同权限边界。

  • RAG 应用中，前端除了展示答案还需要关注什么？

    RAG 先检索与问题相关且用户有权限访问的资料，再把证据交给模型生成。前端要让用户核对来源、理解不足，并区分检索失败与生成失败。

  • 哪些 AI 能力可以直接在浏览器中运行？

    浏览器可以执行适合设备的文本、图像和音频模型，但模型格式、运行时后端、内存、下载成本和输入规模必须同时匹配；本地推理也不自动等于离线或绝对隐私。

  • 浏览器端 AI 为什么用了 WebGPU 或 Worker 仍可能卡顿？

    用户等待的是下载、初始化、预处理、推理、后处理和界面更新的总时间。WebGPU 与 Worker 只优化其中一部分，模型复用、数据传输、内存和任务队列同样决定体验。

  • 为什么不能用字符串长度准确计算 Token 和费用？

    Token 是模型分词器处理输入的单位，前端只能做近似提示，真正的上下文限制和费用必须按目标模型的完整请求与返回用量计算。

  • MCP、模型工具调用和聊天界面是什么关系？

    MCP 规定宿主、客户端与服务器交换工具、资源和提示的协议；模型只提出调用建议，应用仍负责授权、参数校验、执行状态、用户确认和结果恢复。

  • AI 会话持久化为什么不能只保存最后一段回答？

    可恢复的 AI 会话要保存消息、片段、工具调用、引用、附件和运行状态之间的关系，并区分历史展示、模型上下文恢复和后台任务恢复。

  • AI 前端应用为什么需要评测和可观测性？

    AI 接口返回成功不代表答案正确。评测定义质量标准，可观测性解释请求经历的阶段、成本和失败原因，两者需要用同一套版本和样本口径连接起来。

  • 多模态 AI 前端界面需要怎样管理附件状态？

    图片、音频和文档从选择到模型可用要经历预览、上传、解析和权限校验，界面应逐阶段表达状态，避免把本地预览误认为模型已经理解。

  • AI 实时语音界面需要关注哪些前端状态？

    实时语音同时包含麦克风、网络会话、转写、模型生成和音频播放，输入、生成和播放必须分别建模，打断与恢复也要有明确协议。

  • AI 结构化输出为什么仍需要 Schema 校验？

    “返回 JSON”只描述格式愿望，不能证明输出完整、字段符合运行时契约或数据允许执行。结构化输出仍需解析、Schema 校验、业务核验和安全展示。

  • Agent 前端界面怎样展示计划、工具调用和人工确认？

    用可恢复的运行状态解释 Agent 正在做什么、等待什么和已经完成什么，区分模型输出、工具执行事实与用户授权。

  • AI Prompt Caching 对前端请求设计有什么影响？

    Prompt Caching 通常复用请求中稳定前缀的处理结果，可能降低重复计算成本，但不等于复用上一条答案，也不能替代权限隔离和对话持久化。
