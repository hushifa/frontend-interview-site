AI 应用前端面试题

AI 前端开发面试题，涵盖大模型流式对话、SSE 与流解析、工具调用、RAG 引用、MCP、结构化输出、提示词注入和浏览器端推理。共 20 道题。

  • AI 流式响应为什么不能每收到一块就 JSON.parse？

    reader.read 拿到的是网络随便切开的字节块，一块不一定是一个完整字符、一条事件或一段完整 JSON。要先按流解码成文字，再按 SSE 规则切成事件，最后才解析和校验每个事件。

  • AI 聊天界面为什么不能只有 loading 一个状态？

    等待第一个字、正在输出、已完成、被停止、出错、等用户批准工具，这几种状态用户能做的事都不一样，一个 loading 分不出来。要按请求、消息、片段分层记录状态，并给每次请求一个新 ID。

  • 点击“停止生成”后，服务端一定停止调用模型吗？

    不一定。界面停止显示、浏览器请求中止、服务端任务停止、模型调用中止是四件事，取消信号要一层层传下去；已经执行的工具操作也不会因此撤销。

  • AI 流式输出断线后，怎样恢复同一条生成任务？

    服务端要把每次生成存成一个可以查询的"运行"，每条事件带递增序号。客户端记下最后处理到第几条，重连时带上这个位置让服务端补发，并自己去重。恢复不了时，让用户自己选择要不要重新生成。

  • AI 生成的 Markdown 应该怎样安全地渲染？

    模型输出要当成用户输入一样不信任。默认不渲染原始 HTML，链接只放行 http 和 https，外部图片谨慎加载；确实要 HTML 时，在插件链的最后做净化。流式输出要合并更新，未闭合的块先按纯文本显示。

  • AI 对话前端为什么不能直接内置服务商 API 密钥？

    写进前端的东西用户都能看到，密钥被拿走就能拿你的账户随便调模型。长期密钥要放在自己的服务端；纯静态站点可以调用另外部署的接口，或者用服务端签发的短期受限令牌。

  • 为什么不能用字符串长度准确计算 Token 和费用？

    Token 是模型自己切分文字的单位，和字符数、字节数都不一样，换个模型还会变。前端只能估个大概；上下文上限和费用要按目标模型的完整请求算，最终以响应里的 usage 为准。

  • AI 结构化输出为什么仍需要 Schema 校验？

    是合法的 JSON，不代表字段类型、取值范围和业务含义都对。服务商的结构化输出模式能让模型更守规矩，应用自己还要做 JSON 解析、运行时校验和业务检查；流式输出的半成品对象只能拿来预览。

  • 提示词注入与普通 XSS 有什么区别？

    XSS 是让浏览器执行攻击者的代码；提示词注入是让模型把攻击者的文字当成指令。防护要把资料和指令分开、只给模型最少的权限，并在真正执行时单独授权，靠关键词过滤是不够的。

  • RAG 应用中，前端除了展示答案还需要关注什么？

    RAG 是先查出用户有权看的资料，再让模型照着资料回答。前端要把"没查到资料"和"生成失败"分开显示，引用要对应到这次真实查到的记录，并让用户能点开看原文和版本。

  • AI 会话持久化为什么不能只保存最后一段回答？

    一条回答里可能有文字、工具调用、工具结果、引用和附件。保存时要把这些片段和状态都存下来，分清"给界面看的"和"发给模型的"，还要处理数据格式升级和附件引用。

  • 模型提出工具调用后，前端应该怎样展示和确认？

    工具调用是模型提出的"我想用某个工具、参数是这些"的请求。前端要把一次 Agent 运行拆成多个步骤，状态由服务端事件推动；有副作用的操作先展示真实参数请用户确认，服务端执行前再授权一次，结果不明时按调用 ID 去查。

  • MCP、模型工具调用和聊天界面是什么关系？

    MCP 是一套协议，规定 AI 应用怎样发现和调用外部服务提供的工具、资源和提示。模型只是提出"想调用什么"，真正决定、授权、确认和展示的是宿主应用。本题按 2026-07-28 版规范讲无状态请求、server/discover 和授权的变化。

  • 多模态 AI 前端界面需要怎样管理附件状态？

    图片、音频、文档从用户选中到模型能用，要经过本地预览、上传、服务端扫描和解析几步。每个附件单独记录状态，分清用户看到的预览和模型真正收到的内容，用完记得释放预览地址和摄像头麦克风。

  • AI 生成的前端代码应该怎样审查和验证？

    把模型写的代码当成陌生人提交的补丁来审。先把需求写成能检查的条件，再看数据流，跑类型检查、lint 和覆盖失败、取消、竞态的测试，新增依赖也要核实。

  • AI 前端应用为什么需要评测和可观测性？

    接口返回 200 不代表答案对。评测是用固定样本和明确标准给质量打分；可观测性是记录每次请求每一步花了多久、用了哪个版本、出了什么错。两者都要记下模型和提示词版本，日志默认脱敏。

  • AI Prompt Caching 对前端请求设计有什么影响？

    Prompt Caching 是把请求里开头那段相同内容的处理结果存起来，下次直接用，省钱也更快。所以请求里不变的内容要放前面。本题以 Anthropic Messages API 为例讲自动缓存、手动断点、有效期和 usage 字段。

  • AI 实时语音界面需要关注哪些前端状态？

    实时语音同时牵涉麦克风、网络连接、语音转文字、模型生成和声音播放，这些状态要分开记。用户打断时既要清空本地待播的音频，也要通知服务端停止生成；关闭时把整条链路都释放掉。

  • 哪些 AI 能力可以直接在浏览器中运行？

    文本分类、向量生成、图像识别、语音识别这类小模型任务可以在浏览器里跑。能不能落地，要看模型多大、设备够不够、首次下载用户等不等得起；在本地算也不等于完全离线。

  • 浏览器端 AI 为什么用了 WebGPU 或 Worker 仍可能卡顿？

    用户等的是下载、初始化、预处理、推理、后处理和渲染加在一起的时间。Worker 只是让主线程不卡，WebGPU 只加速它支持的运算；会话复用、数据拷贝、任务排队和量化同样影响体验。
