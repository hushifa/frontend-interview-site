AI 应用前端面试题

AI 前端开发面试题，涵盖大模型流式对话、SSE 与流解析、工具调用、RAG 引用、MCP、结构化输出、提示词注入和浏览器端推理。共 20 道题。

  • AI 对话前端为什么不能直接内置服务商 API 密钥？

    浏览器收到的代码、构建变量和网络请求都能被用户查看和复用。长期 API 密钥、额度和工具授权必须放在受控服务端；纯静态站点可以调用另行部署的接口，或使用服务端签发的短期受限凭据。

  • AI 流式响应为什么不能每收到一块就 JSON.parse？

    reader.read 返回的是任意切分的字节块，不对应字符、SSE 事件或完整 JSON。要先流式解码，再按 SSE 协议分帧，最后解析并校验每个事件。

  • AI 聊天界面为什么不能只有 loading 一个状态？

    AI 对话要分别表达等待首字、流式接收、完成、中断、失败和工具待审批。按请求、消息、片段分层建模并使用稳定 ID，才能处理停止、重试和迟到事件。

  • 点击“停止生成”后，服务端一定停止调用模型吗？

    不一定。停止显示、取消浏览器请求、服务端停止任务和上游模型中止是四个层次，取消信号要逐层传递；已经执行的工具副作用不会因此撤销。

  • 模型提出工具调用后，前端应该怎样展示和确认？

    工具调用是模型提出的带参数请求。前端要把一次 Agent 运行拆成步骤，用服务端事件驱动状态，在副作用前展示真实参数请用户确认，执行端重新授权，并用调用 ID 处理结果未知。

  • 提示词注入与普通 XSS 有什么区别？

    XSS 让浏览器执行攻击者的代码；提示词注入让模型把不可信内容当成指令。防护重点是把数据和指令分开、给模型最小权限，并在执行端独立授权，关键词过滤不够。

  • AI 生成的 Markdown 应该怎样安全地渲染？

    模型输出是不可信内容。默认关闭原始 HTML、只放行 http/https 链接、谨慎处理外部图片；确实需要 HTML 时对整条插件链的最终结果做净化；流式输出要按帧合并、保守处理未闭合的块。

  • RAG 应用中，前端除了展示答案还需要关注什么？

    RAG 先检索用户有权访问的资料，再让模型基于这些资料回答。前端要分开展示检索失败和生成失败，把引用绑定到真实的检索记录，并让用户能查看原文片段和版本。

  • 哪些 AI 能力可以直接在浏览器中运行？

    浏览器可以用 ONNX Runtime Web、Transformers.js 等运行时执行小型文本、图像和音频模型，通过 WebGPU 或 WASM 计算。能否落地取决于模型大小、算子支持、设备内存和首次下载成本；本地推理也不自动等于离线或隐私。

  • 浏览器端 AI 为什么用了 WebGPU 或 Worker 仍可能卡顿？

    用户等待的是下载、初始化、预处理、推理、后处理和渲染的总和。Worker 只让主线程不被阻塞，WebGPU 只加速部分算子；会话复用、数据拷贝、任务队列和量化取舍同样决定体验。

  • 为什么不能用字符串长度准确计算 Token 和费用？

    Token 是模型分词器的计量单位，和字符数、字节数都不同，还随模型变化。前端只能估算；上下文限制和费用按目标模型的完整请求计算，以响应里的 usage 为准。

  • MCP、模型工具调用和聊天界面是什么关系？

    MCP 规定 AI 应用怎样发现和调用外部服务器提供的工具、资源和提示；模型只提出调用，宿主应用负责选择能力、授权、确认和展示结果。按 2026-07-28 版规范说明无状态请求、server/discover 和授权变化。

  • AI 会话持久化为什么不能只保存最后一段回答？

    一条助手回答可能由文本、工具调用、工具结果、引用和附件组成。持久化要保存这些片段及其状态，区分界面展示数据和发给模型的上下文，并处理 schema 升级和附件引用。

  • AI 前端应用为什么需要评测和可观测性？

    接口返回 200 不代表答案正确。评测用固定样本和明确标准衡量质量；可观测性按阶段记录耗时、版本和用量，解释每次请求经历了什么。两者都要记录模型和提示词版本，日志默认脱敏。

  • 多模态 AI 前端界面需要怎样管理附件状态？

    图片、音频和文档从选择到模型可用要经过本地预览、上传、服务端扫描与解析。每个附件独立建模状态，区分本地预览和模型实际收到的内容，并正确释放预览 URL 和媒体轨道。

  • AI 实时语音界面需要关注哪些前端状态？

    实时语音同时涉及麦克风、网络会话、转写、生成和播放。这些状态要分开建模；用户打断时要同时清空本地播放队列并通知服务端停止生成；关闭时释放整条链路。

  • AI 结构化输出为什么仍需要 Schema 校验？

    合法 JSON 不代表字段类型、范围和业务含义正确。服务商的结构化输出模式能提高符合率，应用仍要做 JSON 解析、运行时 Schema 校验和业务核验；流式的部分对象只能预览。

  • AI Prompt Caching 对前端请求设计有什么影响？

    Prompt Caching 复用请求中相同前缀的处理结果，降低重复输入的成本和延迟。请求结构要把稳定内容放前面；以 Anthropic Messages API 为例说明自动缓存、显式断点、有效期和 usage 字段。

  • AI 生成的前端代码应该怎样审查和验证？

    把模型生成的代码当作外部贡献者提交的候选补丁：先写清可检查的需求约束，再读差异和数据流，跑类型检查、lint 和覆盖失败与竞态的测试，并审查新增依赖与许可证。

  • AI 流式输出断线后，怎样恢复同一条生成任务？

    断线恢复需要服务端把一次生成保存为可查询的运行，事件带递增序号；客户端记录最后应用的序号，重连时按游标补发并去重。恢复失败时要让用户明确选择重新生成。
