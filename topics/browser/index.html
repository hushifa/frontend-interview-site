浏览器原理面试题

浏览器原理面试题，讲解页面渲染、DOM 事件与事件委托、重排与布局抖动、浏览器存储、Web Worker、同源策略和 bfcache。共 28 道题。

  • 浏览器从 HTML 到页面显示，经历哪些主要步骤？

    浏览器解析 HTML 和 CSS 得到 DOM 与 CSSOM，合成渲染树后依次布局、绘制、合成；脚本和样式会阻塞其中某些阶段。

  • 事件委托是什么？target 和 currentTarget 有何区别？

    事件委托把监听器挂在祖先元素上，利用冒泡统一处理子元素事件；target 是实际触发事件的元素，currentTarget 是当前执行监听器的元素。

  • Cookie、localStorage 和 sessionStorage 如何选择？

    Cookie 会随请求发送，适合服务端需要读取的小数据；localStorage 持久保存、按源共享；sessionStorage 只在当前标签页会话内有效。

  • 什么是强制同步布局？如何避免布局抖动？

    修改样式后立刻读取布局信息，会迫使浏览器在当前任务内同步计算布局；在循环里交替读写就形成布局抖动。

  • addEventListener 的 capture、once、passive 和 signal 有什么作用？

    capture 决定在捕获阶段还是冒泡阶段触发，once 让监听器只执行一次，passive 声明不会调用 preventDefault，signal 用 AbortController 统一移除监听器。

  • IntersectionObserver 适合做什么，能否证明用户看到了内容？

    IntersectionObserver 异步报告元素与视口或祖先容器的相交比例，适合懒加载、无限滚动和曝光统计；它只反映几何相交，不能证明元素没有被遮挡或用户真正看到。

  • Web Worker 可以解决哪些主线程卡顿？

    Web Worker 在独立线程运行脚本，适合解析、压缩、加密、大数据计算等 CPU 密集任务；它不能访问 DOM，通信靠 postMessage 的结构化克隆或转移。

  • IndexedDB 为什么比 localStorage 更适合大型离线数据？

    IndexedDB 是异步的事务型数据库，能存结构化对象和二进制、建索引、按范围查询，容量远大于 localStorage；代价是 API 偏底层，需要处理版本升级和事务生命周期。

  • 页面进入后台后，计时器和动画还会按原速度运行吗？

    不会。后台标签页的 requestAnimationFrame 会暂停，定时器会被节流；页面还可能被冻结或丢弃，需要用 Page Lifecycle 事件保存和恢复状态。

  • 同源、同站点与跨域分别是什么意思？

    同源要求协议、主机、端口都相同；同站点只比较协议和可注册域（eTLD+1），不看端口和子域；跨域通常指跨源，是同源策略和 CORS 讨论的对象。

  • bfcache 与 HTTP 缓存有什么区别？

    HTTP 缓存保存的是响应资源，bfcache 保存的是整个页面在内存中的快照，用户点后退或前进时直接恢复，JavaScript 状态也保留；unload 监听器、Cache-Control no-store 等会让页面无法进入 bfcache。

  • 为什么不断追加微任务会阻塞页面响应？

    浏览器每执行完一个任务都会清空整个微任务队列，清空期间新加入的微任务也会继续执行；如果微任务不断产生新的微任务，渲染和输入处理就一直等不到执行机会。

  • crossOriginIsolated 为 true 需要哪些条件？

    顶层文档同时返回 COOP same-origin 和 COEP require-corp（或 credentialless），且没有被 Permissions-Policy 禁用时，crossOriginIsolated 为 true，页面才能使用 SharedArrayBuffer 等能力。

  • 页面导航的关键阶段怎样用 Navigation Timing 分析？

    PerformanceNavigationTiming 记录一次文档导航从重定向、DNS、连接、请求响应到 DOM 解析和 load 的时间点；按相邻时间点相减得到各阶段耗时，TTFB 是 responseStart 减 startTime。

  • Page Visibility API 适合处理哪些页面生命周期场景？

    Page Visibility API 用 document.visibilityState 和 visibilitychange 事件报告文档是否在前台，适合暂停轮询、动画和计时，并在恢复时重新同步；它不判断单个元素是否可见。

  • BroadcastChannel 适合解决什么跨标签通信问题？

    BroadcastChannel 让同源的标签页、iframe 和 Worker 通过同名频道广播消息，适合同步登录状态、主题和缓存失效；它不保证送达，没有历史消息，也不提供互斥。

  • StorageManager 能告诉我们浏览器存储的哪些信息？

    navigator.storage 提供 estimate() 估算已用空间和配额、persist() 申请持久存储、persisted() 查询状态，以及 getDirectory() 访问 OPFS；返回值是估算值，配额由浏览器决定。

  • SharedWorker 和 Dedicated Worker 有什么区别？

    Dedicated Worker 只属于创建它的页面；SharedWorker 由同源的多个页面共享同一个实例，通过 MessagePort 通信，适合多标签页共用一条连接或一份状态。MDN 标为 Baseline 2026。

  • Web Bluetooth API 的安全和兼容性边界是什么？

    Web Bluetooth 让网页连接低功耗蓝牙设备并读写 GATT 特征值；它只在 Chromium 系浏览器的安全上下文中可用，必须由用户手势触发设备选择器，网页拿不到设备列表。

  • Navigation API 解决了传统 SPA 路由的哪些问题？

    Navigation API 用一个 navigate 事件统一拦截链接点击、表单提交、前进后退和脚本导航，通过 intercept() 交给前端处理，并提供导航完成状态和历史条目；MDN 标为 Baseline 2026。

  • Web Locks 怎样协调多个标签页对同一资源的操作？

    navigator.locks.request() 在同源的标签页和 Worker 之间获取命名锁，回调返回的 Promise 完成时释放；支持共享锁、ifAvailable、steal 和 signal 取消，适合保证只有一个标签页刷新令牌或执行同步。

  • scheduler.postTask 怎样表达前端任务优先级？

    scheduler.postTask 按 user-blocking、user-visible、background 三个优先级排队任务，可用 TaskController 取消或调整优先级；scheduler.yield() 用来在长任务中让出主线程。两者都不是 Baseline，需要特性检测。

  • WebSocketStream 怎样处理消息类型与关闭生命周期？

    WebSocketStream 用 Promise 和 Streams 封装 WebSocket，opened 提供 readable 和 writable，读取自带背压；它是非标准的实验性 API，只有 Chromium 支持，生产环境要保留 WebSocket 回退。

  • View Transitions API 如何实现页面和视图切换动画？

    同文档切换用 document.startViewTransition() 包住 DOM 更新，浏览器截取前后快照并用 CSS 动画过渡；跨文档切换用 @view-transition 规则开启。同文档已是 Baseline，跨文档目前 Firefox 不支持。

  • Cookie Store API 应该怎样安全地管理浏览器 Cookie？

    Cookie Store API 用 Promise 读写 Cookie 并能监听变化，只在 HTTPS 下可用；它读不到 HttpOnly Cookie，适合管理主题、语言等非敏感 Cookie。

  • 中文输入法期间怎样触发搜索？composition 与请求竞态如何一起处理？

    输入法组字期间 input 事件的 isComposing 为 true，此时不应发请求；在 compositionend 后再触发防抖搜索，并用 AbortController 或请求序号丢弃过期结果。

  • requestIdleCallback 适合做什么？为什么不能用它保证任务一定执行？

    requestIdleCallback 在浏览器空闲时执行低优先级工作，回调通过 timeRemaining() 得到剩余时间；页面一直繁忙或在后台时回调可能长时间不执行，Safari 也不支持，所以只适合可推迟、可丢弃的任务。

  • 浏览器为什么要拆分进程？前端如何理解故障隔离边界？

    现代浏览器把浏览器主进程、渲染进程、GPU 进程和网络服务等拆开，一个页面崩溃不会拖垮整个浏览器；站点隔离进一步让不同站点运行在不同渲染进程里，防御 Spectre 类侧信道攻击。
