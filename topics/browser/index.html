浏览器原理面试题

浏览器原理面试题，讲解页面渲染、DOM 事件与事件委托、重排与布局抖动、浏览器存储、Web Worker、同源策略和 bfcache。共 29 道题。

  • 从输入 URL 到页面显示，中间发生了什么？

    浏览器先判断输入是网址还是搜索词，再查 Service Worker 和 HTTP 缓存，没命中就做 DNS 解析、TCP 与 TLS 握手、发请求；拿到 HTML 后交给渲染进程，解析出 DOM 和 CSSOM，经过样式计算、布局、绘制、合成显示出来，最后触发 DOMContentLoaded 和 load。

  • 浏览器从 HTML 到页面显示，经历哪些主要步骤？

    浏览器先把 HTML 和 CSS 解析成 DOM 和 CSSOM，合成渲染树，再算布局、绘制、合成到屏幕上。CSS 会阻塞渲染，同步脚本会阻塞 HTML 解析。

  • 什么是强制同步布局？如何避免布局抖动？

    刚改完样式就去读元素尺寸，浏览器只能当场重新算布局，这叫强制同步布局。在循环里一读一写反复这样做，就是布局抖动。改法是先集中读、再集中写。

  • Cookie、localStorage 和 sessionStorage 如何选择？

    Cookie 会自动跟着请求发给服务端，适合放会话标识；localStorage 一直保存，同源的标签页共享；sessionStorage 只在当前标签页里有效，关了就没。

  • 同源、同站点与跨域分别是什么意思？

    协议、主机、端口都一样才算同源；同站点只看协议和主域名，子域和端口不同也算。平时说的跨域一般就是跨源，是同源策略和 CORS 管的事。

  • 事件委托是什么？target 和 currentTarget 有何区别？

    事件委托就是只在父元素上挂一个监听器，靠事件冒泡处理所有子元素的点击。target 是真正被点的元素，currentTarget 是挂着监听器的元素。

  • 为什么不断追加微任务会阻塞页面响应？

    浏览器每跑完一个任务，都要把微任务队列清空才继续，清空时新加的微任务也算在内。微任务不停地生出新微任务，渲染和点击处理就永远轮不到。

  • addEventListener 的 capture、once、passive 和 signal 有什么作用？

    capture 让监听器在事件往下传时就触发，once 让它只执行一次，passive 告诉浏览器不会阻止默认行为，滚动能马上开始，signal 能用 AbortController 一次移除一组监听器。

  • IntersectionObserver 适合做什么，能否证明用户看到了内容？

    IntersectionObserver 在元素进入或离开视口时通知你，适合懒加载、无限滚动和曝光统计。它只算位置有没有重叠，不能证明元素没被挡住、用户真的看到了。

  • Web Worker 可以解决哪些主线程卡顿？

    Web Worker 在另一个线程里跑脚本，适合解析、压缩、加密、大数据计算这类耗 CPU 的活。它不能碰 DOM，和主线程只能靠 postMessage 传数据。

  • IndexedDB 为什么比 localStorage 更适合大型离线数据？

    IndexedDB 是浏览器里的异步数据库，能存对象和文件、建索引查询，容量比 localStorage 大得多。代价是 API 偏底层，要处理版本升级和事务。

  • 页面进入后台后，计时器和动画还会按原速度运行吗？

    不会。切到后台后 requestAnimationFrame 会暂停，定时器会被放慢，页面还可能被冻结甚至丢弃。所以时间要按真实时间戳算，状态要在页面隐藏时保存。

  • 浏览器为什么要拆分进程？前端如何理解故障隔离边界？

    浏览器把界面、页面渲染、GPU、网络拆成不同进程，一个页面崩了不会拖垮整个浏览器。站点隔离再让不同站点的页面跑在不同进程里，防御 Spectre 这类攻击。

  • 中文输入法期间怎样触发搜索？composition 与请求竞态如何一起处理？

    用拼音打字时，没选完字之前的 input 事件都不该发请求。等 compositionend 后再防抖搜索，并取消上一个请求，只渲染最新结果。

  • bfcache 与 HTTP 缓存有什么区别？

    HTTP 缓存存的是一个个响应文件，bfcache 存的是整个页面在内存里的样子，点后退时页面连同 JS 状态直接恢复。用了 unload 监听器或 no-store 等情况，页面可能进不了 bfcache。

  • BroadcastChannel 适合解决什么跨标签通信问题？

    同源的几个标签页用同一个名字建频道，一个发消息，其他都能收到，适合同步退出登录、切换主题。它不保证送达，也不存历史消息。

  • Page Visibility API 适合处理哪些页面生命周期场景？

    document.visibilityState 告诉你页面当前在不在前台，切换时触发 visibilitychange。适合在后台暂停轮询、动画和计时，回来时马上刷新一次。

  • requestIdleCallback 适合做什么？为什么不能用它保证任务一定执行？

    requestIdleCallback 让浏览器在闲下来时帮你跑一些不急的活，比如预取和上报。页面一直忙或在后台时它可能迟迟不执行，Safari 也不支持，所以只能放可推迟、可丢弃的任务。

  • SharedWorker 和 Dedicated Worker 有什么区别？

    Dedicated Worker 只属于创建它的那个页面；SharedWorker 被同源的多个页面共用一个实例，适合多个标签页共用一条 WebSocket 连接或一份状态。MDN 标为 Baseline 2026。

  • Web Locks 怎样协调多个标签页对同一资源的操作？

    navigator.locks.request() 让同源的标签页和 Worker 抢同一把有名字的锁，回调执行完锁就自动释放。适合保证只有一个标签页去刷新令牌或做同步。

  • StorageManager 能告诉我们浏览器存储的哪些信息？

    navigator.storage 能估算当前网站用了多少空间、还能用多少，能申请让数据不被浏览器自动清除，还能打开 OPFS 文件系统。返回的数字都是估算值。

  • 页面导航的关键阶段怎样用 Navigation Timing 分析？

    浏览器把一次页面加载从重定向、DNS、建连、请求响应到 load 的每个时间点都记了下来，相邻时间点相减就是各阶段耗时。TTFB 就是 responseStart。

  • View Transitions API 如何实现页面和视图切换动画？

    把 DOM 更新包进 document.startViewTransition()，浏览器会截下前后两张画面，用 CSS 动画过渡。跨页面切换用 @view-transition 规则开启。同文档已是 Baseline，跨文档 Firefox 还不支持。

  • Navigation API 解决了传统 SPA 路由的哪些问题？

    Navigation API 用一个 navigate 事件接住链接点击、表单提交、前进后退和脚本跳转，调用 intercept() 交给前端处理，还能知道导航何时完成。MDN 标为 Baseline 2026。

  • scheduler.postTask 怎样表达前端任务优先级？

    scheduler.postTask 让你给任务标上 user-blocking、user-visible、background 三种优先级，还能取消或改优先级；scheduler.yield() 用来在长任务中途让出主线程。两者都要先做特性检测。

  • Cookie Store API 应该怎样安全地管理浏览器 Cookie？

    Cookie Store API 用 Promise 读写 Cookie，还能监听变化，替代手动拼 document.cookie 字符串。它只在 HTTPS 下可用，读不到 HttpOnly Cookie，适合管主题、语言这类不敏感的 Cookie。

  • crossOriginIsolated 为 true 需要哪些条件？

    页面同时返回 COOP same-origin 和 COEP require-corp（或 credentialless）两个响应头，并且没被 Permissions-Policy 禁用，crossOriginIsolated 才是 true，这时才能用 SharedArrayBuffer。

  • WebSocketStream 怎样处理消息类型与关闭生命周期？

    WebSocketStream 把 WebSocket 改成用 Promise 和流来操作，读得慢时浏览器会自动少收，这叫背压。它是非标准的实验性 API，只有 Chromium 支持，生产环境要保留 WebSocket 回退。

  • Web Bluetooth API 的安全和兼容性边界是什么？

    Web Bluetooth 让网页连上低功耗蓝牙设备并读写数据。只有 Chromium 系浏览器在 HTTPS 下支持，而且必须由用户点击后亲自在弹窗里选设备。
