SSR 与渲染面试题

前端渲染方案面试题，对比 CSR、SSR、SSG 与混合渲染，理解 Hydration 水合不匹配，以及 React Server Components 和服务端渲染的区别。共 11 道题。

  • Next.js 的 SSR、SSG、ISR 和 App Router 怎样理解？

    在 Next.js App Router 里，SSR、SSG、ISR 不再靠 getServerSideProps 这类函数区分，而是由组件用到的数据决定：没用到 cookies、headers、searchParams 等请求时 API 的部分默认预渲染（相当于 SSG）；用到了就在请求时渲染（相当于 SSR）；设置 revalidate 或按需失效后在后台重新生成（ISR）。Next.js 16 新项目默认开启 Cache Components，静态和动态的边界细到组件级。

  • 前端 SEO 有哪些具体手段？

    按“让搜索引擎找得到、看得懂、愿意展示”整理成清单：可抓取的 <a href> 链接与 History API 路由、sitemap 和 robots.txt；每页唯一的 title、meta description 和 canonical；正确的 HTTP 状态码，避免 soft 404；正文进初始 HTML 或保证渲染后可见；JSON-LD 结构化数据；图片用 <img> 加 alt；Core Web Vitals 达标。robots.txt 不能阻止页面被编入索引，要用 noindex。

  • CSR、SSR、SSG 和混合渲染如何选择？

    按页面主要内容的 HTML 在什么时候生成来区分：CSR 在浏览器中生成，SSR 在每次请求时由服务器生成，SSG 在构建时生成。内容变化频率、是否个性化、是否需要搜索收录和部署条件决定选择；实际项目通常按页面混合使用。

  • Hydration mismatch 为什么发生，应该怎样修复？

    Hydration 时客户端第一次渲染的结果必须与服务端 HTML 一致。常见原因是渲染中用了时间、随机数、浏览器专属 API，两端数据或时区不同，HTML 嵌套不合法，或者浏览器扩展修改了 DOM。修复方法是让两端用同一份初始数据，只有浏览器才有的内容等挂载后再更新。

  • React Server Components 和 SSR 是同一件事吗？

    不是。SSR 把组件树渲染成 HTML，客户端组件也参与 SSR，之后还要 hydration。Server Components 只在服务端或构建时运行，可以直接访问数据库，代码不会发到浏览器，输出的是序列化的组件结果。两者可以配合使用。

  • React 流式 SSR 解决什么问题？

    流式 SSR 先把 Suspense 边界以外的页面外壳发送给浏览器，慢的部分先显示 fallback，数据就绪后再以 HTML 片段和内联脚本补上。用户能更早看到内容，客户端也能按区域逐步 hydration。React 19.2 在此基础上新增了 resume 系列 API，用于部分预渲染。

  • 前端渲染方式怎样影响 SEO 和部署？

    爬虫和社交分享服务首先读的是服务器返回的 HTML，而 CSR 页面的初始 HTML 通常没有正文。SSR 和 SSG 能直接提供内容，但还要返回正确的状态码、唯一的 title 和 canonical、提供 sitemap。SPA 部署需要配置路径回退，同时让不存在的路径返回 404。

  • Nuxt 和 Vue SSR 是怎样工作的？

    Vue SSR 是在服务器上用 createSSRApp 创建应用、用 renderToString 把组件渲染成 HTML 发给浏览器，浏览器再用 createSSRApp 挂载同一个应用完成 hydration，绑定事件让页面能交互。Nuxt 把这套流程连同路由、数据获取、状态传递和服务器（Nitro）都封装好了，默认就是通用渲染，还能按路由配置预渲染、缓存或只在客户端渲染。

  • Vue SSR 出现水合不匹配（Hydration mismatch）怎样排查？

    水合不匹配是浏览器端第一次渲染的结果和服务端返回的 HTML 对不上。Vue 官方列出的常见原因是 HTML 嵌套不合法被浏览器改写、渲染时用了随机值、服务端和浏览器时区不同。排查时先看开发环境控制台里“rendered on server / expected on client”的对比，生产环境可以用 __VUE_PROD_HYDRATION_MISMATCH_DETAILS__ 打开详细信息；修复方法是让两端首次渲染的输入一致，浏览器才有的内容放到 onMounted 之后，确实无法避免的单个差异用 data-allow-mismatch 抑制。

  • Next.js App Router 中的几层缓存怎样区分？

    Next.js 16 新项目默认开启 Cache Components：数据和组件默认不缓存，用 'use cache' 显式缓存，用 cacheLife 设置时长、cacheTag 打标签，修改后用 updateTag 或 revalidateTag 失效；要请求时数据的部分放进 Suspense 流式输出。未开启时沿用旧模型，fetch 默认不缓存，通过 force-cache 和路由段配置控制。

  • SSR 和 SSG 中的缓存层应该怎样区分？

    服务端渲染常常同时涉及 HTTP 缓存（浏览器和 CDN，由 Cache-Control 控制）、请求内去重、框架跨请求的数据缓存和客户端状态缓存。每一层的作用范围和失效方式不同；个性化内容不能进入共享缓存，缓存键必须包含所有影响结果的因素。
