SSR 与渲染面试题

前端渲染方案面试题，对比 CSR、SSR、SSG 与混合渲染，理解 Hydration 水合不匹配，以及 React Server Components 和服务端渲染的区别。共 7 道题。

  • CSR、SSR、SSG 和混合渲染如何选择？

    按页面主要内容在什么时候生成 HTML 来区分：CSR 在浏览器中生成，SSR 在每次请求时由服务器生成，SSG 在构建时生成。内容变化频率、是否个性化、是否需要搜索收录和部署条件决定选择；实际项目通常按页面混合使用。

  • Hydration mismatch 为什么发生，应该怎样修复？

    Hydration 时客户端第一次渲染的结果必须与服务端 HTML 一致。常见原因是渲染中使用了时间、随机数、浏览器专属 API，两端数据或时区不同，HTML 嵌套不合法，或者浏览器扩展修改了 DOM。修复方法是让两端使用同一份初始数据，只在浏览器中才有的内容等到挂载后再更新。

  • React Server Components 和 SSR 是同一件事吗？

    不是。SSR 把组件树渲染成 HTML，客户端组件也参与 SSR，之后还要 hydration。Server Components 只在服务端或构建时运行，可以直接访问数据库，代码不会发到浏览器，输出的是序列化的组件结果。两者可以配合使用。

  • React 流式 SSR 解决什么问题？

    流式 SSR 先把 Suspense 边界以外的页面外壳发送给浏览器，慢的部分先显示 fallback，数据就绪后再以 HTML 片段和内联脚本补上。用户能更早看到内容，客户端也可以按区域逐步 hydration。React 19.2 在此基础上新增了 resume 系列 API，用于部分预渲染。

  • SSR 和 SSG 中的缓存层应该怎样区分？

    服务端渲染常同时涉及 HTTP 缓存（浏览器和 CDN，由 Cache-Control 控制）、请求内去重、框架跨请求的数据缓存和客户端状态缓存。每一层的作用范围和失效方式不同；个性化内容不能进入共享缓存，缓存键必须包含所有影响结果的因素。

  • 前端渲染方式怎样影响 SEO 和部署？

    爬虫和社交分享服务首先读取服务器返回的 HTML，CSR 页面的初始 HTML 通常没有正文。SSR 和 SSG 能直接提供内容，但还要返回正确的状态码、唯一的 title 和 canonical、提供 sitemap。SPA 部署需要配置路径回退，同时让不存在的路径返回 404。

  • Next.js App Router 中的几层缓存怎样区分？

    Next.js 16 新项目默认开启 Cache Components：数据和组件默认不缓存，用 'use cache' 显式缓存，用 cacheLife 设置时长、cacheTag 打标签，修改后用 updateTag 或 revalidateTag 失效；需要请求数据的部分放进 Suspense 流式输出。未开启时沿用旧模型，fetch 默认不缓存，通过 force-cache 和路由段配置控制。
